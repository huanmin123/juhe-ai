# 模型目录与模型检测

> 这一篇解决：客户端能用的模型清单从哪来、怎么确认某个账户真的能跑某个模型（模型检测）、检测结论怎么读。核心原则：目录决定"能声明什么"，检测回答"是不是真的"。

## 开始之前，先分清三个问题

| 问题 | 归谁管 | 去哪 |
| --- | --- | --- |
| 系统能声明哪些模型、什么价格 | 供应商层模型目录 | [供应商](/__aisys__/providers) |
| 这个账户能不能跑某模型 | 账户支持模型 + 模型检测 | [模型检测](/__aisys__/model-checks) |
| 客户端为什么看不到某模型 | 网关实际返回的清单 | 先查目录状态，再查账户支持模型 |

## 模型目录从哪来

模型目录和价格目录都归属在**供应商层**维护。打开[供应商](/__aisys__/providers)页面，进入某个供应商的模型目录，就能看到该供应商下的全部模型与定价。

每个 AI 账户能声明哪些模型、按什么口径计价，都以所在供应商的目录为准——这就是"目录决定能声明什么"。

### 目录里每个模型的关键字段

| 字段 | 说明 | 注意 |
| --- | --- | --- |
| 状态 | 启用 / 草稿 / 停用 | 启用后进入可用模型目录；草稿和停用状态不会参与正常调用 |
| 作用域 | 全局模型 / 个人模型 | 全局模型对所有用户可见；个人模型只对所选用户可见（名单由管理员在此页面维护） |
| 接口协议 | 该模型支持的接口族 | 只选择上游模型真实支持的接口；此配置会影响账号、映射和路由的可选范围 |
| 服务等级 | 请求档位（如标准/优先/flex 之类，具体档位以供应商实际提供的为准） | 只选择供应商真实支持且已配置独立价格的档位；档位影响计费单价，不影响请求能否路由 |
| 价格 | 计费口径 | 与用量统计、美元额度直接相关 |
| 发布时间 / 停用日期 | 目录排序与生命周期提示 | 供应商未公布停用日期时留空 |
| 最大输入 | 单次请求允许的最大输入 Token | 供应商未单独公布时留空 |

维护目录时的两个实用功能：

- **配置模板**：可复制同一供应商已有模型的用途、协议、能力、输入上限和价格，模型 ID 不会被复制——适合批量录入同系列模型。
- **删除保护**：已绑定 AI 账户的模型不能直接删，需要先从账户支持模型或模型映射中移除。

> ⚠️ 删除模型会影响所有把它列为支持模型或映射目标的账户。删除前先确认引用清单，并通知相关账户的归属人。

## 目录、账户支持模型与客户端看到的关系

三层关系别混淆，出问题时先分清是哪一层的事：

| 层 | 谁维护 | 决定什么 |
| --- | --- | --- |
| 供应商模型目录 | 管理员在供应商页维护 | 系统能声明什么模型、什么价格 |
| 账户支持模型 | 建账户时声明 | 该账户实际能服务哪些模型；决定候选过滤及模型别名的目标范围 |
| 客户端模型清单 | 网关运行时返回 | 调用方通过 `/v1/models` 拿到的清单，以网关实际返回为准 |

配置不能虚构上游能力：账户的支持模型与接口能力只声明真实上游能处理的协议，模型别名的两端都必须满足协议档案和支持模型的限制。谎报能力不会让请求成功，只会让检查和实际调用失败。

## 发起一次模型检测

模型检测回答一个具体问题："这个账户声称能跑的这个模型，是不是真的？"在[模型检测](/__aisys__/model-checks)页面操作：

| 顺序 | 做什么 | 为什么 | 判断标准 |
| --- | --- | --- | --- |
| 1 | 选目标 AI 账户 | 检测按账户执行 | 模型候选**只来自该账户的支持模型**，未选账户时模型下拉为空 |
| 2 | 选目标模型 | 一次检测针对一个"账户 + 模型"组合 | 模型名来自账户支持模型，不回退全局目录 |
| 3 | 可选：选可信对比账户 | 用一个已知可信的账户做对照，提高结论可信度 | 对比账户不能和检测目标相同 |
| 4 | 选检测档位并启动 | 快速检测验证基本可用；深度检测覆盖更多探针 | 运行中出现终端进度流，逐项输出每个探针的结果 |
| 5 | 等待或手动停止 | 检测会真实调用上游 | **同一账户同时只能跑一个检测**；停止后该次检测记为已取消 |

两点边界：

- **检测消耗真实上游额度。** 发起前先确定测试模型、协议形态和上游额度边界，避免检测本身打爆账户配额。
- **除手动外还有自动触发。** 页面支持定时检测计划与质量恢复触发，也有手动检测质量配置可调；历史检测记录全部可查。

### 检测档位怎么选

| 档位 | 覆盖范围 | 适用 |
| --- | --- | --- |
| 快速检测 | 基本协议与可用性探针 | 日常复核、小改动后的快速确认 |
| 深度检测 | 覆盖更多探针（行为、对照、身份类） | 新账户接入验收、重要模型的周期监督 |

### 定时检测与质量配置

页面还提供两类常驻配置：

- **手动检测质量配置**：调整手动检测的质量口径；
- **定时检测计划**：按计划自动对账户发起检测，计划有执行状态（已暂停 / 执行中 / 账户阻塞 / 排队中 / 已启用），"账户阻塞"通常意味着该账户还有一次检测未结束。

### 触发方式一览

| 触发方式 | 来源 | 典型用途 |
| --- | --- | --- |
| 手动检查 | 管理员在页面发起 | 接入验收、排障复核 |
| 定时检查 | 检测计划自动执行 | 周期性质量监督 |
| 质量恢复 | 质量隔离的账户复测 | 确认隔离是否可以解除 |
| 计划立即执行 | 检测计划的手动触发 | 把排队计划提前跑 |

## 怎么读检测结论

### 先看整体结论

每次检测记录带状态与结论等级：

| 字段 | 取值 | 含义 |
| --- | --- | --- |
| 状态 | 检测中 / 已完成 / 失败 / 已取消 | 只有"已完成"的结论可作判断依据 |
| 结论等级 | 高可信 / 较可信 / 不确定 / 疑似不符 / 不可检测 | 对"该模型是否真如声称"的可信度分级 |
| 评分 | 分数 / 满分，附结论消息 | 结合消息文本读，不要只看数字 |

等级怎么用：

| 等级 | 建议动作 |
| --- | --- |
| 高可信 / 较可信 | 可以放心让该账户承接该模型流量 |
| 不确定 | 复测一次，或换可信对比账户再测；先不要基于它做大范围调度变更 |
| 疑似不符 | 核对账户支持模型与模型映射声明，必要时从支持模型中移除该模型 |
| 不可检测 | 检测本身没跑起来：看失败原因（额度、网络、协议），排除后重测 |

### 再看单项检查

检测由多个探针组成，每项结果为：**通过 / 需关注 / 失败 / 未计分**。整体等级由各项结果汇总得出，下结论前先扫一眼哪些项"需关注"——它们往往就是下一个问题的答案。

探针按回答的问题分几类，常见的有：

| 类别 | 代表探针 | 回答什么 |
| --- | --- | --- |
| 协议与格式 | 协议非流式 / 协议流式、结构化输出、工具调用、Usage 字段 | 接口契约是否兑现 |
| 行为 | 行为探针、长上下文找针、稳定性探针 | 实际表现是否稳定达标 |
| 对照 | 可信对比、辅助模型对照、分布相似度对照、题库测试 | 与可信基准比像不像 |
| 身份 | 身份自报一致性、指令完整性复读、推理锚点题 | 是不是声称的那个模型 |

### 最后交叉验证

每条检测记录都带 `runId` 与 `traceId`。需要证据细节时，用 traceId 到[审计日志](/__aisys__/audit-logs)或[使用记录](/__aisys__/usage-records)里查当次真实请求与响应摘要。检测记录本身也有历史列表，可按账户、模型回溯多次结论的变化。

## 检测与账户状态的关系

**检测是诊断证据，不是状态变更凭证。** 检测成功或失败都不改写账户状态、调度开关、冷却或健康事实；账户能否承接流量，仍由后台激活检查与真实调用证据决定。

推荐的接入顺序是反过来用检测：**先检测，结果再决定是否激活账户**——新账户先跑一次模型检测，结论可信再让它承接流量，比"先激活再发现模型不对"省一次线上故障。

接入验收的最小清单：

1. 激活检查通过后，跑一次快速检测确认基本可用；
2. 重要账户或重要模型，补一次深度检测；
3. 把结论等级记入接入记录，作为后续定时检测的基线。

## 检测结论的常见误读

| 误读 | 事实 |
| --- | --- |
| "检测通过了，账户一定能被调度" | 检测只回答模型可信度；账户还要过调度开关、时间计划等候选条件 |
| "分数低就是模型假的" | 先看是哪些探针失分：协议类失分可能是配置问题，身份类失分才指向模型冒充 |
| "检测失败 = 账户坏了" | "失败"是检测流程没跑完（额度、网络、协议）；排除原因重测，不等于账户异常 |
| "测一次管永久" | 上游会变；重要账户用定时检测持续监督 |
| "结论等级高就不用再看单项" | "需关注"的单项往往预示下一类问题；整体等级只是汇总 |
