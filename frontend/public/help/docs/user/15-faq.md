# 常见问题 FAQ

> 这一篇解决：高频问题的两三句快答，每条都告诉你去哪一篇把这件事彻底弄清楚。

## 怎么用这篇

- 先在下面按主题找你的问题；每条答案只有两三句，末尾的《书名号》是详细篇目，点进去看完整做法。
- 想按"症状"查（比如"一直 401"），直接翻《错误码与排障》的按症状定位表更快。

文里形如 [API Keys](/__aisys__/my-api-keys) 的链接会跳转到管理台对应页面，未登录时会先要求登录；页面展示与文档描述不一致时，以页面为准。

## 认证与 Key

最常见的两种情况：Key 泄露了，和一直 401。都能在一分钟内定位。

### Key 泄露了怎么办？

立即到 [API Keys](/__aisys__/my-api-keys) 页面停用（或删除）这把 Key，重建一把新的，然后只更新你的客户端配置。停用立即生效，旧 Key 的请求会开始收到 401。日常预防：Key 用环境变量存、不进代码仓库和截图。详见《API Key 与认证》。

### 为什么一直 401？

九成是认证头没写对：漏了 `Bearer ` 前缀、`Bearer` 后没空格、Key 复制不全，或 Key 已被停用。本项目只认 `Authorization: Bearer <Key>`，没有 `x-api-key` 之类的替代头。详见《API Key 与认证》的 401 检查清单。

## 模型

模型问题多半归结为一句话：名字没复制对，或者路由链路不覆盖。

### 为什么提示"当前分组无账户支持请求模型"？

这是 `unsupported_model`（400）：你的 Key → 策略路由 → 分组这条链路上，没有账户直接支持该模型，模型映射也没命中。先确认模型名与 `GET /v1/models` 返回的完全一致，再找管理员确认路由与目录。详见《模型列表：我能用什么模型》与《核心概念：一次请求的旅程》。

### 模型映射是什么？

账户上配置的一张"你请求的模型名 → 上游真实模型名"对照表。命中映射时，出站请求的模型名会被改写，但你收到的响应里模型名不变，你无感知——好处是上游换了、你的代码不用动。详见《核心概念：一次请求的旅程》。

### 列表里没有我想要的模型？

`GET /v1/models` 返回的是按你这把 Key 过滤后的目录，没有通常意味着链路上无账户支持或目录未上架。另外检查拼写和大小写——模型名要原样复制。详见《模型列表：我能用什么模型》。

## 协议与行为

这一类问题是关于"网关做什么、不做什么"的，弄清楚就不会再怀疑网络。

### 流式和非流式怎么选？

想要打字机效果、长回答早点看到首字，选 `"stream": true`；写脚本、一次拿完整 JSON 更省事，选非流式。两者计费口径一致，只是返回方式不同。详见《流式响应 SSE 怎么读》。

### 网关能帮我存对话历史吗？

不能。网关是无状态透传，不替任何客户端保存上下文：多轮对话要把历史 `messages` 每次都带全，由你自己在客户端维护。详见《对话协议 chat completions》。

### 视频任务多久算超时？

不要按固定秒数死等：视频是异步任务，以任务状态接口返回的状态机为准，按《视频生成》里的轮询方式查到终态再取片。状态长期不动或报 5xx，按《错误码与排障》处理。详见《视频生成：从提交到取片》。

### 收到没有 error 信封的 404（"资源不存在"）？

那是打到了非 `/v1` 的路径：多半是 Base URL 少了 `/v1` 前缀、路径拼写错，或把管理接口当成了 API。`/v1` 协议路径的 404 才是标准错误信封。详见《错误码与排障》。

## 用量与状态

这几个问题的答案最终都指向同一处：三个用量页面，加一个健康页面。

### 怎么查我花了多少钱？

[用量记录](/__aisys__/my-usage-records) 看逐笔，[用量统计](/__aisys__/my-usage-stats) 看按天/按模型汇总，[统计总览](/__aisys__/my-stats) 看大盘。单价在管理台模型目录可见；失败请求算不算钱，以记录里的计费结果为准。详见《用量与统计》。

### 是不是上游挂了？

偶发 5xx 先重试；持续失败看管理台的 [AI 健康](/__aisys__/my-ai-health)（上游是否正常）和 [AI 性能](/__aisys__/my-ai-performance)（成功率、延迟趋势），定位不了就找管理员。详见《错误码与排障》。

### 不写代码能先试试效果吗？

可以。管理台有 [在线聊天](/__aisys__/my-chat) 页面，选个模型直接聊，效果和 API 调用一致，也适合快速验证某个模型能不能用。注意在线聊天用的是系统维护的专属对话 Key，不是你的客户端 API Key——客户端接入验证请以真实客户端调用为准（详见《用量与统计》）。详见《快速开始：发出你的第一个请求》。

## 问人之前的五分钟自查

1. 模型名是不是从 `GET /v1/models` 返回里原样复制的？
2. 认证头是不是 `Authorization: Bearer sk-...` 的形状？
3. Base URL 是不是完整、带了 `/v1` 前缀？
4. 完整的报错 JSON 和发生时间拿到手了吗？

这四点理清，多数问题在上面对应篇目里就有答案；还没解决的，带着这些证据找管理员（要带什么，见《错误码与排障》的"什么时候找管理员"一节）。
