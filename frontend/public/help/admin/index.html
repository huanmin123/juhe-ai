管理链路与范围

管理模式处理所有系统账户的资源。请求链路为 API Key -> 策略路由 -> 分组 -> AI 账户 -> 供应商 / 协议能力。

  1. 先在供应商和代理管理中确认可用的基础资源。
  2. 创建分组并选择供应商。分组会保存 providerCode，它既是账户集合，也是供应商过滤边界；同一分组只接纳该供应商账户。
  3. 为目标系统账户创建或导入 AI 账户，检查成功后激活。
  4. 需要复制配置时，新建一个同配置的策略，再将 API Key 绑定到新策略；不要修改原策略后再绑定以免影响既有流量。

代用户导入账户

先在账户页选择目标系统账户，再导入 juhe-ai-account-import v1 JSON。单次受约 256KB 限制，最多 50 个账户，最多 20 个代理；先解析预览，再确认导入。可按选项创建缺失分组或代理、跳过重复账户。即使来源写 active，新账户仍会以 pending_test 创建，必须由后台激活检查通过后参与调度。

排障顺序

  1. 请求异常：先在使用记录确认 API Key、策略、分组和账户的实际链路。
  2. 账户异常：查看 AI 健康，重试检查前确认凭据、模型与代理可达。
  3. 性能异常：对照 AI 性能、系统指标和运行日志，不以单一慢请求判断全局故障。
  4. 授权或数据范围异常：检查系统账户角色、授权、团队及操作日志。
管理员手册只提供操作路径与风险，不公开上游密钥、OAuth token、代理密码和原始审计内容。
管理角色也可在用户模式查看自己的用户侧页面；管理页展示的是系统范围数据。
