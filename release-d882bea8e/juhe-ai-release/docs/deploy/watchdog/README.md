# 状态检测与自动恢复目录

> 面向明确需要外部状态检测的家庭部署、服务器部署和长期运行节点。
> 默认由 systemd / launchd / Windows Service / Docker restart policy 负责常驻；外部探针默认只告警。本文只说明经评审后如何增加自动恢复并避免重启风暴。

## 适用边界

- 各平台都应有状态检测，但不等于都要部署会重启应用的外部 watchdog。
- 应用内部 supervisor 已负责 DB service / worker 子进程异常退出后的退避重启；主服务常驻由平台服务管理器负责。
- 外部 watchdog 是可选项。默认只告警；只有无人值守自动恢复收益明确、且已经与发布流程互斥时，才允许重启主服务。
- watchdog 不能替代日志、备份、数据库完整性检查和上游代理测试。
- Redis 由各自唯一 launchd/systemd/Docker service 管理；watchdog 不得并行启动第二个相同端口实例，也不得用参数热改把 cache/state/queue 临时合并。单次 Redis 命令失败由应用受控返回或按记录预算丢弃，只有持续依赖不可用且本机双 health 连续失败时才进入既有主服务恢复判断。
- 自动恢复必须带连续失败阈值、启动宽限期、冷却时间和重启次数窗口，避免网络抖动或上游故障触发重启风暴。
- 公网入口、DNS、证书、Caddy、Nginx 或 WireGuard 失败不得触发应用重启；反向代理链路按 [反向代理与高并发隧道部署指南](../反向代理与高并发隧道部署指南.md) 分层排查。
