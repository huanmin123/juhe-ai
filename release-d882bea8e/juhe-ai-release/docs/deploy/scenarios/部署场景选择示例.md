# 部署场景选择示例

## 示例 1：云服务器部署

目标：

- 有一台 Linux VPS。
- 域名 `ai.example.com` 指向 VPS。
- 需要公网 HTTPS 和账号级上游代理。

阅读路径：

```text
docs/deploy/scenarios/服务器部署方案.md
docs/deploy/linux/Linux部署指南.md
docs/deploy/https/Caddy自动HTTPS部署指南.md
docs/deploy/proxy/sing-box网络代理部署指南.md
```

关键配置：

```env
JUHE_AI_HOST=127.0.0.1
JUHE_AI_PORT=3000
JUHE_AI_ALLOWED_ORIGINS=https://ai.example.com
JUHE_AI_COOKIE_SECURE=true
JUHE_AI_TRUST_PROXY=true
```

客户端：

```text
Base URL: https://ai.example.com/v1
API Key : juhe-ai 后台生成的本地 sk-... 密钥
```

## 示例 2：家里 Windows 主机 + 家宽公网 IP

目标：

- juhe-ai 跑在家里 Windows 主机。
- 路由器把 `80/443` 转发到这台主机。
- DDNS 或域名指向家宽公网地址。

阅读路径：

```text
docs/deploy/scenarios/家庭宽带反向代理方案.md
docs/deploy/windows/Windows部署指南.md
docs/deploy/https/Caddy自动HTTPS部署指南.md
docs/deploy/proxy/sing-box网络代理部署指南.md
```

只暴露：

```text
公网 80/443 -> 家里 Windows 主机 Caddy
Caddy -> 127.0.0.1:3000 juhe-ai
```

不要暴露：

```text
3000
7890
PostgreSQL / Redis
DB service
```

## 示例 3：家里主机无公网 IP，用云服务器反代回家

目标：

- juhe-ai 跑在家里 Linux / Windows / macOS 主机。
- 家宽没有公网 IP。
- 云服务器做 HTTPS 入口，通过 WireGuard 回源到家里主机。

阅读路径：

```text
docs/deploy/scenarios/家庭宽带反向代理方案.md
docs/deploy/反向代理与高并发隧道部署指南.md
家里主机对应平台文档
```

网络路径：

```text
客户端 -> ai.example.com -> Edge Caddy layer4 -> WireGuard -> 家里主机 Caddy -> juhe-ai
```

公网服务器 Caddy 只反代到私有地址，不在公网服务器上保存 juhe-ai 数据。

## 示例 4：家里 Mac 主机 + 公网 edge 回源

目标：

- juhe-ai 跑在家里的 Mac。
- Mac 使用 `launchd` 常驻。
- release 通过 `current` 软链接切换。
- 公网入口先到 Edge，再经 WireGuard 回源到 Mac 本机 Caddy。

阅读路径：

```text
docs/deploy/scenarios/家庭宽带反向代理方案.md
docs/deploy/反向代理与高并发隧道部署指南.md
docs/deploy/macos/macOS部署指南.md
docs/deploy/https/Caddy自动HTTPS部署指南.md
docs/deploy/proxy/sing-box网络代理部署指南.md
```

推荐链路：

```text
客户端
  -> 公网 Edge Caddy layer4
  -> WireGuard
  -> Mac Caddy 终止 TLS
  -> Nginx / juhe-ai
```

上线后验证三层：

```text
Mac 本机 juhe-ai health
Mac 本机 Caddy 监听端口
公网域名 health
```

如果后台“使用记录”或“公开接口日志”里所有用户都是同一个 Edge / WireGuard 地址，按 [反向代理与高并发隧道部署指南](../反向代理与高并发隧道部署指南.md) 检查 PROXY v2 信任边界和 `JUHE_AI_TRUST_PROXY`。

新版本正常重启不应再出现旧 `worker` / `db-service` 残留抢锁；只有强杀、系统崩溃或持续 `database is locked` 时，再做旧子进程兜底排查。
