# 账户错误作用域与重试选择验证设计

关联执行计划：[PLAN-0176-20260723T160339731Z](../../plans/计划-0176-20260723T160339731Z-账户错误作用域与重试选择验证.md)。

## 目标

验证请求级、会话级、凭据 Key 级、账户级和路由级故障不会互相越权，尤其防止坏会话并发请求把正常账户池误判为死亡。

## 故障作用域

```text
客户端请求/会话语义错误
-> 只结束当前请求或当前会话 attempt，不修改账户死亡状态

单 Key 认证/传输异常
-> 只隔离该物理 Key / 运行态实例

可确认的账户级上游传输故障
-> SUSPECT -> OPEN，正常请求跳过，后台探针恢复

路由范围耗尽或预算到期
-> 当前请求 handoff；不把所有账户永久写死
```

## 必须验证

1. 同一会话坏输入并发失败时，正常账户仍可被其他会话使用。
2. 客户端取消、模型能力不匹配、上下文/协议语义错误不得累计账户传输失败或推进 `OPEN`。
3. 多 Key 账户按运行态 Key 隔离；一个 Key 失败不能杀死同账户其他健康 Key。
4. 跨优先级只在路由策略允许且高优先级不可承接时发生；健康高优先级恢复后不得被“上次失败后的后续号”永久跳过。
5. 服务端 handoff 后，客户端下一次新请求重新执行当前路由、质量、速度和优先级选择，不继承上次请求的临时候选游标。
6. 原地重试只限仍可安全重试的当前 attempt；完成语义输出后不得跨账户拼接。
7. 全池不可用时等待受 `noAvailableAccountWaitTimeoutSeconds` / 墙钟预算约束，不能无限等待，也不能把暂时阻断写成永久死亡。
8. 上游 HTTP 状态码、错误 code/type/message 和普通 payload 字段不可信；未命中用户显式策略时不得驱动 Key、账户、代理或供应商共享死亡状态。
9. `normalRoutingConfig.firstByteDeadlineMs` 这类配置截止只产生请求级调度/慢样本事实，不是 transport failure；连接、读取和 lane hard timeout 仍保留为传输电路证据。
10. 图片、音频、文件/资源创建、后台任务、hosted tool 和其他副作用 POST 一旦派发后不得隐式重放；图片 in-flight 默认使用 600 秒首响应和 3600 秒未提交上限。
11. 父账户升级默认要求 10 分钟内至少 3 个当前 `OPEN` 的独立子 scope，阈值可配置但不得低于 3；父级关闭使用可配置的通用协议成功证据阈值（当前默认 3），不等待所有肇事子 scope 再获流量，且不得清理仍 `OPEN/RECOVERING` 的子 incident。父子 incident 必须可持久化和冷重建，父 incident 最多携带 64 个恢复子 scope。

## 通过证据

- 账户状态、Key 运行态、质量失败归因、客户端响应和上游命中序列必须同时可断言。
- 至少有两会话、两优先级、一个多 Key 账户和一个“坏会话 + 健康会话”并发场景。
- Mock 场景通过后，真实 Redis/真实账户只做经授权的最小探针，不执行异常风暴。

## 已确认选择语义

- 同一坏会话或相同请求体的传输失败只是一份失败证据；它可以让账户作用域进入 `SUSPECT`，但不能再次使用自己取得的 confirmation 把账户推进到 `OPEN`。不同会话均失败时仍可确认真实账户故障。
- 新 HTTP 请求没有“上次在 2 失败所以下次固定从 3 开始”的游标。每次都从当前候选重新计算：业务/模型优先级、账户电路和运行时抑制、速度降级、上游桶、IP / Codex turn 避让、容量和热质量依次参与；1 已恢复且重新成为最优时回到 1，仍被抑制或降级时选择当前最优的 3。
- 普通质量/成本路由不允许热质量越过业务优先级层；`speed_first` 在高优先级账户已确认慢时允许跨到低优先级健康账户，恢复探针成功后重新回到高优先级账户。
- 安全文本推理端点完整非 `2xx` 在语义提交前只按 `response.ok` 作为 opaque 请求级失败：同账户当前可执行 Key 按池顺序唯一耗尽，再切后续账户/分组；跨账户相同物理凭据只请求一次，整个请求最多 64 次真实上游 attempt。真实池穷尽、64 次安全截断和墙钟截断必须区分，均不得写成 Key 或账户死亡。
- 用户显式策略只有精确命中并选择 `retry_next` 时才授权本次重放；其他状态副作用动作不等于重放授权。图片、音频、文件/资源创建、后台任务、hosted tool 和其他副作用 POST 一旦派发后仍保持 at-most-once。
- 普通路由配置首字截止只影响当前请求的候选推进或 `latency_degraded` 慢样本；不得上报账户 transport failure、推进 `SUSPECT/OPEN`、写 Key 失败或投递恢复副作用。只有 lane hard timeout、建连失败和真实读取中断保留传输失败语义。
- 父账户升级只统计窗口内当前 `OPEN` 的独立 `accountRuntimeKey + protocolProfile + requestLane + modelBucket` scope，默认阈值 3、窗口 600000ms；`SUSPECT` unknown 不开不关电路，按渐进退避和 jitter 重新入 due 队列。父级达到可配置的通用协议成功证据阈值（当前默认 3）即可关闭，不要求所有肇事子 scope 重新获得流量；父关闭只清理本代父级升级证据，仍 `OPEN/RECOVERING` 的子 scope 保持独立。父子 incident 按 generation/revision 持久化并参与冷重建，父级恢复子 scope 集合上限为 64。
- 全池硬不可用立即 handoff；可恢复不可用只等待到 `min(noAvailableAccountWaitTimeoutSeconds, RouteCoordinationBudget, 墙钟减最终响应预留)`，任何一项到期都结束等待。
