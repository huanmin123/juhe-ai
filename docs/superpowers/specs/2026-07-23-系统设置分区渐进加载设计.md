# 系统设置分区渐进加载设计

## 1. 背景与现状

系统设置页当前挂载后并行请求完整系统设置和品牌设置。Node 的 `GET /settings` 会读取、校验并返回 `systemSettingKeys` 中全部运行时字段，而 Vue 页面实际只展示其中一部分；保存时页面又从一个带默认值的完整表单构造 PATCH。这样既让不可见的重设置阻塞首屏，也使后续分区加载一旦直接套用现有表单，存在“尚未加载的字段被本地默认值覆盖”的风险。

内部网关、worker、统计和清理任务依赖完整 `getSettingsAsync()` 快照。本设计只拆分管理页面读写契约，不缩窄、不延迟、不改变内部 runtime 完整 settings 契约。

## 2. 目标

- 管理页面按固定 section key 读取和更新设置，每个 section 只访问白名单字段。
- 品牌和高频网关设置先加载并可交互，其余区块进入视口或用户展开时再加载。
- 未加载字段不进入表单 payload、校验、reset 或 PATCH，任何本地默认值都不能覆盖数据库事实。
- PATCH 只返回当前 section 的最新值，不再返回完整系统设置快照。
- section 读缓存、内部完整 settings 缓存和网关运行时缓存采用明确的写后失效规则。
- SQLite 同步/read worker、PostgreSQL 和 Vue 的权限、字段、错误与竞态语义一致。

## 3. 范围与非目标

本批只修改 Node 后端、Vue 前端、专项测试和后续权威文档；不修改 `backend-go/`，不提交、不推送、不部署、不触碰生产。

本批不修改：

- `system_settings`、`global_settings` schema、默认种子或字段校验范围；
- 内部 `getSettings()` / `getSettingsAsync()` 返回全部 `systemSettingKeys` 的契约；
- 网关、worker、统计、清理、限流和调度读取设置的时机或语义；
- 公共品牌接口 `/settings/public` 及登录页品牌读取；
- 当前页面未展示的运行时字段。未展示字段继续由内部完整设置契约持有，不因为本批自动暴露到管理 UI。

## 4. Section 目录与字段白名单

Node 维护唯一、不可由请求扩展的 `managementSettingsSectionCatalog`。route、repository、worker、DTO、前端类型和测试都从同一语义目录派生；请求只能传 section key，不能传任意字段名数组。

| section key | 存储 | 字段 | 加载时机 |
| --- | --- | --- | --- |
| `brand` | `global_settings` | `appName`、`appIcon` | 首屏立即加载 |
| `gateway-core` | `system_settings` | `gatewayTextRawBodyLimitMegabytes`、`defaultTemporaryUnschedulableMinutes`、`temporaryUnschedulableRetryIntervalSeconds`、`temporaryUnschedulableRetryAttempts`、`textFirstResponseTimeoutSeconds`、`textStreamIdleTimeoutSeconds`、`textUncommittedAttemptMaxLifetimeSeconds`、`imageFirstResponseTimeoutSeconds`、`imageStreamIdleTimeoutSeconds`、`imageUncommittedAttemptMaxLifetimeSeconds`、`noAvailableAccountWaitTimeoutSeconds` | 首屏立即加载 |
| `account-health` | `system_settings` | `accountHealthCheckIntervalHours`、`accountHealthCheckJitterMinutes`、`accountHealthCheckBatchSize`、`accountHealthCheckFailureThreshold` | 进入视口或展开时加载 |
| `api-rate-limit` | `system_settings` | 六个 `systemApiRateLimit*` 字段 | 进入视口或展开时加载 |
| `account-test` | `system_settings` | `accountTestTaskConcurrency` | 进入视口或展开时加载 |
| `cooldown-retest` | `system_settings` | `cooldownAccountRetestMaxBackoffHours` | 进入视口或展开时加载 |
| `data-retention` | `system_settings` | `usageRecordRetentionDays`、`runtimeLogIndexRetentionDays`、`publicApiLogRetentionDays` | 进入视口或展开时加载 |

`gateway-core` 可以继续按现有页面视觉分成“网关请求体限制”“账户调度默认值”“请求等待与流式中断”三个区块，但共享一次高频 section 读取。`streamFailureThresholdCount`、`streamFailureThresholdWindowMinutes` 以及其他未展示的 runtime 字段不在任何管理 section 中；它们不能由默认表单值被顺带写回。

新增可见字段时必须先把字段加入一个且仅一个 section、补齐校验/默认/权限/测试并更新文档，禁止临时允许任意 key。

## 5. HTTP 契约

新增 admin-only 路由：

- `GET /__aisys__/api/settings/sections/:sectionKey`
- `PATCH /__aisys__/api/settings/sections/:sectionKey`

静态 `/global`、`/public` 等路由必须先于参数路由注册，避免被 section 捕获。非法或未知 section key 返回 400；普通用户返回 403；匿名沿用统一认证错误。

响应统一为：

```ts
interface ManagementSettingsSectionResult<K extends ManagementSettingsSectionKey> {
  sectionKey: K
  values: ManagementSettingsSectionValues[K]
}
```

GET 只返回该 section 的精确字段。PATCH body 是普通 JSON 对象，要求至少一个字段；所有 key 必须属于 URL section 白名单，嵌套对象、数组、原型污染键、未知字段和跨 section 字段均返回 400。只校验和写入实际出现的字段，不用缺失字段的默认值补齐 payload。

PATCH 成功后返回该 section 的完整最新 `values`，便于刷新 baseline，但不得返回其他 section 或完整 runtime settings。操作日志只记录本次 body 中的安全字段差异；品牌仍使用品牌字段标签，系统设置沿用现有安全 diff 和全局可见审计语义。

现有完整 `GET/PATCH /settings` 暂时保留为兼容入口，但 Vue 设置页不得继续调用；它们不作为新代码依赖。内部 runtime 继续直接调用 repository 的完整 settings API，不经管理 section 路由。兼容入口的删除另行确认。

## 6. Node 存储、事务与运行时不变量

- 新增 `getManagementSettingsSectionAsync(sectionKey)`，在 repository 内根据白名单生成固定 `IN` 查询；禁止先调用完整 `getSettingsAsync()` 再裁字段作为冷缓存实现。
- `brand` 只查询 `global_settings` 两行；系统 section 只查询对应 `system_account_id = 'sys_admin'` 和白名单 key。缺少任一应存在字段时明确失败，不用代码默认值伪装数据库完整。
- 新增 `updateManagementSettingsSectionAsync(sectionKey, input)`，只规范化实际出现且属于该 section 的 key，在一个事务中 upsert；查询参数和 SQL 占位符必须按 SQLite/PostgreSQL dialect 正确生成。
- SQLite read worker 接收 section key，并在 worker 内再次通过固定目录解析为字段列表；不得从 IPC 接收任意 keys。同步 SQLite、read worker 和 PostgreSQL 返回字段、排序、缺失字段错误和 validator 行为逐项一致。
- 写入后清除目标 section 缓存，同时清除完整 `settings:system` 或 `settings:global` 本地/共享缓存。系统 section 写入继续执行 `clearUsageStatsTimezoneCache()` 的现有广域失效和 `notifyGatewayRuntimeCacheInvalidation('settings_updated')`，不得因当前 section 未含时区而分叉出第二套易漂移协议。
- 完整 `getSettingsAsync()`、同步 `getSettings()`、shared cache schema 校验和全部内部调用方保持全字段、全校验、原子快照语义；不能改成等待页面逐 section 拼装。

## 7. 缓存与失效

服务端 section 缓存按 `sectionKey` 独立，内存和 Redis shared key 均含契约版本；`brand` 与 system sections 分属对应 settings domain。section 冷读只查自身字段，不能为了命中旧完整缓存而使冷路径退回全量查询。

任一 section PATCH 成功后：

1. 清除该 section 的本地/共享缓存；
2. 清除对应完整 settings 本地/共享缓存；
3. 发布现有 settings/page-data domain reset 或 revision；
4. 系统 section 继续通知网关 runtime cache 失效；品牌 section 继续使应用品牌缓存失效。

不受影响 section 可以保留，但若现有 domain 只能广域 reset，则允许全部 section 变 stale，优先保证正确性。不能只清页面 section 缓存而让网关或 worker 继续读旧完整快照。

Vue 缓存 key 至少包含接口契约版本、section key、viewer ID、role 和 auth revision。登出、重新登录、角色变化或 settings domain revision 变化后旧缓存不可直接提交。失败不写成功缓存，也不永久保留 rejected Promise。

## 8. Vue 页面状态与交互

每个 section 独立维护 `unloaded/loading/ready/error/saving`、`values`、`baseline`、`dirtyKeys` 和 generation。页面 mounted 只请求 `brand` 与 `gateway-core`；其他 section 由 `IntersectionObserver` 的接近视口阈值或用户主动展开触发，同一身份/section 的相同请求可 singleflight。

未加载区块显示稳定骨架或折叠摘要，不渲染可编辑默认值。默认值只用于用户在已经成功加载的 section 内点击“恢复默认配置”；reset 只修改该 section 白名单字段，并显式标记相应 dirty keys。

保存改为 section 级：

- 只提交该 section 已加载且 dirty 的字段；无 dirty 字段不发请求。
- build payload 必须从 `dirtyKeys` 与当前 values 取交集，禁止从全局 `defaultSystemSettings` 或完整 `SystemForm` 构造。
- 保存成功用响应 values 更新当前 section baseline，只清除本次提交的 dirty keys；其他 section 状态不变。
- section 未加载、正在加载或加载失败时禁用保存；失败可独立重试，不阻塞已加载 section。
- domain revision 到达时，clean section 可后台重取；dirty section 只标记 stale 并提示刷新/先保存，不得用远端响应覆盖本地编辑。

每次加载/重试/缓存命中都推进 consumer generation。迟到成功或失败只有在 section key、身份签名、auth revision、generation 和页面仍存活都匹配时才可提交。覆盖快速展开/收起、滚动触发后离开、重试、保存中再次编辑、domain reset、A→B→A 身份切换和卸载；旧响应不能清除新 loading、覆盖新值或弹出过期错误。

## 9. 权限与安全

- 所有管理 section GET/PATCH 保持 `requireAdmin`；section key 不能改变权限 scope。
- route、service、repository 和 worker 各自只接受目录定义的 section key，任何客户端字段列表都不是授权来源。
- PATCH 只允许普通对象和本 section 标量字段，拒绝 `__proto__`、`constructor`、`prototype` 等危险 key。
- 响应不包含 secret、凭据、内部未展示设置、其他 section 值或完整 runtime 快照。
- operation log、错误响应和日志不得输出品牌 Data URL 全文、数据库内容或其他敏感设置值；品牌图标沿用现有大小与格式校验。

## 10. 测试与验收

### 10.1 Node

- Catalog/HTTP：所有合法 section 精确字段；未知、空、大小写变体、超长 key 为 400；普通用户 403。
- PATCH：单字段、整 section、空对象、未知/跨 section/危险 key、类型与范围错误；只改提交字段，其他 section 与内部未展示字段保持原值。
- Query guard：section 冷读使用精确 `IN` 投影，不调用完整 settings loader；无 `SELECT *`、任意 keys 或逐字段 N+1。
- Cache：section 与完整缓存的命中、写后失效、Redis/local 等价、品牌/page-data/runtime invalidation；失败事务不清成功缓存或发布成功事件。
- SQLite 同步/read worker 逐字段一致；worker 拒绝未知 key 且不接受任意字段数组。
- 真实 PostgreSQL smoke 覆盖每个 section、部分 PATCH、未加载字段保持、事务回滚、INTEGER/JSON 解析和缓存失效；SKIP 不计通过。
- 现有完整 settings repository、网关 timeout/rate-limit、worker、统计时区、保留清理和品牌回归继续通过，证明内部完整契约未被分区化。

### 10.2 前端

- 首屏只发 `brand` 与 `gateway-core`，未进入视口/未展开 section 请求数为 0。
- 每个懒 section 首次触发只请求一次；重复进出、相同并发 singleflight，失败后可重试。
- 未加载 section 不出现可编辑默认值；保存任意已加载 section 的 payload 不含未加载或其他 section 字段。
- reset、部分编辑、保存中再次编辑、独立错误、缓存命中、revision reset、身份变化和卸载竞态均正确。
- 品牌保存后立即更新应用品牌；系统 section 保存后不要求重拉完整 settings。
- 浏览器 Network 验证桌面/移动首屏、滚动/展开、保存和失败重试；Browser/Playwright 不可用时明确记录环境限制。

### 10.3 门禁

- Node/Vue 专项回归、后端 typecheck、可运行范围内的前端 typecheck/build、`git diff --check`。
- 真实 PostgreSQL、SQLite worker 和现有 runtime settings 回归形成独立证据。
- 至少两名只读 Agent 分别复核 whitelist/权限/缓存与前端未加载字段/竞态，并交叉质疑；高严重度问题全部闭合。

## 11. 完成标准

- 设置页首屏只读取品牌和高频网关 section，其他 section 按视口或展开加载。
- 每个管理 GET/PATCH 都受固定 section 白名单约束，HTTP、SQL 和 worker 均不读取/接受任意字段集合。
- 任一保存请求都不能包含未加载字段，默认值无法覆盖数据库中的其他 section 或内部 runtime 设置。
- PATCH 不返回完整 settings，写后同时失效 section、完整 settings 和运行时缓存。
- 内部完整 settings 契约、SQLite worker、真实 PostgreSQL、前端竞态/网络矩阵和既有 runtime 回归全部闭合后，才可将专项标记完成。
