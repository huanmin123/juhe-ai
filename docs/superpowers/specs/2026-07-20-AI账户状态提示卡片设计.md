# AI 账户状态提示卡片设计

## 1. 背景与目标

当前 AI 账户状态提示把数据库状态、运行态缓存、主动健康检查、真实流量成功信号、冷却复测、质量统计、授权来源和内部调度计数拼在同一张提示卡片中。用户无法判断时间对应哪一种任务，也会把 `runtime.until`、`cooldownUntil` 或旧的 `nextHealthCheckAt` 误解为账户必然恢复时间。

本设计只解决一个用户问题：用户查看账户状态时，应能立即知道账户当前是否可用、最近一次与当前状态相关的检查发生在何时、下一次计划检查何时发生、失败原因是什么，以及用哪个 `traceId` 排查。

设计目标：

- 每张状态提示只展示当前主状态对应的一条用户时间线。
- 默认最多展示状态、最近检查、下次计划检查、原因和 `traceId` 五类信息，每类均可缺省。
- 探测、恢复、到期、额度重置和时间计划使用不同字段和文案，禁止混用。
- 后端选择当前主状态和对应事实，前端不再从多组底层字段自行拼接。
- 30 秒状态快照原子刷新状态提示所需的完整摘要，禁止新旧字段混合。
- 桌面表格和移动卡片复用同一展示摘要和文案。

## 2. 非目标

- 不改变账户状态机、探针调度、冷却退避、路由或授权规则。
- 不把账户质量统计、失败来源统计或内部调度算法搬到新的状态卡片。
- 不承诺后台任务在计划时间精确执行；所有未来检查时间均表示计划到期时间。
- 不为旧前端字段或旧接口结构保留兼容分支；当前列表和状态快照同步切换到新摘要。
- 不执行生产部署。

## 3. 用户信息原则

### 3.1 用户关心的信息

1. 当前是否可用。
2. 当前不可用或受限的直接原因。
3. 状态是否会由后台自动检查恢复。
4. 最近一次相关检查的时间和结果。
5. 下一次计划检查时间，或当前是否正在等待调度。
6. 失败对应的 `traceId`，便于复制和排查。
7. 无自动恢复时，用户需要采取的下一步动作。

### 3.2 默认隐藏的信息

以下信息不进入用户状态提示：

- “数据库状态仍为正常”和“当前网关进程缓存”。
- 观察窗口、generation、租约、半开机制和内部状态机阶段。
- 短窗口失败次数、来源 IP 数、API Key 数、事前探针次数和避让轮次。
- 最近健康成功信号、质量采样、质量刷新、首字延迟统计和路由排序说明。
- 探针并发门禁、重试预算、worker 角色和 Redis / memory 存储方式。
- 历史时间线中与当前主状态无关的检查、复测和授权来源信息。

这些事实仍可保留在日志、审计、使用记录和专门详情页面中，但不进入状态标签提示。

## 4. 状态按退出机制分组

状态提示不按数据库枚举或运行态实现分组，而按“状态如何退出”分组。

### 4.1 检查驱动

状态由后台检查结果推进或恢复，允许展示最近检查和下次计划检查：

- `active` 的周期健康检查。
- `pending_test` 的激活检查。
- `rate_limited`、`temporary_unavailable` 的恢复复测。
- `degraded`、`precheck_pending`、`precheck_failed` 的运行态恢复检查。
- `api_key_pool_unavailable` 的 Key 池复测。
- 授权来源的检查驱动状态，但仅在后端能提供来源账户摘要时展示来源时间线。

### 4.2 时间驱动但非检查

状态由明确时间边界解除，不能把时间叫作“下次检查”：

- 用户显式策略产生的 `local_suppressed`，显示“暂时避让至”。
- 账户可用性时间计划继续由账户列表独立的“时间计划”标签展示，不进入状态 tooltip，也不把计划写成健康检查时间。
- 账户或授权到期，显示“到期时间”。
- 额度耗尽且存在明确重置时间，显示“额度重置时间”。

### 4.3 动作驱动

状态需要用户、管理员或授权方操作，默认不显示检查时间：

- `disabled`、实例停调。
- 无自动恢复任务的 `error`。
- 权限不足、未绑定分组。
- 授权暂停、失效、撤销、归还或来源删除。
- 已到期且必须续期的账户或授权。
- 额度耗尽且不存在明确重置时间。

### 4.4 进行中

`half_open` 表示一次恢复确认正在执行。提示只显示“正在确认”和当前原因，不显示租约截止或虚构的下次检查时间。

## 5. 统一提示卡片

### 5.1 信息顺序

状态标签本身作为标题，提示内容固定使用以下顺序：

1. `最近检查`：时间和结果，仅检查驱动状态展示。
2. `下次检查`：计划时间、等待调度或正在检查，仅存在权威任务事实时展示。
3. `原因`：失败或业务阻断时展示，最长两行，完整内容允许展开或复制。
4. `traceId`：仅存在对应失败事件时展示，提供复制操作。
5. `下一步`：仅动作驱动状态展示，例如“重新检查”“启用账户”“联系授权方”。

不在提示正文重复“当前状态：xxx”；标签已经表达状态。

### 5.2 时间文案

| 事实 | 用户文案 |
| --- | --- |
| 最近真实执行的检查 | `最近检查：2026/7/20 01:02:03 · 失败` |
| 未来已排程的检查资格时间 | `下次检查：2026/7/20 01:12:03` |
| 计划已到期但 worker 尚未完成 | `下次检查：等待调度（原计划 2026/7/20 01:12:03）` |
| 当前检查正在执行 | `下次检查：正在检查` |
| 尚未执行首次检查 | `最近检查：尚未检查` |
| 没有自动检查 | 不显示检查区，展示下一步动作 |
| 策略 TTL | `暂时避让至：...` |
| 时间计划 | `下次开启：...` |
| 生命周期 | `账户到期：...` 或 `授权到期：...` |
| 额度重置 | `额度重置：...` |

未来时间只能称为“计划检查”，不能称为“预计恢复”或“预计释放”。计划到期表示可被调度，不保证精确执行。

### 5.3 原因与 traceId

- 原因按 `HTTP 状态 + 错误码 + 简短上游消息` 组合，删除内部状态机前缀。
- 同一 `lastObservation` 中的 `attemptedAt`、结果、原因和 `traceId` 必须来自同一次检查事件。
- 成功结果不显示历史失败原因和历史 `traceId`。
- 没有当前事件 `traceId` 时保持为空，禁止用旧健康检查或其他状态的 `traceId` 补位。
- 后端为每次摘要保留 `observationId`，`lastObservation` 中的时间、结果、错误、原因和 `traceId` 必须来自同一 observation；`schedule.nextAttemptAt` 不属于 observation。没有完整 observation 时丢弃不完整的最近检查行，而不是跨来源拼接。
- `traceId` 使用等宽文本和复制按钮；不在卡片中直接跳转未授权的审计资源。

## 6. 逐状态展示矩阵

| 用户状态 | 最近检查 | 下次检查或时间 | 原因 / traceId | 下一步 |
| --- | --- | --- | --- | --- |
| 正常 / 可调度 | 最近周期健康检查；仅展示真实探针，不展示业务成功信号 | 下次计划健康检查 | 仅当当前主状态仍由该失败检查解释时显示原因和 traceId；正常状态不展示过期失败 | 无 |
| 待检查 | 最近激活检查；未执行显示“尚未检查” | 下次激活检查；未排到具体时间显示“等待调度” | 最近激活失败原因和 traceId | 可重新检查或按权限恢复 |
| 检查失败 | 最近激活检查及失败结果 | 下次计划激活检查 | 失败原因和 traceId | 可重新检查 |
| 限流中 | 最近恢复复测；尚未复测显示“尚未检查” | 仅存在真实复测队列时显示计划复测；逾期显示“等待调度” | 最近复测原因和 traceId | 仅在当前权限允许时显示手动恢复 |
| 临时不可调用 | 最近恢复复测；尚未复测显示“尚未检查” | 仅存在真实复测队列时显示计划复测；逾期显示“等待调度” | 最近复测原因和 traceId | 仅在当前权限允许时显示手动恢复 |
| 异常 | 仅当错误来源能绑定到真实检查事件时展示 | 仅当存在明确自动恢复任务时展示 | 当前错误原因和 last error traceId | 按错误类型显示修复配置、重新检查或人工恢复 |
| 调度降级 / 近期不稳定 | 只有后端提供真实运行态探针记录时展示 | 只有后端提供真实运行态排程时展示，否则省略 | 当前运行态原因和 traceId（有值才显示） | 仅在当前权限允许时显示手动恢复 |
| 正在确认 | 当前运行态确认记录（没有可靠时间则省略） | 显示“正在检查”，不显示租约截止时间 | 当前确认原因和 traceId（有值才显示） | 仅在当前权限允许时显示手动恢复 |
| 复核未通过 | 只有后端提供真实运行态探针记录时展示 | 只有后端提供真实运行态排程时展示，否则省略 | 最近确认失败原因和 traceId（有值才显示） | 仅在当前权限允许时显示手动恢复 |
| 暂时避让 | 不显示检查时间 | 仅在明确为用户策略 TTL 时显示“暂时避让至” | 用户策略原因 | 可手动恢复 |
| 正在恢复确认 | 当前检查开始时间可省略 | 显示“正在检查” | 当前原因 | 无 |
| Key 全部不可用 | 账户内所有 Key 不可用时，选择 `lastFailureAt` 最新的 Key 失败 observation | 所有不可用 Key 的最早真实 `nextProbeAt`；无任务则省略 | 最新 Key 失败的原因和 traceId | 检查账户 Key |
| 停用 / 停调 | 不显示 | 不显示 | 停用原因 | 启用账户 |
| 账户实例冷却 | 最近实例恢复复测；无复测显示“尚未检查” | 真实复测任务的计划时间；否则显示“冷却结束后等待调度” | 实例冷却原因和 traceId（有值才显示） | 仅在权限允许时显示恢复 |
| 账户到期 | 不显示 | 显示账户到期时间 | 到期原因 | 续期或修改到期时间 |
| 授权到期 | 不显示 | 显示授权到期时间 | 授权到期原因 | 联系授权方或重新授权 |
| 授权暂停 | 不显示 | 不显示 | 授权暂停原因 | 联系授权方或恢复授权 |
| 授权失效 / 不可用 | 不显示 | 不显示 | 授权失效原因 | 重新授权或联系授权方 |
| 授权额度用完 | 不显示 | 有真实 `resetAt` 时显示额度重置时间 | 额度原因 | 有 `resetAt` 时等待重置；否则联系授权方提升额度 |
| 未绑定分组 | 不显示 | 不显示 | 未绑定分组 | 绑定分组 |
| 权限不足 | 不显示 | 不显示 | 当前用户无使用权限 | 联系管理员 |
| 来源缺失 / 已删除 | 不显示 | 不显示 | 授权来源不存在 | 联系授权方 |
| 来源账户待检查 | 不显示来源检查时间（当前来源摘要不提供） | 不显示来源检查计划 | 来源阻断原因；不伪造来源 traceId | 等待授权方处理 |
| 来源账户异常 | 不显示来源检查时间 | 不显示来源检查计划 | 来源阻断原因；有来源 traceId 才显示 | 联系授权方 |
| 来源账户限流 / 临时不可用 / 冷却 | 不显示来源检查时间 | 仅来源后端明确提供复测计划时显示；否则显示来源冷却结束时间 | 来源阻断原因；有来源 traceId 才显示 | 联系授权方 |
| 来源账户停用 / 到期 / 停调 | 不显示 | 仅来源明确返回到期或计划转换时显示 | 来源业务阻断原因 | 联系授权方 |

### 6.1 有效状态到用户状态映射

后端必须覆盖当前 `AccountEffectiveAvailabilityStatus` 的全部值。下表中的“仅原因”表示不显示任何历史探测时间：

| 有效状态 | 用户展示状态 | 时间规则 |
| --- | --- | --- |
| `available` | 正常 | 健康检查摘要 |
| `permission_denied` | 权限不足 | 仅原因 |
| `authorization_expired` | 授权到期 | 授权到期时间 |
| `authorization_paused` | 授权暂停 | 仅原因 |
| `authorization_unavailable` | 授权失效 | 仅原因 |
| `authorization_quota_exceeded` | 授权额度用完 | 只有真实 `quotaResetAt` 才显示额度重置 |
| `source_deleted` | 来源已删除 | 仅原因 |
| `source_expired` | 来源已到期 | 来源到期时间（有值时） |
| `source_disabled` | 来源已停用 | 仅原因 |
| `source_pending_test` | 来源待检查 | 仅原因，不显示当前实例时间 |
| `source_error` | 来源异常 | 仅来源提供真实摘要时显示探测，否则仅原因 |
| `source_rate_limited` | 来源限流中 | 仅来源提供真实复测摘要时显示 |
| `source_temporary_unavailable` | 来源临时不可用 | 仅来源提供真实复测摘要时显示 |
| `source_cooldown` | 来源冷却中 | 来源冷却结束时间；不伪造复测 |
| `source_unschedulable` | 来源已停调 | 仅原因 |
| `instance_expired` | 账户到期 | 账户到期时间 |
| `instance_disabled` | 账户已停用 | 仅原因 |
| `instance_pending_test` | 账户待检查 | 激活检查摘要 |
| `instance_error` | 账户异常 | 按错误类型决定是否显示自动恢复摘要 |
| `instance_rate_limited` | 账户限流中 | 冷却复测摘要 |
| `instance_temporary_unavailable` | 账户临时不可用 | 冷却复测摘要 |
| `instance_cooldown` | 账户冷却中 | 真实复测任务摘要；无任务则仅显示冷却结束 |
| `instance_unschedulable` | 账户已停调 | 仅原因 |
| `binding_missing` | 未绑定分组 | 仅原因 |
| `api_key_pool_unavailable` | API Key 暂不可用 | Key 复测摘要（字段存在时） |
| `runtime_degraded` | 近期不稳定 | 运行探针摘要（字段存在时） |
| `runtime_local_suppressed` | 暂时避让 | 只有策略 TTL 明确时显示避让时间 |
| `runtime_half_open` | 正在确认 | 正在检查，不显示租约 |
| `runtime_precheck_pending` | 正在复核 | 运行探针摘要（字段存在时） |
| `runtime_precheck_failed` | 复核未通过 | 运行探针摘要（字段存在时） |

业务阻断原因使用 `availability.reason`，探针失败原因使用 `probe.reason`；业务阻断没有探针事件时不得生成或复用 `traceId`。

## 7. 后端展示契约

### 7.1 探测摘要

后端在账户完整列表和 30 秒状态快照中统一返回：

```ts
type AccountProbeKind =
  | 'health_check'
  | 'activation_check'
  | 'cooldown_retest'
  | 'runtime_probe'
  | 'api_key_retest'
  | 'source_account_probe'

type AccountProbeResult = 'success' | 'failed'
type AccountProbeScheduleState = 'scheduled' | 'due_waiting' | 'running' | 'none'

interface AccountProbeObservation {
  observationId: string
  attemptedAt: string
  result: AccountProbeResult
  httpStatus?: number
  errorCode?: string
  reason?: string
  traceId?: string
}

interface AccountProbeSchedule {
  state: AccountProbeScheduleState
  nextAttemptAt?: string
}

interface AccountProbeSummary {
  kind: AccountProbeKind
  lastObservation?: AccountProbeObservation
  schedule: AccountProbeSchedule
}

type AccountPresentationStatus =
  | 'available'
  | 'pending_check'
  | 'check_failed'
  | 'rate_limited'
  | 'temporarily_unavailable'
  | 'error'
  | 'degraded'
  | 'verifying'
  | 'verification_failed'
  | 'avoided'
  | 'key_pool_unavailable'
  | 'disabled'
  | 'expired'
  | 'authorization_blocked'
  | 'binding_missing'
  | 'permission_denied'
  | 'source_blocked'

type AccountPresentationAction =
  | 'none'
  | 'retry_check'
  | 'restore_account'
  | 'enable_account'
  | 'bind_group'
  | 'renew_authorization'
  | 'contact_authorizer'
  | 'contact_admin'
  | 'fix_configuration'
```

`lastObservation` 的时间、结果、原因和 `traceId` 必须来自同一次检查。`schedule` 是独立计划事实：真实业务成功可以顺延周期计划，但不能改写最近主动检查 observation。前端可以同时展示“最近实际检查”和“下次计划检查”，但不能把 observation 的旧错误绑定到新的计划事件。

现有持久事件的 `observationId` 不新增通用数据库字段，按 `kind + account/key identity + attemptedAt + traceId/error fingerprint` 确定性派生；运行态使用 `runtimeKey + generation + attemptCount`。缺少可稳定派生的最近事件时省略 `lastObservation`，不得伪造 ID。

### 7.2 可用性与生命周期摘要

探测摘要不承载业务到期、策略 TTL 或授权关系：

```ts
interface AccountAvailabilityPresentation {
  status: AccountPresentationStatus
  label: string
  reason?: string
  action?: AccountPresentationAction
  statusBoundary?: {
    at: string
    kind: 'policy_ttl_expiry' | 'quota_reset' | 'cooldown_expiry' | 'account_expired' | 'authorization_expired' | 'source_expired'
  }
  probe?: AccountProbeSummary
}

interface AccountLifecyclePresentation {
  accountExpiresAt?: string
  authorizationExpiresAt?: string
  quotaResetAt?: string
}
```

后端按现有 effective availability 优先级选择唯一主状态，再选择与该状态匹配的探测摘要。前端状态标签和状态 tooltip 只读取一个后端生成的 `AccountAvailabilityPresentation`；`statusBoundary` 是后端从 lifecycle 中为当前主状态选择的唯一业务时间，tooltip 禁止自行读取 `AccountLifecyclePresentation` 并追加第二条时间线。同一 status 的渲染规则只能选择 `probe` 或 `statusBoundary`；`instance_cooldown` 若存在真实复测任务选择 probe，否则选择 `cooldown_expiry`。若 presentation 没有 probe，则前端不能从 `AccountSummary` 的旧字段回退拼接。

### 7.3 运行态扩展

现有 `AccountRuntimeAvailability` 的 `since` 和 `until` 不具备统一用户语义。运行态必须增加独立字段：

```ts
interface AccountRuntimeProbePresentation {
  lastObservation?: AccountProbeObservation
  schedule: AccountProbeSchedule
  recoveryAt?: string
  recoveryAtKind?: 'policy_ttl_expiry'
}
```

- `precheck_pending` 的 memory 和 Redis 快照必须使用同一 `nextProbeAt` 语义。
- `half_open` 的租约截止不得写入 `nextProbeAt` 或 `recoveryAt`。
- 只有用户显式策略 TTL 才能输出 `policy_ttl_expiry`。
- 运行态探针的执行结果需要携带并保存对应 `traceId`；当前后端无法提供时只展示状态和原因，不从其他健康事件补位。

### 7.4 状态快照一致性

`AccountStatusSnapshotItem` 必须包含完整的 presentation 摘要。列表首次加载和后续 30 秒快照使用同一构造器和同一字段投影；前端合并时整体替换 presentation 对象，禁止逐个合并底层时间字段。快照继续返回 `generatedAt`，前端复用现有 request sequence、列表 revision 和 scope 身份门禁拒绝旧响应；不引入无法比较先后的事实 hash。

快照必须满足：

- 状态、最近检查、下次检查、原因和 `traceId` 来自同一份已组装摘要；跨数据库和运行态无法做到事务级一致时，响应以 `generatedAt` 的组装时刻为界，不宣称更强的一致性。
- 已清空字段使用明确缺省覆盖旧值，不能保留首次列表的陈旧值。
- SQLite 和 PostgreSQL 使用相同的投影语义。
- Redis / memory 运行态不可用时不伪造运行探针时间。
- 任务取消、队列丢失、进程重启且尚未重建 due 任务时，`scheduleState = 'none'`，清空 `nextAttemptAt`；due 但尚未执行时才使用 `due_waiting`。

## 8. 前端组件边界

- `AccountStatusTag` 继续作为桌面和移动端统一入口。
- 新增纯 formatter，将 presentation 摘要转换为结构化行，不再返回拼接了所有机制的字符串数组。
- 状态卡片限制宽度，原因最多两行；超出后提供展开，不允许撑宽表格或遮挡相邻内容。
- 时间、原因和 `traceId` 均允许选择；`traceId` 提供复制按钮和中文提示。
- 用户动作使用现有菜单能力，不在 tooltip 中加入长篇操作说明。
- 质量、优先级和备用标识保留独立入口，不再追加到状态 tooltip。

## 9. 错误与缺失数据处理

- presentation 摘要缺失时只展示状态和可靠原因，不回退到旧底层时间字段。
- `nextAttemptAt` 已过期且任务未完成时显示 `due_waiting`，不继续把旧时间当未来时间。
- `traceId` 缺失是合法状态，不显示占位符，也不借用其他事件的 `traceId`。
- error 无法确定探测来源时只展示原因、traceId 和下一步动作。
- 授权来源缺少来源探测摘要时只展示来源阻断原因，不显示当前实例的探测时间。

## 10. 验证范围

### 10.1 后端契约

- 完整列表和状态快照输出相同 presentation 摘要。
- 快照更新下次检查、traceId、冷却复测和运行态探测字段，并能清除旧值。
- Key 运行态持久记录补充 `last_trace_id`；`db-service-types`、网关 Key 失败和后台 Key 复测都传递探针 `traceId`，成功或状态清理时同步清理陈旧 trace。账户级 Key 池摘要只在 `last_failure_at IS NOT NULL` 的记录中按 `last_failure_at DESC, key_index ASC, key_fingerprint ASC` 选择最近失败 observation，只在 `next_probe_at IS NOT NULL` 的不可用 Key 中选择最早下次计划；两类候选为空时分别省略 observation 或 schedule 时间。
- active、pending_test、temporary_unavailable、rate_limited、error、disabled 和所有 effective availability 阻断选择正确摘要。
- SQLite 与 PostgreSQL 投影行为一致。
- memory 与 Redis 运行态的最近探针、下次探针和 TTL 语义一致。

### 10.2 前端 formatter

- 每个状态只显示当前主时间线。
- 不再出现“数据库状态”“进程缓存”“预计释放”“健康成功信号”“失败次数”“来源 IP”“API Key 数”“事前探针”等文案。
- 成功不显示旧原因和旧 traceId；失败显示同事件原因和 traceId。
- API Key 池只在补齐持久 traceId 后显示 Key 失败 traceId；字段缺失时只显示时间和原因，不伪造 traceId。
- disabled、授权失效、权限不足等动作型状态不显示旧健康检查时间。
- 计划逾期显示等待调度，不显示为未来时间。

### 10.3 页面与构建

- 桌面表格和移动卡片状态提示一致。
- 中文文案、复制交互、长原因换行和窄屏布局通过浏览器检查。
- 前后端类型检查、专项回归、构建通过。

## 11. 发布与回退

本变更不修改状态机，但会为 Key 运行态补充当前 schema 所需的 `last_trace_id` 字段，并同步 SQLite / PostgreSQL 当前结构与回归；不在运行时代码中加入旧结构兼容或自动迁移。上线前需完成 SQLite、PostgreSQL、memory 和 Redis 两种运行态验证。发生问题时按提交回退 presentation 契约和 formatter；不通过兼容分支并行保留新旧卡片。生产部署必须等待用户另行通知。
