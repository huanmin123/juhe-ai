# 账户状态刷新与测试弹窗生命周期设计

## 1. 背景与目标

AI 账户列表当前会在页面可见期间按约 30 秒周期请求运行状态快照。该机制持续产生列表外的后台请求，但对用户可感知体验提升有限。本次取消这条前端自动刷新链路，保留正常列表加载和用户主动刷新，不改变账户状态的服务端计算语义。

账户人工测试当前还有三项需要收口：

1. 测试任务状态每秒轮询，请求频率偏高；
2. 测试会话每 2 秒发送一次心跳，请求频率偏高；
3. 遮罩、右上角关闭按钮或 Esc 关闭弹窗时只脱离当前视图，后端测试仍可能继续运行。

另外，测试弹窗的默认“测试模型”和“测试请求形态”属于账户自身配置，应直接来自账户列表项的 `healthCheckModel` 与 `healthCheckEndpointMode`。Node 列表与现有前端初始化已经采用该语义；Go 管理账户列表尚未完整输出这两个字段，本次补齐迁移链路，保证打开弹窗不为默认值额外请求测试选项接口。

## 2. 已确认决策

- 取消账户运行状态快照的前端定时调度，不删除后端状态快照接口。
- 测试任务状态轮询间隔由 `1s` 调整为 `3s`。
- 测试会话心跳间隔由 `2s` 调整为 `5s`。
- 所有明确关闭测试弹窗的入口统一终止当前测试，而不是让任务在后台继续。
- 测试默认模型和请求形态直接使用账户列表字段；候选模型仍在用户展开模型下拉框时按需加载。
- 本次只开发和验证，不执行生产部署或上线操作。

心跳采用 `5s` 是因为后端会话空闲完成阈值当前为 `15s`。该间隔将心跳请求频率降为原来的 40%，同时保留约三次心跳余量，避免 `10s` 间隔在浏览器后台限频或短时网络抖动下过于接近失活边界。

## 3. 范围与非目标

### 3.1 本次范围

- 账户管理页和个人账户页共用的状态快照自动轮询生命周期。
- 账户测试弹窗共用的任务轮询、会话心跳和关闭行为。
- Node / Go 管理账户列表对测试默认字段的契约一致性。
- 对应前端回归、Go service/store/HTTP 契约测试和构建验证。
- 当前功能文档、前端/后端架构说明及需求计划的事实同步。

### 3.2 非目标

- 不删除或重构后端账户状态快照接口、状态 presentation 构造器和运行态存储。
- 不取消账户列表首次加载、筛选、分页、用户主动刷新及其他显式数据请求。
- 不预加载完整候选模型、模型能力或请求形态数组。
- 不改变测试任务的总等待预算、后端取消协议、恢复会话 TTL 或并发策略。
- 不把页面关闭行为扩展为生产 worker、自动健康检查或批量测试的全局取消规则。
- 不读取、修改或清理生产数据，不执行部署与切流。

## 4. 账户状态快照自动刷新

### 4.1 前端生命周期

从账户列表数据组合器中移除状态快照轮询器的创建、启动、暂停、恢复和销毁连接。页面挂载后只执行现有完整列表加载；筛选、分页和主动刷新继续走现有列表请求。

移除专用于自动轮询的前端 helper 及其旧行为回归，新增防回退断言，证明账户列表生命周期不会：

- 创建状态快照定时器；
- 在页面可见期间递归调用状态快照 API；
- 因 `visibilitychange` 再次启动该轮询。

### 4.2 兼容边界

后端管理视图和个人视图的状态快照路由暂时保留，前端 API client 也可以在仍有其他显式调用方时保留。实施时必须通过 `rg` 确认调用方；若自动轮询是唯一调用方，则可以删除无用的前端 client 包装，但不删除服务端接口。

账户状态卡片继续消费完整列表响应中的状态摘要。本次不改变字段含义，也不通过本地定时推演伪造运行态更新。

## 5. 测试任务轮询与心跳

### 5.1 任务状态轮询

将单次任务状态查询之间的等待常量固定为 `3000ms`。首次创建任务后的查询时序、完成/失败判断、总等待预算和超时结果保持现状；只降低未完成任务的重复查询频率。

轮询停止条件继续包括：

- 任务完成或失败；
- 用户主动停止；
- 用户关闭测试弹窗；
- 当前视图 token 失效或请求被中止；
- 达到既有总等待预算。

### 5.2 会话心跳

将运行中测试会话的心跳周期固定为 `5000ms`。心跳只在当前测试仍归属于已打开视图、未停止且后端任务未结束时发送。

关闭弹窗或停止测试时必须先停止后续心跳调度，再终止本地轮询并请求后端取消，避免关闭后出现迟到心跳延长服务端任务生命周期。

## 6. 弹窗关闭语义

### 6.1 统一关闭入口

Ant Design Vue 弹窗的遮罩点击、右上角关闭按钮和 Esc 都汇入现有 `cancel/close` 事件。页面显式关闭按钮也必须使用同一关闭函数，不得存在只隐藏弹窗的旁路。

当存在运行中测试时，关闭函数按以下顺序处理：

1. 标记当前 run 已停止，使迟到响应无法继续更新 UI；
2. 清除该账户持久化的测试运行会话；
3. 停止会话心跳；
4. 中止本地轮询或流读取；
5. 调用现有后端取消接口；
6. 清理测试模型临时状态并关闭弹窗。

后端取消请求允许异步完成，但必须在清空活动 run 引用前捕获任务标识。取消失败不得恢复已关闭弹窗或重新启动心跳；现有错误记录策略负责保留诊断，用户下次打开时不得把已明确关闭的会话恢复为运行中。

### 6.2 与视图卸载的边界

本次只把“用户明确关闭弹窗”定义为终止。组件卸载、页面刷新等既有恢复会话边界暂不扩大，以免把短暂导航误判成用户要求取消。若现有卸载逻辑与弹窗关闭共用函数，实施时需拆清意图，确保关闭走取消，非关闭卸载仍遵守既有恢复策略。

## 7. 测试默认值列表契约

### 7.1 前端行为

打开测试弹窗时立即使用当前 `AccountSummary`：

- `healthCheckModel` 初始化“测试模型”；
- `healthCheckEndpointMode` 初始化“测试请求形态”。

弹窗首开不得调用测试 options 接口来取得默认值。只有用户展开模型选择器时才加载候选模型；用户改选模型后，所需能力信息继续按现有专用接口按需获取。

### 7.2 Node 契约

Node 的 `AccountSummary` 已包含两个字段，账户列表投影必须继续保留它们。实施以回归断言防止 sanitizer 或 DTO 裁剪误删，不重复增加查询。

### 7.3 Go 契约

Go 管理账户列表和个人账户列表共用的纵向链路补齐：

- PostgreSQL sqlc 列表查询显式选择 `health_check_model` 和 `health_check_endpoint_mode`；
- 重新生成 sqlc 代码，不手工维持生成文件漂移；
- store port row 和 PostgreSQL adapter 映射增加两个字段；
- management account list service item 输出 `healthCheckModel` 和 `healthCheckEndpointMode`；
- 管理视图与个人视图 HTTP 响应字段保持一致。

这两个字段已存在于账户记录，随当前列表行一起返回，不引入新的数据库往返、额外 options 请求或模型目录联表。字段为空或非法时继续遵循现有账户持久化约束，不在前端静默推断替代值。

## 8. 并发、错误与性能边界

- 关闭弹窗和手动停止可能并发触发，取消流程必须保持幂等；同一 run 不重复恢复、重复写 UI 或重启心跳。
- 后端任务恰好在关闭时完成属于合法竞态；关闭后的完成响应不得重新打开弹窗或写入已失效视图。
- 状态快照轮询移除后，每个持续打开的账户页不再产生约每 30 秒一次的状态请求。
- 任务轮询从每秒最多一次降为每 3 秒最多一次；心跳从每 2 秒一次降为每 5 秒一次。
- 账户列表增加两个已有标量字段，只增加固定小行宽，不增加查询次数；相比弹窗首开额外请求，整体延迟和服务端请求数更低。

## 9. 测试与验收

### 9.1 前端自动化

- 先修改回归测试使其对旧实现失败，再实现业务改动。
- 断言账户列表不再导入、创建或启动状态快照轮询器。
- 断言任务轮询常量为 `3000ms`，完成、取消和超时边界不被改变。
- 断言心跳常量为 `5000ms`，关闭后定时器停止。
- 断言遮罩、右上角关闭、Esc 和页面关闭入口最终走同一取消语义。
- 断言关闭运行中测试会调用后端取消、清理本地会话且迟到响应不能恢复 UI。
- 断言管理页和个人页打开测试弹窗时 options 调用次数为 0，默认值来自列表项；展开模型下拉后才发起候选请求。

### 9.2 Go 自动化

- service 测试断言两个健康检查字段从 store row 映射到 JSON item。
- store SQL 契约测试断言列表查询显式选择并映射两个字段。
- HTTP 测试同时覆盖管理员和个人账户列表字段。
- 运行 sqlc 生成检查，保证查询与生成代码一致。

### 9.3 整体验证

- 运行受影响的前端专项回归、类型检查、lint 和生产构建。
- 运行 Go 定向测试，并在资源允许时运行 `go test ./...`、`go vet ./...`。
- 运行 Node 账户列表契约相关测试，证明原有字段未被裁剪。
- 运行 `git diff --check` 并复查定时器、取消竞态、重复请求、文档对齐和无关改动。
- 若真实浏览器环境可用，验证运行中测试分别通过遮罩、右上角关闭和 Esc 关闭后，网络面板不再出现轮询/心跳，取消请求已发出。

## 10. 开发、整合与回退

开发在基于最新 `master` 创建的独立 worktree 和 `codex/account-refresh-lifecycle-20260721` 分支完成。设计、计划、测试门禁和实现按可审查提交分阶段落地；实现期间在关键阶段获取并合并最新 `master`，最终验证前再次同步。

全部验证通过后，将功能分支合并到本地 `master` 并推送远程。原工作区若存在用户未提交修改，整合时必须保留并隔离这些修改，不得覆盖。生产部署、服务重启、数据库清理和上线验证均不属于本次自动执行范围，等待用户另行通知。

回退优先按子增量处理：可恢复前端轮询常量或关闭生命周期代码，但不得通过删除账户字段、伪造默认值或放弃后端取消来掩盖问题。Go 字段补齐不涉及 schema 迁移，回退只影响查询/DTO 契约。
