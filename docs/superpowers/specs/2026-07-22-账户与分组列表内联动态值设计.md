# 账户与分组列表内联动态值设计

## 目标

账户和分组列表在一次 HTTP 响应内返回当前页所需动态字段，前端不再为列表补发 `status-snapshot` 请求。

## 数据流

- 账户列表：基础分页查询后，对当前页账户批量读取累计/当日用量和 API Key 运行态；实时并发与运行可用性由同一个列表请求内的 runtime snapshot 批量补齐。授权账户的 API Key 与并发使用来源账户事实 ID。
- 分组列表：对当前页分组批量读取成员账户 ID、当日用量和 Redis/server 并发槽，在服务端求和后写入 `accountStats`。
- `status-snapshot` 路由保留给显式批量查询和兼容调用，不由列表页面自动调用。

## 可用性与降级

实时并发读取失败时，列表仍返回 SQL/统计动态字段，并用列表级 `runtimeSnapshot` 和行级 `currentConcurrencyAvailable=false` 标记未知值。客户端不得将占位 `0` 当作可信并发。

## 性能约束

- 只对当前页 ID 集合执行固定数量的批量读取，不产生逐行 SQL 或逐行 Redis 调用。
- 成员账户 ID 在内存中去重后一次读取并发；并发读取不得因 100 个 ID 截断而漏算大分组。
- 账户和分组的独立批量读取并行执行；不恢复轮询、焦点刷新或二次 HTTP 请求。
- 详情、凭据、模型映射和 API Key 明细继续排除在列表投影之外。
