# 代理选项与日志列表渐进加载设计

## 1. 背景与目标

本设计承接《全站页面 API 按需加载审计报告（2026-07-20）》的剩余 P1 项，收口以下三个相互独立但可共同验收的页面链路：

1. AI 账户列表不再在首屏、翻页或普通刷新时预取代理 options；代理候选只在编辑或批量编辑的代理下拉首次展开、搜索或需要补齐已选项时请求。
2. 操作日志列表使用专用窄 DTO 和存储投影；详情继续按 ID 加载完整诊断字段。
3. 公开 API 日志默认分页窗口从 100 降为 50，并使用专用窄 DTO；详情继续按 ID 加载完整捕获信息与 payload。

本批不修改供应商列表、策略路由计数、首页统计、响应检查策略、系统设置、Chat API Key 或模型检查 options。这些事项保留在后续 backlog 中。

## 2. 设计原则

- 列表、下拉和详情分别定义契约，不在 route 层查询完整对象后再裁剪。
- 保持现有权限语义、筛选语义、排序语义和详情接口兼容性。
- 已选项补齐不能绕过可见性与权限；代理是现有架构明确允许登录用户读取已启用候选的全局资源例外。
- 已停用但仍被账户引用的代理仅可通过 `selectedIds` 补回，并在响应中保留禁用态，避免编辑旧账户时静默清空绑定。
- 前端必须防止作用域切换、搜索和弹窗关闭后的迟到响应覆盖当前状态。
- 源码正则只作为防回退门禁；完成证据必须包含行为测试、真实 HTTP 契约测试和查询投影检查。

## 3. 代理 options 按需加载

### 3.1 后端契约

保留现有 `GET /proxies/options` 路径，并扩展查询参数：

| 参数 | 规则 |
| --- | --- |
| `keyword` | 可选，按名称进行现有语义的有界搜索 |
| `limit` | 可选，沿用现有最大值；普通候选窗口不超过该值 |
| `selectedIds` | 可选，可重复 query 或数组；去重后最多 20 个，每个 ID 使用现有 ID 长度约束 |

响应保持直接数组，单项为：

```ts
interface ProxyProfileOptionItem {
  id: string
  name: string
  type: ProxyProfileType
  enabled: boolean
}
```

普通窗口只返回已启用代理。`selectedIds` 命中的可见代理独立补齐到结果中，即使其已停用；补齐项不计入普通 `limit`，最终按 ID 去重。不存在的 ID 忽略，格式、数量或长度越界返回 400。接口不返回地址、端口、用户名、密码、测试报告或其他代理详情。

repository 为 SQLite 和 PostgreSQL 分别执行窄投影，不调用完整代理列表 loader，不解密代理密码。SQLite read worker 的消息类型同步支持 `selectedIds`。

### 3.2 前端触发与缓存

- 从账户分页 `fetchPage` 和 mounted 辅助加载中移除代理 options 请求。
- 供应商 definitions 的现有加载不在本批调整，避免混入供应商 DTO 改造。
- 单账户编辑打开时，只用账户详情中的 `proxyProfileId` 作为选中 ID；代理下拉首次展开时请求普通窗口并补齐该 ID。
- 批量编辑仅在用户启用“代理”字段并首次展开下拉时请求候选；没有已选代理时不传 `selectedIds`。
- 远程搜索使用当前关键词和已选 ID；关闭下拉不清空已加载结果。
- 缓存键包含登录用户、角色、管理/个人视图和选中 ID 集合。代理候选属于全局资源，但缓存仍按身份和页面作用域隔离，避免认证切换复用旧状态。
- 同一缓存键的并发请求合并；搜索、作用域切换或弹窗关闭后，旧请求不得覆盖新状态。
- 请求失败时保留已有选中项和已有缓存，显示加载错误；用户再次展开或搜索可以重试。

## 4. 操作日志窄列表

### 4.1 列表契约

新增 `OperationLogListItem`，仅包含页面列表、移动卡片、行点击和权限展示实际需要的字段：

```ts
interface OperationLogListItem {
  id: string
  module: string
  action: string
  actorSystemAccountId?: string
  actorName?: string
  ownerSystemAccountId?: string
  ownerName?: string
  summary: string
  traceId?: string
  createdAt: string
  detailLevel: OperationLogDetailLevel
  visibilityScope: OperationLogVisibilityScope
}
```

具体字段名以现有领域类型为准；实现时不得用空字符串、空对象或默认值伪装已删除字段。列表不再返回 `changes`、`metadata`、`userAgent`、HTTP method/path/status、资源类型/ID/name、client IP 等未展示诊断字段。

管理员和个人列表沿用现有筛选、排序、分页及 targeted/all-users 合并规则。`detailLevel` 和 `visibilityScope` 保留在 repository 内部或列表 DTO 中，以维持普通用户字段裁剪和详情权限判断；不得因为窄投影扩大可见范围。

### 4.2 存储与详情边界

- 列表 repository 使用显式列和专用 mapper，不构造完整 `OperationLogSummary`。
- 名称补齐只加载列表真实展示的操作人和业务归属名称。
- 列表筛选可以引用未返回列，但 SELECT 不得因此带回这些字段。
- 详情路由和详情 repository 保持完整契约；点击行后仍按 ID 请求。
- SQLite 主线程、SQLite read worker 和 PostgreSQL 使用同一字段白名单和映射语义。

## 5. 公开 API 日志窄列表

### 5.1 分页与列表契约

前端默认 `pageSize` 调整为 50，桌面翻页和移动端追加加载沿用现有分页状态。后端最大值暂不改变，以保留其他调用方兼容性；页面请求明确传 50。

新增 `PublicApiLogListItem`：

```ts
interface PublicApiLogListItem {
  id: string
  createdAt: string
  sourceName?: string
  method: string
  path: string
  success: boolean
  statusCode?: number
  durationMs?: number
  clientIp?: string
  traceId?: string
}
```

列表不返回 token、User-Agent、query string、请求/响应大小、捕获状态、错误详情、请求 JSON、响应 JSON或其他只在详情中展示的诊断字段。筛选条件仍可使用对应数据库列，且不得改变当前结果集合与排序。

### 5.2 存储与详情边界

- 列表使用显式 SELECT 和专用 mapper，不构造完整 summary 后填充空 payload。
- `request`、`response`、capture 状态、大小和错误信息只由详情接口按 ID 返回。
- SQLite read worker 与 PostgreSQL 采用相同列表字段和 nullable 归一化规则。
- 第 50/51 条边界必须无重复、无遗漏；筛选变化仍重置到第一页。

## 6. 错误、权限与兼容性

- 三个列表/options 接口继续使用现有鉴权中间件和错误模型，不新增权限。
- 代理 `selectedIds` 只影响结果补齐，不允许读取完整代理详情或秘密。
- 操作日志个人视图继续执行现有两路权限查询与合并，窄投影只降低行宽，不改变授权模型。
- 公开 API 日志保持当前管理员访问边界。
- 两类日志列表 DTO 是前后端同步调整的内部管理契约；详情 DTO、详情路由和筛选参数保持兼容。
- 若仓库中存在列表 DTO 的其他消费者，实施时必须逐一迁移或保留独立兼容入口，不能让缺失字段在运行时变成隐式 `undefined`。

## 7. 测试与验收

### 7.1 代理 options

- 前端行为测试证明账户首屏、翻页和普通刷新对 `/proxies/options` 的调用次数为 0。
- 单账户编辑和批量编辑首次展开各只发一次请求；重复展开命中缓存，搜索使用新关键词。
- 已选第 51 个代理和已停用代理可通过 `selectedIds` 补齐；普通窗口不返回其他停用代理。
- 快速搜索、切换管理/个人视图、关闭弹窗时，迟到响应不覆盖当前状态。
- HTTP 测试覆盖登录要求、输入边界、去重、不存在 ID、禁用项补齐和无敏感字段。
- 查询门禁证明 SQLite/PostgreSQL 不调用完整代理 loader、不读取加密密码。

### 7.2 操作日志

- HTTP 字段白名单覆盖管理员和普通用户列表；详情仍返回原有完整字段。
- 普通用户 targeted/all-users 结果、名称补齐、分页和筛选与改造前一致。
- SQLite worker 与 PostgreSQL 的 SELECT 和 mapper 字段一致。
- 回归测试验证未返回字段不靠默认值伪造。

### 7.3 公开 API 日志

- 前端行为测试证明默认请求窗口为 50，筛选后回到第一页，移动端追加无重复。
- HTTP 字段白名单证明列表不含详情/敏感字段，详情仍包含完整捕获信息。
- 第 50/51 条分页边界、时间/source/path/IP/status/trace 筛选保持正确。
- SQLite worker 与 PostgreSQL 投影一致。

### 7.4 整合门禁

- 运行新增的定向行为、HTTP 和查询回归。
- 运行受影响的账户列表、代理、操作日志、公开 API 日志和权限回归。
- 运行 `pnpm typecheck`、`pnpm lint`、`pnpm build`、`go test ./...` 和 `git diff --check`。
- 更新接口契约、日志安全策略和审计报告的当前 backlog；不把源码正则测试单独作为完成证据。

## 8. 回退与非目标

本批不涉及 schema 迁移、生产数据写入或部署。若实现无法保持权限、筛选或详情兼容，应回退对应子增量，而不是恢复首屏宽查询或用默认字段伪造旧 DTO。

明确非目标：供应商列表 DTO、策略路由 snapshot、首页统计拆分、响应检查策略详情、系统设置分区、Chat API Key 和模型检查专用账户 options。
