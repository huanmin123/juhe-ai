# AI 账户测试弹窗模型按需加载设计

> 当前契约：批量 `test-options` 返回 `{ id, name, testEndpointModes }`。打开弹窗不预取模型；用户首次展开模型下拉才读取一次 options，模型选择后直接显示该模型已计算的请求形态。本轮只涉及 Node + Vue，未修改 Go。

## 1. 问题与目标

账户列表已经返回 `healthCheckModel` 和 `healthCheckEndpointMode`，但测试弹窗打开后仍立即请求 `test-options`，把供应商候选模型及每个模型的请求形态全部加载。该行为重复读取已经随列表返回的默认值，也让未操作下拉的用户承担目录查询、传输、解析和响应式状态成本。

本次目标固定为：打开弹窗零额外 options 请求；模型 options 在用户展开模型下拉时加载一次，并同时提供每个模型可执行的请求形态。

## 2. 已确认契约

- 弹窗初始化直接使用当前 `AccountSummary.healthCheckModel` 和 `AccountSummary.healthCheckEndpointMode`。
- 展开“选择测试模型”才调用 `GET /accounts/:id/test-options` 或个人端镜像接口，返回当前供应商作用域内严格为 `Array<{ id, name, testEndpointModes }>` 的模型窗口；搜索继续复用该接口。
- `testEndpointModes` 是 Node 计算的账户已启用 endpoint modes、模型协议和账户模型映射（包括映射上游协议）的最终交集；响应不暴露凭据或 `supportedApiProtocols`。
- 用户切换模型后立即使用该 options 项的首个可用请求形态；模型列表加载后自动选中首项也必须同步请求形态。
- 单模型 capabilities 路由可以保留作兼容接口，但 Vue 不调用它。
- 测试提交仍由后端重新校验模型、账户能力和请求形态；前端 options 不是授权或能力的最终事实。

## 3. 前端状态与竞态

- 模型列表请求使用 loading、错误、AbortController 和请求代次；切换账户或关闭弹窗时取消该请求。
- 用户选择另一个模型时不发起能力请求，直接同步对应 options 项的请求形态。
- 初始列表默认请求形态仍来自账户摘要；模型列表返回后用对应 options 项校验并保留有效默认值。
- 草稿测试继续使用表单已经计算出的固定模型和请求形态，不进入自由模型/协议加载流程。

## 4. 后端与数据边界

- Node 账户列表返回两个标量字段，本次不新增 schema、列表查询或 DTO 字段；Go 未修改且不纳入本次验收。
- 批量模型 options 受控读取当前账户 endpoint mode 配置和完整模型映射，响应为 `{ id, name, testEndpointModes }`；单模型 capabilities 路由继续保留兼容但不是页面依赖。
- 管理端请求继续携带目标 `systemAccountId`；个人端继续由 self scope 固定调用者范围。

## 5. 验收与回退

- 打开管理端或个人端测试弹窗后，模型 options 调用次数为 0。
- 展开模型下拉只增加一次批量 options 请求；重复展开同一窗口不重复请求。
- 展开请求形态下拉不会产生请求；批量 options 每项严格为 `{ id, name, testEndpointModes }`。
- 模型选择后立即显示并选择该项首个可用请求形态，浏览器不调用 capabilities。
- 切账户和关闭弹窗的迟到模型 options 响应均被隔离。
- 回退时可以恢复前端交互加载器，但不得恢复弹窗打开即预取，也不得从账户协议猜测已保存默认值。
