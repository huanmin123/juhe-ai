## 2. 目标

本次在既有有序助手时间线、直接生图、托管生图、富文本渲染和会话按需加载基础上，补齐以下闭环：

1. 手机端把对话列表入口移出输入框，放入左上角页面级悬浮工具组。
2. 输入框左下角提供 `+` 工具箱，首个能力为本地添加图片。
3. 提供手动上下文压缩和清空当前会话命令。
4. 让生成中状态持续可观察，并用真实传输活动判断连接是否存活。
5. 传输静默时二次查询服务端状态，只有权威终态才显示失败。
6. 最近失败或停止的轮次可以直接重新发送，不要求用户重复输入。
7. 可回滚操作优先显示本地效果，破坏性或计费操作仍以服务端结果为准。
8. 清理未实现的登录会话管理功能，避免“会话”一词与 AI 对话混淆。
9. 建立可供用户直接操作的真实验收会话集合。

## 3. 明确删除：登录会话管理

### 3.1 产品决策

项目不提供登录设备或登录会话管理能力，不保留入口、占位菜单、弹窗、前端 API、后端 API、灰度开关或专用领域类型。AI 问答中的“对话”只表示模型对话，不得复用“会话管理”描述登录状态。

必须删除：

- 应用壳和普通 Header 中的“会话管理”菜单项。
- `SessionManagementModal.vue` 及其状态、分页、刷新和撤销交互。
- 前端 `/auth/sessions`、`DELETE /auth/sessions/:id` API 封装。
- 仅服务该界面的 `AuthSessionSummary`、`AuthSessionListResult`、`AuthSessionRevokeResult` 等未被其他功能使用的类型。
- Go `GET /auth/sessions`、`DELETE /auth/sessions/{id}` 路由、handler、service、port、PostgreSQL 查询和只服务这两条接口的 DTO。
- `JUHE_AI_MANAGEMENT_AUTH_SESSIONS_ENABLED` 配置、校验、路由挂载和部署说明。
- Go 会话列表/撤销单元测试、integration smoke 分支和前端 W3 会话管理 smoke 断言。
- 接口权限矩阵、Go README 和 `PLAN-0081` 中把登录会话列表/撤销描述为当前或待接管能力的正文。
- 只验证该未落地界面的测试断言和文档表述。

不得删除：

- 登录、退出、修改密码和服务端当前登录令牌处理。
- 修改密码后撤销其他令牌等现有安全收口。
- AI 问答自己的对话列表、对话删除和生成任务状态。

### 3.2 长期约束

- 后续维护不得因为看到历史提交、迁移记录或数据库 session 表而恢复“会话管理”入口。
- 当前产品架构不包含登录设备管理，也不预留重新引入路径。
- 当前代码和文档不保留“登录设备”占位文本或隐藏开关。

## 4. 移动端信息架构

### 4.1 左上角悬浮工具组

应用壳在沉浸式手机页面提供固定的 `immersive-mobile-tool-stack` 容器：

- 第一个按钮：系统导航菜单。
- AI 问答页面追加第二个按钮：对话记录。
- 两个按钮均为圆形图标按钮，粗指针设备命中区至少 `44px × 44px`。
- 容器考虑 `safe-area-inset-top` 和 `safe-area-inset-left`，不能覆盖状态栏。
- 消息内容必须为工具组预留首屏空间，不能与第一条消息重叠。

应用壳使用稳定的 Teleport 目标承载页面级工具。`ChatView` 只向该目标贡献“对话记录”按钮，按钮直接控制本页面的对话抽屉。应用壳不持有聊天抽屉状态，聊天页面也不复制系统菜单逻辑。

桌面端继续使用左侧对话栏，不显示手机悬浮对话按钮。

### 4.2 输入框工具箱

输入框左下角增加 `+` 图标按钮：

- 点击后打开工具菜单，不直接执行默认动作。
- 当前只有“添加图片”。
- 选择“添加图片”后复用现有隐藏 `input[type=file]`，由手机浏览器唤起文件、照片或相册选择器。
- 支持 PNG、JPEG、WebP 和 GIF，多选、数量、原图大小与压缩后大小继续沿用现有约束。
- 图片必须先插入本地 Blob 预览，再异步压缩和上传；上传进度、失败重试与删除继续显示在编辑器内。
- 当前模型不支持图片输入时，菜单项禁用并显示中文原因；不能隐藏按钮后让用户无法理解能力边界。
- `+` 工具箱在桌面和手机使用同一组件，手机命中区至少 `44px × 44px`。

原手机“对话记录”按钮从 `AIComposer` 完全移除；输入框只承载当前输入、模型控制、工具箱、上下文状态、发送和停止。

## 5. 命令模型

### 5.1 命令列表

| 命令 | 作用 | 是否乐观执行 | 是否确认 |
| --- | --- | --- | --- |
| `/clear-input` | 仅清空当前编辑器内容 | 是，本地操作 | 否 |
| `/code` | 插入 Markdown 代码围栏 | 是，本地操作 | 否 |
| `/image` | 打开本地图片选择器 | 是，先显示本地预览 | 否 |
| `/compact` | 手动压缩当前对话上下文 | 否 | 是，说明会调用模型并产生用量 |
| `/clear` | 清空当前对话内容但保留对话壳 | 否 | 是，明确不可恢复 |

现有 `/clear` 的“清空输入”语义改为 `/clear-input`。危险命令不能与轻量本地命令复用同一无类型 `insert` 字段，命令定义改为显式动作联合类型，由 `AIComposer` 发出页面级事件。

选择页面级命令时，编辑器先删除本次斜杠命令文本，再交给 `ChatView` 弹出确认。用户取消后不恢复斜杠文本。

### 5.2 手动上下文压缩

接口：

```text
POST /__aisys__/api/my-chat/conversations/:conversationId/context/compactions
```

请求体只提交当前选中模型。API Key、模型可用性、协议、网关地址和上下文限制必须由服务端按当前会话重新解析，不能信任前端传协议或密钥。

服务端行为：

1. 校验登录用户和对话归属。
2. 拒绝正在准备、生成或清理的对话。
3. 对已在压缩中的同一对话返回幂等接受状态。
4. 没有可压缩完整轮次时返回明确的 `no_compactable_turn`，不伪造成功。
5. 先把 `compact_pending` 持久化，再返回 `202`。
6. 后台复用现有 `compactChatContextOnce` 的分页读取、同会话去重、claim、checkpoint 安装和失败状态。
7. 前端在服务端接受后显示“正在压缩”，轮询 `context-status` 直到 `ready` 或 `compact_failed`。

`context-status` 增加安全的 `errorCode`、`retryAt` 和 `attemptCount`，不返回裸上游响应。

### 5.3 清空当前对话

接口：

```text
POST /__aisys__/api/my-chat/conversations/:conversationId/clear
```

清空是一个服务端事务，不使用“删除旧对话再创建新对话”模拟。执行前必须确认，执行中页面保持原内容并显示 loading，只有服务端成功后才清空本地消息和缓存。

事务必须：

- 锁定当前用户的对话。
- 拒绝 active preparation、active turn 和 `compacting` 状态。
- 严格扣减 `chat_user_storage_windows` 的正文与 reservation。
- 删除当前对话消息、幂等提交记录、checkpoint、checkpoint entries 和资产引用。
- 复用资产过期队列处理该对话的上传与生成资产，不能在请求线程直接无界删除文件。
- 重置 `next_sequence_no=1`、`user_turn_count=0`、active turn、上下文 token、claim、retry 和错误字段。
- 递增 `message_revision` 与 `context_revision`，让 IndexedDB 和其他标签页失效旧快照。
- 标题重置为“新对话”，更新时间和最后消息时间更新为当前时间。

必须保留：

- 对话 ID。
- 所属用户。
- API Key 绑定及名称快照。
- 置顶状态。
- 最近模型偏好。

成功后前端清理当前对话的 IndexedDB 消息、running turn、待提交记录、编辑态和本地未提交资产，再刷新摘要、模型和上下文状态。

## 6. SSE 探活与生成状态

### 6.1 两种活动

必须区分：

- 传输活动：收到任意 SSE 数据块或心跳注释，证明连接仍有字节流动。
- 语义进展：收到 message、reasoning、tool、content block 或终态事件，证明回答内容有变化。

长时间推理、生图或上游工具可能没有语义进展，但只要传输心跳存在就不能判失败。

### 6.2 服务端心跳

- SSE 响应建立后每 5 秒写入一次 `: heartbeat`。
- 初次 POST 和重附着 GET 复用同一心跳实现。
- 写入失败、响应关闭或背压不可继续时必须清理 timer 并取消 subscriber。
- 请求仍在 accept 前的 preparation 阶段尚未建立 SSE；前端以本地 preparation 状态和 submission status 查询观察该阶段。

### 6.3 前端活动监测

`consumeChatSseResponse` 为任意 chunk 和注释调用 `onActivity`，但心跳不进入 `ChatStreamEvent`、不占用 `eventVersion`、不写入消息内容。

generation runtime 为每个运行轮次维护：

- `startedAt`
- `lastTransportActivityAt`
- `lastSemanticActivityAt`
- `livenessState: active | checking | reconnecting`
- 单飞的 stale check timer

从开始请求起超过 10 秒没有传输活动时：

1. 状态切换为 `checking`，页面显示“正在确认生成状态”。
2. 调用现有 submission status 接口，不直接把消息改成失败。
3. `preparing`：继续等待，下一次检查仍受单飞和最小间隔限制。
4. `accepted + streaming + runner running`：中断本地旧 reader 并重附着同一 runner，不重复请求上游模型。
5. `accepted + terminal`：刷新当前轮消息并应用权威终态。
6. `accepted + streaming + runner missing`：走现有 attach 收口路径，把轮次权威标记为 `stream_interrupted`，随后刷新失败消息。
7. `not_found`：沿用连续确认和 grace 规则，不能在 POST 与 DB 提交竞态窗口内恢复草稿或重复发送。

同一静默窗口只能有一个状态请求；网络错误按既有有界退避继续确认，不能形成无界轮询。

### 6.4 状态查询扩展

submission status 的 accepted 结果增加：

```ts
{
  state: 'accepted'
  turnId: string
  assistantMessageId: string
  assistantStatus: 'streaming' | 'completed' | 'failed' | 'canceled'
  runnerState: 'running' | 'missing' | 'terminal'
  eventVersion?: number
  errorCode?: string
  errorMessage?: string
  serverTime: string
}
```

`errorMessage` 由服务端根据公开错误码映射为安全中文文案，不持久化或回传裸上游错误。`traceId` 继续用于服务端排障。

generation runner 的意外异常必须调用权威失败收口：先把 DB 助手消息更新为 terminal failed，再发送 `message.failed`。不得只修改内存状态后留下永久 streaming 消息。

## 7. 动态思考状态

当助手消息处于 streaming 且还没有正文、图片或可展示过程块时，显示独立的动态思考指示：

- 文案为“思考中”，后接循环三点动画。
- 显示从 `startedAt` 计算的经过时间，使用固定宽度数字避免布局跳动。
- `livenessState=checking` 时显示“正在确认生成状态”。
- `livenessState=reconnecting` 时显示“正在恢复连接”。
- 收到 reasoning、tool 或正文后，空占位消失，由有序过程块接管展示。
- 活跃过程块保留轻量脉冲状态；完成后折叠并停止动画。
- 动画尊重 `prefers-reduced-motion`。

动态效果只表达 UI 状态，不能代替 heartbeat 或权威状态查询。

## 8. 失败原因与重新发送

### 8.1 可见失败

失败助手消息显示安全中文原因；未知错误统一显示“生成任务异常结束，请重新发送”，并保留可关联 trace 的服务端记录。刷新页面后必须从持久化 `errorCode` 恢复同一类失败文案。

### 8.2 重试入口

只对最近一个可替换的 failed 或 canceled 尾轮，在对应用户消息操作区显示刷新图标按钮：

- failed：按钮提示“重新发送”。
- canceled：按钮提示“重新生成”。
- 旧轮次不显示，后端仍以 replace conflict 兜底。

点击后：

1. 使用原用户文本与 `input_image` 资产引用。
2. 生成新的 `clientMessageId`。
3. 使用原模型（仍可用时），否则使用当前选中模型。
4. 携带原 `turnId` 作为 `replaceTurnId`，继续走既有 stream API。
5. 前端立即把该轮投影为用户消息 + streaming 助手占位，不等待服务端返回。
6. 服务端原位替换尾轮，不能追加重复轮次。
7. 图片资产已过期或模型不再支持图片时显示明确错误，不伪造重试成功。

## 9. 乐观交互白名单

### 9.1 可以先显示

- 发送文本和图片消息。
- 失败轮次重新发送。
- 本地图片预览、压缩进度和上传进度。
- 对话重命名。
- 对话置顶和取消置顶。
- 模型、思考级别和服务等级选择。
- 打开抽屉、工具箱和命令菜单。

重命名和置顶失败时必须恢复原值、原顺序并显示中文错误。

### 9.2 必须等待服务端

- 创建对话：需要真实 ID 和 API Key 快照。
- 删除对话。
- 清空当前对话。
- 手动上下文压缩。
- 停止生成的最终状态。
- 权限、额度、模型可用性和资产引用校验。

破坏性操作在请求成功前不得清空页面或本地缓存。

## 10. 按需加载与并发边界

新增能力不得破坏已完成的首屏性能约束：

- 进入 AI 问答只取最多 30 条对话摘要。
- 没有激活对话时默认选择第一项。
- 只为当前对话加载最近 100 条消息、模型、sync 和 context status。
- 更早消息继续按游标向上加载。
- 快速切换使用 conversation load epoch，旧请求不能覆盖当前对话。
- context status、manual compaction 轮询和 stale status 查询都只绑定当前对话及当前轮次。
- 复杂 Markdown、Mermaid、SVG 和图片仅渲染当前消息窗口，不能恢复全会话 DOM。

## 11. 自动验证

### 11.1 前端

- 手机悬浮工具组、对话抽屉和 `+` 工具箱。
- `+` 触发原生 file input，模型不支持时的禁用说明。
- `/clear-input`、`/compact`、`/clear` 动作类型与确认门禁。
- heartbeat/comment 触发 transport activity 但不产生消息事件。
- 假时钟覆盖 10 秒静默、单飞状态查询、重附着和终态刷新。
- 动态思考、checking、reconnecting、reduced motion。
- 最近失败/停止轮次的重新发送和图片引用。
- 重命名/置顶乐观更新与失败回滚。
- 对话列表入口不再出现在 Composer。
- 登录会话管理入口、弹窗、API 和类型不存在。
- Go 登录会话列表/撤销路由、专用配置、查询和测试不存在。

### 11.2 后端与存储

- 心跳周期、初次流/重附着共用、连接关闭和背压清理。
- submission status 的 preparing、running、terminal、runner missing、越权和安全错误文案。
- runner 意外异常的 DB + SSE 权威终态。
- 手动压缩的 accepted、幂等、无可压缩轮次、active turn 冲突、installed 和 failed。
- 清空事务的容量账本、消息、幂等、checkpoint、资产引用、revision 和保留字段。
- SQLite 与 PostgreSQL 使用同一 clear 契约。
- 最新失败轮含图片的 replace 成功，旧轮 replace conflict。

## 12. 真实验收会话

本地真实账户最终保留以下统一命名的对话，全部通过页面向真实模型发送，不直接向数据库写伪造回答：

| 名称 | 内容 | 关键检查 |
| --- | --- | --- |
| `验收-01 Markdown与GFM` | 标题、强调、删除线、引用、列表、任务、表格、分隔线、链接 | DOM 与手机滚动 |
| `验收-02 多语言代码` | TypeScript、Python、JSON、PowerShell、SQL、YAML、Go、Rust | 高亮、语言标签、复制 |
| `验收-03 LaTeX` | `$`、`$$`、`\(`、`\[` 四类公式 | KaTeX 与窄屏 |
| `验收-04 Mermaid` | flowchart、sequence、state、class | 中文标签、刷新恢复 |
| `验收-05 SVG与外部图片` | 含动画/脚本的 fenced SVG 与 HTTPS 图片 | iframe、懒加载、主 DOM 隔离 |
| `验收-06 联网顺序` | 连续两次联网后总结 | 工具块顺序、展开与折叠 |
| `验收-07 思考与工具过程` | 高思考级别的多步骤任务 | 动态状态、过程顺序、终态工具栏 |
| `验收-08 普通模型托管生图` | 普通 Responses 模型调用图片工具 | 图片、下载、复用、刷新 |
| `验收-09 gpt-image-2直接生图` | Images API 直接生成 | 私有资产与终态 |
| `验收-10 手机图片输入` | `+ -> 添加图片` 后视觉问答 | 本地预览、上传、引用 |
| `验收-11 停止与重新发送` | 主动停止后点击重新生成 | 原位替换、不重复轮次 |
| `验收-12 大会话与切换` | 大上下文、快速切换和向上翻页 | 摘要首屏、当前详情、无串话 |

传输静默、runner 丢失和权威失败使用 Mock AI 与假时钟自动注入，不污染用户最终操作的真实账户数据。既有旧失败测试对话不作为本轮通过证据，也不自动删除用户数据。
