# AI 输入框交互优化设计

## 目标

修正富文本编辑语义与“Enter 发送”的冲突，保证 Markdown 列表、引用、代码块和斜杠命令可以自然使用；同时降低底栏拥挤和上下文提示噪音。

## 键盘规则

1. 普通段落中，`Enter` 发送，`Shift+Enter` 插入软换行。
2. 列表项、标题、引用和代码块中，普通 `Enter` 交给 Tiptap：列表继续下一项，空列表项再次回车退出列表，标题末尾进入普通段落，引用和代码块正常换行。
3. 任意编辑状态下都可使用 `Ctrl+Enter`；macOS 使用 `Cmd+Enter` 发送当前消息。
4. 斜杠命令菜单打开且存在候选项时，`Enter` 选择当前命令，不发送。
5. 斜杠命令没有候选项时，不吞掉编辑器或发送语义。
6. 输入法组合输入期间，所有发送快捷键都不得触发发送。

## Markdown 与命令

- 依赖 StarterKit 的 Markdown 输入规则：输入 `- `、`* `、`1. `、`> ` 和围栏代码语法创建对应块。
- 删除 `/list` 无序列表命令，避免与 Markdown 原生输入重复。
- 保留清空、代码块和图片命令。
- 命令查询只读取当前光标所在文本块中、光标前的 `/查询词`，不再读取整篇文档末尾。
- 从列表连续回车退出到普通段落后，输入 `/` 必须立即打开命令菜单；选择命令时只删除当前块中的查询范围。

## 底栏布局

- 模型、思考级别、服务级别三个下拉框根据当前显示内容计算触发器宽度，并设置各自合理最小宽度。
- 下拉菜单根据选项内容扩展；触发器和菜单最大宽度均为 `200px`。
- 超过 `200px` 的选项省略显示，并通过悬浮提示暴露完整内容。
- 小屏空间不足时，模型控制区保持有界滚动或换行，不挤压上下文图标及发送/停止按钮。
- 上下文圆环移出模型控制区，固定放在发送/停止按钮左侧。

## 上下文提示

- 正常状态仅显示 `已用 / 上限`，例如 `5.2K / 922K`。
- 等待压缩、压缩中、压缩失败时追加对应状态。
- 圆环的无障碍名称保留完整语义，但页面只挂载一个 tooltip。
- 不修改上下文用量来源、计算方式或压缩逻辑。

## 手机端交互

- 沉浸聊天高度以 `visualViewport.height` 为首选来源，并通过 CSS 变量贯穿应用壳、内容区和聊天工作区；固定 `min-height` 不得抵消软键盘收缩后的动态视口。
- 沉浸聊天期间锁定 `body` 外层滚动，消息区保留正高度并独立滚动；顶部系统菜单与底部输入区分别避让 `safe-area-inset-top`、`safe-area-inset-bottom`。
- 手机会话抽屉每行提供可见“更多”入口，包含重命名、置顶、详情和删除；桌面继续支持右键菜单。选择会话后关闭抽屉；从抽屉新建时必须先等待 Drawer 的关闭动画完成，再打开创建 Modal，避免 Drawer 层级遮住 Modal，桌面面板则立即打开。
- 会话菜单使用 `menu/menuitem` 语义，打开后聚焦首项，支持方向键与 Escape，关闭后把焦点还给触发按钮；定位范围以 `visualViewport` 为准。
- 消息列表同时观察内容高度与滚动容器可视高度。原本贴底时，软键盘或输入框变高后继续贴底；自动跟随产生的向上滚动必须标记为程序滚动，用户主动离底后任何尺寸变化都不得抢回滚动位置。
- 顶部系统菜单避让进入索引 0 消息的虚拟测量高度，不给虚拟空间增加外部 margin，确保 distance 与 virtualizer 使用同一高度口径。
- 粗指针设备的系统菜单、会话操作、上下文圆环、发送/停止、消息操作和图片重试/删除命中区至少为 `44x44px`，视觉图标可以保持紧凑。

## 验证范围

- 普通段落：Enter 发送、Shift+Enter 换行、中文输入法不误发送。
- 无序/有序列表：Enter 续项、双 Enter 退出、嵌套列表、Ctrl/Cmd+Enter 发送。
- 标题、引用和代码块：标题 Enter 退出到普通段落，引用和代码块 Enter 留在块内，Ctrl/Cmd+Enter 发送。
- 真实输入规则：挂载 Tiptap `EditorView` 后逐字符输入 `- 验收列表`，确认 StarterKit 转为列表且 Enter 不发送；自动化不得用一次性 fill 代替逐键输入来验证 input rule。
- 斜杠命令：普通段落、列表退出后的新段落、有候选、无候选、键盘上下选择和 Escape 关闭。
- Markdown 序列化：列表编号、嵌套、代码块和换行在发送后保持正确。
- 底栏：三个下拉框的短值、长值、200px 上限、小屏布局和弹层完整名称。
- 上下文圆环：位置、正常提示、压缩状态提示和发送/停止切换。
- 手机端：`390x844`、`360x800` 和可视高度 `420px` 下检查软键盘动态视口、body 不外滚、会话抽屉、更多菜单、底栏横向滚动、长消息跟随与离底、44px 触控命中和安全区。

## 51 轮真实深度验收

### 会话策略配置

- `JUHE_AI_CHAT_RETENTION_DAYS` 控制聊天消息、上下文与图片资产保留期，默认 `3` 天。
- `JUHE_AI_CHAT_MAX_CONVERSATIONS_PER_USER` 控制每个用户可保留的会话数量，默认 `50`；达到上限后拒绝新建并提示先删除旧会话，不自动删除用户仍在保留期内的数据。
- `JUHE_AI_CHAT_MAX_TURNS_PER_CONVERSATION` 控制单会话累计接受的用户轮次数量，默认 `50`。
- 三项均为部署环境配置，不作为用户表单或逐账户系统设置；启动时执行整数范围校验，非法值直接阻止启动。
- 已接受后失败或取消的轮次仍计入累计轮次，防止通过失败重试绕过上限；相同 `clientMessageId` 的幂等确认和最近轮次原子替换不增加计数。
- 会话响应返回 `userTurnCount` 与 `userTurnLimit`。前端提前禁用新的发送并引导新建会话，后端事务仍是并发条件下的唯一权威。

### 会话主题与阶段

- 使用真实账户和真实模型，在一个会话中围绕 HTML + CSS 小项目持续开发。
- 从最小页面开始，逐轮增加结构、内容、视觉样式、响应式、交互细节、无障碍和缺陷修复，要求每轮基于上一轮成果继续演进。
- 中途切换可用模型、思考级别和受支持的服务级别，验证切换前后的需求、文件结构和代码决策可以连续继承。
- 覆盖图片、长 Markdown、列表、代码块、复杂编辑、停止生成、失败恢复和重新编辑最近一轮。

### 记忆与压缩

- 在早期、中期和后期植入可客观核对的项目代号、视觉约束、功能规则和技术决策，并在不同间隔后重新询问。
- 记录记忆正确率、首次遗漏轮次、首次矛盾轮次和压缩前后差异。
- 优先通过持续输出完整项目文件，以及切换到真实可用且上下文窗口更小的模型，自然触发压缩。
- 如果 51 轮仍未自然达到阈值，单独执行受控压缩验收；报告必须区分“真实自然触发”和“受控触发”，不得混合结论。
- 受控压缩会话必须通过 `createChatConversation`、`acceptChatTurn`、`completeChatTurn` 预填语义连续的用户/助手完整轮次，不允许直接 INSERT 消息或拼接不符合 schema 的 JSON。
- 预填内容继续使用同一个 HTML + CSS 项目，每轮包含明确版本、需求决策和有效代码演进；在接近真实模型压缩阈值后，后续轮次必须通过真实 HTTP/SSE 发送，以生产预算与压缩链路触发 checkpoint。
- 受控会话需要核对连续 sequence、幂等映射、`userTurnCount`、容量账本、`contextRevision`、过期时间和助手终态，再验证压缩后的早期锚点、最近完整代码与新需求可以同时继承。

### 容量边界

- 第 50 个用户轮次允许完成发送并得到终态回答。
- 第 51 次发送必须被后端权威边界阻止；前端同时做预防性禁用，保留用户草稿，并明确引导创建新会话。
- 会话达到上限后不得继续创建第 51 个用户消息、助手占位消息或后台生成任务。
- 后端在昂贵的图片说明、上下文压缩和模型请求前做快速预检，并在 `acceptChatTurn` 的会话锁事务内再次检查，避免竞态绕过。

### 量化指标

- 每轮记录首字延迟、总耗时、终态、重试次数、错误码和生成模型。
- 记录上下文已用 Token、窗口上限、压缩次数、压缩耗时、请求体大小和数据库消息/轮次数量。
- 记录上游 cached input Token、缓存命中率以及模型切换前后的缓存变化。
- 记录项目要求完成率、代码连续性、历史决策保持率和记忆问答准确率。
- 检查图片资产状态、消息显示、数据库上下文快照、后台任务与日志错误。

### 验收产物

- 原始逐轮指标写入仓库根目录 `reports/`，保留机器可读 JSON。
- 人工整理结论写入 `docs/reports/`，说明测试模型、轮次、压缩类型、缓存效果、记忆衰减点、边界行为和未覆盖风险。
- 报告不能只写“通过”；必须给出实际数值、异常轮次、问题修复记录和最终结论。

## 非目标

- 不增加新的富文本工具栏。
- 不引入新的编辑器框架或重量级命令插件。
- 不修改上下文预算和压缩算法。
- 不提供旧聊天 schema、旧接口字段或旧部署数据的运行时兼容分支；开发与部署环境按当前 schema 单独同步。
