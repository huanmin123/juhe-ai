# 运行日志索引保留清理设计

## 目标与边界

本切片只把 PostgreSQL 运行日志索引保留清理迁移为 Go 可运行能力。Node `ingest-worker` 继续拥有运行日志文件导入、cursor 写入和 facet 增量写入；本切片不切换生产 owner、不删除 Node、不修改 schema，也不删除原始日志文件。

清理仅在 `JUHE_AI_RUNTIME_LOG_INDEX_ENABLED=true` 时运行。保留天数读取 `sys_admin/runtimeLogIndexRetentionDays`，缺失或零值使用 14，显式值和命令覆盖必须在 1..90。一次运行固定一个 UTC cutoff，避免多批次跨越不同时间边界。

## 组件

- `internal/store/port/runtime_log_retention.go`：定义设置读取、索引批量清理和完成 cursor 批量清理的存储端口。
- `internal/modules/runtimelogretention/service.go`：负责开关、默认值、参数归一化、固定 cutoff、先索引后 cursor 的小批循环、25ms 可取消暂停和结果汇总。
- `internal/store/postgres/runtime_log_retention.go`：实现 PostgreSQL 事务、锁、稳定选删和 facet 维护。
- `internal/app/runtime_log_retention_cleanup_worker.go`：提供可直接由 CLI/supervisor 组装的一次性或周期 worker 入口；本批不改共享 CLI main。

## PostgreSQL 事务与并发

每个索引批次在单个事务中执行：

1. 按固定顺序取得 `runtime_log_facet_summary`、`runtime_log_level_facets`、`runtime_log_event_facets` 的 `SHARE ROW EXCLUSIVE` 表锁。该锁与 Node importer 的 `INSERT/UPDATE` 表锁冲突，使单个有界批次内的 facet 快照不会与 Node 增量写交错。
2. 从 `runtime_logs` 中选择 `time < cutoff` 的最老行，固定 `ORDER BY time ASC, id ASC LIMIT batchSize FOR UPDATE SKIP LOCKED`，并在同一语句删除、返回 `time/level/event`。
3. summary `total_count` 和 level/event count 使用 `GREATEST(0, ...)`，零计数行删除。summary 的 earliest/latest 从 cutoff 后的剩余索引重算；被删除事件可能命中自身 latest 时，从剩余同事件索引重算 `latest_time`。
4. 同一事务提交。任何步骤失败全部回滚。

完成 cursor 使用单条有界 DELETE：仅删除 `updated_at < cutoff`、`cursor_offset >= file_size` 且 `last_error_message IS NULL` 的行，按 `updated_at ASC, log_file ASC` 选取。运行中、未读完或错误 cursor 保留。

## 取消与错误

service 在每个 store 调用和批间暂停使用调用方 context。context 取消、设置读取失败、事务失败或 worker 连接失败立即返回错误；已提交批次不回滚，未提交批次由 PostgreSQL 事务回滚。满批且未达到 `maxBatches` 时暂停 25ms，非满批立即结束该表循环。
