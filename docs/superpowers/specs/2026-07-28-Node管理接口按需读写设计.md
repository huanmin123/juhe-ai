# Node 管理接口按需读写设计

## 1. 背景与范围

本设计修复管理页面把列表、编辑、下拉、运行态和完整领域对象混为同一契约的问题。首个完整落地点是“我的 AI 账户”，同时覆盖“我的 API Key”的同类问题，并审计其他新增 / 编辑弹窗。

范围仅包含 Node 后端与 Vue 前端。Go 后端不修改、不做契约对齐，也不纳入本次验收。

## 2. 已确认的问题

- AI 账户新建弹窗在用户没有操作时刷新供应商定义，并预取分组、标签和模型候选。
- AI 账户普通编辑同时请求 `edit-basic` 和 API Key 运行态，随后又预取模型、分组和标签；基础详情仍由完整 `AccountSummary` 查询后裁剪。
- AI 账户列表虽然在响应层删除了若干大字段，repository 仍以完整摘要为中心，列表、编辑、测试和运行态共享查询图。
- AI 账户保存把大部分表单字段重新发送，Node 再按宽对象执行更新，扩大校验、关联表写入、缓存失效和并发冲突范围。
- API Key 新建 / 编辑在弹窗打开时预取策略路由 options；PATCH 对任何字段都物化多次完整摘要、全列更新并重建额度窗口。
- 分组、策略路由、统一授权、响应检查策略、模型检查和外部来源等页面存在相同的无交互 options 或重复详情请求。

## 3. 不变原则

1. 页面列表、编辑基础区、编辑高级区、下拉、运行态、密钥和任务分别使用场景 DTO；禁止继续用同一个 `Summary` 覆盖所有场景。
2. repository 必须按 DTO 字段查询，禁止“先查完整对象，再在 route/sanitizer 删除字段”。
3. Node 返回稳定的业务值和轻量摘要，让 Vue 无需关联大对象即可渲染；本地化文案、颜色和纯展示格式仍属于前端，避免把中文 UI 固化为后端协议。
4. 打开弹窗只读取当前行、登录后引用缓存或专用最小编辑投影。候选全集只在用户首次展开对应下拉时加载。
5. Vue PATCH 只发送相对打开时 baseline 实际变化的顶层字段；嵌套配置按明确聚合边界整体替换，不做含糊深层 merge。
6. Node 只校验、读取、更新和失效请求涉及且归一化后确实变化的字段。相同值更新必须成为 no-op。
7. 写入权限始终由 Node 依据当前 session、资源 owner 和数据库事实重新校验，不能信任列表行或前端缓存。

## 4. 登录后引用缓存

“默认分组”和“默认策略路由”不是编译期常量；它们的 ID 属于具体系统账户，状态也可能变化。因此将其定义为“用户作用域稳定引用”，而不是把完整动态候选目录永久缓存。

登录或 `/auth/me` 恢复 session 后，Vue 异步单飞加载一个轻量引用接口：

```ts
interface UserReferenceData {
  systemAccountId: string
  providerDefaults: Array<{
    providerCode: string
    defaultGroup: { id: string; name: string }
    defaultRouteStrategy?: { id: string; name: string; mode: string; status: string }
  }>
  preferredDefaultRouteStrategy?: { id: string; name: string; mode: string; status: string }
}
```

- 缓存键包含登录用户 ID、auth revision、self / admin 和目标 owner ID；登出、切换用户或 session 失效时立即清空。
- 管理员代管其他系统账户时使用独立 scope key，不能复用管理员自己的默认资源。
- 缓存未完成不得阻塞弹窗。创建请求可省略默认 `groupId` / `routeStrategyId`，由 Node 按 owner 和 provider / purpose 解析当前默认资源；显式选择后才提交具体 ID。
- 完整分组、策略、模型、标签等候选仍由下拉首次展开按需请求；引用缓存不替代候选目录。
- 默认资源或相关 owner 发生写入后只失效对应 scope；不创建浏览器持久响应缓存。

`preferredDefaultRouteStrategy` 的选择规则由 Node 明确定义，前端不能再从多个 `isDefault` 结果中取第一条。

## 5. AI 账户读契约

### 5.1 列表

`GET /accounts` 与 `GET /my-accounts` 返回专用 `AccountListItem`。字段只允许来自：

- 当前可见列和移动卡片：身份、名称、供应商、类型、状态摘要、标签、分组 / 代理摘要、优先级、并发、用量三元组、时间摘要。
- 行操作判定：精确的 `canEdit`、`canDelete`、`canTest`、`canReturnAuthorization` 等布尔能力，不返回完整权限 / 授权来源对象。
- 测试弹窗零请求默认值：`healthCheckModel`、`healthCheckEndpointMode`。
- 乐观更新和编辑入口：`configRevision` 及列表已经展示的非敏感基础字段。

列表禁止返回或查询 `credentials`、完整 `supportedModels`、`modelMappings`、错误 / 响应策略数组、API Key 运行态明细、完整 usage、完整 authorizationSources 和编辑专用配置。重新授权等需要凭据的动作改用专用按需接口。

用量若是可见列，只返回 `{ requestCount, totalTokens, totalCost }`；不能复用十余字段的通用 usage 对象。

### 5.2 编辑基础投影

`GET /accounts/:id/edit-basic` 只查询打开基础表单所需字段：资源身份与版本、供应商 / 协议 / 类型、名称、当前分组引用、并发 / 优先级 / 状态、标签、备注、检查模型 / 请求形态以及当前账户类型允许编辑的最小凭据字段。

该接口禁止访问 usage、todayUsage、并发运行态、健康 / 冷却运行态、完整 permissions、authorizationSources、API Key 运行态、模型映射和高级策略。

授权实例使用独立只读 / 可写投影，只返回其允许调整的分组和本地优先级，以及来源配置的必要只读值。

### 5.3 高级投影

`GET /accounts/:id/advanced` 仅在用户展开高级配置时请求，返回模型映射、支持模型、endpoint modes、余额查询、时间计划、代理和策略等高级区真实消费字段。仍不返回 usage、列表运行态或权限全集。

凭据级 API Key 运行态保留专用接口，只有账户类型为多 API Key 且用户展开对应运行态区域时才加载；普通账户编辑首开不请求。

## 6. AI 账户写契约

Vue 在打开编辑时保存规范化 baseline。保存时构造严格 PATCH：

```json
{
  "expectedConfigRevision": 12,
  "name": "new-name",
  "credentialsPatch": { "base_url": "https://example.com/v1" }
}
```

- 未变化字段不出现；未加载高级区时任何高级字段都不能出现。
- `credentialsPatch` 只携带变化键，Node 与当前加密凭据合并后再做完整类型校验。显式清空使用 `null`，缺失表示不改。
- `tags`、`supportedModels`、`modelMappings`、`availabilitySchedule`、`balanceQueryConfig` 等数组 / 聚合对象在出现时表示完整替换。
- Node 在同一事务内校验 owner 与 `configRevision`，动态生成实际变化列的 `SET`，只更新涉及的关联表。
- 只有影响网关身份 / 调度的字段才推进配置版本和失效 gateway runtime；纯名称 / 备注不触发上游健康检查、额度或无关缓存。
- 响应返回列表可合并的变更摘要与新版本，不再返回完整 `AccountSummary`；版本冲突返回 `409`。

当前普通基础编辑总是重建 `credentials`，而 Node 合并器没有保留全部高级凭据键，可能在只改名称时删除错误策略、响应策略、GPT 覆盖或 Codex policy。字段级凭据补丁必须同时修复该数据丢失问题。

## 7. API Key 契约

- 列表使用 `ApiKeyListItem`，保留 UI 实际消费字段；usage 收窄为三字段摘要。个人端不返回管理侧 owner 字段。
- 新增弹窗立即打开；默认策略来自用户引用缓存或由 Node 在创建时解析。策略下拉首次展开才加载 options。
- 编辑直接使用列表携带的 edit seed，不增加详情请求；当前策略以已选项注入，展开下拉才补候选。
- PATCH 携带版本和变化字段。Node 在事务内读取最小行、动态更新变化列；只有额度或有效启停状态实际变化才同步小时窗口，只有运行时相关字段变化才失效 gateway / quota。
- secret 接口只查询 `id`、owner、名称、前后缀和密文，不关联策略或统计。
- 创建 / PATCH 响应返回密钥展示或行合并所需最小结果，不重新物化完整摘要。

## 8. 其他页面治理

本轮按同一准则修复已确认的高收益路径：

- 分组编辑直接使用列表 edit seed；供应商 options 在下拉展开时加载。
- 策略路由保留必要详情，但分组 / 模型候选按下拉加载。
- 统一授权新增不预取 owner、resource、grantee 候选；默认目标分组读取作用域引用。
- 外部来源编辑直接使用列表字段，不读取 token 详情。
- 响应检查策略、模型检查计划和供应商模型目录不模拟下拉展开。

公告正文、团队成员、策略完整绑定和日志 payload 等列表确实缺失的数据继续使用专用详情，不为追求零请求而塞回列表。

## 9. 验收证据

- Browser Network：打开账户测试弹窗为 0；账户 / API Key 新增无 group/model/route options；编辑只请求必要最小投影；展开单个下拉只出现对应接口。
- HTTP 字段契约：列表、edit-basic、advanced、secret 和 PATCH 响应均有字段白名单 / 黑名单测试。
- SQL / repository 契约：列表和编辑不调用完整 summary mapper，不访问被禁止的统计或关联 loader。
- 写入契约：单字段 PATCH 只改变对应列 / 关联表；相同值 no-op；并发版本冲突不覆盖其他修改。
- 性能采样：固定夹具记录 20 行列表、edit-basic 和单字段 PATCH 的查询数、未压缩 JSON 字节和耗时，保存改造前后证据。
- Node / Vue typecheck、定向回归、生产构建、`git diff --check` 和隔离自动登录 Browser 验证全部通过。
