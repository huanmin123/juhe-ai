# AI 性能与统计窗口渐进加载设计

## 1. 背景

本设计承接 [全站页面 API 按需加载审计报告](../../reports/全站页面API按需加载审计报告-2026-07-20.md) 的剩余 P2，收敛三个仍可独立验收的尾项：

- AI 性能接口当前把默认前 10、临时追加账户、摘要和所有小时序列放在一个 overview 中；每次新增账户都会重新读取并传输默认账户已有序列。
- AI 性能和 IP 统计每次列表加载都以 `force: true` 请求 `usage-window`；AI 性能的初始三日范围在窗口元数据返回前已按浏览器本地日期构造，部署时区与浏览器时区跨日时可能先请求错误日期。
- 表监控 `database-history` 已按视口加载，但 repository 仍选择并映射完整 `DatabaseStorageSnapshotSummary`，图表只消费六个字段。

三个切片共享“只读、小响应、预聚合不退化、作用域与竞态严格隔离”的原则，但不合并成一个运行时接口，也不改变彼此权限。

## 2. 目标

- AI 性能基础请求固定只返回摘要、默认最近 7 天活跃前 10 账户及其序列；临时追加账户仅通过 `series?accountIds=...` 读取缺失序列。
- AI 性能与 IP 统计复用按 admin/self 隔离的 `usage-window` singleflight/短缓存，不再在每次查询时强制刷新。
- 首次使用隐式日期范围时，必须先取得服务端统计时区窗口，再构造三日、今日、近 7 天或近 1 月边界；浏览器本地日界不能作为服务端统计边界的静默替代。
- 表监控历史查询使用专用窄 DTO 和显式列投影，不再读取路径、页大小、页数、空闲页数、已用字节、索引数等图表未消费字段。
- SQLite 同步、SQLite read worker 和 PostgreSQL 保持逐字段等价；前端对 scope、range、accountIds 和 generation 做完整竞态保护。

## 3. 范围与非目标

本批只修改 Node 后端、Vue 前端、测试和相关权威文档。明确不修改 `backend-go/`，不提交、不推送、不部署、不读取或写入生产。

本批不修改统计 schema、窗口刷新频率、统计归属、费用或耗时公式，不新增实时聚合，不改变 IP 统计列表/详情字段，不重做表监控 overview/清理功能，也不扩展 AI 性能到 P95/P99。

## 4. AI 性能基础与追加序列契约

### 4.1 HTTP 端点

管理端和个人端分别使用：

| 用途 | 管理端 | 个人端 |
| --- | --- | --- |
| 基础数据 | `GET /__aisys__/api/stats/ai-performance` | `GET /__aisys__/api/my-stats/ai-performance` |
| 追加序列 | `GET /__aisys__/api/stats/ai-performance/series` | `GET /__aisys__/api/my-stats/ai-performance/series` |
| 账户搜索 | 保留 `GET /__aisys__/api/stats/ai-performance/accounts` | 保留 `GET /__aisys__/api/my-stats/ai-performance/accounts` |

基础端点只接受 `startDate/endDate`，管理端继续接受 `systemAccountId`；若仍传 `accountIds` 则返回 400，避免旧调用方误以为追加序列已加载。追加序列端点接受同一日期和作用域参数，并要求至少一个 `accountIds`。

`accountIds` 的 canonical 编码使用重复裸键，例如 `accountIds=a&accountIds=b`；可兼容现有 query parser 的 bracket 数组。服务端 trim、去重，按首次出现顺序保留，限制 1..20 个；嵌套对象、CSV/JSON 字符串、空 ID、超长 ID 或超过上限均返回 400。

### 4.2 响应 DTO

```ts
interface AiPerformanceBaseResult {
  range: AccountUsageStatsRange
  summary: AiPerformanceSummary
  accounts: AiPerformanceAccount[] // 仅默认前 10
  hourlySeries: AiPerformanceAccountSeries[] // 与 accounts 同序
}

interface AiPerformanceSeriesResult {
  range: AccountUsageStatsRange
  accounts: AiPerformanceAccount[] // 仅合法、可见的请求账户
  hourlySeries: AiPerformanceAccountSeries[] // 按请求 ID 顺序
}
```

- 基础响应的 `accounts` 数量最多 10，全部为既有最近 7 天排行快照选出的默认账户；不再返回 `defaultAccounts/selectedAccounts` 两套重复数组。
- `summary` 仍是当前调用方/管理作用域的完整窗口摘要，不随页面点选账户或追加账户变化。
- 追加端点不返回 summary、默认排行或未请求账户，只读取被请求且当前可见的账户元数据与小时序列。
- 不存在、已删除、已撤销授权、已离开当前管理 owner scope 或其他不可见 ID 静默省略，不能用 404、占位名称或空序列泄漏存在性。
- 搜索 options 只提供候选与标签；任何 `accountIds` 都必须在 series 端点再次执行权威可见性校验。

### 4.3 Node 查询边界

- 基础 loader 固定读取：一个默认 Top10 排行窗口、对应账户元数据、这 10 个账户的 `usage_stats_hourly`、一个 `ai_performance_summary_windows` 摘要。
- series loader 固定读取：请求 ID 的可见账户元数据和对应 `usage_stats_hourly`；不读取默认排行和摘要。
- 两个 loader 使用专用返回类型，禁止调用旧宽 overview 后裁字段，禁止 `SELECT *`，禁止按账户逐个查询。
- 管理全局仍读取 `system_account_id = global` 的 `account` 缓存；指定用户和个人端继续使用当前 `account/caller_account` 权威口径，账号授权实例与授权分组来源账户不能串入资源归属人的自用曲线。
- SQLite read worker 增加明确的 base/series 只读 operation；同步 SQLite、worker 和 PostgreSQL 的默认排序、可见省略、小时补桶和空值规则完全一致。

### 4.4 Vue 合并规则

- 首屏只请求 base，渲染摘要和默认最多 10 条曲线。
- 搜索添加账户时，只为不在当前 base/extra 结果中的 ID 请求 series；一次添加多个账户可合并为一个有界请求。
- 删除追加账户只更新本地集合，不发网络请求；重置清空追加序列并恢复 base。
- 日期、管理 owner 或身份变化后，base 重新加载；仍保留在当前页面状态中的追加 ID 通过一次 series 请求重载新范围，不把旧范围点位复用到新范围。
- base 与 series 按账户 ID 去重；默认账户优先，追加账户保持用户添加顺序。账户由追加变为默认时，不保留两份图例或两份序列。
- base 成功但 series 失败时，默认图表和摘要继续可用；追加区显示局部错误并允许重试，不回退调用旧宽 overview。

## 5. usage-window 缓存与首次时区边界

### 5.1 共享资源

`useUsageStatsWindow` 保留 admin/self 两个独立状态，并形成稳定 key：

```text
viewScope + currentUserId + currentRole + authRevision
```

- 完全相同 key 的并发请求 singleflight；成功结果使用现有约 60 秒短缓存。
- 切换登录身份、角色或 auth revision 后旧缓存不可复用；admin 和 self 不共享值或在途请求。
- 普通页面刷新、筛选、分页和排序调用不传 `force`。显式的全局缓存失效/登录态清理仍可使 generation 增长，但本批页面刷新不把窗口元数据当业务数据强刷。
- 请求失败不能把浏览器 `Intl`/本地日期生成的 fallback 标记为“服务端窗口已加载”。fallback 只可支撑日期控件占位；凡依赖隐式统计边界的首个业务请求必须等待真实窗口或展示可重试错误。

### 5.2 AI 性能首次加载

- 若页面恢复了用户明确选择的合法 `startDate/endDate`，base 可使用该显式范围，同时并行加载 usage-window 以约束日期控件。
- 若没有显式范围，先加载与页面模式一致的 admin/self usage-window，再以其 `endDate` 构造最近 3 天并发出 base 请求。
- 窗口失败时不按浏览器本地“今天”发出首个隐式 base 请求，避免 UTC/Asia-Shanghai 等跨日环境出现一次错误请求后再跳变。

### 5.3 IP 统计首次加载

- IP 统计继续保持现有预聚合列表和点击详情，不改变 list/detail DTO。
- 首次进入或页面状态只有 `today/recent7d/recent1m` 枚举而没有显式日期时，先取得 admin usage-window，再以服务端 `endDate` 计算范围并请求 list。
- 后续分页、排序、筛选和刷新复用有效窗口缓存，直接与 list 并行或立即计算，不重复强制请求 usage-window。
- `recent1m` 保持当前 31 个自然日（结束日及向前 30 日）语义；所有边界使用服务端统计时区日期键，不使用浏览器偏移推导。

## 6. 表监控 history 窄投影

新增专用 `DatabaseStorageHistoryPoint`，不再让 history 接口复用 overview 的宽 `DatabaseStorageSnapshotSummary`：

```ts
interface DatabaseStorageHistoryPoint {
  databaseRole: MonitoredDatabaseRole
  sampledAt: string
  fileBytes?: number
  walBytes?: number
  freeBytes?: number
  tableCount?: number
}
```

history 响应严格为 `databaseRole/sampledAt/fileBytes/walBytes/freeBytes/tableCount` 六字段。当前 history 图只用主库与 WAL 形成历史占用曲线，并在 tooltip 展示空闲字节与表数；`shmBytes` 属于 overview 当前快照口径，不进入 history DTO。前端 history 图必须使用专用计算函数，不能继续调用依赖 overview 宽字段的 `totalDatabaseBytes`。

- SQLite 和 PostgreSQL SQL 显式选择上述列；禁止读取 `database_path/page_size/page_count/freelist_count/used_bytes/index_count`。
- repository 使用 history 专用 row mapper；不能继续调用完整 `databaseSnapshotFromRow` 后删除字段。
- read-worker operation 和 HTTP typed API 改用专用 DTO，前端图表函数只接受该类型。
- 每个数据库角色仍各自执行有界 `ORDER BY sampled_at DESC, id DESC LIMIT ?`，最终按时间稳定升序合并；不改变当前每角色 limit 语义。
- 视口触发边界继续保留；范围或手动刷新产生新 generation，旧成功/失败不得覆盖当前图表或结束当前 loading。

## 7. 缓存、签名与竞态

### 7.1 后端缓存

- AI base 与 series 在页面内使用不同请求 generation；不恢复已退场的通用 page-data cache。请求签名至少包含 admin/self、有效 viewer/owner scope、auth revision、归一化 range；series 额外包含按首次出现顺序去重后的 ID signature。
- options 继续使用独立缓存，不与 base/series 共享 DTO。
- usage-window 使用前端短缓存/singleflight，不新增长期服务端缓存。
- table-monitor history 保持有界快照查询，不新增跨请求 TTL 缓存，避免当前结束范围内的新采样被隐藏；前端可在同一页面 generation 内复用完全相同 range/limit 的成功结果和在途请求。

### 7.2 前端资源签名

```text
scopeSignature = routeMode + effectiveSystemAccountId + currentUserId + role + authRevision
rangeSignature = normalizedStartDate + ':' + normalizedEndDate
baseSignature = scopeSignature + '|' + rangeSignature
seriesSignature = baseSignature + '|' + orderedUniqueAccountIds
historySignature = normalizedStartAt + ':' + normalizedEndAt + ':' + limit
```

- scope、range、账户集合、窗口枚举、身份、手动刷新或路由模式变化时递增相应 generation。
- 请求提交时捕获 signature 和 generation；迟到成功、迟到失败、finally 都只能影响发起它的资源状态。
- 覆盖 A→B、A→B→A、同 key singleflight、失败重试、卸载/失活、base/series 交错和 usage-window 晚到场景。
- series 的局部 loading/error 不复用 base loading；table history 的 loading/error 不影响 overview 表格。

## 8. 权限与安全

- AI 性能管理端保持 admin/super_admin 权限；个人端强制当前登录用户。管理端 `systemAccountId` 只缩小现有范围，个人端查询参数不能扩大范围。
- series 不可见 ID 静默省略；响应顺序仅针对可见项，不返回拒绝原因或账户存在性。
- IP 统计和表监控继续沿用现有管理权限及统一鉴权，不因缓存或前端复用绕过服务端授权。
- 所有响应均不包含 credential、secret、notes、授权明细或原始 usage record。

## 9. 预聚合不变量

- AI base/series 只读 `usage_rank_snapshots`、`usage_stats_hourly`、`ai_performance_summary_windows` 和必要账户/授权元数据；禁止实时扫描或 `GROUP BY usage_records`。
- IP list/detail 继续读取现有 client-IP 预聚合窗口；去掉 `force` 仅减少窗口元数据 RTT，不触发刷新 worker，也不改 `rangeReady` 语义。
- 表监控 history 只读 `database_storage_snapshots`；不得回退实时数据库文件扫描、`dbstat`、全表统计或 overview 宽 loader。
- 本批不新增表、物化缓存、Redis 聚合或第二套 worker。现有窗口缺失时继续明确返回空/未就绪，不用请求时临时聚合补齐。

## 10. 测试与验收

### 10.1 Node

- HTTP/parser：base 明确拒绝旧 `accountIds`；series 覆盖重复裸键/bracket、trim、去重、1/20/21、空值、CSV/JSON、嵌套和超长边界。
- DTO：base 最多 10 个默认账户且无重复数组；series 只含请求的可见账户且无 summary/default 排行；表 history 精确专用字段。
- 权限：AI 管理全局/指定 owner、个人 self、自有/授权/授权分组来源、撤销授权、伪造 scope、不可见/不存在 ID 省略；IP/表监控普通用户保持 403。
- Query guard：base/series 分离、无旧 overview 裁剪、无 `usage_records`、无 N+1；table history 显式窄列且无宽 mapper。
- SQLite 同步/read worker 对 base、series、history 逐字段等价，错误可传播且 worker 不回退主线程宽查询。
- 真实 PostgreSQL smoke 写入排行、摘要、小时桶和数据库快照样本，验证 scope/range、默认 10、series 省略/顺序、history 精确六字段、空窗口和稳定排序；环境缺失产生的 SKIP 不计通过。

### 10.2 Vue

- AI 首屏只请求一次 usage-window（缓存未命中时）和一次 base，不请求 series；base 响应最多渲染 10 个账户。
- 添加第 11 个账户只请求 series 且不重取 base；重复/默认账户不请求；批量添加、删除、重置、日期/owner 切换均符合合并规则。
- AI/IP 普通刷新、筛选、分页和排序不带 `force`；缓存命中不产生 usage-window 网络请求。
- 首次隐式范围在真实 usage-window 前不发业务请求；模拟浏览器与服务端跨日/跨时区，最终 start/end 只由服务端窗口计算。
- table history 仍只在视口触发，收到的六字段 DTO 可保持主库加 WAL 的历史曲线、空闲和表数 tooltip 不变。
- 覆盖 scope/range/generation、A→B→A、旧成功/失败、并发 singleflight、失败重试、卸载和 auth revision 变化。

### 10.3 测试夹具漂移修复

- 现有 AI 性能 query guard/PG smoke、usage-window 与 table-monitor fixture 若仍按旧 overview 字段、旧账户/profile 必填项或旧数据库快照宽类型构造数据，必须同步到当前生产 schema 和新 DTO。
- 夹具修复应复用当前正式创建入口、provider protocol profile、统计时区和窗口 key 生成器；不得通过放宽生产校验、加入测试专用降级、恢复宽 DTO 或伪造缓存命中让测试通过。
- 对历史 fixture 的每项修复记录“旧假设、当前事实、修复证据”，避免把 fixture 漂移误判为功能回归或把真实回归误判为 fixture 问题。

### 10.4 门禁与复核

- Node/Vue 专项、后端 typecheck、可运行范围内的前端 typecheck/build、`git diff --check`。
- 既有 AI 性能账户 options、小时查询、统计窗口、IP list/detail、table-monitor overview/history/PG smoke 和 page-data revision 回归不退化。
- 浏览器网络验证 AI 首屏/新增账户、IP 首屏/分页、表 history 视口；Browser/Playwright 不可用时明确记录环境限制。
- 至少两名只读 Agent 分别复核权限/SQL/worker 与 Vue 缓存/竞态/时区，并交叉质疑后闭合高严重度问题。

## 11. 完成标准

- AI base 永远只承载默认最多 10 个账户，新增账户只通过 series 按 ID 补充，且权限省略和摘要口径无回归。
- AI/IP 不再反复强制获取 usage-window，首次隐式日期有服务端时区证据，不会先发浏览器本地日界请求。
- table-monitor history SQL、worker、HTTP 和 Vue 全链路使用专用窄投影，同时保持现有图表数值和 tooltip。
- 所有路径继续只读既有预聚合窗口；SQLite worker、真实 PostgreSQL、前端竞态和浏览器请求矩阵证据全部闭合后，才能标记专项完成。
