# 本地 Git 主线收敛与安全清理设计

## 背景

仓库当前同时保留大量历史任务分支、备份分支、并行审查分支、失效 worktree 登记和 stash。Git 拓扑审计确认：部分分支只是 cherry-pick、squash 或 rebase 后留下的旧引用，但仍有分支保存了 `master` 中不存在的代码、测试和生产运维修复。因此不能把 `git branch --no-merged master` 直接等同于“应合并”或“可删除”。

本设计只治理本地 Git 主线和本地引用，不执行生产部署，不删除远端分支，不覆盖其他任务正在进行的未提交修改。

- 本地分支 285 条：133 条已按拓扑进入 `master`，152 条未按拓扑进入。
- 未合并分支互斥分类：补丁等价或仅拓扑不同 58 条、tip 已由其他 ref 保存 5 条、疑似同标题改写 30 条、退役 page-data 或历史文档 34 条、仍有未证明已吸收的代码或测试 25 条。

## 目标状态

1. `master` 包含经当前架构复核后仍有效的独有修复，并通过对应回归、类型检查和构建。
2. 用户明确选择不生成离线 bundle；因此只删除能由 Git 机械证明已合入、补丁等价或由其他保留 ref 完整承载的引用。
3. 脏 worktree 不自动归类为不活跃，也不删除；没有备份时不以目录时间或分支名称推断其内容可丢弃。
4. 失效 worktree 登记被清理；已合并或已证明冗余的本地分支分批删除。
5. 仍未完成语义复核的高风险分支保留，不以“界面整洁”为由强制删除。
6. 最终 `master` 与 `origin/master` 的领先/落后关系明确，仓库对象连通性正常，工作树状态可解释。

## 非目标

- 不整体 merge 明显落后主线的性能候选分支。
- 不恢复已退役的 page-data confirm/revision 机制。
- 不把生产切流、数据库升级或数据清理作为本地 Git 治理的隐含副作用。
- 不删除任何远端分支、tag、stash 或用户未提交内容。
- 不在缺少真实环境证据时宣称生产部署已验证。

## 恢复边界

- 不生成 bundle、archive tag 或脏文件副本，这是用户明确选择的清理约束。
- 精确拓扑已合入的分支只使用 `git branch -d`，让 Git 自身拒绝危险删除。
- patch-id 等价分支只在不存在独有 merge resolution 时进入强制删除候选。
- 重复指针只在另一个明确保留的本地或远端 ref 包含同一 tip 时删除。
- `feature/*`、脏 worktree 对应分支和高风险分支全部保留。
- 强制删除后的短期恢复只能依赖 reflog 或仍未回收的对象，不作为可靠备份承诺。

## 独有修复集成策略

### 近期性能拓扑分支

`codex/performance-topology-hotfix-20260726` 落后当前主线数百提交，不允许整体 merge。按主题审计并移植：

- usage spool 停止竞态和对应回归；
- 多进程拓扑脚本的并发、排空和回滚边界；
- 当前仍适用的验收脚本；
- 运行日志保留测试与现行封装的对齐。

### 生产预演分支

`codex/performance-production-rehearsal-20260727` 按独立主题复核：

- PostgreSQL 前向 schema 升级和业务数据逐表对账；
- Nginx 非幂等/流式请求禁止透明重试；
- 明确 Nginx binary 与主配置路径；
- LaunchDaemon 服务用户边界；
- PostgreSQL smoke 异步 session 接口；
- 模型检测基础连通和可信对比评分；
- BUG-0128 至 BUG-0133 的当前主线适用性。

每个主题先复现或用源码证据定位，再基于最新主线重新实现。旧分支代码只作为证据来源，不直接覆盖当前实现。

### 其余高风险分支

- 以“唯一提交 -> 当前文档事实 -> 当前代码 -> 当前测试”建立四向映射。
- 相同主题的多个分支先选出后续演化版本，再判断是否仍缺失。
- 已被当前实现替代的分支记录替代证据；无法证明的分支继续保留。

## 清理分级

1. 第一批：203 个失效 worktree 登记。只运行 `git worktree prune`，不删除实际目录。
2. 第二批：已按拓扑合入 `master` 的非 `feature/*` 分支。只使用 `git branch -d`；仍被有效 worktree 占用时先跳过。
3. 第三批：56 条存在 patch-id 等价项且无独有 merge resolution 的分支，以及由其他保留 ref 完整保存的重复指针；排除 `feature/*` 和脏 worktree 对应分支。
4. 第四批：疑似 squash/amend 和退役基线分支。先建立 archive 清单并人工复核，不与前三批混删。
5. 禁止批次：25 条高风险分支，直到独有修复已集成或有明确替代证据。

## 历史闭合

- 有效的 Go 迁移已提交 tip 使用普通合并，不使用内容中性策略。
- 已选择性重实现、已被后续替代或明确废弃的旧 tip，按处置类别分组执行 `git merge --no-ff -s ours`。禁止使用 `-X ours`。
- 每组合并使用冻结后的精确 SHA，不直接信任可变分支名；合并前后 `HEAD^{tree}` 必须完全相同。
- 已注册且存在未提交内容的 worktree 不删除。其已提交 tip 成为 `master` 祖先后不再构成历史分叉，但分支名和工作目录继续保留。
- `feature/*` 分支名始终保留；远端分支不删除。
- 最终“无分叉”的机械范围为本地 heads、remote-tracking heads、tags 和 worktree HEAD；`refs/stash` 与 `refs/codex/snapshots/*` 是未提交工作的保护 ref，不写入主线历史。

## 验证与完成标准

- 每个移植主题运行最小回归，再运行后端/前端 `typecheck`；影响构建或发布脚本时运行 `build` 和脚本专项。
- 网关、流式、模型检测、数据库升级、部署脚本分别覆盖成功、失败、取消/中断、重复执行和回滚边界。
- 清理后运行 `git fsck --connectivity-only --no-dangling`、分支分类复算和 worktree 列表复算。
- 最终复查需求完整性、并发安全、错误与回滚路径、文档事实、过度设计和未验证假设。
- 只有有效修复进入主线、测试通过且分支清理结果可解释时，计划才能标记完成。
