# Google 欺骗性网页告警安全修复设计

## 1. 背景与结论

Google Search Console 当前将以下管理端页面标记为 `Deceptive pages`：

- `https://aijh.huanmin.top/__aisys__/`
- `https://aijh.huanmin.top/__aisys__/login?redirect=/`

截至 2026-07-19 的线上核查没有发现当前恶意内容、外部脚本、下载诱导、页面伪装、Googlebot 差异、字符串执行、跨域凭据读取或六个 Edge 内容漂移。浏览器开发工具中的 CSP `eval` 告警来自扩展注入，不是站点产物。当前证据无法证明 Google 的历史触发点；告警可能来自已经消失的历史状态、自动分类误判或登录页安全信号不足，最终仍需在清理和加固后提交人工复审。

本次不把安全响应头描述成唯一根因。它们用于消除当前可确认的管理面安全缺口，并为 Google 复审提供可验证的清理证据。

## 2. 目标

1. 不改变登录页视觉、文案、表单、验证码和登录流程。
2. 不改变管理员开户、用户注册、初始密码、现有密码规则、账户数据或会话。
3. 为 `/__aisys__` 管理面提供与当前前端能力匹配的 CSP 和浏览器安全响应头。
4. 移除 Express 技术栈响应标识。
5. 不改变 `/v1` 网关请求、DNS、WireGuard、Caddy、Nginx 和六个 Edge 的转发关系。
6. 通过自动化测试、本地构建、生产预检、Mac 发布和六入口验收证明功能未受影响。
7. 在完成线上验收后准备 Google Search Console 复审；提交复审仍需用户在动作发生前确认。

## 3. 非目标

- 不重做登录页或增加身份说明文案。
- 不新增用户自助注册。
- 不修改默认管理员初始化或密码强度策略。
- 不增加 `unsafe-eval`。
- 不调整 TLS 证书、域名解析、Edge 权重或反向代理拓扑。
- 不借机处理运行日志 Redis 超时等其他运维问题。

## 4. 响应头设计

### 4.1 管理面 CSP

仅对 `/__aisys__` 路径设置以下策略：

```text
default-src 'self';
base-uri 'self';
object-src 'none';
frame-ancestors 'none';
form-action 'self';
script-src 'self';
style-src 'self' 'unsafe-inline';
img-src 'self' data: blob: https:;
font-src 'self' data: https:;
connect-src 'self' https: wss:;
worker-src 'self' blob:;
media-src 'self' data: blob: https:;
manifest-src 'self'
```

约束说明：

- `script-src 'self'` 是核心限制，只允许当前站点脚本，不允许内联脚本和字符串执行。
- Ant Design Vue 和现有组件会写入内联样式，因此保留 `style-src 'unsafe-inline'`；该放宽不适用于脚本。
- HTTPS 图片、`data:`、`blob:`、Worker、媒体以及 HTTPS/WSS 连接保留，避免影响图标、聊天、图片和实时连接能力。
- `frame-ancestors 'none'` 只禁止其他站点把管理后台嵌入 iframe，不影响正常打开、OAuth 新窗口或站内路由。
- 不添加 HSTS、COOP、COEP 或更严格的跨域资源策略，避免把证书拓扑、OAuth 和媒体兼容性扩大到本次修复范围。

### 4.2 其他响应头

管理面同时设置：

- `X-Frame-Options: DENY`：为不支持 `frame-ancestors` 的浏览器提供防嵌套兜底。
- `X-Content-Type-Options: nosniff`：阻止错误 MIME 类型被当作脚本或样式执行。
- `Referrer-Policy: strict-origin-when-cross-origin`：跨站只发送 Origin，不泄露管理端完整路径。

应用全局执行 `app.disable('x-powered-by')`，移除 `X-Powered-By: Express`。这只删除响应标识，不改变路由或响应体。

## 5. 实现边界

- 在 `backend/src/shared/http-security.ts` 增加纯函数或中间件，集中生成并写入管理面安全头，避免在静态资源和 SPA fallback 中重复常量。
- 在 `backend/src/server.ts` 的 `/__aisys__` 路由之前挂载管理面安全头，并关闭 Express 标识。
- 不修改前端页面；构建产物继续由现有 `express.static` 和 SPA fallback 提供。
- 不修改 Caddy、Nginx 或 Edge 配置。六入口共享 Mac 主应用响应头。
- 不新增第三方依赖；使用 Express 和 Node 现有能力。

## 6. 数据流与错误处理

请求进入 Mac 主应用后，`/__aisys__` 安全头中间件先写入响应头，再由健康检查、System API、静态资源或 SPA fallback 生成原有响应。中间件不读取请求体、不访问数据库、不异步等待，也不改变状态码和响应体。

安全头是固定常量，不存在运行时外部依赖。若后续前端引入新的外部脚本或资源类型，构建和浏览器 CSP 验收必须先失败，再显式评估是否扩展白名单；不得加入 `unsafe-eval` 掩盖问题。

## 7. 测试与验收

### 7.1 自动化测试

- 为安全头生成逻辑增加回归测试，逐项断言 CSP 指令和其他响应头。
- 断言 CSP 不包含 `unsafe-eval`、通配脚本源或外部脚本源。
- 断言 `/__aisys__/` 与 SPA 登录路径返回安全头。
- 断言 `/v1` 不被管理面 CSP 中间件改变。
- 断言响应不再包含 `X-Powered-By`。
- 运行相关回归、`pnpm typecheck` 和 `pnpm build`。

### 7.2 本地浏览器验收

- 登录页桌面和移动端布局不变。
- 控制台无站点 CSP violation。
- 验证码图片正常加载和刷新。
- 登录请求、会话 Cookie、登录后路由和静态资源正常。
- 不使用浏览器扩展注入产生的 CSP 告警判断站点结果；必要时使用独立 Playwright 上下文复核。

### 7.3 生产验收

- 按部署计划锁流程发布 Mac 新 release，不直接覆盖当前 release。
- 切换前验证本机候选健康检查、管理页、验证码、响应头和 `/v1` 基线。
- 切换后逐个验证六个 Edge 返回同一 ETag/资源版本和安全头。
- 验证 DNS、WireGuard、Caddy/Nginx 上游、管理登录和 `/v1` 请求未改变。
- 检查新 release 日志没有 CSP 相关服务端错误、静态资源 404 或登录异常增长。
