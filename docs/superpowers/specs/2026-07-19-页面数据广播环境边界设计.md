# 页面数据广播环境边界设计

## 背景

`BrowserPageDataTabCoordinator` 默认使用全局 `BroadcastChannel`。Node.js 22 同样提供该全局对象，导致前端回归脚本在 Node 环境误创建广播通道和心跳定时器。脚本断言完成后仍持有 `MessagePort` 与 `Timeout`，进程无法自然退出。

## 决策

- 未显式提供 `channelFactory` 时，只在存在浏览器 `window` 且支持 `BroadcastChannel` 的环境自动创建广播通道。
- 浏览器中的多标签页 leader、确认交接和缓存失效广播行为保持不变。
- Node.js、SSR 和无浏览器全局对象的测试环境默认退化为单实例协调，不创建后台句柄。
- 显式注入 `channelFactory` 的测试和调用方不受环境判断影响，仍可完整验证多标签页协议。

## 备选方案

1. 在回归脚本末尾调用 `process.exit()`：能结束测试，但会掩盖默认协调器在非浏览器环境误启用的问题，不采用。
2. 增加仅供测试使用的全局 reset/close API：可以释放句柄，但扩大公开维护面，且要求每个调用方记住清理，不采用。
3. 在默认工厂选择处增加真实浏览器环境边界：修复根因、改动最小，采用。

## 验证

- `pnpm --dir frontend run test:page-data-option-cache` 必须打印通过信息并以退出码 `0` 自然结束。
- `pnpm --dir frontend run test:page-data-cache` 必须继续通过，证明显式注入的标签页协调器测试不受影响。
- `pnpm --dir frontend run test:page-data-resource-cache` 必须继续通过并自然退出。
- 前端类型检查、全仓 lint 与构建必须通过。

## 范围

本次只调整页面数据标签页协调器的默认 channel factory 选择条件，不改变缓存键、缓存内容、确认协议、失效协议或服务端接口。
