# 首页统计渐进加载设计

## 1. 背景

首页统计当前通过一个 `usage-overview` 请求同步返回 `summary`、`hourlyTrend`、`modelDistribution` 和 `errors`。Node PostgreSQL 已使用 `Promise.all` 并行读取四类预聚合窗口，但页面仍需等待四个结果全部完成后才能展示摘要卡片，也会为尚未进入视口的三张图提前读取数据。

本设计承接 [全站页面 API 按需加载审计报告](../../reports/全站页面API按需加载审计报告-2026-07-20.md) 的首页统计 P1，只拆分首页统计读链路，不改变统计口径、预聚合表或 worker 写入语义。

## 2. 目标

- 首页首屏只等待 summary，摘要卡片不再被任一图表查询阻塞。
- 小时趋势、模型分布和错误 TopN 使用三个独立端点，仅在对应图表进入视口后加载。
- 四个端点使用同一 scope、日期归一化和 range 契约，前端只合并当前 scope/range/generation 的结果。
- SQLite 同步路径、SQLite read worker 和 PostgreSQL 返回语义一致。
- 所有端点只读现有 worker 预聚合窗口，不回扫 `usage_records`，不在请求路径执行临时业务聚合。

## 3. 范围与非目标

本批只修改 Node 后端、Vue 前端、测试和后续权威文档，不修改 `backend-go/`，不提交、不推送、不部署、不触碰生产。

本批不处理用量统计、AI 性能、授权用量、表监控、系统指标或其他页面；不修改 schema、统计 worker 调度、窗口刷新频率、统计归属和费用口径。

## 4. HTTP 契约

管理端和个人端分别提供以下端点：

| 区块 | 管理端 | 个人端 |
| --- | --- | --- |
| 摘要 | `GET /__aisys__/api/stats/usage-overview/summary` | `GET /__aisys__/api/my-stats/usage-overview/summary` |
| 小时趋势 | `GET /__aisys__/api/stats/usage-overview/hourly-trend` | `GET /__aisys__/api/my-stats/usage-overview/hourly-trend` |
| 模型分布 | `GET /__aisys__/api/stats/usage-overview/model-distribution` | `GET /__aisys__/api/my-stats/usage-overview/model-distribution` |
| 错误 TopN | `GET /__aisys__/api/stats/usage-overview/errors` | `GET /__aisys__/api/my-stats/usage-overview/errors` |

四个端点共同接受 `startDate/endDate`；管理端额外接受既有 `systemAccountId` scope，个人端始终使用当前登录用户，不能由查询参数扩大作用域。日期继续由 Node 的统一统计日期归一化逻辑校验，最大窗口和部署时区语义保持不变。

响应分别为：

```ts
interface UsageOverviewSummaryResult {
  range: AccountUsageStatsRange
  summary: UsageOverviewSummary
}

interface UsageOverviewHourlyTrendResult {
  range: AccountUsageStatsRange
  hourlyTrend: UsageOverviewHourlyPoint[]
}

interface UsageOverviewModelDistributionResult {
  range: AccountUsageStatsRange
  modelDistribution: UsageOverviewModelRow[]
}

interface UsageOverviewErrorsResult {
  range: AccountUsageStatsRange
  errors: UsageOverviewErrorRow[]
}
```

每个响应必须回显服务端归一化后的完整 `range`。四个窗口允许由 worker 在不同时间提交，因此不声明跨端点事务快照；前端只要求 scope 和归一化 range 一致，不能把不同范围的结果拼接。

现有 `GET .../usage-overview` 组合端点暂时保留兼容，不改变字段和权限，但 Vue 首页及其 typed API 不再调用它。兼容入口不得成为新代码依赖；后续确认所有调用者迁移后再作为独立 P2 删除。

## 5. Node 存储与缓存边界

- 为 summary、hourly trend、model distribution、errors 提供独立 repository 读函数；每个函数只选择对应预聚合窗口所需列。
- PostgreSQL 不再为了单一区块调用四窗口组合 loader；每个 HTTP 请求只发起自身查询。
- SQLite read worker 增加四个明确 operation，响应与同步 SQLite 逐字段一致，不能退回主线程宽组合读取。
- 页面数据读缓存按区块拆分 domain/key；key 至少包含路由区块、权限 scope、归一化 `startDate/endDate` 和数据 revision。不同用户、管理全局与指定用户不得共享结果。
- 保留组合 loader 仅服务兼容端点，其实现仍只读预聚合窗口；不得让新端点经组合 loader 读取后再裁字段。

## 6. Vue 数据流与竞态

### 6.1 首屏

- 页面得到可用统计日期范围后立即请求 summary；摘要卡片只受 summary loading/error 控制。
- 三个图表区块各自建立视口观察。区块首次接近或进入视口时才发起对应请求，同一 scope/range 下只加载一次。
- 图表失败只影响自身空态和重试，不清空已成功的 summary 或其他图表。

### 6.2 签名与 generation

每次页面查询上下文形成稳定签名：

```text
scopeSignature = routeMode + effectiveSystemAccountId + authRevision
rangeSignature = normalizedStartDate + ':' + normalizedEndDate
resourceSignature = scopeSignature + '|' + rangeSignature + '|' + section
```

- `routeMode` 区分管理端和个人端；管理全局使用明确 sentinel，不能与空值或当前用户混淆。
- 筛选用户、日期、路由模式、登录身份或 auth revision 变化时递增统一 generation，并立即使旧区块失效。
- 请求提交时捕获 generation、scope signature 和 range signature；三者任一不匹配时，迟到成功或失败都不得写入当前页面。
- A→B→A 不能复用 A 的旧在途请求；页面卸载、失活或手动刷新后旧请求也不能结束当前 loading。
- 手动刷新递增 generation：summary 立即重取；已进入视口的图表重取，尚未进入视口的图表仍保持未加载。

## 7. 权限与错误

- 管理端沿用 admin/super_admin 权限；普通用户访问管理端返回 403。
- 个人端只读当前登录用户 scope，忽略或拒绝伪造的 `systemAccountId`，不得发生横向读取。
- 参数非法返回 400；查询失败沿用统一 500 错误模型。
- 单一区块失败不降级调用兼容 overview，也不触发另外三个区块请求。

## 8. 预聚合与 worker 不变量

- summary 只读 `usage_overview_summary_windows`。
- hourly trend、model distribution、errors 只读各自现有首页统计窗口表。
- API、repository、SQLite worker 和 PostgreSQL 路径禁止读取或聚合 `usage_records`，禁止在请求路径从日行或其他区块重新 `SUM/GROUP BY` 生成摘要。
- 既有 stats/background worker 继续负责刷新四类窗口；本批不新增第二套聚合表、刷新 worker、Redis 聚合或前端汇总。
- 窗口重建和增量刷新回归必须继续证明四类窗口可独立读取，并保留相同 range/统计 scope。

## 9. 测试与验收

### 9.1 Node

- HTTP：四端点精确字段、统一 range、日期校验、管理/个人权限、管理全局与指定用户 scope。
- Query guard：每个端点只查询自身窗口和列；新端点不调用组合 loader，不读取 `usage_records`。
- SQLite：同步路径与四个 read-worker operation 逐字段等价。
- PostgreSQL：真实 smoke 写入四类窗口样本，分别验证结果、scope 隔离、空窗口和稳定排序，运行结果不得以 SKIP 冒充通过。
- 兼容 overview 回归继续通过，且前端请求矩阵证明首页不再调用它。

### 9.2 前端

- 首屏仅请求一次 summary，三个图表端点均为 0 次。
- 三个图表分别进入视口时只请求自身端点；重复进出视口不重复请求。
- 图表独立 loading/error/retry，任一失败不阻塞或清空其他区块。
- 覆盖 scope/range 切换、A→B→A、旧成功、旧失败、手动刷新、卸载和身份 revision 变化。
- 浏览器网络验证桌面与移动端首屏及滚动行为；若 Browser/Playwright 不可用，明确记录环境限制。

### 9.3 门禁

- Node 与 Vue 专项回归、后端 typecheck、可运行范围内的前端 typecheck/build、`git diff --check`。
- 既有统计窗口刷新、首页 PG 并行读取兼容回归和 page-data revision 回归不退化。
- 至少两名只读 Agent 独立复核，覆盖契约、权限、SQL、worker、竞态和测试证据。

## 10. 完成标准

- 摘要卡片先于图表可独立完成，首屏网络不请求未进入视口的图表数据。
- 每个图表端点只读取自身预聚合窗口，失败互不阻塞。
- 不同 scope/range/generation 的响应不会混合，管理和个人权限无回归。
- SQLite worker、PostgreSQL smoke、前端请求矩阵和竞态测试形成完整证据；仅有类型检查或源码搜索不算完成。
