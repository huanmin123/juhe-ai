# 低风险接口收敛设计

## 1. 背景

本设计承接 [全站页面 API 按需加载审计报告](../../reports/全站页面API按需加载审计报告-2026-07-20.md) 中剩余的低风险 P1/P2 收尾项。它们共同的问题是重复请求、过宽响应、已无调用的前端入口或未纳入命令门禁的现有回归，不需要新 schema、新缓存服务或网关语义变更。

当前事实：

- 登录页和应用壳分别请求公开品牌设置，`useAppBrand` 没有 loaded cache 或 in-flight singleflight。
- `POST /auth/login` 和 `POST /auth/change-password` 返回完整系统账户对象，前端实际以 `CurrentUserSummary` 消费；`GET/PATCH /auth/me` 已是窄投影。
- `GET /my-chat/api-keys` 仍先走完整 API Key 管理列表查询后再裁成 `id/name/status`，但 Vue 聊天已使用后端默认 Key，仓库内没有实际调用。
- 公告管理列表/详情已分层，但 create/update/publish/unpublish 仍返回完整 `AnnouncementSummary`，页面成功后会重新加载列表，不使用宽响应。
- 团队/用户授权用量页各保留一组 `loadOptions/loadOptionsNow/optionsLoaded/optionsLoading`，但交互已由各下拉自身的按需 loader 承担，聚合 loader 没有调用点。
- Node 已有 `external-integration-source-lightweight-http-regression.ts`，但尚未注册到 package/root 回归命令；前端 `externalIntegrationSourcesApi.updateToken` 没有调用点，而 Node token PATCH 是完整的管理能力，不能只因 Vue 未用就判定后端死接口。

## 2. 总体目标与边界

- 把五组小改动拆为可独立确认、实施、验收和回滚的阶段，不以一次大改换取表面上的收尾。
- 只修改 Node 后端、Vue 前端、专项测试和实施后需同步的权威文档。
- 不修改 `backend-go/`，不提交、不推送、不部署、不访问或变更生产。
- 不改 schema、授权口径、聊天默认 Key 选择、公告发布/已读语义、外部来源 token 权限或密钥安全边界。

## 3. Breaking 确认门禁

本设计仍为草稿。以下变更对调用方可见，实施前必须获得用户对对应阶段的明确确认：

1. 登录/改密响应由完整系统账户收窄为 `CurrentUserSummary`。
2. 删除 `GET /my-chat/api-keys` 及对应前端 method/type。
3. 公告写操作改为轻响应。
4. 删除无调用的前端 `externalIntegrationSourcesApi.updateToken`。

品牌 singleflight/cache、删除授权用量页本地死 loader、注册现有外部来源回归本身不改 HTTP 业务契约，仍应在同一阶段确认中列明。未获确认的阶段不实施，不以其他阶段的确认作为默认授权。

## 4. 阶段 A：品牌 singleflight/cache 与认证投影

### 4.1 品牌加载

- `useAppBrand` 只保留一个公开加载入口，登录页和应用壳共用同一资源。
- 首次请求期间保存 in-flight Promise；并发调用共用一次 `GET /settings/public`。成功后保留会话内 loaded cache，从登录页进入壳层不重复 RTT。
- 失败必须清除 in-flight，下次调用可重试；失败时继续显示本地默认品牌，不把 rejected Promise 永久缓存。
- 管理员成功保存全局品牌后，用服务端返回值同步更新品牌 cache 和 document title/icon，避免当前会话再读到旧值。
- 缓存不持久化到 IndexedDB/localStorage，不跨页面刷新承诺实时性；服务端公开设置缓存语义保持不变。

### 4.2 登录与改密

- `POST /auth/login`、`POST /auth/change-password`、`GET /auth/me` 和 `PATCH /auth/me` 统一返回现有 `CurrentUserSummary` 五字段：`id/username/displayName/role/mustChangePassword`。
- Node 统一通过 `currentUserSummary(...)` 投影，不在路由中复制字段列表。`login` 不再返回 `status/description/imageGenerationEnabled/lastLoginAt/createdAt/updatedAt` 等完整账户字段，`change-password` 不再返回完整 account。
- session cookie、登录限流、验证码、密码规则、其他会话撤销和 `mustChangePassword` 流程保持不变。
- Vue API 和 `useAuth` 已以 `CurrentUserSummary` 建模，实施时需增加精确字段 HTTP 回归，不以 TypeScript 宣称替代真实响应检查。

### 4.3 独立验收与回滚

- 验收：登录页与壳层并发/顺序加载只产生一次公开品牌请求；失败可重试；保存品牌后缓存与 DOM 同步；四个认证端点精确返回 `CurrentUserSummary`。
- 回归：覆盖 singleflight、成功 cache、失败重试、登录→壳层、品牌保存，以及 login/change-password/me/update-profile 字段集和会话主流程。
- 回滚：品牌资源改动可单独撤回；认证投影可单独恢复原响应，不涉及 schema/session 数据迁移。

## 5. 阶段 B：删除 Chat API Key 死 GET

- 删除 `GET /__aisys__/api/my-chat/api-keys` 路由和它为完整 API Key 列表引入的 `listApiKeysAsync` 依赖。
- 删除 `chatApi.listApiKeys`、`ChatApiKeyOption` 类型及只服务该入口的 export/import；实施前用 `rg` 再次证明仓库内无调用。
- 保留聊天会话内部的 `findChatApiKeySecretAsync` 和默认 GPT Key 选择；不删除 `chat-api-key.repository.ts`，因其仍服务会话创建、模型访问和上下文压缩。
- 不增加“先留着但改成窄 SQL”的兼容分支；该入口已被审计为无调用死契约，用户确认 breaking 后直接删除。
- 独立验收：路由返回 404，前端 API/type 无残留，新建会话继续绑定后端默认 Key，聊天模型和发送回归通过。
- 回滚：恢复单个 route/method/type 即可，无数据变更。

## 6. 阶段 C：公告 mutation 轻响应

- create/update/publish/unpublish 成功响应统一为 `AnnouncementMutationResult`：

```ts
interface AnnouncementMutationResult {
  id: string
  updatedAt: string
}
```

- create 保持 201，update/publish/unpublish 保持 200；delete 保持无业务实体的成功响应，不为一致性额外返回完整公告。
- repository/service 仍可在服务端内部返回完整对象以完成操作日志和公告变更事件；收窄点只在 HTTP 边界，不为轻响应牺牲审计或发布语义。
- Vue API 类型改为轻响应；页面保持成功后失效详情缓存并重载列表，不用 mutation 响应伪造最新列表行。
- mutation guard 的重放响应必须与新契约一致；详情和公开公告列表/正文契约保持不变。
- 独立验收：四个写操作精确只返回 `id/updatedAt`，页面仍能创建、编辑、发布、下线、删除并看到权威列表结果，公共变更通知和操作日志不退化。
- 回滚：恢复 HTTP serializer 和前端返回类型，无 schema 或数据迁移。

## 7. 阶段 D：删除授权用量页死 options loader

- 在 `AuthorizationTeamUsageView.vue` 和 `AuthorizationUserUsageView.vue` 删除无调用的 `loadOptions`、`loadOptionsNow`、`optionsLoaded`、`optionsLoading` 及由它们独占的 import/state。
- 保留每个下拉的首次展开/搜索 loader、已选项补齐、重置和 force refresh 语义；不把删除死代码扩大为授权用量 DTO/summary 拆分。
- 实施前后都要以调用点搜索和前端行为回归证明它们确实不可达，不能仅凭函数名判定。
- 独立验收：页面首屏 options 请求矩阵不增加，每个筛选下拉仍在首次交互加载、失败可重试，管理/self scope 不变。
- 回滚：只恢复两页本地函数与 state，不涉及后端或数据。

## 8. 阶段 E：外部来源回归注册与 updateToken 决策

### 8.1 注册遗漏回归

- 把已存在的 `backend/src/scripts/regression/external-integration-source-lightweight-http-regression.ts` 注册为 backend package 专项命令，并纳入与本计划对应的 root 聚合门禁。
- 不复制一份新脚本；先审核现有脚本确实覆盖轻量 list/mutation HTTP 契约、权限和路由挂载，如覆盖不足则在原脚本补齐。
- 回归命令不得调用 Go，不以 Go smoke 作为 Node 通过证据。

### 8.2 `updateToken` 决策

- 删除无仓库调用的 Vue `externalIntegrationSourcesApi.updateToken` method，同步删除因此变成无用的 `ExternalIntegrationSourceTokenSummary` import。
- 保留 Node `PATCH /external-integration-sources/:id/tokens/:tokenId` 及 repository 能力。它是已注册、有权限与操作日志边界的管理 HTTP 契约，可能存在仓库外调用方；本计划没有证据将其作为死后端接口删除。
- 如未来 Vue 需要 token 编辑，应从明确 UI 需求重新引入 typed method，而不长期保留无调用包装。
- 独立验收：新 package/root 命令真实运行 Node 轻量 HTTP 回归；前端 method/import 无残留；Node token PATCH 权限、校验、日志和响应回归仍通过。
- 回滚：命令注册和前端 method 删除可分开恢复；后端 route 未改，无数据回滚。

## 9. 验证与复核

每个阶段使用独立专项命令和独立 diff 复核，不要求五个阶段同时合并才能验收。共同门禁：

- Node 后端 typecheck，Vue 专项类型/行为回归，可运行范围内的前端 typecheck/build，`git diff --check`。
- HTTP 回归要断言精确字段集、状态码、权限和错误，不仅检查 TypeScript 类型或搜索源码。
- 死入口/死 loader 删除后要验证真实业务替代路径：聊天默认 Key、授权用量下拉按需加载、外部来源 Node token PATCH。
- 至少两名只读 Agent 独立复核：一名检查契约/权限/路由，一名检查 Vue 缓存/调用点/回归证据；高严重度问题全部闭合。
- Browser/Playwright 可用时验证登录→壳层品牌请求数、公告写操作和授权用量下拉；不可用时明确记录限制，不把源码搜索宣称为浏览器证据。

## 10. 完成标准

- 五个阶段都获得明确 breaking/范围确认，并各自完成实施、专项验收、回归和独立复核。
- 品牌重复 RTT、认证宽响应、Chat 死 GET、公告宽 mutation、授权用量死 loader、外部来源未注册回归和无调用前端 method 均有直接证据闭合。
- 聊天、认证、公告、授权用量和外部来源的业务主流程与权限无回归。
- 实施与验证只覆盖 Node/Vue，无 Go 改动、无提交、无部署和生产操作。
