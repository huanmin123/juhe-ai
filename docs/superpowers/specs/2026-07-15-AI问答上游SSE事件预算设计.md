# AI 问答上游 SSE 事件预算设计

## 目标

修复合法长 Responses / Chat Completions 流在 2048 个事件后被产品 collector 拒绝的问题，同时保留有界事件、内容和辅助数据保护。

## 设计

- `runtimeConfig.chat.upstreamSseMaxEvents` 是两个 OpenAI 协议 collector 的共享事实来源。
- 环境变量为 `JUHE_AI_CHAT_UPSTREAM_SSE_MAX_EVENTS`，默认 `65536`，仅接受 `2048..262144` 的整数。
- `chat.routes.ts` 显式把配置值传给 `collectChatResponsesSse` 和 `collectOpenAIChatSse`，collector 不直接读取全局配置。
- collector 只保存事件计数和既有有界内容，空间复杂度仍为常量；单事件 `64 KiB`、content / aux `192 KiB` 边界不变。
- 超过配置上限时抛出包含实际数值的协议明确错误。

## 验证

- 两协议在默认配置下均能完成超过 2048 个合法小 delta 的流。
- 两协议在显式 `2048` 上限下均拒绝第 2049 个事件。
- runtime env 覆盖缺省、上下界、越界、小数和非数值。
- 路由回归证明两个 collector 都接收同一配置字段。

## 安全权衡

默认值提高是为了容纳真实长输出，不取消 DoS 防护。事件计数上限、单事件字节上限和累计内容上限共同约束 CPU 与内存；部署方只能在严格范围内调整事件数。
