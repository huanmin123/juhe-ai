# 下拉接口轻量化与账户测试模型按需加载设计

## 背景

AI 账户操作中的“测试”入口当前在打开弹窗时读取完整 `test-options` 响应。响应同时携带所有候选模型的协议能力和请求形态，模型下拉实际只需要模型标识和展示名称，造成无用传输、JSON 解析和 Vue 响应式开销。项目其他 `*/options` 接口也存在复用宽 DTO、把详情或成员数组带入选择器响应的风险。

## 目标与范围

- 测试弹窗默认使用当前账户持久化的 `healthCheckModel` 和默认检查请求形态。
- 只有用户打开模型选择或确实需要候选模型时，才请求账户可测试模型列表。
- 模型选择列表默认只返回 `id` 和 `name`；模型协议能力、请求形态和价格等信息按供应商/模型详情按需读取。
- 审计所有管理端和个人端下拉接口，统一采用轻量 `XxxOptionDto` 投影；仅保留有明确页面消费证据的少量字段。
- 扩展审计到所有页面首屏列表、详情、统计、日志和弹窗接口：页面首包只返回当前可见区域需要的字段，重量详情、规则、成员、统计明细和能力数据按交互异步补充。
- 后端每个页面场景使用独立的 repository 查询和 DTO，不为了复用而先读取完整 Summary、关联多张表或构造大数组再在 API 层裁剪。
- 保持后端提交测试时的最终模型和请求形态校验；前端返回值不作为权限或能力事实来源。
- 不改生产数据、不提交 Git，不保留旧宽响应兼容分支。

## 设计

### 账户测试接口

`GET /accounts/:id/test-options` 和 `GET /my-accounts/:id/test-options` 只在模型选择器展开后请求，直接返回：

```ts
type AccountTestOptions = Array<{ id: string; name: string }>
```

默认模型和默认请求形态直接来自当前账户列表行的 `healthCheckModel` 与 `healthCheckEndpointMode`，不由 `test-options` 重复返回。列表接口支持 `keyword`、`limit` 和 `selectedIds`，不返回每个模型的协议列表或请求形态数组。

为用户切换模型提供按需能力读取：

`GET /accounts/:id/test-options/models/:modelId` 和个人端镜像接口返回：

```ts
interface AccountTestModelCapabilities {
  id: string
  name: string
  testEndpointModes: AccountSupportedEndpointMode[]
}
```

后端列表使用带供应商、作用域、关键词、窗口和已选补齐的轻量目录投影；单模型能力再按 `provider + owner + modelId` 定点读取必要协议字段。模型不存在、不可测试或无可用请求形态时返回明确的 4xx 中文错误。

前端打开测试弹窗时只设置默认模型和请求形态，不自动加载候选列表。模型选择器首次展开/点击时加载轻量数组；切换到非默认模型时读取该模型能力并更新请求形态。取消、关闭、请求竞态和接口失败均恢复为当前会话的明确 loading/error 状态，不吞错。

### 全站下拉接口

- `GET /xxx/options` 默认使用独立 repository 查询和 `XxxOptionDto`，最小字段为 `id`、`name`。
- 若页面确实需要过滤或禁用语义，才增加 `status`、`type`、`providerCode`、`disabledReason` 等单字段，并在类型和回归测试中记录消费点。
- 成员、绑定关系、凭据、模型能力、规则、统计和完整供应商定义不进入通用下拉响应；分别使用详情、能力或绑定接口。
- 默认限制窗口、支持 `keyword` 和已选项补齐，保持稳定排序与访问范围过滤。
- 已经满足轻量契约的接口不改行为，只补全审计证据和测试；仍返回宽字段的接口按相同规则裁剪。

### 全页面渐进式加载

- 首屏列表 DTO 只保留表格当前可见列、必要状态和操作禁用原因；详情、成员、规则、凭据、原始 payload、模型能力、统计趋势分别由专用接口提供。
- 页面级 `loadData` 不得为了一个折叠区、隐藏标签或操作按钮预取重量数据；折叠区首次展开、详情抽屉打开、模型选择器展开和筛选器聚焦时才触发对应请求。
- 列表接口不得在 `map(row)` 中逐条补查关联表；需要名称/状态时由主查询一次拿齐或走有界批量 lookup/cache。统计来自预聚合表，不在请求路径扫描明细。
- 每个页面审计记录“首屏请求、可见字段、延迟字段、后端 SQL/关联、目标响应体积和回归命令”，按 P0 重量首屏、P1 大列表/弹窗、P2 已符合规范分类。
- 账户测试、供应商模型、聊天模型和聊天 API Key 选择器作为 P0；代理、系统账户、授权主体、日志 facets 和静态枚举若已轻量只保留验证证据，不为统一而增加接口复杂度。

### 错误与兼容

- 后端提交测试继续调用 `resolveAccountManualTestSelectionAsync` 或等价当前校验，拒绝不属于账户供应商可用目录或不支持请求形态的模型。
- 能力接口失败时前端不伪造默认值；保留账户默认模型时可继续展示已知默认请求形态，切换模型失败则阻止提交并显示中文错误。
- 当前项目按前后端同版本发布，不保留 `supportedApiProtocols`、模型级 `testEndpointModes` 等旧响应字段。

### 验收

- 测试弹窗首开请求不获取候选模型详情列表；默认值等于账户的检查模型和请求形态。
- 点击选择模型后才产生模型列表请求，列表每项只有 `id/name`。
- 切换模型只请求该模型能力，提交仍由后端校验。
- 全站 options 审计表中没有未解释的大字段或详情数组；相关接口回归测试验证 JSON 字段集合和查询列。
- 前后端类型检查、相关回归测试和完整构建通过。
