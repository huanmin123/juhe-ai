# 网关长会话与生图服务端接管实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让网关在客户端尚未收到响应时尽可能在服务端持续等待、切换可用账号并救回长耗时文本 / 生图请求，同时为图像 lane 使用更长的当前尝试超时；响应已经提交后保持协议完整并交给客户端重试。

**Architecture:** 在现有 `requestLane` 基础上新增独立 `GatewayTimeoutProfile`，由请求侧按 `text` / `image` 选择当前账号尝试的首响应、首字节、流式停顿和未提交寿命。路由层不再把 270 秒当作有候选账号时的绝对重试墙；候选循环和可恢复等待负责服务端接管，响应层继续以 `transportCommitted` / `semanticCommitted` 作为透明重试边界，不新增上游状态码 / 错误类型白名单。

**Tech Stack:** Node.js 22、TypeScript、Express、pnpm workspace、SQLite system settings、现有 gateway SSE / non-stream response pipeline、regression scripts。
