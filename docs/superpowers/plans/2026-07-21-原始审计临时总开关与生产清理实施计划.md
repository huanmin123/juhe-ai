# 原始审计临时总开关与生产清理 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 增加默认启用、可由部署环境临时整体关闭的原始审计总开关，在不移除历史查询和后续重启能力的前提下停止全部新审计写入，并在生产验证关闭生效后不可恢复地清空生产审计数据。

**Architecture:** `runtimeConfig.auditLog.enabled` 是唯一配置事实源，审计 capture、dropped capture、队列、transport 和 Redis consumer 都在审计模块边界短路；查询路由继续工作，`/audit-logs/runtime` 把关闭状态表达为正常的 `audit_disabled`。应用按 temporary-first 流程发布，数据清理作为发布成功后的独立阶段，仅删除 PostgreSQL 五张审计表、运行时解析出的审计 Redis Stream 和生产 audit 文件根目录内容。

**Tech Stack:** Node.js 22、TypeScript、Express、PostgreSQL、Redis Streams、Vue 3 管理端现有审计页面、PowerShell 7、本机到 macOS 的 SSH、launchd、Nginx。
