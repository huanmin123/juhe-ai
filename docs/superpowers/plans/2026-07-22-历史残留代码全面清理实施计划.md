# 历史残留代码全面清理 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不改变当前业务行为、不误删动态入口和迁移资产的前提下，删除前端、Node、Go、测试脚本与构建链中没有真实消费者的历史残留，并建立可重复的未使用代码门禁。

**Architecture:** 以正式入口依赖闭包、动态入口清单、命令入口、当前事实文档和 Git 历史共同作为删除证据。工作按候选冻结、前端、Node、Go、脚本/构建、文档与全量验证分批实施；每批由 fresh implementer 执行，随后进行规格符合性和代码质量两级独立复核。

**Tech Stack:** Vue 3、TypeScript、Vite、Node.js、pnpm、Go、PostgreSQL、Redis、PowerShell 7、Git worktree。

- [ ] **Step 3: 写动态入口回归**

`dead-code-entrypoints-regression.ts` 必须读取源码和 package scripts，并断言下列动态入口仍由正式生产代码或正式命令引用：

```ts
const requiredDynamicEntrypoints = [
  'src/worker.ts',
  'src/db-service.ts',
  'src/temporary-maintenance-worker.ts',
```

检查必须限定在非测试生产源码、package scripts、maintenance 和 smoke 目录，失败信息包含缺失入口名称；不得把“只有测试引用”计为生产引用。

- [ ] **Step 4: 写 Go cmd 闭包差集测试**

`deadcode_test.go` 使用 `context.WithTimeout` 和 `exec.CommandContext` 分别运行 `go list -mod=readonly -f {{.ImportPath}} ./...` 与 `go list -mod=readonly -deps -f {{.ImportPath}} ./cmd/...`；每条命令使用 30 秒超时，并显式设置 `cmd.Dir = moduleRoot`，不得依赖测试进程的当前目录。过滤标准库和 `_test` 不可见项后，只允许以下两个测试/门禁资产留在正式 cmd 依赖闭包差集中：

```go
var allowedUnreachablePackages = map[string]struct{}{
	"juhe-ai/backend-go/db/migrationtests":              {},
	"juhe-ai/backend-go/internal/architecture/deadcode": {},
}
```

门禁自身 `juhe-ai/backend-go/internal/architecture/deadcode` 不得被报告为业务死代码；扣除上述两个允许项后，测试失败时打印新增的不可达业务包完整 import path。

- [ ] **Step 5: 暴露统一命令**

在各 package 中增加：

```json
"typecheck:unused": "vue-tsc -p tsconfig.unused.json"
```

```json
"typecheck:unused": "tsc -p tsconfig.unused.json",
"test:dead-code-entrypoints": "tsx src/scripts/regression/dead-code-entrypoints-regression.ts"
```

根 package 增加：

```json
"test:dead-code:go": "go -C backend-go test -count=1 ./internal/architecture/deadcode",
"test:dead-code": "pnpm --filter juhe-ai-frontend typecheck:unused && pnpm --filter juhe-ai-backend typecheck:unused && pnpm --filter juhe-ai-backend test:dead-code-entrypoints && pnpm run test:dead-code:go"
```

根命令中的 Go 测试固定使用 `go -C backend-go` 切换模块目录；`backend-go` 不是 pnpm package，门禁也不能依赖调用者先切换当前目录。

- [ ] **Step 6: 定向验证门禁状态**
