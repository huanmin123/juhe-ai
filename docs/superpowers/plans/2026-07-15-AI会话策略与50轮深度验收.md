# AI Chat Policy And 50-Turn Acceptance Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 实现可配置的聊天保留/数量/轮次策略，并用真实 50 轮项目演进会话输出量化验收结论。

**Architecture:** 环境配置提供部署级默认策略，repository 在用户锁和会话锁事务中执行权威门禁，route 只做昂贵工作前的快速拒绝。会话 DTO 暴露计数供前端提前提示；真实验收脚本使用白名单指标输出 JSON，不保存凭据或完整对话正文。

**Tech Stack:** Node.js、TypeScript、SQLite/PostgreSQL、Redis、Express、Vue 3、SSE、PowerShell

- [ ] **Step 2: Add safe metric collectors**

- [ ] **Step 3: Add objective scoring**

- [ ] **Step 4: Assert turn 51**

第 50 轮完成后发送第 51 次，断言稳定 `409 chat_turn_limit_exceeded`，并核对消息、幂等、context revision、usage、checkpoint、asset 和上游调用均无新增。

- [ ] **Step 5: Add controlled seeded compression**

创建第二个隔离会话，使用 `createChatConversation`、`acceptChatTurn`、`completeChatTurn` 预填语义连续的 HTML/CSS 项目用户/助手消息对。按真实可用模型中最小上下文窗口计算预填量，保持每条消息小于 `192 KiB`、总历史小于上下文装载字节上限，并让估算用量接近 `70%` 压缩阈值；禁止直接写 SQL。

- [ ] **Step 6: Trigger through production HTTP path**

通过真实 `/stream` 继续发送后续需求，等待 `context-status` 出现 `compact_pending/compacting` 并最终回到 `ready` 且 `compactedThroughSequence > 0`。若真实模型窗口过大而无法在安全消息边界内自然触发，调用生产 `compactChatContextOnce` 执行受控压缩，并在报告中标注为受控触发。

- [ ] **Step 7: Verify seeded conversation integrity and recall**

断言 sequence 连续、幂等映射完整、`userTurnCount` 与预填+真实轮次一致、容量账本无偏差、全部助手终态有效；真实追问必须同时召回早期锚点、最近完整项目代码和压缩后新增需求。
