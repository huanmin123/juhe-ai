# 账户测试取消查询无放大 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 消除账号测试 worker 在任务开始、完成和异常收口阶段的取消状态 DB service 读 RPC 放大，同时保持即时取消和数据库最终状态正确。

**Architecture:** 取消接口继续先持久化再发送 worker IPC；活动任务只使用本地 `AbortController` 响应取消。SQLite 与 PostgreSQL 的 claim、complete、fail 使用 `status` 和 `cancel_requested` 条件更新，取消竞态只在数据库 repository 内部的稀有失败分支收口。正常任务不再调用 `is_account_test_task_cancel_requested` 或 `read_account_test_task_cancel_message`。

**Tech Stack:** Node.js 22、TypeScript、SQLite、PostgreSQL、Redis Stream 既有队列、pnpm、tsx 回归脚本。

- [ ] **Step 1: 为 SQLite complete/fail 增加条件更新**

  `completeAccountTestTask` 只允许 `status='running' AND cancel_requested=0`；`failAccountTestTask` 只允许 queued/running 且 `cancel_requested=0`。条件更新未命中时读取当前记录；若已请求取消，则调用既有 canceled 状态转换并保留当前取消消息。

## 任务 3：删除 worker 正常路径的取消查询

**Files:**
- Modify: `backend/src/modules/accounts/account-test-task-queue.service.ts`
- Test: `backend/src/scripts/regression/account-test-cancel-rpc-deamplification-regression.ts`

- [ ] **Step 1: 删除开始前取消查询**

  `mark_account_test_task_running` 返回任务即表示 claim 成功；返回空表示任务已取消、已结束或不存在，worker 不再补发取消状态或取消消息读取。

- [ ] **Step 2: 删除完成后的取消查询**

  三条上游测试分支直接调用 `complete_account_test_task`。数据库条件更新负责拒绝取消后的结果覆盖；`controller.signal.aborted` 时直接调用 canceled 写入。

- [ ] **Step 3: 删除异常路径的取消查询**

  catch 只检查本地 `AbortSignal`；未本地 abort 时调用条件化 fail，数据库内处理取消与失败竞态。删除两个只被队列轮询使用的 helper，不删除仍可能被管理或诊断接口使用的 DB service operation 类型。
