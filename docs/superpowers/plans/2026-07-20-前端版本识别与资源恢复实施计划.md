# 前端版本识别与资源恢复实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为动态前端资源失败增加真实 Build ID 比较，只有确认版本变化时提示系统更新，其余情况使用中性恢复文案并保留一次自动刷新。

**Architecture:** Vite 以完整 Git commit 生成编译期常量和静态 `build-info.json`，发布脚本显式传入冻结提交，Express 对清单设置 `no-cache`。路由恢复先登记防循环状态，再异步读取清单并把结果归类为 `changed/same/unknown`，分类只决定文案，不阻断一次性自动恢复。

**Tech Stack:** Vue 3、TypeScript、Vue Router、Vite 5、Express、pnpm workspace、Node 回归脚本、Playwright。

```ts
const frontendBuildIdPattern = /^[0-9a-f]{40}$/

export function normalizeFrontendBuildId(value: unknown): string | undefined {
  if (typeof value !== 'string') return undefined
  const normalized = value.trim().toLowerCase()
  return frontendBuildIdPattern.test(normalized) ? normalized : undefined
}
```

`frontend/src/router/frontendBuildInfo.ts` 定义 `FrontendBuildStatus = 'changed' | 'same' | 'unknown'`，实现 `classifyFrontendBuild(currentBuildId, loadRemoteBuildId)`；当前或远端标识非法、loader 抛错时返回 `unknown`，两端规范化后再比较。

- [x] **Step 4：实现分类提示与一次性恢复**

`recoverRouteAssetLoadError` 保持同步返回 boolean，并在确认资源错误后立即设置 `routeAssetReloadScheduled`、写入 sessionStorage，再启动异步恢复：

```ts
const status = await classifyFrontendBuild(
  __JUHE_AI_FRONTEND_BUILD_ID__,
  () => loadRemoteFrontendBuildId()
)

if (status === 'changed') {
  showRouteAssetLoadOverlay({ title: '系统已更新', description: '正在刷新页面以加载最新版本，请稍候。', ... })
} else {
  showRouteAssetLoadOverlay({ title: '页面资源加载失败', description: '正在重新加载页面，请稍候。', ... })
}
```

无论分类结果如何都在 `900ms` 后执行一次 `window.location.assign(reloadHref)`。30 秒内再次失败仍走手动刷新分支，说明固定为“自动恢复未成功，请手动刷新页面后重试。”，不请求版本清单。
