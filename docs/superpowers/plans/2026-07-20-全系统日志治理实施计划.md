# 全系统日志治理实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (recommended) or superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 Node、Go、worker、DB service 和运行时日志基础设施中建立统一、默认开启、逐阶段、异步且有界的日志体系，同时完整保留失败现场证据。

**Architecture:** 运行时日志、原始审计、操作日志和公开 API 日志继续保持独立的保留周期与权限语义，但共享事件、链路、耗时和失败契约。Node 由 Pino 在主线程序列化后通过异步 `fs` stream 将 JSONL 顺序追加到角色 durable spool，`ingest-worker` 是唯一 runtime-log file cursor consumer；每个 Node 输出目的地使用 normal 64 MiB / failure 8 MiB 独立待写预算，预算耗尽时累计 drop、保留最后现场且 failure 首次走应急诊断。Go 使用 normal/failure/emergency 三类有界 `slog.Handler` 通道。任何路径不得阻塞业务请求，也不宣称永久慢盘下零丢失、非阻塞和有限内存可以同时成立。

**Tech Stack:** Node.js 22, TypeScript, Pino, Node fs streams, Express, Go, `log/slog`, PostgreSQL, Redis（仅其他事实队列）, SQLite file cursor index, pnpm, Go test.
