# 发布失败恢复与源阻断实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 juhe-ai 发布在任一硬门禁失败时优先恢复客户端可用性，并用独立的发布源阻断记录阻止后续任务重复发布同一坏版本。

**Architecture:** 保留本机部署计划锁的短期互斥职责和现有 `completed`/`rolled-back`/`cancelled` 结果；新增独立 `release-source-blocker.ps1` 注册表，按 commit 祖先关系及 release/migration/verify/rollback hash 阻断失败源。macOS 侧新增恢复协调入口，只有在 main 通过最小健康与拓扑检查后才切回；数据库迁移已开始且无法证明安全恢复时保持 temporary、写 recovery marker 并阻断，不自动执行不可逆恢复。

**Tech Stack:** PowerShell 7、macOS Bash 3.2、Nginx、launchd、JSON/JSONL 审计、现有部署脚本测试 harness。

- [ ] **Step 2: 实现恢复入口**

  - 若 main 已经健康承流，禁止为了“保持回滚目录”把流量切回不健康 temporary。
  - 保留恢复目录和 `recovery-required` 作为 fail-closed 证据，不能由 trap 吞掉状态。

# 2026-07-19 增补：临时接管会话连续性

- 不引入共享认证库或双写。
- 临时库初始快照保持不变；`switch-nginx-upstream.sh temporary` 在首个 Nginx 配置写入前调用 `sync-temporary-sessions.sh`。
- 同步范围只包含主库当前未过期、账户仍 active 的 session，以及这些 session 引用的账户安全状态；在临时库单事务内更新账户并完全替换 session 集合。
- 同步失败、唯一约束冲突、外键异常或脚本缺失时保持 main 承流。
- 前端 `/auth/me` 只有明确 401 才清登录态；503、超时和网络错误保留已有用户，冷启动瞬态失败取消保护路由导航。服务端 logout 成功后才清理本地状态。
- 本增补仅修改本地源码、部署脚本、测试和文档，不执行生产部署。
