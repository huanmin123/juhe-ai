# AI 问答生成续跑与本地缓存 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让已接受的 AI 生成脱离首个页面连接继续执行，并通过轻量 revision 同步与 IndexedDB 展示缓存实现菜单切换、刷新和关闭后重进的快速恢复。

**Architecture:** 后端以单实例 `ChatGenerationRunnerRegistry` 持有上游任务、有界投影和多个 SSE subscriber，数据库以独立 `message_revision` 记录可见消息事实。前端以应用级 runtime 管理重附着，以原生 IndexedDB 缓存可见 DTO；进入会话时先渲染缓存，再用 sync head 判断无需正文、增量追加、状态覆盖或尾部替换。

**Tech Stack:** Node.js 22、TypeScript、Express、SQLite/PostgreSQL DB service、Vue 3、原生 IndexedDB、SSE、现有 tsx regression scripts。

## 自审

- 规格覆盖：message revision、sync、增量游标、runner、attach、显式 stop、应用级 runtime、IndexedDB、容量、身份、多标签、移动端和 50 轮验收均有对应任务。
- 占位符扫描：所有步骤均包含明确文件、实现契约、命令和预期结果。
- 类型一致性：统一使用 `messageRevision`、`eventVersion`、`afterSequenceNo`、`fromSequenceNo`、`ChatConversationSyncHead` 和 `RunningTurn`。
- 边界一致：不引入分布式队列；不把 IDB 当权威存储；不保证服务进程重启后续跑。
