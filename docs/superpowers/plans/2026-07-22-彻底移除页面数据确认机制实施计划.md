# 彻底移除页面数据确认机制实施计划

**目标：** 从前端、Node、Go、Redis 接线、测试和当前文档中彻底删除 page-data confirm/revision 机制，页面恢复直接业务请求。

**架构：** 删除整条 `browser cache -> confirm API -> revision store -> write publisher` 链路，不建立兼容层。保留独立业务快照、后台探针和普通业务缓存。

## 任务 1：建立删除门禁

- 增加或改写源码门禁，列出禁止残留的路由、API、domain/revision 类型、publisher、dirty-domain 和 package script。
- 先让门禁在旧代码上失败，再随删除逐步转绿。

## 任务 2：前端恢复直接请求

- 删除 page-data API、shared/composable 核心文件和专项测试。
- 将账户列表、标签/分组/模型选项、授权选项、统计、审计和使用记录选项改为直接业务请求。
- 移除 HTTP mutation interceptor、登录/退出 page-data generation 和 activation 接线。
- 保留页面自己的请求竞态保护与正常手动刷新。

## 任务 3：删除 Node 运行时与写端发布

- 删除 page-data module、confirm 路由、Redis store、DB service 初始化和 IPC。
- 从所有业务写路径移除 page-data publish/reset 调用。
- 删除 dirty-domain repository、smoke、benchmark、专项回归和 scripts。
- 修正 System API access/rate-limit 回归，证明不再有 confirm 特例。

## 任务 4：删除 Go publisher 与恢复机制

- 删除 platform Redis page-data publisher、app adapter/recovery 和专用 port/store。
- 从 management/public modules、worker 和 HTTP handler 中移除 publisher 依赖。
- 改写测试为只验证业务写入和其他保留副作用。

## 任务 5：文档和残留清理

- 更新当前架构、功能和测试说明。
- 历史计划标记已退场，PLAN-20260722T123439000Z 记录删除证据。
- 全仓扫描运行时、脚本、package 命令和文档入口，不保留空壳或兼容代码。

## 任务 6：验证、复查与合并

- 运行前后端专项、根 typecheck/lint/build 和 Go 全量测试。
- 启动本地应用，用浏览器验证 `/my-accounts` 无 confirm。
- 独立复查需求、性能、竞态、代码组织和文档一致性。
- 同步最新 `origin/master`，解决冲突并复验。
- 独立 master 集成工作区合并并推送；不部署。
