# Google 欺骗性网页告警安全修复实施计划

> **For agentic workers:** Execute this plan task-by-task in the current session. Do not commit or alter unrelated user work.

**Goal:** 为 `/__aisys__` 管理面增加不影响现有功能的安全响应头，移除 Express 标识，并完成本地、六入口和 Mac 生产验收，为 Google 复审提供证据。

**Architecture:** 在现有 `backend/src/shared/http-security.ts` 集中定义固定的管理面安全头，通过 Express 路径中间件只作用于 `/__aisys__`；`app.disable('x-powered-by')` 仅删除框架标识。前端、账户、数据库、`/v1` 网关、反向代理和 Edge 配置不变。

**Tech Stack:** Node.js 22、TypeScript、Express、现有 `tsx` 回归脚本、Vue/Vite 构建、Mac launchd/Caddy/WireGuard 部署流程。

### Task 3: 挂载管理面头并移除 Express 标识

**Files:**
- Modify: `backend/src/server.ts`

- [ ] **Step 1: 在系统路由前挂载中间件**

导入 `managementSecurityHeadersMiddleware`，在 `app.use(requestContextMiddleware)` 之后、System API/静态资源路由之前增加：

```ts
app.disable('x-powered-by')
app.use(systemPrefix, managementSecurityHeadersMiddleware)
```

这样 `/__aisys__/`、登录路径、健康检查、静态资源和 System API 都带管理面安全头；`/v1` 在该路径之外，不接收管理面 CSP。不要修改 Caddy、Nginx、WireGuard 或任何 Edge 配置。

- [ ] **Step 2: 运行相关回归**

运行：`pnpm --filter juhe-ai-backend test:http-security-management` 和 `pnpm --filter juhe-ai-backend test:http-security-production-guard`。

预期：安全头和已有生产 CORS/Cookie 保护同时通过。
