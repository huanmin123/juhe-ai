# 客户端模型目录动态聚合实施计划

> 对应设计：`docs/superpowers/specs/2026-07-22-客户端模型目录动态聚合设计.md`
> 跟踪计划：`docs/plans/计划-0152-20260722T120806000Z-客户端模型目录动态聚合.md`

## 目标

修复无特征 `GET /models` 被误判成 Gemini 的问题，使公开模型列表覆盖全部已启用真实供应商，使认证模型列表严格聚合 API Key 所有有效分组涉及的供应商。网关不再依赖 `default/codex` 发布快照，AI Chat 专用快照继续保留。

## 实施原则

- 严格测试先行：每项行为先补能失败的回归，再写最小实现。
- 供应商目录仍是唯一模型事实来源；客户端聚合只做作用域、可见性、可计价约束和去重。
- 不按发布时间过滤，返回供应商目录内全部可用模型。
- 公开请求的 `providerCodes` 缺省与认证请求的空数组含义不同：前者是全部启用供应商，后者必须返回空列表。
- 开发期间在关键里程碑合并最新 `master`，冲突在功能分支解决。
- 本任务只开发、测试、合并和推送，不执行生产部署。

## 完成标准

- 网关不再读写 `default/codex` 发布响应快照，AI Chat 快照回归通过。
- SQLite、PostgreSQL/Redis smoke、类型检查、构建和独立审查均有记录。
