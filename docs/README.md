# 文档目录说明

> 面向 AI 和维护者。
> 本目录用于沉淀项目目标、架构边界、阶段计划、功能说明、运行验证、部署流程、测试报告、问题记录和重构复盘，避免关键结论只停留在对话里。

## 1. 文档目标

- 固化 `juhe-ai` 的产品定位、模块边界和阶段范围，保证后续实现不偏离轻量闭环目标。
- 给 AI 和维护者提供稳定入口：先看目录说明，再进入具体架构、计划、功能、运行或问题文档。
- 让需求、实现、验证、问题和重构之间有明确关联，方便回溯“为什么这样做”。
- 统一文档命名、引用和更新习惯，减少旧路径、英文文件名和重复说明。

## 2. 主要文档关系

| 文档 | 目标 | 关联关系 |
| --- | --- | --- |
| `architecture/架构总览.md` | 说明产品目标、技术架构、模块边界、数据关系和网关流程 | 需求或功能影响边界时必须同步更新 |
| `plans/README.md` | 说明计划目录规则、需求计划字段和计划索引 | 需求推进、阶段范围和验证结果都从这里进入 |
| `plans/第一阶段计划.md` | 归档早期阶段范围、里程碑和完成标准 | 作为历史范围记录保留；当前功能事实以架构和 functions 文档为准 |
| `functions/README.md` | 汇总功能说明、专题调研和存储说明 | 新字段、新接口、新流程优先关联到这里的具体文档 |
| `architecture/README.md` | 汇总架构设计和通用开发 / 修复 / 重构指导 | 前端架构、专项架构和后续独立设计从这里进入 |
| `architecture/backend/README.md` | 说明后端实现边界、目录规划、数据库设计和配置入口 | 后端接口、存储、脚本、网关或后台任务变更必须先参考 |
| `architecture/frontend/README.md` | 说明前端实现边界和前端规范入口 | 页面、样式、品牌、交互变更必须先参考 |
| `develop/README.md` | 汇总安装、运行、验证和测试文档 | 本地开发、联调和冒烟验证从这里进入 |
| `deploy/README.md` | 汇总构建、部署场景、三端部署差异、网络代理、HTTPS 证书、状态检测、常驻运行、反向代理、备份迁移和排障文档 | 发布、迁移、上游代理、HTTPS、自动恢复和部署问题先从部署场景进入 |
| `reports/README.md` | 汇总人工整理后的压测、性能和验证分析报告 | 报告结论和原始产物索引从这里进入；机器生成产物仍放仓库根目录 `reports/` |
| `bug/README.md` | 说明问题记录规则和 bug 复发关联方式 | 有复用价值的问题修复需要沉淀到这里 |
| `refactors/README.md` | 说明重构案例记录规则 | 大文件拆分、职责收敛和可复用重构经验从这里进入 |

## 3. 关联维护规则

- 影响模块边界、数据关系、权限、安全或网关链路时，同步更新 `architecture/架构总览.md` 和对应计划文档。
- 影响阶段范围、优先级或完成标准时，同步更新 `plans/` 下对应阶段计划或需求计划；当前功能事实还必须同步到架构和 functions 文档。
- 新增功能、字段、接口、存储、脚本或关键流程时，同步更新 `functions/` 下对应说明。
- 通用开发、问题修复或大文件重构规范变化时，同步更新 `architecture/` 下对应指导。
- 影响本地运行、测试、构建或部署时，同步更新 `develop/` 或 `deploy/` 下对应文档。
- 形成独立压测、性能分析、容量结论或验证分析时，Markdown 报告写入 `docs/reports/`；脚本生成的 JSON、log、CPU profile 等原始产物继续写入仓库根目录 `reports/`。
- 修复有复用价值、容易复发或定位成本高的问题时，在 `bug/` 下补充记录。
- 做大文件拆分、模块职责收敛或可复用重构时，在 `refactors/` 下补充记录。

## 4. 文件命名规范

- 目录说明文档统一命名为 `README.md`，这是 `docs/` 下允许保留英文文件名的固定例外。
- 除目录说明文件外，所有 Markdown 文档文件名主体必须使用中文，避免新增英文短横线命名或纯英文描述文件名；必要的产品名、技术名词和编号可以保留原文。
- 需要编号的文档，文件名也使用中文语义，例如 `计划-0001-透传定位修正.md`、`问题-0001-简短标题.md`、`重构-0001-简短标题.md`；报告建议使用 `主题报告-YYYY-MM-DD.md`；正文内可以保留稳定编号如 `PLAN-0001`、`BUG-0001`、`REFACTOR-0001`。
- 重命名文档后必须同步更新所有引用路径，并确认 `docs/` 下不存在旧英文路径残留。
- 新增文档前先查看所在目录的 `README.md`，确认文档目标、归属目录和关联文档。
