# 家庭宽带反向代理方案

## 1. 适用

- juhe-ai 跑在家里电脑、Mac mini、家用小主机、NAS 或 Windows 桌面机。
- 入口依赖家宽公网 IP、DDNS、路由器端口映射，或公网服务器反代回家里。
- 个人或小团队使用；不作为多人高并发生产入口。

云服务器直接部署看 [服务器部署方案](服务器部署方案.md)。

## 2. 入口方式

| 情况 | 推荐入口 | 关键边界 |
| --- | --- | --- |
| 有公网 IPv4/IPv6，路由器可映射端口 | DDNS + 路由器 `80/443` -> 家里主机 Caddy | 只映射 HTTPS 入口 |
| 无公网 IP、端口被封、不想暴露家里 IP | 公网服务器 Caddy -> VPN / 隧道 -> 家里主机 | 公网服务器不保存业务数据 |

不要把 juhe-ai `3000`、sing-box `7890`、PostgreSQL、Redis 或 DB service 端口直接映射到公网。

## 3. 必读顺序

1. 本文确认入口方式。
2. 家里主机平台文档：[Linux](../linux/Linux部署指南.md)、[Windows](../windows/Windows部署指南.md)、[macOS](../macos/macOS部署指南.md) 或 [Docker](../Docker部署指南.md)。
3. [Caddy 自动 HTTPS 部署指南](../https/Caddy自动HTTPS部署指南.md)。
4. [状态检测与自动恢复指南](../watchdog/状态检测与自动恢复指南.md)。
5. 上游请求不通时看 [sing-box 网络代理部署指南](../proxy/sing-box网络代理部署指南.md)。

## 4. 方式 A：家宽公网 IP + DDNS

```text
客户端 -> 域名/DDNS -> 路由器 80/443 -> 家里主机 Caddy -> 127.0.0.1:3000 juhe-ai
```

家里主机 `backend.env`：

```env
JUHE_AI_HOST=127.0.0.1
JUHE_AI_PORT=3000
JUHE_AI_ALLOWED_ORIGINS=https://ai.example.com
JUHE_AI_COOKIE_SECURE=true
JUHE_AI_TRUST_PROXY=true
```

Caddyfile 见 [Caddy 自动 HTTPS 部署指南](../https/Caddy自动HTTPS部署指南.md)。路由器只转发 `80/443` 到 Caddy。

## 5. 方式 B：公网服务器入口 + 隧道回源

```text
客户端 -> 公网服务器 Caddy HTTPS -> VPN / 隧道 -> 家里主机 juhe-ai 或家里主机 Caddy
```

公网服务器 Caddy 示例：

```caddyfile
ai.example.com {
    encode zstd gzip

    reverse_proxy 100.64.0.10:3000 {
        flush_interval -1
    }
}
```

家里主机边界：

- juhe-ai 可以监听隧道地址，例如 `JUHE_AI_HOST=100.64.0.10`。
- 更稳妥的是 juhe-ai 仍监听 `127.0.0.1`，由家里主机 Caddy 或防火墙只接受隧道回源。
- 回源地址用 WireGuard、Tailscale、ZeroTier、frp 等；本文不维护隧道软件教程。

## 6. 真实客户端 IP

`clientIp` 来自 Express `req.ip`，需要同时满足：

- 前置入口把真实来源写入可信转发信息。
- juhe-ai 后端端口只允许 Caddy、edge、隧道或可信内网访问。
- `JUHE_AI_TRUST_PROXY=true`。

链路判断：

```text
客户端 -> 家里主机 Caddy -> juhe-ai
```

Caddy 是第一公网入口时，基础 `reverse_proxy` 即可。

```text
客户端 -> 公网 edge / VPS Caddy -> 隧道 -> 家里主机 Caddy -> juhe-ai
```

多层入口时，优先让前置 edge 到家里 Caddy 使用 PROXY protocol，并在 Caddy 中用 `allow` 限制真实可信回源 CIDR。配置放在 [Caddy 自动 HTTPS 部署指南](../https/Caddy自动HTTPS部署指南.md)，本场景文档不重复维护。

验证：

- 用手机流量和另一条外网分别访问同一个 API Key。
- 在后台“使用记录”或“公开接口日志”确认 `clientIp` 是两个不同来源。
- 如果全部是 `127.0.0.1`、VPS 内网 IP、隧道 IP 或同一个 edge IP，说明真实 IP 没传到 juhe-ai。

## 7. 自动恢复

家庭主机观察判据：

- 本机 `/__aisys__/health` 和 `/__aisys__/api/health` 失败只观察告警，不主动终止主服务。
- 公网域名失败但本机 health 正常时，不重启主服务；先查 DDNS、路由器、edge、隧道、Caddy 和证书。
- 主进程明确退出时由服务管理器拉起，DB service / worker 由内部 supervisor 独立退避。
- CPU 高但 health 正常时默认只记录。

macOS 当前形态：launchd `KeepAlive` 只在 server 进程退出后拉起；外部 HTTP watchdog 已退役。边界见 [自动恢复部署示例](../watchdog/自动恢复部署示例.md)。

## 8. 上游网络代理

公网能访问 juhe-ai，不代表主机能访问上游模型 API。上游出口按账号代理配置：

```text
juhe-ai -> 账号绑定代理 -> sing-box -> 上游模型 API
```

同机 sing-box：

```text
类型：socks5h
Host：127.0.0.1
端口：7890
```

Docker Desktop 访问宿主机 sing-box：

```text
类型：socks5h
Host：host.docker.internal
端口：7890
```

## 9. 验证清单

```bash
curl -i http://127.0.0.1:3000/__aisys__/health
curl -i http://127.0.0.1:3000/__aisys__/api/health
curl -I https://ai.example.com/__aisys__/
```

后台：

- 创建本地 API Key。
- 客户端 Base URL 使用 `https://ai.example.com/v1`。
- 测试 AI 账户。
- 上游失败时先测试账号绑定代理。
