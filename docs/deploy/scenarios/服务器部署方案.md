# 服务器部署方案

## 1. 适用场景

适合这些环境：

- 云服务器、VPS、独立服务器。
- 公司或机房内网服务器，有固定内网入口或边界网关。
- 有可控安全组、防火墙、域名解析和 `80/443` 入站能力。

不适合家里电脑、动态家庭宽带或运营商 NAT 场景；这些看 [家庭宽带反向代理方案](家庭宽带反向代理方案.md)。

## 2. 推荐路线

| 规模 | 推荐部署 | 入口 |
| --- | --- | --- |
| 单机轻量 | Linux + 发布包 + systemd | [Linux 部署指南](../linux/Linux部署指南.md) |
| 快速容器化 | Docker Compose 单容器 | [Docker 部署指南](../Docker部署指南.md) |
| Windows Server | zip 发布包 + Windows 服务化 | [Windows 部署指南](../windows/Windows部署指南.md) |
| 高并发 | Docker Compose + PostgreSQL + Redis | [高性能模式部署指南](../高性能模式部署指南.md) |

服务器生产默认建议：

```text
公网域名 -> Caddy HTTPS -> 127.0.0.1:3000 juhe-ai
```

不要把 `3000` 端口直接暴露到公网长期使用。

## 4. 关键配置

发布包部署 `backend/.env`：

```env
JUHE_AI_HOST=127.0.0.1
JUHE_AI_PORT=3000
JUHE_AI_ALLOWED_ORIGINS=https://ai.example.com
JUHE_AI_COOKIE_SECURE=true
JUHE_AI_COOKIE_SAME_SITE=lax
JUHE_AI_TRUST_PROXY=true
```

Docker 部署 `docker/.env`：

```env
JUHE_AI_PUBLIC_BIND=127.0.0.1
JUHE_AI_PUBLIC_PORT=3000
JUHE_AI_PUBLIC_ORIGIN=https://ai.example.com
JUHE_AI_COOKIE_SECURE=true
JUHE_AI_TRUST_PROXY=true
```

如果只是内网临时验证，可以使用 HTTP，并显式设置 `JUHE_AI_COOKIE_SECURE=false`；上线给浏览器或客户端长期访问时改回 HTTPS。

## 5. HTTPS 入口

服务器默认用 Caddy：

```caddyfile
ai.example.com {
    encode zstd gzip

    reverse_proxy 127.0.0.1:3000 {
        flush_interval -1
    }
}
```

要求：

- 域名 `A` / `AAAA` 记录指向服务器。
- 云安全组和系统防火墙放行 `80/tcp`、`443/tcp`。
- Caddy 与 Nginx 不要同时占用 `80/443`。
- 后端只监听 `127.0.0.1:3000`，由 Caddy 反代访问；这样 `JUHE_AI_TRUST_PROXY=true` 才能安全用于记录真实客户端 IP。

完整证书、续期和 Nginx + Certbot 备选见 [Caddy 自动 HTTPS 部署指南](../https/Caddy自动HTTPS部署指南.md)。

## 6. 上游网络代理

服务器能打开后台不代表能访问上游 API。中转请求上游失败时，按以下方式处理：

```text
juhe-ai -> 账号绑定代理 -> sing-box -> 上游模型 API
```

账号级代理推荐：

```text
类型：socks5h
Host：127.0.0.1
端口：7890
```

Docker 容器访问宿主机 sing-box 时，Host 按平台差异选择 `host.docker.internal` 或宿主机内网 / bridge 可达 IP。完整说明见 [sing-box 网络代理部署指南](../proxy/sing-box网络代理部署指南.md)。

## 7. 验证清单

```bash
curl -i http://127.0.0.1:3000/__aisys__/health
curl -i https://ai.example.com/__aisys__/health
curl -I https://ai.example.com/__aisys__/
```

后台还需要确认：

- 能登录管理后台。
- 能创建或编辑 AI 账户。
- 账号测试成功。
- 如果配置代理，代理测试成功。
- 客户端 Base URL 使用 `https://ai.example.com/v1`。

## 8. 自动恢复

服务器部署使用服务管理器的进程退出恢复。推荐策略：

- systemd / Docker / Windows Service 负责常驻。
- 本机 `/__aisys__/health` 和 `/__aisys__/api/health` 只用于观察和告警。
- 主进程明确退出时由服务管理器按自身退避拉起，不依据 HTTP health 主动终止进程。
- DB service / worker 使用内部 supervisor 的独立退避和稳定窗口。
- 只有公网 health 失败但本机 health 正常时，优先排查入口、证书或隧道，不重启 juhe-ai。

完整配置见 [状态检测与自动恢复指南](../watchdog/状态检测与自动恢复指南.md)。

## 9. 不要混用的内容

- 不要把家庭宽带的 DDNS、路由器端口映射、公网服务器回源隧道写进服务器部署方案。
- 不要为了公网访问把 `JUHE_AI_HOST=0.0.0.0` 和 `3000` 裸露公网作为长期方案。
- 不要把 `JUHE_AI_OAUTH_PROXY_URL` 当成所有模型请求的全局代理；普通上游请求走后台账号代理绑定。
