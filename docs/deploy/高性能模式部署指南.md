# 高性能模式部署指南

> `performance = PostgreSQL + PgBouncer + Redis cache + Redis state`。
> 默认轻量部署看 [Docker 部署指南](Docker部署指南.md)。

## 1. 适用边界

适合 SQLite + 进程内缓存已经不够的部署。家庭宽带入口默认不选高性能模式。

当前边界：

- PostgreSQL repository adapter 仍未整体完成。
- 已迁移链路可按本文回归；未迁移 SQLite 数据库入口在 PostgreSQL 模式下 fail-fast，不回退写 SQLite。
- Redis `SharedJsonCache` 与 `RuntimeStateStore` driver 已有真实连通回归；现有生产 `createAppCache` 调用点仍主要是进程内 LRU，迁移到 Redis shared cache 前不能把它视为全量共享缓存。
- 高性能模式上线前必须在目标机器跑一次本机验证和业务回归。

压测和容量结论只放 [reports 目录](../reports/README.md)，不写进部署 runbook。

## 2. 组件

| 组件 | 默认镜像 | 边界 |
| --- | --- | --- |
| PostgreSQL | `postgres:18-bookworm` | 事实数据、统计结果、日志索引 |
| PgBouncer | `edoburu/pgbouncer:v1.25.2-p0` | 应用只连 PgBouncer |
| Redis cache | `redis:8.2.7-bookworm` | 可丢弃缓存，`allkeys-lru` |
| Redis state | `redis:8.2.7-bookworm` | 短 TTL 运行态、原子计数、Redis Streams，`noeviction` |
| juhe-ai | `node:22-bookworm-slim` | Web/API/网关/worker/DB service 主进程 |

不要使用 `latest` 镜像。Redis 8 授权如果不接受，需要单独评估替代方案。

## 3. 部署文件

```text
docker/
  compose.performance.yml
  .env.performance.example
  postgres/init/001-extensions.sql
```

默认生产入口是宿主机 Caddy HTTPS：

```text
公网 80/443 -> Caddy -> 127.0.0.1:3000 juhe-ai
```

Compose 默认端口边界：

- 应用：`JUHE_AI_PUBLIC_BIND=127.0.0.1`
- 中间件：`JUHE_AI_MIDDLEWARE_BIND=127.0.0.1`
- 公网只开放 Caddy `80/443`

## 4. 配置

```bash
cd docker
cp .env.performance.example .env.performance
nano .env.performance
```

必须填写：

```dotenv
JUHE_AI_PUBLIC_BIND=127.0.0.1
JUHE_AI_PUBLIC_PORT=3000
JUHE_AI_PUBLIC_ORIGIN=https://ai.example.com
JUHE_AI_SECRET=至少32位稳定随机密钥
JUHE_AI_COOKIE_SECURE=true
JUHE_AI_TRUST_PROXY=true

JUHE_AI_MIDDLEWARE_BIND=127.0.0.1
JUHE_AI_POSTGRES_PASSWORD=PostgreSQL强密码
JUHE_AI_REDIS_CACHE_PASSWORD=Redis缓存强密码
JUHE_AI_REDIS_STATE_PASSWORD=Redis运行态强密码

JUHE_AI_RUNTIME_MODE=performance
JUHE_AI_DATABASE_DRIVER=postgres
JUHE_AI_CACHE_DRIVER=redis
JUHE_AI_RUNTIME_STATE_DRIVER=redis
JUHE_AI_QUEUE_DRIVER=redis_stream

JUHE_AI_POSTGRES_URL=postgres://juhe_ai:<PostgreSQL密码URL编码>@pgbouncer:5432/juhe_ai
JUHE_AI_REDIS_CACHE_URL=redis://:<Redis缓存密码URL编码>@redis-cache:6379/0
JUHE_AI_REDIS_STATE_URL=redis://:<Redis运行态密码URL编码>@redis-state:6379/0
JUHE_AI_REDIS_QUEUE_URL=redis://:<Redis运行态密码URL编码>@redis-state:6379/0

JUHE_AI_SYSTEM_API_DB_SERVICE_MAX_IN_FLIGHT=256
JUHE_AI_DB_POOL_MAX=150
JUHE_AI_DB_WRITE_MAX_CONCURRENCY=100
JUHE_AI_DB_WRITE_QUEUE_MAX_ITEMS=50000
```

规则：

- `.env.performance.example` 的密钥和连接串保持空值，未填写时 Compose 必须失败。
- 改数据库或 Redis 密码时，同步改对应 URL；密码和 URL 不能漂移。
- URL 里的密码必须百分号编码；避免直接 `source .env.performance` 后拼接原始密码。
- `JUHE_AI_TRUST_PROXY=true` 只在应用端口被 Caddy、负载均衡或可信内网入口保护时使用。
- 当前 Docker 模板的 `POSTGRES_USER=juhe_ai` 是 PostgreSQL 初始化账号，按官方镜像语义具备较高权限；生产必须把 PostgreSQL / PgBouncer 端口限制在本机、VPN、SSH 隧道或安全组白名单内。独立 admin/app 账号改造需要同步 PgBouncer、初始化脚本和回归验证。

PowerShell 生成 URL 编码密码：

```powershell
[uri]::EscapeDataString('替换为强密码')
```

Node 生成 URL 编码密码：

```bash
node -e "console.log(encodeURIComponent(process.argv[1]))" '替换为强密码'
```

## 5. 启动

项目根目录先构建：

```bash
pnpm install
pnpm build
```

启动：

```bash
cd docker
docker compose --env-file .env.performance -f compose.performance.yml config --quiet
docker compose --env-file .env.performance -f compose.performance.yml up -d --build
docker compose --env-file .env.performance -f compose.performance.yml ps
```

看日志：

```bash
docker compose --env-file .env.performance -f compose.performance.yml logs --tail=100 postgres
docker compose --env-file .env.performance -f compose.performance.yml logs --tail=100 pgbouncer
docker compose --env-file .env.performance -f compose.performance.yml logs --tail=100 redis-cache
docker compose --env-file .env.performance -f compose.performance.yml logs --tail=100 redis-state
docker compose --env-file .env.performance -f compose.performance.yml logs --tail=100 juhe-ai
```

`postgres`、`pgbouncer`、`redis-cache`、`redis-state` 应为 healthy。`juhe-ai` 如果因未迁移 PG adapter 入口 fail-fast，先按第 7 节跑已迁移链路回归，不要让配置回退 SQLite。

## 6. PostgreSQL 初始化

在项目根目录执行。Docker 宿主机验证要把 URL 改成宿主机发布端口：

```bash
export JUHE_AI_RUNTIME_MODE=performance
export JUHE_AI_DATABASE_DRIVER=postgres
export JUHE_AI_CACHE_DRIVER=redis
export JUHE_AI_RUNTIME_STATE_DRIVER=redis
export JUHE_AI_QUEUE_DRIVER=redis_stream
export JUHE_AI_POSTGRES_URL='postgres://juhe_ai:<PostgreSQL密码URL编码>@127.0.0.1:6432/juhe_ai'
export JUHE_AI_REDIS_CACHE_URL='redis://:<Redis缓存密码URL编码>@127.0.0.1:6379/0'
export JUHE_AI_REDIS_STATE_URL='redis://:<Redis运行态密码URL编码>@127.0.0.1:6380/0'
export JUHE_AI_REDIS_QUEUE_URL="$JUHE_AI_REDIS_STATE_URL"

pnpm --filter juhe-ai-backend postgres:init-schema-only
pnpm --filter juhe-ai-backend postgres:init-schema
```

`postgres:init-schema-only` 是幂等 DDL，同样用于旧库补齐当前版本新增字段和索引；例如 `juhe_usage.usage_records` 的 `usage_semantic`、`cache_write_tokens`、`thinking_tokens`、`provider_protocol_profile_id`、`failure_attribution` 等运行态字段会通过 `ALTER TABLE IF EXISTS ... ADD COLUMN IF NOT EXISTS ...` 同步。生产执行前先备份，执行后跑第 7 节 readiness。

抽样检查：

```bash
docker compose --env-file .env.performance -f compose.performance.yml exec -T postgres \
  sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "SELECT count(*) FROM juhe_business.system_accounts;"'
```

旧库同步到当前 schema 时，必须确认调度索引方向：

```sql
DROP INDEX IF EXISTS juhe_business.idx_group_accounts_dispatch_priority;
CREATE INDEX idx_group_accounts_dispatch_priority
  ON juhe_business.group_accounts(
    group_id,
    enabled,
    local_fallback_enabled ASC,
    local_super_priority_enabled DESC,
    local_priority ASC,
    created_at ASC,
    account_id ASC
  );
ANALYZE juhe_business.group_accounts;
```

### 6.1 SQLite 停机迁移

从 SQLite 切换到 PostgreSQL 只支持停机离线迁移，不在应用启动路径自动迁移，也不做运行时双读双写。迁移前必须停止 Web、DB service、worker 和任何会写 SQLite 的脚本，并先备份 SQLite 文件、`backend/.env`、usage shard 目录、Codex context state shard 目录和 PostgreSQL 目标库。

迁移脚本默认读取当前 SQLite 路径环境变量，目标库读取 `JUHE_AI_POSTGRES_URL`。脚本不会输出 PostgreSQL 连接串。

预检查：

```bash
export JUHE_AI_POSTGRES_URL='postgres://juhe_ai:<PostgreSQL密码URL编码>@127.0.0.1:6432/juhe_ai'

pnpm --filter juhe-ai-backend run postgres:migrate-sqlite -- \
  --confirm-offline \
  --dry-run
```

正式导入：

```bash
pnpm --filter juhe-ai-backend run postgres:migrate-sqlite -- \
  --confirm-offline \
  --batch-size=500
```

常用参数：

- `--source-business=...`：覆盖业务库 SQLite 路径，默认 `backend/data/juhe-ai.sqlite3`。
- `--source-dataset=...`：覆盖数据集目录库路径。
- `--source-usage-catalog=...`：覆盖使用记录目录库路径。
- `--source-stats=...`：覆盖统计结果库路径。
- `--source-usage-shard-root=...`：覆盖 usage shard 根目录；脚本仍通过 usage catalog 的 `usage_record_shards` 清单定位 shard 文件，不枚举整个目录。
- `--source-codex-context-state-shard-root=...` 和 `--source-codex-context-state-shard-count=...`：覆盖 Codex context state 分片。
- `--skip-usage-shards` / `--skip-codex-context-state`：明确跳过对应分片数据。
- `--skip-schema`：目标库 schema 已由 `postgres:init-schema-only` 初始化时使用。
- `--allow-non-empty-target`：默认目标表非空会拒绝导入；只有确认要追加导入时才使用。

导入后至少执行：

```bash
pnpm --filter juhe-ai-backend postgres:init-schema-only
pnpm --filter juhe-ai-backend test:performance-system-api-smoke
pnpm --filter juhe-ai-backend test:performance-gateway-persistence-readiness
```

如果迁移了 usage 明细但不迁移统计窗口，必须在停机窗口内按当前统计重建流程刷新派生统计；如果迁移了旧统计窗口，也要以 smoke / readiness 的结果为准，不要直接假定旧窗口口径满足当前版本。

## 7. 健康检查和回归

中间件：

```bash
docker compose --env-file .env.performance -f compose.performance.yml exec postgres \
  sh -c 'pg_isready -U "$POSTGRES_USER" -d "$POSTGRES_DB"'

docker compose --env-file .env.performance -f compose.performance.yml exec pgbouncer \
  sh -c 'pg_isready -h 127.0.0.1 -p 5432 -U "$DB_USER" -d "$DB_NAME"'

docker compose --env-file .env.performance -f compose.performance.yml exec redis-cache \
  sh -c 'redis-cli -a "$REDIS_CACHE_PASSWORD" ping'

docker compose --env-file .env.performance -f compose.performance.yml exec redis-state \
  sh -c 'redis-cli -a "$REDIS_STATE_PASSWORD" ping'
```

## 8. 备份

PostgreSQL：

```bash
mkdir -p backups
docker compose --env-file .env.performance -f compose.performance.yml exec -T postgres \
  sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" --format=custom' \
  > backups/juhe-ai-$(date +%Y%m%d-%H%M%S).dump
```

恢复到空库：

```bash
cat backups/juhe-ai-YYYYMMDD-HHMMSS.dump | docker compose --env-file .env.performance -f compose.performance.yml exec -T postgres \
  sh -c 'pg_restore -U "$POSTGRES_USER" -d "$POSTGRES_DB" --clean --if-exists'
```

Redis：

- `redis-cache` 不做业务备份。
- `redis-state` 是短 TTL 运行态和队列缓冲；AOF 只减少重启瞬时损失，不作为业务事实源。

应用 volume：

- `juhe-ai-data` 仍可能保存审计 blob、上下文文件、自动生成文件和临时数据。
- `juhe-ai-logs` 保存日志。

## 9. 调优基线

起步值：

```text
PostgreSQL max_connections=300
PgBouncer default_pool_size=50
JUHE_AI_DB_POOL_MAX=150
JUHE_AI_SYSTEM_API_DB_SERVICE_MAX_IN_FLIGHT=256
JUHE_AI_DB_WRITE_MAX_CONCURRENCY=100
Redis cache/state maxmemory=512mb
```

调优顺序：

- 先看 PgBouncer 等待、PostgreSQL active session、慢 SQL、锁等待和 Redis Stream backlog（pending + consumer group lag）。
- 不直接通过加大连接数解决慢查询或热点行冲突。
- `redis-cache` 可淘汰；`redis-state` 不允许随机淘汰。
- Redis Streams 是 at-least-once 缓冲，不是使用记录事实源。

## 10. 非 Docker 边界

非 Docker 只要部署出等价边界即可：

```text
PostgreSQL 18
PgBouncer 6432
Redis cache 6379
Redis state 6380
Redis queue 默认复用 Redis state
```

安装命令按目标系统官方文档执行，不在主 runbook 维护逐包教程。完成后仍使用本文第 4、6、7 节的 env、初始化和回归命令。

硬性要求：

- PgBouncer 和 Redis 默认绑定 `127.0.0.1`。
- 跨机器访问只走内网 IP、VPN、SSH 隧道或安全组白名单。
- `pg_hba.conf` 用真实可信 CIDR 占位，不写死示例私网。
- 应用和 worker 连接 PgBouncer，不直连 PostgreSQL。

## 11. 停止和清理

停止：

```bash
docker compose --env-file .env.performance -f compose.performance.yml down
```

删除 volume：

```bash
docker compose --env-file .env.performance -f compose.performance.yml down -v
```

`down -v` 会删除 PostgreSQL、Redis、应用数据和日志，只能用于临时测试环境。
