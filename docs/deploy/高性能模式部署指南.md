# 高性能模式部署指南

> 本文说明 `performance = PostgreSQL + Redis` 模式的中间件部署、配置、验证、备份和调优。默认轻量 Docker 部署仍看 [Docker 部署指南](Docker部署指南.md)。

## 适用边界

高性能模式用于用户量和网关请求量已经超过 SQLite + 进程内缓存承载能力的部署。该模式会引入：

- PostgreSQL：事实数据、统计结果、日志索引和可恢复运行数据。
- PgBouncer：应用和 worker 到 PostgreSQL 的连接池网关。
- Redis cache：可丢弃缓存，允许 LRU 淘汰。
- Redis state：短 TTL 运行态、原子计数、限流、调度状态和默认 Redis Streams 队列，不允许随机淘汰。

当前代码已经具备运行模式配置、Docker 中间件栈、Redis cache / state driver、Redis Streams 使用记录队列首批链路、登录失败窗口 Redis state、账号并发槽 Redis 原子获取 / 释放、使用记录队列 PG 并发 drain 骨架、PostgreSQL pool 骨架、PostgreSQL schema 初始化脚本和默认种子写入脚本。PostgreSQL repository adapter 仍未整体完成，但 provider 只读、登录 / 会话、系统账户管理读写、分组管理读写、API Key 管理读写与网关 Key 校验入口、AI 账户最小创建与分组绑定 repository、AI 账户普通 owner 列表 / 详情 / options 读取、常规更新、异常状态恢复、逻辑删除、账户授权实例归还、授权列表个人归还、分组个人归还、账号支持模型 / 模型映射附属表 replace 写入、公共设置读取、系统 API 限流设置读取和系统设置管理读写已完成双 driver 适配；其他仍未迁移的 SQLite 数据库入口会拒绝在 PostgreSQL 模式下回退写入 SQLite。

## 部署文件

```text
docker/
  compose.performance.yml
  .env.performance.example
  postgres/init/001-extensions.sql
```

本文同时维护两套中间件部署方式：

- Docker 模式：推荐生产默认方案，使用 `docker/compose.performance.yml`，便于复制、回滚和清理。
- 非 Docker 模式：用于不允许 Docker 的服务器或需要系统包托管的环境；部署后仍必须暴露同样的 PostgreSQL / PgBouncer / Redis cache / Redis state 连接边界。

不要使用 `latest` 镜像。当前模板默认：

| 组件 | 默认镜像 | 说明 |
| --- | --- | --- |
| PostgreSQL | `postgres:18-bookworm` | 当前稳定主版本线，启用 `pg_stat_statements`。 |
| PgBouncer | `edoburu/pgbouncer:v1.25.2-p0` | transaction pool，应用只连 PgBouncer。 |
| Redis | `redis:8.2.7-bookworm` | cache / state 拆成两个实例；Redis Streams 队列默认复用 state，也可拆独立实例。 |
| Node | `node:22-bookworm-slim` | 应用运行镜像。 |

Redis 8 授权需要生产前确认；如不能接受 Redis 8 授权，需单独评估替代方案，不能直接静默换实现。

`192.168.1.203` 在 2026-06-25 已完成中间件实启验证。该主机 Docker daemon 配置了 `127.0.0.1:7890` 代理，但代理当前不可用；实际部署时 PostgreSQL / Redis 使用 `docker.m.daocloud.io` 镜像源，PgBouncer 先临时移开 Docker daemon 代理后从 `docker.1ms.run/edoburu/pgbouncer:v1.25.2-p0` 拉取，并本地 tag 为 `edoburu/pgbouncer:v1.25.2-p0`。操作结束后已恢复 Docker daemon 原代理配置。

- 开放宿主机端口只暴露需要访问的端口；PostgreSQL、PgBouncer、Redis 在生产上优先只允许内网或本机访问。

## 非 Docker 中间件部署

非 Docker 模式的目标是部署出与 Docker 模式等价的四个边界：`PostgreSQL 18`、`PgBouncer 6432`、`Redis cache 6379`、`Redis state 6380`。Redis Streams 队列默认复用 Redis state，如业务要把队列与运行态完全隔离，可以额外部署独立 Redis queue 实例并把 `JUHE_AI_REDIS_QUEUE_URL` 指过去。安装命令按 [PostgreSQL 官方 PGDG APT](https://www.postgresql.org/download/linux/ubuntu/)、[Redis 官方安装文档](https://redis.io/docs/latest/operate/oss_and_stack/install/) 和 [PgBouncer 配置文档](https://www.pgbouncer.org/config.html) 整理；生产执行前先按目标发行版确认包源、版本和授权策略。

### 端口检查

先确认端口未被 Docker 或系统服务占用：

```bash
sudo ss -lntp | grep -E ':(5432|6432|6379|6380)\s' || true
```

`192.168.1.203` 当前 Docker 栈已经占用 `5432`、`6432`、`6379` 和 `6380`。在这台机器做非 Docker 演练时，只能选择临时端口，例如 `15432`、`16432`、`16379`、`16380`；或先停掉 Docker 中间件，再使用生产端口。演练结束后必须删除临时 systemd 服务、配置和数据目录，保留 Docker 栈作为后续生产切换准备。

### 安装 PostgreSQL 与 PgBouncer

Ubuntu / Debian：

```bash
sudo apt install -y ca-certificates curl postgresql-common
sudo /usr/share/postgresql-common/pgdg/apt.postgresql.org.sh
sudo apt update
sudo apt install -y postgresql-18 postgresql-client-18 pgbouncer
```

Red Hat / Rocky / AlmaLinux 使用 PostgreSQL 官方 YUM/DNF 仓库安装同一主版本，并安装 `pgbouncer`。不要安装发行版仓库里过旧且不可控的主版本。

创建数据库和管理员 / 应用账号。当前 Docker 模板使用同一个 `juhe_ai` 账号承担初始化和应用读写；非 Docker 模式保持一致，便于脚本和连接串统一：

```bash
export JUHE_AI_POSTGRES_DB=juhe_ai
export JUHE_AI_POSTGRES_USER=juhe_ai
export JUHE_AI_POSTGRES_PASSWORD='替换为强密码'

sudo -u postgres psql -v ON_ERROR_STOP=1 <<SQL
SET password_encryption = 'scram-sha-256';
CREATE ROLE ${JUHE_AI_POSTGRES_USER} WITH LOGIN SUPERUSER PASSWORD '${JUHE_AI_POSTGRES_PASSWORD}';
CREATE DATABASE ${JUHE_AI_POSTGRES_DB} OWNER ${JUHE_AI_POSTGRES_USER};
\c ${JUHE_AI_POSTGRES_DB}
CREATE EXTENSION IF NOT EXISTS pg_stat_statements;
SQL
```

编辑 `/etc/postgresql/18/main/postgresql.conf`，初始值按测试模板对齐，生产再按压测调整：

```conf
listen_addresses = '127.0.0.1'
password_encryption = 'scram-sha-256'
shared_preload_libraries = 'pg_stat_statements'
max_connections = 300
shared_buffers = 512MB
effective_cache_size = 1536MB
work_mem = 8MB
maintenance_work_mem = 256MB
checkpoint_timeout = 10min
max_wal_size = 4GB
wal_compression = on
log_min_duration_statement = 1000
```

编辑 `/etc/postgresql/18/main/pg_hba.conf`，只放行 PgBouncer / 本机或可信内网：

```conf
local   all       postgres                         peer
host    juhe_ai   juhe_ai   127.0.0.1/32           scram-sha-256
host    juhe_ai   juhe_ai   192.168.1.0/24         scram-sha-256
```

如果应用只连本机 PgBouncer，`postgresql.conf` 保持 `127.0.0.1` 即可；需要跨机器直连 PostgreSQL 才把 `listen_addresses` 和防火墙打开到内网 IP。

重启并验证：

```bash
sudo systemctl enable --now postgresql
sudo systemctl restart postgresql
pg_isready -h 127.0.0.1 -p 5432 -U "$JUHE_AI_POSTGRES_USER" -d "$JUHE_AI_POSTGRES_DB"
```

### 配置 PgBouncer

写入 `/etc/pgbouncer/pgbouncer.ini`：

```ini
[databases]
juhe_ai = host=127.0.0.1 port=5432 dbname=juhe_ai user=juhe_ai password=替换为PostgreSQL强密码

[pgbouncer]
listen_addr = 0.0.0.0
listen_port = 6432
auth_type = scram-sha-256
auth_file = /etc/pgbouncer/userlist.txt
pool_mode = transaction
max_client_conn = 1000
default_pool_size = 50
reserve_pool_size = 20
ignore_startup_parameters = extra_float_digits
admin_users = juhe_ai
stats_users = juhe_ai
log_connections = 1
log_disconnections = 1
```

从 PostgreSQL 读取该账号的 SCRAM secret，写入 `/etc/pgbouncer/userlist.txt`。这样 `auth_type = scram-sha-256` 与用户表格式一致，也避免在 PgBouncer 用户表里重复保存明文密码：

```bash
sudo -u postgres psql -At -c "SELECT '\"' || rolname || '\" \"' || rolpassword || '\"' FROM pg_authid WHERE rolname = 'juhe_ai';" \
  | sudo tee /etc/pgbouncer/userlist.txt > /dev/null
```

权限和启动：

```bash
sudo chown pgbouncer:pgbouncer /etc/pgbouncer/pgbouncer.ini /etc/pgbouncer/userlist.txt
sudo chmod 640 /etc/pgbouncer/pgbouncer.ini /etc/pgbouncer/userlist.txt
sudo systemctl enable --now pgbouncer
sudo systemctl restart pgbouncer
pg_isready -h 127.0.0.1 -p 6432 -U "$JUHE_AI_POSTGRES_USER" -d "$JUHE_AI_POSTGRES_DB"
```

应用和 worker 必须连接 PgBouncer，不直接连 PostgreSQL：

```bash
export JUHE_AI_POSTGRES_URL="postgres://${JUHE_AI_POSTGRES_USER}:${JUHE_AI_POSTGRES_PASSWORD}@127.0.0.1:6432/${JUHE_AI_POSTGRES_DB}"
```

### 安装 Redis 并拆分双实例

Ubuntu / Debian：

```bash
sudo apt-get install -y lsb-release curl gpg
curl -fsSL https://packages.redis.io/gpg | sudo gpg --dearmor -o /usr/share/keyrings/redis-archive-keyring.gpg
sudo chmod 644 /usr/share/keyrings/redis-archive-keyring.gpg
echo "deb [signed-by=/usr/share/keyrings/redis-archive-keyring.gpg] https://packages.redis.io/deb $(lsb_release -cs) main" | sudo tee /etc/apt/sources.list.d/redis.list
sudo apt-get update
sudo apt-get install -y redis
sudo systemctl disable --now redis-server || true
```

创建目录：

```bash
sudo install -o redis -g redis -d /var/lib/redis-juhe-cache /var/lib/redis-juhe-state /var/log/redis
```

`/etc/redis/juhe-cache.conf`：

```conf
bind 127.0.0.1
protected-mode yes
port 6379
requirepass 替换为Redis缓存强密码
dir /var/lib/redis-juhe-cache
logfile /var/log/redis/juhe-cache.log
supervised systemd
appendonly no
save ""
maxmemory 512mb
maxmemory-policy allkeys-lru
timeout 0
tcp-keepalive 300
```

`/etc/redis/juhe-state.conf`：

```conf
bind 127.0.0.1
protected-mode yes
port 6380
requirepass 替换为Redis运行态强密码
dir /var/lib/redis-juhe-state
logfile /var/log/redis/juhe-state.log
supervised systemd
appendonly yes
appendfsync everysec
maxmemory 512mb
maxmemory-policy noeviction
timeout 0
tcp-keepalive 300
```

如果应用不在同一台机器，`bind` 改成内网 IP，同时用防火墙限制来源，不允许公网访问 Redis。

systemd 模板 `/etc/systemd/system/redis-juhe@.service`：

```ini
[Unit]
Description=Redis Juhe AI %i
After=network.target

[Service]
Type=notify
User=redis
Group=redis
ExecStart=/usr/bin/redis-server /etc/redis/juhe-%i.conf --supervised systemd --daemonize no
ExecStop=/bin/kill -s TERM $MAINPID
Restart=always
RestartSec=3
LimitNOFILE=100000
NoNewPrivileges=true
PrivateTmp=true
PrivateDevices=true
ProtectHome=true
ProtectSystem=full

[Install]
WantedBy=multi-user.target
```

启动和验证：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now redis-juhe@cache redis-juhe@state
redis-cli -h 127.0.0.1 -p 6379 -a '替换为Redis缓存强密码' ping
redis-cli -h 127.0.0.1 -p 6380 -a '替换为Redis运行态强密码' ping
```

应用连接串：

## PostgreSQL 初始化

中间件启动后，先初始化 PostgreSQL schema 和默认种子数据。脚本是幂等的：

```bash
pnpm --filter juhe-ai-backend postgres:init-schema-only
pnpm --filter juhe-ai-backend postgres:init-schema
```

命令含义：

- `postgres:init-schema-only`：只执行 DDL，用于先验证 PostgreSQL 方言映射。
- `postgres:init-schema`：执行 DDL 后写入默认种子数据，包含默认管理员、内置供应商 / 协议 / 分组、全局设置和系统设置。
- `postgres:print-schema`：只输出生成的 PostgreSQL SQL，便于审计或手工 `psql -f`。

如果在 Docker 宿主机运行脚本，`docker/.env.performance` 里的应用 URL 使用的是容器内 DNS，例如 `pgbouncer:5432`、`redis-cache:6379`、`redis-state:6379`。宿主机命令需要临时改为发布端口：

```bash
set -a
. docker/.env.performance
set +a

export JUHE_AI_POSTGRES_URL="postgres://${JUHE_AI_POSTGRES_USER}:${JUHE_AI_POSTGRES_PASSWORD}@127.0.0.1:${JUHE_AI_PGBOUNCER_PORT}/${JUHE_AI_POSTGRES_DB}"
export JUHE_AI_REDIS_CACHE_URL="redis://:${JUHE_AI_REDIS_CACHE_PASSWORD}@127.0.0.1:${JUHE_AI_REDIS_CACHE_PORT}/0"
export JUHE_AI_REDIS_STATE_URL="redis://:${JUHE_AI_REDIS_STATE_PASSWORD}@127.0.0.1:${JUHE_AI_REDIS_STATE_PORT}/0"
export JUHE_AI_REDIS_QUEUE_URL="redis://:${JUHE_AI_REDIS_STATE_PASSWORD}@127.0.0.1:${JUHE_AI_REDIS_STATE_PORT}/0"

pnpm --filter juhe-ai-backend postgres:init-schema
```

从其他开发机验证同一远端 Docker 栈时，把上面 `127.0.0.1` 换成服务器内网 IP，例如 `192.168.1.203`。

初始化后抽样检查：

```bash

  psql -U "$JUHE_AI_POSTGRES_USER" -d "$JUHE_AI_POSTGRES_DB" -c "SELECT count(*) FROM juhe_business.system_accounts;"
```

Redis：

- `redis-cache` 不需要业务备份，丢失后可重建。
- `redis-state` 只保存短 TTL 运行态，AOF 用于减少重启瞬时损失，不作为业务恢复来源。

- `juhe-ai-logs` 保存日志。
- `juhe-ai-data` 在 performance 模式下仍可能保存审计 blob、上下文文件、自动生成文件和临时数据；生产备份策略需要覆盖。

## 调优基线

PostgreSQL 初始参数在 `compose.performance.yml` 中设置：

- `max_connections=300`
- `shared_buffers=512MB`
- `effective_cache_size=1536MB`
- `work_mem=8MB`
- `maintenance_work_mem=256MB`
- `log_min_duration_statement=1000`

这些值适合中小测试机起步。生产需要按 CPU、内存、磁盘和请求压测调整：

- 内存较小时先降低 `shared_buffers` 和 PgBouncer pool。
- 并发上升时优先看 PgBouncer 等待、PostgreSQL active session、慢 SQL 和锁等待，不直接把连接数加大。
- 写队列最大并发默认 `JUHE_AI_DB_WRITE_MAX_CONCURRENCY=100`，但实际吞吐受 PgBouncer pool、`JUHE_AI_DB_POOL_MAX` 和热点行冲突限制。

Redis：

- `redis-cache` 使用 `allkeys-lru`，达到内存上限会淘汰缓存。
- `redis-state` 使用 `noeviction`，写入必须带 TTL 或 Stream 长度上限；如果写满，调用方必须降级或拒绝。
- Redis Streams 队列默认复用 `redis-state`，消息是 at-least-once 缓冲，不是使用记录事实源；生产监控要看 stream length、pending 数量、consumer idle、AOF rewrite 和 Redis 内存。
- cache 和 state 不要混用同一个 LRU 实例。

## 停止与清理

停止：

```bash
docker compose --env-file .env.performance -f compose.performance.yml down
```

删除 volume：

```bash
docker compose --env-file .env.performance -f compose.performance.yml down -v
```

`down -v` 会删除 PostgreSQL、Redis、应用数据和日志，只能用于临时测试环境。
