# 部署指南（国内单机 Docker，唯一生产形态）

> 2026-09-26 起生产为**国内单台云服务器 + Docker Compose**（PostgreSQL + Redis + gateway/jobs/maintenance + Caddy，域名 HTTPS）。家庭宽带反代、Edge 隧道、macOS/Windows/K8s 等旧形态已废弃删除；本文只描述当前形态。配置源文件与构建/更新命令的权威位置是仓库 `docker/single-server/`（README 为准），本文是面向使用者的总览。

## 1. 前置

- 国内云服务器（生产：4 核 8G，Debian 13），安全组/防火墙放行 22/80/443；域名 A 记录指向服务器 IP（HTTPS 由 Caddy 自动签发续期）。
- 国内网络拉取 Docker Hub 需配镜像加速；BuildKit 构建基础镜像直接用 `docker.m.daocloud.io/...` 前缀（见 `docker/single-server/compose.yml`）。
- 服务器出海上游代理（AI 上游必需）：见 [sing-box 网络代理部署指南](proxy/sing-box网络代理部署指南.md) 与第 5 节当前约定。

## 2. 构建与首次部署

```sh
# 本机构建（交叉编译 + 前端），产物在 docker/single-server/build/
for p in gateway jobs maintenance; do
  (cd backend-go/projects/$p && CGO_ENABLED=0 GOOS=linux GOARCH=amd64 \
    go build -trimpath -ldflags "-s -w" -o ../../../docker/single-server/build/bin/juhe-ai-$p ./cmd/juhe-ai-$p)
done
(cd frontend && pnpm build && rm -rf ../docker/single-server/build/frontend-dist && cp -r dist ../docker/single-server/build/frontend-dist)

# 上传服务器 /opt/juhe-ai 后：build → 起 postgres/redis → maintenance 初始化 → up -d
# 完整初始化序列（含 juhe_jobs/juhe_j3b 预置、J3b 运行态索引）见 docker/single-server/README.md
```

要点（详见 `docker/single-server/README.md`）：

- PG 为单库 `juhe_ai` 多 schema；`juhe_jobs`/`juhe_j3b` 需手工建 schema 后用 maintenance `--apply-*` 建表；J2 余额四表按 `balancePostgresSchema` 手工执行。
- gateway 启动硬性要求 J3b 账户电路运行态索引 ready：新库必须执行 `docker compose run --rm gateway -init-account-circuit-runtime-index`。
- 必需 env：`JUHE_AI_SECRET`（加密封套，有数据后不可换）、`JUHE_AI_RUNTIME_LOG_POSTGRES_URL`/`JUHE_AI_TABLE_MONITOR_POSTGRES_URL`（无回退）、`JUHE_AI_J3B_CIRCUIT_REDIS_URL`（不得与 state 同键空间）、`JUHE_AI_FRONTEND_DIST_PATH`。
- 系统指标 Go Runtime 采样自 2026-09-27 起默认开启（跟随主存储）：生产 PG 模式下默认即 postgres（`JUHE_AI_GO_RUNTIME_METRICS_POSTGRES_URL` 可省略回退主库 URL，通常无需显式配置）；显式 `JUHE_AI_GO_RUNTIME_METRICS_STORE=disabled` 才关闭（`ROLE` 已删除不得配置）。顺序契约按存储分派：postgres 模式新环境首次启动前必须先 maintenance `--check-go-runtime-metrics`/`--apply-go-runtime-metrics` 建表（缺表时 gateway/jobs 启动只读校验 fail-fast 循环重启）；sqlite 模式启动自举建表（幂等），无需预处理；完整契约见 `docker/single-server/README.md` 的".env 契约"节。
- **运行时数据目录契约**：gateway/jobs 的相对路径（`data/`、`logs/`，含用量记录 spool 交接目录）以进程 cwd 为基准；镜像未设 `WORKDIR`，compose 里 gateway/jobs 的 `working_dir: /app/backend` 不可删——两侧必须同源解析到宿主机挂载的 `data/app/data`，否则用量记录永不到库、全部统计为空（详见 `docker/single-server/README.md`"运行时数据目录契约"，BUG-0193）。
- seed 初始管理员 `admin/admin`，首次登录立即改密。

## 3. HTTPS

Caddy 自动 ACME（Let's Encrypt）签发与续期，80 常驻 308 升级 HTTPS；Caddyfile 在 `docker/single-server/Caddyfile`。该文件为同机两栈共享：还承载同机公益站（juhe-pw 栈）`gyai.huanmin.top` 的反代块，同步/修改时不得遗漏，改前备份、改后 `caddy validate` + `caddy reload`。通用证书说明见 [https/Caddy自动HTTPS部署指南](https/Caddy自动HTTPS部署指南.md)（Edge/家庭回源章节已废弃）。

## 4. 更新与回滚

重复"构建 → 上传 → `docker compose build gateway jobs maintenance` → `docker compose up -d`"；发布后跑一次幂等 `maintenance --ensure-schema`。回滚 = 上传上一版 `build/` 重新 build+up。

## 5. 出站代理（AI 上游）

出站代理有两条宿主机侧链路，**当前生产主用本机 sing-box**（实例级事实与主备切换步骤见私有运维手册，不在公开文档记录）：

- **本机 sing-box（当前主用）**：systemd 单元 `juhe-pw-proxy.service`，配置 `/etc/sing-box/config.json`；mixed 入站监听 `172.18.0.1:17892`，出站为订阅云端节点池。多节点订阅池必须配合两件自动化：**择优控制器**（`selector` 组 + `juhe-proxy-switch` timer，2 分钟周期：先对真实上游确认测试再切、10 分钟最小切换间隔、100ms 容差、坏节点拉黑）与**每小时订阅更新器**（`juhe-sub-update` timer：变更检测、check 门禁、失败回滚）——订阅池存在分钟级漂移、目的地相关 503 和服务商随时轮换节点，裸 `urltest`、固定单节点或静态配置都不可靠。策略与部署见 [sing-box 网络代理部署指南](proxy/sing-box网络代理部署指南.md) 第 10、11 节。
- **常驻隧道（备用）**：宿主机 systemd `ssh -L` 转发进程提供 SOCKS5 入口，同样经后台"代理管理"绑定。

容器内访问宿主机代理注意：`host.docker.internal` 解析到 `172.17.0.1`（docker0 网桥），代理进程绑定哪个口就填哪个地址（当前服务器上隧道绑三口、sing-box 只绑 `172.18.0.1`）。该 sing-box 单元为宿主机级服务，与同机公益站（juhe-pw）共用，变更其配置前先评估两栈影响。

## 6. 验证清单

- `docker compose ps` 全 healthy；`GET /__aisys__/health` 全 `ready:true`。
- `https://<域名>/` 301 到 `/__aisys__/`，登录、各管理页、代理测试通过。
- `/v1/models` 返回 401（鉴权层正常）；用真实 API Key 请求业务模型。
- **统计落库验证**：发起一次真实 `/v1` 请求后，`SELECT count(*) FROM juhe_usage.usage_records;` 应 > 0 并持续增长，管理面统计页面出数；恒 0 行 = spool 交接断裂，按 `docker/single-server/README.md`"运行时数据目录契约"检查 gateway/jobs 两侧目录是否同源（BUG-0193）。
- **AI 健康监控验证**：J1 探针首轮运行（分钟级）后，`SELECT count(*) FROM juhe_stats.account_health_hourly;` 应 > 0 并逐小时累积；恒 0 行按 BUG-0194 分层排查（输入版本基线 → outcomes 是否增长 → 条带写入）。
- 宿主机 `data/app/data/`（usage-record-spool、chat-assets、logs 等）与 `data/app/logs/` 应出现内容——出现在容器私有层说明 `working_dir` 丢失。
