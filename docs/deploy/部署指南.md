# 跨平台部署文档

> 本文只说明如何把发布包部署到 Windows、macOS、Linux。如何构建发布包见 `docs/deploy/构建指南.md`。

## 1. 部署兼容矩阵

同一个发布包可以部署到三类目标机器：

| 部署目标 | 推荐压缩包 | 启动脚本 | 常驻运行建议 |
| --- | --- | --- | --- |
| Windows | `juhe-ai-release.zip` | `pwsh ./start.ps1` | NSSM / PM2 / 任务计划程序 |
| macOS | `juhe-ai-release.tar.gz` | `bash ./start.sh` | launchd / PM2 |
| Linux | `juhe-ai-release.tar.gz` | `bash ./start.sh` | systemd / PM2 |

不要跨系统复制 `node_modules`。日志搜索 `grep 模式` 只使用后端生产依赖 `@vscode/ripgrep` 安装的 `rg`，不读取服务器 PATH 中的系统 `rg`，也不回退到 Node 文件扫描。Windows、macOS、Linux 的 x64 / arm64 等平台差异由目标机器执行 `pnpm install --prod` 时自动处理。

## 2. 部署前必须检测

### Windows 目标

```powershell
$PSVersionTable.PSVersion
Get-Location
node -v
node --input-type=module -e "import 'node:sqlite'; console.log('node:sqlite ok')"
corepack --version
pnpm -v
netstat -ano | Select-String ':3000'
```

### macOS 目标

```bash
pwd
sw_vers
uname -a
df -h .
node -v
node --input-type=module -e "import 'node:sqlite'; console.log('node:sqlite ok')"
corepack --version || true
pnpm -v || true
lsof -iTCP:3000 -sTCP:LISTEN || true
```

### Linux 目标

```bash
pwd
uname -a
df -h .
node -v
node --input-type=module -e "import 'node:sqlite'; console.log('node:sqlite ok')"
corepack --version || true
pnpm -v || true
ss -lntp | grep ':3000 ' || true
curl -I https://registry.npmjs.org/ || true
```

必须确认：

- Node.js 支持 `node:sqlite`，建议 Node.js 22.13.0+（22.x）或 23.4.0+。
- pnpm 可用，或 corepack 可用且能启用 pnpm。
- 首次启动能访问 npm registry，或已配置可用代理/缓存。
- 默认端口 `3000` 未被占用；占用时修改 `backend/.env` 的 `JUHE_AI_PORT`。
- 当前部署目录有写入权限和足够磁盘空间。
- 如果 `grep 模式` 报找不到 `rg`，确认目标机器的后端生产依赖安装成功，尤其是 `@vscode/ripgrep` 及其当前平台 optional dependency 没有被跳过。

## 3. 解压发布包

### Windows

推荐 zip：

```powershell
Expand-Archive .\juhe-ai-release.zip -DestinationPath . -Force
Set-Location .\juhe-ai-release
```

如果拿到的是 `tar.gz`：

```powershell
tar -xzf .\juhe-ai-release.tar.gz
Set-Location .\juhe-ai-release
```

### macOS / Linux

推荐 `tar.gz`：

```bash
tar -xzf juhe-ai-release.tar.gz
cd juhe-ai-release
```

如果拿到的是 zip：

```bash
unzip juhe-ai-release.zip
cd juhe-ai-release
```

### 文件检查

Windows：

```powershell
Test-Path .\start.ps1
Test-Path .\start.sh
Test-Path .\backend\dist\server.js
Test-Path .\backend\dist\worker.js
Test-Path .\frontend\dist\index.html
Test-Path .\pnpm-lock.yaml
```

macOS / Linux：

```bash
test -f start.sh
test -f start.ps1
test -f backend/dist/server.js
test -f backend/dist/worker.js
test -f frontend/dist/index.html
test -f pnpm-lock.yaml
```

## 4. 配置 `backend/.env`

### 创建配置文件

Windows：

```powershell
Copy-Item .\backend\.env.example .\backend\.env -ErrorAction SilentlyContinue
notepad .\backend\.env
```

macOS / Linux：

```bash
cp -n backend/.env.example backend/.env
nano backend/.env
```

### 最低配置

```env
JUHE_AI_HOST=127.0.0.1
JUHE_AI_PORT=3000
JUHE_AI_DATABASE_PATH=./data/juhe-ai.sqlite3
JUHE_AI_RECORD_DATABASE_PATH=./data/juhe-ai-records.sqlite3
JUHE_AI_SECRET=换成一串足够长且固定保存的随机密钥
JUHE_AI_OAUTH_PROXY_URL=
```

配置规则：

- 反向代理或本机访问：`JUHE_AI_HOST=127.0.0.1`。
- 局域网/公网直连访问：`JUHE_AI_HOST=0.0.0.0`，并开放系统防火墙或云安全组端口。
- 新部署必须修改 `JUHE_AI_SECRET`，不要使用示例值。
- 迁移旧数据必须沿用旧 `JUHE_AI_SECRET`。
- `JUHE_AI_SECRET` 改错会导致 OAuth token、上游 API Key、代理密码等敏感字段无法解密。
- `JUHE_AI_DATABASE_PATH` 只保存系统账户、AI 账户、分组、API Key、授权、设置和公告等业务数据。
- `JUHE_AI_RECORD_DATABASE_PATH` 保存使用记录、统计缓存、运行日志索引、操作日志、原始审计、系统监控和表监控历史；默认备份不包含记录库。

## 5. 启动

### Windows

```powershell
pwsh .\start.ps1
```

### macOS / Linux

```bash
bash ./start.sh
```

启动脚本会：

- 检查 Node.js 和 `node:sqlite`。
- 尝试通过 corepack 启用 pnpm。
- 缺少 `backend/.env` 时自动创建。
- 创建 `backend/data`。
- 首次安装目标平台生产依赖，并随依赖安装 `@vscode/ripgrep` 对应平台的 `rg` 二进制。
- Web/API/网关主进程会自动 fork 独立 background worker 进程，调度和后台任务执行都在 worker 内完成。

后台任务运行边界：

- Web/API/网关主进程只处理 HTTP 请求和必要的 worker 看护。
- 统计聚合、系统采样、运行日志索引维护、审计日志批量落库和清理任务必须在独立 background worker 进程内运行。OpenAI OAuth 额度快照由真实网关响应头被动更新，不再依赖后台主动刷新任务。
- 部署验证不能只看 `/health`，还要确认后台 worker 已启动并持续存活；否则统计、日志索引和清理会停滞。

- `/api/health` 返回 `200` 和 `status: ok`。

浏览器访问：

```text
http://127.0.0.1:3000/
```

如果使用公网或域名，按实际地址访问。

## 7. 常驻运行

### Windows

推荐：

- NSSM 注册 Windows Service。
- PM2 Windows 服务化方案。
- 任务计划程序开机启动 `pwsh -File start.ps1`。
- 后续后台 worker 进程隔离实现后，常驻运行必须同时守护 Web/API 主进程和 background worker 进程；如果使用 PM2，应使用 ecosystem 配置或两个 app 条目，而不是只守护 `server.js`。

PM2 示例：

```powershell
npm install -g pm2
pm2 start .\backend\dist\server.js --name juhe-ai --cwd (Get-Location).Path
pm2 save
```

### macOS

推荐：

- launchd。
- PM2。
- Caddy/Nginx 反向代理。
- 后续后台 worker 进程隔离实现后，launchd / PM2 需要同时守护 Web/API 主进程和 background worker 进程。

PM2 示例：

```bash
npm install -g pm2
cd /你的路径/juhe-ai-release
pm2 start backend/dist/server.js --name juhe-ai --cwd /你的路径/juhe-ai-release
pm2 save
```

### Linux

推荐：

- systemd。
- PM2。
- Nginx/Caddy 反向代理和 HTTPS。
- 后续后台 worker 进程隔离实现后，systemd / PM2 需要同时守护 Web/API 主进程和 background worker 进程；只启动 `server.js` 会导致后台任务停滞。

PM2 示例：

```bash
npm install -g pm2
cd /你的路径/juhe-ai-release
pm2 start backend/dist/server.js --name juhe-ai --cwd /你的路径/juhe-ai-release
pm2 save
pm2 startup
```

systemd 示例：

```ini
[Unit]
Description=Juhe AI
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/juhe-ai-release
ExecStart=/usr/bin/node /opt/juhe-ai-release/backend/dist/server.js
Restart=always
RestartSec=5
User=你的Linux用户
Environment=NODE_ENV=production

[Install]
WantedBy=multi-user.target
```

## 8. Nginx 反向代理示例

Linux/macOS 使用 Nginx 时可参考：

```nginx
server {
    listen 80;
    server_name 你的域名;

    client_max_body_size 20m;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /v1/ {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_buffering off;
        proxy_read_timeout 3600s;
        proxy_send_timeout 3600s;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

## 9. 数据备份和迁移

默认数据库：

```text
业务库：backend/data/juhe-ai.sqlite3
记录库：backend/data/juhe-ai-records.sqlite3
```

必须备份：

```text
backend/.env
核心业务表数据
```

生产环境默认不做整库 SQLite 备份，避免把短期日志、审计 payload、用量明细、统计缓存、系统监控和运行索引一起带走，导致备份过大或长时间占用数据库锁。默认备份口径只包含可恢复业务配置和资源关系：

```text
system_accounts
global_settings
providers
proxy_profiles
error_policies
accounts
system_teams
system_team_members
resource_authorizations
resource_authorization_sources
resource_authorization_grants
groups
group_accounts
api_keys
system_settings
announcements
announcement_reads
```

默认不备份这些可重建、可过期或排障类数据：`usage_records`、`audit_*`、`operation_log*`、`runtime_logs` / `runtime_log_search`、`usage_*` 统计缓存、`stats_job_state`、`group_account_stats`、`account_quality_*`、`system_metrics_*`、`account_usage_snapshots`、`database_storage_snapshots`、`table_storage_snapshots`。`system_sessions` 虽然在业务库里，但属于短期登录态，常规备份也不需要单独导出；恢复时重新登录即可。如果明确要做迁移级完整快照，应先停服务，再对业务库和记录库做离线备份，不要在高流量时在线整库备份。

Mac 生产库曾出现 `juhe-ai.sqlite3` 约 `7.6GB`、`WAL` 约 `381MB` 的情况。根因不是“数据没删掉”，而是 SQLite 删除记录后只把页放回 freelist，可复用但不会自动归还给文件系统。现场 `page_size = 4096`、`page_count = 1990170`、`freelist_count = 1276031`，约有 `4.9GB` 都是 freelist 空页；同时 `runtime_log_search_data`、`usage_records`、`runtime_logs` 等记录类大表把整库拖大。要真正缩小文件，必须停服务后执行 `VACUUM INTO` 或生成 compact 业务库替换原文件。

Windows 备份：

```powershell
New-Item -ItemType Directory -Force backups | Out-Null
Copy-Item .\backend\.env ".\backups\backend.env.$(Get-Date -Format yyyyMMddHHmmss)"
sqlite3 .\backend\data\juhe-ai.sqlite3 ".dump system_accounts global_settings providers proxy_profiles error_policies accounts system_teams system_team_members resource_authorization_grants resource_authorizations resource_authorization_sources groups group_accounts api_keys system_settings announcements announcement_reads" | Out-File -Encoding utf8 ".\backups\business-tables.$(Get-Date -Format yyyyMMddHHmmss).sql"
```

macOS / Linux 备份：

```bash
mkdir -p backups
cp backend/.env backups/backend.env.$(date +%Y%m%d%H%M%S)
sqlite3 backend/data/juhe-ai.sqlite3 ".dump system_accounts global_settings providers proxy_profiles error_policies accounts system_teams system_team_members resource_authorization_grants resource_authorizations resource_authorization_sources groups group_accounts api_keys system_settings announcements announcement_reads" > backups/business-tables.$(date +%Y%m%d%H%M%S).sql
```

当前版本已经固定为业务库 / 记录库分离模式，不再保留旧整库拆分脚本。历史整库迁移属于已完成的一次性动作；新部署或常规升级都应直接配置 `JUHE_AI_DATABASE_PATH` 和 `JUHE_AI_RECORD_DATABASE_PATH`。

统计口径升级或统计缓存损坏时，必须停服务后显式执行统计重建。发布包和源码构建后都统一使用编译产物入口：

Windows：

```powershell
node .\backend\dist\scripts\maintenance\rebuild-usage-stats.js
```

macOS / Linux：

```bash
node ./backend/dist/scripts/maintenance/rebuild-usage-stats.js
```

说明：

1. 统计重建不是每次上线必跑，只在统计表、统计口径、授权消耗规则或额度窗口规则变化时执行。
2. 该脚本会清空并重建统计缓存、授权消耗月报和统计窗口快照，不删除系统账户、AI 账户、分组、API Key、授权关系或 `usage_records`。
3. 重建只能基于当前记录库里仍保留的 `usage_records`；已经被保留策略清理掉的历史明细不能凭空恢复。
4. 执行前必须确认 `backend/.env` 里的数据库路径指向目标生产库，并先停掉 Web 和 background worker，避免重建期间继续写入统计游标。

迁移时：

1. 解压新发布包。
2. 复制旧 `backend/.env` 到新发布包的 `backend/.env`。
3. 常规升级复用原业务库和记录库路径；只有明确迁移到新库时，才把业务表 SQL 导入到新业务库，记录库按需要复制或丢弃。
4. 如果本次升级包含统计口径变化，先运行统计重建脚本。
5. 启动新服务。
6. 验证登录、账户、API Key、网关和管理员“表监控”页面。

## 10. 常见排障

- `node:sqlite` 失败：升级 Node.js 到 22.13.0+（22.x）或 23.4.0+，或使用更新的 LTS。
- `pnpm install` 失败：检查 npm registry 网络或代理配置。
- `grep 模式` 报找不到 `rg`：重新执行 `pnpm install --prod --frozen-lockfile --filter juhe-ai-backend...`，确认没有使用 `--ignore-optional` 或禁用 optional dependency。
- 页面能开但 API 失败：检查 `/api` 是否到同一后端。
- `/v1` 流式断开：反向代理关闭 buffering，并增大超时。
- 敏感字段无法解密：找回旧 `JUHE_AI_SECRET`。
- 端口外部访问失败：直连用 `JUHE_AI_HOST=0.0.0.0`，并开放防火墙/安全组端口。

## 11. 给 AI 的部署摘要

1. 先判断目标系统：Windows、macOS 或 Linux。
2. 检查 Node.js、`node:sqlite`、pnpm/corepack、端口、网络、磁盘和权限。
3. 按目标系统解压 zip 或 tar.gz。
4. 检查 `start.sh`、`start.ps1`、`backend/dist/server.js`、`frontend/dist/index.html`。
5. 创建并审阅 `backend/.env`。
6. 根据访问方式设置 `JUHE_AI_HOST`。
7. 确认 `JUHE_AI_SECRET`：新部署生成强随机值，迁移部署沿用旧值。
8. Windows 执行 `pwsh ./start.ps1`；macOS/Linux 执行 `bash ./start.sh`。
9. 验证 `/health`、`/api/health`、`/`。
10. 配置目标平台常驻运行。
11. 备份 `.env` 和 SQLite 数据库。
