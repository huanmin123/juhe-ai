# 部署指南（国内单机 Docker，唯一生产形态）

> 2026-09-26 起生产为**国内单台云服务器 + Docker Compose**（PostgreSQL + Redis + gateway/jobs/maintenance + Caddy，域名 HTTPS）。家庭宽带反代、Edge 隧道、macOS/Windows/K8s 等旧形态已废弃删除；本文只描述当前形态。配置源文件与构建/更新命令的权威位置是仓库 `docker/single-server/`（README 为准），本文是面向使用者的总览。

## 1. 前置

- 国内云服务器（生产：4 核 8G，Debian 13），安全组/防火墙放行 22/80/443；域名 A 记录指向服务器 IP（HTTPS 由 Caddy 自动签发续期）。
- 国内网络拉取 Docker Hub 需配镜像加速；BuildKit 构建基础镜像直接用 `docker.m.daocloud.io/...` 前缀（见 `docker/single-server/compose.yml`）。
- 服务器出海上游代理（AI 上游必需）：见 [sing-box 网络代理部署指南](proxy/sing-box网络代理部署指南.md) 与第 5 节当前约定。

## 2. 构建与首次部署

```sh
# 本机构建（交叉编译 + 前端），产物在 docker/single-server/build/
for p in gateway jobs maintenance; do
  (cd backend-go/projects/$p && CGO_ENABLED=0 GOOS=linux GOARCH=amd64 \
    go build -trimpath -ldflags "-s -w" -o ../../../docker/single-server/build/bin/juhe-ai-$p ./cmd/juhe-ai-$p)
done
(cd frontend && pnpm build && rm -rf ../docker/single-server/build/frontend-dist && cp -r dist ../docker/single-server/build/frontend-dist)

# 上传服务器 /opt/juhe-ai 后：build → 起 postgres/redis → maintenance 初始化 → up -d
# 完整初始化序列（含 juhe_jobs/juhe_j3b 预置、J3b 运行态索引）见 docker/single-server/README.md
```

要点（详见 `docker/single-server/README.md`）：

- PG 为单库 `juhe_ai` 多 schema；`juhe_jobs`/`juhe_j3b` 需手工建 schema 后用 maintenance `--apply-*` 建表（含 J2 余额四表 `--apply-account-balance-postgres`，2026-10-02 起取代按 `balancePostgresSchema` 手工执行 SQL）。
- postgres 服务在 compose 中预置内存调优（2026-09-30 起：`shared_buffers=2GB`、`effective_cache_size=4GB`，适配 8GB 单机两库共用形态）——新建/更新实例时保留该 `command`，勿回退到镜像默认 `shared_buffers=128MB`（隐性瓶颈：缓存命中率偏低、iowait 高、checkpoint 频繁）。
- gateway 启动硬性要求 J3b 账户电路运行态索引 ready：新库必须执行 `docker compose run --rm gateway -init-account-circuit-runtime-index`。
- 必需 env：`JUHE_AI_SECRET`（加密封套，有数据后不可换）、`JUHE_AI_RUNTIME_LOG_POSTGRES_URL`/`JUHE_AI_TABLE_MONITOR_POSTGRES_URL`（无回退）、`JUHE_AI_J3B_CIRCUIT_REDIS_URL`（不得与 state 同键空间）、`JUHE_AI_FRONTEND_DIST_PATH`。
- 系统指标 Go Runtime 采样自 2026-09-27 起默认开启（跟随主存储）：生产 PG 模式下默认即 postgres（`JUHE_AI_GO_RUNTIME_METRICS_POSTGRES_URL` 可省略回退主库 URL，通常无需显式配置）；显式 `JUHE_AI_GO_RUNTIME_METRICS_STORE=disabled` 才关闭（`ROLE` 已删除不得配置）。顺序契约按存储分派：postgres 模式新环境首次启动前必须先 maintenance `--check-go-runtime-metrics`/`--apply-go-runtime-metrics` 建表（缺表时 gateway/jobs 启动只读校验 fail-fast 循环重启）；sqlite 模式启动自举建表（幂等），无需预处理；完整契约见 `docker/single-server/README.md` 的".env 契约"节。
- **运行时数据目录契约**：gateway/jobs 的相对路径（`data/`、`logs/`，含用量记录 spool 交接目录）以进程 cwd 为基准；镜像未设 `WORKDIR`，compose 里 gateway/jobs 的 `working_dir: /app/backend` 不可删——两侧必须同源解析到宿主机挂载的 `data/app/data`，否则用量记录永不到库、全部统计为空（详见 `docker/single-server/README.md`"运行时数据目录契约"，BUG-0193）。
- **运行日志文件写侧（BUG-0195，2026-09-28 起）**：gateway slog 同时写 stdout 与 `JUHE_AI_LOG_DIR` 下的 `juhe-ai.log`（按大小轮转，默认 100MB，`JUHE_AI_LOG_MAX_FILE_MB` 可调）；compose 已为 gateway/jobs 显式配 `JUHE_AI_LOG_DIR=/app/backend/logs`，写侧/grep/索引器/清理三方必须同目录；gateway 未配置 `JUHE_AI_LOG_DIR` 时同样经 datadir 派生 `<DATA_DIR>/logs` 默认开启文件日志与 grep 面（写侧 NewFileSink 代建目录，与 jobs 侧派生对称），显式 `disabled` 字面量（大小写不敏感）才关闭（启动事件 `runtime_log_file_sink_disabled`，完整契约见 `docker/single-server/README.md`".env 契约"节）；HTTP 访问日志自此为 JSON 并进文件（`slog.Default()` 由多路 logger 接管）。文件清理由 jobs 索引器按 `JUHE_AI_LOG_MAX_FILES`/`JUHE_AI_LOG_RETENTION_DAYS` 执行，只删已完整索引的 rotated 文件。
- **AI 问答 env 契约（`JUHE_AI_CHAT_*`，gateway/jobs 双进程）**：保留 `JUHE_AI_CHAT_RETENTION_DAYS`（默认 `3`，1..365）与资产根 `JUHE_AI_CHAT_ASSETS_ROOT`（默认 `<数据根>/chat-assets`）双进程必须同值；其余调参——`JUHE_AI_CHAT_DATABASE_PATH`（仅 sqlite 模式）、`JUHE_AI_CHAT_MAX_TURNS_PER_CONVERSATION`（默认 `50`）、`JUHE_AI_CHAT_MAX_CONVERSATIONS_PER_USER`（默认 `50`）、`JUHE_AI_CHAT_UPSTREAM_SSE_MAX_EVENTS`（默认 `65536`，2048..262144）；完整契约与默认值见 `docker/single-server/README.md` 的".env 契约"节。
- **Codex 桥 segments 根 env 契约（`JUHE_AI_CODEX_CONTEXT_ROOT`，2026-10-03 起 gateway 组合根装配，gateway 现亦消费该 env）**：可选，未配置时按 datadir 约定派生 `<数据根>/codex-context`；gateway Responses↔Chat 桥 segment 写入与 jobs retention 清理**双进程必须同值**。PG 模式要求 `juhe_codex_context` schema（例行 `--ensure-schema` 已预置，缺失时 gateway 启动期探针 fail-fast，属部署错误）。完整契约见 `docker/single-server/README.md` 的".env 契约"节。
- **余额手动刷新租约库 env 契约（`JUHE_AI_ACCOUNT_BALANCE_DATABASE_PATH`，2026-10-04 起双方言装配）**：仅 sqlite 模式生效，未配置时按 datadir 约定派生 `<数据根>/account-balance.sqlite3`；gateway 独占、启动期幂等自建租约四表，无需预处理；生产 PG 模式不配置（同构四表在 `juhe_jobs` schema）。完整契约见 `docker/single-server/README.md` 的".env 契约"节。
- **火山语音出站根测试 seam（`JUHE_AI_GATEWAY_VOLCENGINE_SPEECH_BASE_URL`，2026-10-04 M6 批）**：仅验收 E2E 注入的测试覆盖变量（缺省恒官方 `https://openspeech.bytedance.com`）——**生产/compose/直跑一律不配置**；非功能开关，火山 TTS 能力恒生效。登记与误配置后果见 `docker/single-server/README.md`".env 契约"节。
- **实例事实变量化（BUG-0225，2026-09-28）**：compose 三服务 `extra_hosts` 的出海代理公网 IP 与 `deploy.sh` 目标服务器已变量化，git 追踪文件不再含实例 IP/账号。服务器 `.env` 必含 `JUHE_AI_PROXY_IP_A`/`JUHE_AI_PROXY_IP_B`（缺失时 `docker compose config` 阶段即报错）；本地发布机 `docker/single-server/.env` 另需 `JUHE_AI_DEPLOY_SERVER`（deploy.sh fail-fast）。变量清单见 `docker/single-server/README.md`".env 契约"节。
- **非 root 容器（BUG-0225）**：runtime 镜像以固定 UID/GID 1000 的非特权用户 `app` 运行（gateway/jobs/maintenance 三进程不再以 root 跑）。首次启用前的一次性前置：宿主机 `chown -R 1000:1000 /opt/juhe-ai/data/app`（回滚 = `chown -R root:root`），否则容器无权写挂载目录；**chown 必须在旧容器完全停止之后执行**——root→app 过渡窗口内仍在运行的旧容器会继续写 root 属主新文件（BUG-0227 部署侧成因），无法保证时序时发布后必须复查 `usage-record-spool` 属主；caddy/PG/Redis 不受影响。除属主切换发布的 chown 时序外，发布、更新与回滚流程不变。
- **发布过渡窗口租约等待（BUG-0228，2026-09-28 起）**：发布 recreate 窗口旧 gateway 被 SIGKILL 截断 `defer` 租约释放时，新 gateway 启动期有界等待前任 F3/F4 DB 租约 TTL（默认 30s）过期后接管（compose 显式 `JUHE_AI_OWNER_LEASE_ACQUIRE_WAIT=45s`，默认空 = fail-fast 契约；gateway healthcheck `start_period=75s`）——healthy 滞后至多约 1 分钟属预期，不再出现启动失败重启循环。完整契约见 `docker/single-server/README.md`".env 契约"节。
- seed 初始管理员 `admin/admin`，首登强制改密（must_change_password 403 gate，BUG-0224：管理面在公网可达窗口内不得依赖人工改密流程；该行为仅影响新 seed 的实例，现有生产沿用已有 `system_accounts` 行不受影响）。

## 3. HTTPS

Caddy 自动 ACME（Let's Encrypt）签发与续期，80 常驻 308 升级 HTTPS；Caddyfile 在 `docker/single-server/Caddyfile`。该文件为同机两栈共享：还承载同机公益站（juhe-pw 栈）`gyai.huanmin.top` 的反代块，同步/修改时不得遗漏，改前备份、改后 `caddy validate` + `caddy reload`。通用证书说明见 [https/Caddy自动HTTPS部署指南](https/Caddy自动HTTPS部署指南.md)（Edge/家庭回源章节已废弃）。

AI 问答管理面 SSE（`/__aisys__/api/my-chat/*` 流式发送）与 `/v1/*` 一样依赖反代不缓冲：Caddyfile 中该前缀的反代必须显式 `flush_interval -1`（对齐 `/v1/*` 块），SSE 增量传输不能依赖 Caddy 对 `text/event-stream` 的自动刷新行为。

caddy 服务在 compose 中声明 `init: true`（2026-09-29 起）：healthcheck 的 busybox wget https 探测每次泄漏一个 `ssl_client` 子进程，caddy 作为容器 PID 1 不回收会无限堆积 zombie（生产实测 27 小时堆 9470 个后容器 docker exec 全败，实例级损坏）；docker 内置 init 负责收割。若 caddy 容器再次出现 exec 全败/ unhealthy 但流量正常，处置仍是 `docker compose force-recreate caddy`（两栈入口闪断数秒）。

## 4. 更新与回滚

重复"构建 → 上传 → `docker compose build gateway jobs maintenance` → `docker compose up -d`"；发布后跑一次幂等 `maintenance --ensure-schema`。回滚 = 上传上一版 `build/` 重新 build+up。推荐用 `docker/single-server/deploy.sh` 发布：2026-10-02 起其第 [6/6] 步自动运行发布后验证 `verify-release.sh`——usage spool 同源与 jobs drain 接线为强制断言；2026-10-08 起其第 [0/6] 步为前端漏发门禁——发布包含 gateway 时自动探测线上前端版本，`frontend/` 有任何差异即自动重建并上传前端产物，版本未知或产物与 HEAD 不一致时发布中止（此前前端需人工单独构建上传，多次漏发）。~~可选"一条 `/v1` 请求 → 审计 + 用量落库"闭环门禁~~ **已于 2026-10-03 按用户裁定移除**：闭环依赖具体账户/模型的实时可用性，无法保证稳定，作为强制门禁会随上游波动误报；链路落库正确性改由发布后巡检（`audit_logs`/`usage_records` 新行字段核验）覆盖。详见 `docker/single-server/README.md`"更新发布"节。
- **AI 对话工具默认绑定（2026-10-02）**：chat 库新增 `juhe_chat.chat_user_tool_preferences`（用户级搜索/生图默认绑定表），随例行 `--ensure-schema` 幂等建表生效，**无一次性迁移、发布无额外步骤**；回滚上一版二进制无需处理该表（加法式变更，旧代码不读）。
- **AI 账户"特供"恢复标记（2026-10-10）**：业务库加法式两列——`accounts.expedited_recovery_enabled`（integer 0/1，DEFAULT 0）与 `system_accounts.expedited_account_limit`（可空 integer 0–100，NULL 读侧默认 3），随发版执行既有 `--ensure-schema` 幂等补列生效，**无额外命令、无新增环境变量**；回滚上一版二进制无需处理该列（加法式变更，旧代码不读）。契约见 `docs/functions/AI账户特供快速恢复通道设计.md`。
- **模型质量检测约束迁移（2026-10-01 起，两步）**：本次升级的两处 CHECK 约束分属两条迁移通道，发布检查必须两步分别执行：
  1. `maintenance --ensure-schema`（业务库，例行幂等）：迁移 `model_quality_schedules.interval_minutes`（`10..10080` 放宽为 `1..10080`）；PG 用 DO 块替换约束，SQLite 业务库通过重建 `model_quality_schedules` 表完成迁移（数据保持）。
  2. `maintenance --apply-j3b-model-check-postgres`（j3b 库，读 env `JUHE_AI_MAINTENANCE_J3B_POSTGRES_URL`，幂等可重入）：迁移 `juhe_j3b.model_check_runs.trigger_kind`（取值域加 `schedule_now`）。`--ensure-schema` 不包含该迁移；未执行时存量三值 CHECK 不变，首个 `schedule_now` run 插入会因 CHECK 约束写入失败（用户侧表现为"已发起"后静默无记录）。

  升级后验证（PG）：

  ```sql
  -- interval_minutes 约束定义应显示 PG 规范化形态 ((interval_minutes >= 1) AND (interval_minutes <= 10080))
  SELECT conname, pg_get_constraintdef(oid) FROM pg_constraint
   WHERE conrelid = 'juhe_business.model_quality_schedules'::regclass;
  -- trigger_kind 约束应包含 schedule_now
  SELECT pg_get_constraintdef(oid) FROM pg_constraint
   WHERE conrelid = 'juhe_j3b.model_check_runs'::regclass
     AND pg_get_constraintdef(oid) LIKE '%trigger_kind%';
  ```

  也可直接经管理面创建/编辑一条 `intervalMinutes=1` 的定时检查计划验证写入面。回滚提示：约束放宽为向后兼容变更（旧二进制接受的取值是新约束子集），回滚上一版二进制时无需回滚约束。迁移细节见 `docker/single-server/README.md`。
- **AI 对话账户唯一绑定切换（2026-09-28）**：本次发布后须在 `--ensure-schema` 之后再跑一次 `maintenance --migrate-chat-account-only-binding`（`--driver postgres --dsn <app URL>`，幂等可重入）：存量旧模式（`api_key`/`group`）会话归档只读、三旧列删除（副表 `chat_conversations_bind_legacy_backup` 全量备份，stdout 报告含 rollbackSql，回滚时先恢复旧版二进制再按报告执行）。命令完整契约见 `docker/single-server/README.md` 与 maintenance `--help`。

变量化与非 root 化（BUG-0225，2026-09-28）不改变发布流程本身；其一次性前置（服务器 `.env` 追加 `JUHE_AI_PROXY_IP_A/B`、宿主机 `data/app` chown、本地 `.env` 建 `JUHE_AI_DEPLOY_SERVER`）已随 2026-09-28 16:00 发布完成，实例执行记录见私有运维手册 `.local/project-resources/prod/runbooks/国内单机Docker部署与运维.md`。

**发布过渡窗口租约等待（BUG-0228，2026-09-28 起）**：compose 显式配置 `JUHE_AI_OWNER_LEASE_ACQUIRE_WAIT=45s`（gateway）与 healthcheck `start_period=75s` 后，发布 recreate 窗口新 gateway 在启动期等待前任 F3/F4 租约 TTL 过期（启动日志 `owner lease held by another owner process, waiting for predecessor lease expiry`）而非 fail-fast 退出，healthy 滞后至多约 1 分钟属预期、不再有重启循环。该修复随 compose.yml 生效，**发布时须同步上传新 compose.yml**（deploy.sh 只上传二进制）；变量契约见 `docker/single-server/README.md`".env 契约"节。

## 5. 出站代理（AI 上游）

出站代理有两条宿主机侧链路，**当前生产主用本机 sing-box**（实例级事实与主备切换步骤见私有运维手册，不在公开文档记录）：

- **本机 sing-box（当前主用）**：systemd 单元 `juhe-pw-proxy.service`，配置 `/etc/sing-box/config.json`；mixed 入站监听 `172.18.0.1:17892`，出站为订阅云端节点池。多节点订阅池必须配合两件自动化：**择优控制器**（`selector` 组 + `juhe-proxy-switch` timer，2 分钟周期：先对真实上游确认测试再切、10 分钟最小切换间隔、100ms 容差、坏节点拉黑）与**每小时订阅更新器**（`juhe-sub-update` timer：变更检测、check 门禁、失败回滚）——订阅池存在分钟级漂移、目的地相关 503 和服务商随时轮换节点，裸 `urltest`、固定单节点或静态配置都不可靠。策略与部署见 [sing-box 网络代理部署指南](proxy/sing-box网络代理部署指南.md) 的订阅解析、择优控制器与订阅更新器各节。
- **常驻隧道（备用）**：宿主机 systemd `ssh -L` 转发进程提供 SOCKS5 入口，同样经后台"代理管理"绑定。

容器内访问宿主机代理注意：`host.docker.internal` 解析到 `172.17.0.1`（docker0 网桥），代理进程绑定哪个口就填哪个地址（当前服务器上隧道绑三口、sing-box 只绑 `172.18.0.1`）。该 sing-box 单元为宿主机级服务，与同机公益站（juhe-pw）共用，变更其配置前先评估两栈影响。

## 6. 验证清单

- `docker compose ps` 全 healthy；`GET /__aisys__/health` 全 `ready:true`。
- `https://<域名>/` 301 到 `/__aisys__/`，登录、各管理页、代理测试通过。
- `/v1/models` 返回 401（鉴权层正常）；用真实 API Key 请求业务模型。
- **统计落库验证**：deploy.sh 第 [6/6] 步发布后验证（`verify-release.sh`）已把 spool 同源与 jobs drain 接线自动化为强制断言（原"一条 `/v1` 请求 → audit_logs + usage_records 落库"闭环断言已于 2026-10-03 按用户裁定移除，见 `docker/single-server/README.md`"更新发布"节）。手工兜底：发起一次真实 `/v1` 请求后，`SELECT count(*) FROM juhe_usage.usage_records;` 应 > 0 并持续增长，管理面统计页面出数；恒 0 行 = spool 交接断裂，按 `docker/single-server/README.md`"运行时数据目录契约"检查 gateway/jobs 两侧目录是否同源（BUG-0193）。
