# 部署指南（国内单机 Docker，唯一生产形态）

> 2026-09-26 起生产为**国内单台云服务器 + Docker Compose**（PostgreSQL + Redis + gateway/jobs/maintenance + Caddy，域名 HTTPS）。家庭宽带反代、Edge 隧道、macOS/Windows/K8s 等旧形态已废弃删除；本文只描述当前形态。配置源文件与构建/更新命令的权威位置是仓库 `docker/single-server/`（README 为准），本文是面向使用者的总览。

## 1. 前置

- 国内云服务器（生产：4 核 8G，Debian 13），安全组/防火墙放行 22/80/443；域名 A 记录指向服务器 IP（HTTPS 由 Caddy 自动签发续期）。
- **主机层优化（BUG-0313，2026-10-14 起，新装必做）**：以 root 运行仓库内已入库脚本 `docker/single-server/host-init.sh`（幂等，已收敛项自动跳过），一键完成三项——①4G swap（`/swapfile`，fstab 持久，`vm.swappiness=10` 仅作内存耗尽兜底：既防 OOM 前整机冻结、又保住排障现场；激活与 fstab 持久化分别判定，缺 fstab 条目自动补写）；②防冻结 sysctl（`vm.min_free_kbytes=262144`、`vm.watermark_scale_factor=125`，连同既有 Redis 要求的 `vm.overcommit_memory=1` 落 `/etc/sysctl.d/99-juhe-ai.conf`；配置文件与运行值分别核对，漂移自动重写并重新应用）；③journald 容量上限 500M（防日志无限增长挤占磁盘）。此后每次 `deploy.sh` 发布都会自动幂等自检一遍（单项失败仅告警不阻塞发布）。背景：8G 单机上 gateway 流量高峰内存膨胀曾挤光页缓存引发整机僵死（BUG-0313）；容器侧配套为 gateway `GOMEMLIMIT`/`mem_limit` 双限，契约见 `docker/single-server/README.md`「容器内存治理」节。
- 国内网络拉取 Docker Hub 需配镜像加速；BuildKit 构建基础镜像直接用 `docker.m.daocloud.io/...` 前缀（见 `docker/single-server/compose.yml`）。
- 服务器出海上游代理（AI 上游必需）：见 [sing-box 网络代理部署指南](proxy/sing-box网络代理部署指南.md) 与第 5 节当前约定。

## 2. 构建与首次部署

```sh
# 本机构建（交叉编译 + 前端），产物在 docker/single-server/build/
for p in gateway jobs maintenance; do
  (cd backend-go/projects/$p && CGO_ENABLED=0 GOOS=linux GOARCH=amd64 \
    go build -trimpath -ldflags "-s -w" -o ../../../docker/single-server/build/bin/juhe-ai-$p ./cmd/juhe-ai-$p)
done
(cd frontend && pnpm build && rm -rf ../docker/single-server/build/frontend-dist && cp -r dist ../docker/single-server/build/frontend-dist)

# 上传服务器 /opt/juhe-ai 后：build → 起 postgres/redis → maintenance 初始化 → up -d
# 完整初始化序列（含 juhe_jobs/juhe_j3b 预置、J3b 运行态索引）见 docker/single-server/README.md
```

要点（详见 `docker/single-server/README.md`）：

- PG 为单库 `juhe_ai` 多 schema；`juhe_jobs`/`juhe_j3b` 需手工建 schema 后用 maintenance `--apply-*` 建表（含 J2 余额四表 `--apply-account-balance-postgres`，2026-10-02 起取代按 `balancePostgresSchema` 手工执行 SQL）。
- postgres 服务在 compose 中预置内存调优（2026-09-30 起：`shared_buffers=2GB`、`effective_cache_size=4GB`，适配 8GB 单机两库共用形态）——新建/更新实例时保留该 `command`，勿回退到镜像默认 `shared_buffers=128MB`（隐性瓶颈：缓存命中率偏低、iowait 高、checkpoint 频繁）。PG 实例级日志参数另有四项 `ALTER SYSTEM` 重放清单（`log_min_duration_statement` / `log_line_prefix` / `log_connections` / `log_lock_waits`，2026-10-17 盘点固化）+ 一次 `CREATE EXTENSION pg_stat_statements`，新部署必须重放，契约与命令见 `docker/single-server/README.md`。
- gateway 启动硬性要求 J3b 账户电路运行态索引 ready：新库必须执行 `docker compose run --rm gateway -init-account-circuit-runtime-index`。
- 必需 env：`JUHE_AI_POSTGRES_URL` / `JUHE_AI_REDIS_CACHE_URL` / `JUHE_AI_REDIS_STATE_URL`（2026-10-24/25 存储收口后为唯一必填三连接串，缺失启动 fail-fast；`JUHE_AI_RUNTIME_MODE` / `JUHE_AI_DATABASE_DRIVER` 等模式开关与 `*_DATABASE_PATH` 路径族已随 SQLite / memory 模式退役，不再读取）、`JUHE_AI_SECRET`（加密封套，有数据后不可换；所有共享 Redis 会话亲和绑定的 Gateway 实例必须同值，不得多实例混跑不同 secret）、`JUHE_AI_RUNTIME_LOG_POSTGRES_URL`（无回退）、`JUHE_AI_J3B_CIRCUIT_REDIS_URL`（不得与 state 同键空间）、`JUHE_AI_FRONTEND_DIST_PATH`；gateway 另有可选 `JUHE_AI_ACCOUNT_HEALTH_JOBS_OUTCOME_POSTGRES_URL`（AI 健康监控 J1 outcome 合并直读串，未配置保持合并缺席、页面降级可用，生产已显式配置；契约见 `docker/single-server/README.md`）。
- **监控交付（2026-10-14 起）**：应用进程指标经 gateway(3306)/jobs(3305) 健康监听暴露 `GET /__aisys__/metrics`（Prometheus pull），表 / DB 容量由 postgres_exporter 承担；原 gometrics 采样链与 `JUHE_AI_GO_RUNTIME_METRICS_*` / `JUHE_AI_TABLE_MONITOR_*` 全家族 env、gateway 侧 `JUHE_AI_JOBS_HEALTH_LISTEN_ADDRESS` 已删除，`.env` 清理清单与端口发布契约见下文 [7. 监控交付](#7-监控交付prometheus--grafana)，指标族权威见 [Prometheus 指标暴露设计](../functions/Prometheus指标暴露设计.md)。
- **运行时数据目录契约**：gateway/jobs 的相对路径（`data/`、`logs/`，含用量记录 spool 交接目录）以进程 cwd 为基准；镜像未设 `WORKDIR`，compose 里 gateway/jobs 的 `working_dir: /app/backend` 不可删——两侧必须同源解析到宿主机挂载的 `data/app/data`，否则用量记录永不到库、全部统计为空（详见 `docker/single-server/README.md`"运行时数据目录契约"，BUG-0193）。
- **运行日志文件写侧（BUG-0195，2026-09-28 起）**：gateway slog 同时写 stdout 与 `JUHE_AI_LOG_DIR` 下的 `juhe-ai.log`（按大小轮转，默认 100MB，`JUHE_AI_LOG_MAX_FILE_MB` 可调）；compose 已为 gateway/jobs 显式配 `JUHE_AI_LOG_DIR=/app/backend/logs`，写侧/grep/索引器/清理三方必须同目录；gateway 未配置 `JUHE_AI_LOG_DIR` 时同样经 datadir 派生 `<DATA_DIR>/logs` 默认开启文件日志与 grep 面（写侧 NewFileSink 代建目录，与 jobs 侧派生对称），显式 `disabled` 字面量（大小写不敏感）才关闭（启动事件 `runtime_log_file_sink_disabled`，完整契约见 `docker/single-server/README.md`".env 契约"节）；HTTP 访问日志自此为 JSON 并进文件（`slog.Default()` 由多路 logger 接管）。文件清理由 jobs 索引器按 `JUHE_AI_LOG_MAX_FILES`/`JUHE_AI_LOG_RETENTION_DAYS` 执行，只删已完整索引的 rotated 文件。
- **AI 问答 env 契约（`JUHE_AI_CHAT_*`，gateway/jobs 双进程）**：保留 `JUHE_AI_CHAT_RETENTION_DAYS`（默认 `3`，1..365）与资产根 `JUHE_AI_CHAT_ASSETS_ROOT`（默认 `<数据根>/chat-assets`）双进程必须同值；其余调参——`JUHE_AI_CHAT_MAX_TURNS_PER_CONVERSATION`（默认 `50`）、`JUHE_AI_CHAT_MAX_CONVERSATIONS_PER_USER`（默认 `50`）、`JUHE_AI_CHAT_UPSTREAM_SSE_MAX_EVENTS`（默认 `65536`，2048..262144）；完整契约与默认值见 `docker/single-server/README.md` 的".env 契约"节。
- **Codex 桥 segments 根 env 契约（`JUHE_AI_CODEX_CONTEXT_ROOT`，2026-10-03 起 gateway 组合根装配，gateway 现亦消费该 env）**：可选，未配置时按 datadir 约定派生 `<数据根>/codex-context`；gateway Responses↔Chat 桥 segment 写入与 jobs retention 清理**双进程必须同值**。PG 模式要求 `juhe_codex_context` schema（例行 `--ensure-schema` 已预置，缺失时 gateway 启动期探针 fail-fast，属部署错误）。完整契约见 `docker/single-server/README.md` 的".env 契约"节。
- **火山语音出站根测试 seam（`JUHE_AI_GATEWAY_VOLCENGINE_SPEECH_BASE_URL`，2026-10-04 M6 批）**：仅验收 E2E 注入的测试覆盖变量（缺省恒官方 `https://openspeech.bytedance.com`）——**生产/compose/直跑一律不配置**；非功能开关，火山 TTS 能力恒生效。登记与误配置后果见 `docker/single-server/README.md`".env 契约"节。
- **实例事实变量化（BUG-0225，2026-09-28）**：compose 三服务 `extra_hosts` 的出海代理公网 IP 与 `deploy.sh` 目标服务器已变量化，git 追踪文件不再含实例 IP/账号。服务器 `.env` 必含 `JUHE_AI_PROXY_IP_A`/`JUHE_AI_PROXY_IP_B`（缺失时 `docker compose config` 阶段即报错）；本地发布机 `docker/single-server/.env` 另需 `JUHE_AI_DEPLOY_SERVER`（deploy.sh fail-fast）。变量清单见 `docker/single-server/README.md`".env 契约"节。
- **非 root 容器（BUG-0225）**：runtime 镜像以固定 UID/GID 1000 的非特权用户 `app` 运行（gateway/jobs/maintenance 三进程不再以 root 跑）。首次启用前的一次性前置：宿主机 `chown -R 1000:1000 /opt/juhe-ai/data/app`（回滚 = `chown -R root:root`），否则容器无权写挂载目录；**chown 必须在旧容器完全停止之后执行**——root→app 过渡窗口内仍在运行的旧容器会继续写 root 属主新文件（BUG-0227 部署侧成因），无法保证时序时发布后必须复查 `usage-record-spool` 属主；caddy/PG/Redis 不受影响。除属主切换发布的 chown 时序外，发布、更新与回滚流程不变。
- **发布过渡窗口租约等待（BUG-0228，2026-09-28 起）**：发布 recreate 窗口旧 gateway 被 SIGKILL 截断 `defer` 租约释放时，新 gateway 启动期有界等待前任 F3/F4 DB 租约 TTL（默认 30s）过期后接管（compose 显式 `JUHE_AI_OWNER_LEASE_ACQUIRE_WAIT=45s`，默认空 = fail-fast 契约；gateway healthcheck `start_period=75s`）——healthy 滞后至多约 1 分钟属预期，不再出现启动失败重启循环。2026-10-15 起 F3 与 F4 同 owner（进程身份，默认主机名）的未过期租约直接接管、不消耗等待预算，跨 owner 仍等过期。完整契约见 `docker/single-server/README.md`".env 契约"节。
- seed 初始管理员 `admin/admin`，首登强制改密（must_change_password 403 gate，BUG-0224：管理面在公网可达窗口内不得依赖人工改密流程；该行为仅影响新 seed 的实例，现有生产沿用已有 `system_accounts` 行不受影响）。

## 3. HTTPS

Caddy 自动 ACME（Let's Encrypt）签发与续期，80 常驻 308 升级 HTTPS；Caddyfile 在 `docker/single-server/Caddyfile`。该文件为同机两栈共享：还承载同机公益站（juhe-pw 栈）`gyai.huanmin.top` 的反代块，同步/修改时不得遗漏，改前备份、改后 `caddy validate` + `caddy reload`。通用证书说明见 [https/Caddy自动HTTPS部署指南](https/Caddy自动HTTPS部署指南.md)（Edge/家庭回源章节已废弃）。

AI 问答管理面 SSE（`/__aisys__/api/my-chat/*` 流式发送）与 `/v1/*` 一样依赖反代不缓冲：Caddyfile 中该前缀的反代必须显式 `flush_interval -1`（对齐 `/v1/*` 块），SSE 增量传输不能依赖 Caddy 对 `text/event-stream` 的自动刷新行为。

caddy 服务在 compose 中声明 `init: true`（2026-09-29 起）：healthcheck 的 busybox wget https 探测每次泄漏一个 `ssl_client` 子进程，caddy 作为容器 PID 1 不回收会无限堆积 zombie（生产实测 27 小时堆 9470 个后容器 docker exec 全败，实例级损坏）；docker 内置 init 负责收割。若 caddy 容器再次出现 exec 全败/ unhealthy 但流量正常，处置仍是 `docker compose force-recreate caddy`（两栈入口闪断数秒）。

## 4. 更新与回滚

重复"构建 → 上传 → `docker compose build gateway jobs maintenance` → `docker compose up -d`"；发布后跑一次幂等 `maintenance --ensure-schema`（已恢复幂等加法，studio 退场走显式命令；含删列等破坏性收敛的版本须先按 `docker/single-server/README.md`「更新发布」节维护窗口在停写后执行——`deploy.sh` 已内置只读迁移前置核验，capability domain `m2_finalized` 与调度偏好迁移未就绪会直接拒绝发布）。回滚 = 上传上一版 `build/` 重新 build+up。推荐用 `docker/single-server/deploy.sh` 发布：2026-10-02 起其第 [6/6] 步自动运行发布后验证 `verify-release.sh`——usage spool 同源、jobs drain 接线与 gateway 内存限制（GOMEMLIMIT/mem_limit）为强制断言；2026-10-08 起其第 [0/6] 步为前端漏发门禁——发布包含 gateway 时自动探测线上前端版本，`frontend/` 有任何差异即自动重建并上传前端产物，版本未知或产物与 HEAD 不一致时发布中止（此前前端需人工单独构建上传，多次漏发）；2026-10-14 起发布时自动比对并同步 compose.yml / Caddyfile / Dockerfile.runtime 与远端副本（见下文）。~~可选"一条 `/v1` 请求 → 审计 + 用量落库"闭环门禁~~ **已于 2026-10-03 按用户裁定移除**：闭环依赖具体账户/模型的实时可用性，无法保证稳定，作为强制门禁会随上游波动误报；链路落库正确性改由发布后巡检（`audit_logs`/`usage_records` 新行字段核验）覆盖。详见 `docker/single-server/README.md`"更新发布"节。
- **AI 对话工具默认绑定（2026-10-02）**：chat 库新增 `juhe_chat.chat_user_tool_preferences`（用户级搜索/生图默认绑定表），随例行 `--ensure-schema` 幂等建表生效，**无一次性迁移、发布无额外步骤**；回滚上一版二进制无需处理该表（加法式变更，旧代码不读）。
- **AI 账户"特供"恢复标记（2026-10-10）**：业务库加法式两列——`accounts.expedited_recovery_enabled`（integer 0/1，DEFAULT 0）与 `system_accounts.expedited_account_limit`（可空 integer 0–100，NULL 读侧默认 3），随发版执行既有 `--ensure-schema` 幂等补列生效，**无额外命令、无新增环境变量**；回滚上一版二进制无需处理该列（加法式变更，旧代码不读）。契约见 `docs/functions/AI账户特供快速恢复通道设计.md`。
- **模型检测题库提交门禁（2026-10-11）**：业务库加法式一表两列——新表 `model_check_question_tests`（题目可用性测试记录）与 `model_check_question_bank.last_test_id`/`last_test_json` 两列，随发版例行 `--ensure-schema` 幂等建表/补列生效，**无一次性迁移、发布无额外步骤**；回滚上一版二进制无需处理（加法式变更，旧代码不读）。契约见 `docs/functions/模型检测设计.md` §5.7。
- **provider 维度持久列退役（2026-10-23，B4① 存储迁移批；2026-10-25 两表 profile 列收尾）**：破坏性幂等收列——`juhe_codex_context` 三表 `provider_code` + 三个 boundary 索引，`juhe_business` 八列（`account_list_availability_projections`/`_index` 各 `provider_code`/`provider_protocol_profile_id`、`account_test_tasks.provider_code`、`media_jobs.provider_code`；2026-10-25 收尾批追加 `account_test_tasks.provider_protocol_profile_id` 与 `media_jobs.provider_protocol_profile_id`——账户测试任务 JSON 不再输出 `providerProtocolProfileId` 键，草稿测试协议上下文由 `draft_account_encrypted` 快照承载，媒体 usage 行 profile 维度改由轮询时水合账户视图供给）；同批 `account_supported_models.model_id` 声明收紧 NOT NULL（PG 主键隐式 NOT NULL，存量库无需迁移）。随 `--ensure-schema` 收列（PG 11 条 `DROP COLUMN IF EXISTS`），**本版 ensure 含破坏性删列，必须先发停写代码（gateway 与 jobs 同批）再在停写窗口执行**；读面供应商一律经 `accounts.vendor_code` 水合，媒体任务 `providerCode`/`provider` 字段值由 legacy token（gpt 账户曾为 `"openai"`）改显 vendor。**回滚必须「先回代码、再回 schema」**（收列后旧二进制读写该批列报错；恢复收列前备份后才可回退旧二进制，不做保留列软窗口）。完整窗口序列与核验 SQL 见 `docker/single-server/README.md`「更新发布」节；直跑形态等价操作见 `docs/deploy/linux/README.md`。
- **调度偏好独立实体与 P2 迁移（2026-10-12）**：业务库加法式一表一列一内置行——新表 `scheduling_preferences`（对话调度形态 `cost_first/speed_first`、内置位 0/1 词表（v2 起无启用/停用态），owner 内名称唯一精确 + lower 归一双部分唯一索引均挂 `WHERE built_in=0`、`UNIQUE(id) WHERE built_in=1` 内置身份索引）、`api_keys.scheduling_preference_id` 绑定列（text 可空，列级 `REFERENCES scheduling_preferences(id)` 无 ON DELETE 子句仅作 belt，存在性/owner 校验以事务内校验为主）与固定 id 内置行 `schpref-builtin-chat-cost-first`（默认调度偏好，`built_in=1`、owner NULL，全局只读例外；存量旧名「对话·成本优先」由 ensure 拉回）。**新版 gateway/jobs 启动对其做只读校验（表形状 / api_keys 绑定列 / 内置行存在且合规；P2 起追加第四臂——`global_settings` key `scheduling_preferences_migration` 存在且 `stage=completed`），缺失或不符 fail-fast，错误信息直接给出运维动作**。升级顺序固定为**先停写并备份，窗口内再 ensure-schema 与迁移、核验通过后启动新版 gateway/jobs**（在 M1/M2 能力域窗口之后并入同一停写窗口；停写与备份必须先于 ensure——v2 起 ensure 含破坏性删列 `DROP COLUMN enabled`，P1 旧二进制运行时执行会打断写者，ensure 后才备份会失去 P1 回滚价值；若按惯例 `up -d` 之后才补跑，新版 gateway/jobs 会以 fail-fast 错误重启循环，补跑后自动恢复）：

  ```sh
  # 1) 停写窗口第一步：停 gateway/jobs（schema 变更与迁移一律不在写者运行时执行）
  docker compose stop gateway jobs
  # 2) 完成并验证可恢复备份（先于 ensure，保住 P1 回滚价值）
  # 3) P1/P2 schema：例行 ensure-schema（幂等建表/补列/删列 + ensure 臂补种内置行）
  docker compose run --rm maintenance --ensure-schema --dsn "$JUHE_AI_POSTGRES_URL"
  # 4) 预检（只读报告，退出码恒 0；Blocking>0 = 有阻断迁移的坏数据，先修复）
  docker compose run --rm maintenance --verify-scheduling-preferences --scheduling-preferences-check=preflight --dsn "$JUHE_AI_POSTGRES_URL"
  ```

## 7. 监控交付（Prometheus / Grafana）

2026-10-14 起应用进程监控与容量观测统一收敛到 Prometheus pull 抓取 + Grafana 面板；原管理后台「系统指标统计」页与「表监控」页及其读接口、gometrics 采样链、两家族监控 env 已整体删除。指标族、端点与安全边界的权威契约见 [Prometheus 指标暴露设计](../functions/Prometheus指标暴露设计.md)；交付物（Prometheus 抓取配置片段、postgres_exporter 增补查询、Grafana 面板 JSON）在 `docker/single-server/monitoring/`，配置契约权威为 `docker/single-server/README.md`。

端口发布契约：

- gateway 容器内监听 `JUHE_AI_GATEWAY_HEALTH_LISTEN_ADDRESS=0.0.0.0:3306`，compose 端口发布固定 `127.0.0.1:3306:3306`；jobs 监听 `0.0.0.0:3305`，发布固定 `127.0.0.1:3305:3305`。宿主侧仅回环可达，不得发布到非回环地址或加入反代。
- infra Prometheus 经既有 SSH 隧道访问宿主回环 `127.0.0.1:3306/3305`，`scrape_interval: 60s`（隧道为用户自管外部资产，不在 compose 内复制）。

`.env` 清理清单（生产与开发环境同口径，删除即可，无需新增变量）：

- `JUHE_AI_GO_RUNTIME_METRICS_*` 全家族（`STORE`、`POSTGRES_URL`、`ROLE`、`INTERVAL`、`RETENTION_DAYS`、`SERVICE`、`DATABASE_PATH` 及历史 `ENABLED` / `URL`）。
- `JUHE_AI_TABLE_MONITOR_*` 全家族（`STORE`、`POSTGRES_URL`、`DATABASE_PATH`、`INSTANCE_ID`、`INTERVAL`、`RUN_TIMEOUT`、`OWNER_LEASE`、`RETENTION_DAYS`、`MAX_TABLES`、`MAX_CONCURRENT_SOURCES`、`RETENTION_BATCH_SIZE`、`RETENTION_MAX_BATCHES` 及 Node 时代遗留变量）。
- gateway 侧 `JUHE_AI_JOBS_HEALTH_LISTEN_ADDRESS`（jobs 侧该 env 保留，仍是健康监听配置）。
- **存储形态收口退役族（2026-10-24/25，SQLite 与内存模式退役）**：`JUHE_AI_RUNTIME_MODE` / `JUHE_AI_DATABASE_DRIVER` / `JUHE_AI_CACHE_DRIVER` / `JUHE_AI_RUNTIME_STATE_DRIVER` 四开关、全部 `*_DATABASE_PATH` 路径族、usage/codex 分片族（`JUHE_AI_USAGE_SHARD_*` / `JUHE_AI_CODEX_CONTEXT_STATE_SHARD_*`）与 `*_STORE` 选择族（含 `JUHE_AI_ACCOUNT_HEALTH_INPUT_SOURCE`）——完整清单与说明见 `docker/single-server/README.md`「存储形态收口退役 env」节；maintenance 命令同步收敛为 `--dsn` 单形态。

验证步骤：
