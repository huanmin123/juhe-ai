# 生产发布快速流程

> 面向生产维护者和 AI 执行者。本文定义高性能 Mac 拓扑的默认 routine release；真实地址、账号、端口、凭据和当前槽位只从受限私有 runbook 读取。

## 1. 目标

常规发布应在分钟级完成，用户侧只经历一次 Nginx reload。构建、上传、解包和 candidate 启动均在旧槽继续承流时完成。默认不做长观察、预检 journal、全量指标、审计读回或浏览器自动化；这些只在故障调查、首次新拓扑或异常回切时使用。

| 阶段 | 用户流量 | 通过条件 |
| --- | --- | --- |
| 构建与上传 | 旧槽承流 | 原生平台构建完成，release SHA-256 与 `juhe-ai-jobs`、`juhe-ai-gateway`、`juhe-ai-maintenance` 可核对 |
| candidate 启动 | 旧槽承流 | control health、API health、无 Key gateway `401`、共享 Go jobs/gateway health 与 F3/F4 input health 均成功；启动日志无 `panic`/`fatal` |
| 快速切换 | 一次 reload | route fragment 原子替换后，公网 control health、API health、无 Key gateway `401` 均成功 |
| 保留旧槽 | 新槽承流 | 不在发布窗口清理旧槽；下一次 routine release 前再处理 |

任何 candidate 失败都不能停止旧槽。route 切换后任一入口探针失败，脚本必须自动恢复原 route；无法恢复时停止后续动作并保留两槽。

## 2. 窗口前准备

1. 固定一个干净 commit，在目标 Mac 或受控原生 macOS 构建机只构建一次 release。禁止 Windows Git Bash/MSYS 作为生产构建入口。
2. 运行 `pnpm test:release-package`、`pnpm test:release-source-preflight`、`pnpm test:release-go-project-launchers`、`pnpm test:macos-operations`。
3. 上传后只核对 archive SHA-256、`RELEASE_SOURCE_COMMIT`、前端 buildId、目标架构和 `backend-go/juhe-ai-jobs`、`backend-go/juhe-ai-gateway`、`backend-go/juhe-ai-maintenance`。
4. 以独立 release、runtime、label、端口、Nginx slot、upstream suffix、Node instance ID 和 Redis identity 启动 candidate；必须传 `--go-sidecar-mode reuse`，复用正式的 Go jobs/gateway owner，不创建第二个 F1/F2/F3/F4 owner。

candidate 启动使用 `--quick`。它只等待一次 Node control/API health、gateway health、共享 Go jobs/gateway project health 与 F3/F4 input health，跳过指标注册和重复稳定轮询。生产 system scope 的最小参数形状如下；真实路径、端口、标签和身份只从私有 runbook 读取：

```bash
sudo bash ./install-performance-topology.sh --apply --quick \
  --scope system \
  --service-user '<服务用户>' \
  --base-dir '<发布根目录>' \
  --release-dir '<candidate release 绝对路径>' \
  --label-prefix '<candidate launchd label 前缀>' \
  --control-port '<candidate control 端口>' \
  --gateway-base-port '<candidate gateway 起始端口>' \
  --control-count 3 \
  --gateway-count 5 \
  --ingress-port '<candidate 内层 ingress 端口>' \
  --audit-input-port '<正式 Go F3 loopback 端口>' \
  --operation-log-input-port '<正式 Go F4 loopback 端口>' \
  --go-sidecar-mode reuse \
  --runtime-dir '<candidate runtime 绝对路径>' \
  --nginx-upstream-suffix '<candidate upstream 后缀>' \
  --instance-id-prefix '<candidate instance 前缀>' \
  --nginx-config '<candidate 已 include 的 slot 文件>' \
  --nginx-main-config '<外层 nginx 主配置>' \
  --nginx-bin '<nginx 可执行文件>'
```

## 3. 默认切流

从私有 runbook 代入当前 active route、candidate route、candidate loopback URL、共享 Go loopback URL、外层 Nginx main config、candidate startup log 和候选 route identity：

```bash
sudo bash ./quick-performance-cutover.sh --apply \
  --active-route-file '<active route fragment>' \
  --candidate-route-file '<candidate route fragment>' \
  --nginx-main-config '<outer nginx main config>' \
  --candidate-control-url 'http://127.0.0.1:<candidate>/__aisys__/health' \
  --candidate-api-health-url 'http://127.0.0.1:<candidate>/__aisys__/api/health' \
  --candidate-gateway-url 'http://127.0.0.1:<candidate>/v1/models' \
  --go-health-url 'http://127.0.0.1:<shared-go-port>/__aiinternal__/health' \
  --ingress-control-url 'https://<public-host>/__aisys__/health' \
  --ingress-api-health-url 'https://<public-host>/__aisys__/api/health' \
  --ingress-gateway-url 'https://<public-host>/v1/models' \
  --startup-log '<candidate control startup log>'
```

`QUICK_CUTOVER_OK` 是切流完成的唯一成功标志。脚本只做一次 route fragment 替换和 Nginx reload；它不启动、停止或重配 Node/Go 服务。切换后 control、API 或 gateway 任何一条失败，自动写回切换前的 route 并 reload Nginx。

## 4. 回切与异常

切换后的异常，保留两个槽位，直接把旧 route 作为 candidate 用同一 `quick-performance-cutover.sh` 反向执行。若 active route 被人工修改、自动恢复失败，或需要证明进程/worker/指标拓扑，再使用 `performance-handover-controller.sh` 的长 preflight、switchback 和 journal；它不是 routine release 前置。

## 5. 禁止事项

- 禁止对 active 槽执行同端口、同 label 的原地 `--apply`。
- 禁止在切流窗口构建、安装依赖、迁移 schema、清理 Redis/日志或删除旧 release。
- 禁止以静态首页、单个 `200`、F3 `204` 或 launchd loaded 代替 control、API、gateway 三条请求和启动日志。
- 禁止在快速切换成功后立即停止旧槽。
- 禁止手动改 active route 或杀进程来“加快”切换。

## 6. 发布记录

每次只记录：commit、archive SHA-256、candidate identity、四项本地发布回归、三条 candidate 请求、启动日志结果、`QUICK_CUTOVER_OK` 或自动恢复结果。不要把重复备份、重复审查或长时间观察当成发布成功证据。
