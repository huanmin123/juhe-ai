# 代理部署示例（云端单机 Docker 形态）

一次完整落地路径的速览；细节以 [sing-box 网络代理部署指南](sing-box网络代理部署指南.md) 对应章节为准。

## 场景

- 国内单台云服务器，juhe-ai 以 Docker Compose 运行（gateway / jobs 容器）。
- sing-box 安装并常驻于同一台服务器的宿主机（systemd 托管）。
- 节点来源：机场订阅（订阅链接由使用者提供，属用户资产，不入仓库）。
- 目标：juhe-ai 的上游模型请求经本机 sing-box 订阅节点池出海。

## 步骤

1. 安装 sing-box（指南第 3 节），确认版本支持 `selector`、`clash_api`、`cache_file`。
2. 按指南第 4 节写配置骨架：mixed 入站监听 `172.18.0.1:17892`、selector 组 `auto`（暂以 `direct` 作占位 default）、`clash_api 127.0.0.1:19090` + `cache_file`。`sing-box check` 通过后按第 5 节用 systemd 常驻（`Restart=always` 必须保留）。
3. 把订阅链接写入 `/etc/sing-box/subscription-url`（权限 600）；按指南第 8-10 节的思路与策略实现（或交给 AI 生成）订阅解析、订阅定时更新器与择优控制器，实现文件保存在维护者自有目录、不入仓库；手动触发一轮更新，把订阅节点写入配置并重启生效。
4. 按指南第 12 节清单验证：`curl -x socks5h://172.18.0.1:17892 https://api.openai.com/v1/models -I` 有响应；clash_api 返回 `type: Selector` 且组内为全部订阅节点。
5. 后台“代理管理”新增代理（`socks5h`，`172.18.0.1:17892`），测试通过后绑定到 AI 账户（指南第 6 节）；如需 OAuth 兜底再配置 `JUHE_AI_OAUTH_PROXY_URL`（指南第 7 节）。
6. 启用择优控制器 timer 与订阅更新 timer（单元命名可参考 `juhe-proxy-switch` / `juhe-sub-update`），观察一轮决策日志与更新日志确认自动化正常。
