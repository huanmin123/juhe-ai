# 媒体工作室设计

> 状态：已实施契约（P0）；来源 PLAN-20261012T123000000Z 决策 #1-#9。
> 本文是媒体工作室 **P0 工作台地基**（图像工作台、音频工作台 TTS/STT、视频单镜快造 + `studio_assets` / `studio_tasks` + purpose=studio Key + jobs 有界轮询结算）的行为契约权威来源。执行面（`/v1` 媒体网关）契约见《[音频视频模型接入与统一媒体网关设计](音频视频模型接入与统一媒体网关设计.md)》，本文复用其语义、不重复其内容；产品方向与前端蓝图见 [计划-20261012T123000000Z-媒体工作室规划建议](../plans/计划-20261012T123000000Z-媒体工作室规划建议.md)（下称"规划"）。本文与规划冲突时以本文为准，并回改规划对应章节，不保留两套口径。P1 项目模式只在本旨 §11 写"预留与边界"，不展开。

## 1. 功能定位

1. **登录用户的媒体生产入口**：AI 问答内的生图/音视频工具随 [PLAN-20261012T121500000Z AI 问答简化设计](../plans/计划-20261012T121500000Z-AI问答简化设计.md) 退场后，媒体生成能力迁往独立"媒体工作室"菜单。P0 交付三个工作台：`/my-studio/images` 图像生成、`/my-studio/audio` 音频生成（文本转语音 + 语音转文本）、`/my-studio/video` 视频单镜快造。全部路由为登录用户可用（`viewScope: 'self'`，无角色限制）。
2. **`/v1` 执行面复用，零重复**：工作室不直接连供应商，一切生成经既有 `/v1` 媒体网关创建链与任务面（账户选择、受理边界、计费、审计、账户亲和任务面全部复用）；平台不做本地 GPU 推理。公开 `/v1` API 域行为零改变。
3. **产品域资产落库**：`/v1` 执行面实行"零资源存储"（产物不落盘、content 纯流式透传），`media_jobs` 任务行 7 天 TTL 清理。工作室是产品域：作品需可持续回看、下载，产物独立落 `studio_assets`（对象存储 + 元数据），配额内长期保留，与执行面零存储边界互补、互不改变。
4. **Sora 不进入候选**：官方已确认 OpenAI Videos API、`sora-2` / `sora-2-pro` 及各快照型号于 **2026-09-24** 停用、无推荐替代（来源：[OpenAI API Deprecations](https://developers.openai.com/api/docs/deprecations#2026-03-24-sora-2-video-generation-models-and-videos-api)，2026-10-12 已读取原文，裁决记录见规划"Sora 退役裁决"节）。工作室不展示、不测试、不新建 Sora 任务；视频候选 = 当前已注册且未退役的六家 adapter（gemini/Veo、glm/CogVideoX、minimax/Hailuo、volcengine/Seedance、qwen/万相、xai/Grok Imagine）。代码存在不等于上游可用，实际型号以能力载荷与联调为准。Sora 专属目录/计价/adapter/探针退役属执行面清理任务，不在本文范围内展开；本项目 `/v1/videos` 统一 API 保留。
5. **范围边界**：P1 项目模式（要素库/分镜/逐镜/合成）不在 P0；见 §11 预留与边界。

## 3. 数据模型（P0）

全部表落业务库 `juhe_business`，schema 由 `backend-go/projects/maintenance` 幂等迁移交付（`CREATE TABLE IF NOT EXISTS` / `ADD COLUMN IF NOT EXISTS` / 具名约束替换，沿 `media_jobs` 与 `api_keys` 先例）。所有行带 `system_account_id` 强制归属；绝对时间为 RFC3339（接口契约"时间字段契约"）。引用列沿记录表先例**不加外键**（`media_jobs` 同款裁决）：资产删除后任务行 `asset_id` 保留为悬空引用，内容端点按不存在返回 404，不反向阻断清理。

### 3.1 `studio_assets`（产品域资产）

```sql
CREATE TABLE IF NOT EXISTS studio_assets (
  id text PRIMARY KEY,                                -- stasset_ 前缀
  system_account_id text NOT NULL,
  kind text NOT NULL CHECK (kind IN ('image', 'audio', 'video')),
  mime text NOT NULL,
  storage_key text NOT NULL UNIQUE,                   -- 对象存储 key（chat_assets 同款端口语义）
  bytes bigint NOT NULL,
  width integer,                                      -- 可空：仅 image
  height integer,                                     -- 可空：仅 image
  duration_ms bigint,                                 -- 可空：audio/video；来源缺失时保持 NULL
  sha256 text NOT NULL,
  source_task_id text,                                -- 可空：生成任务结算落库时回填 studio_tasks.id；上传为 NULL
  params_json text NOT NULL DEFAULT '{}',             -- 生成参数快照（画廊"回填参数重生成"依据）；上传为 '{}' 或调用方元数据
  created_at text NOT NULL,
  updated_at text NOT NULL
);

CREATE INDEX IF NOT EXISTS idx_studio_assets_owner_created
  ON studio_assets(system_account_id, created_at DESC, id DESC);
CREATE INDEX IF NOT EXISTS idx_studio_assets_owner_sha256
  ON studio_assets(system_account_id, sha256);
-- 生成产物幂等结算闸（§5.4）：同一任务的产物行全库唯一；上传行 source_task_id 为 NULL 不受约束
CREATE UNIQUE INDEX IF NOT EXISTS idx_studio_assets_owner_source_task
  ON studio_assets(system_account_id, source_task_id) WHERE source_task_id IS NOT NULL;
```

要点：

- `kind` 为资产类型（image/audio/video），与任务 `kind`（image/video）是两个词表：TTS 产物落 `kind='audio'` 资产，转写产物是文本不入资产库。
- `(system_account_id, sha256)` 索引只服务**同用户**内容定位与幂等查重辅助；跨用户同 hash 不构成任何匹配或可见性依据（不泄露存在性）。
- 对象存储复用既有存储端口（`chat_assets.storage_key` 同源），不新造存储栈；不设 `expires_at`（配额内长期保留，区别于 `chat_assets` 3 天保留期）。

### 3.2 `studio_tasks`（用户归属生成任务）

```sql
CREATE TABLE IF NOT EXISTS studio_tasks (
  id text PRIMARY KEY,                                -- stask_ 前缀
  system_account_id text NOT NULL,
  client_operation_id text NOT NULL,                  -- 用户范围幂等键（1..128 字符）
  kind text NOT NULL CHECK (kind IN ('image', 'video')),
  status text NOT NULL DEFAULT 'queued' CHECK (status IN
      ('queued', 'in_progress', 'completed', 'failed', 'cancelled', 'expired')),  -- 六值词表同 media_jobs
  settlement text NOT NULL DEFAULT 'pending_settled' CHECK (settlement IN
      ('pending_settled', 'settled', 'failed')),
  account_id text,                                    -- 账户亲和三元组：受理时写入（受理前为 NULL）
  provider_code text,
  upstream_job_id text,                               -- /v1 统一 job id（即 media_jobs.id），非供应商原始 id
  request_snapshot_json text NOT NULL DEFAULT '{}',   -- 轻量参数快照（不含资源字节，零存储同款约束）
  error_json text NOT NULL DEFAULT '{}',              -- 终态/结算错误（脱敏）
  asset_id text,                                      -- 结算产物；资产删除后保留悬空引用
  poll_bookmark_json text NOT NULL DEFAULT '{}',      -- 上游轮询书签（续轮询接续点；与分页无关）
  lease_owner text,                                   -- jobs 领取者身份
  lease_expires_at text,                              -- 租约到期时间
  lease_attempt_count integer NOT NULL DEFAULT 0,     -- 领取/结算尝试次数（有界）
  created_at text NOT NULL,
  updated_at text NOT NULL,
  UNIQUE (system_account_id, client_operation_id)
);

CREATE INDEX IF NOT EXISTS idx_studio_tasks_owner_created
  ON studio_tasks(system_account_id, created_at DESC, id DESC);
CREATE INDEX IF NOT EXISTS idx_studio_tasks_claim
  ON studio_tasks(status, settlement, lease_expires_at);
```

要点：

- **命名说明**：规划所述任务行"轮询游标/期限、lease"在本契约落为 `poll_bookmark_json` + `lease_*` 列；`poll_bookmark_json` 是 jobs 续轮询的上游书签，与任何分页协议无关（分页一律 limit/offset，见 §4.0）。
- `account_id` / `provider_code` / `upstream_job_id` 为**受理时写入**的账户亲和三元组（受理前为 NULL）：受理确立后查询/下载/取消都定位原账户原上游，永不换账户（对齐 `/v1` 任务面账户亲和语义）。`upstream_job_id` 存 `/v1` 统一 job id（`media_jobs.id`），供任务面定位与恢复关联（§5.5），不存供应商原始 id。
- `status` 与 `settlement` 正交：`status` 表达上游执行进度（六值同 `media_jobs`），`settlement` 表达产物结算子状态；"上游已 completed 但未入库"= `status='completed' AND settlement<>'settled'`，这是领取条件必须覆盖未结算态的原因（§5.1）。
- 本地失败（受理前派发穷尽）与上游终态失败（无产物）直接 `settlement='settled'`（无产物可结算）；`settlement='failed'` 专指"有产物需要入库但下载/入库失败"，可被重新领取重试（有界，见 §5.1 / §5.4）。

### 3.3 `studio_operations`（同步生成幂等收据）

TTS / STT 是同步端点、不产生 `studio_tasks` 行（任务 `kind` 词表仅 image/video），但 `client_operation_id` 幂等规则相同：同 ID 重复提交必须返回原结果、不再调上游（防重复付费）。幂等映射由独立收据表承载：

```sql
CREATE TABLE IF NOT EXISTS studio_operations (
  id text PRIMARY KEY,                                -- stoper_ 前缀
  system_account_id text NOT NULL,
  client_operation_id text NOT NULL,
  kind text NOT NULL CHECK (kind IN ('audio_speech', 'audio_transcription')),
  asset_id text,                                      -- speech：已保存资产 id；transcription 为 NULL
  result_json text NOT NULL DEFAULT '{}',             -- transcription：{text, srt?}；speech 为 '{}'
  created_at text NOT NULL,
  updated_at text NOT NULL,
  UNIQUE (system_account_id, client_operation_id)
);
```

- 同步端点收到已存在的 `(system_account_id, client_operation_id)` 时直接按收据返回原资产 / 原文本，HTTP 200，`message` 注明"已返回既有结果"，不调上游、不重复计费。
- 收据行随结果本身长期保留（P0 无 TTL；行体积极小）。资产被用户删除后收据保留：同 ID 重放返回资产缺失错误（404 `studio_asset_not_found`），不重新生成。

### 3.4 `studio_user_asset_usage`（配额账本）

```sql
CREATE TABLE IF NOT EXISTS studio_user_asset_usage (
  system_account_id text PRIMARY KEY,
  asset_bytes bigint NOT NULL DEFAULT 0,
  asset_count bigint NOT NULL DEFAULT 0,
  updated_at text NOT NULL
```

沿 `chat_user_asset_usage` 先例：入库/删除在事务内以 `pg_advisory_xact_lock(hashtextextended('juhe-ai:studio-asset-usage:' || system_account_id, 0))` 串行化增减；账本与行数以事务一致性维护，不做后台对账补偿。

### 3.5 `api_keys.purpose` 扩展与 EnsureStudioKey

对齐 chat 专用 Key 先例（`purpose='chat'` + `idx_api_keys_chat_purpose_unique` + `EnsureChatAPIKey`）：

1. **CHECK 词表扩展**：`api_keys.purpose` CHECK 从 `IN ('general', 'chat')` 扩展为 `IN ('general', 'chat', 'studio')`。存量库幂等迁移：按表 + conkey 定位旧 CHECK 删除后补挂具名约束（沿 `accounts.health_check_endpoint_mode` 迁移先例）。
2. **每用户唯一 partial index**：

   ```sql
   CREATE UNIQUE INDEX IF NOT EXISTS idx_api_keys_studio_purpose_unique
     ON api_keys(system_account_id) WHERE purpose = 'studio';
   ```

3. **Key 域授权列**：`ALTER TABLE api_keys ADD COLUMN IF NOT EXISTS studio_domains_json text`（仅 purpose='studio' 行使用）。P0 ensured Key 恒写 `["text","image","audio","video"]` 四域，不提供编辑入口（越权面 = 执行链校验，见 §4.5）；该列是授权数据不是功能开关。
4. **EnsureStudioKey 幂等机制**（镜像 `EnsureChatAPIKey`，含默认资源自愈）：
   - 触发时机：任一 `/__aisys__/api/my-studio` 生成或账户候选调用前（异步确保，不阻塞响应路径）。
   - 步骤：自愈确保用户默认分组与默认策略路由（chat 同款"默认资源收口"自愈）→ 探测 `(system_account_id, purpose='studio')` 现存 Key → 存在且 active 直接复用 → 不存在则插入新行（name 基名"媒体工作室 API Key"，同名冲突按序号避让；绑定默认策略路由；`studio_domains_json` 四域）。
   - 并发竞态：INSERT 撞 `idx_api_keys_studio_purpose_unique` 或同名唯一索引时，重探并复用胜者行，不报错。
   - 自愈：用户在 API Key 页删除 studio Key 后，下次工作室调用自动重建（同 chat 默认资源自愈语义）；P0 不提供 studio Key 专门管理面，Key 出现在既有 API Key 列表中可读。
   - 职责边界：studio Key 仅承载 `/v1` 链的 Bearer 鉴权、额度与计费归属；工作台生成的账户目标由用户在页面选择后经进程内调度覆盖收敛派发（chat 绑定账户同款机制），Key 的策略路由仅满足 preauth 链结构要求、不参与账户选择，外部 HTTP 请求无法指定调度目标。

### 3.6 资产配额

- **上限（P0 默认值，编译期常量可调、不设开关）**：每用户 studio 资产总容量 **20 GiB**（`20 * 1024^3` 字节）、总个数 **2000 个**。调整限值属代码常量修订，随交付同步本文与容量预算，不新增配置项。
- 计量点：`studio_assets` 行提交（`uploading → ready`，或结算入库）事务内增量；删除事务内回落（§3.4）。`uploading` 孤儿行不计费、不占配额（配额在 ready 提交时才落账）。
- 超限语义：上传与结算入库前预检，容量超限 → 413 `studio_asset_quota_exceeded`，个数超限 → 413 `studio_asset_count_exceeded`（沿 chat 先例 413 + 中文文案）。生成任务的产物入库超限 → 任务结算失败（`settlement='failed'`，error 记配额超限），**不虚计、不静默丢弃**；上游计费已由 `/v1` 如实落账。

## 4. API 契约（`/__aisys__/api/my-studio`）

### 4.0 通用约定

- **接口层**：用户 API（`/__aisys__/api/my-*`），后台登录态 Cookie 鉴权（`requireAuth`），服务端强制当前登录用户 `systemAccountId` 作用域，忽略/拒绝客户端提交的用户 ID；管理员从个人入口调用同样只见自己的数据。响应为项目管理 API 结构 `{data, message}`；错误为 `{message, code, details?}`，`message` 中文、`code` 稳定英文。
- **分页**：全部列表端点 `limit` / `offset`（对齐 `mediaJobs` 先例：`limit` 默认 20、上限 100、非法回落默认；`offset` 负数回落 0），响应 `{data:{rows:[...], total}}`；**不采用任何游标协议**。
- **时间**：RFC3339（推荐 UTC `Z`）；前端按浏览器本地时区展示、不回写 API 值。
- **归属与越权**：所有资源按 `system_account_id` 强制过滤；越权读取与不存在**同型返回 404**（不泄露存在性，对齐 my-chat 口径）。
- **幂等协议**：四个生成端点 `clientOperationId` 必填（1..128 字符，用户范围唯一）。同 ID 重复提交返回原任务/原结果（200，`message` 注明"已返回既有任务/结果"），不再次调用上游。**响应丢失（超时/断网，受理结果未知）时，前端先 `GET /tasks?operation_id=`（异步）或携带同 ID 原样重发（同步，命中收据零副作用）确认，未受理才允许重发**；"重试=新建任务"仅适用于已明确失败的终态任务（换新 `clientOperationId`）。
- **前端调用面**：新增调用全部进入 `pnpm --filter juhe-ai-frontend test:api-contract` 的"前端调用 ⊆ Go 注册面"静态比对，无需手工登记。

### 4.1 账户与模型目录

#### `GET /__aisys__/api/my-studio/accounts`

账户候选。查询参数 `domain`（可选，`image|audio|video|text`，非法 400 `studio_domain_invalid`；缺省返回全域能力账户）。

响应 `data.rows[]`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `accountId` | string | AI 账户 id |
| `name` | string | 账户名称 |
| `providerCode` | string | 供应商标识 |
| `domain` | string | 能力域（`chat/image/audio/video`） |

域模型目录（能力载荷驱动表单的数据源）。`domain` 必填（`image|audio|video`，`text` 域 P0 无工作台目录端点；缺省/非法 400 `studio_domain_invalid`）。目录来源 = 能力域拆分后的既有目录读链（`provider_model_catalog` 静态快照按 mode 过滤 + `custom_provider_models` + hybrid 账户映射），工作室不新造目录。

响应 `data.rows[]`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `model` | string | 模型 id |
| `providerCode` | string | 供应商标识 |
| `domain` | string | `image/audio/video` |
| `endpointModes` | string[] | 端点模式词表（如 `images_json`、`audio_speech`、`audio_transcription`、`video_create`；STT/TTS 页签据此过滤） |

`capabilities` 规范键：

| 域 | 键 | 说明 |
| --- | --- | --- |
| image | `sizes[]`、`supportsNegativePrompt`、`supportsReferenceImage` | `supportsReferenceImage=true` 时参考图走 `/v1/images/edits` 形态 |
| audio | `voices[]`、`responseFormats[]`、`speedRange?`、`emotionOptions?`、`timestampCapable` | `timestampCapable=false` 时 STT 不提供 SRT（不从普通文本虚构时间轴） |

### 4.2 资产

AssetDTO（各端点共用）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | `stasset_` 前缀 |
| `kind` | string | `image/audio/video` |
| `mime` | string | MIME 类型 |
| `bytes` | number | 字节数 |
| `width` / `height` | number \| null | 仅 image |
| `durationMs` | number \| null | audio/video，来源缺失为 null |
| `sha256` | string | 内容摘要 |
| `sourceTaskId` | string \| null | 生成来源任务；上传为 null |
| `params` | object | `params_json` 解析结果 |
| `createdAt` | string | RFC3339 |

#### `POST /__aisys__/api/my-studio/assets`

multipart 上传。表单字段：`file`（必填二进制）、`paramsJson`（可选 JSON 字符串，默认 `'{}'`）。P0 仅接受 `kind=image`（由 MIME 判定：`image/png|image/jpeg|image/webp`），单文件上限 25MB（对齐 `/v1` 同步上传体事实约束）；P1 放开 audio/video 上传（BGM/参考素材）。

流程：写 `uploading` 行 → 流式写对象存储 → 事务内转 `ready` + 解析宽高 + 配额预检与增量。任一步失败回滚行并删除已写对象；进程崩溃残留的 `uploading` 行由 jobs 孤儿回收任务清理（§5.6），不占配额。

- 201：`{data: AssetDTO}`
- 错误：400 `studio_invalid_request`（文件缺失/MIME 不符/超限/paramsJson 非法）、413 `studio_asset_quota_exceeded`、413 `studio_asset_count_exceeded`

#### `GET /__aisys__/api/my-studio/assets?limit=&offset=&kind=`

素材库列表。`kind` 可选（`image|audio|video`）。默认仅返回 `ready` 行（`uploading` 对外不可见）。按 `(created_at DESC, id DESC)` 排序。响应 `{data:{rows: AssetDTO[], total}}`。

#### `DELETE /__aisys__/api/my-studio/assets/{id}`

删除：事务内删行 + 删对象 + 配额账本回落，204 No Content。

引用保护（409 `studio_asset_referenced`）：P0 无项目引用，触发条件为**存在 `settlement='pending_settled'` 且 `asset_id` 指向该资产的 `studio_tasks` 行**（防御结算重试窗口）；错误文案注明引用来源。P1 项目/镜头/字卡/成片引用接入后同码扩展，不新增错误码。

#### `GET /__aisys__/api/my-studio/assets/{id}/content?variant=&download=`

内容端点。`variant` 缺省 `original`；`preview` 仅对 image 有效（P0 不做转码，audio/video 传 `preview` 返回 400 `studio_asset_preview_unavailable`）；`download=1` 时附 `Content-Disposition: attachment`。

沿 chat 内容端点先例：非 `ready` 或归属不符一律 404（`studio_asset_not_found`）`{"message":"素材不存在"}`；响应头 `ETag: "<sha256>"`、`Cache-Control: private, max-age=86400, immutable`、`X-Content-Type-Options: nosniff`；`If-None-Match` 命中返回 304（不读对象）。

### 4.3 生成

四端点公共规则：

- `clientOperationId` 必填，幂等协议见 §4.0；`accountId` 必须在当前用户可派发范围（§4.1 两档口径），越范围 403 `studio_account_not_authorized`。
- `model` 必须属于请求域目录（400 `studio_model_domain_mismatch`）；请求参数中目录能力载荷未声明的项返回 400（不静默忽略——与 `/v1` L2 规范"不猜测、不降级"一致）。
- `providerOptions` 为透传 `/v1` L3 扩展通道的对象，结构约束与派发选中后的合并语义沿用执行面契约，工作室不解析其内容。
- 异步端点（images / videos）受理后立即返回 TaskDTO，终态经任务端点轮询；同步端点（speech / transcriptions）请求-响应内完成，响应即最终结果。
- 同步端点执行失败：502 `studio_generation_failed`（上游已受理后的错误，脱敏中文 + 上游错误摘要）或 502 `studio_upstream_unavailable`（受理前派发穷尽）；确定性 4xx 参数类错误原样映射 400。

#### `POST /__aisys__/api/my-studio/generations/images`

异步受理，返回任务。内部执行链见 §4.5：`/v1` 图像创建为同步形态，工作室以**后台执行 + 任务行**承载（提交即建任务 → 轮询终态），对齐规划 F3 交互约定。

请求 DTO：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `accountId` | string | 是 | 执行账户 |
| `model` | string | 是 | 图像域模型 |
| `prompt` | string | 是 | 提示词 |
| `negativePrompt` | string | 否 | 能力载荷声明 `supportsNegativePrompt` 时才可传 |
| `size` | string | 否 | 能力载荷 `sizes[]` 内取值 |
| `referenceAssetId` | string | 否 | 用户自有 `ready` 图像资产 id；模型 `supportsReferenceImage=true` 时才可传，走 `/v1/images/edits` 形态 |
| `providerOptions` | object | 否 | L3 通道 |
| `clientOperationId` | string | 是 | 幂等键 |

无数量参数（决策 #9④ 首版单张）。响应 201：`{data: TaskDTO}`；同 `clientOperationId` 重放 200 返回原任务。

#### `POST /__aisys__/api/my-studio/generations/speech`

同步返回**已保存资产**（决策 #9③：响应即入库，无独立保存开关）。产物落 `studio_assets(kind='audio')` 后随响应返回；幂等收据见 §3.3。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `accountId` / `model` / `clientOperationId` | string | 是 | 同公共规则 |
| `input` | string | 是 | 待合成文本（长文本分段由前端拆分逐段调用，端点不聚合） |

| `speed` / `volume` / `emotion` | string\|number | 否 | 能力载荷声明才可传 |
| `responseFormat` | string | 否 | `responseFormats[]` 内取值 |
| `providerOptions` | object | 否 | L3 通道 |

#### `POST /__aisys__/api/my-studio/generations/transcriptions`

同步返回文本 / SRT。产物不入资产库；结果写入幂等收据（§3.3）。multipart 表单：`file`（必填音频二进制，≤25MB）、`accountId`、`model`、`clientOperationId`（以上必填），`language`、`providerOptions`（可选）。

异步受理，返回任务。内部经 `/v1` `POST /v1/videos` 创建链（受理边界由 `/v1` 派发循环承担）。

| `accountId` / `model` / `prompt` / `clientOperationId` | string | 是 | 同公共规则 |

TaskDTO：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | `stask_` 前缀 |
| `kind` | string | `image/video` |
| `status` | string | 六值词表 |
| `settlement` | string | `pending_settled/settled/failed` |
| `model` | string | 请求模型 |
| `accountId` / `providerCode` | string \| null | 受理后非空 |
| `promptSummary` | string | 截断 120 字符（对齐 `media-jobs` 先例） |
| `assetId` | string \| null | **仅 `settlement='settled'` 且资产存在时返回，否则 null**（settled 前前端不显示成品） |
| `error` | {code,message} \| null | 终态/结算错误（脱敏） |

#### `GET /__aisys__/api/my-studio/tasks?limit=&offset=&status=&kind=&operation_id=`

任务列表。`status`（六值单值，非法 400）、`kind`（`image|video`）、`operation_id`（按当前用户的 `client_operation_id` 精确匹配，**响应丢失后的受理确认查询入口**）。按 `(created_at DESC, id DESC)` 排序。响应 `{data:{rows: TaskDTO[], total}}`。

#### `DELETE /__aisys__/api/my-studio/tasks/{id}`

取消，按四态分层语义（决策 #9⑨ / 规划 F3.5）：

| 任务态 | 行为 | 响应 |
| --- | --- | --- |
| a. 未上游受理（`status='queued'` 且 `upstream_job_id IS NULL`，图像任务含"尚未进入 `/v1` 调用"） | 本地置 `cancelled`，**不调上游**；执行器感知取消标记后停止发起（已发出未返回的 `/v1` 同步调用尽力 context 中止） | 200 + TaskDTO（`cancelled`） |
| b. 已上游受理（`upstream_job_id` 非空，`status IN ('queued','in_progress')`） | 经任务面**尽力**上游取消（`DELETE /v1/videos/{id}` 语义；图像同步形态无上游取消面，按"迟到成功"处理：产物不落库、任务 `cancelled`，计费按上游实际计量如实落账）；上游拒绝/失败**不阻塞本地收口**，本地置 `cancelled` 并停止轮询 | 200 + TaskDTO |
| c. `completed` 且 `settlement<>'settled'` | 仅停止**展示层**轮询；后台结算照常完成，任务行不变 | 200 + TaskDTO（`completed`），`message` 注明"任务已完成，取消仅停止页面轮询" |
| d. 删除项目级联取消 | P1 范围，P0 不实现 | —— |
| 终态（`failed/cancelled/expired`）或 `completed+settled` | 幂等无操作 | 200 + TaskDTO 原样 |

图像执行中取消（受理后、bytes 在途）：按 b 态迟到成功语义收口——任务 `cancelled`、产物按取消语义回收不落库、不复活任务、容量账本一致；上游已计量部分如实落账（不回滚、不虚计）。

### 4.5 内部执行链约定（/v1 复用，规范性）

1. **进程内受理**：gateway studio 路由以进程内函数链直调 `/v1` 创建面——图像 `POST /v1/images/generations`（或 `/v1/images/edits`）、TTS `POST /v1/audio/speech`、STT `POST /v1/audio/transcriptions`、视频 `POST /v1/videos`；认证语义等价 purpose=studio Key Bearer（构造 preauth 上下文），不经回环 HTTP，不新造协议面。
2. **审计头**：`/v1` 请求上下文写入 `x-juhe-ai-purpose: studio_image | studio_video | studio_audio | studio_text`（先例：`chat_context_compaction`、`chat_image_memory`）。该头是**审计来源标注，不作为授权依据**。`/v1` preauth 对该头新增校验：值以 `studio_` 为前缀时要求 Bearer Key `purpose='studio'`，且值域与请求端点族一致（`studio_image→/v1/images/*`、`studio_video→/v1/videos*`、`studio_audio→/v1/audio/*`、`studio_text→文本端点`）；不匹配返回 400 `studio_purpose_header_rejected`（防其他 Key 伪造审计来源）。缺省时行为与现状完全一致，公开面既有语义零改变。
3. **账户收敛**：工作台用户选定的 `accountId` 经进程内调度覆盖收敛派发（chat 绑定账户同款机制），不走 Key 策略路由选账户、不新增任何对外 header 或请求参数；账户删除/禁用返回明确中文错误。
4. **确定性 4xx 短路**：400/413/422 参数类错误不换账户、不重试创建（换账户无效），直接失败收口；该短路是 `/v1` 派发循环既有语义，studio 侧不重复实现、不再包一层重试。
5. **受理边界**：与 `media_jobs` 一致——上游 2xx（视频为 2xx + job id）确立前失败可经派发循环换账户；确立后永不换账户、永不重新创建上游任务，后续错误只进入任务 `error` / 同步响应错误。studio 侧不重试已受理请求。
6. **计费归属**：usage / cost 由 `/v1` 既有链落账（`api_key_id` = studio Key，账户与分组记账 scope 按派发上下文冻结）；studio 表不存计费字段、不重复计费逻辑。工作室产物入库/回收不产生计费。
7. **同用户创建串行化**：同一 `(system_account_id, kind)` 的创建调用在进程内串行执行（排队而非拒绝），作为 §5.5 恢复关联确定性的前提。

## 5. jobs 结算 worker

工作室任务的后台驱动，落 `jobs` 项目任务族（`jobregistry` 注册、GoWired，沿 `media-jobs-retention` 接线惯例）；`studio_tasks` 表 owner 为 gateway（写面经 §4 API），jobs 仅领取与结算（结算写面见本节，属既定分工，不改变表 owner）。

### 5.1 领取条件与租约

- **领取谓词（规范性）**：`(status IN ('queued','in_progress') OR settlement <> 'settled') AND (lease_owner IS NULL OR lease_expires_at <= now) AND lease_attempt_count < 5`——即决策 #9①的"status 未终态 或 结算子状态 ≠ settled"，显式覆盖"上游已 completed 但下载/入库失败、进程崩溃"中间态。
- **原子领取**：单条条件 `UPDATE` 写 `lease_owner` / `lease_expires_at` / `lease_attempt_count + 1` 后回读，抢占式（不依赖应用锁）；每轮领取 ≤ 20 行分批限流，零任务快速返回。
- **续租**：租约时长 60s；长下载（大视频产物）期间按进度续租；租约过期后其他实例可接管（崩溃恢复的基本机制）。
- 达到 `lease_attempt_count` 上限仍不能结算 → 终局 `settlement='failed'`（不再领取），任务保持 `completed` 展示态、产物缺失标注，`error_json` 记录原因；不无限重试、不虚计。

### 5.2 jobs→gateway 通信身份（**待定案项**）

候选方案：**以该用户 purpose=studio Key 经 loopback 调 `/v1` 任务面**（`GET /v1/videos/{id}` 轮询、`GET /v1/videos/{id}/content` 下载、`DELETE /v1/videos/{id}` 取消），复用任务面账户亲和直连语义（查 `media_jobs` 定位原账户原上游，不进派发循环），不新造服务身份。任务面账户已删/禁用时 `/v1` 返回"任务不可达"明确错误，jobs 据此置 `expired`。

**该候选在 P0 实施前必须定案**：现《[Go三项目架构基线](../architecture/Go三项目架构基线.md)》含"jobs 不调 gateway"的历史限定，是否新增 jobs→gateway 调用形态以基线修订结论为准（文档先行，同批同步本文与基线）；未定案前不得实现对应代码路径。无论采用何种身份，上游查询/下载/取消都必须经 `/v1` 任务面语义，jobs **不得**直连供应商或复制派发逻辑。

### 5.3 有界轮询

- 单任务轮询间隔 5s（经任务面查询上游状态）；`poll_bookmark_json` 保存续轮询接续点（如上游已返回的状态摘要），接管者从书签续跑不重复回溯。
- 上游终态经 `/v1` 任务面归一（adapter 吸收厂商差异）；任务面响应驱动 `/v1` 侧 `media_jobs` 状态与终态计费回填（既有链），studio 侧随后结算产物。
- 无独立任务级 TTL：跟随上游任务面语义——上游 `expired`，或 `media_jobs` 行被 7 天 retention 清理后任务面返回不可达，studio 任务置 `expired` + `settlement='settled'`（无产物可结算）。

### 5.4 幂等结算（三道闸）

1. **终态唯一性**：任务终态与 settlement 推进一律条件 `UPDATE ... WHERE status <> 终态`（或 `WHERE settlement='pending_settled'`），状态只允许沿 §6 状态机单向落定一次，重复回调不产生第二行第二份账。
2. **分条互斥**：原子租约领取（§5.1）+ 同一任务行 `pg_advisory_xact_lock(hashtextextended(task.id, 0))` 事务内互斥，保证并发实例/并发回调不交叉结算同一任务。
3. **digest 同用户查重**：产物入库前在**同用户范围内**查重——主键为 `(system_account_id, source_task_id)`（`idx_studio_assets_owner_source_task` 唯一约束兜底），`sha256` 为辅助定位；命中即复用既有资产行完成结算（幂等重放：崩溃于"已入库未标记 settled"窗口时，重放不再插入、不再触发任何上游调用）。**跨用户同 hash 不构成任何匹配依据**，不因同 hash 暴露或复用其他用户资产。

三道闸共同保证：重复提交、崩溃重启、并发结算下，上游创建次数、studio 资产数量、usage/成本台账记录均唯一（§10 计费唯一性验收断言）。

### 5.5 产物落库与崩溃恢复

- **产物落库**：任务面终态 `completed` → 经任务面下载产物字节 → 计算 sha256 → 写对象存储 → **单事务**内：插入 `studio_assets`（含 `source_task_id`、参数快照、宽高/时长）+ 任务 `status='completed'`（如未落）+ `settlement='settled'` + `asset_id` + 配额增量。入库失败不标 `settled`（`settlement='failed'` 可重试）；宽高/时长来源：图像解码取宽高，视频时长取 `/v1` usage 秒数换算，来源缺失保持 NULL。
- **崩溃恢复**：进程重启后，领取条件（§5.1）自动把未终态与未结算任务重新入列：
  - `upstream_job_id` 已确立 → 从 `poll_bookmark_json` 续轮询/续下载，三道闸保证不重复入库不重复计费。
  - `upstream_job_id IS NULL`（崩溃早于受理持久化）→ 先做**创建关联重扫**：按 `api_key_id`=该用户 studio Key + `kind` + `created_at >= 任务行 created_at` 在 `media_jobs` 中定位唯一关联行（§4.5.7 同用户创建串行化保证唯一）；找到即接管其 job id 继续轮询结算，**绝不重新创建**；未找到且证据表明受理未发生 → 视频任务可安全经 `/v1` 重新创建一次（受理未确立，不构成重复受理），图像任务转 `failed`（`studio_acceptance_unknown`——同步形态无受理凭据可查，为防重复计费不自动重放，由用户以新 `clientOperationId` 显式重试）。

### 5.6 孤儿资产回收

`uploading` 状态超过 24h 的 `studio_assets` 行（上传中断残留）由 jobs 任务族删除行并回收存储对象；不触碰配额账本（孤儿从未入账）。每轮 ≤100 行分批限流。

## 6. 状态机

```text
studio_tasks.status（六值词表同 media_jobs）:
  queued ──→ in_progress ──→ completed
     │             │
     │             ├──→ failed        （受理前派发穷尽 / 上游终态失败 / 受理结果未知 / 结算终局失败标注见 settlement）
     ├──→ cancelled ──┤
     └──→ expired ←──┘
  cancelled / expired 为本地终态；queued → cancelled（本地取消，不调上游）；
  in_progress → cancelled（已受理取消，尽力上游取消不阻塞本地收口；图像执行中取消按迟到成功语义）。

studio_tasks.settlement（与 status 正交）:
  pending_settled ──→ settled（产物入库完成 / 无产物可结算的失败与过期收口）
        │
        └──→ failed ──→（重新领取重试，上限内）──→ settled | 终局 failed

studio_assets:
  uploading ──→ ready ──→（删除：行 + 对象 + 配额回落，事务内）
      └──（24h 未转 ready）──→ jobs 孤儿回收删除

迟到成功（取消后上游完成）: 任务保持 cancelled，产物不落库、已落按删除语义回收；
  任务不复活、容量账本一致、计费按上游实际计量如实保留（不回滚不虚计）。
```

约束：`completed` 且 `settlement='settled'` 且 `asset_id` 悬空（资产已删）是合法展示态（前端按产物缺失渲染）；`settlement='settled'` 的 `completed` 任务 `asset_id` 必非空，除非属上句悬空情形。

## 8. 前端契约摘要

信息架构、布局、交互流、文件组织以规划 F1-F7 为准（[计划-20261012T123000000Z-媒体工作室规划建议](../plans/计划-20261012T123000000Z-媒体工作室规划建议.md) 前端设计章），本文不重复。本契约对前端的**强制点**：

1. **能力载荷驱动表单**：`GET /models` 的 `capabilities` 是表单控件的唯一声明源——未声明的键不渲染（对齐问答 `builtinWebSearch` 能力接口驱动表单先例），不硬编码参数项；`timestampCapable=false` 不提供 SRT 下载，目录价缺失成本预估显式"无法估算"。
2. **分页**：全部列表走 `useResponsivePagedList` 既有页码/增量双形态，端点 `limit/offset`；前端不实现、后端不提供任何游标。
3. **幂等与恢复**：所有创建请求携 `clientOperationId`；响应丢失（超时/断网）先 `GET /tasks?operation_id=` 确认，未受理才重发；失败终态的"重试"换新 `clientOperationId` 新建任务。
4. **keepAlive 行为**：三个工作台路由 `keepAlive: true`，必须实现 `onDeactivated` 暂停轮询与上传计时、`onActivated` 恢复并立即补一轮状态同步；轮询模块沿规划 F4（基础 5s、指数退避封顶 30s、不可见跳过不计失败、迟到响应按任务归属 ID 校验丢弃、残缺终态快照不落定）。
5. **任务与资产展示**：`assetId` 仅在 `settlement='settled'` 后返回——settled 前队列卡不得显示成品占位图；任务失败展示 `error.message`（后端已脱敏），错误提示统一 `extractApiErrorMessage` 中文兜底；`completed` 且产物悬空按"产物缺失"渲染，不报系统错误。
6. **上传**：`POST /assets` 复用 chat `uploadAsset` 模式（FormData + 进度 + `timeout: 0` + AbortSignal）；上传中可取消，取消后不产生孤立占位卡。
7. **同步端点语义**：TTS 响应返回即已入素材库（无保存开关，禁双击重复提交——同 `clientOperationId` 重放虽幂等但不得引导重复点击）；STT 基础输出为文本，SRT 仅在能力声明时出现。
8. **路由接线**：P0 三条路由进 `menuRoutes`（`menuGroup: 'studio'`），菜单三处同步惯例 + `test:api-contract` 契约比对自动生效。
