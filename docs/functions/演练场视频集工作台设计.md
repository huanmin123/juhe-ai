# 演练场视频集工作台设计

> **快速阅读**：先打开[交互原型](prototypes/视频集工作台/index.html)，直接体验工作台。
> 想先了解产品怎么用：阅读 §2「生产工作流映射」和 §7「前端交互」即可。
> 接口、数据表、任务状态和计费细节留给开发实现时阅读：重点看 §3–§6、§8–§10。

> 版本:v1.2(2026-11-22,**设计修订稿,待用户查看交互原型并裁决,未实施**)。原型见 [视频集工作台交互原型](prototypes/视频集工作台/index.html)。原型中的模型能力、素材组合、任务结果和生成进度均为交互示意,不调用上游、不发生计费,不代表当前具体型号已接通。先完成原型反馈和契约确认,再按 §8 文档同步清单回正权威文档并启动实现。
> 定位:演练场「视频生成」页的改版——以**视频集(含多个分镜)**组织已有创作资源并调用视频模型。用户在工作台之外准备角色图、场景图、道具图、台词音频等文件;工作台接收、保存于视频集、按分镜传给模型,帮助用户生成及管理小视频。最终成片由用户在线下剪辑完成。
> 用户裁决(2026-11-22,本设计依据):
> ① 视频以「视频集」为单位组织创作,一个视频集 = 生图的一张"卡片",内含多个**分镜**小视频;完整成片由用户线下用剪映/PR/AE 合成,平台不做拼接。
> ② **资源生成不是工作台职责**:用户用其他工具准备角色图/场景图/道具图/台词音频等资源,再按需上传;资源可完全缺省,工作台接受提示词单独生成视频。
> ③ **音画分离、音频先行**:台词录音或合成由用户控制。修改给线下剪辑使用的音轨不要求重生成画面;需要模型生成画面中的口型时,仅在具体模型和输入组合经验证后把用户音频作为模型参考,或由用户线下处理。不给口型和音色还原度作未验证承诺。
> ④ 单个分镜建议控制在 **15s** 左右(过长易漂移),**硬上限 30s**。
> ⑤ 视频产物**只在本地保留链接,不保留视频文件**。链接有效期由具体上游返回；没有可信期限时只提示用户及时下载，不显示编造的倒计时。
> ⑥ 参考素材(角色/场景/道具/音轨)作用域为**视频集内**素材库;分镜间「尾帧续接」纳入首发设计,只有具体型号和媒体任务链已打通并验证后才开放。
> ⑦ 设计修订稿和交互原型先供用户查看;产品契约以用户对原型的反馈为准,用户确认前不实施。

**阅读口径**:§1 描述当前代码事实;§2–§10 描述**目标行为**,属于待确认、未实施契约。上游厂商能力、仓内已实现能力与本工作台目标能力分别标明,厂商文档有某参数不代表本项目已接通。

## 1. 背景与定位

### 1.1 现状:视频页与图片页的代差(取证)

演练场图片生成页(《演练场设计》§3.4/§4.2,v1.2~v1.5)已是完整的异步任务工作台:`playground_image_jobs` 落库状态机 + 进程内执行器 + 3s 轮询引擎 + 生成历史卡片网格 + 筛选/游标分页 + 手动删除 + 7 天保留期管理。视频生成页仍为 v1.0 交互口径的三端点薄代理(`POST /videos` / `GET /videos/{jobId}` / `GET /videos/{jobId}/content`,《演练场设计》§3.5),差距:

| 维度 | 图片生成(目标范式) | 视频生成(现状) |
| --- | --- | --- |
| 任务持久化 | `playground_image_jobs` 行,按现行保留策略管理 | 无视频集/分镜表;旧页只有单条覆盖式 `video_task` 引用,不形成可检索历史 |
| 历史列表 | 分页 + 四维筛选卡片网格 | 无(仅最近 1 条恢复) |
| 参数表单 | 词表化块状选择器 | size 自由文本 + seconds 裸数字 |
| 参考/首帧 | 参考图上传 UI + 缩略墙 | `inputImageBase64` 有字段无 UI |
| 轮询恢复 | 服务端状态,刷新即恢复续轮 | 前端持有 jobId,60 分钟窗口 |
| 删除/取消 | DELETE 端点 + popconfirm | 无入口 |
| 链接与保留 | 本地记录按现行保留策略管理 | 只保存上游定位信息,链接期限按具体模型回传或标为未知 |
| 多镜创作 | — | 不支持(单任务视图) |

### 1.2 执行层零改动复用(取证)

`/v1/video/generations` 当前提供创建、轮询、content 和取消形态,经 `juhe_business.media_jobs` 落库、账户亲和直连轮询、零视频文件落盘、按媒体任务保留策略清理和统一终态计费。七家视频 adapter 注册:OpenAI、Gemini、GLM、MiniMax、Volcengine、Qwen、xAI。此事实证明工作台可复用公共链的部分能力,不证明本工作台要求的多图、多音频、逐型号参数、尾帧等已接通。

演练场已有 Bearer 直驱通道,以会话 ViewerID 读取并复核所选 Key,再由进程内 `chatGatewayExecutor` 调 `/v1`。视频集工作台可以复用它完成创建、轮询、取消和视频内容代理。Key 权限、限流、计费与 `usage_records` 沿用真实 `/v1` 行为。**这是目标复用边界,不是媒体链零改动**:素材角色、多型号能力、声音、请求预算、尝试版本和尾帧字段都需按后续契约修改媒体 adapter/任务 IR/响应和 mock,并回归真实兼容消费者。

### 1.3 工作台定位与非目标

**定位**:面向短剧/短片的轻量视频生成工作台。最小生成单元是**画面提示词**:用户选好 Key 和模型后仅输入提示词即可生成一个分镜;已有资源时,再按本次生成意图选首帧、参考图或参考音频。工作台生成短视频并保存分镜记录,视频文件由上游托管,本地只保留任务定位信息和链接有效期事实。

**非目标**(明确不做,降低难度):

1. 不做剧本解析/AI 拆分分镜(剧本纯记录);不在本工作台生成角色图、场景图、道具图或台词音频,不做 TTS、音色克隆、素材编辑等专业资源生产。用户可从其他工具导出并按需上传现成文件;演练场「语音合成」页可作为一种外部于本工作台的音频准备途径(《演练场设计》§3.6);
2. 不做 BGM/音乐生成、不做视频拼接器/导出/时间线、不做 zip 打包下载(逐条下载);
3. 不做全局素材库(素材为视频集内作用域)、不做跨用户共享/公开分享;
4. 不做后台主动轮询推进(沿用「客户端 GET 轮询驱动」既有裁决,`media-jobs-retention` 之外的媒体任务无后台轮询);
5. 不改计费公式(§9)。不把 catalog 有模型行、厂商支持某参数或 adapter 注册等同于工作台该型号已可生成;只有本项目当前端到端适配与模型状态已核实的型号方能出现在可用候选。缺少证据的型号保留在目录,本工作台提示暂不可用。

## 2. 生产工作流映射

目标流程是提示词优先、素材可选,用户可以从首镜开始也可以从完整视频集开始:

| 流程阶段 | 工作台落点 |
| --- | --- |
| ① 开始生成 | 首屏先写提示词,显示当前 Key 和可用型号;其余资源、剧本和视频集名称不构成生成前置条件。首次提交时自动建集并追加第一镜,给默认集名,用户稍后可改;已有视频集时可先进入视频集再追加分镜 |
| ② 视频集与剧本 | 自动命名视频集,用户可在详情改名/补定位简介/粘贴剧本;剧本纯记录,不会自动分析或参与模型调用 |
| ③ 可选素材 | 用户可在单镜直接上传或从集内素材库选择角色图/场景图/道具图及音频;分类和台词文本帮助管理,不要求先建资产库 |
| ④ 分镜 | 每镜 = 必填画面描述 prompt + 可选文字备注/台词 + 本次明确参与生成的可选素材 + 当前型号合法参数;单镜建议 ≤15s,硬上限 30s |
| ⑤ 音频 | 音频可保存作线下剪辑,也可显式指定本次作为模型参考(仅在该型号/输入模式可用时);两种作用分开。改线下音轨不重生成画面 |
| ⑥ 生成 | 每镜一次 `/v1/video/generations` 真实调用:仅 prompt、prompt+首帧、prompt+参考素材或已验证组合之一。原型示范设置为 5 秒、16:9、720p、静默;实际可选值和默认值必须以 exact model capability contract 返回为准 |
| ⑦ 剪辑合成(线下) | 逐镜下载视频 + 逐条下载台词音频,线下剪映/PR/AE 合成;上游给出期限时按期限下载,无法确认时只提示尽快下载 |

**对白镜头的处理**:用户确实要求画面角色说出台词时,可在已验证支持的型号与输入模式中显式选「参考这段声音」;这只是向模型提供输入,不承诺 100% 声纹一致或口型成功。模型不支持或组合不合法时,该文件仍能留作剪辑音轨,界面可建议用户用专业工具线下处理。不把“集内有音频”默认解释为“传给模型”,也不把音频条目自动变成对白镜头。

输出声音与输入声音参考彼此独立。模型支持但组合未验证时,先不显示音频参考入口。原生有声且不可关闭的模型要在型号选择前注明;有声模型不等价于使用用户提供的录音。

### 2.1 从空白到下载的例子

用户打开工作台,选择一个自己有权限使用的视频 Key 和该 Key 下显示为可用的 Seedance 准确型号,在画面提示词输入「雨夜的老街,红色雨伞从画面左侧走向远处」,不添加素材,提交「生成分镜」。服务端先保存视频集、分镜草稿和一次生成尝试,然后经现有 Bearer 直驱链发送纯提示词请求。受理后页面显示该尝试的排队/运行状态;用户刷新页面,仍能在该视频集看到同一分镜和同一尝试,不会因刷新再扣一次。

第二个镜头,用户把角色图和街景图上传到同一视频集素材库,在提示词中键入 `@`,从候选菜单选择「林舟 · 角色图」,再输入「穿过雨幕,回头看向镜头」。编辑器里这是一枚带素材名称的引用标记,内部绑定该图片的 `assetId`;它不靠显示名称、上传顺序或 `@Image1` 序号识别。用户另选「街景 · 场景图」并插入后,本次提交预览列出两份参考图和将发送的顺序。若当前型号实际只验证一张参考图,提交被阻止并指出哪项超限,用户移除一项或换到支持该组合的型号后才能继续。

如果素材被删除、当前镜头不再有引用权限或切换型号导致组合不支持,引用显示为待修复。用户可重新绑定到一项明确选中的素材、删掉引用或把它转换为普通文字;同名素材不会被自动替换。任何仍有可读输入快照的历史尝试都可以作为「再生成一版」的回填来源,包括失败和内容已失效的版本;未知受理版本需先明确提示可能重复计费并由用户确认新 request ID。播放、下载和取尾帧仍分别要求结果内容及派生 artifact 可用。重做前展示原版本模型和输入,用户确认后才回填草稿;新的生成快照不会随草稿后续编辑而改变。下载按内容接口的明确结果区分视频过期、Key 鉴权问题和网络故障。

## 3. 实体模型与存储

四张业务表进 `juhe_business`(DDL 权威 `maintenance/internal/schema/pg_schema_business_tables.go`,实施时 schema revision 递增;id 形态沿用图片任务 `{unixNano}-{8字节hex}`),另有一张小型 `playground_video_request_dedup` 幂等登记表。登记表只存 viewer、request ID、请求哈希、原目标 ID、generation ID 和生命周期标记,不存 prompt、素材或内容。登记保留 request ID 的唯一性,不因视频集/分镜级联删除而丢失。

### 3.1 `playground_video_sets`(视频集)

| 列 | 说明 |
| --- | --- |
| `system_account_id` | ViewerID 隔离键(主键之一,与图片任务同构) |
| `id` | 集 id |
| `name` | 必填,≤100 字符 |
| `brief` | 定位/简介,可选 ≤200 字符 |
| `script` | 剧本全文,可选 ≤50,000 字符,纯记录随时可改 |
| `created_at` / `updated_at` | UnixMilli |

无状态列:集合级状态为派生口径(分镜状态汇总),卡片按汇总渲染。

### 3.2 `playground_video_assets`(集内素材库)

| 列 | 说明 |
| --- | --- |
| `system_account_id` / `id` / `set_id` | 隔离键 + 归属集 |
| `category` | CHECK:`image`/`audio`;人物、场景、道具作为用户可编辑标签,不会把模型输入用途隐含绑定到分类 |
| `label` | 名称或台词文本;音频资产 label 填台词原文(构成台词表) |
| `character_asset_id` | audio 资产可挂到同集内标记 `character` 的一张 image,用于声音表归组;可空。角色是 image tag,不是另一种文件 category |
| `mime_type` | 图片 PNG/JPEG/WEBP,文件 ≤10 MiB;音频 WAV/MP3,文件 ≤8 MiB |
| `data` | bytea(存储形态沿用 2026-11-09 PG bytea 裁决) |
| `duration_ms` / `byte_size` / `checksum` | 上传时解析;图片时长为 0;checksum 用于上传校验和同一操作重试,不借此跨用户去重 |
| `created_at` | UnixMilli |

生命周期:随集持久;手动删除单条。当前分镜草稿或 `submitting/submission_unknown/queued/running` generation 仍引用某素材时,删除返回 409 并给出引用摘要。终态 generation 不阻断删除;其不可变 snapshot 保留素材 ID、名称、用途、checksum 和删除状态,历史请求仍可审计。用户先解除或替换草稿引用后可删除素材;已删除素材的旧版本仍显示快照,但不可再取文件,重生成前必须重新选择可用素材。删除视频集时,若有 `submitting/submission_unknown/queued/running` generation 返回 409。用户可对 `submission_unknown` 选择「放弃本地跟踪」并确认上游可能已受理/计费,将 generation 标为 `abandoned` 后再删集;本地放弃不取消上游任务、不撤销或掩盖任何计费记录。删集事务级联删分镜/生成记录/素材字节/尾帧。上传仅验证文件格式、字节数及音频解析结果,不因当前模型缺少某能力而阻止保存;提交生成时才依照本次选择校验素材用途、数量、音频时长和请求预算(§4、§5)。

### 3.3 `playground_video_shots`(分镜草稿/创作单元)

| 列 | 说明 |
| --- | --- |
| `system_account_id` / `id` / `set_id` | 隔离键 + 归属集 |
| `sort_index` | 集内顺序(整数,上移/下移重排);不用于隐式确定已有尾帧来源 |
| `prompt` | 画面描述,必填 ≤4000 字符(与图片页同限) |
| `prompt_parts` | 有序编辑表示,元素仅为 `{type:"text", text:"..."}` 或 `{type:"asset", assetId:"..."}`。素材引用绑定同集图片的稳定 ID,不存显示序号。空白编辑器提交可规范化为一个 text part。手打的 `@xxx` 是普通文字;只有从候选菜单明确选择素材才成为 asset part |
| `dialogue` | 台词文本,可选 ≤2000 字符(台词表记录;与音频资产 label 独立) |
| `draft_params` | 最近保存的编辑态设置,含模式/合法用户选项/Key/精确模型 id;不作为已提交生成的审计快照 |
| `latest_generation_id` | 最新一次尝试记录;保留历史尝试 |
| `created_at` / `updated_at` | UnixMilli |

### 3.4 `playground_video_generations`(一次具体生成尝试)

| 列 | 说明 |
| --- | --- |
| `system_account_id` / `id` / `set_id` / `shot_id` | ViewerID 隔离键、主键与来源分镜 |
| `attempt_no` | 分镜内单调递增的版本序号;用户点「再生成一版」增加序号 |
| `request_id` / `request_hash` | 客户端单次操作 UUID 与原始意图规范化哈希;唯一约束 `(system_account_id, request_id)`。哈希包含目标 set/shot、prompt parts、Key/model、参数、各素材 ID/用途、`replayFromGenerationId` 与 `inputs.firstFrame.sourceGenerationId`。相同 ID、相同目标和哈希重放同一个资源;相同 ID 对应不同目标或输入返回 409 `playground_idempotency_conflict`,不派发 |
| `request_snapshot_json` | 服务端校验并接受后的不可变输入快照:原始 prompt parts、编译后的纯文本 prompt/上游引用映射、用户选择型号与实际出站型号、Key id、合法参数、输入模式、显式参与本次生成的资产 ID、名称、用途和文件 checksum、重做来源 `replayFromGenerationId`、尾帧首帧来源 `inputs.firstFrame.sourceGenerationId`、API/adapter contract version |
| `status` | `submitting`/`submission_unknown`/`queued`/`running`/`completed`/`failed`/`cancelled`/`abandoned`;`expired` 为 completed 产物链接的派生态。`abandoned` 只表示本地放弃跟踪,不表示上游取消 |
| `last_known_status` / `tracking_state` / `tracking_error` | 最近一次有证据的任务状态与本地追踪可用性(`available`/`temporarily_unavailable`/`unavailable`);追踪失败不覆盖 generation 状态。用于区分仍在运行但不可查询与已完成但内容链接过期 |
| `api_key_id` / `selected_model_id` / `dispatched_model_id` / `provider_code` | 创建时所选身份、用户选择的目录型号和实际出站准确型号分别保存;路由可能按账户配置 canonical/upstream model 重写,因此首次写出前须按实际出站型号重新校验 capability。轮询/内容请求恒使用此 Key,不跟随页面后续切换 |
| `media_job_id` | `/v1` 接受后回填的任务 id;一尝试最多关联一个 media job |
| `progress` / `error_message` | 进度仅展示即时查询值;失败存用户可理解摘要和可追溯错误分类,密钥/SQL 等内部细节不返回 |
| `usage` / `cost_usd` | `/v1` 终态结算镜像;平台账单权威仍为 `usage_records` |
| `completed_at` / `link_expires_at` | 完成时间与可信的上游链接有效时间;仅有粗略估计时另存 `estimated` 来源,未知时为空,不得把固定时长写成各模型共同期限 |
| `last_frame_artifact_id` | 媒体响应链确实返回并下载成功的尾帧;与尝试版本绑定 |
| `created_at` / `updated_at` | UnixMilli |

同一分镜的旧版本在新版本生成后仍保留输入快照和结果状态;内容只有在原 Key 仍可用且上游链接仍可访问时才能播放/下载。终态版本只保留素材引用快照,不依赖素材字节;用户解除草稿引用后可删除素材,删除后历史版本仍可审计,但不能用已删除文件重建请求。用户删除分镜或视频集时同时删除业务记录与尾帧,但不影响 `/v1` 已生成的计费事实。

### 3.5 状态机与保留策略

```
draft --submit--> submitting --> queued --> running --> completed / failed / cancelled
                      |            |          |
                      +--> submission_unknown
queued / running --provider cancellation confirmed--> cancelled
submission_unknown / queued / running --user-confirmed abandon--> abandoned
```

- 状态推进由客户端轮询工作台 generation 端点驱动;只有记录里有 `media_job_id` 时,服务端才可用创建时 Key 查询 `/v1/video/generations/{jobId}`。generation 状态与追踪可用性分开保存,并发响应按 DB 当前版本条件更新,终态不可回退。媒体任务 retention 会清理到期行,轮询端点返回 404 也可能是权限隔离或任务行不存在,因此不能据此猜测任务失败或视频过期。未知的上游状态保留上一次已知状态,记录可见的追踪问题并允许手动重查;不得折算为 `failed`。
- 每次提交先以事务写入 `submitting` generation,`/start` 的 set、shot、generation 在同一 DB 事务建立。唯一 request ID 的插入/校验确定唯一派发者;相同 request ID 重放同一目标和哈希时返回已存在记录,不重复调用媒体接口;同 ID 不同意图返回 409。远程媒体调用不能与本地事务原子提交。提交前前端按当前 Viewer 在 IndexedDB 暂存 24 小时有效的“原始意图恢复记录”（原始 `requestId`、目标端点/`setId`、精确请求意图中的 prompt parts、参数、素材 ID 和续接来源）,不保存素材字节或 API Key secret；收到统一受理回执或当前 Viewer 登出时立即清除。页面刷新、关闭后重开或回包丢失时,按原目标端点用同一 `requestId` 和原始意图重放,由幂等记录恢复同一 `{setId, shotId, generationId, status}` 回执,绝不生成第二次任务。编辑请求意图后必须创建新 `requestId`,不复用旧幂等键。24 小时后恢复记录自动过期,但服务端 tombstone 仍阻止该 ID 被当成新操作重用。进程重启发现遗留 `submitting` 时,若没有持久化任务 ID 或明确的未发送/未受理证据,收敛为 `submission_unknown` 并保留草稿,不再次派发。
- `playground_video_request_dedup` 记录在目标被删除时转为 tombstone,不会级联删除;相同 request ID 后续重放返回 410 `playground_idempotency_target_deleted`,绝不重建集/分镜或再次派发。tombstone 保留最小 ID/哈希/原目标关系,不提供原资源内容读取。前端在结果未知时可在 24 小时请求重放窗口内用原 request ID 查到原状态;窗口过期后只能明确创建新请求并确认可能重复计费,原 ID 永久不得作为新操作自动重用。
- 上游调用已发出后发生断连、含糊的 5xx 或在任务 ID 持久化前进程退出时,进入 `submission_unknown`,不自动重发。任何 `/v1` 内部账户切换/故障转移都必须对付费创建保持可证明的单派发语义:只有确定请求尚未写出或上游明确拒绝受理时才允许转下一个候选;写出后断连、含糊 5xx 不得切号重派,除非多个候选共享并实际使用同一可靠幂等作用域。定向验收需包含首个 mock 候选已接单后断连、第二候选收到 0 次 POST。用户在未知态明确选择再次提交时,需新 request ID 并看到可能重复受理和计费的确认。
- 确认未受理的 4xx/限流或其他同步失败收敛为 `failed` 并显示可操作原因。Key 不可用、参数非法和素材冲突保留草稿且不得改成新型号静默重试。
- **视频零落盘**:仅保存 generation 的 `media_job_id` 和链接期限元数据;播放/下载走会话鉴权 content 代理,不长期缓存视频字节。只有工作台内容代理收到可核验的 `410 media_artifact_expired`（或上游提供并校验的明确过期元数据）时才标记产物链接过期。`GET /v1/video/generations/{jobId}` 的 404/410、网络/代理/Key 鉴权失败分别显示为追踪不可用或真实请求错误,不能推断视频过期。若上游不给有效期限,显示「有效期以平台为准,建议尽快下载」,不编造确切倒计时。媒体任务记录被 retention 清理后,工作台保留其最近已知状态,说明无法继续追踪,允许手动重查和明确放弃。
- 尾帧小图是已限定的资源例外:仅为续接由工作台保存在 `playground_artifacts`,对应每个 generation,并对大小/MIME/HTTP SSRF 做限制。尾帧被 artifact retention 策略清理后隐藏续接入口,用户仍可选择其他首帧或新建 generation。
- 资产按视频集持久;尾帧来源 generation 只能属于同一 Viewer、同一视频集,跨集引用统一按 404 处理,不泄露外部对象。删除视频集只要求不存在 `submitting/submission_unknown/queued/running` generation；满足条件后在同一事务内级联删除该集的分镜、历史 generation、素材和尾帧 artifact,不因同集草稿或已完成 generation 的尾帧依赖阻断。删除被同集其他镜头的草稿或在途/未知 generation 引用的 generation 尾帧时,返回 409 `playground_generation_in_use` 并给出依赖镜头,需先解除或替换引用；终态历史依赖不阻断整集级联。正在等待创建响应的 `submitting` 尚可能被上游受理,必须等待调用明确结束或转入 `submission_unknown`,不能直接放弃或删除。删除分镜不隐式取消媒体任务,有在途尝试时返回 409,由用户先通过 generation 级取消或本地放弃动作收敛。放弃不调用上游、不表示上游停止,其是否受理和是否计费仍以媒体链及 `usage_records` 为准。

## 4. API 契约

### 4.1 演练场会话端点(全部 `RequireSession(true)`)

表中路径都相对于前缀 `/__aisys__/api/playground/videos`。例如 `GET /generations/{id}/content` 的完整路径是 `/__aisys__/api/playground/videos/generations/{id}/content`。素材 URL 使用该前缀;尾帧 artifact URL 使用现有 `/__aisys__/api/playground/artifacts/{id}/content` 域。接口需要校验 ViewerID 与每个 set/shot/generation/asset 的归属。

| 端点 | 说明 |
| --- | --- |
| `POST /sets` | 显式建集 `{name?, brief?, script?}` → `{setId}`。省略 `name` 时服务端写入可编辑默认名,保证存储字段非空。用户先上传素材时,界面先调用本端点建立空集再上传,不创建临时全局资产区 |
| `POST /start` | 首次生成 `{requestId, setId?, promptParts, apiKeyId, modelId, params, inputs}` → 统一受理回执 `{setId, shotId, generationId, status}`。省略 `setId` 只允许在没有集内素材或尾帧续接时由服务端在同一事务创建默认命名集、分镜草稿和 generation；带 `setId` 时校验该集后追加分镜。只要请求引用集内素材或 `inputs.firstFrame.source=generation_last_frame`,客户端必须传 `setId`,服务端不得根据排序猜测所属集。提交幂等规则见 §3.4、§3.5 |
| `GET /sets` | 列表 `keyword?/status?(派生态:任意分镜在途/全部完成)/limit?/before?` → `{sets:[卡片],nextCursor?}`(卡片含分镜状态汇总计数) |
| `GET /sets/{id}` | 详情:集字段 + 素材库全量(按 category 分组) + 分镜全量(按 sort_index 排序);返回草稿 `promptParts` 与 generation 快照摘要 |
| `PATCH /sets/{id}` | 改名/简介/剧本 |
| `DELETE /sets/{id}` | 若有 `submitting/submission_unknown/queued/running` generation 返回 409 `playground_set_not_deletable`;无在途/未知任务时在同一事务内级联删除该集的分镜、generation、素材和尾帧 artifact,不因同集草稿或终态尾帧依赖阻断。尾帧不存在跨集引用；越权/外部来源按 404 |
| `POST /sets/{id}/assets` | `multipart/form-data` 上传 `file` 及标签字段,不把整个文件 Base64 后塞进普通会话 JSON。图片 ≤10 MiB,音频 ≤8 MiB;路由请求体限制须显式覆盖当前默认 256 KiB,并有 multipart 开销余量。校验真实 MIME、字节数、checksum 和音频时长;→ `{id, assetUrl, durationMs?, byteSize, checksum}` |
| `DELETE /sets/{id}/assets/{assetId}` | 若被当前草稿或 `submitting/submission_unknown/queued/running` generation 引用则 409 `playground_asset_in_use` 并返回引用摘要;终态 generation 只保留快照,不阻断删除。解除活动引用后删除,历史版本显示素材已不存在 |
| `GET /sets/{id}/assets/{assetId}/content` | 素材取流(图/音频;校验同一集归属,默认用于预览/试听,`?download=1` 时设置逐条下载的 `Content-Disposition` 与原始安全文件名;不打包、不拼接) |
| `POST /sets/{id}/shots` | 建分镜草稿。需要有效画面提示词;纯提示词可不含素材。首次生成路径使用 `/start` 原子建集、建镜和 generation |
| `PATCH /shots/{id}` | 编辑分镜草稿、排序和本次生成默认设置。已有 generation 的分镜仍允许改草稿,不改历史 request snapshot |
| `POST /shots/{id}/generate` | `{requestId, promptParts, apiKeyId, modelId, params, inputs, replayFromGenerationId?}` → 统一受理回执 `{setId, shotId, generationId, status}`。草稿已生成也可再生成一版,每次使用不可变 snapshot;失败后按明确原因修复再提交。`replayFromGenerationId` 仅记录用户选中的历史输入快照来源,服务端校验与目标属于同一 Viewer、同一 shot 且快照完整;它不替代 `inputs.firstFrame.sourceGenerationId`,后者专指尾帧续接来源 generation,并须与目标属于同一 Viewer、同一视频集 |
| `GET /shots/{id}` | 返回分镜草稿、generation 列表和每个 generation 的即时状态;前端按在途 generation 轮询 |
| `GET /generations/{id}` | 查询/推进指定 generation 状态。只有存在 `media_job_id` 且创建时 Key 鉴权成功时才查询上游;没有任务 id 时返回本地状态和追踪可用性,Key 鉴权失败、媒体 404、未知状态均不改写为失败/过期,不换用当前 Key、不重建请求 |
| `GET /generations/{id}/input-snapshot` | 返回该 generation 的完整、脱敏、不可变输入快照,供「再生成一版」回填。包含 `promptParts`、`dialogue`、`modelId`、`dispatchedModelId`、`apiKeyId`、`params`、`inputs`、`replayFromGenerationId` 及素材的名称/用途/checksum/删除状态;尾帧来源保留在 `inputs.firstFrame.sourceGenerationId`。不返回 API Key secret、素材字节或可复用的原 `requestId`。即使素材已删除或型号已下线也返回原快照,同时给出 `replayIssues` 供界面逐项修复 |
| `POST /generations/{id}/cancel` | 请求取消指定尝试。服务端只在 exact-model contract 声明可取消时调用媒体取消端点;响应区分 `confirmed`、`not_supported`、`not_confirmed`。仅可核验的上游取消确认或后续任务查询明确返回取消状态时转 `cancelled`;公共 DELETE 的 HTTP 204 本身不等于上游确认 |
| `POST /generations/{id}/abandon` | 对 `submission_unknown` 或在途 generation 执行明确确认的本地放弃。`submitting` 创建调用尚未结束时不可放弃。不依赖原 Key、不调用上游;只把本地状态收敛为 `abandoned`,不撤销、不确认也不改变上游任务和 `usage_records` 计费事实 |
| `GET /generations/{id}/content` | 仅 completed 且有 `media_job_id` 的尝试可播放/下载;按创建时 Key 代理并完整传输,下载用 `?download=1`。源 Key 失效等错误按原类别返回;不能把 tracking 404 或任意 410 当视频过期 |
| `DELETE /shots/{id}` | 只有无活动 generation 且没有被同一集其他镜头草稿或在途/未知 generation 引用的尾帧依赖时可删除。存在 `submitting/submission_unknown/queued/running` 或活动尾帧依赖返回 409,不会隐式取消/放弃;generation 快照和尾帧级联删除,不删除或改写 `/v1` 的 `usage_records` |

`POST /start` 与 `POST /shots/{id}/generate` 使用同一受理回执形状 `{setId, shotId, generationId, status}`;不要让首镜和重做走两套返回协议。客户端在收到回执前保留 IndexedDB 恢复记录,回包丢失时按原目标端点重放同一 `requestId` 和原始意图,收到回执后清除记录。服务端以 Viewer 隔离的幂等表决定是否已受理,重放只返回原 generation,不再次派发。

错误信封沿用演练场扁平 `{message, code}`。首发至少固定 `playground_invalid_request`、`playground_set_not_found`、`playground_shot_not_found`、`playground_generation_not_found`、`playground_generation_in_use`、`playground_asset_not_found`、`playground_asset_in_use`、`playground_set_not_deletable`、`playground_shot_not_deletable`、`playground_generation_abandon_invalid`、`playground_idempotency_conflict`、`playground_key_not_found`、`playground_model_not_available`、`playground_model_capability_conflict`、`playground_payload_too_large`、`playground_submission_unknown`、`playground_busy`、`playground_dispatch_failed`、`playground_tracking_unavailable`、`playground_artifact_expired`。越权与不存在统一 404,不泄露存在性;生成前的素材冲突、能力不支持和请求体预算错误均为 400;幂等 ID 携不同请求和活动依赖冲突返回 409。abandon 只收敛本地状态,不得伪造取消或计费结算。

### 4.2 播放与下载(content 流式代理)

`GET /generations/{generationId}/content`:仅 completed 且存在 `media_job_id` 的 generation 可取内容,以 snapshot 中的 `api_key_id` 经 Bearer 直驱 `GET /v1/video/generations/{media_job_id}/content`。`download=1` 设置下载 disposition。原 Key 已删除/停用时返回真实鉴权错误,绝不换用当前页面 Key;`abandoned` 或无 `media_job_id` 时不请求上游。只有响应码 410 且机器错误码明确为 `media_artifact_expired` 时才返回 410 `playground_artifact_expired`;上游 404 可能表示权限隔离或任务行不存在,须返回追踪/访问错误,不得标记内容过期。其他代理错误、上游 5xx 和传输失败保留来源类别。

内容代理必须完整交付内容或显式失败,不能把限制读取的前 N 字节作为完整视频返回。旧演练场代理的 64 MiB 读取限制是当前实现细节,不是视频输出上限;新接口默认允许大于 64 MiB 的合法结果完整流转。若存在明确的真实内容限制,且响应前已知 `Content-Length` 超限,须在发送 body 前返回明确错误。传输中断或超出真实上限时立即中止响应并记录原始错误,不得以成功完成的 200/正常 EOF 收尾。上游 `/v1`、`chatGatewayExecutor.Dispatch` 的 `io.Pipe` 与工作台代理都要保留 HTTP 状态、媒体错误码、Content-Length、已传字节数和中断原因。`media_artifact_expired` 只有在来源明确表示内容已过期且不存在可用视频时才转换为工作台 `expired`;本地任务行缺失、权限隔离、没有 URL 或 chunked 断流不能单独触发过期状态。保留上游可核验的内容长度、类型和文件名元数据;不自行拼接/补齐截断视频。验收覆盖大于 64 MiB、半途断流、声明长度与实际字节数不符,并确认下载文件完整或传输明确失败。

### 4.3 `/v1/video/generations` 公共词扩展(需同步媒体契约)

现行 `ParseVideoParams` 的 `image`/`images`/`input_reference` 同义化且最多接收一张图。不能在工作台把 `images[0]` 默认为首帧,因为用户需要表达“仅参考图”和“独立首帧 + 参考图”。目标公共输入先规范化为明确的 `input_mode` 与有序素材 parts,保留旧单图请求的兼容语义。以下 JSON 是字段形状示例,`input_mode` 使用一个确定值,不是枚举占位字符串:

```json
{
  "model": "doubao-seedance-2-5-260628",
  "prompt": "画面描述",
  "input_mode": "first_frame_and_reference",
  "input_images": [
    {"role": "first_frame", "url": "https://media.example/first.png"},
    {"role": "reference_image", "url": "https://media.example/character.png"}
  ],
  "input_audios": [{"role": "reference_audio", "url": "..."}],
  "duration": 5,
  "size": "1280x720",
  "audio": false,
  "return_last_frame": false
}
```

`input_mode`、part role、数量、音频总时长、媒体类型、模型与请求总字节由同一份 model-specific capability contract 校验。缺少对应 adapter 语义时不得把新字段塞进 `metadata` 白名单,不得静默忽略,不得把参考图改成首帧。旧客户端只传 `image` 或 `input_reference` 时保持“单张输入图”兼容语义,等价于一个未标 role 的单输入图片;旧 `images` 单元素也保持该语义。旧单图字段与新 `input_images`/parts 同时出现时明确 400 拒绝,不猜测哪个优先。新工作台请求必须使用显式角色。

`promptParts` 是工作台编辑/提交结构,并非直接复制到现有 `/v1` 的 JSON 字段。前端用候选菜单插入带 `assetId` 的引用片段;后端按同集归属、checksum 和当前输入用途重新校验后,把它编译为 adapter 可用的有序纯文本 prompt 与输入素材列表。首帧由 `input_images` 中唯一 `first_frame` part 表达;角色/场景等参考图由 `reference_image` 表达。尾帧续接表示“来源 generation 的尾帧作为本镜首帧”,即经验证后解析成 `first_frame`,不能和本次生成请求的 `return_last_frame` 混为一谈。后者表示要求本次任务返回尾帧图,是独立输出能力。

当前 provider adapter 映射(用于说明代码事实,不是 exact model capability contract):

| Provider adapter | 当前统一输入/参数映射 | 当前声音/素材边界 | 新工作台规则 |
| --- | --- | --- | --- |
| `volcengine` | prompt + 至多一个 `input_reference` 写入 `content`;映射 duration、size 与 seed | 不接收独立多图角色、文件音频参考或输出音频开关;当前响应链没有尾帧字段 | 首发只开放逐型号已验证的提示词/单图功能;其余字段实现并回归前不显示 |
| `qwen` | prompt + 至多一个 `input_reference` 写入 `input.img_url`;参数写入 `parameters` | 当前没有文件音频参考映射 | 精确型号不得从 family 前缀继承图像、声音或时长能力 |
| `glm` | 单图 `input_reference` 映射 `image_url`;seconds 转为已实现时长档;audio 映射 `with_audio` | 单张图片和输出声音开关是 adapter 级映射,不是各目录型号均已验证 | exact model contract 验证前不承诺素材与声音组合 |
| `minimax` | 单个 `input_reference` 转为 Base64 `first_frame_image`;seconds 映射 duration | 无多图、文件音频参考或声音开关映射 | 仅给通过 exact model 回归的单图/提示词候选开放对应输入 |
| `gemini` / Veo | 单图 Base64 输入;分辨率/画幅参数及型号默认时长由 adapter 处理 | 无统一声音开关、文件音频参考或尾帧输出映射 | 不因 Veo 系列名添加其他 model id 未验证的控制项 |
| `openai` / Sora | 单个 `input_reference` 与 prompt/seconds/size 映射 | 无声音开关或文件音频参考映射 | 只显示 exact model contract 返回的已验证值 |
| `xai` | 单图 `image`、duration/size 与 audio→`generate_audio` 映射 | 输出声音开关是 adapter 级映射;无文件音频资产映射 | 新工作台不把 provider 级开关当作每个 xAI model id 都已验证 |

上述为适配器代码映射,输入模式与模型档位仍须逐型号验证。新能力必须在公共规范化输入、provider adapter、媒体任务 IR、创建/轮询响应和 mock 上游中完整接通。尤其尾帧不能只声明 `metadata.last_frame_url`:媒体 IR、`/v1` 轮询响应、工作台 generation 表和 SSRF 下载链都要有字段及测试。请求体预算按实际网关 body limit 与 Base64 编码后字节数执行预检,不使用其他厂商文档的大小限制替代本地限制。

### 4.4 分镜创建/编辑请求

```json
{
  "setId": "set-existing-3",
  "promptParts": [
    {"type": "text", "text": "林舟穿过雨幕,"},
    {"type": "asset", "assetId": "asset-character-17"},
    {"type": "text", "text": "回头看向镜头。"}
  ],
  "dialogue": "台词文本(可选)",
  "apiKeyId": "key-user-selected",
  "modelId": "model-id-returned-for-key",
  "requestId": "4fbf7a0b-50c6-4274-aece-edb7aeeb188c",
  "params": {"inputMode": "first_frame_and_reference", "aspectRatio": "16:9", "resolution": "720p", "duration": 5, "audio": false, "returnLastFrame": true},
  "inputs": {
    "firstFrame": {"source": "generation_last_frame", "sourceGenerationId": "gen-previous-9"},
    "referenceAssetIds": ["asset-character-17", "asset-street-08"],
    "referenceAudioAssetIds": [],
    "offlineAudioAssetIds": []
  }
}
```

上例两段文本和一个素材引用会保留编辑顺序；`asset-street-08` 是用户在参考素材区显式选择、但没有插入提示词的图片，仍会按 `referenceAssetIds` 的顺序发送。`firstFrame.source` 固定引用同 Viewer、同视频集内某一次已完成 generation 的尾帧，不能根据分镜排序自动推断；`returnLastFrame=true` 则要求本次生成另外返回可供下一镜使用的尾帧，两者是独立输入和输出。首个纯提示词 `/start` 可以省略 `setId`;只要请求引用集内素材或 generation 尾帧续接，`/start` 必须提供对应 `setId`。`POST /shots/{id}/generate` 的目标集由分镜归属确定。纯文字时发送 `promptParts: [{"type":"text","text":"..."}]` 与空 inputs,不强迫用户插入引用。`referenceAssetIds` 是本次明确发送的有序参考图列表,即使用户不在文字中引用也可发送;每个 `asset` part 必须属于这个列表,并解析为同一视频集中的图片参考素材。重复引用同一个 `assetId` 时保留文本中的引用位置,实际传给模型的图片只出现一次;列表重复 ID 视为非法请求。服务端依据本次 `referenceAssetIds` 顺序编译型号要求的 token,例如仅当精确型号契约验证该语法时,列表中的第一张素材才会编译为其对应的 `@Image1`;显示名和素材上传顺序不决定 token。上游若不使用 `@` 语法,adapter 依其已验证输入映射处理 parts,不把 UI 表示原样塞入 prompt。

自由输入的普通 `@`、邮件地址和用户手写数字永远不会自动绑定素材。如果已验证型号把某种手写 token（例如 `@Image1`）解释成输入素材引用,且本次同时提交参考图,后端须按该型号语法检测冲突;只有转义方案有定向验证时才可作为字面文字发送,否则在提交前指明冲突文本并要求用户改写。此规则只针对具体型号的保留语法,不误伤其他普通 `@` 文本。模型方的 `@Image1` 例子只作为相应上游的编码参考,不推出本项目已接通视频素材、`@Audio1` 或其他厂商相同语法。[BytePlus 视频任务文档](https://docs.byteplus.com/en/docs/modelark/create-video-generation-task-api)

首帧在 `inputs.firstFrame` 中传入 `{source:"asset", assetId:"asset-opening-3"}` 或 `{source:"generation_last_frame", sourceGenerationId:"gen-previous-9"}`。不设首帧用 `{source:"none"}`。参考声音通过 `inputs.referenceAudioAssetIds` 显式选择,只供剪辑的音轨通过 `inputs.offlineAudioAssetIds` 记录且绝不发送给模型。`returnLastFrame` 是 `params` 中独立的输出开关；它为 `true` 时，只有 exact-model contract 已验证且媒体响应确实带尾帧，才会在 generation 响应提供 `lastFrameUrl`。当前 UI 没有假定音频可写入文本 `@` 引用。

校验顺序固定为:当前 Viewer 授权 → request ID 幂等查重及冲突判断 → set/shot 归属 → Key 仍属于当前用户且具备 video 权限 → 精确 model id 仍在该 Key 可用候选且 capability contract 状态为 `verified` → promptParts 结构、素材归属、引用状态及本次用途 → `inputMode` 与每个 part role 合法 → duration ≤30 且在该型号合法组合内 → aspect ratio/resolution/size 为该型号合法组合 → 音频素材 MIME、checksum、时长及生成输入编码后字节数通过 → 首帧/参考图/尾帧组合通过。任一失败返回明确错误并保留可编辑草稿,不替换模型、不截断资源、不自动降级参数。同一幂等 ID 对应不同目标或内容返回 409,不向上游发送。

`offlineAudioAssetIds` 只保存到本次 generation snapshot 供卡片显示和后续下载,不进入上游请求。只有 `referenceAudioAssetIds` 明确进入模型。模型 caps 为 0 时不能把参考音频仅作为“记录”后继续提交;用户若只想把声音留给剪辑,改放 offline 字段。`inputMode=reference` 不自动使用首张图当首帧;`first_frame_and_reference` 只有具体型号和 adapter 明确支持时才出现。`generation_last_frame` 固定一个来源 generation id,不按当前 sort_index 动态寻找“上一镜”。

### 4.6 取消、重试、过期与 Key 生命周期

- 取消只能通过工作台的 generation 级 `POST /generations/{id}/cancel` 发起,不复用公共媒体 DELETE 的表面成功。只有 exact-model contract 声明支持且上游响应本身明确表示 cancelled,或随后以同一 Key 查询得到带 provider-confirmed 来源的 cancelled 状态,才把 generation 转为 `cancelled`;公共链路返回 204、上游 404/405、仅写入本地 cached cancelled、已完成任务或仅记录“请求已发送”均不足以证明取消成功。取消失败或结果未知时保留原状态,标记追踪问题并提示“上游可能继续运行”。调用尚未结束的 `submitting` 不可取消或放弃;进入 `submission_unknown` 或已有 `media_job_id` 的在途任务可由用户明确选择本地放弃跟踪,转为 `abandoned`,这不会调用上游。已经 `completed/failed/cancelled/abandoned` 的 generation 不允许回退。
- 任意有可读快照的历史尝试都可点「再生成一版」。前端先调用该 generation 的 `GET /input-snapshot`,在确认面板展示服务端保存的完整输入（包括未点名的参考素材、首帧/尾帧来源、`returnLastFrame` 和实际出站型号），用户确认后才用这份快照回填草稿；不能用当前草稿或“上一镜”动态推断替代。资产缺失时原位置提示修复,不能静默替换;模型、Key 或输入组合当前不可用时保留原值并在提交前重新校验。未知受理时说明潜在重复费用并确认新请求。再次提交才建立新的 `requestId` 和 `attemptNo`,旧 generation 保留。重新生成是新的模型调用和新的计费事实。
- 页面切换 Key 不改变历史或在途 generation 的 snapshot。Key 被删除/停用时,轮询和 content 代理按真实 `/v1` 鉴权错误返回;不把任务转到当前页面 Key,不为历史任务绕过权限。
- 创建请求超时产生 `submission_unknown` 时,页面必须先展示“无法确认是否已受理”,提供使用原 generation 手动查询、放弃本地跟踪和用户确认后新 request ID 重新提交入口。自动重试只允许在 request ID 幂等约束能覆盖真实受理结果的情况下启用;本地 request ID 不能替代上游幂等。上游已写出后断连或含糊 5xx 时不得切换账户重派。宿主媒体链已有内部故障转移时,工作台创建必须向其传递“已写出不可重派”的边界,使首个候选接单后断连时第二候选收到 0 次创建请求。
- 用户明确执行 `POST /generations/{id}/abandon` 后才可把 `submission_unknown` 或有 `media_job_id` 但无法可靠追踪的在途记录收敛为 `abandoned`;尚未结束的 `submitting` 请求不接受 abandon。该动作不要求原 Key 仍可用,也不调用上游;即使本地有 `media_job_id`,也不查询、不取消。`abandoned` 记录仍保留请求快照和“上游可能继续运行或已受理计费”的提示,不得伪装成 `cancelled` 或 `failed`。
- generation 完成后只有内容源明确证实已过期才标记派生 `expired`;通用 404/410、任务追踪失效、上游网络或权限错误不标记 expired。用户仍可查看快照并选择「再生成一版」。

## 5. 模型能力词表(caps)

capabilities 由一份 model-specific contract 提供,包含精确 model id、当前媒体 adapter 实际支持、已验证输入模式、参数组合、默认值和版本。它经 `GET /playground/key-models` 与当前 Key 的 video 候选一并返回,同一 resolver 供生成 handler 和 `/v1` parser 校验。不得维护一份仅给前端看的静态 caps 再让实际 adapter 使用另一套能力;不得按 model 前缀将新能力外推到未验证的 catalog 行。

Key 的目录候选与真实出站型号可能不同,账户路由会把用户选中的 `sourceModel` 映射为 `upstreamModel` 或 canonical 名称。派发层在账户选定并完成型号映射后、首次写出前,必须用实际出站准确型号和账户输入能力重新校验输入组合、引用编码、参数与 contract version;只允许能力完全匹配的账户参与该次创建。所有候选都不匹配时返回 `playground_model_capability_conflict`,保留草稿且不发起上游请求。用户选择型号与实际出站型号、所用能力版本、编译后的引用顺序均冻结到 generation snapshot,供历史审计与重做校验。

能力状态分四种:`verified` 可选择并可提交;`planned` 展示“尚未接通”但不可选择;`unverified` 有目录行或厂商资料但没有项目链路证据,默认不展示为可用;`unavailable` 该型号不属于当前 Key 或上游已不可用。厂商文档定义上游可接受范围,模型目录定义 id/价格,adapter contract 定义当前实现,通过该型号请求与 mock/真实上游样本的定向回归后才升为 `verified`。

```json
{
  "modelId": "doubao-seedance-2-5-260628",
  "availability": "verified|planned|unverified|unavailable",
  "contractVersion": 1,
  "inputModes": ["text", "first_frame", "multimodal_reference"],
  "parameterCombinations": [{
    "inputMode": "text",
    "durations": [5, 10, 15],
    "aspectRatios": ["16:9", "9:16", "1:1"],
    "resolutions": ["480p", "720p", "1080p"],
    "default": {"duration": 5, "aspectRatio": "16:9", "resolution": "720p"}
  }],
  "referenceImages": {"maxCount": 0},
  "referenceAudios": {"maxCount": 0, "maxEachSeconds": 0, "maxTotalSeconds": 0},
  "audioOutput": "switchable|fixed_on|fixed_off|unknown",
  "returnsLastFrame": false,
  "maxEncodedInputBytes": 0
}
```

上例是字段形状,不是对指定型号已接通能力的声明。实际 contract 只能填回归已验证的值。当前仓内能力与首发选择规则如下:

| 范围 | 当前仓内证据 | 工作台行为 |
| --- | --- | --- |
| Seedance / Volcengine | adapter 接收 prompt、通用 duration/size/seed 和至多一张 `input_reference`;映射到 provider 的 `content`。没有独立多图 role、文件音频参考、生成声音开关或尾帧回传链 | Seedance 是产品首推方向。当前先保留提示词生成及已验证的单图入口;多图、音频、声音控制和尾帧在实际请求/回包链路完成前不显示为已支持 |
| 同厂商不同型号 | adapter 能力按 provider 声明,当前没有完整的 exact model capability resolver | 目录中的每个准确 model id 独立验证;不得因共享 `doubao-seedance-*` 前缀继承参数或素材上限 |
| 其他已注册视频 adapter | GLM、MiniMax、Gemini、OpenAI、Qwen、xAI 各自映射字段、时长/尺寸规则、内容定位和取消能力有差异 | Key 模型目录候选需再经过 exact model contract 过滤;只有 `verified` 的实际型号出现为可选项 |
| 无已验证候选 | 目录有 video 型号,但精确 adapter/计费/status/content 任一环节尚无回归证据 | 显示“当前没有可用型号”,允许切换 Key 并保留提示词;不以厂商支持或模型名推断可用性 |

用户先选 Key,再在此 Key 的 `verified` 型号中选择。Seedance 排在当前 Key 的已验证候选前列,不会跨 Key 自动选择或替用户切换 Key。没有已验证 Seedance 时,显示其他已验证纯提示词型号;没有任何已验证型号时显示可读空态并保留提示词。

默认值随 exact model 与 input mode 返回。原型以 Seedance 5 秒、16:9、720p、静默作为交互示范,不是当前默认值或承诺;尤其当前火山 adapter 没有声音输出开关,不能由工作台保证静默。服务端和前端不得把这组值硬编码到所有型号。其他型号只显示 contract 返回的合法值。切换模型保留 prompt 和已选素材引用,不合法参数/输入就地标出并禁用生成;用户明确调整后才改变本次请求。duration/resolution/ratio 不做“就近档位”静默降级。4K 只有精确出站参数、计费维度、结果回显均一致并通过定向回归后才开放。

## 6. 尾帧续接契约(火山系首发)

用户裁决「上一镜尾帧作下一镜首帧」进入首发设计。只有 exact model contract 为 `verified` 且媒体任务响应链已回传尾帧的型号才开放;厂商文档或静态 caps 单独不能开启:

1. **请求侧**:generation snapshot 的 `returnLastFrame=true` 仅在 contract 允许时转换到 provider 字段。不得经旧 `metadata` 白名单偷渡;
2. **媒体链**:adapter 创建请求、统一 IR、轮询响应对象、`/v1` 任务响应和 mock 上游都必须声明同一尾帧字段及测试。当前 adapter 只解析视频定位 URL 的型号保持 `returnsLastFrame=false`;
3. **演练场侧**:首次 completed 轮询若 IR 返回尾帧 URL,经 SSRF 守卫下载小图,落 `playground_artifacts` kind=`video_lastframe`,绑定 generation id,回填 `last_frame_artifact_id`。下载失败不回滚视频 completed,但隐藏续接入口并记录可诊断错误;
4. **消费侧**:用户从具体已完成 generation 点击「用尾帧创建下一镜」,系统把该 generation id 固定写入下一镜草稿。尾帧 artifact 七天清理后,生成前返回 400 并提示改用素材首帧或重新生成来源 generation;
5. 跨镜续接入口只对已满足上述条件的具体 generation 出现。重排分镜、重新生成原镜或切换 Key 不改变已有草稿的固定来源。

## 7. 前端交互

### 7.1 视频集列表页(`/playground/videos` 重写)

- **首屏先生成**:一个画面 prompt 输入框(必填),API Key 选择,Key 就绪后显示型号选择;Seedance 型号在该 Key 可验证候选中优先展示。默认生成参数显示在同一行,主按钮「生成分镜」。填提示词不需要先建集、贴剧本或添加任何素材。
- **选择有据**:Key 显式由用户选择,不跨 Key 自动寻找可用模型。显示精确型号与厂商;不同型号采用合约返回的合法参数和默认值。Key 没有合格视频型号时显示空态,提示可选 Key/模型范围,提示词保持可恢复。
- 「＋ 添加素材」直接打开本机文件选择器并允许从当前集选择。首次在空工作台上传文件时先创建一个默认命名视频集;随后继续上传/编辑。选中图片后再由用户指定「首帧」「参考外观」;音频可选「参考音频」或「仅供线下剪辑」。已选资源在预览中清楚可见,删除、取消引用与更换用途有状态反馈。
- 提交第一镜时 `/start` 原子创建默认视频集、分镜、generation 记录;成功受理后页面切到该集。此后生成直接在所选集内追加分镜,带素材或尾帧续接时请求必须携带该集 `setId`。命名、定位简介和剧本放到集详情的次级编辑区,可晚些时候补填。请求发出到收到 `{setId, shotId, generationId, status}` 回执之间,前端把原始意图暂存到按 Viewer 隔离且 24 小时过期的 IndexedDB;关闭页面后重开仍能用原 `requestId` 恢复,收到回执或登出即清除。
- 页下方可进入最近视频集列表,提供关键词/派生状态筛选和游标加载;卡片只显示集名、镜头数、在途/完成/失败摘要、素材数和更新时间。删除动作分开确认并说明资产/历史记录一起删除。

### 7.2 集合详情页(子路由 `/playground/videos/:setId`,keepAlive 同组)

页面保持「快速生成」焦点,其他集内内容折叠/分区呈现:

- **分镜 composer**:首屏同一 prompt 和 Key/型号/参数/「＋ 添加素材」可见;切换集只改变分镜归属,不丢失草稿。创建多个分镜时同一字段组可复用。
- **生成历史**:集内分镜按 sort_index 排列,每张分镜展示最新可用结果和「版本」入口。版本列表显示 attempt 编号、准确模型、创建时间、状态、输入素材摘要、输出声音状态、过期事实与可用操作。completed 结果可内联播放和下载;失败显示可重试原因;已过期版本可再生成一版但旧内容仍留历史记录。
- **素材库**:角色/场景/道具通过 image tag 分类;图片以缩略图列表显示名称、大小和标签;音频行显示台词文本、角色、长度与试听。用户可更换分镜用途、解除引用、下载或在无阻断引用时删除。上传限额以当前合同为准(图片 ≤10 MiB、音频 ≤8 MiB)。素材库仅集内资源,没有生成图片、TTS 或音色编辑控制。
- **剧本和集信息**:命名、定位文本、剧本均为可折叠纯记录。无剧本也能立即开始;粘贴剧本不改变 prompt、不会触发拆镜或提交。
- **任务状态**:queued/running 在刷新及切页后恢复查询;`submission_unknown` 仅查询本地记录,有 `media_job_id` 时才可查询上游。最多 5 次连续失败后暂停自动查询并提供手动恢复。`submission_unknown` 使用独立警示状态,提供查询、明确放弃和用户确认重新提交选项。
- **链接时间**:只有上游明确报告 expiry 时显示可信倒计时;仅知大致时长时标记“预计”,未知则只提示及时下载。只有带来源证据的内容过期才标记过期,其他 HTTP/Key/网络错误分别显示。
- 首版只提供逐镜提交。逐镜状态、素材组合、尾帧依赖和计费稳定后,如需一次提交多个草稿,必须另立接口与逐项结果契约,不得把多个付费请求折叠成一个总状态。

### 7.3 素材与生成参数

- prompt 为首要字段(≤4000 字符),台词文本纯记录且可选。编辑器内部保存 `promptReferences`（`assetId`、显示 token、文本范围）供光标位置和修复使用,提交快照只保存规范化 `promptParts`。输入模式以分段选择显式呈现:纯提示词、首帧、参考素材、首帧+参考、全模态参考仅显示当前型号已验证的模式;互斥时清楚禁用冲突素材。当前不开放同一请求内的 `last_frame_pair`/“指定尾帧”输入；后续若启用,必须在 `inputs` 明确加入 `lastFrameAssetId` 并编译为 `input_images` 的 `last_frame` role,完成 exact-model adapter/轮询/回归后才能显示控件。
- 图片选择后明确用途,尾帧必须从某个具体 generation 的结果卡片添加。素材按稳定 ID、名称和缩略图显示,编号只作视觉辅助;用户可以在提示词输入 `@` 后从候选菜单插入引用,手打 `@Image1` 不会被绑定。输入模式变化不删除素材;出现冲突时提示“改用途/移除/切回可兼容型号”。引用失效时编辑器在原位置显示待修复,提供重新绑定、转普通文字和删除三项明确操作,不得按同名素材自动替换。
- 音频行提供两个不同选择:「参考声音生成画面」和「仅供线下剪辑」。前者根据具体 model/inputMode 显示数量、各段及合计时长上限;后者不发送给模型。音频输出是第三个独立设置,显示可关/固定有声/固定静音/当前未知;未知时不允许自行编造开关。
- Key 必须显式选择。型号在该 Key 有权使用的 exact verified candidates 中按 Seedance、其他已验证文生型号排序。切换 Key/型号保留 prompt、集内资产与已保存草稿;旧 duration/resolution/ratio/输入 mode 不合法时就地标红并要求用户选择合法项,绝不静默换档。
- 默认参数从 capability contract 返回。原型示范用 Seedance:5 秒、16:9、720p、静默;其他模型仅在该组合真实合法时采用。时长按钮只显示型号合法值,不能把某一型号的快捷档套到其他型号。
- 提交前显示本次模型、模式、参数、音频策略和将被发送的素材清单。Base64 加 JSON 的最终大小受网关当前有效 body limit 与视频硬限制约束;显示估算字节并在提交前验证。发生 413 时保留 prompt 和资产选择,告诉用户缩减参与本次生成的文件。
- 上传通过 multipart/二进制单件请求而非 Base64 JSON;精确的 per-route body limit override 与流式文件字节上限需同批实现。生成时 `/v1/video/generations` 请求仍须先核验 Base64 扩容后的总字节数。建议工作台给单次生成设 10 MiB decoded-input aggregate 上限,但服务端还须以有效网关 body limit 动态收紧该值;此处 10 MiB 是工作台目标上限不是保证任意设置下可提交。

### 7.4 API 域与类型

`frontend/src/api/domains/playground.ts` 扩展视频集/分镜/generation API,包括 `/start`、sets CRUD、multipart asset upload、asset content/download、shot draft CRUD、generation create/list/poll/content/input-snapshot/cancel/abandon;退役旧 `videosCreate/videosPoll/videosContent` 的主入口并按约定回兼容。`frontend/src/types/domain/playground.ts` 增加 `PlaygroundVideoSet/Asset/Shot/Generation/CapabilityContract` 类型;shot 草稿包含 `promptParts` 与编辑态 `promptReferences`,generation 只保留不可变快照;model 行携带 exact-id capabilities。恢复记录以 Viewer 为键写入 IndexedDB,24 小时到期且登出/收到统一回执后清理。回归脚本固定 prompt-only 创建、自动建集、`@` 插入/修复/去重、幂等重放与冲突、关页重开恢复、完整快照回填、素材 mode 组合、模型切换和未知受理恢复。

## 8. 兼容与实施同步清单

- **演练场 API**:以视频集/分镜/generation 新 API 取代旧 `POST /videos`、`GET /videos/{jobId}` 和 `GET /videos/{jobId}/content` 页面主流程。移除旧端点前先核对所有调用方;`video_task` 暂存记录按现有本地清理规则自然到期,不尝试推导成视频集,也不把旧记录 TTL 当成上游视频链接期限。`GET /playground/artifacts` 的 `video` 字段仅在确认无其他消费者后收窄。
- **前端**:改造 `PlaygroundVideoView.vue` 与对应 API/type,保证提示词单独可生成、已有视频集可直接追加分镜、模型/素材组合由能力契约驱动。提交前持久化 Viewer 级 IndexedDB 恢复记录,首镜与重做使用相同回执协议,回包丢失可用原意图恢复;素材/续接请求必须带 `setId`。退役旧 API 调用前用代码搜索和调用链复核,不保留无人维护的双入口。

- **权威文档**:实施同次更新《演练场设计》视频生成章节、《媒体上游协议契约与Mock上游规格》、《接口契约与权限矩阵》、《架构总览》演练场说明及 `docs/functions/README.md` 索引。同步后逐项核对链接和章节号。

## 9. 计费与用量

每次已受理的 generation 经 Bearer 直驱走完整 `/v1` 链,创建时计价冻结到 `media_jobs.request_snapshot_json`,终态账单权威为 `usage_records`。点击「再生成一版」是新的模型调用,可能产生新的计费;素材上传及仅供线下剪辑的音频不发起模型调用。相同 `requestId` 的 API 重放返回原尝试而不重复派发。若请求结果未知,必须保留 `submission_unknown` 并告知用户上游可能已受理和计费,不得自动创建第二次请求。用量页能证明已经入账的费用;页面关闭、Key 失效或本地放弃后尚未观察到上游终态时,用量页暂无记录不能证明上游未接单或没有费用。遵循《演练场设计》现行裁决,工作台不展示 tokens 或扣费金额;不显示目录估价、推算价或未结算价。用量和费用由现有用量页面及 `usage_records` 查看。Key 配额、用户限流、在途预占和日志审计沿用 `/v1`。

## 10. 验收标准与定向验证

1. **最小创作路径**:空工作台只填提示词,选择可用 Key 与已验证型号即可创建第一镜;不要求先建集/贴剧本/上传素材。刷新或切页后能找回视频集、分镜和任务状态。
2. **数据与权限**:四张表覆盖 ViewerID 隔离、CRUD、并发更新、同一 `requestId` 幂等、generation 不可变 snapshot、在途/未知受理状态保护、同 Viewer/同 set 尾帧校验、删单镜活动依赖冲突与删集原子级联。跨 Viewer/跨 set 的素材或 generation 引用按 404 拒绝,越权和不存在不泄露存在性。
3. **模型能力**:至少验证 Seedance 精确型号的纯提示词完整 create/poll/content 及可用取消能力与真实参数映射;选中型号映射到账户真实出站型号后再校验,双账户仅能力匹配者可派发。每个开关/素材用途单独验证出站字段、回显和计价。多图、多音频、声音控制和尾帧只对对应 `verified` 型号开放;为未接通能力验证“不可选且保留草稿”。旧 `/v1` 单图请求回归不变。
4. **前端**:运行本次涉及文件的 typecheck、组件/回归用例,覆盖提示词-only、自动建集、Key/型号切换保稿、素材用途和冲突、生成/重试、取消能力差异、过期与网络错误区分。覆盖 `@` 菜单和重复引用、同名素材、重排、删除/用途变更后的修复、从所选历史完整快照回填、IndexedDB 关页重开恢复、手打保留 token 与普通邮件地址。
5. **定向 E2E**:使用本地 dev PostgreSQL/Redis 和 `mockupstream` 验证建集→提示词-only 生成→轮询→播放/下载→再生成→素材引用→删除/409 的主路径。模拟服务端已受理但首回包丢失,关闭页面后重开,同一原始 request 恢复相同 `{setId, shotId, generationId, status}` 且上游只收到一次创建;验证尾帧不能跨 Viewer/set 引用、删单镜保护活动依赖、无在途/未知任务的整集删除在事务内级联,以及图片/每条音轨均可通过 `?download=1` 单独完整下载。真实上游生成可能产生费用,不作为默认验收;需要真实样片验证时单独安排并明确授权。
6. **派发与完整内容**:mock 两个候选,首个接单后断连,第二候选收到 0 次创建;相同 request ID 重放返回原结果、不同意图 409、目标删除后重放 410 且不派发。取消验收须证明 provider-confirmed 来源,本地 cached cancelled 不得充当证明。经 `/v1`、`chatGatewayExecutor.Dispatch` 的 `io.Pipe` 和工作台 content 全链验证大于 64 MiB、已知/未知长度中断、长度不符、内容源过期与任务不可查询的不同结果。
7. **文档同步**:按 §8 同步权威文档,验收项与模型能力表一致;不要求执行全量测试。任何未通过项须记录具体证据、归属和完成判定。

## 11. 实施前置门槛

本节不是待用户选择的功能清单,而是开发开始和能力开放的证据门槛:

1. **精确型号清单**:项目现有 Key-models 按目录协议行提供 video 候选,adapter 的能力目前仍按厂商/协议层声明;两者都不构成某个 Seedance 型号的完整能力承诺。实施时为实际目录返回的每个准确 model id 建立服务端能力契约,Seedance 在符合条件的候选中优先排序。具体型号未通过请求、轮询、content、参数和计费定向回归前,不标 `verified`,不开放其扩展控件。
2. **声音与素材组合**:当前统一视频请求主要覆盖提示词、通用时长/尺寸和单张 `input_reference`;多图角色、文件音频参考、声音输出开关与其组合不能从厂商文档推断为当前已接通。逐个确认 adapter 出站语义与返回状态后再显示对应控件。口型、音色相似度和画面质量仅作为样片观察,不构成平台保证。
3. **链接期限**:以媒体 IR 或 content 代理能取得的明确 expiry 为准;现阶段没有统一厂商期限字段时,保存未知,只有能确认内容源到期的证据才标记过期。任何模型、供应商或任务 ID TTL 都不能代替视频内容链接期限。
4. **素材上限与请求预算**:图片/音频单件限制和单次生成 aggregate 限制须由接口、代理请求体上限、Base64 编码增量及可用内存共同确定;在服务端实际配置落地前,10 MiB aggregate 仅为原型建议值,不是已生效保证。上传成功只表示文件已保存,生成提交仍需验证完整请求预算。
5. **保留期与删除**:视频集素材遵守产品定义的集内生命周期;generation 历史依工作台 retention 规则保存;尾帧作为小型派生图片依单独 artifact retention 清理。用户删除视频集、素材仍被引用和存在 `submission_unknown` 时的行为按 §3、§4 落地,不继承旧 `video_task` 的本地暂存期限。

## 附录 A:能力事实与证据边界

本附录只描述当前仓内可核实的媒体调用形态,用于防止把目录候选、厂商宣传和项目功能混为一谈。它不枚举第三方报价或承诺各厂商内容链接时效;这两类数据不参与本工作台的能力开关。

| 层次 | 当前事实 | 对本工作台的含义 |
| --- | --- | --- |
| Key 的模型候选 | `key-models` 按模型目录的 `video` 协议和供应商白名单产出候选;只表示模型目录/账户的可路由关系 | 候选列表还需经过精确型号 capability contract 过滤,不能直接展示所有候选为“支持完整素材功能” |
| 公共视频参数 | `ParseVideoParams` 当前接收 prompt、seconds、size 和单图引用等统一字段,再按 adapter 的 provider-level caps 归一 | 当前未按 exact model id 声明所有素材角色、输入组合和参数合法值 |
| 适配器 | OpenAI、Gemini、GLM、MiniMax、Volcengine、Qwen、xAI 视频 adapter 已注册;不同 adapter 的声音、单图、时长、尺寸和取消能力不相同 | 已注册不等于工作台候选已开放,也不等于各型号共用相同表单 |

## 附录 B:用户音频的职责边界

用户可在工作台外录制或使用其他工具准备音频;演练场现有语音合成页可作为备选准备工具,但视频工作台不生成、编辑或克隆音色。上传后,每条音频都必须明确标记为「发送给当前型号作参考」或「仅供线下剪辑」。前一用途只在当前 exact model contract 验证该文件输入和组合后开放;后一用途不进入模型请求。输出声音控制是独立参数,只有 adapter 能明确映射并回显时才显示开关;否则显示已验证的固定状态或不提供该项。
