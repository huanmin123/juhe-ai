# 模型目录元数据审计设计

## 目标

- 逐供应商核对内置模型目录的发布时间、停用时间、接口协议、模态、上下文、输出上限、价格、服务等级和思考级别。
- 让管理页“发布时间”来自可追溯的供应商事实；能确认则补全，不能确认则保留未知，不用猜测值制造完整率。
- 保持代码内置数据、Node/SQLite/PostgreSQL seed、Go migration 快照和前端展示一致。

## 范围

当前审计覆盖 6 个驱动：OpenAI、Anthropic、Gemini、xAI、DeepSeek、GLM。管理员或用户自建模型不属于厂商事实，仍允许发布时间为空。

## 证据规则

1. 优先使用供应商官方模型页、价格页、更新日志、发布公告和废弃公告；官方模型列表 API 只作为模型 ID 的二次核验。
2. 日期精度必须与证据一致。官方给出具体日期时写 `YYYY-MM-DD`；只给月份时仅在现有目录排序规则明确允许近似锚点且文档记录依据时使用月初，否则保持未知。
3. dated model ID 自带的日期可作为该快照发布时间；稳定别名只有在官方公告或更新日志能关联到模型族时才继承族发布日期。
4. 文档页面更新时间、价格页抓取时间、代码提交时间和第三方聚合数据都不能替代模型发布时间。
5. 参数没有官方证据时保持 `undefined` 或空数组。协议可用不推导模态、工具、服务等级或思考级别。

## 字段核对矩阵

| 字段组 | 字段 | 核对标准 |
| --- | --- | --- |
| 生命周期 | `release_date`、`shutdown_date`、`catalog_visible` | 发布与停用公告、官方当前目录；未来停用继续保留，到期由现有过滤逻辑移除 |
| 协议能力 | `supported_api_protocols` | 官方 endpoint / API compatibility 文档，不从 `mode` 单字段猜测 |
| 输入输出 | `input_modalities`、`output_modalities`、`supported_tools` | 官方模型能力页逐项确认 |
| 容量 | `context_window_tokens`、`max_input_tokens`、`max_output_tokens` | 总上下文、最大输入和最大输出分别取证，不互相复制 |
| 计价 | 标准、缓存、图像、音频、档位价格与长上下文倍率 | 官方价格页同一时间口径；缺价不使用倍率猜测 |
| 请求参数 | 服务等级、reasoning effort、默认 effort | 逐模型官方请求文档；供应商套餐名不强行映射为 OpenAI 参数 |

## 数据流与同步

`*-model-pricing.data.ts` 和供应商驱动是内置事实源，`listProviderModelPricing()` 生成运行时目录。SQLite/PostgreSQL 初始化 seed 读取同一事实；Go 当前 schema migration 由 `backend-go/scripts/generate-provider-model-catalog.ts` 生成。修改事实后必须生成新的迁移，禁止回写已执行的历史 migration。

前端 `ProviderModelCatalogModal.vue` 只展示 API 的 `releaseDate`。页面显示 `-` 表示事实源未知，不在前端补日期。

## 完成条件

- 6 个供应商均有逐模型审计结果和官方证据记录。
- 有可靠证据的缺失字段已补齐；可疑、虚构、过期或字段错误的条目已修正或隐藏。
- 新增回归覆盖每个供应商的代表模型、日期排序、未知日期兜底和迁移快照一致性。
- 模型目录专项测试、两端类型检查、构建与管理页浏览器验证通过；若有基线失败，明确区分并记录。
