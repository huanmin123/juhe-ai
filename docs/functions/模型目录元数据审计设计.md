# 模型目录元数据审计设计

## 目标

- 逐供应商核对内置模型目录的发布时间、停用时间、接口协议、模态、上下文、输出上限、价格、服务等级和思考级别。
- 让管理页“发布时间”来自可追溯事实；内置模型必须字段完整，官方资料不足时继续使用官方仓库、模型托管页、可信新闻和社区发布记录交叉核验，仍不能确认则移出内置目录。
- 保持代码内置数据、Node/SQLite/PostgreSQL seed、Go migration 快照和前端展示一致。

## 范围

当前审计覆盖 6 个驱动：OpenAI、Anthropic、Gemini、xAI、DeepSeek、GLM。管理员或用户自建模型不属于厂商事实，仍允许发布时间为空。

## 2026-07-23 审计结果

| 供应商 | 当前内置可见数 | 缺少发布日期 | 主要处理 |
| --- | ---: | ---: | --- |
| GPT / OpenAI | 69 | 0 | 补齐生命周期和能力；删除 `codex-auto-review`、`babbage-002`、`davinci-002`、`gpt-3.5-turbo-instruct`、`gpt-4o-transcribe-diarize` 和缺少完整计价事实的 `gpt-5-search-api` |

| Gemini | 11 | 0 | 补入当前 Flash 系列并补齐日期、分档价格、协议、模态、工具和容量 |
| xAI | 7 | 0 | 补齐当前 Grok 文本与图像模型；`grok-4.3` 无法确认精确首发日期，从内置事实源删除，并将默认检查模型切换为 `grok-4.5` |
| DeepSeek | 4 | 0 | 将 V4 首发日期更正为 `2026-04-24`，同步当前稳定别名、价格、容量和协议能力 |
| GLM | 15 | 0 | 按 Z.ai 公告补齐 4.5 至 5.2 系列；`glm-5-turbo` 以多个社区首发记录交叉确认 `2026-03-16`；`glm-4-long` 无精确日期、`glm-4-flashx-250414` 无官方 USD 价格，均从内置事实源删除 |

本次主要证据入口为 [OpenAI Models](https://developers.openai.com/api/docs/models)、[OpenAI Pricing](https://developers.openai.com/api/docs/pricing)、[OpenAI Deprecations](https://developers.openai.com/api/docs/deprecations)、[Anthropic Models API](https://platform.claude.com/docs/en/api/models)、[Gemini models](https://ai.google.dev/gemini-api/docs/models)、[xAI Models](https://docs.x.ai/docs/models)、[DeepSeek API Docs](https://api-docs.deepseek.com/) 和 [Z.ai Blog](https://z.ai/blog)。`glm-5-turbo` 的精确日期另由知乎、腾讯云开发者社区、博客园和百度百科的首发记录交叉核对；这些二手来源只用于官方页面未提供精确日期的缺口，不覆盖官方能力和价格事实。

运行时还发现 SQLite seed 原先使用 `INSERT OR IGNORE`，导致已有 `provider_model_catalog` 行不会吸收新版内置日期。当前改为冲突更新：普通快照行完整刷新厂商元数据和价格；管理员修改事实或价格的行标记为 `manual-override`，只修改状态或可见性的行标记为 `manual-visibility-override`。历史快照隐藏可以随补全后的新快照恢复，人工隐藏仍保留；stale 清理按 `(provider_code, model)` 识别，兼容旧版无 hash ID，并把已从生成源删除的旧条目标记为停用且不可见。PostgreSQL 使用新的 schema migration 执行同口径同步。

## 证据规则

1. 优先使用供应商官方模型页、价格页、更新日志、发布公告和废弃公告；官方资料缺失时，可使用官方仓库、官方模型托管账号、可信新闻和可追溯社区首发记录交叉核验。
2. 日期精度必须与证据一致。官方给出具体日期时写 `YYYY-MM-DD`；只给月份时仅在现有目录排序规则明确允许近似锚点且文档记录依据时使用月初，否则继续交叉核验，仍无精确日期则从内置源删除。
3. dated model ID 自带的日期可作为该快照发布时间；稳定别名只有在官方公告或更新日志能关联到模型族时才继承族发布日期。
4. 单独的文档页面更新时间、价格页抓取时间或本项目代码提交时间不能替代模型发布时间；第三方资料至少需要能指向明确首发事件，并优先由第二来源交叉确认。
5. 内置事实源不允许发布日期、协议、模态和计价等必填元数据为 `undefined` 或空数组；文本模型必须至少有厂商明确公布的总上下文或最大输入容量。无法核实这些必填事实的条目必须从内置源删除；协议可用不推导模态、工具、服务等级或思考级别。
6. 容量字段不伪造：总上下文、最大输入和最大输出分别展示厂商明确公布的值；未提供的维度不渲染，不做减法推导，也不重复显示“官方未公布”。运行时需要保守输入预算时可以在服务端内部派生，但不能把派生值包装成目录事实。
7. 缓存计费按语义分开：缓存命中、一次性缓存写入、1 小时缓存写入和按 Token·小时收取的缓存存储是不同维度。厂商没有独立写入费用时显示“无独立费用”，不填零也不显示缺失占位；明确不适用缓存时显示“不适用”。

## 字段核对矩阵

| 字段组 | 字段 | 核对标准 |
| --- | --- | --- |
| 生命周期 | `release_date`、`shutdown_date`、`catalog_visible` | 发布与停用公告、官方当前目录；未来停用继续保留，到期由现有过滤逻辑移除 |
| 协议能力 | `supported_api_protocols` | 官方 endpoint / API compatibility 文档，不从 `mode` 单字段猜测 |
| 输入输出 | `input_modalities`、`output_modalities`、`supported_tools` | 官方模型能力页逐项确认 |
| 容量 | `context_window_tokens`、`max_input_tokens`、`max_output_tokens` | 总上下文、最大输入和最大输出分别取证，不互相复制 |
| 计价 | 标准、缓存命中、缓存写入、缓存存储、图像、音频、档位价格与长上下文倍率 | 官方价格页同一时间口径；不同缓存语义不得混用，缺价不使用倍率猜测 |
| 请求参数 | 服务等级、reasoning effort、默认 effort | 逐模型官方请求文档；供应商套餐名不强行映射为 OpenAI 参数 |

## 数据流与同步

`*-model-pricing.data.ts` 和供应商驱动是内置事实源，`listProviderModelPricing()` 生成运行时目录。SQLite/PostgreSQL 初始化 seed 读取同一事实；Go 当前 schema migration 由 `backend-go/scripts/generate-provider-model-catalog.ts` 生成。修改事实后必须生成新的迁移，禁止回写已执行的历史 migration。

前端 `ProviderModelCatalogModal.vue` 对计费和容量采用“只展示已确认字段”的紧凑列表。缓存附加费列统一按字段语义展示写入、1h 写入或存储时费；只有缓存命中价格且没有附加费用时显示“无独立费用”。Token 容量同时兼顾厂商常用单位和精确值，例如 `1_048_576 -> 1M（1,048,576）`、`65_536 -> 64K（65,536）`，避免与十进制 `1,000,000`、`64,000` 混淆。

2026-07-24 复核 Gemini、xAI 和 GLM：Gemini 新增独立 `cacheStorageUsdPer1MPerHour`，Standard 档 Flash/Lite 为 `$1`、Pro 为 `$4.5`；Grok 继续只保留缓存命中价格；GLM 免费 Flash 型号补齐缓存命中 `$0` 和自动缓存能力。`glm-4-flashx-250414` 因仅有人民币官方价格而移出 USD 内置目录。

## 完成条件

- 6 个供应商均有逐模型审计结果和官方证据记录。
- 所有内置模型的必填字段均完整；无法补齐、可疑、虚构、过期或字段错误的条目已修正或从内置事实源删除。
- 新增回归覆盖每个供应商的代表模型、日期排序、无证据条目删除和迁移快照一致性。
- 模型目录专项测试、两端类型检查、构建与管理页浏览器验证通过；若有基线失败，明确区分并记录。
