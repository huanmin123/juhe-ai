## 1. 定案

目标中保留四种不同身份，不能互相代替：

| 身份 | 字段 | 取值 | 职责 |
| --- | --- | --- | --- |
| 真实厂商 | **vendor_code** | **gpt**、**xai**、**deepseek**、**anthropic**、**gemini**、**glm**、**minimax**、**volcengine**、**qwen**；未知时为 **NULL** | 厂商专属认证、模型语义、usage 语义、价格和错误处理 |
| 连接器 | **connection_driver_code** | 上述已接入厂商 driver，或 **generic_http** | 凭据与 token 生命周期、认证、供应商 usage/error 解释、媒体适配 |
| 协议面 | **protocol_surface_code** | **openai_v1**、**anthropic_v1**、**gemini_v1beta** | 文本生成请求/响应/SSE 编解码 |
| 账户入口映射 | **account_entry_mappings** | 账户级映射行 | 将客户端模型名和入口族一跳转换到该账户的目标模型与目标 endpoint family |

**generic_http** 是连接器，不是供应商，不出现在 **vendors**、供应商目录、供应商卡片或默认分组中。它允许接入使用标准协议的未知厂商。已知厂商优先使用其真实 driver。

**openai** 不再是供应商身份。**openai_v1** 只表示协议面；OpenAI 官方账户的 **vendor_code** 与 **connection_driver_code** 均为 **gpt**；通用 OpenAI-compatible 账户为 **vendor_code=NULL**、**connection_driver_code=generic_http**。

**hybrid** 不再是供应商、连接器、账户类型、协议面、模型目录、分组类型或路由模式。所有账户共用同一种入口映射机制；是否需要跨协议只由映射行和目标账户能力决定。

同一注册表展开后恰有 **162** 个允许的 `(connection_driver_code, account_type, oauth_type, connection_preset_code, endpoint_mode)` 单 mode 配置：generic_http=30、gpt=18、xai=10、deepseek=6、anthropic=6、gemini=46、glm=18、minimax=5、volcengine=13、qwen=10。DeepSeek 的 6 个由 `deepseek_openai_v1` 在 chat 域的 4 个 mode 和 `deepseek_anthropic_v1` 收窄后的 2 个消息 mode 组成。一个连接允许的 `endpointModes` 是其精确允许 mode 集合的任意非空子集；mode 不得跨 capability domain。协议面只描述文本编解码；实际 route builder 由 `connection_preset_code` 唯一选择，不能只凭 `protocol_surface_code` 推断媒体 URL、认证或厂商专属请求参数。

**计数来源和阻断规则：** 49 与 162 必须由同一个编译期 registry 生成器计算，而不是手工维护的常量。生成器输出排序稳定的 tuple 清单、按 driver 计数和 SHA-256 fingerprint；fingerprint 固定为对 UTF-8 compact JSON 数组 `[{"driver":"...","vendor":"...|null","accountType":"...","oauthType":"...|null","preset":"...","surface":"...|null","domain":"...","mode":"...","allowedBaseSuffixes":["", "/v1"],"operationTemplates":["METHOD /path",...],"defaultBaseUrl":"https://...|null" }]` 的原始 bytes 计算 SHA-256，数组、`allowedBaseSuffixes` 和 `operationTemplates` 均按 ASCII 字典序排序，`defaultBaseUrl` 按 §1.1 注册表的 canonical bytes 原样写入。任何默认 URL 变化都必须改变 fingerprint。文档中的数字只有在 registry test 断言 `allowlist == expected_tuples`、`sum(driverCounts)==49`、`sum(endpointModeCounts)==162` 时才成立。任何表格修改、registry 修改或 fingerprint 变化都必须同时更新本节、tuple 清单、route builder contract 和验收报告；数字不一致直接阻断构建/迁移，不能通过改测试期望值放行。

`connection_driver_code`、`connection_preset_code`、`protocol_surface_code` 和各自允许集合是版本化编译期 registry，不建 `connection_drivers`、`connection_presets` 或 `protocol_surfaces` 数据表，不提供管理面增删改。tuple 数据的唯一源码放在 `backend-go/shared/contracts`；每个 driver record 必须包含 `credential_schema_key`，每个 preset record 必须同时包含 `operation_path_templates[]`、`allowed_base_path_suffixes[]`、认证策略引用、URL builder key、协议面和完整 mode 集合。`credential_schema_key` 指向该 driver 现有凭据校验器，定义必填/可选 key、类型和密文轮换字段；未知 key（迁移专用的旧 `base_url`、`supported_endpoint_modes` 和 profile 元数据除外）返回 HTTP 400 `credential_field_unsupported`。`operation_path_templates[]` 至少 1 项，模板格式固定为 `METHOD`、一个 ASCII 空格和以 `/` 开头的 path（例如 `POST /v1/responses`）；`allowed_base_path_suffixes[]` 至少 1 项，元素是解码后 path suffix（空字符串表示根路径），用于允许 `/v1`、`/openai/v1`、`/v1beta/openai` 这类 service/version 前缀。URL validator 与 route builder 均只能读取这两组数组，禁止在第二处维护 endpoint 字符串或 Base URL 例外。Gateway、Jobs 只绑定该 tuple 到各自进程内的 runtime driver，Maintenance 使用同一 tuple 校验 schema、seed 和迁移，三个项目不得复制允许集合。vendor 仍是九行 `vendors` 数据表。新增或改变任一 registry tuple 必须同次更新本表、tuple 展开测试和对应 route builder contract。

附加规则：

1. **generic_http** 的 api_key 固定认证为：`generic_openai_v1` 使用 `Authorization: Bearer <api_key>`；`generic_anthropic_v1` 使用 `x-api-key: <api_key>` 与 `anthropic-version: 2023-06-01`；`generic_gemini_v1beta` 使用 `x-goog-api-key: <api_key>`。它只提供标准协议编解码和通用 HTTP 发送，不提供厂商模型目录或厂商价格。
2. 同一账户的多个连接预设共用同一凭据 JSON，但每个连接行有自己的 base_url。不同凭据必须创建不同账户；不同 Base URL 只能保留在同一账户的不同 `connection_preset_code` 行。相同 preset 需要多个 Base URL 时必须拆成多个资源账户；目标 schema 不引入 connection alias，迁移遇到同一账户同一 preset 的多个 canonical Base URL 计入 `connections_blocked`，必须在迁移前离线拆分源账户后重新生成 manifest，正式迁移不执行账户拆分。
   这里的“拆分”只允许在迁移前由维护者离线创建多个源账户并重新生成 manifest；`mapping_disposition` 不得隐式创建或复制资源账户，正式迁移本身不执行账户拆分。
3. deepseek_openai_v1、deepseek_anthropic_v1 和 GLM 三个预设按注册表使用各自默认 Base URL；账户保存后 Base URL 为连接行字段，不再从 provider_protocol_profile 派生。
4. Gemini google_oauth 保留 oauth_type ∈ {code_assist, google_one, ai_studio}；连接预设 registry 逐项定义支持的 mode。未注册的 oauth_type × endpoint_mode 组合拒绝。
5. minimax、volcengine、qwen 的媒体适配仍归各自连接器。媒体 endpoint mode 是账户能力声明，不表示媒体上游采用 OpenAI wire protocol。
6. 注册表中每一格都是允许集合；未列出的 connection_driver_code × account_type × connection_preset × capability_domain 组合返回 HTTP 400 connection_capability_unsupported。
7. URL 拼接只调用注册表绑定的固定 route builder；请求中的客户端 path 不能作为上游 path。每个 builder 将连接 `base_url` 的 path 作为前缀保留，并按 preset 的协议规则追加一次 operation path；不得对所有厂商套用一个通用 `/v1` 拼接器。`generic_openai_v1` 的 `/v1` 归一严格复用 [客户端网关入口路径设计](客户端网关入口路径设计.md) §5.2；Gemini OpenAI Chat、Anthropic、Gemini native 和媒体 preset 分别复用其现有对应协议/媒体契约。此重构只改变连接身份和候选选择，不改变这些 route builder 的 method、path、header、body 或 response/SSE 语义。
8. 本次不改变任何真实 driver 的凭据字段、OAuth 授权/刷新流程、认证 header、usage/error 解释或既有 route builder 行为；这些实现继续由相应 driver 和其厂商接入契约负责。连接 preset 只把已有行为绑定为明确身份，不得按 `protocol_surface_code` 推导认证。generic_http 的三种 API Key 认证按规则 1 固定。

公共协议面的 upstream operation template 固定为：OpenAI `POST /v1/chat/completions`、`POST /v1/responses`、`POST /v1/images/generations`、`POST /v1/audio/speech`、`POST /v1/audio/transcriptions`、`POST /v1/audio/translations`、`POST /v1/audio/jobs`、`GET /v1/audio/jobs/{id}`、`GET /v1/audio/jobs/{id}/content`、`DELETE /v1/audio/jobs/{id}`、`POST /v1/videos`、`GET /v1/videos/{id}`、`GET /v1/videos/{id}/content`、`DELETE /v1/videos/{id}`、`GET /v1/realtime`；Anthropic `POST /v1/messages`、`POST /v1/messages/count_tokens`；Gemini native `POST /v1beta/models/{model}:generateContent`、`POST /v1beta/models/{model}:streamGenerateContent`、`POST /v1beta/models/{model}:countTokens`、`POST /v1beta/models/{model}:embedContent`、`POST /v1beta/interactions`、`GET /v1beta/interactions/{id}`、`DELETE /v1beta/interactions/{id}`、`POST /v1beta/interactions/{id}/cancel`。本地 `GET /v1/videos` 和 `GET /v1/audio/jobs` 不进入 operation template，也不选择上游。厂商媒体 preset 的 additional templates 必须由该 preset record 明确列出，数量和字符串由现有媒体协议契约固定；不能因没有公共模板而回退到 `/v1` 通用拼接。

## 2. 账户与连接面

账户能力域继续使用现行四值：chat、video、audio、image。能力域在创建时确定，编辑不可变更；克隆目标域必须等于源账户域；授权实例继承源账户域。一个账户只能属于一个域。克隆只适用于资源账户：服务端从源账户合成创建载荷，复制身份字段与重新加密的凭据，连接按 preset/Base URL/endpoint modes/enabled 原样重建（连接与映射行 ID 重新生成），支持模型、入口映射与 health-check 三字段按 preset 重新解析复制；新账户 `config_revision` 从 1 开始，不继承源 revision。分组绑定、授权关系、状态与运行态不复制，按新账户默认值；授权实例不提供克隆。

### 2.1 目标表

accounts 保留账户状态、所有者、凭据和不可变 capability_domain，并使用以下连接字段：

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| vendor_code | nullable enum | 只能是 §1.1 的真实厂商值；generic_http 账户必须为 NULL |
| connection_driver_code | nullable enum | 资源账户必填且为 §1.1 固定注册值；授权实例物理列为 NULL，读取时从 `resource_account_id` 投影 |
| account_type | nullable enum | 目标物理列名固定为 `account_type`；资源账户必填且由 §1.1 注册表约束；授权实例物理列为 NULL。迁移时旧 `accounts.type` 按 §10.1a 逐行转换 |
| oauth_type | nullable enum | 资源账户仅 `account_type=google_oauth` 时必填且只允许 `code_assist`、`google_one`、`ai_studio`；其它资源账户必须为 SQL `NULL`；授权实例为 SQL `NULL` |
| credentials_encrypted | nullable encrypted JSON | 资源账户必填，只保存 connection driver 所需凭据；授权实例为 NULL，不复制来源凭据；不得保存 base_url、endpoint modes、目标账户或分组 ID |
| capability_domain | nullable enum | 资源账户必填且为 chat、video、audio、image，创建后不可修改；授权实例为 NULL，读取来源账户的有效域 |
| health_check_connection_id | nullable text | 资源账户在事务外必须非 NULL，指向本资源账户已启用连接；授权实例必须为 NULL，读取来源账户的有效值；与资源账户 id 构成复合外键 |
| health_check_endpoint_mode | nullable enum | 资源账户在事务外必须非 NULL，必须属于 health_check_connection_id 的 mode；图片检查固定为 images_json；授权实例必须为 NULL。数据库 CHECK 与 `account_endpoint_modes.endpoint_mode` 词表必须精确覆盖 §2.2 的 25 个值，不得沿用旧的 22 值 |
| health_check_model_id | nullable text | 资源账户在事务外必须非 NULL，指向本资源账户支持模型并声明 health_check_endpoint_mode；授权实例必须为 NULL |
| config_revision | int64 | 资源账户从 1 开始，管理面配置事务或 OAuth credential rotation 改变有效凭据时各递增 1；授权实例固定为 0，网关和管理面使用来源账户的 `resource_config_revision`；见下方 revision 规则 |
| authorization_instance_authorization_id | nullable text FK → `resource_authorizations.id` | 授权实例判别字段；非 NULL 时必须同时填写 source 与 owner 两字段，且三者只能描述同一条 `resource_type='account'` 授权；普通资源账户必须为 NULL |
| authorization_instance_source_account_id | nullable text FK → `accounts.id` (`ON DELETE RESTRICT`) | 仅授权实例可填写；必须指向非授权的真实资源账户，禁止自指和链式授权；普通资源账户必须为 NULL |
| authorization_instance_owner_system_account_id | nullable text FK → `system_accounts.id` | 仅授权实例可填写；必须等于授权记录的 `resource_owner_system_account_id`，且该 owner 必须等于来源资源账户的 `system_account_id`；普通资源账户必须为 NULL |

目标账户的身份判定固定为 `authorization_instance_authorization_id IS NOT NULL`。授权实例必须同时满足 `authorization_instance_authorization_id`、`authorization_instance_source_account_id`、`authorization_instance_owner_system_account_id` 全部非 NULL；资源账户必须三者全部为 NULL。授权实例的授权行必须存在、`resource_type='account'`、`resource_id=authorization_instance_source_account_id`、`resource_owner_system_account_id=authorization_instance_owner_system_account_id`，并且 `accounts.system_account_id` 等于该授权行的 `grantee_system_account_id`。任何一项不一致都返回 HTTP 409 `authorization_instance_invalid`，迁移时计入 `accounts_blocked`。

删除 accounts.provider_code、accounts.provider_protocol_profile_id 和 client_compatibility。vendor_code 为空不等于 custom 厂商；UI 应显示“自定义协议连接”，不能创建假的供应商记录。连接器与厂商一致性约束为：generic_http 必须 vendor_code=NULL；其它 connection_driver_code 的 vendor_code 必须与 driver registry 中声明值相等。

`credentials_encrypted` 在目标运行时不得保存或读取 `base_url`、`supported_endpoint_modes`、`oauth_type` 或 profile 元数据。所有模型/健康检查/媒体请求只读取选定 `account_connections.base_url` 和 `account_endpoint_modes`；同一账户多个 preset 各自使用自己的 Base URL。OAuth refresh、reauth 和 token exchange 的授权端点只读取 driver registry 的固定 auth endpoint；若某 driver 将来需要可配置授权端点，必须先在 registry 增加显式 auth-endpoint 字段和对应 preset，不能回退到凭据 JSON 或模型连接 Base URL。`accounts.oauth_type` 是 OAuth 分流的唯一运行时来源；refresh/reauth 事务必须以该列选择策略，并在重新加密凭据时删除 `oauth_type` 键，禁止再次写回密文。clone/export 读取该列，import 只能通过 `oauthType` 写列。

account_connections 每行代表账户上的一个可调用连接面：

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| id | text PK | 全局唯一，作为映射目标 target_connection_id |
| account_id | text NOT NULL FK | 账户删除时级联删除 |
| connection_preset_code | enum NOT NULL | §1.1 注册值 |
| protocol_surface_code | nullable enum | 若连接启用任一文本 mode，必须等于 preset registry 的 surface；纯媒体连接必须为 NULL |
| base_url | text NOT NULL | Unicode `TrimSpace` 后原样保存且长度为 1..2048 UTF-8 bytes；必须是带 hostname 的绝对 `http` 或 `https` URL，两个 scheme 均合法，不设置生产/测试 scheme 开关；不得有 userinfo、query、fragment、`.`/`..` path segment、无效 percent escape、percent-decoded slash/backslash 或非 UTF-8 path segment。path 可为空或为 registry `allowed_base_path_suffixes[]` 允许的 service/version 前缀；允许任意自定义前缀，但解码后的 path 必须以该 preset 的一个 suffix 结束。path 按 `/` 切段，每段 strict percent-decode 恰好一次用于安全检查和 template 匹配；匹配前去掉 path 末尾全部 `/`（空 path 保持空），因此 `/v1` 和 `/v1/` 等价。validator 逐段匹配该 preset 注册的全部 operation path template 后缀，并拒绝任何 operation template 的完整路径或中间前缀（例如 `/v1beta/models/foo`），但不得拒绝已登记的 service/version suffix。模板字面段区分大小写，`{name}` 仅匹配一个非空 path segment，嵌入式占位符匹配该 segment 的非空部分；命中完整 endpoint 或非登记 operation 前缀返回 HTTP 400 `invalid_connection_base_url`。模板与 route builder 来自同一 registry 项，不维护第二份 endpoint 清单。通过校验后 route builder 保留原始 encoded service prefix、去掉 path 末尾全部 `/`（根路径仍为 `/`），再追加一次 operation path，不对 path 使用 `path.Clean`。保存和每次出站都执行 [核心功能设计](核心功能设计.md) 的同一 SSRF/DNS/拨号校验；私网和 loopback 是否放行完全遵循既有 `URLSecurityConfig`，本设计不增加生产/测试分支 |
| enabled | bool NOT NULL | false 时不参加健康检查、直接候选或映射候选；管理 API 创建时必须显式提交 |
| created_at、updated_at | timestamp | 必填 |

唯一约束为 `(account_id, connection_preset_code)`。每个账户至少 1 行；最多行数按 driver 注册值固定为：generic_http 3、gpt 1、xai 1、deepseek 2、anthropic 1、Gemini api_key 2、Gemini google_oauth 1、glm 3、minimax 1、volcengine 2、qwen 1。账户可选择其中任意非空子集，不能用重复行表示不同模型或模式。`account_endpoint_modes` 正规化存储 `(connection_id, endpoint_mode)`，唯一键为该二元组。`images_json` 是 image 域唯一 mode，同时可作为图片模型健康检查形态；它不属于 chat 域。

`account_connections` 增加唯一键 `(account_id, id)`；`account_endpoint_modes.connection_id` 外键到连接。资源账户创建事务先写 accounts（health-check 三字段暂为 NULL），再写 connection/mode/model 关系，最后写 health-check 三字段并在提交前校验完整；授权实例创建不写这些资源字段。最终已提交资源账户的 health-check 三字段均非 NULL，且 health-check connection 必须 enabled；授权实例的三个物理列均为 NULL。禁用连接时，所有引用它的 enabled mapping 必须在同一事务内禁用、删除或改指向其他连接；disabled mapping 可以保留。删除连接采用 RESTRICT，所有 mapping（无论 enabled/disabled）都必须先删除或改指向其他连接；health-check 引用也必须在同一事务中改选完整三字段，否则分别返回 `connection_mapping_conflict` 或 `health_check_connection_conflict`。资源账户删除级联删除全部连接、mode、支持模型关系与映射；存在授权实例引用时先返回 HTTP 409 `authorization_source_conflict`，不得留下悬空授权实例。

`config_revision` 只在资源账户以下两类已提交写入时递增：管理面任一账户配置字段或其 connection/mode/supported-model/mapping 子集合发生实际变化时，每个事务加 1；driver 成功轮换 OAuth access/refresh credential 并写入新凭据时，通过 CAS 每次加 1。OAuth 用量快照、探针结果、账户状态、余额、排序和纯展示元数据变化不递增。无实际字段差异的 PATCH 加 0。授权实例固定保留 `config_revision=0`；管理面 `expectedConfigRevision` 和每次网关 attempt 均使用来源账户的 `resource_config_revision`。

授权实例的资源事实统一按 `resource_account_id = COALESCE(accounts.authorization_instance_source_account_id, accounts.id)` 解析；来源账户必须是非授权实例的真实资源账户，不允许授权实例再指向授权实例。`authorization_instance_source_account_id` 使用 `ON DELETE RESTRICT` 外键并建立索引；正常删除来源账户必须先解除全部授权实例引用。若维护工具发现历史数据中的来源 ID 缺失、已删除或自身也是授权实例，该实例计入 `accounts_blocked`，迁移停止，不自动回收或重建。凭据、driver/vendor、connections、endpoint modes、支持模型、入口映射和 health-check 三字段全部归 `resource_account_id` 所指的真实来源账户所有；`account_connections.account_id`、`account_supported_models.account_id`、`account_entry_mappings.account_id` 均存这个来源账户 ID，来源账户的 `config_revision` 作为 `resource_config_revision`。授权实例自己的状态、冷却、分组绑定和授权关系仍以实例 `accounts.id` 为准。授权实例读取来源配置，但不得通过实例 API 修改来源凭据或连接配置；该类 PATCH 返回 HTTP 403 `account_resource_read_only`。来源账户 owner 的配置 PATCH 才能更新来源事实。

`models.scope` 可见性固定为：`builtin`、`global` 对所有资源账户可见；`personal` 仅当 `models.system_account_id = resource_account.system_account_id` 时可见。所有 API、候选、健康检查和 mapping target 校验使用这条同一规则；不可见模型按不存在处理，写入时返回 HTTP 400 `model_not_visible`。授权实例沿用来源账户的模型可见性，不以实例 recipient 的 system account 重新过滤来源模型。

### 2.2 域与 endpoint mode 的完整约束

账户可声明的 mode 必须同时满足：

    AllowedModes = DomainLane(capability_domain) ∩ PresetVocabulary(connection_preset_code, account_type, oauth_type)

未知域、连接预设、账户类型、OAuth 类型或 mode 均拒绝；空交集意味着该预设不能用于该域。

域 lane 固定如下：

| chat | chat_json、chat_sse、responses_json、responses_sse、messages_json、messages_sse、message_token_counting、generate_content_json、generate_content_sse、interactions_json、interactions_sse、count_tokens、embed_content（共 13 个） |

Preset 词表固定如下：

## 3. 模型目录与 wire model 身份

provider_model_catalog 与 custom_provider_models 合并为唯一物理表 `models`。`account_supported_models.model_id` 和映射目标都外键到这张表，不存在跨表逻辑并集。所有模型价格字段保留原有供应商计费驱动语义，不在本次重构中增加统一价格维度、归一化公式或新的成本错误行为；计费实现仍以 [供应商独立计费与模型目录展示设计](供应商独立计费与模型目录展示设计.md) 为准。

`models` 的非价格列固定为：`id`、nullable `vendor_code`、`public_model`、`upstream_model`、`scope`、nullable `system_account_id`、`status`、`catalog_visible`、`catalog_order`、`release_date`、`shutdown_date`、`supported_endpoint_modes_json`、`supported_service_tiers_json`、`supported_reasoning_efforts_json`、`default_reasoning_effort`、`codex_supported_reasoning_levels_json`、`codex_default_reasoning_level`、`codex_multi_agent_version`、`context_window_tokens`、`max_input_tokens`、`max_output_tokens`、`max_tokens`、`supports_prompt_caching`、nullable `source`、nullable `pricing_notes`、nullable `capability_notes`、nullable `notes`、nullable `created_by`、nullable `updated_by`、`created_at`、`updated_at`。价格列固定保留：`input_usd_per_1m`、`output_usd_per_1m`、`cached_input_usd_per_1m`、`cache_write_usd_per_1m`、`cache_write_1h_usd_per_1m`、`cache_storage_usd_per_1m_per_hour`、`service_tier_prices_json`、`long_context_input_token_threshold`、`long_context_input_token_threshold_inclusive`、`long_context_input_cost_multiplier`、`long_context_output_cost_multiplier`、`image_input_usd_per_1m`、`image_output_usd_per_1m`、`audio_input_usd_per_1m`、`audio_output_usd_per_1m`、`output_usd_per_image`、`currency`。14 个数值列均允许 NULL，其中 13 个价格/倍率列使用 nullable PG `double precision` / SQLite `REAL`，`long_context_input_token_threshold` 单独使用 nullable INTEGER；`service_tier_prices_json` 为 JSON object，NOT NULL，默认 `{}`；`long_context_input_token_threshold_inclusive` 为 bool，NOT NULL，默认 false；`currency` 为 text，NOT NULL，默认 `USD`。`status` 精确枚举为 `draft`、`active`、`disabled`。JSON capability 列必须是 JSON array；scope 只允许 `builtin`、`global`、`personal`。

`provider_model_catalog.provider_code` 与 `custom_provider_models.provider_code` 统一为 `vendor_code`；两表的旧 `model` 列不保留，旧值写入 `upstream_model`，默认同时写入 `public_model`。`provider_model_catalog.scope` 固定迁为 `builtin`；custom 表原 `scope/system_account_id` 原样保留。两表不对称的列（例如 Codex 专属字段）均并入上面的列集，非适用行存 NULL 或空 JSON 数组。custom 表无 `source` 时写 NULL；builtin 的来源值原样保留。

物理类型固定沿用 Go/PG/SQLite 可移植映射：所有 ID、code、模型名、备注、日期和时间列均为 TEXT；`catalog_order`、token 上限和 `long_context_input_token_threshold` 为 nullable INTEGER；其余 13 个数值价格/倍率列为 nullable PG `double precision` / SQLite `REAL`；`catalog_visible`、`supports_prompt_caching`、`long_context_input_token_threshold_inclusive` 为非空 PG `boolean` / SQLite `INTEGER CHECK IN (0,1)`。四个 capability JSON 列和 `service_tier_prices_json` 均为非空 TEXT、分别通过 JSON array/object CHECK，默认 `[]`/`{}`。除 `status` 默认 `active`、`catalog_visible` 默认 true、`supports_prompt_caching` 默认 false、threshold-inclusive 默认 false、currency 默认 `USD` 外，不增加默认值；`created_at`、`updated_at` 必填。`release_date`、`shutdown_date` 保留源 TEXT 原值，不在本次变更引入日期解析或重写。

新增字段与唯一性规则：

| 字段 | 约束 |
| --- | --- |
| public_model | 客户端 /v1 请求使用的精确 model 字符串；1..256 UTF-8 bytes、非空、无首尾空白、无控制字符、区分大小写 |
| upstream_model | 实际发送给目标上游的原始模型字符串；1..256 UTF-8 bytes、非空、无首尾空白、无控制字符、区分大小写 |
| supported_endpoint_modes_json | 模型真实支持的精确 mode 集合，JSON 字符串数组，元素唯一且按 ASCII 升序；只允许第 2.2 节的 25 个值。active 模型至少 1 个 mode；draft/disabled 可以为空 |

每个模型的 id 全局唯一。`vendor_code` 只能为 NULL 或 9 个真实厂商值，空字符串拒绝。upstream/public 字符串比较使用 binary/case-sensitive 规则。模型身份唯一键为 `(COALESCE(vendor_code, ''), scope, COALESCE(system_account_id, ''), upstream_model)`；PostgreSQL 与 SQLite 均用同一组表达式唯一索引实现。`personal` 必须有 `system_account_id`，`builtin` 和 `global` 必须为空。同一账户可用的 `public_model` 唯一性由写事务保证：先锁定/串行化该 account 行，再校验该账户当前支持模型和映射源名称；冲突返回 HTTP 409 `account_public_model_conflict`，最后在同一事务写入。

`public_model` 是客户端 wire model；数据库 id 是内部身份；`upstream_model` 是发给上游的名字。三者不得互相替代。Builtin 行默认 `public_model=upstream_model`。需要 alias 时，用一个 models 行表达客户端名和目标名，不在请求链路按厂商名猜测。模型由 `vendor_code` 选择已有计费驱动；未知 vendor 的手工模型沿用现有手工价格契约。通用连接器不会成为价格归属，也不会覆盖目标模型的计费语义。

模型 vendor 与账户 connector 的兼容约束固定为：`generic_http` 可支持任一真实 `models.vendor_code` 或 NULL；真实厂商 driver 只可支持 `models.vendor_code` 等于该 driver 的 vendor，或 `models.vendor_code=NULL` 的手工定价模型；另一个非空 vendor 一律 HTTP 400 `model_vendor_driver_mismatch`。`accounts.vendor_code` 仍必须等于真实 driver registry 的绑定值，generic_http 必须为 NULL。模型 vendor 只决定目录归属和已有价格策略，绝不由 account driver 或 base_url 自动推导。

## 4. 账户支持模型与公开目录

`account_supported_models` 列为 `(account_id, model_id, created_at)`，主键 `(account_id, model_id)`，分别外键到 accounts 和 models。关系只允许 owner-visible 且 `status=active` 的模型。每账户至少绑定 1 个 active 模型；具体 usage 是否可计价按 endpoint family 执行现有 vendor-specific billing 规则，不设跨域统一 `priceable` 布尔值。健康检查模型必须在此集合中，并声明所选 health-check mode；账户写事务执行上一节的 model vendor/driver 约束。

新增或更新支持模型、mapping target、health-check model 时，目标模型必须为 `active` 且 owner-visible。`disabled` 模型不得新增任何支持关系、mapping target 或 health-check 引用；若已被这些关系使用，禁用事务必须同时解除全部支持关系和 mapping，并重选 health-check 三字段，否则返回 HTTP 400 `model_dependency_conflict`。物理删除模型采用 RESTRICT；只要仍被 `account_supported_models`、`account_entry_mappings` 或任一账户的 `health_check_model_id` 引用，就必须先删除或改指向其他模型，否则返回同一错误码。

文本 direct 候选和文本 mapping target 必须通过既有 vendor-specific direct-price 校验；缺少该厂商所需价格字段时分别返回 `model_unpriced` / `mapping_target_unpriced`，不把该模型当作可用文本候选。视频、TTS、转写、realtime 和图片模型不套用 token price 必填条件；它们由现有媒体或图像 billing driver 按实际 usage 解释，模型价格列可以为空，但必须存在对应 driver 的计费规则，否则写入返回 `model_billing_driver_missing`。这条判断按 target endpoint family 执行，不按账户 driver、protocol surface 或模型名猜测。

GET /v1/models 保留[网关模型列表账户并集设计](网关模型列表账户并集设计.md)的静态账户资格、授权门、错误和缓存语义；每个分组资格账户仍按其自己的 account ID 判定，但模型事实统一从 `resource_account_id` 读取。模型名集合改为可达资源账户中 active 且 endpoint mode 有效的 direct `public_model` 与 enabled mapping `source_model` 的去重并集。direct 项要求资源账户有对应 `account_supported_models` 行，且至少一个 enabled connection mode 同时存在于模型的 `supported_endpoint_modes_json`。`catalog_visible` 不参与成员资格；列表不按瞬时健康、冷却、并发或额度过滤。mapping 仅在 target connection enabled、target model active/owner-visible、target mode 同时被连接和模型声明时纳入。去重只按 binary 精确字符串，保留大小写。`/v1/models` 的 `id` 与客户端请求里的 model 都等于该字符串。跨资源账户的同名项允许存在，因为策略/分组/账户候选决定最终目标；单资源账户内冲突保存时以 HTTP 409 `account_public_model_conflict` 拒绝。

## 5. 账户入口映射

所有账户共用 account_entry_mappings。该表只做一跳模型/协议目标选择，不代表供应商、路由策略或目标账户引用。

### 5.1 字段和校验

| 字段 | 类型 / 约束 |
| --- | --- |
| id | 全局唯一 text PK |
| account_id | FK accounts.id |
| source_model | 客户端 wire model 字符串；1..256 UTF-8 bytes、无首尾空白、无控制字符、区分大小写；不要求存在于 models |
| source_endpoint_family | enum：chat_completions、responses、messages、generate_content、stream_generate_content、video_generation、tts |
| target_connection_id | FK `(account_id, target_connection_id)` → `account_connections(account_id, id)`；enabled mapping 的连接必须 enabled，disabled mapping 可暂存 disabled connection 引用 |
| target_model_id | FK `(account_id, target_model_id)` → `account_supported_models(account_id, model_id)`；模型必须 owner 可见且 active |
| target_endpoint_family | 精确目标 family；映射目标仅允许 chat_completions、messages、generate_content、video_generation、tts |
| enabled | bool |
| created_at、updated_at | timestamp |

唯一键为 `(account_id, source_model, source_endpoint_family)`。同账户可达的 direct `public_model` 与 enabled mapping `source_model` 不得相同；同一账户内两个可达 direct 模型也不得使用相同 `public_model`，保存时均返回 HTTP 409 `account_public_model_conflict`。disabled mapping 不参加这两个冲突集合，但重新启用时必须重新校验。`target_connection_id` 与 `target_model_id` 使用复合外键，数据库层保证 target 在同一账户连接和支持模型集合内；mode、连接 enabled、模型 active/owner-visible 由写事务再次校验。文本目标 family `chat_completions/messages/generate_content` 必须通过现有 vendor-specific direct-price 校验；媒体目标 family `video_generation/tts` 允许目录无模型价格列的媒体行，价格由现有媒体 billing driver 解释。不得把 `hasAnyPrice` 用作跨 family 的统一判据。映射行对其它账户不唯一，因此不同账户可以把同一客户端模型映射到各自目标模型。

禁用连接时，最终配置中不得保留引用该连接的 enabled mapping；请求必须在同一事务中把这些 mapping 禁用、删除或改指向其他连接，否则返回 HTTP 400 `connection_mapping_conflict`。如果 health-check 指向该连接，必须在同一事务中改选完整的 health-check 三字段，否则返回 HTTP 400 `health_check_connection_conflict`。管理 API 以 `targetConnectionPresetCode` 表示目标连接，数据库以 `target_connection_id` 外键保存解析后的连接 ID。disabled mapping 可以保留对 disabled connection 的引用，但不参与列表或候选。删除连接时，disabled mapping 也属于引用，必须先删除或改指向其他连接；任一残留都由 `connection_mapping_conflict` 拒绝。

其它固定规则：

1. Source 是客户端提交的字符串，不是模型目录外键；Target 是 models.id，不能只存一个有歧义的上游字符串。
2. source_model 长度超过 256 bytes、空字符串、首尾空白或控制字符返回 HTTP 400 invalid_source_model；不得 trim 后静默改写或做大小写折叠。
3. target vendor 规则遵循 §3 的“模型 vendor 与账户 connector 的兼容约束”；generic connector 不从 target vendor 推导连接器、认证或协议。
4. 目标连接、endpoint family、模型、mode 任一项未启用或不匹配，保存时 HTTP 400 mapping_target_unsupported；文本目标价格缺失返回 HTTP 400 `mapping_target_unpriced`。
5. 不允许链式映射、递归、账号/分组引用、全局自动降级或映射后再做第二次别名解析。
6. direct 命中和 mapping 命中互斥；mapping 命中后目标失效时该账户跳过，不能回退到同账户另一直接模型。

### 5.3 JSON/SSE mode 的唯一选择函数

映射不存一个模糊的“stream 支持”布尔值。运行时在候选账户上按下表计算唯一目标 mode；目标连接没有该 mode 时该账户不具备当前请求能力。下表同时列出 direct candidate 与 mapping candidate；`Responses` 原生行是 direct 分支，`Responses -> Chat bridge` 行是 mapping 分支，二者不会互相转换：

| 来源形态 | 客户端形态 | 目标 family | 目标 mode |
| --- | --- | --- | --- |
| Chat Completions | stream=false | Chat | chat_json |
| Chat Completions | stream=true | Chat | chat_sse |
| Responses | stream=false | Responses 原生 | responses_json |
| Responses | stream=true | Responses 原生 | responses_sse |
| Responses | stream=false | Chat bridge | candidate 不匹配，跳过该账户 |
| Responses | stream=true | Chat bridge | chat_sse |
| Responses | stream=false/true | Messages | messages_json/messages_sse 对应客户端形态 |
| Responses | stream=false/true | GenerateContent | generate_content_json/generate_content_sse 对应客户端形态 |
| Messages | stream=false | Messages | messages_json |
| Messages | stream=true | Messages | messages_sse |
| Chat / Messages | stream=false/true | 其它允许文本 family | 目标 family 的 JSON/SSE mode 与 stream 一一对应 |
| generate_content | JSON 请求 | 其它允许文本 family | 目标 JSON mode |

bridge 不因上游是否支持而静默切换 JSON/SSE。文本映射写入要求至少有一个 source shape 在目标 connection mode 与 target model mode 的交集中可执行；视频映射不适用该“至少一个”收窄规则，必须同时具备并启用 `video_create`、`video_get`、`video_content`、`video_cancel` 四个 mode。运行时只让匹配当前形态的 mapping 进入候选。目标 mode 缺失时记 `endpoint_mode_unsupported` 并跳过该账户，不把请求级差异误报为全局 400。因 `account_entry_mappings` 不保存 stream 字段，Responses→Chat 行可保存；它只对 `stream=true` 请求生效，`stream=false` 时跳过该账户。其它不在 17 个 family pair 中的映射仍在表单、API、导入处返回 400 `mapping_pair_unsupported`。

## 6. Bridge 错误、重试与切号冻结

沿用 [协议桥接框架设计](协议桥接框架设计.md) 的 passthrough / bridge / guidance / reject 四类结果，不引入 strict_reject 字段或静默丢弃策略。

| 结果 | HTTP / 客户端行为 | 调度行为 |
| --- | --- | --- |
| 全局请求非法（坏 JSON、必填缺失、权限/状态链非法） | HTTP 400，客户端协议对应的 invalid_request_error JSON envelope | 不发起上游请求、不切号 |
| 候选连接没有精确 endpoint mode、模型或映射目标失效 | 不立即回客户端；记 endpoint_mode_unsupported、model_unsupported 或 mapping_target_unsupported | 跳过该候选，按路由策略继续 |
| 目标协议无法保真承载请求能力 | account-scoped guidance，HTTP 200；JSON 返回 gateway_guidance.code=unsupported_capability 和精确 details.capability；SSE 返回该下游协议完整成功终止序列并携带相同 code/capability | guidance 属于当前候选；继续尝试同一候选池后续账户。全部候选都 guidance 时返回排序最前候选产生的 guidance |
| 连接/上游可重试失败 | 保留现有传输错误与审计原文 | 仅在下游未提交可见内容且请求可重放时切号 |
| 下游已经提交可见内容 | 保留已写响应并终止流 | 禁止同一响应透明切号 |

guidance 的 details.capability 必须是 bridge registry 中的稳定能力键；初始集合为 tools、json_schema、thinking、cache、hosted_tools、previous_response_state、audio、multiple_candidates、include、logprobs、safety_settings。新增键必须同时更新 bridge registry、JSON/SSE renderer 和 mock contract。Guidance 不写账号健康失败状态。

每个请求在进入调度前固定 source tuple：`source_model`、`client_endpoint_family`、`client_endpoint_mode`、客户端 JSON/SSE 形态和 canonical request context。每次尝试固定独立 target tuple：account_id、target_connection_id、target_model_id、target_endpoint_family、target_endpoint_mode、resource_config_revision。切号时从冻结的 canonical context 为下一候选重新转换，不复用上一候选的最终 body，也不回到客户端协议重新解释 opaque 上游状态。Responses opaque state 未能物化时只允许原生 Responses 候选。

### 6.1 普通与超级分组终态

重构后路由目标的候选全部被跳过或失败时，终态按模型目录和 dispatch 现有错误契约分类；超级分组只负责展开成员，不改变错误分类，不得新增一个“无候选”万能错误：

| 条件 | HTTP / code | 是否继续候选 | 审计要求 |
| --- | --- | --- | --- |
| 没有 active 路由目标 | 配置校验应已阻断；运行时 stale cache 沿用现有 empty-binding 处理 | 否 | `route_group_id=null`、`active_binding_count=0` |
| 请求模型没有一条对当前资源可见且 `status=active` 的 `models` 目录行（不存在、不可见、已禁用或已下线均属此类） | 404 `model_not_found` | 否 | 记录 `candidate_skip_reason` 计数；不得读取绑定账户来改变该分类 |
| 目录中存在可见且 active 的模型，但全部 active 绑定账户在支持模型、入口映射、连接 / endpoint mode、协议、授权或状态硬过滤后均无候选 | 503 `model_target_group_unavailable` | 否 | 记录逐账户硬过滤原因；不得降级成 404 |
| 候选均因组/授权配额超限 | fallback reason `authorization_quota_exceeded`；无回退时 HTTP 429 `rate_limit_exceeded` | 否 | 记录每个胜出组的 quota decision |
| 候选均为 guidance | 200，返回排序第一条候选的 guidance | 是，直到候选耗尽 | 不写健康失败；记录 `guidance_count` |
| 候选发生可重试上游错误且尚未提交可见内容 | `503 upstream_candidates_exhausted` | 是 | 每次 attempt 保留原始错误和 `route_rank` |
| 已提交可见内容或副作用已受理 | 保留已写响应并终止 | 否 | 禁止透明切号，记录 `response_committed=true` |

`model_not_found`、`model_target_group_unavailable`、配额终态、guidance、上游耗尽和已提交终止必须是互斥终态；一个请求只能落入一行。当前迁移前目录分支仍可能产出 `model_target_group_not_bound`，迁移完成后不得再用供应商目录判定该错误。实现不得用“无候选”统一覆盖配额、能力缺失、guidance 和上游失败。

## 7. 候选与路由策略顺序

四种路由模式及分组选择规则保持不变，超级分组展开属于分组域。每个请求按以下顺序处理：

1. API Key 与策略先确定本请求可用分组和分组尝试顺序。normal 只有一个分组；weighted 按现有权重选择起点；failover 从主分组顺序开始；round_robin 使用现有轮询起点。目标可以是普通分组或超级分组，但一次路由解析只选择一个目标。
2. 每个分组内先执行账户状态、授权、不可变 capability domain、请求 family/mode、模型、并发和其他既有硬过滤。
3. 符合 wire `public_model` 的直连候选标为 `route_rank=0`；符合 `account_entry_mappings` 的候选标为 `route_rank=1`。
4. normal、weighted、failover、round_robin 均在当前目标内使用统一排序键：`route_rank ASC -> existing account dispatch comparator -> member_priority ASC -> member_group_id ASC -> account_id ASC`。同一账号重复出现时保留最小 `(route_rank, member_priority, member_group_id)` 归属；因此后成员的 direct 可以胜过前成员的 mapping。普通目标候选耗尽后才按原策略规则尝试下一目标，normal 不跨目标。
5. 若当前目标是超级分组，按 `super_group_members.priority ASC`、同值 `member_group_id ASC` 展开启用的普通成员；逐成员执行同一硬过滤和 direct/mapping rank。成员目标失败按 `no_candidate`、`capacity_exhausted`、`upstream_exhausted`、`non_replayable` 分类；前三类且请求可重放时交回外层模式，成员不提升为路由级目标。
6. 候选硬过滤和排序之后，复用既有 dispatch / session / health / capacity comparator。超级分组的 `capacity_exhausted`、`upstream_exhausted` 和 `no_candidate` 必须沿一次性外层目标快照继续，最终错误分别固定为现有 `429 rate_limit_exceeded`、`503 upstream_candidates_exhausted`、`503 model_target_group_unavailable`；`non_replayable` 保留当前终态。验收必须检查最终派发序列、`route_group_id` 与 `member_group_id`，而不是只检查路由层片段顺序。

审计和使用记录至少保存：source model/family/stream 形态、连接器、nullable vendor、resource account ID、target connection/model/upstream model/family/mode、mapping 是否命中、`route_rank`、计费 model、来源账户 config revision、`route_group_id`、实际 `member_group_id`、实际 group account ID 和终态错误分类。每次切号都从 canonical request context 为下一个候选账户重新生成 target 请求。

## 8. 分组、管理面与 API

`groups.provider_code` 删除。分组目标列固定为 `id`、`system_account_id`、`name`、`description`、`enabled`、`is_default`、`group_kind`（`standard|super`）、`group_type`、`scheduling_policy_json`、`created_at`、`updated_at`；`name` 先做 Unicode `TrimSpace`，长度必须为 1..128 UTF-8 bytes，不得含控制字符，唯一比较使用 binary/case-sensitive 规则。目标唯一约束固定为 binary `(system_account_id, name)`，`group_accounts` 保留 `system_account_id`、`group_id`、`account_id`、授权引用、局部优先级/回退字段、启停和时间列，并以 `(group_id, account_id)` 作为唯一成员键；新增 `super_group_members(super_group_id, member_group_id, priority, enabled, ...)`，成员只能是同一 `system_account_id` 下的普通分组；每个 `system_account_id` 最多一个 `is_default=1` 分组。普通分组可以同时包含 §1.1 中任意厂商和 generic_http 账户，超级分组不直接绑定账号。

加入分组硬校验保留现有权限、归属、授权、状态规则，另要求资源账户至少有一个 enabled connection，并存在一个 owner-visible active 支持模型与该连接启用 mode 的交集。具体条件是 `∃ model, connection, mode: model.status=active AND model.owner_visible(resource_account) AND model∈account_supported_models(resource_account) AND connection.account_id=resource_account.id AND connection.enabled AND mode∈connection.endpointModes AND mode∈model.supported_endpoint_modes_json`。不要求分组内成员共享厂商、协议或计费模式；实际请求的模型、mode 和 vendor-specific billing 校验只在候选阶段执行。

账户表单固定四步：

1. 选择真实厂商 driver；未知厂商选“自定义协议连接”。这个选项写 vendor_code=NULL、connection_driver_code=generic_http，不创建供应商行。
2. 选择 connection preset、账户类型和固定能力域；填写该连接自己的 Base URL 与 endpoint modes。
3. 配置账户支持模型和健康检查模型。
4. 可选配置入口映射；源模型为客户端 wire model 字符串，目标为本账户 connection preset + model + endpoint family。

UI 不得出现“OpenAI 兼容供应商”“混合供应商”“Hybrid 分组”卡片；可显示“自定义协议连接”作为连接器选项。前端模型选择必须区分 wire model 与 target model。

账户创建/更新接口目标 JSON：

    {

      "connectionDriverCode": "generic_http",
      "accountType": "api_key",
      "oauthType": null,
      "capabilityDomain": "chat",
      "credentials": { "api_key": "<redacted>" },
      "connections": [
        {
          "connectionPresetCode": "generic_openai_v1",
          "protocolSurfaceCode": "openai_v1",
          "baseUrl": "https://example.invalid/v1",
          "endpointModes": ["chat_json", "chat_sse"],
          "enabled": true
        }
      ],
      "supportedModelIds": ["model-id"],
      "healthCheckConnectionPresetCode": "generic_openai_v1",
      "healthCheckEndpointMode": "chat_json",
      "healthCheckModelId": "model-id",
      "entryMappings": [
        {
          "sourceModel": "client-model-name",
          "sourceEndpointFamily": "responses",
          "targetConnectionPresetCode": "generic_openai_v1",

          "targetEndpointFamily": "chat_completions",
          "enabled": true
        }
      ]
    }

接口禁止 providerCode、providerProtocolProfileId、clientCompatibility、hybrid、explicitHybridRouteRules、targetAccountId、targetGroupId；`credentials.base_url` 和 `credentials.supported_endpoint_modes` 返回 HTTP 400 `legacy_connection_field`，只接受连接行中的 `baseUrl` 和 `endpointModes`。未知字段返回 HTTP 400 `unknown_field`；不忽略旧字段。

资源账户创建时 `vendorCode`、`connectionDriverCode`、`accountType`、`oauthType`、`capabilityDomain`、`credentials`、非空 `connections`、非空 `supportedModelIds`、`healthCheckConnectionPresetCode`、`healthCheckEndpointMode`、`healthCheckModelId` 和 `entryMappings` 数组全部必填；无映射时提交 `entryMappings: []`。每个 `connections[]` 元素必须提交 `connectionPresetCode`、`protocolSurfaceCode`（纯媒体为 null）、`baseUrl`、非空 `endpointModes` 和 `enabled`；每个 `entryMappings[]` 元素必须提交 `sourceModel`、`sourceEndpointFamily`、`targetConnectionPresetCode`、`targetModelId`、`targetEndpointFamily` 和 `enabled`。连接 ID 永不由客户端提交：`connectionPresetCode` 是账户内自然键，且每个 preset 最多一行；`connections` 重复 preset 返回 HTTP 400 `connection_capability_unsupported`。更新时 `connections` 全集合替换，保留仍存在 preset 的数据库 ID，为新 preset 服务端生成 ID，删除未提交 preset。每个映射的 `targetConnectionPresetCode` 与健康检查的 `healthCheckConnectionPresetCode` 必须解析到最终连接集合中的一行，否则分别返回 `mapping_target_unsupported` 或 `health_check_connection_conflict`。更新沿用账户 PATCH 入口并要求 `expectedConfigRevision`；它必须等于资源账户当前 `resource_config_revision`，否则 HTTP 409 `config_revision_conflict`。`vendorCode`、`connectionDriverCode`、`accountType`、`oauthType`、`capabilityDomain` 是账户身份字段，PATCH 不得修改；显式提交的 `null` 也按值比较，只有与当前 SQL NULL 相同才算无变化，需要改变其中任一字段时必须新建账户或走迁移。任一集合字段出现时整集合替换，不做追加或按 ID 合并；connections、supportedModelIds 不能为空，entryMappings 可为空。重复 `supportedModelIds` 返回 HTTP 400 `duplicate_supported_model`；映射行以 `(sourceModel, sourceEndpointFamily)` 为自然键，重复 natural key 返回 HTTP 409 `mapping_source_conflict`，省略即删除。健康检查三个字段必须同时出现或同时省略。被省略的配置字段保持原值。服务端用最终合并配置执行全部 registry、FK、owner、mode、名称冲突和健康检查校验，并在一个事务内全成全败；配置内容有变化时资源账户 `config_revision` 恰好递增 1，纯元数据字段不递增。

OAuth 管理式建户（gpt / xai / anthropic / gemini 四家 OAuth 专用路由）不暴露 `connections` 与健康检查连接维度入参：服务端按 §2 组合表按 vendor 与账户类型派生缺省连接集合——`connectionPresetCode` 取该组合唯一预设，`baseUrl` 取 §1.1 注册表 `default_base_url`，`endpointModes` 取 `AllowedModes(chat, preset, account_type, oauth_type)` 全集（§2.2 收窄照常生效）；健康检查三件套缺省取该 preset、连接的 JSON 检查形态与支持模型集内首个声明该形态的模型（目标 schema 已删除档案 `default_health_check_model`，§9.3；无模型声明时回落首个支持模型），用户显式提交的健康检查字段优先。派生载荷进入同一创建事务接受本节全量校验，必填门不放宽。

账户导入/导出复用同一 wire schema：连接只写 `connectionPresetCode`，映射与健康检查只引用 preset code，不导出 `account_connections.id`、mapping row ID 或数据库外键值；导入时服务端重新生成内部 ID 并按 preset 解析全部引用。凭据导入仍走现有敏感数据加密与脱敏规则。目标 schema 下导入链的供应商读取面只查 `vendors`；旧导出文件中的 `providerProtocolProfileId` 仅作非空身份载荷（协议码/版本按 vendor 确定性派生，不再做档案行匹配），generic_http 的旧 `openai` 词根在导入读取面合成为兼容条目并沿用旧 generic 缺省模型（来源显式携带 models 时优先）。

## 9. 目标 schema

一次性完成以下 schema 裁决：

1. providers 表改名为 vendors，只保留 §1.1 九个真实厂商；删除 openai 和 hybrid 行，`accounts.vendor_code` 与 `models.vendor_code` 外键到 `vendors.code`。
2. connection driver、connection preset、protocol surface 及其允许矩阵只存在于共用编译期 registry；不创建这三种数据库表。generic_http 只在该 registry 中，不得插入 vendors。
3. 删除 provider_protocol_profiles 数据表；由 connection preset registry 绑定 `connection_driver_code`、`protocol_surface_code`、URL builder、认证策略和 endpoint mode 集合。
4. accounts.provider_code 改为 nullable vendor_code + resource-account-only connection_driver_code；物理列 `type` 重命名为 `account_type`；删除 provider_protocol_profile_id；新增 `authorization_instance_authorization_id`、`authorization_instance_source_account_id`、`authorization_instance_owner_system_account_id` 三个 nullable FK，分别引用 `resource_authorizations.id (ON DELETE RESTRICT)`、`accounts.id (ON DELETE RESTRICT)`、`system_accounts.id`，索引分别为 `idx_accounts_authorization_instance_authorization`、`idx_accounts_authorization_instance_source`、`idx_accounts_authorization_instance_owner`，并按 §2.1 的三字段一致性约束落库。资源账户的 driver/account_type/credentials/capability/health-check 列必须完整；授权实例这些物理列为 NULL、`config_revision=0`，所有读取通过 `resource_account_id` 投影。
5. 新增 account_connections 与 account_endpoint_modes；Base URL 属于连接行，capability_domain 继续属于账户。
6. 将 provider_model_catalog、custom_provider_models 合并为 models 单表，按第 3 节列集保留两表全部非价格字段和价格字段，增加 public_model、upstream_model、supported_endpoint_modes_json；不改变价格字段或供应商计费驱动。
7. account_supported_models 改为 `(account_id, model_id)`，以该复合键供映射和健康检查外键引用；移除 `(provider_code, model)` 双键依赖。
8. account_model_mappings 改为 §5 的 account_entry_mappings；source 存精确字符串，target 全部使用外键 ID。
9. 删除 groups.provider_code；保留 groups 除 provider 字段外的既有列，目标列固定为 §8 列表，`name` 按 §8 的 binary/case-sensitive 规范化处理，新增 `group_kind`、`super_group_members` 及其外键和唯一约束。超级分组只能引用同 owner 的普通分组，不能自引用、嵌套或直接拥有任何 `group_accounts`；disabled 草稿允许 0..20 个成员行，启用或绑定到路由时 enabled 成员必须为 `2..20`，成员行总数始终不得超过 20。`group_kind` 不允许普通 PATCH 改变，成员外键使用 `ON DELETE RESTRICT`，被引用普通分组删除、禁用或改类型必须先解除引用。新增唯一约束 `(system_account_id, name)` 和唯一部分索引 `(system_account_id) WHERE is_default=1`，每 owner 最多一个默认组；普通分组保留 `group_accounts` 为唯一成员关系表。
10. usage、audit、model check、导入导出全部分别记录 nullable vendor、connection driver/surface、source wire model、target model ID 和 target mode；不得把协议面写进 vendor 字段。
11. 删除所有旧字段和旧 seed；不提供兼容视图、触发器、API 双读、配置开关或旧字段回退。目标 `accounts` 表明确不得保留 `provider_code`、`provider_protocol_profile_id`、`protocol_code`、`protocol_version`、旧字符串 `health_check_model` 和 `client_compatibility`；目标只保留 `health_check_model_id`，`health_check_endpoint_mode` 重建为 §2.2 的 25 值约束。旧 `provider_protocol_profiles`、profile family、provider default health-check 表及其索引/seed 一并删除；旧 JSON 的 `base_url`、`supported_endpoint_modes`、`oauth_type` 只允许作为 maintenance migration input，不能成为目标运行时字段。`client_compatibility` 不进入目标运行时 schema；历史值只写入迁移报告的字段计数与 source snapshot hash，不复制到新账户、连接或映射。

**SQL CHECK 与事务提交边界（硬规则）：** SQL `CHECK` 只表达单行可验证约束：`authorization_instance_authorization_id`、`authorization_instance_source_account_id`、`authorization_instance_owner_system_account_id` 三个授权实例字段必须全 NULL 或全非 NULL；资源账户的这三个字段必须全 NULL；授权实例的 `vendor_code`、`connection_driver_code`、`account_type`、`oauth_type`、`credentials_encrypted`、`capability_domain`、`health_check_connection_id`、`health_check_endpoint_mode`、`health_check_model_id` 必须全为 NULL 且 `config_revision=0`；资源账户的 `connection_driver_code`、`account_type`、`credentials_encrypted`、`capability_domain` 必须非 NULL（`vendor_code` 按 §2.1 保持可空）且 `config_revision>=1`，health-check 三字段在单行上必须同 NULL 或同非 NULL；`oauth_type`、`endpoint_mode`、`account_type`、状态和布尔值只能取注册表枚举。health-check 三字段不得做成 NOT NULL CHECK：连接行依赖账户行先存在，创建事务必须先插入 accounts（三字段暂为 NULL）、再写 connection/mode/model 关系，最后在提交前补齐且三字段必须在同一条 UPDATE 内写入，避免语句级 CHECK 看到半更新；因此「资源账户已提交时三字段完整非 NULL」属于事务级校验。跨表约束不得伪装成单行 CHECK，必须在同一事务提交前最终校验：授权行的 owner/grantee/resource type/id、来源账户非授权且不可链式、资源账户提交时 health-check 三字段完整非 NULL 且 connection enabled、connection/mode/model 匹配、mapping target connection/model/mode、模型 owner-visible、账户支持模型关系和 connection enabled 状态。PostgreSQL 可使用 deferred FK，但仍必须在提交前执行上述业务校验；SQLite 在事务提交前执行同一校验并在失败时回滚。任何失败返回对应固定错误码，禁止依赖后续读请求才发现半成品。

三字段互斥性由 SQL `CHECK` 表达，owner/grantee/resource type/id 及来源账户类型由事务校验表达；不得新增兼容 trigger 或把跨表关系下沉为数据库默认值。

## 10. 确定性迁移

迁移命令由 maintenance 实现，先在隔离库验证。dry-run 只读业务数据库，并把可复核清单写到 `--manifest-out`；正式执行读该清单。命令固定为：

    juhe-ai-maintenance --migrate-provider-connection-model --dry-run --manifest-out <path>
    juhe-ai-maintenance --migrate-provider-connection-model --manifest <path> --manifest-sha256 <sha256> --backup-id <id> --backup-receipt <path>

manifest `format_version` 固定为 1；每个 source row 记录 source table/PK、target table/PK、目标字段、判定规则、证据来源和错误，并附各 source table row count、source snapshot hash、source/target schema version 与 UTC 创建时间。manifest 不得包含明文凭据、API key、OAuth token 或解密后 credential；正式执行按 source PK 从数据库直接复制加密 credential。`manifest-out` 是唯一 dry-run 写入；dry-run 不得修改任何数据库或运行时文件。正式执行必须重算 source snapshot hash 并逐字段复核 manifest，任一变化均返回 `migration_source_changed`。`backup-receipt` JSON 固定为 `{"format_version":1,"backup_id":"...","completed_at_utc":"...","restore_tested":true,"targets":[{"kind":"postgres_dump|sqlite_file","logical_name":"...","size_bytes":123,"sha256":"<64 lowercase hex>"}]}`；PostgreSQL dump 和每个 SQLite 目标文件各占一个 target，`sha256` 为该备份文件原始 bytes 的 64 位小写十六进制 SHA-256。缺项、重复 target、目标集合不全或任一 hash/size 不匹配返回 `migration_backup_unverified`。
manifest 中的专项裁决对象字段固定为：`connection_base_url_override={source_table,source_pk,evidence,new_base_url}`；`mapping_disposition={source_table,source_pk,resolution,reason,target_connection_preset_code,target_model_id,target_endpoint_family}`；`health_check_override={resource_account_id,connection_preset_code,endpoint_mode,model_id,evidence}`。同一 source row 至多 1 个 `connection_base_url_override` 或 `mapping_disposition`，且新 Base URL、mapping target 和 health-check target 必须重新通过目标 registry、FK、owner、mode 与 URL validator。public model 冲突对象使用迁移规则 13 的完整字段；health-check 阻塞对象使用 `{resource_account_id,reason,candidate_connection_ids[],candidate_model_ids[],source_fields_hash}`。缺少专项对象、对象重复、引用不存在或对象中的新值未通过目标 schema 校验，分别计入对应 blocked 计数，不能把缺失当作“无裁决”。`connection_base_url_override.evidence` 与 `health_check_override.evidence` 统一为 JSON object `{source_table,source_pk,source_fields,retrieved_at_utc}`：`source_table`/`source_pk` 指向被裁决的源行，`source_fields` 记录参与判定的源列名与 canonical 值 hash（不得含明文凭据或 token），`retrieved_at_utc` 为 dry-run 读取时间的 RFC3339 UTC 字符串。

`source_snapshot_hash` 固定为 SHA-256(canonical source snapshot bytes)。canonical snapshot 使用 UTF-8 JSON、无 BOM、无空白缩进；对象键按 UTF-8 字节序排序；字符串不转义非 ASCII，必须转义 `"`、`\` 和 U+0000..U+001F（`\b`、`\f`、`\n`、`\r`、`\t` 用短写，其余用小写 `\u00xx`），不转义 `/`。table 按 UTF-8 字节序排序，column 按源 schema ordinal 排序，row 按完整 primary-key tuple 各 cell 的 compact JSON bytes 做字节序比较，row 内 cell 与 column 顺序一致。每个 cell 用 `[type_tag, value]` 表示：NULL=`["null",null]`、TEXT=`["text",原字符串]`、INTEGER=`["integer",十进制字符串]`、REAL/DOUBLE=`["real64",16 位小写 IEEE-754 bit hex]`、BOOLEAN=`["boolean",true|false]`、BLOB=`["blob_base64",标准 Base64]`、timestamp=`["timestamp_utc",RFC3339Nano UTC 字符串]`。snapshot 包含 source schema version、表名、列名/源 SQL 类型、主键声明和全部 source row。manifest 使用 UTF-8 JSON 且无 BOM；`--manifest-sha256` 比较输入文件的原始字节 SHA-256（64 位小写十六进制），不对解析后对象重新计算文件 hash。正式执行使用同一 serializer 从当前源库重建 bytes，再比较 `source_snapshot_hash`；不允许只比较 row count。

`generated_target_ids` 只允许用于迁移器确实生成、且没有对应 source row 的目标记录；每张目标表在 manifest 中单独列出该数组和生成原因。没有该字段的目标表按空数组处理，不能用默认 seed 或运行时副作用偷偷增加目标计数。

正式执行的硬门槛是：

- accounts_blocked=0
- connections_blocked=0
- models_blocked=0
- account_supported_models_blocked=0
- mappings_blocked=0
- groups_blocked=0
- health_checks_blocked=0
- history_rows_unmatched=0
- public_model_conflicts=0
- 所有 manifest 的 source row 数与 dry-run 快照一致
- manifest SHA-256 精确匹配，backup receipt 完整且 `restore_tested=true`

逐类映射规则：

0. 迁移开始先对每个旧 `accounts.provider_code` 做 binary 精确校验；允许集合固定为 `gpt`、`xai`、`deepseek`、`anthropic`、`gemini`、`glm`、`minimax`、`volcengine`、`qwen`、`openai`、`hybrid` 共 11 个值。SQL NULL、空字符串、首尾空白、大小写变体、未知值和已删除供应商值一律计入 `accounts_blocked`，manifest `reason=provider_unsupported`；不得归入 `generic_http`，也不得从模型、Base URL 或显示名推断供应商。该账户的子表行不再重复增加 `connections_blocked`、`models_blocked`、`mappings_blocked` 或 `health_checks_blocked`，以保证每个无效账户只计 1 次；fixture 必须覆盖 NULL、空白和未知值。

1. 仅对资源账户应用旧真实供应商 gpt/xai/deepseek/anthropic/gemini/glm/minimax/volcengine/qwen 的 driver 映射；它们直接迁为同 vendor 与 connection driver，profile ID 按 §1.1 固定表唯一变为 connection_preset_code，旧 profile protocol/version 映射到唯一 surface。profile/URL/type/mode 出现不在固定表的组合时计入 `connections_blocked`。
1a. 旧 `accounts.type` 按 binary 精确值迁移到目标 `account_type`：`api_key`→`api_key`、`oauth`→`oauth`、`google_oauth`→`google_oauth`；空值、首尾空白、未知值或与最终 driver/vendor/oauth_type/preset 不相容时计入 `accounts_blocked`。授权实例以 `authorization_instance_authorization_id IS NOT NULL` 判定，目标 `account_type` 固定为 SQL `NULL`；其旧 `type` 原值只写入 `discarded_legacy_fields`，不因非 NULL 阻塞，但三项授权字段不完整或授权/来源/owner 不一致仍按规则 9 计入 `accounts_blocked`。

1b. `config_revision` 迁移不执行隐式递增：资源账户目标值固定为 `max(1, source.config_revision)`；源值为 SQL NULL、0 或负数时写 1，正整数原样保留。manifest 必须同时记录 `source_config_revision` 和 `target_config_revision`，并断言二者满足该公式；正式迁移完成后只有后续真实配置事务才按 §2.1 的规则 `+1`。授权实例目标值固定为 0，不能继承来源 revision。
2. 对资源账户，旧 provider_code=openai 一律迁为 vendor_code=NULL、connection_driver_code=generic_http；不根据 Base URL、模型名、API key 前缀或账号显示名提升为 gpt。只有 manifest 对单账户明确填写真实 vendor、driver 和证据来源时才允许改为官方 driver。
3. 对资源账户，旧 provider_code=hybrid 一律迁为 vendor_code=NULL、connection_driver_code=generic_http。旧 mapping 表只有 `account_id/provider_code/source_model/source_endpoint_family/upstream_model/upstream_endpoint_family/enabled`，没有 mapping 级 profile 或 Base URL；因此目标 connection 只能按下表由 `upstream_endpoint_family` 确定，不能声称读取不存在的 mapping profile：

   | 旧 `upstream_endpoint_family` | 目标 `connection_preset_code` | 目标 surface / mapping target family |
   | --- | --- | --- |
   | `chat_completions`、`responses`、`video_generation`、`tts` | `generic_openai_v1` | `openai_v1` / 原 family（`video_generation`、`tts` 保持原值） |
   | `messages` | `generic_anthropic_v1` | `anthropic_v1` / `messages` |
   | `generate_content`、`stream_generate_content` | `generic_gemini_v1beta` | `gemini_v1beta` / `generate_content` |

   旧 Hybrid profile ID 的唯一迁移表为：`profile_hybrid_openai_chat_v1`→`generic_openai_v1/openai_v1`，`profile_hybrid_anthropic_messages_v1`→`generic_anthropic_v1/anthropic_v1`，`profile_hybrid_gemini_native_v1beta`（若源库存在该 ID）→`generic_gemini_v1beta/gemini_v1beta`。源库出现其它 `profile_hybrid_*` 必须计入 `connections_blocked`，不能按前缀猜测。

    旧 `provider_protocol_profile_id` 只作为没有 mapping 目标族时的账户级默认 profile；Hybrid 映射目标族优先使用上表。表外 family 计入 `mappings_blocked`。同一资源账户同一 preset 的所有 mapping 共享一个 connection，mode 集合取旧账户已启用 mode 与该 preset 词表的交集；交集为空则计入 `connections_blocked`。若同一账户同一 preset 出现多个 canonical Base URL，按 §1.1 规则计入 `connections_blocked`。旧 Hybrid 账户的全部 mapping 必须落在同一个 `capability_domain`；若同时出现 chat、video、audio 或 image 中两个及以上域，计入该账户一次 `accounts_blocked`，其子 mapping 不重复计数，必须在迁移前离线拆成多个独立源账户后再运行迁移；`mapping_disposition` 不得创建或隐式复制账户。Base URL 必须来自旧账户保存值、旧 profile 默认值或 manifest 的明确覆盖，不从目标模型厂商猜测。
4. Hybrid 目标模型通过旧映射 (provider_code, upstream_model) 精确匹配旧内置/自定义模型行；0 个或多个候选时必须 manifest 指定新 target_model_id，否则阻塞。不得按模型字符串前缀猜 vendor 或价格。
5. 旧 account_supported_models 通过原 provider/model 唯一映射 models.id；如果 old Hybrid provider/model 在新模型目录中无唯一目标，manifest 必须显式指定。目标厂商归属和 billing profile 独立于账户 vendor_code。每条支持关系最终还必须满足目标模型 `status=active`、owner-visible、存在于目标资源账户可见域且 `model_id` 唯一；指向 disabled/draft/下线/不可见模型，或来源账户 owner 与目标模型 owner 不一致时，不得静默删除或改指向，记录 `account_supported_models_blocked`，manifest 必须给出 `resolution=map` 的合法 `target_model_id` 或 `resolution=blocked`。任何未解决 disposition 都阻止正式迁移。
6. 旧 mapping 的 source_model 原样转为 source_model 字符串，不要求匹配模型目录；upstream_model 必须唯一转换成 target_model_id，否则按第 4 条阻塞。
6a. 每条旧 mapping 在写入前必须同时通过 target connection、target model、target endpoint family 和 mode 校验：target connection 必须由 §10.3/健康检查连接生成规则唯一解析，target model 必须 `status=active` 且 owner-visible 并属于该资源账户支持模型，`upstream_endpoint_family` 必须能落入 §5.2/§5.3 的允许目标 family，且至少有一个可执行 mode。任何一项失败都生成 `mapping_disposition`：`resolution=map` 时必须给出通过全部校验的新 preset/model/family，`resolution=blocked` 时计入 `mappings_blocked` 并阻止正式迁移；不得先写入无效 mapping 再依靠目标 FK 或 PATCH 失败兜底。旧 `enabled=0` 仍必须有合法 target 才能保留为 disabled mapping；不能用 disabled 标志掩盖坏 target。应用 `resolution=rename_mapping_source` 后还必须检查 `(account_id,new_source_model,source_endpoint_family)` 自然键不与任何现有或另一条迁移 mapping 重复，否则计入 `mappings_blocked`。
7. 旧能力域按已物化 accounts.capability_domain 原样迁移。旧 supported_endpoint_modes 与目标域/preset 交集不一致时阻塞，不静默裁剪；域字段缺失也阻塞，不从模型/模式猜域。
8. `groups.provider_code` 丢弃，但不能只删除列后保留行数。新唯一身份为 `(system_account_id, name)`，默认唯一也按 `system_account_id` 约束；同一 `system_account_id` 下因旧 provider 维度形成的同名组或多个 `is_default=1` 组先在 dry-run 计入 conflict。无冲突组逐行保留原 `group_id`。冲突只能由 manifest 显式解决：`resolution=rename` 时保留各组 ID、给每个目标行指定唯一 `name`；`resolution=merge` 仅在成员、授权、配额、调度参数和启停语义的字段级等价哈希一致时允许，并指定唯一 survivor、字段来源、`group_accounts` / `route_strategy_groups` / 授权引用重映射和默认组保留者。任何未解决冲突、字段不等价、引用缺失或默认组未唯一化都计入 `groups_blocked` 并阻止正式执行；不得自动合并、删除组或改变授权。迁移后每个 `(system_account_id, name)` 至多一行、每个 `system_account_id` 至多一个默认组。
8a. 旧 `route_strategies.mode='merge'` 不进入目标运行时。迁移器按旧策略全部 enabled/disabled 绑定顺序生成或复用一个 `group_kind=super` 的超级分组，写入 `super_group_members` 后把策略改写为单个超级分组绑定的 `normal`；绑定少于 2 个、超过 20 个、跨 owner、成员非普通分组、成员不存在或授权/调度指纹不一致时计入 `groups_blocked`，不得截断、拆分或静默降级。manifest 必须记录 `source_route_strategy_id`、源绑定 ID、`target_super_group_id`、目标成员 ID、`target_route_mode=normal` 和阻断原因；账号、模型、授权和配额事实不得复制。
9. 授权实例由旧 `authorization_instance_authorization_id IS NOT NULL` 判定。迁移必须原样保留 `authorization_instance_authorization_id`、`authorization_instance_source_account_id`、`authorization_instance_owner_system_account_id` 三列；三列缺一、授权行不存在、授权行不是 `resource_type='account'`、`resource_id` 不等于 source、授权 owner 不等于 owner 列、source 不存在/已删除/自身为授权实例、source.system_account_id 不等于授权 owner，或实例 `accounts.system_account_id` 不等于授权 grantee 时，按 `accounts_blocked` 计数并阻止正式迁移。有效授权实例不复制来源账户的 connections、endpoint modes、supported models、mappings 或 health-check；仅保留实例自己的 `accounts` 运行态、授权关系和 `group_accounts`。所有实例请求通过 source 读取来源事实；目标 schema 以 `ON DELETE RESTRICT` 阻止删除仍被引用的来源账户，迁移不得自动回收、重建、改绑授权或把实例升级为资源账户。
10. 模型表合并按原模型 ID 保留 ID。两张旧表存在同一 owner/scope/vendor/model 冲突时，必须 manifest 指定保留行与字段合并来源；字段冲突不得采用“最后写入”。`provider_model_catalog` 设 `scope=builtin`；旧 `model` 写入 `upstream_model` 和默认 `public_model`；`custom_provider_models` 保留 scope/owner。旧 `mode` 与 `supported_api_protocols_json` 不足以唯一确定新 mode，manifest 必须为每个模型明确给出 `supported_endpoint_modes_json`；缺失计入 `models_blocked`。所有共有价格列按 source row 原值复制；provider catalog 缺少 `currency` 时填 `USD`，custom row 原值保留。文本 mode 缺少对应 vendor-specific 价格时计入 `models_blocked`；媒体 mode 仅在对应 billing driver 已注册时通过。两源价格字段冲突必须在 manifest 逐字段指定来源，不换算汇率、不拆分、不重算服务档位或长上下文价格。旧 openai/hybrid 模型行若不能唯一确定 vendor 和完整 mode 集合，manifest 必须逐行指定，否则阻塞。
11. 历史 usage/audit/check 以每行 source identity 转成 target model ID、vendor、connection 和 protocol surface；不能唯一还原的历史行阻塞整批正式迁移，不可只丢弃历史字段。
12. 健康检查迁移只处理资源账户；授权实例不生成 connections、supported models、mappings 或 health-check 目标。对每个资源账户按以下固定顺序解析旧 `health_check_endpoint_mode` 与 `health_check_model`：
    - 先构造 `legacy_connection_candidates`。旧 Base URL 来源优先级固定为：①源 schema 中该账户明确的 Base URL 列；②解密后的 `credentials_encrypted.base_url`；③旧 `provider_protocol_profiles.base_url`；④旧 profile 对应的目标 preset registry 默认 Base URL。每一步都把实际来源写入 manifest；只有前一步缺列或值为 SQL NULL/空字符串时才进入下一步。若四步均无值，必须使用 `base_url_missing`；不得生成占位 host。`connection_base_url_override` 是唯一可以补足该缺失的对象，必须给出 source row、证据来源和新值；提供后重新校验并记录 `effective_canonical_url`，未提供则该账户计入一次 `health_checks_blocked`，reason 固定为 `base_url_missing`。URL 存在但不符合 validator 时 reason 固定为 `base_url_invalid`，不改记为缺失。每条候选必须记录 `source_url`、来源枚举（`account_column|credential_json|legacy_profile|registry_default|manifest_override`）和最终 canonical URL；registry default 的 canonical URL 及 fingerprint 必须写入 manifest。候选 profile 对普通供应商只来自旧 `provider_protocol_profile_id`；Hybrid 不读取不存在的 mapping profile，而按规则 3 的 `upstream_endpoint_family` 表生成候选 preset。profile/默认 URL 必须通过 §1.1 registry 唯一解析为 `connection_preset_code` 与 `protocol_surface_code`；解析失败时该候选不可用，`reason` 固定为 `legacy_profile_unsupported`，该缺陷已按规则 1（普通供应商）或规则 3（Hybrid）计入 `connections_blocked` 的资源账户不再重复计入 `health_checks_blocked`，manifest 仅记录该 reason 供复核。Base URL 比较使用与新 validator 相同的 `TrimSpace`、绝对 URL 解析和去掉末尾全部 `/` 的 canonical bytes；不做 DNS、重写、模型名或供应商推断。
    - 旧 mode 必须是 §2.2 的 25 个值之一，并且在候选 preset、账户域和旧账户已启用 mode 的交集中。只保留迁移后 `enabled=true`、canonical Base URL 与旧值相等、preset 唯一匹配且包含该 mode 的 connection；候选 connection 必须恰好 1 个。0 个记 `connection_zero`，超过 1 个记 `connection_many`，旧 mode 不在 25 值中记 `mode_unsupported`。当旧 mode 与账户 profile 不匹配但 Hybrid 映射表可唯一确定 preset 时使用映射表；仍为 0/多候选或 mode/profile/domain 不兼容时，只允许使用完整的 `health_check_override={resource_account_id,connection_preset_code,endpoint_mode,model_id,evidence}`。五个字段必须全部出现且全部非空；override 可以同时修复 connection preset、mode、model 的 0/多/不兼容候选，但不得改变账户 vendor、driver 或 capability_domain；Base URL 仍只能由 `connection_base_url_override` 提供。应用前必须再次通过 connection enabled、mode 属于 connection、model active、model owner-visible、model 属于 account_supported_models 和 domain/mode 一致性校验。`reason` 仅允许 `legacy_profile_unsupported`、`base_url_missing`、`base_url_invalid`、`mode_unsupported`、`connection_zero`、`connection_many`、`model_zero`、`model_many`、`model_mode_mismatch`。
   - 旧模型只通过旧模型身份映射解析：先按旧 `(provider_code, model)` 行和 manifest 中的 `target_model_id` disposition 找到目标 `models.id`，其中旧 `health_check_model` 必须与旧 `model` 字符串 binary 精确相等；不存在旧模型行、目标多于 1 个或 manifest 未解决时不得直接按 `public_model`、`upstream_model`、供应商或 Base URL 猜测。最终模型还必须同时满足 `status=active`、owner-visible、属于该资源账户 `account_supported_models`，并声明旧 mode；override 中的 `model_id` 也必须通过同一校验，不能从 capability domain 或模型名自动推导。
   - connection 与 model 均唯一通过后，写入 `health_check_connection_id`、`health_check_endpoint_mode`、`health_check_model_id` 三字段。任一阶段失败，每个资源账户只增加 1 个 `health_checks_blocked`，manifest 记录 `reason`、候选 ID 列表和源字段 hash；三字段不得部分写入。来源账户无效的授权实例按规则 9 计入 `accounts_blocked`，不重复计入 `health_checks_blocked`。
13. `public_model_conflicts` 只统计运行时可达集合中的 distinct `(resource_account_id, wire_model)`：`D` 是资源账户支持、`status=active`、owner-visible 且至少存在一个 enabled connection mode 与模型 mode 交集的 direct `(model_id, public_model)`；`M` 是 enabled mapping 中 target connection、target model、target family 均通过 §5.1 校验且至少有一个 §5.2/§5.3 可执行 source shape/mode 的 `(mapping_id, source_model)`；video mapping 只有四个 video mode 全部存在时才算可执行。目标无效的 enabled mapping 先计入 `mappings_blocked`，不重复计入 public model 冲突。当 `D` 对同一 wire name 有两个或更多不同 model，或 `D` 非空且 `M` 非空时计为 1 个冲突；只有 mapping、且来自不同 source endpoint family 的同名行不计冲突，因为其自然键包含 family。每个冲突必须在 manifest 中有且仅有一条对象：`{resource_account_id, wire_model, direct_model_ids[], mapping_ids[], resolution}`。`resolution=rename_public_model` 时必须给出至少一个 `{model_id,new_public_model}`，且 ID 必须属于 `direct_model_ids`；`resolution=rename_mapping_source` 时必须给出至少一个 `{mapping_id,new_source_model}`，且 ID 必须属于 `mapping_ids`，并在 manifest 应用前按 `(account_id,new_source_model,source_endpoint_family)` 检查目标唯一键，不得与既有或另一条迁移 mapping 冲突；无法满足时仍计入 `mappings_blocked`。`resolution=blocked` 不得带 rename 项并阻止正式迁移。新名称必须满足 §3 的 1..256 bytes、无首尾空白/控制字符和 binary 唯一性；应用 manifest 后重新计算 D/M，所有冲突必须为 0。一个冲突对象只解除其 `resolution` 对应的一类冲突；同一 `wire_model` 同时存在 direct 多模型与 direct/mapping 冲突时，应用后重算 D/M，剩余部分在下一轮 dry-run 生成新的冲突对象，按多轮 dry-run 收敛到 0。不得自动加前缀、覆盖、合并或丢弃任一行。

旧 `credentials_encrypted` 只允许由 maintenance 使用既有 runtime secret 在进程内解密；dry-run 只记录 credential fingerprint、可迁移字段集合和解密/校验结果，不写明文。`oauth_type` 提升规则固定为：仅 `account_type=google_oauth` 且 driver/vendor 为 `gemini` 的账户允许读取旧 JSON 的 `oauth_type`，值必须逐字等于 `code_assist`、`google_one` 或 `ai_studio`；缺失、NULL、空字符串、未知值以及非 Gemini 的 `google_oauth` 账户都计入 `accounts_blocked`。`account_type=api_key` 或普通 `oauth` 的目标列固定为 SQL `NULL`；旧 JSON 中的 `oauth_type` 缺失、NULL 或空字符串视为无值，非空值计入 `accounts_blocked`，不得静默改写。正式迁移把 `base_url`、旧 `supported_endpoint_modes`、旧 profile 元数据和已验证的 OAuth 提升结果移入 connection/mode/账户列后，立即用同一加密器重新加密只含 driver credential 的 JSON；`oauth_type` 与 `base_url` 必须从加密 JSON 删除，运行时唯一读取 accounts 列和 `account_connections.base_url`。Gateway/Jobs 的 refresh、reauth、usage snapshot 和账号测试必须从 `accounts.oauth_type` 读取 OAuth 分支；CAS 成功写回时必须保留该列并再次断言密文 JSON 不含 `oauth_type`/`base_url`。OAuth token/refresh endpoint 固定读取 driver registry 的 auth endpoint，不读取任一 connection Base URL；模型、探针和上游请求才读取选定 connection 的 Base URL。clone/export 必须导出 `oauthType` 列而不导出密文旧键，import 只写列。明文只存在于单次事务内存，禁止写 manifest、日志、错误、临时文件或 SQL 参数审计。解密失败、重新加密失败、旧凭据包含无法归属 driver 的关键字段或 fingerprint 不一致，计入 `accounts_blocked` 并停止正式迁移。

旧 `client_compatibility` 是迁移前的账户展示/兼容元数据，不参与任何目标连接、协议面、模型或 mapping 判定。dry-run 只在 manifest 的 `discarded_legacy_fields` 中记录每列的 source row count、非敏感 canonical hash 和丢弃原因；正式迁移不得把该字段复制到任何运行时表，也不得因为它的值缺失或未知而自动选择连接。若审计需要保留原值，只能从源快照和迁移报告恢复。

正式执行前，所有目标库和文件均须有已验证备份；执行器核对 `backup-receipt` 中的 `backup_id`、源对象和 SHA-256，不创建、不复制备份。PostgreSQL 同库在单个事务内完成；旧 `merge` 策略迁移生成 `groups`、`super_group_members`、更新 `route_strategies`、替换 `route_strategy_groups` 和写入 manifest 的目标记录必须在同一事务内提交，任一校验失败整笔回滚，禁止出现策略已改为 `normal` 但超级分组未完成的半迁移状态。SQLite 多文件按 business -> usage -> stats -> dataset 顺序逐文件事务，并为每文件记录 prepared/applied/verified journal 状态；同一 business 文件内上述超级分组迁移仍要求单事务，没有跨文件原子提交。任一文件失败立即停机，错误原样保留；恢复必须从同一备份集恢复全部目标文件后从头重跑，不允许部分恢复后继续。

正式执行先全量只读预检，再要求所有 unresolved blocked/unmatched 为 0。dry-run 可以列出 conflict；只有 manifest 已解决且逐字段验证通过后，各类冲突才从对应 blocked/conflict 计数移出。manifest 每个 source row 必须有唯一 disposition：`mapped`、`merged` 或 `blocked`，并记录 `target_ids[]`、字段级来源和引用重映射。迁移前后分别按 accounts、account_connections、account_endpoint_modes、models、account_supported_models、account_entry_mappings、groups、group_accounts、route_strategy_groups、usage、audit、model-check 逐表比较；对每张目标表定义 `expected_target_ids = union(target_ids of mapped/merged source rows) ∪ generated_target_ids`，`target_count = count(distinct expected_target_ids)`，`blocked_source_count=0`，每个 merged source 必须指向同一 survivor，所有 FK 引用必须落到 survivor。连接展开、模型合并和组 survivor 合并之外的差异必须由 manifest 列出且字段级哈希守恒。完成后写入 migration version；重复运行返回 already_migrated，不重复写入。

## 12. 非目标

- 不新增自动模型降级、成本优化、跨账户递归路由或跨分组模型映射。
- 不让账户引用另一个账户或分组作为上游。
- 不允许未知协议通过 generic_http 自动放行。
- 不保留旧字段运行时兼容分支，也不增加迁移 feature flag。
- 不改变 API Key、策略路由、调度偏好、分组会话亲和、账户健康状态机的职责。
