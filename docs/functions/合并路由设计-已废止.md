# 合并路由设计（已废止）

> 状态：**已废止（2026-10-17）**。
>
> `merge` 不再是路由策略模式。路由策略只负责调度目标和调度顺序；跨普通分组的候选组合改由分组域的 [超级分组设计](超级分组设计.md) 承载。本文只保留迁移前代码和历史决策的索引，不是当前设计契约。

## 废止原因

“合并”描述的是候选资源的组织方式，不是路由策略。把它放进路由模式会让路由同时承担分组建模和账号池组合，造成路由模式、分组边界、配额归属和会话作用域重复定义。

## 当前替代关系

| 旧概念 | 当前目标 |
| --- | --- |
| `route_strategies.mode=merge` | 迁移为绑定一个超级分组的 `normal` 策略 |
| 多个路由绑定分组扁平合并 | `super_group_members` 组合普通分组 |
| `route_source=merged` | `route_group_id` + 实际 `member_group_id` |
| 合并池专属配额/窗口语义 | 成员普通分组的授权、配额和账号调度语义 |
| merge 60 fixture | 超级分组 44 fixture，见《超级分组设计》§7 |

## 迁移前代码基线

2026-10-21 起 Go 运行时的 `ModeMerge` / merge 路由解析 / merge 测试已随超级分组落地全部删除，仓库内不再保留可执行的 merge 运行时路径；仅 `maintenance` 的迁移输入解析（`internal/mergesupermigration`）与路由策略写入口的拒绝判断仍识别该字面量。

完整基线设计见 [合并路由设计](合并路由设计.md)，仅作历史留档；该文不再被任何 Go 代码注释引用。
