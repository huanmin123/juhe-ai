# 公益榜公开聚合接口设计

> 面向 `juhe-ai-public-welfare`、`juhe-ai` 后端和后续 AI 维护者。
> 当前结论：`sub2api-lite` 提供账号维度和 IP 维度聚合事实，不生成公益站业务排行榜快照；公益站自己负责用户维度、IP 到用户归属、排行榜快照、IP 拦截和公网频率拦截。

## 当前状态

- 已实现：外部来源系统 Bearer token 鉴权、来源系统表和 token 表、公开接口授权管理页、接入文档弹窗和内置测试 token。
- 已实现：`GET /__aipublic__/account/usage`，读取 `usage_scope_range_windows` 中 `scope_type='account'` 的账号聚合结果。
- 已实现：`GET /__aipublic__/ip/usage`，读取 `client_ip_usage_range_windows` 和 `client_ip_registry`。
- 已实现：`GET /__aipublic__/consumption/ranking`，基于同一 IP 窗口表返回 TopN 便利视图。
- 已实现：`GET /__aipublic__/access/info`，返回公开接口可用范围和边界说明。
- 已实现：`GET /__aipublic__/account/list` 与 `POST /__aipublic__/account/add|update|del`，用于外部来源系统分页读取、新增、修改或删除指定系统用户和分组内的账号。
- 已实现：`GET /__aipublic__/group/list`、`GET /__aipublic__/api-key/list`、`POST /__aipublic__/group/add|update|del` 和 `POST /__aipublic__/api-key/add|update|del`，用于外部来源系统对账并管理分组和 API Key。
- 保留：`GET /__aipublic__/demo/source-auth`，只用于联调鉴权。
- 不实现于 `sub2api-lite`：公益站用户维度排行榜、贡献排行榜快照、IP 到用户归属、公益站访问拦截、普通 API Key 暴露、`public_ranking_snapshots` 业务快照表。

## 分工边界

| 能力 | 归属 | 说明 |
| --- | --- | --- |
| 来源系统 token 鉴权 | `sub2api-lite` | 统一走 `/__aipublic__`，只认 `Authorization: Bearer <source_token>`。 |
| 账号维度聚合事实 | `sub2api-lite` | 只读账号范围窗口表，不扫使用记录明细。 |
| IP 维度聚合事实 | `sub2api-lite` | 只读 IP 范围窗口表，不扫使用记录明细。 |
| 账号维度贡献 TopN | `sub2api-lite` | 只是账号聚合的排序视图，不等同公益站贡献榜。 |
| IP 维度消耗 TopN | `sub2api-lite` | 只是 IP 聚合的排序视图，不等同公益站用户榜。 |
| 公开资源控制与对账 | `sub2api-lite` | 承接外部来源系统对指定系统用户 / 分组下的分组、API Key 和账号执行脱敏列表读取、新增、修改或删除，不判断公益站业务归属。 |
| 贡献排行榜 | `juhe-ai-public-welfare` | 公益站结合自己的业务配置、用户和公开展示口径生成。 |
| 消耗排行榜快照 | `juhe-ai-public-welfare` | 公益站按 IP 归属映射到用户后生成用户维度快照。 |
| 公开访问 / 公益接入展示 | `juhe-ai-public-welfare` | 若要展示公益入口、说明、访问规则或用户维度摘要，由公益站维护。 |
| IP 拦截与公网频率拦截 | `juhe-ai-public-welfare` | `sub2api-lite` 只做自身管理端 IP 封禁和来源 token 限频。 |

## 通用调用约定

所有真实接口都在公开前缀下：

```http
GET /__aipublic__/<业务>/<功能>
Authorization: Bearer <source_token>
```

真实公开聚合接口按接口独立授权：

```text
GET /__aipublic__/ip/usage -> juhe_ai_public:ip_usage:read
GET /__aipublic__/account/usage -> juhe_ai_public:account_usage:read
GET /__aipublic__/consumption/ranking -> juhe_ai_public:consumption_ranking:read
GET /__aipublic__/access/info -> juhe_ai_public:access_info:read
```

资源控制接口也按接口独立授权：

```text
GET /__aipublic__/group/list -> juhe_ai_public:group_list:read
GET /__aipublic__/api-key/list -> juhe_ai_public:api_key_list:read
GET /__aipublic__/account/list -> juhe_ai_public:account_list:read
POST /__aipublic__/group/add -> juhe_ai_public:group_add:write
POST /__aipublic__/group/update -> juhe_ai_public:group_update:write
POST /__aipublic__/group/del -> juhe_ai_public:group_delete:write
POST /__aipublic__/api-key/add -> juhe_ai_public:api_key_add:write
POST /__aipublic__/api-key/update -> juhe_ai_public:api_key_update:write
POST /__aipublic__/api-key/del -> juhe_ai_public:api_key_delete:write
POST /__aipublic__/account/add -> juhe_ai_public:account_add:write
POST /__aipublic__/account/update -> juhe_ai_public:account_update:write
POST /__aipublic__/account/del -> juhe_ai_public:account_delete:write
```

内置测试 token：

```text
juis_test_mock_public_token
```

可通过环境变量覆盖：

```text
JUHE_AI_EXTERNAL_SOURCE_TEST_TOKEN
```

测试 token 不查真实聚合表，只返回 mock 数据，便于公益站后端先验证请求头、query 和响应解析。生产 token 由“系统运维 / 公开接口授权”创建，创建弹窗和后台单条复制接口可按管理员权限展示完整明文，必须只保存到公益站后端配置。

## 通用成功响应与错误响应

成功响应统一包在 `data` 字段中：

```json
{
  "data": {
    "source": "stats",
    "generatedAt": "2026-05-30T00:00:00.000Z"
  }
}
```

通用响应字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `data.source` | string | 是 | 数据来源；`stats` 表示正式统计或控制面数据，`mock` 表示内置测试 token 模拟数据。 |
| `data.generatedAt` | string | 是 | 响应生成时间，ISO 8601 字符串。 |
| `data.statsLagSeconds` | number | 否 | 统计聚合相对当前时间的滞后秒数，只在统计类接口中返回；无法判断时可能缺省。 |
| `data.page` | number | 否 | 当前页码，只在分页列表中返回。 |
| `data.pageSize` | number | 否 | 当前每页数量，只在分页列表中返回。 |
| `data.pageUpperBound` | number | 否 | 分页上界，不是精确总数。 |
| `data.hasMore` | boolean | 否 | 是否还有下一页。 |

错误响应不包 `data`，格式按错误来源分两类：

```json
{
  "message": "来源系统没有调用该接口的权限",
  "code": "external_source_scope_forbidden"
}
```

```json
{
  "message": "API Key 新增参数无效"
}
```

错误字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `message` | string | 是 | 面向调用方排查的中文错误说明。 |
| `code` | string | 否 | 来源鉴权、scope 和限频错误码；参数校验和业务错误通常只返回 `message`。 |
| `details` | object | 否 | 限频错误附加信息，包含 `windowSeconds`、`maxRequests` 和 `retryAfterSeconds`。 |

常见错误码：

| HTTP 状态 | code | 说明 |
| --- | --- | --- |
| `401` | `external_source_token_missing` | 缺少 `Authorization: Bearer <source_token>`。 |
| `401` | `external_source_unauthorized` | 来源系统或 token 无效。 |
| `401` | `external_source_token_unavailable` | token 已停用、吊销或过期。 |
| `403` | `external_source_disabled` | 来源系统已停用。 |
| `403` | `external_source_expired` | 来源系统授权已过期。 |
| `403` | `external_source_scope_forbidden` | token 没有目标接口所需 scope。 |
| `429` | `external_source_rate_limited` | 来源系统命中公开接口限频；响应头会带 `Retry-After`。 |

统计聚合项通用字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `requestCount` / `successCount` / `errorCount` | number | 请求总数、成功请求数和失败请求数。 |
| `errorRate` | number | 失败率，取值 0 到 1，保留 4 位小数。 |
| `inputTokens` / `outputTokens` / `cacheReadTokens` / `totalTokens` | number | 输入、输出、缓存读取和总 token 数；`totalTokens = inputTokens + outputTokens`。 |
| `cacheRate` | number | 缓存读取 token / 输入 token 的比例，取值 0 到 1。 |
| `totalCost` / `cacheReadCost` | number | 估算总成本和缓存读取成本，单位 USD。 |
| `activeDays` | number | 当前窗口内有请求的活跃天数。 |
| `averageFirstTokenMs` / `averageDurationMs` / `maxDurationMs` | number | 平均首 token 耗时、平均总耗时、最大总耗时，单位毫秒；无样本时可能缺省。 |
| `lastUsedAt` / `lastErrorAt` | string | 最近请求时间和最近错误时间，ISO 8601 字符串；无对应记录时可能缺省。 |

## 账号维度实际用量聚合

```http
GET /__aipublic__/account/usage?range=last7d&page=1&pageSize=20&sortField=totalTokens&sortOrder=desc
Authorization: Bearer <source_token>
```

Query：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `range` | string | 否 | `today`、`last7d`、`last31d`，默认 `today`；公开接口只读取后台已维护的固定窗口。 |
| `page` | number | 否 | 页码，默认 `1`；服务端收敛到 1001 行分页窗口内，避免深分页 offset 扫描。 |
| `pageSize` | number | 否 | 每页数量，`1..100`，默认 `20`。 |
| `keyword` | string | 否 | 账号精确或前缀搜索；支持账号 ID、名称、供应商、类型；后端拆成索引范围查询解析账号 ID，不做多列 OR / LIKE 扫描。 |
| `sortField` | string | 否 | `requestCount`、`successCount`、`errorCount`、`errorRate`、`totalTokens`、`totalCost`、`activeDays`、`lastUsedAt`。 |
| `sortOrder` | string | 否 | `desc` 或 `asc`，默认 `desc`。 |

字段约束：

- `accountId` 是账号维度的唯一事实键，公益站应按这个值映射登记。
- `providerCode`、`type`、`status` 来自当前账号元数据；账号元数据缺失时可能缺省。
- 不返回公益站用户关系、IP、封禁状态、API Key、系统账户归属、分组、模型或上游凭据。
- `rangeReady=false` 时返回空列表，公益站应稍后重试或沿用自己的上次快照。
- 传入 `startDate` / `endDate` 会返回 `400`；自定义窗口需要先设计离线窗口刷新，不能在公开请求路径临时聚合明细。
- `pageUpperBound` 只是分页上界，不是精确总数。
- 正式 token 的账号列表请求只读取 `usage_scope_range_windows` 的预生成范围窗口，并把 SQL `OFFSET` 限制在 1000 行以内。

```json
        "普通 API Key、上游账号凭据或内部授权关系"
      ]
    }
  }
}
```

资源对象：

| 对象 | 字段 | 类型 | 说明 |
| --- | --- | --- | --- |
| `group` / `items[]` | `id`、`name`、`providerCode`、`description`、`enabled`、`groupType`、`isDefault` | string / boolean | 分组脱敏摘要。 |

分组和 API Key 修改 / 删除找不到资源时，正式调用返回 `404 { "message": "..." }`；账号删除找不到资源时返回成功 envelope，并带 `data.action = "not_found"` 和 `data.account = null`，便于外部来源系统做幂等删除。

公开资源列表：

- `GET /__aipublic__/group/list?targetUsername=huanmin&providerCode=openai&page=1&pageSize=20`：返回指定系统用户自己的分组摘要，支持 `providerCode`、`keyword`、`page` 和 `pageSize`。
- `GET /__aipublic__/api-key/list?targetUsername=huanmin&groupId=grp_xxx&page=1&pageSize=20`：返回指定系统用户自己的 API Key 摘要和分组绑定，支持 `keyword`、`status`、`groupId`、`page` 和 `pageSize`，不返回明文 `key`。
- `GET /__aipublic__/account/list?targetUsername=huanmin&targetGroupName=福利&providerCode=openai&page=1&pageSize=20`：返回指定系统用户自己的 AI 账户脱敏摘要，支持 `targetGroupName + providerCode`、`groupId`、`keyword`、`type`、`status`、`schedulable`、`page` 和 `pageSize`；列表返回本系统账号 ID，便于外部来源系统找回并保存后续操作所需的 `accountId`。

`/api-key/add` 和 `/api-key/update` 操作的是 `sub2api-lite` 本地 API Key，分组关系使用当前 `groupBindings` / `groupRouteStrategy` 契约：`groupBindings` 是 1 到 20 个本地分组绑定项，每项包含 `groupId`，可选 `priority`、`weight` 和 `status`；不再接收顶层 `groupId` 或 `groupName` 作为 API Key 主绑定字段。

```json

```

`/account/add` 和 `/account/update` 操作的是上游 API Key 类型 AI 账户，使用 `targetGroupName` 指定账号要进入的目标分组。账号新增响应返回本系统 `account.id`，外部来源系统应自行保存该 ID；后续修改和删除必须回传 `accountId`，`sub2api-lite` 不保存外部系统的登记 ID 或业务主键。上游账号新增请求体示例：

```json

```

当前公开账号新增 / 修改只支持 `type = "api_key"`；`oauth` 或其他类型会被拒绝。账号新增会在目标用户或目标分组不存在时自动创建；账号修改只修改已存在账号，找不到时返回 `404`，不会隐式新增。目标用户、目标分组和 AI 账户写入在同一事务里完成，账号校验失败时不会留下自动创建的用户或分组；正式新增和修改成功后会写入操作日志，记录来源系统、token 前缀、目标用户、目标分组和账号，不记录上游凭据明文。

定位规则：账号新增只按同一目标用户、目标分组和供应商内的同名账号做重复冲突判断；账号修改和删除必须按本系统 `accountId` 精确定位，不再接收外部登记 ID 或账号名称作为定位兜底。外部来源系统需要把新增响应里的 `account.id` 保存到自己的业务记录里。

语义约束：

- `targetUsername` 和 `targetGroupName` 由公益站系统设置决定，例如 `huanmin / 福利`，不由 `sub2api-lite` 推断公益站业务归属。
- 账号新增时，目标系统用户不存在则自动创建普通用户，目标分组不存在则在该用户下自动创建对应供应商分组。
- 同一目标分组、同一供应商内的同名账号再次新增时返回冲突；需要修改时调用 `/__aipublic__/account/update` 并传入新增响应返回的 `accountId`。
- 账号修改时，目标系统用户、目标分组和目标账号都必须已存在；找不到账号时返回 `404`。
- 响应不返回 `apiKey`、凭据明文、凭据 hash 或内部加密内容。
- 内置测试 token 调用时返回 `source=mock`，不写入系统用户、分组或账号表。

## 公益站侧建议契约

以下接口不属于 `sub2api-lite`，建议落在 `juhe-ai-public-welfare` 后端，用于浏览器读取已经脱敏和快照化的公开展示数据：

| 接口 | 建议归属 | 数据来源 |
| --- | --- | --- |
| 贡献排行榜接口 | 公益站 | 公益站维护的贡献配置、供应商展示名、榜单快照。 |
| 消耗排行榜接口 | 公益站 | `sub2api-lite` 的 IP 聚合事实 + 公益站 IP 到用户归属映射。 |
| 公开访问 / 公益接入信息接口 | 公益站 | 公益站可公开的入口、规则、说明和展示配置。 |
| 汇总快照接口 | 公益站 | 公益站按自己的展示周期生成并缓存，不要求 `sub2api-lite` 汇总。 |

公益站前端展示字段建议继续保持：

- 贡献排行榜不展示模型。
- 名称和供应商分开列，不合并。
- 消耗排行榜不展示 key。
- “名称”列不要过宽，指标字段独立成列。
- 缓存 token、缓存率、平均首 token、平均总耗时、最大总耗时如有数据应展示。
- “用户累计活跃天数”类指标改成平均类或快照类指标，不把不可解释的累计天数直接展示。

## 性能与安全约束

- 公开接口只读 `client_ip_usage_range_windows` 和 `client_ip_registry`。
- 不在请求路径扫描 `usage_records`，不临时 `SUM/GROUP BY`，不为了汇总卡片额外扫窗口表。
- IP 范围总汇总暂不提供；如后续确实需要，应新增 worker 维护的范围摘要表。
- 查询接口不写操作日志；来源系统 token 创建、启停和轮换才写操作日志。
- 日志不得记录完整 `Authorization`、完整 token、普通 API Key、上游凭据或公益站业务映射。
- 来源 token 限频只保护 `/__aipublic__` 调用来源；公益站公网 IP 限制和用户频率限制不归 `sub2api-lite` 管。
- 公开资源写入只写入控制面，不写公益站排行榜快照，不把目标用户解释为公益站用户维度统计对象。

## 验证清单

- 无 `Authorization` 返回 `401 external_source_token_missing`。
- token 错误返回 `401 external_source_unauthorized`。
- scope 不足返回 `403 external_source_scope_forbidden`。
- 测试 token 调用真实接口返回 `source=mock`，不读真实聚合表。
- 正式 token 调用 `ip-usage` 返回 `source=stats`，读取 IP 范围窗口表。
- `ip-usage` 响应不包含 `ipHash`、封禁状态、API Key、账号、分组、供应商或模型。
- 窗口未就绪时返回 `rangeReady=false` 和空列表，不在请求内刷新窗口。
- `consumption-ranking` 只表示 IP 维度消耗排行，不被解释为公益站用户排行榜。
