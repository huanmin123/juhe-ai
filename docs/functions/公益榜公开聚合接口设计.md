# 公益榜公开聚合接口设计

> 面向 `juhe-ai-public-welfare`、`juhe-ai` 后端和后续 AI 维护者。
> 当前结论：`sub2api-lite` 只提供底层 IP 维度聚合事实，不生成公益站业务排行榜快照；公益站自己负责用户维度、IP 到用户归属、排行榜快照、IP 拦截和公网频率拦截。

## 当前状态

- 已实现：外部来源系统 Bearer token 鉴权、来源系统表和 token 表、公开接口授权管理页、接入文档弹窗和内置测试 token。
- 已实现：`GET /__aipublic__/juhe-ai/ip-usage`，读取 `client_ip_usage_range_windows` 和 `client_ip_registry`。
- 已实现：`GET /__aipublic__/juhe-ai/consumption-ranking`，基于同一 IP 窗口表返回 TopN 便利视图。
- 已实现：`GET /__aipublic__/juhe-ai/access-info`，返回公开接口可用范围和边界说明。
- 已实现：`POST /__aipublic__/juhe-ai/accounts`，用于公益站把审核后的账号推送到指定系统用户和分组，目标用户或分组不存在时自动创建。
- 已实现：`DELETE /__aipublic__/juhe-ai/accounts`，用于公益站删除登记前真实删除已推送的上游账号，找不到时幂等返回。
- 保留：`GET /__aipublic__/demo/source-auth` 和 `GET /__aipublic__/demo/mock-ranking`，只用于联调鉴权和 mock 解析。
- 不实现于 `sub2api-lite`：公益站用户维度排行榜、贡献排行榜快照、IP 到用户归属、公益站访问拦截、普通 API Key 暴露、`public_ranking_snapshots` 业务快照表。

## 分工边界

| 能力 | 归属 | 说明 |
| --- | --- | --- |
| 来源系统 token 鉴权 | `sub2api-lite` | 统一走 `/__aipublic__`，只认 `Authorization: Bearer <source_token>`。 |
| IP 维度聚合事实 | `sub2api-lite` | 只读 IP 范围窗口表，不扫使用记录明细。 |
| IP 维度消耗 TopN | `sub2api-lite` | 只是 IP 聚合的排序视图，不等同公益站用户榜。 |
| 公益账号推送 / 删除写入 | `sub2api-lite` | 只承接公益站传入的账号写入或真实删除到指定系统用户 / 分组，不判断公益站业务归属。 |
| 贡献排行榜 | `juhe-ai-public-welfare` | 公益站结合自己的业务配置、用户和公开展示口径生成。 |
| 消耗排行榜快照 | `juhe-ai-public-welfare` | 公益站按 IP 归属映射到用户后生成用户维度快照。 |
| 公开访问 / 公益接入展示 | `juhe-ai-public-welfare` | 若要展示公益入口、说明、访问规则或用户维度摘要，由公益站维护。 |
| IP 拦截与公网频率拦截 | `juhe-ai-public-welfare` | `sub2api-lite` 只做自身管理端 IP 封禁和来源 token 限频。 |

## 通用调用约定

所有真实接口都在公开前缀下：

```http
GET /__aipublic__/juhe-ai/...
Authorization: Bearer <source_token>
```

真实 IP 聚合接口需要 scope：

```text
juhe_ai_ip_usage:read
```

账号推送接口需要 scope：

```text
juhe_ai_account_push:write
```

内置测试 token：

```text
juis_test_mock_public_token
```

可通过环境变量覆盖：

```text
JUHE_AI_EXTERNAL_SOURCE_TEST_TOKEN
```

测试 token 不查真实聚合表，只返回 mock 数据，便于公益站后端先验证请求头、query 和响应解析。生产 token 由“系统运维 / 公开接口授权”创建，明文只展示一次，必须只保存到公益站后端配置。

## IP 维度消费聚合

```http
GET /__aipublic__/juhe-ai/ip-usage?range=last7d&page=1&pageSize=20&sortField=totalTokens&sortOrder=desc
Authorization: Bearer <source_token>
```

Query：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `range` | string | 否 | `today`、`last7d`、`last31d`，默认 `today`；公开接口只读取后台已维护的固定窗口。 |
| `page` | number | 否 | 页码，默认 `1`。 |
| `pageSize` | number | 否 | 每页数量，`1..100`，默认 `20`。 |
| `limit` | number | 否 | `pageSize` 兼容别名，适合只取前 N 条。 |
| `keyword` | string | 否 | IP 精确或右侧前缀搜索；不支持 hash 搜索。 |
| `sortField` | string | 否 | `requestCount`、`successCount`、`errorCount`、`errorRate`、`totalTokens`、`totalCost`、`activeDays`、`lastUsedAt`。 |
| `sortOrder` | string | 否 | `desc` 或 `asc`，默认 `desc`。 |

成功响应：

```json
{
  "data": {
    "source": "stats",
    "generatedAt": "2026-05-30T00:00:00.000Z",
    "statsLagSeconds": 60,
    "range": {
      "preset": "last7d",
      "label": "最近7天",
      "startDate": "2026-05-24",
      "endDate": "2026-05-30",
      "days": 7,
      "maxDays": 31
    },
    "rangeReady": true,
    "page": 1,
    "pageSize": 20,
    "pageUpperBound": 1,
    "hasMore": false,
    "items": [
      {
        "rank": 1,
        "dimension": "client_ip",
        "ip": "203.0.113.10",
        "requestCount": 1280,
        "successCount": 1252,
        "errorCount": 28,
        "errorRate": 0.0219,
        "inputTokens": 516000,
        "outputTokens": 326000,
        "cacheReadTokens": 126000,
        "cacheRate": 0.2442,
        "totalTokens": 842000,
        "totalCost": 12.36,
        "cacheReadCost": 0.42,
        "activeDays": 7,
        "averageFirstTokenMs": 820,
        "averageDurationMs": 3160,
        "maxDurationMs": 12880,
        "lastUsedAt": "2026-05-30T00:00:00.000Z"
      }
    ]
  }
}
```

字段约束：

- `ip` 是规范化 IPv4，也是当前 IP 维度业务归属的唯一可用事实。
- 不返回 `ipHash`、封禁状态、封禁原因、管理员 ID、API Key、系统账户、AI 账户、分组、供应商、模型或上游凭据。
- `rangeReady=false` 时返回空列表，公益站应稍后重试或沿用自己的上次快照；接口不会在请求路径重建窗口。
- 传入 `startDate` / `endDate` 会返回 `400`；自定义窗口需要先设计离线窗口刷新，不能在公开请求路径临时聚合明细。
- `pageUpperBound` 只是分页上界，不是精确总数。

## IP 维度消耗排行

```http
GET /__aipublic__/juhe-ai/consumption-ranking?range=last7d&limit=10&metric=totalTokens
Authorization: Bearer <source_token>
```

Query：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `range` | string | 否 | `today`、`last7d`、`last31d`。 |
| `limit` | number | 否 | TopN，`1..100`，默认 `20`。 |
| `metric` | string | 否 | `totalTokens`、`totalCost`、`requestCount`，默认 `totalTokens`。 |

成功响应：

```json
{
  "data": {
    "source": "stats",
    "generatedAt": "2026-05-30T00:00:00.000Z",
    "dimension": "client_ip",
    "metric": "totalTokens",
    "rangeReady": true,
    "items": [
      {
        "rank": 1,
        "id": "ip:203.0.113.10",
        "name": "203.0.113.10",
        "dimension": "client_ip",
        "ip": "203.0.113.10",
        "metricValue": 842000,
        "requestCount": 1280,
        "totalTokens": 842000,
        "cacheReadTokens": 126000,
        "cacheRate": 0.2442,
        "averageFirstTokenMs": 820,
        "averageDurationMs": 3160,
        "maxDurationMs": 12880
      }
    ]
  }
}
```

该接口只是 `ip-usage` 的排序便利视图。公益站如果要展示“用户消耗排行榜”，必须在自己的后端把 `ip` 映射到公益站用户，再生成用户维度快照。

## 公益接入信息

```http
GET /__aipublic__/juhe-ai/access-info
Authorization: Bearer <source_token>
```

成功响应：

```json
{
  "data": {
    "source": "stats",
    "generatedAt": "2026-05-30T00:00:00.000Z",
    "publicApiPrefix": "/__aipublic__",
    "dataDimension": "client_ip",
    "authType": "Bearer",
    "supportedRanges": ["today", "last7d", "last31d"],
    "supportedMetrics": ["totalTokens", "totalCost", "requestCount"],
    "boundary": {
      "provides": ["来源系统 Bearer token 鉴权", "IP 维度聚合事实"],
      "notProvided": ["公益站用户维度排行榜快照", "IP 到公益站用户的业务归属"]
    }
  }
}
```

该接口不返回普通 API Key、公益入口明文密钥、上游账号凭据或内部授权关系。公益站页面需要展示的“公开访问入口 / 接入说明 / 用户可用能力”应由公益站自己维护。

## 公益账号推送与删除

```http
POST /__aipublic__/juhe-ai/accounts
Authorization: Bearer <source_token>
Content-Type: application/json
```

该接口需要 scope：

```text
juhe_ai_account_push:write
```

请求体：

```json
{
  "targetUsername": "huanmin",
  "targetGroupName": "福利",
  "providerCode": "openai",
  "name": "公益站-青芽主通道",
  "type": "api_key",
  "baseUrl": "https://api.openai.com/v1",
  "apiKey": "sk-...",
  "supportedModels": ["gpt-5.5", "gpt-5.4"],
  "concurrencyLimit": 20,
  "status": "active",
  "externalId": "juhe-ai-public-welfare:ai-registration:12"
}
```

当前公开推送只支持 `type = "api_key"`；`oauth` 或其他类型会被拒绝。目标用户、目标分组、AI 账户和 `externalId` 映射写入在同一事务里完成，账号校验失败时不会留下自动创建的用户或分组；正式推送成功后会写入操作日志，记录来源系统、token 前缀、目标用户、目标分组、账号和 `externalId`，不记录上游凭据明文。

幂等规则：同一目标用户、目标分组和供应商内，优先用结构化映射表里的 `externalId` 精确定位既有公益站推送账号；没有 `externalId` 或找不到时，再按账号名称定位。`externalId` 不写入请求路径查询条件里的备注扫描，避免前缀误命中和长文本扫描。因此公益站改名、停用或重新启用同一登记时，应持续传同一个 `externalId`，`sub2api-lite` 会更新原账号而不是用同一凭据创建新账号。

成功响应：

```json
{
  "data": {
    "source": "stats",
    "generatedAt": "2026-05-30T00:00:00.000Z",
    "action": "created",
    "target": {
      "username": "huanmin",
      "displayName": "huanmin",
      "systemAccountId": "sysacc_xxx",
      "created": true,
      "groupId": "grp_xxx",
      "groupName": "福利",
      "groupCreated": true
    },
    "account": {
      "id": "acc_xxx",
      "name": "公益站-青芽主通道",
      "providerCode": "openai",
      "type": "api_key",
      "status": "active",
      "supportedModels": ["gpt-5.5", "gpt-5.4"],
      "boundGroupId": "grp_xxx",
      "boundGroupName": "福利",
      "schedulable": true
    },
    "externalId": "juhe-ai-public-welfare:ai-registration:12"
  }
}
```

语义约束：

- `targetUsername` 和 `targetGroupName` 由公益站系统设置决定，例如 `huanmin / 福利`，不由 `sub2api-lite` 推断公益站业务归属。
- 目标系统用户不存在时自动创建普通用户；目标分组不存在时在该用户下自动创建对应供应商分组。
- 同一目标分组、同一供应商、同名账号再次推送时更新原账号；响应 `action=updated`。
- 响应不返回 `apiKey`、凭据明文、凭据 hash 或内部加密内容。
- 内置测试 token 调用时返回 `source=mock`，不写入系统用户、分组或账号表。

公益站删除本地登记前调用：

```http
DELETE /__aipublic__/juhe-ai/accounts
Authorization: Bearer <source_token>
Content-Type: application/json
```

请求体：

```json
{
  "targetUsername": "huanmin",
  "targetGroupName": "福利",
  "providerCode": "openai",
  "accountId": "acc_xxx",
  "name": "公益站-青芽主通道",
  "externalId": "juhe-ai-public-welfare:ai-registration:12"
}
```

删除接口同样需要 `juhe_ai_account_push:write`。`accountId`、`name`、`externalId` 至少提供一个；服务端优先按 `externalId` 精确定位，再按 `accountId` 和 `name` 兜底。找到账号后会真实删除账号并投递关联记录清理，不是改成 disabled；找不到时返回 `action=not_found`，便于公益站把本地登记删除流程保持幂等。

## 公益站侧建议契约

以下接口不属于 `sub2api-lite`，建议落在 `juhe-ai-public-welfare` 后端，用于浏览器读取已经脱敏和快照化的公开展示数据：

| 接口 | 建议归属 | 数据来源 |
| --- | --- | --- |
| 贡献排行榜接口 | 公益站 | 公益站维护的贡献配置、供应商展示名、榜单快照。 |
| 消耗排行榜接口 | 公益站 | `sub2api-lite` 的 IP 聚合事实 + 公益站 IP 到用户归属映射。 |
| 公开访问 / 公益接入信息接口 | 公益站 | 公益站可公开的入口、规则、说明和展示配置。 |
| 汇总快照接口 | 公益站 | 公益站按自己的展示周期生成并缓存，不要求 `sub2api-lite` 汇总。 |

公益站前端展示字段建议继续保持：

- 贡献排行榜不展示模型。
- 名称和供应商分开列，不合并。
- 消耗排行榜不展示 key。
- “名称”列不要过宽，指标字段独立成列。
- 缓存 token、缓存率、平均首 token、平均总耗时、最大总耗时如有数据应展示。
- “用户累计活跃天数”类指标改成平均类或快照类指标，不把不可解释的累计天数直接展示。

## 性能与安全约束

- 公开接口只读 `client_ip_usage_range_windows` 和 `client_ip_registry`。
- 不在请求路径扫描 `usage_records`，不临时 `SUM/GROUP BY`，不为了汇总卡片额外扫窗口表。
- IP 范围总汇总暂不提供；如后续确实需要，应新增 worker 维护的范围摘要表。
- 查询接口不写操作日志；来源系统 token 创建、启停和轮换才写操作日志。
- 日志不得记录完整 `Authorization`、完整 token、普通 API Key、上游凭据或公益站业务映射。
- 来源 token 限频只保护 `/__aipublic__` 调用来源；公益站公网 IP 限制和用户频率限制不归 `sub2api-lite` 管。
- 账号推送只写入账号控制面，不写公益站排行榜快照，不把目标用户解释为公益站用户维度统计对象。

## 验证清单

- 无 `Authorization` 返回 `401 external_source_token_missing`。
- token 错误返回 `401 external_source_unauthorized`。
- scope 不足返回 `403 external_source_scope_forbidden`。
- 测试 token 调用真实接口返回 `source=mock`，不读真实聚合表。
- 正式 token 调用 `ip-usage` 返回 `source=stats`，读取 IP 范围窗口表。
- `ip-usage` 响应不包含 `ipHash`、封禁状态、API Key、账号、分组、供应商或模型。
- 窗口未就绪时返回 `rangeReady=false` 和空列表，不在请求内刷新窗口。
- `consumption-ranking` 只表示 IP 维度消耗排行，不被解释为公益站用户排行榜。
- `accounts` 推送 / 删除接口需要 `juhe_ai_account_push:write`；scope 不足返回 `403 external_source_scope_forbidden`，正式 token 成功后能创建、更新或真实删除目标用户分组内账号，响应不包含凭据。
