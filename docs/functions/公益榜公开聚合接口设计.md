# 公益榜公开聚合接口设计

> 面向 `juhe-ai-public-welfare`、`sub2api-lite` 后端和后续 AI 维护者。
> 本文定义 juhe-ai 公益榜从 `sub2api-lite` 拉取排行榜数据时使用的受保护外部集成接口。数据用于公开展示，但接口本身不是无鉴权公开 API，必须按第三方调用方式校验。

## 设计目标

- 为 `juhe-ai公益榜` 提供统一数据源，公益站前端和后端不再自行聚合 `sub2api-lite` 明细数据。
- 首版先支持 mock / 快照 payload，让两个项目可以先按稳定结构联调；真实统计 worker 后续替换 payload 来源。
- 接口只能被已配置的集成客户端调用，不能因为数据会公开展示就允许任意来源抓取。
- 排行榜、摘要和 TopN 只读取 worker 预写快照，不在请求路径扫描 `usage_records`，也不临时聚合小时 / 日 / 月缓存。
- 响应不暴露内部凭据、内部用户标识、任意本地 API Key 或上游账号密钥。公益访问入口里的 `apiKey` 只允许来自显式标记为公益公开的专用 Key。

## 接口分层结论

该能力新增为“外部集成 API”：

| 项 | 结论 |
| --- | --- |
| 路径前缀 | `/__aisys__/api/external-integrations/*` |
| 首个接口 | `GET /__aisys__/api/external-integrations/juhe-ai/rankings` |
| 调用方 | `juhe-ai-public-welfare` 后端服务，不允许浏览器直接携带集成 token 调用 |
| 身份来源 | 集成客户端 ID + Bearer 集成 token，后续可升级 HMAC 签名 |
| 返回风格 | 继续使用系统 API 包装：`{ "data": PublicRankingResponse }` |
| 路由落点 | DB service 内部系统 API，在 `requireAuth` 之前挂载专用鉴权中间件 |
| 统计来源 | `public_ranking_snapshots` 快照；快照由 mock、维护脚本或后台 worker 写入 |

注意：它不属于现有“公开 API”。现有公开 API 只服务健康检查、登录前公开设置、验证码和登录流程；公益榜接口虽然服务公开展示数据，但调用入口必须受保护。

## 调用接口

### GET 公益榜完整数据

```http
GET /__aisys__/api/external-integrations/juhe-ai/rankings
Authorization: Bearer <integration_token>
X-Juhe-AI-Client: juhe-ai-public-welfare
```

查询参数首版不开放筛选。公益榜页面需要的筛选项应从当前响应列表中派生，避免展示不存在于列表里的筛选值。

成功响应：

```json
{

    "updatedAt": "2026-05-28T10:00:00.000Z",
    "source": "mock",
    "snapshotStatus": "fresh",
    "statsLagSeconds": 60,
    "dataWindow": {
      "from": "2026-05-28",
      "to": "2026-05-28",
      "label": "今日"
    },
    "summary": {
      "todayContributionTokens": 0,
      "todayConsumptionTokens": 0,
      "cumulativeContributionTokens": 0,
      "cumulativeConsumptionTokens": 0,
      "sustainedContributorCount": 0,
      "publicAccessCount": 0,
      "todayActiveContributorCount": 0,
      "averageConsumerActiveDays": 0
    },
    "supportedModels": [],
    "sustainedContributionRanking": [],
    "cumulativeContributionRanking": [],
    "cumulativeConsumptionRanking": [],
    "dailyContributionRanking": [],
    "dailyConsumptionRanking": [],
    "publicAccess": []

```

响应头建议：

| Header | 说明 |
| --- | --- |
| `Cache-Control: private, max-age=30` | 只允许调用方服务端短缓存，不鼓励公网 CDN 缓存带鉴权响应。 |
| `ETag` | 可选。payload 未变化时后续支持 `304`，不是首版必需。 |
| `X-Trace-Id` | 沿用系统请求上下文，便于排障。 |

## 响应数据结构

首版以公益站当前页面为目标，返回完整页面所需数据。排行榜列表不返回模型列；供应商单独字段返回；消耗榜不返回 Key 信息。

```ts
type PublicRankingSource = 'mock' | 'stats' | 'empty'
type PublicRankingSnapshotStatus = 'fresh' | 'stale' | 'empty'

interface PublicRankingResponse {
  updatedAt: string
  source: PublicRankingSource
  snapshotStatus: PublicRankingSnapshotStatus
  statsLagSeconds?: number | null
  dataWindow: {
    from: string
    to: string
    label: string
  }
  summary: {
    todayContributionTokens: number
    todayConsumptionTokens: number
    cumulativeContributionTokens: number
    cumulativeConsumptionTokens: number
    sustainedContributorCount: number
    publicAccessCount: number
    todayActiveContributorCount?: number
    averageConsumerActiveDays?: number
  }
  supportedModels: string[]
  sustainedContributionRanking: SustainedContributionRankingItem[]
  cumulativeContributionRanking: ContributionRankingItem[]
  cumulativeConsumptionRanking: ConsumptionRankingItem[]
  dailyContributionRanking: ContributionRankingItem[]
  dailyConsumptionRanking: ConsumptionRankingItem[]
  publicAccess: PublicAccessItem[]
}

interface RankingIdentityFields {
  id: number
  name: string
  providerCode?: string
  providerName?: string
  sourceHash?: string
}

interface SustainedContributionRankingItem extends RankingIdentityFields {
  accountCreatedAt: string
  streakDays: number
  averageContributionTokens: number
  badgeTokens: number
}

interface ContributionRankingItem extends RankingIdentityFields {
  contributionTokens: number
  badgeTokens: number
  activeDays: number
  streakDays: number
  todayTokens?: number
  todayActiveChannelCount?: number
}

interface ConsumptionRankingItem extends RankingIdentityFields {
  consumptionTokens: number
  badgeTokens: number
  activeDays: number
  streakDays: number
  todayTokens?: number
}

interface PublicAccessItem {
  id: number
  name: string
  providerCode?: string
  providerName?: string
  baseUrl: string
  apiKey: string
  models?: string[]
}
```

字段约定：

- `id` 是快照内展示 ID，不是 `sub2api-lite` 内部资源 ID。需要排障时使用 `sourceHash`，它只能是不可逆摘要。
- `name` 是公开展示名称。不得默认使用内部用户名、邮箱、真实上游账号名或完整 API Key 前缀。
- `providerCode` / `providerName` 单独返回，前端展示供应商列时不再把供应商合并到名称里。
- `supportedModels` 只表达公益入口当前公开支持的模型集合；排行榜行不带模型字段。
- `publicAccess[].apiKey` 只能来自明确配置为“公益公开入口”的专用本地网关 Key。普通 API Key、管理员自用 Key、用户私有 Key 不能进入该字段。

## 排行口径

| 列表 | 建议 TopN | 主体 | 指标 |
| --- | --- | --- | --- |
| `sustainedContributionRanking` | 3 | 公开贡献实体 | 连续贡献天数、平均每日贡献 Token、徽章 Token |
| `cumulativeContributionRanking` | 3 | 公开贡献实体 | 累计贡献 Token、活跃天数、连续天数、今日贡献 |
| `cumulativeConsumptionRanking` | 3 | 公开消费实体 | 累计消耗 Token、活跃天数、连续天数、今日消耗 |
| `dailyContributionRanking` | 10 | 公开贡献实体 | 今日贡献 Token、活跃天数、连续天数 |
| `dailyConsumptionRanking` | 10 | 公开消费实体 | 今日消耗 Token、活跃天数、连续天数 |

贡献实体和消费实体都需要通过公开展示配置映射：

- 贡献实体可以映射到一个或多个 AI 账户、分组或后续专用公益贡献配置。
- 消费实体可以映射到公益站用户、公益站调用方、专用 API Key 或后续外部调用身份。
- 排名 payload 只返回映射后的公开名称和公开供应商，不暴露底层账号、分组、API Key、系统账户 ID 或授权关系 ID。

## 快照存储设计

新增统计结果库表 `public_ranking_snapshots`，由 mock、维护脚本或后台 worker 写入，接口只读最新可用快照。

```text
public_ranking_snapshots
- snapshot_key TEXT PRIMARY KEY
- source TEXT NOT NULL
- schema_version TEXT NOT NULL
- data_window_from TEXT NOT NULL
- data_window_to TEXT NOT NULL
- window_label TEXT NOT NULL
- payload_json TEXT NOT NULL
- updated_at TEXT NOT NULL
- expires_at TEXT
- stats_lag_seconds INTEGER
- refresh_status TEXT NOT NULL
- last_error_message TEXT
```

首个 `snapshot_key` 固定为：

```text
juhe_ai_public_ranking
```

读取规则：

- API 只按 `snapshot_key` 读取一行 payload，不从 `usage_records`、`usage_stats_daily`、`usage_stats_hourly` 等表现场组合。
- `payload_json` 内保存完整 `PublicRankingResponse` 的业务数据部分。接口可以补充 `snapshotStatus`、`statsLagSeconds` 和缓存头。
- 快照存在且未过期时返回 `source = stats` 或 `mock`、`snapshotStatus = fresh`。
- 快照过期但仍可安全展示时返回旧 payload，并标记 `snapshotStatus = stale`。
- 快照不存在时返回空列表 payload，`source = empty`、`snapshotStatus = empty`，保证公益站页面可以稳定渲染。
- 后续真实 worker 刷新时必须在单事务内完成 payload 覆盖，不能让接口读到半成品。

## 鉴权设计

### 首版必需校验

首版采用集成客户端 ID + Bearer token：

```http
Authorization: Bearer <integration_token>
X-Juhe-AI-Client: juhe-ai-public-welfare
```

服务端验证顺序：

1. 必须存在 `X-Juhe-AI-Client`，且只允许安全字符，例如 `a-zA-Z0-9._-`。
2. 必须存在 `Authorization: Bearer ...`。
3. 根据 client ID 找到启用的集成客户端。
4. 对 token 做 SHA-256 摘要，用常量时间比较命中已启用 token hash。
5. 校验 token 未过期、客户端状态为 `active`、scope 包含 `juhe_ai_public_rankings:read`。
6. 如果配置了 IP allowlist，则校验调用来源 IP。
7. 进入限频检查，通过后读取快照。

集成 token 生成要求：

- 使用至少 32 字节随机数，base64url 或等价高熵字符串展示给调用方。
- 明文只在创建或轮换时展示一次。
- 存储层只保存 `token_hash`、`token_prefix`、`client_id`、状态、过期时间和最近使用时间。
- 普通日志、操作日志、运行日志、错误响应和请求快照都不能保存明文 token。

建议凭据表：

```text
external_integration_clients
- id TEXT PRIMARY KEY
- client_id TEXT UNIQUE NOT NULL
- name TEXT NOT NULL
- status TEXT NOT NULL
- scopes_json TEXT NOT NULL
- allowed_ips_json TEXT
- rate_limit_per_minute INTEGER
- created_at TEXT NOT NULL
- updated_at TEXT NOT NULL

external_integration_tokens
- id TEXT PRIMARY KEY
- client_id TEXT NOT NULL
- name TEXT NOT NULL
- token_hash TEXT UNIQUE NOT NULL
- token_prefix TEXT NOT NULL
- status TEXT NOT NULL
- expires_at TEXT
- last_used_at TEXT
- created_at TEXT NOT NULL
- revoked_at TEXT
```

首版如果暂不做管理页面，可以先用维护脚本创建 / 轮换 token；不建议把明文 token 写入 `.env`。本地开发需要快速联调时，可以只在本地 `.env` 使用一次性 mock token，但生产应写入数据库并只保存 hash。

### HMAC 增强预留

如果后续部署在完全公网、需要抗重放能力，可以为客户端开启 HMAC 模式。HMAC 模式不替代 client ID，它在 Bearer token 之外增加时间戳和 nonce：

```http
X-Juhe-AI-Client: juhe-ai-public-welfare
X-Juhe-AI-Timestamp: 2026-05-28T10:00:00Z
X-Juhe-AI-Nonce: <random_nonce>
X-Juhe-AI-Signature: <base64url_hmac_sha256>
```

签名明文：

```text
METHOD
PATH_WITH_QUERY
TIMESTAMP
NONCE
SHA256_BODY_HEX
```

校验规则：

- 时间戳允许偏移默认 5 分钟。
- nonce 在同一 client 下短期内只能使用一次，TTL 默认 10 分钟。
- GET 空 body 的 `SHA256_BODY_HEX` 使用空字节 SHA-256。
- HMAC secret 需要加密存储，不能只保存 hash；日志只记录 secret ID 或摘要前缀。

HMAC 是生产增强项，不作为首版公益榜联调的必要条件。

## 错误语义

| HTTP | code | 场景 |
| --- | --- | --- |
| `400` | `PUBLIC_INTEGRATION_BAD_REQUEST` | client ID 格式、查询参数或签名头格式错误 |
| `401` | `PUBLIC_INTEGRATION_UNAUTHORIZED` | 缺少认证头、token 无效、签名无效 |
| `403` | `PUBLIC_INTEGRATION_FORBIDDEN` | 客户端停用、scope 不足、IP 不在 allowlist |
| `429` | `PUBLIC_INTEGRATION_RATE_LIMITED` | client + IP 超过限频 |
| `500` | `PUBLIC_RANKING_INTERNAL_ERROR` | 快照读取或 payload 解析异常 |

错误响应沿用系统 API 风格：

```json
{
  "message": "集成认证失败",
  "code": "PUBLIC_INTEGRATION_UNAUTHORIZED"
}
```

快照不存在不是错误，返回空数据。只有数据库不可用、payload 损坏或接口自身异常时才返回 `500`。

## 限频与日志

- 首版用进程内短窗口限频即可，默认 `client_id + IP` 每分钟 60 次；后续多实例再评估共享限频。
- 认证失败同样进入限频，避免坏 token 高频打到 DB service。
- 日志只记录 `clientId`、`tokenPrefix`、来源 IP 摘要、路由、状态码、耗时和 `traceId`。
- 不记录完整 `Authorization`、完整签名、完整 nonce 列表、完整 publicAccess API Key 或 payload 中的敏感字段。
- 查询接口不写操作日志；创建、禁用、轮换集成客户端 token 才写操作日志。

## 公益站调用方式

`juhe-ai-public-welfare` 应由自己的后端调用该接口，随后把需要公开展示的数据提供给浏览器。不要把集成 token 写入前端包、页面源码或浏览器请求。

PowerShell 联调示例：

```powershell
$headers = @{
  Authorization = "Bearer <integration_token>"
  "X-Juhe-AI-Client" = "juhe-ai-public-welfare"
}

Invoke-RestMethod `
  -Uri "https://sub2api.example.com/__aisys__/api/external-integrations/juhe-ai/rankings" `
  -Headers $headers
```

`juhe-ai-public-welfare` 后端适配时需要读取 `response.data` 作为页面数据源；如果公益站内部接口仍保持无包装结构，由公益站后端负责解包，不要求浏览器理解 `sub2api-lite` 的系统 API 包装。

## 实施阶段

### 第一阶段：mock 快照联调

- 新增外部集成鉴权中间件。
- 新增 `GET /__aisys__/api/external-integrations/juhe-ai/rankings`。
- 新增 `public_ranking_snapshots` schema，或在开发期用固定 mock service 生成同结构 payload。
- 提供维护脚本写入 `snapshot_key = juhe_ai_public_ranking` 的 mock payload。
- 公益站后端按真实鉴权和真实响应结构联调。

### 第二阶段：真实统计快照

- 后台 worker 从现有统计缓存、公开贡献配置和公益入口配置生成 payload。
- 贡献榜和消耗榜只读取预聚合表、范围窗口和排行快照，不读明细表。
- `publicAccess` 只读取明确标记为公益公开的专用入口配置。
- worker 刷新失败时保留上一次可用 payload，并更新 `refresh_status` / `last_error_message` 的脱敏摘要。

### 第三阶段：运维管理

- 增加管理员可用的集成客户端列表、创建、禁用和 token 轮换能力。
- 增加最近调用时间、失败次数、限频命中和 token 即将过期提示。
- 需要公网强校验时启用 HMAC 模式。

## 验证清单

- 无 `Authorization` 返回 `401`。
- token 错误返回 `401`，日志不出现明文 token。
- client 停用、scope 不足或 IP 不匹配返回 `403`。
- 正确 token 返回 `{ data: PublicRankingResponse }`。
- 快照缺失返回空数据，页面仍可渲染。
- 排行榜行不包含模型字段，不包含 API Key 明文，不包含内部系统账户 ID。
- 供应商字段以 `providerCode` / `providerName` 单独返回。
- `publicAccess` 只包含显式公益公开入口；普通本地 API Key 不会被扫入。
- 接口实现不能出现请求路径 `SUM/GROUP BY usage_records`、扫描 usage shard 或把统计桶现场相加生成摘要。
