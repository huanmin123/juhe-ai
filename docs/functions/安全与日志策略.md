# 安全与日志策略

> 面向后端、前端、部署和 AI 维护者。
> 本文统一敏感字段、凭据展示、请求快照、日志原文保留、数据保留和迁移密钥规则，避免调试便利性和排障性能互相冲突。

## 文档目标

- 明确哪些数据必须加密、限制展示，以及哪些日志型落点按原文保留。
- 约束使用记录请求 / 响应快照的保存边界；使用记录页面不提供快照查看，具体日志和原文只能从日志管理能力进入。
- 固定本地自用场景下的 API Key、上游凭据、OAuth token 和代理密码处理规则。
- 给新增接口、后台任务、网关错误处理和部署迁移提供安全检查清单。

## 项目级默认约束

- 项目默认不做安全脱敏、日志清洗、sanitizer、字段替换、凭据隐藏或 `[redacted]` 输出处理；前端、后端、测试、脚本、日志、审计、请求快照和诊断输出均适用。只有用户单独明确要求时才实施，不能以安全优化、审查意见或顺手保护为理由自行加入。历史专门规则不因本条自动触发全项目重构。

## 不可回退规则

- 日志型落点不做敏感字段递归脱敏是当前项目的明确规范，不是临时实现。覆盖范围包括系统运行日志、错误日志、原始审计日志、使用记录快照、公开接口日志和操作日志；字段名、字符串形态或 URL 内容不能触发原值替换。唯一例外是操作日志结构化变更项的 `change.field` 经 `trim().toLowerCase()` 后精确命中认证容器 allowlist 时，before / after 改写为“未设置 / 已设置 / 已变更”状态摘要；allowlist 为 `credentials/credential/token/key/secret/password/apikey/api_key/apikeys/api_keys/accesstoken/access_token/refreshtoken/refresh_token/idtoken/id_token/identitytoken/identity_token/clientsecret/client_secret/sessiontoken/session_token/proxypassword/proxy_password`。
- 原始审计 payload 的 body 按原文字节保存；“审计 payload body 未脱敏”不是缺陷，不提供脱敏开关，也不保留审计 body 脱敏 API、配置项或回归入口。
- 后续优化普通日志、安全、审计、使用记录、公开接口日志或操作日志时，不得重新引入字段名匹配、header 名匹配、URL 查询参数匹配、token 字符串正则扫描或 `[redacted]` 替换。操作日志只允许上述结构化字段精确 allowlist 摘要，不得扩展为字段子串、普通文本、metadata、summary、序列化 JSON 或疑似 token 字符串扫描。
- 日志风险控制只能放在捕获范围、权限、保留期、容量上限、深度 / 条目 / 字符串预算、截断标记、压缩去重、分块窗口读取和导出前人工移除这些边界上；不能在日志入队、落库、索引或输出层重新做敏感字段脱敏。操作日志只额外在入队前完成上述结构化字段精确摘要。公开接口日志的请求 header 捕获范围只包含 `contentType` / `contentLength`，不包含 `Authorization`、`Cookie` 或鉴权来源 token。
- 安全加固类审查建议默认不作为缺陷处理；只有影响实际运行、容量、稳定性、数据一致性或用户明确要求的边界，才进入修复范围。
- 不再为任何日志型落点预留恢复敏感字段递归脱敏的开关、兼容分支或回归入口；上述操作日志精确摘要不是可选开关，也不能扩展为递归或文本 sanitizer。

## 管理面浏览器安全头

- `/__aisys__` 管理面固定返回 CSP：脚本只允许 `'self'`，禁止 `unsafe-eval`、对象嵌入和第三方页面 iframe 嵌套；表单只允许提交到本站。
- 当前前端需要 Ant Design Vue 内联样式，因此 `style-src` 保留 `'unsafe-inline'`，但该放宽不得扩展到 `script-src`。图片、字体、媒体、Worker 和连接能力按当前聊天、图片与实时连接边界保留 `data:`、`blob:`、HTTPS 和 WSS。
- 管理面同时返回 `X-Frame-Options: DENY`、`X-Content-Type-Options: nosniff` 和 `Referrer-Policy: strict-origin-when-cross-origin`。
- Express 全局关闭 `X-Powered-By` 响应标识；这只隐藏技术栈，不改变状态码、响应体或路由。
- 管理面 CSP 只挂载在 `/__aisys__`，不得套用到 `/v1` 网关。后续新增外部脚本或资源类型时必须先通过 CSP 回归和无扩展浏览器验证，不得用 `unsafe-eval` 绕过失败。
- 这些响应头不改变系统账户开户、用户注册、密码初始化、登录表单、验证码、DNS、WireGuard 或反向代理拓扑。

## 敏感数据分级

| 级别 | 数据 | 存储规则 | 展示规则 | 日志规则 |
| --- | --- | --- | --- | --- |
| S0 明文禁止 | 上游 API Key、OAuth access token、OAuth refresh token、代理密码、会话 token、外部来源系统 token、加密密钥 | 必须密文或哈希存储；会话 token 只存哈希，外部来源系统 token 保存 hash 和加密密文 | 仅自有资源编辑场景按需展示完整凭据；授权资源永不展示；外部来源系统 token 可在创建弹窗和单条复制接口按管理员权限展示 | 是否进入日志取决于模块捕获范围、权限、保留期和容量预算；已进入捕获范围的值不按字段名或字符串形态替换 |
| S1 高敏摘要 | 本地网关 API Key、凭据指纹、验证码、登录失败上下文 | API Key 明文按产品边界密文存储；验证码答案只短期内存，验证码图片不包含可直接解析的文本答案，公开验证码生成需先做 IP 级限频 | 自用后台可按权限展示本地 API Key；密文字段缺失时停机离线修复或重建 | 不额外做敏感字段替换；调用方必须控制是否捕获 |
| S2 业务敏感 | 请求体、响应体、客户端 IP、模型输入输出、上游错误正文 | 只在必要场景保存，优先失败记录和有限长度快照 | 使用记录页面只展示结构化列表字段，不返回请求 / 响应快照；具体日志按各自日志管理权限查看 | 只保留捕获范围、容量上限和截断标记，不做敏感字段脱敏 |
| S2-B 操作日志 | 业务资源变更摘要、字段差异、操作人、影响用户、trace ID、客户端 IP | 独立操作日志表保存，默认保留时间长于使用记录 | 用户只看与自己有关的权限裁剪结果；管理员看全部 | 只记录成功状态变更，不记录查询；`change.field` 精确命中认证容器 allowlist 时只保存状态摘要，其余字段按传入内容和长度上限保存 |
| S2-P 公开接口日志 | `/__aipublic__` 来源系统调用元数据、有限请求 / 响应快照、客户端 IP、trace ID | 独立公开接口日志表保存；保留期由 `publicApiLogRetentionDays` 控制，默认 30 天，合法范围 `1..365` | 仅管理员可见 | header 只捕获 `contentType` / `contentLength`；query、body、response 在捕获预算内保留原值，超限截断并标记捕获状态 |
| S2-A 原始审计 | 客户端请求、上游请求、上游响应、最终返回中的 headers 和 body | 仅写入原始审计日志 payload，按容量策略压缩和去重 | 当前仅管理员可见，页面默认折叠原文 | headers、queryString 和 body 均按原文保存；只通过原始审计日志队列终态保存 |
| S3 运维信息 | 状态码、耗时、token 用量、模型、账号 ID、分组 ID、错误分类 | 可明文保存 | 按权限展示 | 可记录，但避免拼接敏感上下文 |

## 凭据存储

- OpenAI OAuth token、OpenAI API Key 和代理密码必须通过后端加密后写入 SQLite。
- `JUHE_AI_SECRET` 影响当前业务库中的密文解密，复用当前业务库时必须保持一致。
- 会话 token 只保存哈希，不保存可直接使用的明文 token。
- 外部来源系统 token 保存带用途前缀的 SHA-256 摘要、加密密文和安全展示用前缀 / 后缀；鉴权按 hash 点查，后台复制按单条 token 解密。
- 凭据指纹只用于重复校验和排查，不可反推出原始凭据。
- 不把供应商密钥、OAuth token、代理密码或本地 API Key 写入 `.env`；`.env` 只保存运行配置和加密密钥。

## 凭据展示

- 自有 AI 账户编辑弹窗可以按页面需要查看和修改完整上游凭据。
- AI 账户列表不展示完整上游凭据，只展示账号类型、状态、来源、可用性和必要摘要。
- 授权账户和授权分组接口不能返回完整凭据、代理密码、账户错误处理策略详情中可能含敏感匹配内容的字段。
- 本地网关 API Key 列表按前8位和后8位展示安全标识，创建成功弹窗和单条复制接口可按资源权限返回完整明文；`key_secret_encrypted` 是当前必需字段，数据缺字段或密文不可解时停机离线修复或重建，不在运行时降级展示。
- 外部来源系统 token 列表按前8位和后8位展示安全标识，创建弹窗和单条复制接口可按管理员权限返回完整明文；demo 响应只返回 token 前缀，明文 token 应保存到调用方后端配置。
- 前端复制、查看、测试等操作必须有清晰中文提示，避免用户误以为授权资源拥有管理权。

## 请求和响应快照

使用记录是事实源，但快照不是无限制审计仓库，也不是用户侧日志查看入口。

保存边界：

- 成功记录优先保存结构化指标：endpoint、模型、状态码、耗时、token、成本、账号、分组和授权关系。
- 失败记录可以保存 `request_snapshot_json`、`response_snapshot_json` 用于排查；快照不做敏感字段脱敏，但必须保留大小、深度、字段数量和字符串长度上限。
- 流式响应不保存完整 SSE 内容；只保存错误摘要、完成状态、token 统计和必要的最后错误。
- 使用记录列表只返回结构化统计字段；不论管理端还是个人端，都不能通过使用记录接口读取请求快照、响应快照、客户端 IP 之外的正文或具体日志。授权资源调用的具体内容和日志按日志管理页面及其权限查看。
- 使用记录快照入队 / 落库前只做容量和结构保护，不再按凭据类 headers、敏感字段或 URL 敏感查询参数替换原值。

原文和容量规则：

- 请求和响应 headers 按捕获到的原文保存。
- 请求体、响应体、错误消息和 URL 查询参数按捕获到的原文保存。
- 日志系统不再对疑似 API Key、OAuth token、JWT、refresh token、password、secret、cookie、session、authorization 字段做字符串扫描替换。
- 快照长度必须有上限；超出后截断并标记 `truncated: true`。
- 序列化失败或请求体已被网关拒绝时，可以按模块规则写 `dropped` 或省略正文；不能把截断内容伪装成完整原文。

## 原始审计日志例外

原始审计日志是独立的高权限排障能力，具体捕获边界见 [原始审计日志设计](原始审计日志设计.md)，容量治理见 [审计日志保全策略设计](审计日志保全策略设计.md)。当前日志口径统一按原文保留，原始审计的特殊点在于完整链路捕获、采样和 blob 保全策略。

边界规则：

- 原始审计日志可以捕获客户端请求、上游请求、上游响应和最终返回客户端的 headers 与 body；headers、queryString 和 body 均不脱敏、不改写。
- 完全成功请求默认先进入最近 1 小时原始审计热保留窗口，超过热窗口后只保留 10% 稳定采样；失败、异常、客户端中断、流式中断和重试后成功链路必须进入原始审计。已进入原始审计的正文内容可按保全策略压缩、去重和过期；未完整保留正文时必须明确标记为 `summary_only`、`hash_only`、`expired`、`overflow` 或 `dropped`，不能伪装成完整原文。
- 原始审计日志必须使用独立表和独立管理接口；普通运行日志、错误日志和使用记录快照是否记录完整内容由各自捕获范围和容量上限决定，不再通过敏感字段脱敏区分。
- 原始 payload 可以压缩后存储，用于降低磁盘、备份和查询压力。
- 原始 payload 按原始明文字节计算 hash；相同正文可以通过内容地址去重，多条事件引用同一 blob 不视为删除证据。
- 管理页面点击原始 payload 时只读取 `256 KiB` 首窗口；正文仍有后续内容时由用户点击“加载下一段”继续按 `offset` 读取，后续窗口不重复读取或返回 Headers，禁止页面自动循环拉取完整正文。
- 原始审计 payload 中的 `Authorization`、`Proxy-Authorization`、`Cookie`、`Set-Cookie`、`X-API-Key`、`API-Key`、`OpenAI-API-Key` 等凭据类 headers 按原文保存。
- 原始审计日志仅允许 `admin` 查看；普通用户不能查看自己的原始审计原文，资源所有者也不能通过授权关系查看被授权人的审计原文。
- 列表、搜索和导出默认只展示元数据、hash、大小和保留状态。
- 网关请求链路禁止同步写审计表，只能在请求结束、失败或客户端中断后把终态审计对象放入内存队列，由后台批量落库。
- SSE 和其他流式响应不能按 chunk 实时写库；只有流自然结束、失败、超时或客户端断开后，才允许按终态记录入队。
- 审计队列是 best-effort 内存队列，系统重启、进程崩溃或队列溢出导致数据丢失可以接受；不得为了审计完整性阻塞正常请求。
- 队列上限触发时，优先丢弃成功采样记录；如果仍无法容纳，允许丢弃非成功记录并记录丢弃计数，供运维排查。

## 日志规则

- 普通运行日志只记录时间、级别、`traceId`、事件名、业务摘要和错误摘要；日志输出层不再对结构化字段、Error message/stack 或 JSON 行做敏感字段脱敏。
- 普通运行日志必须使用统一结构化日志框架输出，默认字段包含 `traceId`；请求响应头也应返回 `x-trace-id`，便于按链路 ID 检索同一次请求的相关日志。
- Node 与 Go 普通运行日志统一保留 `version`、`service`、`role`、`event` 基础字段；HTTP、IPC 和 worker 任务按可获得的事实关联 `traceId`、`requestId`、`jobId` 和 `parentId`，不得为无关任务生成同一个伪关联 ID。
- 网关关键流程使用 `gateway.request.stage` info 事件记录 `stage`、固定枚举 `outcome`、阶段局部 `durationMs`、相对请求起点的 `startedOffsetMs/endedOffsetMs`。业务字段不得覆盖这些保留字段；完整阶段清单和性能证据见 `../reports/网关阶段日志与异步写入验证报告-2026-07-21.md`。
- Node Pino 在主线程完成字段组装和 JSON 序列化，再通过异步 `fs` stream 将 JSONL 顺序追加到当前角色 durable spool；积压 chunk 通过 `_writev` 合并为有界批次，避免逐行底层写入。常态不采样，也不因索引队列丢行。每个输出目的地使用独立的 normal 64 MiB 与 failure 8 MiB 待写预算；永久慢盘或目的地故障导致预算耗尽时，必须显式累计 drop、保留最后一条有界现场，并通过单 in-flight + 单 pending 的异步 stderr 保底记录首次目的地故障或 failure 预留耗尽。该极端退化是“非阻塞、内存有界、永久零丢失”不可兼得时的明确取舍，不能宣称每条日志永久无损。文件 I/O、轮转、清理和 runtime-log 索引不在请求路径同步等待。
- Go 使用有界异步 `slog.Handler` 的 normal、failure、emergency failure 通道。normal 满载累计 `normalDropped`；failure 先使用预留容量，只有 normal 之外的两个 failure 通道同时饱和时才累计 `failureDropped`，并在 drop summary 中保留最后一条有界失败现场。不能把此极端退化口径描述成每条失败永久无损。进程优雅退出必须在固定时限内 drain 已接收日志；进程级未捕获异常继续使用独立 fatal diagnostic 作为保底证据。
- 可预知失败日志保留 reason code、阈值、当前值、候选数量、重试/队列决策等非敏感参数；不可预知失败保留原始 Error name/message/stack/code/cause、当前阶段和有界队列/重试快照。失败现场仍受捕获范围、字段/深度/总量预算约束，普通日志不得借此复制原始审计 payload。
- 普通运行日志需要支持文件滚动和历史清理；默认写入项目内后端日志目录，按单文件大小滚动，并按保留天数和最大文件数清理旧文件。
- 普通运行日志的索引查询不直接扫描日志文件；各业务进程只把完整 JSON Lines 顺序追加到角色日志文件，索引启用时由 `ingest-worker` 按持久化 file identity / truncation generation / byte cursor 有界读取并异步索引到当前存储 driver 的 `runtime_logs`。部署环境可用 `JUHE_AI_RUNTIME_LOG_INDEX_ENABLED=false` 临时停止 tail、解析、cursor、facets 与数据库写入；文件输出、轮转、保留和 grep 不受影响。该开关不影响使用记录、操作日志或公开 API 日志。
- 普通运行日志的索引查询不直接扫描日志文件；各业务进程只把完整 JSON Lines 顺序追加到角色日志文件，索引启用时由 `ingest-worker` 按持久化 file identity / truncation generation / byte cursor 有界读取并异步索引到当前存储 driver 的 `runtime_logs`。解析、正则、脱敏、SHA-256、索引 DTO、数据库写入、Redis XADD 和 IPC line 回传禁止进入业务日志热路径；索引按 `traceId`、级别、事件、索引日志时间查询，关键字只对 `message` 列做普通模糊匹配，不检索 `raw_json`。部署环境可用 `JUHE_AI_RUNTIME_LOG_INDEX_ENABLED=false` 临时停止 tail、解析、cursor、facets 与数据库写入；文件输出、轮转、保留和 grep 不受影响。该开关不影响使用记录、操作日志或公开 API 日志。
- 运行日志索引不得通过采样、低级别丢弃或整行截断降低压力。消费端必须先成功提交完整批次再推进 cursor；轮转文件在 cursor 追平前受清理保护，原文件截断时通过持久化代次生成新的稳定索引 ID。
- 运行日志列表接口只返回分页结果；索引筛选项、grep 文件范围和页面告警需要的运行态可用性分别由 `/runtime-logs/facets`、`/runtime-logs/grep-options` 和 `/runtime-logs/runtime` 按页面交互或空闲时机读取。`runtime` 只返回页面实际消费的可用性字段，使用独立轻量 scope 和 O(1) 进程状态，不请求完整 worker 快照、遍历账户运行态或组装队列 / DB service 指标明细；`facets` 不采集运行态或扫描日志文件，grep 命中项只返回一份 `line` 原文。
- 普通运行日志搜索索引只保留最近 3 天；超过 3 天的日志文件即使仍在日志目录里，也不通过“日志搜索”的索引查询模式检索。
- 日志搜索页提供独立 `grep 模式`，仅管理员可用，只允许在后端普通日志目录内搜索当前保留的 `.log` 文件；文件日志默认保留 30 天，并受最多 500 个轮转文件和单文件大小限制。不允许传入任意文件路径；多关键字最多取前 10 个去重关键字，按同一行同时命中处理，同一后端进程一次只允许 1 个 grep 搜索，响应限制返回条数，并对单次 `rg` 搜索设置 15 秒超时。
- `grep 模式` 默认按文件时间搜索最近 3 天，支持选择文件时间范围；单次文件时间范围最多 7 天，后端必须对 `startAt` / `endAt` 归一化和截断，避免一次扫描过多日志文件。时间范围只用于筛选参与扫描的文件，不能读取文件内容判断行时间。
- `grep 模式` 必须由后端调用 `rg --json` 执行文件内容搜索，不允许使用 shell 拼接命令。Go 原生路径优先使用 `JUHE_AI_RG_PATH`，留空时只通过 `exec.LookPath` 查找 `rg`；Node 路径在删除前继续使用生产依赖 `@vscode/ripgrep`。缺少或执行失败时必须直接返回中文不可用提示，不允许回退到应用层逐行扫描，也不得回显日志目录、二进制路径或命令错误；搜索结果必须按最新优先展示。
- 普通运行日志不主动扩大捕获范围；如果业务代码把完整请求体、响应体、请求头、API Key、token、验证码答案、登录密码或代理密码写入日志，日志层按原文输出。
- 上游错误可以记录状态码、错误类型、错误码和截断摘要；进入日志和快照的内容按原文保存。
- 登录失败日志只记录用户名摘要、客户端 IP、失败原因分类和限频状态，不记录密码或验证码原文。
- 登录验证码默认启用。开发、测试自动化或生产临时排障可设置 `JUHE_AI_AUTH_CAPTCHA_DISABLED=true`，但它仅跳过验证码校验，不跳过账号密码、登录限频、会话和权限校验；所有环境开启时必须输出明确 warn 日志，排障结束后恢复 `false`。
- 后台任务日志只记录任务名、作用域、处理数量、成功失败数量、耗时和截断错误摘要。
- 原始审计日志批量落库 worker 的普通日志仍只记录批量数量、耗时、队列长度、丢弃计数和错误摘要，不主动把完整 payload 打到控制台或文件日志；若调用方显式记录 payload，日志层不会脱敏。

## 操作日志规则

操作日志是业务状态变更追溯能力，具体设计见 [操作日志设计](操作日志设计.md)。它记录“谁改了什么、影响了谁”，但不是请求审计仓库。

边界规则：

- 操作日志只记录成功提交的增删改、启停、绑定、授权、成员变化、发布下线、密码变更、系统设置变更等状态变化。
- `GET`、列表、详情、筛选、分页、搜索、日志查看和审计查看都不写操作日志。
- Go W2 account tags PATCH 当前只在标签集合替换成功后 best-effort 投递 operation log；参数校验失败、权限失败、资源不存在或队列入队失败都不能改变业务响应语义，其中入队失败只写普通运行日志。
- 操作日志可以保存操作人、业务作用域、资源 ID、资源名称、字段级差异、影响用户、trace ID、客户端 IP 和 User-Agent 摘要。
- 被授权用户操作授权实例时，操作日志业务作用域和普通用户可见范围归当前被授权用户或管理员代操作的目标用户；来源账户归属人不能因为拥有上游资源事实而自动成为该本地操作日志的可见人。
- 操作日志不作为请求审计仓库，不主动捕获完整请求体、完整响应体或完整 headers；非敏感字段差异按调用方传入值保存，仍受字符串长度和变更条数上限控制。
- 结构化变更项的 `field` 精确命中上述认证容器 allowlist 时，before / after 只保存“未设置 / 已设置 / 已变更”状态摘要，不能序列化容器内的 WIF JWT、Google/OpenAI refresh token、client secret、password 或 API Key。
- 操作日志不对普通文本、metadata、summary、字段子串或序列化 JSON 做敏感关键词正则扫描；调用方仍不得把秘密拼入非敏感字段。
- 普通用户可见的系统设置、代理、账户错误处理策略等管理员资源变更仍按可见级别裁剪；管理员详情按原文日志口径展示已记录内容。
- 普通用户操作日志接口必须由后端按可见级别裁剪，不能返回可见用户列表、客户端 IP 或 User-Agent；`summary` 级还不能返回字段差异、影响对象和请求路径。
- 操作日志入队或落库失败不能静默吞掉，必须写普通运行日志和队列运行态；但操作日志属于数据集目录库追溯数据，不能为了日志完整性回滚已经同步提交成功的业务库变更。

## 公开接口日志规则

公开接口日志是 `/__aipublic__` 外部来源接口的调用排障能力，具体设计见 [公开接口日志设计](公开接口日志设计.md)。它记录“哪个来源系统在什么时候调用了哪个公开接口、耗时和结果如何”，但不是原始审计仓库。

边界规则：

- 只记录 `/__aipublic__` 前缀下的公开接口请求，不记录后台管理接口、网关请求、静态资源或健康检查。
- 公开接口日志可以保存来源系统、token 前缀、接口路径、状态码、耗时、客户端 IP、User-Agent、trace ID、有限请求快照和有限响应快照。
- 公开接口日志的请求 header 快照只捕获 `contentType` / `contentLength`；不捕获 `Authorization`、`Cookie` 或作为 Bearer 凭据传入的来源 token。来源身份只通过 `token_id`、`token_name`、`token_prefix` 等元数据记录。
- query、请求 body 和响应 body 在捕获范围内保留原始值，不按 `key`、`apiKey`、`token`、`secret`、`password`、hash、URL userinfo 或字符串形态递归替换，也不写 `[redacted]` 占位。`api-key/add` 一次性响应中的完整本地 API Key、`account/add|update` 请求中的上游 `apiKey` 和带 userinfo 的 URL 一旦进入正文捕获范围，也按该规则保留。
- 请求和响应单侧快照上限为 `32KB`，结构预算固定为最大深度 `8`、每个对象 / 数组最多 `200` 个条目、单字符串预览最多 `4096` 字节；超限内容写 `truncated`，序列化失败或请求体已被拒绝时写 `dropped`，不能伪装成完整原文。
- 公开接口日志仅允许管理员查看；普通用户和外部来源系统不能查询公开接口日志。
- 公开接口日志保留期由 `publicApiLogRetentionDays` 控制，默认 30 天，合法范围 `1..365`，由后台数据保留清理任务分批删除。

## 客户端 IP 与代理链路

- 服务端可以在本地使用记录中保存客户端 IP，用于调用方排查和管理员审计。
- 默认不向上游透传 `X-Forwarded-For`、`X-Real-IP` 等代理链路头，避免暴露本地或代理链路信息。
- 如果业务需要不同出口身份，应通过账号绑定代理或分组代理策略解决，不通过伪造请求头解决。
- 客户端 IP 可用于认证后的短 TTL 调度辅助和错误风暴止损，例如 IP 级账号回避、单 IP 并发保护和 IP 级错误熔断；这些状态只能作为易失运行态，不得写成永久封禁、账号健康结论或真实用户身份判断。

## 数据保留与清理

- 使用记录和统计缓存需要支持保留天数配置；默认值以系统设置和 SQLite 文档为准。
- 快照保留周期应不长于使用记录保留周期；后续数据量增大时优先清理快照，再清理结构化事实记录。
- 操作日志用于追溯业务状态变化，默认保留周期应长于使用记录和原始审计日志；清理操作日志只按时间执行，不因资源删除级联删除历史日志。
- 公开接口日志只用于外部来源系统调用排障，按 `publicApiLogRetentionDays` 清理过期记录。
- 原始审计日志有独立保留周期：成功样本、失败 / 异常事件、失败 / 异常正文、错误聚合组和无引用 blob 可以采用不同保留时间；清理审计日志不影响使用记录和统计缓存。
- OAuth 额度快照、统计缓存和系统监控样本是缓存或运行态数据，可以按保留策略清理，不作为唯一事实源。
- 删除账户、分组或授权关系不应破坏历史使用记录追溯；历史记录保留当时冗余的资源 ID、所有者和授权关系。

## 备份与恢复

- 复用当前数据时必须同时备份业务库 `backend/data/juhe-ai.sqlite3`（或 `JUHE_AI_DATABASE_PATH` 指向的业务库）和 `backend/.env`。
- 统计数据集目录库 `backend/data/juhe-ai-dataset.sqlite3`（或 `JUHE_AI_DATASET_DATABASE_PATH` 指向的库）和 usage shard 目录默认不纳入业务备份；其中的使用记录、运行日志索引、操作日志、原始审计和模型检测明细都属于可丢失、可过期或排障类数据，新写入的使用记录位于 usage shard 文件。
- 统计结果库 `backend/data/juhe-ai-stats.sqlite3`（或 `JUHE_AI_STATS_DATABASE_PATH` 指向的库）默认不纳入业务备份；其中的统计缓存、额度窗口、账号质量、系统监控、表监控历史和 `stats_job_state` 都属于可重建或运行态结果。
- 业务库和 `backend/.env` 是恢复的硬边界，必须备份。统计数据集目录库、使用记录目录库、usage shard 和统计结果库都可以丢弃、清空或重建；如果做离线取证，才先停服务再额外备份数据集目录库、使用记录目录库或 usage shard 目录。不要在高流量时对整库执行在线 `.backup`。
- 复用当前业务库必须保持 `JUHE_AI_SECRET` 不变，否则已加密凭据无法解密；当前 schema 之外的结构或密文问题由用户按当前 schema 离线修复，不写运行时分支。
- 对外分享日志、数据库、截图或 bug 记录前，必须先移除 S0 / S1 数据、业务敏感快照、操作日志中的人员和资源敏感摘要，以及原始审计日志 payload。
- 文档、计划、bug 和重构记录不得包含真实 token、完整 API Key、真实用户隐私或完整上游敏感错误正文。

## 安全检查清单

- 新字段是否属于 S0 / S1 / S2 / S3？
- 是否需要密文存储、哈希存储或只保存摘要？
- 接口是否会向授权资源返回不该展示的凭据或配置？
- 使用记录或日志是否可能写入完整请求头、请求体、响应体或 token？如果需要查看具体内容，是否明确进入日志管理 / 原始审计模块，而不是使用记录列表？
- 是否需要对快照做截断、捕获状态标记和查看权限限制？
- 如果接口会改变业务状态，是否按 [操作日志设计](操作日志设计.md) 注册操作语义、字段差异和影响用户？如果只是查询，是否明确不写操作日志？
- 如果需要完整原文，是否明确进入原始审计日志模块，而不是普通日志或使用记录快照？
- 原始审计日志是否遵守终态入队、后台批量写库、SSE 结束后入队和不阻塞网关请求？
- 是否影响 `JUHE_AI_SECRET`、备份迁移、部署文档或 `.env.example`？
- 如果原始审计正文体积可能增大，是否按 [审计日志保全策略设计](审计日志保全策略设计.md) 明确了压缩、去重、采样和保留？
- 是否需要同步 [接口契约与权限矩阵](接口契约与权限矩阵.md)、[SQLite 存储说明](SQLite存储说明.md) 或 [部署文档目录](../deploy/README.md)？
