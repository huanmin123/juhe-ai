# 安全与日志策略

> 面向后端、前端、部署和 AI 维护者。
> 本文统一敏感字段、凭据展示、请求快照、日志脱敏、数据保留和迁移密钥规则，避免调试便利性变成凭据泄露风险。

## 文档目标

- 明确哪些数据必须加密、脱敏、限制展示或禁止写入日志。
- 约束使用记录请求 / 响应快照的保存边界和查看权限。
- 固定本地自用场景下的 API Key、上游凭据、OAuth token 和代理密码处理规则。
- 给新增接口、后台任务、网关错误处理和部署迁移提供安全检查清单。

## 敏感数据分级

| 级别 | 数据 | 存储规则 | 展示规则 | 日志规则 |
| --- | --- | --- | --- | --- |
| S0 明文禁止 | 上游 API Key、OAuth access token、OAuth refresh token、代理密码、会话 token、加密密钥 | 必须密文或哈希存储；会话 token 只存哈希 | 仅自有资源编辑场景按需展示完整凭据；授权资源永不展示 | 禁止写入普通日志、错误详情和请求快照 |
| S1 高敏摘要 | 本地网关 API Key、凭据指纹、验证码、登录失败上下文 | API Key 明文按产品边界存储或只创建时返回；验证码只短期内存 | 自用后台可按约定展示本地 API Key；列表可展示尾号或完整密钥需明确提示 | 只记录尾号、哈希前缀或资源 ID |
| S2 业务敏感 | 请求体、响应体、客户端 IP、模型输入输出、上游错误正文 | 只在必要场景保存，优先失败记录和有限长度快照 | 调用者可查看自己的明细；资源所有者只看授权聚合 | 默认脱敏和截断，不写完整大内容 |
| S3 运维信息 | 状态码、耗时、token 用量、模型、账号 ID、分组 ID、错误分类 | 可明文保存 | 按权限展示 | 可记录，但避免拼接敏感上下文 |

## 凭据存储

- OpenAI OAuth token、OpenAI API Key 和代理密码必须通过后端加密后写入 SQLite。
- `JUHE_AI_SECRET` 影响已有密文解密，迁移已有数据库时必须保持一致。
- 会话 token 只保存哈希，不保存可直接使用的明文 token。
- 凭据指纹只用于重复校验和排查，不可反推出原始凭据。
- 不把供应商密钥、OAuth token、代理密码或本地 API Key 写入 `.env`；`.env` 只保存运行配置和加密密钥。

## 凭据展示

- 自有 AI 账户编辑弹窗可以按页面需要查看和修改完整上游凭据。
- AI 账户列表不展示完整上游凭据，只展示账号类型、状态、来源、可用性和必要摘要。
- 授权账户和授权分组接口不能返回完整凭据、代理密码、错误策略详情中可能含敏感匹配内容的字段。
- 本地网关 API Key 是自用管理能力，当前产品可在 API Key 页面展示以方便复制；如果后续引入多人生产部署，应改成“创建时返回一次 + 列表只展示尾号”。
- 前端复制、查看、测试等操作必须有清晰中文提示，避免用户误以为授权资源拥有管理权。

## 请求和响应快照

使用记录是事实源，但快照不是无限制审计仓库。

保存边界：

- 成功记录优先保存结构化指标：endpoint、模型、状态码、耗时、token、成本、账号、分组和授权关系。
- 失败记录可以保存 `request_snapshot_json`、`response_snapshot_json` 用于排查，但必须先脱敏和截断。
- 流式响应不保存完整 SSE 内容；只保存错误摘要、完成状态、token 统计和必要的最后错误。
- 授权资源调用的明细归调用方查看；资源所有者只能查看授权维度聚合用量，不能查看对方请求快照、响应快照、客户端 IP 或业务内容。

脱敏规则：

- 请求头中必须移除或掩码：`authorization`、`cookie`、`set-cookie`、`x-api-key`、`openai-*` 中可能包含会话或组织凭据的字段、代理认证头。
- 请求体和响应体中必须掩码疑似 API Key、OAuth token、JWT、refresh token、password、secret、cookie、session、authorization 字段。
- URL 查询参数中必须掩码 `key`、`token`、`secret`、`code`、`state`、`password` 等敏感参数。
- 快照长度必须有上限；超出后截断并标记 `truncated: true`。
- 脱敏失败时宁可不保存快照，也不要保存原文。

## 日志规则

- 普通运行日志只记录时间、请求路径、状态、耗时、资源 ID、错误分类和安全错误摘要。
- 不记录完整请求体、完整响应体、完整请求头、完整 API Key、完整 token、验证码答案、登录密码和代理密码。
- 上游错误可以记录状态码、错误类型、错误码和截断摘要；完整上游响应只允许进入已脱敏快照。
- 登录失败日志只记录用户名摘要、客户端 IP、失败原因分类和限频状态，不记录密码或验证码原文。
- 后台任务日志只记录任务名、作用域、处理数量、成功失败数量、耗时和截断错误摘要。

## 客户端 IP 与代理链路

- 服务端可以在本地使用记录中保存客户端 IP，用于调用方排查和管理员审计。
- 默认不向上游透传 `X-Forwarded-For`、`X-Real-IP` 等代理链路头，避免暴露本地或代理链路信息。
- 如果业务需要不同出口身份，应通过账号绑定代理或分组代理策略解决，不通过伪造请求头解决。

## 数据保留与清理

- 使用记录和统计缓存需要支持保留天数配置；默认值以系统设置和 SQLite 文档为准。
- 快照保留周期应不长于使用记录保留周期；后续数据量增大时优先清理快照，再清理结构化事实记录。
- OAuth 额度快照、统计缓存和系统监控样本是缓存或运行态数据，可以按保留策略清理，不作为唯一事实源。
- 删除账户、分组或授权关系不应破坏历史使用记录追溯；历史记录保留当时冗余的资源 ID、所有者和授权关系。

## 备份与迁移

- 迁移已有数据时必须同时备份 `backend/data/` 和 `backend/.env`。
- 复用旧数据库必须保持 `JUHE_AI_SECRET` 不变，否则已加密凭据无法解密。
- 对外分享日志、数据库、截图或 bug 记录前，必须先移除 S0 / S1 数据和业务敏感快照。
- 文档、计划、bug 和重构记录不得包含真实 token、完整 API Key、真实用户隐私或完整上游敏感错误正文。

## 安全检查清单

- 新字段是否属于 S0 / S1 / S2 / S3？
- 是否需要密文存储、哈希存储或只保存摘要？
- 接口是否会向授权资源返回不该展示的凭据或配置？
- 使用记录或日志是否可能写入完整请求头、请求体、响应体或 token？
- 是否需要对快照做脱敏、截断和查看权限限制？
- 是否影响 `JUHE_AI_SECRET`、备份迁移、部署文档或 `.env.example`？
- 是否需要同步 [接口契约与权限矩阵](接口契约与权限矩阵.md)、[SQLite 存储说明](SQLite存储说明.md) 或 [部署文档目录](../deploy/README.md)？
