# 调用方分级调度设计（压力自适应四级优先）

> 状态：**v2 审核修订版**（2026-10-17 外部复审 + 用户四项拍板后回写；v1 存在排序键反向、回退契约冲突、信号归因未闭合三项 P0，已全部修正）。批准路径：批次 0/1 发布核验后启动 **M1 影子观测**；M2 仅在 M1 出口判据达标后另行裁决。
> 用户方向原话：「别让坏的把路都堵死了，先让好的通过；坏的你随便折腾都行，但是需要让路、减少资源占用；系统空闲没有分级，资源紧张才分流；纯系统层面，不能影响业务。」

## 1. 目标与非目标

**目标**

- 系统层面的调用方（API Key）四级优先级，行为劣化者让路、降资源占用，优质者优先通过。
- 压力自适应：空闲时全部层级完全同权（无任何差异化），拥塞时分级才产生资源效果。
- 业务零影响：模型、计费、API 形态、正常成功请求的响应语义对任何层级完全一致；分级只作用于排队/等待/唤醒顺序等**资源调度**维度。
- 全自动升降级，无人工配置入口（与「客户端画像由网关内部自动识别、不作用户配置项」的项目边界同构）。

**非目标**

- 不做上游 AI 账户的分级——上游侧已有 J3b 熔断 + J1 健康（账户逐渐降级为长期不可用/异常），本设计只补**调用方侧**。
- 不新增限流/配额维度（额度体系独立，本设计与 429 数值无关）。
- 不永久封禁任何 Key（T4 也只是让路 + aging 防饥饿保证最终被服务，见 §5.3）。
- 不引入 feature flag（压力门控是内在行为，不是开关）。

## 2. 分级对象、主键与四级定义

分级对象 = API Key。**层级状态主键 = API Key ID（不可变主键）**：Key 名称/绑定关系变化不漂移状态；Key 删除后状态仅随 Redis TTL 消亡（§6.3）；Key 轮换（新 ID）即新状态从 T2 起步，不继承旧 ID 层级。层级对管理员只读展示（后续期次），不可手改。

| 层级 | 名称 | 含义 |
| --- | --- | --- |
| T1 | 优质 | 长期干净记录 earned（默认不是 T1，信用要赚） |
| T2 | 正常 | **默认档**，所有新 Key 出生即 T2；一切丢失/异常/样本不足时的保守回退档 |
| T3 | 观察 | 行为劣化信号持续，降资源优先序 |
| T4 | 受限 | 持续劣化（用户裁决 v1：**首版硬信号清单为空，不存在"立即 T4"路径**） |

## 3. 信号源（怎么分）——v2 收敛为高置信本地事实

**v1 教训（复审 P0-3）**：429/4xx 多源混杂（上游/额度/容量/授权都可能产生）、队列 reason 面不足以区分客户端取消/服务端超时/上游超时、`waitCount` 是单请求循环计数推不出跨请求重入率——**v1 信号清单（429 撞击、4xx 率、取消风暴、队列重入、并发超限）全部降为二期候选**，须先完成逐信号归因闭合（provenance 标注到产生路径）才可复评。

**M1 影子观测信号集（仅此两种，全部为本地高置信判定，带明确 provenance）**：

1. 非法 JSON 请求体解析失败（gatewaybody 本地判定，责任方=调用方）。
2. 本地模型过滤失败（请求模型在 Key 资格集内不存在，preauth 本地判定）。

二者只进入软评分。**排除清单（裁决明确）**：上游 429/4xx、额度/授权拒绝、队列/并发/IP 容量类、服务端 timeout、客户端取消、流式已提交失败。**硬信号清单为空**：未有独立「确认滥用」事实前，不存在任何直接 T4 路径。

**分母与最小样本**：每信号必须以「该 Key 同窗口请求总数」为分母计比率；窗口内总请求数不足最小样本（建议 20，内部常量）不评分、层级保持不变——防小样本误降。

## 4. 升降级规则（怎么涨怎么降）

- 滚动窗口：24h 滑动窗口软评分（Redis 滚动计数）。
- 状态转换一律**幂等条件写**（转换带期望前态 CAS 语义，重复消息/重放不产生副作用），M1 起即按此实现。
- 迟滞（v1 骨架保留，阈值首版偏保守）：T2→T3 劣化持续 15 分钟；T3→T4 持续 1 小时；T4→T3 连续 24h 零劣化信号；T3→T2 约 1h 无新增自动回落；T2→T1 连续 7 天干净且量达标。
- 全部阈值为内部常量（「功能不设开关」纪律），M1 以影子观测数据回填校准后再定稿。

## 5. 排序键、资源杠杆与防饥饿（v2 核心修订）

### 5.1 统一排序键（修正 P0-1）

层级排序键统一为复合键 **(tier, enqueuedAtMs, itemID)**——层级高位、入队时间低位、itemID 终局消歧；**绝不用 deadlineAtMs 参与跨层级排序**（v1 缺陷：Redis Lua 以 `deadline_at_ms` 为 ZSET score，缩短 T4 deadline 反而使其先出队）。

- memory 形态：`findQueueWakeCandidate` 的候选集合当前遍历 `q.queues`（Go map，随机序）——改为收集全部可行候选后按复合键排序取首。
- Redis 形态：ZSET score 改为复合编码 `tier*10^13 + enqueuedAtMs`（10^13 大于任何毫秒时间戳，层级严格占高位；同层级内按入队序 FIFO）；成员数据携带原始 deadlineAtMs 供超时清理（清理逻辑与排序逻辑分离）。
- 两形态排序语义等价，M1 起以等价性测试锁定（跨分组 FIFO、分级顺序、双形态对拍）。

### 5.2 资源杠杆（M2 范围，用户裁决）

- **唤醒排序**：按复合键取首（空闲时全员同层级 → 退化为 FIFO，压力门控天然成立）。
- **等待折扣**：T3 ×0.5、T4 ×0.25，**只作用于队列等待子预算**（`WaitForCapacity` 的 MaxWaitMs 入参），不缩短整请求墙钟预算、上游 attempt timeout、不改变任何业务错误语义（超时后仍是标准 queue timeout 语义继续既有 whole-pool round 流程）。已知代价（复审 P1-3）：折扣可能增加重入与 CPU，M1 影子期先量化重入率变化，M2 后观察确认。
- **暂缓项（裁决）**：队列准入拒绝、并发槽排序——仅当 M2 观察显示仍堵才另行裁决。

### 5.3 T4 防饥饿 aging（修正 P1-2）

「永不封禁」必须由机制保证而非文案：**排队 aging 提升有效层级**——item 在队列内每等待 `agingWindowMs`（建议 30s，内部常量），有效层级向 T2 方向提升一级（T4→T3→T2，**永不越过 T2、不影响评分层的持久状态**）。保证：持续 T1 满载下 T4 的最大排队等待有界（约 = aging 提升到 T2 后的正常等待）。M1 出口判据含饥饿仿真项（§8.3）。

### 5.4 准备层适配边界（修正 P1-1）

调度内核（gatewaydispatch/gatewayclientip）不理解客户端画像或业务身份。适配边界：**preauth 准备阶段完成 `APIKeyID → tier` 解析，随请求上下文下发为通用调度参数（通用 queue item 字段/分派段参数，零业务语义）**；队列与调度内核只见「优先级数值」，不感知其来源。tier 解析失败/状态不可用时一律 T2 保守缺省。

## 6. 存储与运行态语义（修正 P0-2）

### 6.1 双形态是部署形态选择，不是运行时回退

依架构总览「易失运行态边界」：**performance 模式下 Redis 是跨进程运行态事实源，Redis 不可用时显式失败或进入保守不可用状态，不得静默改用进程内 memory**。v1「降级为 memory」表述作废。memory 形态（standalone 单进程）在启动时选定驱动，运行期不变。

### 6.2 分级状态的保守缺省

Redis 模式下层级读取失败 → 该请求按 **T2 保守缺省**参与调度（等价于「无分级事实」），并计错误率指标；不阻塞请求主路径（分级是辅助调度，不是事实门槛）。这与「显式失败或保守不可用」的边界一致：分层键空间整体不可用 = 分级功能保守降效（全员 T2），不是跨进程事实改写。

### 6.3 Redis TTL/容量/丢失语义

- key：`juhe-ai:caller-tiers:<apiKeyID>`，滑动 TTL 48h（有流量即续期；无流量自然过期=回 T2，符合「不活跃即默认档」）。
- 容量：每 key 状态为小对象（层级 + 各信号滚动计数 + 时间戳），key 规模 = 活跃 Key 数（十级规模），无容量风险；仍设 key 数上限守卫（超限按 LRU 淘汰，被淘汰者回 T2）。
- 丢失语义：Redis 重启/淘汰/丢失 → 回 **T2 保守默认**（不是 T1 也不惩罚）；T1 需要重新 earned，T3/T4 的处罚随丢失解除（保守方向=对调用方有利的方向）。

## 7. 风险

1. **误伤优质客户**——对策：信号收敛为高置信本地事实 + 最小样本分母 + M1 影子先行 + 首版阈值保守。
2. **排序键/双形态不一致导致层级反转**——对策：复合键统一（§5.1）+ 双形态等价性测试为 M1 交付门。
3. **等待折扣放大重入/CPU**——对策：只作用队列子预算（§5.2）+ M1 量化重入率基线，M2 后对比。
4. **T4 饥饿**——对策：aging 有界等待（§5.3）+ M1 饥饿仿真出口判据。
5. Redis 分片多实例下分级按实例独立（层级是软状态，可接受）。

## 8. M1 影子观测与出口判据

**M1 范围**：状态存储（双形态）+ 信号采集（§3 两种）+ 自动升降级状态机（影子运行）+ 量化观测面板；**无任何资源效果**（排队/调度行为与现状逐字节一致）。

**M1 出口判据（达标才申请 M2 裁决）**：

1. **误降级率**：影子分级结果抽样对拍，T3+ 误判率低于约定阈值（首版建议 <1%，观测期定稿）。
2. **状态滞后**：信号停止到层级回升的实测曲线符合迟滞设计。
3. **Redis 错误**：分层键空间错误率与保守缺省触发率有界（不劫持主路径延迟）。
4. **饥饿退出**：仿真 T1 持续满载下 T4 最大排队等待有界（aging 生效）。
5. 双形态等价性测试全绿（排序/转换/对拍）。

**M2**：唤醒排序 + 等待折扣（§5.2）。启动前提：批次 0/1 发布核验完成 + M1 出口判据达标 + 用户另行裁决。

## 9. 已裁决项记录（2026-10-17 用户）

1. **保留 T1**（长期信用奖励，成本低）；前提=先补公平性（aging）与双驱动一致性（复合排序键）。
2. **首版硬信号清单为空**；M1 只记录高置信、带 provenance 的本地请求事实（非法 JSON、本地模型过滤失败）作软评分；排除上游 429/4xx、额度/授权拒绝、队列/并发/IP 容量、服务端 timeout、客户端取消、流式已提交失败；无「确认滥用」事实不允许立即 T4。
3. **M2 只做唤醒排序 + 等待折扣**（T3 ×0.5、T4 ×0.25，仅队列等待子预算）；队列准入拒绝与并发槽排序暂缓。
4. **M1 等批次 0/1 发布核验后启动**（影子计分、状态转换、量化观测先行）。
