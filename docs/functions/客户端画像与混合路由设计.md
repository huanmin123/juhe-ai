# 客户端画像与混合供应商边界设计

> 状态：当前目标边界，替代旧版“API Key 默认客户端画像 / API Key 显式混合路由”设计。
> 创建时间：2026-06-27。
> 更新说明：本文用于固定 API Key、路由策略、分组、供应商和 AI 账户的职责层级，避免把客户端画像、路由策略、跨协议转换或上游模型映射放错层级。

## 1. 核心职责

| 层级 | 职责 | 不负责 |
| --- | --- | --- |
| API Key | 用户入口、鉴权、额度、状态、过期、时间计划和使用记录归属；选择一个路由策略 | 不配置客户端画像；不直接保存分组绑定、权重、回退、轮询或混合智能路由规则；不配置显式跨协议路由；不管理供应商协议细节、上游凭据或跨协议转换 |
| 路由策略 | 保存路由模式、分组绑定、权重、故障回退、轮询和混合智能路由规则 | 不管理真实上游凭据；不修改账户能力；不做跨协议转换 |
| 分组 | 协调 AI 账户，是账号池和分组内调度层 | 不管理模型目录、供应商语义、上游协议语义、路由模式或协议转换 |
| 供应商 | 对 AI 账户分类，提供协议驱动、模型目录、价格口径、账号测试和供应商专项优化 | 不承接调用方入口、额度或分组调度 |
| AI 账户 | 管理真实上游账户、凭据、Base URL、支持模型、并发、代理、错误策略、账号级限制和真实上游能力 | 不代表 API Key，不管理调用方额度和入口分组策略 |

这套职责是长期边界。新增字段、页面或接口时，先判断字段回答的是哪个问题：

- “谁能调用、额度是多少、入口使用哪条策略”属于 API Key。
- “使用哪些分组、按什么模式选择分组、混合智能路由怎么评分”属于路由策略。
- “从某个账号池里怎么选号”属于分组。
- “这个账号是哪类上游、用哪个协议驱动和模型目录”属于供应商。
- “这个上游账号真实怎么调用、有什么限制”属于 AI 账户。

## 2. 客户端画像

客户端画像描述“谁在调用本系统”，例如普通 OpenAI-compatible SDK、Codex、Claude Code 或 Gemini CLI。它只影响本地入站归一化、SSE 细节、错误形态、上下文恢复、客户端重试语义和审计诊断。

客户端画像是网关内部运行时上下文，不是用户配置：

- 不在 API Key 新建 / 编辑页展示。
- 不作为 API Key 默认字段保存。
- 不放入普通 AI 账户表单。
- 不作为模型路由或供应商选择的依据。
- 可以继续写入审计、使用记录 metadata 和响应检查上下文，方便排障。

识别来源由网关内部维护，例如请求路径、协议族、请求体结构、可信本地 header、已知客户端特征和协议 adapter 解析结果。未识别到专属客户端时走通用画像；不能因为模型名、供应商或 API Key 配置把请求强制升级为某个专属画像。

## 3. 普通供应商账户

普通供应商账户只描述真实上游能力。

允许：

- 保存真实凭据、Base URL、代理、并发、时间计划、错误策略和响应检查规则。
- 声明真实支持的 endpoint modes。
- 声明当前供应商目录内可用模型。
- 做当前供应商、当前协议内的模型别名，例如 `my-gpt -> gpt-5-mini`。

不允许：

- 在普通 GPT / OpenAI / Anthropic / DeepSeek / GLM / Gemini 账户里配置其他供应商模型。
- 在普通账号模型别名里配置跨协议转换，例如 `messages -> chat_completions` 或 `responses -> generate_content`。
- 通过账号字段声明“下游客户端画像”。
- 把 Chat-only 上游伪装成原生 Responses 上游，或把 OpenAI-compatible 扩展成任意协议兼容。

如果普通供应商账户不支持某个下游协议，网关必须跳过该账户或返回本地可读错误，不能靠 API Key 字段隐式改写。

## 4. 混合供应商账户

当前内置 `hybrid` / 混合供应商。混合供应商账户是真实 AI 账户，不是虚拟路由规则，也不是“再指向别的账户或分组”的二次路由节点。

混合供应商账户的定位是：

```text
混合供应商账户 = 真实上游账户 + 跨协议入口适配能力
```

它和普通 AI 账户一样保存真实上游信息：

- 上游凭据。
- Base URL。
- 代理。
- 并发、时间计划、错误策略和限制配置。
- 真实支持的 endpoint modes。
- 真实支持模型。
- 上游模型价格和 usage 口径所需的模型归属信息。

它额外通过账号模型映射保存跨协议配置：

- `sourceEndpointFamily`：允许哪个下游协议入口进入，例如 OpenAI Chat / Responses、Anthropic Messages、Gemini GenerateContent。
- `upstreamEndpointFamily`：真实上游协议目标，由每条映射直接选择 `chat_completions`、`messages` 或 `generate_content`。
- `sourceModel` 到 `upstreamModel`：下游模型名到真实上游模型名的映射。
- 不可保真能力的 guidance / 本地拒绝策略。
- 协议转换所需的 adapter 能力矩阵。

示例：

```text
下游 Anthropic Messages 请求，模型 claude-sonnet
  -> 命中一个混合供应商账户
  -> 该账户真实上游是 GLM OpenAI Chat
  -> 网关把 messages 转成 chat_completions
  -> 上游模型改写为 glm-5.2
  -> 请求这个混合账户自己的 GLM Base URL 和凭据
```

混合供应商账户不应配置目标账户 ID 或目标分组 ID。它自己就是最终上游账户。这样可以避免递归路由、循环引用和“账户管理别的账户”的层级混乱。

## 5. 跨协议转换归属

跨协议转换属于混合供应商账户能力，不属于 API Key 显式规则。

允许方向以 [协议桥接框架设计](协议桥接框架设计.md) 为准。当前白名单仍遵守这些原则：

| 下游 | 混合账户真实上游 | 处理 |
| --- | --- | --- |
| `responses` | `chat_completions` | 允许，Responses 到 Chat bridge |
| `chat_completions` / `responses` | `messages` | 允许，OpenAI 到 Anthropic Messages bridge |
| `messages` | `chat_completions` | 允许，Anthropic Messages 到 Chat bridge |
| `generate_content` / `stream_generate_content` | `chat_completions` | 允许，Gemini native 到 Chat bridge |
| `generate_content` / `stream_generate_content` | `messages` | 允许，Gemini native 到 Anthropic Messages bridge |
| `chat_completions` / `responses` / `messages` | `generate_content` | 允许，OpenAI / Anthropic 到 Gemini native bridge |
| 非 `responses` 来源 | `responses` | 禁止，不合成 Responses 状态机 |
| 未列出的方向 | 禁止，不能靠供应商或客户端画像猜测 |

右侧 `responses` 只允许真实上游原生支持 Responses 的账户直连，不通过混合账户合成 Responses 状态机。

## 6. 与策略路由的边界

混合智能路由属于策略路由层，不属于 API Key 自身字段。API Key 可以在页面上选择或快捷创建一条混合智能路由策略，但保存时应落到 `route_strategies` 和 `route_strategy_groups`。

混合智能路由策略负责配置：

- 路由模式 `hybrid_smart`。
- 评分模型。
- 等级到目标模型的规则。
- 缓存亲和、超时、兜底和质量评分。
- 当前路由策略绑定分组池内的目标模型选择。

它可以配置分组、模型和评分规则，因为这些属于“策略路由选择候选分组和目标模型”的入口调度范围。

它不能配置：

- 默认客户端画像。
- `sourceEndpointFamily -> upstreamEndpointFamily` 这类显式跨协议规则。
- 上游供应商协议细节。
- 真实上游凭据。
- 任意跨协议模型映射。

混合智能路由选中某个目标模型后，仍按路由策略绑定的分组池和分组内账号调度寻找可承接账户。如果命中的是普通账户，按普通账户真实能力直连；如果命中的是混合供应商账户，才进入该混合账户自己的协议转换配置。

## 7. 请求链路

目标请求链路：

```text
请求进入网关
  -> API Key 鉴权、额度、状态和时间计划
  -> API Key 读取绑定的路由策略
  -> 路由策略按普通、混合智能、权重、故障回退或轮询模式选择分组
  -> 分组选出 AI 账户
  -> 普通供应商账户：按真实协议直连上游
  -> 混合供应商账户：按账户内跨协议配置转换后请求自己的真实上游
  -> 返回侧按下游协议和客户端画像渲染响应
```

这条链路中：

- API Key 不知道也不保存客户端画像。
- API Key 不保存显式跨协议规则。
- API Key 不直接保存分组绑定或混合智能路由规则。
- 路由策略保存路由模式和分组绑定。
- 分组不改变账户能力。
- 供应商和 AI 账户负责上游语义。
- 客户端画像只在运行时影响下游体验和错误 / SSE 语义。

## 8. 页面和接口边界

### 8.1 API Key 页面

保留：

- 名称、状态、过期时间、说明。
- 额度和时间计划。
- 路由策略选择。

移除：

- 默认客户端画像。
- 显式混合路由规则。
- 下游协议到上游协议的手工桥接配置。
- API Key 自身的多分组绑定、权重、故障回退、轮询和混合智能路由配置字段。

### 8.2 策略路由页面

新增“策略路由”菜单用于维护：

- 混合智能路由。
- 权重调度路由。
- 故障回退路由。
- 轮询路由。

普通路由是默认单分组路由，不开放复杂配置。五种路由模式的完整规则见 [策略路由设计](策略路由设计.md)。

### 8.3 分组页面

分组只展示和维护账号池关系、分组内排序、权重、启停和分组调度策略。分组可以展示成员账户派生出的供应商 / 协议摘要，但不把这些摘要作为分组自己的上游语义。

### 8.4 AI 账户页面

普通供应商账户展示真实上游接入契约和同协议模型别名。

混合供应商账户展示：

- 真实上游连接信息。
- 真实上游接口能力。
- 允许的下游协议入口。
- 下游模型到上游模型映射。
- 协议转换能力检查。
- 不可保真能力的处理方式。

## 9. 数据契约目标

API Key 写接口不再接收：

```ts
clientProfile
explicitHybridRouteRules
groupBindings
hybridRoutingConfig
```

API Key 只接收或保存：

```ts
routeStrategyId
```

路由策略写接口负责保存路由模式、分组绑定和对应模式配置。目标结构见 [策略路由设计](策略路由设计.md)。

AI 账户在选择混合供应商时新增混合配置，示意结构如下：

```ts
type HybridAccount = {
  providerCode: 'hybrid'
  providerProtocolProfileId: 'profile_hybrid_openai_chat_v1'
  credentials: {
    api_key: string
    base_url: string
    supported_endpoint_modes: string[]
  }
  modelMappings: Array<{
    sourceModel: string
    sourceEndpointFamily:
      | 'chat_completions'
      | 'responses'
      | 'messages'
      | 'generate_content'
      | 'stream_generate_content'
    upstreamModel: string
    upstreamEndpointFamily: string
    enabled: boolean
  }>
}
```

当前实现直接复用账号 `modelMappings` 表达下游到真实上游的模型和协议映射；普通供应商账户仍只允许同协议模型别名。实现不做运行时旧字段兼容；已有 API Key 显式规则如需保留，由用户明确要求后提供一次性离线转换脚本，将协议桥接类规则迁移到混合供应商账户配置，将分组调度类规则迁移到策略路由配置。

## 10. 非目标

- 不在 API Key 层暴露客户端画像。
- 不在 API Key 层保存显式跨协议规则。
- 不在 API Key 层保存分组绑定、权重、故障回退、轮询或混合智能路由规则。
- 不让混合供应商账户指向其他账户或分组。
- 不让普通供应商账户承接跨协议转换。
- 不用客户端画像猜测上游目标。
- 不让分组改变账户真实能力。
- 不做 `chat_completions -> responses`、`messages -> responses` 或 Gemini native 到 Responses 的合成桥接。
- 不做运行时旧字段兼容；需要处理旧配置时只提供离线处理方案。

## 11. 当前落地状态

1. API Key 新建 / 编辑页不展示默认客户端画像和显式混合路由规则。
2. 策略路由实体和菜单承接普通路由、混合智能路由、权重调度路由、故障回退路由和轮询路由。
3. API Key 创建 / 更新接口只绑定 `routeStrategyId`，不接收客户端画像、分组绑定或跨协议桥接规则。
4. 客户端画像由网关内部自动识别，只进入运行时上下文、审计和响应检查。
5. `hybrid` 混合供应商已作为内置供应商定义，使用一个通用混合供应商档案；目标上游协议由账号模型映射的 `upstreamEndpointFamily` 表达。
6. AI 账户选择混合供应商时保存真实上游连接，并通过账号 `modelMappings` 配置下游模型 / 协议入口到真实上游模型 / 协议的映射。
7. 网关调度命中混合供应商账户后，按账户配置执行协议转换和模型映射。
8. 跨协议回归测试应以混合供应商账户为入口；旧 API Key 显式规则只保留拒绝 / 忽略类边界测试。
9. Mockdata、导入导出、接口契约、SQLite / PostgreSQL schema 和验证文档需要随混合供应商通用档案和协议转换矩阵持续同步。

## 12. 验证清单

- API Key 表单不显示默认客户端画像。
- API Key 表单不显示显式混合路由规则。
- API Key 创建 / 更新请求不提交 `clientProfile` 和 `explicitHybridRouteRules`。
- API Key 创建 / 更新请求不直接提交多分组绑定、权重、故障回退、轮询或混合智能路由配置；这些配置必须进入路由策略接口。
- 客户端画像仍能由请求特征自动识别，并进入审计 / 响应检查上下文。
- 普通供应商账户模型别名只能在当前供应商和当前协议内改写。
- 普通供应商账户不能保存跨协议桥接配置。
- 混合供应商账户保存真实凭据和 Base URL。
- 混合供应商账户不指向其他账户或分组。
- `messages -> chat_completions` 等跨协议请求只能由混合供应商账户承接。
- 混合智能路由策略能配置评分模型、等级目标模型和质量评分。
- 混合智能路由策略命中混合供应商账户时，由账户内转换配置决定是否可承接。
