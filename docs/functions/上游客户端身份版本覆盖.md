# 上游客户端身份版本覆盖

## 背景

2026-10-01 生产 Grok OAuth 账户因 xAI 对 `cli-chat-proxy.grok.com` 强制 CLI 版本门槛（>= 1.0.13）批量返回 `426 Upgrade Required`（错误体 "Grok CLI version ... outdated"）：当时代码内置的伪装版本 0.2.93 低于门槛，而版本常量编译在二进制里，发版救急来不及。因此设立系统设置热配置通道：不重启、不发版，通过管理页调整各上游客户端家族的画像版本。

版本常量与锚点注释的权威位置是 `backend-go/shared/platform/upstreamidentity/identity.go`；运行时生效值经 `SetClientVersionOverrides` / `Effective*` API 读取，配置只影响版本段。

## 目标与非目标

目标：

- 提供系统设置键 `upstreamClientVersionOverrides`，按客户端家族热覆盖内置伪装版本。
- 覆盖语义为非空即生效：可升级也可降级，用于应急门槛变化与临时回退。
- 留空 / 删除该家族键即回退到下一层（自动跟版层优先，否则代码内置版本）。

非目标：

- 不做 max 合并：配置值与内置版本不比较大小，配置非空就直接生效（理由见下文"覆盖语义"）。
- 不开放完整 User-Agent 自由文本：UA 骨架由代码拼装，配置只影响版本段，防止格式漂移与请求头注入。
- 不新增 API Key、路由策略或账户级配置项；该设置是系统级应急通道，不属于路由层级。

## 契约

### 设置键与家族表

系统设置键：`upstreamClientVersionOverrides`，存储值为 JSON 对象。允许键恰好为下列五个，值为 semver 三段字符串（`^\d+\.\d+\.\d+$`）；空对象 `{}` 表示该键不覆盖任何家族（生效值回退到自动跟版层，自动层该族也为空时才用内置版本）。

| 家族键 | 对应客户端画像 | 内置版本锚点（2026-10-02） | 常量名（identity.go） | 上游地址 |
| --- | --- | --- | --- | --- |
| `codex` | Codex exec（源码锚定 exec surface，originator `codex_exec`） | 0.159.3 | `CodexExecUserAgent` | `https://chatgpt.com/backend-api/codex` |
| `claudeCode` | Claude Code CLI | 2.1.285 | `ClaudeCodeUserAgent` | `https://api.anthropic.com` |
| `geminiCLI` | Gemini CLI | 0.61.0 | `GeminiCLIUserAgent` | `https://cloudcode-pa.googleapis.com` |
| `zcode` | ZCode | 3.14.3 | `ZCodeVersion` | `https://open.bigmodel.cn` |
| `grokCLI` | Grok CLI | 1.0.13 | `GrokCLIClientVersion` | `https://cli-chat-proxy.grok.com` |

各家族的完整 UA 骨架、附加请求头（如 `x-grok-client-version`、`X-ZCode-App-Version`、`anthropic-beta`、`x-stainless-*`）和适用档案见 identity.go 与各供应商接入文档；覆盖只替换版本段，其余骨架字段不变。

### 覆盖语义

- 非空即生效：某家族键的值非空时，该家族全部身份注入点使用该版本，可升可降。
- 不取 max：配置值不与内置版本比较大小。原因：max 合并无法降级（上游回滚门槛或新版本画像触发风控时，配置值低于内置也会被顶成内置，应急回退失效）；且生效来源不透明——运维无法从配置判断当前实际生效版本，排障时要同时知道内置值与配置值再算 max。显式覆盖让"配置里写什么就生效什么"可预期。
- 清空回下一层：留空或删除该家族键，回退到自动跟版层（键 `upstreamClientVersionAutoOverrides`，由 jobs 任务按官方发布源维护，见《客户端版本自动跟版设计》）；自动层该族也为空时回到代码内置版本。生效优先级为手动 > 自动 > 内置；空对象 `{}` 等价于五个键全部留空。

### 校验规则

- 键白名单：只接受上表五个家族键，出现其他键视为非法。
- 值格式：必须匹配 `^\d+\.\d+\.\d+$`（三段数字，无前缀、无预发布段）。
- 空对象 `{}` 合法，表示该键不覆盖任何家族（生效值回退到自动跟版层，自动层为空才用内置）。
- 非法键或非法值由后端在保存设置时整体拒绝（400），不会部分生效；前端表单同样按"留空或合法 semver"校验后才提交。

## 行为

### 生效路径与延迟

- gateway：启动时加载设置；管理端保存设置后经运行时缓存失效通道即时刷新，无重启、无发版。
- jobs：启动时加载，另按 60 秒定期刷新，最长延迟 60 秒。

### 覆盖范围

覆盖以下身份注入点的版本段：

- 系统主动请求：账户测试、J1 后台探活、Grok 用量快照、受控模型目录刷新、OAuth 刷新。
- 网关链客户端画像补齐：下游请求缺身份时由网关补齐的客户端画像（如 Claude Code 画像补齐 UA）。

不在覆盖范围（边界）：

- modelcheckprobe（J3b 模型质量检测）暂不在覆盖范围（在途批次，后续接入）。
- 正常网关流量中真实下游客户端自带的身份：调用方显式设置的 User-Agent 一律保留，不被本配置覆盖。
- 不伪造动态安全字段（签名、nonce、session、PoW 等），任何配置值都不改变这一边界。

## 维护

- 代码统一升级内置版本后，配置中低于内置的旧覆盖项不会自动失效（显式覆盖语义，不取 max）；运维应在管理页清理低于内置的旧配置，避免长期锁死旧版本。
- 每次调整 identity.go 内置版本锚点时，必须同步更新本文家族表的锚点列。
- 该设置属于系统级应急通道：应急结束后优先清理配置，让自动跟版层与代码锚点重新成为事实源。
