# 动态管理数据刷新与缓存边界设计

## 目标

- 使用记录、日志、账户当前状态等高频变化的管理数据，后端列表接口每次都读取当前事实源或当前权威投影，不返回脱离事实更新链路的旧响应缓存。
- 前端只持久化筛选、分页和排序等页面状态；页面实例可在当前会话内保留已渲染结果，但筛选、分页、重新进入和手动刷新必须重新请求业务接口。
- 手动刷新是强一致的用户动作：不得被前端请求去重、浏览器持久响应缓存或后端列表响应缓存吞掉。
- 上游失败的使用记录保留脱敏后的上游错误 `message/code/type` 或有界正文摘要，避免统一文案覆盖真实原因。

## 数据分层

| 数据类型 | 示例 | 允许的优化 | 一致性要求 |
| --- | --- | --- | --- |
| 高频事实列表 | 使用记录、审计日志、运行日志、操作日志、公开接口日志 | 有界分页、索引、分片、读 worker、请求内批量查询 | 每次业务请求读取当前事实；手动刷新必须可见已落库记录 |
| 当前业务状态 | AI 账户状态、余额、并发、分组状态、API Key 状态 | 当前页批量权威投影、可靠写后失效、短请求 singleflight | 列表响应返回请求时刻可获得的最新权威状态 |
| 统计预聚合 | 趋势、TopN、统计窗口、健康小时快照 | worker 预聚合、staged/window 表 | API 不再叠加响应缓存；页面显示统计生成时间或滞后语义 |
| 稳定元数据 | 供应商协议、模型目录、设置快照、选项字典 | 有界内存/Redis 缓存和明确失效 | 写成功、配置修订或 TTL 后可靠失效；缓存不是事实源 |
| 网关运行态 | 路由候选、账户电路、热质量、配额窗口 | memory/Redis 快速路径、revision/CAS | 服从网关专题设计，不作为管理页面响应缓存 |

## 使用记录规则

- `GET /usage-records` 与 `GET /my-usage-records` 直接调用统一 repository 列表查询。
- 删除使用记录首屏 Redis/内存热列表、写入侧发布、名称补查、30 分钟预热 job、预热候选 repository 和对应测试命令。
- 前端 `usePageStateCache` 只保存查询状态，不保存列表响应。
- `useResponsivePagedList` 只合并相同的在途请求并丢弃迟到响应；刷新请求必须有新的请求代次，不能复用刷新前的在途 Promise。
- 管理页面组件实例默认不进入 `KeepAlive`；只有路由显式声明 `keepAlive: true` 的长会话页面可以保活。
- 使用记录异步入库仍有队列落库时间；刷新保证绕过响应缓存，不承诺展示尚未落库的数据。

## 上游错误可见性

- 完整非 `2xx` 响应优先使用协议驱动解析出的上游 `message`、`code`、`type`。
- 无结构化错误字段时，使用有界、脱敏后的上游正文摘要；空正文才回退到包含 HTTP 状态的中文说明。
- 错误详情写入使用记录与审计诊断，但不得把 Authorization、Cookie、API Key、OAuth token、密码或代理凭据原样写入。
- 错误可见性只改变诊断文本，不改变账户错误分类、切号、重试、电路或共享质量语义。

## 其他页面审计标准

以下任一条件成立即视为需要修复的页面陈旧风险：

1. GET 列表路由先读固定 TTL 响应缓存，且事实写入没有可靠、全作用域失效。
2. 前端把完整列表响应写入 localStorage、sessionStorage 或 IndexedDB，并在刷新时直接复用。
3. 手动刷新和普通加载使用同一在途请求，导致刷新没有产生新业务请求。
4. 动态事实接口在预聚合结果之外再次叠加不可观测的响应缓存。

下列情况不按页面陈旧缺陷处理：请求内 memo/singleflight、筛选状态缓存、稳定 options 缓存、网关运行态缓存、统计 worker 的权威预聚合结果。

本次审计还确认：

- 表监控继续读取后台物化快照，但删除快照之上的 30 秒进程内响应缓存。
- 账户代理选项只保留相同在途请求合并，不跨页面缓存完整结果。
- 账户编辑详情、公告详情、审计/运行/操作/公开接口日志详情和模型检测详情每次打开都重新请求，不保留 5 秒详情结果。
- 模型检测账户选项与聊天可用模型不保留 10/30 秒结果快照，只合并同一时刻的相同在途请求。
- 统计日期窗口属于稳定元数据，可保留 60 秒前端 TTL；个人/管理作用域必须隔离，显式刷新必须传 `force`。
- 统计趋势、TopN 和汇总继续读取 worker 物化结果，不退回业务请求内全量扫描。

## 验收

- 使用记录后端不存在首屏缓存、写入发布或预热残留。
- 桌面和移动端手动刷新都触发新的列表 HTTP 请求，并显示刷新前已落库的新记录。
- 默认首屏、筛选、清除筛选和分页均读取 repository 当前结果。
- Mock 上游返回自定义非 `2xx` 错误时，使用记录显示该脱敏错误，而不是固定的“上游返回非成功 HTTP 响应”。
- 缓存审计对其他页面给出逐项证据；只修改已证实违反本设计的路径。
