# 日志与审计设置设计

- 状态：已实施（2026-10-02）
- 关联：`docs/functions/接口契约与权限矩阵.md`（系统设置分区接口）、`docs/architecture/frontend/样式规范.md` §9（设置页折叠分组模式）
- 范围：把审计日志（F3）保留策略从 env-only 迁移为系统设置热更新；收编操作日志（F4）两个既有孤儿设置键；新增审计日志手动清理 API 与设置页「日志与审计」分组。

## 目标

1. 审计日志保留策略（成功保留天数 / 问题保留天数 / 成功热窗 / 成功采样率）可在系统设置页修改，**无需重启进程**（原为 env 启动固化）。
2. 操作日志 `operationLogRetentionDays` / `operationLogMaxChangesPerRecord` 两个后端已有设置键获得管理入口（原先无 section 归属、无 UI）。
3. 提供审计日志「立即清理」手动触发入口，回传清理统计。

## 非目标

- **不新增审计/运行日志的启用停用开关**：审计是排障与追溯的唯一线索，运行时禁用开关的故障面大于收益；降写入量诉求由既有「成功采样率」承担（1.0 → 0.1 即只保留 10% 成功请求正文）。
- 不改变运行日志索引 / 公开接口日志 / 使用记录的保留配置位置（仍在「数据保留」组）。
- 不做操作日志/运行日志的手动清理（它们的清理在 jobs 任务族，跨进程手动触发需新通道，自动任务已覆盖；仅审计清理在 gateway 进程内可直接触发）。

## 新设置键（system_settings）

| 键 | 域 | 默认 | 语义 |
| --- | --- | --- | --- |
| `auditLogSuccessRetentionDays` | 0..3650 整数 | 3 | 成功审计行保留天数；0 = 只保留热窗（须与采样率 0 成对） |
| `auditLogProblemRetentionDays` | 1..3650 整数 | 7 | 失败/问题行保留天数 |
| `auditLogSuccessHotRetentionHours` | 0..168 整数 | 1 | 成功行热窗（热窗外正文降级为 metadata_only） |
| `auditLogSuccessSampleRate` | 0..1（4 位小数） | 1.0 | 成功行正文保留采样率；0 与成功保留 0 天联动 |

与 env 的对应关系：`JUHE_AI_AUDIT_LOG_SUCCESS_RETENTION_DAYS` / `JUHE_AI_AUDIT_LOG_PROBLEM_RETENTION_DAYS` / `JUHE_AI_AUDIT_LOG_SUCCESS_HOT_RETENTION_HOURS` / `JUHE_AI_AUDIT_LOG_SUCCESS_SAMPLE_RATE`（env 继续支持，作为无 DB 行时的回落）。

### 生效优先级（每轮 retention 读取）

```
DB system_settings 行值 → env 显式配置值 → 代码默认
```

- 审计 retention owner 每个 tick（默认 1 分钟 + 抖动）直读业务库 system_settings 四键构造本轮 `RetentionConfig`（复用 F4 operationlog 的 `RetentionDays(ctx, fallback)` 热读先例：直读、无缓存、读失败跳过本轮不扩大清理范围）。
- DB 行缺省（存量库升级）由 settings 读取的兼容默认补齐（`applyCompatibleSystemSettingDefaults` 加四键，取代码默认）；生产已显式配置的 env 值与代码默认一致（SAMPLE_RATE=1 == 1.0），无行为变化；曾显式配置非默认 env 值的环境，升级后以 DB 值为准（在升级说明中注明）。
- 写入路径（PATCH `log-retention`）做 section 级联动校验：`采样率==0 ⟺ 成功保留天数==0`；成功保留天数 > 0 时 `天数*24 ≥ 热窗小时数`——校验失败 400，不落到"读时静默回退"。

## 新 section：`log-retention`

- 键集：上述审计 4 键 + `operationLogRetentionDays` + `operationLogMaxChangesPerRecord`（两键原已在 `systemSettingSpecs` 白名单与 seed 中，本次仅获得 section 归属，行为不变；F4 每 tick 热读逻辑保持现状）。
- 管理入口：系统设置页第 7 个分组「日志与审计」（见样式规范 §9 设置页折叠分组模式）。

## 手动清理 API

```
POST /__aisys__/api/audit-logs/cleanup      # 仅管理员
```

- 行为：以当前生效保留配置（DB → env → 默认的优先级链）立即执行一轮 `CleanupRetention`（有界批次 + owner lease 事务内校验，与后台自动轮共用同一 lease 与 SQLite 写锁，天然串行安全）。
- 响应：清理统计 `{ successHotTrimmed, deletedNonPersistedLogs, deletedLogs, deletedErrorGroups, deletedPayloadBlobs, deletedHotSearchFiles }`。
- 错误：lease 丢失或清理失败返回错误原文；不重试。
- 防护：`auth.RequireAdmin` + `kernel.MutationGuardMiddleware`（防重放指纹）+ 操作日志 `Sink.Record`（参照 tablemonitor cleanup 先例）。
- 前端入口：设置页「日志与审计」分组操作区「立即清理审计日志」按钮，按钮带确认与 loading，完成后 toast 展示清理统计。

## 验收标准

1. 设置页「日志与审计」分组展示 6 项（4 审计 + 2 操作日志），展示行/编辑/按组保存与既有 6 组行为一致；自定义判定、恢复默认值、取消回滚可用。
2. 修改审计保留键保存后，下一轮自动 retention（≤1 分钟 + 抖动）即按新值执行；不重启进程。
3. 手动清理按钮在隔离实例可触发并回传统计；无 lease 冲突副作用。
4. `go test`（settings / auditlog 包）、前端 vitest、typecheck、相关回归全绿。
5. 契约文档 section 清单同步（含修正 Node 期残留的 `account-test` 偏差——代码 catalog 为准）。
