# 流式拦截策略配置设计

> 设计状态：草案，尚未落地。
> 本文用于打磨 `200 + SSE` 协议内错误、广告污染和上游流内容异常的配置化方案。当前运行时代码仍以 [流式中断与客户端重试调研](流式中断与客户端重试调研.md) 中记录的 Codex 内置策略为准。

## 1. 目标

流式拦截策略解决的是：上游 HTTP 状态码已经是 `2xx`，但 SSE 流内部出现协议级失败、广告插入、异常文本或其他污染内容。普通非 `2xx` 账号错误策略不能覆盖这类问题，因为账户测试和健康检查可能仍然成功。

本设计目标：

- 把当前写死在代码里的 Codex SSE 拦截逻辑沉淀为系统内置 preset。
- 支持按供应商、账号类型、客户端工具类型和协议类型创建流式拦截策略。
- 让前端配置表达业务意图：数据怎么处理、是否重试、是否切号、账户状态怎么处理。
- 让后端执行层根据当前流式阶段自动选择具体落地方式，而不是让用户理解“客户端重试”和“服务端重试”的实现细节。
- 对广告污染这类 `200 + SSE` 弱证据优先使用运行态避让，不默认写持久账号状态。

非目标：

- 不把 Codex 的 `upstream_retryable_error` 语义扩散为所有 OpenAI-compatible 客户端通用能力。
- 不恢复旧的“状态码 / 错误码特征规则”通用兜底模型。
- 不在正常流式路径里为了匹配规则缓存完整响应体。
- 不允许单条规则无边界地把任意已输出流静默重放给客户端。

## 2. 核心判断

策略配置层只回答四个问题：

| 维度 | 问题 | 示例 |
| --- | --- | --- |
| 数据处理 | 命中内容要丢弃单个事件、结束当前流，还是替换为失败事件 | 丢弃当前流 |
| 是否重试 | 命中后本次结果是否不可接受，需要进入下一次尝试 | 是 |
| 是否切号 | 下一次尝试是否应避开当前账号或上游桶 | 切下一个账号并短期避让当前账号 |
| 账户状态 | 是否写入账号持久状态或只做运行态避让 | 仅运行态避让 |

后端执行层再根据当时流阶段决定具体动作：

- 还没有向客户端写任何 SSE body：可以丢弃当前上游并在服务端切号重试，客户端无感。
- 已写过非可见事件但没有可见输出：不能保证所有客户端都能接受响应 ID / metadata 被替换，优先通过客户端支持的协议通知重试；不支持时返回失败。
- 已写过可见输出：禁止服务端静默切号拼接；只能通知客户端重试或返回失败。

## 3. 生效阶段

前端不需要暴露“客户端重试 / 服务端重试”这种执行细节，但需要暴露策略在哪些阶段生效。

| 阶段 | 含义 | 执行约束 |
| --- | --- | --- |
| 写入下游前 | 尚未写任何 SSE body | 可服务端切号重试 |
| 可见输出前 | 可能已写 `response.created`、`response.in_progress`、metadata 或心跳，但未写文本、reasoning、工具参数等可见输出 | 不建议服务端静默重放，优先客户端重试或失败 |
| 可见输出后 | 已向客户端写过文本、reasoning、工具参数或会改变客户端执行状态的 output item | 不允许服务端静默切号，只能客户端重试或失败 |
| 任意阶段 | 规则在以上阶段都可匹配 | 执行层仍受各阶段安全约束限制 |

可见输出边界继续复用当前运行时判断：`response.created`、`response.in_progress`、metadata、心跳不算可见输出；文本 delta、reasoning delta、工具调用参数 delta、可改变 assistant 内容或工具状态的 output item 算可见输出。

## 4. 策略作用域

策略按“系统内置 preset + 管理端策略 + 账户追加规则”合并。

### 4.1 系统内置 preset

内置 preset 由代码维护，默认启用，不在普通页面中删除。它们用于承接当前已经验证过的客户端协议能力。

首批内置 preset：

| preset | 适用条件 | 匹配 | 行为 |
| --- | --- | --- | --- |
| OpenAI Codex Responses 可见输出前失败 | `providerCode = openai`，`clientProfile = codex`，`downstreamProtocol = responses_sse` | `response.failed`、`event/type = error`、`response.error`、top-level `error` | 数据处理为替换失败事件；重试为是；切号交给 Codex turn 策略；账户状态不修改 |
| OpenAI Codex cyber_policy | 同上 | `error.code = cyber_policy` | 允许可见输出后也替换为 `upstream_retryable_error` 失败事件；重试为是；账户状态不修改 |

### 4.2 管理端策略

管理端策略用于“供应商 + 工具类型”维度的通用规则。建议作用域字段：

- 供应商：`providerCode`
- 账号类型：`accountType`，例如 `api_key`、`oauth`
- 客户端工具类型：`clientProfile`，例如 `codex`、`generic_openai`
- 下游协议：`downstreamProtocol`，例如 `responses_sse`、`chat_completions_sse`
- 路径：`endpoint`，例如 `/responses`、`/chat/completions`

### 4.3 账户追加规则

账户追加规则用于处理个别中转的广告、污染文本、私有错误码或异常事件格式。账户规则默认继承系统内置 preset 和管理端策略，也可以在权限允许时关闭继承。

账户规则不应单独决定客户端协议能力。即使账户规则要求“重试”，是否能写 Codex 的 `response.failed/upstream_retryable_error` 仍必须由 `clientProfile` 和 `downstreamProtocol` 决定。

## 5. 前端配置项

### 5.1 基础信息

| 字段 | 说明 |
| --- | --- |
| 规则名称 | 中文名称，用于列表和审计展示 |
| 启用状态 | 是否参与匹配 |
| 执行模式 | `拦截` 或 `试运行`；试运行只记录命中和审计，不改变下游响应 |
| 优先级 | 数字越小越先匹配 |
| 作用域 | 全局、供应商 / 工具类型、账户追加 |
| 备注 | 说明为什么需要这条规则 |

### 5.2 匹配条件

第一版只支持结构化条件和普通关键词包含匹配，不支持正则、大小写忽略、中文繁简转换或多语言模板。

| 条件 | 说明 |
| --- | --- |
| SSE event 类型 | `response.failed`、`response.output_text.delta`、`message`、`error` 等 |
| data.type | OpenAI Responses 事件类型 |
| error.code | 上游错误码，例如 `cyber_policy` |
| error.type | 上游错误类型 |
| 文本包含 | 用于匹配广告、污染文案或中转提示 |
| 文本不包含 | 用于减少误杀 |
| JSON 字段存在 | 例如存在 `error`、`response.error` |
| 内容大小 | 单事件或单行超过阈值时的匹配条件，后续再开放 |

匹配只能在当前 SSE 事件的受限窗口内完成，不能为了匹配文本拼接完整流。

### 5.3 数据处理

| 选项 | 含义 | 典型用途 |
| --- | --- | --- |
| 丢弃命中事件 | 不把当前事件写给客户端，继续读取后续事件 | 单独广告事件、无害污染事件 |
| 丢弃当前流 | 关闭当前上游流，后续按“是否重试”和“是否切号”执行 | 广告混入模型输出、上游失败事件 |
| 替换为失败事件 | 不转发原事件，写入本地构造的失败 SSE | Codex 可重试失败、普通流失败 |

`原样放行` 不作为数据处理选项。需要观察规则命中但不改变响应时，使用基础信息里的 `试运行` 模式；否则“拦截策略”命中后必须产生明确处理结果。

如果“是否重试 = 是”，第一版建议数据处理只允许选择“丢弃当前流”或“替换为失败事件”，避免出现只丢一个事件却要求整轮重试的矛盾配置。

### 5.4 是否重试

只暴露布尔值：

| 选项 | 含义 |
| --- | --- |
| 是 | 命中规则后本次响应不可接受，需要进入下一次尝试 |
| 否 | 命中规则后不触发下一次尝试，只按数据处理和账户处理执行 |

这里不区分“允许重试”和“强制重试”。能否在服务端重试、是否只能通知客户端重试，由执行层按流阶段和客户端能力决定。

### 5.5 是否切号

| 选项 | 含义 |
| --- | --- |
| 不切号 | 重试时不额外避让当前账号 |
| 本次请求切下一个账号 | 仅当前请求后续尝试避开当前账号 |
| 切号并短期避让当前账号 | 当前请求和后续短 TTL 内避开当前账号 |
| 切号并短期避让上游桶 | 短 TTL 内避让同 `proxy`、`baseUrl` 或 `provider` 桶 |

如果“是否重试 = 否”，前端应禁用“本次请求切下一个账号”这类本次重试动作，只保留后续运行态避让类选项。

### 5.6 账户状态

| 选项 | 含义 | 建议边界 |
| --- | --- | --- |
| 不修改 | 只记录审计和使用记录 | 默认 |
| 仅运行态避让 | 写入进程内短 TTL 屏蔽或上游桶避让 | 广告污染、弱证据异常 |
| 标记临时不可调用 | 写入 `temporary_unavailable` 和冷却截止时间 | 需要管理员显式配置，且建议配命中阈值 |
| 标记限流中 | 写入 `rate_limited` | 只用于明确限流语义，不用于广告 |
| 标记异常 | 写入硬异常状态 | 高风险操作，应要求高权限和二次确认 |

第一版建议只实现“不修改”和“仅运行态避让”。持久状态写入可以先在设计中保留字段，等误杀控制、阈值和审计完善后再开放。

## 6. 前端落点

流式拦截不是纯账户级能力，前端主入口不能只放在账户编辑弹窗里。第一版应把“策略管理”和“账户追加”拆开：独立策略管理页负责全局、供应商 / 工具类型和内置 preset 展示；账户编辑只负责当前账户的继承摘要和账户追加规则。

该能力也不放到 `系统设置`。系统设置适合稳定的全局参数，不适合承载按供应商、客户端工具类型、下游协议和账号覆盖组合出来的动态拦截规则。

建议落点：

| 能力 | 前端位置 | 说明 |
| --- | --- | --- |
| 策略管理主入口 | 管理侧 AI 管理菜单下新增“流式拦截策略” | 管理全局规则、供应商 / 工具类型规则，展示内置 preset |
| 内置 preset 展示 | 流式拦截策略页只读分组 | 展示 Codex / 供应商内置策略的适用范围、匹配条件和行为，不允许普通用户删除 |
| 账户追加规则 | AI 账户编辑弹窗 | 在现有非 `2xx` 错误策略卡片旁新增“账户流式拦截规则”折叠卡片，只维护当前账户追加 / 覆盖 |
| 账户继承摘要 | AI 账户编辑弹窗只读展示 | 展示当前账户最终会继承哪些全局、供应商 / 工具类型和内置 preset |
| 命中记录排障 | 审计日志 / 使用记录详情 | 规则命中作为 gateway metadata 展示，不在规则配置页保存完整正文 |

第一版策略管理页建议新增目录 `frontend/src/views/stream-intercept-policies/`：

- `StreamInterceptPoliciesView.vue`：策略列表、筛选、启停和新增入口。
- `StreamInterceptPolicyEditModal.vue`：编辑全局或供应商 / 工具类型策略。
- `streamInterceptPolicyTypes.ts`：前端表单类型、枚举和只读 preset 展示类型。
- `streamInterceptPolicyPayload.ts`：列表和保存 payload 的组装、校验与规范化。
- `streamInterceptPolicyOptions.ts`：数据处理、重试、切号、账户状态、作用域等选项。

菜单位置：

- 管理侧：`AI 管理 / 流式拦截策略`。
- 用户侧：默认不提供全局策略管理入口；用户只在自己的账户编辑弹窗里维护账户追加规则。

账户级追加规则仍复用 `frontend/src/views/accounts/` 现有账户编辑结构：

- 新增 `AccountStreamInterceptPolicyCard.vue`：承载规则列表、添加、删除、试运行 / 拦截模式、数据处理、重试、切号和账户状态表单。
- 新增 `accountStreamInterceptPolicyTypes.ts`：账户追加规则表单类型和继承摘要展示类型。
- 新增 `accountStreamInterceptPolicyRules.ts`：空规则、模板规则和前端选项。
- 新增 `accountStreamInterceptPolicyPayload.ts`：从账户凭据读取 / 写入 `stream_intercept_rules`，并做表单校验。
- 更新 `AccountEditModal.vue`：在 `AccountErrorPolicyCard` 附近插入“账户流式拦截规则”，保持同一个账号编辑入口。
- 更新 `accountCredentials.ts`、`accountSavePayload.ts`、`useAccountEditForm.ts`：把流式规则纳入账号编辑表单的加载、校验和保存。
- 更新 `frontend/src/types/domain/accounts.ts`：补充账户详情返回中的流式策略展示字段或继承摘要。

页面文案要明确区分：

- “错误处理策略”：处理非 `2xx` HTTP 响应。
- “流式拦截策略”：处理 `200 + SSE` 内部事件、广告污染和协议内失败。

策略管理页应以列表 + 抽屉 / 弹窗编辑为主，支持按供应商、账号类型、客户端工具类型、下游协议筛选；不要复用账户编辑弹窗承载全局策略。账户编辑弹窗只展示继承摘要和当前账户追加规则，避免用户误以为修改了全局规则。

## 7. 执行矩阵

| 阶段 | 是否重试 | 是否切号 | 推荐执行 |
| --- | --- | --- | --- |
| 写入下游前 | 是 | 本次切号 | 关闭当前上游，服务端换账号重新请求，客户端无感 |
| 写入下游前 | 是 | 不切号 | 关闭当前上游；如果仍有同账号重试预算才重试，否则返回失败 |
| 写入下游前 | 否 | 任意 | 按数据处理执行；如当前流被丢弃则返回失败或结束 |
| 可见输出前 | 是 | 任意 | 不静默拼接第二条流；客户端支持目标失败协议时写可重试失败事件，否则写普通失败事件 |
| 可见输出前 | 否 | 任意 | 按数据处理执行；如果丢弃当前流则写普通失败事件 |
| 可见输出后 | 是 | 任意 | 丢弃命中坏事件，写客户端可识别的可重试失败事件；不支持时写普通失败事件 |
| 可见输出后 | 否 | 任意 | 丢弃命中事件或当前流；必要时写普通失败事件，不触发重试 |

执行层必须保证：只要已有任何下游 SSE body 写出，就不能把第二个上游流静默拼到同一个响应里。

## 8. 性能边界

流式拦截运行在网关热路径，第一版必须把性能约束当成接口契约的一部分。

- 按 SSE 事件边界增量解析，不允许为了规则匹配缓存完整流、完整响应体或跨事件全文。
- 规则匹配只消费当前完整 SSE event 的受限文本窗口和已解析出的结构化字段；文本关键词只做普通 `includes` 类包含判断。
- 单个 SSE event 超过解析上限时，沿用现有流式解析跳过策略：停止规则匹配并原样转发，不能为了命中广告规则继续堆内存。
- 图像流、超大 base64、文件类 payload 和已经触发正文省略的流，不做文本关键词扫描，只保留结构化事件类型、终止状态和 usage 等轻量解析。
- 每次请求在进入流式转发前合并并编译候选规则；转发循环内不能反复读取数据库、反复解析账户 JSON 或动态计算全量策略列表。
- 规则数量需要有上限：内置 preset、供应商 / 工具类型策略和账户追加规则合并后只保留当前请求作用域内的启用规则，并按优先级短路匹配。
- 关键词数量和单个关键词长度需要有上限；命中摘要只记录短片段，不保存完整命中文本。
- 试运行模式也必须走同一性能边界，不能因为“不拦截”就额外保存更多正文。
- 背压处理继续以 `res.write()` 和现有流式写入等待为准；规则匹配不能绕过下游背压，也不能为了等待匹配结果阻塞后续 raw chunk 超过现有超时语义。

## 9. 示例

### 9.1 中转广告污染

```json
{
  "name": "屏蔽中转广告",
  "enabled": true,
  "priority": 100,
  "appliesTo": {
    "providerCodes": ["openai"],
    "clientProfiles": ["codex"],
    "downstreamProtocols": ["responses_sse"]
  },
  "match": {
    "eventTypes": ["response.output_text.delta", "message"],
    "textIncludes": ["本服务由某某中转提供", "请访问我们的官网"]
  },
  "phases": ["写入下游前", "可见输出前", "可见输出后"],
  "dataHandling": "丢弃当前流",
  "retry": true,
  "accountSwitch": "切号并短期避让上游桶",
  "accountState": "仅运行态避让",
  "avoidanceTtlSeconds": 300
}
```

解释：

- 如果广告事件还没写给客户端，网关直接丢弃当前上游。
- 如果客户端尚未收到任何 SSE body，后端可以服务端切号重试。
- 如果客户端已收到非可见事件或可见输出，后端不能静默拼接新流，只能通知客户端重试或失败。
- 默认只做上游桶短期避让，不写账号临时不可调用。

### 9.2 Codex 可见输出前失败

```json
{
  "name": "OpenAI Codex Responses 可见输出前失败",
  "builtin": true,
  "enabled": true,
  "appliesTo": {
    "providerCodes": ["openai"],
    "clientProfiles": ["codex"],
    "downstreamProtocols": ["responses_sse"]
  },
  "match": {
    "failureEvents": true
  },
  "phases": ["可见输出前"],
  "dataHandling": "替换为失败事件",
  "retry": true,
  "accountSwitch": "按客户端 turn 策略",
  "accountState": "不修改",
  "rewrite": {
    "event": "response.failed",
    "errorCode": "upstream_retryable_error"
  }
}
```

## 10. 存储草案

如果需要管理端创建供应商 / 工具类型策略，建议新增独立表，而不是把所有策略塞进系统设置 JSON。

建议表：`stream_intercept_policies`

| 字段 | 含义 |
| --- | --- |
| `id` | 策略 ID |
| `scope_type` | `builtin`、`global`、`provider_tool`、`account` |
| `account_id` | 账户级规则可选 |
| `provider_code` | 供应商过滤 |
| `account_type` | 账号类型过滤 |
| `client_profile` | 客户端工具类型过滤 |
| `downstream_protocol` | 下游协议过滤 |
| `endpoint` | 请求路径过滤 |
| `enabled` | 是否启用 |
| `priority` | 匹配优先级 |
| `name` | 中文名称 |
| `match_json` | 匹配条件 |
| `behavior_json` | 数据处理、重试、切号、账户状态 |
| `created_at` / `updated_at` | 时间戳 |

内置 preset 可以由代码注册为只读虚拟策略，不必复制到每个账号。账户列表和详情页只展示继承结果与账户追加规则，避免同一内置策略被复制成大量重复配置。

## 11. 审计与诊断

命中规则时必须记录结构化元信息：

- 规则 ID、名称、作用域、优先级。
- 命中的 event 类型、error code、文本匹配摘要。
- 命中时阶段：写入下游前、可见输出前、可见输出后。
- 执行模式：拦截或试运行。
- 数据处理结果：丢弃事件、丢弃流、替换失败事件；试运行时记录计划处理结果但不改写响应。
- 重试意图、切号意图和实际执行路径。
- 账户状态副作用和运行态避让 TTL。
- 原始上游事件和下游改写事件的有限捕获，遵守现有审计 payload 上限和图像流正文省略规则。

## 12. 验证场景

第一版实现前需要补充回归：

- Codex 内置 preset 迁移后，当前 `response.failed`、`event:error`、`cyber_policy` 行为不变。
- 普通 OpenAI-compatible 客户端命中同类事件时，不伪造 Codex 可重试码。
- 广告关键词出现在首个可见事件前：服务端可切号救回。
- 广告关键词出现在已输出后：不服务端拼接新流，只通知客户端重试或失败。
- 规则命中但客户端不支持可重试协议：写普通失败事件并结束 SSE。
- 单事件过大、图像流和解析跳过场景不会为了匹配规则缓存完整正文。
- 高并发流式请求下，规则匹配不引入请求内数据库读取，不按 chunk 重新加载策略。
- 大量关键词配置超过上限时，后端拒绝保存或只启用受控数量，避免单请求线性扫描失控。
- 运行态避让不会写入持久账号状态；服务重启后可自然丢失。

## 13. 第一版待确认边界

这些问题需要在实现前确认，确认后应直接写入接口契约和实现计划，不作为长期开放的“打磨项”悬置。

- 规则合并顺序：内置 preset、供应商 / 工具类型策略、账户追加规则的优先级和冲突处理。
- 账户级规则权限：哪些角色可以新增、编辑、停用账户级规则，以及是否允许关闭继承的内置 preset。
- 运行态避让范围：命中规则后默认避让当前账号、上游桶还是代理；TTL 默认值和最大值。
- 规则规模上限：单账号最多多少条规则、每条规则最多多少关键词、单关键词最大长度和单事件扫描窗口。
- 客户端不支持重试协议时的兜底：统一写普通失败事件并结束 SSE，还是按规则允许只失败不重试。
- 审计展示范围：规则命中记录展示哪些摘要字段，避免保存完整大 payload 或图片流正文。
- 与现有 Codex turn 避让的关系：内置 Codex preset 迁移后，第 4 次 turn 级切号语义必须保持不变。
