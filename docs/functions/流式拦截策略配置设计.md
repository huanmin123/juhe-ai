# 流式拦截策略配置设计

> 设计状态：第一版已落地，后续继续打磨更细的继承摘要和命中详情展示。
> 本文记录 `200 + SSE` 流内错误、广告污染和上游流内容异常的配置化方案。当前运行时已支持默认规则、管理端策略和账户追加规则；普通客户端统一写普通失败事件，客户端专用可重试错误码仍由运行时客户端能力门控。

## 1. 目标

流式拦截策略解决的是：上游 HTTP 状态码已经是 `2xx`，但 AI 对话 SSE 流内部出现失败事件、广告插入、异常文本或其他污染内容。普通非 `2xx` 账号错误策略不能覆盖这类问题，因为账户测试和健康检查可能仍然成功。

本设计目标：

- 把当前写死在代码里的 OpenAI SSE 流内失败拦截逻辑沉淀为系统默认规则。
- 管理端策略默认按供应商隔离；只要运行时把响应作为 AI 对话 SSE 流处理，就进入候选规则匹配，不按接口路径、具体协议或客户端类型缩窄范围。
- 让前端配置表达业务意图：数据怎么处理、是否重试、是否切号、账户状态怎么处理。
- 让后端执行层根据当前流式阶段自动选择具体落地方式，而不是让用户理解“客户端重试”和“服务端重试”的实现细节。
- 对广告污染这类 `200 + SSE` 弱证据优先使用运行态避让，不默认写持久账号状态。

非目标：

- 不把客户端专用的 `upstream_retryable_error` 语义扩散为所有 OpenAI-compatible 客户端通用能力。
- 不引入“状态码 / 错误码特征规则”通用兜底模型。
- 不在正常流式路径里为了匹配规则缓存完整响应体。
- 不允许单条规则无边界地把任意已输出流静默重放给客户端。

## 2. 核心判断

策略配置层只回答四个问题：

| 维度 | 问题 | 示例 |
| --- | --- | --- |
| 数据处理 | 命中内容要丢弃单个事件、结束当前流，还是替换为失败事件 | 丢弃当前流 |
| 是否重试 | 命中后本次结果是否不可接受，需要进入下一次尝试 | 是 |
| 是否切号 | 下一次尝试是否应避开当前账号或上游桶 | 切下一个账号并短期避让当前账号 |
| 账户状态 | 是否写入账号持久状态或只做运行态避让 | 仅运行态避让 |

后端执行层再根据当时流阶段决定具体动作：

- 还没有向客户端写任何 SSE body：可以丢弃当前上游并在服务端切号重试，客户端无感。
- 已经向客户端写过任何 SSE body：禁止服务端静默切号拼接，只能通过下游支持的重试信号通知重试；不支持时返回失败。

第一版实现说明：

- 已实现按完整 SSE event 在写给下游前判断，不需要等整条 SSE 流结束。
- 已实现系统默认规则、管理端策略与账户追加规则合并，支持结构化字段 / 普通文本匹配、事件丢弃、当前流丢弃、失败事件替换、试运行、审计元信息和运行态避让。
- 已将流式响应头延迟到真正写出下游前；命中策略且“是否重试 = 是”时，如果还没有写任何 SSE body，可回到调度循环做同请求服务端重试。已经写出下游 body 后仍禁止静默拼接第二条上游流。

## 3. 运行时阶段

前端不暴露阶段选择，也不让用户选择“写入下游前 / 写入下游后”。阶段只能由网关在当次运行时按真实下游写入状态判断：当前请求是否已经成功向客户端写出 SSE body，配置时无法可靠知道。

| 运行时阶段 | 判断依据 | 执行约束 |
| --- | --- | --- |
| 写入下游前 | 尚未成功写出任何 SSE body | 可服务端切号重试 |
| 写入下游后 | 已成功写出任意 SSE body，包括 metadata、心跳或文本 | 不允许服务端静默切号，只能下游重试或失败 |

## 4. 策略来源与内部范围

策略按“系统默认规则 + 管理端策略 + 账户追加规则”合并。

### 4.1 系统默认规则

系统默认规则由代码维护，默认启用，不在普通页面中删除。它们用于承接当前已经验证过的供应商级 SSE 流内失败场景。

首批默认规则：

| 默认规则 | 适用条件 | 匹配 | 行为 |
| --- | --- | --- | --- |
| OpenAI response.failed | `providerCode = openai` 且响应按 SSE 流处理 | `event/type = response.failed` | 数据处理为替换失败事件；重试为是；账户状态不修改；普通客户端写普通失败码，是否写专用可重试错误码由运行时客户端能力决定 |
| OpenAI event:error | `providerCode = openai` 且响应按 SSE 流处理 | `event/type = error` | 同上 |
| OpenAI data.error | `providerCode = openai` 且响应按 SSE 流处理 | 存在 top-level `error` | 同上 |
| OpenAI response.error | `providerCode = openai` 且响应按 SSE 流处理 | 存在 `response.error` | 同上 |
| OpenAI cyber_policy | `providerCode = openai` 且响应按 SSE 流处理 | `error.code = cyber_policy` | 写入下游后仍可替换为失败事件；客户端支持专用重试信号时写 `upstream_retryable_error`；账户状态不修改 |

### 4.2 管理端策略

管理端策略用于当前供应商内的通用规则。前端不暴露客户端类型、接口路径、具体协议或账号类型作用范围。第一版只按供应商隔离，OpenAI 网关下创建的策略由后端写入内部 `provider_code = openai`；是否进入拦截由运行时 SSE 流处理入口决定。

### 4.3 账户追加规则

账户追加规则用于处理个别中转的广告、污染文本、私有错误码或异常事件格式。账户规则固定叠加在系统默认规则和管理端策略之前，第一版不提供关闭继承的开关。

账户规则不应单独决定客户端重试能力。即使账户规则要求“重试”，是否能写特定客户端可识别的可重试错误码仍由运行时客户端能力决定。

## 5. 前端配置项

### 5.1 基础信息

| 字段 | 说明 |
| --- | --- |
| 规则名称 | 中文名称，用于列表和审计展示 |
| 启用状态 | 是否参与匹配 |
| 执行模式 | `拦截` 或 `试运行`；试运行只记录命中和审计，不改变下游响应 |
| 优先级 | 数字越小越先匹配 |
| 备注 | 说明为什么需要这条规则 |

### 5.2 匹配条件

第一版只支持结构化条件和普通关键词包含匹配，不支持正则、大小写忽略、中文繁简转换或多语言模板。

| 条件 | 说明 |
| --- | --- |
| SSE event 类型 | `response.failed`、`response.output_text.delta`、`message`、`error` 等 |
| data.type | SSE data JSON 内的事件类型 |
| error.code | 上游错误码，例如 `cyber_policy` |
| error.type | 上游错误类型 |
| 文本包含 | 用于匹配广告、污染文案或中转提示 |
| 文本不包含 | 用于减少误杀 |
| JSON 字段存在 | 例如存在 `error`、`response.error` |

匹配只能在当前 SSE 事件的受限窗口内完成，不能为了匹配文本拼接完整流。

### 5.3 数据处理

| 选项 | 含义 | 典型用途 |
| --- | --- | --- |
| 丢弃命中事件 | 不把当前事件写给客户端，继续读取后续事件 | 单独广告事件、无害污染事件 |
| 丢弃当前流 | 关闭当前上游流，后续按“是否重试”和“是否切号”执行 | 广告混入模型输出、上游失败事件 |
| 替换为失败事件 | 不转发原事件，写入本地构造的失败 SSE | 客户端可重试失败、普通流失败 |

`原样放行` 不作为数据处理选项。需要观察规则命中但不改变响应时，使用基础信息里的 `试运行` 模式；否则“拦截策略”命中后必须产生明确处理结果。

如果“是否重试 = 是”，第一版建议数据处理只允许选择“丢弃当前流”或“替换为失败事件”，避免出现只丢一个事件却要求整轮重试的矛盾配置。

### 5.4 是否重试

只暴露布尔值：

| 选项 | 含义 |
| --- | --- |
| 是 | 命中规则后本次响应不可接受，需要进入下一次尝试 |
| 否 | 命中规则后不触发下一次尝试，只按数据处理和账户处理执行 |

这里不区分“允许重试”和“强制重试”。能否在服务端重试、是否只能通知客户端重试，由执行层按流阶段和客户端能力决定。

### 5.5 是否切号

| 选项 | 含义 |
| --- | --- |
| 不切号 | 重试时不额外避让当前账号 |
| 本次请求切下一个账号 | 仅当前请求后续尝试避开当前账号 |
| 切号并短期避让当前账号 | 当前请求和后续短 TTL 内避开当前账号 |
| 切号并短期避让上游桶 | 短 TTL 内避让同 `proxy`、`baseUrl` 或 `provider` 桶 |

如果“是否重试 = 否”，前端应禁用“本次请求切下一个账号”这类本次重试动作，只保留后续运行态避让类选项。

### 5.6 账户状态

| 选项 | 含义 | 建议边界 |
| --- | --- | --- |
| 不修改 | 只记录审计和使用记录 | 默认 |
| 仅运行态避让 | 写入进程内短 TTL 屏蔽或上游桶避让 | 广告污染、弱证据异常 |
第一版只实现“不修改”和“仅运行态避让”。`200 + SSE` 流内污染本身不能证明账号真实不可调用，因此不在这里提供临时不可调用、限流中或异常这类持久状态写入。

## 6. 前端落点

流式拦截不是纯账户级能力，前端主入口不能只放在账户编辑弹窗里。第一版应把“策略管理”和“账户追加”拆开：独立策略管理页负责供应商内管理端规则和默认规则展示；账户编辑只负责当前账户的继承摘要和账户追加规则。

该能力也不放到 `系统设置`。系统设置适合稳定的全局参数，不适合承载按供应商和账号覆盖组合出来的动态拦截规则。

建议落点：

| 能力 | 前端位置 | 说明 |
| --- | --- | --- |
| 策略管理主入口 | 管理侧 AI 管理菜单下新增“流式拦截策略” | 管理当前供应商内规则，展示默认规则 |
| 默认规则展示 | 流式拦截策略页只读分组 | 展示供应商默认规则的匹配条件和行为，不允许普通用户删除 |
| 账户追加规则 | AI 账户编辑弹窗 | 在现有非 `2xx` 错误策略卡片旁新增“账户流式拦截规则”折叠卡片，只维护当前账户追加 / 覆盖 |
| 账户继承摘要 | AI 账户编辑弹窗只读展示 | 展示当前账户最终会继承哪些供应商内管理端策略和默认规则 |
| 命中记录排障 | 审计日志 / 使用记录详情 | 规则命中作为 gateway metadata 展示，不在规则配置页保存完整正文 |

第一版策略管理页已落地在 `frontend/src/views/stream-intercept-policies/`：

- `StreamInterceptPoliciesView.vue`：策略列表、筛选、默认规则只读展示、新增 / 编辑 / 删除和编辑弹窗。第一版先保持单文件页面，后续字段继续膨胀时再拆出 modal、payload 和 options 文件。

菜单位置：

- 管理侧：`AI 管理 / 流式拦截策略`。
- 用户侧：默认不提供全局策略管理入口；用户只在自己的账户编辑弹窗里维护账户追加规则。

账户级追加规则仍复用 `frontend/src/views/accounts/` 现有账户编辑结构：

- 新增 `AccountStreamInterceptPolicyCard.vue`：承载规则列表、添加、删除、试运行 / 拦截模式、数据处理、重试、切号和账户状态表单。
- 新增 `accountStreamInterceptPolicyTypes.ts`：账户追加规则表单类型和继承摘要展示类型。

- 更新 `accountCredentials.ts`、`accountSavePayload.ts`、`useAccountEditForm.ts`：把流式规则纳入账号编辑表单的加载、校验和保存。

页面文案要明确区分：

- “错误处理策略”：处理非 `2xx` HTTP 响应。
- “流式拦截策略”：处理 `200 + SSE` 内部事件、广告污染和流内失败。

策略管理页应以列表 + 抽屉 / 弹窗编辑为主，第一版不暴露客户端类型、请求路径、具体协议或账号类型筛选；只要是当前供应商的 AI 对话 SSE 流，就会按完整 event 进入拦截判断。账户编辑弹窗只展示继承摘要和当前账户追加规则，避免用户误以为修改了管理端规则。

## 7. 执行矩阵

| 阶段 | 是否重试 | 是否切号 | 推荐执行 |
| --- | --- | --- | --- |
| 写入下游前 | 是 | 本次切号 | 关闭当前上游，服务端换账号重新请求，客户端无感 |
| 写入下游前 | 是 | 不切号 | 关闭当前上游；如果仍有同账号重试预算才重试，否则返回失败 |
| 写入下游前 | 否 | 任意 | 按数据处理执行；如当前流被丢弃则返回失败或结束 |
| 写入下游后 | 是 | 任意 | 不静默拼接第二条流；客户端支持专用重试信号时写可重试失败事件，否则写普通失败事件 |
| 写入下游后 | 否 | 任意 | 按数据处理执行；如果丢弃当前流则写普通失败事件 |

执行层必须保证：只要已有任何下游 SSE body 写出，就不能把第二个上游流静默拼到同一个响应里。

## 8. 性能边界

流式拦截运行在网关热路径，第一版必须把性能约束当成接口契约的一部分。

- 按 SSE 事件边界增量解析，不允许为了规则匹配缓存完整流、完整响应体或跨事件全文。
- 规则匹配只消费当前完整 SSE event 的受限文本窗口和已解析出的结构化字段；文本关键词只做普通 `includes` 类包含判断。
- 单个 SSE event 超过解析上限时，沿用现有流式解析跳过策略：停止规则匹配并原样转发，不能为了命中广告规则继续堆内存。
- 图像流、超大 base64、文件类 payload 和已经触发正文省略的流，不做文本关键词扫描，只保留结构化事件类型、终止状态和 usage 等轻量解析。
- 每次请求在进入流式转发前合并并编译候选规则；转发循环内不能反复读取数据库、反复解析账户 JSON 或动态计算全量策略列表。
- 规则数量需要有上限：默认规则、供应商内管理端策略和账户追加规则合并后只保留当前请求供应商内的启用规则，并按来源顺序和优先级短路匹配。
- 关键词数量和单个关键词长度需要有上限；命中摘要只记录短片段，不保存完整命中文本。
- 试运行模式也必须走同一性能边界，不能因为“不拦截”就额外保存更多正文。
- 背压处理继续以 `res.write()` 和现有流式写入等待为准；规则匹配不能绕过下游背压，也不能为了等待匹配结果阻塞后续 raw chunk 超过现有超时语义。

## 9. 示例

### 9.1 中转广告污染

```json
{
  "name": "屏蔽中转广告",
  "enabled": true,
  "priority": 100,
  "match": {
    "eventTypes": ["response.output_text.delta", "message"],
    "textIncludes": ["本服务由某某中转提供", "请访问我们的官网"]
  },
  "dataHandling": "丢弃当前流",
  "retry": true,
  "accountSwitch": "切号并短期避让上游桶",
  "accountState": "仅运行态避让",
  "avoidanceTtlSeconds": 300
}
```

解释：

- 如果广告事件还没写给客户端，网关直接丢弃当前上游。
- 如果客户端尚未收到任何 SSE body，后端可以服务端切号重试。
- 如果客户端已收到任何 SSE body，后端不能静默拼接新流，只能通知客户端重试或失败。
- 默认只做上游桶短期避让，不写账号临时不可调用。

### 9.2 OpenAI SSE 流内失败

```json
{
  "name": "OpenAI response.failed",
  "defaultRule": true,
  "enabled": true,
  "priority": 10,
  "match": {
    "eventTypes": ["response.failed"]
  },
  "dataHandling": "替换为失败事件",
  "retry": true,
  "accountSwitch": "本次请求切下一个账号",
  "accountState": "不修改"
}
```

## 10. 存储草案

管理端策略使用独立表，不把策略塞进系统设置 JSON。第一版用户不配置接口、协议或客户端类型范围，后端保存为供应商内规则；未来新增供应商时由对应管理入口或后端上下文写入内部 `provider_code`。

已落地表：`stream_intercept_policies`

| 字段 | 含义 |
| --- | --- |
| `id` | 策略 ID |
| `enabled` | 是否启用 |
| `execution_mode` | `intercept` 或 `dry_run` |
| `priority` | 匹配优先级，数字越小越先匹配 |
| `name` | 中文名称 |
| `provider_code` | 内部供应商范围字段；第一版默认 `openai`，不对用户开放账号类型、客户端工具、接口或协议过滤 |
| `match_json` | 匹配条件 |
| `data_handling` | 丢弃命中事件、丢弃当前流或替换为失败事件 |
| `retry_enabled` | 是否重试 |
| `account_switch` | 是否切号及运行态避让范围 |
| `account_state` | 账户状态处理，第一版只开放不修改和运行态避让 |
| `avoidance_ttl_seconds` | 短 TTL 避让秒数 |
| `notes` | 备注 |
| `created_at` / `updated_at` | 时间戳 |

默认规则由代码注册为只读虚拟策略，不复制到每个账号。账户追加规则第一版写入账户凭据里的 `stream_intercept_rules`，随账户详情加载和保存，避免为少量账号覆盖提前拆出重型账户规则表。

## 11. 审计与诊断

命中规则时必须记录结构化元信息：

- 规则 ID、名称、来源、内部供应商、优先级。
- 命中的 event 类型、error code、文本匹配摘要。
- 命中时阶段：写入下游前、写入下游后。
- 执行模式：拦截或试运行。
- 数据处理结果：丢弃事件、丢弃流、替换失败事件；试运行时记录计划处理结果但不改写响应。
- 重试意图、切号意图和实际执行路径。
- 账户状态副作用和运行态避让 TTL。
- 原始上游事件和下游改写事件的有限捕获，遵守现有审计 payload 上限和图像流正文省略规则。

## 12. 验证场景

第一版回归覆盖以下场景：

- OpenAI 默认规则生效后，当前 `response.failed`、`event:error`、`cyber_policy` 行为不变。
- 普通 OpenAI-compatible 客户端命中同类事件时，写普通失败事件，不伪造客户端不支持的可重试码，也不承诺保留下游可见原始上游错误码。
- 广告关键词出现在首个下游 body 写出前：服务端可切号救回。
- 广告关键词出现在已写下游后：不服务端拼接新流，只通知客户端重试或失败。
- 规则命中但客户端不支持专用重试信号：写普通失败事件并结束 SSE。
- 单事件过大、图像流和解析跳过场景不会为了匹配规则缓存完整正文。
- 高并发流式请求下，规则匹配不引入请求内数据库读取，不按 chunk 重新加载策略。
- 大量关键词配置超过上限时，后端拒绝保存或只启用受控数量，避免单请求线性扫描失控。
- 运行态避让不会写入持久账号状态；服务重启后可自然丢失。

## 13. 已确认边界

- 规则合并顺序：账户追加规则优先于管理端策略，管理端策略优先于默认规则；同一来源按优先级从小到大匹配。
- 账户级规则第一版只能追加规则，不提供关闭默认规则或管理端继承的开关。
- 运行态避让只支持当前账号和上游桶短 TTL 避让，不写持久账号状态。
- 规则规模上限：账户追加规则最多 20 条；每个匹配字段最多 50 项；文本扫描单事件窗口为 64 KiB，超大事件和图像类事件跳过文本扫描。
- 客户端不支持专用重试信号时，不伪造 `upstream_retryable_error`；已经写出下游 body 后只按普通失败或结束处理。
- 审计只记录规则 ID、名称、来源、命中字段、命中值、短摘要和处理结果，不保存完整污染正文。
- OpenAI 默认规则进入运行时策略后仍保持客户端能力门控，普通客户端不继承客户端专用重试语义。
