# 外部来源系统鉴权设计

> 面向 `juhe-ai` 后端、`juhe-ai-public-welfare` 后端和后续 AI 维护者。
> 当前已落地来源授权管理、最小 demo、账号维度和 IP 维度公开聚合接口：来源授权 token 负责统一鉴权，每一个公开接口都是独立资源 scope。

## 当前状态

- 已实现：外部来源系统表、来源 token 表、管理 API、系统运维 / 公开接口授权页面、来源鉴权中间件和 `GET /__aipublic__/demo/source-auth` demo 接口。
- 已实现：维护脚本生成 demo token，明文 token 只在创建时输出一次；生产 token 在数据库保存 hash、加密密文、前缀和后缀。
- 已实现：来源授权新增、编辑、删除、启停、到期时间、生产 token 生成、完整 token 单条复制、token 到期时间和来源授权级公开接口限频。
- 已实现：公开接口接入文档弹窗、接口名称搜索、接口 curl 复制和授权列表内置测试 Token；接入文档不返回明文测试 Token，测试 Token 只返回 mock 数据。
- 已实现：`GET /__aipublic__/account/usage`、`GET /__aipublic__/ip/usage`、`GET /__aipublic__/consumption/ranking` 和 `GET /__aipublic__/access/info`。
- 已实现：`GET /__aipublic__/group/list`、`GET /__aipublic__/api-key/list`、`GET /__aipublic__/account/list`、`POST /__aipublic__/group/add|update|del`、`POST /__aipublic__/api-key/add|update|del`、`POST /__aipublic__/account/add|update|del`，由外部来源系统对指定系统用户执行受控资源对账、新增、修改和删除。
- 已实现：`/__aipublic__` 调用写入公开接口日志，记录来源、接口、状态码、耗时、trace ID 和按原文容量上限捕获的有限请求 / 响应摘要，最大保留 7 天。
- 未实现：公益站用户维度排行榜快照、HMAC 防重放和来源系统审计报表。

## 目标

- 给后续外部接口提供统一入口，先回答“这个来源系统是否被允许调用”。
- 让 `juhe-ai-public-welfare` 这类后端服务通过来源授权 token 调用，而不是把接口暴露给任意浏览器或匿名公网请求。
- 把外部接口鉴权与具体业务接口解耦：账号用量、IP 用量、公益榜、快照等后续接口只复用鉴权结果，不重新设计一套认证规则。

## 边界

`juhe-ai` 只负责：

- 校验 `Authorization: Bearer <source_token>` 是否命中某个来源系统的 active token。
- 校验来源授权、token 状态、过期时间、接口需要的 scope 和来源授权限频。
- 返回统一的 401 / 403 错误语义。

`juhe-ai` 不负责：

- 公益站公网 IP 拦截。
- 公益站公网访问频率控制。
- 公益站用户权限、用户与 IP 映射、排行榜快照。
- 浏览器直接调用外部来源接口。

## 请求约定

公开接口只需要 Bearer 来源 token：

```http
Authorization: Bearer <source_token>
```

来源系统由 token 唯一定位，后台管理只维护来源名称；当前契约只认 `Authorization: Bearer <source_token>`，其他来源标识头不参与鉴权。

## Demo 接口

```http
GET /__aipublic__/demo/source-auth
Authorization: Bearer <source_token>
```

该接口只用于验证来源系统鉴权链路，成功响应不包含任何业务数据：

```json
{
  "data": {
    "ok": true,
    "sourceName": "juhe-ai公益站",
    "tokenName": "来源系统鉴权 demo token",
    "tokenPrefix": "juis_xxx",
    "authenticatedAt": "2026-05-30T00:00:00.000Z",
    "mock": false
  }
}
```

响应只返回 token 前缀，不返回明文 token、token hash、授权能力或内部数据库 ID。

## 账号与 IP 聚合公开接口

真实公益站对接应优先使用账号维度和 IP 维度接口，而不是 demo：

```http
GET /__aipublic__/account/usage?range=last7d&page=1&pageSize=20
Authorization: Bearer <source_token>
```

账号维度接口返回账号实际消耗聚合事实：账号 ID、账号名称、供应商、请求数、成功数、失败数、Token、缓存、成本、活跃天数、平均首 token、平均总耗时和最大总耗时。公益站贡献榜应按 `accountId` 映射自己的 `sub2apiAccountId`，不能通过 IP 推断贡献归属。

```http
GET /__aipublic__/ip/usage?range=last7d&page=1&pageSize=20
Authorization: Bearer <source_token>
```

该接口需要 scope：

```text
juhe_ai_public:ip_usage:read
```

IP 维度接口返回内容只包含 IP 维度聚合事实：请求数、成功数、失败数、错误率、输入 / 输出 token、缓存 token、缓存率、成本、活跃天数、平均首 token、平均总耗时和最大总耗时。正式 token 读取 `client_ip_usage_range_windows` 和 `client_ip_registry`；内置测试 token 返回 mock 数据。公开接口只支持 `range=today|last7d|last31d` 三个后台固定窗口，传 `startDate/endDate` 会返回 `400`。

账号维度、消耗排行和接入信息都使用自己的独立 scope，不能复用 IP 用量读取 scope。

这些接口不返回封禁策略、API Key、分组、模型、上游凭据或公益站用户关系。公益站需要自己把账号映射到登记、把 IP 映射到用户并生成排行榜快照。

## 公开资源控制接口

外部来源系统可用独立资源控制 scope 读取脱敏列表，并新增、修改和删除分组、API Key 与账号：

```http
GET /__aipublic__/group/list
GET /__aipublic__/api-key/list
GET /__aipublic__/account/list
POST /__aipublic__/group/add
POST /__aipublic__/group/update
POST /__aipublic__/group/del
POST /__aipublic__/api-key/add
POST /__aipublic__/api-key/update
POST /__aipublic__/api-key/del
POST /__aipublic__/account/add
POST /__aipublic__/account/update
POST /__aipublic__/account/del
Authorization: Bearer <source_token>
Content-Type: application/json
```

这些接口分别需要自己的独立 scope：

```text
juhe_ai_public:group_list:read
juhe_ai_public:api_key_list:read
juhe_ai_public:account_list:read
juhe_ai_public:group_add:write
juhe_ai_public:group_update:write
juhe_ai_public:group_delete:write
juhe_ai_public:api_key_add:write
juhe_ai_public:api_key_update:write
juhe_ai_public:api_key_delete:write
juhe_ai_public:account_add:write
juhe_ai_public:account_update:write
juhe_ai_public:account_delete:write
```

列表接口用于外部来源系统对账和找回本系统 ID：分组列表支持 `targetUsername`、`providerCode` 和 `keyword`；API Key 列表支持 `targetUsername`、`keyword`、`status` 和 `routeStrategyId`，不返回明文 `key`；账号列表支持 `targetUsername`、`targetGroupName + providerCode`、`providerProtocolProfileId`、`groupId`、`keyword`、`type`、`status` 和 `schedulable`，不返回上游凭据或外部来源系统业务主键。

公开资源接口不再配置目标用户白名单；`targetUsername` 对列表和新增是业务目标用户参数，对修改和删除是可选校验条件。来源授权只判断 token 是否拥有当前接口对应的独立资源 scope。目标系统用户已停用时，分组、API Key 和账号的新增、列表、修改、删除都会返回“目标用户已停用”，不会继续创建、更新或删除该用户的资源。分组接口新增时按 `targetUsername` 定位或自动创建目标用户，修改和删除按本系统 `groupId` 定位资源，`targetUsername` 可选且传入时必须匹配归属用户。API Key 接口要求目标用户已存在，新增时返回一次性明文 `key` 和本系统 `apiKey.id`，修改和删除按 `apiKeyId` 定位资源，修改至少提交一个变更字段，且不会回显明文密钥。账号接口当前只支持 `type=api_key`，新增只创建资源并返回本系统 `account.id`，重复时返回冲突；修改必须使用 `accountId` 并至少提交一个变更字段，支持只更新 `apiKey`、`baseUrl`、`status` 等单个字段，未提交字段保留原值；删除必须使用 `accountId`，可选目标用户、分组、供应商和协议档案只作防误删校验，找不到时分别返回 `404` 或幂等 `action=not_found`；删除会真实删除账号并投递关联记录清理。

这些接口只负责资源控制面读取和写入，不生成公益站业务排行榜快照，也不判断公益站用户和 IP 归属。公开路径统一按 `/__aipublic__/业务/功能` 定义。

## 存储设计

业务库新增两张低增长表：

```text
external_integration_sources
- id TEXT PRIMARY KEY
- name TEXT NOT NULL
- status TEXT NOT NULL DEFAULT 'active'
- scopes_json TEXT NOT NULL DEFAULT '[]'
- rate_limits_json TEXT NOT NULL DEFAULT '[]'
- expires_at TEXT
- notes TEXT
- last_used_at TEXT
- created_at TEXT NOT NULL
- updated_at TEXT NOT NULL

external_integration_source_tokens
- id TEXT PRIMARY KEY
- source_ref_id TEXT NOT NULL
- name TEXT NOT NULL
- token_hash TEXT UNIQUE NOT NULL
- token_secret_encrypted TEXT NOT NULL
- token_prefix TEXT NOT NULL
- token_suffix TEXT NOT NULL
- status TEXT NOT NULL DEFAULT 'active'
- scopes_json TEXT NOT NULL DEFAULT '[]'
- expires_at TEXT
- last_used_at TEXT
- created_at TEXT NOT NULL
- updated_at TEXT NOT NULL
- revoked_at TEXT

```

设计要点：

- token 明文在创建响应返回；后台列表只展示安全标识，复制时通过单条 token 接口按管理员权限读取完整 token。
- `token_hash` 使用带用途前缀的 SHA-256 摘要，`token_secret_encrypted` 加密保存完整 token，`token_prefix` 和 `token_suffix` 只用于管理列表安全识别。
- `token_hash` 全局唯一并走索引点查，不扫描表；命中 token 后通过 `source_ref_id` 关联来源系统。
- `rate_limits_json` 保存来源授权级公开接口限频规则，空数组表示不限制。示例：`[{ "windowSeconds": 60, "maxRequests": 10 }, { "windowSeconds": 10, "maxRequests": 3 }]`。
- `last_used_at` 低频更新，默认同一来源 / token 至少间隔 60 秒才刷新一次，避免外部接口高频调用时每次都写业务库。
- scope 需要来源系统和 token 同时拥有，避免只改一个对象就误放开接口。
- 每一个公开接口都是独立资源 scope。来源授权和 token 都必须包含当前接口 scope，才允许调用该接口。
- 删除来源授权会同时删除该来源下的 token 摘要；原 Bearer token 随即按无效 token 处理。
- 公开资源写入接口不保存外部来源系统的业务 ID；新增响应返回的本系统 `group.id`、`apiKey.id` 和 `account.id` 由外部来源系统自行记录并在后续修改或删除时回传。
- 后台来源系统列表先按来源表 `updated_at` 或 `status + updated_at` 固定窗口分页，再按当前页来源 ID 补读 token 摘要；不能在分页前 join / group 全量 token 表。

## 鉴权流程

1. 读取 `Authorization: Bearer <source_token>`。
2. 对 token 做摘要，按 `token_hash` 点查。
3. 通过 token 的 `source_ref_id` 关联来源系统。
4. 校验来源系统为 `active`。
5. 校验来源系统未过期。
6. 校验 token 为 `active` 且未过期。
7. 校验来源授权和 token 都包含当前接口所需的独立资源 scope。
8. 执行来源授权级限频；默认没有限频规则时直接通过。
9. 把来源上下文写入本次请求上下文，进入具体业务接口。

无论鉴权成功、鉴权失败、限频、参数错误还是公开前缀 404，本次 `/__aipublic__` 请求都会在响应结束后写入公开接口日志；日志保存有限原文摘要和元数据，进入快照的来源 token 明文按原文保存。公开接口日志的字段、页面和保留策略见 [公开接口日志设计](公开接口日志设计.md)。

## 错误语义

| 场景 | HTTP | code | 说明 |
| --- | --- | --- | --- |
| 缺少 Bearer token | 401 | `external_source_token_missing` | 未携带来源授权 token。 |
| 来源系统或 token 不匹配 | 401 | `external_source_unauthorized` | 不暴露具体是来源不存在还是 token 错误。 |
| 来源系统停用 | 403 | `external_source_disabled` | token 有效但来源系统已停用。 |
| 来源系统过期 | 403 | `external_source_expired` | 来源系统已到期。 |
| token 不可用或过期 | 401 | `external_source_token_unavailable` | token 被撤销、停用或过期。 |
| scope 不足 | 403 | `external_source_scope_forbidden` | 来源系统没有调用目标接口的权限。 |
| 目标用户已停用 | 400 | - | 来源系统已获准操作该用户名，但目标系统用户当前不可作为有效调用方或资源控制边界。 |
| 超过来源限频 | 429 | `external_source_rate_limited` | 当前来源系统超过配置的公开接口限频。 |

外部来源 token 不能访问后台登录态接口。比如携带来源 token 调用 `/__aisys__/api/accounts` 仍返回后台未登录。

## 管理入口

系统管理员可在“系统运维 / 公开接口授权”里维护来源系统：

- 查看接入文档：弹窗展示公开接口手册，支持按接口名称和路径搜索，并支持复制指定接口的 curl。
- 使用内置测试 Token：授权列表默认展示“内置测试来源 / 内置测试 Token”，管理员可从列表复制完整 Token；接入文档和 curl 示例只展示 `<source_token>` 占位符，不暴露明文测试 Token。内置测试 Token 只进入 mock 数据分支，固定限频 `60s/10次`，可停用或重置，不支持编辑、删除或新增子 Token。
- 新增来源授权：填写名称、接口资源授权、到期时间和限频规则；保存后直接生成一个生产 token，创建弹窗展示完整 token。
- 启用 / 停用来源系统：停用后该来源所有公开接口调用都会被拒绝。
- 删除来源授权：删除来源及其关联 token 摘要，原生产 token 立即失效。
- 生成 token：创建成功时展示完整 token；列表只展示前后缀标识，复制按钮按单条 token 读取完整 token。
- 启用 / 停用 token：用于临时阻断某个调用方凭据。
- 撤销 token：用于永久废弃旧 token。

公开接口限频只作用于 `/__aipublic__` 前缀下的接口，不影响后台管理 API、网关 API 或系统健康检查。限频规则为空时不限制；可以同时配置多条规则，例如 `60s/10次` 和 `10s/3次`。

## 维护脚本

生成 demo 来源和 token：

```powershell
pnpm --filter juhe-ai-backend external-source:demo-token
```

可选参数：

```powershell
pnpm --filter juhe-ai-backend external-source:demo-token -- --name "juhe-ai公益站" --token-name "公益站联调 token"
pnpm --filter juhe-ai-backend external-source:demo-token -- --scopes "external_integrations:source_auth_demo:read,juhe_ai_public:account_add:write"
```

脚本输出 PowerShell 调用示例。生产 token 输出后应保存到调用方后端配置，不要写进前端包、浏览器请求或公开文档。

## 后续接入

后续如果新增其他外部接口，仍复用同一鉴权中间件并新增独立 scope。业务接口只暴露明确允许的底层事实或受控写入能力，不把公益站用户、榜单快照、封禁策略或内部账号关系放入 `juhe-ai` 公开响应。
