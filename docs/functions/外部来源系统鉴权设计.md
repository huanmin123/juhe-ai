# 外部来源系统鉴权设计

> 面向 `juhe-ai` 后端、`juhe-ai-public-welfare` 后端和后续 AI 维护者。
> 当前已落地来源系统管理、最小 demo 和 IP 维度公开聚合接口：来源系统 token 负责统一鉴权，真实业务接口只复用鉴权结果。

## 当前状态

- 已实现：外部来源系统表、来源 token 表、管理 API、系统运维 / 公开接口授权页面、来源鉴权中间件和 `GET /__aipublic__/demo/source-auth` demo 接口。
- 已实现：维护脚本生成 demo token，明文 token 只在创建时输出一次，数据库只保存 hash。
- 已实现：来源系统启停、到期时间、token 启停、token 到期时间和来源系统级公开接口限频。
- 已实现：公开接口接入文档弹窗、接口名称搜索、接口 curl 复制和内置测试 token；测试 token 只返回 mock 数据。
- 已实现：`GET /__aipublic__/juhe-ai/ip-usage`、`GET /__aipublic__/juhe-ai/consumption-ranking` 和 `GET /__aipublic__/juhe-ai/access-info`。
- 已实现：`POST /__aipublic__/juhe-ai/accounts` 和 `DELETE /__aipublic__/juhe-ai/accounts`，由公益站后端把登记账号推送到指定系统用户和分组，并在删除登记前真实删除上游账号。
- 未实现：公益站用户维度排行榜快照、HMAC 防重放和来源系统审计报表。

## 目标

- 给后续外部接口提供统一入口，先回答“这个来源系统是否被允许调用”。
- 让 `juhe-ai-public-welfare` 这类后端服务通过来源系统 token 调用，而不是把接口暴露给任意浏览器或匿名公网请求。
- 把外部接口鉴权与具体业务接口解耦：IP 用量、公益榜、快照等后续接口只复用鉴权结果，不重新设计一套认证规则。

## 边界

`juhe-ai` 只负责：

- 校验 `Authorization: Bearer <source_token>` 是否命中某个来源系统的 active token。
- 校验来源系统、token 状态、过期时间、接口需要的 scope 和来源系统限频。
- 返回统一的 401 / 403 错误语义。

`juhe-ai` 不负责：

- 公益站公网 IP 拦截。
- 公益站公网访问频率控制。
- 公益站用户权限、用户与 IP 映射、排行榜快照。
- 浏览器直接调用外部来源接口。

## 请求约定

公开接口只需要 Bearer 来源 token：

```http
Authorization: Bearer <source_token>
```

不再使用旧草案里的 `X-Juhe-AI-Client` 或 `X-Juhe-AI-Source`。来源系统由 token 唯一定位，后台管理只维护来源名称。

## Demo 接口

```http
GET /__aipublic__/demo/source-auth
Authorization: Bearer <source_token>
```

该接口只用于验证来源系统鉴权链路，成功响应不包含任何业务数据：

```json
{
  "data": {
    "ok": true,
    "sourceName": "juhe-ai公益站",
    "tokenName": "来源系统鉴权 demo token",
    "tokenPrefix": "juis_xxx",
    "scopes": ["external_integrations:source_auth_demo:read"],
    "authenticatedAt": "2026-05-30T00:00:00.000Z",
    "mock": false
  }
}
```

响应只返回 token 前缀，不返回明文 token、token hash 或内部数据库 ID。

内置 mock 数据 demo：

```http
GET /__aipublic__/demo/mock-ranking?range=last7d&limit=5
Authorization: Bearer <source_token>
```

该接口返回固定 mock 排行数据，用于调用方验证请求头、路径、query 和响应解析。使用内置测试 token 调用时，响应中的 `testToken = true`，不读取真实统计或业务数据。

## IP 聚合公开接口

真实公益站对接应优先使用 IP 维度接口，而不是 demo：

```http
GET /__aipublic__/juhe-ai/ip-usage?range=last7d&page=1&pageSize=20
Authorization: Bearer <source_token>
```

该接口需要 scope：

```text
juhe_ai_ip_usage:read
```

返回内容只包含 IP 维度聚合事实：请求数、成功数、失败数、错误率、输入 / 输出 token、缓存 token、缓存率、成本、活跃天数、平均首 token、平均总耗时和最大总耗时。正式 token 读取 `client_ip_usage_range_windows` 和 `client_ip_registry`；内置测试 token 返回 mock 数据。公开接口只支持 `range=today|last7d|last31d` 三个后台固定窗口，传 `startDate/endDate` 会返回 `400`。

同一 scope 还允许读取：

- `GET /__aipublic__/juhe-ai/consumption-ranking`：基于 IP 聚合表的 TopN 便利视图。
- `GET /__aipublic__/juhe-ai/access-info`：公开接口可用范围与边界说明。

这些接口不返回封禁策略、API Key、系统账户、AI 账户、分组、供应商、模型或公益站用户关系。公益站需要自己把 IP 映射到用户并生成排行榜快照。

## 公益账号推送接口

公益站保存“公益 AI 登记”后，可用独立写入 scope 推送账号：

```http
POST /__aipublic__/juhe-ai/accounts
Authorization: Bearer <source_token>
Content-Type: application/json
```

该接口需要 scope：

```text
juhe_ai_account_push:write
```

请求体包含 `targetUsername`、`targetGroupName`、`providerCode`、`name`、`type=api_key`、`baseUrl`、`apiKey`、`supportedModels`、`concurrencyLimit`、`status` 和可选 `externalId`。目标系统用户或分组不存在时会自动创建；同一目标用户、目标分组和供应商内优先按结构化 `externalId` 映射精确更新原账号，未传或找不到时再按同名账号更新。目标用户、分组、AI 账户和 `externalId` 映射写入在同一事务内完成，账号校验失败不会残留自动创建的目标资源；正式推送成功会写操作日志。响应只返回账号 ID、目标用户 / 分组、安全状态和模型限制摘要，不返回上游凭据明文。

公益站删除本地登记前应调用同一 path 的删除接口：

```http
DELETE /__aipublic__/juhe-ai/accounts
Authorization: Bearer <source_token>
Content-Type: application/json
```

删除接口同样需要 `juhe_ai_account_push:write`。请求体包含 `targetUsername`、`targetGroupName`、`providerCode`，并在 `accountId`、`name`、`externalId` 中至少提供一个。服务端优先按结构化 `externalId` 定位，再按账号 ID 和名称兜底；找到账号后调用账号真实删除流程并投递关联记录清理，找不到时幂等返回 `action=not_found`，便于公益站继续删除本地登记。正式删除成功会写操作日志。

该接口只负责账号控制面写入，不生成公益站业务排行榜快照，也不判断公益站用户和 IP 归属。

## 存储设计

业务库新增三张低增长表：

```text
external_integration_sources
- id TEXT PRIMARY KEY
- name TEXT NOT NULL
- status TEXT NOT NULL DEFAULT 'active'
- scopes_json TEXT NOT NULL DEFAULT '[]'
- rate_limits_json TEXT NOT NULL DEFAULT '[]'
- expires_at TEXT
- notes TEXT
- last_used_at TEXT
- created_at TEXT NOT NULL
- updated_at TEXT NOT NULL

external_integration_source_tokens
- id TEXT PRIMARY KEY
- source_ref_id TEXT NOT NULL
- name TEXT NOT NULL
- token_hash TEXT UNIQUE NOT NULL
- token_prefix TEXT NOT NULL
- status TEXT NOT NULL DEFAULT 'active'
- scopes_json TEXT NOT NULL DEFAULT '[]'
- expires_at TEXT
- last_used_at TEXT
- created_at TEXT NOT NULL
- updated_at TEXT NOT NULL
- revoked_at TEXT

external_integration_account_push_records
- id TEXT PRIMARY KEY
- system_account_id TEXT NOT NULL
- provider_code TEXT NOT NULL
- group_id TEXT NOT NULL
- external_id TEXT NOT NULL
- account_id TEXT NOT NULL
- created_at TEXT NOT NULL
- updated_at TEXT NOT NULL
- UNIQUE (system_account_id, provider_code, group_id, external_id)
```

设计要点：

- token 明文只在创建或轮换时展示一次。
- `token_hash` 使用带用途前缀的 SHA-256 摘要，不保存明文。
- `token_hash` 全局唯一并走索引点查，不扫描表；命中 token 后通过 `source_ref_id` 关联来源系统。
- `rate_limits_json` 保存来源系统级公开接口限频规则，空数组表示不限制。示例：`[{ "windowSeconds": 60, "maxRequests": 10 }, { "windowSeconds": 10, "maxRequests": 3 }]`。
- `last_used_at` 低频更新，默认同一来源 / token 至少间隔 60 秒才刷新一次，避免外部接口高频调用时每次都写业务库。
- scope 需要来源系统和 token 同时拥有，避免只改一个对象就误放开接口。
- 公益账号推送的 `externalId` 使用结构化表做精确幂等匹配，不从 `accounts.notes` 做前导通配符扫描。

## 鉴权流程

1. 读取 `Authorization: Bearer <source_token>`。
2. 对 token 做摘要，按 `token_hash` 点查。
3. 通过 token 的 `source_ref_id` 关联来源系统。
4. 校验来源系统为 `active`。
5. 校验来源系统未过期。
6. 校验 token 为 `active` 且未过期。
7. 校验来源系统和 token 都包含接口所需 scope。
8. 执行来源系统级限频；默认没有限频规则时直接通过。
9. 把来源上下文写入本次请求上下文，进入具体业务接口。

## 错误语义

| 场景 | HTTP | code | 说明 |
| --- | --- | --- | --- |
| 缺少 Bearer token | 401 | `external_source_token_missing` | 未携带来源系统 token。 |
| 来源系统或 token 不匹配 | 401 | `external_source_unauthorized` | 不暴露具体是来源不存在还是 token 错误。 |
| 来源系统停用 | 403 | `external_source_disabled` | token 有效但来源系统已停用。 |
| 来源系统过期 | 403 | `external_source_expired` | 来源系统已到期。 |
| token 不可用或过期 | 401 | `external_source_token_unavailable` | token 被撤销、停用或过期。 |
| scope 不足 | 403 | `external_source_scope_forbidden` | 来源系统没有调用目标接口的权限。 |
| 超过来源限频 | 429 | `external_source_rate_limited` | 当前来源系统超过配置的公开接口限频。 |

外部来源 token 不能访问后台登录态接口。比如携带来源 token 调用 `/__aisys__/api/accounts` 仍返回后台未登录。

## 管理入口

系统管理员可在“系统运维 / 公开接口授权”里维护来源系统：

- 查看接入文档：弹窗展示公开接口手册，支持按接口名称、路径和 scope 搜索，并支持复制指定接口的 curl。
- 使用测试 token：弹窗展示内置测试 token，复制出来的 curl 默认使用该 token；测试 token 只进入 mock 数据分支。
- 新增来源系统：填写名称、授权能力、到期时间和限频规则。
- 启用 / 停用来源系统：停用后该来源所有公开接口调用都会被拒绝。
- 生成 token：明文 token 只在创建成功时展示一次，页面只保存和展示前缀。
- 启用 / 停用 token：用于临时阻断某个调用方凭据。
- 撤销 token：用于永久废弃旧 token。

公开接口限频只作用于 `/__aipublic__` 前缀下的接口，不影响后台管理 API、网关 API 或系统健康检查。限频规则为空时不限制；可以同时配置多条规则，例如 `60s/10次` 和 `10s/3次`。

## 维护脚本

生成 demo 来源和 token：

```powershell
pnpm --filter juhe-ai-backend external-source:demo-token
```

可选参数：

```powershell
pnpm --filter juhe-ai-backend external-source:demo-token -- --name "juhe-ai公益站" --token-name "公益站联调 token"
```

脚本输出 PowerShell 调用示例。生产 token 输出后应保存到调用方后端配置，不要写进前端包、浏览器请求或公开文档。

## 后续接入

后续如果新增其他外部接口，仍复用同一鉴权中间件并新增独立 scope。业务接口只暴露明确允许的底层事实或受控写入能力，不把公益站用户、榜单快照、封禁策略或内部账号关系放入 `juhe-ai` 公开响应。
