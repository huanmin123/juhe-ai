# AI 工具创建规范

> 面向创建或修改 AI function tool、站内工具执行器和外部能力适配器的维护者。
> 本文定义模型决策、参数契约、执行器校验和外部副作用之间的稳定边界。

## 1. 核心原则

- AI 模型负责理解用户意图，并根据工具的 `description`、参数说明和 JSON Schema 选择工具、填写参数。
- 工具执行器只消费本次工具调用的显式参数和经过授权的执行上下文；不得重新读取用户原始提示词、聊天历史或模型提示词来推断、补写、覆盖或放宽工具参数。
- 同一组规范化工具参数和同一份授权执行上下文必须产生相同的请求与副作用，不能因用户原话中出现某个关键词而改变行为。
- 权限、额度、并发、超时、资源大小、目标白名单和供应商协议约束仍由服务端强制执行。这些是确定性的系统边界，不属于模型语义决策。

## 2. 工具描述与参数契约

- `description` 说明工具用途、何时调用、参数之间的语义关系、默认值和重要限制；需要模型做出的选择必须在这里或对应字段的 `description` 中写清楚。
- JSON Schema 是模型参数声明和结构校验的唯一事实来源。枚举、格式、长度、必填项、数组数量和是否允许额外字段应尽量直接表达在 Schema 中。
- 无法由 JSON Schema 完整表达的跨字段或协议约束，由执行器做确定性校验；校验规则只能依赖显式参数和稳定协议事实。
- 默认值必须公开写进工具描述并保持确定性。没有明确默认值的参数不得由执行器根据提示词猜测。
- 参数规范化只允许无损且无歧义的处理，例如去除首尾空白或统一枚举大小写。会改变用户意图、成本、质量、尺寸、范围或目标的修正不属于规范化。

## 3. 执行器禁止行为

- 禁止用关键词、正则、分类器或额外模型重新分析用户提示词，再决定是否放行某个参数档位。
- 禁止在执行器或传输适配器中偷偷改写提示词、扩写提示词、调整风格、改变质量、缩放尺寸、切换模型或替换输出格式。
- 禁止把非法参数静默修正为另一个合法值。参数非法时应在产生外部副作用前返回有界、可理解的错误，由调用模型决定是否修正后重试。
- 禁止在执行器和传输适配器各维护一套语义决策。传输层只负责协议编码、网络调用、有界响应读取和取消传播。
- 只有工具契约明确声明“自动选择”或“允许有损转换”时，执行器才能执行该行为；其算法、边界和结果字段必须可测试，不能依赖未声明的提示词推断。

## 4. 创建与评审清单

1. 工具用途、调用时机、参数语义、默认值和限制是否已在描述与 Schema 中完整表达。
2. 执行器是否只读取工具参数和最小授权上下文，没有读取原始用户提示词进行二次决策。
3. 非法参数是否在网络、文件、数据库或付费调用前确定性失败，没有静默降级或自动纠正。
4. 相同参数是否能稳定产生相同的上游请求；不同用户措辞是否不会改变既定工具参数的执行结果。
5. 权限、资源、超时、取消、结果大小和目标白名单是否仍由服务端强制控制。
6. 回归测试是否覆盖合法边界、非法边界、缺省值，以及“提示词关键词不能影响执行参数”的反例。

## 5. 生图工具示例

`generate_image` 的文本模型根据用户需求填写 `size`、`quality` 和 `output_format`。执行器只验证这些参数是否满足 `gpt-image-2` 的协议约束并原样传递：

- `size` 缺省时使用文档化默认值 `auto`；显式尺寸合法时原样传递。
- 宽高不是 16px 倍数、最长边超过 3840px、比例超过 3:1，或总像素不在 655,360 到 8,294,400 之间时直接失败。
- 执行器不得因为用户文本出现“2K”“4K”“超高清”等词放宽限制，也不得在没有这些词时把合法大尺寸自动缩小。
