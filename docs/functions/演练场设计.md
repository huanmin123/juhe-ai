## 1. 目标与非目标

### 1.1 目标

1. 新建一级菜单「演练场」,含六个子页:对话试玩、图片生成、视频生成、语音合成、向量生成、重排测试(v1.1 扩展后两页,2026-11-22 用户裁决「重点是让用户体验到效果」)。
2. 对话试玩为**一次性**对话:消息只存在于浏览器内存,刷新即空,无会话落库、无历史列表、无断线重连续传。
3. **六页统一交互契约(v1.4)**:每页各自先选一个**真实 API Key**(本人 active Key,复用控制台 api-keys 列表,self scope,六页互不影响)、再选模型(两级联动,顺序固定);左侧参数面板 + 右侧消息区,对标门户参考站 Playground 形态。演练场请求与真实用户请求**零差异**:以所选 Key 明文注入 `Authorization: Bearer` 走完整 /v1 链(Bearer 鉴权→IP 守卫→认证前熔断→用户级限流→分组路由→Key 额度→调度→usage_records 落库),计费、限流、记录与真实请求一致,无来源标记。
4. 视频/语音/向量/重排为 Key × 模型直连演示,复用既有媒体与同步执行器(v1.2 起图片生成除外,见第 5 条);v1.4 起全部经 §3.1 真实链路通道派发。
5. **图片生成(v1.2,UI v1.3 修订,v1.5 操作区改版)为工作台形态**:顶部卡片式快速入口 + 「生成设置」弹窗 + 生成历史卡片网格;生成为**真异步任务**(后端任务行 + 进程内执行器 + 前端轮询,「生成中」状态跨刷新可见);任务执行 v1.4 起改真实链路派发(Key 计费);结果图与参考图保留 **7 天**到期删字节,任务记录保留至用户手动删除或长期(v1.5,§3.4.6);卡片展示状态角标(缩略图左上)、参数标签、图像删除倒计时与下载/删除图标按钮(v1.3 起不展示 tokens 与扣费,全状态等高);点击卡片回填弹窗配置。
6. 对话试玩仅走 `chat_completions` 协议入口(用户裁决「只支持 chat 协议其他都不支持」);Claude/Gemini 等经网关既有跨协议转换桥出站,测的就是 `/v1` 用户实际拿到的路径。
7. 模型原生能力默认打开、不靠外部代偿:不实现「工具模型绑定」,也不做任何服务端工具注入;目录矩阵声明的能力由模型自身承担。

### 1.2 非目标

1. 不做对话/消息持久化(对话与参数不落库;向量/重排结果为纯 JSON 随响应呈现,不进产物暂存 §3.8)。**例外(v1.2)**:图片生成的任务记录与产物暂存落库(§3.4/§3.8),是媒体三页中唯一有历史的页面。
2. 不做工具模型绑定、候选解析、用户偏好、回写(连同旧 /my-chat 面整体退役,见 §8)。
3. 不做 hosted 工具注入:目录矩阵 `chat_completions` 协议下当前无任何模型声明 hosted 工具(`web_search` 等仅存在于 responses 协议,而对话试玩只走 chat 入口);若未来出现 chat 协议 hosted 声明,按「默认打开」原则另行小批接入。
4. 不做 responses / generate_content / messages 协议入口;responses 独占模型(gpt-6.1-terra、gpt-5.5-pro 系等无 chat 等价物的旗舰)不进模型下拉。
5. 不做断线续传、多标签页同步、导出。
6. 图片生成不做:任务重试按钮(重新生成即新建任务)、跨用户共享、公开分享链接(§4.2);~~手动删除任务/图像~~(v1.5 起改判:终态任务支持手动删除,记录与字节一并删,§3.4.6)。
7. 不做来源标记与豁免通道(v1.4):不注入 trafficSource/`x-juhe-ai-purpose`、不置 `SuppressUsage`、不提供免计费或限额豁免——「与真实请求零差异」是验收语义本身,演练场用量与真实用户流量在计费面不可区分。

## 3. 后端契约

### 3.1 挂载与鉴权

- 新包 `backend-go/projects/gateway/internal/playground`,经 `cmd/juhe-ai-gateway` 组合根挂载:`GET/POST /__aisys__/api/playground/...`(kernel Register,与 my-chat 同级,自动获得 kernel 的 body limit / IP rate limit / no-store 包裹)。
- 鉴权:每条路由套 `authDeps.RequireSession(true)`(与 chat 面同款)。数据范围(v1.4 改版):不再沿用 `ChatBindScope` 账户口径——Key 列表 = **当前登录者本人的 active Key**(复用控制台 api-keys 列表,self scope;admin 亦只看自己的 Key,无全量号池语义)。
- 派发(v1.4):playground handler 以**所选 Key 明文**构造 `Authorization: Bearer <key>` 请求,进程内直驱 `/v1` 链 handler(复用 `chatGatewayExecutor` 的 `chain.ServeHTTP` 直调模式——origin hop 替换为 handler 调用,io.Pipe 保活 SSE 流式,路径/头部/请求体契约与真实 /v1 请求同形);`RemoteAddr` 透传控制台请求 IP。**不注入 pinned 调度目标与内部身份,不置 `SuppressUsage`**。派发前 fail-closed 校验 Key 归属(`key.system_account_id == viewer`,非本人一律拒绝,admin 不例外)。因此 Bearer 鉴权、IP 守卫、认证前熔断、用户级限流、分组路由、Key 额度 429、在途预占、usage_records 落库与 `request.accepted` 审计全部与真实请求一致。playground 定义自己的 Dispatch 端口类型,cmd 层提供 Bearer 直驱适配器;旧 `WithChatDispatchAccount`/内部身份通道随 §8 v1.4 批退役。

### 3.2 GET /key-models —— 所选 Key 的模型目录(v1.4;旧 GET /accounts 退役,§8)

请求:`GET /playground/key-models?apiKeyId=`(`apiKeyId` 必填)。

响应(单请求返回该 Key 全量 kind 标记行,按模型名排序):

```json
{ "models": [
  { "modelId": "gpt-5.4", "kind": "chat", "providerCode": "gpt" },
  { "modelId": "gpt-image-2", "kind": "image", "providerCode": "gpt" },
  { "modelId": "grok-imagine-video-1.5", "kind": "video", "providerCode": "xai" },
  { "modelId": "speech-2.8-hd", "kind": "audio", "providerCode": "minimax" },
  { "modelId": "text-embedding-v4", "kind": "embedding", "providerCode": "qwen" },
  { "modelId": "gte-rerank-v2", "kind": "rerank", "providerCode": "qwen" }
] }
```

装载链(v1.4):派发前经 runtime cache `ReadGatewayRuntimeByAPIKeyID` 读 Key 行 + `GroupBindings` → 按 Key 路由策略的全部分组绑定取可达账户模型并集(`/v1/models` 成员资格语义同源,不只取当前选中分组;同一 `ListCachedGroupModelUnionAsync` 装载)→ **平行目录分类投影**:目录行按 `IncludeUnpriced` 全量读取(演练场候选不按计价过滤,故可列出 /v1/models 不列的无价行;模型目录元数据缓存聚合复用)。前端按**当前页面能力域(kind)过滤后展示,不展示全部六域**;响应按 `apiKeyId` 内存缓存,切换 Key 重新拉取并重置本页模型选择(六页缓存互不影响)。

模型分类口径(kind 六值;在 Key 模型并集上按目录行 `supportedAPIProtocols` × 提供该模型账户的能力域复核——延续 2026-10-31 E2E 裁决「目录声明 × 实际可派发」收口:纯目录分类会列出跑不通的模型,违背「跑不通的组合不进候选」原则):

- `chat`:目录协议含 `chat_completions`、`messages` 或 `generate_content` 之一 × 并集内提供账户能力域为 `chat`(域闸门现行口径)× 并集成员(含映射)可路由。
- `image`:既有生图家族白名单(`gpt-image-2` / grok-imagine 系 × 并集成员可路由,与旧 chat 生图候选同口径)。
- `video`:`chatMediaProviderAllowed` 供应商 × 目录声明 `video` 协议 × 提供账户能力域为 `video` 可路由。
- `audio`:目录声明 `audio_speech` 协议 × 并集成员可路由。
- `embedding`(v1.1):目录声明 `embeddings` 协议 × 提供账户能力域为 `embedding`(capability_domain 六值域闸门现行口径,不走已退役端点模式)× 并集成员(含映射)可路由。
- `rerank`(v1.1):目录声明 `rerank` 协议 × 提供账户能力域为 `rerank` × 并集成员(含映射)可路由。

校验:`apiKeyId` 缺失/非法 → 400 `playground_invalid_request`;Key 不存在或非当前登录者本人(fail-closed,含 admin)→ 404 `playground_key_not_found`(扁平错误信封,同下)。同一模型由多个供应商提供时按 `(modelId, kind)` 收敛单行,`providerCode` 取目录 scope rank 高者再字典序小者(确定性消歧)。Key 无任何分组绑定或并集为空时返回空 `models`(不回退匿名全量)。

**image 模型行的计价投影(v1.3 退役,v1.4 不恢复)**:v1.2 曾为「预计扣费」在账户目录的 image 模型行投影 `imageEstimate`;v1.3 起演练场不展示费用,该投影整体退役(`playground.ImageEstimate`、`playgroundImageEstimateOf`、前端 `PlaygroundImageEstimate` 已删),本端点响应**不含 `imageEstimate` 字段**。图像任务的 `costUsd` 本地计价落库(§3.4.2)不受影响,继续保留。

**成功载荷信封**:全部 JSON 成功响应走仓内统一 `{"data": <payload>}` 信封(kernel `WriteOK`/chat `okEnvelope` 同款;下文示例仅示 payload,省略信封);错误载荷为**扁平** `{"message","code"}`(与 chat 面 `messageCodePayload` 同款,非嵌套)。SSE 帧与二进制端点(视频 content / 语音音频)不包信封。

### 3.3 POST /chat/stream —— 一次性对话(SSE)

请求体(全量上下文由客户端携带,服务端零状态):

```json
{
  "apiKeyId": "key_...", "modelId": "gpt-5.4",
  "messages": [ { "role": "user" | "assistant", "content": "..." } ],
  "system": "可选 system 提示词",
  "temperature": 0.7, "maxTokens": null, "stream": true,
  "topP": 1, "frequencyPenalty": 0, "presencePenalty": 0
}
```

- 校验:`apiKeyId`/`modelId` 必填且 `modelId` 在 §3.2 该 Key 候选内(400 `playground_model_not_available`;Key 不存在或非本人 404 `playground_key_not_found`);`messages` 1~200 条、单条 ≤64KB、**role 仅 user|assistant**;`stream` 仅支持 `true`(false 返回 400)。
- 出站(v1.4):经 §3.1 直驱通道以所选 Key 的 Bearer 身份派发 `POST /v1/chat/completions`(SSE);请求体由服务端构造(system 进首条 system 消息;`stream_options.include_usage` 保持置位,保证 usage 末帧可达)。**无服务端工具注入、无多轮工具循环**(v1.4 移除 `fetch_url`,§8)。
- 归一 SSE 事件(v1.4 收缩为三事件,`data: <json>\n\n` 帧,与上游 chat chunk 解耦;帧间空闲超 5s 写 `: ping` 注释心跳防代理断流,仅在帧头已提交后发出;流式连接正常关闭即收尾,无独立 done 事件):

| type | 载荷 | 说明 |
| --- | --- | --- |
| `delta` | `{text}` | 助手正文增量 |
| `usage` | `{promptTokens, completionTokens, totalTokens}` | 上游末 chunk usage(缺省则无此事件) |
| `error` | `{code, message}` | 失败收尾(此前已发 delta 的照常已透出) |

错误码:`playground_invalid_request` 400、`playground_key_not_found` 404、`playground_model_not_available` 400、`playground_dispatch_failed` 502(上游失败,message 带上游状态码摘要)。链上 Bearer 失败、限流与 Key 额度 429 等按真实 /v1 语义经归一 error 帧透出,不做演练场专属豁免。

### 3.4 图片生成工作台(v1.2,异步任务)

> v1.0 的同步端点 `POST /images` 退役(§8);生图改为「上传参考图 → 创建任务 → 轮询」三步。产物字节保留 7 天;任务记录行保留至用户手动删除或长期(v1.5 手动删除入口 §3.4.6,§3.8)。单次恒 1 张,无 n 参数(2026-10-31 裁决延续)。

#### 3.4.1 POST /images/references —— 参考图上传

- 请求:`{ dataBase64 }`(纯 base64,无 data: 前缀;解码后字节 ≤10MB)。
- **body limit 例外**:kernel 对 `/__aisys__/api` 系统面默认 256KiB JSON body limit,本端点是唯一例外——kernel 新增路由级覆盖能力 `RegisterBodyLimitOverride(method, path, limit)`(默认不注册 = 行为零变化),playground 注册 `POST /images/references` → 20MB(10MB × base64 膨胀 4/3 ≈ 13.34MB,取 1.5 倍余量);领域侧 10MB 校验独立生效。超限响应统一走 playground 自有读取通道的 400「请求体读取失败或超过上限」口径(kernel 层拦截与领域层拦截同文案,§3.1 例外口径唯此一条)。
- 处理:解码 + MIME 嗅探(png/jpeg/webp)→ 落暂存 `kind='image_reference'`、`job_id=''`(孤儿态)。
- 响应:`{ id, url }`(`url` 为 `/playground/artifacts/{id}/content` 相对地址,同 §3.8 取流契约)。
- 孤儿参考图(上传后 24h 内未绑定任务)由懒清理删除(§3.8)。

#### 3.4.2 POST /images/jobs —— 创建生成任务

请求:

```json
{
  "apiKeyId": "key_...", "modelId": "gpt-image-2",
  "prompt": "提示词",
  "aspectRatio": "1:1",        // 1:1 | 16:9 | 9:16,可省略(由上游默认)
  "resolution": "1k",          // 1k | 2k | 4k,可省略
  "quality": "standard",       // standard(标准) | fine(精细),可省略
  "outputFormat": "png",       // png | jpeg | webp,可省略
  "referenceIds": ["art_..."]  // ≤10 张,须为本人未删参考图(§3.4.1 返回的 id)
}
```

- 校验:`apiKeyId`/`modelId` 必填且 `modelId` 在 §3.2 该 Key 候选内(400 `playground_model_not_available`;Key 不存在或非本人 404 `playground_key_not_found`,与 §3.3 同口径);`prompt` trim 非空且 ≤ 既有 `imagesPromptMaxBytes`;`referenceIds` 0~10 条、逐条校验归属(本人 `kind='image_reference'` 未删行,不存在/越界/已删 → 400);`aspectRatio/resolution/quality/outputFormat` 词表外 → 400。
- **任务记住创建时 Key(v1.4)**:`apiKeyId` + `providerCode` 记入任务 `params` jsonb(无 schema 迁移);页面切换 Key 不影响在途任务(执行、轮询、取流均以创建时 Key 为准);`account_id` 列保留为历史列(NOT NULL 约束不变),v1.4 起新任务写空串,归属以 `params.apiKeyId` 为准。
- **size 映射**:`aspectRatio × resolution → 上游 size("W×H")` 静态映射表(按白名单模型支持集精确映射:16:9→横版、9:16→竖版、1:1→方版;超出模型支持集的档位取最近支持档,不臆测上游能力)。实际发送的 size 记入任务 `params.size`,卡片标签显示实际值(「最终以上游返回为准」口径,与参考产品一致)。API 层两者皆可省略(透传上游默认);**v1.3 起工作台 UI 必选其一并恒传,实际请求恒走映射表**(E2E 实证:16:9+1K → 1536x1024)。
- 处理:落库 `playground_image_jobs` 行 `status='queued'`(`expires_at=0`,完成时回填)→ 参考图行事务内绑定 `job_id` → 任务进**进程内队列**(缓冲 channel + 2 worker);队列满时 503 `playground_busy` 且**任务行收敛为 failed**("排队已满,请稍后重试"——不留永不执行的 queued 僵尸行;收敛落库失败时行留 queued 由启动恢复兜底)。
- 响应:`{ jobId, status: "queued" }`。

**执行器**(gateway 进程内;v1.4 起任务执行经 §3.1 真实链路通道派发——以任务 `params.apiKeyId` 的 Bearer 身份直驱 `/v1` 链,Key 计费、额度与限流照常生效):

- 执行前原子 claim(`UPDATE ... SET status='running' WHERE id=? AND status='queued'`),防重启恢复与慢 goroutine 竞态;**任务级超时 10min**(context deadline,与链内既有首响应/空闲超时双保险);claim 后先校验 `params.apiKeyId` 归属(Key 已删除或非本人 → failed);
- 无参考图 → `POST /v1/images/generations`(JSON,`response_format:"b64_json"` 优先);有参考图 → `POST /v1/images/edits`(multipart,**fields 在前、image parts 在后**——网关计量扫描层 fields 上限 16 / parts 上限 24,顺序保证计量字段可提取;多参考图为多个 image part 直通上游,上游能力裁决);
- **quality/outputFormat 真实派发**(2026-11-22 用户裁决「参数完整对齐参考产品」):请求带 `quality` 时派发体补 `quality`(映射 standard→`"medium"`、fine→`"high"`,词表外原样透传交上游裁决);带 `outputFormat` 时补 `output_format`(png/jpeg/webp 原值);generations JSON 与 edits fields 同口径,上游不支持时按 §7 既有口径 failed 透出原文;
- 上游只回临时 URL 时(如 grok)由服务端经 SSRF 守卫客户端回退下载字节(v1.0 口径延续);
- 结果解码落暂存 `kind='image_result'`(恒 1 张);解析上游响应 `usage`(宽容,缺省 0);
- **扣费计算**:经 cmd 层注入的计价端口按目录行本地计算(张数 × 档位单价,复用 `pricing.BuildCostBreakdown` 与媒体模板 `PriceForTier`;目录无价 → `cost_usd` 存 null);**v1.4 起平台计费以链上 usage_records 为权威**,任务行 tokens/cost 为本地解析展示口径(UI v1.3 起不展示,字段保留);
- 终态:`completed`(`expires_at = completed_at + 7d`)或 `failed`(上游/下载/落库失败,`error_message` 存上游原文;**Key 额度不足、限流 429 等链上错误同样按 failed 收敛并展示归一原因**;无图无 expires_at;**failed 已绑定的参考图由清理任务 failed 臂按 7d 删除**,§3.8);
- **启动恢复**:网关启动时扫描——`queued` 重新入队(继续执行;存量行 `params` 无 `apiKeyId` 的按 failed 收敛,错误信息说明「任务创建于免 Key 固定派发版本,缺少 API Key 归属,无法按真实链路派发」);`running` 置 `failed`("网关重启,任务中断";goroutine 已随进程死亡,不可续)。

#### 3.4.3 GET /images/jobs —— 生成历史列表

- query:`keyword?`(提示词 ILIKE)、`apiKeyId?`、`status?`(`queued|running|completed|failed|expired|active`;`expired` 为派生态 = completed 且图像已过期;`active` 为派生态 = queued+running,供前端「生成中」筛选项一次覆盖两种在途状态)、`quality?`、`limit?`(默认 24,≤100)、`before?`(游标,`createdAt` UnixMilli)。
- 响应:`{ jobs: [卡片], nextCursor?: number }`(按创建时间倒序;`nextCursor` 缺省 = 无更多)。

#### 3.4.4 GET /images/jobs/{id} —— 任务详情(轮询)

- 单个卡片形状;id 不属于本人 → 404 `playground_job_not_found`。
- 轮询口径:前端对 queued/running 卡片 3s 轮询(§4.2)。

**卡片形状**(列表与详情同形):

```json
{
  "jobId": "...", "status": "queued|running|completed|failed",
  "prompt": "...", "model": "...", "apiKeyId": "...",
  "aspectRatio": "1:1", "resolution": "1k", "quality": "standard", "outputFormat": "png",
  "size": "1024x1024",
  "referenceCount": 2,
  "references": [ { "id": "...", "url": "/playground/artifacts/.../content" } ],
  "images":     [ { "id": "...", "url": "/playground/artifacts/.../content" } ],
  "imageDeleted": false,
  "usage": { "inputTokens": 12, "outputTokens": 4096, "totalTokens": 4108 },
  "costUsd": 0.0631,
  "error": "",
  "createdAt": 1760000000,
  "completedAt": 1760000300,
  "expiresAt": 1760604800
}
```

- `images`/`references`:completed 且未删时给出(每项含取流 url);过期或失败为空数组。
- `imageDeleted`:**读时判定**(`expires_at > 0 && expires_at < now`)与清理标记(`images_expired`)取或——字节删除可滞后于判定,展示恒收敛。
- `usage`/`costUsd`:completed(含已删)有值,失败为 null;`costUsd=null` 表示目录无价。**v1.3 起演练场 UI 不展示 tokens 与扣费**(用户裁决:演练场不显示这些),字段保留——API 形状不变,历史记录数据完整;**v1.4 起平台计费以链上 usage_records 为权威**(api_key_id/tokens/cost 为所选 Key 口径),卡片字段为本地解析展示口径。`createdAt/completedAt/expiresAt` 为 unix 秒;`expiresAt` 仅 completed 非删时有值(已删收敛 0,无倒计时)。

#### 3.4.5 保留期与删除语义(2026-11-22 用户裁决)

- **结果图与参考图一并保留 7 天**,到期删除字节(任务记录行保留至用户手动删除或长期,卡片显示「已删除图像」与历史参数);
- 删除倒计时:卡片按 `expiresAt - now` 显示「X 天 X 时后删除图像」;
- 到期删除为自动行为;手动删除入口 v1.5 起提供(§3.4.6,与到期清理不同:记录行与字节一并删除)。

#### 3.4.6 DELETE /images/jobs/{id} —— 手动删除任务(v1.5,2026-11-22 用户裁决)

- 语义:任务记录行与产物字节(`image_result`+`image_reference`)在**同一事务**内一并删除,不可恢复——区别于到期清理的「删字节留记录」;删除后历史列表/详情/轮询均不可再见(轮询侧读 404 自然停轮)。
- 边界:仅终态可删(`completed`(含图像已删)/`failed`);`queued|running` 返回 409 `playground_job_not_deletable`(生成中任务不做取消语义,等终态后可删);不存在或越权统一 404 `playground_job_not_found`(不泄露他户任务存在性)。
- 成功 204 无响应体;错误面为扁平 `{message, code}`(§3.3 同形)。
- 前端:卡片操作行删除图标(a-popconfirm 二次确认「删除后任务记录与图像一并删除,不可恢复」),删除成功后本地移除卡片、清理该任务轮询定时器并 toast「已删除」(§4.2)。

### 3.5 POST /videos + 轮询 —— 异步视频

- `POST /videos`:请求 `{ apiKeyId, modelId, prompt, size?, seconds?, inputImageBase64?(首帧) }` → 经 §3.1 真实链路通道以该 Key 的 Bearer 身份派发(`POST /v1/video/generations`)→ 响应 `{ jobId }`;**创建、轮询、产物下载均携带创建时所选 Key(前端条目持有),页面换 Key 不影响在途轮询**;任务引用随暂存区记录(§3.8,视频产物本体不落盘——上游内容链接有效期 24h,凭 jobId 可持续获取)。
- `GET /videos/{jobId}?apiKeyId=`:复用 `PollChatMediaTask` 代理上游轮询 → 归一 `{ status: "queued"|"running"|"completed"|"failed"|"cancelled", progress?, error?: {code, message} }`(未知上游状态按 failed 收敛并携带原文;`error` 为对象形态)。jobId 由前端持有,服务端不落库;`jobId` 须匹配 `^[A-Za-z0-9._-]{1,512}$`(否则 400);网关重启后凭前端持有的 jobId 仍可轮询。
- `GET /videos/{jobId}/content?apiKeyId=`:复用 `DownloadChatMediaContent` 流式代理视频字节(`Content-Type` 透传,`Content-Disposition: inline`)。

### 3.6 POST /speech —— 同步语音

请求:`{ apiKeyId, modelId, input(≤2000 字), voice, speed?, format? }` → 经 §3.1 真实链路通道以该 Key 的 Bearer 身份派发(`POST /v1/audio/speech`)→ 音频落暂存(§3.8),响应 `{ id, url, mimeType }`;前端 `<audio src=url>` 播放、下载走 url。Key 不存在或非本人统一 404 `playground_key_not_found`(images/videos/speech 三端点同口径);无 audio 模型/端点模式时 400。

### 3.8 产物暂存(v1.2 双保留期:图像 7 天按任务、语音/视频 24h 覆盖式)

**范围与两类保留期**(2026-11-22 用户裁决:图像「随便一张都好几 M」,平台不长期存储,但 7 天内可回看;语音/视频维持测试台口径):

| 类别 | kind | 保留期 | 清理方式 |
| --- | --- | --- | --- |
| 生成任务结果图 | `image_result` | **7 天**(按任务,`expires_at` = 完成时间 + 7d) | jobs 定时任务删字节 + 记录行置 `images_expired`(到期清理不删记录行;记录行仅经 v1.5 手动删除移除,§3.4.6) |
| 参考图 | `image_reference` | **7 天**(随所属任务;孤儿态 24h) | 同上;孤儿(`job_id=''`)由懒清理 24h 删 |
| **failed 任务的参考图** | `image_reference` | **7 天**(随任务,按 `updated_at` 起算;failed 无图无 `expires_at`) | jobs 定时任务 failed 臂扫描删参考图字节 + 置 `images_expired` |
| 语音 | `speech` | 24h 覆盖式(不变) | 懒清理(v1.0 口径) |
| 视频任务引用 | `video_task` | 24h 覆盖式(不变) | 懒清理(v1.0 口径) |
| 旧 `image`(v1.0 覆盖式) | — | 已退役,不再产生 | 存量行由 jobs 清理任务按 7d 窗口顺带删除 |

**形态**（2026-11-09 用户裁决：改 PG bytea，多节点无需共享盘）：业务库表 `juhe_business.playground_artifacts`（`system_account_id` / `id` / `kind` / `mime_type` / `data bytea` / `job_id`(v1.2 加列,默认空) / `created_at bigint`，主键 `(system_account_id,id)`，`created_at` 索引）：

- id 为 `{unixNano}-{随机 token}`（无扩展名，MIME 存 `mime_type`）；
- `image_result`/`image_reference` 行携带 `job_id`;语音/视频维持 v1.0 同 kind **事务内覆盖式替换**;
- **图像字节清理**由 jobs 项目定时任务 `playground-images-retention` 执行(每时节拍,§5):两臂扫描——到期臂(`expires_at>0` 且超期,走部分索引)与 **failed 臂**(`status='failed'` 且 `updated_at` 超 7d,覆盖失败任务已绑定的参考图,否则参考图随任务失败永久滞留)——对命中任务按 `(system_account_id, job_id)` 删除 `image_result`+`image_reference` 行(结果图与参考图一起删),并置任务行 `images_expired=true`(**语义 = 图像资源已清理**,completed 到期与 failed 超窗两类共用标记);**到期清理不删任务记录行**(记录行仅经 v1.5 手动删除入口移除,§3.4.6);滞留 queued/running 行不在清理范围(其状态由 gateway 启动恢复收敛后自然进入两臂);
- **懒清理**(挂 GET artifacts、GET content 等读写点)继续按 24h 处理 speech/video_task 与孤儿参考图;清理失败静默吞掉(缓存 GC 语义,不阻断主路径);
- 归属与安全：`GET /playground/artifacts/{id}/content` 按 `system_account_id + id` 定位(kind 集扩为 `image_result`/`image_reference`/`speech`;id 白名单字符)，跨用户不可达；视频 content 走既有 jobId 代理（§3.5）。

**恢复端点**:`GET /playground/artifacts` → `{ speech: {id,url,mimeType,createdAt} | null, video: {jobId,apiKeyId,modelId,status,createdAt} | null }`——**v1.2 起移除 `images` 字段**(图片历史改走 `GET /images/jobs`,§3.4.3),v1.4 起 video 条目 `accountId` 改 `apiKeyId`(轮询/取流携带创建时 Key,§3.5),speech/video 前端刷新恢复口径不变。`createdAt` 为 **unix 秒**(int64);`url` 为**相对路径** `/playground/artifacts/{id}/content`(前端经 axios baseURL 拼 `/__aisys__/api` 前缀;同源请求自动携带会话 Cookie)。

**边界**:暂存是展示缓存不是资产库——图像字节不保证 beyond 7 天,用户留档靠下载;产物存业务库,跨节点可读,gateway 重启不丢;图像存储总量 = 每用户 7 天窗口内的任务产物(单任务恒 1 张结果图 + ≤10 张参考图),由到期清理自然封顶;语音/视频总量维持覆盖式封顶。

### 3.7 用量与审计(v1.4 改版)

- **与真实请求完全一致**(v1.4):六域请求走完整 /v1 链,`usage_records` 照常落库(`api_key_id`/tokens/cost 为所选 Key 口径)、Key 额度与用户级限流照常生效、在途预占与 `request.accepted` 审计照常;**无来源标记**——不置 `SuppressUsage`、不注入内部身份、不带 `x-juhe-ai-purpose` 请求头、不新增 trafficSource 字段,演练场流量与真实用户流量在计费、限流与审计面不可区分。
- 图像任务行 tokens/cost 为任务记录的本地解析口径(§3.4.2,目录无价计 `costUsd=null` 不虚构金额),仅作历史卡片数据;平台计费对账以 usage_records 为权威。
- 历史口径存档:v1.0~v1.3 固定派发曾走内部身份通道 `SuppressUsage`(不落 usage_records)并以 `x-juhe-ai-purpose: playground_<scene>` 六常量标记审计——该通道与标记随 v1.4 整体退役(§8),不再产生新流量。

### 3.9 POST /embeddings —— 同步向量生成(v1.1)

请求体:

```json
{
  "apiKeyId": "key_...", "modelId": "text-embedding-v4",
  "input": [ "文本一", "文本二" ],
  "dimensions": 1024, "encodingFormat": "float"
}
```

- 校验:`apiKeyId`/`modelId` 必填且 `modelId` 在 §3.2 该 Key 候选内(400 `playground_model_not_available` / 404 `playground_key_not_found`,与 §3.3 同口径);`input` 为字符串或字符串数组——单字符串视为一条,数组 ≤10 条、每条 trim 后非空且 ≤8192 字节;`dimensions` 可选正整数透传;`encodingFormat` 为后端契约保留的透传字段(API 直调 /v1 面可自行使用);演练场前端不提供该选项——`encoding_format=base64` 时上游字符串形态向量在演练场归一层按失败 502 收敛(不做转码,归一只接受 float 数组)。

```json
{ "model": "text-embedding-v4",
  "usage": { "promptTokens": 12, "totalTokens": 12 },
  "items": [ { "index": 0, "dimensions": 1024, "vector": [0.1, ...] } ] }
```

- **完整向量回传**:相似度矩阵由前端本地计算(§4.3);输入限制(≤10 条 × 8KB)已兜住响应体积,响应读取上限 8MB 防带外。
- 无产物落盘:向量是纯 JSON 结果随响应呈现,不进 §3.8 暂存(暂存范围仍是「无法持续获取」的媒体产物)。

### 3.10 POST /rerank —— 同步重排(v1.1)

请求体:

```json
{
  "apiKeyId": "key_...", "modelId": "gte-rerank-v2",
  "query": "查询语句",
```

## 4. 前端契约

**六页统一交互契约(v1.4)**:每页各自选 Key,六页互不影响;交互顺序固定**先选 Key 后选模型**——未选 Key 时无模型下拉、不请求模型列表;选定后加载该 Key 模型列表(`GET /key-models`,§3.2)并**只展示本页能力域(kind)的模型,不展示全部**;切换 Key 时模型选择重置并按新 Key 重新拉取。

### 4.1 对话试玩页(/playground/chat)

- 左栏(表单):Key 下拉(必选,本人 active Key,复用控制台 api-keys 列表数据源)→ 模型下拉(必选,联动该 Key 的 chat 模型,§3.2 按 kind 过滤)→ System 提示词(可选 textarea)→ 温度滑杆(0~2,默认 0.7)→ 最大生成长度(可选数字)→ 流式输出开关(默认开,唯一值)→ 高级参数折叠(top_p / 频率惩罚 / 存在惩罚)→ 清空对话按钮(红字,二次确认)。

## 7. 风险与边界

- 跨协议桥(chat→messages / chat→gemini)承载 Claude/Gemini 试玩:桥接为既有生产链路,行为以 `/v1` 现状为准,演练场不修桥。
- **v1.4 真实链路风险**:演练场消耗真实 Key 额度并进入限流、熔断与计费面——「测试即真实用量」是改版预期语义而非损耗;演示应使用额度可控的 Key,避免与生产消费共用同一 Key 造成额度挤占;演练场高频试玩会真实触发用户级限流与认证前熔断,属预期行为。
- Key 生命周期交互:创建任务/发起轮询后 Key 被删除或停用——在途图像任务按 failed 收敛(§3.4.2),视频轮询/取流按真实 /v1 鉴权语义失败透出,不做演练场侧豁免或兜底派发。
- 大上下文滥用:messages 总量上限 200 条 / 单条 64KB + kernel body limit 兜底。
- 退役批已执行:T85 编排改造先留档提交(`9dada7010`)后随 internal/chat 拆除,历史可溯。
- **v1.2 图像工作台**:
  - multipart 计量扫描层 fields 上限 16 / files 上限 5 / parts 上限 24(`gatewaybody/multipart.go`)——扫描层仅做计量字段提取,请求体直通上游不改写;执行器构造 edits multipart 恒 fields 在前、image parts 在后,10 张参考图派发不受扫描限额影响(已核);
  - size 映射按白名单模型支持集精确映射,超出支持集取最近档,不臆测上游能力;上游拒绝 → 任务 failed 透出上游原文,不静默降级;
  - 目录无价模型计 `costUsd=null` 不虚构金额(v1.3 起 UI 不展示扣费);usage 解析宽容(上游无 usage 字段时全 0),不因此判失败;
  - 进程内队列在网关重启时丢失——`queued` 行启动恢复重入队,`running` 行置 failed;异步语义不承诺重启后正在执行中的任务成功;
