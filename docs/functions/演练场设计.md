# 演练场设计

> 版本:v1.0(2026-10-31)。状态:契约定稿,实施中。
> 定位:演练场是模型能力试玩台——测「某个 AI 账户的某个模型好不好用」,不是产品级 AI 助手。
> 用户裁决(2026-10-31):AI 对话(会话式 + 工具模型绑定)整体下线,由演练场替代;媒体生成(图/视频/语音)撤出 AI 对话,改为演练场独立演示页;本功能是测试台,不做深。

## 1. 目标与非目标

### 1.1 目标

1. 新建一级菜单「演练场」,含四个子页:对话试玩、图片生成、视频生成、语音合成。
2. 对话试玩为**一次性**对话:消息只存在于浏览器内存,刷新即空,无会话落库、无历史列表、无断线重连续传。
3. 先选账户、再选模型(两级联动下拉),左侧参数面板 + 右侧消息区,对标门户参考站 Playground 形态。
4. 媒体三页为账户 × 模型直连演示,复用既有媒体执行器,零新增存储面。
5. 对话试玩仅走 `chat_completions` 协议入口(用户裁决「只支持 chat 协议其他都不支持」);Claude/Gemini 等经网关既有跨协议转换桥出站,测的就是 `/v1` 用户实际拿到的路径。
6. 模型原生能力默认打开、不靠外部代偿:不实现「工具模型绑定」;目录矩阵声明的能力由模型自身承担。
7. 提供一个后端执行的函数工具 `fetch_url`(抓取链接信息),让无原生搜索的模型也能取到网页资料;模型目录声明 `function_calling` 时默认注入,无开关。

### 1.2 非目标

1. 不做会话/消息/资产持久化(零新表;对话与参数不落库)。
2. 不做工具模型绑定、候选解析、用户偏好、回写(连同旧 /my-chat 面整体退役,见 §8)。
3. 不做 hosted 工具注入:目录矩阵 `chat_completions` 协议下当前无任何模型声明 hosted 工具(`web_search` 等仅存在于 responses 协议,而对话试玩只走 chat 入口);若未来出现 chat 协议 hosted 声明,按「默认打开」原则另行小批接入。
4. 不做 responses / generate_content / messages 协议入口;responses 独占模型(gpt-6.1-terra、gpt-5.5-pro 系等无 chat 等价物的旗舰)不进模型下拉。
5. 不做用量计费记录(固定派发走内部身份通道,`SuppressUsage`,与既有 chat 工具子调用同口径;上游账户侧照常产生真实消耗)。
6. 不做断线续传、多标签页同步、导出。

## 2. 信息架构

```
演练场(menuGroup: playground)
├─ /playground/chat    对话试玩
├─ /playground/images  图片生成
├─ /playground/videos  视频生成
└─ /playground/speech  语音合成
```

- 四条路由 `meta.viewScope: 'self'`、`meta.menuGroup: 'playground'`、`meta.menuGroupTitle: '演练场'`、`keepAlive: true`(页内内存态在导航间保留)、`heavy: false`。
- 原 `/my-chat` 路由、菜单项、页面整体删除(§8);「对话账户」等账户管理菜单不变。
- 登录用户默认入口不变(仍为 `/my-accounts`)。

## 3. 后端契约

### 3.1 挂载与鉴权

- 新包 `backend-go/projects/gateway/internal/playground`,经 `cmd/juhe-ai-gateway` 组合根挂载:`GET/POST /__aisys__/api/playground/...`(kernel Register,与 my-chat 同级,自动获得 kernel 的 body limit / IP rate limit / no-store 包裹)。
- 鉴权:每条路由套 `authDeps.RequireSession(true)`(与 chat 面同款);数据范围沿用 `ChatBindScope` 口径——admin/super_admin 看全量号池,其余用户看自有 + 被授权账户。
- 派发:固定派发到所选账户(复用 `chatGatewayExecutor` 的 `WithChatDispatchAccount` 调度覆盖端口 + 内部身份注入,pinned 候选窗口、无跨分组回退)。playground 定义自己的 Dispatch 端口类型,cmd 层提供适配器包装既有执行器;**不修改 internal/chat**(该包随 §8 整体退役)。

### 3.2 GET /accounts —— 账户与模型目录(单请求,四页共用)

响应:

```json
{ "accounts": [ {
    "accountId": "acc_...", "accountName": "神影-克隆", "providerCode": "gpt",
    "models": [
      { "modelId": "gpt-5.4", "kind": "chat",   "functionCalling": true },
      { "modelId": "gpt-image-2", "kind": "image" },
      { "modelId": "grok-imagine-video-1.5", "kind": "video" },
      { "modelId": "speech-2.8-hd", "kind": "audio" }
    ] } ] }
```

模型分类口径(按目录行 `supportedAPIProtocols`,经 chat 面读取链含 custom 继承;四类统一「目录声明 × 账户实际可派发」复核——2026-10-31 E2E 裁决收口:纯目录 chat 分类会让视频账户列出不可能跑通的 chat 模型,违背「跑不通的组合不进候选」原则):

- `chat`:协议含 `chat_completions`、`messages` 或 `generate_content` 之一 × 账户连接面含 chat lane 端点模式(`chat_json`/`chat_sse`,/v1/chat/completions 派发路由依据)× 账户模型清单(含映射)可路由;`functionCalling` = 任一协议行声明 `function_calling`。
- `image`:既有生图家族白名单(`gpt-image-2` / grok-imagine 系 × 账户可路由,与旧 chat 生图候选同口径)。
- `video`:`chatMediaProviderAllowed` 供应商 × 目录声明 `video` 协议 × 账户可路由(`video_create` 端点模式)。
- `audio`:目录声明 `audio_speech` 协议 × 账户可路由。

账户仅列 `active` 且启用、当前用户可见者;无运行时快照的账户一并剔除(固定派发不可达,与 chat 面 convergeChatAccountScope 空视图同口径);单户查询失败时跳过该户(列表展示面的部分结果边界,非业务写入)。不可派发对应协议的模型不列。前端在内存缓存本响应(会话内一次)。

**成功载荷信封**:全部 JSON 成功响应走仓内统一 `{"data": <payload>}` 信封(kernel `WriteOK`/chat `okEnvelope` 同款;下文示例仅示 payload,省略信封);错误载荷为**扁平** `{"message","code"}`(与 chat 面 `messageCodePayload` 同款,非嵌套)。SSE 帧与二进制端点(视频 content / 语音音频)不包信封。

### 3.3 POST /chat/stream —— 一次性对话(SSE)

请求体(全量上下文由客户端携带,服务端零状态):

```json
{
  "accountId": "acc_...", "modelId": "gpt-5.4",
  "messages": [ { "role": "user" | "assistant", "content": "..." } ],
  "system": "可选 system 提示词",
  "temperature": 0.7, "maxTokens": null, "stream": true,
  "topP": 1, "frequencyPenalty": 0, "presencePenalty": 0
}
```

- 校验:`accountId`/`modelId` 必填且在 §3.2 候选内(400 `playground_model_not_available`;账户不存在或不在当前用户范围 404 `playground_account_not_found`);`messages` 1~200 条、单条 ≤64KB、**role 仅 user|assistant**(工具上下文由服务端循环内部持有,客户端不接受 tool 消息);`stream` 仅支持 `true`(false 返回 400)。
- 出站:固定派发 `POST /v1/chat/completions`(SSE);请求体由服务端构造(system 进首条 system 消息;`function_calling` 模型注入 `fetch_url` 工具定义)。
- 工具循环:`fetch_url` 由后端执行,最多 3 轮工具轮;每轮把工具结果以 `role:"tool"` 消息追加后重新派发。第 3 轮后不再注入工具(强制收尾)。
- `fetch_url` 契约:参数 `{ "url": "<http(s) URL>" }`;执行 = GET 该 URL,20s 超时,下载上限 512KB,剥 HTML 标签取正文文本(上限 50KB);SSRF 防护——仅 http/https、解析后拒绝私网/环回/链路本地/组播地址。失败不产生 HTTP 错误,把「抓取失败:<原因>」作为工具结果回喂模型。

SSE 事件(归一协议,`data: <json>\n\n` 帧,与上游 chat chunk 解耦;帧间空闲超 5s 写 `: ping` 注释心跳防代理断流,仅在帧头已提交后发出):

| type | 载荷 | 说明 |
| --- | --- | --- |
| `round` | `{round}` | 一轮上游派发开始 |
| `delta` | `{text}` | 助手正文增量 |
| `tool_start` | `{callId, name, args}` | 模型发起 fetch_url(args 为模型参数 JSON **字符串**,与上游 tool_calls 原文同形) |
| `tool_end` | `{callId, name, ok, summary}` | 后端执行完成(summary 为正文首行摘要) |
| `usage` | `{promptTokens, completionTokens, totalTokens}` | 上游末 chunk usage(缺省则无此事件) |
| `done` | `{rounds}` | 正常收尾 |
| `error` | `{code, message}` | 失败收尾(此前已发 delta 的照常已透出) |

错误码:`playground_invalid_request` 400、`playground_account_not_found` 404、`playground_model_not_available` 400、`playground_dispatch_failed` 502(上游失败,message 带上游状态码摘要)。

### 3.4 POST /images —— 同步生图

请求:`{ accountId, modelId, prompt, size?, inputImageBase64?(图生图,走 /v1/images/edits) }`。复用 `GenerateChatImage`(固定派发 `/v1/images/generations|edits`)。单次产物 1 张。**单次恒 1 张,无 n 参数**（2026-10-31 用户裁决:张数功能移除——上游 images 接口对 n 参数恒回 1 张,多张由用户自行多次生成;曾实现的按张数并发分次与前端张数控件同批拆除）。

响应:`{ images: [ { id, url } ], model }` ——**产物落服务端暂存(§3.8),不再内联 base64**;前端 `<img src=url>` 展示、下载走 url。

### 3.5 POST /videos + 轮询 —— 异步视频

- `POST /videos`:请求 `{ accountId, modelId, prompt, size?, seconds?, inputImageBase64?(首帧) }` → 复用 `CreateChatVideo`(`POST /v1/videos`)→ 响应 `{ jobId }`;任务引用随暂存区记录(§3.8,视频产物本体不落盘——上游内容链接有效期 24h,凭 jobId 可持续获取)。
- `GET /videos/{jobId}?accountId=`:复用 `PollChatMediaTask` 代理上游轮询 → 归一 `{ status: "queued"|"running"|"completed"|"failed"|"cancelled", progress?, error?: {code, message} }`(未知上游状态按 failed 收敛并携带原文;`error` 为对象形态)。jobId 由前端持有,服务端不落库;`jobId` 须匹配 `^[A-Za-z0-9._-]{1,512}$`(否则 400);网关重启后凭前端持有的 jobId 仍可轮询。
- `GET /videos/{jobId}/content?accountId=`:复用 `DownloadChatMediaContent` 流式代理视频字节(`Content-Type` 透传,`Content-Disposition: inline`)。

### 3.6 POST /speech —— 同步语音

请求:`{ accountId, modelId, input(≤2000 字), voice, speed?, format? }` → 复用 `GenerateChatAudio`(`POST /v1/audio/speech`)→ 音频落暂存(§3.8),响应 `{ id, url, mimeType }`;前端 `<audio src=url>` 播放、下载走 url。账户不存在或不在当前用户范围统一 404 `playground_account_not_found`(images/videos/speech 三端点同口径);无 audio 模型/端点模式时 400。

### 3.8 产物暂存(2026-10-31 用户裁决:平台帮用户暂存,但测试台不留存)

**范围**:仅「无法持续获取」的产物——图片(上游临时 URL 断链即失)与语音(字节流直接返回);视频产物本体不落盘(上游内容链接有效期 24h,凭 jobId 可持续获取),仅任务引用随暂存。

**形态**:`JUHE_AI_DATA_DIR/playground-artifacts/{systemAccountId}/` 目录约定,零新表、零新 env(数据根既有派生):

- 文件名 `{unixNano}-{随机 token}.{ext}`,id 即文件名去扩展;写入时同 kind **覆盖式替换**——用户重新生成即删除该用户旧产物(图片一批 ≤4 张算一次、语音一条、视频任务引用一条);
- **24h 自动过期**:懒清理挂全部产物读写点(POST images/speech/videos、GET artifacts、GET content),扫暂存根删除 mtime >24h 的文件与空用户目录;测试台不留存,过期即删;
- 归属与安全:`GET /playground/artifacts` 返回当前登录用户暂存清单(经 RequireSession);`GET /playground/artifacts/{id}/content` 按用户目录定位文件(id 不含路径分隔符,白名单字符),跨用户不可达;视频 content 走既有 jobId 代理(§3.5)。

**恢复端点**:`GET /playground/artifacts` → `{ images: [{id,url,createdAt}], speech: {id,url,mimeType,createdAt} | null, video: {jobId,accountId,modelId,status,createdAt} | null }`——前端刷新后凭此恢复三页展示与视频轮询。`createdAt` 为 **unix 秒**(int64);`url` 为**相对路径** `/playground/artifacts/{id}/content`(前端经 axios baseURL 拼 `/__aisys__/api` 前缀;同源请求自动携带会话 Cookie)。

**边界**:暂存是展示缓存不是资产库——后端不保证 beyond 24h,用户留档靠下载;gateway 重启不丢(文件在磁盘);存储总量 = 每用户最近一批图(≤4×16MiB)+ 一条音频,受覆盖式替换自然封顶。

### 3.7 用量与审计

- 固定派发内部身份通道 `SuppressUsage`(不落 usage_records);审计照常(fail 面)。设计权衡:演练场是测试台,不产生平台计费面;上游账户真实消耗不可免。
- `x-juhe-ai-purpose: playground_<scene>` 请求标记(chat=playground_chat),便于审计区分。

## 4. 前端契约

### 4.1 对话试玩页(/playground/chat)

- 左栏(表单):账户下拉(必选,active 账户)→ 模型下拉(必选,联动该账户 chat 模型,显示 `functionCalling` 徽标「工具:fetch_url」)→ System 提示词(可选 textarea)→ 温度滑杆(0~2,默认 0.7)→ 最大生成长度(可选数字)→ 流式输出开关(默认开,唯一值)→ 高级参数折叠(top_p / 频率惩罚 / 存在惩罚)→ 清空对话按钮(红字,二次确认)。
- 右栏:空态文案「选择账户与模型,发送第一条消息开始试玩」;消息气泡(user 右 / assistant 左,markdown 渲染);`fetch_url` 工具块(时间线:发起 → 摘要);底部用量行(tokens / 轮次);输入框 Ctrl+Enter 发送;流式打字机渲染。
- 无:会话列表、历史、工具绑定、图/视频/语音入口、上下文压缩、停止按钮(短轮次工具循环不需要;上游失败直接 error 帧)。

### 4.2 媒体三页

- 图片生成:账户 → 模型(该账户 image 模型)→ 提示词 → 可选尺寸/张数/参考图(base64 上传)→ 生成按钮 → 结果网格(base64 直显)+ 下载按钮。同步等待,loading 态。
- 视频生成:账户 → 模型 → 提示词 → 可选参数 → 创建 → 轮询进度(3s 间隔)→ 完成后 `<video>` 内联播放;失败显示归一错误。页面卸载停止轮询。
- 语音合成:账户 → 模型 → 文本(2000 字计数)→ 音色(账户可用的固定输入,自由文本)→ 合成 → `<audio>` 播放 + 下载。
- 四页共用 `api.playground.accounts()` 结果(内存缓存);账户或模型变更不影响其他页。

### 4.3 API 域与类型

- `frontend/src/api/domains/playground.ts`(`playgroundApi`:accounts / chatStream(SSE fetch+ReadableStream,复用 chat.ts 的 SSE 分帧惯例) / images / videosCreate / videosPoll / videosContent / speech),注册进 `client.ts`。
- `frontend/src/types/domain/playground.ts`:`PlaygroundAccount`、`PlaygroundModelOption`、`PlaygroundChatMessage`、`PlaygroundStreamEvent` 等。
- 路由与菜单按 §2;图标用既有 antd 图标(如 ExperimentOutlined)。

## 7. 风险与边界

- 跨协议桥(chat→messages / chat→gemini)承载 Claude/Gemini 试玩:桥接为既有生产链路,行为以 `/v1` 现状为准,演练场不修桥。
- `fetch_url` 抓取的是公网任意 URL,存在内容注入面(网页文本进模型上下文);工具结果以 tool role 呈现并标注来源 URL,由模型自身判断,不做人审。
- 大上下文滥用:messages 总量上限 200 条 / 单条 64KB + kernel body limit 兜底。
- - 退役批已执行:T85 编排改造先留档提交(`9dada7010`)后随 internal/chat 拆除,历史可溯。
