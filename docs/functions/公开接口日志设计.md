# 公开接口日志设计

> 面向外部来源系统公开接口、日志管理、后端存储、前端页面和 AI 维护者。
> 本文定义 `/__aipublic__` 公开接口调用日志能力，用于追踪外部来源系统调用时间、速度、状态、请求数据、响应数据和错误摘要。公开接口日志不同于原始审计日志，不捕获网关上游链路，也不长期保留；保留期由系统设置 `publicApiLogRetentionDays` 控制，默认 30 天，合法范围 `1..365`。

## 文档目标

- 在“日志管理”中新增 `公开接口日志` 管理菜单。
- 记录每次公开接口调用的来源系统、接口、调用时间、耗时、状态、客户端 IP、请求摘要、响应摘要和 traceId。
- 公开接口日志保留期由系统设置控制，默认 30 天，范围 `1..365`，并由后台数据保留清理任务执行。
- 固定请求 / 响应正文的日志边界：按原文保存、有上限、有截断标记，不伪装成完整原文。
- 复用审计日志的排障展示思路，但不复用原始审计日志的全链路 payload blob、成功采样和上游尝试模型。

## 模块定位

公开接口日志回答这些问题：

- 哪个外部来源系统、哪个 token 摘要调用了哪个公开接口？
- 请求发生在什么时候，耗时多少，最终 HTTP 状态码是什么？
- 请求 query、有限请求体、有限响应体和错误摘要是什么？
- 公开接口是 mock 测试 token 调用，还是正式来源 token 调用？
- 调用是否命中鉴权失败、scope 不足、限频、参数错误或业务处理异常？

公开接口日志不回答这些问题：

- OpenAI 网关请求命中了哪个上游账号、代理和上游响应内容。
- 使用记录中的 token、成本、模型统计和授权额度。
- 原始审计日志中的客户端请求、上游请求、上游响应和最终返回完整链路。

## 记录范围

只记录 `/__aipublic__` 前缀下的公开接口请求：

- `GET /__aipublic__/api-key/list`
- `GET /__aipublic__/route-strategy/list`
- `GET /__aipublic__/group/list`
- `GET /__aipublic__/account/list`
- `POST /__aipublic__/api-key/add|update|del`
- `POST /__aipublic__/route-strategy/add|update|del`
- `POST /__aipublic__/group/add|update|del`
- `POST /__aipublic__/account/add|update|del`
- 公开前缀下的 404、鉴权失败、限频和 JSON body 解析失败也记录。

不记录：

- `/__aisys__/api/*` 后台管理接口。
- OpenAI 兼容网关 `/v1/*` 和根路径网关请求。
- 静态资源、健康检查和前端路由。

## 数据保存边界

公开接口日志是轻量排障日志，保存结构化元数据和有限快照。

必须保存：

- `trace_id`
- `source_ref_id`、`source_name`
- `token_id`、`token_name`、`token_prefix`
- `is_test_token`
- `method`
- `path`
- `query_string`
- `client_ip`
- `user_agent`
- `status_code`
- `success`
- `duration_ms`
- `request_size_bytes`
- `response_size_bytes`
- `request_capture_status`
- `response_capture_status`
- `request_data_json`
- `response_data_json`
- `error_code`
- `error_message`
- `started_at`
- `ended_at`
- `created_at`

正文快照规则：

- 公开接口日志不保存 `Authorization` header、来源 token 或 Cookie 明文；来源 token 只保存 `token_id`、`token_name` 和 `token_prefix`。请求 header 只保留安全摘要，例如 `contentType` / `contentLength`。
- query、请求 body 和响应 body 按现行快照容量规则保存原文摘要；`api-key/add` 响应中的一次性本地 API Key 明文、`account/add|update` 请求体中的上游 `apiKey` 都可能进入详情快照。调用方不要在公开接口传递非必要敏感字段，详情页仅管理员可见。
- 请求和响应快照只保存 JSON 摘要，单侧快照默认最多 `32KB`；超限后截断并写入 `capture_status='truncated'`。
- 完整请求或响应为空时写 `capture_status='empty'`。
- 请求体已被网关拒绝或序列化失败时写 `capture_status='dropped'`，不能把缺失内容伪装成完整原文。

## 与审计日志的边界

| 能力 | 公开接口日志 | 原始审计日志 |
| --- | --- | --- |
| 入口 | `/__aipublic__` 外部来源接口 | OpenAI 网关和账号测试等排障链路 |
| 主要目的 | 外部来源接口调用排障和对接追踪 | 客户端、网关、上游完整链路复盘 |
| 保存内容 | 元数据、来源信息、有限请求 / 响应快照 | 请求、上游尝试、上游响应、最终返回 payload |
| 正文策略 | 原文、截断、有状态标记 | headers、queryString 和 body 原文，按保全策略压缩去重 |
| 写入粒度 | 每个公开接口请求 1 条 | 每个进入审计的客户端请求 1 条，挂多 payload |
| 保留期 | 默认 30 天，系统设置范围 `1..365` | 成功样本 7 天，失败 / 异常默认 30 天 |
| 页面权限 | 管理员 | 管理员 |

公开接口日志不能替代原始审计日志，也不能把公开接口请求体写入原始审计日志。

## 存储设计

公开接口日志写入数据集目录库，表名：

```text
public_api_logs
- id TEXT PRIMARY KEY
- trace_id TEXT
- source_ref_id TEXT
- source_name TEXT
- token_id TEXT
- token_name TEXT
- token_prefix TEXT
- is_test_token INTEGER NOT NULL DEFAULT 0
- method TEXT NOT NULL
- path TEXT NOT NULL
- query_string TEXT
- client_ip TEXT
- user_agent TEXT
- status_code INTEGER
- success INTEGER NOT NULL DEFAULT 0
- duration_ms INTEGER
- request_size_bytes INTEGER NOT NULL DEFAULT 0
- response_size_bytes INTEGER NOT NULL DEFAULT 0
- request_capture_status TEXT NOT NULL DEFAULT 'empty'
- response_capture_status TEXT NOT NULL DEFAULT 'empty'
- request_data_json TEXT NOT NULL DEFAULT '{}'
- response_data_json TEXT NOT NULL DEFAULT '{}'
- error_code TEXT
- error_message TEXT
- started_at TEXT NOT NULL
- ended_at TEXT NOT NULL
- created_at TEXT NOT NULL
```

索引：

- `public_api_logs(created_at, id)`：默认短窗口分页和保留清理。
- `public_api_logs(source_ref_id, created_at, id)`：按来源系统 + 日期窗口筛选，是公开接口日志的主查询入口。
- `public_api_logs(source_ref_id, trace_id, created_at, id)`：来源系统范围内 trace 定位的例外索引。

不默认建立全局 `path/status_code/success/client_ip/trace_id` 索引。公开接口日志页面必须以来源系统和日期窗口为前提；path、状态码、成功 / 失败和客户端 IP 仅在当前窗口内过滤，容量异常时走离线诊断。

## 后端 API

只提供管理员接口：

- `GET /__aisys__/api/public-api-logs`：分页查询公开接口日志。
- `GET /__aisys__/api/public-api-logs/:id`：查看单条详情和请求 / 响应快照。

查询条件：

- `traceId`：右侧前缀匹配。
- `sourceRefId`：来源系统精确匹配。
- `path`：接口路径精确匹配。
- `statusCode`：HTTP 状态码精确匹配。
- `result`：`success`、`failed`、`all`。
- `clientIp`：右侧前缀匹配。
- `startAt` / `endAt`：按 `created_at` 范围筛选。
- `page` / `pageSize`：页码分页，`pageSize` 最大 100，列表窗口最多 1001 行。

列表接口只返回元数据和快照大小，不返回大段请求 / 响应内容。详情接口返回按容量规则保存的原文 `requestData` 和 `responseData`。

## 前端页面

菜单：

- 分组：`日志管理`
- 菜单名：`公开接口日志`
- 路由：`/public-api-logs`
- 权限：仅 `super_admin` / `admin`

列表展示：

- 调用时间
- 来源系统
- 接口
- 请求方式
- 状态
- 状态码
- 耗时
- 客户端 IP
- traceId

token 摘要只在详情抽屉中展示，不在列表的来源系统列混排。

详情抽屉展示：

- 基本信息：来源系统、token 摘要、是否测试 token、接口、状态码、耗时、客户端 IP、User-Agent、traceId。
- 请求数据：query、body 摘要、捕获状态、原始大小。
- 响应数据：响应摘要、捕获状态、原始大小。
- 错误信息：错误码、错误消息。

页面文案保持中文；请求 / 响应详情使用只读代码查看器，不在列表中直接暴露大段内容。

## 保留与清理

- 公开接口日志按系统设置 `publicApiLogRetentionDays` 保留，默认 `30` 天，合法范围 `1..365`。
- 清理任务接入 `data-retention-cleanup` 后台任务。
- 每轮按 `created_at ASC, id ASC` 分批删除，避免一次性大事务。
- 清理失败只写普通运行日志，不影响公开接口请求。
- 删除公开接口日志不影响外部来源系统授权、操作日志、使用记录或统计缓存。

## 验证清单

- 无 `Authorization` 调用公开接口返回 401，并写入公开接口日志。
- token 错误返回 401，并写入公开接口日志；`Authorization` header 和来源 token 明文不进入日志快照。
- scope 不足返回 403，并记录来源系统和接口路径。
- 正式 token 调用成功返回业务数据，并记录 `success=true`、状态码和耗时。
- 测试 token 调用成功时记录 `isTestToken=true`。
- `account/add` 请求体中的 `apiKey`、`api-key/add` 响应体中的 `key` 在详情中按原文显示。
- 列表筛选按 traceId、来源、接口、状态码、成功 / 失败和客户端 IP 生效。
- 保留清理按当前 `publicApiLogRetentionDays` 删除过期记录，保留期内记录保留。
