# 公开接口日志设计

> 面向外部来源系统公开接口、日志管理、后端存储、前端页面和 AI 维护者。
> 本文定义 `/__aipublic__` 公开接口调用日志能力，用于追踪外部来源系统调用时间、速度、状态、请求数据、响应数据和错误摘要。公开接口日志不同于原始审计日志，不捕获网关上游链路，也不长期保留；保留期由系统设置 `publicApiLogRetentionDays` 控制，默认 30 天，合法范围 `1..365`。

## 文档目标

- 在“日志管理”中新增 `公开接口日志` 管理菜单。
- 记录每次公开接口调用的来源系统、接口、调用时间、耗时、状态、客户端 IP、请求摘要、响应摘要和 traceId。
- 公开接口日志保留期由系统设置控制，默认 30 天，范围 `1..365`，并由后台数据保留清理任务执行。
- 固定请求 / 响应正文的日志边界：有限保存、有大小和结构预算、有截断标记；捕获范围内保留原始值，不做递归脱敏，也不伪装成完整原文。
- 复用审计日志的排障展示思路，但不复用原始审计日志的全链路 payload blob、成功采样和上游尝试模型。

## 模块定位

公开接口日志回答这些问题：

- 哪个外部来源系统、哪个 token 摘要调用了哪个公开接口？
- 请求发生在什么时候，耗时多少，最终 HTTP 状态码是什么？
- 请求 query、有限请求体、有限响应体和错误摘要是什么？
- 公开接口是 mock 测试 token 调用，还是正式来源 token 调用？
- 调用是否命中鉴权失败、scope 不足、限频、参数错误或业务处理异常？

公开接口日志不回答这些问题：

- OpenAI 网关请求命中了哪个上游账号、代理和上游响应内容。
- 使用记录中的 token、成本、模型统计和授权额度。
- 原始审计日志中的客户端请求、上游请求、上游响应和最终返回完整链路。

## 记录范围

只记录 `/__aipublic__` 前缀下的公开接口请求：

- `GET /__aipublic__/api-key/list`
- `GET /__aipublic__/route-strategy/list`
- `GET /__aipublic__/group/list`
- `GET /__aipublic__/account/list`
- `POST /__aipublic__/api-key/add|update|del`
- `POST /__aipublic__/route-strategy/add|update|del`
- `POST /__aipublic__/group/add|update|del`
- `POST /__aipublic__/account/add|update|del`
- 公开前缀下的 404、鉴权失败、限频和 JSON body 解析失败也记录。

不记录：

- `/__aisys__/api/*` 后台管理接口。
- OpenAI 兼容网关 `/v1/*` 和根路径网关请求。
- 静态资源、健康检查和前端路由。

## 数据保存边界

公开接口日志是轻量排障日志，保存结构化元数据和有限快照。

必须保存：

- `trace_id`
- `source_ref_id`、`source_name`
- `token_id`、`token_name`、`token_prefix`
- `is_test_token`
- `method`
- `path`
- `query_string`
- `client_ip`
- `user_agent`
- `status_code`
- `success`
- `duration_ms`
- `request_size_bytes`
- `response_size_bytes`
- `request_capture_status`
- `response_capture_status`
- `request_data_json`
- `response_data_json`
- `error_code`
- `error_message`
- `started_at`
- `ended_at`
- `created_at`

正文快照规则：

- 请求 header 快照只捕获 `contentType` / `contentLength`，不捕获 `Authorization`、`Cookie` 或作为 Bearer 凭据传入的来源 token；来源身份只保存 `token_id`、`token_name` 和 `token_prefix` 等元数据。
- query、请求 body 和响应 body 在捕获范围内保留原始值，不按字段名、header 名、URL 查询参数或字符串形态递归脱敏，不写 `[redacted]`。因此本地 API Key、上游 `apiKey`、普通 `token` / `secret` 字段、64 位 hash 或带 userinfo 的 URL 一旦进入正文捕获范围，也会保留原值；详情页仅管理员可见。
- 请求和响应快照只保存有界 JSON 摘要，单侧最多 `32KB`；最大深度 `8`，每个对象 / 数组最多 `200` 个条目，单字符串预览最多 `4096` 字节。超限后截断并写入 `capture_status='truncated'`。
- 完整请求或响应为空时写 `capture_status='empty'`。
- 请求体已被网关拒绝或序列化失败时写 `capture_status='dropped'`，不能把缺失内容伪装成完整原文。

## 与审计日志的边界

| 能力 | 公开接口日志 | 原始审计日志 |
| --- | --- | --- |
| 入口 | `/__aipublic__` 外部来源接口 | OpenAI 网关和账号测试等排障链路 |
| 主要目的 | 外部来源接口调用排障和对接追踪 | 客户端、网关、上游完整链路复盘 |
| 保存内容 | 元数据、来源信息、有限请求 / 响应快照 | 请求、上游尝试、上游响应、最终返回 payload |
| 正文策略 | 捕获范围内原值、有大小 / 深度 / 条目 / 字符串预算、截断、有状态标记 | headers、queryString 和 body 原文，按保全策略压缩去重 |
| 写入粒度 | 每个公开接口请求 1 条 | 每个进入审计的客户端请求 1 条，挂多 payload |
| 保留期 | 默认 30 天，系统设置范围 `1..365` | 成功样本 7 天，失败 / 异常默认 30 天 |
| 页面权限 | 管理员 | 管理员 |

公开接口日志不能替代原始审计日志，也不能把公开接口请求体写入原始审计日志。

## 存储设计

公开接口日志逻辑表名为 `public_api_logs`，Go fresh Goose schema 位于 `juhe_dataset.public_api_logs`。核心字段仍包括来源 / token 摘要、请求元数据、成功状态、耗时、请求 / 响应大小、捕获状态、`request_data_json`、`response_data_json` 和三个时间字段。

Node PostgreSQL 旧结构由 SQLite DDL 转换生成：`is_test_token` / `success` 是 `integer`，`duration_ms` 是 `integer`，`started_at` / `ended_at` / `created_at` 是 ISO 文本 `text`。Go fresh Goose `000003_w1b_public_api_foundation.sql` 使用 PostgreSQL 原生 `boolean`、`bigint` 和 `timestamptz`；两种物理结构不兼容，不能把 Node 旧表直接交给 Go writer / reader。

生产切流前必须在停写或受控维护窗口离线完成结构与数据同步，并明确同一张 `public_api_logs` 表的单一写入 owner；迁移期不得让 Node / Go 双写同一 owner，也不得在运行时代码中加入 integer/boolean、text/timestamptz 双读、自动转换或兼容分支。

本批没有新增索引。Go 管理读 integration 的 `EXPLAIN` 只验证 fresh Goose 已有的 `idx_public_api_logs_created` 和 `idx_public_api_logs_source_created` 常用路径；`traceId`、`clientIp` 及其他筛选只有功能回归，没有本批 `EXPLAIN` 索引证据，不能据此声称已建立或已验证对应索引。

## 后端 API

只提供管理员接口：

- `GET /__aisys__/api/public-api-logs`：分页查询公开接口日志。
- `GET /__aisys__/api/public-api-logs/{id}`：查看单条详情和请求 / 响应快照。

查询条件：

- `traceId`：右侧前缀匹配。
- `sourceRefId`：来源系统精确匹配。
- `path`：接口路径精确匹配。
- `statusCode`：HTTP 状态码精确匹配。
- `result`：`success`、`failed`、`all`。
- `clientIp`：右侧前缀匹配。
- `startAt` / `endAt`：按 `created_at` 范围筛选。
- `page` / `pageSize`：页码分页，`pageSize` 最大 100，列表窗口最多 1001 行。

列表接口只返回元数据和快照大小，SQL 不选择 `request_data_json` / `response_data_json`。详情接口按 `{id}` 单行读取并返回按容量规则保存的原文 `requestData` 和 `responseData`；不存在时返回 `404 { message: "公开接口日志不存在" }`。

W6 已将上述两条管理读接口加入 Go `JUHE_AI_MANAGEMENT_API_ENABLED=true` 的 opt-in 路由。语义保持管理员权限、只读 session 不 touch、`Cache-Control: no-store`、Node 当前分页 / 筛选归一化和 progressive `total/hasMore`；迁移不改变公开日志写入 owner，也不代表生产切流或 Node 路由已删除。

## 前端页面

菜单：

- 分组：`日志管理`
- 菜单名：`公开接口日志`
- 路由：`/public-api-logs`
- 权限：仅 `super_admin` / `admin`

列表展示：

- 调用时间
- 来源系统
- 接口
- 请求方式
- 状态
- 状态码
- 耗时
- 客户端 IP
- traceId

token 摘要只在详情抽屉中展示，不在列表的来源系统列混排。

详情抽屉展示：

- 基本信息：来源系统、token 摘要、是否测试 token、接口、状态码、耗时、客户端 IP、User-Agent、traceId。
- 请求数据：query、body 摘要、捕获状态、原始大小。
- 响应数据：响应摘要、捕获状态、原始大小。
- 错误信息：错误码、错误消息。

页面文案保持中文；请求 / 响应详情使用只读代码查看器，不在列表中直接暴露大段内容。

## 保留与清理

- 公开接口日志按系统设置 `publicApiLogRetentionDays` 保留，默认 `30` 天，合法范围 `1..365`。
- 清理任务接入 `data-retention-cleanup` 后台任务。
- 每轮按 `created_at ASC, id ASC` 分批删除，避免一次性大事务。
- 清理失败只写普通运行日志，不影响公开接口请求。
- 删除公开接口日志不影响外部来源系统授权、操作日志、使用记录或统计缓存。

## 验证清单

- 无 `Authorization` 调用公开接口返回 401，并写入公开接口日志。
- token 错误返回 401，并写入公开接口日志；`Authorization` header 和来源 token 明文不进入日志快照。
- scope 不足返回 403，并记录来源系统和接口路径。
- 正式 token 调用成功返回业务数据，并记录 `success=true`、状态码和耗时。
- 测试 token 调用成功时记录 `isTestToken=true`。
- query、`account/add|update` 请求体中的上游 `apiKey`、`api-key/add` 响应体中的本地 API Key `key`、普通 token / secret-like 字符串和带 userinfo 的 URL 在捕获预算内保留原值，详情中不出现 `[redacted]` 占位。
- `Authorization`、`Cookie` 和作为 Bearer 凭据传入的来源 token 不进入快照 headers；请求 headers 只包含 `contentType` / `contentLength`。
- 列表筛选按 traceId、来源、接口、状态码、成功 / 失败和客户端 IP 生效。
- 管理列表不读取或返回 payload，详情只按 ID 单行读取；匿名 401、普通用户 403、详情 404、`no-store` 和只读 session 不 touch 保持不变。
- 保留清理按当前 `publicApiLogRetentionDays` 删除过期记录，保留期内记录保留。
