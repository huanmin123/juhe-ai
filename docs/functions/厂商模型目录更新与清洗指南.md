# 厂商模型目录更新与清洗指南

> 面向 AI 和维护者。
> 本文记录各厂商模型目录的更新、核对、清洗和验证方法。不同厂商的官方来源、废弃规则和模型命名方式可能不同，后续新增厂商时必须单独补充厂商章节，不要把 OpenAI 的做法直接套用到其他厂商。
> 本文只管理代码内置的官方厂商模型目录。管理员全局模型、用户个人模型、自定义价格和账号模型映射见 [自定义模型与模型映射设计](自定义模型与模型映射设计.md)。

## 1. 目标

- 保证代码内置官方模型目录只展示当前真实存在、可用于对应厂商 API 的模型；`/v1/models` 的最终输出还会叠加调用方可见的全局自定义模型和个人自定义模型。`providerCode=openai` 是通用 OpenAI-compatible 聚合目录，只包含自身和显式纳入聚合的供应商模型；DeepSeek 这类独立供应商不进入 `openai` 聚合目录，具体供应商例如 `gpt`、`deepseek` 只维护自身目录。
- 清理官方已废弃、已关闭、仅历史兼容、仅旧快照、第三方快照误收录或官方不存在的模型。
- 保留成本估算需要的当前稳定别名和官方快照，避免旧模型被误估价。
- 新增智谱 GLM 等非 OpenAI 厂商时，必须单独记录官方模型页、价格页、接入端点、废弃规则和模型别名，不要复用 OpenAI 的清洗结论。
- 模型价格和 usage 统计口径的详细核对方法见 [模型价格与用量统计口径](模型价格与用量统计口径.md)。
- 记录每次清洗的来源、工具、口径和验证方式，让下一次更新可以快速复用。

## 2. 通用流程

1. 先定位当前内置模型来源。
   - 当前 OpenAI 目录在 `backend/src/modules/model-pricing/`。
   - 内置供应商模型列表由 `listProviderModelPricing()` 暴露；网关 `/v1/models` 的最终目录在内置模型基础上叠加全局 / 个人自定义模型。
   - 管理后台通用模型筛选由 `/providers/models/options` 暴露启用供应商的模型名称选项，前端只在该选项目录内做输入匹配，列表查询仍提交完整模型名。
   - 前端账号测试候选在 `frontend/src/views/accounts/accountOptions.ts`，测试弹窗优先从后端模型接口加载。

2. 收集厂商官方来源。
   - 优先使用厂商官方文档、官方模型列表、官方价格页和官方废弃说明。
   - 不把第三方价格仓库、博客、论坛或社区清单作为最终事实来源。
   - 如果厂商提供真实 API 的模型列表接口，可以在安全环境下作为二次核验，但不要在文档或日志中暴露真实 API Key。

3. 抽取本地模型 ID。
   - 使用 `rg` 查找模型定义，不手动凭印象整理。
   - 对模型 ID 去重、分组，并标出是否是稳定别名、日期快照、预览模型、专用能力模型或废弃模型。

4. 建立清理口径。
   - 官方模型页不存在：从展示目录移除。
   - 官方价格页没有可用单价：不要猜价；除非单模型页明确给出同口径价格，否则先不进入计价目录。
   - 官方废弃页列出 shutdown date：只有 shutdown date 已经到达或早于当前 UTC 日期时，才从展示目录移除并在成本估算中屏蔽；shutdown date 仍在未来的模型继续保留计价，并标记关闭日期。
- 仅历史快照、旧 preview、旧 realtime/audio/search 预览：从展示目录移除。
- 当前稳定别名和仍推荐使用的官方快照：可保留。
- 模糊匹配不能把不存在的模型映射到相近模型，例如不能把 `xxx-spark` 误映射到 `xxx`。
- 模型用途和接口协议必须分开记录：用途用于前端分类，例如对话 / 编码、图像、音频；接口协议用于展示模型支持的 API 形态，例如 `Chat Completions`、`Responses`、`Images API`。
- 本地价格数据里的 `mode` 只能作为计价或默认口径参考，不能当成模型唯一支持的接口协议；如果官方确认同一模型同时支持多个协议，应在接口返回里同时展示。
- 供应商模型接口里的 `releaseDate` 在页面展示为“发布时间”，表示模型大致对外可用或官方快照对应的发布时间，用于模型列表倒序排序；不要把它理解成价格数据更新日期。

5. 修改代码后做验证。
   - 验证模型列表数量和具体 ID。
   - 验证已废弃或不存在 ID 不再命中。
   - 跑相关 typecheck。
   - 如果后端类型检查失败，要区分是否为本次改动造成，并记录失败位置。

## 3. OpenAI 厂商

### 3.1 官方来源

OpenAI 模型目录清洗必须优先使用官方页面：

- 模型总览：[OpenAI Models](https://developers.openai.com/api/docs/models)
- 最新模型指南：[Using the latest model](https://developers.openai.com/api/docs/guides/latest-model.md)
- 价格目录：[OpenAI Pricing](https://developers.openai.com/api/docs/pricing)
- 废弃说明：[OpenAI Deprecations](https://developers.openai.com/api/docs/deprecations)
- 单模型页面：`https://developers.openai.com/api/docs/models/<model-id-or-family>`

如果 `openai-docs` 技能可用，先用 OpenAI developer docs MCP 检索和读取官方文档；如果当前会话没有 MCP 工具或无结果，再回退到官方域名网页检索。回退检索只使用 `developers.openai.com` 或 `platform.openai.com`。

### 3.2 本次清洗方法记录

本次清洗日期：`2026-05-08`。

本次采用的方法：

- 先读取 `openai-docs` 技能说明，确认 OpenAI 资料必须以官方文档为准。
- 尝试配置 OpenAI docs MCP：`codex mcp add openaiDeveloperDocs --url https://developers.openai.com/mcp`。
- 当前会话 MCP 工具未热刷新，因此回退到官方网页。
- 用 OpenAI developer docs MCP、`web` 和 PowerShell `Invoke-WebRequest` 访问官方模型页、价格页和废弃页。
- 用正则从官方页面提取模型 ID、单模型链接和废弃页中的关闭表。
- 用本地脚本逐个检查内置模型对应的官方单模型页面是否存在。
- 用本地脚本验证已关闭或不存在 ID 不再出现在内置展示清单，未来关闭但仍可用的 ID 仍能计价。

关键判断：

- `Models` 页面用于确认当前推荐和可见模型族。
- `Pricing` 页面用于确认仍有官方计价的模型和价格字段。
- `Deprecations` 页面用于确认 shutdown date 和替代模型；“已宣布废弃”不等于“现在不能用”，只有 shutdown date 到达后才视为不可访问。
- 单模型页标题为 `Page not found | OpenAI API` 时，视为官方模型页不存在。
- 有些旧模型不再推荐但仍有官方模型页、价格页和未来 shutdown date，例如 `gpt-5.2-codex`、`gpt-5-codex`、`gpt-4`、`gpt-3.5-turbo`；这些模型仍应进入计价目录，避免用户真实调用后无法记账。
- OpenAI 的 `Chat Completions` 和 `Responses` 是接口协议，不是模型用途分类；通用文本模型如果官方端点表同时支持 `/v1/chat/completions` 和 `/v1/responses`，供应商页应同时显示两个协议标签。Codex / Pro 等仅 Responses 口径的模型只显示 `Responses`。

### 3.3 常用命令

抽取本地内置模型：

```powershell
rg 'model: "' backend/src/modules/model-pricing
```

从 OpenAI 官方模型首页提取单模型页面链接：

```powershell
$content = (Invoke-WebRequest -Uri 'https://developers.openai.com/api/docs/models' -UseBasicParsing).Content
[regex]::Matches($content, '/api/docs/models/[^"''?#< ]+') |
  ForEach-Object { $_.Value } |
  Sort-Object -Unique
```

从 OpenAI 官方价格页提取可能出现的模型 ID：

```powershell
$content = (Invoke-WebRequest -Uri 'https://developers.openai.com/api/docs/pricing' -UseBasicParsing).Content
[regex]::Matches($content, 'gpt-[a-zA-Z0-9.\-]+|o[0-9][a-zA-Z0-9.\-]*') |
  ForEach-Object { $_.Value } |
  Sort-Object -Unique
```

从 OpenAI 官方废弃页提取废弃相关模型 ID：

```powershell
$content = (Invoke-WebRequest -Uri 'https://developers.openai.com/api/docs/deprecations' -UseBasicParsing).Content
[regex]::Matches($content, 'gpt-[a-zA-Z0-9.\-]+|o[0-9][a-zA-Z0-9.\-]*') |
  ForEach-Object { $_.Value } |
  Sort-Object -Unique
```

验证内置模型是否都有官方模型页：

```powershell
$ids = rg 'model: "' backend/src/modules/model-pricing |
  ForEach-Object {
    if ($_ -match 'model:\s*"([^"]+)"') { $Matches[1] }
  } |
  Sort-Object -Unique

$bad = @()
foreach ($id in $ids) {
  $slug = ($id -replace '-\d{4}-\d{2}-\d{2}$','')
  $content = (Invoke-WebRequest -Uri "https://developers.openai.com/api/docs/models/$slug" -UseBasicParsing).Content
  $title = [regex]::Match($content, '<title>(.*?)</title>').Groups[1].Value
  if ($title -match '^Page not found') {
    $bad += "$id -> $slug"
  }
}

if ($bad.Count) { $bad } else { 'All curated model docs pages resolved.' }
```

### 3.5 OpenAI 清理规则

- 保留官方当前模型页存在、价格页有单价、且 shutdown date 尚未到达的模型，包括不再推荐但仍可访问的旧模型。
- 可以保留官方当前日期快照，例如 `gpt-5.5-2026-04-23`；旧快照如果官方价格页仍有单价且 shutdown date 未到，也可保留用于计费。
- 不保留已经 shutdown 的模型、官方模型页不存在的模型、官方价格页没有单价且无法从单模型页确认同口径价格的模型。
- 不保留旧 realtime preview、旧 audio preview、旧 search preview 等已经 shutdown 或由 GA 模型替代的 preview 展示项。
- 不保留官方模型页不存在的 ID，例如 `gpt-5.3-codex-spark`。
- 不让不存在或已 shutdown 的模型进入 `findOpenAIModelPricing()` 的模糊匹配结果，避免旧 ID 被误计价。
- 更新账号测试默认模型时，优先选择当前稳定、低风险的官方模型；前端默认候选必须来自后端模型接口或与后端目录一致。

## 4. 智谱 GLM 厂商

### 4.1 官方来源

智谱 GLM 模型目录清洗必须优先使用官方来源：

- 通用 OpenAI 兼容入口：[OpenAI API 兼容](https://docs.bigmodel.cn/cn/guide/develop/openai/introduction)
- 通用 HTTP API：[HTTP API](https://docs.bigmodel.cn/cn/guide/develop/http/introduction)
- GLM Coding Plan 接入：[接入工具](https://docs.bigmodel.cn/cn/coding-plan/tool/others)
- GLM Coding Plan 套餐概览：[套餐概览](https://docs.bigmodel.cn/cn/coding-plan/overview)

如果需要核对开源模型，可参考官方仓库：

- [GLM-4.5](https://github.com/zai-org/GLM-4.5)
- [GLM-5](https://github.com/zai-org/GLM-5)

### 4.2 本地目录规则

- 通用 GLM API、GLM Coding Plan 和 GLM Coding Anthropic 都归入 `providerCode = glm`，但必须分成独立协议档案和默认分组；当前模型目录清洗优先维护两个 OpenAI v1 Chat 档案，Anthropic Messages 档案按自身协议能力独立验收。
- 当前只收录 `chat_completions` 支持模型，不把 `/responses` 当成 GLM 默认能力。
- Coding Plan 模型只在 Coding Plan 分组和测试中使用，不要默认和通用 GLM API 混用同一套测试模型或分组。
- `glm-5.1` 和 `glm-5` 这类历史模型如果官方说明会自动切换到 `glm-5.2`，目录中应优先保留官方当前可见模型，旧别名只在明确确认可计价且有稳定兼容价值时保留。
- 价格必须来自官方价格页或官方模型页；如果短期内无法确认单价，先不进入计价目录。

- 模型废弃说明：[Model deprecations](https://docs.anthropic.com/en/docs/about-claude/model-deprecations)

Anthropic 没有放入 `openai` 聚合目录；官方 Claude 模型只归入 `providerCode = anthropic` 和 `profile_anthropic_anthropic_v1`。如果未来重新评估第三方 Anthropic-compatible、Vertex Anthropic 或 Bedrock Claude，必须建立各自供应商 / 协议档案，不复用官方 Anthropic 目录结论；当前 DeepSeek 不接入 Anthropic-compatible surface。

### 5.2 本地目录规则

- 当前只接入官方 Anthropic API Key 直连，账户类型只允许 `api_key`；Claude Code 是下游客户端画像，模型目录可以补充 Claude Code 官方模型配置别名，但不新增 Anthropic OAuth / Claude Code token 账号目录。
- 模型能力以 Anthropic native `messages` 和 `message_token_counting` 标记，不把 `/v1/chat/completions` 或 `/v1/responses` 当成默认能力。
- `GET /v1/models` 在 Anthropic 档案下返回 Anthropic native 模型列表形态；OpenAI v1 分组不会因为同名模型接收 `/v1/messages` 请求。
- 官方 dated ID 可以直接进入 Anthropic 目录并沿用同族稳定别名价格，例如 `claude-haiku-4-5-20251001` 沿用 `claude-haiku-4-5`，`claude-sonnet-4-5-20250929` 沿用 `claude-sonnet-4-5`，`claude-opus-4-5-20251101` 沿用 `claude-opus-4-5`。
- 可见目录按 Anthropic Models API 的“新模型在前”口径维护；当稳定别名没有官方精确发布日期时，不编造 `releaseDate`，用 `catalog_order` 固定下拉框从最新到旧。
- 官方 deprecations 已给 shutdown date 的模型只在 shutdown date 晚于当前 UTC 日期时保留，例如 `claude-opus-4-1`、`claude-opus-4-1-20250805` 在 `2026-08-05` 前可保留并标记关闭日期；`claude-opus-4-20250514`、`claude-sonnet-4-20250514`、Claude 3.x 等已经退休的模型不进入目录。
- Claude Code 官方模型配置别名可以进入目录并按目标族价格计价：`best`、`fable`、`opus`、`opus[1m]`、`opusplan`、`sonnet`、`sonnet[1m]`、`haiku`。`default` 是清除覆盖并回到推荐模型的控制值，不是模型别名，不进入目录。
- Antigravity / 兼容网关别名可以作为隐藏计价别名收录并按对应 Claude 族计价，但不能进入官方 Anthropic 模型发现目录；必须明确它们不是 Anthropic 官方直连模型 ID。当前隐藏计价覆盖 Opus 4.6 thinking 的 `antigravity/`、`google/antigravity-`、`google-antigravity/`、`google-antigravity:` 写法，以及 Sonnet 4.6 / Sonnet 4.6 thinking 的同类写法。
- Antigravity 的 `-low`、`-medium`、`-high`、`-max` 等 effort 后缀只做计价回落，不单独列入模型发现目录；旧的 `claude-opus-4-5-thinking` / `google/antigravity-claude-opus-4-5-thinking` 不收录。
- 兼容代理真实联调模型如 `claude-fake-5` 可以作为临时隐藏计价别名收录，但不能进入官方 Anthropic 模型发现目录；后续如果该代理拆为独立供应商，应迁移到对应供应商目录。
- 除已记录的兼容代理验证别名外，价格必须来自 Anthropic 官方价格页或官方模型页；如果短期内无法确认输入、输出、缓存读写等单价，先不进入可计价目录。
- Prompt cache、thinking、tool use、vision 等能力只作为模型能力或 usage 口径记录，不用 OpenAI `chat_completions` 标签代替。
