# 厂商模型目录更新与清洗指南

> 面向 AI 和维护者。
> 本文记录各厂商模型目录的更新、核对、清洗和验证方法。不同厂商的官方来源、废弃规则和模型命名方式可能不同，后续新增厂商时必须单独补充厂商章节，不要把 OpenAI 的做法直接套用到其他厂商。
> 本文只管理代码内置的官方厂商模型目录。管理员全局模型、用户个人模型、自定义价格和账号模型映射见 [自定义模型与模型映射设计](自定义模型与模型映射设计.md)。

## 1. 目标

- 保证代码内置官方模型目录只展示真实存在、可用于对应厂商 API 的模型。公开客户端 `/models`、`/v1/models` 动态聚合全部启用真实供应商目录；有效 API Key 按其路由策略全部 active 分组涉及的供应商聚合，并叠加调用方可见的全局 / 个人自定义模型。各具体供应商仍只维护自身模型事实，客户端聚合不改变供应商归属。
- 清理官方已废弃、已关闭、仅历史兼容、仅旧快照、第三方快照误收录或官方不存在的模型。
- 保留成本估算需要的当前稳定别名和官方快照，避免旧模型被误估价。
- 新增智谱 GLM 等非 OpenAI 厂商时，必须单独记录官方模型页、价格页、接入端点、废弃规则和模型别名，不要复用 OpenAI 的清洗结论。
- 模型价格和 usage 统计口径的详细核对方法见 [模型价格与用量统计口径](模型价格与用量统计口径.md)。
- 记录每次清洗的来源、工具、口径和验证方式，让下一次更新可以快速复用。

## 2. 通用流程

> 逐厂商官方入口全集、抓取通道实测、数据陷阱与历史案例集中在 §13 实操手册；每次做模型获取/复核调研前先读 §13，再回本节走流程、进各厂商章节查专属规则。

1. 先定位当前内置模型来源。
   - 当前 OpenAI 目录在 `backend-go/projects/gateway/internal/pricing/`（静态快照 `data_*.go`）。
   - 内置供应商模型列表由 `listProviderModelPricing()` 暴露；网关 `/v1/models` 的最终目录在内置模型基础上叠加全局 / 个人自定义模型。
   - 客户端模型列表和 AI 问答直接复用供应商级目录缓存，不读取 `default/codex`、`chat_list:*` 或 `chat_model:*` 发布响应快照；最终发布快照基础设施已完整退场。
   - 管理后台通用模型筛选由 `/providers/models/options` 暴露启用供应商的模型名称选项，前端只在该选项目录内做输入匹配，列表查询仍提交完整模型名。
   - 新账户检查模型默认来自供应商模型目录的有效默认链；列表人工测试候选由账户 `test-options` 接口按所有者作用域和协议档案按需返回，不维护前端静态候选。

2. 收集厂商官方来源。
   - 优先使用厂商官方文档、官方模型列表、官方价格页和官方废弃说明。
   - 官方资料缺少发布日期时，可以使用官方仓库、官方模型托管账号、可信新闻、论坛或社区首发记录交叉核验；单一无来源转载不能作为最终事实。
   - 如果厂商提供真实 API 的模型列表接口，可以在安全环境下作为二次核验，但不要在文档或日志中暴露真实 API Key。

3. 抽取本地模型 ID。
   - 使用 `rg` 查找模型定义，不手动凭印象整理。
   - 对模型 ID 去重、分组，并标出是否是稳定别名、日期快照、预览模型、专用能力模型或废弃模型。

4. 建立清理口径。
   - 官方模型页不存在：从展示目录移除。
   - 官方价格页没有可用单价：不要猜价；除非单模型页明确给出同口径价格，否则不进入内置可见目录。
   - 官方废弃页列出 shutdown date：只有 shutdown date 已经到达或早于当前 UTC 日期时，才从展示目录移除并在成本估算中屏蔽；shutdown date 仍在未来的模型继续保留计价，并标记关闭日期。
- 仅历史快照、旧 preview、旧 realtime/audio/search 预览：从展示目录移除。
- 当前稳定别名和仍推荐使用的官方快照：可保留。
- 模糊匹配不能把不存在的模型映射到相近模型，例如不能把 `xxx-spark` 误映射到 `xxx`。
- 模型用途和接口协议必须分开记录：用途用于前端分类，例如对话 / 编码、图像、音频；接口协议用于展示模型支持的 API 形态，例如 `Chat Completions`、`Responses`、`Images API`。
- 音频模型（TTS/STT，`mode=audio`）已随 M1 同步音频呼叫链落地（2026-10-04），按"音频"分类收录；OpenAI TTS/STT 与 Gemini TTS 模型行已进目录，计费口径见 [模型价格与用量统计口径](模型价格与用量统计口径.md)。Realtime、视频、embedding、OCR 模型已随后续批次陆续收录（见 [音频视频模型接入与统一媒体网关设计](音频视频模型接入与统一媒体网关设计.md) 与各厂商章节；2026-10-05 全厂商补全批已覆盖 OpenAI Realtime/transcribe 系、Gemini veo-3.1 系、火山 seedance 系、MiniMax H3 系、智谱 cogvideox、百炼 wan 系等视频 / Realtime 行及 embedding、OCR 行），专用 Agent 模型仍不新增。模型虽有对话或视觉能力，但价格需要按时段、分辨率或其它现有字段无法表达的维度计算时，也不猜测价格或扩展结构，保留为后续独立能力改造事项。
- 本地价格数据里的 `mode` 只能作为计价或默认口径参考，不能当成模型唯一支持的接口协议；如果官方确认同一模型同时支持多个协议，应在接口返回里同时展示。
- 供应商模型接口里的 `releaseDate` 在页面展示为“发布时间”，表示模型大致对外可用或官方快照对应的发布时间，用于模型列表倒序排序；不要把它理解成价格数据更新日期。
- 客户端模型聚合不按 `releaseDate` 过滤，但内置事实源在聚合前执行完整性门禁；缺少发布日期、协议、输入输出模态或计价事实的内置模型必须从内置源删除。管理员和用户自定义模型仍可按自身资料完整度保留空字段。
- GPT 模型必须同时核对精确 API 请求能力：`supportedServiceTiers`、`supportedReasoningEfforts` 和可选 `defaultReasoningEffort`。稳定别名、日期快照和 `pricingModel` 别名继承已确认规范模型能力，不能按模型名前缀猜测。
- OpenAI API wire reasoning 与 Codex picker 能力分开记录。Codex `/models` 使用独立默认 reasoning、支持级别、服务等级和多代理版本；`ultra` 不进入账户 reasoning 覆盖数组，自定义模型第一版也不能仅凭字符串声明 Ultra。Responses Multi-agent Beta 不纳入本期账户覆盖字段。
- 容量字段必须拆开：`context_window_tokens` 表示总上下文窗口，`max_input_tokens` 表示官方明确公布的最大输入，`max_output_tokens` 表示最大输出。厂商只公布总窗口和最大输出时，不得把总窗口复制到最大输入；请求预算可以用 `context - max output` 派生保守输入上限。
- `input_modalities`、`output_modalities` 和 `supported_tools` 必须来自模型官方页。协议支持不能替代模型能力，例如 Responses 可用不等于模型支持图片，也不等于模型支持 `web_search`。
- `supported_service_tiers` 只记录供应商真实请求参数支持的 `priority` / `flex`；购买套餐、预置吞吐、批处理或同名但取值不同的厂商能力不得强行映射。
- 上游标准模型列表接口通常只负责返回可用模型 ID；AI 问答使用“上游 ID 列表与本地官方能力快照取交集”，不能把列表接口缺少能力字段解释为模型不支持。

5. 修改代码后做验证。
   - 验证模型列表数量和具体 ID。
   - 验证已废弃或不存在 ID 不再命中。
   - 跑相关 typecheck。
   - 如果后端类型检查失败，要区分是否为本次改动造成，并记录失败位置。

### 2.1 当前逐供应商能力核对矩阵

以下结论只描述当前代码能安全透传和计价的能力；“默认”表示目录是否替上游或客户端做选择，不表示模型一定支持该档位。

| 供应商 | 服务等级 | 思考级别 | 默认思考级别 | 当前处理结论 |
| --- | --- | --- | --- | --- |
| GPT / OpenAI | `priority`、`flex` 按模型精确声明；未声明时省略 | `none`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max` 按模型精确声明 | 不写入 GPT API 模型目录，由上游决定；Codex `/models` 的独立 picker 元数据另行维护 | 中转不替 OpenAI API 请求选择默认 effort |
| Anthropic | 官方原生 `service_tier` 是 `auto` / `standard_only`，不等价于本站 `priority` / `flex`，因此目录不展示本站服务等级 | 仅官方模型公开的 `low`、`medium`、`high`、`xhigh`、`max` | 当前官方 effort 文档明确为 `high` 的模型记录 `high` | 原生 Messages 透传自己的 service tier 语义，禁止错误映射成 OpenAI 档位 |
| Gemini | `service_tier=priority|flex`；Standard 通过省略字段或 `standard` 表达 | 按模型记录 `minimal` / `low` / `medium` / `high` | 3.5 Flash=`medium`；3.1 Pro / 3 Flash=`high`；3.1 Flash-Lite 与 2.5 系列不替上游填写 | Priority/Flex 专用价格必须进入原始计价、目录计价和账单明细 |
| xAI / Grok | 官方请求支持 `default` / `priority`；本目录只列非默认的 `priority`，标准由省略字段表示 | 仅对官方发布资料明确列出的模型记录 `low` / `medium` / `high` / `xhigh` 等精确档位 | 有官方默认值时记录，否则不替上游设置 | 复用 OpenAI Chat / Responses 协议，模型间能力不按名称推断 |
| DeepSeek | 不支持本站服务等级 | V4=`high` / `max`；V4.1-Flash（deepseek-flash）=`low` / `high` / `max`；旧兼容模型不声明 | V4 官方默认 `high`；V4.1-Flash 官方默认未明示，不替上游设置 | `reasoning_effort` 只在 DeepSeek 自身 wire 能力成立时透传 |
| GLM | 不支持本站服务等级 | GLM-5.2=`high` / `max`；其他模型不声明离散 effort | GLM-5.2 官方默认 `max` | 不把 thinking 开关扩写成 OpenAI 服务等级 |
| 火山方舟 | 不支持本站服务等级，目录不声明 | doubao-seed 系官方公开 `low`、`medium`、`high`、`minimal`（个别模型官方仅列三档） | 官方明示默认 `high` 的行记录 `high`；未明示的行不替上游设置 | 对话由 `profile_volcengine_openai_v1` 承接（OpenAI 兼容 `/api/v3`），`reasoning_effort` 按官方口径透传；媒体面不适用本表能力字段 |
| 通义百炼 | 不支持本站服务等级，目录不声明 | 目录不声明离散 effort 档位 | 不替上游设置 | 对话由 `profile_qwen_openai_v1` 承接（DashScope OpenAI 兼容模式 `/compatible-mode/v1`）；不从模型名猜测能力 |
| 通用 OpenAI-compatible | 只能使用用户自定义且有真实上游依据的 `priority` / `flex` | 只能使用用户自定义且有真实上游依据的 effort | 新增自定义模型默认留空 | 不从供应商名称、模型前缀或客户端字段猜测能力 |

GPT 和自定义模型的默认 effort 留空是有意设计：本项目是中转，不是客户端；转发路径应保留客户端显式参数，未提供时让真实上游自行决策。

## 3. OpenAI 厂商

### 3.1 官方来源

OpenAI 模型目录清洗必须优先使用官方页面：

- 模型总览：[OpenAI Models](https://developers.openai.com/api/docs/models)
- 最新模型指南：[Using the latest model](https://developers.openai.com/api/docs/guides/latest-model.md)
- 价格目录：[OpenAI Pricing](https://developers.openai.com/api/docs/pricing)
- 废弃说明：[OpenAI Deprecations](https://developers.openai.com/api/docs/deprecations)
- 单模型页面：`https://developers.openai.com/api/docs/models/<model-id-or-family>`

如果 `openai-docs` 技能可用，先用 OpenAI developer docs MCP 检索和读取官方文档；如果当前会话没有 MCP 工具或无结果，再回退到官方域名网页检索。回退检索只使用 `developers.openai.com` 或 `platform.openai.com`。

### 3.2 本次清洗方法记录

本次清洗日期：`2026-05-08`。

本次采用的方法：

- 先读取 `openai-docs` 技能说明，确认 OpenAI 资料必须以官方文档为准。
- 尝试配置 OpenAI docs MCP：`codex mcp add openaiDeveloperDocs --url https://developers.openai.com/mcp`。
- 当前会话 MCP 工具未热刷新，因此回退到官方网页。
- 用 OpenAI developer docs MCP、`web` 和 PowerShell `Invoke-WebRequest` 访问官方模型页、价格页和废弃页。
- 用正则从官方页面提取模型 ID、单模型链接和废弃页中的关闭表。
- 用本地脚本逐个检查内置模型对应的官方单模型页面是否存在。
- 用本地脚本验证已关闭或不存在 ID 不再出现在内置展示清单，未来关闭但仍可用的 ID 仍能计价。

关键判断：

- `Models` 页面用于确认当前推荐和可见模型族。
- `Pricing` 页面用于确认仍有官方计价的模型和价格字段。
- `Deprecations` 页面用于确认 shutdown date 和替代模型；“已宣布废弃”不等于“现在不能用”，只有 shutdown date 到达后才视为不可访问。
- 单模型页标题为 `Page not found | OpenAI API` 时，视为官方模型页不存在。
- 有些旧模型不再推荐但仍有官方模型页、价格页和未来 shutdown date，例如 `gpt-4`、`gpt-3.5-turbo`；这些模型仍应进入计价目录，避免用户真实调用后无法记账。
- OpenAI 的 `Chat Completions` 和 `Responses` 是接口协议，不是模型用途分类；通用文本模型如果官方端点表同时支持 `/v1/chat/completions` 和 `/v1/responses`，供应商页应同时显示两个协议标签。Codex / Pro 等仅 Responses 口径的模型只显示 `Responses`。

2026-07-10 能力口径补充：

- GPT 模型目录以精确数组表达服务等级与 OpenAI API reasoning effort；`supportsServiceTier` 如保留，只能由 `supportedServiceTiers.length > 0` 派生。
- GPT 档位价格分别维护 standard / priority / flex；模型声明支持档位但缺少专用价时保持未定价，禁止使用系统倍率或默认倍率猜测。长上下文阈值与输入、输出倍率属于同一价格快照，计价时在选定档位后应用。
- Priority 与 Flex 平级，模型能力数组必须逐模型精确声明，不允许从 `supportsServiceTier`、Priority 能力或通用倍率推导 Flex。
- 账户服务等级 / 思考级别覆盖的配置候选取支持模型能力并集；运行时使用映射后的最终上游模型能力逐字段判断，最终模型不支持或能力未知时保留客户端值，不做向下降级。
- Codex `/models` 不再为所有模型统一返回 `minimal|low|medium|high` 和空服务等级，必须消费 Codex 专用能力字段。
- 模型目录默认检查模型只初始化后续新账户；已有账户的 `healthCheckModel` 不随目录默认修改。

2026-07-13 跨厂商能力复查：

- OpenAI 模型把总上下文、最大输入、最大输出、输入/输出模态、工具、reasoning effort 和 service tier 分开记录；AI 问答不再接受客户端自报上下文大小。
- 同一模型 ID 可由多个可达供应商账户承接时，AI 问答只暴露所有候选目录共同支持的思考档位、服务等级、模态和工具，并取最小容量，避免切换账户后把不支持的参数发给上游。

### 3.5 OpenAI 清理规则

- 保留官方当前模型页存在、价格页有单价、且 shutdown date 尚未到达的模型，包括不再推荐但仍可访问的旧模型。
- 可以保留官方当前日期快照，例如 `gpt-5.5-2026-04-23`；旧快照如果官方价格页仍有单价且 shutdown date 未到，也可保留用于计费。
- 不保留已经 shutdown 的模型、官方模型页不存在的模型、官方价格页没有单价且无法从单模型页确认同口径价格的模型。
- 不保留旧 realtime preview、旧 audio preview、旧 search preview 等已经 shutdown 或由 GA 模型替代的 preview 展示项。
- 不保留官方模型页不存在的 ID，例如 `gpt-5.3-codex-spark`。

## 13. 模型获取调研实操手册（Runbook）

> 本文的"怎么做"层：每次给目录补模型/复核价格时，调研怎么抓、走什么通道、哪些数字不能信、踩过哪些坑——全部沉淀在此，避免每轮从零摸索。章节内容以 2026-10-05 两轮全厂商调研实测为准；通道可达性与页面结构会变，每次调研后把新事实回写本章。

### 13.1 调研流程 checklist（每次照走）

1. **定范围**：明确本轮覆盖哪些厂商、哪些用途面（对话/视觉/TTS/ASR/视频/图像/embedding/realtime）；待复核项从计划文档 §复核清单 或上次遗留取。
2. **过通道**：按 §13.2 通道表选每家的抓取方式；官方页打不开先换 `.md` 后缀、再换服务端抓取（WebFetch/web_reader）、再换国际站，全部失败记"不可达"，**禁止编造**。
3. **抓原文**：能拿页面原文文件就拿（见 §13.3 教训 P1/P2）；价格、上下文、日期逐项记"数值 + 来源 URL + 页面原句摘录 + 置信（高/中/低）"。
4. **辨口径**：过一遍 §13.4 陷阱清单（币种、单位、折扣、分段、按次、别名、废弃）。
5. **仲裁**：本轮结论与库内/历史调研冲突时，以**页面原文逐字**为最终裁判；摘要类二手转写一律重抓原文核对。

7. **验证**：pricing/providers/schema 定向测试 + 受影响链路测试 + typecheck；golden 钉值按新事实更新但不放宽断言语义。
8. **回写**：厂商章节更新记录、本章通道/陷阱新事实、计划文档复核清单收敛。

### 13.3 数据陷阱清单（编号固化，调研时逐条过）

- **P1 转写/摘要失真**：服务端工具转写大表格会丢档位标签、错配数值（实例：gemini-3.6-flash 转写 $0.50/$2.50 实为 $0.75/$3.75；gemini-3.5-flash "长上下文档" 官方根本无此档）。对策：低置信数值不落库；复核时重抓原文逐字对。
- **P2 摘要通道数字错误**：web_reader 摘要曾给错 grok-4.6 价格（$3/$0.75/$15，原文 $2/$0.50/$6）。对策：关键模型以原文文件仲裁（xAI 案例留存 Temp 文件）。
- **P3 档位语义错归属**：区域端点乘数 ≠ 计费档（grok-4.7 "1.1x" 是 us.api.x.ai 全 token 乘数，长上下文档实为 2x）；改名档位要追语义（OpenAI priority→Fast 改名，键仍是 priority）。
- **P4 单位换算**：$/1M tokens→`perToken(x)`；$/min→÷60、$/hr→÷3600 落 per-second；元/万字符→USD/1M chars **×10** 再换汇；每换算一个写一道算式进注释。
- **P5 按次/按视频价进不了每秒槽位**：`VideoOutputCostPerSecond` 是每秒语义，按次价（CogVideoX $0.2/video）硬塞会错计费——撤回无价 + 注释按次口径（0 计费兜底 + usage_missing）。
- **P6 模型 ID 映射差异**：BytePlus 豆包系 `dola-/seed-/dreamina-` 前缀 ↔ 国内 `doubao-`；日期快照与稳定别名两形态（豆包 `-260915`、百炼 `-2026-05-26`）——两条形态都收、价格挂稳定别名；后缀日期行 ReleaseDate 必须等于后缀（门禁）。
- **P7 无 model_id 产品线不落目录**：豆包语音（appid/cluster/voice_type）、火山 V3 TTS（req_params.speaker）——无 API 模型 ID 字符串就没有目录行，只有接入文档配置事实。
- **P8 滚动别名与审批制**：`chat-latest` 类类目滚动别名（快照推进+旧快照废弃）不收静态目录；trusted-access 审批制模型（gpt-rosalind-research）不收。
- **P9 preview 死亡与 GA 改名**：preview ID 会整体 shutdown（`embedding-2-preview`→`gemini-embedding-2`；veo-3.1 全系 preview 2026-10-22 下线）——收 GA 形态，preview 行必须落 ShutdownDate。
- **P10 折扣与牌价**：限时折扣（BytePlus seedance 25%/60% off、阿里 20%/30% off、MiniMax M3 永久五折）一律落**牌价**，折扣进注释；促销到期日（如 Gemini 3.6-flash 2027-01-01 调价）注释登记。
- **P11 分段/阶梯计费**：火山 2.0 系按输入长度三段、百炼全 token 阶梯——目录无分段通道，统一落主流主档/首段，其余档位注释登记全值。
- **P12 站点性质混淆**：国际站未售 ≠ 无价（保留换算并注明）；第三方上架（BytePlus 卖 glm）与官方国际品牌（z.ai）口径分开记录；国内站英文界面 ≠ 国际站（火山英文文档无定价）。

### 13.4 多能力标注与无法独立计费清单（2026-10-05 用户裁决固化）

**多能力标注规则**：`mode` 只承担主用途分类（前端对话/图像/音频/视频 tab 语义）；一个模型官方支持的**全部能力必须完整标注**——`InputModalities`/`OutputModalities`（模态数组）、`SupportedAPIProtocols`（协议数组）、多能力价格落对应分模态槽位（`InputCostPerAudioToken`/`OutputCostPerAudioToken`/`InputCostPerImageToken`/`TtsInputCostPerChar`/`AudioInputCostPerSecond`/`VideoOutputCostPerSecond`/`OutputCostPerImage`）。调度按协议+模态发现候选、计费按分模态槽位匹配单价；**严禁因"单一 mode 装不下"而漏标**（实例：MiniMax-M3 输入漏 image/video、qwen3-omni-flash 音频输出价 $15.11 有明文未落——均已补）。模态数组只写官方明文支持项，"多模态"概括词无逐模态明细时不推（火山 doubao 系视觉模态待官方明细，见待复核）。

**无法独立计费清单**（目录当前全部无价行 + 无模型 ID 能力；"无价"=静态层无任何单价 → 计费走契约 §2.8 兜底 0 计费 + `usage_missing`，用量维度照记不丢）：

| 条目 | 有无模型 ID | 无价根因 | 解锁条件 |
| --- | --- | --- | --- |
| `cogvideox-2` / `cogvideox-3`（glm 视频） | 有 | 官方按次计费（1 元/0.5 元每次、z.ai $0.2/video），按次语义进不了每秒槽位；且 cogvideox 轮询 `usage`/`duration` 字段未回填契约（秒数抽不到，即便落秒价也算不出） | 契约回填轮询 usage/duration 字段族 + 按次计费结构（两项独立改造） |
| `MiniMax-Hailuo-2.3`（minimax 视频 v1 API） | 有 | 官方按条计费（$0.28/768P-6s），同上按条 vs 每秒 | 上游 usage/duration 回填 + 按次结构 |
| `doubao-seedance-1-0-pro-250528` | 有 | 官方"即将下线"无明文日期，人民币按 token 口径——临近退役不投入 | 官方下线前如需用，按 BytePlus 国际站口径重估 |
| 豆包语音复刻/ASR/S2S/同传/播客/机器翻译/音频生成 | **无**（appid+cluster+音色调用，无 model_id） | 网关无 adapter 未承接——不涉及调度，无计费问题 | 有需求时按 volcengine_tts adapter 模式逐个立项 |
| 语音合成（TTS）能力本身 | 占位 ID `doubao-tts`（非官方 ID，统一面 model 被 adapter 忽略） | **已解决**：占位行 + 换算字符价 $4.2857/百万字符（静态层计费生效；目录表无字符价列故目录行价格列空属正常） | — |

注意：目录表（provider_model_catalog）**没有**字符价/秒价列——TTS 字符价、ASR/视频秒价只落在 gateway 静态层 `PriceSet`（计费真实读取处）；目录行价格列空 ≠ 计费无价。两者职责勿混。

### 13.5 上游 usage 回报与计费链（每类调度方式的回报事实）

| 调度面 | 上游是否返回计费信息 | 网关计费行为 |
| --- | --- | --- |
| 对话（chat_completions / responses / generate_content / messages） | **全部返回** usage（token 明细） | 照抽落 `usage_records`，按目录价精确计费——主链路 |
| 音频对话（audio token 维度） | OpenAI/Gemini 等返回 audio token 明细 | 音频输入/输出分模态价计费（M1/M5） |
| Realtime（WS） | 会话内 usage 事件（部分厂商） | 旁路 usage 观测器照抽（M5） |
| TTS（/v1/audio/speech） | 多数**不返回** usage | 网关按请求字符**自算计量**（`TtsInputChars`）照落，成本按静态层字符价；上游有回报则以回报为准 |
| ASR 长音频（/v1/audio/jobs） | qwen usage 字段族已核实（返回可计费时长） | 秒计量照抽按秒价计费 |
| 视频异步（/v1/videos） | 分上游：qwen usage/duration 已核实；cogvideox/volcengine 未回填或无回报 | 有回报照抽按秒价计费；无回报 `usage_missing` + 0 计费（不编造） |
| 图像 | 按 image token 或按张回报 | `OutputCostPerImage` / image token 价计费 |

总原则：**上游回报什么抽什么；能自算的维度（TTS 字符等请求侧）自算照落；上游产物且无回报的维度（视频秒数）标 `usage_missing` 绝不估算**。权威口径见《模型价格与用量统计口径》。
