# 供应商卡片选择与图标设计

> 状态：已实施完成（2026-10-17，独立复审通过无 blocker）。实施与验证记录见 [计划-20261016T235628000Z](../plans/计划-20261016T235628000Z-供应商卡片选择与图标实施.md)。

## 1. 背景与目标

添加 AI 账户时，供应商选择目前由 [AccountFormSelector](../../frontend/src/views/accounts/AccountFormSelector.vue) 承载：默认供应商（GPT 优先）+「切换」下拉菜单，菜单项只有名称与「N 种类型」。随着供应商规模增长（8 个内置 + 媒体族 minimax/volcengine/qwen + 数据库自定义定义上限 50），下拉无法承载搜索、图标、说明与账户分布等选择依据。

目标：

1. 新建账户向导第 1 步提供**供应商卡片墙**：图标、名称、接入方式、当前范围账户数、说明与搜索框；点选卡片后进入现有「接入方式 + 凭据」表单。
2. 新增通用组件 `ProviderIcon`，以**本地内联 SVG** 维护供应商品牌图标，并接入账户列表、供应商表、模型目录、模型下拉等展示面。

非目标：

- 不改后端、schema 与任何接口；图标为前端静态映射，不做 `provider_definitions.icon` 数据库字段（自定义供应商图标需求出现时另行立项）。
- 不改 `openCreate` 默认供应商逻辑、编辑/克隆动线、三步向导骨架与 `AccountMediaForm` 三段式结构。
- 不做卡片分类 tab（现实规模 ≤ 50、常态 < 15，搜索 + 排序足够；空分类与维护成本不划算）。
- 跨供应商聚合的模型下拉（[useProviderModelSelectOptions](../../frontend/src/composables/useProviderModelSelectOptions.ts)，一个模型聚合多个 `providerCodes`）不挂图标；[ProviderSelect](../../frontend/src/components/ProviderSelect.vue)（CachedSelect 封装）本批不动，登记为后续。
- 不改移动端独立布局结构；卡片墙使用响应式 grid 自适应。

## 2. 可见行为

### 2.1 卡片墙（新建态向导第 1 步）

第 1 步是**两个先后阶段**：先进入独立的供应商选择，再进入配置。

- 仅新建态显示（`editing` 为 true 的编辑/克隆态完全不渲染卡片墙，维持现状）。
- 打开创建弹窗时**阶段一：卡片墙独立呈现**——弹窗整体只呈现供应商卡片：标题固定为「添加账户」（不指向任何供应商或接入方式），向导步骤指示（对话域）、「凭据」小节头（媒体域）与底部按钮区（测试/上一步/下一步/取消/创建）全部隐藏。
- 点选卡片后**阶段二：进入配置**——卡片墙收起为「已选摘要条」（图标 + 名称 +「更换」按钮），标题恢复为「添加 <供应商><接入方式> 账户」，向导步骤指示与小节头恢复，底部按钮区恢复；摘要条下方保留现有 `a-segmented` 接入方式选择（多选择时显示，逻辑不变），并展示配置表单。
- **接入方式展示名（2026-10-17 统一简化为协议短词）**：多档案供应商用 Chat（OpenAI Chat 兼容入口）/ Claude（Anthropic / Claude Code 入口）/ Coding（GLM Coding Plan）/ Gemini（原生协议）区分，标题如「添加 Chat API Key 账户」「添加 Claude API Key 账户」；单档案供应商沿用「供应商名 + API Key / OAuth」（如「xAI API Key」「GPT OAuth」）。供应商已由卡片墙与已选摘要条承载，标题不再重复供应商前缀；档案细节（官方/原生/兼容、Base URL 差异）由接入方式描述文案（`accountTypeDescription`）承载。
- 「更换」重新展开卡片墙并再次隐藏配置区；不直接重置表单，重置仍由既有 `selectProvider` → `resetForm(providerCode, '')` 完成。卡片墙展开状态在弹窗每次打开时复位为展开。
- 卡片为**横向布局**（对齐 AgentZAPS 参考样式）：左侧 logo 块（`--juhe-accent-soft` 圆角底 + ProviderIcon，高 26px），右侧自上而下依次为名称（加粗单行省略）、接入方式标签（OAuth / API Key，来自轻量 `accountTypes` / `protocolProfiles.accountTypes`）、账户数（当前系统账户范围内按 `providerCode` 计数；0 显示「还没有账户」）。不渲染 `description`。`google_oauth` 类型的展示名与其他 OAuth 统一为「OAuth」（2026-10-17，同样适用于类型列与弹窗标题；底层类型值仍为 `google_oauth`，机制文档中的「Google OAuth」指凭据机制，不受展示名影响）。
- 搜索框：按名称与 `code` 前端过滤；排序为有账户在前按账户数降序，其余保持传入顺序。
- 数据源：现有 `providers` prop（FALLBACK 与懒加载 definitions 的合并结果），**不在打开时预载全量 definitions**（懒加载是既有契约）。账户数采用**读时聚合**（2026-10-17 裁决：量级 ≤1 万行、毫秒级索引聚合，不做写时计数表——计数表需覆盖创建/克隆/导入/单删/批删五类写入路径且存在静默漂移风险）：AccountsView 在创建弹窗打开时调用一次 `GET /__aisys__/api/accounts/provider-counts`（管理面，随 `systemAccountId` 范围参数）或 `GET /__aisys__/api/my-accounts/provider-counts`（用户面，强制本人范围），携带当前 `capability_domain`，拿到与列表同一可见范围的**全量**分组计数（`Record<providerCode, count>`）——不受列表分页（每页 20 行）与搜索筛选影响。AccountEditModal 以 `accountCounts` prop 接收并透传两个域的选择器（prop 形状不变，内部不再从已加载账户行归并计数）。
- 媒体域：[AccountMediaForm](../../frontend/src/views/accounts/AccountMediaForm.vue) 第 1 段内嵌 AccountFormSelector，重构后自动获得卡片墙，展开/收起与对话域同阶段语义（展开时隐藏凭据字段与段2/段3 配置区，「凭据」小节头一并隐藏，展开状态上抛弹窗驱动标题与按钮区）；其媒体域供应商清单兜底（弹窗打开拉全量 definitions）维持现状。

### 2.2 供应商图标（ProviderIcon）

- 组件：`frontend/src/components/ProviderIcon.vue`；映射表：`frontend/src/shared/providerIcons.ts`。
- Props：`providerCode?: string`、`name?: string`（fallback 字符来源，缺省回退 `providerCode`）、`size?: number`（高度 px，默认 16）。
- 渲染：命中映射表时渲染内联 `<svg>`，每条目自带 `viewBox`（不要求方形），高度取 `size`、宽度按纵横比自适应；未命中渲染**字母圆标**（`name`/`providerCode` 首字符，底色与文字用 `--juhe-*` 变量）。
- 映射条目（品牌图形与登录页 [LoginView](../../frontend/src/views/login/LoginView.vue) 同源，Minimax 取自 simple-icons，xAI 取自 x.ai 官网页头；**全部内联进源码，运行时零网络请求**）：

| providerCode | 图形 | 来源 |
| --- | --- | --- |
| `gpt` | OpenAI | LoginView 既有 path |
| `anthropic` | Claude | LoginView 既有 path（品牌色 #D97757） |
| `gemini` | Gemini | LoginView 既有 path（品牌色 #8E75B2） |
| `deepseek` | DeepSeek | LoginView 既有 path（品牌色 #4D6BFE） |
| `glm` | 智谱 GLM | LoginView 既有 path（品牌色 #3859FF） |
| `qwen` | 通义 Qwen | LoginView 既有 path（品牌色 #615CED） |
| `volcengine` | 豆包 | LoginView 既有 path（多色） |
| `moonshot` | Kimi（预留） | LoginView 既有 path |
| `minimax` | Minimax | simple-icons 单色 path（currentColor） |
| `xai` | xAI 方形 X 标 | Boxicons `bxl:xai` 单色 path（currentColor）；官网横版 logo 宽高比约 2.6:1，内联场景偏宽，2026-10-17 改用方形标 |
| `hybrid` | 自绘通用分支图形（非品牌） | 本项目自绘 |
| `openai-compatible` | 自绘通用接插图形（非品牌） | 本项目自绘 |
| 其它 / 自定义供应商 | 字母圆标 | fallback 规则 |

- 映射表条目结构：`{ viewBox: string; paths: Array<{ d: string; fill?: string; fillRule?: 'evenodd' | 'nonzero' }> }`，`fill` 缺省 `currentColor`，`fillRule` 仅非默认值时携带（当前为 Qwen 的 `evenodd` 镂空必需）。项目当前为静态浅色主题（global.css 单一 `:root` 变量组），无深色适配负担。
- 本批接入面：账户列表桌面供应商 tag（[AccountTableCell](../../frontend/src/views/accounts/AccountTableCell.vue)）、移动卡（[AccountMobileCard](../../frontend/src/views/accounts/AccountMobileCard.vue)）、[ProvidersView](../../frontend/src/views/providers/ProvidersView.vue) 供应商表名称列（新增 bodyCell `name` 分支）、[ProviderModelCatalogModal](../../frontend/src/views/providers/ProviderModelCatalogModal.vue) 标题、[ModelFilterSelect](../../frontend/src/components/ModelFilterSelect.vue) 单供应商选项、卡片墙。其余展示面（用量、AI 性能、健康、API Key 等）按需后续复用同一组件。

## 3. 关键取舍

1. **卡片墙是向导第 1 步的重构，不是独立页面**：向导骨架、事件名（`select-provider` / `select-type-choice`）与 `useAccountEditForm` 选择流程全部复用，编辑/克隆零影响。
2. **不在打开时预载全量 definitions**：卡片所需字段（code/name/enabled/accountTypes/protocolProfiles）`providers` prop 已含；懒加载契约由回归 `test:account-provider-definitions-lazy-loading` 锚定，自定义供应商定义未加载完成时卡片显示基础信息，点选后走既有 `ensureProviderDefinition`。
3. **静态映射而非数据库字段**：零 schema/后端/部署改动；图标与供应商的绑定锚点是 `providerCode`，模型目录、模型下拉、账户列表全部经 `providerCode` 间接复用，不在 `provider_model_catalog` 行上存图标。
4. **品牌图形边界**：管理界面使用供应商品牌图形以标识来源，沿用登录页既有做法与范围（识别用途、不暗示背书）；未收录品牌（含全部自定义供应商）一律字母圆标，不为品牌图形扩量而引入运行时网络或二进制资产。

## 4. 影响面与既有锚点（实现与复审对照）

以下既有断言锚点不得破坏（证据见实施计划第 3 节）：

- `useAccountEditForm.ts` 中 `selectProvider` / `selectAccountType` / `selectAccountTypeChoice` / `applyCachedDefaultGroup` / `ensureDefaultGroupSelected` / `cachedDefaultGroupForProvider` / `openCreate` / `openEdit` 的函数名、切片内容与相对顺序（多个源码断言回归依赖）。
- `selectProvider` 切片内必须保留 `ensureProviderDefinition(...)` 与 `applyProviderDefinitionDefaultsAfterLoad(`，且切换入口经 `resetForm(providerCode, '')`；卡片点击处理不得内联预载模型目录。
- [AccountEditModal](../../frontend/src/views/accounts/AccountEditModal.vue) open-watch 默认名逻辑（`defaultAccountNameFromBaseUrl`）与第 3 步「持续恢复探活」等字符串位置不动；`<AccountMediaForm ... />` 标签切片不动。
- AccountTableCell 的 `account.providerName || providerName(account.providerCode)` 表达式保留（回归正则锚定），图标在 tag 内加法式插入。
- 账户弹窗相关既有回归（`test:account-type-choice`、`test:xai-account-capability`、`test:account-provider-definitions-lazy-loading`、`test:account-model-mapping-model-options`、`test:account-default-group-selection`、`test:account-edit-save-flow`、`test:account-name-suggestion`、`test:temporary-unavailable-probe-toggle`）与单测 `useAccountEditForm.test.ts`、`accountMediaFormBlocks.test.ts` 全部保持绿。

## 5. 验收标准

1. 新建账户：第 1 步展开卡片墙，展示全部启用供应商（含媒体族）；搜索可过滤；点选卡片收起为摘要条并落位接入方式 segmented；「更换」可重新展开；凭据输入与后续两步行为不变。
2. 编辑与克隆弹窗不出现卡片墙，行为与现状一致。
3. 媒体域（视频/音频/图像）三段式第 1 段同样呈现卡片墙，域默认供应商逻辑不变（既有单测锚定 `glm`/`gpt` 收敛）。
4. 图标：上表 10 个品牌供应商在卡片墙、账户列表（桌面 + 移动）、供应商表名称列、模型目录弹窗标题、模型下拉、分组列表（桌面 + 移动）、模型检测运行历史（桌面 + 移动）、AI 健康监控账户卡、统计概览账户用量表（桌面 + 移动）、AI 性能 / 统计概览的账户管理面板候选项、使用记录「模型」列（桌面 + 移动，行数据 `providerCode` 非空才渲染）显示品牌图形；各供应商统一方形视觉（`xai` 用方形 X 标）；自定义供应商显示字母圆标。
5. `pnpm --filter juhe-ai-frontend typecheck`、`pnpm --filter juhe-ai-frontend test:unit`、第 4 节所列回归脚本、新增回归 `test:account-provider-card-picker` 全部通过；`pnpm --filter juhe-ai-frontend lint` 与 `pnpm --filter juhe-ai-frontend build` 通过。
6. 文档同步：本设计、[通用组件规范](../architecture/frontend/通用组件规范.md)（ProviderIcon 登记）、`docs/functions/README.md` 与 `docs/plans/README.md` 索引同批更新。
