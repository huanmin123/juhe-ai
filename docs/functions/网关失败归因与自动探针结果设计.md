# 网关失败归因与自动探针结果设计

## 目标

自动恢复探针必须区分上游真实失败与探针任务自身失败。任务超时、取消、数据库或进程异常没有形成上游请求时，不得把账户或账户内 API Key 记为失败。

## 结果契约

自动探针内部使用以下离散结果：

- `complete_success`：完成上游请求并取得协议成功证据。
- `upstream_failure`：完成上游请求，但上游响应、协议或传输失败。
- `probe_task_failure`：未形成可归因的上游请求，探针任务自身失败。
- `stale`：结果产生后已过期或不再对应当前凭据版本。

只有 `upstream_failure` 才允许触发账户或 API Key 的上游失败副作用；`complete_success` 只允许清理对应恢复状态；另外两类只记录任务诊断。

## 第一批范围

第一批只覆盖账户运行态恢复、账户预检和账户内 API Key 冷却重试。正常周期健康检查、人工测试、模型探测、客户端响应语义和错误 HTTP 状态保持现状，待独立验证后再调整。

探针日志保留 `probeOutcome`、`upstreamAttemptObserved`、`credentialRevision` 和 `traceId`，不得记录凭据内容。客户端错误响应不因本设计改变。
