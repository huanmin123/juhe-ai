# 网关失败归因与自动探针结果设计

> 多模型目标作用域见 [AI 账户多模型能力健康与精确隔离设计](AI账户多模型能力健康与精确隔离设计.md)。完整 HTTP / SSE 失败仍不得推进 transport 电路或推断具体错误类型；但精确模型能力的独立探针可以把它归并为通用 `capability_unavailable`，只阻断该模型和 endpoint mode，不直接改变整号状态。

## 目标

自动账户 / Key 探针必须区分协议成功、完整但业务中性的响应、传输未完成和探针任务自身失败。上游状态码、错误码、错误类型和正文都不可信，不能据此推断凭据失效、授权失败、限流、封禁或服务故障，也不能把账户或账户内 API Key 记为失败。

## 结果契约

自动探针内部使用以下离散结果：

- `complete_success`：HTTP / SSE framing 完整，并取得当前协议要求的成功对象或完成事件。上层职责可以用它激活账户、写入正向健康事实，或在 generation、claim、配置 revision、凭据代次和状态来源全部匹配时恢复对应自动状态。
- `framing_complete_neutral`：HTTP / SSE framing 完整，但没有取得协议成功证据，包括任意完整 `2xx/3xx/4xx/5xx` 业务失败、`2xx-invalid-body` 或协议错误对象。它对 transport 电路、冷却恢复和 Key 恢复保持中性；`pending_test` 激活把它作为账户连接失败，active 周期哨兵、请求派生探针和质量确认只把它作为匹配 Route / Attempt 的通用 execution 失败。目录探针缺少模型只形成 visibility unknown，不能证明 execution unavailable。
- `upstream_failure`：仅表示 `transport_incomplete`，即建连 / DNS / TLS 失败、lane hard timeout、读取中断、响应 aborted/error/close-before-end 或 framing 未完成。它是 transport 状态机唯一的负向证据，也是 pending_test 的连接失败或 active 精确能力的一次 execution 失败；24 小时 / 7 天账户窗口和传输电路只能由各自 owner 消费独立且通过 CAS 的合法结果，模型子 scope 不得升级账户状态。
- `probe_task_failure`：执行器、队列、数据库、进程、配置读取、解密或本地任务异常，无法形成可归因的上游传输结论。
- `stale`：结果产生后已过期或不再对应当前凭据版本。

`probe_task_failure`、`stale` 和其他 `unknown` 结果不计数、不改变状态，只记录任务诊断并有界重排。用户显式写入的 `temporary_unavailable` / `rate_limited` 只能由其 TTL、匹配来源的恢复动作或人工恢复清理；普通网关成功、后台无 provenance 成功和其他来源的 `complete_success` 都不得越权清理。

人工账户测试、草稿测试、列表测试和模型检测始终是无状态诊断：无论得到哪种结果，都不得激活、恢复、降级或改写账户 / Key 的生产状态。可在本地确定的凭据缺失、解密失败、配置非法和 OAuth token 生命周期错误走独立本地配置 / 授权维护路径；该路径同样不得借上游 HTTP status/body 反推原因。

## 第一批范围

该契约覆盖账户激活、周期哨兵、请求派生的精确能力确认、质量确认、运行态恢复、账户冷却复测和账户内 API Key 恢复。各 owner 必须消费自己的 Route / Attempt / generation / provenance，不能把结果回退给账户哨兵。人工测试和模型检测只复用诊断结果结构，不获得任何生产状态副作用授权。

探针日志保留 `probeOutcome`、`upstreamAttemptObserved`、`credentialRevision` 和 `traceId`，不得记录凭据内容。客户端错误响应不因本设计改变。
