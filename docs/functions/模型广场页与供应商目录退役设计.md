# 模型广场页与供应商目录退役设计

> **本文定义**：跨供应商「模型广场」单页（用户与管理员共用，管理员在广场内直接维护模型）的页面契约、新增聚合读接口契约、供应商目录弹窗的退役清单与回归改写范围。
> **本文不定义**：模型价格与计费语义（见 [供应商独立计费与模型目录展示设计](供应商独立计费与模型目录展示设计.md)）、卡片与抽屉的渲染细节（见 [模型目录卡片化与详情抽屉设计](模型目录卡片化与详情抽屉设计.md)，其契约整体迁移至本页消费）、模型检测与账户域模型选择器（走 `/providers/models/options` 链，不受影响）。
> **裁决记录**：2026-10-28 用户裁决——不搞两套界面，管理员与用户共用同一个模型广场，管理员在广场内正常维护模型，供应商目录弹窗整体退役；后端写接口零变更。

## 1. 要解决的问题

1. 浏览模型需要逐个供应商打开目录弹窗，想知道"哪个供应商有 X 模型、什么价"无法一次看清；跨供应商对比不存在。
2. 用户面与管理面各挂一套模型入口（`/my-models` 供应商表 + 弹窗、`/providers` 供应商表 + 弹窗），同一弹窗组件两种 scope，信息分层后仍以供应商为一级维度，模型本身不是一级公民。
3. 「用户新增个人模型」寄生在目录弹窗内，没有独立入口。

## 2. 目标与非目标

### 目标

1. 新增**一个**模型广场页，同一组件双路由挂载（沿用 ProvidersView 的 viewScope 既有模式）：用户面 `/my-models`（菜单「模型目录」改名「模型广场」），管理面新增 `/models`（菜单入「系统运维」组，roles 限定 `managementRoles`）。
2. 卡片跨供应商平铺：厂商标签（含数量）+ 用途 Tabs + 关键词 + 客户端分页；卡片与详情抽屉整体复用《模型目录卡片化与详情抽屉设计》的已实施成果（`modelPriceSlots`/`formatSpec`/`catalogDisplay` 抽屉渲染/复制/焦点归还），卡片增加供应商徽标。
3. 维护能力搬进广场，**逐行沿用现有后端写接口与权限**（`canMutateModel` 口径不变）：用户可新增/编辑/删除自己的个人模型（新增时先选供应商）；管理员可维护全部（内置模型改配、草稿、全局模型）并按归属筛选。
4. 供应商目录弹窗（`ProviderModelCatalogModal.vue`）及 ProvidersView 的模型态接线退役；`/providers` 页保留供应商管理本体，原「查看模型」入口改为跳转管理面广场并预选该供应商。
5. 后端仅**新增**一个聚合读接口；写接口（POST/PATCH/DELETE `/providers/{code}/models`）零变更。

### 非目标

1. 不改任何写接口契约、不改 `canMutateModel` 权限语义、不做服务端分页（目录规模 213 内置行 + custom，见 §5.3）。
2. 不做 DeepSeek 时段价、不动 `/providers/models/options` 账户域链路、不动 aipublic 公开面。
3. 不新增定时轮询；广场数据为进入页面时一次加载 + 变更后重载 + 手动刷新。
4. `providerModelFormatters.ts` 等既有文件**位置不迁移**（回归脚本与引用面已稳定，避免无谓 churn）。

## 3. 后端契约：聚合读接口

### 3.1 端点

`GET /__aisys__/api/providers/models/plaza`，挂现有 `read = RequireSession(false)` 中间件（与 `/providers/models/options` 同族）。查询参数：

| 参数 | 语义 |
| --- | --- |
| `viewScope=admin` | 管理面请求（单值 + admin 角色判定，复用 `isManagementProviderRequest`，routes.go:65-72） |
| `systemAccountId` | 仅 admin 生效：按归属过滤（`all` 视为空）；非 admin 恒 pin 到自己（`requestSystemAccountID` 现语义，routes.go:82-97） |

不设 `includeInactive`/`includeUnpriced` 参数：现弹窗两参恒为 `true`（ProvidersView.vue:781-786，用户与管理面同口径，草稿/无价行以状态徽标区分），广场保持差异=0。

### 3.2 响应

```json
{
  "providers": [
    { "code": "gpt", "name": "OpenAI", "enabled": true, "defaultHealthCheckModel": "gpt-5.2" }
  ],
  "items": [ { "providerCode": "gpt", "model": "…", "scope": "builtin|global|personal", "…ModelCatalogItem 全字段…": "…" } ]
}
```

- `providers`：本次窗口涉及的供应商摘要（code/name/enabled/defaultHealthCheckModel），数据源即 `GET /providers/list` 的 `ListCatalogListItems`（store.go:191-224，登录即可访问；管理面多含 disabled 供应商，卡片据此灰显）。
- `items`：逐供应商沿用现有 `ListProviderModelsForRequest` 的窗口与合并语义（同供应商内 personal > global > builtin 按裸 model 名合并、`isSupportedCatalogModel` 过滤、release date desc → catalogOrder → model 排序），**跨供应商不合并**——同名模型在不同供应商是不同卡片（价格与归属各自独立）；供应商按启用注册表顺序拼接。实现上把 `listBuiltInCatalogModels`/`listCustomModelRows` 的 `vendor_code IN (...)` 窗口扩为全部启用 vendor 单查询（无 N+1，catalog.go:283-286、442-443），每行照常挂 `catalogDisplay`（buildProviderCatalogDisplay 按行自分派）。
- 管理面窗口含 disabled 供应商的行（用户面仅 enabled 供应商）；`catalogVisible=false` 的 builtin 行管理面可见、用户面不可见（现 SQL 谓词不变，catalog.go:275-281）。
- 体积量级：213 内置行 ≈ 320-530 KB 未压缩（gzip 约 1/5-1/8），一次性加载，客户端过滤分页。**不做服务端分页**；若未来目录规模量级增长再立项服务端分页。

### 3.3 写接口复用表（零变更）

| 操作 | 调用 | 权限（现契约不变） |
| --- | --- | --- |
| 新增 | `POST /providers/{code}/models` | 用户 scope 强制 personal、归属 pin 自己；global 需 admin（write_routes.go:605-620） |
| 编辑 custom | `PATCH /providers/{code}/models/{modelId}` | personal 行 owner 本人或 admin（`canMutateCustomModel`）；乐观锁 `expectedUpdatedAt` |
| 编辑 builtin | 同上（builtin fork） | admin-only（write_handlers.go:119-122） |
| 删除 | `DELETE /providers/{code}/models/{modelId}` | custom only；AI 账户绑定 guard 409 |

## 4. 前端契约：广场页

### 4.1 结构（自上而下）

```
PPageHeader「模型广场」  描述 + [手动刷新]  （管理面另有：归属筛选 SystemPrincipalSelect）
状态行：共 N 个模型 · 供应商 M 家（管理面含归属与状态说明）
厂商标签（pill，全部 + 各供应商带数量，portal 同款交互；管理面 disabled 供应商灰显标签）
用途 Tabs（text/image/audio/video，复用 buildModelCategoryTabs，含计数）
工具行：关键词搜索 ｜（用户面）「添加模型」按钮 ｜ USD 结算标识
卡片网格（复用已实施卡片：minmax(280px,1fr)、网格区内部滚动、≤767px 单列）
分页（客户端 24/48/96，筛选/切 Tab/pageSize 变更回第 1 页，越界收敛）
详情抽屉（复用已实施抽屉契约：Hero / 计费与规格 / 接入信息 / 按行权限操作区）
```

### 4.2 卡片增补（相对已实施卡片仅一处）

1. **供应商徽标**：卡片徽标行首位加供应商徽标（`ProviderIcon` + name，数据来自 `providers` 摘要），抽屉 Hero 同步。
2. **内部机制徽标不展示**（2026-10-28 用户裁决）：内置来源徽标（`scope === 'built_in'`）与默认检查徽标（`defaultHealthCheckModel` 属后端探针内部机制）均不上卡面与抽屉；范围徽标仅在自定义模型（`global` / `personal`）时显示，供用户区分自己的模型与全局模型。

其余（模型 ID 行/复制、服务档位∩徽标、价格三槽 `modelPriceSlots`、容量行、状态/将停用、操作区按行权限 `rowActions(record)` 渲染）照搬已实施契约，不重复定义。

### 4.3 维护能力（两角色同一套交互）

| 能力 | 用户面 | 管理面 |
| --- | --- | --- |
| 添加模型 | 「添加模型」→ 弹窗内第一步选供应商（enabled 列表）→ 现有创建表单（scope 固定 personal、归属自己） | 同入口；表单内 scope 可选 global/personal（global 需 admin，现表单已有该字段） |
| 编辑 | 自己的 personal 行（含表单内改价、模板套用） | 全部行（builtin 走改配 fork，含乐观锁基线） |
| 删除 | 自己的 personal 行（绑定 guard 409 原样透出） | 全部 custom 行 |
| 归属筛选 | 无 | `SystemPrincipalSelect`，变更即重载聚合 |
| 草稿/无价行 | 可见（现口径），状态徽标区分 | 同左 |

创建/编辑/删除表单从 ProvidersView 抽取为独立组件 `CustomModelFormModal.vue`（纯逻辑已在 `customProviderModelForm.ts`，UI 模板 + editing refs + 模板 options 计算随迁；模板 options 改从广场 items 按供应商过滤计算，不新增请求）。广场页持有与现 ProvidersView 等价的状态机：编辑基线/乐观锁、`applyProviderModelMutationResult` 就地更新、创建/删除后重载聚合、loading 门控操作区。

**能力声明编辑区（2026-10-30 起，仅 custom 行）**：创建与编辑 custom 行（`global` / `personal`）时，表单新增「能力声明」区——输入模态多选（`inputModalities`）与输出模态多选（`outputModalities`），词表 `text` / `image` / `audio` / `video` / `file`；按已选协议逐协议的工具多选（`supportedToolsByProtocol`：仅为该行 `supportedApiProtocols` 已选协议渲染工具多选行，值 = 工具 token 多选；固定工具词表与校验见 [AI 问答工具体系与主子模型设计](AI问答工具体系与主子模型设计.md) §6.4）。仅 custom 行可编辑：built_in 行改配表单不显示该区、后端亦不接受三键；配置模板复制不携带能力三键；PATCH 语义 = 提交键整值替换、缺键保持（三键留空 = 未声明，沿既有继承/静态兜底语义）。写接口仍为既有 `POST/PATCH /providers/{code}/models`，端点与权限不变，载荷新增能力三键——§2 目标 5 / §3.3 的「零变更」自本批起指端点、权限与权限矩阵不变。列语义与生效优先级见 [供应商与上游协议面重构设计](供应商与上游协议面重构设计.md) §3。

### 4.4 刷新语义

进入页面加载一次；归属筛选变更、创建/删除成功后重载；编辑成功就地更新（现契约）；页头提供手动刷新。不做激活自动刷新与轮询（遵循《动态管理数据刷新与缓存边界设计》与 no-auto-data-refresh 门禁，具体断言随 §6 改写）。

### 4.5 退役清单

| 对象 | 处置 |

| 脚本 | 改写 |

## 6. 验收标准

1. 用户与管理员打开各自菜单的「模型广场」，看到同一交互形态的跨供应商平铺卡片；同名模型在不同供应商各占一卡、价格独立。
2. 厂商标签/用途 Tabs/关键词/（管理面）归属筛选可组合，分页行为符合 §4.1；客户端筛选不发起请求。
3. 用户：添加模型（选供应商 → personal 表单）、编辑/删除自己名下模型全部可用；对内置/他人/全局行无操作入口（逐行权限与现弹窗完全一致）。
4. 管理员：广场内可新增 global/personal、编辑内置改配（乐观锁 409 透出）、删除 custom、按归属筛选、看到 disabled 供应商与草稿行（灰显/徽标区分）。
5. `/providers` 页不再有模型目录弹窗；「查看模型」跳转广场并预选供应商。
6. 卡片与抽屉渲染契约与《模型目录卡片化与详情抽屉设计》一致（价格槽位/单 Token 合并/0 值/锚点价分层/抽屉全分组/焦点归还）。
7. 列出写接口 diff 为空、后端仅新增聚合接口及其测试；§5 六个回归脚本 + 单测 + `vue-tsc` + lint + build 全绿。
8. 文档同步：本文新建并录入 functions/README、《模型目录卡片化与详情抽屉设计》头部标注消费方迁移、待办登记与关闭。
