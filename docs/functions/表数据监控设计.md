# 表数据监控设计

## 目标

表数据监控用于让管理员看到 SQLite 业务库和记录库的容量变化，尽早发现日志、统计、审计或索引异常增长，辅助扩容、清理、VACUUM 或后续分库分表判断。

## 存储边界

- 监控历史写入记录库，不进入业务库。
- 采样表：
  - `database_storage_snapshots`：保存业务库 / 记录库文件大小、WAL / SHM、页大小、页数、空闲页、已用空间、空闲空间、表数量和索引数量。
  - `table_storage_snapshots`：保存每张表的行数、表大小、索引大小、总大小、页数、索引数，以及 1 小时 / 24 小时增长。
- 监控历史默认保留 30 天；这些数据是运维记录，不纳入默认业务备份。

## 采样策略

- 后台 worker 每 5 分钟采样一次，启动后立即执行第一轮。
- 采样只在 worker 进程内执行，Web/API 主进程不注册定时器。
- 表大小优先读取 SQLite `dbstat`，不可用时仍保留行数和文件级指标。
- 普通表行数使用 `COUNT(*)`；FTS5 影子表如 `_data`、`_idx`、`_content`、`_docsize`、`_config` 只记录大小，不做行数统计，避免对日志全文索引产生额外扫描。
- SQLite 使用 WAL 时，读采样不阻塞正常写入；采样仍应保持 5 分钟粒度，不提高到秒级。

## 管理页面

管理员菜单新增 `表监控`：

- 汇总展示业务库和记录库总文件大小、主库大小、WAL 大小、空闲空间和表数量。
- 表格展示库类型、表名、行数、表大小、索引大小、总大小、1 小时增长、24 小时增长和采样时间。
- 支持按业务库 / 记录库筛选和表名搜索。
- 点击表行查看该表最近 24 小时或 3 天的总大小与行数趋势。
- 提供 `立即采样`，用于部署、清理或压缩后的人工确认。

## 口径说明

- `fileBytes` 是 SQLite 主库文件大小，不含 WAL 和 SHM；页面总文件大小会把三者相加。
- `freeBytes` 来自 `freelist_count * page_size`，表示 SQLite 文件内部可复用但尚未归还给文件系统的空闲页。
- 删除大量数据后，`freeBytes` 会升高，但数据库主文件不会自动变小；需要停机后执行 `VACUUM INTO` 并替换文件，才能释放磁盘空间。
- 记录库中的日志、统计、审计和监控历史可丢失；业务恢复默认只依赖业务库和 `backend/.env`。
