# 表数据监控设计

## 目标

表数据监控用于让管理员看到 SQLite 业务库和记录库的容量变化，尽早发现日志、统计、审计或索引异常增长，辅助扩容、清理、VACUUM 或后续分库分表判断。

## 存储边界

- 监控历史写入记录库，不进入业务库。
- 采样表：
  - `database_storage_snapshots`：保存业务库 / 记录库文件大小、WAL / SHM、页大小、页数、空闲页、已用空间、空闲空间、表数量和索引数量。
- `table_storage_snapshots`：保存每张表的可选行数、表大小、索引大小、总大小、页数、索引数，以及 1 小时 / 24 小时增长；后台常规采样默认不统计精确行数，`row_count` 允许为空。
- 监控历史默认保留最近一月；这些数据是运维记录，不纳入默认业务备份。

## 采样策略

- 后台 worker 每 10 分钟采样一次文件级指标，启动后立即执行第一轮。
- 采样只在 worker 进程内执行，Web/API 主进程不注册定时器。
- 表级大小使用游标轮转采样，默认每轮每个库最多刷新 4 张表；不得在常驻 10 分钟任务中对所有表全量 `dbstat` 或对增长表执行精确 `COUNT(*)`。
- 表大小只对本轮选中的表及其索引读取 SQLite `dbstat`；不可用时仍保留文件级指标。
- 行数统计默认关闭，只有显式诊断场景传入 `rowCountMode: 'full'` 时才对本轮选中的普通表执行；FTS5 影子表如 `_data`、`_idx`、`_content`、`_docsize`、`_config` 始终不做行数统计，避免对日志全文索引产生额外扫描。
- SQLite 使用 WAL 时，读采样不阻塞正常写入；采样仍应保持 10 分钟粒度，不提高到秒级。

## 管理页面

管理员菜单新增 `表监控`：

- 汇总展示业务库和记录库总文件大小、主库大小、WAL 大小、空闲空间和表数量。
- 汇总统计展示在表格列表上方，并固定为左侧业务库、右侧记录库；某一侧暂无采样时仍保留位置并显示占位。
- 趋势统计展示为两个独立视图，并固定同一行左侧业务库、右侧记录库；点击业务库表只更新业务库趋势图，点击记录库表只更新记录库趋势图。
- 表格展示每张表在所选时间范围内的最近一次表级快照；不同表的采样时间允许不同，以配合游标轮转采样。
- 页面时间范围默认最近一月，选择粒度精确到日；查询时开始日期按当天 00:00:00、结束日期按当天 23:59:59 覆盖，并同时约束摘要、表格和趋势图。
- 表格展示库类型、表名、行数、表大小、索引大小、总大小、1 小时增长、24 小时增长和采样时间；后台默认采样的行数可能为空，列表只可回退展示所选时间范围内最近一次非空采样值，不在请求时实时 `COUNT(*)`。
- 表格默认每页显示 20 行，允许管理员切换到更大的分页数量。
- 支持表名搜索；不提供固定业务库 / 记录库筛选，库类型直接保留在表格列和摘要卡片中。
- 点击表行查看该表在所选时间范围内的总大小与可用行数趋势；业务库和记录库趋势统计各自独立，时间范围默认最近一月。
- 页面不提供 `立即采样`，采样只由后台 worker 自动执行。
- 页面提供 `usage_records` 使用记录清理入口，管理员选择截止时间后，后端只强制保护最近 1 天；截止时间不能落入最近 24 小时。
- 后端先按 `created_at < cutoffAt` 做有限预检查；没有可清理记录或后台 worker 投递不可用时，不提交后台清理任务，并返回 `queued = false`、`eligibleRows` 和可读原因。
- 预检查确认存在可清理记录后，后端把任务投递给 `recordMaintenanceQueue`，由 worker 按批次删除早于截止时间的事实记录。接口返回 `queued = true`、`jobId`、`submittedAt` 和 `eligibleRows`，实际删除数量以 worker 完成后的记录库状态为准。
- 手动清理不删除系统账户、AI 账户、分组、API Key、授权关系、统计缓存、审计日志或操作日志。

## 口径说明

- `fileBytes` 是 SQLite 主库文件大小，不含 WAL 和 SHM；页面总文件大小会把三者相加。
- `freeBytes` 来自 `freelist_count * page_size`，表示 SQLite 文件内部可复用但尚未归还给文件系统的空闲页。
- 删除大量数据后，`freeBytes` 会升高，但数据库主文件不会自动变小；需要停机后执行 `VACUUM INTO` 并替换文件，才能释放磁盘空间。表监控里的使用记录清理也是同一口径。
- 记录库中的日志、统计、审计和监控历史可丢失；业务恢复默认只依赖业务库和 `backend/.env`。
- `runtime_log_search_data`、`runtime_log_search_idx`、`runtime_log_search_content`、`runtime_log_search_docsize` 和 `runtime_log_search_config` 是 SQLite FTS5 为 `runtime_log_search` 自动维护的影子表；表监控只展示其容量，不提供单独清理入口，清理运行日志索引时必须删除 `runtime_log_search` 主虚表记录并让 SQLite 自动维护影子表。
