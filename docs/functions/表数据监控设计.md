# 表数据监控设计

## 目标

表数据监控用于让管理员看到当前运行模式下事实库和统计库的容量变化，尽早发现日志、审计、usage catalog、统计结果、Responses 桥接状态索引异常增长，辅助扩容、清理、VACUUM 或后续分区判断。standalone 模式监控 SQLite 业务库、数据集目录库、使用记录目录库、统计结果库和可轮询的 usage shard 文件集合；performance 模式监控 PostgreSQL `juhe_business`、`juhe_dataset`、`juhe_usage`、`juhe_stats` 和 `juhe_codex_context` schema，不再读取或展示 SQLite 文件路径。

## 存储边界

- 监控历史写入当前模式的统计结果库：standalone 写入 SQLite 统计结果库，performance 写入 PostgreSQL `juhe_stats` schema。
- 同一运行实例只采一套存储：`JUHE_AI_DATABASE_DRIVER=sqlite` 时采 SQLite 多库，`JUHE_AI_DATABASE_DRIVER=postgres` 时采 PostgreSQL schema，不做 SQLite 与 PostgreSQL 双采样、双展示或回退读取。
- 采样表：
  - `database_storage_snapshots`：保存当前模式下被监控存储角色的主库 / schema 估算大小、页大小、页数、空闲页、已用空间、空闲空间、表数量和索引数量；WAL / SHM 大小字段保留但常规采样不做同步文件 `stat`，PostgreSQL 下无等价字段时保持未知。
- `table_storage_snapshots`：保存每张表的可选行数、表大小、索引大小、总大小、页数、索引数、分区 / 归档状态，以及 1 小时 / 24 小时增长；后台常规采样随表级游标滚动写入本轮 `dbstat` 可推导的行数，`dbstat` 不可用或表类型不适合推导时 `row_count` 允许为空。SQLite `dbstat` 不可用时，大小与页数字段也允许为空，不能回退成 0。
- performance 模式下监控角色映射为 PostgreSQL schema：`business -> juhe_business`、`dataset -> juhe_dataset`、`usage-catalog -> juhe_usage`、`stats -> juhe_stats`、`codex-context-state -> juhe_codex_context`；容量来自 PostgreSQL catalog 函数与统计视图，`database_path` 使用 `postgres:<schema>` 口径。不存在的预留 schema 不能作为固定占位项展示。
- usage shard 文件属于统计数据集存储域的一部分。当前表监控主路径不直接采样 shard 文件集合；后续接入时可以把 shard 文件汇总为独立的 `usage_shards` 逻辑角色，同时保留单个异常 shard 的明细观测，且不能为了精确总行数扫描所有 shard。
- 监控历史默认保留最近一月；这些数据是运维记录，不纳入默认业务备份。

## 采样策略

- 后台 worker 每 10 分钟采样一次文件级指标，启动后立即执行第一轮。
- 采样只在 worker 进程内执行，Web/API 主进程不注册定时器。
- 表级大小和行数使用游标轮转采样，默认每轮每个库 / schema 最多刷新 4 张表；不得在常驻 10 分钟任务中对所有表全量 `dbstat`，也不提供精确 `COUNT(*)` 采样分支。
- 表大小只对本轮选中的表及其索引读取 SQLite `dbstat`；可从 `dbstat` 叶子页 cell 数推导的普通表同步写入 `row_count`，不可用时仍保留文件级指标，并把表级大小与行数字段留空。
- performance 模式表大小读取 `pg_relation_size`、`pg_indexes_size` 和 `pg_total_relation_size`；行数使用 `pg_stat_all_tables.n_live_tup` / `pg_class.reltuples` 估算，不执行 `COUNT(*)`。
- SQLite 使用 WAL 时，读采样不阻塞正常写入；采样仍应保持 10 分钟粒度，不提高到秒级。
- PostgreSQL 采样只读取系统 catalog / 统计视图和 relation size 函数；采样结果、增长计算和表级游标在同一个 PostgreSQL 事务内写入 `juhe_stats`。
- usage shard 采样优先读取 shard catalog、文件 stat 和 writer 运行态快照；只有轮到具体 shard 时才读取该 shard 的有限 `dbstat` 信息。

## 管理页面

管理员菜单新增 `表监控`：

- 汇总展示当前模式监控角色的主库 / schema 估算大小、可用 WAL 大小、空闲空间和表数量；常规采样不为 WAL / SHM 做同步文件系统读取，缺失时按未知展示。
- 汇总统计展示在表格列表上方，standalone 固定为业务库、数据集目录库、使用记录目录库和统计结果库四类，performance 额外展示 Responses 桥接状态索引库；某一类暂无采样时仍保留位置并显示占位。
- 趋势统计按监控角色展示为独立视图；点击某个库 / schema 的表只更新对应趋势图。
- 表格展示每张表在所选时间范围内的最近一次表级快照；不同表的采样时间允许不同，以配合游标轮转采样。概览查询只读取 `database_storage_snapshots` 和 `table_storage_snapshots` 各自的最新窗口，不通过关联查询拼接过期采样值。
- 页面时间范围默认最近一月，选择粒度精确到日；查询时开始日期按当天 00:00:00、结束日期按当天 23:59:59 覆盖，并同时约束摘要、表格和趋势图。
- 表格展示库类型、表名、行数、表大小、索引大小、总大小、1 小时增长、24 小时增长和采样时间；后台默认采样的行数随表游标逐步补齐，`dbstat` 不可用或尚未轮到的表可能为空，列表直接展示当前快照值，不关联过期快照补值，也不在请求时实时 `COUNT(*)`。
- 表格默认每页显示 10 行，允许管理员切换到更大的分页数量。
- 支持表名搜索；不提供固定库类型筛选，库类型直接保留在表格列和摘要卡片中。
- 点击表行查看该表在所选时间范围内的总大小与可用行数趋势；业务库、数据集目录库、使用记录目录库和统计结果库趋势统计各自独立，时间范围默认最近一月。
- 页面不提供 `立即采样`，采样只由后台 worker 自动执行。
- 页面提供非业务数据硬清理入口，管理员选择截止时间后，后端只校验截止时间不能晚于当前时间，不再强制保留最近 1 天。
- 后端把任务投递给 `recordMaintenanceQueue`，由 worker 按批次清理早于截止时间的数据集目录库、使用记录目录库、统计结果库、usage shard 和审计 payload 外部文件；performance 模式清理 `juhe_dataset`、`juhe_usage` 和 `juhe_stats` 内的同类非业务数据。业务库不参与清理，`juhe_codex_context` 继续由 Responses 桥接状态过期清理任务维护。数据集目录库、使用记录目录库和统计结果库的普通表按 schema 动态枚举，只要表内存在可识别时间列就纳入清理。
- 硬清理是管理员应急释放入口，不替代常规保留策略。常规过期治理中，standalone 下 usage 超期数据优先 seal / archive / delete shard 文件；performance 下 `usage_records` 在统计安全游标追平后按整日分区 `DETACH / DROP`，不保留同库冷归档副本。硬清理不等待统计安全游标，也不按业务关联反向扣减统计；确需删除明细行时只能小批次按可识别时间列推进，PG usage 明细必须使用 `(created_at, id)` 命中分区。
- 硬清理覆盖数据集目录库、使用记录目录库和统计结果库内具备时间字段的全部非业务表，包括审计、操作日志、运行日志索引、模型检测、公开接口日志、usage shard 目录、统计缓存、额度窗口、排行 / 范围窗口、系统监控、表监控历史、IP 统计和后台游标 / 扣减账本；新增非业务表只要使用标准时间列命名，也会被该入口自动覆盖。
- 审计 payload 外部文件按 `audit_payload_blobs.created_at < cutoffAt` 删除本地 blob 文件和元数据，不为保留期内数据做关联保护。
- API Key 删除后的记录和统计清理由 API Key 删除流程自动登记并交给后台 worker 重试处理；表监控页面不展示 API Key 删除清理队列，也不提供单独查看或操作入口。
- 后续把 usage shard 文件集合接入表监控后，页面再额外展示 shard 总数、active shard 数、最大 shard 主文件大小、最大 WAL 大小、当天 shard 分布、writer 队列长度、最近 flush 时间和统计延迟；手动清理优先提交 shard seal / delete 任务，而不是在请求链路同步删除明细行。

## 口径说明

- `fileBytes` 是 SQLite `page_size * page_count` 估算的主库大小，不含 WAL 和 SHM；为避免后台 worker 阻塞事件循环，常规采样不同步 `stat` WAL / SHM 文件，相关字段允许为空。
- `freeBytes` 来自 `freelist_count * page_size`，表示 SQLite 文件内部可复用但尚未归还给文件系统的空闲页。
- performance 模式下 `fileBytes` 表示对应 PostgreSQL schema 内普通表 / 分区表 / 物化视图的 `pg_total_relation_size` 汇总，`pageSize` 来自 PostgreSQL `block_size`，`pageCount` 为总大小按 block size 估算；表级快照通过 `pg_inherits` 标记分区父表 / 子表，不再采样同库冷归档 schema；`freelistCount`、`freeBytes`、WAL / SHM 字段没有 SQLite 等价口径，保持未知。
- standalone 删除大量数据后，`freeBytes` 会升高，但 SQLite 主文件不会自动变小；需要停机后执行 `VACUUM INTO` 并替换文件，才能释放磁盘空间。performance 下空间回收遵循 PostgreSQL autovacuum / VACUUM 与表膨胀口径，表监控只展示 relation size 变化，不把 `freeBytes` 伪造成 SQLite 等价字段。usage shard 和审计 payload 外部文件被物理删除后会直接归还对应文件占用。
- 数据集目录库中的日志、审计和明细事实可丢失或按保留期清理；使用记录目录库中的 usage shard 定位关系可重建；统计结果库中的统计缓存和监控历史可重建；业务恢复默认只依赖业务库和 `backend/.env`。
- 日志搜索不维护额外回填型搜索影子表；操作日志摘要词项随操作日志写入同步生成并随保留期清理。数据集目录库、使用记录目录库和统计结果库新增表必须是表监控可观测、统一保留期可清理的普通表，长期保留表需要在存储文档中说明理由。
- usage shard 的 `freeBytes` 只解释单个 shard 文件内部可复用空间；超过保留期且统计游标安全的 shard 应优先整文件删除或归档，不把大规模 `DELETE + VACUUM` 作为常规释放空间路径。
