## 接口分层

| 接口层 | 路径 | 身份来源 | 返回风格 | 说明 |
| --- | --- | --- | --- | --- |
| 用户 API | `/__aisys__/api/my-*` | 后台登录态 Cookie | 项目管理 API 结构 | 前端 `我的...` 页面使用，后端强制当前登录用户作用域，忽略 `systemAccountId` 查询。 |
| 管理 API | `/__aisys__/api/*` | 后台登录态 Cookie | 项目管理 API 结构 | 前端管理页面使用，默认需要 `requireAuth`；涉及跨系统账户管理、全局数据或系统配置的接口必须叠加 `requireAdmin`，系统账户写入接口还必须叠加 `requireSuperAdmin`。 |
| 静态帮助页面 | `/__aisys__/help/*` | 后台登录态 Cookie | 静态 HTML | 由主 Web 进程在 `express.static` 前校验登录态；未登录跳转登录页，普通用户访问管理员手册时跳转普通用户手册。 |
| 公开 API | `/__aisys__/health`、`/__aisys__/api/health`、公开品牌设置、登录和验证码 | 无登录态或登录流程 | 项目管理 API 结构 | 只暴露健康检查、未登录所需品牌信息、登录验证码和登录接口。 |
| 运维指标 | `/__aisys__/metrics`（gateway 健康监听 `3306`、jobs 健康监听 `3305`） | 受限观测网络（宿主回环发布 + 既有 SSH 隧道） | Prometheus text exposition（promhttp pull，60s 抓取） | gateway 族：低基数 `juhe_ai_http_requests_total` / duration / in-flight、上游失败分类、首输出耗时、审计与操作日志丢弃计数；jobs 族：任务执行、耗时与最近成功时间戳；标准 `go_*` / `process_*` 由 client_golang 默认收集器提供。不含 URL、ID、追踪号、请求内容或错误正文；部署层必须只回环发布端口，不得加入反代。指标族与部署边界契约见 [Prometheus 指标暴露设计](Prometheus指标暴露设计.md)。（原 Node 兼容族 `juhe_ai_process_*` 等已于 2026-10-14 删除。） |
| 外部集成 API | `/__aipublic__/*` | Bearer 来源 token | 项目管理 API 结构 | 面向允许来源系统的后端服务，不使用后台登录态；当前提供 API Key、路由策略、分组和 AI 账户公开维护接口，以及供应商目录只读同步接口。 |
| 网关 API | `/*`、`/v1/*` | 本地网关 API Key | 协议原生或本地统一错误结构 | 面向 OpenAI 兼容客户端和 Anthropic native 客户端，不使用后台登录态，不返回管理 API 包装；系统前缀 `/__aisys__/*` 除外。 |

后台管理 API 在 `/__aisys__/api` 下有系统设置可配置的粗限流：IP 级读 / 写限流先于 JSON body parser 执行，登录用户级读 / 写限流在 `requireAuth` 之后执行；命中后返回 `429`、中文 `message` 和 `Retry-After`。`/__aisys__/api/health` 与 `/__aisys__/health`（owner 聚合存活探针，503 表示有 owner 组件未运行）不参与该限流。

网关 API 的“OpenAI 兼容”只表示 OpenAI v1 本地入口、认证和基础响应结构尽量兼容 OpenAI 客户端，不表示每种上游账号都支持公开 OpenAI API 全路径。具体能力以各供应商账号接入文档为准：GPT OAuth 使用 Codex adapter；Grok OAuth 只支持 Responses；Anthropic OAuth 使用 Messages Bearer；Gemini Code Assist / Google One 只支持 GenerateContent JSON / SSE 并通过 Cloud Code wrapper；AI Studio 使用 Gemini Developer API native 能力。账户类型或共享协议档案不能替代供应商 driver 的最终能力过滤。

当前后端已挂载 API Key、路由策略、分组和 AI 账户公开维护接口：`GET /__aipublic__/api-key/list`、`GET /__aipublic__/route-strategy/list`、`GET /__aipublic__/group/list`、`GET /__aipublic__/account/list` 以及对应 `POST /add|/update|/del` 写接口，用于外部来源系统对指定系统用户执行受控资源对账、新增、修改和删除。同时已挂载供应商目录只读同步接口：`GET /__aipublic__/provider/list` 和 `GET /__aipublic__/provider/detail`，用于外部来源系统只读同步供应商目录并按 tab 获取详情。`sub2api-lite` 不再提供来源鉴权 demo、IP 维度消耗排行、IP 维度消费聚合、账号维度实际消耗聚合或公益接入信息接口，也不实现公益站用户维度排行榜快照。

供应商认证与协议契约当前包括：xAI API Key 的 Chat / Responses、Responses-only Grok OAuth 和 SSO device flow；Gemini `code_assist|google_one|ai_studio` 三模式 Google OAuth、Code Assist runtime 与原生 Interactions；Anthropic API Key、托管 OAuth 和 Bearer Token 导入。官方 WIF 仍不增加 `workload_identity` 账户类型；资料不完整的 `codex-auto-review` 也不进入 GPT 内置目录和新账户默认支持模型。

## 时间字段契约

- 管理 API、网关 API 和异步任务回执中的绝对时间统一使用 RFC3339；推荐输出 UTC `Z`，也可输出带明确数字偏移的 RFC3339。调用方必须按时间戳解析为同一个瞬时值，不能按字符串中的业务地区猜测时区。
- 后端只负责产生、校验、比较和持久化绝对时间，不把绝对时间改写成展示时区；管理 API 不再把 `createdAt`、`updatedAt`、`lastLoginAt`、`expiresAt`、任务时间等字段输出为 `Asia/Shanghai` 裸 `YYYY-MM-DD HH:mm:ss.SSS`。所有绝对时间输入（包括历史请求或持久化值）都必须携带 `Z` 或明确数字 offset；无 offset 字符串一律拒绝，不提供兼容解析。
- Vue 端按浏览器用户本地时区展示 RFC3339 时间，展示格式变化不得回写 API 值。前端不能把浏览器时区当成业务日历时区，也不能用本地格式字符串参与跨接口比较或超时计算。
- 排班窗口、API Key / AI 账户可用时段、用量统计日界线、日期范围到期日等业务日历继续携带并校验显式 IANA timezone（例如 `Asia/Shanghai`）；日期字段 `YYYY-MM-DD` 只表示该业务日历中的日期，不等同于 UTC 午夜。

## 菜单入口与视图范围

- `super_admin` 和 `admin` 同时拥有用户身份和管理员身份，因此前端提供用户模式和管理模式；左侧菜单只展示当前模式的入口，头部用户下拉提供模式切换。
- 管理角色首次进入默认用户模式；切换后可把菜单模式作为当前浏览器里的个人使用习惯保存，下次登录或访问根路径时沿用上次模式。该偏好只影响前端入口，不改变后端权限。
- 普通用户只显示用户侧入口；管理角色在用户模式的 `我的...` 入口中也只能按当前登录用户查询自己的数据，不能因为角色是管理员就自动进入全局查询范围。
- 管理侧入口必须使用管理员路由和管理员接口能力，例如 `AI 账户管理`、`AI 分组管理`、`API Key 管理`、`模型检测`、`使用记录管理`、`用量统计管理`、`AI性能监控` 和 `统一授权管理` 下的 `统一授权`、`团队消耗明细`、`用户消耗明细`、`授权团队`。
- 用户侧入口必须使用当前用户作用域，例如 `我的 AI 账户`、`我的分组`、`我的 API Key`、`模型检测`、`我的使用记录`、`我的用量`、`任务中心`、`统计概览`、`AI性能监控`，以及 `我的授权` 下的 `授权操作`、`团队消耗明细`、`用户消耗明细`、`我的授权团队`。
- 用户侧页面优先调用 `/__aisys__/api/my-accounts`、`/__aisys__/api/my-groups`、`/__aisys__/api/my-api-keys`、`/__aisys__/api/my-model-checks`、`/__aisys__/api/my-authorizations`、`/__aisys__/api/my-openai-oauth`、`/__aisys__/api/my-usage-records`、`/__aisys__/api/my-media-jobs`、`/__aisys__/api/my-stats` 和 `/__aisys__/api/my-teams`；用户侧 `我的授权` 下的消耗明细调用 `/__aisys__/api/my-authorizations/usage/team-details` 和 `/__aisys__/api/my-authorizations/usage/user-details`，`统计概览` 使用 `/__aisys__/api/my-stats/usage-overview`，用户侧 `AI性能监控` 使用 `/__aisys__/api/my-stats/ai-performance`。
- AI 问答使用 `/__aisys__/api/my-chat/*` 登录用户接口。会话列表、消息游标、模型选项、发送 SSE、停止和删除都强制使用当前 session 的 `systemAccountId`，忽略或拒绝客户端提交的用户 ID；管理员从个人入口调用时同样不能查看其他用户聊天。会话唯一绑定一个 AI 账户（2026-09-28 起，旧 `api_key` / `group` 绑定模式退场，存量旧模式会话迁移归档只读）：`POST /my-chat/conversations` 免请求体直接创建空会话；`PATCH /my-chat/conversations/{id}` 携带 `accountId` 写入/切换绑定账户——未锁定空会话可自由切换，首轮接受并提交后账户与模型一并锁定，实际改变或清空 `accountId` 返回 409 `chat_conversation_locked`，换模型发送返回 400 `chat_model_locked`（2026-10-12，PLAN-20261012T121500000Z（已清理，git 历史可溯））；未绑定账户发送返回 400 `chat_account_required`，归档会话的发送与绑定修改返回 403。鉴权主体由服务端幂等确保为该用户唯一 `purpose=chat` 专用对话 Key——仅承载 Bearer 鉴权、额度与计费归属，不参与调度与模型作用域。账户候选下拉读 `/__aisys__/api/my-chat/accounts`（登录用户数据范围内全部可派发账户；范围按角色两档：普通用户仅见自有或被授权的启用账户，`admin`/`super_admin` 见全量启用号池）。会话经网关进程内未导出 context 的调度覆盖收敛派发到绑定账户，不新增任何对外 header 或请求参数，外部 HTTP 请求无法指定调度目标。
- `/__aisys__/api/my-chat/conversations/:id/stream` 使用真实会话绑定 API Key 进入按绑定账户供应商主推协议入口（`/v1/chat/completions` 或 `/v1/responses`，anthropic/gemini 经既有桥接），但仍属于登录态用户接口；同会话只允许一个活动轮次，不同会话可并发。容量超限只禁止新发送，读取、停止与删除保持可用。
- 用户侧页面如果需要表单下拉或辅助目录，只能调用用户侧接口或明确允许登录用户访问的轻量辅助接口，例如 `/__aisys__/api/my-ui-bootstrap/options`、`/__aisys__/api/my-accounts/options`、`/__aisys__/api/my-groups/options`、`/__aisys__/api/my-route-strategies/options`、`/__aisys__/api/my-authorization-options/*`、`/__aisys__/api/providers/:code/models`、`/__aisys__/api/providers/models/options`、`/__aisys__/api/providers/models/options/provider-codes` 和 `/__aisys__/api/proxies/options`；新增此类调用必须同步纳入 `pnpm --filter juhe-ai-frontend test:api-contract` 的前端调用面 ⊆ Go 路由注册面静态固定；普通用户可访问性与 `my-*` 命名空间下管理员例外的 403 边界由 Go 侧各域授权与挂载测试固定（gateway `go test`）。`my-ui-bootstrap/options` 只返回当前登录用户的稳定默认资源引用；`my-authorization-options/grantee-groups` 只返回指定被授权用户可作为授权账户目标绑定的分组最小摘要，不返回分组成员、用量或并发信息。
- `GET /__aisys__/api/media-jobs`（M2 媒体任务列表，requireAdmin，只读无写端点）：查询参数 `limit`（默认 20，上限 100，非法回落默认）/`offset`/`status`/`kind`/`api_key_id`/`account_id`/`system_account_id`（可选，按任务归属 API Key 的属主用户过滤，2026-10-17 增补）；响应 `{data:{rows,total}}`，行字段 `{id,kind,status,providerCode,providerJobId,model,promptSummary(截断 120 字符),seconds,size,apiKeyId,accountId,createdAt,updatedAt,costUsd,error{code,message}}`（error 仅终态错误行携带）。
- `GET /__aisys__/api/media-jobs/{id}`（媒体任务详情，2026-10-17 增补，requireAdmin，只读）：响应 `{data:{...}}` 为单行全量对象，字段与列表行同形的 `id/kind/status/providerCode/providerJobId/model/seconds/size/apiKeyId/accountId/createdAt/updatedAt/costUsd/error` 之外补 `prompt`（全文，取代列表行的 promptSummary 截断——详情行不含 promptSummary）、`n`/`language`/`providerOptionsApplied`、`artifact{contentUrl,expiresAt}`（零资源存储定位指针，可能已过期，非终态或缺省省略）、`usage{outputVideoSeconds,audioInputSeconds,raw}`、`paramsApplied`/`paramsIgnored`；未命中 404 `媒体任务不存在`。
- `GET /__aisys__/api/my-media-jobs` 与 `GET /__aisys__/api/my-media-jobs/{id}`（媒体任务用户面，2026-10-17 增补，RequireSession 任意登录角色，只读无写端点）：列表查询参数 `limit`/`offset`/`status`/`kind`/`api_key_id` 同管理面语义（无 `system_account_id`——归属恒钉死当前登录用户，经 `media_jobs.api_key_id → api_keys.system_account_id = 调用者` 收敛，只能看到自己名下任务）。行/详情字段与管理面同形，但**不透出 `providerJobId`**（上游任务号为平台内部信息），`accountId`（命中账户）与 `costUsd` 可见——与 `/my-usage-records` 口径一致；详情未命中或跨属主统一 404 `媒体任务不存在`（不泄露存在性）。管理面两个端点（列表/详情）不变，仍为 requireAdmin 全量面。
- 管理侧页面保留 `/__aisys__/api/accounts`、`/__aisys__/api/groups`、`/__aisys__/api/api-keys`、`/__aisys__/api/model-checks`、`/__aisys__/api/authorizations`、`/__aisys__/api/openai-oauth`、`/__aisys__/api/usage-records`、`/__aisys__/api/stats`、`/__aisys__/api/media-jobs` 等管理入口；`/__aisys__/api/stats/ai-performance` 与 `/__aisys__/api/stats/ai-performance/accounts` 是管理侧监控入口，并由后端显式校验管理员身份。AI 账户能力域拆分 M3 起，有账户维度的统计读面支持可选 `domain` 查询参数（`chat` / `video` / `audio` / `image`；`all` 与空缺省一致表示不过滤，其他值按各端点既有参数错误语义返回 400）：`/stats/account-usage` 与 `/my-stats/account-usage`（列表主查询与 `accountIds` 选中账户按域收敛，与 `keyword` 取 AND 交集）、`/stats/account-usage/options`（候选下拉）、`/stats/ai-performance` 与 `/my-stats/ai-performance`（base/series/accounts 三端点共用的账户水合查询）、`/stats/ai-health` 与 `/my-stats/ai-health`（账户列表）；管理面与用户面同规则，筛选一律服务端执行。统计读面为只读查询，不触碰 usage 记录链；`/stats/usage-overview/*` 为系统级预聚合窗口（无账户维度），不提供域筛选。（原 `/stats/system-metrics/*` 6 条读接口与 [系统指标统计设计] 页面已于 2026-10-14 下线，进程监控走 Prometheus，见 [Prometheus 指标暴露设计](Prometheus指标暴露设计.md)。）
- 后台任务执行历史（`background_task_runs`）基础设施保留（任务对账与告警数据面）；原读取路由 `GET /__aisys__/api/stats/system-metrics/runtime/jobs` 已随 2026-10-14 监控改造删除，任务运行与停摆改由 Prometheus 指标 `juhe_ai_jobs_task_runs_total` / `juhe_ai_jobs_task_run_duration_seconds` / `juhe_ai_jobs_task_last_success_timestamp_seconds` 表达。jobs `/health`（`JUHE_AI_JOBS_HEALTH_LISTEN_ADDRESS`，缺省 `127.0.0.1:3305`）继续承载 owner readiness 与 `/__aisys__/metrics`，其载荷中 tableMonitor 就绪项已删除。
- 管理侧列表、详情、筛选选项和已有资源操作未传 `systemAccountId` 时表示管理员全局作用域；传入具体 `systemAccountId` 时收窄到该系统账户。新建、导入、OAuth 创建这类需要写入新资源归属的动作仍必须明确目标系统账户，不能把全局作用域当作默认归属。
- 系统账户管理是管理角色唯一的差异点：`GET /__aisys__/api/system-accounts` 和 `GET /__aisys__/api/system-accounts/options` 允许 `super_admin` / `admin` 查看；`POST /__aisys__/api/system-accounts`、`PATCH /__aisys__/api/system-accounts/:id` 只允许 `super_admin`，普通管理员必须返回 403。默认仅 `admin/admin` 是 `super_admin`；系统账户写入接口只允许提交 `admin` / `user` 角色，不能新增或升级其他 `super_admin`。
- 同一 Vue 页面可以复用，但系统账户筛选、系统账户列、全量管理接口和跨用户查询只能在管理侧入口启用。

## 管理 API 响应

当前实现已使用 `backend/src/shared/http.ts` 的 `ok(data, message?)` 和 `badRequest(message)` 作为基础约定。后续新增接口优先沿用以下结构。

成功响应：

```json
{
  "data": {},
  "message": "可选中文提示"
}
```

错误响应：

```json
{
  "message": "中文错误提示",
  "code": "可选稳定错误码",
  "details": {}
}
```

约定：

- 成功响应必须包含 `data`；没有业务返回值时可返回 `{ "data": { "ok": true } }`，删除接口也可以使用 `204 No Content`。
- 系统自身生成、直接通过接口返回或持久化后面向客户端展示的 `message` 必须使用中文；后端内部日志和脚本输出不在本条客户端错误契约范围内。
- 已确认属于上游原始响应、上游 OAuth 错误或显式上游诊断的 `message` 保留原文，不翻译、不脱敏；该例外只能由明确的上游来源标记启用，不能把任意本地 `Error.message` 当作上游错误返回。
- OAuth 标准回调 URL 中的 `error`、`error_description` 是供应商重定向结果，按上游 OAuth 错误处理；数据库、代理解析、运行库和其他未标记异常仍是系统错误，必须走中文提示。
- 只翻译面向人阅读的描述性文案，不翻译机器可读字段或协议值；`code`、`type`、`event`、状态枚举、header、路由路径、SQL 常量、缓存 key、OpenAI / SSE 事件名和数据库字段值必须保持稳定。
- 技术名词可以保留原文并嵌入中文文案，例如 `API Key`、`OAuth`、`Bearer Token`、`Refresh Token`、`access_token`、`HTTP` 和 `SSE`。
- 简单错误可以只返回 `{ "message": "..." }`；需要前端分支处理、脚本识别或跨接口复用的错误必须提供稳定 `code`。
- `details` 只放字段级校验摘要、可安全展示的限制原因或操作上下文，不放敏感凭据、完整请求体、完整上游响应或 token。
- 前端不能通过 HTTP 状态码之外的字段自行推断权限，必须以接口返回和 `permissions` 摘要为准。
- `我的授权` 必须包含当前用户授权出去和授权给当前用户的记录；授权给当前用户但资源不属于当前用户的记录，在授权关系页只提供查看、明细和归还入口，不能展示暂停、回收或修改授权关系配置等管理动作。授权账户自身的现有使用侧调度操作在“我的 AI 账户”账户页按授权实例权限执行；锁死 / 解除锁死及锁死高级参数方案已确定，当前接口尚未提供。

## HTTP 状态

| 状态码 | 使用场景 | 前端处理 |
| --- | --- | --- |
| `200` | 查询、更新、操作成功 | 读取 `data`，必要时展示 `message`。 |
| `201` | 创建成功 | 读取 `data`，创建 API Key 时注意明文只按约定展示。 |
| `202` | 持久异步命令已建立，正在 admission、排队或执行 | 读取 `taskId` 和 `Location`，按 `Retry-After` 查询任务资源，不重复创建命令。 |
| `204` | 删除或无返回内容操作成功 | 不读取 body，直接刷新列表或回到上级页面。 |
| `400` | 参数格式错误、业务输入不合法 | 展示 `message`，表单场景尽量定位字段。 |
| `401` | 未登录、会话过期、网关密钥缺失或无效 | 后台跳转登录；网关返回 OpenAI 兼容错误。 |
| `403` | 已登录但无权限 | 展示无权限提示，不自动重试。 |
| `404` | 资源不存在或当前用户不可见 | 展示不存在或已失效，避免暴露其他用户资源是否存在。 |
| `409` | 名称唯一约束、重复授权、批量编辑乐观版本冲突等 | 展示冲突原因，引导用户更换输入、刷新资源或处理旧关系。 |
| `429` | 后台接口限流、登录限频、上游限流或账号冷却 | 展示冷却或稍后重试信息。 |
| `500` | 未知服务端错误 | 展示通用错误，详细信息只进入安全日志。 |
| `502` | 上游 OAuth、上游模型或代理请求失败 | 系统生成的失败摘要使用中文；明确的上游透传或上游诊断返回上游原文。 |

- 所有 `/__aisys__/api/my-chat/*` 接口都以当前登录 session 的 `systemAccountId` 校验会话、消息、提交事实、上下文和资产归属；管理员从个人入口调用时也不能越权读取或修改他人会话。

## 登录与当前用户接口

- `GET /__aisys__/api/auth/me`：登录用户读取当前会话用户摘要，返回 `id`、`username`、`displayName`、`role` 和有效 `mustChangePassword`；管理员角色始终返回 `false`。Go W3 当前已覆盖该只读端点的 opt-in 实现；它不 touch session。
- `GET /__aisys__/api/auth/profile`：登录用户按当前 session 读取自己的完整安全资料摘要，返回 `id`、`username`、`displayName`、`description`、`role`、`status`、有效 `mustChangePassword`、`imageGenerationEnabled`、`lastLoginAt`、`createdAt` 和 `updatedAt`；不接受账户 ID 或查询范围参数，不返回密码 hash、session token、API Key 或上游凭据。普通用户初始密码未修改时仍允许读取该接口，以便进入个人信息页完成强制改密；Node 和 Go 均已实现同一 self-only 契约。
- `POST /__aisys__/api/auth/logout`：登出当前后台会话；接口允许无 Cookie 或已失效 Cookie 调用，有 `juhe_ai_session` 时按当前 token hash 删除 `system_sessions` 对应行，成功返回 `200 { data: { loggedOut: true } }` 并清除 `juhe_ai_session` Cookie；清 Cookie 的 `Secure` / `SameSite` 必须和登录签发 Cookie 使用同一运行时配置。Go W3 当前已覆盖该当前会话撤销端点的 opt-in 实现；它不 touch session，也不撤销其他会话。
- 项目不提供登录会话列表、登录设备列表、按会话 ID 撤销或远程下线接口；`GET /auth/sessions`、`DELETE /auth/sessions/:id` 及其 Go opt-in 灰度实现已明确撤销，不得作为当前或待接管契约恢复。认证只保留当前用户读取、当前令牌退出、资料修改和改密后的其他令牌安全撤销。
- `PATCH /__aisys__/api/auth/me`：登录用户修改自己的显示名称，只接受 `displayName`；未知字段、缺字段、非字符串和空字符串返回 `400 { message: "用户资料参数无效" }`，包含任何空白字符返回 `400 { message: "显示名称不能包含空格" }`，大小写不敏感重复返回 `409 { message: "用户名称已存在" }`。用户名、角色、状态、图像生成权限和初始改密状态仍只能由系统账户管理或改密流程调整。普通用户初始密码未修改时返回 `403` 和 `must_change_password`。Go W3 当前已覆盖该资料更新端点的 opt-in 实现，并在真实变更时 best-effort 写入 `auth.update_profile` 操作日志；写鉴权会按 60 秒窗口 touch 当前 session。
- `POST /__aisys__/api/auth/change-password`：登录用户修改密码，只接受严格 JSON `{ oldPassword?: string, newPassword: string }`。`newPassword` 必填且至少 4 位，未知字段、非字符串、`null`、`oldPassword=""` 返回 `400 { message: "密码参数无效" }`；新旧密码包含任意空白字符返回 `400 { message: "登录密码不能包含空格" }`。普通用户初始密码强制修改场景可只提交新密码；普通改密和管理员改密必须提交并校验当前密码，缺旧密码返回 `400 { message: "请填写当前密码" }`，旧密码错误返回 `400 { message: "当前密码不正确" }`。成功后写入 Node 兼容 PBKDF2-SHA512 `password_hash`、清除 `mustChangePassword`、只保留当前会话，响应返回完整系统账户摘要但不返回密码 hash。Go W3 当前已覆盖该改密端点的 opt-in 实现；写鉴权会按 60 秒窗口 touch 当前 session。

## 模块操作补充

### 管理接口场景 DTO 通则（Node + Vue）

- 管理列表、编辑基础区、编辑高级区、options、runtime、secret 和 mutation 必须使用各自的白名单 DTO 与 repository 投影；禁止复用宽 `Summary` 后再由 route、sanitizer 或 Vue 丢弃字段。新增字段时必须先证明当前场景有真实消费者，并同步字段契约与回归。
- “前端拿到即可展示”表示 Node 已解析关联名称、有效状态、权限动作和当前列需要的轻量摘要，Vue 不再接收完整领域关联后自行拼装业务事实；它不表示 Node 返回中文标签、颜色或页面格式。稳定枚举、数值和摘要属于接口，本地化文案、颜色和纯展示格式仍由 Vue 负责。
- 写接口只接受当前动作允许且实际变化的字段。Node 必须按字段存在性、归一化后的真实差异和 owner / revision 重新校验，确保请求字段、SQL 更新列、关联表改动、后台任务与缓存失效处于同一作用域；mutation 响应只返回当前页面可合并的最小结果。任何归一化后确实发生的业务配置变化都推进 `configRevision`，同值请求不推进；只有网关身份、调度、连接、额度或健康相关字段才触发对应运行态、探针或缓存副作用，名称、备注等展示字段不得扩大到这些副作用。

### 用户作用域默认资源引用（Node + Vue）

- 本节原「只约束 Node 管理 API 与 Vue 页面、Go 后端不在本次契约范围」的框架表述属历史截面（Node 已于 2026-09-05 归档清零，现行后端为 Go 三项目）；本节接口契约由 Go gateway 管理 API 承接实现，行为口径继续生效。
- `GET /__aisys__/api/my-ui-bootstrap/options` 强制使用当前登录 session 的系统账户；不接受前端扩大 owner 作用域。`GET /__aisys__/api/ui-bootstrap/options?systemAccountId=...` 仅管理员可用，必须显式指定目标系统账户；缺少目标返回 `400`，目标不存在返回 `404`。
- 响应固定为 `{ systemAccountId, providerDefaults, preferredDefaultRouteStrategy? }`。`providerDefaults[]` 每项只包含 `providerCode`、`defaultGroup: { id, name }` 和可选的 `defaultRouteStrategy: { id, name, mode, status }`（Go `uibootstrap` 对每个有默认路由的供应商恒下发；前端当前不读，属契约镜像）；不得混入完整分组、完整路由绑定、permissions、用量、运行态或候选全集。`preferredDefaultRouteStrategy` 由后端按启用 GPT 默认分组及其启用默认路由的稳定顺序选出，Vue 不能从多个 `isDefault` 候选中自行取第一条。
- 这些 ID 是用户作用域数据库事实，不是跨用户编译期常量。Vue 在登录恢复后异步单飞预热内存缓存，缓存键至少区分 viewer、auth revision、self / admin 视图和目标 owner；登出、切换用户、session revision 变化及相关默认资源写入必须失效对应作用域。预热失败不得阻塞弹窗，也不得回退为首开加载完整 options。
- AI 账户创建省略 `groupId` 时，Node 必须在同一 owner、同一 `providerCode` 下解析当前启用默认分组；API Key 创建省略 `routeStrategyId` 时，Node 必须解析 `preferredDefaultRouteStrategy`。显式提交仍按当前 owner、状态和供应商重新校验；前端缓存永远不是写权限或默认资源存在性的最终依据。

### AI 账户

- `POST /__aisys__/api/accounts`、`PATCH /__aisys__/api/accounts/:id`、`PATCH /__aisys__/api/accounts/:id/tags`、用户侧 `my-accounts` 同源接口和 OpenAI OAuth 创建接口支持 `tags: string[]`。单个账户最多 24 个标签，单个标签最长 40 个字符，后端会去空白并按大小写敏感去重；`Prod` 和 `prod` 属于两个不同标签；账户列表和详情在账户摘要中返回 `tags`。Go W2 opt-in 仅覆盖 `PATCH /__aisys__/api/accounts/:id/tags` 和 `PATCH /__aisys__/api/my-accounts/:id/tags` 的独立标签集合替换；不覆盖账户创建 / 编辑请求体 `tags`、OpenAI OAuth 创建和导入确认标签写入。当前 Go PATCH 已 best-effort 写入 operation log，Go operation log 读接口也已补；但独立标签 PATCH 成功响应仍不是完整账号详情契约，且仍缺前端 smoke、生产单 owner 切流和 Node 删除证据，不能作为生产接管或 Node 删除证据。
- `GET /__aisys__/api/accounts` 和用户侧 `my-accounts` 的 `keyword` 只按 AI 账户名称做精确 / 前缀 / 包含匹配；账户名称最长 128 个字符，包含匹配必须由 `account_name_search_terms` 先收敛候选账号 ID，再由 `account_name_search_documents.normalized_name` 校验连续片段，不在 `accounts` 主表执行无界 `%keyword%`。供应商、协议档案、账户类型、分组和标签筛选分别使用 `providerCode`、`providerProtocolProfileId`、`type`、`groupId` 和 `tagIds` 查询参数，`tagIds` 可用英文逗号分隔多个标签 ID，多个标签按命中任一标签筛选；协议档案筛选按账户健康检查连接的 `connection_preset_code` 反解匹配（同一账户的多连接不参与，未注册档案不匹配任何行）。能力域筛选使用 `domain` 查询参数（`chat` / `video` / `audio` / `image`；`all` 与空缺省一致表示不过滤，其他值按既有参数错误语义返回 400，不静默退化为全量列表）。管理侧未传具体 `systemAccountId` 时，分组选项和 `groupId` 筛选按管理员全局可见范围生效；标签字典按系统账户维度维护，前端管理侧仅在选择具体系统账户后提供标签筛选。
- `supportedModels` 的可选值必须来自所属供应商模型目录。写入时后端去重、去空白并校验目录；账户支持模型不能清空。`providerCode=glm` 时只允许选择 GLM 目录模型，不能从 `openai` 聚合目录或 `gpt` 目录借用模型名。
- 智谱 GLM 账户只支持 `type=api_key`；当前页面接入类型分为通用 GLM API Key、GLM Coding Plan Chat Key 和 GLM Coding Anthropic Key，Responses Key 仍处于方案阶段。当前创建、导入预览、导入确认和公开外部账号推送必须提交 `providerProtocolProfileId = profile_glm_general_openai_v1 | profile_glm_coding_openai_v1 | profile_glm_coding_anthropic_v1`；实现 `profile_glm_coding_openai_responses_v1` 并完成模型/探针验收后，才扩展该枚举。接口层只接收显式协议档案字段，不能只靠 `credentials.base_url` 区分通用 GLM API、GLM Coding Chat、GLM Coding Responses 和 GLM Coding Anthropic。GLM OpenAI Chat 档案默认端点能力只包含 Chat JSON/SSE；Responses 档案必须绑定官方 `/api/v1` 并单独声明 Responses JSON/SSE。
- DeepSeek 账户只支持 `type=api_key`；页面接入类型分为 DeepSeek OpenAI API Key 和 DeepSeek Claude Code（Anthropic-compatible）API Key。创建、导入预览、导入确认和公开外部账号推送必须提交 `providerCode = deepseek` 和 `providerProtocolProfileId = profile_deepseek_openai_v1 | profile_deepseek_anthropic_v1`。接口层不能只靠 `credentials.base_url` 猜测档案，也不能接受 DeepSeek OAuth、Refresh Token、Setup Token 或 Claude Code token 字段。OpenAI 档案默认具备 Chat Completions 与 Responses JSON / SSE，目录中的 `deepseek-v4-flash` 与预兼容的 `deepseek-v4-pro` 可承接原生 Responses；不声明 FIM、Chat Prefix beta、Strict Tool Calls beta 或 Anthropic Messages。Anthropic 档案默认只具备 Messages JSON / SSE，不声明 Count Tokens 或 OpenAI Chat。
- Anthropic 账户支持 `type=api_key` 和 Bearer Token 型 `type=oauth`，固定落到 `providerCode=anthropic`、`providerProtocolProfileId=profile_anthropic_anthropic_v1`。`api_key` 账户使用 `credentials.api_key`，`oauth` 账户使用 `credentials.access_token`，两者都可使用 `credentials.base_url` 和 `credentials.supported_endpoint_modes = ['messages_json', 'messages_sse', 'message_token_counting']`。`anthropic-version` 和 `anthropic-beta` 属于客户端请求 header，不作为账号凭据字段；接口层仍不接受 Anthropic Setup Token、WIF、Cookie / sessionKey 或 GPT/Codex OAuth 字段。
- xAI 账户支持 `type=api_key|oauth`，固定落到 `providerCode=xai`、`providerProtocolProfileId=profile_xai_openai_v1`。API Key 默认可用 Chat / Responses；OAuth 固定 `responses_json/responses_sse`。`POST /grok-oauth|my-grok-oauth/auth-url`、`create-from-code`、`create-from-refresh-token`、账户 refresh / reauthorize 提供托管闭环；`POST /grok-oauth|my-grok-oauth/sso-to-oauth` 接受单个或多个 SSO key，最多 3 路并发并返回有序 `created/failed` 逐项结果。SSO key 不得进入响应、账户凭据或操作日志。
- Gemini native 账户支持 `type=api_key|google_oauth`。`GET /gemini-oauth|my-gemini-oauth/capabilities` 返回 `code_assist|google_one|ai_studio` 的 client、redirect、scope 与 endpoint modes；其他 OAuth 创建、刷新和重新授权接口必须提交或继承同一 `oauthType`。Code Assist 缺少 `project_id` 时拒绝，Code Assist / Google One 只允许 GenerateContent JSON / SSE；AI Studio 使用自定义 Client ID / Secret 与 native 能力。`profile_gemini_openai_chat_v1beta` 仍只接受 API Key。
- OpenAI、Anthropic、Gemini 和 Grok 的账户 `refresh-token`、`reauthorize-from-code`、`reauthorize-from-refresh-token` 统一使用专用 OAuth 凭据轮换命令。请求必须携带 `expectedConfigRevision>=1`；Node 只按账户 ID、owner、供应商、协议档案、账户类型和 revision 锁定目标，只读取轮换凭据所需投影，归一化后相同的凭据是 no-op。实际变化只更新凭据密文 / 指纹 / mask、OAuth 到期与 refresh-token 标记、`configRevision` 和 `updatedAt`，必要时推进账户 circuit dispatch revision，并只返回 `{ id, configRevision, updatedAt }` 最小 receipt；不得返回完整账户、凭据、usage 或权限摘要。并发版本冲突返回 `409`，不能用宽账户 PATCH 覆盖。
- AI 账户继续复用现有 `service_tier_override` 和 `reasoning_effort_override` 两项覆盖；字段缺失表示保留客户端值，只有 `service_tier_override=default` 表示使用供应商默认。保存校验只做 token 形状与协议族全集校验：openai 族（gpt/openai/deepseek/glm/xai 等 OpenAI 兼容供应商）思考级别 `none|minimal|low|medium|high|xhigh|max`、服务等级 `default|priority|flex`；anthropic 族思考级别 `low|medium|high|xhigh|max`、不提供服务等级选项；gemini 族思考级别 `minimal|low|medium|high`、服务等级 `default|priority|flex`；不再要求已选支持模型在模型目录声明该值，`default` 恒可保存。后端按账户类型与目标 driver 校验写入；运行时按最终上游模型判断：思考级别向下兼容降级到不高于配置值的最高可用档，无可用档位时保留客户端值；服务等级不降级，`default` 恒删除客户端 `service_tier`，`priority`/`flex` 仅在最终模型声明支持时写入。授权实例只读展示来源覆盖值。Anthropic `speed`、thinking budget、Codex `ultra` 和 Responses Multi-agent Beta 首版只按各自字段保护或专属能力处理，不增加账户覆盖控件。
- 账户创建、编辑、导入和公开外部账号推送可提交 `availabilitySchedule`；为空或 `null` 表示不限制时段。账户计划只影响网关账号候选，不改写账户 `status`，时区跟随系统默认值。
- `POST /__aisys__/api/accounts/export` 和 `POST /__aisys__/api/my-accounts/export` 导出当前作用域内可查看凭据且可编辑的自有 AI 账户，授权账户不导出；管理侧可用 `systemAccountId` 指定目标用户，用户侧忽略 `systemAccountId` 并固定当前登录用户。导出账户必须写回当前 `providerProtocolProfileId`，保证导出的 JSON 再导入时能还原到原协议档案，不能依赖 `base_url`、供应商默认值或历史接入类型字段猜测。
- `POST /__aisys__/api/accounts/import/preview`、`POST /__aisys__/api/accounts/import/confirm` 和用户侧 `my-accounts` 同源接口按当前作用域预览或确认导入；普通用户可导入自己的账户并自动创建缺失分组，但只能复用已启用代理，不能创建新代理。

- `POST /__aisys__/api/accounts/batch-update` 和 `POST /__aisys__/api/my-accounts/batch-update` 是独立批量编辑事务接口。请求包含去重后至少 2 个 `accountIds`、按 `{ enabled, value }` 表达的显式 `updates` 和覆盖全部目标的 `expectedVersions`；字段名必须来自后端白名单，未启用字段保持原值，启用字段直接覆盖。任一账户无权限、属于授权实例、跨作用域、版本冲突或最终配置非法时整批不写；模型与协议字段只允许全部目标具有相同 `providerCode + providerProtocolProfileId + type` 时提交。
- 批量编辑白名单当前包含标签、代理、并发限制、账户优先级、超级优先、降级备用、账户到期时间、可用时间计划、备注、账户错误处理规则、账户响应检查规则，以及同构账户的支持模型、检查模型、模型映射、endpoint modes 和已登记的供应商请求覆盖配置。名称、归属、分组、供应商、协议档案、类型、凭据、Base URL、状态、健康事实、错误、冷却、统计和运行态必须拒绝。事务提交后只对检查模型、支持模型、模型映射、endpoint modes 或代理发生变化的账户投递后台系统检查。
- 打开账户测试弹窗时立即调用 `GET /__aisys__/api/accounts/:id/test-options` 或用户侧同源接口，响应 envelope 的 `data` 为 `Array<{ id, name, testEndpointModes }>`（保持数组，既有调用方零破坏），顶层附加截断元数据（T23，2026-10-20）：`total` 为 `keyword`/`selectedIds` 过滤与去重后、`limit` 截断前的候选总数，`hasMore` = `total` > 实际返回条数；`POST /accounts/test-draft-options` 与用户侧镜像同形。前端以 `hasMore` 元数据判定截断提示（判定口径见 `docs/architecture/frontend/通用组件规范.md` 3.5），接口支持 `keyword`、`limit` 和 `selectedIds`；在首次请求完成前或失败后，测试按钮必须禁用。Node 为每个模型计算账户已启用形态、模型目录协议和有效模型映射的交集，只返回至少一个可测试形态的候选，不返回凭据或原始协议数组。浏览器切换模型必须直接使用该项的 `testEndpointModes` 渲染请求形态，不能为请求形态下拉再发模型 capabilities 请求，也不得把服务端已经过滤的 `selectedIds` 模型用缓存的旧形态插回。映射命中时 source model 仅是客户端键，交集依据映射上游模型声明的目标 endpoint family；上游模型目录不存在或不支持目标 family 时不得宣告或接受该形态。提交测试时后端仍以同一规则重新校验模型和请求形态；模型选项不受账户 `supportedModels` 限制。

- `GET /__aisys__/api/providers/models/options` 返回启用供应商的模型名称选项，响应行携带目录 `mode` 字段（`provider_model_catalog.mode` 词表六值 `chat/responses/embedding/audio/video/image_generation`；custom 行未声明 mode 时省略）。响应 envelope 的 `data` 保持数组（既有调用方零破坏），envelope 顶层附加截断元数据（T25，2026-10-19）：`total` 为当前筛选（`keyword`/`modes`/`systemAccountId` scope，含 `selectedIds` 可见性）下去重后的候选总数（`limit` 截断前），`hasMore` = `total` > 实际返回条数——`selectedIds` 行全部可见、返回条数可超 `limit`，`hasMore` 因此按实际返回条数而非 `limit` 比较；前端以该元数据替代"浏览取数达 50 条"的条数推断（判定口径见 `docs/architecture/frontend/通用组件规范.md` 3.5）。该接口支持 `modes` 查询参数：逗号分隔（亦接受重复参数），按六值词表白名单校验，任一非法值返回 `400`（`modes 必须是 chat、responses、embedding、audio、video 或 image_generation`），大小写不敏感；缺省或空值不过滤（既有调用方零破坏）。命中时内置目录查询按六值词表原样追加 `mode IN (...)` 过滤；自定义目录查询先把白名单翻译成 `custom_provider_models.mode` 的四值 UI 分类词表（`chat`/`responses`→`text`、`image_generation`→`image`、`audio`/`video` 原样；翻译后为空——如 `modes=embedding`——时该子查询恒假）再追加 `mode IN (...)`，custom 空 mode 行自然排除（BUG-0324，2026-10-17：自定义写入链只产出四值词表，v8-C 按六值原样过滤曾使对话/图像类自定义模型在域过滤下拉整表消失；调用方始终传六值白名单，翻译只在服务端）；前端账户模型候选按账户能力域传值（对话域 `chat,responses`、视频域 `video`、音频域 `audio`、图像域 `image_generation`），对话账户据此选不出非对话模型。`POST /__aisys__/api/providers/:code/models` 创建个人或管理员全局自定义模型；`PATCH /__aisys__/api/providers/:code/models/:id` 修改有权限的自定义模型，统一目标还允许管理员用同一路径和模型行 `id` 只更新内置模型价格字段；`DELETE` 只删除有权限的自定义模型。模型 ID 创建后不可修改，提交不同 ID 返回 `400`。`GET /__aisys__/api/providers/models/options/provider-codes`（v8-D 媒体域新建默认供应商收敛，2026-10-15）返回域内在售目录供应商去重编码列表：查询参数 `modes`（必填语义同 `/models/options` 的 `modes` 词表校验，非法值同文案返回 `400`）与可选 `protocol`、`systemAccountId`（个人 custom 行范围规则同 `/models/options`）；口径与 `/models/options` 完全一致（`status=active` + 目录可见 + 未过下线日，内置 `provider_model_catalog` 与自定义 `custom_provider_models` 并集，hybrid 不参与），响应 `{ providerCodes: string[] }`（去重升序）；挂在与 `/models/options` 相同的登录读面。

### AI 分组

- `GET /__aisys__/api/groups` 和用户侧 `my-groups` 同源接口返回当前作用域内自有分组和有效授权给当前作用域的分组。授权分组返回 `accessType=authorized`、来源所有者摘要、授权状态、授权来源摘要和 `permissions`，前端据此展示来源说明、编辑本地使用配置、归还入口和 API Key 绑定能力。
- 授权分组只授予使用权。被授权人可以查看分组基础信息和来源说明，可以让自己的路由策略引用有效授权分组，API Key 仍只绑定该路由策略；被授权人也可以在分组编辑弹窗里调整本地 `enabled`、`groupType` 和 `schedulingPolicy`。这些配置只写入被授权人自己的授权分组使用配置，不修改授权方原分组的名称、供应商、说明、默认标记、分组类型或调度策略。
- `PATCH /__aisys__/api/groups/:id` 在管理员指定 `systemAccountId` 且该用户看到的是授权分组时，只接受 `enabled`、`groupType` 和 `schedulingPolicy`；用户侧 `PATCH /__aisys__/api/my-groups/:id` 同理。分组目标字段不接受 `providerCode`；授权分组编辑不得提交 `name`、`groupKind`、`description` 或成员关系，后端必须重新按当前作用域校验该分组授权仍可见。
- `POST /__aisys__/api/groups` 与 `POST /__aisys__/api/my-groups` 接受可选 `groupKind`（`standard` / `super`，缺省 `standard`）；`groupKind` 创建后不可通过 `PATCH` 修改；超级分组禁止 `isDefault=1`，且不得直接持有 `group_accounts` 行。账户创建显式 `groupId` 指向超级分组、或账户 `PATCH` 换组到超级分组时，统一返回 `400 { code: "group_kind_conflict", message: "超级分组不能直接绑定账户" }`，不得产生 `group_accounts` 行。
- `GET /__aisys__/api/groups/:id/model-options`（管理面）与 `GET /__aisys__/api/my-groups/:id/model-options`（个人面）返回分组内启用账户 `account_supported_models` 的真实 models 行（超级分组取 enabled 成员并集），仅 `{ id, name }`；`keyword` 模糊过滤、`limit` 取值 1..50（缺省 50）。该端点只用于模型参考，空 provider 不得作为通配符，也不得按模型名猜 vendor。
- 超级分组成员关系使用独立接口：`GET|PATCH /__aisys__/api/groups/:id/super-members`（管理面）和 `GET|PATCH /__aisys__/api/my-groups/:id/super-members`（个人面）。GET 响应固定为 `{ data: { superGroupId, groupKind: "super", revision, members: [{ memberGroupId, memberGroupName, priority, enabled, groupEnabled }] } }`；PATCH 请求严格只接受 `{ expectedRevision, members: [{ memberGroupId, priority, enabled }] }`，语义为完整替换，成功返回同一摘要和新 revision，no-op 不推进 revision。`revision` 为分组 `updated_at` 单调毫秒时间戳（不透明字符串），成员变更在同一事务内推进，no-op 不推进。管理面需要 `super_group_members:read/write` 且可指定 `systemAccountId`，个人面固定当前 owner，需要 `my_super_group_members:read/write`。只有超级分组 owner 可写；授权可见但无管理权的分组不能作为成员写入。
- 公开成员更新使用 `POST /__aipublic__/group/super-members/update`，请求严格只接受 `{ targetUsername, superGroupId, expectedRevision, members: [{ memberGroupId, priority, enabled }] }`，需要 scope `juhe_ai_public:group_super_members_update:write`，规则与管理面相同。所有成员写入必须在单事务内完成 owner、`groupKind`、同 `system_account_id`、非嵌套、调度指纹和 20 行上限校验。
- 成员关系错误码固定为 `group_kind_conflict`、`super_group_member_invalid`、`super_group_member_limit`、`super_group_member_owner_mismatch`、`super_group_member_unauthorized`、`super_group_member_nested`、`super_group_member_dispatch_policy_mismatch`、`super_group_member_dispatch_policy_conflict`、`super_group_member_reference_conflict`、`super_group_revision_conflict`。校验错误 HTTP 400、权限 403、不存在 404、引用/CAS 409，错误体固定 `{ code, message }`。
- `DELETE /__aisys__/api/groups/:id` 和用户侧 `my-groups` 删除接口只接受自有分组；授权分组不能被被授权人删除。被授权人不想继续使用个人直授权分组时，必须调用归还接口。
- 管理侧删除在省略 `systemAccountId` 或使用 `all` 时可按全局 owner 作用域处理，指定账户时只能删除该账户自有分组；用户侧始终强制当前登录账户。不存在、越权或授权成员删除返回 `404`，默认分组和会使 active 路由策略失去最后可用分组的删除返回 `400`，成功返回 `204`。
- 分组删除是硬删除。账户绑定、路由策略绑定和授权成员本地使用配置按当前 fresh schema 外键级联；多态授权 source / grant 历史保留。删除请求不因存在账户绑定而拒绝，但必须在事务内按 owner 和全部有效 grantee 作用域检查 active 路由策略，查询固定 `LIMIT 101`，超过 100 条或没有替代可用分组时拒绝。
- 删除事务同时写入 `group_account_stats_dirty`，reason=`group_deleted`；请求路径不实时删除或重算旧统计行。提交后 best-effort 失效 `lookup:group`、`lookup:group-account-ids` 和 gateway runtime，并记录 `groups.delete` 操作日志。
- `POST /__aisys__/api/groups/:id/return-authorization`：管理员按被授权人系统账户作用域代归还个人直授权分组；必须通过 `systemAccountId` 指定被授权人作用域。`POST /__aisys__/api/my-groups/:id/return-authorization`：当前登录用户从分组页归还个人直授权分组。团队来源授权分组或被团队来源覆盖的授权分组不提供个人归还入口。

### 策略路由

- 策略路由管理 / 个人读取由完整列表和详情组成：`GET /__aisys__/api/route-strategies`、`GET /__aisys__/api/my-route-strategies`、`GET /__aisys__/api/route-strategies/:id`、`GET /__aisys__/api/my-route-strategies/:id`。管理侧只允许 `admin` / `super_admin`，未指定 `systemAccountId` 或使用 `all` 时是全局 owner 视图，指定具体 ID 时收窄到该 owner；个人侧强制当前登录账户并忽略伪造的 `systemAccountId`，管理员在用户模式也不能读取全局。
- `GET /__aisys__/api/route-strategies/:id/speed-first-runtime` 与 `GET /__aisys__/api/my-route-strategies/:id/speed-first-runtime` 是同一权限边界下的只读短 TTL 运行态接口；必须先验证该策略在当前管理 / 个人作用域可见，随后返回 `{ routeStrategyId, generatedAt, enabled, runtimeAvailable, degradedCount, items }`。非 `speed_first` 策略返回 `enabled=false`、空 `items`；运行态不可读返回 `runtimeAvailable=false`，不得把不可读解释为零降级。`items` 只能返回账号、策略分组、慢样本、降级 TTL、下次探针、真实请求恢复进度、后台探针窗口和原因，禁止返回 `stateKey`、generation、runtime key 或 claim。
- 列表 `page` 默认 `1`、最小 `1` 且无最大页；`pageSize` 默认 `50`、范围 `1..200`。主查询使用 `pageSize + 1` 判断 `hasMore`，`total = (page - 1) * pageSize + items.length + (hasMore ? 1 : 0)`，不执行精确 `COUNT(*)`，因此 `total` 只是渐进上界。
- 列表 `keyword` 只按策略路由名称做大小写敏感的字面前缀匹配，不搜索说明，`%/_` 不作为通配符。`mode` 只识别四种当前路由模式（`normal` / `weighted` / `failover` / `round_robin`）和 `all`，`status` 只识别 `active/disabled/all`；提交或筛选 `merge` 按未知模式处理，不能返回为当前能力。排序固定为 `updated_at DESC, created_at DESC, id DESC`。
- 管理、个人和公开路由策略新增/修改写入口对未知 mode 或 payload 中的 `merge` / `merge*` 键统一返回 `400 { code: "unsupported_route_mode", message: "不支持的路由模式" }`；该错误不做静默转换。管理/个人入口也必须返回 `code`，不能只返回 `{message}`。
- 列表在同一响应中返回静态字段、管理侧 owner 摘要、四种调度模式（普通 / 权重 / 故障回退 / 轮询）规范化 `normalRoutingConfig`、精确 `bindingCount`、精确 `apiKeyCount` 和最多 3 条 `groupBindingPreview`。若绑定目标为超级分组，预览只返回超级分组摘要，不把成员展开成路由绑定行。仅 `speed_first` 项附加 `speedFirstLatencyRuntime: { runtimeAvailable, degradedCount }`；它由当前页已授权策略 ID 单批读取，不发起逐行查询。真实零值返回 `0`，但只有 `runtimeAvailable=true` 的零值才可解释为当前无速度降级账号（列表正常态不展示常驻“速度正常”文案）；超过单批 50 条速度优先策略或运行态不可用时必须返回 `runtimeAvailable=false`。响应包含 `generatedAt`，列表不返回完整 `groupBindings`。
- 详情必须按单条权限返回完整 `groupBindings`、对应模式完整规范化配置和精确 `apiKeyCount`，不能用列表 preview 代替编辑回填数据。独立 `list-snapshot` HTTP 路由已删除，前端只在进入、翻页、筛选、排序、操作完成或手动刷新时重新请求列表。
- W5 Go 迁移当前仅为 `JUHE_AI_MANAGEMENT_API_ENABLED` 控制的 opt-in 路径。真实 PostgreSQL / HTTP、前端真实 Go 后端 smoke、反向代理单 owner 切流、回滚和 Node 删除证据完成前，不得描述为生产接管；真实依赖测试输出 `SKIP` 不计通过。

**实体与存储契约**

- 表 `scheduling_preferences`：`id TEXT PRIMARY KEY`、`system_account_id TEXT NULL`（内置行为 `NULL`）、`name TEXT NOT NULL`、`chat_mode TEXT NOT NULL CHECK (chat_mode IN ('cost_first','speed_first'))`、`chat_speed_first_config_json TEXT NULL`、`built_in INTEGER NOT NULL DEFAULT 0 CHECK (built_in IN (0,1))`、`created_at TEXT NOT NULL`、`updated_at TEXT NOT NULL`。双方言 `CREATE TABLE IF NOT EXISTS` 条目 + PG 索引独立条目 + 存储形状测试（沿用 media_jobs 形状测试模式；"双方言"为 P1 设计门历史截面，现行 schema 仅 PostgreSQL）。v2 起无启用/停用态（创建即启用），P1 曾交付的 `enabled INTEGER NOT NULL DEFAULT 1` 列与全部读写入口退役；P2 迁移未在任何库执行，schema 随 P2 收尾直接收敛（推荐删列而非保留恒 1，最终列形状以实施为准）。
- 内置行固定为：`id='schpref-builtin-chat-cost-first'`、`name='默认调度偏好'`、`chat_mode='cost_first'`、`built_in=1`、`system_account_id=NULL`、`chat_speed_first_config_json=NULL`（v2 起内置行名固定为「默认调度偏好」；固定 ID 不变——迁移命令、种子、前后端常量与在途引用均锚定该 ID，仅作不透明标识；P1 名称「对话·成本优先」退役）。作为全局只读例外供所有 owner 读取与绑定，不得挂在真实用户名下再按 scope 过滤。由 maintenance `--seed` 幂等建立：固定 ID 恢复式 upsert（`ON CONFLICT(id) DO UPDATE ... WHERE scheduling_preferences.built_in=1`，只恢复内置行权威值，不触碰用户行）；gateway / jobs 不在热路径补种，内置行缺失或结构错误是初始化失败，启动校验报错，不得临时造默认对象掩盖问题。
- 唯一约束：`(system_account_id, name) WHERE built_in=0`（PG 部分唯一索引；双方言时期 SQLite 表达式唯一索引已随 2026-10-25 存储收口退役）限定自定义行 owner 内名称唯一，名称归一化 / 比较复用现有资源名称规则（精确 + 大小写不敏感归一双唯一索引，均挂 `WHERE built_in=0` 条件）；`UNIQUE(id) WHERE built_in=1` 固定内置身份唯一。自定义行必须 `built_in=0` 且 owner 非空；任何写入口不可伪造 `built_in`、不可修改 owner（归属创建后不可变），内置固定 ID 不可被自定义行占用。
- `api_keys` 加列 `scheduling_preference_id TEXT NULL` + 普通索引；列上声明 `REFERENCES scheduling_preferences(id)`（NO ACTION、无级联）仅作 belt（双方言时期 SQLite 运行时 PRAGMA 不保证开启，现行 PostgreSQL 外键默认强制）；存在性与 owner 校验以事务内校验为主。v2 起删除偏好总是成功：服务层在同一事务内先把绑定该偏好的 API Key 重置为内置默认 ID 再删行，数据库 RESTRICT 仅作兜底，不再依赖 409 拒绝（见「端点一览」删除条目）。

**策略路由写入口旧调度字段退场（P2）**

- 适用入口：管理 `POST /__aisys__/api/route-strategies`、`PATCH /__aisys__/api/route-strategies/{id}`；个人 `POST|PATCH /__aisys__/api/my-route-strategies*`；公开 `POST /__aipublic__/route-strategy/add|update`（test-token mock 分支同样拒绝）。

**速度运行态命名空间与查询契约**

- v1（现状，完整保留）：`juhe-ai:{ns}:state:gateway-normal-route-latency-degradation:v1:{systemAccountID}:{routeStrategyID}:{groupID}:{runtimeKey}` 及派生键（generation / all-index / probe-index / mutation-lock / probe-claim）与 state JSON 内嵌 Scope + RuntimeKey + Config 快照结构不变，只服务有效配置来源为策略的 Key（历史 `NULL` 与 `purpose=chat` 沿用现状），既有 Key 不因换键失去慢样本与降级状态。
- v2（新增）：同前缀版本段改为 `v2:{systemAccountID}:{routeStrategyID}:{preferenceID}:{configFingerprint}:{groupID}:{runtimeKey}`，派生键（generation / all-index / probe-index / mutation-lock / probe-claim）按 v2 版本段同构构造；gateway（`gatewayproxyhealth`）与 jobs（`speedfirstrepo`）两侧键构造同步实现。
- `configFingerprint` 为规范化调度参数稳定哈希（sha256）十六进制前 12 位，输入是 `chat_mode` + 上表九字段规范化有效值全集；名称变更不参与指纹（不清空速度状态），参数变更即产生新键；同路由 + 同偏好 + 同参数的多个 Key 共享同一键与恢复计数，不同偏好 / 不同参数不共享。
- 归属规则：有效配置来源为策略 → v1；来源为偏好（含绑定内置成本优先行的 Key）→ v2。成本优先（无论来源）不消费速度降级，不产生降级状态；一般账户健康、熔断、计费与全局并发状态不迁移到偏好维度。
- 清理：按 `routeStrategyID` 的运行态清理（`ClearNormalRouteLatencyDegradationForRouteStrategy` 及 jobs 侧同类）必须同时覆盖 v1 与 v2 中该策略段；偏好参数变更后的旧 v2 键随新键启用自然停写。
- 迟到探针围栏沿用 mutation-lock + generation + `candidateMatchesState`（v2 scope 携带 preferenceID 与指纹），配置变更后旧身份不再用于新请求，迟到探针不能更新新身份。
- 查询契约：`GET /__aisys__/api/route-strategies/{id}/speed-first-runtime` 与个人同源端点同时透出该策略段 v1 + v2 状态；响应包络不变（`{ routeStrategyId, generatedAt, enabled, runtimeAvailable, degradedCount, items }`），`items[]` 每条新增 `source`（`strategy` | `preference`）、`preferenceId`、`preferenceName`（`source=strategy` 时缺席）；同一账号在两个命名空间的条目并存，行复合键为 `source + preferenceId + accountId + dimension` 等字段组合，前端已按并存预设。`degradedCount` 为两命名空间合计；继续禁止返回 `stateKey`、generation 或 claim；owner 权限、批量预算与 `runtimeAvailable=false` 语义不变。

**失效契约**

- API Key 绑定列真实变化：事务提交后必须执行既有 `InvalidateValidation`（reason 沿用 `ReasonAPIKeyUpdated`）；失效最终失败返回 `500 { message: "API Key validation cache 失效失败" }`，已提交的数据库写入不回滚，操作日志按现有失败契约记录。同值 no-op 不 bump `revision`、不失效。额度未变不新增 quota 失效。
- 偏好实体 update（名称 / 形态 / 速度参数；v2 起 `enabled` 退役不再可写）与 delete 成功：提交后发布既有全局网关运行态失效（`topic:gateway_runtime_cache`，与策略路由侧同一机制），使全部绑定 Key 下次加载重建快照；必须核对 topic reason 的实际订阅条件，不得仅凭调用名判定生效。删除不再被 `409` 挡下：事务内重置绑定后照常发布失效，被重置 Key 下次加载按内置默认重建快照，无悬空引用残留。
- 偏好绑定 Key 较多时优先全局 runtime 代际与跨实例 topic，不做逐 Key N+1 失效；数据库提交后失效失败的 HTTP、操作日志与恢复行为沿用现有明确契约，不宣称回滚已提交写入。

### API Key

- `GET /__aisys__/api/api-keys` 和用户侧 `my-api-keys` 返回专用 `ApiKeyListItem`。`keyword` 只按 API Key 名称做精确 / 前缀匹配；Key 前缀、后缀和说明不进入通用搜索，不支持多字段组合关键词搜索。策略路由筛选使用独立 `routeStrategyId`，状态筛选使用独立 `status`。每行只返回 ID / revision、名称 / 说明、前后缀、状态 / 默认用途、到期 / 配额 / 时间计划、策略路由最小摘要、调度偏好最小摘要（`schedulingPreferenceId` / `schedulingPreferenceName` / `schedulingPreferenceBuiltIn`，与公开面 `PublicApiKeySummary` 同形；列表「策略路由」列后展示「调度偏好」列显示偏好名，`purpose=chat` 会话 Key 与内部用途 Key 绑定恒 `NULL` 时显示「-」），以及 `usage: { requestCount, totalTokens, totalCost }`；不得返回 `key`、策略 `groupBindings` 或十余字段通用 usage。个人端不得返回管理 owner 字段。
- CC Switch 导出由前端构造 `ccswitch://v1/import` URL，只要求 endpoint、API Key 与用户明确选择的客户端类型；分组与模型均为可选参考，不得从分组或 vendor 推断客户端。模型候选走分组模型参考端点（`GET /groups/:id/model-options`），不得继续使用 `group.providerCode`。
- API Key 创建成功和刷新密钥响应只在本次返回 `{ id, key, keyPrefix, keySuffix, revision }`。`GET /__aisys__/api/api-keys/:id/secret` 和用户侧同源接口只按单条资源权限查询 `id`、owner、名称、前后缀和密文，响应只返回 `{ key }`；不得关联策略、统计或列表 mapper。所有返回明文密钥的响应都必须 `no-store`。
- 新增弹窗立即打开，省略 `routeStrategyId` 时使用已预热的用户引用仅作回显，最终由 Node 解析当前 preferred 默认策略；只有用户首次展开策略下拉时才加载 route strategy options。编辑直接使用列表行作为 edit seed，并注入当前已选策略；打开编辑不得请求详情或 options。
- `PATCH /__aisys__/api/api-keys/:id` 和用户侧同源接口必须携带 `expectedRevision`，其余只允许出现实际变化的 `name`、`description`、`routeStrategyId`、`status`、`expiresAt`、`quotaLimits` 或 `availabilitySchedule`。Node 在事务内锁定最小行、比较 revision、剔除等值字段并动态生成 `SET`；只有额度或最终有效状态实际变化才同步小时额度窗口，只有影响运行时的字段实际变化才执行相应 gateway / quota 失效。成功响应为 `{ id, revision, changedFields, rowPatch }`，前端合并当前行而不重拉列表；冲突返回 `409` 并携带当前 revision。
- 创建和 PATCH 不得为返回值重新读取完整 `ApiKeySummary` 或访问 usage；相同值 PATCH 返回空 `changedFields` 且不写表、不推进 revision、不失效缓存。完整密钥读取、列表、写入、刷新密钥和删除是不同场景，不能因为共享类型再次合并为宽查询。
- 管理侧 API Key 列表未传具体 `systemAccountId` 时，`routeStrategyId` 可跨全部可管理系统账户匹配策略路由；编辑、启停、删除和读取完整密钥按目标 API Key 自身归属系统账户校验和记录操作范围。
- API Key 创建和编辑只提交 `routeStrategyId`；分组绑定、权重、故障回退和轮询等路由配置在策略路由接口维护，超级分组成员关系在分组成员接口维护，组内调度配置（调度偏好）在调度偏好接口维护并经 `schedulingPreferenceId` 绑定生效（P2 起策略路由接口不再接受调度配置字段，见「策略路由写入口旧调度字段退场（P2）」）。运行时先按 API Key 找到策略路由，再由策略路由选择分组，最后进入分组内账号调度。
- API Key 创建、编辑和公开外部 API Key 推送可提交 `availabilitySchedule`。为空或 `null` 表示不设置计划，继续按 `status` 手动启停；启用时结构为 `{ enabled: true, timezone, mode: 'allow_windows', windows: [{ daysOfWeek, start, end }] }`，其中 `daysOfWeek` 为 `1-7`，`start/end` 为 `HH:mm`。API Key 只有一个可用状态 `status`：创建和编辑计划时按当前时间初始化 `status`；后台任务之后只在开始 / 结束边界继续写 `status`。人工启用 / 停用同样只提交 `status`，不再提交独立的 `availabilityScheduleActive`。接口返回 `availabilitySchedule` 和当前 `status` 供列表展示和编辑回填。计划配置不包含敏感字段。
- `DELETE /__aisys__/api/api-keys/:id` 只允许 `admin` / `super_admin`。省略 `systemAccountId` 或传 `all` 时按全局精确 ID 删除，传一个非空值时收窄到该 owner；空值返回 `400 { message: "系统账号 ID 不能为空" }`，重复参数返回 `400 { message: "Expected string, received array" }`。`DELETE /__aisys__/api/my-api-keys/:id` 强制当前 session 系统账户，忽略伪造或重复 `systemAccountId`。不存在或 owner 不匹配返回 `404 { message: "API Key 不存在" }`，默认 Key 返回 `409 { message: "默认 API Key 不允许删除" }`。
- 两条 API Key DELETE 先进入鉴权前 IP write limiter，再执行管理 API 写鉴权和 session touch、已认证用户 write limiter；管理路由随后叠加 admin role。限流阈值按当前系统设置读取，fresh schema 默认值为 IP write `180/minute`、`40/10 seconds` burst 和已认证用户 write `120/minute`。路由不挂 JSON body parser 和 mutation guard，malformed body 不参与业务解析。成功固定返回 `204 No Content`，body 为空，并设置 `Cache-Control: no-store` 与 `Pragma: no-cache`；未知内部错误只返回 `500 { message: "服务器内部错误" }`。
- API Key 删除在单个 PostgreSQL 事务内按 ID 和可选 owner 执行 `SELECT ... FOR UPDATE OF api_keys`、默认 Key 保护、按实际 owner 硬删除，并 upsert `api_key_record_cleanup_targets`。cleanup target 写入失败必须回滚删除。冲突时只刷新 `system_account_id` 和 `updated_at`，保留 `created_at`、`attempt_count`、`last_attempt_at`、`last_blocked_reason` 和 `last_error_message`；当前表没有 `retry_after` 列。
- API Key 删除请求路径不扫描、聚合或同步删除 usage、audit、runtime log、operation log 等记录明细；只登记 cleanup target，由后台 cleanup worker 后续按目标处理。提交后 validation cache 失效是必需步骤；失败时数据库删除保持提交，HTTP 返回通用 500，并写 `api_keys.delete` operation log 的最终 `status_code=500`。lookup、gateway runtime、quota 失效和一次签名 F4 操作日志提交均为 best-effort；正常删除日志状态为 204。当前没有 validation 失效的持久化重试，生产接管前必须补真实环境告警、风险评估与恢复证据，不能把 cleanup target 当作失效重试队列。
- AI 账户创建、编辑可提交 `availabilitySchedule`；结构与 API Key 时间计划一致，接口返回 `availabilitySchedule` 和当前 `status`，不返回也不接收 `availabilityScheduleActive`。AI 账户只有一个可用控制状态 `status`：创建和编辑计划时按当前时间初始化 `active/disabled`，后台任务之后只在开始 / 结束边界继续写 `status`。人工启用 / 停用同样只提交 `status`，不会再有独立计划状态。账户计划只自动切换 `active <-> disabled`，不能把 `pending_test`、`error`、`rate_limited`、`temporary_unavailable` 等保护状态自动恢复为正常。授权账户的来源账户时间计划通过来源账户 `status` 参与实际可用性判断。

### 外部来源系统鉴权

外部来源系统鉴权用于 `juhe-ai-public-welfare` 等允许来源后端调用 `juhe-ai` 的受保护外部接口。它不使用后台登录 cookie，也不能访问后台管理 API。完整设计见 [外部来源系统鉴权设计](外部来源系统鉴权设计.md)。

- 统一请求头：`Authorization: Bearer <source_token>`。来源系统由 token 唯一定位，后台管理只维护来源名称。
- 来源系统鉴权只认 `Authorization: Bearer <source_token>`；其他来源标识头不参与当前契约。
- `GET /__aipublic__/group/list`：分页读取指定系统用户的分组脱敏摘要，支持 `targetUsername`、`groupKind`、`keyword`、`page` 和 `pageSize`；不接受 `providerCode`，提交该参数返回 `400 legacy_group_provider_field`；需要 scope `juhe_ai_public:group_list:read`。
- `GET /__aipublic__/api-key/list`：分页读取指定系统用户的 API Key 脱敏摘要和策略路由摘要，支持 `targetUsername`、`keyword`、`status`、`routeStrategyId`、`page` 和 `pageSize`；`routeStrategyId` 按 API Key 绑定的策略路由 ID 筛选；不返回明文 `key`；需要 scope `juhe_ai_public:api_key_list:read`。
- `GET /__aipublic__/route-strategy/list`：分页读取指定系统用户的路由策略摘要，支持 `targetUsername`、`keyword`、`mode`、`status`、`page` 和 `pageSize`；返回分组绑定摘要和路由模式，不返回账号凭据；需要 scope `juhe_ai_public:route_strategy_list:read`。
- `GET /__aipublic__/account/list`：分页读取指定系统用户的 AI 账户脱敏摘要，支持 `targetUsername`、`targetGroupName + providerCode + providerProtocolProfileId`、`groupId`、`keyword`、`type`、`status`、`schedulable`、`page` 和 `pageSize`；响应返回只读 `clientCompatibility` 作为内部派生能力摘要；不返回上游凭据或外部来源系统业务主键，列表中的本系统 `account.id` 可用于后续修改 / 删除；需要 scope `juhe_ai_public:account_list:read`。
- `GET /__aipublic__/provider/list`：分页读取启用中的供应商目录；需要 scope `juhe_ai_public:provider_list:read`。
- `GET /__aipublic__/provider/detail`：按 code 读取供应商详情，tab=basic 返回基本信息与协议档案，tab=models 返回模型目录（支持分类筛选与分页）；需要 scope `juhe_ai_public:provider_detail:read`。
- `POST /__aipublic__/group/add|update|del`：分组新增、修改和删除；新增按 `targetUsername` 定位或自动创建目标用户，修改和删除按 `groupId` 定位，修改至少提交一个变更字段，`targetUsername` 只作为可选归属校验；普通分组创建可提交 `groupKind=standard`，超级分组创建可提交 `groupKind=super` 但成员必须通过专用成员接口维护；新增严格拒绝 `providerCode`，修改将该字段作为历史兼容入参接受但忽略（分组目标已无供应商维度）。分别需要 scope `juhe_ai_public:group_add:write`、`juhe_ai_public:group_update:write`、`juhe_ai_public:group_delete:write`。
- `POST /__aipublic__/api-key/add|update|del`：API Key 新增、修改和删除；新增响应只在本次返回明文 `key`，修改和删除按 `apiKeyId` 定位，修改至少提交一个变更字段且不返回明文密钥，`targetUsername` 只作为可选归属校验；分别需要 scope `juhe_ai_public:api_key_add:write`、`juhe_ai_public:api_key_update:write`、`juhe_ai_public:api_key_delete:write`。
- `POST /__aipublic__/route-strategy/add|update|del`：路由策略新增、修改和删除；新增按 `targetUsername` 定位目标用户，普通路由只能绑定一个分组，其他模式可维护分组绑定、权重、故障回退和轮询配置；超级分组成员通过分组接口维护，路由策略不接收 `merge` 或成员展开配置；旧 `merge` payload 显式返回 HTTP 400 `unsupported_route_mode`，不得静默转换；P2 起 payload `normalRoutingConfig` 携带旧调度字段显式 `400`（见「策略路由写入口旧调度字段退场（P2）」）；修改和删除按 `routeStrategyId` 定位，默认路由或已被 API Key 使用的路由策略不能删除；分别需要 scope `juhe_ai_public:route_strategy_add:write`、`juhe_ai_public:route_strategy_update:write`、`juhe_ai_public:route_strategy_delete:write`。
- `POST /__aipublic__/account/add|update|del`：账号新增、修改和删除；账号新增可自动创建目标用户和目标分组，只创建资源并返回本系统 `account.id`，重复时返回冲突；公开账号写接口不接收账号级 `clientCompatibility`，Codex / OpenAI-compatible / Anthropic / Gemini 等客户端画像由网关内部识别，跨协议桥接后续统一落到混合供应商账户配置；账号修改必须使用 `accountId` 精确定位，并至少提交一个变更字段，支持只更新 `apiKey`、`baseUrl`、`status` 等单个字段，未提交字段保留原值；账号删除按 `accountId` 定位，可选目标用户、分组、供应商和协议档案只作防误删校验；修改找不到时返回 `404`，删除找不到时幂等返回 `action=not_found`；账号新增 / 修改 / 删除只支持 `type=api_key` 账户，响应不返回上游凭据明文；上游凭据在后端可逆加密保存并保留凭据指纹，不能按本地 API Key 的 hash-only 方式处理；Go 公开账户新增和修改与 Node 共用 `JUHE_AI_UPSTREAM_BASE_URL_PRIVATE_ALLOWLIST` 语义，默认空且仅按 `scheme + IP + effective port` 精确放行，不接受 host 级或路径级扩大；分别需要 scope `juhe_ai_public:account_add:write`、`juhe_ai_public:account_update:write`、`juhe_ai_public:account_delete:write`。
- `GET /__aisys__/api/external-integration-sources/api-docs`：管理员读取公开接口手册，返回接口名称、路径、方法、请求头、query、请求体和响应示例；不返回内置测试 Token 明文。前端用于文档弹窗、模糊搜索和 curl 复制，curl 示例统一使用 `<source_token>` 占位符。
- `GET /__aisys__/api/external-integration-sources`：管理员查看来源系统列表，支持名称搜索、状态筛选、分页；返回来源系统启停、到期时间、授权能力、限频规则和 token 安全标识摘要。
- `POST /__aisys__/api/external-integration-sources`、`PATCH /__aisys__/api/external-integration-sources/:id`、`DELETE /__aisys__/api/external-integration-sources/:id`：管理员创建、更新或删除来源授权，支持 `status`、`scopes`、`expiresAt`、`rateLimits` 和备注；PATCH 和 DELETE 都必须提交 `expectedUpdatedAt`，DELETE 在同一事务内以 `id + updated_at` 做 CAS，陈旧页面返回 `409` 且不得删除后来更新的来源或其 token。创建时直接生成一个生产 token，创建响应返回完整 token；删除来源授权会同时删除关联 token 摘要和密文，原 Bearer token 立即失效。`targetUsername` 是公开资源接口的业务目标参数，不再通过来源授权白名单控制。
- `POST /__aisys__/api/external-integration-sources/:id/tokens`：管理员为来源系统生成 token，创建响应返回完整 token；`GET /__aisys__/api/external-integration-sources/:id/tokens/:tokenId/secret` 按单条 token 返回完整 token，用于后台复制。
- `PATCH /__aisys__/api/external-integration-sources/:id/tokens/:tokenId`：管理员更新 token 名称、状态、scope 和到期时间。
- 每个公开接口都是独立资源 scope。API Key、路由策略、分组和账号的每个列表 / 新增 / 修改 / 删除接口都必须分别授权；scope 不足返回 `403 external_source_scope_forbidden`。
- 来源系统限频只作用于 `/__aipublic__` 公开接口前缀，空规则表示不限制；例如可配置 `60s/10次` 和 `10s/3次`。
- 缺少 Bearer token 返回 `401 external_source_token_missing`；来源或 token 不匹配返回 `401 external_source_unauthorized`；来源停用返回 `403 external_source_disabled`；来源过期返回 `403 external_source_expired`；token 不可用或过期返回 `401 external_source_token_unavailable`；scope 不足返回 `403 external_source_scope_forbidden`；超过限频返回 `429 external_source_rate_limited`。
- 外部来源 token 调用其他后台接口仍按后台登录态处理，例如 `/__aisys__/api/accounts` 没有登录 cookie 时返回 `401`。

### IP管理

IP管理属于系统运维能力，只允许管理员访问。它提供 `sub2api-lite` 自身按来源 IP 维度的聚合事实和封禁策略，不维护公益站用户、IP 与业务身份之间的关系。

- `GET /__aisys__/api/ip-stats`：管理员读取 IP 管理列表，支持 `page`、`pageSize`、`keyword`、`status=all|normal|blacklisted`、`startDate`、`endDate`、`sortField=requestCount|successCount|errorCount|errorRate|totalTokens|totalCost|activeDays|lastUsedAt`、`sortOrder=asc|desc`，默认 `requestCount desc`。`startDate/endDate` 表示 IP 用量统计范围，管理页默认近 7 天，只能切换今天、近 7 天、近 31 天，不再提供自定义日期筛选。`keyword` 只按明文 IP / 聚合 IP 做精确或右侧前缀匹配，不支持 hash 搜索。接口只读已生成且 ready 的 `client_ip_usage_range_windows` 和 `client_ip_registry`，不在请求内重建窗口，也不为了总统计临时 `SUM/COUNT/MAX` 窗口表；返回 `items`、`pageUpperBound`、`hasMore`、`range` 和 `rangeReady`。窗口未生成、已被新 IP daily 标记为 stale，或 dirty IP 未全部刷新完成时，`rangeReady=false` 且列表为空，等待后台 worker 刷新。`page` 会被服务端限制在安全上限内，避免超大 `OFFSET` 拖慢高基数窗口查询；响应中的 `page/pageSize` 是最终生效分页。`pageUpperBound` 只作为分页器上界，不能作为数量或范围总统计展示，是否还有下一页以 `hasMore` 为准。`rangeUsage` 可包含 `averageFirstTokenMs`、`averageDurationMs` 和 `maxDurationMs`，这些速度指标来自 IP 维度窗口行，只展示不参与 IP 列表排序。
- `POST /__aisys__/api/ip-stats/:ipHash/blacklist`：管理员创建 active 封禁策略，body 支持 `reason`，以及可选的 `durationMinutes` 或 `durationDays`；不传时为永久封禁，两个时长字段只能传一种。创建后会停用同 IP 旧 active 封禁策略，并通知网关进程清理 IP 封禁缓存。
- `POST /__aisys__/api/ip-stats/:ipHash/unblock`：管理员停用 active 封禁策略，body 可为空，前端不要求填写解封原因。解封后通知网关进程清理 IP 封禁缓存。

网关命中 active 封禁策略时返回 OpenAI 兼容错误结构，HTTP 状态为 `403`，错误码为 `client_ip_blacklisted`，错误消息中会带当前来源 IPv4；响应中的 `error.client_ip` 为当前来源 IPv4。网关请求入口按部署模式读取策略：standalone 读取 server 进程内 active IP 策略快照和来源级短 TTL 决策缓存，高性能 Redis cache driver 下读取单 IP Redis shared cache，cache miss 只能按当前 `ip_hash` 索引回源；请求链路不能加载全量 active 策略。管理员创建 / 解封策略后通知网关进程清理策略缓存；策略不能随 API Key 运行态快照携带全量数组。封禁命中先写入进程内缓冲，再异步批量落到 `client_ip_policy_hits`。

### 模型检测

模型检测用于对 AI 账户执行目标模型可信度检测，不提供绝对真伪证明。检测请求必须复用本地 OpenAI 网关链路；检测 AI 账户时复用账号测试的单账号候选能力，不能静默切换同分组其他账号，检测产生的真实请求按当前调用方计入使用记录、额度和授权消耗。完整设计见 [模型检测设计](模型检测设计.md)。

- `POST /__aisys__/api/model-checks/run`：管理员触发一次模型检测，`targetType` 固定为 `account`，支持 `targetId`、`model`、`profile=quick|full`、`trustedComparison` 和 `trustedComparisonAccountId`；省略 `profile` 时默认 `quick`。快速检测只执行 2 次单轮轻量探针，最高输出 `likely`，不写模型指纹 / Token observation；`full` 对应深度检测并保留原有完整探针与重试。可信对比只允许和 `full` 一起使用且默认关闭；快速检测携带可信对比参数，或深度检测显式开启但没有选择可信对比账户时，接口返回中文错误并拒绝本次检测，不能静默降级。可信对比开启成功时，后端会额外生成 `trusted_comparison` 和 `distribution_similarity` 检测项，用隐藏分布探针比较目标账户与可信对比账户。
- `GET /__aisys__/api/model-checks/runs`：管理员查看模型检测历史分页列表，可按系统账户、AI 账户、目标模型、可信等级和时间筛选。列表只投影页面直接展示的标量字段，以 `pageSize + 1` 判断 `hasMore`，请求路径不读取详情 JSON、检测项或执行 `COUNT(*)`；详情只由 `runs/:id` 按需读取。
- `GET /__aisys__/api/model-checks/runs/:id`：管理员查看单次检测详情，返回脱敏检测项、得分、traceId、五维可信状态和 stats-worker 预聚合的 Token 斜率 / 截距、身份 observation 数、paired 距离、LOO 身份偏离、baseline version / 状态及证据覆盖；接口不扫描 observation 或普通流量正文。
- `GET /__aisys__/api/model-checks/options`：管理员读取支持模型选项和可信对比状态摘要。该轻量静态结果允许首屏读取，但前端必须使用页面模块级内存缓存复用；切换 owner 或再次进入页面不重复请求，只有用户主动刷新才强制更新。质量策略、定时计划和账户候选不得并入该响应或被它带动预取。
- `GET /__aisys__/api/model-checks/account-options`：管理员按全局或指定 `systemAccountId` 读取模型检查账户候选；`purpose=run|history|schedule` 必填，普通候选请求支持 `keyword`、`limit=1..50` 和最多 20 个 `selectedIds`。普通候选响应只返回 `id/name/providerCode/providerProtocolProfileId/protocolCode/protocolVersion`，不读取支持模型或模型映射；`run` 过滤当前可运行、授权 quota 和协议资格，`history` 保留仍可见的历史账户，`schedule` 只返回目标 owner 的自有物理账户。只有用户展开已选账户的模型下拉时，前端才提交互斥的 `accountId=<id>&limit=1` 定点请求；该响应才附带 `modelCheckModels`，且不能同时携带 `keyword` 或 `selectedIds`。不可见、不存在或不合格的 ID 静默省略，run/stream 提交仍执行最终权限和运行资格校验。
- `GET /__aisys__/api/model-checks/quality-policy` 与 `PATCH /__aisys__/api/model-checks/quality-policy`：管理端必须指定具体 `systemAccountId`。页面首屏不读取策略，用户打开手动检测配置时才 GET。PATCH 必须携带 `expectedRevision>=0` 和至少一个可变字段，只提交相对当前策略实际变化的 `profile/manualEnforcementEnabled/penaltyThreshold/penaltyAction/recoveryIntervalMinutes`；同值更新零 DML且不推进 revision，版本冲突拒绝覆盖，成功返回当前完整策略。
- `GET /__aisys__/api/model-checks/quality-schedules`：管理端必须指定具体 `systemAccountId`，只在用户打开定时检查浮窗后按页读取，响应使用后端分页和稳定排序，页面首屏不预取。每条计划新增三个状态字段：`executionState`（五态，按优先级 `paused`(!enabled) > `running`(lease_until>now) > `blocked_account`(账户非 active 或已删) > `queued`(next_run_at<=now) > `enabled` 取值，单一“运行中”文案废弃）、`accountStatus`（计划关联账户当前状态）和 `lastRunScore`（number 或 null，取 `last_run_id` 对应 run 的 score）。
- `POST /__aisys__/api/model-checks/quality-schedules`：只创建新计划，提交完整创建字段且不接受 `expectedRevision`；同一系统账户下同一账户已有计划时拒绝创建，不以 POST 做全量编辑。`intervalMinutes` 取值 `1..10080` 整数分钟（默认 60）；`recoveryIntervalMinutes` 维持 `10..10080`。
- `PATCH /__aisys__/api/model-checks/quality-schedules/:id`：编辑、暂停和恢复统一使用该接口，必须携带 `expectedRevision>=1` 和至少一个可变字段，只提交实际变化的 `model/intervalMinutes/profile/penaltyThreshold/penaltyAction/recoveryIntervalMinutes/enabled`。同值更新零 DML且不推进 revision，版本冲突拒绝覆盖；成功返回单条计划，前端局部替换当前列表行，不重新加载整页。
- `POST /__aisys__/api/model-checks/quality-schedules/:id/run-now`：管理员（管理面挂载要求 admin/super_admin）对单条计划发起立即执行，body 为 `{ revision?, requestId? }`；受理返回 `200 {"data":{"scheduleId","accepted":true,"status":"started","runId":string|null}}`。同账户已有检测或恢复任务在执行返回 `409`“正在执行”；携带 `revision` 与计划当前版本不一致返回 `409`（版本过期）；计划不存在或不属于目标 owner 返回 `404`。执行使用计划行当前配置异步进行（不绑定 HTTP 请求生命周期）：已暂停计划允许单次执行且保持暂停（不推进 `next_run_at`，但回写 `last_run_*`），已启用计划完成后 `next_run_at=完成时间+间隔`；同 `(scheduleId, requestId)` 幂等（进程内 10 分钟记忆）；run 的 `triggerKind` 记为 `schedule_now`，达标后可触发立即复测恢复（见 [模型质量定时检查与处罚恢复设计](模型质量定时检查与处罚恢复设计.md) §7.2.1）。
- `POST /__aisys__/api/model-checks/quality-schedules/run-now-batch`：管理员批量立即执行，body 为 `{ items: [{ scheduleId, revision?, requestId? }] }`；恒返回 `200`，`{"data":{"results":[{"scheduleId","accepted","status":"started"|"already_running"|"not_found"|"stale_revision"|"invalid","runId","message"}]}}`，允许部分成功，逐条结果互不影响；单条执行语义同上。
- 管理侧模型检测未传 `systemAccountId` 时默认读取全部系统账户作用域；传入具体 `systemAccountId` 时，账户 options、发起检测、历史列表和详情读取都收窄到该系统账户，不能落回当前管理员自己的默认作用域。
- `POST /__aisys__/api/my-model-checks/run`：当前登录用户触发自己的模型检测，忽略传入的 `systemAccountId`；`profile` 省略时默认 `quick`，显式传 `full` 才执行深度检测。`trustedComparison` 默认关闭且只允许用于 `full`，非法组合或未选择可信对比账户时接口返回中文错误并拒绝本次检测。
- `GET /__aisys__/api/my-model-checks/runs`：当前登录用户查看自己的模型检测历史分页列表。
- `GET /__aisys__/api/my-model-checks/runs/:id`：当前登录用户查看自己的单次检测详情；授权资源只返回脱敏可信度和安全摘要。
- `GET /__aisys__/api/my-model-checks/options`：当前登录用户读取支持模型选项和可信对比状态摘要，缓存和主动刷新边界同管理端。
- `GET /__aisys__/api/my-model-checks/account-options`：参数、普通六字段候选和 `accountId=<id>&limit=1` 定点模型响应边界同管理端，但强制当前登录用户作用域并忽略伪造 owner；首屏不调用。
- `GET|PATCH /__aisys__/api/my-model-checks/quality-policy`、`GET|POST /__aisys__/api/my-model-checks/quality-schedules`、`PATCH|DELETE /__aisys__/api/my-model-checks/quality-schedules/:id`、`POST /__aisys__/api/my-model-checks/quality-schedules/:id/run-now`、`POST /__aisys__/api/my-model-checks/quality-schedules/run-now-batch`：读写契约、字段级差量、CAS/no-op、列表状态字段（executionState/accountStatus/lastRunScore）和 run-now 执行语义边界同管理端（run-now 两端点在自助面要求登录用户），但 owner 固定为当前登录用户，忽略客户端伪造的系统账户 ID。
- 检测题库提供 9 个端点，同时挂 `/__aisys__/api/model-checks/*`（管理面挂载要求管理员）与 `/__aisys__/api/my-model-checks/*`（自助面挂载要求登录用户）双前缀；题库数据全局共享，不做系统账户作用域过滤，`systemAccountId` 不参与其读写范围，前端管理视图的题库管理入口因此不依赖系统账户作用域选择，进入页面即可打开。
- 题库题目契约（`QuestionView`）在管理面响应中额外透出 `createdByName`（创建者系统账户显示名），供管理员审核时识别提交者；自助面响应省略该字段（字段级 `omitempty`，与 `reviewedBy` 仅管理面透出的约定一致）。名称解析失败的读请求按整体失败返回，不得静默省略后仍返回 200。
- 题库题目契约透出 `isBuiltin`（系统内置题标记，omitempty，仅内置题为 true 时出现）。内置题由 maintenance `--seed` 以固定 id 幂等预置为 `approved`（8 道经典公开检测题，条件 upsert：存量内置行题面随 seed 版本恢复权威值），对 Update/Delete/Review 一律拒绝并返回中文错误（下架后无恢复入口，题面调整随版本 seed 演进）；内置题与用户题同池参与查重（同标题/高相似提交仍 409）与最多 3 题选择限制，所有登录用户可直接选用。`model_check_question_bank.is_builtin` 列由 `--ensure-schema` 幂等补齐（PG `ADD COLUMN IF NOT EXISTS`；双方言时期 SQLite PRAGMA 守卫已随 2026-10-25 存储收口退役）。
- 题库题目契约（`QuestionView`）可选透出 `lastTest`（omitempty）：`{testId, accountId, accountName, model, passedAt}`，来自提交门禁校验通过后写入的 `last_test_id`/`last_test_json` 测试快照，列表与详情都带，供题库列表与详情/审核界面展示"已测试通过"证据；历史数据与内置题无该字段，前端可缺省。审核侧只读展示该快照，审核流程不加测试按钮。
- `GET /__aisys__/api/model-checks/question-bank?status=&keyword=&page=&pageSize=`：管理员分页读取全量题库，支持 `pending|approved|rejected` 状态筛选与标题关键字；自助面前缀只返回 `approved` 题目加本人提交。
- `POST /__aisys__/api/model-checks/question-bank`：登录用户提交题目（标题、题面、参考答案必填，评分要点可选 1..10 条），body 必填 `testId`（题目可用性测试提交门禁，见 [模型检测设计](模型检测设计.md) §5.7）：服务端校验该测试记录存在、`created_by` 为当前登录用户、`verdict='pass'`、`draft_hash` 与本次提交内容一致且 `created_at` 在 24 小时内，任一不满足返回 `400`（错误信息分别指向未测试/记录不存在、测试未通过、内容已改动需重测、测试已过期）。门禁通过后在 `pending` + `approved` 范围内执行标题归一化精确查重与内容 bigram Jaccard 相似度查重；标题重复或相似度 ≥0.80 返回 `409` 并提示重复或最相似题目的标题，创建后进入 `pending` 并写入 `lastTest` 测试快照。
- `GET /__aisys__/api/model-checks/question-bank/:id`：题目详情按行级权限返回；`approved` 题目的题面与参考答案、评分要点自 2026-10-11 起全员可读（题库共享契约，`pending`/`rejected` 题目仍仅创建者与管理员可见）。
- `PATCH /__aisys__/api/model-checks/question-bank/:id`：创建者或管理员可改，仅限 `pending` / `rejected` 状态；`rejected` 修改后回到 `pending`，`approved` 题目锁定不可编辑。修改后重新提交同样必填 `testId`，门禁校验与 `400` 语义同 POST（管理员代改别人题目也必须用自己账户完成测试并提交自己的 `testId`）；修改时重新执行查重。
- `DELETE /__aisys__/api/model-checks/question-bank/:id`：管理员可删除任意题目；创建者只能删除本人 `pending` / `rejected` 题目。硬删除并写操作日志，历史检测结果保留题目 id 与标题快照。
- `POST /__aisys__/api/model-checks/question-bank/:id/review`：管理员审核，body 为 `{ action: "approve" | "reject", reason? }`，`reject` 理由必填；对 `approved` 题目执行 `reject` 即下架。审核走状态 CAS，并发双审影响行数为 0 时返回 `409`。
- `GET /__aisys__/api/model-checks/question-bank/options?keyword=&limit=`：登录用户检测配置选择器专用，只返回 `approved` 题目的 `id` 与 `title`。
- `GET /__aisys__/api/model-checks/question-bank/by-ids?ids=`：登录用户按已选 id 批量回显标签，`ids` 逗号分隔、去重后上限 20，只返回 `approved` 题目的 `id` 与 `title`，失效或越权 id 静默省略。
- `POST /__aisys__/api/model-checks/question-bank/test` 与 `POST /__aisys__/api/my-model-checks/question-bank/test`：题目可用性测试（提交门禁的前置步骤），登录用户，双前缀同权且均按当前登录用户解析账户。body `{ questionText, referenceAnswer, keyPoints?, accountId, model }`（title 不参与），字段上限同题库契约（题面 ≤5000、参考答案 ≤4000、评分要点 1..10 条每条 ≤50）；同步执行 custom_quiz 两跳（作答跳 + 诊断裁判跳），服务端超时上限 120 秒。账户经 `BusinessTargetSource.Resolve` 解析（只能测自己名下或被授权可用的账户，空 revision 按最新配置解析），不可解析/不可用返回 `400` 及原始错误，未登录 `401`。成功 `200 {"data":{testId, verdict:"pass"|"fail"|"invalid"|"request_failed", questionAlignment:"aligned"|"misaligned"|"unknown", keyPointResults, answerExcerpt?, graderNote?, verdictReason?, httpStatus?, latencyMs, accountId, accountName, model, testedAt}}`（`accountId`/`model` 回填被测账户 id 与模型；`verdictReason` 为裁判 reason 原文、由 runner 映射，`request_failed` 时为空）；verdict 语义、门禁校验与错误分支引导见 [模型检测设计](模型检测设计.md) §5.7。
- `PATCH /__aisys__/api/model-checks/quality-policy` 与 `POST|PATCH /__aisys__/api/model-checks/quality-schedules` 的读写 payload 增加 `customQuestionIds`：JSON 数组长度 1..3、去重、每个 id 必须存在且 `approved`，空数组表示清空并不再执行题库环节；字段级差量规则不变（PATCH 缺省该字段 = 不修改）。定时检查在 claim 时把该配置冻结进不可变 `ScheduledPayload`。

接口返回必须使用“高可信、较可信、不确定、疑似不符、不可检测”等中文结论，不返回“已证明为真模型”。可信对比是可选增强项，默认不开启；开启失败时必须明确提示“请选择可信对比账户后再开启可信对比检测”或同义中文错误。分布相似度对照只保存 prompt key、统计摘要、traceId 和短输出预览，不返回完整隐藏题面。检测详情不得包含上游 API Key、OAuth token、代理密码、完整敏感请求头、大体积完整响应体或完整探针题库；该边界指系统内置隐藏探针题面，用户提交的题库题面按 [模型检测设计](模型检测设计.md) §5.7 审核后公开，其参考答案与评分要点自 2026-10-11 起全员可见（题库共享契约），但不进入检测证据回显。

身份群体窗口发生共同变化时，latest 返回 `baselineVersionStatus = drift_protected` 并把身份状态保持为 `insufficient_evidence`。该状态只用于诊断展示，接口不得据此自动停用账户、修改 usage、成本、额度或账单。

### 代理检测

- `GET /__aisys__/api/proxies`：管理员代理管理分页列表，支持 `page`、`pageSize`、`keyword`；关键词只按代理名称做精确 / 前缀匹配，不搜索代理 ID、地址、类型、用户名或说明。返回最近检测状态 `testStatus`、最近延迟 `latencyMs`、最近出口 IP `outboundIp`、最近出口地区 `outboundRegion`、检测摘要 `lastTestMessage` 和检测时间 `lastTestedAt`。
- `GET /__aisys__/api/proxies/options`：登录用户代理选择项，支持按代理名称前缀搜索的 `keyword`、`limit` 和重复裸键或 bracket 数组键 `selectedIds`；`limit` 默认 50，服务端限制在 1-50，非法整数按未传处理。`selectedIds` 会 trim、去重并按 ID 字典序规范化，最多 20 个；普通搜索窗与命中的启用已选项去重后按 `name ASC, updated_at DESC, id ASC` 排序，停用、不存在或无权 ID 静默省略。接口只返回已启用代理的 `id`、`name`、`type` 和 `enabled`，用于 AI 账户表单和 OpenAI OAuth 流程；不得返回 host、port、username、password、检测状态、出口信息或系统账户信息。
- `POST /__aisys__/api/proxies`：管理员创建代理。请求严格只允许 `name/description/type/host/port/username/password/enabled`；`name/type/host/port` 必填，`description`/`username` 可为 `null`（与缺省一致，落 `NULL`；空字符串归一为 `NULL`），密码一旦提交就不能是空白字符串。密码使用 `JUHE_AI_SECRET` 派生的 Node 兼容 AES-256-GCM `v1` 密文保存，响应和操作日志不返回明文。
- `PATCH /__aisys__/api/proxies/:id`：管理员局部更新代理，空对象允许提交；省略密码时保留原密文，提交密码时替换密文。`description`/`username` 为 nullable 文本三态：缺省不修改，`null` 显式清除（行内落 `NULL`，与创建侧归一一致），字符串按 trim 后原样写入（含空串，不做创建侧的空串归一），非字符串拒绝。`type/host/port/username/password` 任一变化都把最近检测状态重置为 `unknown`，并清空延迟、出口信息、检测消息和检测时间。
- `DELETE /__aisys__/api/proxies/:id`：管理员删除未被账户引用的代理。删除前只读取最多 4 个未删除绑定账户，前 3 个账户名用于提示；存在绑定时返回 `409`，第 4 条命中后数量按“至少 4 个账户”表达，不执行精确 `COUNT(*)`。
- `GET /__aisys__/api/route-strategies/options`：管理员读取 API Key 表单使用的策略路由选项；必须登录且具备 `admin` / `super_admin`，普通用户返回 `403 { message: "需要管理员权限" }`。支持 `systemAccountId` 指定用户，空值或 `all` 表示管理员全局可见；支持 `ids` 逗号或重复参数，去空白、去重、最多 50 个；`keyword` 按路由策略名称前缀搜索；`limit` 默认 50，范围 1-100；`activeOnly` 默认 true，`0/false/no` 表示包含停用策略，非法值按 true。响应只返回 `id`、`name`、`mode`、`status`、`isDefault`、`systemAccountId` 和 `systemAccountName`，排序为默认策略优先、更新时间倒序、名称和 ID 稳定升序；不得返回路由配置 JSON、绑定分组、API Key 数量或账号信息。
- `GET /__aisys__/api/my-route-strategies/options`：当前登录用户读取自己的 API Key 表单策略路由选项；后端强制当前登录用户作用域并忽略 query `systemAccountId`，即使管理员在用户模式调用也不能查询全局。`ids`、`keyword`、`limit` 和 `activeOnly` 语义同管理侧；响应只返回 `id`、`name`、`mode`、`status` 和 `isDefault`，不得返回 `systemAccountId` 或 `systemAccountName`。
- 账户一旦绑定代理，上游请求、OAuth token 交换、账户测试和后台冷却复测都必须使用该代理；代理不存在、被停用、无法解密或已形成明确的代理握手 / 隧道失败时请求应失败并提示重新选择已启用代理，不能静默直连。同一次网关调度中，只有该请求已经独立确认的代理准备或代理握手失败才允许排除同一代理；某个账户发生的普通上游 transport failure、完整 HTTP 或协议失败不得扩大为代理级排除，绑定同一代理的其他账户仍须独立可派发。账户测试和后台冷却复测中的模型请求必须复用本地 OpenAI 网关链路并写入使用记录；OAuth token 交换、代理检测和 OAuth 额度快照被动写入不是模型请求，不计入使用统计。OAuth 额度快照不再有后台主动刷新任务，只从真实网关请求或账户测试响应头被动更新。
- `POST /__aisys__/api/proxies/:id/test`：管理员在代理测试弹窗内确认后手动触发代理质量检测，检测目标来自全部已启用供应商的默认地址（`vendors.enabled=1` 与连接器 registry 的 vendor→preset 默认 Base URL 相交，每个 vendor 一条；不再读取已退役的供应商协议档案表），返回 `ProxyTestReport`；报告和列表同时展示出口 IP 和出口地区。
- 检测报告中的 `items` 至少包含“基础连通性”汇总项，以及每个已启用供应商默认地址对应的检测项。
- 出口信息参考 sub2api 的探测方式并扩展多级兜底：通过代理依次访问 `ip-api.com`、`ipwho.is`、`api.ip.sb`、`ipinfo.io`、`api.ipify.org`、`httpbin.org/ip`；出口信息不可用不影响供应商默认地址检测结果。
- 任意状态码的完整 HTTP framing 都只表示本次代理 transport 可达，`2xx/3xx/4xx/5xx` 只作为诊断字段展示，不得映射为代理告警或失败。只有连接、DNS、TLS、代理握手 / 隧道、绝对 hard timeout、响应中断或 EOF 前 framing 未完成才标记 `failed`；没有启用供应商、worker / 配置异常、总截止前未发出真实请求时标记 `unknown`。
- 代理检测读取配置时取得配置 revision，结果写回同时校验该 revision 和 `lastTestedAt` 水位；编辑代理后的迟到结果、较早开始但较晚完成的检测不得覆盖新配置或较新诊断。检测元数据只更新 `test_status/latency/outbound/last_tested_*`，不推进代理配置 `updated_at`，也不触发与选路配置无关的网关全局缓存失效。
- 代理检测不会返回代理密码或完整代理 URL；前端只能展示安全摘要、HTTP 状态和延迟。

## 列表、筛选与分页

低增长配置类列表可以返回数组。新增高增长列表应使用统一分页结构。

推荐列表结构：

```json
{
  "data": {
    "items": [],
    "page": 1,
    "pageSize": 100,
    "total": 0,
    "hasMore": false
  }
}
```

约定：

- 查询参数使用 `page`、`pageSize`、`keyword`、`status`、`providerCode`、`systemAccountId`、`sortField`、`sortOrder` 等稳定名称。
- 普通用户传入 `systemAccountId` 应被忽略；只有管理员可以使用系统账户筛选。
- 排序字段必须后端白名单校验，不把任意字段名拼入 SQL。
- 使用记录、统计明细、授权用量这类持续增长数据必须优先支持后端分页或有限窗口查询；账户用量趋势接口只支持自然日范围，最大 1 个月。
- 使用记录、操作日志、原始审计日志、审计错误组、运行日志索引、账户用量统计明细和授权用量明细属于高增长或统计窗口列表，默认不执行精确 `COUNT(*)`；接口通过多取 1 条返回 `hasMore`，`total` 只作为兼容分页器的当前位置上界，前端不能把它展示成全量精确总数。
- 操作日志属于持续增长的业务追溯数据，列表必须分页查询；用户侧只能返回当前用户可见日志，管理侧可以按操作人、影响用户、资源和 trace ID 筛选。
- 审计日志属于持续增长且 payload 体积较大的高权限数据，列表必须分页查询元数据，详情 payload 必须按需加载，不能在列表接口返回完整原文。
- 前端表格分页、空态、错误态和加载态必须保持中文体验。

## 写接口防重复提交

管理端会改变业务状态的接口必须遵循 [幂等与唯一约束设计](幂等与唯一约束设计.md)，避免前端重复点击、网络卡顿重试或客户端脚本重复提交造成重复数据。

约定：

- `GET` 查询、列表、筛选、分页、详情、日志查看和审计查看不进入防重复提交缓存。
- 创建类 `POST` 默认需要后端声明操作指纹，包括 AI 账户、OAuth 账户、分组、API Key、代理、系统账户、系统团队、团队成员、统一授权和公告创建。
- 修改类 `PATCH`、删除类 `DELETE` 和发布 / 下线等状态切换接口建议接入短 TTL 防重复缓存，避免短时间重复写操作日志。
- 同一登录用户、同一路由、同一业务作用域、同一资源指纹的请求短时间内只允许一个进入真实业务写入。
- 同资源指纹请求正在处理时，返回 `409` 和中文提示，不执行业务写入。
- 缓存失效或进程重启后，数据库业务唯一约束继续兜底；命中唯一约束时返回 `409`，不写操作日志。
- 前端按钮 loading 和禁用只作为体验优化，不能替代服务端防重复缓存和数据库唯一约束。

## 权限摘要

资源列表中如果同一接口同时返回自有资源、个人授权资源和团队授权资源，应返回 `accessType`、授权来源摘要与 `permissions`，前端据此控制操作入口，后端仍在每个写接口重新校验。

推荐字段：

```json
{
  "accessType": "owner",
  "ownerSystemAccountId": "sa_xxx",
  "ownerDisplayName": "用户名称",
  "effectiveAuthorizationId": null,
  "authorizationSources": [],
  "authorizationGranteeType": null,
  "authorizationGranteeId": null,
  "permissions": {
    "canUse": true,
    "canEdit": true,
    "canDelete": true,
    "canReturnAuthorization": false,
    "canAuthorize": true,
    "canViewCredentials": true,
    "canManageMembers": true,
    "canBindToApiKey": true
  }
}
```

命名约定：

- 后端和前端类型优先使用 camelCase；数据库字段继续使用 snake_case。
- `accessType` 可取 `owner`、`authorized`、`admin_view`。
- 管理员查看他人资源时不改变资源所有者；必要时使用 `admin_view` 表示管理员视角。
- 授权资源必须返回所有者和授权来源摘要；如果个人来源与团队来源同时命中同一资源，只返回一行资源并在 `authorizationSources` 中列出全部来源，不能返回重复 AI 账户或重复分组。
- 资源列表应返回用户级 `authorizationId`，同时保留 `authorizationSources` 供前端显示“个人授权 + 团队授权”等来源。
- 授权 AI 账户列表必须返回 `effectiveAvailability` 表达实际可用性，并可返回 `authorizationInstanceSourceAccountStatus`、`authorizationInstanceSourceAccountSchedulable`、`authorizationInstanceSourceAccountExpiresAt`、`authorizationInstanceSourceAccountCooldownUntil` 和来源错误摘要作为来源侧证据。前端主状态和可操作性优先读取 `effectiveAvailability`；来源字段可以阻断实际可用性，但不能被当作授权实例 `accounts.status` 的覆盖值，也不能回写授权实例本地运行态。
- 授权分组列表必须返回被授权人本地生效后的 `enabled`、`groupType` 和 `schedulingPolicy`，以及授权方原分组所有者摘要；本地配置只影响当前被授权人通过该分组绑定 API Key 和网关调度，不回写授权方原分组。
- 授权管理页默认筛选“生效中”记录；资源被删除后，相关授权应变为 `revoked`，只在“全部状态”或“已回收”筛选下用于历史追溯。
- 授权资源不能返回完整凭据或代理密码；授权账户详情可以返回来源账户的非敏感公开配置用于只读展示，包括 `base_url`、公开 OAuth 元数据、模型、代理 ID、并发、时间计划、账户追加流式规则和来源状态，但永远不能返回 OpenAI API Key、Access Token、Refresh Token、ID Token 或代理密码。

## 系统设置分区接口

- `GET/PATCH /__aisys__/api/settings/sections/:sectionKey` 仅允许管理员，section key 固定为 `brand`、`gateway-core`、`user-request-limit`、`account-health`、`api-rate-limit`、`cooldown-retest`、`data-retention`、`log-retention`（2026-10-02 日志与审计设置，见 `日志与审计设置设计.md`；早期文档误列的 `account-test` 从未存在于 Go catalog，已修正）；未知 key、跨 section 字段和危险对象 key 返回 400。
- GET 从 section 白名单对应的设置行读取，现行 PostgreSQL 使用 async 窄查询（历史双方言时期 SQLite DB service 的独立 read-worker operation 已随 DB service 消失与存储收口退役），不能先加载完整 settings 后在 route 裁字段。
- PATCH 只接受本 section 已知字段并返回该 section 最新值，不返回完整 settings。写入后必须失效 section 和运行态相关缓存，并从数据库重载、写回对应完整 system/global settings cache；网关和 worker 的完整 `getSettingsAsync()` 契约不由前端 section 拼装。
- 管理页面（2026-10-02 方案 C 重设计：折叠分组 + 展示行 + 按组编辑）首屏并行加载全部 section——折叠分组条的自定义状态胶囊与展示行需要全部 baseline，各 section 均为轻量键值 GET；每个 section 具有独立 loading/error/retry/baseline/dirty 状态。UI 7 个分组（品牌与展示 / 请求与限流 / 调度与恢复 / 超时与中断 / 上游版本覆盖 / 数据保留 / 日志与审计）多对一映射后端 section，编辑按组进行、保存按组触发并按字段所属 section 生成差异 payload，不含未加载区块或未修改字段；多组可同时编辑、各自独立保存。完整 `GET/PATCH /settings` 暂留兼容，但 Vue 不再作为首屏入口调用。
- `user-request-limit` 只包含 `gatewayUserRequestLimitPerMinute`、`gatewayUserRequestLimitPerDay`、`gatewayUserRequestLimitPerWeek`、`gatewayUserRequestLimitPerMonth`，均为 `0..1,000,000,000` 整数；`0` 表示全局无限。Node 读取旧 PostgreSQL 数据库时若缺少这四行，按 `0` 兼容，不把缺行扩大为设置加载失败。

## 网关权限

- `/*` 和 `/v1/*` 网关入口不读取后台登录态，只读取 `Authorization: Bearer <本地网关 API Key>` 或 `x-api-key: <本地网关 API Key>`；系统前缀 `/__aisys__/*` 除外。`x-api-key` 只作为本地网关认证入口，转发 Anthropic 上游时会被替换为命中账号自己的上游 API Key。
- API Key 的所有者就是本次调用方系统账户。
- API Key 认证完成后、候选账号调度前，Node 网关按 API Key 所有者的最终用户请求限制执行同步进程内计数；`/v1/models` 等模型列表请求不计入。超限返回 HTTP `429`、`type=rate_limit_exceeded`、`code=user_request_limit_exceeded`，并按分钟、日、周、月顺序选择首个阻断窗口。
- `/models`、`/v1/models`（OpenAI-compatible 形态，同一路径按 Codex / Anthropic 客户端信号切换响应形态）与 `/v1beta/models` 及 Gemini native models 族按 [网关模型列表账户并集设计](网关模型列表账户并集设计.md) 返回该 Key 激活绑定分组集合上、静态门与授权门通过的资格主体之模型事实主体（`COALESCE(来源账户, 账户)`）的 `supportedModels` ∪ 有效映射源模型的配置能力并集；供应商模型目录只作响应元数据字典，不再决定成员资格。模型列表数据面装载失败返回 HTTP `500`、`type=internal_error`、`code=models_list_unavailable`，不渲染 200 空列表；无激活绑定或无可贡献账户时返回空列表。网关入口鉴权（`Authorization: Bearer` / `x-api-key` / Gemini `x-goog-api-key`）与 models 端点限流语义不变。
- API Key 只选择一条路由策略；路由策略可以绑定调用方自己的一个或多个分组，也可以绑定有效授权给调用方的分组。授权分组在运行态必须重新校验授权状态、到期时间和授权额度。
- 网关先读取 API Key 绑定的路由策略及其 active 分组绑定，按优先级选择可承接号池；当前分组无候选账号、模型不匹配、本地容量不可承接或上游未输出前全部失败时，可以尝试下一优先级分组。API Key 无效、Key 额度耗尽、请求本身无效、强制图像生成请求、已经产生可见流式输出时，不做跨号池切换；仅 auto 暴露的 Responses `image_generation` 工具在图像权限关闭时会被移除后继续按文本请求处理，不触发跨号池失败。
- API Key 时间计划由 background worker 在开始 / 结束边界直接写入 API Key `status`；网关认证阶段只读取落库后的单一 `status`。结束边界写入停用后的请求按不可用 Key 处理，不再返回独立的 `api_key_schedule_inactive` 错误码。
- AI 账户时间计划同样由 background worker 在开始 / 结束边界写入 `accounts.status`；网关候选只读取落库后的单一状态，不在请求链路解析计划 JSON。人工启用 / 停用也只写 `status`。账户仍需同时满足状态正常、可调度、未冷却、未到期、授权有效和额度可用等硬门禁；计划边界不会自动恢复待检查、异常、限流或临时不可调用账户。
- 授权账户加入自有分组时，分组成员关系记录用户级 `accountAuthorizationId`；授权暂停、到期、回收或归还后调度必须实时拦截，重新激活同一最终授权后可恢复使用。
- 网关调度时必须重新校验 API Key 状态、路由策略分组绑定、分组可见性、统一授权有效性、授权额度、授权实例账户状态、实例到期、实例冷却和来源账户可用性；授权实例使用的凭据、模型、代理、并发、可用时段和账户追加流式规则从来源账户补齐，来源账户停用、异常、限流 / 临时不可调用、冷却未结束、关闭调度、套餐到期、删除或凭据缺失都是实际调度硬门禁。团队和成员变化应先同步到最终用户授权关系或来源状态，网关运行时不再额外遍历授权来源团队 / 成员状态。
- 网关调度时必须按后台统计缓存的 `total_cost_usd` 校验 API Key 美元成本额度、分组授权美元成本额度和账户授权美元成本额度；命中额度返回 429，错误文案为“额度已用完，请联系管理员提升额度”。
- 使用授权账户或授权分组时，使用记录必须同时冗余调用方、账户所有者、分组所有者、统一授权 ID 和授权对象类型，便于调用方明细、授权实例账户行用量、个人授权消耗、团队授权总消耗和团队成员消耗分开统计；被授权人的调用明细、测试、模型检测和本地操作日志归调用方自己，分组授权调用不能写入资源归属人的普通账户 / 分组统计，只能进入授权报表聚合；路由策略绑定入口接受调用方自有分组和有效授权分组。
- 授权用量接口只由用户侧 `我的授权` 下的 `团队消耗明细` / `用户消耗明细` 或管理侧 `统一授权管理` 下的同名明细进入；团队 / 用户明细按 `startDate/endDate` 现场聚合授权日摘要表，31 天窗口内任意自定义区间均可出数。
- `授权操作` / `统一授权` 只服务授权关系列表，不展示用量筛选或用量列；`团队消耗明细` / `用户消耗明细` 必须使用专用后端接口按日范围直接聚合授权日摘要表（`authorization_team_usage_summary_daily` / `authorization_user_usage_summary_daily`），不能通过授权列表接口或前端本地汇总替代；接口不扫描 `usage_records` 明细、不读取统计缓存行二次汇总。
- 同一调用方对同一资源同时拥有个人来源和团队来源时，网关仍只使用一条用户级授权写入一条使用记录，不能重复写入或重复计入事实总量。
- 网关返回给客户端的错误使用本地网关统一错误结构，不使用管理 API 的 `{ data, message }` 包装；Anthropic 成功响应保持 Anthropic native JSON / SSE 形态，不改写成 OpenAI `choices` 或 `response.*`。
- 服务等级和思考级别字段必须进入各供应商现有请求白名单或映射器；同协议路径保留客户端值，跨协议无法支持或映射时返回目标 driver / bridge 现有的 `400` 请求错误，不能静默删除，也不写账户失败副作用。

### 同步音频端点（M1 已实施，2026-10-04）

- `POST /v1/audio/speech`（TTS）、`POST /v1/audio/transcriptions`（STT，multipart）、`POST /v1/audio/translations`（STT 翻译，multipart）挂网关 API Key 认证（同 `/*`、`/v1/*` 入口：`Authorization: Bearer` 或 `x-api-key`），走既有 preauth → 派发 → 响应 → 终态链。
- 车道与候选过滤：按路径族 `/v1/audio/*` 判定 `audio` lane（`gatewayproto.RequestLane` 已含 `audio`）；候选账户须启用对应 endpoint mode——`audio_speech`（speech）与 `audio_transcription_json`（transcriptions/translations），模型须属 `mode=audio` 分类目录。
- 上游行为：OpenAI 账户按 OpenAI 形态直连转发；Gemini 账户由 `internal/gatewaymedia` adapter 转换（`generateContent` + `responseModalities:["AUDIO"]` + 公共 `voice` 到 `voiceName` 映射），`response_format` 仅接受 `pcm`（上游裸 PCM 透传），其余 400，零转码。
- 受理边界：上游 2xx 响应头到达为受理凭据。调度自 2026-10-19 起按[对话与非对话媒体调度分离设计](对话与非对话媒体调度分离设计.md)的 `StatelessMediaDispatch` 域收敛（已实施）：仅在下游尚未语义提交且统一错误契约或 adapter 明确确认可安全重试时按一次静态候选快照换候选，不能由 `401/403/429/5xx` 等状态码单独授权，无规则命中不轮换兄弟 Key，失败不派发请求失败健康检查；body 开始透传后不切换，流中断只报错不重放。
- 响应与存储：speech 为音频二进制纯流式透传，transcriptions/translations 透传上游 JSON；产物零存储（只记元数据与计量）。
- 计费口径：按厂商真实定价维度双口径——`gpt-4o-mini-tts` 与 `gpt-4o-transcribe` 系按 token 口径（既有 audio token 单价；`gpt-4o-tts` 未收录——官方无定价，待官方价后补行，不编造），`tts-1`/`tts-1-hd` 按输入字符（`tts_input_chars`），`whisper-1` 按秒（`audio_input_seconds`）；usage 优先 → `duration` → 0 + `usage_missing`，不猜测。明细见 [模型价格与用量统计口径](模型价格与用量统计口径.md) §2.5。

### 异步视频任务端点（M2 已实施，2026-10-04）

- `POST /v1/videos`（创建）、`GET /v1/videos`（列表，按当前 API Key 过滤）、`GET /v1/videos/{id}`（轮询，终态含 usage 摘要）、`GET /v1/videos/{id}/content`（产物下载）、`DELETE /v1/videos/{id}`（取消/删除，本地行置终态 `cancelled`）挂网关 API Key 认证（同 `/*`、`/v1/*` 入口：`Authorization: Bearer` 或 `x-api-key`）。
- 车道与候选过滤：按路径族 `/v1/videos*` 判定 `video` lane（`gatewayproto.RequestLane` 已含 `video`）；创建端点候选账户须启用 `video_create` endpoint mode 且模型属 `mode=video` 分类目录；任务面 endpoint mode（列表/轮询 `video_get`、content `video_content`、取消 `video_cancel`）不设候选过滤，不进派发循环。
- 受理边界：受理凭据 = 上游 2xx + job id（落 `media_jobs`）；调度自 2026-10-19 起按[对话与非对话媒体调度分离设计](对话与非对话媒体调度分离设计.md)的 `StatelessMediaDispatch` 域收敛（已实施）：仅在未拿到受理凭据、下游尚未语义提交且统一错误契约或 adapter 确认可安全重试时按一次静态候选快照换候选，不能按状态码字面值直接换账户，无规则命中不轮换兄弟 Key，失败不派发请求失败健康检查；确定性参数类 `400/413/422` 不换账户。任务面走**账户亲和直连**：查 `media_jobs` 定位原账户原上游转发，不换账户；账户已删/禁用返回 `503` `media_job_unreachable`。任务面出站消费原账户绑定代理（2026-10-16 起）：按账户行 `proxy_profile_id` 解析 proxy_profiles 档案出站（与创建派发同源；未配代理保持直连通道，档案缺失/停用/凭据不可解密返回失败不回落直连；授权实例按记录绑定账户行自身档案解析，不读实例覆盖）。
- 任务面本地错误码：`media_artifact_expired`（`410`，产物已过上游时效，网关不补救）、`media_job_not_completed`（`409`，非 `completed` 状态请求 content）、`media_job_unreachable`（`503`，见上）。
- 零存储与审计：content 为纯流式透传代理（边收边转发，content-type 透传）；任何媒体资源字节不落盘/不入库/不进审计快照（`media_jobs.request_snapshot_json` 只含轻量参数元数据，不含 base64 资源字段）。任务面短路路径接最小审计：身份绑定 + jobId 网关元数据 + 请求级 Finalize（方法/路径/状态码/outcome），不记请求/响应 body。
- 计费：轮询终态驱动回填——`completed` 按秒数 × 静态目录秒价（`sora-2` $0.10/s、`sora-2-pro` $0.30/s，720p 基准）落 `video_output_seconds` 行项与 `media_jobs.cost_usd`；`failed` 不虚计，usage_missing/目录未命中保持 NULL。明细见 [模型价格与用量统计口径](模型价格与用量统计口径.md) §2.6。
- 行为契约总源见 [音频视频模型接入与统一媒体网关设计](音频视频模型接入与统一媒体网关设计.md) §4.2/§7/§8；管理面媒体任务列表端点 `GET /__aisys__/api/media-jobs` 已登记于「菜单入口与视图范围」节。

### 异步长音频任务端点（M3f 已实施，2026-10-04，首个上游=百炼 paraformer）

### Realtime ephemeral token 签发端点（M5b1 已实施，2026-10-04；M5b2 增补签发侧目录校验）

- `POST /v1/realtime/client_secrets` 挂网关 API Key 认证（同上入口；preauth 含用户请求限流四窗消费）。请求体 `{"model":"<realtime 目录模型>"}`（非空必填，缺失/空白 400 `invalid_request_body`；M5b2 起签发前校验 model 必须命中 realtime 目录行——active 且协议含 `realtime`，未命中 400 `model_not_in_realtime_catalog`）；响应 OpenAI 形态 `{"value":"<43 字符 token>","expires_at":<Unix 秒>}`。token 绑定签发 API Key 与 model（TTL 120 秒，Redis `realtime_token:<t>`，多环境插命名空间段；TTL 内可多次校验，模型不一致拒绝——不记名复用防护）。非 POST 方法 404；运行态驱动非 redis 时显式 503。

### Realtime WS 会话端点（M5b2 已实施，2026-10-04）

- `GET wss://<gateway>/v1/realtime?model=<model>`（精确路径；非 GET 方法 404）。WebSocket 升级请求，不进 chain 响应管道（HTTP 语义管道不适用），协议门放行后短路进专用 WS 桥接 handler（`cmd/juhe-ai-gateway/chain_realtime.go`）。
- **认证二选一，Bearer 优先**：`Authorization: Bearer <网关 API Key>`（服务端客户端，preauth 全套守卫：IP 黑名单 + 用户请求限流四窗）或 `?token=<ephemeral>`（浏览器形态——WS 无自定义头能力；Verify 含 model 一致性，按 token 载荷 `api_key_id` 解析运行时后过同一 preauth 守卫）。错误码：缺认证 401 `invalid_api_key`；token 无效/过期 401 `invalid_realtime_token`；token 与 model 不一致 403 `realtime_token_model_mismatch`；token 服务未装配（运行态驱动非 redis）503。
- **模型解析**：`?model=` 非空必填（缺失 400 `missing_model`）；必须命中 realtime 目录行（active + 协议 `realtime`，openai 聚合目录），未命中 400 `model_not_in_realtime_catalog`。会话中途不可换模型。
- **并发限制**：每 API Key 并发 WS 连接数（设置键 `realtimeMaxConnectionsPerApiKey`，默认 5，进程内计数——多实例部署各进程独立生效），超限 429 `realtime_connection_limit`；会话占用账户并发槽（沿既有账户并发语义，lane=`realtime`）。
- **派发与受理边界**：候选账户须启用 `realtime_session` endpoint mode（opt-in 语义同 images/video）+ 支持模型 + 可用 Bearer 凭据（首版仅 api_key 账户——OAuth 账户活期 access token 属引擎刷新面，WS 面不经该面）；上游拨号 `wss://<account base>/v1/realtime?model=`（Bearer 账户凭据、代理沿账户 ProxyURL）。拨号/握手/升级拒绝失败=受理前，换下一候选（候选耗尽 503 `no_candidate_accounts`/`upstream_unavailable`）；上游 101 升级成功=受理，此后会话绑定账户，任一侧断开只关另一侧不换账户。
- **会话生命周期**：升级成功后双向泵逐字节透传（opcode+payload 不重写）；客户端侧 ping/pong 保活（20s 间隔、连续 3 次无 pong 断开）；空闲超时（`realtimeIdleTimeoutSeconds` 默认 120，双向无帧）；最大会话时长（`realtimeMaxSessionSeconds` 默认 1800，到期服务端 close 1000）。查询参数除 `token`（网关认证参数不外泄上游）外透传上游。
- **usage/审计/零存储**：上游→客户端方向旁路观测器只解析文本帧 `response.done.response.usage`（`*_token_details.audio_tokens`）累计会话汇总（解析失败静默忽略不影响转发）；任一侧关闭终态落 `usage_records`（endpoint=`/v1/realtime`、`inputAudioTokens`/`outputAudioTokens` 计量、目录 $32/$64 per 1M audio token 计价；空会话 0 计费 + `usage_missing`；受理前失败不落 usage 行）。审计只记会话元数据（模型/账户/时长/断开原因/usage 事件数，`realtime_session` 网关元数据 + 状态码 Finalize；升级成功记 101）。音频字节与事件序列零存储。
- 行为契约总源见 [实时语音Realtime网关设计](实时语音Realtime网关设计.md) §2-§5；报文级契约见 [媒体上游协议契约与Mock上游规格](媒体上游协议契约与Mock上游规格.md) §4.4。

## 团队与授权对象接口

### 用户请求限制契约

- `POST /__aisys__/api/system-accounts` 和 `PATCH /__aisys__/api/system-accounts/:id` 的 Node 契约允许超级管理员提交 `requestLimits`：四个窗口字段缺失表示继承全局，`0` 表示该用户无限，正整数表示覆盖；`requestLimits:null` 表示清空全部用户覆盖。
- `requestLimits.expiresOn` 为可选真实日历日期 `YYYY-MM-DD`，作用于整组覆盖；所选日期当天仍有效，按 `usageStatsTimezone` 从次日 `00:00` 起整组覆盖失效并继承全局。没有到期日表示永久有效。
- `GET /__aisys__/api/auth/profile` 返回 `effectiveRequestLimits`，四个窗口均包含 `limit` 与 `source=global|user`，同时返回 `timezone`、`overrideActive`，已配置到期日时返回 `overrideExpiresOn`。到期后四个窗口的 `source` 与 `limit` 均反映全局最终值，但保留到期日供页面解释。
- 同一响应还返回 `effectiveAiAccountLimit` 与 `effectiveExpeditedAccountLimit`（同 `{limit, source=global|user}` 形状，2026-10-24 用户裁决新增）：AI 账户数量上限按「用户覆盖 → 全局设置 `userAiAccountLimit`（缺省 100）」解析，`0` 表示不限制；特供账户名额按「用户覆盖 → 内置默认 3」解析，`0` 表示禁止新增/重新启用特供。解析语义与创建校验（`assertAiAccountCreationLimit`）及特供名额校验执行侧一致，个人信息页「账户上限」卡片只读展示，用户不可自行修改。
- 以上增量只属于当前 Node/Vue 实现；不据此声明 Go 管理接口或 Go profile 已实现同一契约。

- `GET /__aisys__/api/system-accounts`：仅管理员可用，返回系统账户管理分页列表；`keyword` 按用户名 `username` 和用户名称 `displayName` 做精确 / 前缀匹配，不搜索 ID、角色或说明；`page` 默认 1，`pageSize` 默认 20 且限制在 1-100；响应为 `{ items, total, hasMore, page, pageSize }`，`items` 恒为 JSON 数组，无匹配或越页时返回 `[]` 而不是 `null`（前端分页列表直接读取 `items.length`），`total` 只作为当前窗口上界，不做全表精确 `COUNT(*)`；列表字段包含 `id`、`username`、`displayName`、`description`、`role`、`status`、`mustChangePassword`、`imageGenerationEnabled`、`aiAccountLimit`、`expeditedAccountLimit`、`requestLimits`、`lastLoginAt`、`createdAt` 和 `updatedAt`（限额三字段是编辑弹窗回填的数据源；按「列表只做概览」原则列表不展示它们，细节在编辑弹窗查看），不得读取或返回 `password_hash`。Go W2 已覆盖该只读列表端点；Go W3 opt-in 已覆盖系统账户创建和完整 mixed PATCH，但前端 smoke、生产切流和 Node 删除仍未完成。
- `GET /__aisys__/api/system-accounts/options`：仅管理员可用，返回管理侧筛选和选择器所需的 `id`、`username`、`displayName`、`status`，支持 `ids`、`keyword` 和 `limit`；`ids` 用于已选系统账户回填，支持逗号或重复参数，去空白、去重、最多 50 个；`keyword` 只按用户名和展示名做精确 / 前缀匹配，不搜索 ID、角色或说明；`limit` 默认 50，服务端限制在 1-50，非法整数按未传处理；不得读取或返回 `password_hash`、角色、改密状态、最后登录、创建 / 更新时间等系统账户管理字段。Go W2 已覆盖该只读 options 端点；系统账户完整写接口生产接管仍归后续 W3 收口。
- `POST /__aisys__/api/system-accounts`：仅 `super_admin` 可用，创建系统账户；严格 JSON object 只允许 `username`、`displayName`、`description`、`password`、`role`、`status`、`mustChangePassword` 和 `imageGenerationEnabled`。`username/displayName/password` 包含任意空白字符时分别返回“用户名不能包含空格”“用户名称不能包含空格”“登录密码不能包含空格”；`role` 只允许 `admin/user`，`status` 只允许 `active/disabled`，布尔字段不接受 `null`。成功后返回新系统账户摘要，不返回密码 hash、默认 API Key 明文或默认资源 ID；后端事务创建 7 个默认分组、6 条非 hybrid 默认普通路由、6 条路由分组绑定和 6 个默认 API Key，默认 API Key 完整密钥只以 `key_secret_encrypted` 落库。Go W3 当前已覆盖该 create opt-in 子动作，但真实 PG+Redis+Asynq create integration、前端系统账户页 smoke、生产切流和 Node 删除仍未完成。
- `PATCH /__aisys__/api/system-accounts/:id`：仅 `super_admin` 可用，完整 mixed partial update；严格 JSON object 只允许 `displayName`、`description`、`password`、`role`、`status`、`mustChangePassword` 和 `imageGenerationEnabled` 任意组合，至少提交一个字段；`username` 返回“用户账户创建后不能修改”，未知字段、非法枚举、`null` 布尔和尾随 JSON 返回 400。`password` 或 `status="disabled"` 会撤销目标账户全部 session；状态或图像生成权限真实变化必须清理 gateway runtime cache / API Key validation cache，二者同时变化时状态原因优先；数据库提交后若 API Key validation cache 失效最终失败，PATCH 仍返回已提交的最新 mutation（含 `updatedAt`），并以 `apiKeyValidationCacheInvalidationFailed = true` 提示前端告警，不能返回 500 假失败或诱导旧版本重试。密码日志只记录“已重置”，不记录明文。Go W3 当前已覆盖该 opt-in 路径，但真实 mixed patch integration、前端系统账户页 smoke、生产切流和 Node 删除仍未完成。
- `PATCH /__aisys__/api/system-accounts/:id` 在上述白名单之外支持 `expeditedAccountLimit`（"特供账户上限"，可空整数 0–100）三态：字段缺省表示不修改，显式 `null` 表示清除覆盖值恢复 NULL（读侧 `COALESCE` 归一为默认 3，不写回），整数表示设置并校验 0–100，越界返回 400；`0` 表示该用户禁止新增/重新启用特供账户（语义有意不同于 `aiAccountLimit` 的 `0 = 不限制`），存量标记按"上限下调不回溯"保留。系统账户摘要 JSON 的 `expeditedAccountLimit` 键恒存在，NULL 输出 `null`。权限沿用系统账户编辑权限面（仅 `super_admin`），不新增权限点。
- `GET /__aisys__/api/system-teams`：仅管理员可用，返回系统团队分页列表和每行 `memberCount`，不返回成员数组；支持 `page`、`pageSize`、`keyword`，关键词只按团队名称做精确 / 前缀匹配，不搜索团队 ID 或说明。只有用户点击成员管理时才调用 `GET /system-teams/:id/members`，返回 `{ id, memberCount, updatedAt, items }` 的当前团队成员专用投影。
- `GET /__aisys__/api/my-teams`：所有登录用户可用，返回当前用户加入的团队分页列表和每行 `memberCount`，不预取成员数组；停用团队仍返回状态供页面展示，但不代表团队授权继续生效。成员只在用户点击查看后通过 `GET /my-teams/:id/members` 按需读取。
- `PATCH /__aisys__/api/system-teams/:id`、`POST /__aisys__/api/system-teams/:id/members` 和 `DELETE /__aisys__/api/system-teams/:id/members/:memberId` 必须携带 `expectedUpdatedAt` 做 CAS。团队字段 PATCH 只返回 `{ id, changedFields, rowPatch, updatedAt }`；添加成员只返回 `{ id, memberCount, updatedAt, addedMembers }`；删除成员只返回 `{ id, memberCount, updatedAt, removedMemberId }`。no-op 不推进版本，冲突返回 `409`；前端局部合并当前行和已打开的成员列表，不重载团队整页或返回完整团队聚合对象。
- `GET /__aisys__/api/accounts`、`GET /__aisys__/api/my-accounts`：分页响应只包含账户表格 / 移动卡片当前真实消费的标量与最小摘要；当前列需要的实时并发、运行可用性、冷却 / 最近错误、最近使用、当日三字段用量、余额快照、`effectiveAvailability` 和 `availabilityPresentation` 在同一响应内按当前页 ID 批量读取。多 Key 状态如用于可见状态判定，只返回聚合摘要，不返回 `apiKeyRuntimeDetails`。并发无占用或运行态读取失败时返回 `0`，前端不展示“未知 / 暂不可用”；正常可调用状态展示为“可调度”，不能退化为数据库 `active` 的“正常”。独立账户 `status-snapshot` HTTP 路由已删除；页面未消费的字段不得仅因领域对象已有而加入列表投影。投影读为 Node 侧默认关闭、生产未启用的可选演进，Go 未采用；两条列表路由权威契约为 live hydrate。
- `GET /__aisys__/api/accounts/options`、`GET /__aisys__/api/my-accounts/options`：返回授权资源、模型检测、审计和用量筛选下拉所需的 AI 账户最小摘要，可包含 `systemAccountId/systemAccountName`（仅管理侧）、`ownerSystemAccountId/ownerSystemAccountName`、`providerCode`、`providerProtocolProfileId`、`protocolCode`、`protocolVersion`、`name`、`type`、有效 `status`、`accessType`、授权状态字段、`accountExpiresAt` 和完整 `permissions`；支持 `ids`、`page`、`keyword`、`providerCode`、`groupId`、`tagIds`、`type`、`status`、`schedulable` 和 `limit=1..50` 远程搜索，`sorts` 必须稳定忽略。关键词只按账号名称精确 / 前缀或专用名称检索索引命中，不搜索 notes、分组名、账号 ID、供应商编码或账户类型；不得返回或读取凭据、用量、并发、质量分、完整列表字段或长文本备注。Go W2 已覆盖 owner + 授权账户只读 union、`accessType=authorized`、授权状态字段、authorized permissions、owner `tagIds` 命中任一标签过滤、账号标签只读下拉、未绑定标签删除、独立 PATCH 标签集合替换和名称包含搜索，但不覆盖授权来源 / grant / 授权写接口、主账户写入 `tags`、OAuth / 导入等标签写路径、完整账号 summary 响应、operation log 保留清理或其他写接口 operation log。
- `GET /__aisys__/api/my-authorization-options/grantee-accounts`：所有登录用户可用，返回全系统授权对象选择所需的 `id`、`username`、`displayName`、`status`，支持 `ids`、`keyword` 和 `limit`；`ids` 用于已选授权对象回填，支持逗号或重复参数，最多 50 个；该候选目录按产品口径允许全系统可见，但不得返回角色、改密状态、最后登录时间等系统账户管理字段。Go W2 已覆盖该 grantee accounts 只读端点。
- `GET /__aisys__/api/my-authorization-options/grantee-teams`：所有登录用户可用，返回全系统授权对象选择所需的系统团队最小摘要 `id`、`name`、`status`，支持 `ids`、`keyword` 和 `limit`；该候选目录按产品口径允许全系统可见，但不得返回成员明细。Go W2 已覆盖该 grantee teams 只读端点。
- `GET /__aisys__/api/authorization-options/grantee-accounts`：仅管理员管理侧使用，返回管理授权时需要的系统账户摘要，支持 `ids`、`keyword` 和 `limit`；普通用户必须返回 403。Go W2 已覆盖该 grantee accounts 只读端点。
- `GET /__aisys__/api/authorization-options/grantee-teams`：仅管理员管理侧使用，返回管理授权时需要的系统团队最小摘要，支持 `ids`、`keyword` 和 `limit`；普通用户必须返回 403。Go W2 已覆盖该 grantee teams 只读端点。
- `GET /__aisys__/api/groups`、`GET /__aisys__/api/my-groups`：返回分组列表，并在同一响应内返回当前页的 `accountStats.currentConcurrency` 和 `todayUsage`。`currentConcurrency` 由当前页分组成员账户 ID 的一次批量实时读取求和覆盖：单机 go-only 形态事实源是网关进程内运行时并发计数（`MemoryAccountConcurrency`，与 dispatch 引擎同一实例），按分组成员去重求和后写入 `accountStats`；`juhe_stats.group_account_stats.current_concurrency` 列由 jobs 维护但当前恒 0，仅作为运行时读数失败时的降级保留值（保留后渲染 0）。账户数 / 可用 / 状态等计数仍来自 `group_account_stats` 预聚合（PG 方言必须以 `juhe_stats.` 限定表名）。授权实例必须按来源账户事实 ID 汇总；并发无占用时返回 `0`；独立分组 `status-snapshot` HTTP 路由已删除。
- `GET /__aisys__/api/groups/options`、`GET /__aisys__/api/my-groups/options`：返回 API Key、授权和资源筛选下拉所需的分组最小摘要，字段白名单为 `id`、`name`、`groupKind`、`enabled`，可附带已定义的归属、`accessType`、`groupAuthorizationId`、授权状态 / 到期 / limits 和 `permissions`；支持 `ids`、`keyword`、`groupKind`、`limit=1..50`、`manageableOnly` 和 `preferDefault`，不接受 `providerCode`（返回 `400 legacy_group_provider_field`）；非 `manageableOnly=true` 时应返回 owner 分组与授权给 viewer 的可见分组，关键词只按分组名称做精确 / 前缀匹配，不得返回 `accountStats`、`accountIds`、用量或并发快照。
- `GET /__aisys__/api/groups/route-strategy-options`、`GET /__aisys__/api/my-groups/route-strategy-options`：策略路由编辑器专用分组下拉，字段严格为 `id`、`name`、`groupKind`、`enabled`，支持 `keyword`、`ids`、`limit=1..50`，不接受 `providerCode`、`accountIds` 或成员明细；候选只包含当前作用域可绑定的 owner/有效授权分组，超级分组作为一个目标返回，成员只能由 `/super-members` 接口读取。
- `GET /__aisys__/api/groups/account-options`、`GET /__aisys__/api/my-groups/account-options`：返回账户页所需的分组最小摘要加 `accountIds`，字段至少含 `id/name/groupKind/enabled`；仅用于账户到分组名映射、默认分组和绑定分组下拉，不接受 `providerCode`，授权分组的 `accountIds` 必须为空，避免暴露授权方成员账号。
- `GET /__aisys__/api/authorization-options/grantee-groups`、`GET /__aisys__/api/my-authorization-options/grantee-groups`：返回授权创建弹窗所需的目标用户分组最小摘要，字段至少含 `id/name/groupKind/enabled`，必须传 `granteeSystemAccountId`；不接受 `providerCode`，只返回目标 active 用户自己的启用分组，不能返回分组成员、用量、并发快照、授权来源或 grant。
- `GET /__aisys__/api/authorizations/:id`、`GET /__aisys__/api/my-authorizations/:id`：授权详情只按 `resource_authorization_grants.id` 读取授权业务记录，返回授权关系、来源、额度和权限摘要；不能把 `resource_authorizations.id` 当作详情路径 ID，也不能把详情接口作为消耗明细数据源。管理员列表与详情带 `systemAccountId` 时强制资源归属作用域：列表在该作用域下 `direction=outbound/inbound` 生效（`outbound` 只返回该用户授权出去的关系，`inbound` 只返回授权给该用户的关系，含其作为活跃成员的团队），详情资源归属与该作用域不匹配时按 404 处理。
- `POST /__aisys__/api/authorizations`、`POST /__aisys__/api/my-authorizations`：资源归属人不能把自己的 AI 账户或分组授权给自己；即使授权对象候选接口返回当前用户用于统一选择器展示，提交自授权仍必须失败。创建 / 恢复只读取资源、授权对象和目标分组所需最小投影，成功返回 `{ item, created, previousStatus? }` 的列表可合并 mutation，不再为响应装配完整授权详情或重载列表。团队授权 AI 账户创建时为每个活跃成员克隆授权实例并绑定成员自己的同供应商默认启用分组；任一成员缺少该默认分组时整个创建事务失败，返回指明成员的中文错误（`团队成员 X 缺少该供应商的默认分组`），系统不自动补建分组。
- `PATCH /__aisys__/api/authorizations/:id`、`PATCH /__aisys__/api/my-authorizations/:id`：授权普通更新只按 `resource_authorization_grants.id` 授权业务记录 ID 操作，管理侧可按 `systemAccountId` 收窄资源归属作用域，用户侧忽略 `systemAccountId` 并固定当前登录用户；请求体必须携带 `expectedUpdatedAt`，并只允许实际变化的 `status=active/paused`、`expiresAt` 和 `limits`，至少提交一个变化字段；`expiresAt:null` 和 `limits:null` 表示清空。响应固定为列表可合并的 `id/status/expiresAt/limits/updatedAt`，同值不推进版本，过期版本返回 `409`。
- `PATCH /__aisys__/api/authorizations/:id/expire`、`PATCH /__aisys__/api/my-authorizations/:id/expire`：授权有效期更新同样只按 `resource_authorization_grants.id` 操作，管理侧和个人侧作用域与普通更新一致；请求体必须提交 `expiresAt`，可选提交 `limits`，两者都允许 `null`；该接口不接受 `status`，后台批量到期 worker 不属于 HTTP 有效期配置更新。
- `DELETE /__aisys__/api/authorizations/:id`、`DELETE /__aisys__/api/my-authorizations/:id`：授权回收只按 `resource_authorization_grants.id` 授权业务记录 ID 操作，管理侧可按 `systemAccountId` 收窄资源归属作用域，用户侧忽略 `systemAccountId` 并固定当前登录用户；不能把 `resource_authorizations.id` 当作回收路径 ID。
- `GET /__aisys__/api/authorizations/usage/team-details`：仅管理员管理侧使用，按日期、分页和筛选条件现场聚合授权团队日摘要行；固定返回 `range/rows/total/page/pageSize/hasMore`，不接受 `includeSummary`，`total` 只是分页上界。
- `GET /__aisys__/api/authorizations/usage/user-details`：仅管理员管理侧使用，按日期、分页和筛选条件现场聚合授权用户日摘要行；固定返回 `range/rows/total/page/pageSize/hasMore`，不接受 `includeSummary`，`total` 只是分页上界。
- `GET /__aisys__/api/my-authorizations/usage/team-details`：所有登录用户可用，忽略 `systemAccountId`，按当前用户作为资源归属人聚合授权团队日摘要行，分页契约同管理侧团队消耗明细。
- `GET /__aisys__/api/my-authorizations/usage/user-details`：所有登录用户可用，忽略 `systemAccountId`，按当前用户作为资源归属人聚合授权用户日摘要行，分页契约同管理侧用户消耗明细。
- `GET /__aisys__/api/authorizations/usage/team-summary` / `user-summary`：仅管理员管理侧使用，按同一 owner、日期和筛选条件折叠日摘要行（计数/Token/成本 SUM、最后使用时间 MAX）返回汇总，只返回 `range/summary`，拒绝分页参数。
- `GET /__aisys__/api/my-authorizations/usage/team-summary` / `user-summary`：所有登录用户可用并强制 self scope，契约同管理侧 summary；伪造 `systemAccountId` 不扩大范围。

## 新增接口检查清单

- 是否明确属于 `/__aisys__/api/my-*` 用户接口、`/__aisys__/api/*` 管理接口还是 `/*` / `/v1/*` 网关接口？
- 如果接口会改变业务状态，是否注册操作日志语义和可见范围？如果只是查询，是否明确不写操作日志？
- 是否明确登录态、管理员权限、资源所有者权限或授权使用权？
- 普通用户可见页面会调用的接口，是否已被 `pnpm --filter juhe-ai-frontend test:api-contract` 的前端调用面固定覆盖（前端调用 ⊆ Go 注册路由）；`my-*` 命名空间下的管理员例外，是否有 Go 授权/挂载测试固定为普通用户 403？
- 是否使用统一成功和错误响应结构？
- 是否需要 `permissions` 摘要？
- 是否做后端参数校验、排序白名单和系统账户隔离？
- 是否会返回或记录敏感字段？如会，是否符合 [安全与日志策略](安全与日志策略.md)？
- 是否需要同步前端类型、功能设计、存储设计（[PostgreSQL 与 Redis 高性能模式设计](PostgreSQL与Redis高性能模式设计.md)）、开发验证或部署文档？
