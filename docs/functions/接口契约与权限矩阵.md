# 接口契约与权限矩阵

> 面向前端、后端与 AI 维护者。
> 本文统一管理后台 `/__aisys__/api/*`、网关 `/*` 与 `/v1/*`、响应结构、分页筛选、错误语义和核心权限矩阵，避免接口口径散落在页面、路由和计划文档里。

## 文档目标

- 固定前后端对接口返回、错误、分页、筛选和权限摘要的共同理解。
- 明确 `super_admin`、`admin`、普通 `user`、资源所有者和被授权用户在各模块里的操作边界。
- 给新增接口提供默认契约，减少每个路由自行设计返回结构。
- 只记录稳定契约，不替代具体功能字段说明；业务字段仍以 [核心功能设计](核心功能设计.md) 和 [SQLite 存储说明](SQLite存储说明.md) 为准。

## 接口分层

| 接口层 | 路径 | 身份来源 | 返回风格 | 说明 |
| --- | --- | --- | --- | --- |
| 用户 API | `/__aisys__/api/my-*` | 后台登录态 Cookie | 项目管理 API 结构 | 前端 `我的...` 页面使用，后端强制当前登录用户作用域，忽略 `systemAccountId` 查询。 |
| 管理 API | `/__aisys__/api/*` | 后台登录态 Cookie | 项目管理 API 结构 | 前端管理页面使用，默认需要 `requireAuth`；涉及跨系统账户管理、全局数据或系统配置的接口必须叠加 `requireAdmin`，系统账户写入接口还必须叠加 `requireSuperAdmin`。 |
| 静态帮助页面 | `/__aisys__/help/*` | 后台登录态 Cookie | 静态 HTML | 由主 Web 进程在 `express.static` 前校验登录态；未登录跳转登录页，普通用户访问管理员手册时跳转普通用户手册。 |
| 公开 API | `/__aisys__/health`、`/__aisys__/api/health`、公开品牌设置、登录和验证码 | 无登录态或登录流程 | 项目管理 API 结构 | 只暴露健康检查、未登录所需品牌信息、登录验证码和登录接口。 |
| 外部集成 API | `/__aipublic__/*` | Bearer 来源 token | 项目管理 API 结构 | 面向允许来源系统的后端服务，不使用后台登录态；当前只提供 API Key、路由策略、分组和 AI 账户公开维护接口。 |
| 网关 API | `/*`、`/v1/*` | 本地网关 API Key | 协议原生或本地统一错误结构 | 面向 OpenAI 兼容客户端和 Anthropic native 客户端，不使用后台登录态，不返回管理 API 包装；系统前缀 `/__aisys__/*` 除外。 |

后台管理 API 在 `/__aisys__/api` 下有系统设置可配置的粗限流：IP 级读 / 写限流先于 JSON body parser 执行，登录用户级读 / 写限流在 `requireAuth` 之后执行；命中后返回 `429`、中文 `message` 和 `Retry-After`。`/__aisys__/api/health` 不参与该限流。

网关 API 的“OpenAI 兼容”只表示 OpenAI v1 本地入口、认证和基础响应结构尽量兼容 OpenAI 客户端，不表示每种上游账号都支持公开 OpenAI API 全路径。Anthropic 官方直连使用独立 `anthropic/v1` 档案，只承接 Anthropic Messages / Models / Count Tokens 形态。具体能力以 [OpenAI 账号接入](OpenAI账号接入.md)、[Anthropic 账号接入](Anthropic账号接入.md)、[智谱 GLM 账号接入](智谱GLM账号接入.md) 和 [DeepSeek 账号接入](DeepSeek账号接入.md) 的账号类型能力矩阵为准：GPT API Key 账号按上游 `/v1` 透传，GPT OAuth 账号只通过 Codex adapter 支持明确列出的 Responses 路径，Anthropic 当前只支持 API Key 账号，不实现 OAuth / Setup Token / Claude Code token 账号链路；GLM 和 DeepSeek 作为 OpenAI-compatible 第三方默认只声明 Chat Completions JSON / SSE；Claude Code 仅作为下游客户端画像接入。

当前后端已挂载 API Key、路由策略、分组和 AI 账户公开维护接口：`GET /__aipublic__/api-key/list`、`GET /__aipublic__/route-strategy/list`、`GET /__aipublic__/group/list`、`GET /__aipublic__/account/list` 以及对应 `POST /add|/update|/del` 写接口，用于外部来源系统对指定系统用户执行受控资源对账、新增、修改和删除。`sub2api-lite` 不再提供来源鉴权 demo、IP 维度消耗排行、IP 维度消费聚合、账号维度实际消耗聚合或公益接入信息接口，也不实现公益站用户维度排行榜快照。

PLAN-0143 正在扩展供应商认证与协议契约：xAI/Grok 使用官方 API Key 并接入 OpenAI Chat / Responses；Gemini 增加官方 Google OAuth 和原生 Interactions；Anthropic 当前仍只开放 API Key。官方 Workload Identity Federation 仅完成能力调研，因为静态数据库 IdP JWT 无法自动获取或轮换可信 assertion，本次不增加 `workload_identity` 账户类型、导入、表单或运行时 token exchange；后续需先具备受控的服务端 assertion provider。GPT 模型目录新增 `codex-auto-review`，但不主动写入账户默认模型。

## 菜单入口与视图范围

- `super_admin` 和 `admin` 同时拥有用户身份和管理员身份，因此前端提供用户模式和管理模式；左侧菜单只展示当前模式的入口，头部用户下拉提供模式切换。
- 管理角色首次进入默认用户模式；切换后可把菜单模式作为当前浏览器里的个人使用习惯保存，下次登录或访问根路径时沿用上次模式。该偏好只影响前端入口，不改变后端权限。
- 普通用户只显示用户侧入口；管理角色在用户模式的 `我的...` 入口中也只能按当前登录用户查询自己的数据，不能因为角色是管理员就自动进入全局查询范围。
- 管理侧入口必须使用管理员路由和管理员接口能力，例如 `AI 账户管理`、`AI 分组管理`、`API Key 管理`、`模型检测`、`使用记录管理`、`用量统计管理`、`AI性能监控` 和 `统一授权管理` 下的 `统一授权`、`团队消耗明细`、`用户消耗明细`、`授权团队`。
- 用户侧入口必须使用当前用户作用域，例如 `我的 AI 账户`、`我的分组`、`我的 API Key`、`模型检测`、`我的使用记录`、`我的用量`、`统计概览`、`AI性能监控`，以及 `我的授权` 下的 `授权操作`、`团队消耗明细`、`用户消耗明细`、`我的授权团队`。
- 用户侧页面优先调用 `/__aisys__/api/my-accounts`、`/__aisys__/api/my-groups`、`/__aisys__/api/my-api-keys`、`/__aisys__/api/my-model-checks`、`/__aisys__/api/my-authorizations`、`/__aisys__/api/my-openai-oauth`、`/__aisys__/api/my-usage-records`、`/__aisys__/api/my-stats` 和 `/__aisys__/api/my-teams`；用户侧 `我的授权` 下的消耗明细调用 `/__aisys__/api/my-authorizations/usage/team-details` 和 `/__aisys__/api/my-authorizations/usage/user-details`，`统计概览` 使用 `/__aisys__/api/my-stats/usage-overview`，用户侧 `AI性能监控` 使用 `/__aisys__/api/my-stats/ai-performance`。
- AI 问答使用 `/__aisys__/api/my-chat/*` 登录用户接口。会话列表、消息游标、API Key 选项、模型选项、发送 SSE、停止和删除都强制使用当前 session 的 `systemAccountId`，忽略或拒绝客户端提交的用户 ID；管理员从个人入口调用时同样不能查看其他用户聊天。
- `/__aisys__/api/my-chat/conversations/:id/stream` 使用真实会话绑定 API Key 进入 `/v1/chat/completions`，但仍属于登录态用户接口；同会话只允许一个活动轮次，不同会话可并发。容量超限只禁止新发送，读取、停止与删除保持可用。
- 用户侧页面如果需要表单下拉或辅助目录，只能调用用户侧接口或明确允许登录用户访问的轻量辅助接口，例如 `/__aisys__/api/my-accounts/options`、`/__aisys__/api/my-groups/options`、`/__aisys__/api/my-route-strategies/options`、`/__aisys__/api/my-authorization-options/*`、`/__aisys__/api/providers/:code/models`、`/__aisys__/api/providers/models/options` 和 `/__aisys__/api/proxies/options`；新增此类调用必须同步加入 `pnpm test:scope`。`my-authorization-options/grantee-groups` 只返回指定被授权用户可作为授权账户目标绑定的分组最小摘要，不返回分组成员、用量或并发信息。
- 管理侧页面保留 `/__aisys__/api/accounts`、`/__aisys__/api/groups`、`/__aisys__/api/api-keys`、`/__aisys__/api/model-checks`、`/__aisys__/api/authorizations`、`/__aisys__/api/openai-oauth`、`/__aisys__/api/usage-records`、`/__aisys__/api/stats` 等管理入口；`/__aisys__/api/stats/ai-performance` 和 `/__aisys__/api/stats/ai-performance/accounts` 是管理侧 AI 性能监控入口，并由后端显式校验管理员身份。
- 管理侧列表、详情、筛选选项和已有资源操作未传 `systemAccountId` 时表示管理员全局作用域；传入具体 `systemAccountId` 时收窄到该系统账户。新建、导入、OAuth 创建这类需要写入新资源归属的动作仍必须明确目标系统账户，不能把全局作用域当作默认归属。
- 系统账户管理是管理角色唯一的差异点：`GET /__aisys__/api/system-accounts` 和 `GET /__aisys__/api/system-accounts/options` 允许 `super_admin` / `admin` 查看；`POST /__aisys__/api/system-accounts`、`PATCH /__aisys__/api/system-accounts/:id` 只允许 `super_admin`，普通管理员必须返回 403。默认仅 `admin/admin` 是 `super_admin`；系统账户写入接口只允许提交 `admin` / `user` 角色，不能新增或升级其他 `super_admin`。
- 同一 Vue 页面可以复用，但系统账户筛选、系统账户列、全量管理接口和跨用户查询只能在管理侧入口启用。

## 管理 API 响应

当前实现已使用 `backend/src/shared/http.ts` 的 `ok(data, message?)` 和 `badRequest(message)` 作为基础约定。后续新增接口优先沿用以下结构。

成功响应：

```json
{
  "data": {},
  "message": "可选中文提示"
}
```

错误响应：

```json
{
  "message": "中文错误提示",
  "code": "可选稳定错误码",
  "details": {}
}
```

约定：

- 成功响应必须包含 `data`；没有业务返回值时可返回 `{ "data": { "ok": true } }`，删除接口也可以使用 `204 No Content`。
- `message` 面向前端直接展示，默认使用中文；后端内部日志、脚本输出和使用记录错误摘要中的系统自定义描述也必须使用中文。
- 只翻译面向人阅读的描述性文案，不翻译机器可读字段或协议值；`code`、`type`、`event`、状态枚举、header、路由路径、SQL 常量、缓存 key、OpenAI / SSE 事件名和数据库字段值必须保持稳定。
- 技术名词可以保留原文并嵌入中文文案，例如 `API Key`、`OAuth`、`Bearer Token`、`Refresh Token`、`access_token`、`HTTP` 和 `SSE`。
- 简单错误可以只返回 `{ "message": "..." }`；需要前端分支处理、脚本识别或跨接口复用的错误必须提供稳定 `code`。
- `details` 只放字段级校验摘要、可安全展示的限制原因或操作上下文，不放敏感凭据、完整请求体、完整上游响应或 token。
- 前端不能通过 HTTP 状态码之外的字段自行推断权限，必须以接口返回和 `permissions` 摘要为准。
- `我的授权` 必须包含当前用户授权出去和授权给当前用户的记录；授权给当前用户但资源不属于当前用户的记录只提供查看、明细和归还入口，不能展示暂停、回收或修改配置等管理动作。

## HTTP 状态

| 状态码 | 使用场景 | 前端处理 |
| --- | --- | --- |
| `200` | 查询、更新、操作成功 | 读取 `data`，必要时展示 `message`。 |
| `201` | 创建成功 | 读取 `data`，创建 API Key 时注意明文只按约定展示。 |
| `204` | 删除或无返回内容操作成功 | 不读取 body，直接刷新列表或回到上级页面。 |
| `400` | 参数格式错误、业务输入不合法 | 展示 `message`，表单场景尽量定位字段。 |
| `401` | 未登录、会话过期、网关密钥缺失或无效 | 后台跳转登录；网关返回 OpenAI 兼容错误。 |
| `403` | 已登录但无权限 | 展示无权限提示，不自动重试。 |
| `404` | 资源不存在或当前用户不可见 | 展示不存在或已失效，避免暴露其他用户资源是否存在。 |
| `409` | 名称唯一约束、重复授权、批量编辑乐观版本冲突等 | 展示冲突原因，引导用户更换输入、刷新资源或处理旧关系。 |
| `429` | 后台接口限流、登录限频、上游限流或账号冷却 | 展示冷却或稍后重试信息。 |
| `500` | 未知服务端错误 | 展示通用错误，详细信息只进入安全日志。 |
| `502` | 上游 OAuth、上游模型或代理请求失败 | 展示上游请求失败摘要，避免暴露完整上游敏感响应。 |

## 页面数据变更确认接口（PLAN-0115 目标契约）

> 本节记录 [页面数据缓存与增量更新设计](页面数据缓存与增量更新设计.md) 的目标契约；截至当前仅为待实现规格，不能据此判断接口已经挂载。

- `POST /__aisys__/api/data-changes/confirm`：登录用户读取当前页面关心的数据域 revision。普通用户和管理角色用户模式由后端固定当前用户 scope；管理模式可以带目标系统账户，但 scope、权限指纹和不透明摘要均由后端根据登录态计算，不能信任前端自报身份。
- 请求最多包含 32 个稳定数据域及各自 `{ protocolVersion, epoch, sequence }` token；数据域不得包含任意查询文本、页码或筛选值。未知域、重复域、非法 token 或超出数量返回 400。
- 响应按域返回 `unchanged`、`delta`、`reload` 或 `reset` 以及新 token；`delta` 只返回变化实体 ID 和 field mask，不返回任意领域完整 DTO。
- confirm 只读 Redis state 或 standalone DB service 内存 revision，业务数据库查询次数必须为 0。performance Redis 不可用时返回 503 和 `Retry-After`，不能回源 PostgreSQL 承接页面轮询。
- 具体数据继续由强类型领域接口读取：AI 账户使用字段快照，静态列表使用实体 upsert / tombstone，使用记录和日志使用 `(createdAt, id)` cursor，统计使用既有预聚合区块接口。
- epoch 变化、cursor 早于服务端最老变更、field mask 版本未知、权限 scope 变化或日志不连续时返回 `reset`，前端只重建受影响域。
- 该接口沿用 System API 读限流、登录态和 `Cache-Control: no-store`；前端 IndexedDB 缓存是应用层显式存储，不依赖浏览器 HTTP cache。

## 登录与当前用户接口

- `GET /__aisys__/api/auth/me`：登录用户读取当前会话用户摘要，返回 `id`、`username`、`displayName`、`role` 和有效 `mustChangePassword`；管理员角色始终返回 `false`。Go W3 当前已覆盖该只读端点的 opt-in 实现；它不 touch session。
- `POST /__aisys__/api/auth/logout`：登出当前后台会话；接口允许无 Cookie 或已失效 Cookie 调用，有 `juhe_ai_session` 时按当前 token hash 删除 `system_sessions` 对应行，成功返回 `200 { data: { loggedOut: true } }` 并清除 `juhe_ai_session` Cookie；清 Cookie 的 `Secure` / `SameSite` 必须和登录签发 Cookie 使用同一运行时配置。Go W3 当前已覆盖该当前会话撤销端点的 opt-in 实现；它不 touch session，也不撤销其他会话。
- `GET /__aisys__/api/auth/sessions`：登录用户读取自己未过期后台会话列表；走普通后台会话鉴权，普通用户初始密码未修改时仍按普通管理鉴权返回 `403` 和 `must_change_password`。支持 `page/pageSize`，默认 `1/20`，`pageSize` 最大 100；响应为 `{ items, total, hasMore, page, pageSize }`，`total` 只作为窗口上界，不做全表精确 `COUNT(*)`。列表项只返回 `id`、`current`、`createdAt`、`lastSeenAt` 和 `expiresAt`，不得读取或返回 `token_hash` / `password_hash`。Go W3 当前已覆盖该只读端点的 opt-in 实现；它不 touch session。
- `DELETE /__aisys__/api/auth/sessions/:id`：登录用户撤销自己系统账户下的指定后台会话；走管理端写鉴权并按 60 秒窗口 touch 当前 session，只允许按当前 `systemAccountId + sessionId` 删除，不能跨账户撤销。成功返回 `{ id, revoked: true, current }`；撤销当前 session 时必须清除 `juhe_ai_session` Cookie，清 Cookie 的 `Secure` / `SameSite` 和登录签发 Cookie 一致；会话不存在或不属于当前用户返回 `404 { message: "会话不存在" }`。Go W3 当前已覆盖该写端点的 opt-in 实现；暂不写 operation log。
- `PATCH /__aisys__/api/auth/me`：登录用户修改自己的显示名称，只接受 `displayName`；未知字段、缺字段、非字符串和空字符串返回 `400 { message: "用户资料参数无效" }`，包含任何空白字符返回 `400 { message: "显示名称不能包含空格" }`，大小写不敏感重复返回 `409 { message: "用户名称已存在" }`。用户名、角色、状态、图像生成权限和初始改密状态仍只能由系统账户管理或改密流程调整。普通用户初始密码未修改时返回 `403` 和 `must_change_password`。Go W3 当前已覆盖该资料更新端点的 opt-in 实现，并在真实变更时 best-effort 写入 `auth.update_profile` 操作日志；写鉴权会按 60 秒窗口 touch 当前 session。
- `POST /__aisys__/api/auth/change-password`：登录用户修改密码，只接受严格 JSON `{ oldPassword?: string, newPassword: string }`。`newPassword` 必填且至少 4 位，未知字段、非字符串、`null`、`oldPassword=""` 返回 `400 { message: "密码参数无效" }`；新旧密码包含任意空白字符返回 `400 { message: "登录密码不能包含空格" }`。普通用户初始密码强制修改场景可只提交新密码；普通改密和管理员改密必须提交并校验当前密码，缺旧密码返回 `400 { message: "请填写当前密码" }`，旧密码错误返回 `400 { message: "当前密码不正确" }`。成功后写入 Node 兼容 PBKDF2-SHA512 `password_hash`、清除 `mustChangePassword`、只保留当前会话，响应返回完整系统账户摘要但不返回密码 hash。Go W3 当前已覆盖该改密端点的 opt-in 实现；写鉴权会按 60 秒窗口 touch 当前 session。

## 静态帮助页面

- `GET /__aisys__/help/`：已登录用户按角色跳转到对应手册；管理员进入管理员手册，普通用户进入普通用户手册。
- `GET /__aisys__/help/user/`：所有已登录用户可访问普通用户手册。
- `GET /__aisys__/help/admin/`：仅 `super_admin` 和 `admin` 可访问；普通用户访问时跳转到普通用户手册。
- 未登录访问任意帮助页面时，后端返回 `302` 到 `/__aisys__/login?redirect=原始帮助路径`；登录页识别该静态 redirect，登录成功后使用浏览器跳转回帮助页面。

## 模块操作补充

### AI 账户

- `POST /__aisys__/api/accounts`、`PATCH /__aisys__/api/accounts/:id` 和 OpenAI OAuth 创建接口统一支持 `supportedModels: string[]` 与 `healthCheckModel: string`；最终支持模型必须非空，检查模型必须属于最终支持模型并满足协议最小检查能力。创建时未提交 `supportedModels` 按供应商默认支持模型回填，未提交 `healthCheckModel` 按“当前系统账户个人默认 > 管理员维护的供应商系统默认 > 协议档案内置默认”解析并持久化；默认值只初始化新账户。GLM 和 DeepSeek 账户继续按各自供应商与协议档案目录校验模型。
- `GET /__aisys__/api/accounts` 和用户侧 `my-accounts` 列表返回展示、筛选、权限、版本控制以及测试首开所需摘要；不返回完整 `supportedModels`、完整 endpoint modes 或凭据，但必须返回非敏感的 `healthCheckModel` 与 `healthCheckEndpointMode`，供测试弹窗直接初始化。`GET /__aisys__/api/accounts/:id` 和用户侧详情接口返回完整配置；授权实例可只读查看来源有效值。
- 新建账户以及导入请求中声明的 `active` 都先保存为 `pending_test`，提交事务后投递后台激活检查，成功后才进入 `active`；明确提交 `disabled` 时保持停用且不投递激活检查。凭据、Base URL、协议档案或关键代理等连接配置编辑后同样交给后台激活复检，人工测试任务 ID 和结果不能作为激活凭证。
- `PATCH /__aisys__/api/accounts/:id` 和用户侧 `my-accounts/:id` 只允许资源所有者修改账号硬并发上限。授权账户的 `concurrencyLimit` 由来源账号共享控制，被授权人或管理员代被授权人通过普通更新接口提交该字段时必须返回 `400`，不能修改来源账号或授权实例账号里的并发上限。
- `GET /__aisys__/api/accounts/tags` 和 `GET /__aisys__/api/my-accounts/tags` 返回当前系统账户维度的标签下拉，字段包含 `id`、`name`、`accountCount`、`createdAt` 和 `updatedAt`；`DELETE /__aisys__/api/accounts/tags/:tagId`、`DELETE /__aisys__/api/my-accounts/tags/:tagId` 只允许删除当前作用域内未绑定任何未删除账户的标签，成功返回 `204 No Content`，绑定中返回 `400 { message: "标签已绑定账户，不能删除" }`，不存在或越权返回 `404 { message: "标签不存在" }`。Go W2 已覆盖 GET 标签下拉、DELETE 未绑定标签和独立 PATCH 标签集合替换。
- `POST /__aisys__/api/accounts`、`PATCH /__aisys__/api/accounts/:id`、`PATCH /__aisys__/api/accounts/:id/tags`、用户侧 `my-accounts` 同源接口和 OpenAI OAuth 创建接口支持 `tags: string[]`。单个账户最多 24 个标签，单个标签最长 40 个字符，后端会去空白并按大小写敏感去重；`Prod` 和 `prod` 属于两个不同标签；账户列表和详情在账户摘要中返回 `tags`。Go W2 opt-in 仅覆盖 `PATCH /__aisys__/api/accounts/:id/tags` 和 `PATCH /__aisys__/api/my-accounts/:id/tags` 的独立标签集合替换；不覆盖账户创建 / 编辑请求体 `tags`、OpenAI OAuth 创建和导入确认标签写入。当前 Go PATCH 已 best-effort 写入 operation log，Go operation log 读接口也已补；但独立标签 PATCH 成功响应仍不是完整账号详情契约，且仍缺前端 smoke、生产单 owner 切流和 Node 删除证据，不能作为生产接管或 Node 删除证据。
- `GET /__aisys__/api/accounts` 和用户侧 `my-accounts` 的 `keyword` 只按 AI 账户名称做精确 / 前缀 / 包含匹配；账户名称最长 128 个字符，包含匹配必须由 `account_name_search_terms` 先收敛候选账号 ID，再由 `account_name_search_documents.normalized_name` 校验连续片段，不在 `accounts` 主表执行无界 `%keyword%`。供应商、协议档案、账户类型、分组和标签筛选分别使用 `providerCode`、`providerProtocolProfileId`、`type`、`groupId` 和 `tagIds` 查询参数，`tagIds` 可用英文逗号分隔多个标签 ID，多个标签按命中任一标签筛选。管理侧未传具体 `systemAccountId` 时，分组选项和 `groupId` 筛选按管理员全局可见范围生效；标签字典按系统账户维度维护，前端管理侧仅在选择具体系统账户后提供标签筛选。
- `supportedModels` 的可选值必须来自所属供应商模型目录。写入时后端去重、去空白并校验目录；账户支持模型不能清空。`providerCode=glm` 时只允许选择 GLM 目录模型，不能从 `openai` 聚合目录或 `gpt` 目录借用模型名。
- 智谱 GLM 账户只支持 `type=api_key`；页面接入类型分为通用 GLM API Key、GLM Coding Plan Key 和 GLM Coding Anthropic Key。创建、导入预览、导入确认和公开外部账号推送必须提交 `providerProtocolProfileId = profile_glm_general_openai_v1 | profile_glm_coding_openai_v1 | profile_glm_coding_anthropic_v1`；接口层只接收显式协议档案字段，不能只靠 `credentials.base_url` 区分通用 GLM API、GLM Coding Plan 和 GLM Coding Anthropic。GLM OpenAI 档案默认只具备 OpenAI 标准请求能力，默认端点能力只包含 Chat JSON/SSE，不声明 Responses。
- DeepSeek 账户只支持 `type=api_key`；页面接入类型分为 DeepSeek OpenAI API Key 和 DeepSeek Claude Code（Anthropic-compatible）API Key。创建、导入预览、导入确认和公开外部账号推送必须提交 `providerCode = deepseek` 和 `providerProtocolProfileId = profile_deepseek_openai_v1 | profile_deepseek_anthropic_v1`。接口层不能只靠 `credentials.base_url` 猜测档案，也不能接受 DeepSeek OAuth、Refresh Token、Setup Token 或 Claude Code token 字段。OpenAI 档案默认只具备 Chat Completions JSON / SSE，不声明 Responses、FIM、Chat Prefix beta、Strict Tool Calls beta 或 Anthropic Messages；Anthropic 档案默认只具备 Messages JSON / SSE，不声明 Count Tokens 或 OpenAI Chat。
- Anthropic 账户当前只支持 `type=api_key`，固定落到 `providerCode=anthropic`、`providerProtocolProfileId=profile_anthropic_anthropic_v1`。`credentials.api_key` 保存上游 Anthropic API Key，`credentials.base_url` 默认可使用 `https://api.anthropic.com/v1`，`credentials.supported_endpoint_modes` 只允许 `messages_json`、`messages_sse`、`message_token_counting`。`anthropic-version` 和 `anthropic-beta` 属于客户端请求 header，不作为账号凭据字段；接口层不接受 Anthropic OAuth、Setup Token、Claude Code token 或 GPT/Codex OAuth 字段。
- AI 账户继续复用现有 `service_tier_override` 和 `reasoning_effort_override` 两项覆盖；字段缺失表示保留客户端值，只有 `service_tier_override=default` 表示使用供应商默认，`reasoning_effort_override` 必须是模型目录声明的精确值。其他字符串必须属于账户全部支持模型的共同可用值。后端按账户供应商、账户类型、最终上游模型和目标 driver 校验并写入供应商原生字段；授权实例只读展示来源覆盖值。Anthropic `speed`、thinking budget、Codex `ultra` 和 Responses Multi-agent Beta 首版只按各自字段保护或专属能力处理，不增加账户覆盖控件。
- 账户创建、编辑、导入和公开外部账号推送可提交 `availabilitySchedule`；为空或 `null` 表示不限制时段。账户计划只影响网关账号候选，不改写账户 `status`，时区跟随系统默认值。
- `POST /__aisys__/api/accounts/export` 和 `POST /__aisys__/api/my-accounts/export` 导出当前作用域内可查看凭据且可编辑的自有 AI 账户，授权账户不导出；管理侧可用 `systemAccountId` 指定目标用户，用户侧忽略 `systemAccountId` 并固定当前登录用户。导出账户必须写回当前 `providerProtocolProfileId`，保证导出的 JSON 再导入时能还原到原协议档案，不能依赖 `base_url`、供应商默认值或历史接入类型字段猜测。
- `POST /__aisys__/api/accounts/import/preview`、`POST /__aisys__/api/accounts/import/confirm` 和用户侧 `my-accounts` 同源接口按当前作用域预览或确认导入；普通用户可导入自己的账户并自动创建缺失分组，但只能复用已启用代理，不能创建新代理。
- `PATCH /__aisys__/api/accounts/:id` 和用户侧 `my-accounts/:id` 提交 `clearFailureState: true` 时，除了清理数据库里的冷却、限流、异常和最近错误，也会通知 server 网关进程清理该账号当前的 `degraded` / `local_suppressed` / `precheck_pending` / `precheck_failed` 运行态；授权账户的 `authorized-dispatch` 同理清理当前授权实例账户维度。
- `POST /__aisys__/api/accounts/batch-update` 和 `POST /__aisys__/api/my-accounts/batch-update` 是独立批量编辑事务接口。请求包含去重后至少 2 个 `accountIds`、按 `{ enabled, value }` 表达的显式 `updates` 和覆盖全部目标的 `expectedVersions`；字段名必须来自后端白名单，未启用字段保持原值，启用字段直接覆盖。任一账户无权限、属于授权实例、跨作用域、版本冲突或最终配置非法时整批不写；模型与协议字段只允许全部目标具有相同 `providerCode + providerProtocolProfileId + type` 时提交。
- 批量编辑白名单当前包含标签、代理、并发限制、账户优先级、超级优先、降级备用、账户到期时间、可用时间计划、备注、账户错误处理规则、账户响应检查规则，以及同构账户的支持模型、检查模型、模型映射、endpoint modes 和已登记的供应商请求覆盖配置。名称、归属、分组、供应商、协议档案、类型、凭据、Base URL、状态、健康事实、错误、冷却、统计和运行态必须拒绝。事务提交后只对检查模型、支持模型、模型映射、endpoint modes 或代理发生变化的账户投递后台系统检查。
- `GET /__aisys__/api/accounts/:id/test-options` 和 `GET /__aisys__/api/my-accounts/:id/test-options` 只在用户展开测试模型选择器后请求，响应直接为 `Array<{ id, name }>`；支持 `keyword`、`limit` 和 `selectedIds`，管理端与个人端均使用不含凭据的最小账户上下文。测试弹窗默认模型和请求形态直接来自账户列表行的 `healthCheckModel` / `healthCheckEndpointMode`，不由该接口重复返回。切换模型时使用 `GET .../:id/test-options/models/:modelId` 定点读取 `{ id, name, testEndpointModes }`；提交测试时后端仍重新校验模型和请求形态。模型选项来自账户供应商、协议档案和所有者作用域可见的启用文本模型目录，不受账户 `supportedModels` 限制。
- `POST /__aisys__/api/accounts/:id/test` 和 `POST /__aisys__/api/my-accounts/:id/test` 只创建独立单账户人工测试任务并返回 `202` 与 `AccountTestTask`；列表测试显式提交本次 `model`，新增 / 编辑表单测试固定提交草稿 `healthCheckModel`，后端拒绝表单测试切换到其他模型。任务字段包含 `id`、`testSessionId`、`accountId`、`status=queued|running|success|failed|canceled`、`model`、`clientCompatibility`、`message`、`result`、`queuedAt`、`startedAt`、`finishedAt` 和 `updatedAt`。多 API Key 账户可在 `result.apiKeyPool.results` 返回逐 Key 脱敏诊断，但不能写 Key 运行态。
- `GET /__aisys__/api/accounts/test-tasks/:taskId`、`GET /__aisys__/api/my-accounts/test-tasks/:taskId` 用于查询当前单账户测试任务；`POST /__aisys__/api/accounts/test-tasks/:taskId/cancel` 和用户侧同源接口只取消该任务所属 `testSessionId` 的未完成任务。账户 A、B 使用独立会话，互不阻塞，旧结果不能覆盖后来打开的测试弹窗；项目不提供多账户批量测试创建、批量取消或用户级全局测试 session。
- 人工测试 worker 只负责执行诊断和写入脱敏任务结果、使用记录与审计，`traffic_source = manual_account_test`。测试成功或失败均不得修改账户、授权实例、来源账户、Key、配额快照、健康事实、持久状态、调度运行态、代理桶、客户端回避或会话亲和；真实激活、周期健康和恢复副作用只由对应后台系统检查策略执行。
- `GET /__aisys__/api/providers/:code/models`：登录用户可读取指定供应商模型目录，用于账户编辑、账户测试、模型限制和模型映射下拉。`openai` 只聚合自身与显式纳入的 OpenAI-compatible 子供应商；`gpt`、`anthropic`、`glm`、`deepseek` 分别返回自身目录。模型按 `releaseDate` 倒序；默认只返回当前作用域内启用且可计价的模型，维护页面可传 `includeInactive=true`、`includeUnpriced=true`，管理员还可传 `systemAccountId`。响应直接返回现有扁平价格字段和 `serviceTierPrices`，不增加独立价格接口；built-in 项必须返回数据库模型行现有 `id`。
- `GET /__aisys__/api/providers/models/options` 返回启用供应商的模型名称选项。`POST /__aisys__/api/providers/:code/models` 创建个人或管理员全局自定义模型；`PATCH /__aisys__/api/providers/:code/models/:id` 修改有权限的自定义模型，统一目标还允许管理员用同一路径和模型行 `id` 只更新内置模型价格字段；`DELETE` 只删除有权限的自定义模型。模型 ID 创建后不可修改，提交不同 ID 返回 `400`。
- 聚合目录中的可见自定义模型必须使用响应中的 `providerCode` 发起修改或删除。模型被未删除 AI 账户的支持模型或同来源模型映射引用时，删除返回 `409`，需先解除绑定。
- 计划 0044 继续复用调用方可见模型目录和现有 `modelKey -> providerCode[]` 缓存：零命中或多供应商命中时返回本地明确错误，不能通过覆盖、去重或顺序选择静默消除歧义；不新增 alias claim、catalog surface 或路由表。
- 模型基础信息维护页面只提交展示和能力字段；管理员在同一页面通过模型 `PATCH` 保存现有扁平价格字段和 `serviceTierPrices`，普通用户提交任何价格字段返回 `400`。遗留 `pricingModel` 不展示、不再接受写入。`GET /__aisys__/api/providers` 仍只允许管理员访问。
- 当前价格直接保存在现有模型行，按模型行 `id` 更新并继续支持按 `providerCode + model` 查找，不增加 pricing purpose、profile / rate 表或独立价格 GET / PUT。管理员保存时后端同步校验完整价格、直接更新模型行、写操作审计并失效模型目录缓存；版本发布时内置目录只用已核对的官方快照补齐空价格和空档位价格，不覆盖管理员已有当前价，自定义模型价格不参与该同步。usage 继续按现有路径在入队或写库前固化 `cost_breakdown_snapshot_json` 和 `cost_usd`，历史详情与统计 worker 不按模型目录当前价格重算。
- `supportedServiceTiers` 只描述客户端可请求值；provider driver 将实际默认 / 标准结果归一到 `billed_service_tier=standard` 并读取现有扁平标准价，`serviceTierPrices` 只保存其他实际计费档位且不要求 key 与请求值同名。价格 key 非空且价格非负即可，不增加档位 registry。
- 普通用户以及模型普通 create / update、账户导入和批量编辑 DTO 不接受任何 price、rate、multiplier、price reference 或 `pricingModel` 计价字段；发现后必须返回明确 `400`，不能被 route、service、repository 或上游请求白名单静默过滤。管理员使用同一模型 `PATCH` 的价格分支时，可给内置、全局或个人模型提交现有扁平价格字段和 `serviceTierPrices`；该分支也使用严格 schema，未知字段和服务端字段必须拒绝。
- 各供应商模型响应和 `/providers/models/options` 必须复用 `supportedServiceTiers`、`supportedReasoningEfforts`、`defaultReasoningEffort` 三项现有能力字段，值改为供应商自己的字符串；两组数组继续保持非空类型，空数组统一表示当前目录未声明可选值，不增加“未核验 / 不支持”数据库三态。GPT 内置模型和全部自定义模型的 `defaultReasoningEffort` 固定为 `null`，默认行为交给上游；模型写接口只维护可选能力数组，提交默认值时归一为空。Codex `/models` 使用独立的 Codex 默认 reasoning、支持级别、服务等级和多代理版本字段，不再为所有模型伪造统一能力。
- `PUT /__aisys__/api/providers/:code/default-health-check-model`：登录用户可设置当前系统账户作用域下的供应商个人默认检查模型；管理员可通过 `systemAccountId` 指定目标系统账户，普通用户传入该字段时固定到当前登录用户。请求体只接受 `{ model: string }`，模型必须在目标作用域可见、状态为 `active` 且属于可用于协议最小检查的文本生成模型。成功返回 `{ data: { providerCode, defaultHealthCheckModel } }`，写入 `provider_default_health_check_models`；管理员维护的供应商系统默认和协议档案内置默认作为更低优先级。所有默认只用于初始化新账户，不修改已有账户的 `healthCheckModel`、支持模型或检查任务。
- 不提供账户级 `default-test-model` / `default-health-check-model` 独立保存接口。已有账户的检查模型只能通过单账户编辑或批量编辑白名单中的 `healthCheckModel` 修改，并继续满足最终 `supportedModels` 校验。
- `GET /__aisys__/api/response-inspection-policies`：管理员读取响应检查默认规则和管理端策略，返回 `scopeType`、`protocolCode`、可选 `providerCode`、语义匹配条件和 `action`。`POST /__aisys__/api/response-inspection-policies` 与 `PUT /__aisys__/api/response-inspection-policies/:id` 只接受当前完整结构：`scopeType = protocol` 时不允许提交 `providerCode`，`scopeType = provider` 时必须提交已启用 OpenAI v1 供应商编码；`outputTextExcludes` 只作为负向排除条件，不能单独构成命中规则；不接受客户端类型、接口路径、账号类型或底层执行参数组合。`DELETE /__aisys__/api/response-inspection-policies/:id` 只删除管理端可编辑策略，默认规则只读。当前 OpenAI v1 适配器覆盖 Chat JSON、Chat SSE、Responses JSON 和 Responses SSE；其他原生协议需要先接入自己的响应语义适配器。
- 网关调度在账号池缓存快照内按请求 `model` 做内存过滤。模型不匹配只跳过账号，不记录为上游失败，不触发账户错误处理策略、本地屏蔽或临时不可调用；分组内没有任何可调度账号支持该模型时，直接返回本地 OpenAI 兼容错误。
- DeepSeek 账户调度必须同时满足 `providerCode = deepseek`、请求入口对应的精确档案与 endpoint mode：OpenAI Chat 只能命中 `profile_deepseek_openai_v1 + chat_json|chat_sse`，Anthropic Messages 只能命中 `profile_deepseek_anthropic_v1 + messages_json|messages_sse`；模型还必须按 `providerCode + model` 命中 DeepSeek 目录，或命中该账户的一跳模型映射。不能让 GPT、通用 OpenAI-compatible、GLM 或官方 Anthropic 账户兜底承接 DeepSeek 模型请求，也不能让任一 DeepSeek 档案跨协议承接或承接其他供应商模型。

### AI 分组

- `GET /__aisys__/api/groups` 和用户侧 `my-groups` 同源接口返回当前作用域内自有分组和有效授权给当前作用域的分组。授权分组返回 `accessType=authorized`、来源所有者摘要、授权状态、授权来源摘要和 `permissions`，前端据此展示来源说明、编辑本地使用配置、归还入口和 API Key 绑定能力。
- 授权分组只授予使用权。被授权人可以查看分组基础信息和来源说明，可以让自己的路由策略引用有效授权分组，API Key 仍只绑定该路由策略；被授权人也可以在分组编辑弹窗里调整本地 `enabled`、`groupType` 和 `schedulingPolicy`。这些配置只写入被授权人自己的授权分组使用配置，不修改授权方原分组的名称、供应商、说明、默认标记、分组类型或调度策略。
- `PATCH /__aisys__/api/groups/:id` 在管理员指定 `systemAccountId` 且该用户看到的是授权分组时，只接受 `enabled`、`groupType` 和 `schedulingPolicy`；用户侧 `PATCH /__aisys__/api/my-groups/:id` 同理。授权分组编辑不得提交 `name`、`providerCode` 或 `description`，后端必须重新按当前作用域校验该分组授权仍可见。
- `DELETE /__aisys__/api/groups/:id` 和用户侧 `my-groups` 删除接口只接受自有分组；授权分组不能被被授权人删除。被授权人不想继续使用个人直授权分组时，必须调用归还接口。
- 管理侧删除在省略 `systemAccountId` 或使用 `all` 时可按全局 owner 作用域处理，指定账户时只能删除该账户自有分组；用户侧始终强制当前登录账户。不存在、越权或授权成员删除返回 `404`，默认分组和会使 active 路由策略失去最后可用分组的删除返回 `400`，成功返回 `204`。
- 分组删除是硬删除。账户绑定、路由策略绑定和授权成员本地使用配置按当前 fresh schema 外键级联；多态授权 source / grant 历史保留。删除请求不因存在账户绑定而拒绝，但必须在事务内按 owner 和全部有效 grantee 作用域检查 active 路由策略，查询固定 `LIMIT 101`，超过 100 条或没有替代可用分组时拒绝。
- 删除事务同时写入 `group_account_stats_dirty`，reason=`group_deleted`；请求路径不实时删除或重算旧统计行。提交后 best-effort 失效 `lookup:group`、`lookup:group-account-ids` 和 gateway runtime，并记录 `groups.delete` 操作日志。
- `POST /__aisys__/api/groups/:id/return-authorization`：管理员按被授权人系统账户作用域代归还个人直授权分组；必须通过 `systemAccountId` 指定被授权人作用域。`POST /__aisys__/api/my-groups/:id/return-authorization`：当前登录用户从分组页归还个人直授权分组。团队来源授权分组或被团队来源覆盖的授权分组不提供个人归还入口。

### 策略路由

- 策略路由列表与详情固定为四条 GET：`GET /__aisys__/api/route-strategies`、`GET /__aisys__/api/my-route-strategies`、`GET /__aisys__/api/route-strategies/:id`、`GET /__aisys__/api/my-route-strategies/:id`。管理侧只允许 `admin` / `super_admin`，未指定 `systemAccountId` 或使用 `all` 时是全局 owner 视图，指定具体 ID 时收窄到该 owner；个人侧强制当前登录账户并忽略伪造的 `systemAccountId`，管理员在用户模式也不能读取全局。
- 列表 `page` 默认 `1`、最小 `1` 且无最大页；`pageSize` 默认 `50`、范围 `1..200`。主查询使用 `pageSize + 1` 判断 `hasMore`，`total = (page - 1) * pageSize + items.length + (hasMore ? 1 : 0)`，不执行精确 `COUNT(*)`，因此 `total` 只是渐进上界。
- 列表 `keyword` 只按策略路由名称做大小写敏感的字面前缀匹配，不搜索说明，`%/_` 不作为通配符。`mode` 只识别五种当前路由模式和 `all`，`status` 只识别 `active/disabled/all`；非法值按未传处理，不返回 `400`。排序固定为 `updated_at DESC, created_at DESC, id DESC`。
- 列表只返回基础字段、管理侧 owner 摘要、`normal` 模式规范化 `normalRoutingConfig`、最多 3 条 `groupBindingPreview`、完整 `bindingCount` 和 `apiKeyCount`；不得返回完整 `groupBindings` 或 `hybridRoutingConfig`。详情必须按单条权限返回完整 `groupBindings`、对应模式完整规范化配置和 `apiKeyCount`，不能用列表 preview 代替编辑回填数据。
- W5 Go 迁移当前仅为 `JUHE_AI_MANAGEMENT_API_ENABLED` 控制的 opt-in 路径。真实 PostgreSQL / HTTP、前端真实 Go 后端 smoke、反向代理单 owner 切流、回滚和 Node 删除证据完成前，不得描述为生产接管；真实依赖测试输出 `SKIP` 不计通过。

### API Key

- `GET /__aisys__/api/api-keys` 和用户侧 `my-api-keys` 的 `keyword` 只按 API Key 名称做精确 / 前缀匹配；Key 前缀、后缀和说明不进入通用搜索，不支持多字段组合关键词搜索。策略路由筛选使用独立 `routeStrategyId` 查询参数；状态筛选使用独立 `status` 查询参数。列表只返回 `routeStrategyId`、`routeStrategyName`、`routeStrategyMode` 和 `routeStrategyStatus` 等策略摘要，不返回策略内 `groupBindings`；不批量返回完整 API Key 明文，只返回 `keyPrefix`、`keySuffix` 和空 `key`。完整密钥可在创建成功响应中返回，也可通过 `GET /__aisys__/api/api-keys/:id/secret` 或用户侧 `GET /__aisys__/api/my-api-keys/:id/secret` 按单条资源权限读取。`POST /__aisys__/api/api-keys/:id/refresh-key` 和用户侧 `POST /__aisys__/api/my-api-keys/:id/refresh-key` 会重新生成完整密钥，旧密钥立即失效，响应只在本次操作返回新明文密钥。
- 管理侧 API Key 列表未传具体 `systemAccountId` 时，`routeStrategyId` 可跨全部可管理系统账户匹配策略路由；编辑、启停、删除和读取完整密钥按目标 API Key 自身归属系统账户校验和记录操作范围。
- API Key 创建和编辑只提交 `routeStrategyId`；分组绑定、权重、故障回退、轮询和混合智能路由配置必须在策略路由接口维护。运行时先按 API Key 找到策略路由，再由策略路由选择分组，最后进入分组内账号调度。
- API Key 创建、编辑和公开外部 API Key 推送可提交 `availabilitySchedule`。为空或 `null` 表示不设置计划，继续按 `status` 手动启停；启用时结构为 `{ enabled: true, timezone, mode: 'allow_windows', windows: [{ daysOfWeek, start, end }] }`，其中 `daysOfWeek` 为 `1-7`，`start/end` 为 `HH:mm`。API Key 只有一个可用状态 `status`：创建和编辑计划时按当前时间初始化 `status`；后台任务之后只在开始 / 结束边界继续写 `status`。人工启用 / 停用同样只提交 `status`，不再提交独立的 `availabilityScheduleActive`。接口返回 `availabilitySchedule` 和当前 `status` 供列表展示和编辑回填。计划配置不包含敏感字段。
- `DELETE /__aisys__/api/api-keys/:id` 只允许 `admin` / `super_admin`。省略 `systemAccountId` 或传 `all` 时按全局精确 ID 删除，传一个非空值时收窄到该 owner；空值返回 `400 { message: "系统账号 ID 不能为空" }`，重复参数返回 `400 { message: "Expected string, received array" }`。`DELETE /__aisys__/api/my-api-keys/:id` 强制当前 session 系统账户，忽略伪造或重复 `systemAccountId`。不存在或 owner 不匹配返回 `404 { message: "API Key 不存在" }`，默认 Key 返回 `409 { message: "默认 API Key 不允许删除" }`。
- 两条 API Key DELETE 先进入鉴权前 IP write limiter，再执行管理 API 写鉴权和 session touch、已认证用户 write limiter；管理路由随后叠加 admin role。限流阈值按当前系统设置读取，fresh schema 默认值为 IP write `180/minute`、`40/10 seconds` burst 和已认证用户 write `120/minute`。路由不挂 JSON body parser 和 mutation guard，malformed body 不参与业务解析。成功固定返回 `204 No Content`，body 为空，并设置 `Cache-Control: no-store` 与 `Pragma: no-cache`；未知内部错误只返回 `500 { message: "服务器内部错误" }`。
- API Key 删除在单个 PostgreSQL 事务内按 ID 和可选 owner 执行 `SELECT ... FOR UPDATE OF api_keys`、默认 Key 保护、按实际 owner 硬删除，并 upsert `api_key_record_cleanup_targets`。cleanup target 写入失败必须回滚删除。冲突时只刷新 `system_account_id` 和 `updated_at`，保留 `created_at`、`attempt_count`、`last_attempt_at`、`last_blocked_reason` 和 `last_error_message`；当前表没有 `retry_after` 列。
- API Key 删除请求路径不扫描、聚合或同步删除 usage、audit、runtime log、operation log 等记录明细；只登记 cleanup target，由后台 cleanup worker 后续按目标处理。提交后 validation cache 失效是必需步骤；失败时数据库删除保持提交，HTTP 返回通用 500，并写 `api_keys.delete` operation log 的最终 `status_code=500`。lookup、gateway runtime、quota 失效和 operation-log enqueue 为 best-effort；正常删除日志状态为 204。当前没有 validation 失效的持久化重试，生产接管前必须补真实环境告警、风险评估与恢复证据，不能把 cleanup target 当作失效重试队列。
- AI 账户创建、编辑可提交 `availabilitySchedule`；结构与 API Key 时间计划一致，接口返回 `availabilitySchedule` 和当前 `status`，不返回也不接收 `availabilityScheduleActive`。AI 账户只有一个可用控制状态 `status`：创建和编辑计划时按当前时间初始化 `active/disabled`，后台任务之后只在开始 / 结束边界继续写 `status`。人工启用 / 停用同样只提交 `status`，不会再有独立计划状态。账户计划只自动切换 `active <-> disabled`，不能把 `pending_test`、`error`、`rate_limited`、`temporary_unavailable` 等保护状态自动恢复为正常。授权账户的来源账户时间计划通过来源账户 `status` 参与实际可用性判断。

### 外部来源系统鉴权

外部来源系统鉴权用于 `juhe-ai-public-welfare` 等允许来源后端调用 `juhe-ai` 的受保护外部接口。它不使用后台登录 cookie，也不能访问后台管理 API。完整设计见 [外部来源系统鉴权设计](外部来源系统鉴权设计.md)。

- 统一请求头：`Authorization: Bearer <source_token>`。来源系统由 token 唯一定位，后台管理只维护来源名称。
- 来源系统鉴权只认 `Authorization: Bearer <source_token>`；其他来源标识头不参与当前契约。
- `GET /__aipublic__/group/list`：分页读取指定系统用户的分组脱敏摘要，支持 `targetUsername`、`providerCode`、`keyword`、`page` 和 `pageSize`；需要 scope `juhe_ai_public:group_list:read`。
- `GET /__aipublic__/api-key/list`：分页读取指定系统用户的 API Key 脱敏摘要和策略路由摘要，支持 `targetUsername`、`keyword`、`status`、`routeStrategyId`、`page` 和 `pageSize`；`routeStrategyId` 按 API Key 绑定的策略路由 ID 筛选；不返回明文 `key`；需要 scope `juhe_ai_public:api_key_list:read`。
- `GET /__aipublic__/route-strategy/list`：分页读取指定系统用户的路由策略摘要，支持 `targetUsername`、`keyword`、`mode`、`status`、`page` 和 `pageSize`；返回分组绑定摘要和路由模式，不返回账号凭据；需要 scope `juhe_ai_public:route_strategy_list:read`。
- `GET /__aipublic__/account/list`：分页读取指定系统用户的 AI 账户脱敏摘要，支持 `targetUsername`、`targetGroupName + providerCode + providerProtocolProfileId`、`groupId`、`keyword`、`type`、`status`、`schedulable`、`page` 和 `pageSize`；响应返回只读 `clientCompatibility` 作为内部派生能力摘要；不返回上游凭据或外部来源系统业务主键，列表中的本系统 `account.id` 可用于后续修改 / 删除；需要 scope `juhe_ai_public:account_list:read`。
- `POST /__aipublic__/group/add|update|del`：分组新增、修改和删除；新增按 `targetUsername` 定位或自动创建目标用户，修改和删除按 `groupId` 定位，修改至少提交一个变更字段，`targetUsername` 只作为可选归属校验；分别需要 scope `juhe_ai_public:group_add:write`、`juhe_ai_public:group_update:write`、`juhe_ai_public:group_delete:write`。
- `POST /__aipublic__/api-key/add|update|del`：API Key 新增、修改和删除；新增响应只在本次返回明文 `key`，修改和删除按 `apiKeyId` 定位，修改至少提交一个变更字段且不返回明文密钥，`targetUsername` 只作为可选归属校验；分别需要 scope `juhe_ai_public:api_key_add:write`、`juhe_ai_public:api_key_update:write`、`juhe_ai_public:api_key_delete:write`。
- `POST /__aipublic__/route-strategy/add|update|del`：路由策略新增、修改和删除；新增按 `targetUsername` 定位目标用户，普通路由只能绑定一个分组，其他模式可维护分组绑定、权重、故障回退、轮询或混合智能路由配置；修改和删除按 `routeStrategyId` 定位，默认路由或已被 API Key 使用的路由策略不能删除；分别需要 scope `juhe_ai_public:route_strategy_add:write`、`juhe_ai_public:route_strategy_update:write`、`juhe_ai_public:route_strategy_delete:write`。
- `POST /__aipublic__/account/add|update|del`：账号新增、修改和删除；账号新增可自动创建目标用户和目标分组，只创建资源并返回本系统 `account.id`，重复时返回冲突；公开账号写接口不接收账号级 `clientCompatibility`，Codex / OpenAI-compatible / Anthropic / Gemini 等客户端画像由网关内部识别，跨协议桥接后续统一落到混合供应商账户配置；账号修改必须使用 `accountId` 精确定位，并至少提交一个变更字段，支持只更新 `apiKey`、`baseUrl`、`status` 等单个字段，未提交字段保留原值；账号删除按 `accountId` 定位，可选目标用户、分组、供应商和协议档案只作防误删校验；修改找不到时返回 `404`，删除找不到时幂等返回 `action=not_found`；账号新增 / 修改 / 删除只支持 `type=api_key` 账户，响应不返回上游凭据明文；上游凭据在后端可逆加密保存并保留凭据指纹，不能按本地 API Key 的 hash-only 方式处理；Go 公开账户新增和修改与 Node 共用 `JUHE_AI_UPSTREAM_BASE_URL_PRIVATE_ALLOWLIST` 语义，默认空且仅按 `scheme + IP + effective port` 精确放行，不接受 host 级或路径级扩大；分别需要 scope `juhe_ai_public:account_add:write`、`juhe_ai_public:account_update:write`、`juhe_ai_public:account_delete:write`。
- `GET /__aisys__/api/external-integration-sources/api-docs`：管理员读取公开接口手册，返回接口名称、路径、方法、请求头、query、请求体和响应示例；不返回内置测试 Token 明文。前端用于文档弹窗、模糊搜索和 curl 复制，curl 示例统一使用 `<source_token>` 占位符。
- `GET /__aisys__/api/external-integration-sources`：管理员查看来源系统列表，支持名称搜索、状态筛选、分页；返回来源系统启停、到期时间、授权能力、限频规则和 token 安全标识摘要。
- `POST /__aisys__/api/external-integration-sources`、`PATCH /__aisys__/api/external-integration-sources/:id`、`DELETE /__aisys__/api/external-integration-sources/:id`：管理员创建、更新或删除来源授权，支持 `status`、`scopes`、`expiresAt`、`rateLimits` 和备注；创建时直接生成一个生产 token，创建响应返回完整 token；删除来源授权会同时删除关联 token 摘要和密文，原 Bearer token 立即失效。`targetUsername` 是公开资源接口的业务目标参数，不再通过来源授权白名单控制。
- `POST /__aisys__/api/external-integration-sources/:id/tokens`：管理员为来源系统生成 token，创建响应返回完整 token；`GET /__aisys__/api/external-integration-sources/:id/tokens/:tokenId/secret` 按单条 token 返回完整 token，用于后台复制。
- `PATCH /__aisys__/api/external-integration-sources/:id/tokens/:tokenId`：管理员更新 token 名称、状态、scope 和到期时间。
- 每个公开接口都是独立资源 scope。API Key、路由策略、分组和账号的每个列表 / 新增 / 修改 / 删除接口都必须分别授权；scope 不足返回 `403 external_source_scope_forbidden`。
- 来源系统限频只作用于 `/__aipublic__` 公开接口前缀，空规则表示不限制；例如可配置 `60s/10次` 和 `10s/3次`。
- 缺少 Bearer token 返回 `401 external_source_token_missing`；来源或 token 不匹配返回 `401 external_source_unauthorized`；来源停用返回 `403 external_source_disabled`；来源过期返回 `403 external_source_expired`；token 不可用或过期返回 `401 external_source_token_unavailable`；scope 不足返回 `403 external_source_scope_forbidden`；超过限频返回 `429 external_source_rate_limited`。
- 外部来源 token 调用其他后台接口仍按后台登录态处理，例如 `/__aisys__/api/accounts` 没有登录 cookie 时返回 `401`。

### IP管理

IP管理属于系统运维能力，只允许管理员访问。它提供 `sub2api-lite` 自身按来源 IP 维度的聚合事实和封禁策略，不维护公益站用户、IP 与业务身份之间的关系。

- `GET /__aisys__/api/ip-stats`：管理员读取 IP 管理列表，支持 `page`、`pageSize`、`keyword`、`status=all|normal|blacklisted`、`startDate`、`endDate`、`sortField=requestCount|successCount|errorCount|errorRate|totalTokens|totalCost|activeDays|lastUsedAt`、`sortOrder=asc|desc`，默认 `requestCount desc`。`startDate/endDate` 表示 IP 用量统计范围，管理页默认近 7 天，只能切换今天、近 7 天、近 31 天，不再提供自定义日期筛选。`keyword` 只按明文 IP / 聚合 IP 做精确或右侧前缀匹配，不支持 hash 搜索。接口只读已生成且 ready 的 `client_ip_usage_range_windows` 和 `client_ip_registry`，不在请求内重建窗口，也不为了总统计临时 `SUM/COUNT/MAX` 窗口表；返回 `items`、`pageUpperBound`、`hasMore`、`range` 和 `rangeReady`。窗口未生成、已被新 IP daily 标记为 stale，或 dirty IP 未全部刷新完成时，`rangeReady=false` 且列表为空，等待后台 worker 刷新。`page` 会被服务端限制在安全上限内，避免超大 `OFFSET` 拖慢高基数窗口查询；响应中的 `page/pageSize` 是最终生效分页。`pageUpperBound` 只作为分页器上界，不能作为数量或范围总统计展示，是否还有下一页以 `hasMore` 为准。`rangeUsage` 可包含 `averageFirstTokenMs`、`averageDurationMs` 和 `maxDurationMs`，这些速度指标来自 IP 维度窗口行，只展示不参与 IP 列表排序。
- `POST /__aisys__/api/ip-stats/:ipHash/blacklist`：管理员创建 active 封禁策略，body 支持 `reason`，以及可选的 `durationMinutes` 或 `durationDays`；不传时为永久封禁，两个时长字段只能传一种。创建后会停用同 IP 旧 active 封禁策略，并通知网关进程清理 IP 封禁缓存。
- `POST /__aisys__/api/ip-stats/:ipHash/unblock`：管理员停用 active 封禁策略，body 可为空，前端不要求填写解封原因。解封后通知网关进程清理 IP 封禁缓存。

网关命中 active 封禁策略时返回 OpenAI 兼容错误结构，HTTP 状态为 `403`，错误码为 `client_ip_blacklisted`，错误消息中会带当前来源 IPv4；响应中的 `error.client_ip` 为当前来源 IPv4。网关请求入口按部署模式读取策略：standalone 读取 server 进程内 active IP 策略快照和来源级短 TTL 决策缓存，高性能 Redis cache driver 下读取单 IP Redis shared cache，cache miss 只能按当前 `ip_hash` 索引回源；请求链路不能加载全量 active 策略。管理员创建 / 解封策略后通知网关进程清理策略缓存；策略不能随 API Key 运行态快照携带全量数组。封禁命中先写入进程内缓冲，再异步批量落到 `client_ip_policy_hits`。

### 模型检测

模型检测用于对 AI 账户执行目标模型可信度检测，不提供绝对真伪证明。检测请求必须复用本地 OpenAI 网关链路；检测 AI 账户时复用账号测试的单账号候选能力，不能静默切换同分组其他账号，检测产生的真实请求按当前调用方计入使用记录、额度和授权消耗。完整设计见 [模型检测设计](模型检测设计.md)。

- `POST /__aisys__/api/model-checks/run`：管理员触发一次模型检测，`targetType` 固定为 `account`，支持 `targetId`、`model`、`trustedComparison` 和 `trustedComparisonAccountId`，检测 profile 后端固定为 `full`，返回检测报告摘要。可信对比默认关闭；显式开启但没有选择可信对比账户时，接口返回中文错误并拒绝本次检测，不能静默降级。可信对比开启成功时，后端会额外生成 `trusted_comparison` 和 `distribution_similarity` 检测项，用隐藏分布探针比较目标账户与可信对比账户。
- `GET /__aisys__/api/model-checks/runs`：管理员查看模型检测历史分页列表，可按系统账户、AI 账户、目标模型、可信等级和时间筛选。
- `GET /__aisys__/api/model-checks/runs/:id`：管理员查看单次检测详情，返回脱敏检测项、得分、traceId、五维可信状态和 stats-worker 预聚合的 Token 斜率 / 截距、身份 observation 数、paired 距离、LOO 身份偏离、baseline version / 状态及证据覆盖；接口不扫描 observation 或普通流量正文。
- `GET /__aisys__/api/model-checks/options`：管理员读取支持模型选项和可信对比状态摘要；AI 账户和可信对比账户下拉都来自对应作用域的账户 options 接口。
- 管理侧模型检测未传 `systemAccountId` 时默认读取全部系统账户作用域；传入具体 `systemAccountId` 时，账户 options、发起检测、历史列表和详情读取都收窄到该系统账户，不能落回当前管理员自己的默认作用域。
- `POST /__aisys__/api/my-model-checks/run`：当前登录用户触发自己的模型检测，忽略传入的 `systemAccountId`；`trustedComparison` 默认关闭，显式开启但没有选择可信对比账户时，接口返回中文错误并拒绝本次检测。
- `GET /__aisys__/api/my-model-checks/runs`：当前登录用户查看自己的模型检测历史分页列表。
- `GET /__aisys__/api/my-model-checks/runs/:id`：当前登录用户查看自己的单次检测详情；授权资源只返回脱敏可信度和安全摘要。
- `GET /__aisys__/api/my-model-checks/options`：当前登录用户读取支持模型选项和可信对比状态摘要；AI 账户和可信对比账户下拉都来自 `我的 AI 账户` 对应 options 接口。

接口返回必须使用“高可信、较可信、不确定、疑似不符、不可检测”等中文结论，不返回“已证明为真模型”。可信对比是可选增强项，默认不开启；开启失败时必须明确提示“请选择可信对比账户后再开启可信对比检测”或同义中文错误。分布相似度对照只保存 prompt key、统计摘要、traceId 和短输出预览，不返回完整隐藏题面。检测详情不得包含上游 API Key、OAuth token、代理密码、完整敏感请求头、大体积完整响应体或完整探针题库。

身份群体窗口发生共同变化时，latest 返回 `baselineVersionStatus = drift_protected` 并把身份状态保持为 `insufficient_evidence`。该状态只用于诊断展示，接口不得据此自动停用账户、修改 usage、成本、额度或账单。

### 代理检测

- `GET /__aisys__/api/proxies`：管理员代理管理分页列表，支持 `page`、`pageSize`、`keyword`；关键词只按代理名称做精确 / 前缀匹配，不搜索代理 ID、地址、类型、用户名或说明。返回最近检测状态 `testStatus`、最近延迟 `latencyMs`、最近出口 IP `outboundIp`、最近出口地区 `outboundRegion`、检测摘要 `lastTestMessage` 和检测时间 `lastTestedAt`。
- `GET /__aisys__/api/proxies/options`：登录用户代理选择项，支持按代理名称前缀搜索的 `keyword` 和 `limit`；`limit` 默认 50，服务端限制在 1-50，非法整数按未传处理。接口只返回已启用代理的 `id`、`name`、`type` 和 `enabled`，用于 AI 账户表单和 OpenAI OAuth 流程；不得返回 host、port、username、password、检测状态、出口信息或系统账户信息。
- `POST /__aisys__/api/proxies`：管理员创建代理。请求严格只允许 `name/description/type/host/port/username/password/enabled`；`name/type/host/port` 必填，`description` 可为 `null`，密码一旦提交就不能是空白字符串。密码使用 `JUHE_AI_SECRET` 派生的 Node 兼容 AES-256-GCM `v1` 密文保存，响应和操作日志不返回明文。
- `PATCH /__aisys__/api/proxies/:id`：管理员局部更新代理，空对象允许提交；省略密码时保留原密文，提交密码时替换密文。`type/host/port/username/password` 任一变化都把最近检测状态重置为 `unknown`，并清空延迟、出口信息、检测消息和检测时间。
- `DELETE /__aisys__/api/proxies/:id`：管理员删除未被账户引用的代理。删除前只读取最多 4 个未删除绑定账户，前 3 个账户名用于提示；存在绑定时返回 `409`，第 4 条命中后数量按“至少 4 个账户”表达，不执行精确 `COUNT(*)`。
- `GET /__aisys__/api/route-strategies/options`：管理员读取 API Key 表单使用的策略路由选项；必须登录且具备 `admin` / `super_admin`，普通用户返回 `403 { message: "需要管理员权限" }`。支持 `systemAccountId` 指定用户，空值或 `all` 表示管理员全局可见；支持 `ids` 逗号或重复参数，去空白、去重、最多 50 个；`keyword` 按路由策略名称前缀搜索；`limit` 默认 50，范围 1-100；`activeOnly` 默认 true，`0/false/no` 表示包含停用策略，非法值按 true。响应只返回 `id`、`name`、`mode`、`status`、`isDefault`、`systemAccountId` 和 `systemAccountName`，排序为默认策略优先、更新时间倒序、名称和 ID 稳定升序；不得返回路由配置 JSON、绑定分组、API Key 数量或账号信息。
- `GET /__aisys__/api/my-route-strategies/options`：当前登录用户读取自己的 API Key 表单策略路由选项；后端强制当前登录用户作用域并忽略 query `systemAccountId`，即使管理员在用户模式调用也不能查询全局。`ids`、`keyword`、`limit` 和 `activeOnly` 语义同管理侧；响应只返回 `id`、`name`、`mode`、`status` 和 `isDefault`，不得返回 `systemAccountId` 或 `systemAccountName`。
- 账户一旦绑定代理，上游请求、OAuth token 交换、账户测试和后台冷却复测都必须使用该代理；代理不存在或被停用时请求应失败并提示重新选择已启用代理，不能静默直连。同一次网关调度中，某个代理已经失败后，后续绑定同一个代理的账号直接跳过，不重复请求。账户测试和后台冷却复测中的模型请求必须复用本地 OpenAI 网关链路并写入使用记录；OAuth token 交换、代理检测和 OAuth 额度快照被动写入不是模型请求，不计入使用统计。OAuth 额度快照不再有后台主动刷新任务，只从真实网关请求或账户测试响应头被动更新。
- `POST /__aisys__/api/proxies/:id/test`：管理员在代理测试弹窗内确认后手动触发代理质量检测，检测目标来自全部已启用供应商的默认地址，返回 `ProxyTestReport`；报告和列表同时展示出口 IP 和出口地区。
- 检测报告中的 `items` 至少包含“基础连通性”汇总项，以及每个已启用供应商默认地址对应的检测项。
- 出口信息参考 sub2api 的探测方式并扩展多级兜底：通过代理依次访问 `ip-api.com`、`ipwho.is`、`api.ip.sb`、`ipinfo.io`、`api.ipify.org`、`httpbin.org/ip`；出口信息不可用不影响供应商默认地址检测结果。
- `401`、`403`、`404`、`405`、`429` 等上游状态表示目标可达但鉴权、方法或频率受限，前端展示为告警；网络异常或 5xx 作为失败展示。
- 代理检测不会返回代理密码或完整代理 URL；前端只能展示安全摘要、HTTP 状态和延迟。

## 列表、筛选与分页

低增长配置类列表可以返回数组。新增高增长列表应使用统一分页结构。

推荐列表结构：

```json
{
  "data": {
    "items": [],
    "page": 1,
    "pageSize": 100,
    "total": 0,
    "hasMore": false
  }
}
```

约定：

- 查询参数使用 `page`、`pageSize`、`keyword`、`status`、`providerCode`、`systemAccountId`、`sortField`、`sortOrder` 等稳定名称。
- 普通用户传入 `systemAccountId` 应被忽略；只有管理员可以使用系统账户筛选。
- 排序字段必须后端白名单校验，不把任意字段名拼入 SQL。
- 使用记录、统计明细、授权用量这类持续增长数据必须优先支持后端分页或有限窗口查询；账户用量趋势接口只支持自然日范围，最大 1 个月。
- 使用记录、操作日志、原始审计日志、审计错误组、运行日志索引、账户用量统计明细和授权用量明细属于高增长或统计窗口列表，默认不执行精确 `COUNT(*)`；接口通过多取 1 条返回 `hasMore`，`total` 只作为兼容分页器的当前位置上界，前端不能把它展示成全量精确总数。
- 操作日志属于持续增长的业务追溯数据，列表必须分页查询；用户侧只能返回当前用户可见日志，管理侧可以按操作人、影响用户、资源和 trace ID 筛选。
- 审计日志属于持续增长且 payload 体积较大的高权限数据，列表必须分页查询元数据，详情 payload 必须按需加载，不能在列表接口返回完整原文。
- 前端表格分页、空态、错误态和加载态必须保持中文体验。

## 写接口防重复提交

管理端会改变业务状态的接口必须遵循 [幂等与唯一约束设计](幂等与唯一约束设计.md)，避免前端重复点击、网络卡顿重试或客户端脚本重复提交造成重复数据。

约定：

- `GET` 查询、列表、筛选、分页、详情、日志查看和审计查看不进入防重复提交缓存。
- 创建类 `POST` 默认需要后端声明操作指纹，包括 AI 账户、OAuth 账户、分组、API Key、代理、系统账户、系统团队、团队成员、统一授权和公告创建。
- 修改类 `PATCH`、删除类 `DELETE` 和发布 / 下线等状态切换接口建议接入短 TTL 防重复缓存，避免短时间重复写操作日志。
- 同一登录用户、同一路由、同一业务作用域、同一资源指纹的请求短时间内只允许一个进入真实业务写入。
- 同资源指纹请求正在处理时，返回 `409` 和中文提示，不执行业务写入。
- 缓存失效或进程重启后，数据库业务唯一约束继续兜底；命中唯一约束时返回 `409`，不写操作日志。
- 前端按钮 loading 和禁用只作为体验优化，不能替代服务端防重复缓存和数据库唯一约束。

## 权限摘要

资源列表中如果同一接口同时返回自有资源、个人授权资源和团队授权资源，应返回 `accessType`、授权来源摘要与 `permissions`，前端据此控制操作入口，后端仍在每个写接口重新校验。

推荐字段：

```json
{
  "accessType": "owner",
  "ownerSystemAccountId": "sa_xxx",
  "ownerDisplayName": "用户名称",
  "effectiveAuthorizationId": null,
  "authorizationSources": [],
  "authorizationGranteeType": null,
  "authorizationGranteeId": null,
  "permissions": {
    "canUse": true,
    "canEdit": true,
    "canDelete": true,
    "canReturnAuthorization": false,
    "canAuthorize": true,
    "canViewCredentials": true,
    "canManageMembers": true,
    "canBindToApiKey": true
  }
}
```

命名约定：

- 后端和前端类型优先使用 camelCase；数据库字段继续使用 snake_case。
- `accessType` 可取 `owner`、`authorized`、`admin_view`。
- 管理员查看他人资源时不改变资源所有者；必要时使用 `admin_view` 表示管理员视角。
- 授权资源必须返回所有者和授权来源摘要；如果个人来源与团队来源同时命中同一资源，只返回一行资源并在 `authorizationSources` 中列出全部来源，不能返回重复 AI 账户或重复分组。
- 资源列表应返回用户级 `authorizationId`，同时保留 `authorizationSources` 供前端显示“个人授权 + 团队授权”等来源。
- 授权 AI 账户列表必须返回 `effectiveAvailability` 表达实际可用性，并可返回 `authorizationInstanceSourceAccountStatus`、`authorizationInstanceSourceAccountSchedulable`、`authorizationInstanceSourceAccountExpiresAt`、`authorizationInstanceSourceAccountCooldownUntil` 和来源错误摘要作为来源侧证据。前端主状态和可操作性优先读取 `effectiveAvailability`；来源字段可以阻断实际可用性，但不能被当作授权实例 `accounts.status` 的覆盖值，也不能回写授权实例本地运行态。
- 授权分组列表必须返回被授权人本地生效后的 `enabled`、`groupType` 和 `schedulingPolicy`，以及授权方原分组所有者摘要；本地配置只影响当前被授权人通过该分组绑定 API Key 和网关调度，不回写授权方原分组。
- 授权管理页默认筛选“生效中”记录；资源被删除后，相关授权应变为 `revoked`，只在“全部状态”或“已回收”筛选下用于历史追溯。
- 授权资源不能返回完整凭据或代理密码；授权账户详情可以返回来源账户的非敏感公开配置用于只读展示，包括 `base_url`、公开 OAuth 元数据、模型、代理 ID、并发、时间计划、账户追加流式规则和来源状态，但永远不能返回 OpenAI API Key、Access Token、Refresh Token、ID Token 或代理密码。

## 网关权限

- `/*` 和 `/v1/*` 网关入口不读取后台登录态，只读取 `Authorization: Bearer <本地网关 API Key>` 或 `x-api-key: <本地网关 API Key>`；系统前缀 `/__aisys__/*` 除外。`x-api-key` 只作为本地网关认证入口，转发 Anthropic 上游时会被替换为命中账号自己的上游 API Key。
- API Key 的所有者就是本次调用方系统账户。
- API Key 只选择一条路由策略；路由策略可以绑定调用方自己的一个或多个分组，也可以绑定有效授权给调用方的分组。授权分组在运行态必须重新校验授权状态、到期时间和授权额度。
- 网关先读取 API Key 绑定的路由策略及其 active 分组绑定，按优先级选择可承接号池；当前分组无候选账号、模型不匹配、本地容量不可承接或上游未输出前全部失败时，可以尝试下一优先级分组。API Key 无效、Key 额度耗尽、请求本身无效、强制图像生成请求、已经产生可见流式输出时，不做跨号池切换；仅 auto 暴露的 Responses `image_generation` 工具在图像权限关闭时会被移除后继续按文本请求处理，不触发跨号池失败。
- API Key 时间计划由 background worker 在开始 / 结束边界直接写入 API Key `status`；网关认证阶段只读取落库后的单一 `status`。结束边界写入停用后的请求按不可用 Key 处理，不再返回独立的 `api_key_schedule_inactive` 错误码。
- AI 账户时间计划同样由 background worker 在开始 / 结束边界写入 `accounts.status`；网关候选只读取落库后的单一状态，不在请求链路解析计划 JSON。人工启用 / 停用也只写 `status`。账户仍需同时满足状态正常、可调度、未冷却、未到期、授权有效和额度可用等硬门禁；计划边界不会自动恢复待检查、异常、限流或临时不可调用账户。
- 授权账户加入自有分组时，分组成员关系记录用户级 `accountAuthorizationId`；授权暂停、到期、回收或归还后调度必须实时拦截，重新激活同一最终授权后可恢复使用。
- 网关调度时必须重新校验 API Key 状态、路由策略分组绑定、分组可见性、统一授权有效性、授权额度、授权实例账户状态、实例到期、实例冷却和来源账户可用性；授权实例使用的凭据、模型、代理、并发、可用时段和账户追加流式规则从来源账户补齐，来源账户停用、异常、限流 / 临时不可调用、冷却未结束、关闭调度、套餐到期、删除或凭据缺失都是实际调度硬门禁。团队和成员变化应先同步到最终用户授权关系或来源状态，网关运行时不再额外遍历授权来源团队 / 成员状态。
- 网关调度时必须按后台统计缓存的 `total_cost_usd` 校验 API Key 美元成本额度、分组授权美元成本额度和账户授权美元成本额度；命中额度返回 429，错误文案为“额度已用完，请联系管理员提升额度”。
- 使用授权账户或授权分组时，使用记录必须同时冗余调用方、账户所有者、分组所有者、统一授权 ID 和授权对象类型，便于调用方明细、授权实例账户行用量、个人授权消耗、团队授权总消耗和团队成员消耗分开统计；被授权人的调用明细、测试、模型检测和本地操作日志归调用方自己，分组授权调用不能写入资源归属人的普通账户 / 分组统计，只能进入授权报表聚合；路由策略绑定入口接受调用方自有分组和有效授权分组。
- 授权用量接口只由用户侧 `我的授权` 下的 `团队消耗明细` / `用户消耗明细` 或管理侧 `统一授权管理` 下的同名明细进入；团队 / 用户明细按 `startDate/endDate` 读取后台已写好的最近 31 天范围窗口。
- `授权操作` / `统一授权` 只服务授权关系列表，不展示用量筛选或用量列；`团队消耗明细` / `用户消耗明细` 必须使用专用后端接口直读授权范围窗口表，不能通过授权列表接口或前端本地汇总替代，接口不得实时 `SUM usage_records`，也不得临时汇总统计缓存。
- 同一调用方对同一资源同时拥有个人来源和团队来源时，网关仍只使用一条用户级授权写入一条使用记录，不能重复写入或重复计入事实总量。
- 网关返回给客户端的错误使用本地网关统一错误结构，不使用管理 API 的 `{ data, message }` 包装；Anthropic 成功响应保持 Anthropic native JSON / SSE 形态，不改写成 OpenAI `choices` 或 `response.*`。
- 服务等级和思考级别字段必须进入各供应商现有请求白名单或映射器；同协议路径保留客户端值，跨协议无法支持或映射时返回目标 driver / bridge 现有的 `400` 请求错误，不能静默删除，也不写账户失败副作用。

## 团队与授权对象接口

- `GET /__aisys__/api/system-accounts`：仅管理员可用，返回系统账户管理分页列表；`keyword` 按用户名 `username` 和用户名称 `displayName` 做精确 / 前缀匹配，不搜索 ID、角色或说明；`page` 默认 1，`pageSize` 默认 20 且限制在 1-100；响应为 `{ items, total, hasMore, page, pageSize }`，`total` 只作为当前窗口上界，不做全表精确 `COUNT(*)`；列表字段只包含 `id`、`username`、`displayName`、`description`、`role`、`status`、`mustChangePassword`、`imageGenerationEnabled`、`lastLoginAt`、`createdAt` 和 `updatedAt`，不得读取或返回 `password_hash`。Go W2 已覆盖该只读列表端点；Go W3 opt-in 已覆盖系统账户创建和完整 mixed PATCH，但前端 smoke、生产切流和 Node 删除仍未完成。
- `GET /__aisys__/api/system-accounts/options`：仅管理员可用，返回管理侧筛选和选择器所需的 `id`、`username`、`displayName`、`status`，支持 `ids`、`keyword` 和 `limit`；`ids` 用于已选系统账户回填，支持逗号或重复参数，去空白、去重、最多 50 个；`keyword` 只按用户名和展示名做精确 / 前缀匹配，不搜索 ID、角色或说明；`limit` 默认 50，服务端限制在 1-50，非法整数按未传处理；不得读取或返回 `password_hash`、角色、改密状态、最后登录、创建 / 更新时间等系统账户管理字段。Go W2 已覆盖该只读 options 端点；系统账户完整写接口生产接管仍归后续 W3 收口。

- `GET /__aisys__/api/authorization-options/grantee-teams`：仅管理员管理侧使用，返回管理授权时需要的系统团队最小摘要，支持 `ids`、`keyword` 和 `limit`；普通用户必须返回 403。Go W2 已覆盖该 grantee teams 只读端点。

## AI 性能监控接口

AI 性能监控接口只服务后台页面，不参与网关请求链路。接口趋势只能读取 `usage_stats_hourly` 和账户元数据，摘要只能读取 `ai_performance_summary_windows`，不能在请求时实时汇总 `usage_records` 或把小时曲线再次聚合成摘要。

统计概览当前接口：

- `GET /__aisys__/api/my-stats/usage-overview`：当前登录用户查看自己的业务统计概览，支持 `startDate=YYYY-MM-DD&endDate=YYYY-MM-DD`，忽略 `systemAccountId`；默认今天，最大最近 31 天。
- `GET /__aisys__/api/stats/usage-overview`：管理员查看业务统计概览，支持同样的日期范围，默认全局汇总；可选 `systemAccountId` 筛选指定用户。
- `GET /__aisys__/api/my-stats/usage-window`：当前登录用户读取统计日期窗口配置，返回 `timezone`、`startDate`、`endDate`、`days` 和 `maxDays`；忽略 `systemAccountId`，供前端默认日期和禁用范围对齐服务端窗口。
- `GET /__aisys__/api/stats/usage-window`：管理员读取统计日期窗口配置，返回字段同用户侧；用于管理侧统计页面默认日期和禁用范围，接口不参与业务明细聚合。
- `GET /__aisys__/api/stats/system-metrics`：仅管理员可用，返回主机性能 / 网络吞吐趋势、进程事件循环趋势、进程内存趋势以及各进程 latest / 24 小时 peak 采样；日期缺省时按服务端统计时区的当天单日读取，最大 31 天。该接口只读预聚合窗口和进程采样，不采集 server runtime 或 Redis Stream 队列。当前 Node 过渡契约中，`processEventLoopLatestStatus` 与 `processEventLoopPeakStatus` 固定覆盖 `server`、`ingest-worker`、`stats-worker`、`ops-worker`、`db-service` 五个角色，每项包含 `sampleAvailable`、`processPid`、`sampledAt`、`eventLoopLagMs`、`processRssBytes`、`processHeapUsedBytes`、`processHeapTotalBytes`、`processExternalBytes` 和 `processArrayBuffersBytes`；`processEventLoopTrend` 按日期范围返回窗口桶，供趋势图直读。
- `GET /__aisys__/api/stats/system-metrics/runtime`：仅管理员可用，独立采集 server / worker runtime 和 Redis Stream 队列，返回 `runtimeSnapshotAvailable`、`ingestWorkerSnapshotAvailable`、`statsWorkerSnapshotAvailable`、`opsWorkerSnapshotAvailable`、三类 worker 摘要、`backgroundJobsAvailable` 和 `backgroundJobs`。该接口用于异步填充后台任务 / 队列卡片，不得阻塞系统趋势首屏；运行态不可用时 `backgroundJobs=null`，不伪装成空数组。Go 接管时必须按 [Go 迁移指标与观测规划](../migration/Go迁移指标与观测规划.md) 和 [Go 系统指标字段迁移清单](../migration/Go系统指标字段迁移清单.md) 重建为 Go runtime、PG、Redis、Asynq、worker lag 和网关 SLI 指标，不继续暴露 Node 专属指标。

账户用量趋势接口：

- `GET /__aisys__/api/my-stats/account-usage`：当前登录用户查看本人调用产生的账户按日消耗趋势，忽略 `systemAccountId`；支持临时 `accountIds` 追加账户，响应包含 `hasMore`，`total` 是分页上界，不执行精确 `COUNT(*)`。
- `GET /__aisys__/api/stats/account-usage`：管理员查看系统账户维度的本人账户按日消耗趋势，可选 `systemAccountId` 筛选指定用户；支持临时 `accountIds` 追加账户，响应包含 `hasMore`，`total` 是分页上界，不执行精确 `COUNT(*)`。

契约要求：

- 支持 `startDate`、`endDate`、`keyword`、`page`、`pageSize` 和 `accountIds`；日期格式为 `YYYY-MM-DD`，按服务端本地自然日解释。页面筛选不提供账户类型筛选，用户侧和管理侧页面默认都传日期范围；账号类型只在明细中作为运行态展示，不作为统计筛选、统计分片、额度分片、会话亲和或 prompt cache 分片。
- 日期范围最大 31 天；接口缺省为最近 31 天，超过范围或超出最近 31 天由后端收敛到允许范围；用户侧 `我的用量` 和管理侧 `用量统计管理` 页面首次进入都会显式传最近 31 天范围。
- 统计口径读取 `usage_stats_daily` 的 `scope_type = caller_account`，自有账户不混入被授权人的调用，授权给自己的账户只展示当前登录用户自己的调用。
- 账户明细始终按后端分页窗口返回，未传分页参数时使用服务端默认 `pageSize`；排序按范围内请求数、成本、Token 和最后使用时间稳定排列，`total` 只作为分页器上界，是否还有下一页以 `hasMore` 为准。
- `accountIds` 可用逗号分隔或重复 query 参数传入，只表示本次请求临时追加到账户列表的账号；后端去重后最多取 50 个，不写数据库、不写系统设置、不作为用户偏好，也不表示前端点击账户列表后的筛选状态。
- 响应返回 `range`、`summary`、`defaultTrendAccountIds`、`rows[].rangeUsage` 和 `rows[].dailyUsage`；`dailyUsage` 每天一项，缺失日期补 0。
- 默认趋势账户池：普通用户和管理员指定 `systemAccountId` 时，只读取 `usage_rank_snapshots` 中当前调用方 `caller_account + last7d + request_count` 的最近 7 天活跃前 10；管理员未指定 `systemAccountId` 查看全部用户时，从本次范围统计缓存结果中选出全局可见账户 Top 10。两种路径都不能在接口请求时实时回扫 `usage_records`。
- 接口只能读取统计缓存、排行快照和账户元数据，不能在请求时实时汇总 `usage_records`。
- 授权用量明细不通过该接口返回，也不在用量统计页提供跳转入口。

AI 性能监控当前接口：

- `GET /__aisys__/api/my-stats/ai-performance`：当前登录用户查看自己可使用 AI 账户的整体性能趋势，包含自有账户、账号授权实例和授权分组内来源账户；支持 `startDate=YYYY-MM-DD&endDate=YYYY-MM-DD` 和用于搜索追加账户列表的临时 `accountIds`，忽略 `systemAccountId`。
- `GET /__aisys__/api/my-stats/ai-performance/accounts`：当前登录用户查看自己可使用 AI 账户的轻量选项，支持 `keyword`、`accountIds` 和 `limit`，忽略 `systemAccountId`。
- `GET /__aisys__/api/stats/ai-performance`：管理员查看全部用户或指定系统账户可使用 AI 账户的整体性能趋势，支持 `systemAccountId`、`startDate=YYYY-MM-DD&endDate=YYYY-MM-DD` 和临时 `accountIds`。
- `GET /__aisys__/api/stats/ai-performance/accounts`：管理员查看全部用户或指定系统账户可使用 AI 账户的轻量选项，支持 `systemAccountId`、`keyword`、`accountIds` 和 `limit`。

契约要求：

- 接口日期范围缺省为今天，最大最近 31 天；页面首次进入显式传最近 3 天范围，超过范围由后端收敛到允许范围。
- 默认账户池固定读取 `usage_rank_snapshots` 中 `last7d + request_count` 的最近 7 天活跃前 10；用户侧和管理侧指定用户读取对应系统账户的 `caller_account` 快照，管理侧全部用户读取全局 `account` 快照。快照缺失时返回空数组，不能在接口请求时临时聚合降级。
- 用户侧接口只能返回当前登录用户可使用的 AI 账户；别人授权给当前用户使用的账户以授权实例账户出现在默认账户、搜索结果或临时追加结果中，授权分组内来源账户只读取当前调用方的 `caller_account` 数据。管理侧按管理员权限读取全部用户或指定用户范围。指定用户视图统计值读取 `scope_type = caller_account`，全局管理视图读取 `scope_type = account`，授权实例、授权分组来源账户和归属人原账户互不混入。
- `accountIds` 只表示本次搜索追加到账户列表的账户，添加上限由后端限制；不写数据库、不写系统设置、不作为用户偏好；不表示前端点击筛选状态。
- 响应需要区分 `defaultAccounts`、`selectedAccounts`、当前账户列表 `accounts` 和 `hourlySeries`；`selectedAccounts` 沿用接口字段名，语义为搜索追加账户。
- 前端点击账户列表筛选统计视图时，只在已返回的 `accounts` 和 `hourlySeries` 内控制图表显隐，不重新请求后端，也不重算页面顶部摘要。
- 管理侧全部用户视图读取 `system_account_id = global` 的账户统计缓存和排行快照；指定用户视图读取该系统账户的账户统计缓存。
- 空小时不伪造成 `0s`，平均 / 最大首 token 和平均 / 最大总耗时没有数据时返回空值。
- 前端绘图可以连接空小时两侧的有效点，但不能把空小时展示为 `0s` 或有效采样点。
- 详细字段和性能边界见 [AI 性能监控设计](AI性能监控设计.md)。

## 表监控接口

表监控接口仅允许管理员访问，服务容量观测和统计数据集域维护，不参与网关请求链路。

- `GET /__aisys__/api/table-monitor/overview`：读取业务库、数据集目录库、使用记录目录库和统计结果库最新采样摘要和表大小列表，支持 `startAt`、`endAt` 和 `limit`；usage shard 文件集合观测仍在后续增强阶段。
- `GET /__aisys__/api/table-monitor/history`：读取指定库和表的采样历史，`databaseRole` 支持 `business`、`dataset`、`stats`，并支持 `tableName`、`startAt`、`endAt` 和 `limit`。
- `POST /__aisys__/api/table-monitor/non-business-data/cleanup`：按 `cutoffAt` 申请硬清理早于该时间的非业务数据；`cutoffAt` 不能晚于当前时间；请求可传 `batchSize` 和 `maxBatches`，后端有上限；接口只负责投递 worker，返回是否已投递、任务 ID、提交时间和投递失败原因。

契约要求：

- 清理接口不清理业务库，不删除系统账户、AI 账户、分组、API Key、授权关系、代理、供应商和系统设置等业务数据。
- 清理接口会清理数据集目录库、统计结果库、usage shard 和审计 payload 外部文件中早于 `cutoffAt` 的非业务数据；数据集目录库和统计结果库普通表按 schema 动态枚举可识别时间列；不等待统计安全游标，不做关联保护，也不做旧统计反向扣减。
- 提交成功或投递失败都会写入操作日志，操作日志动作为 `cleanup_non_business_data`。
- API Key 删除后的关联记录清理由删除事务写入 `api_key_record_cleanup_targets`，交给后台 cleanup worker 后续处理，不作为表监控接口或页面展示项。目标表只有 `api_key_id`、`system_account_id`、`created_at`、`updated_at`、`attempt_count`、`last_attempt_at`、`last_blocked_reason`、`last_error_message`，没有 `retry_after`；冲突 upsert 保留创建时间和实际重试字段，只刷新 owner 与更新时间。该目标不承担 validation cache 失效重试。

## 操作日志接口

操作日志接口记录业务状态变更的追溯结果。查询操作日志本身属于查询行为，不写操作日志。

当前接口：

- `GET /__aisys__/api/my-operation-logs`：当前登录用户分页查看与自己有关的操作日志，支持摘要、模块、动作、资源类型、资源 ID、时间和 trace ID 筛选。
- `GET /__aisys__/api/my-operation-logs/:id`：当前登录用户查看自己可见的操作日志详情。
- `GET /__aisys__/api/operation-logs`：仅管理员可用，分页查看全部操作日志，支持摘要、操作人、影响用户、业务作用域、模块、动作、资源类型、资源 ID、时间和 trace ID 筛选。
- `GET /__aisys__/api/operation-logs/:id`：仅管理员可用，查看任意操作日志详情。

契约要求：

- `GET`、列表查询、详情查看、筛选、分页、搜索、日志查看和审计查看都不写操作日志。
- 操作日志记录已经提交的业务状态变更；失败且未改变数据的请求不写操作日志。请求最终返回 500 不等于数据库一定未提交，例如 API Key update / delete 的 validation cache 必需失效失败必须按真实已提交变更写日志，并记录最终 HTTP 状态。
- API Key 正常删除写 module=`api_keys`、action=`delete`、resource type=`api_key`、`status_code=204` 和 `deleted: false -> true`；删除已提交但 validation cache 失效失败时仍写同一操作日志，`status_code=500`。目标不存在、owner 不匹配、默认 Key 冲突和事务回滚不写删除日志；日志不得包含完整 Key、hash 或 ciphertext。
- 迁移期 Go W2 标签 PATCH 已补成功状态变更后的 operation log 写入基线；Go W2 已补 operation log 管理 / 个人读接口，但仍未覆盖保留清理和其他管理端写接口 operation log，不放宽“成功业务状态变更写操作日志”的长期规则。
- 普通用户接口不能接受跨用户筛选条件，后端必须按 `operation_log_viewers` 和全员安全摘要过滤。
- 普通用户接口必须按日志 `detailLevel` 和 viewer `detail_level` 裁剪返回；`summary` 级不返回字段差异、影响对象、可见用户、请求路径、客户端 IP 或 User-Agent，用户侧 `full` 级也不返回可见用户列表。
- 管理员接口可以查看全部日志，但仍不能展示凭据、token、代理密码、完整 API Key 或原始审计 payload。
- 列表只返回摘要、资源快照、关键差异和可见原因；详情可以返回目标资源和完整安全 diff。
- `summaryKeyword` 只检索操作日志 `summary` 经 NFKC、转小写和非字母数字分词后生成的摘要倒排词项，支持去重的中文、英文字母和数字单字符；资源类型、资源 ID、操作人、影响用户、业务作用域、模块、动作和 trace ID 使用独立筛选参数。后端不能在列表请求里对 `operation_logs` 主表做前导通配符扫描，也不能把资源名、操作人、操作键、模块或动作混入摘要搜索；历史日志在词项规则升级后通过发布维护命令按 `(created_at, id)` 游标离线重建。
- `traceId` 支持右侧前缀定位，不使用前导通配符。
- 使用记录页可把 `traceId` 深链到 `/runtime-logs`、`/audit-logs`、`/operation-logs` 或 `/my-operation-logs`；目标页读取 `traceId` query 初始化筛选，用户手动搜索、切换模式或重置后应移除一次性 query，并恢复为页面本地筛选状态。
- 操作日志错误提示使用中文；错误详情不能把原始请求体或敏感字段打回前端。

## 审计日志接口

审计日志接口仅允许 `admin` 访问，普通用户即使是请求调用方也不能读取完整原文。

当前接口：

- `GET /__aisys__/api/audit-logs`：分页查询审计日志元数据，支持时间、系统账户、API Key、分组、账号、接口、模型、状态码、结果和 trace ID 筛选。
- `GET /__aisys__/api/audit-logs/:id`：查看审计详情、上游尝试列表和 payload 摘要。
- `GET /__aisys__/api/audit-logs/:id/payloads/:payloadId`：按需读取某段原始 payload，支持 `offset` 和 `limit`，只返回当前窗口。
- `GET /__aisys__/api/audit-logs/runtime`：查看审计队列长度、队列字节数、最近落库时间、最近错误和丢弃计数；响应必须包含部署开关 `enabled`、`runtimeAvailable`、`workerSnapshotAvailable`、`auditLogQueueAvailable` 和 `activeCaptureAvailable`。`enabled=false` 时 `unavailableReason=audit_disabled`，运行态不可用时相关数字返回 `null`，不能伪装成 `0` 或 `false`；历史列表和详情读取仍保持可用。

契约要求：

- 列表接口只返回元数据，不返回完整 headers 或 body。
- 审计详情的 payload 摘要返回 `headersSha256` 和 `bodySha256`，分别表示完整 headers JSON 和 body 原文字节的摘要；`bodySha256` 不代表整条审计记录。
- 审计 payload body 按原文字节保存和读取，不做字段级脱敏，不提供 body 脱敏开关或兼容配置；“body 未脱敏”不是待修复缺陷。
- payload 读取接口必须重新校验管理员权限，不能只依赖详情页已加载。
- payload 读取接口不得一次性读取完整大 blob；响应需要带 `bodyOffset`、`bodyLimit`、`bodyTotalBytes`、`bodyNextOffset` 和 `bodyTruncated`，前端按游标继续加载。
- payload 响应可以返回文本、JSON 或二进制摘要；前端无法安全解码时展示大小、hash 和十六进制预览。
- 审计日志写入不通过管理 API 直接发生；网关只终态入队，后台批量落库。
- 审计日志接口错误提示使用中文；错误详情不能再把完整 payload 打回普通错误响应。
- 审计列表的 `path`、`model` 等结构化条件按精确值匹配；`traceId` 和客户端 IP 只支持右侧前缀定位，不允许前导通配符扫描审计主表。

## 公开接口日志接口

公开接口日志接口仅允许 `admin` 访问，用于排查 `/__aipublic__` 外部来源系统调用。公开接口日志保存来源、接口、状态、耗时和按原文容量上限捕获的有限请求 / 响应摘要；保留期由系统设置 `publicApiLogRetentionDays` 控制，默认 30 天，合法范围 `1..365`。完整设计见 [公开接口日志设计](公开接口日志设计.md)。

当前接口：

- `GET /__aisys__/api/public-api-logs`：分页查询公开接口日志元数据，支持 `traceId`、`sourceRefId`、`path`、`result=success|failed|all`、`statusCode`、`clientIp`、`startAt`、`endAt`、`page` 和 `pageSize`。
- `GET /__aisys__/api/public-api-logs/:id`：查看单条公开接口日志详情，返回按原文容量上限捕获的请求摘要和响应摘要。

契约要求：

- 只有 `/__aipublic__/*` 请求写入公开接口日志；后台管理接口、OpenAI 兼容网关接口、静态资源和健康检查不写入该表。
- 成功、失败、缺少 token、token 错误、scope 不足、限频、公开前缀 404 和 JSON body 解析失败都应记录。
- 列表接口只返回元数据、大小和捕获状态，不返回大段请求 / 响应内容；详情接口返回的 `requestData` 和 `responseData` 按原文保存并带捕获状态。
- 公开接口日志的请求 header 快照只捕获 `contentType` / `contentLength`，不捕获 `Authorization`、Cookie 或作为 Bearer 凭据传入的来源 token；query、请求 body 和响应 body 在容量与结构预算内保留原值，不按字段名或字符串形态递归脱敏，也不写 `[redacted]` 占位。
- `traceId` 和 `clientIp` 支持右侧前缀定位；`path`、`sourceRefId` 和 `statusCode` 使用结构化精确筛选，不使用前导通配符。
- 公开接口日志按当前 `publicApiLogRetentionDays` 清理过期记录。

## 日志搜索接口

日志搜索接口仅允许 `admin` 访问，不读取原始审计 payload。索引查询读取普通运行日志的 SQLite 索引；`grep 模式` 由后端调用 `rg` 扫描日志目录中当前保留的 `.log` 文件，当前文件日志默认保留 30 天、最多 500 个轮转文件。

当前接口：

- `GET /__aisys__/api/runtime-logs`：分页查询当前存储 driver 索引表内的运行日志，支持 `page`、`pageSize`、`traceId`、`level`、`event`、`keyword`、`startAt` 和 `endAt`，默认返回最近 100 条；时间范围按索引日志时间 `runtime_logs.time` 筛选，索引表保留周期由后台清理任务控制。响应中的 `retentionDays` 只表示 worker snapshot 中的运行日志索引保留期，快照不可用时返回 `null` 并标记 `retentionDaysSource=unavailable`。
- `GET /__aisys__/api/runtime-logs/facets`：读取数据库索引范围、级别分布和事件 facets；历史索引在写入开关关闭后仍可读取。
- `GET /__aisys__/api/runtime-logs/runtime`：返回部署开关 `indexEnabled`，并用 `runtimeAvailable`、`workerSnapshotAvailable`、`runtimeLogIndexQueueAvailable`、`gatewayAccountSideEffectsAvailable` 和 `dbService.statusAvailable/stateAvailable` 区分真实空 backlog 与运行态不可观测。`indexEnabled=false` 时 `unavailableReason=index_disabled`、索引队列不可用，但不得把整个 ingest-worker 或 DB service 误报为关闭。运行态关注文件数、pending bytes、当前文件 offset、最近读取 / 提交时间和轮转文件保护数，不包含 runtime-log Redis producer 指标。
- `GET /__aisys__/api/runtime-logs/grep`：在后端普通日志目录内通过 `rg` 按任意关键字搜索当前保留的 `.log` 文件，支持 `keywords` 或重复 `keyword` 参数，支持 `startAt` / `endAt` 文件时间范围；默认按文件时间搜索最近 3 天，单次最多 7 天，同一后端进程一次只允许 1 个 grep 搜索，单次 `rg` 搜索 15 秒超时，最多返回 100 行匹配。多关键字按 AND 处理，最多取前 10 个去重关键字，必须在同一行同时命中。

契约要求：

- 响应只返回有限条数，后端限制 `limit` 上限，避免把日志搜索变成全量导出。
- 索引查询中，`traceId`、级别、事件和日志时间必须走索引字段；`traceId` 支持右侧前缀定位，不使用前导通配符；关键字只对 `runtime_logs.message` 做普通模糊匹配，不检索 `raw_json`，完整正文搜索使用 `grep 模式`。
- 运行日志数据库搜索索引默认启用并保留 14 天；`JUHE_AI_RUNTIME_LOG_INDEX_ENABLED=false` 时索引停止更新，已有历史索引仍可分页读取，清空后分页结果自然为空，文件 grep 仍可用。
- `grep 模式` 后端仍返回文件名、完整文件路径、行号、实际文件搜索范围和匹配行，前端列表与索引查询使用同一组运行日志展示字段；文件和位置只放在详情里。后端固定在日志目录内按文件时间范围筛选当前保留的 `.log` 文件；时间范围只决定哪些文件参与扫描，进入文件后只做关键字匹配，不读取文件内容判断行时间。不接收路径参数，不支持多条件筛选，同一后端进程一次只允许 1 个 grep 搜索，单次 `rg` 搜索 15 秒超时。当前文件日志保留由 `JUHE_AI_LOG_RETENTION_DAYS`、`JUHE_AI_LOG_MAX_FILES` 和单文件大小共同约束，默认 30 天、最多 500 个轮转文件，按时间或文件数清理最早日志。
- `JUHE_AI_RUNTIME_LOG_INDEX_ENABLED=false` 只停止文件扫描、cursor/facets/runtime_logs 新写入和索引保留清理；Pino 文件输出、轮转文件保留清理、历史索引读取及 `grep 模式` 不受影响。重新开启前应评估现存日志文件是否会被 importer 回填。
- 全平台如果缺少生产依赖 `@vscode/ripgrep` 提供的 `rg`，`grep 模式` 必须返回安装提示而不是退化为慢速扫描；不能回退到 Node 文件扫描、服务器 PATH 或系统 `grep` 造成不同部署平台行为不一致。

## 公告中心接口

公告中心接口只服务后台用户界面，不参与网关调用链路。

当前接口：

- `GET /__aisys__/api/announcements/public?limit=30`：所有登录用户可用，只返回最近已发布公告的 `id/title/level/publishedAt/readAt` 轻量摘要，后端限制最多 30 条，不返回正文。
- `GET /__aisys__/api/announcements/public/:id`：所有登录用户可用，按 ID 返回单条已发布公告完整正文；草稿和已下线公告不可见。
- `POST /__aisys__/api/announcements/public/read`：所有登录用户可用，把当前用户看到的公告 ID 写入已读记录，最多 30 条。
- `GET /__aisys__/api/announcements`：仅管理员可用，分页返回公告管理列表，正文仅为 `contentPreview`。
- `GET /__aisys__/api/announcements/:id`：仅管理员可用，按 ID 返回包含完整 `content` 的公告详情。
- `POST /__aisys__/api/announcements`：仅管理员可用，创建草稿或直接发布公告。
- `PATCH /__aisys__/api/announcements/:id`：仅管理员可用，更新公告标题、正文、重要性和状态。
- `POST /__aisys__/api/announcements/:id/publish`：仅管理员可用，发布公告。
- `POST /__aisys__/api/announcements/:id/unpublish`：仅管理员可用，下线公告。
- `DELETE /__aisys__/api/announcements/:id`：仅管理员可用，删除公告。

契约要求：

- 普通用户接口永远不能返回草稿或已下线公告。
- 应用壳首屏和 60 秒公告轮询只能调用轻量公共列表；用户展开单条公告时才调用公共详情接口。
- 公共列表和管理列表必须在 SQL 查询层裁掉无关字段；公共列表不关联创建人或更新人，管理列表不得读取完整正文后再在 Node.js 中截断。
- 公告列表响应字段使用 camelCase；数据库字段使用 snake_case。
- 公告正文第一版按纯文本处理，不允许 HTML 注入。
- 新公告提醒由用户侧列表中的 `readAt` 判断；点击铃铛打开公告弹窗后，前端批量调用已读接口，后端按 `announcement_id + system_account_id` 维护已读事实。
- 管理员重新发布草稿或已下线公告时，后端必须刷新 `publishedAt` 并删除该公告的已读记录，确保所有用户重新收到提醒；普通编辑已发布公告不清理已读。

## 新增接口检查清单

- 是否明确属于 `/__aisys__/api/my-*` 用户接口、`/__aisys__/api/*` 管理接口还是 `/*` / `/v1/*` 网关接口？
- 如果接口会改变业务状态，是否注册操作日志语义和可见范围？如果只是查询，是否明确不写操作日志？
- 是否明确登录态、管理员权限、资源所有者权限或授权使用权？
- 普通用户可见页面会调用的接口，是否已在 `pnpm test:scope` 固定为普通用户可访问；`my-*` 命名空间下的管理员例外，是否已固定为普通用户 403？
- 是否使用统一成功和错误响应结构？
- 是否需要 `permissions` 摘要？
- 是否做后端参数校验、排序白名单和系统账户隔离？
- 是否会返回或记录敏感字段？如会，是否符合 [安全与日志策略](安全与日志策略.md)？
- 是否需要同步前端类型、功能设计、SQLite 文档、开发验证或部署文档？
