# 接口契约与权限矩阵

> 面向前端、后端与 AI 维护者。
> 本文统一管理后台 `/__aisys__/api/*`、网关 `/*` 与 `/v1/*`、响应结构、分页筛选、错误语义和核心权限矩阵，避免接口口径散落在页面、路由和计划文档里。

## 文档目标

- 固定前后端对接口返回、错误、分页、筛选和权限摘要的共同理解。
- 明确 `super_admin`、`admin`、普通 `user`、资源所有者和被授权用户在各模块里的操作边界。
- 给新增接口提供默认契约，减少每个路由自行设计返回结构。
- 只记录稳定契约，不替代具体功能字段说明；业务字段仍以 [核心功能设计](核心功能设计.md) 和 [SQLite 存储说明](SQLite存储说明.md) 为准。

## 接口分层

| 接口层 | 路径 | 身份来源 | 返回风格 | 说明 |
| --- | --- | --- | --- | --- |
| 用户 API | `/__aisys__/api/my-*` | 后台登录态 Cookie | 项目管理 API 结构 | 前端 `我的...` 页面使用，后端强制当前登录用户作用域，忽略 `systemAccountId` 查询。 |
| 管理 API | `/__aisys__/api/*` | 后台登录态 Cookie | 项目管理 API 结构 | 前端管理页面使用，默认需要 `requireAuth`；涉及跨系统账户管理、全局数据或系统配置的接口必须叠加 `requireAdmin`，系统账户写入接口还必须叠加 `requireSuperAdmin`。 |
| 公开 API | `/__aisys__/health`、`/__aisys__/api/health`、公开品牌设置、登录和验证码 | 无登录态或登录流程 | 项目管理 API 结构 | 只暴露健康检查、未登录所需品牌信息、登录验证码和登录接口。 |
| 外部集成 API | `/__aipublic__/*` | Bearer 来源 token | 项目管理 API 结构 | 面向允许来源系统的后端服务，不使用后台登录态；当前已挂载来源系统鉴权 demo、账号维度聚合读取和 IP 维度聚合读取接口。 |
| 网关 API | `/*`、`/v1/*` | 本地网关 API Key | OpenAI 兼容结构 | 面向 OpenAI 兼容客户端，不使用后台登录态，不返回管理 API 包装；系统前缀 `/__aisys__/*` 除外。 |

网关 API 的“OpenAI 兼容”只表示本地入口、认证和基础响应结构尽量兼容 OpenAI 客户端，不表示每种上游账号都支持公开 OpenAI API 全路径。具体能力以 [OpenAI 账号接入](OpenAI账号接入.md) 的账号类型能力矩阵为准：OpenAI API Key 账号按上游 `/v1` 透传，OpenAI OAuth 账号只通过 Codex adapter 支持明确列出的 Responses 路径。

当前后端已挂载 `/__aipublic__/demo/source-auth` 用于验证来源系统鉴权链路，并已挂载 `/__aipublic__/account/usage`、`/__aipublic__/ip/usage`、`/__aipublic__/consumption/ranking` 和 `/__aipublic__/access/info` 用于公益站后端读取账号维度和 IP 维度聚合事实；`GET /__aipublic__/group/list`、`GET /__aipublic__/api-key/list`、`GET /__aipublic__/account/list`、`POST /__aipublic__/group/add|update|del`、`POST /__aipublic__/api-key/add|update|del`、`POST /__aipublic__/account/add|update|del` 用于外部来源系统对指定系统用户执行受控资源对账、新增、修改和删除。`sub2api-lite` 不实现公益站用户维度排行榜快照，也不维护 `public_ranking_snapshots` 业务快照表。

## 菜单入口与视图范围

- `super_admin` 和 `admin` 同时拥有用户身份和管理员身份，因此前端提供用户模式和管理模式；左侧菜单只展示当前模式的入口，头部用户下拉提供模式切换。
- 管理角色首次进入默认用户模式；切换后可把菜单模式作为当前浏览器里的个人使用习惯保存，下次登录或访问根路径时沿用上次模式。该偏好只影响前端入口，不改变后端权限。
- 普通用户只显示用户侧入口；管理角色在用户模式的 `我的...` 入口中也只能按当前登录用户查询自己的数据，不能因为角色是管理员就自动进入全局查询范围。
- 管理侧入口必须使用管理员路由和管理员接口能力，例如 `AI 账户管理`、`AI 分组管理`、`API Key 管理`、`模型检测`、`使用记录管理`、`用量统计管理`、`AI性能监控` 和 `统一授权管理` 下的 `统一授权`、`团队消耗明细`、`用户消耗明细`、`授权团队`。
- 用户侧入口必须使用当前用户作用域，例如 `我的 AI 账户`、`我的分组`、`我的 API Key`、`模型检测`、`我的使用记录`、`我的用量`、`统计概览`、`AI性能监控`，以及 `我的授权` 下的 `授权操作`、`团队消耗明细`、`用户消耗明细`、`我的授权团队`。
- 用户侧页面优先调用 `/__aisys__/api/my-accounts`、`/__aisys__/api/my-groups`、`/__aisys__/api/my-api-keys`、`/__aisys__/api/my-model-checks`、`/__aisys__/api/my-authorizations`、`/__aisys__/api/my-openai-oauth`、`/__aisys__/api/my-usage-records`、`/__aisys__/api/my-stats` 和 `/__aisys__/api/my-teams`；用户侧 `我的授权` 下的消耗明细调用 `/__aisys__/api/my-authorizations/usage/team-details` 和 `/__aisys__/api/my-authorizations/usage/user-details`，`统计概览` 使用 `/__aisys__/api/my-stats/usage-overview`，用户侧 `AI性能监控` 使用 `/__aisys__/api/my-stats/ai-performance`。
- 用户侧页面如果需要表单下拉或辅助目录，只能调用用户侧接口或明确允许登录用户访问的轻量辅助接口，例如 `/__aisys__/api/my-accounts/options`、`/__aisys__/api/my-groups/options`、`/__aisys__/api/my-authorization-options/*`、`/__aisys__/api/providers/:code/models`、`/__aisys__/api/providers/models/options` 和 `/__aisys__/api/proxies/options`；新增此类调用必须同步加入 `pnpm test:scope`。`my-authorization-options/grantee-groups` 只返回指定被授权用户可作为授权账户目标绑定的分组最小摘要，不返回分组成员、用量或并发信息。
- 管理侧页面保留 `/__aisys__/api/accounts`、`/__aisys__/api/groups`、`/__aisys__/api/api-keys`、`/__aisys__/api/model-checks`、`/__aisys__/api/authorizations`、`/__aisys__/api/openai-oauth`、`/__aisys__/api/usage-records`、`/__aisys__/api/stats` 等管理入口；`/__aisys__/api/stats/ai-performance` 和 `/__aisys__/api/stats/ai-performance/accounts` 是管理侧 AI 性能监控入口，并由后端显式校验管理员身份。
- 系统账户管理是管理角色唯一的差异点：`GET /__aisys__/api/system-accounts` 和 `GET /__aisys__/api/system-accounts/options` 允许 `super_admin` / `admin` 查看；`POST /__aisys__/api/system-accounts`、`PATCH /__aisys__/api/system-accounts/:id` 只允许 `super_admin`，普通管理员必须返回 403。默认仅 `admin/admin` 是 `super_admin`；系统账户写入接口只允许提交 `admin` / `user` 角色，不能新增或升级其他 `super_admin`。
- 同一 Vue 页面可以复用，但系统账户筛选、系统账户列、全量管理接口和跨用户查询只能在管理侧入口启用。

## 管理 API 响应

当前实现已使用 `backend/src/shared/http.ts` 的 `ok(data, message?)` 和 `badRequest(message)` 作为基础约定。后续新增接口优先沿用以下结构。

成功响应：

```json
{
  "data": {},
  "message": "可选中文提示"
}
```

错误响应：

```json
{
  "message": "中文错误提示",
  "code": "可选稳定错误码",
  "details": {}
}
```

约定：

- 成功响应必须包含 `data`；没有业务返回值时可返回 `{ "data": { "ok": true } }`，删除接口也可以使用 `204 No Content`。
- `message` 面向前端直接展示，默认使用中文；后端内部日志、脚本输出和使用记录错误摘要中的系统自定义描述也必须使用中文。
- 只翻译面向人阅读的描述性文案，不翻译机器可读字段或协议值；`code`、`type`、`event`、状态枚举、header、路由路径、SQL 常量、缓存 key、OpenAI / SSE 事件名和数据库字段值必须保持稳定。
- 技术名词可以保留原文并嵌入中文文案，例如 `API Key`、`OAuth`、`Bearer Token`、`Refresh Token`、`access_token`、`HTTP` 和 `SSE`。
- 简单错误可以只返回 `{ "message": "..." }`；需要前端分支处理、脚本识别或跨接口复用的错误必须提供稳定 `code`。
- `details` 只放字段级校验摘要、可安全展示的限制原因或操作上下文，不放敏感凭据、完整请求体、完整上游响应或 token。
- 前端不能通过 HTTP 状态码之外的字段自行推断权限，必须以接口返回和 `permissions` 摘要为准。
- `我的授权` 必须包含当前用户授权出去和授权给当前用户的记录；授权给当前用户但资源不属于当前用户的记录只提供查看、明细和归还入口，不能展示暂停、回收或修改配置等管理动作。

## HTTP 状态

| 状态码 | 使用场景 | 前端处理 |
| --- | --- | --- |
| `200` | 查询、更新、操作成功 | 读取 `data`，必要时展示 `message`。 |
| `201` | 创建成功 | 读取 `data`，创建 API Key 时注意明文只按约定展示。 |
| `204` | 删除或无返回内容操作成功 | 不读取 body，直接刷新列表或回到上级页面。 |
| `400` | 参数格式错误、业务输入不合法 | 展示 `message`，表单场景尽量定位字段。 |
| `401` | 未登录、会话过期、网关密钥缺失或无效 | 后台跳转登录；网关返回 OpenAI 兼容错误。 |
| `403` | 已登录但无权限 | 展示无权限提示，不自动重试。 |
| `404` | 资源不存在或当前用户不可见 | 展示不存在或已失效，避免暴露其他用户资源是否存在。 |
| `409` | 名称唯一约束、重复授权等冲突 | 展示冲突原因，引导用户更换输入或处理旧关系。 |
| `429` | 登录限频、上游限流或账号冷却 | 展示冷却或稍后重试信息。 |
| `500` | 未知服务端错误 | 展示通用错误，详细信息只进入安全日志。 |
| `502` | 上游 OAuth、上游模型或代理请求失败 | 展示上游请求失败摘要，避免暴露完整上游敏感响应。 |

## 模块操作补充

### AI 账户

- `POST /__aisys__/api/accounts`、`PATCH /__aisys__/api/accounts/:id` 和 OpenAI OAuth 创建接口支持 `supportedModels: string[]`；字段为空数组或不提交表示账户不限制模型。
- `GET /__aisys__/api/accounts`、`GET /__aisys__/api/accounts/:id`、用户侧 `my-accounts` 同源接口在账户摘要中返回 `supportedModels`。该字段是非敏感调度约束，授权账户可查看但只能由资源所有者在账户编辑中修改。
- `GET /__aisys__/api/accounts` 和用户侧 `my-accounts` 的 `keyword` 只按 AI 账户名称做精确 / 前缀匹配；供应商、账户类型和分组筛选分别使用 `providerCode`、`type` 和 `groupId` 查询参数。管理侧 `systemAccountId=all` 不提供跨用户分组下拉筛选，需先选定系统账户后再传 `groupId`。
- `supportedModels` 的可选值必须来自所属供应商模型目录。写入时后端去重、去空白并校验目录；清空限制必须提交空数组，不能依赖前端省略字段。
- 账户创建、编辑、导入和公开外部账号推送可提交 `availabilitySchedule`；为空或 `null` 表示不限制时段。账户计划只影响网关账号候选，不改写账户 `status`，时区跟随系统默认值。
- `PATCH /__aisys__/api/accounts/:id` 和用户侧 `my-accounts/:id` 提交 `clearFailureState: true` 时，除了清理数据库里的冷却、限流、异常和最近错误，也会通知 server 网关进程清理该账号当前的 `local_suppressed` / `precheck_pending` / `precheck_failed` 运行态；授权账户的 `authorized-dispatch` 同理清理当前授权实例账户维度。
- `GET /__aisys__/api/providers/:code/models`：登录用户可读取指定供应商模型目录，用于账户编辑、账户测试和模型限制下拉；`GET /__aisys__/api/providers/models/options` 返回启用供应商的模型名称选项，用于使用记录等按模型精确筛选的页面；`GET /__aisys__/api/providers` 仍是供应商管理列表，只允许管理员访问。
- 网关调度在账号池缓存快照内按请求 `model` 做内存过滤。模型不匹配只跳过账号，不记录为上游失败，不触发错误策略、本地屏蔽或临时不可调用；分组内没有任何可调度账号支持该模型时，直接返回本地 OpenAI 兼容错误。

### API Key

- `GET /__aisys__/api/api-keys` 和用户侧 `my-api-keys` 的 `keyword` 只按 API Key 名称做精确 / 前缀匹配；Key 前缀、后缀和说明不进入通用搜索，不支持多字段组合关键词搜索。分组筛选使用独立 `groupId` 查询参数，并匹配任意绑定号池；状态筛选使用独立 `status` 查询参数。列表返回 `groupBindings`，但不批量返回完整 API Key 明文，只返回 `keyPrefix`、`keySuffix` 和空 `key`；完整密钥可在创建成功响应中返回，也可通过 `GET /__aisys__/api/api-keys/:id/secret` 或用户侧 `GET /__aisys__/api/my-api-keys/:id/secret` 按单条资源权限读取。
- API Key 创建和编辑提交 `groupBindings: { groupId, priority, status }[]`；后端必须校验分组归属、重复绑定、同供应商、active 优先级唯一和至少一个 active 号池。
- API Key 创建、编辑和公开外部 API Key 推送可提交 `availabilitySchedule`。为空或 `null` 表示不限制时段；启用时结构为 `{ enabled: true, timezone, mode: 'allow_windows', windows: [{ daysOfWeek, start, end }] }`，其中 `daysOfWeek` 为 `1-7`，`start/end` 为 `HH:mm`。接口返回同名字段供列表展示和编辑回填；计划配置不包含敏感字段。

### 外部来源系统鉴权

外部来源系统鉴权用于 `juhe-ai-public-welfare` 等允许来源后端调用 `juhe-ai` 的受保护外部接口。它不使用后台登录 cookie，也不能访问后台管理 API。完整设计见 [外部来源系统鉴权设计](外部来源系统鉴权设计.md)。

- 统一请求头：`Authorization: Bearer <source_token>`。来源系统由 token 唯一定位，后台管理只维护来源名称。
- 来源系统鉴权只认 `Authorization: Bearer <source_token>`；其他来源标识头不参与当前契约。
- `GET /__aipublic__/demo/source-auth`：只验证来源系统鉴权链路，成功时返回来源系统、token 前缀和认证时间；不返回明文 token、token hash、scope、业务数据或内部数据库 ID。
- `GET /__aipublic__/account/usage`：读取账号维度聚合事实，支持 `range=today|last7d|last31d`、分页、关键词和排序；需要 scope `juhe_ai_public:account_usage:read`。正式 token 读取 `usage_scope_range_windows` 中 `scope_type='account'` 的预生成窗口，测试 token 返回 mock。账号分页只允许 1001 行窗口内的页码，避免公开请求深 `OFFSET`；关键词先通过账号 ID、名称、供应商和类型的索引范围查询解析账号 ID，不做多列 OR / LIKE 扫描。响应包含 `accountId`、账号名称、供应商、请求数、Token、缓存、成本、活跃天数和速度指标，用于公益站按 `sub2apiAccountId` 映射贡献榜，不返回上游凭据。
- `GET /__aipublic__/ip/usage`：读取 IP 维度聚合事实，支持 `range=today|last7d|last31d`、分页和排序；需要 scope `juhe_ai_public:ip_usage:read`。正式 token 读取 `client_ip_usage_range_windows` 和 `client_ip_registry`，测试 token 返回 mock。公开接口暂不支持自定义 `startDate/endDate`，避免请求路径临时聚合未预生成窗口。响应不包含 `ipHash`、封禁状态、API Key、系统账户、AI 账户、分组、供应商或模型。
- `GET /__aipublic__/consumption/ranking`：读取基于 IP 聚合表的 TopN 消耗排行，支持 `metric=totalTokens|totalCost|requestCount`；它只是 IP 维度排序视图，不是公益站用户排行榜。
- `GET /__aipublic__/access/info`：返回当前公开接口前缀、鉴权方式、可用范围和可用指标；不返回普通 API Key、上游凭据或公益站业务配置。
- `GET /__aipublic__/group/list`：分页读取指定系统用户的分组脱敏摘要，支持 `targetUsername`、`providerCode`、`keyword`、`page` 和 `pageSize`；需要 scope `juhe_ai_public:group_list:read`。
- `GET /__aipublic__/api-key/list`：分页读取指定系统用户的 API Key 脱敏摘要和分组绑定，支持 `targetUsername`、`keyword`、`status`、`groupId`、`page` 和 `pageSize`；不返回明文 `key`；需要 scope `juhe_ai_public:api_key_list:read`。
- `GET /__aipublic__/account/list`：分页读取指定系统用户的 AI 账户脱敏摘要，支持 `targetUsername`、`targetGroupName + providerCode`、`groupId`、`keyword`、`type`、`status`、`schedulable`、`page` 和 `pageSize`；不返回上游凭据或外部来源系统业务主键，列表中的本系统 `account.id` 可用于后续修改 / 删除；需要 scope `juhe_ai_public:account_list:read`。
- `POST /__aipublic__/group/add|update|del`：分组新增、修改和删除；分别需要 scope `juhe_ai_public:group_add:write`、`juhe_ai_public:group_update:write`、`juhe_ai_public:group_delete:write`。
- `POST /__aipublic__/api-key/add|update|del`：API Key 新增、修改和删除；新增响应只在本次返回明文 `key`，修改和删除不返回明文密钥；分别需要 scope `juhe_ai_public:api_key_add:write`、`juhe_ai_public:api_key_update:write`、`juhe_ai_public:api_key_delete:write`。
- `POST /__aipublic__/account/add|update|del`：账号新增、修改和删除；账号新增只创建资源并返回本系统 `account.id`，重复时返回冲突；账号修改和删除必须使用 `accountId` 精确定位，修改找不到时返回 `404`，删除找不到时幂等返回 `action=not_found`；账号新增 / 修改只支持 `type=api_key`，响应不返回上游凭据明文；分别需要 scope `juhe_ai_public:account_add:write`、`juhe_ai_public:account_update:write`、`juhe_ai_public:account_delete:write`。
- `GET /__aisys__/api/external-integration-sources/api-docs`：管理员读取公开接口手册，返回接口名称、路径、方法、请求头、query、请求体、响应示例和内置测试 token；前端用于文档弹窗、模糊搜索和 curl 复制。
- `GET /__aisys__/api/external-integration-sources`：管理员查看来源系统列表，支持名称搜索、状态筛选、分页；返回来源系统启停、到期时间、授权能力、限频规则和 token 安全标识摘要。
- `POST /__aisys__/api/external-integration-sources`、`PATCH /__aisys__/api/external-integration-sources/:id`、`DELETE /__aisys__/api/external-integration-sources/:id`：管理员创建、更新或删除来源授权，支持 `status`、`scopes`、`expiresAt`、`rateLimits` 和备注；创建时直接生成一个生产 token，创建响应返回完整 token；删除来源授权会同时删除关联 token 摘要和密文，原 Bearer token 立即失效。`targetUsername` 是公开资源接口的业务目标参数，不再通过来源授权白名单控制。
- `POST /__aisys__/api/external-integration-sources/:id/tokens`：管理员为来源系统生成 token，创建响应返回完整 token；`GET /__aisys__/api/external-integration-sources/:id/tokens/:tokenId/secret` 按单条 token 返回完整 token，用于后台复制。
- `PATCH /__aisys__/api/external-integration-sources/:id/tokens/:tokenId`：管理员更新 token 名称、状态、scope 和到期时间。
- 每个公开接口都是独立资源 scope。demo、账号聚合读取、IP 聚合读取、IP 消耗排行、接入信息、分组、API Key 和账号的每个列表 / 新增 / 修改 / 删除接口都必须分别授权；scope 不足返回 `403 external_source_scope_forbidden`。
- 来源系统限频只作用于 `/__aipublic__` 公开接口前缀，空规则表示不限制；例如可配置 `60s/10次` 和 `10s/3次`。
- 缺少 Bearer token 返回 `401 external_source_token_missing`；来源或 token 不匹配返回 `401 external_source_unauthorized`；来源停用返回 `403 external_source_disabled`；来源过期返回 `403 external_source_expired`；token 不可用或过期返回 `401 external_source_token_unavailable`；scope 不足返回 `403 external_source_scope_forbidden`；超过限频返回 `429 external_source_rate_limited`。
- 外部来源 token 调用其他后台接口仍按后台登录态处理，例如 `/__aisys__/api/accounts` 没有登录 cookie 时返回 `401`。

### IP管理

IP管理属于系统运维能力，只允许管理员访问。它提供 `sub2api-lite` 自身按来源 IP 维度的聚合事实和封禁策略，不维护公益站用户、IP 与业务身份之间的关系。

- `GET /__aisys__/api/ip-stats`：管理员读取 IP 管理列表，支持 `page`、`pageSize`、`keyword`、`status=all|normal|blacklisted`、`startDate`、`endDate`、`sortField=requestCount|successCount|errorCount|errorRate|totalTokens|totalCost|activeDays|lastUsedAt`、`sortOrder=asc|desc`，默认 `requestCount desc`。`keyword` 只按明文 IP / 聚合 IP 做精确或右侧前缀匹配，不支持 hash 搜索。接口只读已生成且 ready 的 `client_ip_usage_range_windows` 和 `client_ip_registry`，不在请求内重建窗口，也不为了总统计临时 `SUM/COUNT/MAX` 窗口表；返回 `items`、`pageUpperBound`、`hasMore`、`range` 和 `rangeReady`。窗口未生成、已被新 IP daily 标记为 stale，或 dirty IP 未全部刷新完成时，`rangeReady=false` 且列表为空，等待后台 worker 刷新。`page` 会被服务端限制在安全上限内，避免超大 `OFFSET` 拖慢高基数窗口查询；响应中的 `page/pageSize` 是最终生效分页。`pageUpperBound` 只作为分页器上界，不能作为数量或范围总统计展示，是否还有下一页以 `hasMore` 为准。`rangeUsage` 可包含 `averageFirstTokenMs`、`averageDurationMs` 和 `maxDurationMs`，这些速度指标来自 IP 维度窗口行，只展示不参与 IP 列表排序。
- `POST /__aisys__/api/ip-stats/:ipHash/blacklist`：管理员创建 active 封禁策略，body 支持 `reason`，以及可选的 `durationMinutes` 或 `durationDays`；不传时为永久封禁，两个时长字段只能传一种。创建后会停用同 IP 旧 active 封禁策略，并通知网关进程清理 IP 封禁缓存。
- `POST /__aisys__/api/ip-stats/:ipHash/unblock`：管理员停用 active 封禁策略，body 可为空，前端不要求填写解封原因。解封后通知网关进程清理 IP 封禁缓存。

网关命中 active 封禁策略时返回 OpenAI 兼容错误结构，HTTP 状态为 `403`，错误码为 `client_ip_blacklisted`，错误消息中会带当前来源 IPv4；响应中的 `error.client_ip` 为当前来源 IPv4。网关请求入口优先读取 server 进程内来源级封禁缓存；有效 API Key 且本地早拒绝检查通过后的缓存未命中请求，只允许按当前 `ip_hash` 通过 DB service 精确查询一条 active 策略并写入短 TTL 缓存。缺少 Bearer、无效 Key、计划停用或图像权限早拒绝不为 IP 策略额外查库；策略也不能随 API Key 运行态快照携带全量数组，避免高频认证失败放大成全量策略扫描。管理员创建 / 解封策略后通知网关进程清理 IP 封禁缓存。封禁命中先写入进程内缓冲，再异步批量落到 `client_ip_policy_hits`。

### 模型检测

模型检测用于对 AI 账户执行目标模型可信度检测，不提供绝对真伪证明。检测请求必须复用本地 OpenAI 网关链路；检测 AI 账户时复用账号测试的单账号候选能力，不能静默切换同分组其他账号，检测产生的真实请求按当前调用方计入使用记录、额度和授权消耗。完整设计见 [模型检测设计](模型检测设计.md)。

- `POST /__aisys__/api/model-checks/run`：管理员触发一次模型检测，`targetType` 固定为 `account`，支持 `targetId`、`model`、`trustedComparison` 和 `trustedComparisonAccountId`，检测 profile 后端固定为 `full`，返回检测报告摘要。可信对比默认关闭；显式开启但没有选择可信对比账户时，接口返回中文错误并拒绝本次检测，不能静默降级。可信对比开启成功时，后端会额外生成 `trusted_comparison` 和 `distribution_similarity` 检测项，用隐藏分布探针比较目标账户与可信对比账户。
- `GET /__aisys__/api/model-checks/runs`：管理员查看模型检测历史分页列表，可按系统账户、AI 账户、目标模型、可信等级和时间筛选。
- `GET /__aisys__/api/model-checks/runs/:id`：管理员查看单次检测详情，返回脱敏检测项、得分、traceId 和跳转排障所需摘要。
- `GET /__aisys__/api/model-checks/options`：管理员读取支持模型选项和可信对比状态摘要；AI 账户和可信对比账户下拉都来自对应作用域的账户 options 接口。
- `POST /__aisys__/api/my-model-checks/run`：当前登录用户触发自己的模型检测，忽略传入的 `systemAccountId`；`trustedComparison` 默认关闭，显式开启但没有选择可信对比账户时，接口返回中文错误并拒绝本次检测。
- `GET /__aisys__/api/my-model-checks/runs`：当前登录用户查看自己的模型检测历史分页列表。
- `GET /__aisys__/api/my-model-checks/runs/:id`：当前登录用户查看自己的单次检测详情；授权资源只返回脱敏可信度和安全摘要。
- `GET /__aisys__/api/my-model-checks/options`：当前登录用户读取支持模型选项和可信对比状态摘要；AI 账户和可信对比账户下拉都来自 `我的 AI 账户` 对应 options 接口。

接口返回必须使用“高可信、较可信、不确定、疑似不符、不可检测”等中文结论，不返回“已证明为真模型”。可信对比是可选增强项，默认不开启；开启失败时必须明确提示“请选择可信对比账户后再开启可信对比检测”或同义中文错误。分布相似度对照只保存 prompt key、统计摘要、traceId 和短输出预览，不返回完整隐藏题面。检测详情不得包含上游 API Key、OAuth token、代理密码、完整敏感请求头、大体积完整响应体或完整探针题库。

### 代理检测

- `GET /__aisys__/api/proxies`：管理员代理管理分页列表，支持 `page`、`pageSize`、`keyword`；关键词只按代理名称做精确 / 前缀匹配，不搜索代理 ID、地址、类型、用户名或说明。返回最近检测状态 `testStatus`、最近延迟 `latencyMs`、最近出口 IP `outboundIp`、最近出口地区 `outboundRegion`、检测摘要 `lastTestMessage` 和检测时间 `lastTestedAt`。
- `GET /__aisys__/api/proxies/options`：登录用户代理选择项，支持按代理名称搜索的 `keyword` 和 `limit`，只返回已启用代理的 `id`、`name`、`type` 和 `enabled`，用于 AI 账户表单和 OpenAI OAuth 流程。
- 账户一旦绑定代理，上游请求、OAuth token 交换、账户测试和后台冷却复测都必须使用该代理；代理不存在或被停用时请求应失败并提示重新选择已启用代理，不能静默直连。同一次网关调度中，某个代理已经失败后，后续绑定同一个代理的账号直接跳过，不重复请求。账户测试和后台冷却复测中的模型请求必须复用本地 OpenAI 网关链路并写入使用记录；OAuth token 交换、代理检测和 OAuth 额度快照被动写入不是模型请求，不计入使用统计。OAuth 额度快照不再有后台主动刷新任务，只从真实网关请求或账户测试响应头被动更新。
- `POST /__aisys__/api/proxies/:id/test`：管理员在代理测试弹窗内确认后手动触发代理质量检测，检测目标来自全部已启用供应商的默认地址，返回 `ProxyTestReport`；报告和列表同时展示出口 IP 和出口地区。
- 检测报告中的 `items` 至少包含“基础连通性”汇总项，以及每个已启用供应商默认地址对应的检测项。
- 出口信息参考 sub2api 的探测方式并扩展多级兜底：通过代理依次访问 `ip-api.com`、`ipwho.is`、`api.ip.sb`、`ipinfo.io`、`api.ipify.org`、`httpbin.org/ip`；出口信息不可用不影响供应商默认地址检测结果。
- `401`、`403`、`404`、`405`、`429` 等上游状态表示目标可达但鉴权、方法或频率受限，前端展示为告警；网络异常或 5xx 作为失败展示。
- 代理检测不会返回代理密码或完整代理 URL；前端只能展示安全摘要、HTTP 状态和延迟。

## 列表、筛选与分页

低增长配置类列表可以返回数组。新增高增长列表应使用统一分页结构。

推荐列表结构：

```json
{
  "data": {
    "items": [],
    "page": 1,
    "pageSize": 100,
    "total": 0,
    "hasMore": false
  }
}
```

约定：

- 查询参数使用 `page`、`pageSize`、`keyword`、`status`、`providerCode`、`systemAccountId`、`sortField`、`sortOrder` 等稳定名称。
- 普通用户传入 `systemAccountId` 应被忽略；只有管理员可以使用系统账户筛选。
- 排序字段必须后端白名单校验，不把任意字段名拼入 SQL。
- 使用记录、统计明细、授权用量这类持续增长数据必须优先支持后端分页或有限窗口查询；账户用量趋势接口只支持自然日范围，最大 1 个月。
- 使用记录、操作日志、原始审计日志、审计错误组、运行日志索引、账户用量统计明细和授权用量明细属于高增长或统计窗口列表，默认不执行精确 `COUNT(*)`；接口通过多取 1 条返回 `hasMore`，`total` 只作为兼容分页器的当前位置上界，前端不能把它展示成全量精确总数。
- 操作日志属于持续增长的业务追溯数据，列表必须分页查询；用户侧只能返回当前用户可见日志，管理侧可以按操作人、影响用户、资源和 trace ID 筛选。
- 审计日志属于持续增长且 payload 体积较大的高权限数据，列表必须分页查询元数据，详情 payload 必须按需加载，不能在列表接口返回完整原文。
- 前端表格分页、空态、错误态和加载态必须保持中文体验。

## 写接口防重复提交

管理端会改变业务状态的接口必须遵循 [幂等与唯一约束设计](幂等与唯一约束设计.md)，避免前端重复点击、网络卡顿重试或客户端脚本重复提交造成重复数据。

约定：

- `GET` 查询、列表、筛选、分页、详情、日志查看和审计查看不进入防重复提交缓存。
- 创建类 `POST` 默认需要后端声明操作指纹，包括 AI 账户、OAuth 账户、分组、API Key、代理、系统账户、系统团队、团队成员、统一授权和公告创建。
- 修改类 `PATCH`、删除类 `DELETE` 和发布 / 下线等状态切换接口建议接入短 TTL 防重复缓存，避免短时间重复写操作日志。
- 同一登录用户、同一路由、同一业务作用域、同一资源指纹的请求短时间内只允许一个进入真实业务写入。
- 同资源指纹请求正在处理时，返回 `409` 和中文提示，不执行业务写入。
- 缓存失效或进程重启后，数据库业务唯一约束继续兜底；命中唯一约束时返回 `409`，不写操作日志。
- 前端按钮 loading 和禁用只作为体验优化，不能替代服务端防重复缓存和数据库唯一约束。

## 权限摘要

资源列表中如果同一接口同时返回自有资源、个人授权资源和团队授权资源，应返回 `accessType`、授权来源摘要与 `permissions`，前端据此控制操作入口，后端仍在每个写接口重新校验。

推荐字段：

```json
{
  "accessType": "owner",
  "ownerSystemAccountId": "sa_xxx",
  "ownerDisplayName": "用户名称",
  "effectiveAuthorizationId": null,
  "authorizationSources": [],
  "authorizationGranteeType": null,
  "authorizationGranteeId": null,
  "permissions": {
    "canUse": true,
    "canEdit": true,
    "canDelete": true,
    "canReturnAuthorization": false,
    "canAuthorize": true,
    "canViewCredentials": true,
    "canManageMembers": true,
    "canBindToApiKey": true
  }
}
```

命名约定：

- 后端和前端类型优先使用 camelCase；数据库字段继续使用 snake_case。
- `accessType` 可取 `owner`、`authorized`、`admin_view`。
- 管理员查看他人资源时不改变资源所有者；必要时使用 `admin_view` 表示管理员视角。
- 授权资源必须返回所有者和授权来源摘要；如果个人来源与团队来源同时命中同一资源，只返回一行资源并在 `authorizationSources` 中列出全部来源，不能返回重复 AI 账户或重复分组。
- 资源列表应返回用户级 `authorizationId`，同时保留 `authorizationSources` 供前端显示“个人授权 + 团队授权”等来源。
- 授权 AI 账户列表必须返回 `effectiveAvailability` 表达实际可用性，并可返回 `authorizationInstanceSourceAccountStatus`、`authorizationInstanceSourceAccountSchedulable`、`authorizationInstanceSourceAccountExpiresAt`、`authorizationInstanceSourceAccountCooldownUntil` 和来源错误摘要作为来源侧证据。前端主状态和可操作性优先读取 `effectiveAvailability`；来源字段可以阻断实际可用性，但不能被当作授权实例 `accounts.status` 的覆盖值，也不能回写授权实例本地运行态。
- 授权管理页默认筛选“生效中”记录；资源被删除后，相关授权应变为 `revoked`，只在“全部状态”或“已回收”筛选下用于历史追溯。
- 授权资源不能返回完整凭据或代理密码；授权账户详情可以返回来源账户的非敏感公开配置用于只读展示，包括 `base_url`、公开 OAuth 元数据、模型、代理 ID、并发、自动启停计划、错误策略、流式规则和来源状态，但永远不能返回 OpenAI API Key、Access Token、Refresh Token、ID Token 或代理密码。

## 网关权限

- `/*` 和 `/v1/*` 网关入口不读取后台登录态，只读取 `Authorization: Bearer <本地网关 API Key>`；系统前缀 `/__aisys__/*` 除外。
- API Key 的所有者就是本次调用方系统账户。
- API Key 只能绑定调用方自己的一个或多个本地分组；即使调用方拥有分组授权，也不能把授权方分组作为自己的 API Key 调度池。
- 网关先读取 API Key active 分组路由绑定，按优先级选择可承接号池；当前分组无候选账号、模型不匹配、本地容量不可承接或上游未输出前全部失败时，可以尝试下一优先级分组。API Key 无效、Key 额度耗尽、请求本身无效、强制图像生成请求、已经产生可见流式输出时，不做跨号池切换；仅 auto 暴露的 Responses `image_generation` 工具在图像权限关闭时会被移除后继续按文本请求处理，不触发跨号池失败。
- API Key 自动启停计划在网关认证通过后、账号调度前判断；不命中允许时段时返回 OpenAI 兼容错误结构，HTTP 状态为 `403`，错误码为 `api_key_schedule_inactive`，错误消息为“API Key 当前不在允许使用时段”。该结果不计入无效 Key 探测，也不触发跨分组路由重试。
- 授权账户加入自有分组时，分组成员关系记录用户级 `accountAuthorizationId`；授权暂停、到期、回收或归还后调度必须实时拦截，重新激活同一最终授权后可恢复使用。
- 网关调度时必须重新校验 API Key 状态、分组路由绑定、分组可见性、统一授权有效性、授权额度、授权实例账户状态、实例到期、实例冷却和来源账户可用性；授权实例使用的凭据、模型、代理和错误策略从来源账户补齐，来源账户停用、异常、限流 / 临时不可调用、冷却未结束、关闭调度、套餐到期、删除或凭据缺失都是实际调度硬门禁。团队和成员变化应先同步到最终用户授权关系或来源状态，网关运行时不再额外遍历授权来源团队 / 成员状态。
- 网关调度时必须按后台统计缓存的 `total_cost_usd` 校验 API Key 美元成本额度、分组授权美元成本额度和账户授权美元成本额度；命中额度返回 429，错误文案为“额度已用完，请联系管理员提升额度”。
- 使用授权账户或授权分组时，使用记录必须同时冗余调用方、账户所有者、分组所有者、统一授权 ID 和授权对象类型，便于调用方明细、授权实例账户行用量、个人授权消耗、团队授权总消耗和团队成员消耗分开统计；被授权人的调用明细、测试、模型检测和本地操作日志归调用方自己，分组授权调用不能写入资源归属人的普通账户 / 分组统计，只能进入授权报表聚合；API Key 绑定入口只接受调用方自己的本地分组。
- 授权用量接口只由用户侧 `我的授权` 下的 `团队消耗明细` / `用户消耗明细` 或管理侧 `统一授权管理` 下的同名明细进入；团队 / 用户明细按 `startDate/endDate` 读取后台已写好的最近 31 天范围窗口。
- `授权操作` / `统一授权` 只服务授权关系列表，不展示用量筛选或用量列；`团队消耗明细` / `用户消耗明细` 必须使用专用后端接口直读授权范围窗口表，不能通过授权列表接口或前端本地汇总替代，接口不得实时 `SUM usage_records`，也不得临时汇总统计缓存。
- 同一调用方对同一资源同时拥有个人来源和团队来源时，网关仍只使用一条用户级授权写入一条使用记录，不能重复写入或重复计入事实总量。
- 网关返回给客户端的错误保持 OpenAI 兼容结构，不使用管理 API 的 `{ data, message }` 包装。

## 团队与授权对象接口

- `GET /__aisys__/api/system-accounts`：仅管理员可用，返回系统账户管理所需完整摘要；`keyword` 只按用户名称 `displayName` 做精确 / 前缀匹配，不搜索 ID、用户名或说明。
- `GET /__aisys__/api/system-accounts/options`：仅管理员可用，返回管理侧筛选和选择器所需的 `id`、`username`、`displayName`、`status`，支持 `keyword` 和 `limit`；关键词只按用户 ID、用户名和展示名做精确 / 前缀匹配并转义 LIKE 通配符，未传 `limit` 时也有服务端默认上限；不得读取或返回 `password_hash`、角色、改密状态、最后登录、创建 / 更新时间等系统账户管理字段。
- `GET /__aisys__/api/system-teams`：仅管理员可用，返回系统团队分页列表和当前页团队成员，支持 `page`、`pageSize`、`keyword`；关键词只按团队名称做精确 / 前缀匹配，不搜索团队 ID 或说明。
- `GET /__aisys__/api/my-teams`：所有登录用户可用，返回当前用户加入的团队分页列表和当前页团队成员，支持 `page`、`pageSize`、`keyword`；停用团队仍返回状态供页面展示，但不代表团队授权继续生效。
- `GET /__aisys__/api/accounts`、`GET /__aisys__/api/my-accounts`：返回账户分页列表；实时并发来自 server 进程快照，快照不可用时必须返回 `runtimeSnapshot.accountConcurrencyAvailable=false`，并在受影响账户上返回 `currentConcurrencyAvailable=false`，前端不能把仓库层默认 `0` 当成真实并发。
- `GET /__aisys__/api/accounts/options`、`GET /__aisys__/api/my-accounts/options`：返回授权资源下拉所需的 AI 账户最小摘要，可包含归属、授权状态和 `permissions`，支持 `keyword` / `limit` 远程搜索，不得返回凭据、用量、并发、质量分或完整列表字段。
- `GET /__aisys__/api/my-authorization-options/grantee-accounts`：所有登录用户可用，返回全系统授权对象选择所需的 `id`、`username`、`displayName`、`status`，支持 `keyword` 和 `limit`；该候选目录按产品口径允许全系统可见，但不得返回角色、改密状态、最后登录时间等系统账户管理字段。
- `GET /__aisys__/api/my-authorization-options/grantee-teams`：所有登录用户可用，返回全系统授权对象选择所需的系统团队最小摘要 `id`、`name`、`status`，支持 `keyword` 和 `limit`；该候选目录按产品口径允许全系统可见，但不得返回成员明细。
- `GET /__aisys__/api/authorization-options/grantee-accounts`：仅管理员管理侧使用，返回管理授权时需要的系统账户摘要，支持 `keyword` 和 `limit`。
- `GET /__aisys__/api/authorization-options/grantee-teams`：仅管理员管理侧使用，返回管理授权时需要的系统团队最小摘要，支持 `keyword` 和 `limit`。
- `GET /__aisys__/api/groups`、`GET /__aisys__/api/my-groups`：返回分组列表；分页响应带 `runtimeSnapshot.accountConcurrencyAvailable`，分组行的 `accountStats.currentConcurrencyAvailable=false` 表示实时并发快照不可用，不能展示为 `0` 积压。
- `GET /__aisys__/api/groups/options`、`GET /__aisys__/api/my-groups/options`：返回 API Key、授权和资源筛选下拉所需的分组最小摘要，可包含归属、授权状态和 `permissions`，支持 `keyword`、`providerCode`、`limit`、`manageableOnly` 和 `preferDefault`；关键词只按分组 ID、名称和供应商做精确 / 前缀匹配并转义 LIKE 通配符，不得返回 `accountStats`、`accountIds`、用量或并发快照。
- `GET /__aisys__/api/groups/account-options`、`GET /__aisys__/api/my-groups/account-options`：返回账户页所需的分组最小摘要加 `accountIds`，仅用于账户到分组名映射、默认分组和绑定分组下拉；同样支持远程搜索参数，不得返回 `accountStats`、用量或并发快照。
- `GET /__aisys__/api/authorization-options/grantee-groups`、`GET /__aisys__/api/my-authorization-options/grantee-groups`：返回授权创建弹窗所需的目标用户分组最小摘要，必须传 `granteeSystemAccountId`，可选 `providerCode`、`keyword`、`ids`、`limit` 和 `preferDefault`；只返回目标用户自己的启用分组，不能返回其他用户分组、分组成员、用量或并发快照。
- `GET /__aisys__/api/authorizations/usage/team-details`：仅管理员管理侧使用，按 `startDate=YYYY-MM-DD&endDate=YYYY-MM-DD`、`page`、`pageSize` 和筛选条件直读授权团队范围窗口表，不在接口内临时汇总；响应包含 `rows`、`summary`、`teamCount`、`page`、`pageSize`、`total`、`hasMore`，其中 `total` 和 `teamCount` 都是分页上界，不要求请求链路额外精确 `COUNT(*)` / `COUNT(DISTINCT)`。
- `GET /__aisys__/api/authorizations/usage/user-details`：仅管理员管理侧使用，按 `startDate=YYYY-MM-DD&endDate=YYYY-MM-DD`、`page`、`pageSize` 和筛选条件直读授权用户范围窗口表，不在接口内临时汇总；响应包含 `rows`、`summary`、`userCount`、`page`、`pageSize`、`total`、`hasMore`，其中 `total` 和 `userCount` 都是分页上界，不要求请求链路额外精确 `COUNT(*)` / `COUNT(DISTINCT)`。
- `GET /__aisys__/api/my-authorizations/usage/team-details`：所有登录用户可用，忽略 `systemAccountId`，按当前用户作为资源归属人读取授权团队范围窗口表，分页契约同管理侧团队消耗明细。
- `GET /__aisys__/api/my-authorizations/usage/user-details`：所有登录用户可用，忽略 `systemAccountId`，按当前用户作为资源归属人读取授权用户范围窗口表，分页契约同管理侧用户消耗明细。

## AI 性能监控接口

AI 性能监控接口只服务后台页面，不参与网关请求链路。接口趋势只能读取 `usage_stats_hourly` 和账户元数据，摘要只能读取 `ai_performance_summary_windows`，不能在请求时实时汇总 `usage_records` 或把小时曲线再次聚合成摘要。

统计概览当前接口：

- `GET /__aisys__/api/my-stats/usage-overview`：当前登录用户查看自己的业务统计概览，支持 `startDate=YYYY-MM-DD&endDate=YYYY-MM-DD`，忽略 `systemAccountId`；默认今天，最大最近 31 天。
- `GET /__aisys__/api/stats/usage-overview`：管理员查看业务统计概览，支持同样的日期范围，默认全局汇总；可选 `systemAccountId` 筛选指定用户。
- `GET /__aisys__/api/stats/system-metrics`：管理员查看主机级系统监控趋势，系统性能 / 网络吞吐趋势支持同样的日期范围；用户侧不可调用。后台任务状态来自 worker snapshot，响应用 `runtimeSnapshotAvailable`、`workerSnapshotAvailable` 和 `backgroundJobsAvailable` 区分“暂无任务”和“暂时不可观测”，不可用时 `backgroundJobs=null`。进程事件循环延迟不跟随日期筛选，固定读取最近 24 小时：`processEventLoopLatestStatus` 返回各角色最新采样，`processEventLoopPeakStatus` 返回各角色 24 小时内最大延迟采样，二者都固定覆盖 `server`、`worker`、`db-service` 三个角色，每项包含 `sampleAvailable`、`processPid`、`sampledAt` 和 `eventLoopLagMs`；缺少样本时用 `sampleAvailable=false` 与 `null` 表达未知。

账户用量趋势接口：

- `GET /__aisys__/api/my-stats/account-usage`：当前登录用户查看本人调用产生的账户按日消耗趋势，忽略 `systemAccountId`；支持临时 `accountIds` 追加账户，响应包含 `hasMore`，`total` 是分页上界，不执行精确 `COUNT(*)`。
- `GET /__aisys__/api/stats/account-usage`：管理员查看系统账户维度的本人账户按日消耗趋势，可选 `systemAccountId` 筛选指定用户；支持临时 `accountIds` 追加账户，响应包含 `hasMore`，`total` 是分页上界，不执行精确 `COUNT(*)`。

契约要求：

- 支持 `startDate`、`endDate`、`keyword`、`page`、`pageSize` 和 `accountIds`；日期格式为 `YYYY-MM-DD`，按服务端本地自然日解释。页面筛选不提供账户类型筛选，用户侧和管理侧页面默认都传日期范围；账号类型只在明细中作为运行态展示，不作为统计筛选、统计分片、额度分片、会话亲和或 prompt cache 分片。
- 日期范围最大 31 天；接口缺省为最近 31 天，超过范围或超出最近 31 天由后端收敛到允许范围；用户侧 `我的用量` 和管理侧 `用量统计管理` 页面首次进入都会显式传最近 31 天范围。
- 统计口径读取 `usage_stats_daily` 的 `scope_type = caller_account`，自有账户不混入被授权人的调用，授权给自己的账户只展示当前登录用户自己的调用。
- 账户明细始终按后端分页窗口返回，未传分页参数时使用服务端默认 `pageSize`；排序按范围内请求数、成本、Token 和最后使用时间稳定排列，`total` 只作为分页器上界，是否还有下一页以 `hasMore` 为准。
- `accountIds` 可用逗号分隔或重复 query 参数传入，只表示本次请求临时追加到账户列表的账号；后端去重后最多取 50 个，不写数据库、不写系统设置、不作为用户偏好，也不表示前端点击账户列表后的筛选状态。
- 响应返回 `range`、`summary`、`defaultTrendAccountIds`、`rows[].rangeUsage` 和 `rows[].dailyUsage`；`dailyUsage` 每天一项，缺失日期补 0。
- 默认趋势账户池：普通用户和管理员指定 `systemAccountId` 时，只读取 `usage_rank_snapshots` 中当前调用方 `caller_account + last7d + request_count` 的最近 7 天活跃前 10；管理员未指定 `systemAccountId` 查看全部用户时，从本次范围统计缓存结果中选出全局可见账户 Top 10。两种路径都不能在接口请求时实时回扫 `usage_records`。
- 接口只能读取统计缓存、排行快照和账户元数据，不能在请求时实时汇总 `usage_records`。
- 授权用量明细不通过该接口返回，也不在用量统计页提供跳转入口。

AI 性能监控当前接口：

- `GET /__aisys__/api/my-stats/ai-performance`：当前登录用户查看自己可使用 AI 账户的整体性能趋势，包含自有账户、账号授权实例和授权分组内来源账户；支持 `startDate=YYYY-MM-DD&endDate=YYYY-MM-DD` 和用于搜索追加账户列表的临时 `accountIds`，忽略 `systemAccountId`。
- `GET /__aisys__/api/my-stats/ai-performance/accounts`：当前登录用户查看自己可使用 AI 账户的轻量选项，支持 `keyword`、`accountIds` 和 `limit`，忽略 `systemAccountId`。
- `GET /__aisys__/api/stats/ai-performance`：管理员查看全部用户或指定系统账户可使用 AI 账户的整体性能趋势，支持 `systemAccountId`、`startDate=YYYY-MM-DD&endDate=YYYY-MM-DD` 和临时 `accountIds`。
- `GET /__aisys__/api/stats/ai-performance/accounts`：管理员查看全部用户或指定系统账户可使用 AI 账户的轻量选项，支持 `systemAccountId`、`keyword`、`accountIds` 和 `limit`。

契约要求：

- 接口日期范围缺省为今天，最大最近 31 天；页面首次进入显式传最近 3 天范围，超过范围由后端收敛到允许范围。
- 默认账户池固定读取 `usage_rank_snapshots` 中 `last7d + request_count` 的最近 7 天活跃前 10；用户侧和管理侧指定用户读取对应系统账户的 `caller_account` 快照，管理侧全部用户读取全局 `account` 快照。快照缺失时返回空数组，不能在接口请求时临时聚合降级。
- 用户侧接口只能返回当前登录用户可使用的 AI 账户；别人授权给当前用户使用的账户以授权实例账户出现在默认账户、搜索结果或临时追加结果中，授权分组内来源账户只读取当前调用方的 `caller_account` 数据。管理侧按管理员权限读取全部用户或指定用户范围。指定用户视图统计值读取 `scope_type = caller_account`，全局管理视图读取 `scope_type = account`，授权实例、授权分组来源账户和归属人原账户互不混入。
- `accountIds` 只表示本次搜索追加到账户列表的账户，添加上限由后端限制；不写数据库、不写系统设置、不作为用户偏好；不表示前端点击筛选状态。
- 响应需要区分 `defaultAccounts`、`selectedAccounts`、当前账户列表 `accounts` 和 `hourlySeries`；`selectedAccounts` 沿用接口字段名，语义为搜索追加账户。
- 前端点击账户列表筛选统计视图时，只在已返回的 `accounts` 和 `hourlySeries` 内控制图表显隐，不重新请求后端，也不重算页面顶部摘要。
- 管理侧全部用户视图读取 `system_account_id = global` 的账户统计缓存和排行快照；指定用户视图读取该系统账户的账户统计缓存。
- 空小时不伪造成 `0ms`，平均 / 最大首 token 和平均 / 最大总耗时没有样本时返回空值。
- 前端绘图可以连接空小时两侧的有效点，但不能把空小时展示为 `0ms` 或有效采样点。
- 详细字段和性能边界见 [AI 性能监控设计](AI性能监控设计.md)。

## 表监控接口

表监控接口仅允许管理员访问，服务容量观测和统计数据集域维护，不参与网关请求链路。

- `GET /__aisys__/api/table-monitor/overview`：读取业务库、数据集目录库和统计结果库最新采样摘要和表大小列表，支持 `startAt`、`endAt` 和 `limit`；usage shard 文件集合观测仍在后续增强阶段。
- `GET /__aisys__/api/table-monitor/history`：读取指定库和表的采样历史，`databaseRole` 支持 `business`、`dataset`、`stats`，并支持 `tableName`、`startAt`、`endAt` 和 `limit`。
- `POST /__aisys__/api/table-monitor/usage-records/cleanup`：按 `cutoffAt` 申请清理早于该时间的 `usage_records`；`cutoffAt` 不能晚于当前时间 24 小时前，最近 1 天只是最小年龄门槛；请求可传 `batchSize` 和 `maxBatches`，后端有上限，提交前返回首批可清理数量、是否已投递 worker、任务 ID、是否仍有更多可清理记录和可能的投递失败原因。

契约要求：

- 清理接口会先强制保护最近 1 天，但实际删除仍受统计安全游标和必要回填游标保护；游标未就绪或未追平时返回 `queued = false`、`eligibleRows = 0` 和 `blockedReason`。
- 清理接口只删除已经被相关统计 / 回填游标确认处理过的 `usage_records`，不删除统计缓存、审计日志、操作日志或业务关系表。
- 提交成功、未提交或被游标阻塞时都会写入操作日志；`eligibleRows = 0` 时也会记录未提交原因，方便运维追踪。
- API Key 删除后的关联记录清理由 API Key 删除流程自动登记并交给后台 worker 重试处理，不作为表监控接口或页面展示项。

## 操作日志接口

操作日志接口记录业务状态变更的追溯结果。查询操作日志本身属于查询行为，不写操作日志。

当前接口：

- `GET /__aisys__/api/my-operation-logs`：当前登录用户分页查看与自己有关的操作日志，支持摘要、模块、动作、资源类型、资源 ID、时间和 trace ID 筛选。
- `GET /__aisys__/api/my-operation-logs/:id`：当前登录用户查看自己可见的操作日志详情。
- `GET /__aisys__/api/operation-logs`：仅管理员可用，分页查看全部操作日志，支持摘要、操作人、影响用户、业务作用域、模块、动作、资源类型、资源 ID、时间和 trace ID 筛选。
- `GET /__aisys__/api/operation-logs/:id`：仅管理员可用，查看任意操作日志详情。

契约要求：

- `GET`、列表查询、详情查看、筛选、分页、搜索、日志查看和审计查看都不写操作日志。
- 操作日志只记录成功提交的业务状态变更；失败且未改变数据的请求不写操作日志。
- 普通用户接口不能接受跨用户筛选条件，后端必须按 `operation_log_viewers` 和全员安全摘要过滤。
- 普通用户接口必须按日志 `detailLevel` 和 viewer `detail_level` 裁剪返回；`summary` 级不返回字段差异、影响对象、可见用户、请求路径、客户端 IP 或 User-Agent，用户侧 `full` 级也不返回可见用户列表。
- 管理员接口可以查看全部日志，但仍不能展示凭据、token、代理密码、完整 API Key 或原始审计 payload。
- 列表只返回摘要、资源快照、关键差异和可见原因；详情可以返回目标资源和完整安全 diff。
- `summaryKeyword` 通过操作日志写入时生成的摘要倒排词项只检索中文摘要；资源类型、资源 ID、操作人、影响用户、业务作用域、模块、动作和 trace ID 使用独立筛选参数。后端不能在列表请求里对 `operation_logs` 主表做前导通配符扫描，也不能把资源名、操作人、操作键、模块或动作混入摘要搜索。
- `traceId` 支持右侧前缀定位，不使用前导通配符。
- 使用记录页可把 `traceId` 深链到 `/runtime-logs`、`/audit-logs`、`/operation-logs` 或 `/my-operation-logs`；目标页读取 `traceId` query 初始化筛选，用户手动搜索、切换模式或重置后应移除一次性 query，并恢复为页面本地筛选状态。
- 操作日志错误提示使用中文；错误详情不能把原始请求体或敏感字段打回前端。

## 审计日志接口

审计日志接口仅允许 `admin` 访问，普通用户即使是请求调用方也不能读取完整原文。

当前接口：

- `GET /__aisys__/api/audit-logs`：分页查询审计日志元数据，支持时间、系统账户、API Key、分组、账号、接口、模型、状态码、结果和 trace ID 筛选。
- `GET /__aisys__/api/audit-logs/:id`：查看审计详情、上游尝试列表和 payload 摘要。
- `GET /__aisys__/api/audit-logs/:id/payloads/:payloadId`：按需读取某段原始 payload，支持 `offset` 和 `limit`，只返回当前窗口。
- `GET /__aisys__/api/audit-logs/runtime`：查看审计队列长度、队列字节数、最近落库时间、最近错误和丢弃计数；响应必须包含 `runtimeAvailable`、`workerSnapshotAvailable`、`auditLogQueueAvailable` 和 `activeCaptureAvailable`，运行态不可用时相关数字返回 `null`，不能伪装成 `0` 或 `false`。

契约要求：

- 列表接口只返回元数据，不返回完整 headers 或 body。
- 审计详情的 payload 摘要返回 `headersSha256` 和 `bodySha256`，分别表示完整 headers JSON 和 body 原文字节的摘要；`bodySha256` 不代表整条审计记录。
- payload 读取接口必须重新校验管理员权限，不能只依赖详情页已加载。
- payload 读取接口不得一次性读取完整大 blob；响应需要带 `bodyOffset`、`bodyLimit`、`bodyTotalBytes`、`bodyNextOffset` 和 `bodyTruncated`，前端按游标继续加载。
- payload 响应可以返回文本、JSON 或二进制摘要；前端无法安全解码时展示大小、hash 和十六进制预览。
- 审计日志写入不通过管理 API 直接发生；网关只终态入队，后台批量落库。
- 审计日志接口错误提示使用中文；错误详情不能再把完整 payload 打回普通错误响应。
- 审计列表的 `path`、`model` 等结构化条件按精确值匹配；`traceId` 和客户端 IP 只支持右侧前缀定位，不允许前导通配符扫描审计主表。

## 公开接口日志接口

公开接口日志接口仅允许 `admin` 访问，用于排查 `/__aipublic__` 外部来源系统调用。公开接口日志只保存来源、接口、状态、耗时和脱敏后的有限请求 / 响应摘要，最大保留 7 天；完整设计见 [公开接口日志设计](公开接口日志设计.md)。

当前接口：

- `GET /__aisys__/api/public-api-logs`：分页查询公开接口日志元数据，支持 `traceId`、`sourceRefId`、`path`、`result=success|failed|all`、`statusCode`、`clientIp`、`startAt`、`endAt`、`page` 和 `pageSize`。
- `GET /__aisys__/api/public-api-logs/:id`：查看单条公开接口日志详情，返回脱敏后的请求摘要和响应摘要。

契约要求：

- 只有 `/__aipublic__/*` 请求写入公开接口日志；后台管理接口、OpenAI 兼容网关接口、静态资源和健康检查不写入该表。
- 成功、失败、缺少 token、token 错误、scope 不足、限频、公开前缀 404 和 JSON body 解析失败都应记录。
- 列表接口只返回元数据、大小和捕获状态，不返回大段请求 / 响应内容；详情接口返回的 `requestData` 和 `responseData` 必须已脱敏并带捕获状态。
- `Authorization`、来源 token、普通 API Key 明文、上游 API Key、OAuth token、代理密码、Cookie、password / secret 类字段和敏感 query 参数都不能保存原文。
- `traceId` 和 `clientIp` 支持右侧前缀定位；`path`、`sourceRefId` 和 `statusCode` 使用结构化精确筛选，不使用前导通配符。
- 公开接口日志固定最多保留 7 天，不能通过系统设置延长到超过 7 天。

## 日志搜索接口

日志搜索接口仅允许 `admin` 访问，不读取原始审计 payload。索引查询读取普通运行日志的 SQLite 索引；`grep 模式` 由后端调用 `rg` 扫描日志目录中当前保留的 `.log` 文件，当前文件日志默认保留 30 天、最多 500 个轮转文件。

当前接口：

- `GET /__aisys__/api/runtime-logs`：分页查询当前 SQLite 索引表内的运行日志，支持 `page`、`pageSize`、`traceId`、`level`、`event`、`keyword`、`startAt` 和 `endAt`，默认返回最近 100 条；时间范围按索引日志时间 `runtime_logs.time` 筛选，索引表保留周期由后台清理任务控制。响应中的 `retentionDays` 只表示 worker snapshot 中的运行队列保留期，快照不可用时返回 `null` 并标记 `retentionDaysSource=unavailable`。
- `GET /__aisys__/api/runtime-logs/facets`：读取最近 3 天索引范围、级别分布、事件和索引队列运行态；响应用 `runtimeAvailable`、`workerSnapshotAvailable`、`runtimeLogIndexQueueAvailable`、`gatewayAccountSideEffectsAvailable` 和 `dbService.statusAvailable/stateAvailable` 区分真实空队列与运行态不可观测，不可观测对象返回 `null`。
- `GET /__aisys__/api/runtime-logs/grep`：在后端普通日志目录内通过 `rg` 按任意关键字搜索当前保留的 `.log` 文件，支持 `keywords` 或重复 `keyword` 参数，支持 `startAt` / `endAt` 文件时间范围；默认按文件时间搜索最近 3 天，单次最多 7 天，同一后端进程一次只允许 1 个 grep 搜索，单次 `rg` 搜索 15 秒超时，最多返回 100 行匹配。多关键字按 AND 处理，最多取前 10 个去重关键字，必须在同一行同时命中。

契约要求：

- 响应只返回有限条数，后端限制 `limit` 上限，避免把日志搜索变成全量导出。
- 索引查询中，`traceId`、级别、事件和日志时间必须走索引字段；`traceId` 支持右侧前缀定位，不使用前导通配符；关键字只对 `runtime_logs.message` 做普通模糊匹配，不检索 `raw_json`，完整正文搜索使用 `grep 模式`。
- 运行日志搜索索引固定保留 3 天，超过 3 天返回空结果或只返回仍在索引范围内的结果。
- `grep 模式` 后端仍返回文件名、完整文件路径、行号、实际文件搜索范围和匹配行，前端列表与索引查询使用同一组运行日志展示字段；文件和位置只放在详情里。后端固定在日志目录内按文件时间范围筛选当前保留的 `.log` 文件；时间范围只决定哪些文件参与扫描，进入文件后只做关键字匹配，不读取文件内容判断行时间。不接收路径参数，不支持多条件筛选，同一后端进程一次只允许 1 个 grep 搜索，单次 `rg` 搜索 15 秒超时。当前文件日志保留由 `JUHE_AI_LOG_RETENTION_DAYS`、`JUHE_AI_LOG_MAX_FILES` 和单文件大小共同约束，默认 30 天、最多 500 个轮转文件，按时间或文件数清理最早日志。
- 全平台如果缺少生产依赖 `@vscode/ripgrep` 提供的 `rg`，`grep 模式` 必须返回安装提示而不是退化为慢速扫描；不能回退到 Node 文件扫描、服务器 PATH 或系统 `grep` 造成不同部署平台行为不一致。

## 公告中心接口

公告中心接口只服务后台用户界面，不参与网关调用链路。

当前接口：

- `GET /__aisys__/api/announcements/public?limit=30`：所有登录用户可用，只返回最近已发布公告，后端限制最多 30 条。
- `POST /__aisys__/api/announcements/public/read`：所有登录用户可用，把当前用户看到的公告 ID 写入已读记录，最多 30 条。
- `GET /__aisys__/api/announcements`：仅管理员可用，返回公告管理列表。
- `POST /__aisys__/api/announcements`：仅管理员可用，创建草稿或直接发布公告。
- `PATCH /__aisys__/api/announcements/:id`：仅管理员可用，更新公告标题、正文、重要性和状态。
- `POST /__aisys__/api/announcements/:id/publish`：仅管理员可用，发布公告。
- `POST /__aisys__/api/announcements/:id/unpublish`：仅管理员可用，下线公告。
- `DELETE /__aisys__/api/announcements/:id`：仅管理员可用，删除公告。

契约要求：

- 普通用户接口永远不能返回草稿或已下线公告。
- 公告列表响应字段使用 camelCase；数据库字段使用 snake_case。
- 公告正文第一版按纯文本处理，不允许 HTML 注入。
- 新公告提醒由用户侧列表中的 `readAt` 判断；点击铃铛打开公告弹窗后，前端批量调用已读接口，后端按 `announcement_id + system_account_id` 维护已读事实。
- 管理员重新发布草稿或已下线公告时，后端必须刷新 `publishedAt` 并删除该公告的已读记录，确保所有用户重新收到提醒；普通编辑已发布公告不清理已读。

## 新增接口检查清单

- 是否明确属于 `/__aisys__/api/my-*` 用户接口、`/__aisys__/api/*` 管理接口还是 `/*` / `/v1/*` 网关接口？
- 如果接口会改变业务状态，是否注册操作日志语义和可见范围？如果只是查询，是否明确不写操作日志？
- 是否明确登录态、管理员权限、资源所有者权限或授权使用权？
- 普通用户可见页面会调用的接口，是否已在 `pnpm test:scope` 固定为普通用户可访问；`my-*` 命名空间下的管理员例外，是否已固定为普通用户 403？
- 是否使用统一成功和错误响应结构？
- 是否需要 `permissions` 摘要？
- 是否做后端参数校验、排序白名单和系统账户隔离？
- 是否会返回或记录敏感字段？如会，是否符合 [安全与日志策略](安全与日志策略.md)？
- 是否需要同步前端类型、功能设计、SQLite 文档、开发验证或部署文档？
