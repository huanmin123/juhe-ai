# 接口契约与权限矩阵

> 面向前端、后端与 AI 维护者。
> 本文统一管理后台 `/api/*`、网关 `/v1/*`、响应结构、分页筛选、错误语义和核心权限矩阵，避免接口口径散落在页面、路由和计划文档里。

## 文档目标

- 固定前后端对接口返回、错误、分页、筛选和权限摘要的共同理解。
- 明确 `admin`、普通 `user`、资源所有者和被授权用户在各模块里的操作边界。
- 给新增接口提供默认契约，减少每个路由自行设计返回结构。
- 只记录稳定契约，不替代具体功能字段说明；业务字段仍以 [核心功能设计](核心功能设计.md) 和 [SQLite 存储说明](SQLite存储说明.md) 为准。

## 接口分层

| 接口层 | 路径 | 身份来源 | 返回风格 | 说明 |
| --- | --- | --- | --- | --- |
| 用户 API | `/api/my-*` | 后台登录态 Cookie | 项目管理 API 结构 | 前端 `我的...` 页面使用，后端强制当前登录用户作用域，忽略 `systemAccountId` 查询。 |
| 管理 API | `/api/*` | 后台登录态 Cookie | 项目管理 API 结构 | 前端管理页面使用，默认需要 `requireAuth`；涉及跨系统账户管理、全局数据或系统配置的接口必须叠加 `requireAdmin`。 |
| 公开 API | `/api/health`、公开品牌设置、登录和验证码 | 无登录态或登录流程 | 项目管理 API 结构 | 只暴露健康检查、未登录所需品牌信息、登录验证码和登录接口。 |
| 网关 API | `/v1/*` | 本地网关 API Key | OpenAI 兼容结构 | 面向 OpenAI 兼容客户端，不使用后台登录态，不返回管理 API 包装。 |

## 菜单入口与视图范围

- 管理员同时拥有用户身份和管理员身份，因此前端提供用户模式和管理模式；左侧菜单只展示当前模式的入口，头部用户下拉提供模式切换。
- 管理员首次进入默认用户模式；切换后可把菜单模式作为当前浏览器里的个人使用习惯保存，下次登录或访问根路径时沿用上次模式。该偏好只影响前端入口，不改变后端权限。
- 普通用户只显示用户侧入口；管理员在用户模式的 `我的...` 入口中也只能按当前登录用户查询自己的数据，不能因为角色是管理员就自动进入全局查询范围。
- 管理侧入口必须使用管理员路由和管理员接口能力，例如 `AI 账户管理`、`AI 分组管理`、`API Key 管理`、`使用记录管理`、`用量统计管理`、`系统团队管理` 和 `统一授权管理`。
- 用户侧入口必须使用当前用户作用域，例如 `我的 AI 账户`、`我的分组`、`我的 API Key`、`我的使用记录`、`我的用量`、`我的团队` 和 `我的授权`。
- 用户侧页面优先调用 `/api/my-accounts`、`/api/my-groups`、`/api/my-api-keys`、`/api/my-authorizations`、`/api/my-openai-oauth`、`/api/my-usage-records`、`/api/my-stats` 和 `/api/my-teams`。
- 管理侧页面保留 `/api/accounts`、`/api/groups`、`/api/api-keys`、`/api/authorizations`、`/api/openai-oauth`、`/api/usage-records`、`/api/stats` 等管理入口，并由后端显式校验管理员身份。
- 同一 Vue 页面可以复用，但系统账户筛选、系统账户列、全量管理接口和跨用户查询只能在管理侧入口启用。

## 管理 API 响应

当前实现已使用 `backend/src/shared/http.ts` 的 `ok(data, message?)` 和 `badRequest(message)` 作为基础约定。后续新增接口优先沿用以下结构。

成功响应：

```json
{
  "data": {},
  "message": "可选中文提示"
}
```

错误响应：

```json
{
  "message": "中文错误提示",
  "code": "可选稳定错误码",
  "details": {}
}
```

约定：

- 成功响应必须包含 `data`；没有业务返回值时可返回 `{ "data": { "ok": true } }`，删除接口也可以使用 `204 No Content`。
- `message` 面向前端直接展示，默认使用中文；后端内部日志、脚本输出和使用记录错误摘要中的系统自定义描述也必须使用中文。
- 只翻译面向人阅读的描述性文案，不翻译机器可读字段或协议值；`code`、`type`、`event`、状态枚举、header、路由路径、SQL 常量、缓存 key、OpenAI / SSE 事件名和数据库字段值必须保持稳定。
- 技术名词可以保留原文并嵌入中文文案，例如 `API Key`、`OAuth`、`Bearer Token`、`Refresh Token`、`access_token`、`HTTP` 和 `SSE`。
- 现有部分错误只返回 `{ "message": "..." }`，这是当前兼容形态；新增复杂错误建议补稳定 `code`。
- `details` 只放字段级校验摘要、可安全展示的限制原因或操作上下文，不放敏感凭据、完整请求体、完整上游响应或 token。
- 前端不能通过 HTTP 状态码之外的字段自行推断权限，必须以接口返回和 `permissions` 摘要为准。
- `我的授权` 必须包含当前用户授权出去和授权给当前用户的记录；授权给当前用户但资源不属于当前用户的记录只提供查看和明细入口，不能展示暂停、回收或修改配置等管理动作。

## HTTP 状态

| 状态码 | 使用场景 | 前端处理 |
| --- | --- | --- |
| `200` | 查询、更新、操作成功 | 读取 `data`，必要时展示 `message`。 |
| `201` | 创建成功 | 读取 `data`，创建 API Key 时注意明文只按约定展示。 |
| `204` | 删除或无返回内容操作成功 | 不读取 body，直接刷新列表或回到上级页面。 |
| `400` | 参数格式错误、业务输入不合法 | 展示 `message`，表单场景尽量定位字段。 |
| `401` | 未登录、会话过期、网关密钥缺失或无效 | 后台跳转登录；网关返回 OpenAI 兼容错误。 |
| `403` | 已登录但无权限 | 展示无权限提示，不自动重试。 |
| `404` | 资源不存在或当前用户不可见 | 展示不存在或已失效，避免暴露其他用户资源是否存在。 |
| `409` | 唯一约束、重复授权、重复凭据等冲突 | 展示冲突原因，引导用户更换输入或收回旧关系。 |
| `429` | 登录限频、上游限流或账号冷却 | 展示冷却或稍后重试信息。 |
| `500` | 未知服务端错误 | 展示通用错误，详细信息只进入安全日志。 |
| `502` | 上游 OAuth、上游模型或代理请求失败 | 展示上游请求失败摘要，避免暴露完整上游敏感响应。 |

## 模块操作补充

### 代理检测

- `GET /api/proxies`：管理员代理管理列表，返回最近检测状态 `testStatus`、最近延迟 `latencyMs`、最近出口 IP `outboundIp`、最近出口地区 `outboundRegion`、检测摘要 `lastTestMessage` 和检测时间 `lastTestedAt`。
- `GET /api/proxies/options`：登录用户代理选择项，只返回已启用代理的 `id`、`name`、`type` 和 `enabled`，用于 AI 账户表单和 OpenAI OAuth 流程。
- 账户一旦绑定代理，上游请求、OAuth token 交换、账户测试、后台冷却复测和 OAuth 用量刷新都必须使用该代理；代理不存在或被停用时请求应失败并提示重新选择已启用代理，不能静默直连。账户测试、后台冷却复测和 OAuth 用量刷新中的模型探测必须复用本地 OpenAI 网关链路并写入使用记录；OAuth token 交换和代理检测不是模型请求，不计入使用统计。
- `POST /api/proxies/:id/test`：管理员在代理测试弹窗内确认后手动触发代理质量检测，检测目标来自全部已启用供应商的默认地址，返回 `ProxyTestReport`；报告和列表同时展示出口 IP 和出口地区。
- 检测报告中的 `items` 至少包含“基础连通性”汇总项，以及每个已启用供应商默认地址对应的检测项。
- 出口信息参考 sub2api 的探测方式并扩展多级兜底：通过代理依次访问 `ip-api.com`、`ipwho.is`、`api.ip.sb`、`ipinfo.io`、`api.ipify.org`、`httpbin.org/ip`；出口信息不可用不影响供应商默认地址检测结果。
- `401`、`403`、`404`、`405`、`429` 等上游状态表示目标可达但鉴权、方法或频率受限，前端展示为告警；网络异常或 5xx 作为失败展示。
- 代理检测不会返回代理密码或完整代理 URL；前端只能展示安全摘要、HTTP 状态和延迟。

## 列表、筛选与分页

第一阶段列表数据量较小，部分接口可先返回数组。新增高增长列表应使用统一分页结构。

推荐列表结构：

```json
{
  "data": {
    "items": [],
    "page": 1,
    "pageSize": 100,
    "total": 0
  }
}
```

约定：

- 查询参数使用 `page`、`pageSize`、`keyword`、`status`、`providerCode`、`systemAccountId`、`sortField`、`sortOrder` 等稳定名称。
- 普通用户传入 `systemAccountId` 应被忽略；只有管理员可以使用系统账户筛选。
- 排序字段必须后端白名单校验，不把任意字段名拼入 SQL。
- 使用记录、统计明细、授权用量这类持续增长数据必须优先支持后端分页或有限窗口查询。
- 审计日志属于持续增长且 payload 体积较大的高权限数据，列表必须分页查询元数据，详情 payload 必须按需加载，不能在列表接口返回完整原文。
- 前端表格分页、空态、错误态和加载态必须保持中文体验。

## 权限摘要

资源列表中如果同一接口同时返回自有资源、个人授权资源和团队授权资源，应返回 `accessType`、授权来源摘要与 `permissions`，前端据此控制操作入口，后端仍在每个写接口重新校验。

推荐字段：

```json
{
  "accessType": "owner",
  "ownerSystemAccountId": "sa_xxx",
  "ownerDisplayName": "用户名称",
  "effectiveAuthorizationId": null,
  "authorizationSources": [],
  "authorizationGranteeType": null,
  "authorizationGranteeId": null,
  "permissions": {
    "canUse": true,
    "canEdit": true,
    "canDelete": true,
    "canAuthorize": true,
    "canViewCredentials": true,
    "canManageMembers": true,
    "canBindToApiKey": true
  }
}
```

命名约定：

- 后端和前端类型优先使用 camelCase；数据库字段继续使用 snake_case。
- `accessType` 可取 `owner`、`authorized`、`admin_view`。
- 管理员查看他人资源时不改变资源所有者；必要时使用 `admin_view` 表示管理员视角。
- 授权资源必须返回所有者和授权来源摘要；如果个人来源与团队来源同时命中同一资源，只返回一行资源并在 `authorizationSources` 中列出全部来源，不能返回重复 AI 账户或重复分组。
- 资源列表应返回用户级 `authorizationId`，同时保留 `authorizationSources` 供前端显示“个人授权 + 团队授权”等来源。
- 授权资源不能返回完整凭据、代理密码或不可展示配置。

## 网关权限

- `/v1/*` 不读取后台登录态，只读取 `Authorization: Bearer <本地网关 API Key>`。
- API Key 的所有者就是本次调用方系统账户。
- API Key 只能绑定一个自有分组，或一个通过个人授权 / 团队授权授权给自己的分组。
- 授权账户加入自有分组时，分组成员关系记录用户级 `accountAuthorizationId`；授权暂停、到期或撤销后调度必须实时拦截，重新激活同一最终授权后可恢复使用。
- 网关调度时必须重新校验 API Key 状态、分组可见性、统一授权有效性、团队状态、成员状态、账户状态、账户到期、账号冷却、代理和错误策略。
- 网关调度时必须按后台统计缓存的 `total_cost_usd` 校验 API Key 美元成本额度、分组授权美元成本额度和账户授权美元成本额度；命中额度返回 429，错误文案为“额度已用完，请联系管理员提升额度”。
- 使用授权账户或授权分组时，使用记录必须同时冗余调用方、账户所有者、分组所有者、统一授权 ID 和授权对象类型，便于调用方明细、资源真实总量、个人授权消耗、团队授权总消耗和团队成员消耗分开统计。
- 授权用量接口按“资源 × 用户”返回消耗；团队筛选只是把团队成员的用户消耗去重汇总，不单独制造团队统计事实。
- 同一调用方对同一资源同时拥有个人来源和团队来源时，网关仍只使用一条用户级授权写入一条使用记录，不能重复写入或重复计入事实总量。
- 网关返回给客户端的错误保持 OpenAI 兼容结构，不使用管理 API 的 `{ data, message }` 包装。

## 团队与授权对象接口

- `GET /api/system-accounts`：仅管理员可用，返回系统账户管理所需完整摘要。
- `GET /api/system-teams`：仅管理员可用，返回全部系统团队和成员，用于系统团队管理。
- `GET /api/my-teams`：所有登录用户可用，返回当前用户加入的团队和成员，用于 `我的团队` 只读页面；停用团队仍返回状态供页面展示，但不代表团队授权继续生效。
- `GET /api/my-authorization-options/grantee-accounts`：所有登录用户可用，只返回授权对象选择所需的 `id`、`username`、`displayName`、`status`，不得返回角色、改密状态、最后登录时间等系统账户管理字段。
- `GET /api/authorization-options/grantee-accounts`：仅管理员管理侧使用，返回管理授权时需要的系统账户摘要。

## 审计日志接口

第一阶段审计日志接口仅允许 `admin` 访问，普通用户即使是请求调用方也不能读取完整原文。

建议接口：

- `GET /api/audit-logs`：分页查询审计日志元数据，支持时间、系统账户、API Key、分组、账号、接口、模型、状态码、结果和 trace ID 筛选。
- `GET /api/audit-logs/:id`：查看审计详情、上游尝试列表和 payload 摘要。
- `GET /api/audit-logs/:id/payloads/:payloadId`：按需读取某段原始 payload。
- `GET /api/audit-logs/runtime`：查看审计队列长度、队列字节数、最近落库时间、最近错误和丢弃计数。

契约要求：

- 列表接口只返回元数据，不返回完整 headers 或 body。
- payload 读取接口必须重新校验管理员权限，不能只依赖详情页已加载。
- payload 响应可以返回文本、JSON 或二进制摘要；前端无法安全解码时展示大小、hash 和十六进制预览。
- 审计日志写入不通过管理 API 直接发生；网关只终态入队，后台批量落库。
- 审计日志接口错误提示使用中文；错误详情不能再把完整 payload 打回普通错误响应。

## 日志搜索接口

日志搜索接口仅允许 `admin` 访问，不读取原始审计 payload。索引查询读取普通运行日志的 SQLite 索引；`grep 模式` 直接扫描后端日志目录中当前保留的 `.log` 文件。

建议接口：

- `GET /api/runtime-logs`：分页查询最近 3 天运行日志，支持 `page`、`pageSize`、`traceId`、`level`、`event`、`keyword`、`startedAt` 和 `endedAt`，默认返回最近 100 条。
- `GET /api/runtime-logs/facets`：读取最近 3 天索引范围、级别分布、事件和索引队列运行态。
- `GET /api/runtime-logs/grep`：在后端普通日志目录内按关键字搜索当前保留的全部 `.log` 文件，支持 `keywords` 或重复 `keyword` 参数，最多返回 100 行匹配。

契约要求：

- 响应只返回有限条数，后端限制 `limit` 上限，避免把日志搜索变成全量导出。
- 索引查询中，`traceId`、级别、事件和时间范围必须走索引字段；关键字走 FTS5 `runtime_log_search`。
- 运行日志搜索索引固定保留 3 天，超过 3 天返回空结果或只返回仍在索引范围内的结果。
- `grep 模式` 后端仍返回文件名、完整文件路径、倒数行位置和匹配行，前端列表与索引查询使用同一组运行日志展示字段；文件和位置只放在详情里。后端固定在日志目录内按日志文件更新时间从近到远枚举当前保留的全部 `.log` 文件，同一文件内必须从文件末尾向开头搜索并按倒数位置展示，不接收路径参数，不支持多条件筛选，不设置查询超时。
- 全平台如果缺少 `rg`，`grep 模式` 必须返回安装提示而不是退化为慢速扫描；不能回退到系统 `grep` 造成不同部署平台行为不一致。

## 新增接口检查清单

- 是否明确属于 `/api/my-*` 用户接口、`/api/*` 管理接口还是 `/v1/*` 网关接口？
- 是否明确登录态、管理员权限、资源所有者权限或授权使用权？
- 是否使用统一成功和错误响应结构？
- 是否需要 `permissions` 摘要？
- 是否做后端参数校验、排序白名单和系统账户隔离？
- 是否会返回或记录敏感字段？如会，是否符合 [安全与日志策略](安全与日志策略.md)？
- 是否需要同步前端类型、功能设计、SQLite 文档、开发验证或部署文档？
