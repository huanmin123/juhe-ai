# 接口契约与权限矩阵

> 面向前端、后端与 AI 维护者。
> 本文统一管理后台 `/api/*`、网关 `/v1/*`、响应结构、分页筛选、错误语义和核心权限矩阵，避免接口口径散落在页面、路由和计划文档里。

## 文档目标

- 固定前后端对接口返回、错误、分页、筛选和权限摘要的共同理解。
- 明确 `admin`、普通 `user`、资源所有者和被授权用户在各模块里的操作边界。
- 给新增接口提供默认契约，减少每个路由自行设计返回结构。
- 只记录稳定契约，不替代具体功能字段说明；业务字段仍以 [核心功能设计](核心功能设计.md) 和 [SQLite 存储说明](SQLite存储说明.md) 为准。

## 接口分层

| 接口层 | 路径 | 身份来源 | 返回风格 | 说明 |
| --- | --- | --- | --- | --- |
| 管理 API | `/api/*` | 后台登录态 Cookie | 项目管理 API 结构 | 前端管理页面使用，默认需要 `requireAuth`，管理员接口叠加 `requireAdmin`。 |
| 公开 API | `/api/health`、公开品牌设置、登录和验证码 | 无登录态或登录流程 | 项目管理 API 结构 | 只暴露健康检查、未登录所需品牌信息、登录验证码和登录接口。 |
| 网关 API | `/v1/*` | 本地网关 API Key | OpenAI 兼容结构 | 面向 OpenAI 兼容客户端，不使用后台登录态，不返回管理 API 包装。 |

## 管理 API 响应

当前实现已使用 `backend/src/shared/http.ts` 的 `ok(data, message?)` 和 `badRequest(message)` 作为基础约定。后续新增接口优先沿用以下结构。

成功响应：

```json
{
  "data": {},
  "message": "可选中文提示"
}
```

错误响应：

```json
{
  "message": "中文错误提示",
  "code": "可选稳定错误码",
  "details": {}
}
```

约定：

- 成功响应必须包含 `data`；没有业务返回值时可返回 `{ "data": { "ok": true } }`，删除接口也可以使用 `204 No Content`。
- `message` 面向前端直接展示，默认使用中文；后端内部日志可以保留更详细英文或上游错误摘要。
- 现有部分错误只返回 `{ "message": "..." }`，这是当前兼容形态；新增复杂错误建议补稳定 `code`。
- `details` 只放字段级校验摘要、可安全展示的限制原因或操作上下文，不放敏感凭据、完整请求体、完整上游响应或 token。
- 前端不能通过 HTTP 状态码之外的字段自行推断权限，必须以接口返回和 `permissions` 摘要为准。

## HTTP 状态

| 状态码 | 使用场景 | 前端处理 |
| --- | --- | --- |
| `200` | 查询、更新、操作成功 | 读取 `data`，必要时展示 `message`。 |
| `201` | 创建成功 | 读取 `data`，创建 API Key 时注意明文只按约定展示。 |
| `204` | 删除或无返回内容操作成功 | 不读取 body，直接刷新列表或回到上级页面。 |
| `400` | 参数格式错误、业务输入不合法 | 展示 `message`，表单场景尽量定位字段。 |
| `401` | 未登录、会话过期、网关密钥缺失或无效 | 后台跳转登录；网关返回 OpenAI 兼容错误。 |
| `403` | 已登录但无权限 | 展示无权限提示，不自动重试。 |
| `404` | 资源不存在或当前用户不可见 | 展示不存在或已失效，避免暴露其他用户资源是否存在。 |
| `409` | 唯一约束、重复授权、重复凭据等冲突 | 展示冲突原因，引导用户更换输入或收回旧关系。 |
| `429` | 登录限频、上游限流或账号冷却 | 展示冷却或稍后重试信息。 |
| `500` | 未知服务端错误 | 展示通用错误，详细信息只进入安全日志。 |
| `502` | 上游 OAuth、上游模型或代理请求失败 | 展示上游请求失败摘要，避免暴露完整上游敏感响应。 |

## 列表、筛选与分页

第一阶段列表数据量较小，部分接口可先返回数组。新增高增长列表应使用统一分页结构。

推荐列表结构：

```json
{
  "data": {
    "items": [],
    "page": 1,
    "pageSize": 20,
    "total": 0
  }
}
```

约定：

- 查询参数使用 `page`、`pageSize`、`keyword`、`status`、`providerCode`、`systemAccountId`、`sortField`、`sortOrder` 等稳定名称。
- 普通用户传入 `systemAccountId` 应被忽略；只有管理员可以使用系统账户筛选。
- 排序字段必须后端白名单校验，不把任意字段名拼入 SQL。
- 使用记录、统计明细、授权用量这类持续增长数据必须优先支持后端分页或有限窗口查询。
- 前端表格分页、空态、错误态和加载态必须保持中文体验。

## 权限摘要

资源列表中如果同一接口同时返回自有资源和授权资源，应返回 `accessType` 与 `permissions`，前端据此控制操作入口，后端仍在每个写接口重新校验。

推荐字段：

```json
{
  "accessType": "owner",
  "ownerSystemAccountId": "sa_xxx",
  "ownerDisplayName": "用户名称",
  "authorizationId": null,
  "permissions": {
    "canUse": true,
    "canEdit": true,
    "canDelete": true,
    "canAuthorize": true,
    "canViewCredentials": true,
    "canManageMembers": true,
    "canBindToApiKey": true
  }
}
```

命名约定：

- 后端和前端类型优先使用 camelCase；数据库字段继续使用 snake_case。
- `accessType` 可取 `owner`、`authorized`、`admin_view`。
- 管理员查看他人资源时不改变资源所有者；必要时使用 `admin_view` 表示管理员视角。
- 授权资源必须返回所有者摘要，但不能返回完整凭据、代理密码或不可展示配置。

## 权限矩阵

| 模块 / 操作 | admin | user 自有资源 | user 被授权资源 |
| --- | --- | --- | --- |
| 系统账户列表 | 可查看和管理全部 | 不可查看系统账户管理页 | 不适用 |
| 修改自己密码 | 可修改自己 | 可修改自己 | 不适用 |
| 全局品牌设置 | 可查看和修改 | 可查看 | 可查看 |
| 供应商管理 | 可查看和维护 | 不可见 | 不可见 |
| 代理管理 | 可查看和维护 | 不可见 | 不可见 |
| AI 账户查看 | 可查看全部并显示归属 | 可查看自有账户 | 可查看授权账户摘要 |
| AI 账户创建 | 可为当前作用域创建，默认归属自己或筛选账户 | 可创建自有账户 | 不可基于授权账户创建新凭据 |
| AI 账户编辑 | 可按管理权限编辑 | 可编辑自有账户 | 不可编辑 |
| AI 账户删除 | 可按管理权限删除 | 可删除自有账户 | 不可删除 |
| AI 账户凭据查看 | 可按管理权限查看 | 可查看自有完整凭据 | 不可查看完整凭据 |
| AI 账户测试 | 可按管理权限测试 | 可测试自有账户 | 默认不可测试；如保留必须按使用动作记录 |
| AI 账户授权管理 | 可协助查看或管理 | 可授权自有账户、收回授权、看聚合用量 | 不可继续转授权 |
| 分组查看 | 可查看全部并显示归属 | 可查看自有分组 | 可查看授权分组摘要 |
| 分组创建 / 编辑 / 删除 | 可按管理权限操作 | 可管理自有分组 | 不可管理 |
| 分组账户管理 | 可按管理权限操作 | 可增删自有可用账户和授权账户使用关系 | 不可修改授权分组成员 |
| 分组授权管理 | 可协助查看或管理 | 可授权自有分组、收回授权、看聚合用量 | 不可继续转授权 |
| API Key 查看 | 可查看全部并显示归属 | 可查看自有 API Key | 不可查看他人 API Key |
| API Key 创建 / 编辑 / 删除 | 可按管理权限操作 | 可绑定自有分组或授权给自己的分组 | 只能通过自己的 API Key 使用授权分组 |
| 使用记录明细 | 可查看全部，显示系统账户列 | 可查看自己的调用明细 | 只能看自己的调用明细 |
| 授权资源用量聚合 | 可查看管理所需聚合 | 资源所有者可看授权对象聚合用量 | 不能看资源所有者或其他被授权人的明细 |
| 统计概览 | 可查看全局和系统维度 | 可查看自己的业务统计 | 只能体现在自己的调用统计里 |
| 系统设置 | 可查看和修改自己的设置，必要时可管理用户数据 | 可查看和修改自己的设置 | 不适用 |

## 网关权限

- `/v1/*` 不读取后台登录态，只读取 `Authorization: Bearer <本地网关 API Key>`。
- API Key 的所有者就是本次调用方系统账户。
- API Key 只能绑定一个自有分组或一个授权给自己的分组。
- 网关调度时必须重新校验 API Key 状态、分组可见性、授权有效性、账户状态、账户到期、账号冷却、代理和错误策略。
- 使用授权账户或授权分组时，使用记录必须同时冗余调用方、账户所有者、分组所有者和授权关系，便于调用方明细与资源所有者聚合分开统计。
- 网关返回给客户端的错误保持 OpenAI 兼容结构，不使用管理 API 的 `{ data, message }` 包装。

## 新增接口检查清单

- 是否明确属于 `/api/*` 管理接口还是 `/v1/*` 网关接口？
- 是否明确登录态、管理员权限、资源所有者权限或授权使用权？
- 是否使用统一成功和错误响应结构？
- 是否需要 `permissions` 摘要？
- 是否做后端参数校验、排序白名单和系统账户隔离？
- 是否会返回或记录敏感字段？如会，是否符合 [安全与日志策略](安全与日志策略.md)？
- 是否需要同步前端类型、功能设计、SQLite 文档、开发验证或部署文档？
