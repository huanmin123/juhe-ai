# AI 问答会话账户唯一绑定设计

- 状态：已实施（2026-09-28；阶段 1/2/3 提交 4a5309674 / 195b1cbb6 / 前端改造）
- 日期：2026-09-28
- 关联：《AI 问答设计》5.2（会话绑定规则）、《AI 问答工具体系与主子模型设计》6.3（工具绑定候选作用域，本设计将修订其口径）
- 验证记录（2026-09-28）：免请求体创建 + 免弹窗直进、PATCH accountId 绑定/切换（lastModel 不可路由联动清空）、归档会话发送/切账户/工具绑定 403 + 详情只读展示、非候选工具绑定 400 候选返回、迁移命令 SQLite 预演（归档 3/备份 5/删列/表重建/幂等/回滚精确还原/回滚后重迁移循环安全）与 dev PostgreSQL 库真实迁移（ensure-schema 623 语句 → 0 行迁移 → 幂等复跑 alreadyMigrated）全通过。生产发布序列见《部署指南》与运维手册：先 `--ensure-schema`，再 `--migrate-chat-account-only-binding`（幂等可重入，报告含 rollbackSql）。

## 1. 背景与动机

现状：创建会话支持三种绑定模式（`api_key` / `group` / `account`），经新建弹窗选择。实际使用结论（用户裁决）：**最佳方式是直接选择账户**——分组/Key 模式徒增复杂度，且用户场景以「测试某个账户是否好用」为主。

改造：会话**只支持账户绑定**；新建会话**免弹窗直接进入**，进入后先选账户 → 再选模型与参数 → 才能发送。

## 2. 已确认决策

1. 会话绑定模式收敛为**仅 `account`**；`group` / `api_key` 会话模式整体退场（代码与数据不留双轨）。
2. 新建会话免弹窗：点击新建即进入空会话；会话内完成「选账户 → 选模型与参数 → 发送」的顺序流程，未选账户前不能发送。
3. 工具子代理绑定候选的作用域放宽为**用户授权范围内的全部可派发账户**（不限于会话绑定的账户）——否则「grok 对话会话 + gpt 生图工具」这类跨账户组合无法成立。
4. 不做向后兼容（延续工具体系设计的同一裁决）：生产发布即切换，直接处理存量数据；**遗留列一并删除**（DROP COLUMN），不停用不保留，风险按第 10 节识别与对策执行。
5. 会话鉴权主体不变：仍是自动创建/复用的 chat 专用 Key（`EnsureChatAPIKey`），仅绑定模式收敛。供应时机（2026-10-07 默认资源收口）：chat 专用 Key 不再随账户创建预置，改为真正新建 AI 对话会话时由 `EnsureChatAPIKey` 幂等补建；默认 GPT 分组/默认 GPT 路由缺失时该链自愈重建后再补建。

## 3. 非目标

- 不改动 `/v1` 网关的 API Key/路由策略/分组能力（那是外部 API 的路由体系，与 AI 对话解耦）。
- 不支持一个会话多账户轮询（主模型就是绑定的这一个账户上的一个模型）。
- 不改动账户管理面本身。

## 4. 数据模型

- `chat_conversations` 列变更（**删列，不留停用列**）：
  - 新增 `archived INTEGER NOT NULL DEFAULT 0`——存量旧模式会话的归档标记（1 = 只读归档）。
  - **删除列**：`bind_mode`、`bind_group_id`、`bind_group_name_snapshot`（读取投影与扫描结构体同步删除，全链不留引用）。
  - 保留列：`bind_account_id` / `bind_account_name_snapshot`（会话唯一绑定载体）、`api_key_id`（chat 专用 Key 鉴权主体，语义不变）。
- 新建会话即建行：`bind_account_id` 允许 NULL（「未选账户」状态），选定账户后 PATCH 写入；未选账户的会话不可发送（发送预检 400 `chat_account_required`）。
- 工具绑定三列（`search_account_id`/`search_model_id`/`image_account_id`，见工具体系设计第 7 节）照常。
- schema 执行方式：`maintenance` 新增一次性迁移命令（如 `--migrate-chat-account-only-binding`），幂等可重放：① `bind_mode IS NULL OR bind_mode != 'account'` 的行置 `archived=1`；② 备份将删三列数据到副表；③ 双方言 `DROP COLUMN`（SQLite 3.35+ / PostgreSQL 均支持）。dev 库按生命周期手册同命令处理。

## 5. API 契约变更

1. `POST /my-chat/conversations`：不再需要请求体（免弹窗直进，创建空会话即返回）；兼容忽略历史字段。
2. `GET /my-chat/conversation-bind-options` **退场**，由新端点替代：
   - `GET /my-chat/accounts`：用户授权范围内全部可派发账户（id、名称、供应商、状态），供会话绑定与工具绑定统一使用。
3. `GET /my-chat/conversations/{id}/models`：候选 = **会话绑定账户**可路由的模型（含能力标注：协议、`inputModalities`、`supportedToolsByProtocol` 摘要），未绑定账户返回空列表。
4. `PATCH /my-chat/conversations/{id}`：`accountId` 键写入/切换绑定账户；切换账户时若已选模型不在新账户可路由范围，联动清空模型选择并提示重选；工具绑定不联动（跨账户合法）。
5. 发送预检：未绑定账户 → 400 `chat_account_required`；绑定账户不可派发/停用 → 400 提示重选。

## 6. 免弹窗交互流

```
点击「新建会话」→ 立即进入空会话
状态 A（未选账户）：输入区禁用，顶部引导「选择 AI 账户开始对话」（账户下拉=用户全部账户）
状态 B（已选账户，未选模型）：默认选中该账户可路由模型列表首个，模型/参数选择器可用
状态 C（可发送）：账户+模型就绪，参数按模型能力显示（reasoning effort 等）
工具绑定（搜索/生图）：会话设置面板，候选=用户全部账户 × 能力白名单（跨账户合法，如 grok 会话 + gpt 生图）
```

- 会话列表：未选账户的空会话显示「未配置」标记，可删除。
- 切换账户视为新语境：保留消息历史，模型选择联动重置（历史消息只读保留）。

## 7. 工具绑定候选作用域修订（对工具体系设计 6.3 的修订）

- 原口径「候选范围 = 会话同一授权作用域」修订为：**候选范围 = 用户授权范围内的全部可派发账户 × 已实现执行器能力白名单 × 模型目录能力声明**。
- 理由：会话绑定收敛为单账户后，若工具候选仍限会话作用域，「非 GPT 账户会话 + GPT 生图工具」「非搜索模型会话 + 搜索工具」均无法成立，违背主子解耦的初衷。
- 权限边界：工具子调用仍经 chat 专用 Key 的 `/v1` 链派发，账户可见性以用户授权为准，不越权。

## 8. 存量会话处理（生产直接切换）

- 存量 `api_key` / `group` 模式会话：一次性迁移置 `archived=1` **归档为只读**——会话列表保留可见、历史消息可读，发送入口禁用并提示「该会话绑定方式已升级，请新建会话」。不做原地迁移（无法推断应绑定哪个账户），不删除会话与消息数据。
- 存量 `account` 模式会话：行为不变，直接兼容为新体系（`archived=0`）。
- 归档判定读取 `archived` 列（不依赖已删的 `bind_mode`）；归档会话的会话级删除照常可用。

## 9. 删除项清单

1. `group` / `api_key` 绑定模式的全部代码路径：`resolveChatBindingScope` 收敛为单一路径、bind-options 旧端点、新建弹窗（前端组件）、三种模式的预检分叉与对应测试。
2. 列依赖同步删除：`conversationRow` 扫描结构体、`conversationColumns` 常量、全部会话 SQL、REST 投影、前端会话类型与 IndexedDB 缓存形状中的 `bindMode` / `bindGroupId` / `bindGroupNameSnapshot` 字段（扫描结构与 SQL 若漏改，列删除后查询直接报错——BUG-0219 同型事故面，逐处核对）。
3. `conversationBindOptions` 端点及其响应形状。
4. 前端新建会话弹窗组件与相关状态。
5. 《AI 问答设计》5.2 同步改写并指向本文档。

## 10. 删列风险识别与对策

| 风险 | 识别 | 对策 |

## 11. 验收标准（可观察行为）

1. 新建会话零弹窗直接进入；未选账户不能发送（明确错误与引导）。
2. 选账户后模型列表 = 该账户可路由模型；切账户联动重置模型；发送请求固定派发到绑定账户。
3. 会话绑 grok 对话账户 + 工具绑 gpt 生图账户：生图正常；会话绑 gpt 对话账户 + 搜索绑任一含搜索模型账户：搜索正常。
4. 存量 group/api_key 会话只读可见、不可发送；存量 account 会话行为不变。
5. 删除项全部落地：代码中不再存在三种绑定模式分叉与新建弹窗。
