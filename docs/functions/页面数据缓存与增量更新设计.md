# 页面数据缓存与增量更新设计

## 文档目标

本文定义管理后台页面数据的统一缓存、变更确认、字段增量更新和高频预热边界，解决页面反复进入时重复加载、静态列表反复查询数据库、动态字段整页刷新和高频用户冷启动等待问题。

执行跟踪见 [PLAN-0115 页面数据缓存与增量更新](../plans/计划-0115-页面数据缓存与增量更新.md)。AI 账户当前已上线的 30 秒动态快照继续以 [PLAN-0104 账户动态快照与私网 Base URL 白名单](../plans/计划-0104-账户动态快照与私网BaseURL白名单.md) 为现状基线，本设计复用并纳入统一协议，不重复建立第二套账户轮询。

## 已确认目标

- 页面优先展示浏览器缓存，避免每次进入页面都等待后端和数据库。
- 页面可见时每 `30 秒`执行一次轻量变更确认；页面隐藏时停止，恢复可见、窗口聚焦或路由重新激活时立即确认一次。
- 当前用户自己的新增、编辑、删除在写接口成功后立即更新当前页面和浏览器缓存，不等待下一轮确认。
- 其他会话产生的变化采用最终一致性：revision 成功发布后，当前可见页面正常最多再等待 30 秒确认；端到端可见时间还包含事实落库、队列 / 统计聚合、outbox 发布和网络延迟。
- 统一确认接口只读 Redis 或 standalone 内存 revision，不查询业务数据库。
- 变更确认后只获取发生变化的实体、字段、记录游标或统计区块；只有成员关系、筛选、排序、分页、权限或日志连续性受影响时才重取当前页。
- 本方案将在 `performance` 使用 Redis 保存 revision、变更日志、运行态和服务端投影，在当前 Node `standalone` 使用紧凑 SQLite outbox / dirty generation、内存 owner 与 IPC；两种模式暴露同一 HTTP 契约。
- Node / Go 共存期间使用同一协议、数据域和契约夹具；Go 长期目标只实现 PostgreSQL + Redis，不新增 SQLite / memory adapter。
- IndexedDB 允许直接保存 System API 已返回的数据，不做字段级敏感信息排除；仍按用户、视图、权限范围和查询签名隔离，避免不同页面缓存互相覆盖。
- 最近 `7 天`登录过的用户预热首页默认窗口和“我的 AI 账户”默认第一页，使高频入口优先命中服务端缓存。
- 最终覆盖全部页面，但按收益和风险分阶段落地；不要求所有页面都使用同一种增量算法。

## 不做什么

- 不使用固定 TTL 到期后无条件整页重查作为主要一致性方案。
- 不把任意筛选参数直接展开成无界 Redis revision key 或无界预热任务。
- 不让前端根据使用记录自行 `reduce` 生成业务统计；统计继续只读 worker 预聚合结果。
- 不在轻量确认接口、列表接口或缓存 miss 路径扫描明细表、实时 `SUM/GROUP BY` 或逐行补数。
- 不为本方案引入 Kafka、ClickHouse、WebSocket、SSE 广播或新的分布式协调系统。
- 不把 Redis / IndexedDB 视为业务事实源；这些缓存都可以丢弃和重建。
- 不让 Redis 故障触发全量数据库回源风暴。
- 不给 Go 增加 standalone 运行模式；SQLite + memory 只服务当前 Node 迁移期。

## 当前基线

### 2026-07-18 实现基线

- 前端已经具备 `pageDataCache`、IndexedDB 降级存储、规范化缓存键、跨标签协调、30 秒可见页确认和竞态保护；本轮已接入供应商 / 模型、账户、分组、策略路由、系统账户 / 团队、授权和统计的第一批资源。
- Node 已具备 `data-changes/confirm`、standalone 有界进程缓存、Redis store 和 page-data read-through cache；Go management API 已 opt-in 复用同一 v2 token、scope、Redis key 与单次 Lua confirm 协议，Redis 故障保持 `503 + Retry-After: 5` 且不回源业务库。当前页面接入仍只覆盖供应商、账户、分组、策略路由、系统账户 / 团队、授权和统计的有限选项 / 区块。
- 供应商模型目录已将 SQLite read worker 限定为 cache miss loader，并通过同 key singleflight、generation 和查询计数回归避免重复读取与迟到旧值回填。
- 前端页面响应已统一迁入 IndexedDB resource store；保留的短生命周期缓存只服务模型检测运行态、详情 / 偏好等不适合持久化的边界，不再用于上述静态下拉响应。

### 前端

- Vue 路由页面通过 `KeepAlive` 保留当前会话内的页面实例，页面查询状态通过 `usePageStateCache` 保存；现有能力不缓存完整接口结果。
- `useResponsivePagedList` 提供请求签名去重、过期响应丢弃和当前项更新，但筛选、分页、排序、重新进入和手动刷新仍会重新请求列表。
- 项目仍有详情、选择偏好和模型检测运行态的短时缓存；接口列表响应使用统一 IndexedDB resource store，并通过写成功后的 domain reset 和 30 秒 confirm 维持一致性。
- AI 账户当前已实现最多 100 个可见账户的 `30 秒 +/- 1 秒`动态快照，页面隐藏和卸载时停止，恢复可见和聚焦时立即刷新。

### 后端

- AI 账户完整列表仍由 Node 负责，读取主列表后还会补模型、映射、标签、用量、余额、并发和账户内 Key 运行态；其中部分字段最终不会进入列表响应，存在可收敛查询。
- AI 账户动态快照已经是字段投影接口，但当前仍会查询业务库和多组统计，尚未完全变成 Redis / 内存优先的运行态投影。
- 使用记录列表已经按用户和日期窗口读取，PostgreSQL 模式使用分区表，SQLite 模式使用 usage shard；前端目前仍按完整当前页重新请求。
- 统计接口只读 worker 预聚合窗口，天然适合按区块 revision 更新。
- 现有 Redis gateway cache invalidation 是失效主题，不是页面变更日志，不能直接替代本设计。

## 核心原则

### 就近读取顺序

可持久化的有界读请求统一遵守以下顺序：

1. 当前页面 / 模块内已确认的内存快照。
2. 当前用户、权限、视图、目标范围和完整查询签名隔离的 IndexedDB 快照。
3. 后端进程缓存或 Redis shared cache。
4. 业务数据库、统计预聚合表或 standalone SQLite read worker。

IndexedDB 快照仍在领域 `maxStaleMs` 内时立即展示并异步 confirm；超过直接展示上限时先阻塞执行一次轻量 confirm。confirm 报告 `unchanged` 时直接复用 IndexedDB，不调用完整业务接口；报告 `delta/reload/reset` 或 confirm 不可用时才访问对应领域接口。后端 cache miss 只允许有界回源，并对相同 key 合并并发请求。

### 模型目录与人工测试选项

- 普通供应商模型目录缓存键至少包含 `providerCode + systemAccountId scope + includeInactive + includeUnpriced`；聚合目录还必须包含协议过滤或来源供应商集合。不能只用供应商代码，因为个人自定义模型会随系统账户范围变化。
- 供应商内置模型和全局自定义模型可以在相同供应商全局 scope 内共享；个人自定义模型只能在对应系统账户 scope 内共享。
- 人工测试模型不是纯供应商列表。`test-options` 还依赖账户配置 revision、协议档案、支持模型、模型映射、检查模型和可测试请求形态，因此前端缓存键继续包含账户 ID 与 `configRevision`，其目录构建部分复用供应商模型缓存。
- 内置模型配置、自定义模型新增 / 更新 / 删除、模型价格 / 能力目标变化后，必须同时推进 `providers.catalog` revision，并失效后端模型目录、前端供应商模型和账户人工测试选项缓存；失效发生在事实提交之后。
- 人工测试运行失败、测试选项加载失败和后台测试进度恢复失败都只写入测试弹窗内的终端结果，不再额外触发全局错误 / warning toast；成功和用户主动停止提示保留。

### 下拉与统计缓存分类

- 可持久化：供应商 / 模型、账户轻量选项、分组、策略路由、系统账户与团队的轻量候选、授权候选，以及 worker 已提交的首页 / 用量 / 性能统计区块。
- 只保存接口已经返回的有界 DTO；搜索关键字、分页、排序、目标系统账户和用户 / 管理视图必须进入完整查询签名。
- 只保留会话或内存：代理候选、包含运行态的高频选项、模型检测运行态、IP / 系统指标等短窗口数据。
- 不缓存：captcha、`auth.me`、写 / 导入 / 导出 / 测试命令、运行中的人工测试和模型检测任务、代理凭据、API Key 明文、OAuth token、审计 / 运行日志正文和无界搜索结果。
- 统计缓存只保存 worker 预聚合区块，前端和请求路径不得从明细或缓存桶重新汇总。

### 事实与投影

- PostgreSQL / SQLite 业务表、使用记录、日志索引和统计预聚合表是持久事实源。
- Redis、standalone 内存和 IndexedDB 是可丢弃投影，不承担事实恢复责任。
- 页面使用 stale-while-revalidate：先展示缓存，再确认 revision；确认失败时保留旧数据，不伪造“已是最新”。
- 缓存命中只改变读取成本，不改变权限、统计口径、调度状态或写入事务语义。

### 精细更新与整页重取

只有同时满足以下条件时，前端才原位 patch：

- 变更实体仍属于当前页面查询结果。
- 变化字段不参与当前筛选或排序。
- 变更不改变授权、所有权、分组绑定或其他成员关系。
- 变更不改变当前页记录数、分页归属或稳定排序兜底键。
- revision 日志连续且协议版本可识别。

出现以下任一情况时，重取当前页而不是猜测：

- 新增、删除或 tombstone。
- 排序字段、筛选字段、权限范围、所属用户、授权关系或分组绑定变化。
- `membershipChanged`、`orderChanged`、`filterChanged` 或 `pageChanged` 为 true。
- epoch 变化、revision cursor 过期、变更日志被裁剪、收到未知字段版本或 `resetRequired`。
- 高增长列表发生保留期清理、分区删除、日志轮转或索引水位重置。

## 总体架构

### 前端页面数据协调器

新增统一前端协调层，职责如下：

- 规范化当前用户、用户 / 管理视图、目标系统账户、路由、数据域和查询参数，生成稳定缓存键。
- 从 IndexedDB 读取仍在 `maxStaleMs` 内的缓存并立即交给页面，随后异步执行轻量变更确认；超过上限的缓存必须先确认，`unchanged` 后原样复用，不得无条件重取完整接口。
- 只为当前可见页面订阅需要的数据域；KeepAlive 隐藏页只标记 dirty，不持续轮询。
- 根据确认结果调用已有字段快照、领域 delta、记录 cursor 或统计区块接口。
- 按 sequence 和页面 request revision 拒绝迟到、乱序、旧作用域和已卸载响应。
- 写接口成功后由当前业务页面处理响应值，同时删除受影响的 IndexedDB domain；下一次读取先命中后端缓存，只有前后端缓存都 miss 才回事实库。
- 使用 `BroadcastChannel` 在多标签页之间选举单个确认 leader；只广播 token、按键 / 按域失效和实体 ID 等有界元数据，具体 DTO 先写 IndexedDB，再由其他标签读取。写入标签即使没有实例化目标资源 key，也必须广播 domain 失效。浏览器不支持时退化为各标签独立确认，不影响正确性。

### 统一变更确认接口

建议新增：

```http
POST /__aisys__/api/data-changes/confirm
```

请求只携带当前页面关心的数据域和已持有 token：

```json
{
  "viewScope": "self",
  "targetSystemAccountId": null,
  "domains": {
    "accounts.static": {
      "protocolVersion": 1,
      "epoch": "01J...",
      "sequence": 128
    },
    "accounts.runtime": {
      "protocolVersion": 1,
      "epoch": "01J...",
      "sequence": 912
    }
  }
}
```

响应说明每个域应保持、增量、重取当前页还是整域重置：

```json
{
  "serverTime": "2026-07-16T12:00:00.000Z",
  "domains": {
    "accounts.static": {
      "action": "unchanged",
      "token": {
        "protocolVersion": 1,
        "epoch": "01J...",
        "sequence": 128
      }
    },
    "accounts.runtime": {
      "action": "delta",
      "token": {
        "protocolVersion": 1,
        "epoch": "01J...",
        "sequence": 915
      },
      "changes": [
        {
          "entityId": "acc_a",
          "fieldMask": ["status"]
        },
        {
          "entityId": "acc_b",
          "fieldMask": ["currentConcurrency"]
        }
      ]
    }
  }
}
```

约束：

- confirm 路径的业务数据库查询次数必须为 `0`。
- 服务端根据认证上下文计算 scope，不能信任前端自报的用户身份或权限。
- 单次最多确认 `32` 个数据域，请求体和响应体都必须有界；超过范围返回 400。
- 单域变化项和 confirm 总响应都有数量与字节上限；超过上限返回 `reload`，不能为了坚持字段增量返回无界实体数组。
- 未变化域不返回实体列表或字段正文。
- confirm 不承载具体业务 DTO，避免演变成第二个全量聚合接口。
- `performance` 下 Redis 不可用时返回轻量 `503` 和 `Retry-After`，不得回源业务数据库。

### 领域增量接口

确认接口统一，但数据读取继续使用强类型领域接口：

- AI 账户运行态复用现有 `status-snapshot`，逐步改为 Redis / memory projection 优先。
- 静态列表提供按实体 ID 的 `upsert/delete + changedFields` 增量读取；必要时直接重取当前页。
- 使用记录和日志使用 `(createdAt, id)` cursor 拉取新增记录；详情继续按 ID 独立缓存。
- 统计继续调用现有区块接口，只拉取变化的 summary、trend、TopN、error、model、cost 等区块。
- 设置和详情按对象 revision 精确失效，返回完整对象或明确 tombstone。

不建立一个返回任意领域任意 DTO 的“万能 delta”接口，避免类型、权限和分页语义失控。

### 变更发布与投影构建

持久变更和运行态变更分两类处理：

1. 持久变更：业务 CRUD、授权、绑定、使用记录落库、日志索引落库、统计窗口提交和保留清理在事实真正提交后发布。
2. 运行态变更：并发、账户运行状态、余额快照、网关可用性等直接更新运行态投影和 revision。

持久写入要求：

- PostgreSQL 模式在原业务事务内写入有界 outbox，提交后由 worker 至少一次发布到 Redis；发布失败可重试，不能永久漏 revision。
- 使用记录和日志只能在 ingest worker 真正落库后发布，不能在 Redis Stream 入队时提前发布。
- 统计只能在 worker 完成预聚合窗口提交后发布，不能由前端或 API 请求推测。
- Node / Go writer 共用事件 schema、幂等 `eventId` 和契约夹具。
- 运行态投影值与对应 revision 必须在同一个 state Redis Lua 操作内更新，防止先看到新 revision 却读到旧字段。

standalone 约束：

- revision owner 固定在 DB service；server、ingest-worker、stats-worker 和 ops-worker 通过有界 IPC 提醒 owner 消费变更。
- 业务库、数据集目录库、使用记录目录库和统计结果库的实际写 owner，在同一事实提交事务中按批写入紧凑 `page_data_change_outbox` 或等价 dirty generation；usage / 日志按落库批次写一条，不按明细逐条写。
- IPC 只负责加速通知。IPC 发送失败或未确认时，持久 outbox 仍保留并由 owner 按游标重放；无法证明连续时更换对应域 generation 并返回 `resetRequired`，不能继续返回 unchanged。
- DB service 重启生成新的 standalone owner epoch，重放各 owner 的未确认 outbox 后再对外返回稳定 revision；前端发现 epoch 变化后整域重新确认和回填。
- worker 不能只更新自己的 Map 后假设 API 进程可见。

## Revision 与事件契约

### Revision token

禁止只使用单个递增整数或 `MAX(updated_at)`。统一 token 至少包含：

```ts
interface PageDataRevisionToken {
  protocolVersion: number
  epoch: string
  scope: string
  domain: string
  sequence: number
}
```

- `protocolVersion`：事件和 field mask 契约版本。
- `epoch`：部署 / Redis namespace 的共享世代；performance 所有 Node / Go 实例读取同一个 epoch，不能按进程身份生成。standalone 由唯一 DB service owner 维护进程 epoch。
- `scope`：后端实例、当前用户 / 管理范围、目标系统账户和权限指纹的服务端摘要。
- `domain`：稳定有限的数据域，不包含任意查询参数。
- `sequence`：当前 epoch、scope、domain 内单调递增。

scope 只作为不透明摘要返回，不能暴露全局写入速率或其他用户活动。

### 变更事件

```ts
interface PageDataChangeEvent {
  protocolVersion: number
  eventId: string
  domain: string
  entityType: string
  entityId?: string
  operation: 'upsert' | 'delete' | 'append' | 'range_reset' | 'window_replace'
  fieldMask: string[]
  scopeSelectors: Array<{
    type: 'global' | 'owner' | 'team' | 'system_account'
    id?: string
  }>
  membershipChanged: boolean
  orderChanged: boolean
  filterChanged: boolean
  pageChanged: boolean
  occurredAt: string
}
```

规则：

- `fieldMask` 使用版本化枚举；未知字段或未知版本必须返回 `resetRequired`。
- 单事件最多 8 个有限 scope selector，禁止枚举所有受影响用户；大范围影响使用 `global` / `team` selector 或域级 reset sentinel。
- 单事件序列化后最大 4 KiB；超过上限发布域级 reset，不把大 DTO 或无限 ID 列表写入 state Redis。
- 删除必须发布 tombstone，不能只删除缓存 key。
- outbox 和 Redis consumer 按 `eventId` 幂等，允许至少一次投递。
- 高频使用记录按落库批次发布 cursor 范围和数量，不为每条记录生成独立 Redis 事件。
- 保留期清理、整日分区删除、日志轮转和大范围重建发布 `range_reset`，不逐行发布 tombstone。
- Redis 变更日志同时按条数和时间裁剪；客户端 cursor 早于最老事件时返回 `resetRequired`。
- state Redis 还必须限制每域总日志字节、活跃 scope key 数和 namespace 总预算；接近预算时优先合并批事件或发布 reset，不能继续在 `noeviction` 实例无界增长。

## 数据域矩阵

## 关键页面行为

### 页面首次打开

1. 恢复页面筛选、分页和排序状态。
2. 使用完整规范化查询签名读取 IndexedDB。
3. 命中后立即渲染，不显示阻塞式全页 loading。
4. 页面可见时立即调用 confirm。
5. unchanged 时结束；delta 时只取变化；reload 时重取当前页；reset 时删除当前域缓存并重建。
6. 新响应只有在用户、视图、目标范围、查询签名和页面 revision 仍匹配时才能提交。

### 当前用户写操作

- 写接口继续返回最新实体或明确删除结果，并可返回 `mutationId/eventId`；revision token 只允许由 confirm 推进，不能在 outbox 尚未发布时用写响应提前跳过 sequence。
- 前端立即更新当前行和当前列表，同时对受影响域递增 O(1) 本地 dirty generation；同域其他筛选、分页和排序缓存不逐条扫描，下一次进入时必须先 confirm，成员关系不确定时直接 reload。
- 如果写入改变当前筛选、排序、成员资格或分页，写成功后重取当前页。
- 不为了单行启停、恢复、标签、优先级等操作无条件刷新整张列表。

### AI 账户

- P0 协调器上线前继续沿用 PLAN-0104 的独立 `30 秒 +/- 1 秒`递归刷新。协调器上线后关闭原独立 timer，由唯一 30 秒 tick 先 confirm；只有 `accounts.runtime` 变化时才请求现有状态快照，只有 `accounts.balance` 变化时才请求余额投影，二者不得合并成无条件双请求。
- 唯一 tick 仍保持最多 100 个当前账户、隐藏页停止、聚焦 / 恢复可见时 debounce 后立即确认和复用 in-flight，不能在生命周期触发时叠加第二个请求。
- 第一阶段先把 status snapshot 的持久字段、并发、今日用量和最近使用时间改为投影优先，避免每 30 秒重复访问业务库和多组统计表。
- 状态、并发、今日用量、最近使用时间和余额使用独立 revision / field mask，未变化字段不返回。
- 账户配置、标签、分组绑定和授权变化归 `accounts.static`，不能混入高频 runtime revision。

### 使用记录与日志

- 只有第一页、`createdAt desc` 且新记录确定满足当前筛选时，前端才直接 prepend。
- 其他页或无法证明满足筛选时，页面记录“有新数据”状态并在用户返回第一页或下一次重载时获取，不在中间页强行插入。
- 列表排序和翻页 cursor 使用稳定 `(createdAt, id)`；变更检测使用落库 sequence / outbox sequence，不能只用业务 `createdAt`，避免队列延迟落库的旧时间记录落在客户端水位之前。服务端按新增 ID 返回记录后，再按业务稳定排序合并。
- 使用记录、日志正文和 grep 结果不参与无界预热；只缓存已经请求的有界响应。

### 统计

- summary、trend、TopN、模型分布、错误分布、成本、延迟等分别维护 revision。
- revision 可以按稳定窗口和作用域细分，但不能按任意查询参数创建无界 key。
- 前端只替换后端已生成的区块，不从明细或已有区块重新汇总。
- 自定义范围仍先登记按需窗口，由 worker 生成；confirm 只能报告窗口是否完成或发生重建。

## 前端 IndexedDB 缓存

### 缓存键

缓存键至少包含：

- 缓存协议版本和共享 deployment epoch；performance 不按具体 Node / Go 进程生成 epoch。
- 当前登录系统账户 ID、角色 / 权限指纹。
- `self` / `admin` 视图和目标系统账户 ID。
- 路由、数据域、接口版本。
- 规范化后的完整查询参数、分页、排序、日期窗口和字段投影版本。

同一 Vue 文件复用到 `/my-*` 和管理路由时必须形成不同键。

### 保存范围

- 允许保存 System API 已返回的完整有界响应，不做字段级敏感信息排除。
- 页面查询状态和接口数据使用不同 object store，避免“重置筛选”误删所有数据缓存。
- 流式下载、导出文件、无界日志、未分页正文和超过单项上限的大响应不进入通用页面缓存。
- 写失败、结构校验失败和不完整响应不进入缓存。

### 容量默认值

- 每 origin 目标上限取 `min(256 MiB, StorageManager 可用 quota 的 20%)`；无法取得 quota 时使用 `64 MiB`。
- 单条通用响应上限 `8 MiB`，超过后只驻留内存，不持久化。
- 最多 `4,000` 个响应项，按最近访问 LRU 淘汰。
- 连续 `30 天`未访问的查询缓存可以清理；revision 失效、epoch 变化和协议升级优先清理对应域。
- 容量清理按小批执行，不在页面主线程一次扫描全部 IndexedDB。

这些限制用于控制磁盘、序列化和启动成本，不是字段安全限制。

## 服务端投影缓存

### Redis 分工

- `redis-state`：revision、epoch、运行态投影、确认日志水位和必要原子更新；使用 `noeviction`，key 数量必须有界。
- `redis-cache`：静态实体投影、规范化查询结果、默认页面和统计响应缓存；允许 LRU 淘汰。
- `redis-queue`：现有记录型可靠队列和 outbox 发布消费，不和 state/cache 共库。

不同 Redis 实例之间不假设原子事务。confirm 以 state Redis revision 为准；读取具体投影时发现 cache Redis key miss，按有界回填规则处理。

### 回填和击穿保护

- Redis 健康且投影 key miss 时，允许对当前实体 ID、当前页或已有预聚合窗口做一次有界数据库回填。
- 同一规范化 key 使用进程内 singleflight；performance 跨实例使用短租约分布式锁。
- 回填设置并发上限、请求预算和 TTL 抖动；等待者不同时访问数据库。
- Redis 不健康时禁止回源业务数据库，返回 `503 + Retry-After`，防止缓存故障转化为数据库故障。
- 请求路径禁止在回填时扫描使用记录、日志明细或统计桶。

### 建议生命周期

| 投影类型 | 建议有效期 / 刷新方式 |
| --- | --- |
| deployment epoch | 共享部署世代，不滚动过期；Redis namespace 重建或不兼容协议升级时更换 |
| per-scope revision | 活跃用户候选滚动续期 8 天；缺失或过期返回 reset |
| 静态实体投影 | 6 小时 TTL + 写后主动失效 / 更新 |
| 默认列表页 | 30 分钟 TTL + 写后 revision；预热周期内刷新 |
| AI 账户运行态 | 按字段事实源确定：并发跟随槽租约，调度状态跟随状态机 TTL，今日用量跟随统计窗口，余额跟随刷新计划；禁止统一使用 90 秒 TTL |
| 统计区块 | 跟随对应 worker 窗口提交，不单独拍脑袋刷新 |
| 变更日志 | 事件只保存一次并使用有限 scope selector；候选上限为每域 10,000 个批事件 / 24 小时，同时受总字节与 key 预算限制；超窗 reset |

实际默认值必须通过压测确认后写入配置；不能把 TTL 当作唯一一致性机制。

## 最近 7 天用户预热

### 目标

预热只解决高频用户默认入口冷启动，不尝试提前生成所有筛选组合。

P0 预热内容：

- 首页默认时间窗口所需的已预聚合区块。
- “我的 AI 账户”默认筛选、默认排序和默认第一页。
- 该页当前账户的运行态、并发、今日用量和最近使用时间投影。
- 公共设置和页面壳所需的小对象。

### 目标用户

- 使用 `system_accounts.last_login_at >= now - 7 days` 且账户状态允许登录的用户。
- 按 `last_login_at DESC, id` 使用 cursor 分批读取，不一次加载全部用户。
- 登录成功后立即把当前用户加入高优先级预热队列，不等待下一次周期扫描。

### 执行边界

- performance 由后台 worker 分批生成并写 Redis cache/state。
- Node standalone 由 DB service 作为内存投影 owner，其他 worker 通过 IPC 提交已生成的小投影或 dirty 信号；不得只预热 worker 自己的 Map。
- Go 只实现 PostgreSQL + Redis 预热，不实现 standalone 分支。
- 首轮候选参数为每 `5 分钟`扫描一次增量目标、每批最多 `200` 个用户、并发不高于 `8`、单轮硬上限 `10,000` 个用户；这些不是未经验证的生产默认值，必须先用目标数据规模压测再写入配置。
- 每轮还必须受数据库查询次数、读取行数、返回字节、总耗时和当前连接池 / worker 负载预算约束；任一预算触顶即保留 cursor 到下一轮。登录成功用户进入独立高优先级小队列，不能被全量追平任务长期阻塞。
- 预热失败采用有界退避，不影响事实写入和用户正常按需回填。

## 故障与恢复

### 前端确认失败

- 保留当前 IndexedDB / 内存数据，不清空页面，不弹出高频重复错误。
- 周期确认使用递归 timeout，当前请求完成后再安排下一轮，不允许请求重叠。
- 连续失败时保留页面刷新入口，并标记当前数据可能过期；恢复可见或网络恢复后立即重试一次。
- 失败响应不能推进 token，迟到响应不能覆盖较新 sequence。

### Epoch 变化

以下情况必须生成新 epoch：

- Redis state namespace 被清空或替换。
- standalone DB service 重启。
- revision / event / field mask 协议发生不兼容变化。
- 整个部署世代发生切换。

权限、角色、目标系统账户或授权范围变化只更换 scope fingerprint，不滚动 performance 全局 epoch；多实例 Node / Go 不能按进程身份各自生成 epoch。

前端发现 epoch 不同后删除对应域的 token 和响应缓存，执行当前页重建；不能把 sequence 从 0 开始的新实例误判为旧缓存未变化。

### 变更日志缺口

- cursor 早于最老事件、事件解码失败、field mask 未知或 outbox 水位不可证明连续时返回 `resetRequired`。
- `resetRequired` 只让受影响域重建，不默认清空全部 IndexedDB。
- 删除、分区清理、日志轮转和统计重建必须有明确 reset / tombstone 事件。

## Node / Go 迁移边界

- HTTP confirm 契约、revision token、事件 schema、field mask、scope 算法和测试夹具必须跨 Node / Go 一致。
- 当前仍由 Node owner 的完整 AI 账户列表、状态、使用记录和多数统计先在 Node 落地；Go 不提前复制未接管业务 writer。
- 已由 Go 接管的管理列表写接口必须发布同一事件，使 Node 读取端和前端能看到变更。
- performance 共存期通过同一 Redis namespace 和 PostgreSQL outbox 协调，不建立 Node / Go 双写业务事实。
- Go 长期只保留 PostgreSQL + Redis；Node 下线后删除 standalone memory / IPC adapter，不保留兼容分支。

## 分阶段落地

### P0：基础设施与最高收益页面

- revision / event / confirm 契约和 Node 双模式 adapter。
- 前端 IndexedDB 协调器、多标签 leader、30 秒可见页确认和写后立即 patch。
- AI 账户动态快照改为投影优先，复用 PLAN-0104。
- 首页默认窗口和“我的 AI 账户”最近 7 天用户预热。

### P1：高频用户业务

- 使用记录首页 cursor 增量。
- 我的用量、用量统计、AI 性能监控按区块更新。
- API Key、分组、策略路由、授权列表静态增量和当前页重取判定。

### P2：管理后台

- 系统账户、团队、供应商、代理、公告、外部来源、响应策略和设置。
- 授权团队 / 用户统计、系统指标、表监控、IP 统计等管理窗口。
- Go 已迁移 writer 接入统一事件发布。

### P3：低频和诊断页面

- 操作日志、公开接口日志、审计日志、运行日志和模型检测历史。
- 详情、facets 和默认时间窗缓存；任意 grep 不做预热。
- 全路由覆盖审计和遗漏域收口。

每个阶段都必须可独立启用、验证和回滚到“当前页重取”，但不保留旧 schema、旧 token 或旧事件协议兼容代码。

## 观测指标

至少记录：

- confirm QPS、p50 / p95 / p99、响应字节数和每次确认域数量。
- confirm 业务数据库查询次数，目标始终为 0。
- IndexedDB 首屏命中率、读取耗时、写入失败和淘汰数量。
- Redis 投影命中率、回填次数、singleflight 合并数、分布式锁等待和回填拒绝数。
- delta、当前页重取、整域 reset 的比例和原因。
- outbox 待发布数量、最老消息年龄、重复消费和日志裁剪 reset 数量。
- 预热目标用户数、成功率、跳过数、耗时、并发和缓存命中提升。
- 页面缓存渲染耗时、后台确认耗时、完整接口请求减少率和数据库查询减少率。

不得为生成这些指标实时扫描业务明细表；观测使用计数器、直方图、队列水位和已有预聚合结果。

## 验证要求

### 契约与功能

- Node / Go 使用同一组 confirm、token、event 和 field mask JSON fixture。
- 覆盖 unchanged、delta、reload、reset、删除 tombstone、未知版本、日志断档和 epoch 变化。
- 覆盖用户 / 管理视图、目标系统账户、权限变化和伪造 scope 不越权。
- 覆盖写后立即 patch、迟到响应、乱序 sequence、页面卸载和查询签名切换。
- 覆盖多标签 leader、BroadcastChannel 不可用退化和重复事件幂等。

### 存储与恢复

- standalone 验证 DB service revision owner、worker IPC、IPC 失败 reset 和重启换 epoch。
- performance 验证 Redis Lua 原子更新、Redis cache miss 有界回填、Redis 故障 503 且数据库无流量放大。
- 验证 outbox 在“数据库已提交、Redis 发布前进程退出”后可以重放。
- 验证 Redis 清空、namespace 变化、变更日志裁剪和投影淘汰后正确 reset / 回填。

### 页面专项

- AI 账户 30 秒确认不查询完整列表，不扫描使用记录，最多处理 100 个当前账户。
- 使用记录仅在可证明满足筛选的第一页前插，其他情况重取第一页或提示有新数据。
- 统计只替换 worker 已生成区块，不在请求或前端实时聚合。
- 删除、排序、筛选、分页和授权变化不会留下幽灵行或错误顺序。
- IndexedDB 在刷新和重新打开后先显示缓存，随后完成轻量确认。

### 性能验收目标

正式阈值必须绑定测试机器、浏览器、Node / Go 版本、Redis / PostgreSQL 配置、用户数、账户数、记录量、查询签名和网络位置，并先保存改造前基线。以下仅为首轮候选目标，不能脱离环境直接宣称达标：

- confirm 服务端 p95 不高于 `20ms`，且业务数据库查询数为 0。
- 热缓存页面从 IndexedDB 到可见内容 p95 不高于 `100ms`。
- P0 页面重复进入时完整列表 / 统计请求减少至少 `80%`。
- P0 服务端业务数据库查询次数相对现有基线减少至少 `70%`。
- delta 响应字节数相对完整接口平均减少至少 `70%`。
- Redis 故障演练期间数据库 QPS不因页面确认流量上升，前端继续展示旧缓存并可恢复。

### 必跑验证

- 前后端类型检查和构建。
- Node standalone 专项回归。
- Node performance PostgreSQL + Redis 真实依赖 smoke。
- Go 已迁移模块契约测试、race、vet 和真实 Redis / PostgreSQL smoke。
- 前端 IndexedDB、30 秒协调、多标签、竞态和全路由覆盖回归。
- 冷缓存、热缓存、预热、击穿、Redis 重启、DB service 重启和混合读写压测。
- `git diff --check`、文档链接和计划索引检查。

## 验收标准

- 全部实际路由和壳层读入口都已进入可机器检查的“路由 -> API -> owner -> domain -> 策略”registry；只有分类矩阵不能视为完成。未登记入口不能默认接入通用缓存。
- 页面重复进入和浏览器刷新可以先展示 IndexedDB 缓存。
- 当前可见页面的周期 tick 最多每 30 秒执行一次统一确认，多标签默认只有一个 leader；聚焦、恢复可见和路由激活允许提前触发，但必须 debounce 并复用 in-flight。
- confirm 在 standalone 和 performance 都不查询业务数据库。
- 变化字段、追加记录和统计区块按各自协议增量获取；不安全 patch 的场景正确重取当前页。
- Redis / 内存 projection miss 只有在基础设施健康时才允许有界回填，且不会击穿数据库。
- 最近 7 天用户的首页和“我的 AI 账户”默认入口完成有界预热。
- Node / Go 共存期间，已定义的提交后崩溃、重复投递和乱序窗口可重放或幂等处理；无法证明日志连续时必须 reset，不能静默返回 unchanged。Go 不新增 standalone 实现。
- 观测和压测能够量化首屏、完整请求、数据库查询、缓存命中和故障恢复收益。

## 风险与注意事项

- 这是一项横跨几乎全部页面和多个 writer 的基础设施改造，必须按 P0-P3 分阶段，不能一次性给所有接口套通用缓存装饰器。
- outbox 是新的持久写入副作用，需要控制表增长、批量发布、重放和清理；它只服务低频持久变更和批事件，不记录每次运行态抖动。
- 权限、筛选、排序和分页影响判断错误会造成页面幽灵行或错误顺序；无法证明可 patch 时必须重取当前页。
- 30 秒从 revision 成功发布后开始计算，不等于业务事实端到端实时一致性；使用记录、日志和统计还包含队列 / 聚合延迟。用户自己的写操作靠写响应立即更新当前页并标记同域缓存 dirty，其他会话变化存在正常延迟。
- Redis state 和 cache 分离后不能跨实例做原子事务；revision 与运行态投影同 state Redis 原子更新，静态 query cache miss 通过 reset / 回填解决。
- IndexedDB 容量、序列化和多标签协调会增加前端基础设施复杂度，必须先服务 P0 页面并证明收益，再扩展到低频诊断页。
- 当前前端文档中“接口结果不得进入页面状态缓存”的规则继续适用于 page-state store；本设计新增的是独立 IndexedDB page-data store，两者不能混用。
