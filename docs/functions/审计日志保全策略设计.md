# 审计日志保全策略设计

> 面向网关、后端、前端、存储和 AI 维护者。
> 本文定义原始审计日志在高请求量、大请求体和重复错误场景下的容量治理方案。目标不是少记审计，而是在资源有限的单机 SQLite 部署中保留可验证证据链。

## 文档目标

- 明确“审计事件全量保留，正文内容按策略保全”的长期设计。
- 定义请求 / 响应正文的压缩、加密、去重、引用和清理边界。
- 定义成功请求、错误请求、安全事件、慢请求和大 payload 的保留策略。
- 定义重复错误聚合方式，避免重试风暴刷爆页面和存储，同时不破坏每次请求发生过的证据。
- 给后续 schema、后台 worker、管理 API 和前端页面改造提供计划依据。

## 背景问题

原始审计日志需要保存完整请求链路，但单条请求和响应可能接近 `1MB`。如果一天产生几万到几十万次请求，直接把每次请求的完整 headers、body 和 SSE 内容写入 SQLite，会带来这些问题：

- 磁盘增长不可控，几十万请求可能形成数十 GB 到数百 GB 日增量。
- SQLite 主库、WAL、备份和查询临时空间都会被大字段拖慢。
- 重试风暴和重复错误会产生大量近似相同的上游响应，列表也难以排查。
- 简单删除或粗暴抽样会破坏排障链路，后续无法证明某次请求是否发生过。

因此审计日志需要从“每条记录物理复制一份完整原文”升级为“每次事件可追溯，正文内容可验证保全”。

## 核心原则

- 每次客户端请求都必须生成一条轻量审计事件，事件本身不做随机抽样。
- 请求 / 响应正文可以按策略采样、压缩、加密、去重和过期清理，但必须保存内容哈希和保留状态。
- 去重只复用完全相同的内容 blob，不删除审计事件。
- 错误聚合只影响列表展示、统计和重复错误摘要，不抹掉每次 occurrence。
- 采样只控制正文是否完整保留，不控制事件是否存在。
- 压缩必须发生在加密之前；内容哈希必须基于原始明文字节计算。
- 网关主链路不等待压缩、加密、写库或清理；这些能力都在终态入队后由后台 worker 处理。
- 第一版保持轻量单机方案，使用 SQLite 保存元数据，使用本地文件保存大 payload blob，不引入 Redis、Kafka、ClickHouse 或对象存储。

## 与原始审计日志的关系

[原始审计日志设计](原始审计日志设计.md) 定义捕获范围、终态入队、SSE 结束后入队、权限和安全边界。本文定义原始审计日志的容量治理和保全策略。

两者分工如下：

| 问题 | 原始审计日志设计 | 审计日志保全策略 |
| --- | --- | --- |
| 是否捕获完整链路 | 定义必须捕获哪些阶段 | 继承该捕获范围 |
| 网关是否同步写库 | 禁止同步写库 | 继承异步终态入队 |
| 每次请求是否有记录 | 要求有审计事件 | 固定事件全量保留 |
| 正文是否每次完整落盘 | 不再要求每条物理复制 | 按策略采样、压缩、去重和过期 |
| 重复错误如何处理 | 标记 outcome 和错误摘要 | 聚合错误组并保留 occurrence |
| 数据如何清理 | 独立保留策略 | 按事件、payload、错误组分层清理 |

## 概念模型

- `audit_event`：每次客户端请求的轻量事件。可继续由 `audit_logs` 表承载，也可以在实现时重命名为 `audit_events`。
- `audit_attempt`：一次客户端请求下的上游尝试记录。
- `audit_payload_blob`：按内容哈希保存的请求 / 响应正文或 headers blob，可被多条事件引用。
- `audit_payload_ref`：事件或尝试对某个 payload blob 的引用，记录 part 类型、顺序、捕获状态和保留状态。
- `audit_error_group`：一段时间窗口内重复错误的聚合记录。
- `audit_error_occurrence`：错误组中的每次发生。第一版可以直接由带 `error_group_id` 的 `audit_event` 承载，不必单独建表。

## 数据流

1. 网关请求开始时创建内存态捕获上下文，只追加元数据和原始片段。
2. 请求结束、失败、超时或客户端断开后生成终态快照。
3. 终态快照进入审计队列，主请求链路立即结束，不等待写库。
4. 后台 worker 根据 outcome、状态码、错误类型、请求大小、响应大小、稳定采样桶和磁盘水位计算保全策略。
5. worker 对需要保留的 headers/body 计算原始哈希，再执行压缩和加密。
6. worker 按 `sha256 + raw_size + content_type` 查找已有 blob，相同内容只增加引用，不重复写入。
7. worker 写入事件、尝试、payload 引用、blob 元数据和错误聚合信息。
8. 数据保留任务按事件、payload 引用、blob 引用计数和错误组窗口清理过期数据。

## 压缩策略

默认策略：

- 小于 `4KB` 的文本 payload 可以不压缩，避免 CPU 开销大于收益。
- 大于等于 `4KB` 的 JSON、文本、SSE 和错误响应优先使用 Brotli；不适合时回退 gzip。
- 已经压缩的二进制内容不重复压缩，只记录原始大小和哈希。
- 压缩在后台 worker 执行，不在网关主链路执行。
- 压缩后再加密，保证加密前仍能获得压缩收益。

每个 blob 必须记录：

- 原始大小
- 压缩后大小
- 压缩算法
- 加密方式
- 原始内容哈希
- 存储位置

## 内容去重策略

内容去重只做完全相同内容复用：

- 按原始明文字节计算 `sha256`。
- 相同 `sha256 + raw_size + content_type` 的 blob 只存一份。
- 多个审计事件通过 `audit_payload_refs` 引用同一个 blob。
- 清理时先删除过期引用，再按 `ref_count = 0` 或无引用 blob 删除文件。

去重不做这些事：

- 不把“看起来相似”的正文合并。
- 不删除 `audit_event`。
- 不因为错误组聚合而删除 occurrence。
- 不把截断摘要伪装成完整原文。

## 错误聚合策略

错误聚合用于处理链路重试、客户端自动重试、账号冷却前重复失败等场景。

默认聚合窗口建议 `5` 分钟，后续可配置为 `1`、`5`、`15` 分钟。

错误指纹建议由这些字段组成：

- `system_account_id`
- `api_key_id`
- `group_id`
- `provider_code`
- `account_id`
- `path`
- `model`
- `final_status_code`
- `error_phase`
- `error_code`
- `error_type`
- `normalized_request_fingerprint`
- `normalized_error_fingerprint`

`normalized_request_fingerprint` 需要移除或归一化这些易变字段：

- `trace_id`
- `request_id`
- 时间戳
- 随机 nonce
- 流式事件 ID
- 客户端重试序号
- SDK 自动生成的诊断字段

聚合组保存：

- 首次发生时间
- 最近发生时间
- 发生次数
- 第一条事件
- 最近一条事件
- 代表样本事件
- 最近错误摘要

页面默认展示错误组，点开后读取该组下的事件列表。事件列表仍能看到每次发生的时间、状态码、耗时、trace ID、request hash 和 response hash。

## 采样和保留策略

采样只控制正文，不控制事件。

默认建议：

| 请求类型 | 事件 | 正文策略 |
| --- | --- | --- |
| 安全、认证、权限失败 | 全量保留 | 默认完整保留，保留期最长 |
| 网关异常、上游失败、流式中断、客户端中断 | 全量保留 | 默认完整保留 |
| 重试后成功 | 全量保留 | 默认完整保留失败尝试，成功响应可按策略保留 |
| 慢请求 | 全量保留 | 默认完整保留 |
| 普通成功请求 | 全量保留 | 稳定采样保留完整正文，未命中时保存 hash 和摘要 |
| 超大成功响应 | 全量保留 | 可降级为 hash + 摘要 + 前后片段，并明确 `summary_only` |

成功正文采样使用稳定桶，不使用纯随机：

```text
sampleHit = sha256(trace_id 或 event_id) % 10000 < sampleRate * 10000
```

这样同一条事件是否命中采样可复现，也方便解释为什么某条正文被保留。

默认保留期建议：

| 数据 | 默认保留 |
| --- | --- |
| 审计事件元数据 | 90 天 |
| 普通成功正文 | 7 天 |
| 错误请求正文 | 30 天 |
| 安全 / 认证 / 权限事件正文 | 90 天 |
| 错误聚合组 | 180 天 |
| 无引用 payload blob | 下次清理任务删除 |

## 磁盘水位保护

审计保全策略必须能在磁盘压力上升时降级。

建议水位：

- 低于 `70%`：标准策略。
- 高于 `80%`：降低普通成功请求正文采样率。
- 高于 `90%`：普通成功请求只保留事件、hash 和摘要；错误请求仍尽量完整保留。
- 高于 `95%`：进入保护模式，只保留事件和关键错误正文；运维页面提示审计正文保全风险。

水位保护不能静默伪造完整审计。任何降级都必须写入 `payload_policy` 和 `payload_capture_status`。

## 安全策略

- 原始 payload 仍属于 `S2-A 原始审计` 高敏数据。
- 本地 blob 文件必须加密保存，密钥仍由 `JUHE_AI_SECRET` 或其派生密钥管理。
- 页面默认折叠 headers 和 body，管理员主动查看时才加载。
- 查看完整原文本身应写入操作日志或专门的原文访问日志。
- 对外分享数据库、日志、截图或备份前，必须同时移除 SQLite 元数据和本地 blob 目录。
- 备份迁移时必须同时备份 SQLite、blob 目录和 `.env` 中的稳定密钥。

## 管理 API 和页面

建议新增或扩展：

- `GET /api/audit-logs`：事件列表，展示是否有完整正文、是否采样、是否过期、是否进入错误组。
- `GET /api/audit-logs/error-groups`：重复错误聚合列表。
- `GET /api/audit-logs/error-groups/:id/events`：错误组 occurrence 列表。
- `GET /api/audit-logs/:id`：事件详情、尝试、payload 引用和保留状态。
- `GET /api/audit-logs/:id/payloads/:payloadRefId`：读取某段原文，后端解密解压后返回。
- `GET /api/audit-logs/runtime`：队列、磁盘水位、采样率、压缩收益、去重收益和最近错误。
- `GET /api/audit-logs/policy`：读取当前审计保全策略。

前端页面建议：

- 列表默认展示事件视图和错误组视图两个 tab。
- 事件列表展示 `payload_policy`、`capture_status`、压缩前后大小和是否过期。
- 错误组列表展示发生次数、首次 / 最近时间、代表错误、影响账号和模型。
- 详情页在每段 payload 上明确标注 `完整原文`、`仅摘要`、`仅 hash`、`已过期` 或 `因保护策略丢弃`。
- 原文加载按钮必须有中文风险提示，不在列表中直接渲染大段内容。

## 配置边界

建议进入系统设置或后端策略配置的字段：

- 审计保全模式：`轻量`、`标准`、`全量调试`、`合规保留`
- 普通成功正文采样率
- 错误正文是否完整保留
- 慢请求完整保留阈值
- 单条 payload 完整保留上限
- 压缩启用开关和压缩阈值
- 内容去重启用开关
- 错误聚合窗口
- 事件元数据保留天数
- 成功正文保留天数
- 错误正文保留天数
- 磁盘水位保护阈值

`全量调试` 必须支持自动过期，例如 `2` 小时或 `24` 小时，避免临时排障后忘记关闭。

## 实施阶段建议

### 第一阶段：事件与 payload 解耦

- 将大 body 从事件表中移出。
- 新增 payload blob 元数据和引用模型。
- 本地文件保存加密压缩 blob。
- 按原始哈希做精确去重。
- 事件列表不读取大正文。

### 第二阶段：正文采样与分层保留

- 成功请求正文稳定采样。
- 错误、安全、慢请求正文默认完整保留。
- payload 引用支持过期状态。
- 清理任务按引用和 blob 分层清理。

### 第三阶段：重复错误聚合

- 新增错误指纹和错误组。
- 列表增加错误组视图。
- 事件详情展示所属错误组和 occurrence。
- 重试风暴场景下页面默认按组展示。

### 第四阶段：资源保护与证据链增强

- 增加磁盘水位保护。
- 增加压缩率、去重率和正文降级指标。
- 增加可选 hash chain。
- 增加原文查看访问审计。

## 验收标准

- [ ] 每次网关请求都有轻量审计事件，普通成功请求未命中正文采样时也能查到事件。
- [ ] 大 payload 不直接写入审计事件主表，列表查询不读取正文 blob。
- [ ] 相同正文通过原始 `sha256` 精确去重，多条事件引用同一个 blob。
- [ ] 压缩发生在加密之前，并能记录压缩前后大小。
- [ ] 错误请求默认完整保留正文，普通成功请求按稳定采样保留正文。
- [ ] 未保留完整正文的事件明确显示 `hash_only`、`summary_only` 或 `expired`，不伪装成完整原文。
- [ ] 重复错误按错误指纹聚合展示，但每次 occurrence 仍能按事件追溯。
- [ ] 清理任务能删除过期引用和无引用 blob，不影响事件元数据。
- [ ] 磁盘水位保护触发后能降低成功正文保留，同时保留审计事件和降级原因。
- [ ] 普通用户不能访问原始审计，管理员查看原文有明确高敏提示。
