# 审计日志保全策略设计

> 面向网关、后端、前端、存储和 AI 维护者。
> 本文定义原始审计日志的轻量容量治理方案，不扩展为安全审计、合规审计或重型日志平台。

> 当前 owner（F3）：Node 只捕获并发送一次审计输入；Go F3 负责 payload/blob、错误分组、NDJSON 热搜索写入和全部审计保留清理；Node 只读端以有界流式扫描检索该镜像，不调用 `rg`。本文中涉及 Node 审计队列、Redis Stream、background worker 或 `data-retention-cleanup` 的描述均是 F3 前历史基线，不得作为现行启动、写入或清理路径。F3 开发验收和部署边界以 [F3 原始审计日志持久化与保留迁移计划](../migration/F3-原始审计日志持久化与保留迁移计划.md) 为准。

## 文档目标

- 默认成功请求最近 `1` 小时全量热保留；超过热窗口后主记录继续保留至成功保留期结束，仅 `10%` 稳定采样保留 attempts 和 payload，未命中记录裁剪为 `metadata_only`；两个数值允许通过环境变量在受控范围内调整。
- 失败、异常、中断和包含失败尝试的链路固定必须进入原始审计，不开放失败采样。
- 固定 payload 压缩、精确去重、重复错误聚合和定期清理策略。
- 明确当前不做的重型能力，避免实现跑偏。

## 当前口径

每次请求发生过的结构化事实由 `usage_records` 保底。原始审计日志不替代使用记录；普通成功请求先进入最近 `1` 小时热保留窗口，便于问题刚发生时排查原始链路。超过热窗口后，命中稳定桶的 `10%` 继续保留 attempts 和 payload；其余成功主记录保留到成功保留期结束，但删除 attempts 和 payload 引用并标记为 `metadata_only`。

原始审计的持久化来源包括 `gateway`、`manual_account_test`、`hybrid_scoring` 和 `hybrid_quality_scoring`。健康检查、恢复探针和冷却复测属于高频后台运行事件，不写入 `audit_logs` 或热搜索 NDJSON，也不出现在管理端来源筛选；这些来源仍可由 `usage_records` 按使用记录契约保留。

原始审计只处理两类数据：

- 成功热窗口：完全成功请求最近 `1` 小时全量写入原始审计，用于突发 `200` 链路问题的即时排查。
- 成功长期样本：超过热窗口后，完全成功请求默认按稳定桶采样 `10%` 长期保留 attempts 和 payload，用于抽查客户端请求、网关改写和上游适配是否正确；未命中样本仍保留主记录元数据。
- 问题链路：失败、网关异常、上游异常、客户端中断、流式中断，以及中间发生失败尝试后最终成功的重试链路，必须保存。

body 保全按请求结果分两档：

- 成功样本 body 不超过 `512KB` 时保存完整正文，超过后只保存摘要。
- 问题链路 body 不超过 `2MB` 时保存完整正文，超过后保存原始 `SHA256`、原始大小、原始 content-type、前 `256KB`、后 `256KB` 和文本预览，不解析原始 JSON Body，也不默认保存完整正文。

## 不做范围

当前不考虑这些能力：

- 不做 hash chain。
- 不做合规保留模式。
- 不做长期全量调试模式。
- 不做原文查看访问审计。
- 不做安全事件特殊保留。
- 不做慢请求特殊保留。
- 不做 payload 加密和密钥管理。
- 不做复杂磁盘水位分层策略。
- 保全策略本身不强制引入 Kafka、ClickHouse、对象存储或分布式队列；F3 不使用 Redis Stream 作为审计传输层。

如果真的需要其中某项，再单独立项，不混进当前容量治理。

## 核心原则

- 成功请求先全量热保留，再按稳定桶做后置长期 payload / attempt 采样；未命中样本保留主记录并降为 `metadata_only`。
- 失败和异常链路必须写原始审计。
- 进入原始审计的长期 payload blob 要压缩。
- 最近 `1` 小时内容搜索使用 Go F3 写入的未压缩 NDJSON 热搜索镜像；Node 只读端按文件、行数和单行字节数上限流式扫描并匹配关键字，不启动 `rg`。热窗口内完全成功请求的完整已保全正文参与搜索；`summary_only`、`hash_only` 或已裁剪为 `metadata_only` 的记录只按其实际仍保留的内容参与，镜像只服务热窗口搜索，不替代长期 payload blob。
- 相同 payload 只存一份，多条事件引用同一个 blob。
- 重复错误默认按组展示，组里保留发生次数和必要 occurrence。
- 不把相似内容合并，只做完全相同内容的 hash 去重。
- 不把摘要、截断内容或已过期内容伪装成完整原文。
- 报表口径拆成两个字段：`raw_payload_bytes` 表示原始逻辑字节，`compressed_payload_bytes` 表示实际落盘 blob 字节。

## 数据流

1. 网关请求结束、失败、超时或客户端断开后生成终态快照。
2. 后端根据 outcome 判断保全档位；普通成功请求也进入最近 `1` 小时热保留窗口。
3. 普通成功请求仍计算稳定采样桶，作为超过热窗口后的长期 payload / attempt 保留依据；未命中 `10%` 的成功记录删除 attempts 和 payload 引用，主记录更新为 `metadata_only`。
4. 成功热保留、命中成功长期采样或属于问题链路时，先按 body 保全档位把超大正文改成 `summary_only` 摘要，保留原始 hash 和原始大小；热窗口内的完全成功请求以实际完整保全正文写入热搜索镜像。
5. Node 把终态快照一次性发送给本机 Go F3 sidecar；失败只记原因和计数，不在 Node 内排队或重试。
6. Go F3 校验输入、计算 headers/body 原始 hash；summary-only payload 的 `body_sha256` 使用原始 body hash。
7. Go F3 压缩 payload，并按 `sha256 + raw_size + content_type` 查找已有 blob。
8. 相同 blob 只增加引用，不重复写入文件。
9. Go F3 在一个 owner-fenced 事务内写入审计事件、上游尝试、payload 引用、blob 元数据和错误组。
10. Go F3 写入未压缩 NDJSON 热搜索镜像；Node 只读端有界流式扫描后按 `auditLogId` 回表展示审计行，不调用 `rg`。
11. Go F3 retention 按批次把超过热窗口且未命中长期采样的普通成功记录裁剪为 `metadata_only`，并在各自保留期结束后删除过期事件、过期引用、无引用 blob 文件、错误聚合和已过期热搜索镜像。
12. 热搜索镜像写入和清理同样执行来源边界校验，历史镜像中的已知后台来源按批次移除，防止高频后台事件继续占用审计容量。

## 成功采样

成功请求采样使用稳定桶，不用纯随机：

```text
sampleHit = sha256(trace_id 或 request_id) % 10000 < 1000
```

规则：

- `success` 且没有任何失败尝试：最近 `1` 小时全量写入 `audit_logs`，完整已保全正文可参与热搜索；超过热窗口后仅命中长期采样的记录继续保留 attempts 和 payload。
- 未命中采样的成功请求：热窗口内可查；超过热窗口后由 Go F3 retention 删除 attempts 和 payload 引用、将主记录降为 `metadata_only`，主记录仍保留到成功保留期结束；结构化事实仍写 `usage_records`。
- `success_after_retry`：因为链路中存在失败尝试，按问题链路进入原始审计。

## 大 body 保全

进入原始审计后，body 的默认处理是：

| 场景 | 完整正文上限 | 超限后保留 |
| --- | --- | --- |
| 成功样本 | `512KB` | `summary_only` 摘要 |
| 问题链路 | `2MB` | `summary_only` 摘要 |

`summary_only` 摘要必须包含：

- 原始 body 的 `SHA256`。
- 原始 body 字节数。
- 原始 `content-type` 和 `content-encoding`。
- 前 `256KB` 和后 `256KB` 原始字节，以 base64 保存。
- 文本类 payload 的头尾文本预览。
- 摘要不保留 JSON 顶层类型、key 或数组结构；禁止为了展示对原始 Body 做完整解析或前缀结构扫描。

因此 hash 去重仍然是精确去重：完全相同正文可复用 blob；相似但不完全相同的大 JSON 不会被合并，只会走摘要保全来控制落盘放大。

## 压缩策略

- 小于 `4KB` 的 payload 可以不压缩。
- 大于等于 `4KB` 的 JSON、文本和 SSE payload 默认压缩。
- 已经压缩的二进制内容不重复压缩。
- 压缩由 Go F3 在接收输入后的持久化路径执行，不阻塞 Node 网关主链路。
- blob 元数据记录原始大小、压缩后大小、压缩算法和原始 hash。

## 去重策略

- 只做完全相同内容去重。
- hash 基于原始字节计算。
- 相同 `sha256 + raw_size + content_type` 只存一份 blob。
- 多个审计事件通过 `audit_payload_refs` 引用同一个 blob。
- 清理时先删引用，再删无引用 blob 文件。

不做：

- 不做相似文本合并。
- 不做语义级去重。
- 不删除失败 occurrence。
- 不把摘要标成完整原文。

## 错误聚合

错误聚合用于处理短时间内重复失败，例如客户端重试、上游 429、账号错误、代理失败、超时。

当前聚合窗口为 `5` 分钟。

错误指纹包含：

- `system_account_id`
- `api_key_id`
- `group_id`
- `provider_code`
- `account_id`
- `path`
- `model`
- `final_status_code`
- `error_phase`
- `error_code`
- `request_fingerprint`
- `error_fingerprint`

聚合组保存：

- 首次发生时间
- 最近发生时间
- 次数
- 第一条事件
- 最近一条事件
- 代表样本事件
- 最近错误摘要

错误聚合只作为后台降噪、保留和后续排障索引元数据，不在单条审计详情里默认展示；单条请求内部的失败路径以 `上游尝试` 为准。

## 保留与清理

当前默认保留期（问题事件包括 `success_after_retry`、`gateway_failed`、`upstream_failed`、`stream_failed` 和 `downstream_closed`）：

| 数据 | 默认保留 |
| --- | --- |
| 成功样本 | 3 天 |
| 问题事件 | 7 天 |
| 问题 payload | 7 天 |
| 错误聚合组 | 7 天 |
| 无引用 blob 文件 | 下次清理任务删除 |

环境变量契约：成功热窗口 `0..168` 小时、成功采样率 `0..1`（最多四位小数）、成功保留期 `0..3650` 天、问题保留期 `1..3650` 天。成功采样率与成功保留期必须同时为 0 或同时大于 0；长期采样启用时成功保留期必须覆盖热窗口，热窗口可在长期采样关闭时单独保留，三项全 0 时不采集成功审计。成功 / 问题正文上限分别为 `0..512KB` 和 `0..2048KB`；设为 `0` 时正文按 `hash_only` 保存。非法配置直接阻止进程启动。

清理规则：

- 清理由 Go F3 sidecar 的 owner-fenced retention 执行，不在 Node 后台 worker 或列表读取中执行。
- 未命中长期采样的成功记录超过热窗口后先删除 attempts、payload 引用和无引用 blob，并把主记录标记为 `metadata_only`；成功保留期结束后才删除该主记录。
- 命中长期采样的成功样本在成功保留期结束后删除事件、尝试、引用和 blob 引用。
- 失败事件过期后再删除对应引用。
- 删除引用后，如果 blob 没有其他引用，再删除本地文件和 blob 元数据。

## 管理页面

页面保留单一 `审计事件` 列表，成功样本和失败链路都从同一入口查看。重复错误聚合不单独作为主视图，也不在单条审计详情里默认展示，避免和 `上游尝试` 信息重复。

问题列表 / 审计事件列表不新增 payload 字节列；`raw_payload_bytes` 和 `compressed_payload_bytes` 只用于后端报表、容量分析和内部接口字段。

事件列表展示：

- 时间
- outcome
- 状态码
- path
- model
- API Key
- 分组
- 账号
- 采样原因

详情页展示：

- 链路概览
- 上游尝试
- payload 引用
- 原文或摘要
- hash 和大小

## 当前落地

- 成功请求最近 `1` 小时全量进入原始审计，超过热窗口后全部保留主记录，只有 `10%` 稳定采样继续保留 attempts 和 payload。
- 失败和异常链路必须进入原始审计。
- 未命中长期采样的成功请求超过热窗口后由 F3 retention 删除 attempts 和 payload 引用并降为 `metadata_only`，不删除主记录；主记录到成功保留期结束后才删除，`usage_records` 仍独立写入。
- 成功样本超过 `512KB`、问题链路超过 `2MB` 的 body 转为 `summary_only`，不再默认保存完整大正文。
- 大 payload 不直接写入 `audit_logs` 主表。
- payload 从主表移出，保存为本地压缩 blob。
- payload 可以压缩并记录原始逻辑字节和实际落盘字节。
- 相同 payload 只存一份 blob，多条审计事件引用同一个 blob。
- blob 根目录由 `JUHE_AI_AUDIT_LOG_BLOB_DIRECTORY` 显式配置，必须属于 F3 专用存储范围，不得写死到仓库 `backend/data` 或复用 Node dataset 路径；隔离开发实例因此能独立创建、检查和清理审计附件，不污染用户本地数据。
- 审计列表不读取大正文，正文通过 payload 窗口接口按需读取。
- Go F3 在 owner-fenced 事务中生成错误指纹，写入或更新错误组；错误组可通过管理接口查询组内事件。
- Go F3 retention 删除过期记录和无引用 blob。
