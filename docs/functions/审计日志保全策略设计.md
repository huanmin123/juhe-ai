# 审计日志保全策略设计

> 面向网关、后端、前端、存储和 AI 维护者。
> 本文定义原始审计日志的轻量容量治理方案，不扩展为安全审计、合规审计或重型日志平台。

## 文档目标

- 默认成功请求最近 `1` 小时全量热保留，超过热窗口后只保留 `10%` 稳定采样；两个数值允许通过环境变量在受控范围内调整。
- 失败、异常、中断和包含失败尝试的链路固定必须进入原始审计，不开放失败采样。
- 固定 payload 压缩、精确去重、重复错误聚合和定期清理策略。
- 明确当前不做的重型能力，避免实现跑偏。

## 当前口径

每次请求发生过的结构化事实由 `usage_records` 保底。原始审计日志不替代使用记录；普通成功请求先进入最近 `1` 小时热保留窗口，便于问题刚发生时排查原始链路，超过热窗口后再按稳定桶保留 `10%`。

原始审计只处理两类数据：

- 成功热窗口：完全成功请求最近 `1` 小时全量写入原始审计，用于突发 `200` 链路问题的即时排查。
- 成功长期样本：超过热窗口后，完全成功请求默认按稳定桶采样 `10%` 长期保留，用于抽查客户端请求、网关改写和上游适配是否正确。
- 问题链路：失败、网关异常、上游异常、客户端中断、流式中断，以及中间发生失败尝试后最终成功的重试链路，必须保存。

body 保全按请求结果分两档：

- 成功样本 body 不超过 `512KB` 时保存完整正文，超过后只保存摘要。
- 问题链路 body 不超过 `2MB` 时保存完整正文，超过后保存原始 `SHA256`、原始大小、原始 content-type、前 `256KB`、后 `256KB` 和 JSON 结构摘要，不默认保存完整正文。

## 不做范围

当前不考虑这些能力：

- 不做 hash chain。
- 不做合规保留模式。
- 不做长期全量调试模式。
- 不做原文查看访问审计。
- 不做安全事件特殊保留。
- 不做慢请求特殊保留。
- 不做 payload 加密和密钥管理。
- 不做复杂磁盘水位分层策略。
- 保全策略本身不强制引入 Kafka、ClickHouse、对象存储或分布式队列；高性能 PostgreSQL + Redis 模式按高性能设计使用 Redis Streams 作为审计队列传输层。

如果真的需要其中某项，再单独立项，不混进当前容量治理。

## 核心原则

- 成功请求先全量热保留，再按稳定桶做后置长期采样。
- 失败和异常链路必须写原始审计。
- 进入原始审计的长期 payload blob 要压缩。
- 最近 `1` 小时内容搜索使用额外的未压缩 NDJSON 热搜索镜像，供 rg 匹配关键字；镜像只服务热窗口搜索，不替代长期 payload blob。
- 相同 payload 只存一份，多条事件引用同一个 blob。
- 重复错误默认按组展示，组里保留发生次数和必要 occurrence。
- 不把相似内容合并，只做完全相同内容的 hash 去重。
- 不把摘要、截断内容或已过期内容伪装成完整原文。
- 报表口径拆成两个字段：`raw_payload_bytes` 表示原始逻辑字节，`compressed_payload_bytes` 表示实际落盘 blob 字节。

## 数据流

1. 网关请求结束、失败、超时或客户端断开后生成终态快照。
2. 后端根据 outcome 判断保全档位；普通成功请求也进入最近 `1` 小时热保留窗口。
3. 普通成功请求仍计算稳定采样桶，作为超过热窗口后的长期保留依据；未命中 `10%` 的成功记录只在热窗口内保留。
4. 成功热保留、命中成功长期采样或属于问题链路时，先按 body 保全档位把超大正文改成 `summary_only` 摘要，保留原始 hash 和原始大小。
5. 把终态快照放入审计队列。
6. 后台 worker 计算 headers/body 原始 hash；summary-only payload 的 `body_sha256` 使用原始 body hash。
7. worker 压缩 payload，并按 `sha256 + raw_size + content_type` 查找已有 blob。
8. 相同 blob 只增加引用，不重复写入文件。
9. worker 写入审计事件、上游尝试、payload 引用、blob 元数据和错误组。
10. worker 写入未压缩 NDJSON 热搜索镜像，用于最近 `1` 小时 rg 关键字搜索；搜索命中后按 `auditLogId` 回表展示审计行。
11. `audit-hot-retention-cleanup` 每分钟分批删除超过热窗口且未命中长期采样的普通成功事件，并清理已完全过期的热搜索镜像；`data-retention-cleanup` 每天继续按长期保留期删除过期事件、过期引用、无引用 blob 文件和错误聚合。

## 成功采样

成功请求采样使用稳定桶，不用纯随机：

```text
sampleHit = sha256(trace_id 或 request_id) % 10000 < 1000
```

规则：

- `success` 且没有任何失败尝试：最近 `1` 小时全量写入 `audit_logs`；超过热窗口后只保留命中长期采样的记录。
- 未命中采样的成功请求：热窗口内可查，超过热窗口后由后台清理删除；结构化事实仍写 `usage_records`。
- `success_after_retry`：因为链路中存在失败尝试，按问题链路进入原始审计。

## 大 body 保全

进入原始审计后，body 的默认处理是：

| 场景 | 完整正文上限 | 超限后保留 |
| --- | --- | --- |
| 成功样本 | `512KB` | `summary_only` 摘要 |
| 问题链路 | `2MB` | `summary_only` 摘要 |

`summary_only` 摘要必须包含：

- 原始 body 的 `SHA256`。
- 原始 body 字节数。
- 原始 `content-type` 和 `content-encoding`。
- 前 `256KB` 和后 `256KB` 原始字节，以 base64 保存。
- 文本类 payload 的头尾文本预览。
- JSON payload 的顶层类型、顶层 key 或数组摘要；超大 JSON 不做完整解析时也要保留可推断的顶层结构。

因此 hash 去重仍然是精确去重：完全相同正文可复用 blob；相似但不完全相同的大 JSON 不会被合并，只会走摘要保全来控制落盘放大。

## 压缩策略

- 小于 `4KB` 的 payload 可以不压缩。
- 大于等于 `4KB` 的 JSON、文本和 SSE payload 默认压缩。
- 已经压缩的二进制内容不重复压缩。
- 压缩在后台 worker 执行，不阻塞网关主链路。
- blob 元数据记录原始大小、压缩后大小、压缩算法和原始 hash。

## 去重策略

- 只做完全相同内容去重。
- hash 基于原始字节计算。
- 相同 `sha256 + raw_size + content_type` 只存一份 blob。
- 多个审计事件通过 `audit_payload_refs` 引用同一个 blob。
- 清理时先删引用，再删无引用 blob 文件。

不做：

- 不做相似文本合并。
- 不做语义级去重。
- 不删除失败 occurrence。
- 不把摘要标成完整原文。

## 错误聚合

错误聚合用于处理短时间内重复失败，例如客户端重试、上游 429、账号错误、代理失败、超时。

当前聚合窗口为 `5` 分钟。

错误指纹包含：

- `system_account_id`
- `api_key_id`
- `group_id`
- `provider_code`
- `account_id`
- `path`
- `model`
- `final_status_code`
- `error_phase`
- `error_code`
- `request_fingerprint`
- `error_fingerprint`

聚合组保存：

- 首次发生时间
- 最近发生时间
- 次数
- 第一条事件
- 最近一条事件
- 代表样本事件
- 最近错误摘要

错误聚合只作为后台降噪、保留和后续排障索引元数据，不在单条审计详情里默认展示；单条请求内部的失败路径以 `上游尝试` 为准。

## 保留与清理

当前默认保留期（问题事件包括 `success_after_retry`、`gateway_failed`、`upstream_failed`、`stream_failed` 和 `client_aborted`）：

| 数据 | 默认保留 |
| --- | --- |
| 成功样本 | 3 天 |
| 问题事件 | 7 天 |
| 问题 payload | 7 天 |
| 错误聚合组 | 7 天 |
| 无引用 blob 文件 | 下次清理任务删除 |

环境变量契约：成功热窗口 `1..168` 小时、成功采样率 `0.0001..1`（最多四位小数）、成功保留期 `1..3650` 天且必须覆盖热窗口、问题保留期 `1..3650` 天。成功 / 问题正文上限分别为 `0..512KB` 和 `0..2048KB`；设为 `0` 时正文按 `hash_only` 保存。非法配置直接阻止进程启动。

清理规则：

- 清理任务只在后台 worker 执行。
- 成功样本过期后可以直接删除事件、尝试、引用和 blob 引用。
- 失败事件过期后再删除对应引用。
- 删除引用后，如果 blob 没有其他引用，再删除本地文件和 blob 元数据。

## 管理页面

页面保留单一 `审计事件` 列表，成功样本和失败链路都从同一入口查看。重复错误聚合不单独作为主视图，也不在单条审计详情里默认展示，避免和 `上游尝试` 信息重复。

问题列表 / 审计事件列表不新增 payload 字节列；`raw_payload_bytes` 和 `compressed_payload_bytes` 只用于后端报表、容量分析和内部接口字段。

事件列表展示：

- 时间
- outcome
- 状态码
- path
- model
- API Key
- 分组
- 账号
- 采样原因

详情页展示：

- 链路概览
- 上游尝试
- payload 引用
- 原文或摘要
- hash 和大小

## 当前落地

- 成功请求最近 `1` 小时全量进入原始审计，超过热窗口后只保留 `10%` 稳定采样。
- 失败和异常链路必须进入原始审计。
- 未命中长期采样的成功请求超过热窗口后从 `audit_logs` 删除，但仍写入 `usage_records`。
- 成功样本超过 `512KB`、问题链路超过 `2MB` 的 body 转为 `summary_only`，不再默认保存完整大正文。
- 大 payload 不直接写入 `audit_logs` 主表。
- payload 从主表移出，保存为本地压缩 blob。
- payload 可以压缩并记录原始逻辑字节和实际落盘字节。
- 相同 payload 只存一份 blob，多条审计事件引用同一个 blob。
- 审计列表不读取大正文，正文通过 payload 窗口接口按需读取。
- 后台生成错误指纹，写入或更新错误组，错误组可通过管理接口查询组内事件。
- 清理任务删除过期记录和无引用 blob。
