# 审计日志保全策略设计

> 面向网关、后端、前端、存储和 AI 维护者。
> 本文只定义原始审计日志的轻量容量治理方案，不扩展为安全审计、合规审计或重型日志平台。

## 文档目标

- 固定成功请求原始审计只采样 `10%`。
- 固定失败、异常、中断和包含失败尝试的链路必须进入原始审计。
- 固定 payload 压缩、精确去重、重复错误聚合和定期清理策略。
- 明确本计划不做的重型能力，避免后续实现跑偏。

## 当前口径

每次请求发生过的结构化事实由 `usage_records` 保底。原始审计日志不替代使用记录，也不需要保存每次成功请求。

原始审计只处理两类数据：

- 成功样本：完全成功请求默认按稳定桶采样 `10%`，用于抽查客户端请求、网关改写和上游适配是否正确。
- 问题链路：失败、网关异常、上游异常、客户端中断、流式中断，以及中间发生失败尝试后最终成功的重试链路，必须保存。

## 不做范围

本计划不考虑这些能力：

- 不做 hash chain。
- 不做合规保留模式。
- 不做全量调试模式。
- 不做原文查看访问审计。
- 不做安全事件特殊保留。
- 不做慢请求特殊保留。
- 不做 payload 加密和密钥管理。
- 不做复杂磁盘水位分层策略。
- 不引入 Redis、Kafka、ClickHouse、对象存储或分布式队列。

后续如果真的需要其中某项，再单独立项，不混进本次容量治理。

## 核心原则

- 成功请求只采样，不保底写原始审计。
- 失败和异常链路必须写原始审计。
- 进入原始审计的 payload 要压缩。
- 相同 payload 只存一份，多条事件引用同一个 blob。
- 重复错误默认按组展示，组里保留发生次数和必要 occurrence。
- 不把相似内容合并，只做完全相同内容的 hash 去重。
- 不把摘要、截断内容或已过期内容伪装成完整原文。

## 数据流

1. 网关请求结束、失败、超时或客户端断开后生成终态快照。
2. 后端根据 outcome 和稳定采样桶判断是否进入原始审计。
3. 完全成功且未命中 `10%` 采样时，不写 `audit_logs`。
4. 命中成功采样或属于问题链路时，把终态快照放入审计队列。
5. 后台 worker 计算 headers/body 原始 hash。
6. worker 压缩 payload，并按 `sha256 + raw_size + content_type` 查找已有 blob。
7. 相同 blob 只增加引用，不重复写入文件。
8. worker 写入审计事件、上游尝试、payload 引用、blob 元数据和错误组。
9. 清理任务按保留期删除过期事件、过期引用和无引用 blob 文件。

## 成功采样

成功请求采样使用稳定桶，不用纯随机：

```text
sampleHit = sha256(trace_id 或 request_id) % 10000 < 1000
```

规则：

- `success` 且没有任何失败尝试：只在命中采样时写 `audit_logs`。
- 未命中采样的成功请求：不写原始审计，仍写 `usage_records`。
- `success_after_retry`：因为链路中存在失败尝试，按问题链路进入原始审计。

## 压缩策略

- 小于 `4KB` 的 payload 可以不压缩。
- 大于等于 `4KB` 的 JSON、文本和 SSE payload 默认压缩。
- 已经压缩的二进制内容不重复压缩。
- 压缩在后台 worker 执行，不阻塞网关主链路。
- blob 元数据记录原始大小、压缩后大小、压缩算法和原始 hash。

## 去重策略

- 只做完全相同内容去重。
- hash 基于原始字节计算。
- 相同 `sha256 + raw_size + content_type` 只存一份 blob。
- 多个审计事件通过 `audit_payload_refs` 引用同一个 blob。
- 清理时先删引用，再删无引用 blob 文件。

不做：

- 不做相似文本合并。
- 不做语义级去重。
- 不删除失败 occurrence。
- 不把摘要标成完整原文。

## 错误聚合

错误聚合用于处理短时间内重复失败，例如客户端重试、上游 429、账号错误、代理失败、超时。

默认聚合窗口建议 `5` 分钟。

错误指纹建议包含：

- `system_account_id`
- `api_key_id`
- `group_id`
- `provider_code`
- `account_id`
- `path`
- `model`
- `final_status_code`
- `error_phase`
- `error_code`
- `request_fingerprint`
- `error_fingerprint`

聚合组保存：

- 首次发生时间
- 最近发生时间
- 次数
- 第一条事件
- 最近一条事件
- 代表样本事件
- 最近错误摘要

页面默认显示错误组，例如“同类错误 127 次”。点开后查看 occurrence 列表。

## 保留与清理

默认建议：

| 数据 | 默认保留 |
| --- | --- |
| 成功样本 | 7 天 |
| 失败 / 异常事件 | 30 天 |
| 失败 / 异常 payload | 30 天 |
| 错误聚合组 | 30 天 |
| 无引用 blob 文件 | 下次清理任务删除 |

清理规则：

- 清理任务只在后台 worker 执行。
- 成功样本过期后可以直接删除事件、尝试、引用和 blob 引用。
- 失败事件过期后再删除对应引用。
- 删除引用后，如果 blob 没有其他引用，再删除本地文件和 blob 元数据。

## 管理页面

页面保留两个视图即可：

- `审计事件`：成功样本和失败链路列表。
- `错误聚合`：重复错误按组展示。

事件列表展示：

- 时间
- outcome
- 状态码
- path
- model
- API Key
- 分组
- 账号
- payload 大小
- 压缩后大小
- 采样原因
- 错误组

详情页展示：

- 链路概览
- 上游尝试
- payload 引用
- 原文或摘要
- hash 和大小

## 实施阶段

### 第一阶段：成功采样、压缩和去重

- 成功请求只按 `10%` 稳定采样进入原始审计。
- 失败和异常链路必须进入原始审计。
- payload 从主表移出，保存为本地压缩 blob。
- 按 hash 精确去重。
- 审计列表不读取大正文。

### 第二阶段：错误聚合和清理

- 生成错误指纹。
- 写入或更新错误组。
- 页面默认按错误组展示重复错误。
- 定期清理成功样本、失败事件和无引用 blob。

## 验收标准

- [ ] 完全成功请求默认只有约 `10%` 写入 `audit_logs`。
- [ ] 未命中采样的成功请求仍写入 `usage_records`。
- [ ] 失败、异常、中断和重试失败链路必须写入 `audit_logs`。
- [ ] 大 payload 不直接写入 `audit_logs` 主表。
- [ ] payload 可以压缩并记录压缩前后大小。
- [ ] 相同 payload 只存一份 blob，多条审计事件引用同一个 blob。
- [ ] 重复错误按组展示，并能查看 occurrence。
- [ ] 清理任务能删除过期记录和无引用 blob。
