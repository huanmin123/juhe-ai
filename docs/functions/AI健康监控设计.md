# AI 健康监控设计

## 目标

新增管理页“AI 健康监控”，以账户为行展示最近最多 31 天、每小时一个状态槽位。状态来源是 `usage_records` 中 `traffic_source = 'account_health_check'` 的后台健康检查记录。

## 状态口径

- 绿色：该账户该小时最后一次健康检查成功。
- 红色：该账户该小时最后一次健康检查失败。
- 灰色：该小时没有健康检查记录，不能推断为失败。
- 同一小时多次检查按 `created_at DESC, id DESC` 取最后一条；页面同时显示最后检查时间、成功率摘要和最近错误信息。
- 查询窗口固定为最近 31 个本地统计日，结束日来自统计窗口设置；不允许任意扩大到一个月之外。

## 存储与性能

`stats-worker` 消费使用记录时，将健康检查记录增量写入统计库 `account_health_hourly`（SQLite 与 PostgreSQL 同步建表）。唯一键为 `(account_id, stat_hour)`，使用 `last_observed_at`/`last_record_id` 做幂等的最后结果覆盖。页面查询只读取统计库预聚合，不扫描 usage shard 或 `usage_records`。

管理 API 先按账户名在业务库做稳定分页，再批量读取当前页账户的窗口记录；返回 DTO 时生成最多 744 个小时槽位。搜索使用账户名前缀边界和稳定 `name, id` 排序，分页大小限制在 10..100。

## 权限与页面

管理视图显示所有可管理账户，可按系统账户上下文过滤；用户视图显示自己拥有或被授权可见的账户。菜单入口位于“AI 管理”，路径为 `/ai-health`，并提供 `/my-ai-health` 用户入口。页面使用现有响应式分页组件，不使用表格，桌面和移动端均为账户卡片列表。

## 不做的事

本功能不把普通网关请求成功/失败当作健康检查，不在请求链路同步写入健康历史，也不把灰色缺测槽位解释成账户不可用。账户当前可调度状态仍以账户事实和后台探针状态机为准。
