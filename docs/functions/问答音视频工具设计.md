# 问答音视频工具设计（M7）

> 状态：设计定稿（2026-10-04）；M7b 后端已实施（2026-10-04，工具/绑定/执行链/任务结算接口/资产扩展/单测链测；实施取舍见 §4 与《AI问答工具体系与主子模型设计》§6.5/§6.6 回填——消息任务块保留块型并附 assetId 终态字段，不迁移为 output_video）。M7c/M7d/M7e 未实施。父计划：[计划-20261003T164247971Z-音频视频模型接入与多供应商扩展](../plans/计划-20261003T164247971Z-音频视频模型接入与多供应商扩展.md)。
> 基座：M1-M5 媒体网关（`/v1/audio/speech`、`/v1/videos` job 全套）；工具体系参照《[AI问答工具体系与主子模型设计](AI问答工具体系与主子模型设计.md)》（generate_image 模式）。

## 1. 目标与非目标

**目标**：
1. 问答新增两个模型工具：`generate_video`（视频生成，异步任务）与 `generate_audio`（语音合成 TTS，同步），主模型 function calling 触发，会话/用户级绑定「账户+模型」与既有工具同构。
2. 异步任务的前端形态：消息流内**任务块**（排队/生成中/完成/失败 + 进度），完成后自动转换为可播放资产（`<video controls>` / `<audio controls>`）+ 下载。
3. Mock 全链路可测可看：mockupstream 返回**真实可播放**的音频（既有合法 WAV）与视频（升级为带 moov 的最小可播放 MP4），隔离实例打通主模型→工具→网关→mock→资产→渲染全流程。
4. 截图验收渲染效果并调优 UI。

**非目标**：不做长音频转写工具（`/v1/audio/jobs` 属 API 域，进问答待后续需求）；不做 Realtime 工具（M5 域）；不改动 `/v1` 媒体域零存储契约（见 §2 边界裁决）。

## 2. 关键裁决

1. **产物处置（两域边界）**：网关 `/v1` 媒体 API 域维持**零存储**（产物时效由上游定）；chat 产品域的媒体工具产物按**既有 chat_assets 落库模式**（与 generate_image 一致：original 对象 + `chat_assets` 行 + 会话资产内容端点回看）——聊天记录要求历史媒体长期可播放，上游 URL 1 小时~2 天过期不满足。工具执行器在终态时从上游 content 下载落资产（限额：视频 ≤64MB、音频 ≤32MB，超限失败不落）。
2. **异步适配（任务块 + 前端轮询驱动结算）**：`generate_video` 工具创建 job 后**立即完成工具调用**（结果="任务已创建"+jobId，主模型据此告知用户生成中）；消息落 `output_media_task` 内容块。**无后台常驻任务**：前端对未终态任务块每 5s 轮询 `GET /my-chat/conversations/{cid}/media-tasks/{jobId}`，后端实时查 `media_jobs` 并按需 poll 上游；到达终态时**幂等结算**（completed→下载产物落 chat_assets→更新消息块为 `output_video` + assetId；failed→块置失败态）。页面重开同样触发轮询结算（幂等由 media_jobs 终态唯一性 + 资产查重保证）。
3. **音频同步即时**：`generate_audio`（TTS）秒级同步完成，沿 generate_image 模式直接落资产 + `output_audio` 块即时播放。
4. 子调用一律经**进程内 /v1 链**（chatGatewayExecutor 固定派发绑定账户；视频轮询走任务面账户亲和——创建时归属 chat API Key，亲和查表成立）；purpose 头 `chat_media_generation`（审计区分）。

## 3. 对外契约（chat 域）

**工具定义**（function calling）：
- `generate_video(prompt: string, seconds?: number, size?: string, model?: string)`——model 暴露视频模型注册枚举（sora-2/veo/cogvideox/...按绑定账户可路由收敛，同 BUG-0230 模式）。
- `generate_audio(text: string, voice?: string, format?: string, model?: string)`——TTS 模型枚举同收敛。

**绑定**：`chat_conversations` 增 `video_account_id/default_video_model`、`audio_account_id/default_audio_model` 四列；`chat_user_tool_preferences` 同；`tool-preferences` 响应 `tools[]` 增两节（candidates 沿 `resolveChatToolBindingCandidates` 模式：模型家族白名单 openai/gemini/minimax/volcengine/qwen 的视频/TTS 目录行 × 账户可路由）；PATCH 键 `videoBinding/audioBinding`。

**内容块**（前后端同形）：
- `output_audio { blockId, order, assetId, mimeType, durationHint? }`；
- `output_video { blockId, order, assetId, mimeType }`；
- `output_media_task { blockId, order, jobId, kind: "video", status: queued|in_progress|completed|failed, progress?, model, promptSummary, assetId?(终态), error? }`。

**任务接口**：`GET /my-chat/conversations/{cid}/media-tasks/{jobId}` → 任务块当前态（内部：media_jobs 查行→未终态则经任务面 poll 上游→终态幂等结算落资产→返回终态块）；403 归属校验。

**资产**：`chat_assets` MIME 词表扩展 `audio/*`、`video/*`（扩展名 .mp3/.wav/.mp4 等）；内容端点 `.../assets/{assetId}/content` 复用（inline 播放 + download 参数）。

## 4. 后端落点（chat 域）

1. `internal/chat/generation_tools.go`：注册两工具（kind=model）+ 编排器特判（generate_video 的 started progress 阶段 `submitting`；generate_audio `synthesizing`；MaxToolCalls 预算内）。
2. `internal/chat/tool_bindings.go`：运行时/候选扩展（`chatSearchVideoModelFamily`/`chatSearchAudioModelFamily` 白名单 + `accountSupportsMediaModel`——协议 video/audio_speech 可路由判定）。
3. `internal/chat/generation_media.go`（新）：`GenerateChatAudio`（进程内 `/v1/audio/speech`，响应音频字节→MIME 嗅探→资产）；`CreateChatVideo`（进程内 `/v1/videos` 创建→jobId）；`ResolveChatMediaTask`（轮询+结算：经进程内链 `GET /v1/videos/{id}`（亲和）→ 终态时 `GET content`（亲和）下载落资产）。
4. `internal/chat/stream_execute.go`：执行上下文回调 `VideoGeneration/AudioGeneration`；`generate_video` 完成事件投影 `output_media_task` 块；`generate_audio` 投影 `output_audio` 块。
5. `internal/chat/media_task_routes.go`（新）：任务查询接口（幂等结算 + 会话归属校验）。
6. purpose 头 `chat_media_generation`；审计/usage 天然继承进程内链。

## 5. 前端落点

1. `types/domain/chat.ts`：三块类型 + 偏好键 + SSE（无需新事件——任务态经轮询）。
2. 新组件：`ChatGeneratedVideo.vue`（`<video controls preload="metadata">` + 下载）、`ChatGeneratedAudio.vue`（`<audio controls>`）、`ChatMediaTask.vue`（任务卡：状态 Tag/进度条/promptSummary/失败重试提示→完成后被 output_video 替换）。
3. `ChatAssistantMessageContent.vue`：三块分支；`ChatToolEvent.vue`：toolLabel（视频生成/语音合成）+ 阶段文案。
4. 任务轮询：消息列表层扫描未终态 `output_media_task` 块，5s 间隔轮询（页面不可见暂停），块级状态就地更新（SSE 外的渐进通道，与既有轮询退避模式一致）。
5. `ChatToolBindingDialog.vue`：toolTitles + 两区段。
6. 回归脚本锚点更新（tool-preferences/message-process/composer 系按需）。

## 6. Mock 与可播放载荷

1. **视频**：mockupstream 的 MP4 载荷升级为**真实可播放**最小 MP4（带 moov/mvhd/trak 的 H.264 黑屏或纯色 1-2 秒；实现方式：预制字节常量嵌入——ffmpeg 生成或已知最小模板，落库前用文件头/ffprobe 校验；M2 的 ftyp+mdat 占位载荷仅 magic bytes 断言用，E2E 沿用不破坏——**chat 场景用新载荷**，`/v1` 域 E2E 断言不变）。
2. **音频**：既有合成 WAV（RIFF+静音）已可播放，直接复用。
3. 隔离实例全链路：mock 账户（base_url→mockupstream `media_video_ok_poll3`/`media_tts_ok`）+ 会话绑定 → 主模型（mock chat 场景驱动 function calling——读既有工具 E2E 的主模型 mock 驱动方式）→ 任务块→轮询→结算→播放器。

## 7. 测试与验收

1. 单测/链级：两工具执行、候选收敛、任务结算幂等（并发两请求一资产）、MIME/限额。
2. E2E（acceptance 或 chain 级 fixture）：视频全链（任务块→poll→completed→资产字节数>0 且 MP4 头 moov）、音频全链。
3. **隔离实例人工验收 + 截图**（按 AGENTS.md 隔离规范）：问答页发"生成一段视频"→任务卡→完成后播放器可播放（截图核对布局/尺寸/暗色模式）；音频同；据此调 UI 细节（播放器宽度、任务卡样式、加载态）。
4. 回归：既有 12+2 E2E 与 40 个 chat 回归脚本零回归（锚点按需更新）。
