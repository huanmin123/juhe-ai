# 统一模型能力与计费抽象设计

> 状态：跨供应商能力字符串、明确 wire 映射与字段保护、数据库唯一价格源、管理员改价和 usage 计价快照已实现；供应商计费公式和目录展示已由 [供应商独立计费与模型目录展示设计](供应商独立计费与模型目录展示设计.md) 接管。本文件中的“统一”只指能力字段透传、美元结算结果和历史快照，不再指统一供应商计费规则或统一目录栏目。
>
> 调研基线：2026-07-14。
>
> 本文只保留三类公共边界：服务等级与思考字段不能被错误过滤；模型当前价格只在模型目录由管理员维护；历史 usage 固化美元成本快照。模型目录如何展示、usage 如何解释和费用如何计算由供应商策略分别负责。

## 当前实现边界

- PLAN-0137 目标：GPT 账户覆盖按全部已选模型能力合集提供选项，不再运行时向下选择；最终模型精确支持配置值时才逐字段生效，不支持或能力未知时保留对应客户端字段。GPT API Key 与 OAuth 使用同一能力规则。既有 Responses -> Chat 和受支持 bridge 继续按自身映射能力保留或明确拒绝服务等级 / 思考字段；usage 固化 requested / effective / reported / billed 与成本快照、删除系统设置中的 GPT Priority / Flex 通用倍率均已完成。
- 已完成：无法安全映射的重建型 bridge 对受保护字段返回明确 `400`，不再静默丢弃。
- PLAN-0137 目标：非 GPT 文本模型继续保存供应商原生能力字符串；账户覆盖控件按已选模型能力合集显示，供应商支持该配置区但当前没有可选能力时仍显示禁用控件和中文原因。Anthropic `service_tier=auto|standard_only` 与 `speed` 只在原生 Messages 同协议路径透传，不映射为本站 `priority` / `flex`；`output_config.effort` 按模型能力处理。Gemini 使用原生 `service_tier` 与 `generationConfig.thinkingConfig.thinkingLevel`。Anthropic / Gemini thinking budget 仅原样保护，DeepSeek / GLM 不虚构档位或 effort。
- 已完成：`serviceTierPrices`、内置模型管理员改价、Node 数据库目录计价，以及 SQLite / PostgreSQL / Go / 前端和一次性迁移闭环。普通用户提交价格字段会被拒绝，目录同步不会覆盖管理员价格。

## 1. 最终结论

首版直接复用当前模型目录、账户覆盖字段和 usage 价格快照，不新建平行体系：

- 模型身份继续使用现有模型行 `id`；业务查找仍按 `providerCode + model`。
- 模型能力继续使用现有服务等级、思考级别和默认思考级别三个可选字段，只把值域从 GPT 枚举改成供应商自己的字符串；没有这些概念的供应商不生成对应目录分组。
- 账户继续只有服务等级覆盖和思考级别覆盖两个可选字段，不增加通用 request policy、账户权益表或动态 control。
- 归一后的美元价格直接保存在现有模型目录行；这些可选字段是存储载体，不构成跨供应商统一计费公式。供应商 billing policy 独立选择适用价格并生成费用行。
- 历史计费继续使用 usage 已有的 `cost_breakdown_snapshot_json`，不增加价格版本、计费行表或多份 attempt 快照。
- GPT Priority / Flex 通用倍率从系统设置删除；缺少精确档位价格时标记未定价，不再运行时套倍率。

不引入以下内容：

- `catalogModelId` / `catalogSurfaceId` 新身份体系。
- 独立账户权益层。
- pricing profile / rate / purpose / selector 表。
- provider cost、local quota 和 product credits 三套价格。
- 在线 FX、价格 revision、草稿、预览、发布或历史价格接口。非美元官方源价允许随模型事实保存固定汇率快照，但请求运行时禁止在线换汇。

## 2. 模型目录字段

### 2.1 复用现有能力字段

```ts
interface ProviderModelCatalogItem {
  id: string
  providerCode: string
  model: string
  supportedApiProtocols: string[]

  // [] = 未声明可选值；非空 = 支持值
  supportedServiceTiers: string[]
  supportedReasoningEfforts: string[]
  defaultReasoningEffort?: string

  // 标准价继续使用现有扁平字段
  inputUsdPer1M?: number
  outputUsdPer1M?: number
  serviceTierPrices?: Record<string, ModelPriceSet>
}
```

规则：

- 值只在当前供应商内解释，不跨供应商比较同名的 `priority`、`fast` 或 `high`。
- 前端根据 `providerCode` 集中格式化中文标签，不在模型 ID 上猜能力。
- `supportedApiProtocols` 已经能表达 Chat、Responses、Messages、GenerateContent 和 Batch 等入口；首版不再拆 surface 实体。
- 某个端点是否真正接受该值，仍由目标 provider driver 校验。
- Anthropic `speed`、Gemini / Anthropic thinking budget 等原生字段会进入白名单保护，但首版不增加对应账户覆盖控件；有真实配置需求时再单独增加。

### 2.2 账户覆盖

现有 GPT 两个覆盖字段改成供应商通用字段：

```ts
interface AccountRequestOverrides {
  service_tier_override?: string
  reasoning_effort_override?: string
}
```

- 字段缺失：保留客户端原值。
- 只有 `service_tier_override=default` 表示删除客户端服务档位并使用供应商默认。
- `reasoning_effort_override` 没有 `default` 哨兵；它和其他服务档位值必须至少属于账户一个已选模型声明的可用值，保存选项取已选模型能力合集。
- provider driver 负责把统一值写成自己的 wire 字段。
- 不增加独立 revision；账户继续使用现有配置版本和保存流程。
- 运行时在最终上游模型和目标协议确定后逐字段校验精确值；支持时写入，不支持或能力未知时不改写该客户端字段，不替换成较低值，也不把账户整体判为不可用。
- 不建立账户权益 registry。账户保存校验只接受已选模型能力合集中的值；上游套餐是否真正可用仍由上游响应表达，GPT API Key 与 OAuth 不做本地 Flex 差异化限制。

## 3. 服务等级与思考级别字段白名单

“白名单”只保护下面两类字段，不扩大成全请求字段治理：

| 类型 | 常见原生字段 |
| --- | --- |
| 服务等级 | `service_tier`、`speed` |
| 思考级别 | `reasoning.effort`、`reasoning_effort`、`thinking`、`thinkingConfig`、`budget_tokens` |

实现规则：

1. 将对应原生字段加入 OAuth normalizer、客户端画像、模型映射和 bridge 的现有允许列表或转换逻辑。
2. 同协议路径保留客户端原值；配置了账户覆盖时才替换对应值。
3. 跨协议只有存在明确映射时才转换；无法映射时返回目标 driver / bridge 现有的 `400`，不能静默删除。
4. 用 mock upstream 回归确认最终请求包含这些字段。

最终模型不支持或未声明账户覆盖值时不再返回 `account_request_override_unsupported`，而是逐字段保留客户端原值。重建型 bridge 无法安全映射客户端已有受保护字段时，仍返回目标 driver / bridge 的既有明确 `400`；两者不能混为同一错误路径。不增加通用请求保护层或新的全局错误码。

usage 沿用现有 `requested / effective / reported / billed` 标量字段；只把类型从 GPT 固定枚举改成供应商字符串。最终 serialized 值只进入调试日志，不再新增 usage JSON。

## 4. 供应商调研结果

| 供应商 | 服务等级 | 思考级别 | 首版处理 |
| --- | --- | --- | --- |
| OpenAI | `service_tier`，包含标准、Priority、Flex 等供应商值 | `reasoning.effort` | 填入现有两组模型能力；支持账户覆盖和精确档位价格 |
| Anthropic | 原生 `service_tier=auto|standard_only`；另有 `speed=fast`，均不等价于本站 `priority` / `flex` | thinking mode、effort、`budget_tokens` | effort 按模型进入目录；service tier、speed 和 budget 只做同协议字段保护，不进入本站通用服务等级控件；上游报告的非标准实际档位只有具备模型级精确价格时才可计费 |
| Gemini | 原生 `service_tier=priority|flex`；Standard 省略或使用 `standard` | thinking level 或 thinking budget | level 可进入目录并映射；budget 只做字段保护；服务档位必须具备模型级精确价格后才开放 |
| DeepSeek | 当前没有请求级服务档位，Flash / Pro 是模型 SKU | 主要是 thinking 开关 | 目录不声明服务档位；不虚构 reasoning effort |
| 智谱 GLM | 当前没有请求级服务档位 | thinking 开关，部分模型有 effort alias | 目录不声明服务档位；只录入已核验 effort |

请求值和实际计费值不能强制相同。例如 Anthropic 原生 Messages 请求可以透传 `speed="fast"`，响应通过 `usage.speed` 报告实际速度；这不代表本站通用请求控件应展示 `fast`。计费只读取 provider driver 归一后的实际 `billed_service_tier`，并要求模型目录中存在该档位的精确价格。

本表是目录录入依据，不表示首版必须给所有原生字段增加账户配置项。

## 5. 模型目录美元价格载体

### 5.1 一行模型保存当前美元结算价

不增加价格表。现有 `provider_model_catalog` 和 `custom_provider_models` 模型行直接保存当前价格。

标准 input、output、cache、image、audio 等可选字段继续作为当前已支持费用维度的 USD 存储载体；它们不能驱动一套跨供应商万能公式。`serviceTierPrices`（数据库为 `service_tier_prices_json`）只保存供应商明确公布的非标准档位或 Batch 价格；是否属于请求级档位、怎样选择和怎样展示由供应商 billing policy 判断：

```ts
interface ModelPriceSet {
  inputUsdPer1M?: number
  outputUsdPer1M?: number
  cachedInputUsdPer1M?: number
  cacheWriteUsdPer1M?: number
  cacheWrite1hUsdPer1M?: number
  imageInputUsdPer1M?: number
  imageOutputUsdPer1M?: number
  audioInputUsdPer1M?: number
  audioOutputUsdPer1M?: number
  outputUsdPerImage?: number
}

type ServiceTierPrices = Record<string, ModelPriceSet>
```

- `supportedServiceTiers` 只驱动请求控件；`serviceTierPrices` 保存供应商价格变体，不要求所有 key 都是请求级服务等级。
- provider driver 复用协议 usage parser 的原始观察值，再由供应商 billing policy 把实际档位、缓存、长上下文和模态数量解释成美元费用行。公共层不得按字段名自动回退标准价。
- 标准价和长上下文规则继续使用现有扁平字段，不增加 `pricing.standard` 包装层，也不改现有 GET / PATCH 的整体结构。
- 非标准 `billed_service_tier` 没有精确档位价格时返回未定价，不能套系统倍率或相似模型价格。
- 免费价格明确保存为 `0`；缺失字段表示没有价格，两者不能混淆。
- 结算币种固定 USD。官方源价不是 USD 时，在目录录入阶段保存原币、固定汇率、汇率日期和来源说明并生成 USD 单价；请求期间不访问汇率服务。
- Codex Fast credits、订阅成本和预留容量不属于本次模型 API 价格，等有真实计费需求时另做。

### 5.2 保存方式

复用现有模型目录 GET 和模型 PATCH：

- 模型目录 GET 直接返回现有扁平价格字段和 `serviceTierPrices`，不新增单独 pricing GET。
- 管理员可以在模型目录页面保存该模型完整价格。
- 内置模型只开放价格字段更新；模型身份和官方能力仍由目录维护。
- 普通用户以及模型普通创建 / 编辑、账户、API Key、分组和路由策略不能提交价格字段；管理员通过同一模型 `PATCH` 的价格分支可给内置、全局或个人模型定价。
- 后端同步校验后直接更新当前模型行，记录普通操作审计并失效现有模型目录缓存。
- 官方目录同步只更新模型事实，不能覆盖管理员价格。

管理员操作仍然只有“编辑 -> 保存”，保存后立即生效。

### 5.3 运行时唯一价格源

SQLite 与 PostgreSQL 的模型目录现在都是 Node 运行时唯一价格源：

```text
provider_model_catalog / custom_provider_models
  -> 现有模型目录缓存
  -> 现有成本计算
```

SQLite 轻量模式使用同概念的 `provider_model_catalog` 表，不建立价格域表。静态 TypeScript 数据只用于初始化空目录和离线目录生成，不参与请求计价；目录生成器只维护模型事实和初始部署数据，运行后的管理员价格不会被自动同步覆盖。

## 6. usage 与历史价格

现有 usage 已经具备所需结构：

- `requested_service_tier`
- `effective_service_tier`
- `reported_service_tier`
- `billed_service_tier`
- `requested_reasoning_effort`
- `effective_reasoning_effort`
- `cost_usd`
- `cost_breakdown_snapshot_json`

`cost_breakdown_snapshot_json` 已用于固化记录写入时可得的计价事实：目录命中时保存实际单价、各项金额、总金额和档位价格来源；目录未命中时保存 `unknown` 及当时已有的金额。继续复用它：

1. 请求使用当前缓存中的模型价格，并按 `billed_service_tier` 选择实际档位价。
2. 按现有路径在入队或写库前生成价格快照。
3. 历史详情读取已保存的快照，统计 worker 只聚合 `costUsd` 等现有标量；两者都不用当前目录重新计价。

不新增 attempt price snapshot、billing line item、billing engine version、price revision 或 worker 计费表。当前一条真实上游调用对应一条 usage 的记账方式保持不变。

本地额度和统计继续使用现有 `costUsd / total_cost_usd`，不增加第二套本地售价。

## 7. 前端

模型目录不再固定服务等级、思考级别、计费、缓存或容量列。Node 的供应商 billing policy 根据当前模型事实生成 `catalogDisplay` 分组，前端只负责格式化和响应式布局：

- 桌面表格取当前供应商、当前模型分类实际分组的并集生成列。
- 移动卡片按模型返回的非空分组顺序渲染。
- 空能力不显示“仅标准”“不支持”“不适用”或“官方未公布”等补齐占位。
- Anthropic 缓存写入、Gemini Token·小时存储费和 xAI 长上下文倍率保持供应商原生分组；GLM 当前只保留 4.5 及更新系列，不生成 Batch 或美元换算列。
- 管理员只有在管理入口看到价格编辑区域；普通用户可查看价格事实但不能提交价格。

账户页面继续使用现有两个覆盖控件，将 GPT 限制改成按供应商和模型目录能力显示。支持该配置区的供应商即使当前没有可选值也保留控件，以禁用态和中文说明表达“当前已选模型未声明能力”；不动态生成其他控件，也不因能力变化静默清空已有配置。

## 8. 当前代码需要改的地方

### 8.1 字段过滤

普通 API Key raw body、同协议模型改名和多数供应商 native 路径不会过滤这两类字段。风险集中在：

- GPT OAuth normalizer 会删除部分 `service_tier`；`/responses/compact` 会删除 `reasoning`。
- GPT 覆盖只在最终模型精确支持配置值时生效；不支持或能力未知时逐字段保留客户端原值。
- Responses -> Chat 以及 OpenAI / Anthropic / Gemini bridge 重建 body 时可能漏掉服务等级或思考字段。

只修改这些 normalizer、override 和 bridge，不扩展普通未知字段处理。

### 8.2 模型目录和价格

- 删除 Node、Go 和前端对“只有 GPT 才能配置两组能力”的限制。
- 将两组能力值类型从 GPT 枚举改为供应商字符串。
- 模型目录 GET 返回数据库现有 built-in 模型行 `id`；管理员价格 `PATCH` 固定使用该 `id`，不增加第二种寻址方式。
- 补齐 Node / 前端缺少的档位价格 DTO。
- Node 网关改为读取现有数据库模型目录缓存，不再读取静态价格数组。
- 删除系统设置里的 GPT Priority / Flex 通用倍率。

## 9. 实施顺序

1. 泛化现有三项模型能力字段和前端两列，不新增 capability schema。
2. 泛化现有两个账户覆盖字段，不新增 request policy 或权益表。
3. 补齐 OAuth、模型映射和 bridge 的两类字段保护。
4. 在现有模型行保存完整当前价格，并让 Node 网关改读数据库目录缓存。
5. 删除 Priority / Flex 系统倍率和 GPT 专属展开价格列。
6. 继续使用现有 usage 价格快照和统计字段。

## 10. 验证

- 五家供应商的两组模型能力可按“无可选值 / 支持值”展示。
- 账户覆盖显示所选模型声明能力的合集，未知模型不清空已知模型能力；GPT API Key 与 OAuth 对 Flex 使用同一规则。
- 两类原生字段在支持路径的 mock upstream 中可见。
- 最终模型不支持账户覆盖值时保留对应客户端字段；重建型 bridge 无法映射客户端已有受保护字段时仍得到现有明确 `400`，不能静默删除。
- 普通用户提交价格字段被拒绝，管理员保存后新请求立即使用新价格。
- 管理员改价后，历史 usage 的单价和金额保持不变。
- Node / Go / 前端不再读取 GPT 通用倍率。
- 统计 worker 继续只聚合现有 `costUsd` 等标量。
