# 供应商独立计费与模型目录展示设计

## 1. 目标

- 模型调用成本统一以美元结算，但不把不同供应商的计费语义强行映射成同一套规则。
- 每个供应商分别解释自己的 usage、价格档位、缓存、长上下文、多模态和按次费用。
- 模型目录只展示当前供应商、当前模型真实存在的字段，不用“仅标准”“不支持”“不适用”等固定占位补齐统一表格。
- 本设计只覆盖 Node.js 后端和 Vue 前端；`backend-go/` 正在由其他工作迁移，不属于本轮实现、验证或文档同步范围。

## 2. 核心边界

### 2.1 统一的是结算结果，不是计费规则

公共结算层只负责三件事：

1. 接收供应商计费策略生成的美元费用行。
2. 汇总 `costUsd` 并生成不可变的历史成本快照。
3. 向额度、统计和使用记录提供稳定的美元金额。

公共层不得自行决定缓存 Token 是否包含在输入 Token 中、某个档位如何取价、长上下文从哪个边界生效、图片按 Token 还是按张计费，也不得把未知厂商字段按名称猜成既有费用。

### 2.2 供应商 driver 拥有计费语义

每个供应商计费策略独立负责：

- 解释该供应商或协议解析后的 usage 维度。
- 选择标准价、供应商档位价或长上下文价格。
- 生成该供应商实际存在的费用行。
- 声明无法从单次请求 usage 精确结算的项目。
- 生成模型目录使用的供应商计费展示分组。

允许多个策略复用无业务含义的算术工具，例如“Token 数乘美元单价”和“小数舍入”；不得复用包含厂商假设的万能计费函数。

### 2.3 模型价格使用可选字段超集，不等于统一计费

数据库和 API 可以继续使用可选字段超集承载当前已支持的美元单价。字段缺失只表示该模型没有该计费维度，不能自动回退、补零或复制其他字段。

供应商策略只读取自己明确支持的字段。例如：

| 供应商 | 供应商策略负责的主要维度 |
| --- | --- |
| OpenAI | 输入、缓存读、缓存写入、输出、Priority / Flex、多模态 Token、按张图片 |
| Anthropic | 输入、输出、缓存读、5 分钟缓存写入、1 小时缓存写入 |
| Gemini | 输入、输出、cached content、缓存存储时费、Flex / Priority、音频输入、长上下文 |
| xAI | 输入、缓存输入、输出、Priority、200K 长上下文倍率、按张图片 |
| DeepSeek | 输入、输出、cache hit / miss |
| GLM | 厂商公布的单一 Token 价或输入/输出价、缓存读；Coding Plan 套餐权益不冒充 API Token 价 |

## 3. 美元归一化

### 3.1 运行时只使用美元单价

- 模型目录中的可执行单价均为 USD。
- 上游以 CNY 等其他币种报价时，在目录录入或管理员保存阶段完成换算。
- 网关请求计费期间禁止访问汇率服务，避免性能、可用性和历史重算漂移。

### 3.2 非美元源价必须可追溯

非美元官方价格需要同时记录：

- 官方源币种。
- 固定的“1 源币种 = N USD”换算率。
- 汇率生效日期。
- 汇率来源与原始官方价格说明。

运行时使用归一后的美元单价；模型目录可以展示“已按固定汇率换算为 USD”，但不得把换算价描述为供应商官方美元报价。

当前内置 GLM 目录只保留 4.5 及更新系列，不包含需要单独人民币换算和 Batch 展示的 2025-04-14 旧模型。非美元源价的固定换算能力仍作为跨供应商架构边界保留，但没有实际目录数据时不生成展示列。

## 4. Node 计费架构

### 4.1 输入与输出

协议 usage parser 继续保留上游事实字段并归一到已知用量维度。供应商计费策略接收：

- 实际供应商和实际上游模型。
- 供应商报告或最终确认的档位。
- 归一化 usage 数量。
- 当前模型目录中的美元价格事实。

策略输出由若干费用行和供应商计费元数据组成。每一行至少包含稳定 key、中文标签、数量、单位、美元单价和美元小计；公共层只求和并写入 `ProviderCostBreakdown`。

### 4.2 当前供应商规则

- Anthropic 的 input usage 不按 OpenAI 的 cached input 包含关系处理；缓存写入 5m 和 1h 分别计价。
- Gemini 缓存存储按 Token·小时计费，但当前单次请求 usage 没有稳定的存储持续时间，因此目录展示该费率，单请求成本不虚构存储费用。
- xAI 的长上下文阈值和 Priority 由 xAI 策略应用，不进入其他供应商默认逻辑。
- DeepSeek 和 GLM 只计算厂商实际报告、目录有明确美元价格的维度。
- 图片、音频或工具费用只有在 usage 能提供对应数量且目录存在精确单价时才进入成本；否则明确保持未计价，不按文本 Token 猜测。

### 4.3 历史与失败语义

- `cost_breakdown_snapshot_json` 继续保存请求发生时的美元费用行和合计，后续汇率或目录价格变化不得重算历史。
- 已产生某项用量但供应商策略没有对应价格时，该请求保持未定价，不能使用相似模型、其他供应商或基础输入价格回退。
- 上游直接返回可信总成本时可以记录为账户实际成本，但仍需保留本地可确认的费用行和来源。

## 5. 模型目录展示

### 5.1 公共信息

模型名、范围、状态、发布时间、接口协议和操作属于目录公共信息，可以保持公共布局。

### 5.2 按需分组

计费、缓存、服务档位、思考能力、容量和多模态信息由 Node 根据供应商策略和模型事实生成展示分组。每个分组只包含真实存在的条目：

同一能力概念使用统一中文栏目标题，例如各供应商的 Reasoning / Thinking 统一显示为“思考能力”；栏目内只保留供应商原始支持参数值，不展示默认思考级别，也不翻译或改写 `low`、`medium`、`high` 等 wire 值。`none` 表示关闭推理，不属于思考级别，因此不在目录的“思考能力”中显示，但底层参数能力仍可保留。

- Anthropic 可以在“Token 计费”内显示输入、输出、缓存读和 5m / 1h 缓存写入。
- GPT / OpenAI 的“Token 计费”按官网模态明确显示文本输入、文本缓存读、图片输入、图片缓存读和图片输出，不再单列“多模态计费”；只有按张图片等不同计费单位按需单列。当前未实现专用音频模型调用链，目录和自定义模型用途均不提供音频 Tab。
- Gemini 的“Token 计费”合并输入、输出、缓存读、缓存存储、图片 / 音频 Token 价格，以及 `> 200K` 长上下文的实际单价；多模态与长上下文不单列。Flex / Priority 与容量按需显示。
- xAI 的“Token 计费”合并普通输入、缓存读、输出，以及 `>= 200K` 长上下文的实际单价；长上下文不单列。xAI 没有公开缓存写入单价时，不生成缓存写入项。Priority 和图片生成按需单列。
- DeepSeek 将官方 `Cache miss` 归一显示为“输入”，将 `Cache hit` 归一显示为“缓存读”。
- GLM 可以显示“Token 计费”“缓存读”“容量”。

桌面表格根据当前模型集合实际存在的分组生成列；移动卡片按返回顺序渲染分组。空分组不生成列，也不显示占位文案。

前端只负责 USD、Token、倍率和文本格式化，不复制供应商计费判断。

## 6. 完成条件

- Node 计费入口明确委派给供应商策略，公共层不再包含跨供应商的万能价格选择规则。
- 至少覆盖 OpenAI、Anthropic、Gemini、xAI、DeepSeek、GLM 的代表性计费回归。
- 非美元源价具备固定汇率元数据，运行时没有联网汇率依赖。
- 模型目录桌面和移动端只展示实际分组，不再为所有文本模型固定展示服务等级、思考级别或缓存附加费。
- 前后端类型检查、构建、模型目录回归和隔离浏览器验证通过。
- 本轮没有修改或验证 `backend-go/`。
