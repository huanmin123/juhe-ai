# 使用手册页面设计

> 状态：第六版已落地（供应商参数透传与差异两篇）。
> 本文定义在线帮助的访问边界、内容架构、篇目清单和维护验收，不替代正式协议或后台功能文档。

## 1. 目标与非目标

- 目标：让最终用户从零跑通每一类网关协议（chat / SSE / responses / 视频 / TTS / 转写 / realtime / images / embeddings），每篇文档讲明白一件事；让管理员按资源域分篇完成账户接入、路由治理、授权、观测与运维。
- 目标：**Markdown 是帮助内容的唯一人工维护层**；页面渲染物与"下载为 Markdown"产物都由它派生，源与生成物同库、回归钉一致（与 maintenance 种子生成器同模式）。
- 目标：小白视角写作——每篇固定结构（这一篇解决什么 → 准备条件 → 分步操作 → 参数表 → 完整示例 → 常见错误 → 接下来），示例可复制运行。
- 非目标：不把 API Key 明文、OAuth token、上游凭据、代理密码、原始审计 payload 或完整账户导入协议放入帮助页；不做全文检索引擎；不新增帮助内容后端接口。

## 2. 页面路径与访问控制

静态资产位于 `frontend/public/help/`，构建后由系统前缀暴露：

| 路径 | 用途 |
| --- | --- |
| `/__aisys__/help/` | 确认登录态后进入唯一手册（`help-gate` 页）。 |
| `/__aisys__/help/user/` | **《使用手册》唯一入口**（28 篇，hash 路由 `#/doc/<id>`）。 |
| `/__aisys__/help/admin/` | 同一份手册壳（旧书签兼容；helpweb 保留管理员角色校验）。 |

手册不区分管理员/用户角色门槛：26 篇对全部登录用户可见，按「接入与调用 / 管理运维」两个分区组织。

- 后端在通用静态资源之前校验 `/__aisys__/help/*` 登录态（`internal/helpweb/`）；未登录跳转 `/__aisys__/login?redirect=原始帮助路径`；普通用户访问 admin 路径跳回 user。本改版未改任何后端代码。
- 顶部帮助入口（`AppLayout.vue` `openHelp()`）按角色在新页面打开对应文档站。

## 3. 内容架构（Markdown 单一数据源）

```
frontend/public/help/
├── index.html            # 登录态门控页（确认登录后进入唯一手册）
├── help.css / help.js    # 文档站样式与交互（零依赖，无内联脚本）
├── manifest.json         # 篇目清单 v2：sections{接入与调用, 管理运维}→docs
├── docs/                 # ★ 唯一人工维护层：user/ 18 篇 + admin/ 8 篇 Markdown
└── rendered/             # 生成物（入库，Code generated 头，DO NOT EDIT）
```

- 渲染器 `frontend/scripts/render-help-docs.mjs`（marked + GFM；原生 HTML token 一律剥离）：`npm run render:help` 重渲染；`--check` 校验源与生成物一致，由回归测试调用。
- 篇目 id 即 hash 路由锚点；`manifest.updatedAt` 驱动页面"更新于"徽标，内容变更时同步更新。
- 下载：每篇正文右上「下载 Markdown」为同源静态直链（`<a download>`），Content-Type 为 `text/markdown`，无转换层。

### 3.1 篇目清单（单一手册，26 篇）

「接入与调用」20 篇（`docs/user/`）：01 快速开始 / 02 API Key 与认证 / 03 模型列表 / 04 chat completions / 05 流式 SSE / 06 Responses / 07 视频生成 / 08 TTS / 09 语音转文字 / 10 Realtime / 11 图像与嵌入 / **16 协议总览 / 17 Anthropic 原生 / 18 Gemini 原生 / 19 供应商参数怎么传（透传规则+provider_options 通道）/ 20 各供应商参数差异速查（九家逐家+思考级别字段对照+跨协议限制）** / 12 错误码与排障 / 13 核心概念 / 14 用量与统计 / 15 FAQ。

「管理运维」8 篇（`docs/admin/`）：01 快速上手 / 02 AI 账户与供应商接入 / 03 分组与路由策略 / 04 模型目录与模型检测 / 05 授权与团队（含代用户导入）/ 06 观测：日志与统计 / 07 系统设置与日常运维 / 08 风险操作与排障。

### 3.2 内容契约（硬性语义）

- **深链资产**：旧手册 17 条用户页深链（`(/my-*)` 形态）与 28 条管理页深链（`(/__aisys__/*)` 形态）必须全部出现在对应受众篇目中。
- **AI 问答**：站内 AI 问答使用系统维护的专属对话 Key，走与客户端相同的网关链路；不得写成客户端 API Key 的验证入口。
- **账户状态**：`active` 是进入候选的必要条件，不保证当前一定可调度。
- **代用户导入**：仅接受 `juhe-ai-account-import v1` JSON；`active` 导入创建为 `pending_test`；限额等语义见 admin-05。
- **分组**：保存 `providerCode`，既是账户集合也是供应商过滤边界；复制策略需求应新建同配置策略再绑定 API Key。
- **协议事实**：端点/参数/错误码以实现为准（认证 Bearer、`/v1/videos` 异步任务机、`/v1/audio/speech` 同步、`/v1/audio/jobs` 以 `input_url` 为唯一输入、realtime 两步握手、统一 `{"error":{message,type,code}}` 信封）；实现没有的能力不写。

## 4. UI 与可访问性

- 设计语言与主应用一致：`#f5f7fb` 页面底色、白色卡片、Ant Design 蓝、`/__aisys__/brand-icon.svg`（加载失败回退文字徽标）。
- 文档站布局：sticky 顶栏（品牌/搜索/控制台入口/更新时间）+ 左侧篇目导航（manifest 驱动，当前篇 `aria-current`）+ 右侧正文卡片（标题/简介/下载按钮/渲染正文/上下篇翻页）。
- 搜索：篇目标题+简介前端过滤；`Enter` 打开首篇；`Esc` 清空；状态经 `aria-live` 播报。
- 正文加载经 `aria-busy` 播报；渲染产物不得包含 `<script>` 或内联事件（回归钉住）；页面壳无内联脚本（CSP `script-src 'self' 'unsafe-inline'`）。
- 平板宽度（≤900px）切单列；`prefers-reduced-motion` 降级。

## 5. 维护与验证

- 新增/调整篇目：改 `docs/**/*.md` → 更新 `manifest.json`（含 updatedAt）→ `npm run render:help` → 同步本设计文档。
- 调整路由、权限、导入语义、链路或页面入口时，同步更新对应篇目与本设计文档；字段与默认值以 `frontend/src/views/` 实际表单和功能文档核对，不复制过期数字。
- 协议篇的参数表变更（端点、字段、错误码）先核对 `docs/functions/` 权威设计文档（音频视频模型接入与统一媒体网关设计.md、实时语音Realtime网关设计.md 等）再动笔。
- 回归 `frontend/src/scripts/regression/help-content-regression.ts` 固定：渲染物一致性（--check）、23 篇 manifest/h1/存在性、17+28 深链覆盖、AI 问答与导入/active/分组语义、页面壳与下载属性、渲染产物无脚本、样式与构建契约（helpPageDirectoryIndexPlugin、dev 不代理 help）。
- 执行 `npm run test:help-content`；随前端改动执行类型检查和构建。
