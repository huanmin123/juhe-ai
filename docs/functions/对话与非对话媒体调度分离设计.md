# 对话与非对话媒体调度分离设计

> 状态：目标设计，尚未实施（2026-10-18）。
>
> 本文回答一个边界问题：文本对话需要会话连续性和上游上下文复用，图像、音频、视频请求没有这个需求，不应继续共享文本调度的会话亲和、缓存率排序和复杂恢复状态。本文是媒体调度策略的目标契约；媒体协议、任务字段和受理边界仍以《音频视频模型接入与统一媒体网关设计》和《媒体上游协议契约与Mock上游规格》为准。

## 1. 设计结论

网关保留同一条认证、权限和上游传输基础设施，但在调度策略上分为两个域：

| 调度域 | 请求范围 | 主要目标 |
| --- | --- | --- |
| `ConversationDispatch` | Chat、Responses、Messages、Gemini 对话 | 保持会话连续性，尽量复用上游上下文和账户内 Key |
| `StatelessMediaDispatch` | 图像、同步音频、视频创建、长音频创建 | 快速找到一个可承接账户；失败时按受理边界有限换号 |

Realtime 不归入本文的媒体创建域。Realtime 是连接生命周期能力，单独遵循《实时语音Realtime网关设计》；不能因为它使用音频就把它当作普通音频请求。

“非对话无缓存”指不使用上游上下文缓存、会话亲和、缓存率排序或会话级避让。API Key、分组和账户快照的运行时缓存仍可保留，它只用于减少配置读取，不改变选号语义。异步任务的 `media_jobs` 也不是响应缓存，而是继续轮询、下载和取消时定位原账户所需的业务事实。

## 2. 当前实现与目标差异

当前媒体请求已有独立 `audio` / `video` lane，但创建请求仍进入通用 preflight 和 `v1DispatchLoop`：

- preflight 仍可能从客户端会话身份生成 `SessionAffinityKey`，并在满足条件时查询 `GroupAffinityKey`；
- 候选准备仍调用账户亲和排序、claim 和成功写回；
- 媒体只跳过了部分文本能力，例如速度优先、热质量和同账户瞬态重试；容量等待、恢复等待、账户锁、熔断和跨组回退仍共享；
- 图像当前不属于 `audio/video/realtime` 的媒体跳过集合，仍可能进入文本热质量排序；
- 视频和长音频的任务面已经按 `media_jobs.account_id` 直连原账户，这部分应继续保留。

目标是把媒体创建从“通用对话循环中关闭几个开关”改成明确的 `StatelessMediaDispatch` 策略入口。底层认证、模型能力过滤、并发槽、HTTP 传输、provider adapter 和 usage 结算继续复用。

## 3. 非对话创建调度

### 3.1 路由目标

非对话请求仍使用 API Key 绑定的路由策略完成授权和目标组选择，但每次请求只生成一份静态路由快照：

组候选快照沿用《策略路由设计》现有的路由模式、绑定顺序、权重/轮询状态、超级分组成员展开、direct/mapping 候选层级和实际成员组记账规则；媒体只移除文本动态排序维度，不另造一套路由排序契约。

1. 普通路由只使用唯一绑定组。
2. 故障回退按绑定顺序生成组候选。
3. 权重和轮询只在本次请求选择组时生效，不读取或写入会话绑定。
4. 超级分组只在当前请求展开成员组，不产生新的会话亲和层。
5. 候选快照生成后，不因某个账户失败重新读取路由状态或重新推进权重/轮询状态。

这样保留现有路由拓扑语义，同时避免媒体请求在多次失败后进入组级会话恢复循环。

### 3.2 账户候选

在静态组快照内，按以下顺序处理：

1. 模型、协议、endpoint mode、授权、账户状态、冷却和额度硬过滤；
2. 按 lane 独立并发限制过滤或排队；
3. 沿用现有账户候选比较器的账户配置优先级和稳定收尾顺序，不新增媒体排序字段；
4. 每个物理凭据（账户 + API Key）在当前请求最多尝试一次；同一账户的兄弟 API Key 只有在现有显式 `retry_next` 规则授权且通过安全重放门禁时才可继续轮换。

媒体请求不参与以下文本调度维度：

- `SessionAffinityKey`、`GroupAffinityKey`、账户内 API Key 会话亲和；
- 上游缓存率、热质量、`latency_degraded` 和速度优先；
- 同账户语义重试、Codex 上下文恢复、流式服务端重试；
- 客户端来源级失败避让和长时间 `recoverable wait`。

账户快照缓存可以继续使用，但缓存命中不改变候选优先级，也不写入任何媒体会话状态。

### 3.3 受理前后边界

媒体创建仍遵循“受理前可切换、受理后固定账户”，但“可切换”必须由现有统一错误契约和协议适配器共同确认，不能由 HTTP 状态码字面值直接推断：

| 请求形态 | 受理凭据 | 受理前 | 受理后 |
| --- | --- | --- | --- |
| 图像生成 | 上游成功响应头且响应形态可确认 | 下游尚未语义提交、且完整非 `2xx` 或已确认的未受理传输失败满足统一候选边界时，可尝试下一个候选；不得把 `401/403/429/5xx` 单独解释为某种账户语义。图片请求体已发送后的断连、timeout、未知失败和 `2xx` 正文中断按当前 attempt 终止，不切换 | 已收到成功头后不换账户；正文中断直接结束 |
| TTS/STT | 上游 2xx 响应头 | 下游尚未语义提交，且统一错误契约或 adapter 明确允许安全重试时，可尝试下一个候选；状态码本身不授权切换 | body 已开始透传后不换账户 |
| 视频/长音频创建 | `2xx + job_id` | 未拿到受理凭据且统一错误契约允许时尝试下一个候选；本地参数错误和确定性参数类 `400/413/422` 不切换，其他状态码不按字面值分类 | `media_jobs` 落行后永不换账户 |

本地参数错误和确定性参数错误（400/413/422）不换账户。收到 2xx 但无法解析出可靠 job id 时视为结果不确定，直接终止，不冒险向第二个账户重复创建。

## 4. 非对话恢复

恢复分为请求级、账户级和任务级三个最小边界，不引入文本会话状态机。

### 4.1 请求级

- 失败账户只加入当前请求排除集合；
- 不做同凭据自动请求体重放，不等待账户恢复，不重新排序已尝试候选；
- 同一账户的兄弟 API Key 仅在现有显式 `retry_next` 策略及安全重放门禁内，允许尝试尚未使用的兄弟 Key；未知媒体失败不能触发该轮换；
- 静态候选耗尽后立即返回最终错误，保留最后一个有意义的上游错误。

### 4.2 账户级

- 继续尊重账户已有的 `schedulable`、状态、冷却和 lane 并发硬门；
- 媒体请求不直接写入会话亲和、缓存率、热质量或 `latency_degraded`；
- 如需传输保护，只复用现有按 lane 隔离的基础 transport circuit，不引入文本的来源聚合、质量确认和恢复窗口；
- 音频、视频账户继续遵守现有健康检测边界：不因为一次用户请求自动启动文本探针；视频终态成功后的账户 CAS 恢复逻辑保持不变，长音频继续使用 `active-only` 规则。

### 4.3 异步任务级

- 创建成功后将 `account_id`、供应商、协议档案、上游 job id 和必要参数快照写入 `media_jobs`；
- 轮询、下载和取消只访问该记录指向的原账户，不重新走候选调度；
- 任务面瞬时上游失败（网络、timeout、完整非终态错误响应等）只返回当前错误，不换账户，也不把任务改成终态；本地任务状态保持可解释的 `queued/in_progress`，等待后续客户端轮询、取消或 retention 过期；
- adapter 明确返回 `completed`、`failed` 或 `cancelled` 时，才按现有任务状态机通过 `status NOT IN` 的条件更新收敛 `media_jobs` 终态；retention 任务显式置 `expired` 也沿用同一终态守卫。该条件只保证拒绝覆盖已终态化状态，不引入新的 `generation` 字段；
- 保留既有任务面协议例外：上游轮询 404 对非终态任务回显本地任务对象；`SupportsCancel=false` 直接本地收敛 `cancelled`；取消上游 404/405 也本地收敛；产物 404/410 继续返回 `media_artifact_expired`。
- 任务终态收敛默认不反向改变账户健康、会话亲和、Key 状态或候选排序；现有“视频任务 `completed` 后按账户生命周期 CAS 恢复账户”的窄例外继续保留，它是账户成功观测，不是媒体调度或会话状态。账户不可达只返回任务不可达错误。
- retention 只清理超期任务，不产生新的调度或计费事实。

## 5. 代码边界

实现时增加显式的调度域判断，不在现有文本循环中继续堆 lane 特判：

```text
ResolveDispatchDomain(request)
  -> ConversationDispatch
  -> StatelessMediaDispatch
```

`StatelessMediaDispatch` 的 preflight 结果必须满足：

```text
SessionAffinityKey = ""
GroupAffinityKey = ""
InteractionResourceAffinity = nil
```

媒体创建路径应使用独立的候选准备和受理前尝试循环，但复用以下基础组件：

- API Key 认证、配额和授权检查；
- 路由策略静态组快照；
- 模型和协议能力过滤；
- lane 并发槽和请求级超时；
- provider adapter、响应解析、usage 和审计元数据；
- `media_jobs` 创建、轮询、content、取消和 retention。

媒体创建不应进入以下对话专属出口：

- 组/账户/Key 会话亲和查询和写回；
- `resolveRouteAction` 的会话级跨组重入；
- `streamServerRetry`、Codex encrypted-content recovery；
- `recoverable wait`、账户锁重试租约和同账户 retry；
- 文本热质量结算和速度降级状态机。

## 6. 非目标与防过度设计边界

本文不新增媒体专用调度偏好、媒体专用前端开关、媒体专用缓存、媒体后台全量轮询或媒体资源存储。

第一版不新增账户级媒体质量分、媒体专用探针编排或新的持久化状态。只有现有 lane transport circuit 确实无法满足故障隔离时，才另立小范围设计；不能先为媒体复制文本恢复状态机。

第一版也不改变路由策略的四种配置模式、分组权限模型、媒体 adapter、计费口径和 `media_jobs` 表结构。

## 7. 实施顺序

1. 先以本文目标契约修订媒体调度和重试文档，标明当前代码尚未实施。
2. 在 preflight 统一由调度域决定是否解析/传递会话亲和键；媒体域直接清空三类亲和输入。
3. 新增媒体候选准备入口，复用硬过滤、并发槽和 adapter，不复用文本候选重排和恢复循环。
4. 将图像纳入非对话域，移除图像创建对文本热质量的依赖；保留图像独立并发和超时档位。
5. 将视频/长音频创建接入媒体受理前循环；任务面继续使用现有 `media_jobs` 直连路径。
6. 删除媒体创建路径对文本恢复状态的依赖后，再清理不再需要的参数传递和测试夹具。

## 8. 验收标准

- 带有 `conversationKey` 的图像、音频和视频创建请求不会产生 `SessionAffinityKey` 或 `GroupAffinityKey`；成功后也没有亲和写回。
- 媒体请求不会调用账户亲和 `Order/Claim/Remember/Forget`，不会进入热质量和速度降级排序。
- 单个媒体请求中每个物理凭据候选最多尝试一次，不发生同凭据自动请求体重放、长恢复等待或动态重排；显式 `retry_next` 规则仅在既有安全重放门禁内允许尚未使用的兄弟 Key 轮换。
- 受理前且被统一错误契约确认可安全重试的失败能按静态候选顺序切换；参数错误、图片请求体已发送后的 timeout/断连和未知失败不切换；受理后不切换。
- 视频/长音频任务创建成功后，轮询、content 和取消始终使用 `media_jobs.account_id` 对应账户；瞬时轮询失败不改终态，明确终态才按现有状态条件更新收敛。
- 现有运行时配置缓存仍可命中，但不会把缓存命中转化为媒体会话粘性。
- 对话请求的会话亲和、缓存率、速度优先、复杂恢复和跨协议兼容行为不变。
