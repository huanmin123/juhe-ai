# 系统指标统计设计

> 面向前端、后端与 AI 维护者。
> 本文是管理后台"系统指标统计"页面（管理员）的行为契约权威：页面三层信息架构、Go Runtime 指标接口契约、空态规则、env 契约与生产启用步骤。接口权限与通用错误语义以 [接口契约与权限矩阵](接口契约与权限矩阵.md) 为准。

## 目标

- 让管理员在一个页面看到当前部署两个 Go 进程的运行事实：进程状态（Gateway / Jobs 双卡）、Go Runtime 指标趋势（角色 × 指标组）与后台任务执行历史。
- 读取链路全部收敛在 gateway 进程内：gateway 自采样自身 runtime 指标并直查共享 Store 聚合 `go-runtime-trend`；浏览器不直连 jobs loopback，也不存在 Node 管理 API 同源转发（Node 后端已归档）。
- 采样自 2026-09-27 起默认开启（跟随主存储驱动），显式 `JUHE_AI_GO_RUNTIME_METRICS_STORE=disabled` 才关闭；关闭时页面给出恢复指引空态，不伪造空数据或全 0 曲线。

## 非目标

- 不恢复 Node 系统指标历史口径（system_metrics 趋势、事件循环、Node RSS、后台队列快照）；不复用 Node 事件循环字段。
- 不提供页面内采样配置入口；采样开关（含显式关闭）只通过环境变量控制，PG 采样存储由 maintenance 建表。
- 不做跨实例 / 多节点聚合；数据只来自当前部署的 gateway 与 jobs 两进程。
- 不承载业务统计（用量、成功率、模型质量）；那些属于用量统计与 AI 性能监控页面。

## 页面信息架构（三层）

页面自上而下固定三层，均为管理员入口（后端显式校验管理员身份）：

1. **进程状态双卡（Gateway / Jobs）**：数据来自 `GET /__aisys__/api/stats/system-metrics/health-snapshot`。gateway 段是本进程 owner readiness 载荷透传；jobs 段是 gateway 经 loopback 抓取 jobs `/health` 的载荷透传，不可达时降级为 `available:false` + 中文 `reason`。前端把两侧就绪项映射为中文并给出整体结论（就绪 / 降级 / 不可用原因），不得静默吞掉 `reason`。
2. **Go Runtime 指标**：数据来自 `GET /__aisys__/api/stats/system-metrics/go-runtime-trend`。角色 tab（固定 gateway 在前、jobs 在后）× 指标组（并发、内存、CPU）趋势图，辅以所选范围最新窗口的摘要 chips（均值摘录；峰值仅进趋势曲线）。`samplingEnabled=false` 时该层展示启用指引空态（见"空态规则"）。
3. **后台任务表**：数据来自 `GET /__aisys__/api/stats/system-metrics/runtime/jobs`。支持状态筛选、中文任务名映射、失败行高亮与手动刷新；分页 `page` / `pageSize`。

## API 契约

### GET /__aisys__/api/stats/system-metrics/go-runtime-trend

- 管理员。查询参数 `startDate` / `endDate`（`YYYY-MM-DD`，可省略，省略时按服务端业务时区取默认范围），服务端按业务时区解析日界线；日期范围与其他统计页共用统一的 31 天日历钳制（超出按窗口边界截断，不报错），服务端另有 90 天防御上限兜底。
- 响应 `data`：

```json
{
  "runtimeKind": "go",
  "service": "juhe-ai",
  "timezone": "Asia/Shanghai",
  "range": { "startDate": "2026-09-01", "endDate": "2026-09-27" },
  "samplingEnabled": true,
  "roles": [
    { "role": "gateway", "items": [] },
    { "role": "jobs", "items": [] }
  ]
}
```

- `roles` 固定 gateway 在前、jobs 在后，每项为 `{ role, items }`；旧响应外层的聚合 `role` / `items` 字段已删除，前端不得再读。
- `samplingEnabled=false` 表示读侧采样存储被显式关闭（`JUHE_AI_GO_RUNTIME_METRICS_STORE=disabled`；未配置时默认跟随主存储驱动开启）；此时仍是 200 正常响应，`roles` 两项 `items` 均为空数组，前端据此展示启用指引空态。
- `items` 是小时窗口聚合（`WindowAggregate`）：`windowStart` / `windowEnd` / `service` / `role` / `runtimeKind` / `sampleCount`，以及并发组（`goroutines*`、`goroutinesRunnable*`、`goroutinesWaiting*`、`gomaxprocs*`、`threads*`）、内存组（`heapAllocBytes*`、`heapLiveBytes*`、`heapObjects*`、`rssBytes*`）、CPU 组（`cpuPercent*`、`fdCount*`、`uptimeSeconds*`）的 `Avg` / `Max` 字段。平台不支持的字段为 `null`（如部分平台无 `cpuPercent` / `rssBytes` 观测），不以 0 占位。

### GET /__aisys__/api/stats/system-metrics/runtime/jobs

- 管理员。分页 `page`（≥1，默认 1）、`pageSize`（10..50，默认 10）。
- 新增可选 `status` 参数：`queued` / `running` / `completed` / `failed` / `skipped`；缺省返回全部状态，非法值返回 400（中文 message）。
- 行契约：`runId`、`jobName`、`jobType`、`workerRole`、`status`、`startedAt`、`finishedAt`、`durationMs`、`errorMessage`；按更新时间倒序（`updated_at`、`run_id`）。行来自 Go jobs worker 每次调度执行后持久化的 `background_task_runs`。
- `background_task_runs` 表未迁移或统计库句柄缺失时返回 200 + 空 `items` 降级；只有真实查询失败才按读错误返回。

### GET /__aisys__/api/stats/system-metrics/health-snapshot

- 管理员。响应 `{ checkedAt, gateway, jobs }`；`gateway` / `jobs` 段为就绪载荷透传，任何降级都是 `available:false` + 有界 `reason`，接口不因对端缺失或不健康而失败。

## 空态规则

- **未启用采样**（`samplingEnabled=false`）：Go Runtime 层展示启用指引空态，说明监控默认跟随主存储开启、当前被显式关闭（`JUHE_AI_GO_RUNTIME_METRICS_STORE=disabled`），并指引移除该配置或改为 `sqlite`/`postgres` 后重启 gateway/jobs 恢复；不渲染全 0 曲线，也不把该状态当错误提示。
- **已启用但时段无采样**（`samplingEnabled=true` 且所选范围 `items` 为空）：展示"该时段暂无采样"空态，与未启用空态明确区分；常见原因是进程刚启动、所选范围早于首次采样或超出保留期。
- **后台任务表空列表**：表未迁移（空 `items` 降级）与状态筛选无结果分别展示，不混淆为加载失败。

## env 契约

- `JUHE_AI_GO_RUNTIME_METRICS_STORE=sqlite|postgres|disabled`：存储选择。自 2026-09-27 起出厂默认开启：未配置/空时跟随 `JUHE_AI_DATABASE_DRIVER`（`postgres` → postgres；`sqlite`、空或未知值 → sqlite 零配置 standalone 默认），跟随派生与显式取值同样启用采样；显式取值优先于 driver 跟随；唯一关闭方式是显式 `disabled`（读接口返回 `samplingEnabled=false`）。建表语义：sqlite 模式由 gateway/jobs 启动自举建表（`CREATE TABLE IF NOT EXISTS` 幂等，duplicate column 与检查-后-行动竞态已做幂等容错，无需预处理）；postgres 模式 DDL 维护 owned——由 maintenance 显式执行，启动只读校验、缺表 fail-fast。已知边界：两个进程对同一全新 sqlite 文件**同时建立首个连接**时，WAL 翻转的排他锁在 modernc 驱动建连期不受 busy_timeout 保护，可能一次性 `SQLITE_BUSY` 失败——`pnpm dev`（先 gateway 后 jobs 顺序拉起）与容器 `restart: unless-stopped` 重启自愈均不受影响，无需处理。
- `JUHE_AI_GO_RUNTIME_METRICS_POSTGRES_URL`：可省略。省略时自动回退复用 `JUHE_AI_POSTGRES_URL`；写入仍严格限定 `juhe_stats.go_runtime_metrics_samples`、`go_runtime_metrics_hourly`、`go_runtime_metrics_trend_windows` 三表。两个 URL 都为空才启动报错。
- `JUHE_AI_GO_RUNTIME_METRICS_ROLE`：**已删除**，不得配置。role 由进程身份固定（gateway→gateway、jobs→jobs）；删除理由：该变量被两个进程共享转发时会导致 gateway 冒用 jobs 角色写入。
- `JUHE_AI_GO_RUNTIME_METRICS_INTERVAL`：采样周期，2026-10-08 起默认 `1m`（原 `15s`——明细表 `go_runtime_metrics_samples` 无读取消费方，页面只读小时/天聚合表，裁决见 `docs/plans/计划-20261008T203741000Z-表监控采样粒度根治.md` 第 7 节），下限 `1s`。
- `JUHE_AI_GO_RUNTIME_METRICS_RETENTION_DAYS`：保留天数，默认 `30`，范围 1..3650。
- `JUHE_AI_GO_RUNTIME_METRICS_SERVICE`：服务名，默认 `juhe-ai`。
- `JUHE_AI_GO_RUNTIME_METRICS_DATABASE_PATH`：SQLite 模式独立指标文件路径；未配置时按 `JUHE_AI_DATA_DIR`（缺省 `./data`，与 jobs datadir.Root 语义一致）派生为 `<数据根>/go-runtime-metrics.sqlite3`。
- gateway 与 jobs 共享同一份 env 家族与同一个 Store；写入按 `service` + `role` 维度区分，读取按角色分组返回，不存在跨进程 metrics URL。

## 生产启用步骤

单机 Docker 形态（env 契约条目见 `docker/single-server/README.md` 的".env 契约"节）：

1. 只读校验：`juhe-ai-maintenance --check-go-runtime-metrics`（可用 `--go-runtime-metrics-postgres-url` 或 `JUHE_AI_MAINTENANCE_GO_RUNTIME_METRICS_POSTGRES_URL` 提供 maintenance 专用连接串）。
2. 建表：按运维手册完成预演 / 备份后执行 `juhe-ai-maintenance --apply-go-runtime-metrics --node-stopped --go-stopped --backup-confirmed` 显式创建三表（该命令仅支持 PostgreSQL）；postgres 模式下 Go 进程启动只读校验 schema，DDL 维护 owned、不自动建表。sqlite 模式不适用本步：gateway/jobs 启动自举建表（幂等）。
3. 启动：监控默认跟随主存储开启，生产 PG 模式无需新增任何 STORE env（专用 URL 可省略，自动回退主库 URL），直接 `docker compose up -d gateway jobs`。
4. **顺序不可反（仅 postgres）**：PG 环境新库首次启动前必须先建表；缺表时 gateway / jobs 启动只读校验失败并循环重启。sqlite 模式启动自举建表，无此顺序约束。
5. 验证：`go-runtime-trend` 返回 `samplingEnabled=true`，且 `roles` 中出现非空窗口数据。不打算启用监控的环境显式 `STORE=disabled`，页面 Go Runtime 层展示"默认跟随主存储开启、当前被显式关闭"的恢复指引空态。

## 验收标准

- 显式 `JUHE_AI_GO_RUNTIME_METRICS_STORE=disabled` 时：gateway / jobs 正常启动；`go-runtime-trend` 返回 `samplingEnabled=false` 且 `roles` 两项 `items` 为空；页面 Go Runtime 层展示恢复指引空态。未配置 STORE 时默认跟随主存储驱动（`samplingEnabled=true`）；PG 主存储三表未建时启动 fail-fast（顺序契约见"生产启用步骤"）。
- 已建表后（显式或跟随派生的 postgres）：双角色 tab 出现并发 / 内存 / CPU 趋势与最新摘要 chips；`roles` 顺序固定 gateway、jobs；响应中不存在外层 `role` / `items` 字段。
- `runtime/jobs` 支持 `status` 筛选，非法值 400；页面失败行高亮、任务名展示中文映射。
- jobs `/health` 不可达时，进程状态双卡展示 `available:false` + 中文原因的整体结论，页面不出现未处理错误。
- 启动器（`scripts/start-go-project.mjs`）不再把 `JUHE_AI_GO_RUNTIME_METRICS_ROLE` 作为家族成员转发；`docs/` 与 `docker/single-server/README.md` 不再把 ROLE 描述为可配置项（历史文档与"已删除"说明性提及除外）。
