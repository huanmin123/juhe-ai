# 模型目录卡片化与详情抽屉设计

> **本文定义**：供应商模型目录的展示形态契约——紧凑卡片网格、详情抽屉、工具栏与分页行为、前端实现落点与验收标准。
> **消费方迁移（2026-10-28）**：原承载组件 `ProviderModelCatalogModal.vue` 已随《模型广场页与供应商目录退役设计》退役删除，本契约整体迁移至模型广场页（`ModelPlazaView.vue`）消费；§9 落点表为当时实施快照，现行消费方与页面结构以退役设计 §4 为准。
> **本文不定义**：目录分组的生成语义（各供应商投影哪些 section、条目取舍，见 [供应商独立计费与模型目录展示设计](供应商独立计费与模型目录展示设计.md) §5，本文仅接管其"呈现形态"部分）、目录接口契约（`GET /providers/{code}/models` 响应字段零变更）、跨供应商聚合模型广场（见 §10 后续立项）。

## 1. 要解决的问题

当前模型目录用宽表格承载详情型内容，信息密度倒挂：

1. 每个模型条目的每个 `catalogDisplay` 分组（Token 计费、tier_priority、tier_flex、思考能力、容量、长上下文、媒体计费、来源披露……）各生成一条 320px 动态列，典型 text 模型达 6-8 列，表格总宽常超 3000px，在 1180px 弹窗内横向滚动极长。
2. 单元格内是"小标签 + 数值"键值对列表（320px 里 6-9 行），既没有表格的可比性，也没有卡片的信息分组；长来源说明文本会把单行撑得极高，行高参差。
3. 对比"输入价 vs Priority 输入价"必须左右拖动；工具能力列是协议×工具矩阵堆叠（300px 宽）。
4. 与《样式规范》§5.3"详情型内容优先用弹窗、抽屉或展开行，不让主列表承担过多长文本"相悖。

## 2. 目标与非目标

### 目标

1. 模型目录改为**卡片网格 + 详情抽屉**：卡片只放高频判读信息，完整分组进抽屉，任何视口无横向滚动。
2. `catalogDisplay` 服务端预排版机制**完整保留**：后端零改动，分组仍由后端投影生成，前端只换消费形态（表格动态列 → 抽屉分组渲染）。
3. 管理面全部操作（新增、编辑、删除、归属筛选）与用户面/管理面可见性差异保持不变；现模型操作列仅编辑 / 删除两个动作（`ProvidersView.vue` `modelRowActions`），本设计不新增启停 / 排序等操作。
4. 移动端不再维护"表格 + 卡片"双形态，卡片网格单形态覆盖全部视口。

### 非目标

1. 不改 `GET /providers/{code}/models` 响应契约与 `catalogDisplay` 投影（`backend-go/` 零变更；前端类型补齐后端已下发的 4 个媒体字段不算契约变更，见 §5.1 槽位表）。
2. 不做跨供应商聚合的"模型广场"独立页面（§10 立项 1）。
3. 不做 DeepSeek 高峰/空闲价结构化展示与时段计费（§10 立项 2）。本次高峰/空闲说明仍随"美元换算/来源披露"分组完整展示，信息不丢失。
4. 外层供应商列表页（`ProvidersView.vue` 主体表格）形态不动。
5. 不引入任何定时轮询刷新；目录数据仍为打开弹窗时一次加载。

## 3. 参照与取舍

参照 `juhe-ai-portal` 客户面模型广场（`ModelsView.vue`：厂商标签筛选 + 卡片网格 + 右侧抽屉 + 官方价删除线），取其**信息分层骨架**（卡片只放关键信息、详情进抽屉、紧凑数字单位、tabular-nums），不照搬的部分及理由：

| portal 做法 | 本项目取舍 | 理由 |
| --- | --- | --- |
| 厂商标签筛选（带数量） | 不采纳，保留现有用途分类 Tabs（text/image/audio/video） | 弹窗已限定单一供应商，厂商筛选无意义；用途分类是现有有效维度 |
| 分组倍率实收价、官方参考价删除线 | 不采纳 | 本项目目录展示的是目录价（USD），无分组倍率与"官方价 vs 售价"双轨语义 |
| 高峰徽标与时段 banner | 不采纳 | 本项目时段价未建模（立项 2）；不展示不存在契约支撑的状态 |
| 「创建密钥使用此模型」CTA | 不采纳 | 管理台场景，模型与密钥创建无直接跳转契约 |
| 详情抽屉承载完整价格表 | 采纳，数据源换为 `catalogDisplay` 分组 | 服务端已按供应商投影裁决"真实存在的字段"，前端零判断消费 |

## 5. 卡片契约

每张卡片只展示高频判读信息，自上而下四个区域：

### 5.1 价格槽位：候选序列 + 取存在者

价格区最多三槽。每个用途分类（`getModelCategory` 现有词表）定义一个**候选字段序列**（label + 取值字段 + 计费单位），实现按序列顺序**只取真实存在（非 null/undefined）的字段，最多 3 个**；分类候选全空但行上仍有其他直价字段时按回退序列补取（见补充规则），**全部直价字段为空才整块隐藏**。不做固定三槽的 `-` 占位——"字段缺失 = 无该计费维度，不补零"（既有"可选字段超集"边界），只展示真实存在的价格也让 audio/video 等"单价形态互斥"的模型不再出现大块 `-`。

| 分类 | 候选序列（按优先级） |
| --- | --- |
| text / 默认 | 输入 `inputUsdPer1M`（USD/1M）→ 输出 `outputUsdPer1M` → 缓存读 `cachedInputUsdPer1M` |
| image | 每张输出 `outputUsdPerImage`（USD/张）→ 图片输入 `imageInputUsdPer1M` → 图片输出 `imageOutputUsdPer1M` |
| audio | 音频输入 `audioInputUsdPer1M` → 音频输出 `audioOutputUsdPer1M` → 语音合成 `ttsInputUsdPer1MChars`（USD/1M 字符）→ 语音识别 `audioInputUsdPerSecond`（USD/秒）→ 输入 `inputUsdPer1M` |
| video | 视频（每秒）`videoOutputUsdPerSecond` → 视频（每次）`videoOutputUsdPerCall` → 输入 `inputUsdPer1M` |

audio/video 的字符价、秒价、次价覆盖真实目录数据：当前 31 个 audio 模型中 20 个只带 `ttsInputUsdPer1MChars` 或 `audioInputUsdPerSecond`（glm/minimax/qwen/gpt/volcengine/xai 的 TTS、ASR、实时行），固定三槽会导致这些卡片价格区整块隐藏；video 的秒价与次价在目录中互斥落库，取存在者后只显示真实那一项。

补充规则：

- **单 Token 价合并**：仅当后端投影呈单「Token」条目时（读 `catalogDisplay` 的 token_pricing 分组，目前仅 glm 有此合并投影，`derived.go` `usesSingleTokenPrice` 判定），卡片同步合并为单槽「Token」；**不做字段级全局判定**——其他供应商的 input==output 同值行在抽屉仍是输入 / 输出两条目，卡片须保持两槽同口径，避免制造新的分叉。
- **槽位是锚点价，不是全貌**：卡片槽位是该分类的锚点价（如 gemini 图像行仅有「图片输出」一槽，文本输入 / 输出价只在抽屉），全貌一律以抽屉「计费与规格」为准；单槽卡片为正常形态。
- **分类回退（2026-10-28 补充，台账 C1）**：mode 缺失的 custom 草稿行会被分类为 text，其媒体价不在 text 候选内——分类候选产出 0 槽时，按「text → image → audio → video」全字段顺序回退取存在者（同样最多 3 个、同一存在判定与 trimNumber 口径），价格区不因分类误配隐藏真实价格；仅当行上全部直价字段为空才整块隐藏。回退不改 Tab 归类（分类仍由 mode 决定，卡片可能出现在"对话"Tab 下但显示真实媒体价）；根治分类误配属 mode 必填校验立项，不在本批。
- **数值格式化**：槽位数值与抽屉价格值统一使用 `trimNumber` 口径，**最多 2 位小数**：`|v| ≥ 0.01` 时 `toFixed(2)` 去尾零（`0.28571429 → 0.29`、`1.14285714 → 1.14`）；`0 < |v| < 0.01` 时保留 2 位有效数字（`0.00571429 → 0.0057`，避免缓存读等小单价被舍成 0.01 或 0）；0 显示 `0`。数值不另拼单位后缀，单位语义由槽位 label 表达。抽屉侧口径不同：token 价渲染为 `$X / 1M tokens`、媒体条目由服务端拼接 `$X/s` 等后缀——**两端口径不要求字符串相等**（卡片管速览、抽屉管精确事实，与容量行分层同则）。0 值是真实价（免费维度），按存在显示，不得用 falsy 判断过滤。

后端 `ModelCatalogItem` 已下发 `videoOutputUsdPerSecond` / `videoOutputUsdPerCall` / `ttsInputUsdPer1MChars` / `audioInputUsdPerSecond` 四个媒体字段（`catalog.go:107-110`），前端 `ProviderModelPricing` 类型补齐这 4 个可选字段即可，属类型补齐而非契约变更。

槽位选择是跨供应商通用的"分类 → 候选序列"展示规则，不含供应商计费判断；供应商差异仍由后端投影负责，完整价格在抽屉呈现。

### 5.2 卡片布局

```
┌────────────────────────────────┐
│ deepseek-v4-pro            ⧉   │  ← 模型 ID（mono）+ 复制按钮
│ [内置] [对话] [Priority]        │  ← 徽标行
│ 输入        输出        缓存读   │
│ 1.285714   3.857142    0.042857 │  ← 价格三槽（tabular-nums）
│ 上下文 128k · 输出 64k          │  ← 容量行（紧凑单位，缺失整段隐藏）
│                     [操作图标组] │  ← 管理面 RowActions；用户面无
└────────────────────────────────┘
```

| 区域 | 内容与来源 |
| --- | --- |
| 模型 ID 行 | `record.model`（`--juhe-font-mono`，长 ID `overflow-wrap: anywhere` 换行完整可见，保证可读可复制）+ 复制按钮（复用 `shared/clipboard.ts` 的 `copyTextToClipboard`，成功与失败文案随该工具现有分场景口径，见 §9，不裸写 `navigator.clipboard`） |
| 徽标行 | 范围（**仅自定义模型显示**：`scope !== 'built_in'` 时以 `formatModelScope` + 现有 scope 色展示全局/个人；内置属内部机制不展示）；用途（`formatModelCategory`）；服务档位（key 取 `supportedServiceTiers` ∩ `serviceTierPrices` 且该档位价格集非空，与后端 tier_* 分组生成条件同构——后端要求分组内至少一个价格非 nil，`derived.go` `serviceTierSections`/`priceSection`；key 经 `formatModelServiceTier` 映射——`priority`→Priority、`flex`→Flex，未知 key 原样透传，多个并排）；状态（仅非 `active` 时显示，`formatModelStatus`）；将停用（有 `shutdownDate` 时，`将停用 {date}` 橙标）。**默认检查徽标不展示**（`defaultHealthCheckModel` 属后端探针内部机制，不上卡面）。用途常驻，其余有值才显示 |
| 价格区 | 标题行「USD 计费价」；槽位 = §5.1 候选序列取存在者（1-3 个），槽位 label 即候选序列中的语义名；数值 `tabular-nums` + `trimNumber` 口径（§5.1） |
| 容量行 | `上下文 {formatSpec(contextWindowTokens)}` · `输出 {formatSpec(maxOutputTokens)}`（与抽屉容量组同源，不做 `maxTokens` 回退——`maxTokens` 仅 maintenance 种子写入、custom 行读链不选该列、且与 `maxOutputTokens` 语义不等价）；两个值都缺失时整行隐藏。`formatSpec`：0 或缺失显示 `-`，≥1_000_000 显示 `{n}m`，≥1_000 显示 `{n}k`，其余原样（`parseFloat(toFixed(1))` 去尾零）。口径说明：卡片容量是 1000 进制的量级速览，与抽屉分组内服务端格式化的精确 token 值（如 `128K`）口径不同且刻意分层——卡片管快速扫描、抽屉管精确事实 |
| 操作区 | 操作区按现有 `rowActions(record)` 逐行判定渲染（父级 `modelRowActions` 内含 loading 与 `canMutateModel` 门控：内置模型仅管理面；个人/全局模型管理面全量、用户面仅自有个人模型），icon 形态迁到卡片右下，`RowActions` 的 click 与 keydown（Enter / Space）都需阻断冒泡；无权限的行不渲染。**用户面对自有个人模型的编辑/删除能力保持不变** |

排序沿用后端返回顺序（release date desc → catalogOrder asc → model asc），前端不重排。

## 6. 详情抽屉契约

点击卡片本体（或键盘 Enter / Space）打开右侧抽屉，宽度 `min(560px, 100vw)`；关闭方式为遮罩 / 关闭按钮 / Esc，关闭后焦点归还触发卡片（实现落点见 §9）。卡片内嵌按钮（复制、RowActions）的 click 与 keydown 均不得触发抽屉：卡片 keydown 处理须判别事件目标为卡片本体（参照实现 `ModelsView.vue` 的 `onCardKeydown` 无 target 判别，不可照抄）。抽屉打开期间发生列表变更（切换用途 Tab、关键词、归属筛选、分页，及新增模型保存后的 reload）时关闭抽屉——`detailModel` 是快照引用，列表重算后可能脱离当前列表（对齐 portal `switchGroup` 的处置）。

自上而下：

1. **Hero**：`ProviderIcon` + 供应商名；模型 ID + 复制按钮；徽标全集（同卡片徽标行，另加发布时间 `releaseDate`、管理面显示归属用户 `systemAccountId`）。
2. **「计费价格」区块（对齐 juhe-ai-portal 模型广场抽屉：一张表，不是每组一张）**：全部分组合并渲染为**一张价格表**。
   - **行** = 价格项：`token_pricing` 的条目顺序（DeepSeek 归一后的输入 / 缓存读 / 输出）；`image_generation` / `media_pricing` 的独有项（每张、视频每秒等）追加为额外行（服务端 `text` 格式值原样入格）。
   - **列** = 价格档位，语义对齐官方「正常价 / 高峰价」：无高峰档模型单列「正常价」（`token_pricing` 值）；有 `offpeak_pricing` 分组（DeepSeek）时两列——「正常价」（`offpeak_pricing` 值，官方空闲/正常时段价）+「高峰价」（`token_pricing` 值，官方高峰时段价），按 `item.key` 行配对、缺配对显示 `-`；存在 `tier_*` 分组时每个档位追加一列（`formatModelServiceTier` 列头）。
   - **样式**：`table-layout: fixed`；表头整行浅灰底（`--juhe-bg`）、价格项列约 38% 宽左对齐深色、档位列居中 `tabular-nums`；行高舒展（单元格 14px 垂直内边距）；`overflow-wrap: anywhere`，禁止首列塌陷。
   - **时段描述**：有高峰列时表下附口径说明「高峰时段为工作日 09:00–12:00、14:00–18:00（北京时间）；时段计费未启用，当前所有请求按高峰价结算。」（时段信息唯一落点，不另设分组，避免与说明重复）。
   - **值**：`formatPriceTableCell`（去掉 `/ 1M tokens` 后缀，值只留 `$` 数字），单位语义由区块标题「USD / 1M tokens」承担。
3. **「基础信息」区块（对齐 portal info-grid）**：`reasoning`（思考能力）、`capacity`（容量）、`long_context`（阈值/倍率）等**非价格分组**渲染为 label/value 两列网格小卡（label 小字弱化、值 strong），按后端返回顺序；不单独成表；接口协议 / 输入输出模态（合并为「能力」一行）等接入事实并入同一网格；工具矩阵与模型模式属内部机制不展示；时段描述不重复出现（仅价格表下方说明承担）。
4. **永不渲染的分组**：`currency_conversion` / `source_disclosure`（后端已停止生成，前端仍按 key 过滤兜底旧后端响应）；其余分组按 §2/§3 归类渲染。`catalogDisplay` 为空时价格表与基础信息区块整体隐藏——注意为空的不止 unknown 供应商：具名厂商下无价格 / 无能力的行（如 draft 行）投影同样为空。unknown 供应商行（无投影）若 DB 直价列有值，卡片价格区照常显示而抽屉无价格明细——该不对称是有意接受，卡片槽位即其价格信息。
3. **「接入信息」区块**（catalogDisplay 未覆盖的目录事实）：接口协议（`supportedApiProtocols` tags，现有协议色）；工具矩阵（`modelToolsByProtocol`，协议 → 工具列表，空则 `-`）；输入 / 输出模态（`formatModelModalities`，空则 `-`）；模型模式（`mode` 原始 wire 值，读侧词表为 `chat` / `responses` / `embedding` / `image_generation` / `audio` / `video`——写侧 UI 的 `image` 在读侧派生为 `image_generation`，空则 `-`）。不含端点形态字段——`supported_endpoint_modes` 在后端派生 `mode` 与协议后即丢弃、不随目录接口下发，展示它需要后端改动，违反本文非目标。
4. **操作区（按行权限）**：`rowActions(record)` 以按钮组呈现，与现表格操作列完全一致——当前仅编辑 / 删除两个动作（现无启停 / 排序，本设计不新增），渲染条件与卡片一致（逐行 `rowActions(record).length`：内置模型仅管理面可见，用户面对自有个人模型保留编辑/删除）。抽屉内操作成功后的处置是**行为性契约：编辑保存成功、删除确认成功后立即关闭抽屉**（编辑走列表项内存替换 `applyProviderModelMutationResult`，`detailModel` 引用不更新会显示过期快照；删除走 reload 整表重建）；**抽屉打开时经工具栏新增模型、保存成功后的 reload 同样关闭抽屉**。关抽屉不依赖 reload 机制本身（编辑路径不 reload），按操作种类直接关。reload 进行中操作区按钮为空是现状继承（`modelRowActions` 在 loading 时返回空数组），不加新语义。

抽屉是"完整分组"的唯一展示位：不在卡片上重复任何 `catalogDisplay` 条目，也不在抽屉之外新增价格判断。抽屉内容区内部滚动（`overflow-y: auto`，高度受弹窗视口约束），长 `sourcePricingNote` 等文本随内容区滚动可达，不在抽屉层产生页面级滚动；条目 value 单元格沿用现表格的 `overflow-wrap: anywhere` 换行口径，超长来源说明在两列布局内换行不溢出。

## 7. 工具栏、筛选与分页

全部保持现有契约，仅分页微调：

| 项 | 契约 |
| --- | --- |
| 关键词搜索 | 现有 `filterProviderModelsByKeyword` 行为不变（模型名 / 用途 / 协议 / 模态 / 工具） |
| 用途 Tabs | `buildModelCategoryTabs` 行为不变（含计数，空分类不出现） |

| 新增模型 / 计数 / USD 标识 | 不变 |

## 8. 状态与响应式

状态判定优先级：loading > 错误 > 空列表 > 筛选无结果——reload 期间 `providerModels` 已清空且 loading=true，须先判 loading，避免闪现「没有匹配的模型」（对齐 `ResponsiveDataList` 现状语义）。

| 状态 | 表现 |
| --- | --- |
| 加载 | 卡片骨架 × 8（`a-skeleton`），不闪表格 |
| 空（无模型 / 加载失败） | 沿用现有 `a-empty` 文案（`loadError || '这个供应商暂未配置模型价格。'`） |
| 筛选无结果 | `a-empty`「没有匹配的模型」 |
| 错误重试 | 沿用现有弹窗关闭重开加载路径，不新增重试按钮 |

- 网格：`display: grid; grid-template-columns: repeat(auto-fill, minmax(280px, 1fr)); gap: 12px`——1180px 弹窗内约 3 列；≤767px 需媒体查询显式 `grid-template-columns: minmax(0, 1fr)` 单列（auto-fill 在 560-767px 宽度会产生 2 列，与单列目标矛盾）；无横向滚动。
- **滚动接管**：弹窗 body 为 `overflow: hidden` + 固定高度 flex 列，`ResponsiveDataList` 移除后卡片网格区是滚动主体（`overflow-y: auto`），分页区固定在网格区之下、始终可达——按设计字面缺失此契约会导致第 2 行起被裁剪、分页不可达。
- **新状态归属**：page / detailOpen / detailModel 为弹窗内部状态，不进 props / emits；弹窗关闭（`resetModelModal` 路径）时一并重置，跨供应商重开不残留页码与抽屉（现状 `a-modal` 未设 `destroyOnClose`，组件内 ref 跨开关持久）。
- 弹窗内**不再使用 `ResponsiveDataList`**：卡片网格是 div grid，非 `a-table`，不违反《响应式列表规范》§6"业务页不得直写 a-table"；《响应式列表规范》§5「卡片只展示 PC 列表已有字段」按单形态语义适用（卡片=高频字段、抽屉=完整分组）。**有意的行为变化**：移动端完整 catalog 分组的可达路径从现移动卡片平铺（0 跳）变为详情抽屉（1 跳）。外层供应商列表继续用 `ResponsiveDataList`，不受影响。
- 卡片样式遵循《样式规范》§6.2：`--juhe-surface` 背景、`--juhe-border` 边框、`var(--juhe-radius)` 圆角、无多层嵌套；hover 仅边框加深 + 轻阴影（用现有 `--juhe-shadow-card` 令牌，不自造 rgba），不做位移动效；数字 `tabular-nums`，模型 ID 用 `--juhe-font-mono`；状态色沿用现有 `modelScopeColor` / `modelStatusColor` / 协议色映射。
