# 前端版本识别与资源恢复

## 1. 目标

前端异步资源加载失败时，先比较当前页面与服务器静态清单中的真实 Build ID。只有两个合法 Build ID 确认不同时，页面才提示“系统已更新”；网络波动、缓存异常、资源丢失或清单不可用不能被描述成发版。

本功能只在动态资源加载失败后运行，不做后台轮询，不依赖数据库、Redis、worker 或生产启停记录。

## 2. Build ID 契约

- Build ID 固定为构建源提交的完整 40 位 Git commit，比较前统一转为小写并严格校验。
- Vite 将同一个 Build ID 注入编译期常量 `__JUHE_AI_FRONTEND_BUILD_ID__`，并在前端产物根目录生成 `build-info.json`。
- 正式发布包由 `scripts/package-release.ps1` 或 `scripts/package-release.sh` 把已冻结的 `RELEASE_SOURCE_COMMIT` 注入 `VITE_JUHE_AI_BUILD_ID`；维护者不得手工填写或使用短 SHA。
- 非发布构建没有显式环境变量时，Vite 从当前 worktree 的 `git rev-parse HEAD` 读取 Build ID；无法得到合法完整提交时构建直接失败。
- 后端对 `build-info.json` 返回 `Cache-Control: no-cache`；浏览器读取时同时使用 `cache: no-store` 和时间参数，避免中间缓存把旧清单当作当前事实。

## 3. 失败分类

资源加载失败后，前端最多等待 1500ms 读取静态清单，并将结果归为：

| 状态 | 条件 | 用户提示 |
| --- | --- | --- |
| `changed` | 当前页面和远端清单均合法，且 Build ID 不同 | “系统已更新”，说明正在加载最新版本 |
| `same` | 两个合法 Build ID 相同 | “页面资源加载失败”，说明正在重新加载 |
| `unknown` | 任一 Build ID 非法、请求超时、非成功响应、JSON 异常或网络失败 | 与 `same` 相同的中性恢复提示 |

分类只决定文案，不改变恢复次数。首次命中资源失败会登记目标路径并在 900ms 后自动重新加载一次；用户也可以立即触发重新加载。

## 4. 防循环边界

- 同一浏览器会话在 30 秒内对同一路径重复失败时，不再读取版本清单，也不再自动刷新。
- 重复失败固定提示“自动恢复未成功，请手动刷新页面后重试”，只保留手动刷新操作。
- 版本清单读取或提示渲染异常不能阻断恢复；异常时直接执行已登记的一次重新加载。
- 本机制不能证明服务器发生过启停，也不把资源失败、代理缓存或客户端网络错误推断为发布行为。

## 5. 验证入口

```powershell
pnpm --filter juhe-ai-frontend test:frontend-build-info
pnpm --filter juhe-ai-frontend test:route-load-recovery
pnpm --filter juhe-ai-frontend typecheck
pnpm --filter juhe-ai-frontend build
```

构建后还应确认 `frontend/dist/build-info.json` 中的 `buildId` 等于本次构建所用的完整提交。
