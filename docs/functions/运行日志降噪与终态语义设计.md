# 运行日志降噪与终态语义设计

## 1. 目标

- 普通 `info` 运行日志只保留一次请求耗时汇总、失败、中断、重试和真正的慢操作，不记录每个正常快速阶段。
- DB service 保留错误和慢请求证据；后台任务通过既有 `jobId` / `operationId` 关联，不伪造用户请求 `traceId`。
- 网关收到成功协议终止事件后，即使连接随后触发 `close`，请求终态仍为 `success`，不得被覆盖为 `aborted`。
- 日志搜索能识别点号事件名，并用可读事件名称区分耗时汇总、慢阶段和 DB service 请求。

## 2. 事件与级别

### 2.1 DB service

- `db_service.request.start`：仅 `debug`。
- `db_service.request.complete`：耗时低于 `50ms` 时为 `debug`；达到或超过 `50ms` 时为 `info`，消息明确操作名和耗时。
- `db_service.request.failed`：保持 `error`，携带操作名、耗时、`jobId`、`operationId`、`parentId`；存在用户请求上下文时继续携带真实 `traceId`。
- 没有用户请求上下文的后台任务允许没有 `traceId`。排障应使用 `jobId` / `operationId`，不能为满足展示而生成无意义 trace。

### 2.2 网关阶段与汇总

- standalone 中 `logRequestStage` 继续在请求上下文内累计完整有界阶段摘要。performance 默认按 `traceId` 稳定采样 50/1000 的正常阶段详情，避免大请求和重试把 JSON 序列化重新放大到网关事件循环。
- 正常、跳过且低于 `1000ms` 的阶段只写 `debug`；默认 `info` 不落盘、不进入运行日志索引。
- 正常、跳过且达到 `1000ms` 的阶段写 `info`，消息包含阶段名和耗时。
- 预期失败和中断阶段写 `warn`；未预期失败只写一条 `error` `gateway.request.failure`，不再同时复制一条 `info`。
- 每个进入网关阶段观测的请求在 HTTP `finish` 或有效 `close` 边界只写一条 `gateway.request.timing_summary`。standalone 和 performance 命中详情采样的请求保留完整有界 `stages`；performance 未命中采样的正常成功请求保留标量计数、耗时、队列峰值和 `stageDetailsSampled=false`，不附带 `stages` 数组。失败、中断和问题阶段不受正常采样影响。
- performance 的日志 publisher 待写字节达到 `JUHE_AI_GATEWAY_STAGE_PRESSURE_MAX_PENDING_MB` 后，正常阶段详情立即暂停；每请求终态摘要、warn、error 和 fatal 仍保留。

## 3. 终态规则

- 流式协议解析器观察到成功终止事件后，在请求上下文登记 `protocolTerminalOutcome=success`。
- `close` 发生时：若已登记协议成功终态，则耗时汇总按 `success` 收口；若已登记协议失败终态，则按已知失败阶段收口；两者都不写“HTTP 请求在完成前关闭”告警。只有没有协议终态的提前关闭仍按 `aborted` 处理。
- 后续若明确观察到协议失败终态，失败可以覆盖此前的成功提示；普通连接关闭不能覆盖已确认成功。
- HTTP `finish`、`close` 并发触发时继续依赖 `timingSummaryLogged` 保证汇总最多一次。

## 4. 日志搜索展示

- 精确映射 `gateway.request.stage`、`gateway.request.failure`、`gateway.request.timing_summary`、`db_service.request.start`、`db_service.request.complete`、`db_service.request.failed`。
- 点号命名使用 `gateway.` / `db_service.` 兜底，不再显示为“未映射运行事件”。
- 日志列表直接使用后端消息中的阶段、操作和耗时摘要；完整字段仍在日志详情原始 JSON 查看。

## 5. 验证门禁

- `info` 级原始日志探针中，大量快速成功阶段只能产生一条耗时汇总，不得逐阶段刷屏。
- performance 未命中稳定采样时，成功汇总必须保留标量诊断并省略 `stages`；standalone 必须保持 100% 详情。
- 慢阶段、预期失败、中断和未预期失败分别按 `info` / `warn` / `warn` / `error` 保留。
- 快速 DB service 成功请求在默认 `info` 下不出现；慢请求和失败必须出现且有关联字段。
- 协议成功终止后的 `close` 汇总结果为 `success`，且没有 `http_request_closed` 告警。
- 日志搜索桌面和移动页面均显示已映射中文事件，无框架错误或控制台异常。
