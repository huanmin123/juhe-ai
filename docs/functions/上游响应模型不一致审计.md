# 上游响应模型不一致审计

## 目标

在使用记录中对比本次**实际发送给上游**的模型与上游原始响应声明的模型。只有两者均存在且规范化后不相等时，才显示红色 `上游响应 <模型>` 与 `模型不一致` 标签。

该能力用于发现供应商把请求路由到不同模型的情况；不是模型映射、计费、路由或失败判定机制。

## 比较口径

| 字段 | 来源 | 用途 |
| --- | --- | --- |
| `model` | 客户端请求模型 | 保留现有展示、筛选和统计语义，不参与不一致比较。 |
| `upstream_model` | 选中账号、模型映射和协议转换后实际发送的模型 | 不一致比较的左值。 |
| `upstream_response_model` | 上游原始响应的模型字段 | 不一致比较的右值。 |

- 比较前只去除首尾空白；不做别名、大小写、日期后缀或模型家族归并。
- `upstream_model` 缺失、`upstream_response_model` 缺失或两者相同，均不显示提示。
- 本地映射例如 `gpt-5.6-sol -> gpt-5.4`，只要上游响应仍为 `gpt-5.4`，不显示不一致。
- 历史记录没有新字段时保持无提示，不根据 `model`、价格模型或账号配置猜测。

## 原始响应观察

观察器位于上游响应返回、协议桥接改写之前，流式转发时只旁路读取字节，不缓冲或替换完整下游响应。

- OpenAI-compatible：读取 JSON / SSE 中的 `response.model` 或 `model`；`response.completed` 等终态事件优先。
- Anthropic：读取 `message.model` 或顶层 `model`。
- Gemini：读取 `modelVersion`。
- 明确的协议档案优先决定响应格式；混合供应商等协议不确定场景再根据实际请求 Header 和上游 URL 判断。Google OpenAI 兼容路径按 OpenAI 格式解析，不因 Google 域名或 `x-goog-*` Header 误判为 Gemini 原生协议。
- 无法解析、响应过大、提前断流或同一响应包含冲突模型时，不阻断请求。冲突模型保留终态值并记录运行日志。

原始响应 body 不会因本能力额外持久化；只保存最多 200 个字符的模型 ID。

## 存储与升级

使用记录新增可空字段 `upstream_response_model`，列表和详情由后端计算 `upstreamModelMismatch`，前端不自行复现比较逻辑。

- PostgreSQL：启动 schema 与离线命令均执行幂等 `ADD COLUMN IF NOT EXISTS`。
- SQLite：新 shard 自动建列；已存在的 shard 必须停服后执行：

```powershell
pnpm --filter juhe-ai-backend maintenance:migrate-usage-response-model -- --confirm-offline
```

该命令只补齐列，不修改历史记录值。不得在网关、worker 或管理 API 仍写入时执行。

## 页面行为

使用记录桌面表格和移动卡片保留既有请求模型与映射标签；仅在不一致时追加两个红色标签。长模型 ID 可以换行，且不会扩展移动卡片或表格列的稳定尺寸。

不新增筛选项、统计指标、告警、阻断或账号状态副作用。
