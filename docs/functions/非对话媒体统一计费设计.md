# 非对话媒体统一计费设计

> 状态：设计定稿（2026-11-19 用户裁决：视频同样乘分辨率倍率；其余细节由实现方决定）；代码未实施。
> 定位：非对话媒体模型（`image` / `image_generation` / `audio` / `video`，不含 `realtime` 对话语音，也不改变 chat / responses / embedding 的 token 计费）的统一计价模板——**秒 / 张 / 次 + 分辨率倍率 + 自定价**。
> 取代关系：本文生效后，[模型价格与用量统计口径](模型价格与用量统计口径.md) §2.5/§2.6 与 [音频视频模型接入与统一媒体网关设计](音频视频模型接入与统一媒体网关设计.md) §10 中「按厂商真实定价维度逐行适配」的口径只适用于历史快照与存量记录；[供应商独立计费与模型目录展示设计](供应商独立计费与模型目录展示设计.md) §2.1/§2.3 的「不统一媒体计费规则」在本域让位于本文。历史 `cost_breakdown_snapshot_json` 不重算。

## 1. 问题与目标

### 1.1 当前问题（证据）

1. **计价维度碎片化。** `catalogdata/*.json` 共 215 行，其中 83 行是媒体模型（audio 40、video 24、image_generation 19），使用 11 种价格维度组合：视频秒价、视频次价、TTS 字符价、音频秒价、图像按张、图像按 token、音频输入/输出 token 及其组合；`video_output_seconds` 与 `video_output_calls` 还互斥。
2. **媒体价格没有进入模型行。** `models` 表只有 `input/output/cached/...`、`image_input/output_usd_per_1m`、`audio_input/output_usd_per_1m`、`output_usd_per_image` 等 token/按张列，没有 `tts_input_usd_per_1m_chars`、`audio_input_usd_per_second`、`video_output_usd_per_second`、`video_output_usd_per_call`。运行时由 `chain_pricing.go:280` 的 `chainCatalogPricing` 从 `go:embed` 静态 JSON 补齐；前端明确注释这些字段「由后端静态定价表透传、随目录 API 下发，只读展示」（`providerModelFormatters.ts:98-105`）。结果是改价/加模型要改 JSON、重生成 seed、补锚点测试、同步文档，管理面改不了。
3. **视频自定义模型实际上无法定价。** `write_routes.go` 的 `customInputHasCompletePrice` 对 `mode=video` 恒返回 `false`，注释写明「无管理面秒价/次价通道」；`audio` 只认音频 token 价，`per-second/per-char` 价只在静态层。
4. **官方分辨率档被压成主档。** xAI `grok-imagine-video-1.5` 官方 480p `$0.08/s`、720p `$0.14/s`、1080p `$0.25/s`，目录只落 720p；MiniMax Hailuo 官方 768P-6s `$0.28/条`，1080P-6s、10s、512P 各档只写在注释；Volcengine Seedance 官方按输出 token × 分辨率档，网关只落 720p 参考秒价；Gemini/OpenAI 图像按 image token，OpenAI/xAI/GLM 图像按张，分辨率和质量都不进价格。非主档实际成本偏差常见 2~5 倍。
5. **缺失计量时存在漏计。** TTS token 口径模型（如 `gpt-4o-mini-tts`）上游二进制响应无 usage，网关无 token 自算维度，直接 0 计费 + `usage_missing`；视频按次与按秒两套维度让同一类产物出现两种结算形态。
6. **成本语义被混用。** `cost_usd` 同时承担「上游账单估算」和「API Key / 授权美元额度扣减」（`limits_json` 的 `limit` 为美元金额，配额读 `success_cost_usd`）。按厂商官方价逐行适配时，任何非主档偏差都会同时污染成本观测和客户额度。

### 1.2 目标

- 媒体域只保留三种计价单位：**秒、张、次**；token 计费维持现状。
- 分辨率作为统一倍率维度：视频秒价乘分辨率倍率，图片张价乘分辨率倍率；音频不乘。
- 媒体价格进入模型行，管理面可编辑、目录可展示、seed 可默认；新增模型不再逐厂商适配官方价格表。
- `cost_usd` 在媒体域明确为**统一结算价（tariff）**，官方价只作定价参考。
- 上游拿不到秒时，能以纯 Go 解析音频/视频时长或从生效请求推导，绝不因缺计量静默计 0。

### 1.3 非目标

- 不改 chat / responses / embedding 的 token 价格模型、长上下文倍率、服务档位、缓存价。
- 不改 `realtime` 对话语音的 audio token 计费（属对话域，另立需求）。
- 不改媒体请求/响应协议、分辨率选择、厂商 adapter 报文；只改计价与计量。
- 不追求与厂商官方账单逐档一致；不要求新增媒体模型时逐行官方取证。
- 不重算历史 `usage_records` 与 `cost_breakdown_snapshot_json`。

## 2. 核心裁决

| 编号 | 裁决 | 影响 |
| --- | --- | --- |
| D1 | 媒体域统一为 `second` / `image` / `call` 三种计量单位；`tts_input_chars` 与 image/audio token 不再作为新媒体模型计费维度 | 新增模型只选类别和单位，不再选厂商维度 |
| D2 | 视频秒价、图片张价都乘**统一分辨率倍率**；音频不乘 | 480p/4K、1K/4K 不再同价 |
| D3 | 媒体价格以 `models.media_pricing_json` 为运行时唯一权威；静态 `catalogdata/*.json` 只做 seed 来源与 legacy 兜底 | 管理面可改价，目录可显示 |
| D4 | 媒体域 `cost_usd` = 统一结算价，不再是厂商账单估算；额度、统计继续用它 | 成本观测口径改变，需在文档与界面标注 |
| D5 | 缺失秒数按「上游事实 → 生效请求 → 适配器默认（视频）→ 网关解析 → 估算」降级，并记录来源；全部失败才 0 + `usage_missing` | 消除成功流量静默 0 计费 |
| D6 | 计量解析使用纯 Go 实现，不依赖 ffprobe/mediainfo 等外部本地工具、不使用 cgo | 部署零新增外部依赖 |

## 3. 计量单位与类别映射

| 模型形态 | `unit` | 计量字段 | 计费行项（`CostLineKind`） | 说明 |
| --- | --- | --- | --- | --- |
| `image` / `image_generation` | `image` | `output_image_count` | `image_output_unit` | 成功响应 `data[]` 计数优先，否则请求 `n` |
| `audio`（TTS，`audio_speech` 协议） | `second` | `audio_input_seconds`（列名沿用旧名，语义为「音频秒」） | `audio_input_seconds` | 优先上游 `duration`，否则网关解析产出音频时长 |
| `audio`（STT / ASR，`audio_transcription` / `audio_job_*` 协议） | `second` | `audio_input_seconds` | `audio_input_seconds` | 优先上游 `duration`，否则解析请求上传的音频 |
| `video`（时间型产物） | `second` | `output_video_seconds` | `video_output_seconds` | 上游 `duration` 优先，否则请求生效 `seconds` / 适配器默认 |
| `video`（非时间型产物，如 3D 文件） | `call` | 无独立列（`cost_usd` 落库，行项在快照） | `video_output_calls` | 一次任务 = 一次调用；只用于 3D 等没有时长概念的产物 |
| `audio` + `realtime` 协议 | 不适用 | audio token 列 | 既有 audio token 行项 | 对话域，保持现状 |
| `audio` + `chat_completions` / `responses`（如 `gpt-audio` 系） | 不适用 | audio token 列 | 既有 audio token 行项 | 音频对话模型，按对话 token 计费，不改 |
| `chat` / `responses` / `embedding` | 不适用 | token 列 | 既有 token 行项 | 保持现状 |

约束：

- `mode=audio` 且协议含 `audio_speech` / `audio_transcription` / `audio_job_create` 等音频媒体协议：`unit` 必须是 `second`。
- `mode=audio` 但协议为 `realtime` 或 `chat_completions` / `responses`（`gpt-audio` 系）：不允许配置 `media_pricing_json`，继续 token 计费。
- `mode=video`：`unit` 必须是 `second` 或 `call`；默认 `second`，只有管理员显式选择 `call` 的非时间型产物才允许。
- `mode=image` / `image_generation`：`unit` 必须是 `image`。
- `mode=chat` / `responses` / `embedding` 与 `realtime` 协议：不允许配置 `media_pricing_json`，配置即保存失败。
- `call` 不是「拿不到秒」的兜底；拿不到秒按 §7 的降级链处理，避免把可计量视频退化成按次。

## 4. 分辨率档

### 4.1 视频档位

统一五档，按**短边**（`min(width, height)`）归桶：

| 档位 | 短边条件 | 典型尺寸 |
| --- | --- | --- |
| `480p` | ≤ 576 | 854×480、640×480 |
| `720p` | ≤ 900 | 1280×720、720×1280 |
| `1080p` | ≤ 1350 | 1920×1080、1080×1920 |
| `1440p` | ≤ 1800 | 2560×1440 |
| `2160p` | > 1800 | 3840×2160 |

### 4.2 图片档位

统一三档，按**长边**（`max(width, height)`）归桶：

| 档位 | 长边条件 | 典型尺寸 |
| --- | --- | --- |
| `1k` | ≤ 1280 | 1024×1024 |
| `2k` | ≤ 2560 | 1536×1024、1024×1536、1536×1536、2048×2048 |
| `4k` | > 2560 | 4096×4096 |

档位是**我们的计价桶**，不是厂商官方档位名；厂商 768P、1.5K 等标签按上述阈值归桶。

### 4.3 档位事实来源与冻结

- 视频：创建时取参数归一层产出的生效 `size` / `resolution`（不是原始请求，不含被忽略参数），冻结进 `media_jobs.request_snapshot_json`；终态上游回报了不同分辨率时以终态为准并回写快照。创建时同时冻结该模型当时的 `mediaPricing` 价格快照（`baseUsd` / `baseTier` / `tierMultipliers` / `unit`）与生效档位；终态按快照计价，不读当前目录价——任务创建后管理员改价不影响在途任务。快照仅内部计量使用，不在任务面响应回显。
- 图片：取请求生效 `size`；`auto` / 缺省 / 无法解析时用模型 `baseTier`，不因上游实际输出尺寸二次改价。
- 异步任务轮询不得重新解析原始请求；只读创建时冻结值。
- 视频/图片模型必须配置**完整档位集合**（五档/三档），缺档拒绝保存；`baseTier` 必须在集合内且倍率为 `1.0`。这样任何请求档位都有确定价格，不出现「未配置档位按基础价」的漏价。`unit=call` 的视频模型没有档位，`baseTier`/`tierMultipliers` 为空。

## 5. 价格模型

### 5.1 `media_pricing_json`

`models` 表新增可空列 `media_pricing_json text`。非空即为统一模板；NULL/空表示继续走 legacy 维度（历史兼容，见 §9.4）。结构：

```json
{
  "version": 1,
  "unit": "second",
  "baseUsd": 0.10,
  "baseTier": "720p",
  "tierMultipliers": {
    "480p": 0.5,
    "720p": 1.0,
    "1080p": 2.0,
    "1440p": 3.0,
    "2160p": 5.0
  }
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `version` | int | 是 | 当前固定 `1`；未知版本拒绝 |
| `unit` | string | 是 | `second` / `image` / `call` |
| `baseUsd` | number | 是 | 基准档每单位美元价（视频/音频秒价、图片张价、按次价） |
| `baseTier` | string | 视频/图片必填 | 必须是 `tierMultipliers` 的键；倍率必须为 `1.0` |
| `tierMultipliers` | object | 视频/图片必填 | 键为 §4 的完整档位集合；值为有限正数 |

示例：

```json
{"version":1,"unit":"second","baseUsd":0.0002,"baseTier":"","tierMultipliers":{}}
{"version":1,"unit":"image","baseUsd":0.04,"baseTier":"1k","tierMultipliers":{"1k":1.0,"2k":1.6,"4k":3.0}}
{"version":1,"unit":"call","baseUsd":0.3429,"baseTier":"","tierMultipliers":{}}
```

### 5.2 校验

- `unit` 与模型 `mode` / 协议按 §3 匹配。空串 `mediaPricing` 归一为 NULL（legacy），不落空串。
- `baseUsd` 有限且 ≥ 0；免费价格明确保存 `0`，`0` 视为有效价格（可绑定、可按 0 结算），不得按 falsy 判成未定价。硬上限 1000 USD/单位，防止误输入。
- `tierMultipliers` 的值有限且 > 0 且 ≤ 100；视频/图片必须全集；`baseTier` 倍率 = `1.0`。音频/按次：`baseTier` 必须为空字符串，`tierMultipliers` 必须为空对象。
- 未知字段、未知档位键、`version != 1` 拒绝保存；JSON 体积上限 4KB。
- 同一写入（创建/`PATCH`）同时提交 `mediaPricing` 与 legacy 媒体价格字段（`ttsInputUsdPer1MChars`、`audioInputUsdPerSecond`、`videoOutputUsdPerSecond`、`videoOutputUsdPerCall`、`outputUsdPerImage`、图像/音频 token 价）返回 `400`，避免双口径并发写入。
- 已配置 `mediaPricing` 的目录模型（内置/全局）不允许通过 `PATCH` 清空回 legacy；自定义模型可清空，但清空后变为未定价、不可绑定。确需回退目录行由维护脚本在授权下执行并审计。
- 运行期遇到非法 `media_pricing_json`：不静默回落 legacy 猜测，按「未配置有效价格」处理并记 error；绑定/计价目录按无价行拒绝，避免用坏数据算出错误成本。
- `media_pricing_json` 存在的行，legacy 维度字段（`tts_input_usd_per_1m_chars`、`audio_input_usd_per_second`、`video_output_usd_per_second`、`video_output_usd_per_call`、`output_usd_per_image`、`image/audio token`）不再参与结算；管理面隐藏 legacy 价格编辑，只读展示历史值（如有）。
- 非管理员提交任何价格字段继续 `400`；权限矩阵不变。

### 5.3 价格权威源与模板默认

- **运行时唯一权威**：`models.media_pricing_json`（DB 行）。`chainCatalogPricing` 只读该列；静态层只在 `media_pricing_json` 为空时供 legacy 计价。
- **seed 来源**：`catalogdata/*.json` 每行新增 `mediaPricing`；maintenance seed 写入 `media_pricing_json`。该列采用 **`COALESCE(NULLIF(existing, ''), EXCLUDED)`** 语义：已有非空值（含管理员保存/手工覆盖）不覆盖，NULL/空串才填充；不套用其他价格列的「`source='manual-override'` 整列保护」，否则历史手工覆盖行的新媒体价格永远无法补齐。
- **新增模型模板**：管理员创建媒体模型时若未提交 `mediaPricing`，后端复制**同供应商 + 同 `mode` + 同 `unit` + 同媒体协议族**的最近一行 `media_pricing_json` 作为默认（未提交时 `unit` 按模式默认推导：image→`image`、audio→`second`、video→`second`；视频 `call` 必须显式提交 `mediaPricing`，不触发复制；协议族按 `audio_speech`、`audio_transcription` / `audio_job_*`、视频时间型区分，避免把 TTS 秒价复制给 STT）；没有同族同单位行则返回 `400`「请先配置媒体统一价格」。普通用户创建个人媒体模型仍走现有「配置模板」可信来源复制；未选择模板则保持未定价，不能由客户端自带价格。管理员只需改基准价，不重复填档位。
- **改价**：现有模型 `PATCH` 价格分支接受 `mediaPricing`，保存前完整校验，写操作审计（旧值/新值），失效模型目录缓存；不新增独立 pricing API。
- 官方价只进 `pricing_notes` / `sourcePricingNote` 供参考，不参与计算；不再要求新增媒体模型逐行官方取证。

## 6. 计费引擎与行项

### 6.1 引擎分支

`internal/pricing` 的 `BuildCostBreakdown` / `EstimateProviderCostUsd` 在供应商策略之前增加统一媒体分支：

1. `pricing.MediaPricing != nil` → 统一模板；否则走既有 per-provider 策略（legacy）。
2. 选择档位：`CostInput.ResolutionTier`（由计量层传入）；为空用 `baseTier`；`ResolutionTier` 非空但不在 `tierMultipliers` 中视为价格数据无效——不回落 `baseTier` 猜测，按无价处理并记 error（目录绑定/派发拒绝；已发生请求记 0 成本与错误日志）。
3. `unitPrice = baseUsd × tierMultipliers[tier]`（基础档倍率 1.0；音频 / 按次无档位，倍率按 `1.0`）。
4. 数量：
   - `second` + video → `OutputVideoSeconds`
   - `second` + audio → `AudioInputSeconds`
   - `image` → `OutputImageCount`
   - `call` → `VideoCalls`（任务粒度恒 1）
5. 产出唯一行项；`BillingPolicy = "media_unified_v1"`。

`EstimateProviderCostUsd` 在媒体域同样返回统一结算价，不是厂商账单估算（符合 D4）；账户成本/毛利如仍要对照官方价，另立只读参考字段，不参与结算。`CostInput.CostUsd` 显式覆盖沿用既有优先级；同步媒体路径不根据上游账单注入该字段。异步媒体任务沿既有机制在终态由统一引擎算出结算价后作为 `CostUsd` 传给 usagewriter（是网关 tariff，不是上游账单金额）。

**两处引擎必须同源实现**：`gateway/internal/pricing`（派发/在途估算）与 `shared/platform/usagepricing`（usagewriter 冻结路径，gateway 直投与 jobs 共用）都实现同一 `media_unified_v1` 分支；两处由同一组黄金用例对齐输入、行项与 `cost_usd`，禁止只改一处造成「在途估算」和「落库快照」两套价格。`usagepricing` 的目录 SELECT/row 同步读取 `media_pricing_json`；`usagewriter.UsageRecordInput` / `gatewayusage.PricingCostInput` 增加 `ResolutionTier` 透传字段。运行时目录缓存 `gatewayruntimecache.ProviderModelCatalogItem` 增加 `MediaPricing json.RawMessage`，模型 SELECT/scan 与 `chainCatalogPricing` 同步。

### 6.2 行项扩展

`CostLineItem` 增加可选字段（JSON `omitempty`，历史快照读取不受影响）：

- `Tier`：`480p` / `720p` / ... / `1k` / `2k` / `4k` / 空。
- `Multiplier`：本次实际倍率。
- `BaseUnitPriceUsd`：`baseUsd`。
- `QuantitySource`：`upstream` / `request` / `request_media` / `gateway_parse` / `default` / `estimated`。

同一组字段必须同时加到 `gateway/internal/pricing.CostLineItem` 与 `shared/platform/usagewriter.CostLineItem`（冻结快照 JSON 的结构体），否则 gateway 估算与落库快照字段不一致。

行项标签：

- 视频秒：`视频秒（720p）`
- 音频秒：`音频秒`
- 图片：`输出图片（1k）`
- 按次：`按次`

### 6.3 不重复计费

- `media_pricing_json` 非空时，引擎**不产出** `tts_input_chars`、`image_output`、`audio_input`、`audio_output` 或 legacy 视频行项，即使上游返回了对应 token；token 只作为 usage 列记录，用于统计与诊断。
- `media_pricing_json` 为空时，完全走 legacy 路径，行为与现状一致。
- 同一行只能有一个模板分支，禁止 legacy + 新模板同时产出行项。

## 7. 计量来源与优先级

### 7.1 视频

优先级：

1. 上游终态 `duration` / `seconds_length` → `source=upstream`。
2. 创建请求生效 `seconds` → `source=request`（现有 §2.8.2 已实现）。
3. 适配器默认时长常量（请求未传 `seconds` 时厂商默认，如 Hailuo 6s、Seedance 5s）→ `source=default`。默认时长由 `gatewaymedia` 视频 adapter 按厂商/模型族声明，不新增模型价格字段；新模型族默认时长不同则随 adapter 一起声明。
4. 产物时长探测（纯 Go 解析，见 §8.4，默认不发起网络请求，仅 `DurationProbe=true` 的适配器启用）→ `source=gateway_parse`。
5. 全部失败 → 0 秒 + `usage_missing`，成本 0；不猜测。

分辨率：创建冻结的生效档位；终态上游回报不同档位时以终态为准。异步任务终态计价优先使用创建时冻结的 `mediaPricing` 快照；历史任务无快照时回退当前目录（legacy）计价，并在日志标注。

### 7.2 音频

TTS：

1. 上游回报 `duration`（如 Volcengine 同步 TTS）→ `source=upstream`。
2. 网关解析产出音频字节（WAV/PCM/MP3/AAC/FLAC/OGG）→ `source=gateway_parse`。
3. 解析失败但请求 `input` 字符数可得 → `seconds = chars ÷ charsPerSecond`（默认常量 4 字符/秒；由 TTS adapter 按厂商/模型族声明覆盖，不进 `media_pricing_json`）→ `source=estimated`。
4. 全部失败 → 0 + `usage_missing`。

STT / 同步转写：

1. 上游 `duration` → `source=upstream`。
2. 在请求体转发链路上 tee 解析上传音频（multipart `file` 或二进制 body），不额外缓冲整段：WAV/FLAC/MP4/M4A 读容器头总样本；MP3/AAC 优先 CBR 字节率（文件大小 ÷ 每秒字节数），VBR MP3 需完整流扫描，无法完整扫描时按码率估算并标 `estimated`。
3. 全部失败 → 0 + `usage_missing`。

长音频异步任务（ASR）：

1. 轮询终态 `duration` / `audio_info.duration`（现有已实现）→ `source=upstream`。
2. 创建时同样冻结 `mediaPricing` 价格快照；终态按快照秒价结算，不受中途改价影响。
3. 失败 → `usage_missing`，不按上传文件重复解析（上游已给出规模）。

### 7.3 图像

- 张数：响应存在 `data[]` → 有效条目数（`0` 也按 `0`，不按请求 `n` 补差）→ `source=upstream`；响应缺失 `data[]` → 请求 `n` → `source=request`。
- 档位：请求生效 `size` → `source=request`；`auto`/缺省 → `baseTier` → `source=default`。
- 图片 token（若上游返回）继续写入 usage 列，但不计费。

### 7.4 来源标记与 `usage_missing`

- 来源写入 `cost_breakdown_snapshot_json` 的行项 `QuantitySource`，并在 `media_jobs.usage_json` / `usage_records` 既有元数据中保留可读摘要；不新增专用列。
- `usage_missing` 仍用现有标记；只在所有降级来源都不可用时置位。
- 失败 / 取消 / 过期任务不虚计（现状不变）。

## 8. 纯 Go 媒体时长解析

### 8.1 能力边界

Go 标准库**没有**现成的音频/视频时长解析器（`image/*` 只处理静态图片；没有 `audio`/`video` 标准包）。本设计用标准库（`encoding/binary`、`bufio`、`bytes`、`io`、`net/http`）实现容器头/帧解析，**不调用 ffprobe/mediainfo/ffmpeg，不使用 cgo**，也不依赖外部本地工具。纯 Go 第三方库非必要，优先自研最小解析器。

### 8.2 格式与策略

新增共享包 `backend-go/shared/platform/mediaduration`：

| 格式 | 解析点 | 流式策略 | 失败条件 |
| --- | --- | --- | --- |
| WAV（RIFF） | `fmt ` 的 byte rate + `data` chunk 大小 | 头部即可得；流式累计 data 字节 | 缺 `fmt `/`data` |
| 裸 PCM | 请求 `response_format=pcm` 的采样率/位深/声道（OpenAI/Gemini 约定） | `字节数 ÷ (采样率×声道×位深/8)` | 参数缺失 |
| MP3 | ID3v2 跳过；MPEG 帧头；Xing/Info/VBRI；CBR 可用字节数 ÷ 字节率 | 帧扫描状态机，只保留少量状态 | 无有效帧 |
| AAC ADTS | ADTS 帧头（采样率、每帧 1024 样本） | 帧计数 | 无有效帧 |
| FLAC | STREAMINFO 的 total samples + sample rate | 头部即可得 | 缺 STREAMINFO |
| OGG（Opus/Vorbis） | 页面 granule position（Opus 48kHz，扣 pre-skip；Vorbis 取 identification 采样率） | 保留最后一页头/尾段 | 无 granule |
| MP4/M4A/MOV | `moov/mvhd`（或 `mdhd`）的 duration/timescale；`moov` 在尾部时用有界尾缓冲 | 头部 + 尾环缓冲（≤4MB） | 找不到 `moov/mvhd` |
| WebM | EBML Segment Info Duration；缺失时取最后一个 Cluster 时间码 + 该 Cluster 内最后 Block 相对时间（或 DefaultDuration） | 头部 + 有界尾缓冲 | 缺 Duration 且无 Cluster |
| 未知格式 | 不解析 | — | 返回不支持 |

### 8.3 集成点

- `Meter`：实现 `io.Writer`，由响应管道的 `OnChunkRead` / `io.TeeReader` 喂入；只在成功响应、且模型 `unit=second` 时启用。
- TTS 二进制透传（`gatewayresponse/nonstream.go` 的纯透传管道）与 JSON 转二进制（gemini/minimax/volcengine 转换管道）都接同一 `Meter`；流结束后取时长再落 usage。
- STT：在请求解析阶段对上传音频做一次有界解析（容器头优先；CBR 用文件大小/码率；不落盘）；失败不阻断请求，来源标 `request_media` 或 `estimated`。
- 视频：优先上游/请求/默认；`ProbeURL` 作为可选兜底，见 §8.4。

### 8.4 视频产物探测（可选兜底）

- 仅当以下全部成立才发起：上游无 duration、请求无生效 seconds、适配器未声明默认时长、且适配器 `DurationProbe=true`。
- 复用既有内容下载路径（`adapter.BuildContentRequest` 或 `ContentFromArtifact`），带 Range：先取前 2MB，再取尾 4MB；总下载 ≤8MB、超时 10s、读完即丢弃，不落盘、不缓存（零资源存储原则不变）。
- 服务器不支持 Range 或解析失败 → `usage_missing`，不整段下载。
- 默认关闭（`DurationProbe=false`），当前已知厂商均有上游/请求/默认来源；未来接入无时长元数据的厂商时再显式开启。

### 8.5 内存与安全边界

- 头部解析状态 ≤64KB；MP4/WebM 尾环缓冲 ≤4MB；MP3 帧扫描只保留帧计数/时长状态；不整段缓冲音频/视频。
- 解析器只读字节，不执行媒体内容；不引入解码器、不处理像素/采样数据。
- 任何解析失败都不改变上游响应与转发结果，只影响计量来源。

## 11. 与统计、额度、成本语义的关系

- `cost_usd` 在媒体域 = 统一结算价；API Key / 授权额度（`limits_json` 美元额度）继续按 `success_cost_usd` 扣减，无需改额度逻辑。
- 账户「成本」统计变为「按统一结算价」，不再等于厂商账单；报表/页面文案标注「统一结算价」，避免误读为上游发票金额。
- 统计聚合 worker 继续聚合 `cost_usd` 与现有媒体计量列；分辨率档不新增聚合维度。
- 历史报表与切换后报表不可直接横向比较；以 `billingPolicy=media_unified_v1` 或切换日期区分。
- 如需毛利对账，后续可加只读「官方参考价」字段/报表，不参与结算。

## 12. 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 自定价低于上游实际成本 | 用量越大亏越多 | 设置基准价时保证 `baseUsd × 最高档倍率 ≥ 最高档官方价 × 安全系数（建议 ≥1.2）`，低档倍率下浮；定期复核 |
| 分辨率/质量/帧率/输入图等未建模 | 个别请求估算偏差 | 接受为产品定价近似；必要时提高对应档倍率或模型覆盖 |
| TTS 解析失败 | 少计/估算偏差 | 字符/语速估算兜底 + `estimated` 标记；监控 `usage_missing` 比例 |
| 视频探测产生额外网络成本 | 带宽/时延 | 默认关闭，仅显式 `DurationProbe` 模型启用；Range + 上限 8MB |
| 历史数据不可比 | 报表误读 | 标注切换日期与 `billingPolicy`；不重算 |
| 存量未迁移行继续 legacy | 同一目录两种口径 | 66 行一次性迁移 + 16 行显式保持 + 1 行缺口登记；目录「旧口径」标识；后续清理 legacy 分支另立任务 |
| 回滚旧二进制 | 媒体价回退静态 legacy 价，管理员新改 `mediaPricing` 不生效 | 回滚窗口内接受旧口径；发布说明标注；回滚后恢复新版本即恢复 DB 价 |
| 价格被误改 | 额度异常 | 严格校验 + 操作审计 + 目录缓存失效；改价仅管理员 |

| MEDIA-BILL/AC-010 | MUST | 新媒体模型未提交 `mediaPricing` | 自动复制同供应商同 mode 同 unit 同协议族的最近一行价格；无同族同单位行 400 |
| MEDIA-BILL/AC-011 | MUST | 目录/广场读取媒体模型 | 返回 `mediaPricing`；卡片/抽屉显示逐档价格，不再只读灰显 |
| MEDIA-BILL/AC-012 | MUST | 读取历史 usage 明细 | 旧快照与 `cost_usd` 原样展示，不重算 |
| MEDIA-BILL/AC-013 | MUST | 纯 Go 解析器对 WAV/PCM/MP3/AAC/FLAC/OGG/MP4/WebM 夹具 | 秒数误差 ≤ 50ms；无外部工具/cgo；内存不随文件线性增长 |
| MEDIA-BILL/AC-014 | MUST | 解析器对未知格式/损坏字节 | 返回不支持/失败，不 panic，不影响响应转发 |
| MEDIA-BILL/AC-015 | MUST | 同一媒体请求分别经 `gateway/internal/pricing` 与 `shared/platform/usagepricing` | 两处 `cost_usd`、行项 kind/unit/tier/multiplier 和快照金额一致；黄金用例钉住 |
| MEDIA-BILL/AC-016 | MUST | `media_pricing_json` 为非法 JSON | 不静默回落 legacy 猜测；按无价行拒绝绑定/计价并记 error |
| MEDIA-BILL/AC-017 | MUST | 媒体模型 `baseUsd=0`（免费） | 保存/绑定/结算均按有效价格处理，成本为 0；不得被判成未定价 |
| MEDIA-BILL/AC-018 | MUST | 异步视频/音频任务创建后管理员改价，任务随后终态 | 按创建时冻结的 `mediaPricing` 结算；在途任务不受改价影响 |
| MEDIA-BILL/NFR-001 | MUST | 计费热路径 | 新模板只读内存目录，不新增每请求 DB 扫描；目录查询沿用现有 1s memo |
| MEDIA-BILL/NFR-002 | MUST | 媒体响应计量 | 不整段缓冲音频/视频；尾环缓冲 ≤4MB，头部状态 ≤64KB |
