# 非对话媒体统一计费设计

> 状态：设计定稿（2026-11-19 用户裁决：视频同样乘分辨率倍率；其余细节由实现方决定）；已完成深挖复查修订。P0/P1/P2/P3/P4 已落地于当前工作区（schema 26、`media_pricing_json` 读写、两引擎 `media_unified_v1` 分支、分辨率档冻结、异步任务价格快照、同步图片 size/n 计量、纯 Go `mediaduration` 8 格式解析、TTS/STT 秒数取证与 `charsPerSecond` 兜底、legacy 行秒/字符互斥门控、67 行 `catalogdata` 迁移与 seed 重生成、GLM/MiniMax 视频产物有界 Range 探测），定向单测通过。链级媒体用例已在 macOS + 真实 dev PG 复跑通过（`JUHE_AI_TEST_EXTERNAL=1 go test ./projects/gateway/cmd/juhe-ai-gateway/ -run 'Media|Video|Playground'`，2026-11-19；`cmd` 包的 Windows 依赖测试已加 `//go:build windows`、`models.media_pricing_json` 夹具列已补齐）。
> 定位：非对话媒体模型（`image` / `image_generation` / `audio` / `video`，不含 `realtime` 对话语音，也不改变 chat / responses / embedding 的 token 计费）的统一计价模板——**秒 / 张 / 次 + 分辨率倍率 + 自定价**。
> 取代关系：本文生效后，[模型价格与用量统计口径](模型价格与用量统计口径.md) §2.5/§2.6 与 [音频视频模型接入与统一媒体网关设计](音频视频模型接入与统一媒体网关设计.md) §10 中「按厂商真实定价维度逐行适配」的口径只适用于历史快照与存量记录；[供应商独立计费与模型目录展示设计](供应商独立计费与模型目录展示设计.md) §2.1/§2.3 的「不统一媒体计费规则」在本域让位于本文。历史 `cost_breakdown_snapshot_json` 不重算。

## 1. 问题与目标

### 1.1 当前问题（证据）

1. **计价维度碎片化。** `catalogdata/*.json` 共 216 行，其中 84 行是媒体模型（audio 41、video 24、image_generation 19）。其中 67 个可迁移行合并同义维度后为 10 种价格维度组合：视频秒价、视频次价、TTS 字符价、音频秒价、图像按张、图像按 token、音频输入/输出 token 及其组合；把 1 个无价 video 行也算入为 11 种；若把 16 个不迁移行（13 个 `realtime` + 3 个 `gpt-audio`）也计入，共 14 种。`video_output_seconds` 与 `video_output_calls` 还互斥。
2. **媒体价格没有进入模型行。** `models` 表只有 `input/output/cached/...`、`image_input/output_usd_per_1m`、`audio_input/output_usd_per_1m`、`output_usd_per_image` 等 token/按张列，没有 `tts_input_usd_per_1m_chars`、`audio_input_usd_per_second`、`video_output_usd_per_second`、`video_output_usd_per_call`。运行时由 `chain_pricing.go:280` 的 `chainCatalogPricing` 从 `go:embed` 静态 JSON 补齐；前端明确注释这些字段「由后端静态定价表透传、随目录 API 下发，只读展示」（`providerModelFormatters.ts:98-105`）。结果是改价/加模型要改 JSON、重生成 seed、补锚点测试、同步文档，管理面改不了。
3. **视频自定义模型实际上无法定价。** `write_routes.go` 的 `customInputHasCompletePrice` 对 `mode=video` 恒返回 `false`，注释写明「无管理面秒价/次价通道」；`audio` 只认音频 token 价，`per-second/per-char` 价只在静态层。
4. **官方分辨率档被压成主档。** xAI `grok-imagine-video-1.5` 官方 480p `$0.08/s`、720p `$0.14/s`、1080p `$0.25/s`，目录只落 720p；MiniMax Hailuo 国内站 768P-6s 2.00 元/条（$0.2857），768P-10s、1080P-6s 等档只写在注释（国际站 512P 历史价另留档）；Volcengine Seedance 官方按输出 token × 分辨率档，网关只落 720p 参考秒价；Gemini/OpenAI 图像按 image token，MiniMax/xAI/GLM/Qwen/Volcengine 图像按张，分辨率和质量都不进价格。非主档实际成本偏差常见 2~5 倍。
5. **缺失计量时存在漏计。** TTS token 口径模型（如 `gpt-4o-mini-tts`）上游二进制响应无 usage，网关无 token 自算维度，直接 0 计费 + `usage_missing`；视频按次与按秒两套维度让同一类产物出现两种结算形态。
6. **成本语义被混用。** `cost_usd` 同时承担「上游账单估算」和「API Key / 授权美元额度扣减」（`limits_json` 的 `limit` 为美元金额，配额读 `success_cost_usd`）。按厂商官方价逐行适配时，任何非主档偏差都会同时污染成本观测和客户额度。

### 1.2 目标

- 媒体域只保留三种计价单位：**秒、张、次**；token 计费维持现状。
- 分辨率作为统一倍率维度：视频秒价乘分辨率倍率，图片张价乘分辨率倍率；音频不乘。
- 媒体价格进入模型行，管理面可编辑、目录可展示、seed 可默认；新增模型不再逐厂商适配官方价格表。
- `cost_usd` 在媒体域明确为**统一结算价（tariff）**，官方价只作定价参考。
- 上游拿不到秒时，能以纯 Go 解析音频/视频时长或从生效请求推导，绝不因缺计量静默计 0。

### 1.3 非目标

- 不改 chat / responses / embedding 的 token 价格模型、长上下文倍率、服务档位、缓存价。
- 不改 `realtime` 对话语音的 audio token 计费（属对话域，另立需求）。
- 不改媒体请求/响应协议、分辨率选择、厂商 adapter 报文；只改计价与计量。
- 不追求与厂商官方账单逐档一致；不要求新增媒体模型时逐行官方取证。
- 不重算历史 `usage_records` 与 `cost_breakdown_snapshot_json`。

## 2. 核心裁决

| 编号 | 裁决 | 影响 |
| --- | --- | --- |
| D1 | 媒体域统一为 `second` / `image` / `call` 三种计量单位；`tts_input_chars` 与 image/audio token 不再作为新媒体模型计费维度 | 新增模型只选类别和单位，不再选厂商维度 |
| D2 | 视频秒价、图片张价都乘**统一分辨率倍率**；音频不乘 | 480p/4K、1K/4K 不再同价 |
| D3 | 媒体价格以 `models.media_pricing_json` 为运行时唯一权威；静态 `catalogdata/*.json` 只做 seed 来源与 legacy 兜底 | 管理面可改价，目录可显示 |
| D4 | 媒体域 `cost_usd` = 统一结算价，不再是厂商账单估算；额度、统计继续用它 | 成本观测口径改变，需在文档与界面标注 |
| D5 | 缺失秒数按「上游事实 → 生效请求 → 适配器默认（视频）→ 网关解析 → 估算」降级，并记录来源；全部失败才 0 + `usage_missing` | 消除成功流量静默 0 计费 |
| D6 | 计量解析使用纯 Go 实现，不依赖 ffprobe/mediainfo 等外部本地工具、不使用 cgo | 部署零新增外部依赖 |

## 3. 计量单位与类别映射

| 模型形态 | `unit` | 计量字段 | 计费行项（`CostLineKind`） | 说明 |
| --- | --- | --- | --- | --- |
| `image` / `image_generation` | `image` | `output_image_count` | `image_output_unit` | 成功响应 `data[]` 计数优先，否则请求 `n` |
| `audio`（TTS，`audio_speech` 协议） | `second` | `audio_input_seconds`（列名沿用旧名，语义为「音频秒」） | `audio_input_seconds` | 优先上游 `duration`，否则网关解析产出音频时长 |
| `audio`（STT / ASR，`audio_transcription` / `audio_job_*` 协议） | `second` | `audio_input_seconds` | `audio_input_seconds` | 优先上游 `duration`，否则解析请求上传的音频 |
| `video`（时间型产物） | `second` | `output_video_seconds` | `video_output_seconds` | 上游 `duration` 优先，否则请求生效时长词（`duration`/`seconds`）/ 适配器默认 |
| `video`（非时间型产物，如 3D 文件） | `call` | 无独立列（`cost_usd` 落库，行项在快照） | `video_output_calls` | 一次任务 = 一次调用；只用于 3D 等没有时长概念的产物 |
| `audio` + `realtime` 协议 | 不适用 | audio token 列 | 既有 audio token 行项 | 对话域，保持现状 |
| `audio` + `chat_completions` / `responses`（如 `gpt-audio` 系） | 不适用 | audio token 列 | 既有 audio token 行项 | 音频对话模型，按对话 token 计费，不改 |
| `chat` / `responses` / `embedding` | 不适用 | token 列 | 既有 token 行项 | 保持现状 |

约束：

- `mode=audio` 且协议含 `audio_speech` / `audio_transcription` / `audio_job_create` 等音频媒体协议：`unit` 必须是 `second`。
- `mode=audio` 但协议为 `realtime` 或 `chat_completions` / `responses`（`gpt-audio` 系）：不允许配置 `media_pricing_json`，继续 token 计费。
- `mode=video`：`unit` 必须是 `second` 或 `call`；默认 `second`，只有管理员显式选择 `call` 的非时间型产物才允许。
- `mode=image` / `image_generation`：`unit` 必须是 `image`。
- `mode=chat` / `responses` / `embedding` 与 `realtime` 协议：不允许配置 `media_pricing_json`，配置即保存失败。
- `call` 不是「拿不到秒」的兜底；拿不到秒按 §7 的降级链处理，避免把可计量视频退化成按次。

## 4. 分辨率档

### 4.1 视频档位

统一五档，按**短边**（`min(width, height)`）归桶：

| 档位 | 短边条件 | 典型尺寸 |
| --- | --- | --- |
| `480p` | ≤ 576 | 854×480、640×480 |
| `720p` | ≤ 900 | 1280×720、720×1280 |
| `1080p` | ≤ 1350 | 1920×1080、1080×1920 |
| `1440p` | ≤ 1800 | 2560×1440 |
| `2160p` | > 1800 | 3840×2160 |

### 4.2 图片档位

统一三档，按**长边**（`max(width, height)`）归桶：

| 档位 | 长边条件 | 典型尺寸 |
| --- | --- | --- |
| `1k` | ≤ 1280 | 1024×1024 |
| `2k` | ≤ 2560 | 1536×1024、1024×1536、1536×1536、2048×2048 |
| `4k` | > 2560 | 4096×4096 |

档位是**我们的计价桶**，不是厂商官方档位名；厂商 768P、1.5K 等标签按上述阈值归桶。

### 4.3 档位事实来源与冻结

- 视频：创建时取参数归一层产出的生效 `size` / `resolution`，先经 adapter 实际出站换算再冻结进 `media_jobs.request_snapshot_json`——分辨率按 adapter 真实档位（Veo 仅 720p/1080p；xAI/Volcengine 仅 480p/720p/1080p，不能把原始 size 标准归档成 1440p/2160p），秒数按 adapter 真实出站值（GLM 量化到 5s/10s、xAI 四舍五入到整数秒、Veo 无 seconds 字段固定默认 8s）。创建时同时冻结该模型当时的 `mediaPricing` 价格快照（`baseUsd` / `baseTier` / `tierMultipliers` / `unit`）与生效档位；终态按快照计价，不读当前目录价——任务创建后管理员改价不影响在途任务。终态上游回报了不同分辨率时以终态为准（写入 `media_jobs.usage_json.resolution_tier`，不回写 `request_snapshot_json`）。快照仅内部计量使用，不在任务面响应回显。
- 图片：取请求生效 `size`；`auto` / 缺省 / 无法解析时用模型 `baseTier`，不因上游实际输出尺寸二次改价。
- 异步任务轮询不得重新解析原始请求；只读创建时冻结值。
- 视频/图片模型必须配置**完整档位集合**（五档/三档），缺档拒绝保存；`baseTier` 必须在集合内且倍率为 `1.0`。这样任何请求档位都有确定价格，不出现「未配置档位按基础价」的漏价。`unit=call` 的视频模型没有档位，`baseTier`/`tierMultipliers` 为空，计量层不得传入 `ResolutionTier`；引擎也不做档位选择或倍率相乘，倍率恒 `1.0`。
- 默认倍率表以 `720p` / `1k` 为 `1.0` 锚点。若模型 `baseTier` 不是锚点档，必须把整组默认倍率按 `1 / 默认倍率[baseTier]` 等比缩放，使 `baseTier` 倍率恒为 `1.0`；例如 `baseTier=1080p` 时视频默认倍率变为 `480p 0.25 / 720p 0.5 / 1080p 1.0 / 1440p 1.5 / 2160p 2.5`，`baseTier=2k` 时图片默认倍率变为 `1k 0.625 / 2k 1.0 / 4k 1.875`。不得直接套用锚点表导致 `baseTier` 倍率不为 `1.0`。

## 5. 价格模型

### 5.1 `media_pricing_json`

`models` 表新增可空列 `media_pricing_json text`。非空即为统一模板；NULL/空表示继续走 legacy 维度（历史兼容，见 §9.4）。结构：

```json
{
  "version": 1,
  "unit": "second",
  "baseUsd": 0.10,
  "baseTier": "720p",
  "tierMultipliers": {
    "480p": 0.5,
    "720p": 1.0,
    "1080p": 2.0,
    "1440p": 3.0,
    "2160p": 5.0
  }
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `version` | int | 是 | 当前固定 `1`；未知版本拒绝 |
| `unit` | string | 是 | `second` / `image` / `call` |
| `baseUsd` | number | 是 | 基准档每单位美元价（视频/音频秒价、图片张价、按次价） |
| `baseTier` | string | 视频/图片必填 | 必须是 `tierMultipliers` 的键；倍率必须为 `1.0` |
| `tierMultipliers` | object | 视频/图片必填 | 键为 §4 的完整档位集合；值为有限正数 |

示例：

```json
{"version":1,"unit":"second","baseUsd":0.0002,"baseTier":"","tierMultipliers":{}}
{"version":1,"unit":"image","baseUsd":0.04,"baseTier":"1k","tierMultipliers":{"1k":1.0,"2k":1.6,"4k":3.0}}
{"version":1,"unit":"call","baseUsd":0.3429,"baseTier":"","tierMultipliers":{}}
```

### 5.2 校验

- `unit` 与模型 `mode` / 协议按 §3 匹配。空串 `mediaPricing` 归一为 NULL（legacy），不落空串。
- `baseUsd` 有限且 ≥ 0；免费价格明确保存 `0`，`0` 视为有效价格（可绑定、可按 0 结算），不得按 falsy 或 `<= 0` 判成未定价。实现必须用独立的「价格存在」布尔/指针（如 `HasMediaPricing`）区分三类：有效 0 价、无 `media_pricing_json`、非法 `media_pricing_json`。硬上限 1000 USD/单位，防止误输入。
- `tierMultipliers` 的值有限且 > 0 且 ≤ 100；视频/图片必须全集；`baseTier` 倍率 = `1.0`。音频/按次：`baseTier` 必须为空字符串，`tierMultipliers` 必须为空对象。
- 未知字段、未知档位键、`version != 1` 拒绝保存；JSON 体积上限 4KB。
- 同一写入（创建/`PATCH`）同时提交 `mediaPricing` 与 legacy 媒体价格字段（`ttsInputUsdPer1MChars`、`audioInputUsdPerSecond`、`videoOutputUsdPerSecond`、`videoOutputUsdPerCall`、`outputUsdPerImage`、图像/音频 token 价）返回 `400`，避免双口径并发写入。
- 已配置 `mediaPricing` 的目录模型（内置/全局）不允许通过 `PATCH` 清空回 legacy；自定义模型可清空，但清空后变为未定价、不可绑定。确需回退目录行由维护脚本在授权下执行并审计。
- 非法 `media_pricing_json` 定义：JSON 语法错误、顶层非对象、缺 `version`/`unit`/`baseUsd`、`version != 1`、`unit` 不在枚举、`unit` 与 model `mode`/协议不匹配、视频/图片档位集合不完整或含未知档位、`baseTier` 不在集合或倍率不为 `1.0`、倍率非有限正数、体积超过 4KB。写入路径一律 `400`。
- 运行期读到非法 `media_pricing_json`：不静默回落 legacy 猜测，不猜测档位；该行按「无有效价格」处理并记 error，绑定/计价目录按无价行拒绝。已发生且无法拒绝的请求按 0 成本 + `usage_missing` 落库，不产生任何计费行项；禁止把非法值当作免费 0 价。
- 读侧 mode 推导例外：目录 `mode` 由 `supported_endpoint_modes_json` 投影而来，Gemini 原生 `generate_content` 图像行会投影为 `chat`，无 endpoint modes 的历史/迁移行投影为空。读侧仅在 `KindForMode(mode)` 可映射到 video/image/audio 时执行 unit/kind 校验；`chat`/`responses`/`embedding`/空 mode 保留结构合法的模板，由结算按请求 kind 的 `ValidateFor` 兜底（避免把真实图像价误判为非法价）。
- 写入路径按「新建 / 编辑既有模板」分流：新建永远严格，`mode=chat`/`responses`/`embedding`/空 mode 新配置 `mediaPricing` 仍 `400`。`PATCH` 已存在合法媒体模板的行（`HasMediaPricing=true`，含 Gemini `generate_content` 图像行、无 endpoint modes 迁移行）允许继续编辑价格/日期；模板仍按 `ValidateForMappedMode` 校验，可映射媒体 mode 的 unit/kind 错误仍拒绝。内置行完整性校验对这类行不再按文本模型要求上下文/最大输入容量，否则只改发布日期也会被 400 拦截。
- 管理面模型分类不能只依赖投影后的 `mode`：当 `mode` 投影为文本时，前端优先用 `mediaPricing.unit`（`image`/`second`/`call`）与 `outputModalities` 还原图像/视频/音频分类，保证既有媒体行的统一价格编辑入口可见且保存不被前端隐藏。
- 结算落库 `cost_usd=0` 有两种语义：有效 0 价（`mediaPricing` 校验通过且 `baseUsd=0`）不置 `usage_missing`；无价、非法价或计量缺失则置 `usage_missing`。统计与额度判断不得只用 `cost_usd=0` 推断免费。
- `media_pricing_json` 存在的行，legacy 维度字段（`tts_input_usd_per_1m_chars`、`audio_input_usd_per_second`、`video_output_usd_per_second`、`video_output_usd_per_call`、`output_usd_per_image`、`image/audio token`）不再参与结算；管理面隐藏 legacy 价格编辑，只读展示历史值（如有）。
- 非管理员提交任何价格字段继续 `400`；权限矩阵不变。

### 5.3 价格权威源与模板默认

- **运行时唯一权威**：`models.media_pricing_json`（DB 行）。`chainCatalogPricing` 只读该列；静态层只在 `media_pricing_json` 为空时供 legacy 计价。
- **seed 来源**：`catalogdata/*.json` 每行新增 `mediaPricing`；maintenance seed 写入 `media_pricing_json`。该列采用 **`COALESCE(NULLIF(existing, ''), EXCLUDED)`** 语义：已有非空值（含管理员保存/手工覆盖）不覆盖，NULL/空串才填充；不套用其他价格列的「`source='manual-override'` 整列保护」，否则历史手工覆盖行的新媒体价格永远无法补齐。**人工覆盖例外**：`source='manual-override'`、任一 legacy 媒体价格非空且 `media_pricing_json` 为空的行，由一次性迁移脚本在 `upgrade` 之后（`--phase=all` 或 `--phase=expand` 均可）按该行现有 legacy 值套用 §9.3 同一换算规则生成 `media_pricing_json` 并写入（expand 内含的 seed 对该类行保持 NULL）；无法自动换算的行保持 NULL、继续 legacy，并在 T215 登记人工补价。seed 不得直接用 catalogdata 值覆盖这类行的人工 legacy 价格，否则运行时权威会从人工价静默切到目录价。
- **新增模型模板**：管理员创建媒体模型时若未提交 `mediaPricing`，后端复制**同供应商 + 同 `mode` + 同 `unit` + 同媒体协议族**的最近一行 `media_pricing_json` 作为默认（未提交时 `unit` 按模式默认推导：image→`image`、audio→`second`、video→`second`；视频 `call` 必须显式提交 `mediaPricing`，不触发复制；协议族按 `audio_speech`、`audio_transcription` / `audio_job_*`、视频时间型区分，避免把 TTS 秒价复制给 STT）；没有同族同单位行则返回 `400`「请先配置媒体统一价格」。**最近一行**按 `release_date DESC NULLS LAST, catalog_order DESC NULLS LAST, id ASC` 排序取首行。普通用户创建个人媒体模型仍走现有「配置模板」可信来源复制；未选择模板则保持未定价，不能由客户端自带价格。管理员只需改基准价，不重复填档位。模板候选的 mode 同样可能投影为 `chat`/空：匹配时按候选模板的 `unit`、`outputModalities` 与协议族还原媒体类型后再与目标 `mode` 的 kind 比较，Gemini `generate_content` 图像行仍可作为同供应商图像模型的自动模板来源。
- **改价**：现有模型 `PATCH` 价格分支接受 `mediaPricing`，保存前完整校验，写操作审计（旧值/新值），失效模型目录缓存；不新增独立 pricing API。
- 官方价只进 `pricing_notes` / `sourcePricingNote` 供参考，不参与计算；不再要求新增媒体模型逐行官方取证。

## 6. 计费引擎与行项

### 6.1 引擎分支

`internal/pricing` 的 `BuildCostBreakdown` / `EstimateProviderCostUsd` 在供应商策略之前增加统一媒体分支：

1. `pricing.MediaPricing != nil` → 统一模板；否则走既有 per-provider 策略（legacy）。
2. 选择档位：`CostInput.ResolutionTier`（由计量层传入）；为空用 `baseTier`；`ResolutionTier` 非空但不在 `tierMultipliers` 中视为价格数据无效——不回落 `baseTier` 猜测，按无价处理并记 error（目录绑定/派发拒绝；已发生请求记 0 成本、`usage_missing` 与错误日志）。`unit=call` 跳过档位选择，要求 `ResolutionTier` 为空，倍率恒 `1.0`。
3. `unitPrice = baseUsd × tierMultipliers[tier]`（基础档倍率 1.0；音频 / 按次无档位，倍率按 `1.0`）。
4. 数量：
   - `second` + video → `OutputVideoSeconds`
   - `second` + audio → `AudioInputSeconds`
   - `image` → `OutputImageCount`
   - `call` → `VideoCalls`（任务粒度恒 1）
5. 产出唯一行项；`BillingPolicy = "media_unified_v1"`。

`EstimateProviderCostUsd` 在媒体域同样返回统一结算价，不是厂商账单估算（符合 D4）；账户成本/毛利如仍要对照官方价，另立只读参考字段，不参与结算。`CostInput.CostUsd` 显式覆盖沿用既有优先级；同步媒体路径不根据上游账单注入该字段。异步媒体任务在终态由统一引擎按创建时冻结的快照算出 `CostBreakdown` 与 `CostUsd`，`CostBreakdown` 作为 `UsageRecordInput.PricingSnapshot`、`CostUsd` 作为账户扣减金额一并交给 usagewriter（都是网关 tariff，不是上游账单金额）。

**两处引擎必须同源实现**：`gateway/internal/pricing`（派发/在途估算）与 `shared/platform/usagepricing`（usagewriter 冻结路径，gateway 直投与 jobs 共用）都实现同一 `media_unified_v1` 分支；两处由同一组黄金用例对齐输入、行项与 `cost_usd`，禁止只改一处造成「在途估算」和「落库快照」两套价格。`usagepricing` 的目录 SELECT/row 同步读取 `media_pricing_json` 并携带「价格存在」标志；`usagewriter.UsageRecordInput` 增加 `VideoCalls`、`ResolutionTier`、`QuantitySource`，`gatewayusage.PricingCostInput` 增加 `OutputVideoSeconds`、`VideoCalls`、`ResolutionTier`、`QuantitySource`。`usagewriter.HasCostDimension` 必须把 `TtsInputChars`、`AudioInputSeconds`、`OutputVideoSeconds`、`VideoCalls` 纳入计费维度，否则冻结路径会提前返回、既不生成行项也不落 `cost_usd`。异步任务终态不能只把 `CostUsd` 传给 usagewriter：必须把按冻结价算出的完整 `CostBreakdown` 作为 `UsageRecordInput.PricingSnapshot` 传入（含行项 kind、tier、multiplier、quantity source），否则 `usagepricing` 会按当前目录重新构建快照，冻结价失效。运行时目录缓存 `gatewayruntimecache.ProviderModelCatalogItem` 增加 `MediaPricing json.RawMessage` 与 `HasMediaPricing bool`，模型 SELECT/scan、`chainCatalogPricing` 与 `usagepricing` 目录行同步。媒体终态传入完整 `CostBreakdown` 后，`usagepricing` 的 60s 目录缓存只是无快照兜底，不参与媒体重算；本设计不新增跨进程缓存失效机制（在途任务按创建快照，不受改价窗口影响）。

### 6.2 行项扩展

`CostLineItem` 增加可选字段（JSON `omitempty`，历史快照读取不受影响）：

- `Tier`：`480p` / `720p` / ... / `1k` / `2k` / `4k` / 空。
- `BaseUnitPriceUsd`：`baseUsd`；类型为 `*float64`。免费价 `0` 必须保留在快照中，不能因 `omitempty` 被省略。
- `Multiplier`：本次实际倍率；类型为 `*float64`，`1.0` 也必须保留。
- `QuantitySource`：`upstream` / `request` / `request_media` / `gateway_parse` / `default` / `estimated`。

同一组字段必须同时加到 `gateway/internal/pricing.CostLineItem` 与 `shared/platform/usagewriter.CostLineItem`（冻结快照 JSON 的结构体），否则 gateway 估算与落库快照字段不一致。

行项标签：

- 视频秒：`视频秒（720p）`
- 音频秒：`音频秒`
- 图片：`输出图片（1k）`
- 按次：`按次`

### 6.3 不重复计费

- `media_pricing_json` 非空时，引擎**不产出** `tts_input_chars`、`image_output`、`audio_input`、`audio_output` 或 legacy 视频行项，即使上游返回了对应 token；token 只作为 usage 列记录，用于统计与诊断。
- `media_pricing_json` 为空时，完全走 legacy 路径，行为与现状一致。
- 同一行只能有一个模板分支，禁止 legacy + 新模板同时产出行项。

## 7. 计量来源与优先级

### 7.1 视频

优先级：

1. 上游终态 `duration` / `seconds_length` → `source=upstream`。
2. 创建请求生效时长词（`duration`/`seconds`，按用户原始词记录于 `params_applied`）→ `source=request`（现有 §2.8.2 已实现）。
3. 适配器默认时长常量（请求未传 `seconds` 时厂商默认；当前仅 Veo 3.0/3.1 系五模型声明 8s，出站显式 `parameters.durationSeconds=8`；Hailuo/Seedance 等上游默认值不在此表硬编码，缺失观测时走 P4 产物探测或 `usage_missing`）→ `source=default`。默认时长由 `gatewaymedia` 视频 adapter 按厂商/模型族声明，不新增模型价格字段；未在默认表声明的模型不猜。
4. 产物时长探测（纯 Go 解析，见 §8.4，仅显式声明 `ProbeArtifactDuration=true` 的适配器启用：当前 GLM、MiniMax）→ `source=gateway_parse`。
5. 全部失败 → 0 秒 + `usage_missing`，成本 0；不猜测。

`n>1` 不进入统一计费：`MediaJobIR` 只承载单产物/单秒数，P1 在参数层直接 400（`ErrParamUnsupported`），不调上游、不按 1 个少计；多产物支持另立需求（§14.4 #5）。

分辨率：创建冻结的生效档位（adapter 实际换算后的档位）；终态上游回报不同档位时以终态为准（`MediaJobUsage.ResolutionTier`）。异步任务终态计价优先使用创建时冻结的 `mediaPricing` 快照；历史任务无快照时回退当前目录（legacy）计价，并在日志标注。

### 7.2 音频

TTS：

1. 上游回报 `duration`（如 Volcengine 同步 TTS）→ `source=upstream`。
2. 网关解析产出音频字节（WAV/PCM/MP3/AAC/FLAC/OGG）→ `source=gateway_parse`。
3. 解析失败但请求 `input` 字符数可得 → `seconds = chars ÷ charsPerSecond`（默认常量 4 字符/秒；由 TTS adapter 按厂商/模型族声明覆盖，不进 `media_pricing_json`）→ `source=estimated`。
4. 全部失败 → 0 + `usage_missing`。

STT / 同步转写：

1. 上游 `duration` → `source=upstream`。
2. 在请求体转发链路上解析上传音频（multipart `file` 零拷贝切片或二进制 body），不额外缓冲整段、不落盘：WAV/FLAC/MP4/M4A 读容器头总样本；MP3/AAC ADTS/OGG 扫描完整帧/页面得到精确时长（请求体已在内存，不做码率估算）。解析失败不阻断请求 → `usage_missing`。
3. 全部失败 → 0 + `usage_missing`。

长音频异步任务（ASR）：

1. 轮询终态 `duration` / `audio_info.duration`（现有已实现）→ `source=upstream`。
2. 创建时同样冻结 `mediaPricing` 价格快照；终态按快照秒价结算，不受中途改价影响。
3. 失败 → `usage_missing`，不按上传文件重复解析（上游已给出规模）。

### 7.3 图像

- 张数：OpenAI images 面响应存在 `data[]` → 有效条目数（`0` 也按 `0`，不按请求 `n` 补差）→ `source=upstream`；响应缺失 `data[]` → 请求 `n` → `source=request`。Gemini 原生 `generateContent` 非流式响应按 `candidates[].content.parts[].inlineData` 的 `image/*` part 计数 → `source=upstream`；流式分片不按 part 计数（避免同一张图的分片重复计费），无上游计数时按请求 `generationConfig.candidateCount`（缺省 1）→ `source=request`。
- 档位：请求生效 `size` → `source=request`；`auto`/缺省 → `baseTier` → `source=default`。Gemini 原生面请求无像素尺寸时同样回落到 `baseTier`。
- 图片 token（若上游返回）继续写入 usage 列，但不计费。

### 7.4 来源标记与 `usage_missing`

- 来源写入 `cost_breakdown_snapshot_json` 的行项 `QuantitySource`，并在 `media_jobs.usage_json` / `usage_records` 既有元数据中保留可读摘要；不新增专用列。
- legacy 行（`media_pricing_json` 为空）只消费上游回报时长（`QuantitySource=upstream`：volcengine 同步 TTS duration、STT verbose_json duration 且无 token）；网关解析/字符估算秒数不进入 legacy 计费，`chain_usage` 在记录持久化前清空对应维度，避免字符+秒或 token+秒双重计费。统一模板行保留 `tts_input_chars` 作为可观测性字段，但计费只取秒数。
- `usage_missing` 仍用现有标记；只在所有降级来源都不可用时置位。
- 失败 / 取消 / 过期任务不虚计（现状不变）。

## 8. 纯 Go 媒体时长解析

### 8.1 能力边界

Go 标准库**没有**现成的音频/视频时长解析器（`image/*` 只处理静态图片；没有 `audio`/`video` 标准包）。本设计用标准库（`encoding/binary`、`bufio`、`bytes`、`io`、`net/http`）实现容器头/帧解析，**不调用 ffprobe/mediainfo/ffmpeg，不使用 cgo**，也不依赖外部本地工具。纯 Go 第三方库非必要，优先自研最小解析器。

### 8.2 格式与策略

新增共享包 `backend-go/shared/platform/mediaduration`：

| 格式 | 解析点 | 流式策略 | 失败条件 |
| --- | --- | --- | --- |
| WAV（RIFF） | `fmt ` 的 byte rate + `data` chunk 大小 | 头部即可得；流式累计 data 字节 | 缺 `fmt `/`data` |
| 裸 PCM | 请求 `response_format=pcm` 的采样率/位深/声道（OpenAI/Gemini 约定） | `字节数 ÷ (采样率×声道×位深/8)` | 参数缺失 |
| MP3 | ID3v2 跳过；MPEG 帧头逐帧累计 `samples / sampleRate`；Xing/Info/VBRI 只用于截断校验 | 帧扫描状态机，只保留帧计数/时长状态 | 无有效帧 |
| AAC ADTS | ADTS 帧头（采样率、每帧 1024 样本） | 帧计数 | 无有效帧 |
| FLAC | STREAMINFO 的 total samples + sample rate | 头部即可得 | 缺 STREAMINFO |
| OGG（Opus/Vorbis） | 页面 granule position（Opus 48kHz，扣 pre-skip；Vorbis 取 identification 采样率） | 保留最后一页 granule 与首包识别前缀 | 无 granule |
| MP4/M4A/MOV | `moov/mvhd` 的 duration/timescale；`moov` 在尾部时用有界尾缓冲 | 头部 + 尾环缓冲（≤4MB） | 找不到 `moov/mvhd` |
| WebM | EBML Segment Info Duration；缺失时取最后一个 Cluster 的 Timecode + 该 Cluster 内最后 Block 相对时间 | 头部 + 有界尾缓冲 | 缺 Duration 且无 Cluster |
| 未知格式 | 不解析 | — | 返回不支持 |

### 8.3 集成点（P2 已落地）

- `Meter`：实现 `io.Writer`，由响应管道的 `OnChunkRead` 喂入；只在成功 TTS 响应、非转换型（二进制透传）时启用，流结束后取时长再落 usage（`gatewayresponse/nonstream.go`）。
- TTS 二进制透传与 JSON 转二进制（gemini/minimax/volcengine 转换管道）接同一时长解析：转换型响应直接解析 `TransformResponse` 产物字节，透传型读取 `Meter.Duration()`；两者失败后回落 `chars ÷ charsPerSecond`（默认 4，`gatewaymedia.DefaultTTSCharsPerSecond`）。取证入口为 `gatewayresponse/speech_duration.go` 的 `ttsAudioSeconds`。
- STT：在请求解析阶段用 `gatewaybody.ExtractMultipartFilePart`（零拷贝）或 `RawBody` 对上传音频做一次完整解析；失败不阻断请求，来源标 `request_media`，全失败 `usage_missing`。入口为 `speech_duration.go` 的 `sttRequestAudioDuration`。
- 上游时长优先：`gatewaymedia.SpeechReportedSecondsFromJSON` 汇总 volcengine 顶层 `duration`（秒）与 minimax `extra_info.audio_length`（毫秒），来源 `upstream`。
- 视频：优先上游/请求/默认；仅 GLM/MiniMax 适配器声明 `ProbeArtifactDuration=true` 时，才在三级来源全缺失后走 §8.4 有界 Range 探测（P4 已实施）。

### 8.4 视频产物探测（可选兜底，P4 已实施）

- 仅当以下全部成立才发起：`completed` 视频任务、上游无 duration、请求无生效时长词（`duration`/`seconds`）、适配器未声明默认时长、目录模板 `unit=second`、且适配器实现 `VideoArtifactDurationProbeProvider` 并返回 true。当前仅 GLM（`video_result.url`）与 MiniMax（`file_download_url`）开启；其余已接入视频厂商均由上游 duration、请求时长或默认时长覆盖，不发起探测。
- 实现入口：`gatewaymedia.ProbeArtifactDuration`（Range 编排与边界校验）+ `mediaduration.ParseSegments`（头/尾片段解析 MP4/WebM）；链层 `chain_media_video_probe.go` 负责 HTTP 传输与 SSRF 防线。成功 `QuantitySource=gateway_parse` 并把秒数回填 `ir.Usage.OutputVideoSeconds`，终态 usage JSON 可审计。
- Range 策略：先取前 2MB；对象更大时再取尾 4MB；总下载 ≤8MB、超时 10s、读完即丢弃，不落盘、不缓存（零资源存储原则不变）。服务器返回 200 整包（忽略 Range）、416、`Content-Range` 缺失/非法、响应超限或片段解析失败，一律失败关闭为 `usage_missing`，不整段下载、不猜测。
- 传输安全：每次探测创建独立 `http.Transport`/`http.Client`（不复用账户认证、不带 Cookie/Authorization），强制接入 `shared/platform/upstreamhttp.NewDialGuard`；`artifacturl.go` 的 scheme/host 预检保留为第一层，探测层再拒绝 userinfo，`DialGuard.ValidateHost` 在请求前解析并阻断私网/回环/链路本地/保留地址，直连拨号由同一 guard 钉住已校验 IP。重定向 ≤3 次，每次重定向都重新做 scheme/host 预检；SOCKS 代理因远端解析无法钉住目标，探测面失败关闭。不要求产物 host 与账户 base URL 同源（Veo GCS、各厂商 CDN 域名与 API base 不同，同源/allowlist 会误杀）。开发环境仅通过既有 `JUHE_AI_UPSTREAM_BASE_URL_PRIVATE_ALLOWLIST` 放行 mock。
- 归属字段：探测失败只记 `media_duration_probe_failed` 结构化日志（`jobId`/`model`/`reason`），不记录签名 URL；任务仍按 `usage_missing` 结算，成本 0。

### 8.5 内存与安全边界

- 头部解析状态 ≤64KB；MP4/WebM 尾环缓冲 ≤4MB；MP3 帧扫描只保留帧计数/时长状态；不整段缓冲音频/视频。
- 解析器只读字节，不执行媒体内容；不引入解码器、不处理像素/采样数据。
- 任何解析失败都不改变上游响应与转发结果，只影响计量来源。
- 已知限制（P2 实测，均在失败时回落 `usage_missing`/字符估算，不猜测）：
  - WebM 无 `Duration` 时回退到最后 Cluster Timecode + 最后 Block 相对时间，未加 BlockDuration，通常低估一帧/一个 Cluster 尾部；最后 Cluster 不在 4MB 尾环内时无法回退。
  - `Meter` 对文件尾 `moov` 只保留最后 4MB，超过时拿不到 `mvhd`；完整切片 `Parse` 与 P4 的 `ParseSegments` 头/尾扫描不受此限（`moov` 跨越头尾且 `mvhd` 不在任一可见片段时仍失败关闭）。未实现 fragmented MP4（`moof`）汇总、未加 `BlockDuration` 的 WebM 尾帧精确修正。
  - MP3/AAC 在帧边界精确截断时无法区分“完整短文件”与“截断文件”；MP3 free-format（bitrate index 0）不支持。
  - OGG 只跟第一个 logical stream；多流复用/链式流可能少计。
  - WAV 仅支持 RIFF/WAVE（不含 RF64）；裸 PCM 必须由 `Options`/`Content-Type` 提供采样参数。
  - `Meter` 按提示格式优先，提示错误时不回退嗅探（`Parse` 会回退）；TTS 以请求 `response_format`/上游 Content-Type 为准。

- 已有库的升级路径按**库当前 revision** 分流：库仍低于 25（尚有 revision 25 启动前必需数据迁移）时必须 `upgrade --phase=all`（停写 + 备份），把 revision 25 与 26 在同一窗口完成；库已到 25、仅剩 26 加法列时才走 `upgrade --phase=expand` 保留 `min_readable_binary_revision=25` 的回滚窗口。expand 需 `--backup-confirmed` 与 `--secret`（或 `JUHE_AI_SECRET`）；默认还要 `--stop-write-confirmed`，已备份时可改用 `--online`。expand 只执行非破坏语句（DDL 加法与既有内置 seed 补种，不含破坏性步骤），`schema_state.schema_revision` 推进到 26（revision 26 无注册步骤，账本最高步骤仍为 25），minReadable 保持旧值 25。`--ensure-schema` 只做幂等建表/加列与既有内置行补种，不写 `schema_migrations` 账本、不推进 `schema_state`，不能作为发布升级步骤；新库建表内联该列。

## 10. API、管理面与前端

### 10.1 读写契约

- `GET /__aisys__/api/providers/:code/models`、`/providers/models/plaza` 的模型行新增 `mediaPricing` 对象（结构同 §5.1）与 `hasMediaPricing`（区分有效 0 价与无价）；保留现有扁平字段用于 legacy 行与兼容读取。`mediaPricingInvalid=true` 表示列存在但解析/校验失败（后端按无价处理、不回落 legacy），仅作诊断展示，前端不得据此自行推导价格。
- `POST /__aisys__/api/providers/:code/models`、`PATCH .../:id` 的价格分支接受 `mediaPricing`；严格 schema，未知字段、非管理员、非价格分支一律拒绝。
- 双口径判定按**请求体键是否存在**而非值是否非空：`mediaPricing` 键存在且非 null，同时任一 legacy 媒体价格键存在（即使值为 null）→ `400`；只有完全省略 `mediaPricing` 键才走 legacy / 模板复制。前端编辑统一价时必须省略 legacy 价格键，不能发送 null 占位。
- 创建媒体模型未带 `mediaPricing` 时，管理员路径按 §5.3 复制同供应商同 `mode` 同 `unit` 同媒体协议族的最近一行价格；普通用户路径只走「配置模板」可信来源，不能自带价格。无同族同单位行返回 400。
- 非管理员提交任何价格字段（含 `mediaPricing`、legacy 媒体价、token 价、`serviceTierPrices`）一律 `400`，不是忽略或过滤；服务端按「配置模板」复制价格不算客户端提交。个人 scope 不例外；已有个人价格行保留只读，不批量清洗。
- 保存成功写操作审计（旧值/新值），失效模型目录缓存；不新增独立 pricing GET/PUT。

### 10.2 前端

- 模型编辑表单（供应商模型广场/目录）：
  - image：`unit=image` 只读；编辑 `baseUsd`、`baseTier`、三档倍率；实时显示每档每张价。
  - audio：`unit=second` 只读；编辑秒价。
  - video：`unit` 可选 `second` / `call`；`second` 编辑秒价 + 五档倍率；`call` 编辑次价。
  - 显示「统一结算价（USD）」与「官方价仅供参考」说明；不再展示「仅静态表可改」的只读文案。
- 目录卡片/详情抽屉：
  - 卡片价格槽位显示基础档价格与单位（`$0.10/s @720p`、`$0.04/张 @1k`、`$0.3429/次`）。
  - 抽屉增加「统一计价」分组，逐档列出最终单价；音频显示单秒价。
  - 未配置 `mediaPricing` 的旧行显示「旧口径」标识，不伪造新价格。
- 管理面仍只允许管理员改价；普通用户只读。

## 11. 与统计、额度、成本语义的关系

- `cost_usd` 在媒体域 = 统一结算价；API Key / 授权额度（`limits_json` 美元额度）继续按 `success_cost_usd` 扣减，无需改额度逻辑。
- 账户「成本」统计变为「按统一结算价」，不再等于厂商账单；报表/页面文案标注「统一结算价」，避免误读为上游发票金额。
- 统计聚合 worker 继续聚合 `cost_usd` 与现有媒体计量列；分辨率档不新增聚合维度。
- 报表标签使用「统一结算价（USD）」而非「上游成本」；`tts_input_chars` 只作为可观测性字段，不参与媒体计费；`audio_input_seconds` 同时覆盖 TTS 与 STT，按模型 `mode`/协议区分统计，不能把两者相加当成单一业务量。
- 历史报表与切换后报表不可直接横向比较；以 `billingPolicy=media_unified_v1` 或切换日期区分。
- 如需毛利对账，后续可加只读「官方参考价」字段/报表，不参与结算。

## 12. 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 自定价低于上游实际成本 | 用量越大亏越多 | 设置基准价时保证 `baseUsd × 最高档倍率 ≥ 最高档官方价 × 安全系数（建议 ≥1.2）`，低档倍率下浮；定期复核 |
| 分辨率/质量/帧率/输入图等未建模 | 个别请求估算偏差 | 接受为产品定价近似；必要时提高对应档倍率或模型覆盖 |
| TTS 解析失败 | 少计/估算偏差 | 字符/语速估算兜底 + `estimated` 标记；监控 `usage_missing` 比例 |
| Hailuo 6s/10s 套餐非线性 | 2.3 的 6s 短套餐与实际官方价偏差约 20% | 以 10s 总价 ÷10 为基准；Fast 线性无需修正；按模型倍率覆盖 |
| 人工覆盖 legacy 价被 seed 静默替换 | 管理员改价失效、历史行为漂移 | 先转换 `source='manual-override'` 行的 `mediaPricing` 再 seed；无法转换保持 NULL 并登记 |
| 视频探测产生额外网络成本 | 带宽/时延 | 仅 GLM/MiniMax 在三级来源全缺失时启用；Range + 上限 8MB + 10s 超时；失败关闭 |
| 历史数据不可比 | 报表误读 | 标注切换日期与 `billingPolicy`；不重算 |
| 存量未迁移行继续 legacy | 同一目录两种口径 | 67 行一次性迁移 + 16 行显式保持 + 1 行缺口登记；目录「旧口径」标识；后续清理 legacy 分支另立任务 |
| 回滚旧二进制 | 媒体价回退静态 legacy 价，管理员新改 `mediaPricing` 不生效 | 回滚窗口内接受旧口径；发布说明标注；回滚后恢复新版本即恢复 DB 价 |
| 价格被误改 | 额度异常 | 严格校验 + 操作审计 + 目录缓存失效；改价仅管理员 |

### 14.4 生命周期与边界裁决（2026-11-19 已确认）

| # | 边界 | 已裁决 | 落点 |
| --- | --- | --- | --- |
| 1 | 未轮询 / 过期任务 | 7 天 TTL 到期置 `expired`，成本保持 0，不写 `usage_records`；行保留一个完整 TTL（expired 按置态时刻计算删除窗口），期间请求快照、上游 job id、结构化日志与 410 可观察。P1 不新增到期前对账 sweeper，后续按实际漏收观测再立项。 | P1 |
| 2 | 创建响应即 completed | 落库后立即走共享终态结算函数，成本/usage 一次写入并入队一次；`Insert` 支持携带终态成本，不依赖 `UpdateTerminal` 的非终态 WHERE 补写。创建响应 `failed` 仍按受理凭据未确立返回 502、不落行。 | P1 |
| 3 | 受理后落库失败 / 孤儿 | `Insert` 同请求重试 3 次（约 50/200/500ms，仅可重试 DB 错误）；仍失败返回 500，固定字段 `media_job_insert_failed`（`traceId`/`accountId`/`upstreamJobId`/`model`/`requestSnapshotHash`）并计数告警。P1 不做 orphan spool/回放。 | P1 |
| 4 | Veo 默认时长 | Veo 3.0/3.1 系 5 个模型默认 `8s`，来源 `default`，出站显式 `parameters.durationSeconds=8`；仅在请求无生效 seconds 且上游无回报时使用；未声明模型仍 `usage_missing`。 | P1 |
| 5 | 视频 `n>1` | P1 参数层返回 400（`ErrParamUnsupported`），OpenAI 视频 adapter `SupportsN=false`；不调上游、不按 1 个少计。多产物另立需求。 | P1 |
| 6 | P4 产物探测 SSRF | 独立 HTTP client 强制 `upstreamhttp.NewDialGuard`；scheme/host 预检 + DNS 解析后私网阻断双层；只 http(s)、无凭据、重定向 ≤3；不要求产物 host 与账户 base URL 同源。已落地：GLM/MiniMax 显式开启，SOCKS 代理与无 DialGuard 环境失败关闭。 | P4 已落地 |
| 7 | 目录缓存一致性 | 媒体终态携带完整 `CostBreakdown` 快照，成本与快照同源；`usagepricing` 60s 缓存仅作无快照兜底，不新增跨进程失效机制。 | P1 |
| 8 | Hailuo 基准价 | 按 10s 套餐锚定：2.3 `4.00/7/10 = 0.057142857`、2.3-Fast `2.25/7/10 = 0.032142857` USD/s @720p；1080p 倍率 `1.458333` / `1.711111`。2.3 的 6s 短套餐约高 20%，Fast 线性。 | P3 迁移 |
| 9 | `charsPerSecond` | TTS 优先解析返回音频时长；无音频体时默认 4 字符/秒，来源 `estimated`；P2 以全局常量 `gatewaymedia.DefaultTTSCharsPerSecond` 落地，不按语言/音色细分，待有具体模型族证据时再由 adapter 覆盖。 | P2 已落地 |
| 10 | 非管理员价格写入 | 非管理员 create/patch 出现任一价格键即 400（含 `mediaPricing`、legacy 媒体价、token 价、`serviceTierPrices`）；服务端模板复制不算客户端提交；个人 scope 不例外；存量个人价格行保留只读。 | P0/P1 权限门 |

以上裁决为 2026-11-19 确认的最终口径；实施跟踪归 T215。
