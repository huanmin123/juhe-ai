# 音频视频模型接入与统一媒体网关设计

> 状态：设计定稿（2026-10-04）；**M1 同步音频已实施**（代码与测试落地，2026-10-04，遗留项见计划文档进度记录）；**M2 异步任务框架 + 视频已实施**（2026-10-04，acceptance E2E 用例随收尾批补，遗留项见计划文档进度记录），M3+ 未实施。实施分期与进度见 [计划-20261003T164247971Z-音频视频模型接入与多供应商扩展](../plans/计划-20261003T164247971Z-音频视频模型接入与多供应商扩展.md)。
> 本文是媒体域（音频/视频）网关链、模型分类、供应商扩展的**行为契约权威来源**；报文级厂商协议与 Mock 上游规格见《[媒体上游协议契约与Mock上游规格](媒体上游协议契约与Mock上游规格.md)》（adapter 实现与 Mock 上游的字段依据）。实施后本文与 `docs/architecture/架构总览.md`、`docs/functions/厂商模型目录更新与清洗指南.md` 同步生效。

## 1. 目标与非目标

### 目标

1. 网关支持音频模型（语音合成 TTS、语音转写 STT、长音频异步）与视频生成模型的完整调用链。
2. 模型目录用途分类从 `text` / `image` 扩展为 `text` / `image` / `audio` / `video`，前端分类 Tab 同步。
3. 对客户端只呈现统一 OpenAI 形态契约；上游厂商协议差异全部由内部 adapter 吸收。
4. **已有供应商中凡上游真实具备音频/视频能力的，全部补齐接入**（openai/gpt、gemini、glm 确认补齐，xai 核实后补齐）；另接入三家主流音视频供应商：`minimax`、`volcengine`（火山方舟/豆包）、`qwen`（通义/阿里云百炼）。
5. 请求参数分两层：公共参数统一稳定；厂商专有参数经 `provider_options` 扩展通道按 provider 命名空间透传。
6. 切换语义统一为**受理边界**：上游受理凭据确立前失败可换账户；确立后永不换账户。

### 非目标

1. 不做任何媒体资源存储：产物不落盘、不进对象存储、不缓存（见 §8 零资源存储原则）。
2. 不做 Realtime 双向流式语音（WebSocket）——本期仅预留 lane 词表位与目录协议值，独立为最后期实施（见 §12 M5）。
3. 不做 `embedding` 分类放开（维持现状：目录事实存在但前端归一进文本，不新增 Tab）。
4. 不重构 `ProviderDriver` 单体 switch 与 anthropic/gemini 完整 `ProtocolDriver` 化——属既有技术债轨迹，与本设计解耦。
5. 不改变路由层级（API Key → 路由策略 → 分组 → AI 账户 → 供应商/协议能力）与模型映射机制；媒体模型沿用同一调度框架。
6. 不做客户端上传文件的持久化暂存；不做产物预取、CDN 或转码。

## 3. 三层分类体系

"分类"在媒体域涉及三层概念，各管各的，不得混用：

| 层 | 字段/载体 | 词表 | 本次动作 |
| --- | --- | --- | --- |
| 用途分类 | `provider_model_catalog.mode` / `custom_provider_models.mode` / 前端 `modelCategoryOrder` | `text`、`image` → **新增 `audio`、`video`**；历史值 `chat`/`responses`/`image_generation`/`image` 保留并归一（前端别名表已存在）；`embedding` 维持现状 | M1 加 `audio`，M2 加 `video` |
| 模态元数据 | `inputModalities` / `outputModalities`（目录展示用，源自 `internal/pricing/data_*.go` 静态表） | 已是五值 `text/image/audio/video/file` | 不动 |
| 请求车道 | `gatewayproto.RequestLane`（`internal/gatewayproto/driver.go:22-23`，现为 `text`/`image`） | **新增 `audio`、`video`、`realtime`**（`realtime` 仅占位，M5 前无行为） | M1 加 `audio`，M2 加 `video`，M5 启用 `realtime` |

车道行为规则（延续 image lane 既有模板，全部不新增机制）：

- 每车道独立超时档位（系统设置新增 `audio*` / `video*` 超时键，模式同 `imageFirstResponseTimeoutSeconds`）。
- 每车道独立并发上限与 raw body 限额（`/v1` 入口硬上限 64MB 不变；audio 同步上传体对齐 OpenAI 事实约束 25MB；video 创建请求为小 JSON，产物走流式代理不受 body 限额约束）。
- 全部媒体车道不参与 speed-first、首 token 截止、同账户瞬态重试（现有机制本就仅文本 lane：`internal/gatewaydispatch/attemptoutcomes.go:278`、`internal/gatewayrouting/firstbytedeadline.go`，无需改动即满足）。
- 媒体车道（audio/video）不参与热质量排序与电路 lane 作用域（2026-10-04 裁决：媒体请求不污染文本质量统计；受理失败沿既有 engine 语义换账户；独立媒体质量维度为后续增强）。热质量侧 audio/video 跳过排序与 attempt 记账（不排序、不报错、不归并 text，候选保持既有顺序）；电路侧 scope 车道词表扩展为 `text/image/audio/video`（媒体 lane 以独立维度入作用域键，不归并 text、不拒斥，与 text/image 电路隔离，账户级熔断保护语义不变）。

车道判定：按请求路径族优先（`/v1/audio/*` → `audio`，`/v1/videos*`、`/v1/audio/jobs*` → `video`），路径不判定时回退模型目录 `mode`；不得依赖模型名前缀硬编码清单扩张（image lane 的前缀清单维持现状不删）。

## 4. 对外统一契约（下游只认 OpenAI 形态）

### 4.1 同步音频端点（秒级返回，M1）

| 端点 | 语义 | 响应 |
| --- | --- | --- |
| `POST /v1/audio/speech` | TTS 语音合成 | 音频二进制，纯流式透传（现状行为保留，补门控与计费） |
| `POST /v1/audio/transcriptions` | STT 转写，multipart | JSON（`text` 等字段），透传上游 JSON |
| `POST /v1/audio/translations` | STT 翻译转写，multipart | 同上 |

### 4.2 异步媒体任务端点（视频全部异步 + 长音频异步，M2/M3）

视频采用 OpenAI Sora 形态（生态兼容最大）：

| 端点 | 语义 |
| --- | --- |
| `POST /v1/videos` | 创建视频任务；返回 OpenAI 形态 job 对象（`id`、`status: queued/in_progress/completed/failed`、`model`、`seconds`、`size` 等） |
| `GET /v1/videos` | 列表，按当前 API Key 过滤 |
| `GET /v1/videos/{id}` | 轮询状态；终态含 usage 摘要 |
| `GET /v1/videos/{id}/content` | 产物下载：流式透传代理（§8） |
| `DELETE /v1/videos/{id}` | 取消/删除（转发上游 + 本地行终态） |

长音频为平台自有扩展面（OpenAI 无官方异步音频 API），按同一 job 语义：

| 端点 | 语义 |
| --- | --- |
| `POST /v1/audio/jobs` | 创建长音频任务（长转写 / 长 TTS） |
| `GET /v1/audio/jobs`、`GET /v1/audio/jobs/{id}` | 列表 / 轮询 |
| `GET /v1/audio/jobs/{id}/content` | 产物流式透传 |
| `DELETE /v1/audio/jobs/{id}` | 取消/删除 |

规则：

- 所有媒体端点必须完成 Gateway API Key 认证，走既有 preauth → 派发 → 响应 → 终态链；任务面端点（`GET`/`DELETE`/`content`）不走派发循环，走账户亲和直连（§7）。
- 响应统一附带 `provider`、`provider_job_id` 元数据字段，便于排查；不透出上游原始 URL。
- 不采用 302 重定向产物方案：OpenAI content 端点需上游账户认证、Veo 为 GCS 签名 URL 直连会暴露上游身份，均违背统一面定位。

### 4.3 模型目录端点

- `/v1/models` 聚合收录 `audio` / `video` 分类模型（读链排除规则收窄，§2）。
- Codex 形态 `InputModalities` 硬编码 `["text","image"]`（`internal/gatewayresponse/models.go:182`）改为按模型目录真实 modalities 返回。

## 5. 内部统一架构：媒体 IR + 每厂商一个 adapter

延续《协议桥接框架设计》定下的收敛方向（下游协议 → 统一中间表示 → 上游协议，禁止 N×N 扩散），媒体域新增两个内部中间表示（IR）：

```text
客户端请求（OpenAI 形态）
   │ 统一参数模型（§6）
   ▼
媒体中间表示
   ├─ SpeechIR      ：TTS/STT 同步请求的规范表示（模型、文本/音频引用、voice、语言、格式）
   └─ MediaJobIR    ：异步任务统一模型（create → job{id,status,progress,error,usage} → poll → artifact 定位）
   │ 每厂商一个出站 adapter
   ▼
openai │ gemini(veo/tts) │ glm │ xai │ minimax │ volcengine │ qwen
```

adapter 职责边界（对齐《供应商驱动分层规范》六接口）：参数映射（公共参数 + 该 provider 的 `provider_options` → 上游请求体）、URL 与认证构造、上游 job 语义 → `MediaJobIR` 状态归一（各家 queued/running/succeeded 的字段名差异在此吸收）、终态 usage 抽取、产物定位（上游 uri / 需重新调用的 API 定位参数）。

**禁止项**：媒体域不新增点对点桥接方向；不把厂商差异写进组合根 switch（`chain_driver.go` 模式不得为媒体域扩张，媒体 adapter 以 provider 注册表挂载）；新增供应商只写 adapter + 目录 seed + 计费 policy + 前端常量 + 账号接入文档，复用既有接入清单（《供应商驱动分层规范.md:139-149》）。

## 6. 统一参数模型：自建规范（L1/L2/L3）+ provider_options

**设计立场**：文本域 OpenAI 协议已是事实标准，网关无需再统一；视频/音频域当前无正式行业标准（2026-10 调研：OpenRouter/LiteLLM 聚合层同样自选 OpenAI 形态骨架 + 跨厂商归一，SiliconFlow 有国内统一视频 API 先例），因此**网关自建统一参数规范**——用户请求只面向网关规范，绝不透传厂商原生参数面。参数分三层：

- **L1 核心参数**：跨厂商语义一致（`model`、`prompt`、`input`、`file`、`voice` 等），网关直接消费。
- **L2 规范参数**：网关统一定义名与值域（`seconds`、`size`、`n`、`input_reference`、`negative_prompt`、`seed`、`audio`、`speed`、`response_format`、`instructions`、`language`、`timestamp_granularities` 等），由 adapter 映射换算到厂商字段；厂商不支持时按统一规则"可选语义忽略并回显 `params_ignored` / 语义无法表达则 400"，换算结果回显 `params_applied`——**不静默、不猜测、不降级**。
- **L3 provider_options**：厂商个例参数唯一扩展通道，请求体 `provider_options: {"<provider_code>": {...}}`；派发选中账户后只取该 provider 子对象，deep-merge 覆盖同名 L2 值，其余子对象忽略（混合分组多厂商共存不串参数）；只开放这一个通道，不引入 `extra_body` 等第二通道。

各域参数的完整定稿表（层归属、值域、厂商不支持时的处理）、忽略/拒绝/回显通用规则、规范演进策略与业界对标记录，统一维护在《媒体上游协议契约与Mock上游规格》§2——**该章是参数规范唯一事实源**；TTS 音色值域按模型目录各模型标注的 `voices` 清单校验（跨厂商音色名不通用，目录元数据承载）。

任务面响应（`GET /v1/videos/{id}` 等）与同步响应固定附 `provider`、`provider_job_id`、`params_applied`、`params_ignored` 字段，便于排查与确认命中；`provider_options_applied` 回显 L3 命中子对象的键名摘要（不含值，契约 §2.4 规则 4），创建时随 `request_snapshot` 冻结、任务面/列表回显同一份数据，空数组即未使用扩展通道。

## 7. 独立通道与受理切换边界

全车道统一规则（推广现有"未提交候选切换边界"，《核心功能设计.md:775》本来即覆盖音频/资源创建/后台任务）：

> **上游受理凭据确立之前（未收到 2xx），失败可切换账户重试；受理凭据确立之后，永不切换，错误直接透传客户端。**

各形态"受理凭据"定义与行为：

| 形态 | 受理凭据 | 受理前（可切换） | 受理后（不切换） |
| --- | --- | --- | --- |
| TTS/STT 同步 | 上游 2xx 响应头到达 | 网络错误/连接失败/429/5xx → 现有派发循环换候选 | body 已开始透传；流中断只报错，不重放 |
| 视频/长音频创建 | **2xx + 拿到上游 job id** | 同上；4xx 参数类（400/413/422）不切换（换账户无效），401/403/429 视同未受理可切换 | job id 已落 `media_jobs`；后续错误只报错 |
| 任务面（轮询/下载/删除） | 不适用（请求本身即受理后操作） | —— | **账户亲和**：查 `media_jobs` 定位原账户原上游，不进派发循环；账户已删/禁用返回明确"任务不可达"错误 |
| Realtime（M5） | WebSocket 升级成功 | 升级失败换账户重试 | 连接存活期绑定账户；断开由客户端重连，重连重新派发 |

## 8. 零资源存储原则与异步媒体任务框架

### 8.1 零资源存储（全局原则）

1. 网关只做协议统一与转发；任何媒体资源（视频产物、音频文件、图片字节）只在内存流式经过——不落盘、不进对象存储、不缓存、不预取。
2. `content` 端点 = 纯流式透传代理：查表定位 → 账户亲和转发原上游 → 边收边转发；与现有 `/v1/audio/speech` 二进制透传管道（`internal/gatewayresponse/nonstream.go:521`）同模式。
3. 客户端上传资源（STT multipart、图生视频首帧）同样只透传：网关仅解析必要元数据（`gatewaybody/multipart.go` 既有模式），body 转发后即弃。
4. 审计与 usage 记录只记元数据（模型、参数摘要、job id、计量数字、状态），**不记录资源 body**；`request_snapshot` 不含 base64 资源字段。
5. 全量审计捕获（`FullBodyCaptureEnabled`，既有 opt-in 契约）开启时请求体按原始审计既有行为捕获，不受本节约束。
6. 行为代价（对外契约明示）：产物可取回性完全由上游时效决定（OpenAI content 约 1 小时、GCS 签名 URL 会过期）；客户端逾期未取，`content` 返回明确"产物已过期"错误码，网关不补救。

### 8.2 `media_jobs` 表（业务库，M2）

```text
media_jobs
├─ id                    对外 job id（不使用上游 id，避免跨厂商碰撞与暴露）
├─ kind                  video | audio_transcription | audio_speech
├─ api_key_id            归属 API Key（列表/鉴权过滤）
├─ account_id / provider_code / provider_protocol_profile_id   账户亲和三元组
├─ upstream_job_id       上游任务定位
├─ status                queued | in_progress | completed | failed | cancelled | expired
├─ request_snapshot_json 轻量参数元数据（§8.1.4，不含资源字段）
├─ artifact 定位         上游 uri / 重新调用参数 + 上游时效时间
├─ error                 终态错误摘要（脱敏）
├─ usage / cost 终态字段 终态回填（§10）
└─ created_at / updated_at
```

链路要点：

- **创建**：走正常派发循环（受理边界生效），2xx + job id 后落表并返回统一 job 对象。
- **轮询**：客户端 GET → 查表 → 账户亲和转发 → adapter 归一状态；**不做后台全量轮询**（不为闲置任务消耗上游配额）；每次轮询响应驱动本地状态与终态计费回填。
- **下载**：`content` 实时流式转发（§8.1.2）。
- **清理**（M2 已实施）：jobs 项目保留任务 `media-jobs-retention`（`jobregistry` 注册，GoWired，interval 1h / fixedDelay / storage-maintenance lane / initial delay 9min 错峰）；每轮扫 `created_at` 早于 now-7d 的超期行——未终态（queued/in_progress）先置 `expired`，全部超期行（含终态）删除；每阶段每轮 ≤500 行分批限流，零任务快速返回，表缺席（老库未跑 maintenance 迁移）按零任务处理；过期清理不产生计费。
- 管理面新增只读"媒体任务列表"（M2 已实施）：`GET /__aisys__/api/media-jobs`（requireAdmin，权限沿使用记录列表）；查询参数 `limit`（默认 20，上限 100）/`offset`/`status`/`kind`/`api_key_id`/`account_id`，响应 `{rows:[{id,kind,status,providerCode,providerJobId,model,promptSummary(截断 120 字符),seconds,size,apiKeyId,accountId,createdAt,updatedAt,costUsd,error{code,message}}],total}`；无写端点，第一版不含重试操作。

## 9. 供应商标的清单与协议形态矩阵

已有供应商逐家盘点（有则补齐）+ 新增三家主流：

| provider | TTS | STT | 视频生成 | 决策 |
| --- | --- | --- | --- | --- |

## 10. 计费与 usage

计量与计费行项扩展（`internal/pricing` + `gatewayproto.ParsedUsage` + usage 落库）：

| 维度 | 新增内容 | 行项（`CostLineKind`） |
| --- | --- | --- |
| TTS（按输入字符的模型） | `tts-1` / `tts-1-hd` 按输入字符计费；`PriceSet` 新增 `TtsInputUsdPer1MChars` 类单价字段 | `tts_input_chars` |
| TTS（按 token 的模型） | `gpt-4o-mini-tts` 按 token 口径计价（厂商真实定价维度），复用既有 `audioInputUsdPer1M` / `audioOutputUsdPer1M` 字段（seed 已填价），走既有 audio token 行项；`gpt-4o-tts` 未收录（官方无定价，待官方价后补行，不编造） | —— |
| STT（按秒的模型） | `whisper-1` 按音频秒数计费；`AudioInputUsdPerSecond` 类字段 | `audio_input_seconds` |
| STT（按 token 的模型） | `gpt-4o-transcribe` 系按 token 口径计价，复用既有 `audioInputUsdPer1M` / `audioOutputUsdPer1M` 字段（seed 已填价），走既有 audio token 行项 | —— |
| 视频生成 | 按输出秒数计费，可按分辨率分档（沿目录价格字段模式扩展） | `video_output_seconds` |
| 既有对话内 audio token | 已有 `audio_input` / `audio_output` 行项与 token 单价，不动 | —— |

- 同步音频在终态一次计费（现有链路）；异步任务在**任务终态**由轮询响应驱动回填 `media_jobs` 与 `usage_records`；失败任务按上游实际计量为准（上游无计量则 0 计费，不猜测）。
- 视频终态计费（M2 已实施）：completed 按轮询响应秒数 × 静态定价目录秒价（`pricing.EstimateProviderCostUsd`，`sora-2` $0.10/s / `sora-2-pro` $0.30/s）算出 `cost_usd` 随 `UpdateTerminal` 一次落行；usage 行的 `costUsd` 在 enqueue 前直接带值（秒数/模型/供应商在行上恒可得，无"已入队回追"窗口），usage_missing/目录未命中保持 NULL（不写 0）；failed 不虚计。终态 usage 行的记账 scope 五元组（AccountAccessType/AccountAuthorizationID/GroupID/GroupAccessType 等）在创建时从派发上下文（账户视图 BoundGroupID 覆盖语义）冻结进 `request_snapshot_json`，轮询终态时投影——轮询请求上派发上下文已不可得。任务面（poll/content/cancel/list）短路路径接最小审计：身份绑定 + jobId 网关元数据 + 请求级 Finalize（方法/路径/状态码/outcome），不记请求/响应 body（§8.1.4）。
- 同步音频计量优先级（M1 已实施）：上游 `usage` 优先（token 口径模型）→ `duration` 秒（`whisper-1`）→ 0 计费 + `usage_missing` 标记，**不猜测**；`usage_records` 新增 `tts_input_chars` / `audio_input_seconds` 两计量列。
- `usage_records` 新增 video 维度计量列（`output_video_seconds`）；聚合统计表补 audio/video 列在 M4（现有聚合表连 audio token 均未聚合，不影响主链）。
- 媒体任务过期清理不产生计费；取消任务按上游实际计量为准。

## 13. 验收标准（总体）

1. 对外契约：仅 §4 端点集；客户端（OpenAI SDK 生态）无需感知上游厂商即可完成 TTS/STT/视频生成全流程。
2. 切换语义：受理前失败换账户、受理后不换，各形态回归用例覆盖（含 4xx 不切换、401/403/429 可切换）。
3. 零存储：审计、日志、快照、DB 中检索不到任何媒体资源字节（仅元数据）；部署面无新增卷/盘。
4. 计费：TTS 按字符、STT 按秒、视频按秒×档位，任务终态回填；失败任务不虚计。
5. 目录：`audio`/`video` 分类在管理面与 `/v1/models` 一致呈现；`realtime` 模型仍被排除。
6. 验收基线：**全部验收以 Mock 上游完成**（`mockupstream` 扩展 + acceptance E2E，规格见契约文档 §3），不依赖真实厂商账户；真实上游验证为上线前可选补充，不阻塞各期完成判定。
