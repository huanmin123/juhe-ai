# 公告中心设计

> 面向 AI 与维护者。
> 本文记录公告中心的功能边界、数据字段、接口契约、权限和前端交互。计划推进记录见 `docs/plans/计划-20260510T011518000Z-公告中心与铃铛提醒.md`。

## 1. 功能定位

- 公告中心用于向所有登录用户展示平台公告，例如充值说明、订阅调整、模型折扣、系统界面更新和运维通知。
- 用户侧入口放在头部用户头像左侧的小铃铛，点击后打开公告弹窗。
- 管理侧新增独立菜单 `公告管理`，仅管理员在管理模式下可见，用于新增、编辑、发布、下线和删除公告。
- 公告不参与网关调度、统计计量、授权链路或审计原文保存。

## 2. 展示规则

- 公告弹窗最多展示最近 30 条已发布公告，按 `published_at DESC, created_at DESC` 排序。
- 弹窗使用时间轴样式：左侧竖线和圆点，圆点颜色表示重要性，同时用中文标签展示重要性，避免只靠颜色传达语义。
- 重要性级别：

| 字段值 | 中文文案 | 圆点颜色 | 使用场景 |
| --- | --- | --- | --- |
| `critical` | 重要 | 红色 | 服务变更、重大风险、需要用户立即关注 |
| `warning` | 提醒 | 橙色 | 订阅、余额、计划变更等需要关注的信息 |
| `info` | 通知 | 蓝色 | 普通产品、功能和运营通知 |
| `normal` | 普通 | 灰色 | 低优先级说明或记录 |

- 时间展示建议同时包含相对时间和绝对时间，例如 `2 天前 2026-05-07 18:00`。
- 用户公告弹窗先展示轻量标题、重要性和发布时间；用户点击“查看内容”时才按公告 ID 读取正文，避免应用壳首屏和 60 秒轮询重复下载最多 30 条完整正文。
- 正文读取期间只显示当前公告的局部加载态；已读取正文由本次弹窗会话缓存，重复展开不重复请求。
- 公告管理列表只返回最多 240 字的正文预览和 `contentTruncated`。管理员编辑未截断的短正文时直接使用列表值；只有 `contentTruncated=true` 时才按 ID 读取编辑详情。
- 空列表显示中文空态 `暂无公告`。
- 弹窗内不展示上限说明和刷新按钮，保持入口轻量；上限由接口和前端请求共同约束。

## 3. 新公告提醒

- 铃铛正常态使用默认图标色。
- 存在新公告时，铃铛使用主色，右上角显示红点，并在首次检测到新公告时短暂轻摇。
- 摇晃动画只用于吸引注意，不应持续高频循环；第一版采用短时动画，红点保留到用户查看。
- 后端按 `announcement_reads` 记录每个系统账户读过哪些公告，前端不再依赖浏览器本地已读时间。
- 判断规则：最近 30 条已发布公告中，只要存在当前用户没有 `readAt` 的公告，就认为有新公告。
- 用户点击铃铛并成功打开公告弹窗后，前端把当前弹窗内未读公告 ID 批量提交给后端写入已读记录，写入成功后铃铛恢复正常。
- 编辑已发布公告默认不重新提醒用户；重新发布草稿或已下线公告会刷新 `publishedAt` 并清理该公告的已读记录，从而重新提醒所有用户。

## 4. 数据模型

SQLite 表：`announcements`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `TEXT PRIMARY KEY` | 公告 ID |
| `title` | `TEXT NOT NULL` | 标题 |
| `content` | `TEXT NOT NULL` | 正文 |
| `level` | `TEXT NOT NULL DEFAULT 'info'` | 重要性：`critical` / `warning` / `info` / `normal` |
| `status` | `TEXT NOT NULL DEFAULT 'draft'` | 状态：`draft` / `published` / `archived` |
| `created_by` | `TEXT NOT NULL` | 创建管理员系统账户 ID |
| `updated_by` | `TEXT` | 最近更新管理员系统账户 ID |
| `published_at` | `TEXT` | 发布时间；只有已发布公告有值 |
| `created_at` | `TEXT NOT NULL` | 创建时间 |
| `updated_at` | `TEXT NOT NULL` | 更新时间 |

索引：

- `idx_announcements_public`：`status, published_at DESC, created_at DESC`，用于用户侧读取最近已发布公告。
- `idx_announcements_admin`：`updated_at DESC, created_at DESC`，用于管理员列表。

SQLite 表：`announcement_reads`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `announcement_id` | `TEXT NOT NULL` | 公告 ID，关联 `announcements.id` |
| `system_account_id` | `TEXT NOT NULL` | 阅读用户系统账户 ID，关联 `system_accounts.id` |
| `read_at` | `TEXT NOT NULL` | 最近阅读时间 |

约束和索引：

- 主键：`announcement_id + system_account_id`，同一用户对同一公告只保留一条已读记录。
- `announcement_id` 外键级联删除，公告删除后自动清理对应已读记录。
- `idx_announcement_reads_account`：`system_account_id, read_at DESC`，用于后续按用户查看已读情况。

## 5. 接口契约

所有接口都属于后台 `/__aisys__/api/*` 管理 API 风格，成功响应使用 `{ data }`。

用户侧只读接口：

- `GET /__aisys__/api/announcements/public?limit=30`
  - 登录用户可用。
  - 只返回 `status = published` 且 `published_at` 不为空的公告。
  - `limit` 最大 30，默认 30。
  - 返回字段仅为 `id`、`title`、`level`、`publishedAt` 和可选 `readAt`，不返回正文、状态、创建时间或更新时间。
  - repository 只查询上述字段及当前用户的已读记录，不使用 `SELECT *`，不关联创建人或更新人。
- `GET /__aisys__/api/announcements/public/:id`
  - 登录用户可用，仅允许读取当前仍为已发布状态且有发布时间的公告。
  - 返回 `id`、`title`、`content`、`level`、`publishedAt`；草稿、已下线或不存在的公告统一返回 404。
- `POST /__aisys__/api/announcements/public/read`
  - 登录用户可用。
  - 入参：`announcementIds`，最多 30 个。
  - 后端用单条 `INSERT ... SELECT ... ON CONFLICT DO NOTHING` 只写当前仍为已发布状态的公告 ID；重复已读为零 DML，不刷新旧 `readAt`。

管理员接口：

- `GET /__aisys__/api/announcements`
  - 仅管理员可用。
  - 分页返回公告管理列表，按最近更新排序；字段固定为 `id`、`title`、最多 240 字的 `contentPreview`、`contentTruncated`、`level`、`status`、可选 `updatedByName`、可选 `publishedAt` 和 `revision`。
  - 列表不返回 `content`、创建人 / 更新人 ID、创建时间或重复的更新时间字段；repository 直接关联出更新人显示名，不再把 actor ID 返回前端加工。
- `GET /__aisys__/api/announcements/:id`
  - 仅管理员可用，只返回 `id`、`title`、`content`、`level`、`status` 和 `revision`。
  - 仅当管理列表的 `contentTruncated=true` 时由编辑动作调用；新增弹窗和未截断短正文编辑不请求该接口。
- `POST /__aisys__/api/announcements`
  - 仅管理员可用。
  - 创建公告，可指定 `draft` 或 `published`；发布态自动写入 `published_at`。
  - 成功只返回 `{ id, revision }`，前端据此局部插入列表，不再无条件重载列表。
- `PATCH /__aisys__/api/announcements/:id`
  - 仅管理员可用。
  - 必须提交 `expectedRevision`，并在标题、正文、重要性和状态中至少提交一个真实动作字段；前端只发送相对编辑基线变化的字段。
  - repository 在事务内按本次字段读取当前投影并校验 revision，只为真实变化动态生成 `SET`；同值请求为零 DML、零 revision 推进、零操作日志。
  - 草稿或已下线公告切换为已发布时刷新 `published_at` 并清理该公告的已读记录；已发布公告普通编辑不改变 `published_at` 或已读记录。
  - revision 冲突返回 409；成功只返回 `{ id, revision }` 并由前端局部合并，只有冲突才回源刷新列表。
- `POST /__aisys__/api/announcements/:id/publish`
  - 仅管理员可用。
  - 请求体必须带 `expectedRevision`。发布草稿或已下线公告时刷新 `published_at` 并清理该公告的已读记录；同 revision 的已发布状态请求为 no-op，不重复提醒。
  - 成功只返回 `{ id, revision }`。
- `POST /__aisys__/api/announcements/:id/unpublish`
  - 仅管理员可用。
  - 请求体必须带 `expectedRevision`。下线公告状态变为 `archived`，保留 `published_at` 供历史追踪；已下线同值请求为 no-op。
  - 成功只返回 `{ id, revision }`。
- `DELETE /__aisys__/api/announcements/:id`
  - 仅管理员可用。
  - 请求体必须带 `expectedRevision`，事务内校验后删除；成功返回 204 空响应。

## 6. 权限与安全

- 所有公告内容都默认对全部登录用户可见，因此管理员创建时不能填写敏感凭据、内部 token、完整上游错误原文或用户隐私。
- 普通用户只能读取已发布公告，不能看到草稿或已下线公告。
- 管理端所有写操作必须由后端重新校验管理员权限，前端菜单隐藏不能作为权限依据。
- 公告内容第一版使用纯文本多行输入，不引入富文本和 HTML 渲染，避免 XSS 和样式污染。

## 7. 后续扩展

- 已读状态查询：当管理员需要排查公告触达情况时，再新增只读统计或明细接口。
- 定向公告：当需要按系统账户、系统团队或角色定向展示时，再扩展公告目标表。
- 重新通知：当管理员编辑旧公告后确实需要再次提醒时，再新增显式操作，不把普通编辑时间作为提醒依据。
- 富文本、图片和附件：需要配套安全过滤、上传限制和展示规范后再引入。
