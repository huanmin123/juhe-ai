# 账户模型限制设计

## 背景

网关的默认兜底策略是：上游账号真实失败后，可以按错误策略进入临时不可调用、限流或异常状态。这是账号池自我保护能力，不能靠状态码、固定错误文案或某个客户端协议做被动拦截。

当客户端请求的模型和账号实际上游能力不匹配时，如果直接逐个账号打上游，可能把同一分组内多个账号连续打入临时不可调用。账户模型限制用于把这类“用户已知的模型能力边界”前置到本地调度，让用户自行决定是否启用安全约束。

## 核心语义

- 供应商维护模型目录，账户配置模型限制时只能从账号所有者可见的所属供应商模型目录选择；目录包含内置模型、管理员全局自定义模型和账号所有者个人自定义模型。当前供应商代码为 `gpt`，使用 OpenAI v1 协议；模型限制不能按协议码 `openai` 混用不同供应商的模型目录。
- AI 账户可以配置支持模型列表。
- 支持模型列表为空表示不限制，等价于该账号接受任意请求模型。
- 支持模型列表非空时，下游请求模型必须精确命中列表中的某个模型，该账号才直接进入候选池。
- 如果下游请求模型没有直接命中支持模型，但账号存在启用的模型映射，且 `sourceModel` 精确等于下游请求模型、`upstreamModel` 精确命中账号支持模型，则该账号也可进入候选池。这只解决账号级显式别名映射，不做模型族、前缀或模糊匹配。
- 模型映射只在选中账号后改写上游请求体；调度阶段只使用账号运行时快照中的 `supportedModels` 和 `modelMappings` 判断是否保留候选账号。完整边界见 [自定义模型与模型映射设计](自定义模型与模型映射设计.md)。
- 因模型不匹配被跳过的账号不算失败，不进入账号错误策略，不写临时不可调用，不触发本地短期屏蔽。
- 如果分组内存在不限制账号，请求缺少 `model` 时仍可由不限制账号承接；有限制账号会被跳过。
- 如果分组内所有可用账号都因缺少 `model` 或模型不匹配被过滤，网关直接返回本地错误，不请求上游。
- `GET /models` / `GET /v1/models` 继续由本地供应商模型目录返回，不参与账户模型限制过滤。

## 性能设计

模型限制不能让每次客户请求都查询数据库。

- 账号支持模型使用业务库轻量关系表保存，空行表示账号不限制。
- 网关账号池缓存 miss 时，一次性读取分组内候选账号，并按账号 ID 批量读取支持模型列表。
- `OpenAIAccountSecret` 运行时快照带上 `supportedModels`，进入 `gatewayRuntimeCache` 和 `openAIAccountsCache`。
- 每次请求只在缓存账号数组上按下游请求 `model`、账号 `supportedModels` 和启用的 `modelMappings` 做内存过滤，再进入会话亲和、本地屏蔽、授权额度和上游尝试。
- 账号创建、编辑、删除、分组绑定、授权变更等现有写路径已经清理网关 runtime cache；模型限制写入复用账号创建 / 编辑路径，避免额外维护一套失效机制。
- 后续如果单个分组账号池过大，再增加 `groupId + systemAccountId + model` 的派生候选缓存；第一版不引入，避免同时维护两套缓存失效链路。

## 存储

新增业务库表 `account_supported_models`：

| 字段 | 说明 |
| --- | --- |
| `account_id` | AI 账户 ID |
| `provider_code` | 供应商代码，冗余用于后续供应商模型目录约束和索引 |
| `model` | 模型 ID，精确匹配请求体中的 `model` |
| `created_at` | 创建时间 |

约束：

- 主键：`account_id + model`
- `account_id` 外键级联删除到 `accounts`
- 索引：`provider_code + model + account_id`
- 账号没有任何行时表示不限制。

不把模型限制塞进 `credentials`，也不作为错误策略的一部分。凭据只保存上游认证材料，错误策略只处理上游失败后的账号副作用，模型限制是调度前的能力约束。

## 接口与页面

- 账户创建 / 编辑 payload 增加 `supportedModels: string[]`。
- 后端接受空数组作为清空限制；不提交该字段表示更新时不变。
- 后端校验模型 ID 必须存在于账号所有者可见的所属供应商模型目录。
- 账户列表和详情返回 `supportedModels`，授权账户也可以查看该非敏感调度约束，但不能编辑。
- 前端账户表单在调度策略区域展示“支持模型”搜索多选。
- 空值文案表达为“不限制模型”；保存时提交空数组，确保可以从有限制清空为不限制。

## 网关过滤流程

1. 校验 API Key、分组授权和额度。
2. `GET /models` 直接返回本地模型目录。
3. 从 runtime cache / accounts cache 取得分组账号快照。
4. 读取请求 `model`，作为下游模型。
5. 对账号快照做内存过滤：
   - `supportedModels` 为空：保留。
   - `supportedModels` 非空且请求 `model` 精确命中：保留。
   - `supportedModels` 非空、请求 `model` 未直接命中，但启用模型映射的 `sourceModel` 精确命中请求 `model` 且 `upstreamModel` 精确命中 `supportedModels`：保留，并在调度审计 metadata 中记录映射命中数。
   - `supportedModels` 非空但请求无 `model`、未命中直接模型且未命中上述映射规则：跳过。
6. 如果过滤后为空且过滤前有账号，返回本地模型不支持错误。
7. 继续执行会话亲和、本地屏蔽、Codex turn 避让、授权额度和上游转发；如果选中账号配置了模型映射，后续只改写上游请求体顶层 `model`，不回头改变本轮账号过滤结果。

## 非目标

- 不根据 HTTP 状态码、上游错误文案、客户端 UA 或路径硬编码判断模型不支持。
- 不把 Claude、OpenAI、Codex 等协议差异写成通用调度规则。
- 不在每次请求里查询模型表或供应商模型目录。
- 不自动探测账号真实支持模型；模型限制是用户显式配置。
