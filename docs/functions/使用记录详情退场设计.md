# 使用记录详情退场设计

## 1. 目标

- `我的使用记录` 和 `使用记录管理` 只提供分页列表、筛选、排序和列表内字段展示。
- 使用记录页面不提供操作列、按行详情、请求 / 响应快照、运行日志跳转或审计日志跳转。
- 具体日志正文和日志详情只能从对应日志管理页面进入；普通用户不通过使用记录获得日志详情能力。

## 2. 接口边界

- 保留 `GET /__aisys__/api/usage-records` 和 `GET /__aisys__/api/my-usage-records`。
- 删除 `GET /__aisys__/api/usage-records/{id}` 和 `GET /__aisys__/api/my-usage-records/{id}`；Node 与 Go 均不得注册兼容路由。
- 列表 DTO 继续排除 `requestSnapshot` 和 `responseSnapshot`，不得通过查询参数恢复这些字段。
- 有该使用记录读取权限的用户可在列表行获取完整持久化 `errorCode` / `errorMessage`，错误消息按原值返回且不拼接 HTTP 状态或代码；失败记录即使携带 `2xx` 传输状态，也必须明确标为“非成功终态”。列表仍不得返回 `requestSnapshot`、`responseSnapshot` 或其他原始快照。
- 使用记录的内部写入、统计聚合、数据保留和存储级验证不属于页面详情能力，继续保留；这些内部能力不得重新暴露为使用记录读接口。

## 3. 前端边界

- 桌面表格不生成 `actions` 列。
- 移动端卡片不生成查看详情、运行日志或审计日志操作。
- 删除详情抽屉、详情请求 API、作用域转发和请求竞态门禁。
- traceId 仍作为列表字段展示并允许复制；日志检索由用户进入日志管理后完成。
- 桌面与移动端直接展示失败摘要和中性归因；未证实下游关闭的触发方时不得写成客户端主动取消。

## 4. 权限与安全

- 普通用户只能读取自己的使用记录列表。
- 管理员可读取管理作用域的使用记录列表，并可获取列表行完整持久化 `errorCode` / `errorMessage`；同样不能从使用记录接口读取请求 / 响应快照或按 ID 详情。
- 原始审计日志、运行日志和操作日志继续遵守各自的管理页面、接口和权限规则，本次不删除日志管理详情能力。

## 5. 验证门禁

- 前端源码与编译产物不得出现使用记录详情抽屉、`open-detail`、详情 API 或使用记录日志跳转。
- Node 和 Go 路由表不得注册两个使用记录按 ID 路径，请求这些路径应返回 `404`。
- 管理端和个人端使用记录列表仍可加载，桌面无操作列表头，移动端无详情 / 日志操作。
- 定向回归、前后端类型检查、Go 测试、构建和页面验证通过后才可完成退场。
