# 流式语音跨协议转换设计（M6 立项）

> 状态：立项设计（2026-10-04），未实施。父计划：[计划-20261003T164247971Z-音频视频模型接入与多供应商扩展](../plans/计划-20261003T164247971Z-音频视频模型接入与多供应商扩展.md)。
> 背景：M5 已交付 OpenAI Realtime 形态 WS 透传（openai/gpt 账户）；本设计把 `/v1/realtime` 对外面扩展到**转换型上游**（Gemini Live、阿里云 CosyVoice）——客户端永远只说 OpenAI Realtime 事件协议，跨协议转换由网关内建。

## 1. 目标与非目标

**目标**：`/v1/realtime` 会话按账户协议分派——openai 族透传（现状零变化）、gemini 账户走 Live 转换、（后续）qwen 账户走 CosyVoice 转换；对客户端、ephemeral token、usage 计费、受理边界全部沿用 M5 语义不变。

**非目标**：不新增对外端点/事件（对外仍纯 OpenAI Realtime 形态）；不做 WebRTC；不做会话内容存储（零存储延续）；不承诺全事件集无损转换（见 §3 映射裁决）。

## 2. 架构：Realtime 上游适配层

M5 桥接泵的"上游连接"抽象为接口：

```text
RealtimeUpstreamConn 接口：
  Dial(账户, model) → 受理边界语义不变（拨号/握手失败换候选，101/连接建立=受理）
  ReadEvent() → 统一内部事件（RealtimeEvent 形态）
  WriteEvent(RealtimeEvent) → error
```

- **透传实现**（openai/gpt）：现状泵逻辑原样搬入，帧逐字节直通（行为零变化，M5 测试全量护航）。
- **转换实现**（gemini live / cosyvoice）：连接后首帧自动注入 `setup`（由对客户端 `session.update` 事件转换）；双向各一个事件转换器（client Realtime → 上游消息；上游事件 → Realtime 事件），内部事件形态即 OpenAI Realtime 事件 JSON——泵的观测器/usage/审计逻辑对三种实现同构复用。

## 3. Gemini Live 映射矩阵（B 级报文，2026-10-04 检索）

上游端点：`wss://generativelanguage.googleapis.com/ws/google.ai.generativelanguage.v1beta.GenerativeService.BidiGenerateContent`（API key 头认证；google_oauth 账户同面）。

| 客户端 Realtime 事件 | → Live 客户端消息 | 说明 |
| --- | --- | --- |
| `session.update` | `setup{model,generationConfig(voice/modalities/systemInstruction/tools)}` | 缓存会话配置；未到 session.update 即拨号的用默认 setup |
| `input_audio_buffer.append` | `realtimeInput{audio:{data(base64),mimeType}}` | 音频分块 |
| `conversation.item.input_text` 等文本输入 | `clientContent{turns,turnComplete}` | 文本轮次 |
| `response.create` | （Live 由 turnComplete 驱动响应） | 不直接映射 |
| `tool 响应` | `toolResponse` | M6 后期 |

| Live 服务端事件 | → 客户端 Realtime 事件 |
| --- | --- |
| `setupComplete` | `session.created`（+缓存配置回显 `session.updated`） |
| `serverContent.modelTurn.inlineData`（音频） | `response.audio.delta`（base64 透传） |
| `serverContent.outputTranscription` | `response.audio_transcript.delta` |
| `serverContent.interrupted` | `input_audio_buffer.speech_started`/`speech_stopped`（近似映射，注释留痕） |
| `serverContent.turnComplete` | `response.done`（**usage 合成点**：Live 无 usage 事件，按音频字节/时长估算？——**不估算**，usage_missing，与"不猜测"原则一致） |
| `toolCall` | `response.function_call_arguments.done`（M6 后期） |

**不映射面（明确降级）**：Realtime 的精细 VAD 配置（`turn_detection` 细项）、部分工具事件细项、Live 的 AOQ 专属特性——转换层按"忽略+不回显"处理并在文档列明；映射矩阵是 M6 实施契约的唯一事实源，未列事件一律忽略并计数观测。

## 4. CosyVoice 池（M6b）

官方接入为 AOQ(QUIC)/WebSocket 双向事件流（客户端事件/服务端事件，契约 §10.2 已修正归类）。M6b 只评估其 **WebSocket 面**（AOQ/QUIC 不引入）；事件映射矩阵待官方事件参考页回填后定稿，未回填不实施。

## 5. 分期与验收

- **M6a（Gemini Live）**：RealtimeUpstreamConn 抽象重构（透传零回归护航）→ Live 转换器 + 映射矩阵实现 → mockupstream 增 Live 形态 WS 场景（setup 断言/audio 回吐/turnComplete）→ E2E（OpenAI Realtime 客户端经网关与 Live mock 会话、audio delta 透传、usage_missing 终态）→ 受理边界沿用（Live WS 拨号失败换候选）。
- **M6b（CosyVoice）**：待事件参考回填。
- 验收：M5 全部用例零回归（透传不变）；转换用例三层（转换器单测/链级/E2E）；映射矩阵外事件忽略且观测计数。
