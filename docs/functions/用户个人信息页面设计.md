# 用户个人信息页面设计

> 状态：已实现并完成隔离浏览器验收。
> 关联计划：[PLAN-20260726T063803063Z](../plans/计划-20260726T063803063Z-用户个人信息页面.md)。

## 1. 目标

- 在右上角用户头像下拉中提供统一的“个人信息”入口，并跳转到独立页面。
- 把现有“修改名称”和“修改密码”从应用壳弹窗收拢到个人信息页面。
- 向所有登录用户展示自己的身份、角色、账户状态、图像生成权限和关键时间信息。
- 复用现有系统账户事实和认证能力，不新增平行用户表、权限表、头像文件存储或密码流程。
- 保持普通用户、管理员和超级管理员使用同一页面，页面只读取当前登录账户，不提供切换他人账户的能力。

## 2. 现状与术语决策

当前系统账户同时存在两个容易混淆的名称字段：

| 字段 | 用户语义 | 本期是否可编辑 | 说明 |
| --- | --- | --- | --- |
| `username` | 登录账号 | 否 | 用于登录和认证上下文，现有系统账户契约明确为创建后不可修改 |
| `displayName` | 用户名称 | 是 | 当前头像、头部名称、系统账户选项和操作展示使用的名称 |

本需求中的“修改用户名”统一落为修改“用户名称” `displayName`；页面同时展示只读“登录账号” `username`，避免用户误以为两者相同。若未来确实需要修改登录账号，应另立需求处理重新认证、唯一性、登录限频键、操作日志和会话一致性，不混入本页面首期实现。

## 3. 入口与路由

### 3.1 头像菜单

普通头部和 AI 问答移动端沉浸式菜单保持一致：

1. `个人信息`：跳转 `/profile`。
2. `切换到用户模式 / 管理模式`：仅管理员角色展示，保留现有行为。
3. `退出登录`：保留现有行为。

删除头像菜单中的 `修改名称` 和 `修改密码` 两个直达弹窗入口，避免同一能力存在页面与弹窗两套交互。

### 3.2 路由属性

- 路径：`/profile`。
- 页面标题：`个人信息`。
- 页面说明：`查看账号资料、权限能力并维护名称与登录密码。`
- 权限：任意已登录且状态有效的系统账户。
- `viewScope: 'self'`，不进入左侧菜单，也不随管理 / 用户模式切换改变数据范围。
- `keepAlive: false`，避免密码表单或错误信息在离开页面后继续保留。
- 头像菜单进入时复用现有路由切换反馈；重复点击当前路由不重复导航。

## 4. 页面信息架构

桌面端使用最大宽度约 `960px` 的单页双栏布局；手机端改为单栏。页面不使用多层 Tab，也不堆叠装饰卡片。

```text
┌─────────────────────────────────────────────────────────┐
│  [头像缩写]  用户名称                    [角色] [启用中] │
│              登录账号：username                         │
└─────────────────────────────────────────────────────────┘

┌──────────────────────────────┐  ┌──────────────────────┐
│ 基本资料                     │  │ 权限与能力           │
│ 用户名称      [可编辑输入框] │  │ 角色：普通用户       │
│ 登录账号      username  复制 │  │ 使用入口：用户模式   │
│ 账户 ID       id        复制 │  │ 图像生成：已开通     │
│ 说明          description    │  │ 账户状态：启用中     │
│                     [保存]   │  │ 以上由管理员配置     │
└──────────────────────────────┘  └──────────────────────┘

┌─────────────────────────────────────────────────────────┐
│ 账号安全                                                │
│ 当前密码 [••••••]  新密码 [••••••]  确认密码 [••••••]  │
│ 修改后其他登录会话会失效。                   [修改密码] │
└─────────────────────────────────────────────────────────┘

最近登录：2026-...   创建时间：2026-...   更新时间：2026-...
```

### 4.1 身份摘要

- 头像继续使用现有用户名称首字符 / ASCII 前两字符生成，不新增头像上传。
- 主标题显示 `displayName`，副标题显示只读 `username`。
- 角色使用现有角色文案：`超级管理员`、`管理员`、`用户`。
- 账户状态使用文字和状态色共同表达，不只依赖颜色。

### 4.2 基本资料

- `用户名称`：唯一可编辑资料字段，复用现有无空白字符、非空和大小写不敏感唯一约束。
- `登录账号`、`账户 ID`：只读并提供复制按钮。
- `说明`：只读；空值显示 `暂无说明`。首期不允许普通用户修改管理员维护的说明。
- 保存按钮只在名称发生真实变化时可用；保存期间禁止重复提交；失败保留输入。
- 保存成功后同时更新页面资料和全局 `authState.currentUser`，头部名称与头像立即同步。

### 4.3 权限与能力

- `角色`：来自 `role`，只读。
- `可用入口`：由角色派生；管理员显示“用户模式、管理模式”，普通用户显示“用户模式”。这只是解释已有角色能力，不保存新字段。
- `图像生成`：直接展示 `imageGenerationEnabled`，文案使用 `已开通 / 未开通`；未开通时提示“由管理员在系统账户管理中开启”。
- `账户状态`：展示 `status`；有效会话通常只能看到启用状态，但字段仍由详情契约返回，便于契约完整和后续状态变化处理。
- 不把模型是否支持图片输入、某个 AI 账户是否有 Images endpoint 等上游能力混入这里；本区只展示系统账户级权限。

### 4.4 账号安全

- 普通改密要求填写当前密码、新密码、确认密码。
- 初始密码强制修改时不要求当前密码，页面顶部显示警告，并把焦点定位到安全区。
- 前端沿用当前密码至少 4 个字符且不能包含空白字符的规则，最终以后端校验为准。
- 修改成功后清空全部密码输入；当前会话继续有效，其他会话沿用现有逻辑被撤销。
- 密码不进入页面状态缓存、URL、日志、错误详情或浏览器持久化。
- 不在本期增加密码强度策略、设备管理、查看密码或“退出所有设备”开关。

### 4.4.1 用户请求限制

- 页面新增只读“请求限制”卡片，展示每分钟、每日、每周、每月四个最终生效值；`0` 显示“无限制”，有限值显示格式化数字。
- 每个窗口显示来源：继承系统设置时标记“全局默认”，用户覆盖时标记“单独配置”。用户不能在个人信息页修改。
- 用户覆盖可带整组到期日 `overrideExpiresOn`。所选日期当天仍有效；按 `timezone` 从次日 `00:00` 起 `overrideActive=false`，页面提示已到期并显示当前已继承全局。
- 未设置到期日表示用户覆盖永久有效；到期状态不依赖浏览器本地日期自行推断，以后端 `effectiveRequestLimits` 为准。

### 4.5 时间信息

- 展示 `lastLoginAt`、`createdAt`、`updatedAt`。
- 空的最近登录时间显示 `暂无记录`。
- 时间使用项目统一本地时区格式化，并保留完整时间 tooltip。

## 5. 强制改密流程

现有应用壳通过全屏锁定加弹窗完成初始改密。迁移到个人信息页面后统一为路由流程：

1. 登录或接口返回 `must_change_password` 时刷新轻量当前用户摘要。
2. 若 `mustChangePassword=true`，只允许访问 `/profile` 和执行退出登录；其他受保护路由重定向到 `/profile?section=security&required=1&redirect=<原目标>`。
3. 个人信息页面仍可展示身份和权限事实，但名称保存按钮禁用，安全区置顶或自动滚动并展示“请先修改初始密码”。
4. 改密成功后更新全局认证状态；存在合法同源 `redirect` 时返回原目标，否则进入当前用户偏好首页。
5. `redirect` 只接受站内路由，不接受绝对 URL 或协议相对 URL。

首期实现完成后删除应用壳中的常规 `DisplayNameModal` 和 `ChangePasswordModal` 挂载；如果这两个组件没有其他消费者则一并删除。强制改密也不再依赖布局层弹窗。

## 6. API 与类型契约

### 6.1 轻量当前用户摘要

`GET /__aisys__/api/auth/me`、登录、资料修改和改密返回继续使用轻量 `CurrentUserSummary`，供路由守卫与应用壳使用：

```ts
interface CurrentUserSummary {
  id: string
  username: string
  displayName: string
  role: 'super_admin' | 'admin' | 'user'
  mustChangePassword: boolean
}
```

不把详情字段全部塞入每次导航依赖的认证摘要，个人页面按需加载详情。

### 6.2 当前用户详情

新增 `GET /__aisys__/api/auth/profile`，只根据当前 session 的 `systemAccountId` 查询自己的系统账户，返回：

```ts
interface CurrentUserProfile {
  id: string
  username: string
  displayName: string
  description?: string
  role: 'super_admin' | 'admin' | 'user'
  status: 'active' | 'disabled'
  mustChangePassword: boolean
  imageGenerationEnabled: boolean
  effectiveRequestLimits: {
    perMinute: { limit: number; source: 'global' | 'user' }
    perDay: { limit: number; source: 'global' | 'user' }
    perWeek: { limit: number; source: 'global' | 'user' }
    perMonth: { limit: number; source: 'global' | 'user' }
    timezone: string
    overrideExpiresOn?: string
    overrideActive: boolean
  }
  lastLoginAt?: string
  createdAt: string
  updatedAt: string
}
```

约束：

- 未登录或会话失效返回 `401`。
- 初始密码未修改时仍允许读取本人的 profile，以便强制改密页展示身份；不能复用会阻断 `mustChangePassword` 的普通管理 API 中间件。
- 不接受 `systemAccountId`、用户 ID 或任何查询范围参数。
- 不返回 `password_hash`、session token、API Key、上游账户凭据或管理员专用内部状态。
- 当前用户请求限制增量只要求 Node/Vue 返回上述字段；本次不扩展 Go profile 契约。

### 6.3 写接口复用

- `PATCH /__aisys__/api/auth/me`：继续只接受 `{ displayName }`，不接受 `username`、角色、状态、说明或权限字段。
- `POST /__aisys__/api/auth/change-password`：继续接受 `{ oldPassword?, newPassword }`，沿用当前密码校验、强制改密和撤销其他 session 的行为。
- 页面保存成功后直接合并响应；管理员在其他页面调整角色、状态或生图权限后，以再次进入 / 刷新 profile 的详情结果为准。

## 7. 前端落点

- `frontend/src/router/index.ts`：新增不进入 `menuRoutes` 左侧菜单投影的 `/profile` 受保护路由，并增加强制改密路由守卫。
- `frontend/src/views/profile/ProfileView.vue`：页面组合、加载 / 错误 / 保存状态和响应式布局。
- `frontend/src/views/profile/profileDisplay.ts`：时间、状态和权限展示等纯函数；只在确有多个调用点或需要独立回归时拆分。
- `frontend/src/api/domains/auth.ts`：新增 `profile()`；保留现有 `updateProfile()` 与 `changePassword()`。
- `frontend/src/types/domain/identity.ts`：新增 `CurrentUserProfile`。
- `frontend/src/layouts/AppHeader.vue`、`frontend/src/layouts/AppLayout.vue`：菜单改为“个人信息”，删除常规资料 / 改密弹窗状态和处理函数。

页面需要覆盖：详情加载态、加载失败重试、保存中、保存失败保留输入、只读能力、强制改密警告和小屏单栏。

## 8. 后端落点

- Node：`backend/src/modules/auth/auth.routes.ts` 增加 profile GET，复用 `findSystemAccountByIdAsync` 和现有系统账户 mapper / summary 语义。
- Go：`backend-go/internal/modules/managementauth/` 增加只读 profile service / port，`backend-go/internal/httpapi/management_auth.go` 增加同契约 handler，并接入现有管理路由 opt-in 边界。
- 不新增数据库字段或迁移；`system_accounts` 已具备全部目标字段。
- 不使用管理员 `GET /system-accounts/:id` 代替 self profile，避免普通用户权限扩大和前端拼接当前 ID。

## 9. 状态同步与并发边界

- 个人详情是页面局部状态；认证摘要仍由 `useAuth` 维护。
- `displayName` 写成功时同时更新详情和认证摘要；角色、生图权限、状态和时间不由前端乐观修改。
- 页面加载和保存都应使用请求 generation 或等价门，离开页面、切换登录用户或后发请求完成后，旧响应不得覆盖新用户状态。
- 不为低频 profile 引入轮询、IndexedDB 响应缓存、全局 store 或 WebSocket。

## 10. 验收标准

- 所有登录角色都能从头像菜单进入 `/profile`；左侧菜单不新增“个人信息”。
- 头像菜单不再出现“修改名称”和“修改密码”两个旧入口，普通与沉浸式移动菜单一致。
- 页面完整展示登录账号、用户名称、账户 ID、说明、角色、账户状态、图像生成权限、最近登录、创建和更新时间。
- 用户名称修改成功后，页面和头部立即一致；失败时输入不丢失。
- 改密要求、错误提示、成功清空和其他会话撤销行为与现有后端一致。
- 强制改密用户只能进入个人信息安全区或退出，改密完成后可安全返回原目标。
- 普通用户不能读取或修改他人资料，任何响应都不包含密码 hash、session token 或其他凭据。
- Node / Go 接口契约、前端类型检查、生产构建、专项回归和隔离浏览器桌面 / 手机验收通过。

## 11. 非目标与后续扩展

- 不做头像上传、裁剪或对象存储。
- 不修改登录账号 `username`。
- 不允许用户自助修改角色、状态、说明或图像生成权限。
- 不增加手机号、邮箱、真实姓名、第三方账号绑定或设备管理。
- 后续新增系统账户级能力时，可以在 `CurrentUserProfile` 增加明确事实字段并在“权限与能力”区展示；不能把 AI 账户、模型或供应商的动态能力误写成用户权限。
