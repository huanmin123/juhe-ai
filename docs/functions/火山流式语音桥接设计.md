# 火山流式语音桥接设计（V1 流式 TTS 先行）

> 状态：V1a 已实施（2026-10-18；**真实 2.0 出音直探通过**——`zh_female_cancan_uranus_bigtts` 71KB mp3，A 级帧形态回填完成；网关级全链 E2E 待 volctest 库从并发迁移中间态恢复）。
> 背景：火山「语音」分类 11 子类中 9 个未承接面里有 6 个是 openspeech WebSocket/HTTP 流式协议族（语音合成 2.0、实时语音、流式识别、同传、语音播客、长文本合成）。本批立项桥接，**V1 以流式 TTS 切入**——探测发现它有 HTTP chunked 面（非 WS），桥接复杂度最低且与我们现役语音臂同 host 同凭据体系；WS 桥基座作为 V2 服务于其余 WS-only 子能力。
> 关联：[火山方舟账号接入](火山方舟账号接入.md)（语音域既有承接）、[流式语音跨协议转换设计](流式语音跨协议转换设计.md)（M6：/v1/realtime 会话转换，与本设计互补不重叠）、[实时语音Realtime网关设计](实时语音Realtime网关设计.md)（M5 基座先例）。

## 1. 目标与非目标

**目标**：OpenAI 兼容 `/v1/audio/speech` 面新增豆包语音合成模型 2.0（`seed-tts-2.0`）的**流式合成承接**——客户端请求即合成，音频字节以 chunked 流式回流（低首包时延），计量计费落库闭环。

**非目标**：不新增对外端点（复用 `/v1/audio/speech` 统一面）；不做双向流式 WS 客户端面（V2）；不做实时语音/同传/播客承接（V2 后各自设计）；不做 WebRTC；不承诺 1.0 seed-audio 臂行为变化（既有同步面零回归）。

## 2. 上游面事实（2026-10-18 A 级实测，隔离库凭据即用即删）

- **端点**：`POST https://openspeech.bytedance.com/api/v3/tts/unidirectional`（语音服务域，与既有 TTS/ASR 臂同 host——URL 构造特例同 `chainVolcengineSpeechUpstreamURL` 先例）。
- **鉴权**：`X-Api-Key` 单头（**与现役 `speech_token` 同一凭据实测可行**——请求穿过鉴权层进入业务校验，零新凭据字段）+ `X-Api-Resource-Id: seed-tts-2.0`。
- **请求体**：`{"user":{"uid":...},"req_params":{"text","speaker","audio_params":{"format","sample_rate",...}}}`（字段全集实施首步对照官方文档回填）。
- **响应（A 级实测，2026-10-18 真实 2.0 出音 71KB mp3）**：`Content-Type: text/plain` NDJSON 流——音频帧 `{"code":0,"data":"<base64 分块>"}`（data 为 base64 字符串非对象）、句级帧 `{"code":0,"data":null,"sentence":{...}}`、终止帧 `{"code":20000000,"message":"OK"}`、错误帧 `{"reqid","code","message"}`；帧形态已钉入契约 §9.2。**音色配对规则**：2.0 用 `*_uranus_bigtts` 系音色（如 `zh_female_cancan_uranus_bigtts` 灿灿 2.0），1.0 系 `*_mars_bigtts` 音色错配即 55000000。
- **错误码实测**：`55000000 "resource ID is mismatched with speaker related resource"`（音色未授权 2.0 / 音色与资源不配对）；经典资源 `volc.service_type.10029` → **403 `45000030 "requested resource not granted"`**（该账号未开通经典大模型 TTS 资源）。
- **当前阻塞（唯一）**：账号无 2.0 音色授权（语音控制台开通 2.0 音色或提供可用音色清单）——开通后 V1 真实出音即通。
- **计费维度（已取证）**：语音合成 2.0 按字符 **3 元/万字符**（豆包语音计费页，取证指南数据源表在册）——沿既有 `TtsInputChars` 字符计量口径 + `ttsInputCostPerChar` 字段先例（minimax speech 行）。

## 3. V1a 架构：全缓冲 NDJSON 转换（已实施；复查后与初稿的偏差）

复查（对代码取证）修正初稿两处：① 语音 adapter 注册表按 provider 分键（`SpeechAdapterForProvider`），流式/同步分派在 volcengine adapter **内部按 model 分支**（`IsVolcengineTTSStreamModel`），不扩注册表接口；② 响应是 **NDJSON**（每行 `{"event","data":{"audio":"<base64 分块>"}}`，B 级帧名待实弹回填），按 minimax/gemini「JSON 回 base64 音频」同族**全缓冲转换**先例实施（32MB 窗口），**首包流式回流（chunked 逐块）降级为 V1b**——需共享管道新增转换透传模式（解码字节改变 commit-state 记账），独立跟进，不阻塞能力交付。

```text
POST /v1/audio/speech  (OpenAI 形态)
  → 路由（audio 域账户, supportedModels 含 seed-tts-2.0, audio_speech mode）
  → volcengineSpeechRequest 分派（ParseSpeechRequest L1 校验共用）
  → volcengineSpeechAdapter.BuildRequest 内部 model 分支：
      seed-tts-2.0 → /api/v3/tts/unidirectional
        body {"user":{"uid"},"req_params":{"text","speaker","audio_params":{"format","speech_rate?"}}}
        词表 mp3/pcm/ogg_opus/wav（2.0 与 1.0 不同：无 opus、pcm 正式支持）；speed 区间 [0.2,3.0]
      seed-audio-1.0/doubao-tts → 既有同步面（零变化）
  → chainVolcengineSpeechUpstreamURL 同源出站（openspeech 固定域）+ X-Api-Key 凭据注入
  → 非流式管道全缓冲（32MB 窗口）→ TransformResponse NDJSON 解析：
      data.audio base64 分块按序拼接 → 二进制音频透传；错误行（code 非 0）→ 上抛
  → usage：TtsInputChars（请求字符自算，官方计费维度为字符——nonstream 管道按 model 分流，
    1.0 时长口径不变）× 目录行 ttsInputCostPerChar
```

- **客户端语义**：响应为完整音频二进制（全缓冲后一次写出），`Content-Type` 按请求 `response_format` 推导（`volcengineTTSStreamContentTypeOf`：mp3→audio/mpeg、pcm→audio/pcm、ogg_opus→audio/ogg、wav→audio/wav）。
- **失败语义**：本地 400（词表外/越界/缺参沿同步臂规则）；上游错误行（HTTP 200 包 `{"code","message"}`，55000000 音色未授权形态实测）→ 502 `upstream_error` 透传 message；`45000030`（资源未授权，实测 403）→ 上游错误透传，显式失败**不静默回退** 1.0 模型；凭据缺失 → 沿既有 `speech_credentials_missing`。
- **计量计费**：`TtsInputChars` × 目录行 `ttsInputCostPerChar = 3 元/万字符 ÷ 7.0 ≈ $4.2857e-05/字符`（CNY 四件套）；失败/中断不虚计。响应内 duration 不参与计费。

## 4. 目录与凭据

## 5. V2 展望：openspeech WS 桥基座（另批设计）

WS-only 子能力（双向流式 TTS、实时语音、流式识别 sauc、同传 AST、语音播客）共享一个 openspeech WS 泵基座——拨号（自定义鉴权头）、二进制帧编解码（协议版本字节 + payload 类型）、背压、会话级计量。客户端面分两类：会话型（实时语音/流式识别/同传——复用 M6 `RealtimeUpstreamConn` 抽象或新客户端 WS 面，各自设计稿）与任务型（播客）。V2 立项前提：各资源的 grant 开通（同传/实时语音/播客 resource id 未实测，不预判）。

## 6. 分期与验收

- **V1 实施序**：① 实弹回填帧格式与 req_params 全字段（A 级化）→ ② 目录行 + 钉值 → ③ 流式 adapter + 链接线（错误映射单测）→ ④ mockupstream 增 unidirectional chunked 场景（音频帧 + JSON 错误帧 + 中断）→ ⑤ 链级 E2E（mock 全链 + 计量计费落库断言）→ ⑥ 真实实弹（2.0 音色开通后，真实音频字节 + usage/cost 核对 + 接入文档实测记录）。
- **验收门**：既有同步 TTS 臂全量用例零回归；流式臂三层（adapter 单测/链级/真实实弹）；计费位逐单核对；`vue-tsc`/Go 全量相关包绿。
- **开放问题**：① 2.0 音色授权清单（用户控制台开通）；② chunked 流内帧格式（实施首步回填契约 §9.2）；③ `audio_params` 速度/情感字段名（回填）；④ 并发会话库迁移落地后排期（实现期与迁移期错峰）。
