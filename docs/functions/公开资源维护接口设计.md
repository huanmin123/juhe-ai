# 公开资源维护接口设计

> 当前结论：`sub2api-lite` 的 `/__aipublic__` 只面向受信任来源系统后端提供受控资源维护能力，不再提供 IP 维度消耗排行、IP 维度消费聚合、账号维度实际消耗聚合、公益接入信息或来源鉴权 demo。公开能力固定为 API Key、路由策略、分组和 AI 账户的列表、新增、修改、删除，以及供应商目录的只读同步（列表 + 分 tab 详情）。

## 当前状态

- 已实现：外部来源系统 Bearer token 鉴权、来源 / token 管理、scope 校验、来源限频、公开接口日志和动态接入文档。
- 已实现：API Key、路由策略、分组、AI 账户的公开 CRUD 接口。
- 已实现：供应商目录只读同步接口（`GET /__aipublic__/provider/list`、`GET /__aipublic__/provider/detail`）。
- 已移除：`GET /__aipublic__/demo/source-auth`、`GET /__aipublic__/ip/usage`、`GET /__aipublic__/account/usage`、`GET /__aipublic__/consumption/ranking`、`GET /__aipublic__/access/info`。
- 不实现：公益站用户维度排行榜、IP 到用户归属、公益接入展示、账号 / IP 消耗公开聚合快照。

## 公开接口清单

所有接口都需要：

```http
Authorization: Bearer <source_token>
```

| 资源 | 列表 | 新增 | 修改 | 删除 |
| --- | --- | --- | --- | --- |
| API Key | `GET /__aipublic__/api-key/list` | `POST /__aipublic__/api-key/add` | `POST /__aipublic__/api-key/update` | `POST /__aipublic__/api-key/del` |
| 路由策略 | `GET /__aipublic__/route-strategy/list` | `POST /__aipublic__/route-strategy/add` | `POST /__aipublic__/route-strategy/update` | `POST /__aipublic__/route-strategy/del` |
| 分组 | `GET /__aipublic__/group/list` | `POST /__aipublic__/group/add` | `POST /__aipublic__/group/update` | `POST /__aipublic__/group/del` |
| AI 账户 | `GET /__aipublic__/account/list` | `POST /__aipublic__/account/add` | `POST /__aipublic__/account/update` | `POST /__aipublic__/account/del` |
| 供应商（只读） | `GET /__aipublic__/provider/list`，详情 `GET /__aipublic__/provider/detail` | - | - | - |

## Scope

每个接口使用独立 scope，来源系统和 token 必须同时拥有目标 scope 才允许调用。

```text
juhe_ai_public:api_key_list:read
juhe_ai_public:api_key_add:write
juhe_ai_public:api_key_update:write
juhe_ai_public:api_key_delete:write

juhe_ai_public:route_strategy_list:read
juhe_ai_public:route_strategy_add:write
juhe_ai_public:route_strategy_update:write
juhe_ai_public:route_strategy_delete:write

juhe_ai_public:group_list:read
juhe_ai_public:group_add:write
juhe_ai_public:group_update:write
juhe_ai_public:group_delete:write

juhe_ai_public:account_list:read
juhe_ai_public:account_add:write
juhe_ai_public:account_update:write
juhe_ai_public:account_delete:write

juhe_ai_public:provider_list:read
juhe_ai_public:provider_detail:read
```

## 供应商目录同步

供应商目录同步提供两个只读接口，向外部来源系统暴露启用中供应商的目录信息；不提供供应商新增、修改或删除。

### 供应商列表

`GET /__aipublic__/provider/list`，scope 为 `juhe_ai_public:provider_list:read`。

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `page` | 否 | 页码，默认 `1`。 |
| `pageSize` | 否 | 每页数量，范围 `1..100`，默认 `20`。 |

行为：

- 只读返回启用中（enabled）的供应商，不返回已停用供应商。
- 按 `name`、`code` 稳定排序。
- 分页响应包含 `page`、`pageSize`、`pageUpperBound` 和 `hasMore`；`pageUpperBound` 是分页上界而非精确总数，与其他公开 list 接口口径一致。
- `items[]` 每项包含 `code`（唯一标识）、`name`（显示名）、`parentCode`（父级供应商，可空）、`description`（可空）和 `enabled`。

### 供应商详情

`GET /__aipublic__/provider/detail`，scope 为 `juhe_ai_public:provider_detail:read`。

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `code` | 是 | 供应商唯一标识，长度 1..60，按 `code` 精确匹配定位；供应商不存在或已停用返回 `404`。 |
| `tab` | 是 | 详情分 tab，取值 `basic` 或 `models`。 |
| `category` | 否 | 仅 `tab=models` 时有效，可选枚举 `text` 或 `image`。 |
| `page` | 否 | 仅 `tab=models` 时有效，≥1。 |
| `pageSize` | 否 | 仅 `tab=models` 时有效，1..100。 |

详情按 tab 按需获取，单次响应只返回当前 tab 数据，不返回另一个 tab 的内容。

- `tab=basic`：返回基本信息和协议档案，包含 `provider` 对象（`code`、`name`、`parentCode`、`description`、`enabled`）、`defaultSupportedModels[]` 和 `protocolProfiles[]`；每个协议档案包含 `id`、`name`、`description`、`enabled`、`protocolCode`、`protocolVersion`、`baseUrl`、`defaultHealthCheckModel`、`accountTypes[]`、`capabilities[]` 和 `endpointFamilies`（每项含 `code`、`name`）。
- `tab=models`：返回该供应商模型目录，只包含 active 且有价的模型；hybrid 供应商返回展开合并后的目录。服务端按规则计算 `category`：模型 ID 以 `gpt-image` 或 `dall-e` 前缀开头归为 `image`，其余归为 `text`。支持按 `category` 筛选和分页。`items[]` 每项包含 `model`、`category`、`status`、`contextWindowTokens`、`maxInputTokens`、`maxOutputTokens`、`inputUsdPer1M`、`outputUsdPer1M`、`cachedInputUsdPer1M`、`supportsPromptCaching` 和 `sourcePricingCurrency`。

内置测试 token 调用两个接口时返回 `source:'mock'` 的确定性数据。

### 验收标准

- 两个接口只响应 `Authorization: Bearer <source_token>` 来源 token，且来源系统和 token 必须同时拥有对应 scope；scope 不足返回 `403`。
- `provider/list` 只包含启用中（enabled）供应商；`provider/detail` 对已停用或未知 `code` 返回 `404`。
- 详情按 tab 按需获取，单次响应不返回另一个 tab 的数据；`tab=models` 支持 `category` 筛选和分页。
- 本文档与 [外部来源系统鉴权设计](外部来源系统鉴权设计.md)、[接口契约与权限矩阵](接口契约与权限矩阵.md)、[公开接口日志设计](公开接口日志设计.md)、[安全与日志策略](安全与日志策略.md) 及 api-docs 目录、scope 枚举同步更新。

## 资源边界

- `targetUsername` 是公开资源维护接口的业务目标用户参数，不是来源授权白名单。
- 分组新增可按 `targetUsername` 定位或自动创建目标系统用户；AI 账户新增也可自动创建目标系统用户和目标分组；路由策略和 API Key 新增要求目标用户已存在或依赖前序分组 / 账号流程创建完成。
- 修改和删除接口以本系统资源 ID 精确定位，`targetUsername` 只作为可选归属校验。
- API Key 只绑定路由策略；路由策略负责绑定分组和调度模式。
- AI 账户公开新增 / 修改当前只支持 `type=api_key` 账户，不接收 OAuth 凭据，不返回上游凭据；上游 `apiKey` 和 `baseUrl` 只进入后端凭据存储，响应永远不回显。
- 公开接口不保存外部来源系统的业务 ID；新增响应返回的本系统 ID 由调用方自行记录。
- 公开接口只服务控制面维护，不返回用量聚合、公益展示信息、封禁策略、排行榜或 IP 归属关系。
- 供应商目录同步接口只读、只暴露启用中（enabled）供应商，不包含 AI 账户、凭据、用量与健康状态；账号数据仍走 `/__aipublic__/account/list`。协议档案 `baseUrl` 属供应商目录配置，不是账户凭据；接口日志与脱敏规则沿用现有前缀级策略。

## 返回安全

- API Key 列表和修改响应不返回明文 `key`；只有新增接口在本次响应返回一次性明文。
- AI 账户列表和修改响应不返回上游 `apiKey`、OAuth token、代理密码或加密字段。
- 路由策略返回分组绑定摘要和调度配置，不返回账号凭据。
- 分组返回分组摘要和绑定数量，不返回组内账号凭据。
- 供应商目录同步接口不返回凭据类字段；协议档案 `baseUrl` 属供应商目录配置，不是账户凭据。
- 公开接口日志的请求 header 快照只捕获 `contentType` / `contentLength`，不捕获 `Authorization`、Cookie 或作为 Bearer 凭据传入的来源 token；query、请求 body 和响应 body 在容量与结构预算内保留原值，不按字段名或字符串形态递归脱敏。调用方仍不要把非必要敏感字段放入公开接口。

## 动态接入文档

管理员通过 `GET /__aisys__/api/external-integration-sources/api-docs` 读取当前公开接口手册。该接口只返回当前 18 个接口的请求说明、字段、响应示例和 curl 示例，curl 中的 token 固定展示为 `<source_token>`，不会暴露内置测试 Token 或生产 token 明文。

## 旧接口处理

以下旧路径不再对外提供，访问应返回 404：

```text
GET /__aipublic__/demo/source-auth
GET /__aipublic__/ip/usage
GET /__aipublic__/account/usage
GET /__aipublic__/consumption/ranking
GET /__aipublic__/access/info
```

后续如需新增公开能力，必须先明确它是否仍属于资源维护；统计、排行榜、公益展示、公网入口说明和 IP / 用户归属不重新放回 `sub2api-lite` 公开接口。
