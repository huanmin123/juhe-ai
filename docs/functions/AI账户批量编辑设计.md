# AI 账户批量编辑设计

## 1. 目标

AI 账户列表新增“批量编辑”能力。用户选择多个可编辑账户后，通过独立弹窗勾选需要覆盖的配置项，并把同一组新配置直接覆盖到全部目标账户。

批量编辑只处理可共享的账户配置，不复制账户身份、上游凭据、资源归属、分组关系或系统运行状态。

## 2. 基本原则

- 用户必须明确勾选要修改的字段；未勾选字段保持原值。
- 被勾选字段使用“直接覆盖”语义，不做数组追加、对象深合并或按旧值猜测。
- 空数组、空规则或 `null` 是明确的清空值，必须和“未勾选、不修改”区分。
- 后端在一个事务中先校验全部目标账户和最终配置，再统一写入；任一账户失败则整批不写。
- 列表仍只加载摘要。打开批量编辑时按所选 ID 批量读取必要详情，不能把所有可编辑字段提前塞入主列表。
- 批量编辑不能修改健康、错误、冷却和运行态，也不能复用人工测试结果。

## 3. 不允许批量修改

以下字段属于账户身份、私有连接配置、关系或系统事实，必须隔离：

- 账户名称。
- 账户归属系统账户和授权来源。
- 加入分组、分组绑定和授权关系。
- 供应商、协议档案和账户类型。
- API Key、API Key 池、OAuth Token、Refresh Token 和其他凭据。
- Base URL。
- 账户 ID、创建时间和凭据版本。
- `status`、`schedulable`、冷却时间、最近错误。
- 健康检查时间、失败计数、下次检查时间和其他健康事实。
- 运行态恢复、客户端回避、代理桶、Key 运行态和会话亲和。
- 最近使用、用量、额度、质量和统计结果。

授权实例账户不进入批量编辑。管理侧只能批量编辑目标作用域内的自有物理账户，用户侧只能批量编辑自己的自有账户。

## 4. 可批量覆盖字段

### 4.1 通用配置

- 账户标签。
- 代理配置。
- 并发限制。
- 账户优先级。
- 超级优先。
- 降级备用。
- 账户到期时间。
- 时间计划。
- 说明。
- 账户错误处理规则。
- 账户响应检查规则。

### 4.2 模型与协议配置

- 支持模型。
- 上游接口能力 / endpoint modes。
- 检查模型。
- 检查请求形态。
- 账号模型别名。
- 服务等级和思考级别；后续新增的供应商账户请求覆盖配置必须先登记到批量编辑字段白名单。

“检查模型”和“检查请求形态”在“模型与协议”页签内同一行展示，但各自保留独立的覆盖复选框；用户可以只覆盖其中一项，未勾选的另一项保持不变。批量编辑与单账户编辑统一使用“账户标签、时间计划、说明、账号模型别名、新增别名、客户端模型、上游模型、服务等级、思考级别”中文文案。

模型与协议配置只在全部目标账户具有相同 `providerCode + providerProtocolProfileId + type` 时开放。混合供应商、不同协议档案或不同账户类型不能用同一组模型配置覆盖。

检查模型与支持模型的最终校验：

- 如果只覆盖检查模型，新模型必须属于每个目标账户原有支持模型。
- 如果同时覆盖支持模型和检查模型，按本次最终支持模型校验。
- 如果覆盖支持模型但不覆盖检查模型，每个账户原检查模型都必须仍属于新支持模型，否则整批拒绝。
- 账号模型别名（`modelMappings`）复用单账户选择与校验规则：普通账户客户端模型来自当前供应商完整目录，Hybrid 客户端模型按来源协议过滤；上游模型取全部目标账户最终支持模型交集，并按每行上游协议过滤。

### 4.3 代理配置

代理虽然不属于凭据，但会改变连接链路：

- 目标代理必须对全部目标账户归属作用域可见。
- 允许明确设置代理或清空代理。
- 保存后为受影响账户投递后台健康检查，不使用人工测试确认。
- 批量修改代理不直接把账户写为异常；系统检查按正常阈值确认账户级故障。

## 5. 弹窗交互

入口：

- 账户列表勾选至少 2 个账户后显示“批量编辑”。
- 选中授权实例、跨管理作用域或无编辑权限账户时，入口禁用并提示原因。

弹窗结构：

1. 顶部显示选中账户数量和名称摘要。
2. 每个配置项左侧使用复选框或开关表示“本次覆盖此字段”。
3. 未启用的字段控件禁用，不读取某个账户值作为隐式默认。
4. 启用字段后填写统一新值。
5. 保存前展示“将覆盖 N 个账户的 X 项配置”确认摘要。
6. 提交成功后关闭弹窗、清理勾选并刷新列表。
7. 提交失败时保留表单和选择，展示具体失败账户及原因。

不得使用“混合值”占位后直接提交。批量编辑不是同时编辑多个表单，而是显式构造一组覆盖操作。

## 6. 接口契约

批量编辑弹窗上下文使用独立的有界批量投影：

```text
POST /__aisys__/api/accounts/batch-edit-context
POST /__aisys__/api/my-accounts/batch-edit-context
```

```json
{
  "accountIds": ["account-a", "account-b"],
  "fields": ["supportedModels", "modelMappings", "supportedEndpointModes"]
}
```

- `accountIds` 去重后为 2-100 个；管理端始终提交所选账户的 owner scope，owner 条件进入账户查询 SQL。
- 基础响应只包含 `id`、`configRevision`、供应商、协议档案、协议和账户类型；不返回名称、标签、代理、策略、usage、运行态、权限或授权来源。
- `supportedModels`、`modelMappings`、`supportedEndpointModes` 只有在 `fields` 显式请求时返回；endpoint modes 由仓储从密文列提取为顶层字段，响应不返回 `credentials`。
- 仓储按全部目标 ID 批量读取。基础上下文固定 1 条账户查询；请求全部三类模型依赖时固定为 1 条账户查询和 2 条关系查询，不能逐账户装配完整 `AccountSummary`。

批量保存接口如下。

管理侧：

```text
POST /__aisys__/api/accounts/batch-update
```

用户侧：

```text
POST /__aisys__/api/my-accounts/batch-update
```

请求结构：

```json
{
  "targets": [
    {
      "accountId": "account-a",
      "configRevision": 3
    },
    {
      "accountId": "account-b",
      "configRevision": 7
    }
  ],
  "updates": {
    "tags": {
      "enabled": true,
      "value": ["生产"]
    },
    "concurrencyLimit": {
      "enabled": true,
      "value": 5
    },
    "proxyProfileId": {
      "enabled": true,
      "value": null
    }
  }
}
```

约束：

- `targets` 去重后至少 2 个、最多 100 个；每项必须包含账户 ID 和打开弹窗时读取到的正整数 `configRevision`。
- `updates` 至少启用一个字段。
- 字段名必须来自后端白名单，未知字段返回 `400`。
- `targets[].configRevision` 用于防止弹窗打开后账户被其他操作修改；任一版本冲突返回 `409`，整批不写。
- 后端重新加载全部账户和引用配置，不能信任前端详情快照。
- 返回批次操作 ID、账户 ID 和各账户提交后的 `configRevision`。

## 7. 事务与副作用

事务内：

1. 校验调用方对全部目标账户的编辑权限。
2. 拒绝授权实例和跨作用域账户。
3. 校验乐观版本。
4. 计算每个账户的最终配置。
5. 校验模型、协议、代理、标签、计划和规则。
6. 批量写入账户配置及关联表。
7. 提交事务。

事务后：

- 写操作日志，记录批次 ID、账户 ID 和字段变化，不记录凭据。
- 失效账户详情、列表摘要、账号池和相关模型能力缓存。
- 对检查模型、检查请求形态、支持模型、账号模型别名、endpoint modes 或代理发生变化的账户投递后台健康检查。
- 非连接配置变化不触发检查。
- 后台任务投递失败必须可补偿，不回滚已经成功提交的配置；使用 dirty 标记或待检查时间由 worker 兜底扫描。
- 事务提交后的统计脏标记、缓存失效、日志或摘要刷新失败只能记录告警，接口仍返回批次已提交成功，不能向前端伪装成整批未写入。

## 8. 审计与权限

- 操作日志保存一个批次主记录和每个账户的字段变化摘要。
- 管理侧操作记录目标系统账户作用域和实际管理员。
- 用户侧只能操作当前登录用户自己的自有账户。
- 不允许通过批量接口绕过单账户编辑中的字段校验、模型目录权限、代理权限或规则限制。
- 导入、公开外部接口和授权实例接口不复用该批量编辑接口，除非后续单独设计权限和幂等契约。

## 9. 与后台检查的关系

- 批量编辑本身不执行人工测试。
- 批量编辑不接受测试任务 ID。
- 批量编辑不直接修改健康状态。
- 影响连接或检查配置的字段保存后，由后台系统检查确认。
- 检查失败按 [AI 账户检查模型与人工测试设计](AI账户检查模型与人工测试设计.md) 的模型级 / 账户级故障分类处理。

## 10. 验证要求

- 未勾选字段保持不变。
- 勾选字段在全部目标账户上直接覆盖。
- 空数组和 `null` 可以明确清空，未勾选不清空。
- 名称、分组、供应商、协议档案、凭据、Base URL 和运行状态不能通过接口修改。
- 混合供应商或协议账户不能批量覆盖模型与协议配置。
- 检查模型和支持模型组合按最终快照校验。
- 任一账户无权限、版本冲突或配置非法时整批不写。
- 缓存失效和后台检查投递覆盖全部受影响账户。
- 列表初始加载不增加完整详情字段。
- 操作日志能按批次和账户追踪，不包含敏感凭据。
