# 请求错误策略配置设计

## 目标

请求错误策略用于把上游 HTTP 非 `2xx` 错误从黑盒兜底改为可视化、结构化的系统级运维配置。策略不归属某个用户、账户或 API Key，而是由管理员在系统运维菜单统一维护，运行时按当前请求的协议、供应商、客户端和模型上下文匹配。

当前只落地 OpenAI v1 协议；后续新增 Anthropic、Gemini 或其他协议时，应复用同一层级模型，不把厂商私有规则写死到通用网关层。

## 边界

- 只处理上游 HTTP 非 `2xx` 响应。
- 不处理 `200 + SSE` 流内失败、广告污染或协议内事件；这些由 [流式拦截策略配置设计](流式拦截策略配置设计.md) 承接。
- 不开放请求头、请求体、上下文改写配置。Header 补齐、body 归一化、客户端上下文适配和 OAuth / Codex adapter 兼容逻辑仍属于系统内部策略。
- 不做账户维度、用户维度或 API Key 维度规则。用户无法安全维护请求头改写、body 替换、上下文补齐和上游协议适配，也通常不需要参与这些兼容策略。

## 层级模型

策略层级从通用到具体为：

1. 全局层：所有协议通用兜底。
2. 协议层：当前为 OpenAI v1，后续可扩展到 Anthropic、Gemini 等协议。
3. 供应商层：同一协议下某个供应商的局部规则，例如 GPT。
4. 客户端层：Codex 等客户端 profile 的专属错误语义。
5. 模型层：某个模型或模型族的局部规则，可按精确、前缀或包含匹配。

运行时下级继承上级：没有更具体命中时继续使用上级策略；多个策略同时匹配时，先按模型、客户端、供应商、协议、全局的具体性排序，再按 `priority` 从小到大排序。

## 存储

`error_policies` 保存系统级请求错误策略：

- `scope_type`：`global`、`protocol`、`provider`、`client`、`model`。
- `protocol_code`：非全局层必须写入，当前为 OpenAI v1 协议编码。
- `provider_code`：供应商层必填；模型层可选，用于把模型规则限制在某个供应商下。
- `client_profile`：客户端层必填，例如 `codex`。
- `model_pattern` / `model_match_type`：模型层匹配值和匹配方式。
- `match_json`：匹配条件，只包含 `statusCodes`、`errorCodes`、`errorTypes`、`keywords`。
- `action`：`retry_next`、`temp_unschedulable`、`rate_limited`、`error_disabled`。
- `reset_strategy`、`duration_hours`、`daily_reset_hour`、`weekly_reset_day`、`weekly_reset_hour`：仅 `rate_limited` 使用。

状态码匹配禁止填写 `2xx` 成功状态码；错误码、错误类型和关键词只作为上游错误体诊断输入，不允许替代流式 `2xx` 内部事件处理。

## 管理入口

系统运维菜单提供 `请求错误策略` 页面，只允许管理员访问。页面支持新增、编辑、删除、启停、搜索和配置指南。

当前管理 API 为 `/__aisys__/api/error-policies`，写操作记录操作日志，且策略变化会通知网关运行时缓存失效。

## 运行时处理

网关在 API Key 校验、分组选定、账号候选确定和上游响应返回后处理非 `2xx`：

1. 读取受限错误响应体并记录使用记录和审计尝试。
2. 根据当前 `protocolCode`、`providerCode`、`clientProfile` 和下游 `model` 读取候选策略。
3. 匹配状态码、错误码、错误类型和关键词；多个匹配字段必须同时满足。
4. 命中策略后只形成待确认目标，不立即写持久账号状态。
5. 当前账号先进入本进程短 TTL 屏蔽，当前请求继续切后续账号。
6. 只有运行态确认失败且当前账号并发归零后，才按策略目标写当前命中的账户行或授权实例账户行。

未命中策略或命中 `retry_next` 时，仍按通用上游失败形成 `temporary_unavailable` 待确认目标；代码不再内置 OAuth reset、余额不足、限流、固定状态码或错误文案分支。

## 动作语义

| 动作 | 语义 |
| --- | --- |
| `retry_next` | 不改变策略目标，继续走通用失败确认和切号流程。 |
| `temp_unschedulable` | 确认失败后写 `temporary_unavailable`，恢复走系统级快速 / 慢速后台复测。 |
| `rate_limited` | 确认失败后写 `rate_limited`，按固定时长、每天固定时间或每周固定时间恢复。 |
| `error_disabled` | 确认失败后写 `status = error`，等待人工恢复异常。 |

## 维护规则

- 新增已知上游非 `2xx` 错误时，优先新增或调整请求错误策略，不在兜底层写状态码、错误码或文案特判。
- 新增客户端专属错误语义时，先确认是否属于客户端层策略；Codex 之外的新客户端不能写进通用 OpenAI 逻辑。
- 新增协议或供应商时，先补协议 / 供应商事实，再把错误处理落到协议层或供应商层策略。
- 请求头、请求体和上下文改写必须继续在 adapter 或网关内部实现，不进入请求错误策略页面。
