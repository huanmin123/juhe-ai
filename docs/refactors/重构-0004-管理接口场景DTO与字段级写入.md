## 重构目标

- 把共享宽 `AccountSummary` / `ApiKeySummary` 从管理列表和编辑写链路退出。
- 让列表、编辑基础、高级、options、runtime、secret 和 mutation 各自拥有明确 DTO 与 repository。
- 让 PATCH 的字段存在性、实际差异、SQL 更新列、关联表写入和缓存失效保持同一作用域。

## 重构前问题

- route 通过 sanitizer 删除字段，但 repository 已经完成宽查询和关联加载。
- Vue 打开弹窗主动加载可变候选，已有 dropdown 按需入口却未成为唯一入口。
- 编辑基础与高级共用同一 form loader 和完整 summary，导致加载状态和 dirty 状态边界模糊。
- Node 用当前完整对象构造 next 后全列 UPDATE，单字段请求仍扩大到整个资源及统计域。

## 拆分设计

- account list repository：只负责当前页显示字段及有界批量摘要。
- account edit-basic repository：只负责基本表单和可编辑凭据投影。
- account advanced repository：只负责高级折叠区。
- account patch command：严格字段白名单、版本、归一化差异和字段分类失效。
- API Key list / edit seed、secret read、patch command：彼此独立，禁止默认加载 usage。
- user reference resource：用户作用域默认分组和默认策略引用，登录后异步单飞。
- Vue modal state：baseline、loaded section、dirty section、按需候选与请求代次分离。

## 变更范围

- `backend/src/modules/accounts/*`、账户 storage / domain 场景类型。
- `backend/src/modules/api-keys/*`、`api-key.repository.ts` 及专用 mapper。
- `frontend/src/views/accounts/*`、`frontend/src/views/api-keys/*`、共享引用 cache 与 API types。
- 审计确认的分组、路由、授权、响应检查、模型检查和外部来源弹窗入口。
- 契约、回归、计划、问题和功能文档。

## 行为边界

- 保持权限、资源 owner、默认资源、状态机、健康检查、授权实例和网关最终校验语义。
- 明确变化为弹窗不再预取候选，编辑保存采用 delta + revision，mutation 响应不再返回完整领域对象。
- 任何真实业务变化都推进 `configRevision`；副作用按字段分类，名称 / 备注只更新自身列与版本，不失效无关运行态或投递探针。
- 账户人工测试批量模型 DTO 严格为 `{ id, name }`；单模型 capabilities 独立提供协议与请求形态，避免批量接口重新膨胀。
- Go 不在本次范围，不保留为了 Go 对齐而增加的兼容字段或双实现。

## 风险与后续

- `repositories.ts` 与账户表单文件仍偏大，需按场景逐步抽离，避免一次性无证据重写网关共用逻辑。
- 凭据聚合 JSON、授权实例和多数据库驱动是最高风险边界，必须用字段级与并发测试保护。
- 其他低收益页面只在真实审计证据支持时继续拆分，不以“所有详情请求都应删除”为目标。
- 已完成的横向审计确认：代理、系统账户、系统团队和供应商模型编辑仍是全量 payload / 宽查询 / 全列覆盖；账户批量编辑上下文仍逐个装配完整账户摘要。这些项目需要各自的 revision、场景 DTO、字段级 SQL 和 no-op 回归，按独立小批次治理，不能借本轮账户改造直接复用未经证明的聚合写逻辑。
- 已排除的误报包括代理、系统账户、外部来源弹窗首开，团队成员候选和普通账户标签候选；它们已经按真实交互加载，不能为了形式上的统一再增加预取或无意义详情接口。
