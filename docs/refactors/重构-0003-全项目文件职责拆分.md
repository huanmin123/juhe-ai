# 重构-0003-全项目文件职责拆分

## 基本信息

- 编号：REFACTOR-0003
- 状态：进行中
- 创建时间：2026-06-13
- 关联模块：前端、后端、存储、网关
- 触发原因：前一轮已完成网关目录分层，但项目内仍存在大文件继续混合 API 聚合、页面格式化、表单模型、存储校验、业务写入和运行流程的问题，后续维护容易继续误把新逻辑塞回旧大文件。

## 重构目标

- 先完成 `backend/src` 与 `frontend/src` 代码文件级审计，按行数和职责混杂程度识别继续拆分对象。
- 保持现有外部导入入口和页面行为不变，优先抽离纯函数、格式化、参数序列化、表单模型和输入归一化。
- 对高风险流程只做边界移动，不混入业务语义变化。
- 每次拆分后立即跑对应 typecheck 和最小回归。

## 已完成拆分

### 前端 API 客户端

- `frontend/src/api/client.ts`
  - 保留对外 `api` 聚合、参数类型导出和旧入口兼容。
  - 不再直接承载 axios 实例、登录失效通知、fetch SSE、错误读取、查询参数构造和 API 契约类型定义。
- `frontend/src/api/contracts.ts`
  - 负责前端 API 参数、payload 和流选项等类型契约。
  - 由 `client.ts` re-export，页面旧的 `@/api/client` 类型导入保持可用。
- `frontend/src/api/http.ts`
  - 负责 axios 实例、`unwrap`、无超时配置、认证失败通知、fetch 错误文本读取和基础 query string。
- `frontend/src/api/modelCheckStream.ts`

## 行为边界

- 前端页面仍从 `@/api/client` 导入 `api` 和类型，未要求页面批量改路径。
- API Key 页面模板、按钮、弹窗、分组选项搜索 / 缓存 / 失效清理、保存 payload 字段保持不变。
- 授权页面模板、筛选项、路由 query 筛选语义、远程选项选中项回填、创建 / 修改 payload 字段保持不变。
- 外部集成来源页的列表筛选、来源保存字段、Token 创建 / 复制、接入文档加载、curl 复制和 Markdown 导出语义保持不变。
- 审计日志页的筛选、详情加载、payload 分块读取窗口、原文查看、复制和搜索语义保持不变。
- 模型检测页面的筛选项、状态 / 级别颜色、终端输出文案、结果详情 JSON 展示和检测流程保持不变。
- 模型检测支持模型、探针集合、检测评分口径和记录字段保持不变；仅补齐非流式探针在下游 SSE 体中提取 response model 的兜底解析。
- 账号测试和模型检测共用同一套 OpenAI v1 JSON / SSE 输出和失败消息解析；账号测试的原始非 JSON 失败文案仍保留 240 字符兜底。
- 账户凭据保存仍走原 `storage/repositories.js` 对外入口；Base URL SSRF 策略和凭据字段限制保持不变。
- 账户支持模型和模型映射的外部入口、错误文案、供应商目录校验和写库流程保持不变。
- 账户草稿测试、编辑快照测试、成功草稿测试激活、测试任务归属校验和内容变化提示保持不变。
- 本轮只做职责移动，不调整数据库结构、不改接口字段、不改页面交互语义。
