## 重构前问题

- `backend/src/storage/repositories.ts` 同时包含账号、分组、授权、用量汇总等多类职责，资源授权 helper 与其他仓储逻辑混在同一文件内。
- 多个前端页面重复实现 `parseDateKey`、`formatDateKey`、日期范围归一化、最近窗口禁用日期和 ECharts 初始化 / 销毁 / resize 逻辑。
- 重复逻辑散落后，统计窗口边界、日期合法性判断和图表释放策略容易在后续页面改动中出现不一致。
- `frontend/src/views/accounts/AccountsView.vue` 在已组件化的基础上仍承载账号权限判断、菜单项拼装、授权提示和流量迁移目标判断，修改账号动作需要进入页面容器阅读较多无关状态。
- 账号页面还内联了测试模型选项、代理选项、账号与分组映射、绑定分组选项、流量迁移目标选项等派生数据构造逻辑，增加了页面容器噪音。
- 账号页面还内联列表加载、筛选、排序、分页、移动端加载更多和页面状态缓存，导致页面容器既处理数据获取又处理弹窗动作。
- 账号页面批量测试、批量启用 / 停用和批量更新流程与单账号弹窗逻辑混在一起，导致选择状态、批量提示和接口更新逻辑不容易独立维护。
- 账号页面单账号菜单动作还内联了测试弹窗、恢复正常、启停用、OAuth 令牌刷新、超级优先、降级备用和流量迁移入口；这些流程依赖权限规则但不需要直接留在页面容器。
- 流量迁移弹窗把打开前校验、默认目标账户选择、目标选项计算、保存接口调用和成功提示全部放在页面容器中，和账号编辑、测试、列表状态混杂。
- 重新授权弹窗把 OAuth 授权 URL 生成、回调 URL / Refresh Token 校验、保存 API 分支和弹窗状态放在页面容器中，和账号创建 OAuth 流程互相穿插。
- 绑定分组弹窗把异常账户校验、默认分组选取、分组选项 / 提示计算和绑定接口调用留在页面容器中，和账号编辑默认分组逻辑重复靠近但职责不同。
- 账号测试弹窗把测试模型加载、AbortController、运行 / 停止、成功 / 失败提示、失败结果构造和批量静默测试请求都留在页面容器中，使页面底部沉积了较长的异步流程。
- 账号编辑弹窗还承载创建 / 编辑入口、默认表单、账户类型切换、分组选项、状态选项、OAuth 授权链接、保存提交和 OpenAI OAuth 创建分支，是账号页面容器中剩余最大的业务流程。

- `backend/src/modules/gateway/openai-gateway.routes.ts` 的账号循环前半段还内联代理重复失败跳过、代理 profile 不可用副作用、OAuth access token 刷新和 Codex 本地校验失败记录，使“账号准备”和“上游尝试”混在一个函数中。
- `backend/src/modules/gateway/openai-gateway.routes.ts` 的 OpenAI models 固定响应和认证失败审计仍直接留在主请求编排中，导致成功 usage 入队、响应 JSON 和 auth audit payload 与路由主流程混杂。
- `backend/src/modules/gateway/openai-gateway.routes.ts` 的主请求 catch 块还内联客户端取消、上游可见拒绝响应和 Codex 本地校验失败响应收口，导致兜底 dispatch 失败前需要阅读多段响应写回和审计字段拼装。

- `backend/src/modules/gateway/openai-gateway.routes.ts` 的上游账号选择循环仍承载并发槽保留 / 释放、账号准备、代理失败跳过、URL / attempt 重试、失败响应策略和 session affinity 成功记忆，导致路由需要直接理解底层调度状态机。
- `backend/src/modules/gateway/openai-gateway-usage.ts` 同时承担请求 / 响应 usage snapshot、JSON usage 提取、SSE 流式解析、可见输出判断和 token 估算 fallback，导致非流式 usage 工具与流式解析状态机耦合。

- `backend/src/storage/usage-stats.repository.ts` 同时承担统计窗口生成、窗口行分组、用量趋势聚合、模型 / 错误排行聚合和 SQLite 读写，统计口径纯逻辑不便单独复用或测试。

- AI 性能概览同时包含访问范围解析、默认账号选择、选中账号补齐、小时趋势查询、摘要读取和选项搜索，挤在通用统计仓库中会放大文件体量，也让 AI 性能口径难以独立维护。
- 配额小时窗口刷新和通用排行快照写入 SQL 是快照阶段的可复用基础动作，放在主仓库文件中会让阶段编排、窗口刷新和 SQL 模板互相穿插。
- caller account 用量统计回填和账号质量分钟缓存回填共享同一套 `stats_job_state` 读取、`usage_records` 游标分页、事务提交、完成 / 进度 / 失败状态写入流程，重复维护容易让后续 backfill 状态口径不一致。
- 操作日志、审计日志、运行日志、使用记录和 API Key 页面都重复实现了服务端分页、移动端追加加载、刷新、`loading` / `mobileLoadingMore` / `mobileHasMore` 状态和表格分页事件解析；页面真正差异只在筛选参数、选项加载、排序和附属运行时信息读取。
- `backend/src/storage/audit-logs.repository.ts` 同时承载审计日志 / 尝试 / 错误分组 SQL 和 payload blob 文件压缩、去重、清理、gzip / plain offset 读取逻辑，导致审计业务编排与大 payload 文件 IO 边界混在一起。
- `backend/src/storage/audit-logs.repository.ts` 还内联审计日志、错误分组、attempt 和 payload ref 的 row 映射，以及账号 / 分组 / API Key 名称补齐逻辑，SQL 编排和展示 DTO 映射互相穿插。
- `backend/src/storage/usage-records.repository.ts` 同时承载使用记录列表 / 详情 SQL、名称补齐、row-to-DTO 映射、分页参数归一化、排序 SQL 和筛选 SQL 构造；后续调整使用记录展示字段或筛选项时容易误碰写入链路。
- `backend/src/storage/usage-records.repository.ts` 的写入路径还内联归属系统账户推断、账号 / 分组 owner 查询、资源授权快照读取和 access type 推断；这些逻辑属于 usage 记录授权语义，不属于 INSERT 编排本身。
- `backend/src/storage/openai-account-selector.repository.ts` 自己维护了一份 active authorization 查询和分组 owner 查询，和 `resource-authorization-helpers.ts` 中的资源授权 helper 重复。
- 记录库维护队列引入后，API Key 关联记录清理导出口、worker 消息消费和 db-service runtime snapshot 字段需要统一接线，否则全仓类型检查会被后台队列边界打断。

## 拆分设计

- `backend/src/storage/resource-authorization-helpers.ts`
  - 负责资源授权的基础查询、账号 / 分组归属查询、过期判断、使用汇总 scope 构造、授权来源脱敏和资源归属管理判断。
  - 不负责系统团队、授权写入、分组绑定同步和仓储对外 API。
- `backend/src/storage/audit-log-payload-blobs.ts`
  - 负责审计 payload blob 的内容类型归一化、压缩判断、文件路径安全校验、去重持久化、孤儿 blob 清理和按 offset / limit 读取窗口。
  - 不负责审计日志列表、详情、错误分组、attempt / payload ref 写入和接口响应映射。
- `backend/src/storage/audit-log-mappers.ts`
  - 负责审计日志、错误分组、attempt 和 payload ref 的 row-to-DTO 映射，以及 API Key / 分组 / 账号名称补齐。
  - 不负责 SQL 查询、事务、payload 文件 IO 和错误分组聚合写入。
- `backend/src/storage/usage-record-mappers.ts`
  - 负责使用记录名称补齐、row-to-DTO 映射、详情快照解析和 snapshot endpoint fallback。
  - 不负责列表 SQL、权限 scope、写入事务、账号 last used 更新和授权元数据计算。
- `backend/src/storage/usage-record-list-query.ts`
  - 负责使用记录列表分页参数归一化、排序 SQL、筛选 SQL、账号关键字匹配和状态码校验。
  - 不负责执行查询、DTO 映射、详情读取和 usage record 写入。
- `backend/src/storage/usage-record-access-metadata.ts`
  - 负责 usage 写入前的归属系统账户推断、账号 / 分组 owner 查询、资源授权快照读取和 access type / 授权来源字段生成。
  - 不负责 usage records INSERT、API Key 存在性检查、账号 last used 更新和列表 / 详情查询。
- `frontend/src/shared/dateRange.ts`
  - 负责日期 key 校验 / 解析 / 格式化、默认日期范围、日期范围归一化和最近窗口禁用日期判断。
