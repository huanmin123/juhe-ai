## 使用规则

1. 本文只记录未完成事项。事项完成后立即删除对应条目，不保留“已完成”段落或历史记录；需要保留过程时，写入对应计划、问题或复盘文档。
2. 新增事项必须放入正确的状态分区，并至少包含：现象或目标、证据、归属、下一步、完成判定和关联文档。没有可核对证据的事项不进入本清单。
3. 事项使用稳定编号（`B`=阻塞、`C`=待确认、`T`=待办、`W`=观察、`P`=指针），跨条目引用使用编号锚点，例如 `#B1`。引用外部计划、设计或提交时提供仓库相对链接或提交哈希。
4. “完成判定”必须是可观察、可验证的结果。证据变化时更新条目；状态变化时移动到对应分区并保留原编号，避免引用失效。`W` 观察项升级为缺陷后删除本条并给档案链接；`P` 指针在对应载体了结后删除。
5. 每次修改后更新“最后核验”日期；核验只说明本清单所依据的代码、文档或提交，不代表条目已经完成。

## 条目格式

新增条目按以下顺序组织，内容不适用时写“无”：

```markdown
### B/C/Tx/Wx 标题

- 现象 / 目标：
- 证据：
- 归属：
- 下一步：
- 完成判定：
- 关联：
```
