# 待办与阻塞事项

> 定位：多会话共享的当前工作清单，只记录尚未关闭的阻塞、待确认、已明确待排期事项，以及暂不处理但需要观察的事项和其它跟踪载体的指针。

## 使用规则

1. 本文只记录未完成事项。事项完成后立即删除对应条目，不保留“已完成”段落或历史记录；需要保留过程时，写入对应计划、问题或复盘文档。删除条目的提交同时包含完成该条目的改动，git 历史即已完成记录。
2. 新增事项必须放入正确的状态分区，并至少包含：现象或目标、证据、归属、下一步、完成判定和关联文档。没有可核对证据的事项不进入本清单。
3. 事项使用稳定编号（`B`=阻塞、`C`=待确认、`T`=待办、`W`=观察、`P`=指针），跨条目引用使用编号锚点，例如 `#B1`。引用外部计划、设计或提交时提供仓库相对链接或提交哈希。
4. “完成判定”必须是可观察、可验证的结果。证据变化时更新条目；状态变化时移动到对应分区并保留原编号，避免引用失效。`W` 观察项升级为缺陷后删除本条并给档案链接；`P` 指针在对应载体了结后删除。每条 `W` 观察项写明最长观察期，到期强制复核：升级为对应分区或缺陷档案，或删除本条，不留无限期观察项。

## 条目格式

新增条目按以下顺序组织，内容不适用时写“无”：

```markdown
### B/C/Tx/Wx 标题

- 现象 / 目标：
- 证据：
- 归属：
- 下一步：
- 完成判定：
- 关联：
```

### W55 生产 SSRF 出站守卫对本地 DNS 被污染域名间歇误判（2026-11-21 已修复，待发布验证；观察至 2026-12-21）

- 现象 / 目标：生产账户 `api.0-0-luna`（`acc_1780450302807_7398c7cd`，base_url `https://api.0-0.pro/v1`，代理「本机代理17892」= socks5h `172.18.0.1:17892`）的余额刷新间歇返回 `余额查询目标地址不被允许`（`upstream_blocked`），同一分钟内人工刷新可在成功（`$1.16`）与被拒绝之间来回。根因不是账户配置或上游：`api.0-0.pro` 在大陆本地 DNS 被污染，偶发返回 `2001::68f4:2eb9`（Teredo，落在 `upstreamhttp` 的 `2001::/23` blocked range），`DialGuard.ValidateHost` 对“任一解析地址命中保留段”整体拒绝；账户实际请求经 socks5h 远端解析可正常到达（经生产代理 DoH 核实真实 A 记录为 `15.204.81.199`，无 AAAA）。
- 证据：
  - 生产遥测（近 7 天，`juhe_jobs.account_balance_outcomes`）：periodic 1703 ok / 141 `http_404` / 67 `upstream_blocked` / 42 `transport_error`；2026-11-21 02:07-02:08 人工刷新依次 ok → ok → upstream_blocked → ok → upstream_blocked。
  - 网关容器本地解析 `api.0-0.pro` 60 次（jobs/宿主机抽查同类）：A 记录为 `31.13.112.4`、`31.13.68.169`、`108.160.167.165`、`168.143.171.154`（GFW 污染地址）；AAAA 40 次中出现 2 次 `2001::68f4:2eb9`。经生产代理 DoH 查询返回真实 A `15.204.81.199`、AAAA NODATA。
  - 代码（行号以修复前父提交 `e621e0a52` 为准）：`backend-go/shared/platform/accountbalance/direct_http.go:368-373`（余额发送前 `ValidateHost`；HEAD 对应 `:374`）、`backend-go/shared/platform/upstreamhttp/urlguard.go:396-424`（修复前口径：任一解析地址命中即拒绝；2026-11-21 已改为全部命中才拒绝）、`urlguard.go:84`（`2001::/23` 在黑名单）；`/v1` 派发同源校验见 `backend-go/projects/gateway/internal/business/gateway_dispatch/dispatch.go:289` 与 `backend-go/projects/gateway/internal/gatewaydispatch/gatewayupstream/transport_urlpolicy.go:97`（HEAD 对应 `:103`），因此同类账户真实流量也存在间歇被拒可能。
  - 当前实际流量未见影响：该账户近 24h `juhe_usage.usage_records` 19 条全部 200；`http_404` 为该站点只实现 `/v1/usage`、其余适配器端点均 404 时回退链的最终诊断，与密钥/配置无关（人工刷新同一 Key 可成功，`/v1/usage` 无鉴权稳定 401 证明路由存在）。
- 归属：`shared/platform/upstreamhttp`（守卫策略）与生产网络环境（域名 DNS 污染）；非账户/上游配置问题。
- 修复实施（2026-11-21，代码+测试完成）：`upstreamhttp.DialGuard` 解析语义改为混合放行——至少一个解析地址不命中 blocked ranges 即通过，只有全部解析地址被 blocked 才拒绝；直连与本地解析 socks5 只拨号/发送校验通过的地址，socks5h 保持远端解析（发送前预检为 best-effort）。远端解析代理（HTTP(S)、socks5h）的发送前预检同样采用混合放行，代理侧最终解析不受本地控制、仍可能选择 blocked 地址；该残余窗口为已接受 best-effort 边界（2026-11-21 用户裁决不做额外限制）。同一解析 helper 覆盖 `ValidateHost` 与拨号路径，新增 DNS 污染回归（`ValidateHost`/`DialContext`/socks5 本地解析/余额查询混合解析）；核心功能设计、OpenAI 账号接入、余额查询设计、安装指南与 `docker/single-server/README.md` env 契约已同步。原未决选项（`extra_hosts`、放宽代理预检）不再采用。
