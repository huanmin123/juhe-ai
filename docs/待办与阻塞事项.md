# 待办与阻塞事项

> 定位：多会话共享的当前工作清单，只记录尚未关闭的阻塞、待确认、已明确待排期事项，以及暂不处理但需要观察的事项和其它跟踪载体的指针。

## 使用规则

1. 本文只记录未完成事项。事项完成后立即删除对应条目，不保留“已完成”段落或历史记录；需要保留过程时，写入对应计划、问题或复盘文档。删除条目的提交同时包含完成该条目的改动，git 历史即已完成记录。
2. 新增事项必须放入正确的状态分区，并至少包含：现象或目标、证据、归属、下一步、完成判定和关联文档。没有可核对证据的事项不进入本清单。
3. 事项使用稳定编号（`B`=阻塞、`C`=待确认、`T`=待办、`W`=观察、`P`=指针），跨条目引用使用编号锚点，例如 `#B1`。引用外部计划、设计或提交时提供仓库相对链接或提交哈希。
4. “完成判定”必须是可观察、可验证的结果。证据变化时更新条目；状态变化时移动到对应分区并保留原编号，避免引用失效。`W` 观察项升级为缺陷后删除本条并给档案链接；`P` 指针在对应载体了结后删除。每条 `W` 观察项写明最长观察期，到期强制复核：升级为对应分区或缺陷档案，或删除本条，不留无限期观察项。

## 条目格式

新增条目按以下顺序组织，内容不适用时写“无”：

```markdown
### B/C/Tx/Wx 标题

- 现象 / 目标：
- 证据：
- 归属：
- 下一步：
- 完成判定：
- 关联：
```

### W47 F3 审计 payload blob 目录存在 66746 个 GC 永不回收的孤儿文件（17.32GB，71.7%），是主机持续 IO 压力的写入源

  - 2026-11-02 08:5x 全量比对（`find … -printf "%f\n"` 对 `SELECT split_part(storage_key,'/',2)`）：磁盘唯一文件 111708 / 表内唯一 44962 / **磁盘有表无 66746 / 表有磁盘无 0**；python 逐文件求和得孤儿 17.32GB。

- 修复（2026-11-02 实施，两道治理）：①写侧 `compensatePublishedBlobs`——`Persist` 在 publish 之后失败时补偿删除本次由本进程 rename 成功的新文件（复用既有 canonical 不删；commit 未知结果不删），且**补偿必须先于 `tx.Rollback()` 求值**以持住 per-blob advisory lock（独立复审确认的原实现缺陷，已修）；②读侧 `reconcileOrphanBlobFiles`——owner retention tick 在既有 `CleanupRetention` 主链之后追加有界 FS→DB 对账：遍历 `<blobDir>/sha256/**`、按 `storage_key` 反查表行、对 mtime 超过 1 小时安全窗口的无行文件走同一 per-blob advisory lock + 复核路径删除；跨轮游标按目录字典序推进、走完回卷；结果计 `RetentionResult.DeletedOrphanBlobFiles` 并进 `audit_retention_completed` 日志与手动清理操作日志。
