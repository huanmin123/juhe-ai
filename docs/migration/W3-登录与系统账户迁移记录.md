# W3 登录与系统账户迁移记录

> 本文记录 W3 “登录与系统账户”迁移的当前切片。W3 涉及登录、验证码、会话、改密、系统账户写接口和会话撤销，风险高；必须按小切片推进，不能因为某个读接口完成就声明 W3 接管。

| --- | --- | --- | --- |

## 当前契约

| 项 | 内容 |
| --- | --- |
| 路径 | `GET /__aisys__/api/auth/me` |
| 启用条件 | 仅在 `JUHE_AI_MANAGEMENT_API_ENABLED=true` 时注册；默认生产 server 不注册 |
| 登录态 | 读取 `juhe_ai_session` Cookie，按 SHA-256 token hash 查询 `system_sessions`，校验 session 未过期、session active、系统账户 active |
| 成功响应 | `200 { data: { id, username, displayName, role, mustChangePassword } }` |
| 初始密码用户 | 普通 `user` 即使 `mustChangePassword=true` 也允许读取当前用户摘要，并返回 `mustChangePassword=true`；`admin` / `super_admin` 的有效值始终为 `false` |
| 未登录 | `401 { message: "请先登录" }` |
| 会话失效 | `401 { message: "登录会话已过期" }` |
| 内部错误 | `500 { message: "服务器内部错误" }`，不泄露数据库、密钥或连接串 |
| 副作用 | 不更新 `last_seen_at`，不写 operation log，不写 Redis，不写 session |

## 本轮不迁移范围

- `GET /__aisys__/api/auth/captcha`
- `POST /__aisys__/api/auth/login`
- `POST /__aisys__/api/auth/logout`
- `PATCH /__aisys__/api/auth/me`
- `POST /__aisys__/api/auth/change-password`
- 系统账户创建、更新、停用、启用、重置密码、改密提醒、图像生成权限调整
- 登录失败锁定、验证码一次性消费、session 创建 / touch / 撤销、默认资源 fanout、gateway cache invalidation
- 系统账户写接口 operation log；Node 当前系统账户创建 / 重置密码日志可能记录明文密码，Go 迁移时必须先修正，不复刻该行为

## Go 实现范围

- `managementauth.Authenticator` 保留受保护后台接口的初始密码 403 拦截，同时新增 current-user 读取分支，允许前端读取 `mustChangePassword` 状态。
- `httpapi.NewManagementCurrentUserHandler` 直接调用 current-user 鉴权分支并返回当前用户摘要，不套用普通管理端 middleware。
- `router.go` 在 `JUHE_AI_MANAGEMENT_API_ENABLED=true` 时注册 `GET /auth/me`；其他管理端接口仍走 `ManagementAPIAuthMiddleware`。
- `server.go` 复用同一个 `Authenticator` 注入 current-user handler；默认关闭和启动依赖不变。
- integration smoke 在现有管理端 session 鉴权 smoke 中覆盖 `GET /auth/me` 当前用户响应。

## 后续拆分建议

1. `PATCH /__aisys__/api/auth/me`：只允许修改当前用户 `displayName`，普通初始密码用户继续 403。
2. `POST /__aisys__/api/auth/change-password`：允许初始密码用户改密，成功后撤销其他 session；必须先固定密码 hash、session revoke 和 operation log 边界。
3. `POST /__aisys__/api/auth/logout`：按 token hash 撤销当前 session 并清 Cookie。
4. `GET /__aisys__/api/auth/captcha` + `POST /__aisys__/api/auth/login`：必须统一迁移验证码状态、登录失败锁定、session 创建和 `last_login_at` 更新；Node / Go 不能并行各自维护进程内登录状态。
5. 系统账户写接口：创建 / 更新 / 停用 / 重置密码必须补齐默认资源 fanout、session revoke、cache invalidation、operation log 敏感字段脱敏和事务边界。

## 接管与删除门禁

- `GET /auth/me` 只代表 W3 当前用户读切片可灰度验证，不能删除 Node `/auth` router。
- W3 必须等登录、验证码、登出、改密、session touch / revoke、系统账户写接口和安全日志全部迁移并通过真实 PG/Redis 验证后，才能进入 `待删除 Node`。
- 删除 Node 前必须确认前端登录页、初始密码修改页、头像菜单、系统账户管理页和权限拦截全部指向 Go 单 owner。
- 删除后使用 `rg "authRouter|requireSessionContext|system-accounts|findSessionByTokenAsync|createSessionAsync|revokeSessionAsync" backend/src` 检查旧入口，只允许未迁移历史文档引用。
