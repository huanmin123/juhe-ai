## 当前契约

### `GET /__aisys__/api/auth/captcha`

| 项 | 内容 |
| --- | --- |
| 路径 | `GET /__aisys__/api/auth/captcha` |
| 启用条件 | 仅在 `JUHE_AI_MANAGEMENT_API_ENABLED=true` 时注册；默认生产 server 不注册 |
| 登录态 | 不要求登录，不读取 `juhe_ai_session` |
| 成功响应 | `200 { data: { captchaId, image, expiresAt } }`，`image` 固定为 `data:image/png;base64,...` |
| 验证码规则 | 5 位，字符集为 `23456789ABCDEFGHJKLMNPQRSTUVWXYZ`；答案只写 Redis state，不写响应，不输出 SVG / 文本 |
| 存储 | Redis state key 为 `auth_captcha:challenge:{captchaId}`，JSON 值包含 `answer` 和毫秒级 `expiresAt`，TTL 5 分钟；校验时通过 Redis `GETDEL` 一次性消费，错误答案也会消费 challenge |
| 生成限流 | 按客户端 IP 经 SHA-256 派生低泄漏 key，Redis fixed-window 限制 60 次 / 分钟；超限不创建新 challenge |
| 超限响应 | `429 { message: "验证码请求过于频繁，请稍后再试" }`，带 `Retry-After` |
| system API 读限流 | 虽然是 GET，但属于写 runtime state 的入口，Go router 明确跳过 system API IP 读限流，避免和验证码自身限流叠加 |
| 副作用 | 只写 Redis state / rate-limit 计数，不写 PG，不 touch session，不写 operation log，不创建登录 session |

### `POST /__aisys__/api/auth/login`

| 项 | 内容 |
| --- | --- |
| 路径 | `POST /__aisys__/api/auth/login` |
| 启用条件 | 仅在 `JUHE_AI_MANAGEMENT_API_ENABLED=true` 时注册；默认生产 server 不注册 |
| 登录态 | 不要求已有登录态；该入口是 session 创建小切片 |
| 请求体 | 严格 JSON object，只允许 `username`、`password`、`captchaId`、`captchaCode` 四个字符串字段；未知字段、缺字段、非字符串、空字符串、尾随 JSON 返回 `400 { message: "登录参数无效" }` |
| 空白字符 | `username` 或 `password` 包含任意空白字符时返回 `400 { message: "用户名和密码不能包含空格" }` |
| 验证码 | 先调用 Go `CaptchaService.VerifyChallenge`，通过 Redis `GETDEL` 一次性消费 challenge；验证码错误 / 过期返回 `400 { message: "验证码错误或已过期" }`，且不计入登录失败锁 |
| 登录失败锁 | 验证码通过后检查 Redis state 登录失败锁；IP 和用户名各按 10 分钟窗口累计 10 次失败，锁定 15 分钟；IP 锁优先返回 `429 { message: "尝试过于频繁，请稍后再试" }`，用户名锁返回 `429 { message: "账号暂时锁定，请稍后再试" }`，均带 `Retry-After` |
| 凭据校验 | 只允许 `system_accounts.status='active'` 的系统账户登录；密码使用 Node 兼容 PBKDF2-SHA512 hash 校验；账号不存在、停用或密码错误统一返回 `401 { message: "账号或密码错误" }` |
| session 创建 | 成功后生成 32 字节随机 base64url token，PG 只存 SHA-256 hex `token_hash`；`system_sessions.id` 使用 `sess_` 前缀；TTL 为 14 天；`created_at` 和初始 `last_seen_at` 使用同一登录时间 |
| 登录时间 | 同一条 PG CTE 中更新 `system_accounts.last_login_at` / `updated_at` 并插入 `system_sessions`，避免 session 与登录时间局部成功 |
| Cookie | 成功后签发 `juhe_ai_session`，`Path=/`、`HttpOnly`、`Max-Age=14d`、`Expires=session_expires_at`；`Secure` 与 `SameSite` 由 `JUHE_AI_COOKIE_SECURE` / `JUHE_AI_COOKIE_SAME_SITE` 控制，`SameSite=None` 要求 `Secure=true` |
| 成功响应 | `200 { data: { id, username, displayName, role, mustChangePassword } }`；Go 明确不返回 Node 当前可能泄漏的 `passwordHash` |
| 副作用 | 写 Redis 登录失败计数 / 锁、成功清理当前 IP 与用户名登录失败状态、写 PG session 和登录时间；不写 operation log，不创建系统账户默认资源，不处理系统账户管理端重置密码 / 停用带来的完整 revoke |

### `PATCH /__aisys__/api/auth/me`

| 项 | 内容 |
| --- | --- |
| 路径 | `PATCH /__aisys__/api/auth/me` |
| 启用条件 | 仅在 `JUHE_AI_MANAGEMENT_API_ENABLED=true` 时注册；默认生产 server 不注册 |
| 登录态 | 走管理端写鉴权 `ManagementAPIAuthTouchMiddleware`，读取 `juhe_ai_session`、校验 session 未过期、系统账户 active，并拦截普通初始密码用户 |
| 请求体 | 严格 JSON object，只允许 `displayName: string`；未知字段、缺字段、非字符串和空字符串返回 `400 { message: "用户资料参数无效" }` |
| 显示名规则 | 不允许任何空白字符；命中返回 `400 { message: "显示名称不能包含空格" }`；大小写不敏感全局唯一，冲突返回 `409 { message: "用户名称已存在" }` |
| 成功响应 | `200 { data: { id, username, displayName, role, mustChangePassword } }` |
| 初始密码用户 | 普通 `user` 且有效 `mustChangePassword=true` 时返回 `403 { message: "请先修改初始密码", code: "must_change_password" }`；管理员角色有效值始终为 `false` |
| no-op | `displayName` 与当前值完全相同时直接返回当前用户摘要，不更新 PG，不写 operation log |
| 存储约束 | `juhe_business.system_accounts` 新增 `idx_system_accounts_display_name_unique_lower`，PG 层捕获 `23505` 作为重复显示名冲突；更新 SQL 不读取 `password_hash` |
| 操作日志 | 真实变更时 best-effort 入队 `operation-log:write`，`operationKey=auth.update_profile`、`module=system_accounts`、`action=update`、`mode=self`、`changes=[displayName]`；入队失败不影响业务成功 |
| session touch | 有效 session 且 `last_seen_at < now - 60s` 时更新当前 `system_sessions.last_seen_at=now`；fresh session 跳过写库；touch 错误按内部错误返回，不继续执行业务 |
| 内部错误 | `500 { message: "服务器内部错误" }`，不泄露数据库、密钥或连接串 |

### `POST /__aisys__/api/auth/change-password`

| 项 | 内容 |
| --- | --- |
| 路径 | `POST /__aisys__/api/auth/change-password` |
| 启用条件 | 仅在 `JUHE_AI_MANAGEMENT_API_ENABLED=true` 时注册；默认生产 server 不注册 |
| 登录态 | 读取 `juhe_ai_session` Cookie，按 SHA-256 token hash 查询 `system_sessions`，校验 session 未过期、session active、系统账户 active，并在通过鉴权后按写模式 touch 当前 session；该路由不能套普通管理端 middleware，否则普通初始密码用户会被提前 403 |
| 请求体 | 严格 JSON object，只允许 `oldPassword?: string` 和 `newPassword: string`；未知字段、缺少 `newPassword`、非字符串、`null`、`newPassword` 少于 4 个字符或 `oldPassword=""` 返回 `400 { message: "密码参数无效" }` |
| 空白字符 | `oldPassword` 或 `newPassword` 包含任意空白字符时返回 `400 { message: "登录密码不能包含空格" }` |
| 初始密码用户 | 普通 `user` 且有效 `mustChangePassword=true` 时可只提交 `{ newPassword }`，不校验旧密码；成功后 `mustChangePassword=false` |
| 普通改密 | 有效 `mustChangePassword=false` 时必须提交 `oldPassword`，缺失返回 `400 { message: "请填写当前密码" }`；旧密码校验失败或校验账号不等于当前 session 账号返回 `400 { message: "当前密码不正确" }` |
| 管理员角色 | `admin` / `super_admin` 的有效 `mustChangePassword` 始终为 `false`，因此管理员改密也必须提交旧密码 |
| 密码 hash | Go 使用 Node 兼容格式 `pbkdf2$sha512$120000$salt-base64url$derived-base64url`，16 字节随机 salt、32 字节 PBKDF2-SHA512 派生值；响应和 operation log 都不得返回 `password_hash` |
| 成功响应 | `200 { data: { id, username, displayName, description, role, status, mustChangePassword, imageGenerationEnabled, lastLoginAt, createdAt, updatedAt } }` |
| 会话副作用 | 鉴权阶段按 60 秒窗口更新当前 session `last_seen_at`；成功后删除同账号下 `id <> 当前 sessionId` 的 `system_sessions`，保留当前 session；不重新签发 Cookie，不清 Cookie |
| 操作日志 | 当前 Node 自助改密不写 operation log；Go 本切片保持一致。系统账户管理端 reset-password 已脱敏记录密码重置和撤销 session 数，status-only 已记录状态变化和撤销 session 数；其他完整系统账户写接口日志仍随后续切片处理 |
| 内部错误 | `500 { message: "服务器内部错误" }`，不泄露数据库、密钥、旧密码、新密码或密码 hash |

### `POST /__aisys__/api/auth/logout`

| 项 | 内容 |
| --- | --- |
| 路径 | `POST /__aisys__/api/auth/logout` |
| 启用条件 | 仅在 `JUHE_AI_MANAGEMENT_API_ENABLED=true` 时注册；默认生产 server 不注册 |
| 登录态 | 不要求当前 session 仍有效；只解析 `juhe_ai_session` Cookie |
| 有 Cookie | 对 Cookie token 做 SHA-256，按 `system_sessions.token_hash` 删除当前 session |
| 无 Cookie | 不报错，直接按已登出处理 |
| 成功响应 | `200 { data: { loggedOut: true } }`，并清除 `juhe_ai_session` Cookie |
| 清 Cookie | Cookie 名称固定 `juhe_ai_session`，`Path=/`，`HttpOnly`，`Max-Age=0`；`Secure` / `SameSite` 完整运行时配置随后续登录 / Cookie 配置切片统一收口 |
| 撤销失败 | `500 { message: "服务器内部错误" }`，不清 Cookie，避免前端误判服务端 session 已撤销 |
| 副作用 | 只删除当前 token hash 命中的 session，不撤销同账号其他 session，不写 operation log，不写 Redis |

### `PATCH /__aisys__/api/system-accounts/{id}` reset-password 子动作

| 项 | 内容 |
| --- | --- |
| 路径 | `PATCH /__aisys__/api/system-accounts/{id}` |
| 启用条件 | 仅在 `JUHE_AI_MANAGEMENT_API_ENABLED=true` 时注册；默认生产 server 不注册 |
| 登录态 | 走管理端写鉴权 `ManagementAPIAuthTouchMiddleware`，读取 `juhe_ai_session`、校验 session 未过期、系统账户 active，并按 60 秒最小间隔 touch 当前 session |
| 权限 | 只允许 `super_admin`；普通 `admin` 和 `user` 返回 `403 { message: "需要超级管理员权限" }` |
| 请求体 | 严格 JSON object，只允许 `password: string` 和可选 `mustChangePassword: boolean`；`mustChangePassword:null`、字符串布尔值、`username` 以外的完整 PATCH 字段返回 `400 { message: "系统账户参数无效" }`；`username` 返回 `400 { message: "用户账户创建后不能修改" }`；尾随 JSON 返回 `400 { message: "请求体无效" }` |
| 密码规则 | 少于 4 个字符返回 `400 { message: "系统账户参数无效" }`；包含任意空白字符返回 `400 { message: "登录密码不能包含空格" }` |
| 密码 hash | Go 使用 Node 兼容 PBKDF2-SHA512 格式写入 `password_hash`；响应、operation log 和错误信息均不得回显明文密码或 hash |
| `mustChangePassword` | 请求未传时保留当前值；目标角色为 `admin` / `super_admin` 时有效值固定为 `false`，不会通过请求体设置为 true |
| PG 写入 | 使用 `w3_management_system_accounts.sql` 单条 CTE：锁定目标账户、更新 `password_hash` / `must_change_password` / `updated_at`、删除目标账户全部 `system_sessions` 并返回撤销数量；目标不存在返回 `404 { message: "系统账户不存在" }` |
| 成功响应 | `200 { data: { id, username, displayName, description, role, status, mustChangePassword, imageGenerationEnabled, lastLoginAt, createdAt, updatedAt } }`；不返回 `password_hash` |
| 操作日志 | best-effort 入队 `operation-log:write`，`operationKey=system_accounts.reset_password`、`module=system_accounts`、`action=reset_password`、`mode=admin`、`resourceType=system_account`、`viewer=admin_managed_my_resource`；`changes.password` 标记 `sensitive=true` 且 `after="已重置"`，不记录用户提交的密码 |
| 切片边界 | 这是通用 PATCH 路径下的 reset-password 子动作，仅用于灰度验证；如果请求混入 `status`、`displayName`、`role`、`description` 或 `imageGenerationEnabled` 等字段，Go 会直接拒绝。生产不能按 method/path 把整个 PATCH 切到 Go，除非完整 PATCH 契约全部迁移完成 |

### `PATCH /__aisys__/api/system-accounts/{id}` status-only 子动作

| 项 | 内容 |
| --- | --- |
| 路径 | `PATCH /__aisys__/api/system-accounts/{id}` |
| 启用条件 | 仅在 `JUHE_AI_MANAGEMENT_API_ENABLED=true` 时注册；默认生产 server 不注册 |
| 登录态 | 走管理端写鉴权 `ManagementAPIAuthTouchMiddleware`，读取 `juhe_ai_session`、校验 session 未过期、系统账户 active，并按 60 秒最小间隔 touch 当前 session |
| 权限 | 只允许 `super_admin`；普通 `admin` 和 `user` 返回 `403 { message: "需要超级管理员权限" }` |
| 请求体 | 严格 JSON object，只允许 `status: "active" | "disabled"`；`status:null`、未知状态、`password`、`mustChangePassword`、`displayName`、`description`、`role`、`imageGenerationEnabled` 等完整 PATCH 字段返回 `400 { message: "系统账户参数无效" }`；`username` 返回 `400 { message: "用户账户创建后不能修改" }`；尾随 JSON 返回 `400 { message: "请求体无效" }` |
| PG 写入 | 使用 `w3_management_system_accounts.sql` 单条 CTE：锁定当前启用 `super_admin` 集合和目标账户；如果目标是最后一个启用 `super_admin` 且请求状态不是 `active`，返回 `409 { message: "至少保留一个启用的超级管理员" }`；否则更新 `status` / `updated_at`，当请求状态为 `disabled` 时删除目标账户全部 `system_sessions` 并返回撤销数量；目标不存在返回 `404 { message: "系统账户不存在" }` |
| 成功响应 | `200 { data: { id, username, displayName, description, role, status, mustChangePassword, imageGenerationEnabled, lastLoginAt, createdAt, updatedAt } }`；不返回 `password_hash` |
| 操作日志 | best-effort 入队 `operation-log:write`，`operationKey=system_accounts.update`、`module=system_accounts`、`action=update`、`mode=admin`、`resourceType=system_account`、`viewer=admin_managed_my_resource`；只记录 `status` before / after 和 `revokedSessionCount`，不写密码字段 |
| 切片边界 | 这是通用 PATCH 路径下的 status-only 子动作，仅用于灰度验证；它尚未迁移 Node 状态变化后的 gateway cache invalidation / API Key validation cache 清理，不代表完整系统账户 PATCH、系统账户页生产切流或 Node `/system-accounts` 删除已完成 |

## 本轮不迁移范围

- 系统账户创建、完整更新、改密提醒、图像生成权限调整、默认资源 fanout；当前只迁移 `PATCH /system-accounts/{id}` 的 reset-password 与 status-only 子动作，不代表完整系统账户写接口已接管
- 登录生产接管、前端登录页 smoke、反向代理切流和 Node `/auth` 删除
- 完整会话管理、完整 Cookie 部署验收、gateway cache invalidation / API Key validation cache 清理、安全日志和完整系统账户写接口 operation log；Node 当前系统账户创建 / 重置密码日志可能记录明文密码，Go reset-password 子动作已修正为敏感字段脱敏，后续其他系统账户写接口也不能复刻明文日志
- 系统指标迁移不属于本 W3 登录小切片；本切片只保持 Go 指标规划链接，不新增或改写 `/stats/system-metrics`，也不把 Node event-loop / DB service / SQLite 文件指标模拟成 Go 指标

## Go 实现范围

- `managementauth.CaptchaService` 固定验证码发放、Redis state challenge、Redis `GETDEL` 一次性消费、答案归一化、60 次 / 分钟生成限流和 PNG data URL 输出；不引入额外 captcha 库，不退回进程内 Map。
- `managementauth.LoginService` 固定登录顺序：严格输入校验、验证码一次性消费、Redis 登录失败锁检查、active 账号密码校验、失败计数 / 锁定、成功清锁、PG session 创建和 `last_login_at` 更新；session token 只以 SHA-256 hash 落库，响应不返回 `passwordHash`。
- `managementauth.LoginGuardService` 使用 Redis state 做 IP / 用户名失败窗口和锁定，key 只保存 SHA-256 派生值，不落明文 IP 或用户名；失败计数和锁定通过 Redis Lua 原子完成，不退回进程内 Map。
- `managementauth.Authenticator` 保留受保护后台接口的初始密码 403 拦截，同时新增 current-user 读取分支，允许前端读取 `mustChangePassword` 状态；写鉴权分支复用同一 session 查询并按 60 秒最小间隔 touch `last_seen_at`。
- `managementauth.ProfileService` 只处理当前用户 `displayName` 更新，固定 no-op、空白字符、重复名和管理员有效 `mustChangePassword=false` 语义。
- `managementauth.PasswordService` 固定 Node 兼容 PBKDF2-SHA512 密码 hash / verify、初始密码用户免旧密码、普通改密校验旧密码、成功清除 `mustChangePassword` 和撤销其他 session 语义。
- `managementauth.Authenticator.LogoutCookie` 复用 Node 兼容 Cookie 解析和 SHA-256 token hash，只删除当前 session token；没有 Cookie 时直接成功。
- `managementsystemaccounts.Service.ResetPassword` 固定管理端 reset-password 子动作：只接收目标系统账户 ID、明文新密码和可选 `mustChangePassword`，在 service 层完成空白字符 / 长度校验和 Node 兼容 hash，不处理创建、完整更新或默认资源补齐。
- `managementsystemaccounts.Service.UpdateStatus` 固定管理端 status-only 子动作：只接收目标系统账户 ID 和 `active` / `disabled` 状态；非枚举状态直接返回参数错误，不做脏数据兜底；PostgreSQL CTE 负责并发锁定、最后一个启用 `super_admin` 保护、状态写入和禁用 session 删除；SQL guard 固定先 `MATERIALIZED` 锁定并聚合启用 `super_admin` 集合，再锁目标账户，避免并发停用不同超级管理员时退化成互锁或绕过保护。
- `httpapi.NewManagementCaptchaHandler` 不要求登录，按 `JUHE_AI_TRUST_PROXY` 解析客户端 IP，返回 Node 兼容 `{ data: { captchaId, image, expiresAt } }`，并把生成限流映射为 429 + `Retry-After`。
- `httpapi.NewManagementLoginHandler` 不要求已有 session，严格解析登录 JSON，按 `JUHE_AI_TRUST_PROXY` 解析客户端 IP，成功后签发 `juhe_ai_session` Cookie，并把登录参数、验证码、凭据和登录锁错误映射为 Node 兼容中文文案。
- `httpapi.NewManagementCurrentUserHandler` 直接调用 current-user 鉴权分支并返回当前用户摘要，不套用普通管理端 middleware。
- `httpapi.NewManagementProfileUpdateHandlerWithOperationLog` 走管理端写鉴权 middleware，严格解析 JSON，成功后返回当前用户摘要并 best-effort 写 `auth.update_profile` 操作日志。
- `httpapi.NewManagementPasswordChangeHandler` 直接调用 current-user 写鉴权分支，严格解析 `oldPassword` / `newPassword` JSON，成功后返回完整系统账户摘要；它不套用普通管理端 middleware，避免初始密码用户被提前拦截。
- `httpapi.NewManagementLogoutHandler` 直接调用 logout 分支；它不套用普通管理端 middleware，避免过期 session 或无 Cookie 时被提前拦截。
- `httpapi.NewManagementSystemAccountPatchHandlerWithOperationLog` 只实现 `PATCH /system-accounts/{id}` 的 reset-password 与 status-only 两个窄子动作，要求 `super_admin`，严格拒绝混合字段和完整 PATCH 字段；reset-password 成功后 best-effort 写脱敏 operation log，status-only 成功后 best-effort 写状态变更 operation log。
- `router.go` 在 `JUHE_AI_MANAGEMENT_API_ENABLED=true` 时注册 `GET /auth/captcha`、`POST /auth/login`、`GET /auth/me`、`PATCH /auth/me`、`POST /auth/change-password`、`POST /auth/logout` 和 `PATCH /system-accounts/{id}` 两个窄子动作；`PATCH /auth/me`、`PATCH /system-accounts/{id}` 与其他已迁移管理端写接口一样必须走 `ManagementAPIAuthTouchMiddleware`，router 会拒绝缺失 touch middleware 的写接口装配；`GET /auth/captcha` 明确跳过 system API IP 读限流，`POST /auth/login` 不加入写鉴权 touch middleware。
- `server.go` 复用同一个 `Authenticator` 注入 current-user、change-password 和 logout handler，并注入 Redis state captcha service、login guard、login service、profile / password service 与 operation log queue；默认关闭和启动依赖不变。
- integration smoke 在现有管理端 session 鉴权 smoke 中覆盖 `GET /auth/me` 当前用户响应且不 touch、`PATCH /auth/me` 真实 PG 更新 / operation log payload / stale session touch、`POST /auth/change-password` 真实 PG 密码 hash / 初始改密 / 普通改密 / fresh session touch 跳过 / stale session touch / 其他 session 撤销、`POST /auth/logout` 清 Cookie 和登出后旧 Cookie 401；reset-password 与 status-only 子动作目前已有 unit / handler / SQL guard 覆盖，真实 PG+Redis+operation-log integration 仍待后续补齐。

## 后续拆分建议

1. 系统账户写接口：下一步应继续拆 `POST /system-accounts` 创建、完整 `PATCH /system-accounts/{id}` 更新、`displayName` / `description` / `role` / `mustChangePassword` / `imageGenerationEnabled` 字段、默认资源 fanout 和 gateway cache invalidation；reset-password 子动作已覆盖密码 hash、目标 session 全量撤销和敏感日志脱敏，status-only 子动作已覆盖状态写入、禁用 session 删除和最后一个启用 `super_admin` 保护，但二者仍需要真实 PG+Redis integration 与前端 smoke。
2. 完整会话管理收口：后续完整 revoke 和 Cookie 安全部署验收迁移时，必须继续沿用“读不 touch、写按 60 秒窗口 touch、logout 不要求有效 session、login 是唯一 session 创建 owner”的规则。

## 接管与删除门禁

- `GET /auth/captcha`、`POST /auth/login`、`GET /auth/me`、`PATCH /auth/me`、`POST /auth/change-password`、`POST /auth/logout` 和 `PATCH /system-accounts/{id}` 的 reset-password / status-only 子动作只代表 W3 验证码、登录 / session 创建、当前用户读、资料更新、当前用户改密、当前会话撤销、系统账户管理端重置密码与状态更新小切片可灰度验证，不能删除 Node `/auth` 或 `/system-accounts` router。
- `POST /auth/login` 只证明验证码校验、Redis 登录失败锁定、active 账号密码校验、PG session 创建、`last_login_at` 更新和 Cookie 签发的小闭环；仍不能作为完整 `/auth` 接管证据。
- W3 必须等完整会话管理、完整系统账户写接口、gateway cache invalidation / API Key validation cache 清理、安全日志、真实 PG+Redis 验证、前端 auth / 系统账户管理页 smoke、生产单 owner 切流和 Node `/auth` / `/system-accounts` 删除证据全部完成后，才能进入 `待删除 Node`。
- 删除 Node 前必须确认前端登录页、初始密码修改页、头像菜单、系统账户管理页和权限拦截全部指向 Go 单 owner。
- 删除后使用 `rg "authRouter|requireSessionContext|system-accounts|findSessionByTokenAsync|createSessionAsync|revokeSessionAsync" backend/src` 检查旧入口，只允许未迁移历史文档引用。
