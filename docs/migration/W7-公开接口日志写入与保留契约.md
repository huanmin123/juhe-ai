# W7 公开接口日志写入与保留契约

> 状态：契约已冻结，生产 owner 仍为 Node。本记录只为后续 Go writer / retention 迁移提供边界，不执行切流，不允许双写，也不删除 Node。

## 1. 迁移目标

- 搬迁公开接口日志的业务语义、容量边界和可恢复性，不逐行复制 Node 的进程角色、IPC、本地数组队列或 Redis Stream consumer 循环。
- Go 使用已有 `public-api-log:write` Asynq task、`public-api-logs` queue、稳定日志 ID 和 PostgreSQL `ON CONFLICT(id) DO NOTHING` 形成至少一次投递下的幂等落库。
- 写入和保留清理接管前，Go 管理 reader 继续只读当前单 owner 产生的数据；任何环境都不能同时启用 Node / Go writer 写同一张表。
- 机器可读事实固定在 `backend-go/internal/modules/publicapilog/testdata/node_writer_contract.json`，跨运行时测试负责发现 Node、Go capture/job 和 reader 的契约漂移。

| 生产写入 owner | Node |

Node PostgreSQL 旧表仍使用 integer/text 物理类型，fresh Goose 使用 boolean/bigint/timestamptz。后续切流必须在停写窗口离线同步到当前 Goose schema；运行时代码不增加旧结构兼容，也不通过双写过渡。

## 3. 必须保持的写入契约

### 3.1 记录身份与投递

- 日志在跨进程或持久队列投递前必须拥有稳定 `id`；重试不得生成新 ID。
- Redis / Asynq 投递失败不能回落到进程内队列或另一套 IPC 后继续假装成功。失败要保留可观测错误和丢弃计数，由调用边界决定业务请求是否继续。
- 消费成功以 PostgreSQL 幂等写入完成为准；重复任务通过 `ON CONFLICT(id) DO NOTHING` 收敛。
- 非法 payload 是永久错误，不重试；存储或短暂依赖错误保留重试资格。
- shutdown 必须有有界 drain；不得因为日志积压无限阻塞业务进程退出。

Node 当前本地队列容量是压测和迁移比较基线：最多 5000 条、32 MiB，单批 50 条，shutdown 最多 100 批。它不是要求 Go 再实现一个相同数组队列。Go 应通过 Asynq queue concurrency、Redis 容量、任务 payload 上限、超时、重试和 lag 指标表达等价边界。

现有 Go 灰度任务固定 30 秒执行超时、24 小时任务结果保留和最多 10 次重试；Node PostgreSQL writer 单事务内每条 INSERT 最多 1000 行。这些值进入机器契约，后续可以基于压测调整，但调整时必须同步更新清单、验证和容量说明。

### 3.2 行字段

写入必须完整覆盖当前 27 列：来源 / Token 快照、method/path/query、client IP/user agent、status/success/duration、请求响应原始大小、捕获状态、两个 JSON payload、错误摘要和三个时间字段。来源或 Token 删除后历史快照仍保留，不增加外键回删。

`started_at` 是请求开始时间；`ended_at` 是完成或提前断开时间；`created_at` 默认等于 `ended_at`。客户端提前断开固定记为状态码 499、`success=false`、`errorCode=public_api_client_closed`。

### 3.3 payload 捕获

- 请求和响应各自最多 32 KiB JSON 捕获预算，最大深度 8、对象 / 数组最多 200 项、单字符串预览最多 4096 字节。
- 捕获状态只有 `complete`、`truncated`、`empty`、`dropped`。
- query/body/response 在预算内保留原值，不做字段名扫描、正则脱敏或 `[redacted]` 替换。
- headers 只允许 `contentType` 和 `contentLength`；`Authorization`、Cookie 和来源 Bearer token 不进入捕获 headers。
- `request_size_bytes` / `response_size_bytes` 表示原始大小，不是截断后 JSON 长度；截断记录必须保留原始大小和显式标记。
- Go flat query map 与 Express + qs extended parser 对 bracket / 畸形转义仍存在已知差异，未解决前不能宣称完整 query parity。

## 4. 保留清理契约

- 设置键为 `publicApiLogRetentionDays`，默认 30 天，合法范围 `1..365`。
- cutoff 使用当前时间减保留天数，删除条件固定为 `created_at < cutoff`；等于 cutoff 的记录不删除。
- 候选按 `created_at ASC, id ASC` 稳定选择，每批最多 1000 行，每轮最多 20 批；满批继续，非满批结束。
- 清理只由后台任务运行，不进入请求路径；单批失败不能把未删除记录计为成功。
- Go 接管时应使用单条有界 PostgreSQL 删除语句或等价事务，并支持并发 worker 的 `SKIP LOCKED` / 单实例租约。不得先把无界 ID 列表读入内存。

Node 当前 PostgreSQL repository 是“先选最多 1000 个 ID，再事务删除”。这是当前行为事实，但不是 Go 最终 SQL 形态；Go 应收敛为有界、稳定、并发安全的数据库原生实现。

## 5. Go reader 反向约束

- 列表最多展示 1000 条窗口，`pageSize` 最大 100，使用 lookahead，不执行 `COUNT(*)`。
- 列表固定 `created_at DESC, id DESC`，只选择摘要列，禁止读取 `request_data_json` / `response_data_json`。
- 详情按原始 ID、`LIMIT 1` 单行读取，才包含两个有界 JSON payload。
- writer 不得改变 capture status、时间类型或 JSON 对象形态而让 reader 增加兼容分支；schema / payload version 变化必须先更新契约、reader 和跨运行时测试。

## 6. Go-native 接管顺序

1. 在独立切片实现 Go retention repository / run-once worker，仍保持生产关闭。
2. 补真实 PostgreSQL 并发清理、cutoff 边界、失败重试和 reader 互操作测试。
3. 对最新 Node writer 执行一次契约复核；任何差异先判断是业务调整、Node 缺陷还是 Go 可简化实现，并记录原因。
4. 在停写窗口离线同步 Node 旧物理类型到 fresh Goose，核对行数、ID、时间、状态和 payload hash。
5. 只切换一个 writer owner，观察 queue lag、写失败、重复任务、日志增长和 reader 错误；准备明确回滚点。
6. writer 稳定后再切 retention owner，最后按减法清单删除 Node queue、writer、cleanup 和对应配置入口。
