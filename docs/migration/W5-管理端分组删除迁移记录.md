## 当前切片

本切片只包含：

- `DELETE /__aisys__/api/groups/{id}`
- `DELETE /__aisys__/api/my-groups/{id}`

两条路径只在 `JUHE_AI_MANAGEMENT_API_ENABLED=true` 且完整注入管理鉴权、PostgreSQL store、shared cache invalidator 和 gateway runtime invalidator 时注册。DELETE 没有业务 JSON body，不挂载写接口 JSON parser 或 mutation guard；仍使用写鉴权 touch、system API IP write limiter 和 authenticated user write limiter。全局 system API JSON transport 与 Node 的差异继续作为横向生产门禁处理，不能由本切片宣称已完成。

本切片不包含分组授权归还、前端生产入口切换、生产单 owner 切流或 Node 路由删除。授权成员放弃分组使用权仍调用独立的授权归还接口。

## 权限与错误边界

- `/groups/{id}` 只允许 `admin` / `super_admin`；省略 `systemAccountId` 或使用 `all` 时可按全局 owner 作用域删除，指定账户时只能删除该账户自有分组。
- `/my-groups/{id}` 强制当前 session 账户作用域，不接受 query 参数扩大作用域。
- 路径 `{id}` 保持原值查询，不做 trim。
- owner 可以删除自己的非默认分组；authorized grantee 不能删除来源分组，返回 `404`，避免泄露越权资源。
- 默认分组返回 `400`，不能删除。
- 路由策略保护失败返回 `400`；不存在、越权或授权成员删除均返回 `404`。
- 成功删除返回 `204 No Content`，不返回业务 JSON。

## 存储与并发边界

- 删除使用 PostgreSQL 单事务，先锁定 owner 分组，再锁定所有 owner / grantee 作用域中关联该分组的 active 路由策略。
- 路由策略查询固定 `LIMIT 101`；超过 100 条绑定时拒绝删除，避免请求路径无界读取。
- 只要任一 active 路由策略在删除该分组后没有其他可用分组，就拒绝删除；存在替代分组时允许删除。
- 账户绑定不阻止删除。`group_accounts`、`route_strategy_groups` 和 `group_authorization_settings` 依赖当前 fresh schema 外键级联清理。
- `resource_authorization_sources`、`resource_authorization_grants` 等多态授权历史不因分组删除而级联删除，保留既有授权关系历史。
- 删除为硬删除，不保留软删除分支。
- 删除成功后在同一事务写入 `group_account_stats_dirty`，reason=`group_deleted`。旧 `juhe_stats.group_account_stats` 行不在请求路径同步删除或重算，后续由统计 worker 按脏标记处理。
- 事务锁顺序固定为“目标分组 -> 关联路由策略”，删除判定在锁内完成，避免跨进程并发绕过唯一可用分组保护。

## 写后副作用

- 成功删除后 best-effort 递增 `lookup:group` shared cache version。
- 成功删除后 best-effort 递增 `lookup:group-account-ids` shared cache version。
- 成功删除后 best-effort 发布 gateway runtime reason=`group_deleted`。
- 成功请求 best-effort 写入 operation key=`groups.delete`；失败删除不产生日志。
- 操作日志只记录最多 20 个受影响路由策略 target / metadata，summary 最多列出 3 个策略，超出部分使用“另有 N 个策略路由受影响”收口。
- cache、runtime 和 operation log 均在数据库提交后执行，不把外部依赖失败伪装成数据库回滚。
