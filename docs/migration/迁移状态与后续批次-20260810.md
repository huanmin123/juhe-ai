# Node 到 Go 迁移状态与后续批次

> 更新时间：2026-08-10
> 本文是当前 `master` 的状态记录，不代表生产部署或切流通过。

## 当前结论

当前不是“整个 Node 后端已经迁到 Go”。已经完成或进入唯一 owner 接线的范围只有下面列出的完整功能；网关主流程、账户管理和其他业务写入仍由 Node 负责。

## 已迁移功能

### F1 运行日志索引与保留

- Go `juhe-ai-runtime-log-indexer` 是 JSONL 发现、解析、索引、cursor、facet 和保留清理的唯一写 owner。
- Node 继续产生日志文件，并通过只读查询提供运行日志管理接口；Node 不再写 F1 专库、不再调度 F1 retention。
- SQLite 使用独立事实库，Go 强制 `journal_mode=WAL`、`busy_timeout=5000` 和单 writer；PostgreSQL 写 `juhe_dataset`。
- 已有隔离开发 PostgreSQL、Node -> Go -> Node HTTP 读回和资源清理证据。该证据不等于生产部署通过。

### F2 表存储监控采样与保留

- Go `juhe-ai-table-monitor` 是采样、快照写入、owner lease/fence 和 retention 的唯一写 owner。
- Node 只保留 `/table-monitor` 查询；Node stats worker 不再调度、写入或清理 F2 快照。
- SQLite 输出库独立并启用 WAL/`busy_timeout=5000`；PostgreSQL 输出 `juhe_stats`。
- 已有隔离开发 PostgreSQL adapter smoke、采样读回和资源清理证据。生产 listener、发布包生命周期和 Mac launchd 现场仍未验收。

### F3 原始审计日志持久化与保留

当前 `master` 已完成主要代码接线，但在本记录发布时仍按“开发验收中”管理，不能把它描述成生产已接管：

- Go 已有独立 schema/store、owner lease/fence、`in_progress -> finalized` 幂等、attempt、payload refs/blobs、error groups、hot-search、retention 和离线旧 SQLite 迁移工具。
- Go sidecar 提供 loopback HMAC 一次性输入 RPC：`POST /__aiinternal__/v1/audit-captures`。Node capture 只负责归一化和非阻塞投递，不保留本地队列、Redis Stream、IPC fallback 或 Node writer。
- Node 读侧使用显式 F3 专库只读适配器；旧 dataset 审计 schema、旧 writer/queue/transport、旧 retention 和旧 db-service/read-worker 审计读取入口已退出活跃路径并归档。
- 已通过 Go 全包、race/vet、Node typecheck 及 F3 静态/SQLite/输入协议回归；2026-08-10 在一次性开发库 `juhe_ai_sub2api_dev_f3_smoke_20260810` 上完成真实 PostgreSQL foundation smoke，并在测试后删除临时库、复核主库未受影响。
- 已完成隔离 Node -> Go -> Node 闭环：应用经 PgBouncer `6432` 的真实 Node `dispatchAuditLogToGo` 先写入 `in_progress`，Node F3 只读适配器读回占位；sidecar 停止后 health 不可达，等待最小 `5s` owner lease 到期后同一 stable instance ID 重启接管；`finalized` 使用同 ID 覆盖占位，Node 读回 1 attempt、1 payload 及可用的 headers/body storage；无效 HMAC 返回 `401`。测试库、会话、PIDs、scratch/profile/log 与控制脚本已清理，主库、Redis、`shared.env` 和生产未触碰。当前只剩独立总审和后续发布/部署验收，仍不得描述为生产已接管。

## 尚未迁移的功能

以下功能仍由 Node 负责，不能因为 F1/F2/F3 的代码存在就推断已迁移：

- 网关请求调度、provider/OAuth、账户、API Key、分组、权限和主业务 HTTP API；
- 使用记录（usage records）、usage shard 写入、统计窗口和通用数据保留；
- 操作日志（operation logs）；
- 公开接口日志（public API logs）；
- 模型检测、后台探针、账号健康、系统任务和其他 Node worker 任务；
- 生产 listener、Mac/Docker 常驻生命周期、发布/回滚、代理和 Edge 切流。

## 后续迁移顺序

每一批都必须先冻结 Node -> Go 字段和失败语义，完成双模式 Store、输入/读取、retention、重启/停机、真实隔离 smoke、部署接线后，才能切换唯一 owner 并整体归档 Node 文件。不得长期保留双写或 fallback。

1. **F3 验收收口**：完成独立总审；发布包、Docker/Mac 常驻、listener、回滚和切流另列部署验证，不把开发闭环当作生产证据。
2. **F4 操作日志**：覆盖所有 `recordOperationLog*` producer、actor/viewer/targets/search terms、admin/self 读权限和 365 天 retention。业务事务不能因日志失败回滚；稳定 ID 和幂等写必须保留。
3. **F5 公开接口日志**：覆盖 finish/close/aborted exactly-once、bounded request/response snapshot、capture status、敏感 header 过滤、30 天 retention 和管理读契约。
4. **F6 使用记录与统计**：最后处理 pricing freeze、Redis Stream/ACK 或明确的新 handoff 语义、usage shard、统计游标与恢复；不能把 usage 直接改成无恢复源的裸 goroutine。

## 并发与队列边界

Go 侧不新增 Redis/Asynq/通用业务队列，也不设置人为的全局业务限速。这里的“直接异步”不等于无限并发：SQLite 文件级单 writer、PostgreSQL 连接池/事务锁、请求和写入超时、payload 4 MiB wire 预算、文件句柄和内存上限仍是必须保留的资源与正确性边界。超过边界必须显式失败或记录丢弃原因，禁止静默切回 Node。

## 生产文档边界

项目公共部署手册和 `.local/project-resources/prod/` 私有 Mac 手册只能记录已经在开发闭环中证实的 owner、配置和启动顺序。开发 smoke 不能写成生产通过；Mac `launchd --apply`、Docker 实启动、发布包生命周期、回滚、listener、Edge/Caddy/WireGuard 和切流必须在获得生产操作授权后单独验收。
