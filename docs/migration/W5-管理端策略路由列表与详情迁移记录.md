## 当前切片

本切片只包含四条只读接口：

- `GET /__aisys__/api/route-strategies`
- `GET /__aisys__/api/my-route-strategies`
- `GET /__aisys__/api/route-strategies/{id}`
- `GET /__aisys__/api/my-route-strategies/{id}`

本切片不包含：

- `POST`、`PATCH`、`DELETE` 策略路由写接口；
- API Key 绑定修改；
- 分组写入、授权写入或网关运行态失效；
- 前端生产入口切换；
- 反向代理单 owner 切流；
- Node 路由、repository、类型或回归测试删除。

Go 路由必须继续受 `JUHE_AI_MANAGEMENT_API_ENABLED` opt-in 保护。默认关闭时不得注册这些迁移路径；显式开启只用于灰度、测试或受控联调。

## 权限与作用域

四条接口都必须登录，并走管理 API 只读鉴权、鉴权前 IP read limiter、鉴权后已认证用户 read limiter。GET 不更新 session 活跃时间，响应使用 `Cache-Control: no-store`；内部依赖错误返回通用 `500`，不能泄露 PostgreSQL、SQL 或配置内容。

管理侧：

- `/route-strategies` 与 `/route-strategies/{id}` 只允许 `admin` / `super_admin`。
- 未传 `systemAccountId` 或传 `all` 时使用管理员全局作用域。
- 传具体 `systemAccountId` 时收窄到该 owner。
- 管理侧列表和详情可以返回 `systemAccountId`、`systemAccountName`。
- 指定 owner 后不可见或不存在的详情统一返回 `404 { "message": "策略路由不存在" }`。

个人侧：

- `/my-route-strategies` 与 `/my-route-strategies/{id}` 对所有已登录用户开放。
- 后端强制使用当前 session 的系统账户 ID。
- query 中伪造的 `systemAccountId` 不得改变作用域；管理员在用户模式调用时也只能读取自己。
- 个人侧列表和详情不得返回 `systemAccountId`、`systemAccountName`。
- 不属于当前用户或不存在的详情统一返回 `404 { "message": "策略路由不存在" }`。

## 列表查询契约

列表读取以下查询参数：

- `page`
- `pageSize`
- `keyword`
- `mode`
- `status`
- 管理侧可选 `systemAccountId`

分页规则：

- `page` 默认 `1`，小于 `1` 时归一为 `1`。
- `page` 无最大页限制，也不按固定窗口把深页截回前面的页。
- `pageSize` 默认 `50`，范围 `1..200`，超出范围时钳制到边界。
- 无法解析为有限整数的 `page` / `pageSize` 按未传处理。
- 主查询固定读取 `pageSize + 1` 行，不执行精确 `COUNT(*)`。
- `hasMore = rows.length > pageSize`。
- `total = (page - 1) * pageSize + items.length + (hasMore ? 1 : 0)`。
- `total` 是渐进上界，不是精确总数；前端不得用它推断全量记录已统计完成。

筛选规则：

- `keyword` trim 后只匹配策略路由 `name` 的大小写敏感字面前缀。
- `keyword` 不搜索 `description`，`%`、`_` 等字符按字面量处理，不获得 SQL 通配符语义。
- `mode` 只识别 `normal`、`hybrid_smart`、`weighted`、`failover`、`round_robin` 和 `all`。
- `status` 只识别 `active`、`disabled` 和 `all`。
- `mode` / `status` 为 `all` 或非法值时忽略该筛选，不返回 `400`。

稳定排序固定为：

```text
updated_at DESC, created_at DESC, id DESC
```

## 列表轻量 DTO

列表顶层保持：

```json
{
  "data": {
    "items": [],
    "total": 0,
    "hasMore": false,
    "page": 1,
    "pageSize": 50
  }
}
```

列表项包含：

- `id`
- 管理侧可见的 `systemAccountId/systemAccountName`
- `name/description/mode/status/isDefault`
- `normal` 模式的规范化 `normalRoutingConfig`
- `groupBindingPreview`
- `bindingCount`
- `apiKeyCount`
- `createdAt/updatedAt`

轻量边界：

- `groupBindingPreview` 最多返回 3 条，保留 `id/groupId/groupName/providerCode/status/groupEnabled`。
- `bindingCount` 返回完整绑定数量，不能用 preview 长度代替。
- `apiKeyCount` 返回当前 owner 下绑定该策略的 API Key 数量。
- `normal` 模式列表返回规范化后的 `normalRoutingConfig`；缺省配置按 `cost_first` 默认值回填。
- 列表不返回完整 `groupBindings`。
- 列表不返回 `hybridRoutingConfig`，也不返回其他模式的完整配置。
- 列表不得为了组装预览逐条查询；应先裁掉 lookahead 行，再按当前页策略 ID 批量读取最多 3 条绑定预览和两个计数。

## 详情完整 DTO

详情按路径 `{id}` 精确读取单条可见策略，返回完整 `RouteStrategySummary`：

- 基础字段与管理侧 owner 摘要；
- `normal` 模式的完整规范化 `normalRoutingConfig`；
- `hybrid_smart` 模式的完整规范化 `hybridRoutingConfig`；
- 完整 `groupBindings`，包含 `id/groupId/groupName/providerCode/priority/weight/status/groupEnabled`；
- `apiKeyCount`；
- `createdAt/updatedAt`。

完整绑定排序必须与 Node 保持一致：

```text
active 优先,
priority ASC,
binding.created_at ASC,
binding.id ASC
```

详情不能复用列表 preview 代替完整 bindings。配置 JSON 损坏或结构不符合当前模型时必须显式失败，不能静默回退为空配置或伪造默认 hybrid 配置。

## 存储与性能边界

- 列表主查询只读取当前页基础行和 `pageSize + 1` lookahead。
- 绑定预览、绑定总数和 API Key 总数按当前页策略 ID 批量读取，禁止 N+1。
- 详情只读取单条策略及其完整绑定，不扫描使用记录、审计日志或网关运行态。
- 列表和详情不执行使用量、额度、趋势、TopN 或其他业务统计聚合。
- owner 条件必须同时约束策略、绑定和 API Key 计数，避免相同 ID 或错误关联造成跨 owner 数据泄露。
- 名称前缀在 PostgreSQL 下保持与 Node 一致的大小写敏感 C 排序语义，不能改成 `ILIKE` 或默认大小写不敏感搜索。
- 读路径不得补建默认路由策略，也不得产生写副作用。

## 验收矩阵

- 未登录 `401`，普通用户访问管理侧 `403`。
- admin 全局列表 / 详情与指定 owner narrowing。
- self 强制当前账户，伪造 `systemAccountId` 不越权。
- 管理 DTO 返回 owner 字段，个人 DTO 隐藏 owner 字段。
- `page=1`、默认 `pageSize=50`、`pageSize` 的 `1..200` 边界、非法整数和深页不截断。
- `pageSize + 1`、`hasMore` 和 progressive `total` 公式。
- 名称大小写敏感字面前缀，说明字段不参与搜索，`%/_` 不作为通配符。
- 五种合法 mode、两种合法 status、`all` 和非法值忽略。
- `updated_at DESC, created_at DESC, id DESC` 稳定排序。
- lookahead 行不参与 preview / count enrichment。
- 列表 preview 不超过 3 条，`bindingCount/apiKeyCount` 为完整计数。
- normal 列表配置存在，hybrid 完整配置不进入列表。
- 详情返回完整 bindings 和对应模式完整配置。
- 不存在、owner 不匹配或 self 越权详情统一 404。
- SQL / store guard 证明无 N+1、无明细扫描、无读路径写副作用。
- `plan0081-real-go-management-smoke` 已纳入管理侧策略列表和选中详情回读：允许通过 `JUHE_REAL_GO_MANAGEMENT_ROUTE_STRATEGY_ID` 固定目标；未指定时选择首条，空列表只跳过详情；列表严格检查 progressive 分页、最多 3 条 preview、完整 `bindingCount/apiKeyCount` 和配置字段边界，详情检查完整 bindings 及列表 / 详情一致性；摘要只输出计数和是否完成详情检查，不输出策略 ID、名称、owner 或配置。

## 真实依赖门禁

以下证据全部满足前，不得声明生产接管：

1. 健康 Docker/testcontainers 或独立测试环境中，fresh migrations、真实 PostgreSQL 和真实 Go HTTP 四条路由 smoke 通过。
2. smoke 覆盖真实管理 session、read limiter、admin/self 权限、owner 字段显隐、列表筛选分页、preview/count 和详情完整配置。
3. `SKIP`、仅 integration 包编译、mock store 或单元测试通过都不能记为真实依赖通过。
4. Node 契约对照回归通过，至少包含 `test:route-strategy-list-query-guard` 和管理权限 / scope 回归。
5. 前端策略路由列表、筛选、编辑详情回填连接真实 Go 后端完成 smoke。
6. 反向代理按这四条路径完成 Go 单 owner 切流，并验证停止 Go 后可回退 Node。
7. 生产观测确认错误率、延迟、连接池和深页查询边界符合要求。
8. 对应 Node 路由、repository 分支、类型和回归测试删除后提供 `rg` 静态证据，并同步最终部署与回滚文档。
