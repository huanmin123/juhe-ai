# Go 迁移测试与验收策略

## 1. 测试目标

迁移测试不是只证明 Go 代码能跑，而是证明没有漏功能、少逻辑、改错权限、破坏统计口径或丢失网关行为。

每个模块都要先固定当前行为，再迁移实现，最后删除旧实现。短期 Node vs Go 对比只能作为测试手段，不能变成长期运行架构。

## 2. 测试层级

| 层级 | 目标 | 示例 |
| --- | --- | --- |
| 单元测试 | 验证纯业务规则、校验、映射和错误语义 | DTO 校验、调度评分、脱敏、模型映射 |
| Store 测试 | 验证 PostgreSQL + Redis 单模式的当前 schema 行为 | 新库初始化、事务、唯一约束、分页排序、Redis TTL、Asynq 队列重试 |
| API 契约测试 | 验证 HTTP 入参、出参、状态码、错误结构、权限和中文文案 | 登录、列表、详情、创建、删除、公开接口 |
| 前端联调测试 | 验证现有 Vue 页面调用 Go API 不缺字段 | 表格、表单、options、空态、错误提示 |
| Worker 测试 | 验证后台任务游标、队列上限、重试、租约和幂等 | 使用记录写入、统计聚合、审计入队、账号测试 |
| 网关测试 | 验证真实中转协议、SSE、调度、重试和副作用 | mock AI、真实上游、取消、backpressure、usage |
| 性能测试 | 验证迁移收益和容量边界 | 管理读接口压测、网关并发、CPU/memory/pprof |
| 删除验证 | 验证 Node 旧实现已清除 | `rg` 旧 route、旧 service、旧测试命令 |

## 3. 单模块验收门禁

每个模块迁移至少覆盖：

- 成功路径：正常创建、读取、更新、删除、触发任务或转发请求。
- 权限路径：未登录、普通用户、管理员、资源所有者、被授权用户。
- 非法输入：缺字段、类型错误、越界、重复、非法状态、非法 scope。
- 空数据：空列表、空详情、空 options、未配置系统设置。
- 错误语义：HTTP 状态、错误码、中文文案、敏感信息脱敏。
- 数据边界：稳定排序、分页、cursor/window、事务、唯一约束和索引路径。
- 存储边界：已迁移模块只能走 PostgreSQL + Redis，不能保留 SQLite runtime、standalone 配置或双模式分支。
- 删除证据：旧 Node 入口、旧测试命令和旧引用已清理。

## 4. 契约固定方式

迁移前为当前 Node 行为建立契约：

- 对 HTTP API 保存请求 fixture、响应字段清单、状态码和错误结构。
- 对存储行为保存 PostgreSQL 初始化 schema、seed 默认值、关键查询、Redis state/cache/queue 和边界数据。
- 对 worker 保存输入队列、游标推进、失败重试和结果表变化。
- 对网关保存 mock upstream 请求、响应、SSE 事件、usage、审计和账号副作用。

契约固定不代表保留旧内部实现。若迁移时确认旧行为本身不合理，可以按当前最优方案调整，但必须更新功能文档、计划和测试预期。

## 5. Go 默认验证命令

后续 Go 代码落地后，默认验证命令按 PowerShell 7 书写：

```powershell
go test ./...
go test ./... -race
go test ./... -run TestName
go test ./... -bench . -benchmem
go vet ./...
```

测试分层命令边界：

| 类型 | 命令形态 | 依赖 | 规则 |
| --- | --- | --- | --- |
| 单元 | `go test ./...` | 无外部服务 | 不得隐式依赖 PostgreSQL / Redis / 真实上游 |
| Race | `go test ./... -race` | 无外部服务或本地 mock | 迁移期默认门禁；发现 data race 不允许降级跳过 |
| 集成 | `go test -tags=integration ./...` | PostgreSQL + Redis | 必须显式读取测试 env，缺少依赖时失败或标记未执行，不能静默跳过关键断言 |
| 网关 E2E | `go test -tags=gateway_e2e ./...` | mock upstream，可选真实凭据 | mock 为必跑；真实上游按凭据可用性记录覆盖范围 |
| 性能 | `go test -run '^$' -bench . -benchmem` 或专项压测命令 | PG/Redis、mock upstream | 产物写入 `reports/`，人工报告写入 `docs/reports/` |

现有前端仍需要保留：

```powershell
pnpm --filter juhe-ai-frontend typecheck
pnpm --filter juhe-ai-frontend build
```

迁移完成前，涉及未迁移 Node 后端的相邻回归仍按现有 `pnpm test:*` 执行。对应模块由 Go 接管后，必须删除或替换该模块的 Node 测试命令。

## 5.1 波次验收矩阵

| 波次 | 必跑项 | 通过标准 | 删除验证 |
| --- | --- | --- | --- |
| W0 Go 与 PG/Redis 基线 | `go test ./...`、`go test ./... -race`、PG schema / seed smoke、Redis cache/state、Asynq queue smoke | 新库初始化、Redis 隔离、Asynq enqueue / consume / retry / dead 基础断言通过 | Go 代码无 SQLite driver、SQLite env、standalone / performance 分支 |
| W1-W2 公开和只读接口 | API 契约测试、权限测试、前端 smoke | 字段、错误结构、中文文案、分页、敏感字段脱敏一致 | Node 对应 route/service/test 命令删除 |
| W3-W5 管理写接口 | CRUD、权限矩阵、事务回滚、审计/操作日志副作用 | 当前公开契约等价或文档已更新 | Node 对应写路径和 SQLite repository 分支删除 |
| W6 记录和统计读 API | cursor/window、范围查询、无实时扫描、PG 分区窗口 | 不全表扫描，不读旧 usage shard | Node 记录读路径、usage shard 读取入口删除 |
| W7 worker | Asynq task queue、游标、租约、重试、dead / archived、shutdown drain | 重启可恢复未完成任务，重复投递幂等，queue depth / retry / dead 可观测 | Node worker、IPC 队列、临时维护 worker 删除 |
| W8 storage 删除收尾 | 静态搜索、发布包检查、PG/Redis smoke | 无 SQLite runtime、env、schema、usage shard 写入 | DB service、SQLite schema、双模式测试命令删除 |
| W9 网关准备层 | Go 读模型压力测试、缓存失效、配额、候选过滤 | 不接管真实网关，不删除 Node preflight | 无删除；只记录契约和压测产物 |
| W10 真实网关 | mock 全矩阵、响应检查、错误兜底、side effects、慢客户端、真实 smoke、性能压测 | 首字、SSE、backpressure、取消、usage/audit/统计副作用全部通过 | Node gateway 主链路、preflight、协议 adapter、响应检查旧实现删除 |
| W11 发布收尾 | 发布包、Docker、systemd/Windows/launchd、备份恢复、回滚 smoke | 新安装可启动，PG/Redis 连接和 worker 正常，回滚步骤可执行 | Node 后端依赖、dist、启动脚本、SQLite env、旧部署文档删除或改写 |

## 6. 网关专项测试矩阵

真实网关迁移必须单独验收：

| 场景 | 必测内容 |
| --- | --- |
| OpenAI Chat JSON / SSE | raw body、模型、stream、usage、错误结构、上游 header 过滤 |
| OpenAI Responses JSON / SSE | Codex profile、Responses 事件、usage、失败事件、上下文恢复边界 |
| Anthropic Messages | native messages、OpenAI bridge、SSE 语义帧、错误转换 |
| Gemini native | generateContent、streamGenerateContent、目标协议桥接边界 |
| Hybrid | 模型映射、目标协议、不可保真能力处理、审计记录 |
| 调度 | API Key -> 路由策略 -> 分组 -> 账号 -> 供应商 / 协议能力 |
| 失败恢复 | 非 2xx、SSE 内失败、首字超时、账号屏蔽、后续账号切换 |
| 取消与反压 | 客户端断开、`ResponseWriter` flush、慢客户端、上游 cancel |
| 副作用 | usage、audit、账号状态、代理桶、运行日志、统计入队 |

额外阻断项：

- 入口路径：`/__aisys__/*`、`/__aipublic__/*`、根路径和 `/v1/*` 不能互相抢路由。
- Body：认证前可拒绝路径不得读取大 body；raw body、文本 lane 和图像 lane 上限继承当前契约。
- Header：上游危险 header、`content-length` / `content-encoding`、压缩响应解码和下游 header 过滤必须有断言。
- 响应检查：Chat / Responses JSON / SSE 污染、畸形 SSE、Codex compact、普通客户端不可见 Codex 专用错误码必须覆盖。
- 协议桥接：允许 / 禁止方向、endpoint mode、工具、图像、usage、bad SSE 和 guidance 都必须走 mock 矩阵。
- 灰度：W10 必须给出 canary 入口、失败阈值、快速停止和回退步骤。

## 7. 性能与内存验收

- 管理接口迁移后，必须对高频列表和 options 做并发读压测，确认没有全表扫描和无界内存增长。
- worker 迁移后，必须验证游标推进、批量窗口、队列容量和重试不会压垮请求路径。
- 网关迁移后，必须生成独立报告放入 `docs/reports/`，至少包含并发、首字时间、SSE 稳定性、CPU、内存、goroutine 数量、GC、数据库连接池和上游连接池观察。
- 长时间压测要检查 goroutine 泄漏、body 未关闭、timer 未释放、channel 未关闭和缓存无界增长。
- pprof、runtime metrics 和结构化日志必须能定位热点。
- 性能报告必须给出当前 Node 基线或最近可用报告作为对比，至少记录管理读 P95 / P99、网关首字、SSE 完成率、worker lag、PG/Redis 延迟、CPU、内存、goroutine、GC 和文件描述符。

## 8. 不通过处理

测试失败时不允许用长期兼容分支掩盖问题。处理顺序：

1. 判断是 Go 实现偏离当前契约，还是当前契约应按当前最优方案调整。
2. 如果是实现问题，修 Go 代码并补回归。
3. 如果是契约调整，先更新功能文档和计划，再更新测试预期。
4. 如果涉及旧数据，只记录离线处理方案，不写入运行路径。
5. 如果模块无法删除 Node 旧实现，状态保持 `阻塞` 或 `待删除 Node`，不能标记 `已接管`。
6. 如果模块仍依赖 SQLite runtime 或双模式分支，状态最多只能到 `待删除 Node`，不能标记 `已接管`。
