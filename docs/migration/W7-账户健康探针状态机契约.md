# W7 账户健康探针状态机契约

> 归属：PLAN-0081 W7。状态：契约固定，Go worker 接线 / 真实依赖验收仍进行中。

## 目标与边界

本记录冻结 Node 当前账户健康检查、冷却复测和自动探针结果的可观察规则，供 Go 原生 worker 复用。实现不逐行搬运 Node 的 retry queue、IPC 或 DB service；Go 以有类型的纯判断函数表达状态机，队列、HTTP 探针、PostgreSQL 事务和运行态发布继续由各自 owner 实现。

本记录不把人工账户测试变成健康状态 writer，也不把周期健康检查与冷却复测合并：前者处理 `active` / `pending_test`，后者只恢复 `temporary_unavailable` / `rate_limited`。

正常账户周期健康检查默认使用 1 小时基础间隔，并按账户 ID 在 0 到 10 分钟内稳定错峰。`000080_w7_account_health_check_hourly_defaults.sql` 只把仍保持旧默认组合 `12 小时 + 120 分钟` 的设置更新为新默认；其他自定义组合保持不变。迁移同时把这些作用域内已有正常账户的远期计划收敛到新窗口，已过期账户按哈希分散到未来 10 分钟内，不在迁移时集中触发。

## 证据规则

1. 自动探针成功始终为 `complete_success`。
2. 自动探针已完整收到并完成协议 framing、但诊断业务结果失败时为 `framing_complete_neutral`；它不能被当作上游 transport failure 或账户状态写入证据。
3. 自动探针失败只有同时满足“真实 HTTP(S) 上游 URL”和“已收到上游响应头”，且不属于上述 framing neutral 时才是 `upstream_failure`，可交给账户状态 writer。
4. 本地合成错误、URL 非 HTTP(S)、拨号失败、超时或未收到响应头是 `probe_task_failure`，不得增加账户冷却失败次数、延长观察期或将账户推进到 `error`。
4. `accountFailureEligible` 不是账户状态写入证据；Go 不保留这个会混淆任务失败与账户失败的布尔门。

- `backend/src/modules/gateway/upstream/attempt.ts`

## 候选与并发护栏

| 场景 | 可运行候选 | 任务陈旧条件 | 结果动作 |
| --- | --- | --- | --- |
| 周期健康检查 | 已绑定分组的 `active`（必须 `schedulable`）或 `pending_test`；未到期且 `next_health_check_at` 已到 | 配置版本变化或重新读取后不再符合资格 | 由健康检查 result sink 写入对应激活 / 诊断结果 |
| 冷却复测 | `temporary_unavailable` / `rate_limited`、`schedulable=true`、已绑定分组、`cooldown_until <= now`、未到期 | `config_revision` 或 `cooldown_retest_observation_started_at` 与入队快照不一致 | 成功恢复；任务失败短暂 defer；可归因上游失败交给退避 / 观察期事务 |
| 网关质量确认 | 已绑定、可调度且有效的 `active` 账户 | 运行态事件 generation 已变化或账户资格变化 | 成功不改健康事实；仅可归因失败才可标记 `temporary_unavailable` |

冷却复测的三种持久化动作固定为：

- `complete_success`：恢复为 `active`、恢复调度并清理冷却 / 本轮失败诊断。
- `probe_task_failure`：保留现有状态，仅短暂 defer，默认 10 秒。
- `upstream_failure`：由 PostgreSQL outcome store 在同一状态机中更新退避、长期复测或终态 `error`；不要在 worker 内重算或复制该 SQL 逻辑。

恢复探活固定使用账户自己的 `health_check_model` 和 `health_check_endpoint_mode`，写入 `traffic_source = cooldown_retest`。此类明细和审计保留，但不进入业务用量、授权消耗或账户质量统计。

## Go 落点

- `backend-go/internal/accounthealth/contract.go`：纯状态机类型与函数，无数据库、队列、HTTP 或全局时钟依赖。
- `backend-go/internal/accounthealth/contract_test.go`：Node 等价反例，包括本地合成 URL、无响应头、到期边界、陈旧 generation 和 action 映射。
- 既有 `internal/modules/accounthealthcheck` 与 `internal/modules/cooldownaccountretest` 保留 runner / scheduler owner；后续接线时应调用本包，而不是再复制候选或 outcome 判断。

## Go 化调整及原因

| Node 原理 | Go 方式 | 原因 |
| --- | --- | --- |
| `success + upstreamResponseObserved` 临时布尔组合 | `ProbeEvidence -> ProbeOutcome` 有类型分类 | 调用者不能把任务错误当作账户错误写入。 |
| service 内局部 eligibility 函数 | 注入 `now` 的无副作用判断 | 可直接单测边界，不依赖系统时间或任务 runner。 |
| 队列项用多个散落字段防陈旧 | `RetestTaskVersion` 原子比较 | 配置更新和新一轮观察都能明确使旧任务失效。 |

## 迁移与验收门禁

- 当前仅代表 W7 契约固定，不代表 Node worker、internal health bridge、`JUHE_AI_NODE_INTERNAL_*`、DB service 或 Node IPC 可以删除。
- Go worker 实现必须保持候选读取、任务幂等、状态写入与运行态发布的单一 owner，并补真实 PostgreSQL / Redis / Asynq / 上游 mock 验收。
- 第三轮统一验收须覆盖：本地任务故障不改变账户状态、真实响应失败的退避和长期窗口、成功恢复、配置改动后的旧任务丢弃、`cooldown_retest` 统计排除、owner manifest、切流和回滚。
