# W7 账户健康探针状态机契约

> 归属：PLAN-0081 W7。状态：W7a 五元 fence、授权 quota 候选过滤、Go 候选 / 任务版本契约与 schema 91 已对齐；W7b 已补原生十模式 Probe、API Key/OAuth 凭据准备、URL/DNS/代理策略、发送前撤销栅栏、PostgreSQL outcome adapter 和默认关闭的生产构造。真实依赖验收、job owner handoff 和生产切换仍未完成。

## 目标与边界

本记录冻结 Node 当前账户健康检查、冷却复测和自动探针结果的可观察规则，供 Go 原生 worker 复用。实现不逐行搬运 Node 的 retry queue、IPC 或 DB service；Go 以有类型的纯判断函数表达状态机，队列、HTTP 探针、PostgreSQL 事务和运行态发布继续由各自 owner 实现。

本记录不把人工账户测试变成健康状态 writer，也不把周期健康检查与冷却复测合并：前者处理 `active` / `pending_test`，后者只恢复 `temporary_unavailable` / `rate_limited`。

正常账户周期健康检查默认使用 1 小时基础间隔，并按全局被动调度策略在每轮重新偏移。`000080_w7_account_health_check_hourly_defaults.sql` 只把仍保持旧默认组合 `12 小时 + 120 分钟` 的设置更新为新默认；其他自定义组合保持不变。迁移同时把这些作用域内已有正常账户的远期计划收敛到新窗口，已过期账户按全局被动策略分散，不在迁移时集中触发。

## 证据规则

1. 自动探针成功始终为 `complete_success`。
2. 自动探针已完整收到并完成协议 framing、但诊断业务结果失败时为 `framing_complete_neutral`；它不能被当作上游 transport failure 或账户状态写入证据。
3. 自动探针已创建真实 HTTP(S) 上游 attempt，且 typed transport evidence 明确为 `timeout`、`connection` 或 `read` 未完成时是 `upstream_failure`；此类失败不以“已收到响应头”为前提，可交给账户状态 writer。
4. 本地合成错误、URL 非 HTTP(S)、没有真实 attempt、取消、executor 故障或互相矛盾 / 非法的 transport evidence 是 `probe_task_failure`，不得增加账户冷却失败次数、延长观察期或将账户推进到 `error`。
5. `accountFailureEligible` 不是账户状态写入证据；Go 不保留这个会混淆任务失败与账户失败的布尔门。

## 候选与并发护栏

| 场景 | 可运行候选 | 任务陈旧条件 | 结果动作 |
| --- | --- | --- | --- |
| 周期健康检查 | 已绑定分组的 `active`（必须 `schedulable`）或 `pending_test`；未到期且 `next_health_check_at` 已到；`active + images_json` 不进入周期候选 | 配置版本变化或重新读取后不再符合资格 | 由健康检查 result sink 写入对应激活 / 诊断结果 |
| 冷却复测 | `temporary_unavailable` / `rate_limited`、`schedulable=true`、已绑定分组、`cooldown_until <= now`、未到期；授权实例还要求授权、物理来源账户继续有效且 direct / team quota 均未耗尽 | 五元 fence 任一分量不一致，或重新读取后不再符合资格 | 成功恢复；任务故障 / framing neutral 做中性 defer；可归因上游失败交给退避 / 观察期事务 |
| 网关质量确认 | 已绑定、可调度且有效的 `active` 账户 | 运行态事件 generation 已变化或账户资格变化 | 成功不改健康事实；仅可归因失败才可标记 `temporary_unavailable` |

### 五元 fence 与 generation

冷却复测的入队去重、执行前复读以及成功 / defer / 失败三类 outcome 必须使用同一组五元 fence，不允许降级为只比较配置版本或观察起点：

| 分量 | 语义 |
| --- | --- |
| `config_revision` | 当前复测目标账户的配置代次。 |
| `dispatch_revision` | 当前复测目标账户的调度语义代次；状态、授权实例或绑定语义变化必须使旧任务失效。 |
| `cooldown_retest_observation_started_at` | 本轮连续恢复观察窗口起点。 |
| `cooldown_retest_generation` | 本轮冷却复测 incarnation 的非空 opaque generation；相同观察时间也不能复用旧代次。 |
| source `config_revision` | 仅授权实例携带其物理来源账户的配置代次；自有账户必须保持为空，不能把两类身份混用。 |

`000090_w7_cooldown_retest_generation.sql` 只为 Goose PostgreSQL schema 增加 nullable `cooldown_retest_generation text`，不批量伪造 generation。连续 migration `000091_w7_cooldown_retest_candidate_order.sql` 用与 Node ECMAScript `trim()` 相同的显式空白集合收紧 CHECK，要求非空且已 canonical，并接管全局 keyset due scan 的 partial index。旧行继续保持 `NULL`，由仍拥有该状态机的权威 runtime 在受 fence 保护的 repair / 新观察代次路径中分配；缺少合法 generation 或含首尾 ECMAScript 空白的候选必须 fail closed，不能直接投递。

Asynq payload v3 只编码五元 fence，`maxPauseMinutes` / `maxRecoveryHours` 策略快照放入持久 task headers；Asynq 的 unique digest 不包含 headers，因此同一 fence 即使策略值变化也会在 4 小时 lease 内跨进程去重。该 lease 只按队列持续运行、最多 100 个任务和 3 个消费者的理论执行 / 重试预算设置，并不是无界 exactly-once：Redis 或 consumer 停机超过 4 小时后仍可能再次入队。生产切换前必须用真实队列积压 / 时延证明生命周期，并增加覆盖长停机的 durable intent / lifecycle lock；所有 outcome 仍必须执行五元 CAS。

授权候选在并发 enqueue 前批量读取 direct authorization、有效 team grant 与五类预聚合成本；owner 直接放行，authorized 的任一小时 / 日 / 周 / 月 / 总额度耗尽即拒绝。授权事实、limits、成本 key、时区或依赖缺失均 fail closed，且不得退化为逐账户 N+1 查询。

冷却复测的三种持久化动作固定为：

- `complete_success`：恢复为 `active`、恢复调度并清理冷却 / 本轮失败诊断。
- `probe_task_failure` 或 `framing_complete_neutral`：保留现有状态和失败计数，仅执行中性 defer。延迟从 30 秒基线开始，按本 observation generation 已经历窗口指数增长，使用全局被动策略每轮重新施加有界偏移，最短 3 秒、最长 15 分钟；不能退回固定 10 秒轮询。
- `upstream_failure`：由 PostgreSQL outcome store 在同一状态机中更新退避、长期复测或终态 `error`；不要在 worker 内重算或复制该 SQL 逻辑。

恢复探活固定使用账户自己的 `health_check_model` 和 `health_check_endpoint_mode`，写入 `traffic_source = cooldown_retest`。此类明细和审计保留，但不进入业务用量、授权消耗或账户质量统计。

## Go 落点

- `backend-go/internal/accounthealth/contract.go`：纯状态机类型与函数，无数据库、队列、HTTP 或全局时钟依赖。
- `backend-go/internal/accounthealth/contract_test.go`：Node 等价反例，包括本地合成 URL、无响应头、到期边界、陈旧 generation 和 action 映射。
- `backend-go/internal/store/port/cooldown_account_retest.go` 与 `internal/store/postgres/cooldownaccountretest*.go`：候选、Asynq task 和 PostgreSQL 读取已携带五元 fence；outcome adapter 以账户行锁、锁后数据库时间、五元 CAS、dispatch revision outbox 和 family 有界批量更新实现 success / defer / failure，但尚未形成跨授权、绑定和账户 writer 的提交级 lease。
- `backend-go/internal/modules/cooldownaccountretest/quota.go` 与 `internal/store/postgres/cooldownaccountretest_quota.go`：批量 direct / team quota eligibility；缺失或异常证据拒绝调度。
- `backend-go/internal/modules/accountprobe`：按精确候选复读、水合和模型能力检查构造十种 endpoint mode 请求；使用 mode-specific completion evidence 区分 success/neutral，完成 API Key 选择、OAuth refresh/CAS、Gemini enrichment、xAI 403 fallback 和发送前完整请求重建 fence。`RevocationGuardTransportFactory` 在写请求前进入 PostgreSQL 撤销门，最终复读仍须验证五元 fence、授权、绑定、到期、额度、凭据、模型、代理和请求事实。
- `backend-go/internal/platform/upstreamtransport` 与 `internal/platform/upstreamurlpolicy`：单次 HTTP(S) attempt、禁止 redirect/隐式 retry、有界响应、typed transport failure、HTTP/HTTPS/SOCKS 代理、DNS 全量校验与固定拨号；协议成功证据仍由 accountprobe 分类器负责。
- `backend-go/internal/app/cooldown_account_retest_probe.go`：默认关闭的生产依赖构造，连接 PostgreSQL runtime store、独立 revocation gate pool、Node 同键 Redis OAuth refresh lock、secret codec、raw refresh/enrichment transport 和 guarded model transport。构造存在不等于真实依赖或生产 owner 已验收。
- `backend-go/db/migrations/000090_w7_cooldown_retest_generation.sql` 与 `000091_w7_cooldown_retest_candidate_order.sql`：补齐 generation 存储、canonical CHECK、keyset index 和 schema gate，不负责旧行 backfill。
- 既有 `internal/modules/accounthealthcheck` 与 `internal/modules/cooldownaccountretest` 保留 runner / scheduler owner；后续接线时应调用本包，而不是再复制候选或 outcome 判断。

## Go 化调整及原因

| Node 原理 | Go 方式 | 原因 |
| --- | --- | --- |
| `success + upstreamResponseObserved` 临时布尔组合 | `ProbeEvidence -> ProbeOutcome` 有类型分类 | 调用者不能把任务错误当作账户错误写入。 |
| service 内局部 eligibility 函数 | 注入 `now` 的无副作用判断 | 可直接单测边界，不依赖系统时间或任务 runner。 |
| 队列项用多个散落字段防陈旧 | `RetestTaskVersion` 原子比较五元 fence | 目标配置、调度语义、新一轮观察、incarnation 和授权来源任一变化都能明确使旧任务失效。 |
