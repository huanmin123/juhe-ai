# W5 管理端分组创建迁移记录

> 本文记录 W5 管理端与个人端分组创建的 Go opt-in 迁移边界。当前只迁移创建闭环，不代表分组列表、详情、更新、删除、授权分组本地配置或完整分组模块已经接管。

## 基本信息

- 模块：分组创建
- 状态：Go 设计完成，待实现
- 迁移波次：W5 供应商、账号、分组、API Key、策略路由、代理、设置
- 当前 Node owner：`backend/src/modules/groups/groups.routes.ts`、`backend/src/storage/group-write.repository.ts`、`backend/src/domain/group-scheduling.ts`
- 目标 Go owner：`backend-go/internal/modules/managementgroups/`、`backend-go/internal/httpapi/management_groups.go`、`backend-go/internal/store/postgres/`、`backend-go/internal/httpapi/router.go`、`backend-go/internal/app/server.go`
- 关联计划：`../plans/计划-0081-Node转Go渐进减法迁移.md`

## 当前切片

本切片只包含：

- `POST /__aisys__/api/groups`
- `POST /__aisys__/api/my-groups`

两条路径都只在 `JUHE_AI_MANAGEMENT_API_ENABLED=true` 时注册，默认生产 server 不挂载。

### 权限与作用域

- `/groups` 只允许 `admin` / `super_admin`。
- `/groups?systemAccountId=<id>` 为指定系统账户创建分组。
- `/groups` 未提供 `systemAccountId` 时，为当前管理员自己的系统账户创建分组。
- `/my-groups` 允许任意已认证账户，只为当前账户创建分组，忽略外部账户作用域。
- 两条路径都使用写 session 鉴权并按现有 60 秒窗口 touch 当前 session。
- 两条路径都进入 system API IP write limiter 和 authenticated user write limiter。

## 请求契约

请求体必须是单个 strict JSON object，最大 `256 KiB`，只允许：

| 字段 | 必填 | 规则 | 默认值 |
| --- | --- | --- | --- |
| `name` | 是 | trim 后非空字符串 | 无 |
| `providerCode` | 是 | trim 后非空字符串；供应商必须存在且启用 | 无 |
| `description` | 否 | 字符串；trim 后空字符串保存为 `NULL` | `NULL` |
| `enabled` | 否 | 布尔值 | `true` |
| `groupType` | 否 | `personal` 或 `high_concurrency` | `personal` |
| `schedulingPolicy` | 否 | strict object，只允许 5 个当前可写字段 | 高并发默认策略 |

`schedulingPolicy` 当前可写字段：

- `defaultSoftConcurrency`：整数 `1..1_000_000`，默认 `5`
- `maxQueueWaitMs`：整数 `1..3_600_000`，默认 `60_000`
- `clientIpConcurrencyLimit`：整数 `0..1_000_000`，默认 `0`
- `clientIpConcurrencyOverflowMode`：`reject` 或 `queue`，默认 `reject`
- `imageLaneMaxConcurrency`：整数 `0..1_000_000`，默认 `0`

`personal` 分组不保存 `scheduling_policy_json`。`high_concurrency` 分组必须写入当前完整 16 字段策略 JSON，未开放字段使用 Node 当前内置默认值：

- `mode=balanced_fast`
- `fastFirstEnabled=true`
- `fallbackOnQueueEnabled=true`
- `breakAffinityOnSoftLimit=true`
- `breakAffinityOnQueueWaitMs=0`
- `slowRequestThresholdMs=30000`
- `firstOutputSlowThresholdMs=15000`
- `recentTimeoutWindowSeconds=120`
- `recentTimeoutPenaltyThreshold=2`
- `maxQueueSize=1000`
- `perApiKeyQueueLimit=1000`

请求不得提交这些内部固定字段，也不得提交历史 `providerProtocolProfileId` 等非当前分组字段。

## 存储契约

- 分组 ID 使用 `grp_` 前缀。
- 目标系统账户必须存在；运行时代码不自动创建系统账户。
- 写入 `juhe_business.groups` 当前字段，不新增表、字段、索引或兼容分支。
- `is_default=false`。
- 同一 `system_account_id + provider_code + lower(name)` 下名称唯一。
- 创建使用单条有界写入；唯一冲突映射为 `409`，不得先执行无锁 exists 查询替代数据库唯一约束。
- 创建成功后返回已提交的分组基础摘要，不读取账户、使用记录、审计或统计明细。

## 响应契约

成功返回 `201` 与 `{ "data": GroupSummary }`。

- 管理端响应包含 `systemAccountId`；个人端响应不包含该字段。
- 新分组固定 `isDefault=false`、`accountIds=[]`。
- `accountStats` 使用全零摘要；创建请求不得为了组装响应扫描账户或统计明细。
- `personal` 不返回 `schedulingPolicy`；`high_concurrency` 返回完整策略。
- 响应不包含 `providerProtocolProfileId`、账户详情、授权来源或运行态并发快照。

## 写后副作用

PostgreSQL 提交成功后：

1. best-effort 发布 reason=`group_created` 的 gateway runtime cache 失效；
2. best-effort 入队 `groups.create` operation log；
3. operation log 固定记录名称、供应商、分组类型和启用状态；
4. operation log scope 为分组 owner，管理端与个人端分别使用现有管理写日志作用域；
5. Redis 或 operation log 入队失败不能把已提交创建误报为失败。

`POST /groups` 使用现有短 TTL mutation guard，业务指纹固定为 owner + providerCode + 标准化 name。个人端同样按当前 owner 隔离，不能跨账户互相拦截。

## 错误边界

| 场景 | 响应 |
| --- | --- |
| 未登录、session 无效或过期 | `401` |
| 普通用户访问 `/groups` | `403 { "message": "需要管理员权限" }` |
| body 超过 `256 KiB` | `413 { "message": "请求体过大" }` |
| body 非对象、字段缺失、类型错误、未知字段或策略非法 | `400 { "message": "分组参数无效" }` |
| 目标系统账户不存在 | `400` 中文错误 |
| 供应商不存在 | `400 { "message": "不支持的供应商：<code>" }` |
| 供应商已停用 | `400 { "message": "供应商已停用：<code>" }` |
| 同一 owner / provider 下名称重复 | `409`，消息包含 `同一供应商下分组名称已存在` |
| PostgreSQL 写入失败 | 通用 `500 { "message": "服务器内部错误" }` |
| 提交后 Redis / operation log 失败 | 仍返回 `201` |

HTTP 错误不得泄露 PostgreSQL、Redis、内部 SQL、配置或凭据。

## 验证矩阵

- service：字段 trim、默认值、个人 / 高并发策略、非法字段、非法范围、供应商状态和唯一冲突。
- store：固定字段 INSERT、`NULL` 说明、完整策略 JSON、唯一错误映射和稳定 DTO。
- HTTP：admin / self 作用域、strict JSON、`256 KiB` / `413`、`201`、普通用户 403、错误脱敏。
- router / app：默认关闭不注册，显式 opt-in 后双路由挂载，写 auth touch 与两层 write limiter。
- 副作用：gateway runtime 失效和 operation log 都是事务外 best-effort。
- integration：fresh migrations、真实 PostgreSQL / Redis / 管理 session、两条 HTTP POST、DB 行、session touch、runtime invalidation 和 operation log payload。
- Node 对照：`test:group-management-driver`、`test:group-scheduling-policy`、`test:system-api-rate-limit` 和 performance system API smoke。

Docker/testcontainers `SKIP` 只记录为未执行，不计真实依赖通过。

## 明确排除

本切片不包含：

- `GET /groups`、`GET /groups/{id}` 或对应 `my-*` 读取；
- owned group 更新；
- authorized group 本地 `enabled/groupType/schedulingPolicy` 更新；
- 分组删除、默认分组保护和策略路由绑定重写；
- 授权归还；
- 富列表账户统计、用量、授权来源和实时并发；
- 前端连接真实 Go 后端 smoke；
- 生产单 owner 切流或 Node 分组实现删除。

## 删除门禁

只有创建双路由进入 Go opt-in 不能作为分组模块删除 Node 的证据。至少完成列表、详情、owned / authorized 更新、删除保护、前端真实 Go 后端 smoke、真实依赖 integration、生产切流与回滚记录后，才能评估 Node 分组 route / service / repository 删除。
