## 3. 总原则与不变量

1. **切片完整性（本轮最高原则）。** 迁移单元 = 完整功能纵切片（该功能全部路由 读+写、store 双模式、副作用、失效链、测试）。禁止把一个功能迁出一半；切片闭环验收通过前不得归档，通过后必须立即归档。
2. **无双轨。** 任何时刻、任何功能，代码库里只有一份 owner 实现。切片归档提交 = 删除 Node 实现 + 移除 Node 挂载 + 摘除过渡代理规则，三件事同一提交完成。不为"保险"保留 Node fallback、bridge 或双写。
3. **归档可找回，但不侥幸。** 归档目录 `migration-backup/node/final-archive/<slice-id>/` 带逐文件 SHA-256 manifest，用于日后查逻辑；验收从不依赖"反正 Node 还在"。
4. **契约等价，不逐行翻译。** 以 HTTP 契约、存储事实、失败语义等价为准；Node 为进程模型做的规避层（IPC、db-service、worker 队列）直接消除。
5. **双存储模式贯穿。** 每个 Go store 同时支持 SQLite 与 PostgreSQL；SQLite 文件单写者（Go 内单 writer goroutine + `busy_timeout`）；PG 保持连接池/事务/锁边界。
6. **mock 闭环优先。** 每片验收以 mock 体系为硬门禁（§5）：mock AI 上游、失败注入矩阵、golden 录制对照；真实上游只做每阶段一次的 dev 冒烟，不是门禁主体。
7. **配置兼容。** `JUHE_AI_*` 环境变量、默认值、53 个系统设置 key、前端 API 契约不变。
8. **语义对照先行。** 每片 G0 完成对照表（入口、鉴权、参数、错误码、状态码、事务、失效、流式终态）才能动手。
9. **每片可回滚。** 切片内提交粒度受控（§8）；切片失败 revert 该片提交序列即可；已归档切片的回滚 = 从归档目录恢复对应 Node 文件 + 恢复挂载（有 manifest 逐步文件路径），这是最后手段，不是计划路径。
10. **验收边界 = 隔离开发环境。** 不触碰 `.local/prod`，不执行任何生产操作。

## 4. 切片生命周期：G0 → G5

每个切片按固定七步走完，任何一步不过即停在原地：

| 步骤 | 内容 | 产出 |
| --- | --- | --- |
| G0 冻结 | 该片 Node 权威源清单、路由×场景矩阵（从 B0.2 路由矩阵裁剪）、错误码表；**录制 golden**：用当片仍未归档的 Node 实例对 mock 上游/请求集录制请求与响应样本 | 切片记录 `G0` 段 + golden fixture 文件 |
| G1 实现 | Go 代码 + 单测（store 双模式） | 提交 ①`migrate(<slice>): go implementation` |
| G2 mock 闭环 | 按 §5 门禁矩阵跑完全部 mock 测试 + 三项目 build/vet + 定向 `-race` + 前端 typecheck/build | 测试证据写入切片记录 |
| G3 对照验收 | golden diff（Node 录制 vs Go 实测）逐路由归零；浏览器冒烟（UI 可见切片） | diff 报告归档 |
| G4 翻转+归档 | Go 接管该前缀 → 摘除过渡代理规则 → 删除 Node 挂载与模块文件 → 文件移入 final-archive 并生成 manifest → route manifest 登记 `implemented` | 提交 ②`migrate(<slice>): flip entry and archive node sources` |
| G5 登记 | 切片记录收口（状态=archived、提交 SHA、证据链接）、看板更新、迁移 README/功能文档按需同步 | 提交 ③`docs(migration): close <slice>` |

**"不算半个功能"的硬性检查**（G4 前逐项打勾）：该片在路由矩阵中的所有行全部绿；该片的后台 job/retention 若属于功能闭环的一部分则同片完成（不属于的注明归属切片）；operation log、缓存失效、权限矩阵三项断言齐全；归档 manifest 行数与 Node 源文件清单行数一致。

### 5.2 Mock AI 场景矩阵（P5 网关链与 J 族探活的统一门禁）

每个供应商 × 以下场景全部覆盖，先对 Node 录制 golden，再要求 Go 等价：

| 类别 | 场景 |
| --- | --- |
| 正常 | 非流式 JSON；流式 SSE 全程；工具调用/结构化输出；多轮上下文 |
| 边界 | 接近 token 上限的长输入；空补全；超长行 SSE；非 UTF-8 字节 |
| 上游错误 | 400 / 401 / 403 / 429（Retry-After 语义 → neutral、不自动重试）/ 500 / 502 / 504；错误体 malformed JSON |
| 传输故障 | 首字节慢（触发网关超时）；流中 TCP 断开；SSE 半行截断；响应体超限；试图重定向（验证不跟随）；错误 Content-Type |
| 客户端行为 | 客户端中途取消（aborted exactly-once、499 语义）；并发同 Key 请求 |
| 凭据/代理 | 错误 API Key；过期 OAuth token（触发对应处理路径）；经 mock SOCKS5 成功/拒连/握手失败 |

判定等价的三元组：① Go 发往 mock 上游的请求（method、path、header 白名单、body 语义规范化后）与 Node 录制一致；② Go 返回客户端的状态码、header 白名单、body/流分片与录制一致（时钟与随机量注入后逐字节可比）；③ 失败归因落进冻结的四类结果（complete_success / framing_complete_neutral / upstream_failure / probe_task_failure）一致。

## 7. 入口翻转与过渡代理（无双轨的实现方式）

- **B1.6 起，Go gateway 是唯一入口**（业务端口 + 静态托管 + `/metrics`）。未迁移前缀经 `legacybridge`（httputil.ReverseProxy，SSE flush、取消与超时透传、原始 IP 头语义与 Node 一致）反代到仍在运行的 Node 进程。
- 每个切片 G4：该前缀在 Go 路由表原生接管 → 同一提交删除 `legacybridge` 对应规则 → 删除 Node 挂载与模块文件并归档。**任何前缀任一时刻只有一个 owner。**
- Node 进程只在"还有未翻转前缀"期间作为被代理后端存在；P8.1 时因无剩余前缀而自然退役，不存在长期双轨。
- AI 网关 `/v1/*` 因协议链不可拆分翻转，整链归 P5-G10 一次翻转；期间经 legacybridge 透传流式。

## 8. Git 提交纪律（按切片，缓冲区不堆积）

1. **每切片固定 2-3 个提交，切片收口时工作树必须干净**：
   - ① `migrate(<slice>): go implementation and mock tests`（Go 代码+测试+fixture）；
   - ② `migrate(<slice>): flip entry and archive node sources`（翻转+摘代理规则+Node 文件移入 final-archive+manifest）；
   - ③ `docs(migration): close <slice>`（切片记录收口+看板+按需文档）。
   小切片允许 ②③ 合并；禁止把两个切片混进一个提交；禁止跨切片留未提交改动。
2. 切片内部开发中的中间态允许提交到切片分支（`migrate-wip/<slice>`），但合入迁移主线仍按 ①②③ 结构 squash 成固定结构；主线永远只有完整切片。
3. 每切片开始前记录主线基线（fetch 后四元组）；主线漂移先 merge 再继续；合回 master 仅 fast-forward 且主目录干净。
4. 归档提交里 `git status` 必须显示纯 rename（Node 文件 → final-archive），保证历史可追溯；manifest 与文件同一提交。
5. 底线：任何时刻 `git status` 不出现与本切片无关的文件改动；发现混入立即拆出。
