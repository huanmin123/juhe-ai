### 统计 overview schema 审计

2026-07-22 对照最新 Node `stats-schema.ts`、`usage-stats.repository.ts` 和 `usage-overview-windows.repository.ts` 后确认，统计 overview 不是只依赖 Go reader 直接查询的三张窗口表。Node `usage_overview_windows` 刷新阶段的完整 PostgreSQL 契约如下：

- 已由 Goose `000026` 提供：`usage_stats_totals`、`usage_stats_daily`、`stats_job_state`。
- Goose 仍需统一补齐的源表：`usage_stats_hourly`、`usage_model_daily`、`usage_error_daily`。
- Goose 仍需统一补齐的发布表：`usage_overview_summary_windows`、`usage_overview_trend_windows`、`usage_model_rank_windows`、`usage_error_rank_windows`。
- 目标 migration 必须同时保留 Node 当前 18 个源表 / 发布表索引和七张表的精确主键。只补 Go reader 当前读取的 trend / model / error 三张表，会让 fresh Goose 上的 Node stats worker 在读取源表或写 summary window 时失败，不能作为 Node writer -> Go reader 共存证据。

本审计不占用并行 migration 版本，不新增 DDL，也不接入 Go reader 或 Go worker。`backend-go/db/migrationtests/usage_overview_node_contract_test.go` 以可执行测试冻结上述 Node schema、索引和 writer source-table 依赖，供统一 schema owner 生成 migration 时复用。

当前 owner gate 固定为：Node `stats-worker` 是 overview window 唯一 writer，Go 只允许只读预迁移；Go worker 没有 overview refresh stage，也不得因表已存在而自动启用 writer。未来切换 writer 时必须同时满足：统一 Goose migration 与 schema contract preflight 通过、Node stats writer 已停止、Go 专用 stage 开关默认关闭并显式启用、Go worker 持有 owner lock 且通过精确 Goose 版本门禁、真实 PostgreSQL 证明单 writer 后再切 reader 流量。migration 纯 DDL、路由编译或空表读取都不构成 owner 接管证据。

### Node stats writer 与 Go reader schema 共存门禁

统计概览、系统历史指标和表监控的 Go 只读实现会直接消费 Node `stats-worker` 单写的 `juhe_stats` 关系。这里不照搬 Node 的 SQLite 多库初始化，也不在 Go reader 启动时运行 Node schema reconcile；原因是请求进程自动补表会绕过 Goose 版本、制造双 schema owner，并使缺失部署步骤被伪装成正常空数据。

Go maintenance 新增 `stats-schema-contract-preflight`，以 contract version `2` 只读检查当前 reader 的真实依赖：

- `account-usage-ai-performance`：`usage_scope_range_windows`、`usage_rank_snapshots`、`usage_stats_daily`、`usage_stats_hourly`、`ai_performance_summary_windows`。账户用量列表 / 趋势与 AI 性能概览 / 账号选项都会读取这些预聚合关系；缺任一关系或列不得切流。

- `stats-overview`：`usage_stats_daily`、`usage_overview_trend_windows`、`usage_model_rank_windows`、`usage_error_rank_windows`。summary 按最新 Node 语义从 daily 聚合，另外三部分读取预聚合窗口；不依赖 raw `usage_records`。
- `system-metrics`：`system_metrics_trend_windows`、`process_event_loop_trend_windows`、`process_event_loop_samples`。
- `table-monitor`：`database_storage_snapshots`、`table_storage_snapshots`。

门禁检查查询只允许访问 `information_schema.columns`，关系缺失、reader 所需列缺失或数据库检查失败都会非零退出；底层数据库错误不会写入 JSON 结果。成功结果固定返回 `contractVersion=2` 与 `writerOwner=node`，只证明 Go reader schema 兼容，不证明数据新鲜、索引计划、Node writer 正在运行、Go writer 已实现或生产切流完成。Node stats worker 的源表、目标窗口、索引和发布原子性由独立 writer schema contract 维护，不能用本 reader 门禁替代。

部署顺序固定为：从真实 catalog 派生并统一分配下一连续 migration、离线应用 -> 启动 Node `stats-worker` 单 writer -> 运行本 preflight -> 执行真实 Node writer 到 Go reader smoke 与查询计划 -> 精确切换只读路由。当前权威 catalog 已连续到 `000073`，本切片不创建 migration、不修改 owner manifest、不复用或改写已发布版本；后续 fresh schema 补齐必须由统一 schema owner 合并。

## 契约与边界

- 管理侧只允许 `admin` / `super_admin`；个人侧允许任意已认证系统账户。
- 两条路径都使用只读 session 鉴权，不更新 `system_sessions.last_seen_at`。
- 查询参数不参与窗口计算；个人侧不会接受 `systemAccountId` 改写全局统计窗口。
- 时区校验兼容 Node `Intl.DateTimeFormat` 的大小写不敏感 IANA 名称和必要历史别名，并显式拒绝 Go-only 的 `Local` / `Factory`；响应保留配置原文返回，服务内缓存已验证时区 60 秒，避免每次请求读取 PostgreSQL。
- 配置缺失、空字符串、非法 JSON 或非法 IANA 时区均返回通用 `500`，不静默回退 UTC。
- 请求路径只读取系统设置，不读取 `usage_records`、统计日表或 range window，不执行 `SUM`、`GROUP BY` 或前端聚合。
- 当前生产 router 默认关闭；只有显式设置 `JUHE_AI_MANAGEMENT_API_ENABLED=true` 才注册 Go 路径。

### 使用记录列表

- 管理路径 admin-only，自助路径强制当前系统账户；均使用只读 session、不 touch，并经过管理端读限流。
- 列表最多 1000 条可见窗口，固定 `created_at DESC, id DESC`、多取一行计算 `hasMore`，不执行 `COUNT/SUM/GROUP BY`；管理员 DTO保留系统账户字段，自助 DTO不允许 query 改写 owner。
- 已补齐授权账户名称的 Node 四来源优先级、按账户 ID 去重和 200 条上限语义；列表 DTO 不返回请求 / 响应快照。2026-07-23 起两条按 ID 详情路径从 Node 与 Go 路由退场并返回 404，具体日志统一由日志管理页面提供；真实 PostgreSQL 多分区 `EXPLAIN`、Node writer -> Go reader 与生产切流仍必须独立完成。

### 运行日志列表、详情与渐进辅助读

- 两条路径只允许 `admin` / `super_admin`，使用只读 session 鉴权，不更新 `system_sessions.last_seen_at`，并经过管理端用户读限流。
- 列表保持 Node 当前宽容 query 语义：`page/pageSize` 非整数时使用默认值，`pageSize` 固定 `1..100`，页码按最多 1000 条可见记录的窗口截断；读取 `pageSize + 1` 判断 `hasMore`，`total` 是 progressive upper bound，不执行 `COUNT(*)`。
- 支持 `traceId` 大小写敏感 C 排序前缀、精确 `level/event`、`startAt/endAt` 和只匹配 `message` 的字面 keyword；keyword 未提供有效时间边界时自动限定最近 6 小时，`%/_/\\` 不作为调用方通配符。
- PostgreSQL 列表 repository 只为实际存在的筛选条件生成白名单参数化谓词，不保留 `参数为空 OR 条件` 形式；默认列表、trace 前缀、level、event 和 keyword + 时间窗口都必须在 `force_generic_plan` 下保留可验证的索引路径。
- query 首值、十六进制 / 二进制 / 八进制 / 指数整数、ECMAScript `trim()` 空白、合法 RFC3339、year-only、year-month、纯日期、无秒本地时间、无冒号 offset 和反向时间范围按 Node 当前语义归一化；ANSIC 无时区文本按本机时区解释，不得用更宽的 Go `strings.TrimSpace` 把 `U+0085` 等非 ECMAScript 空白误删。
- 列表固定按 `time DESC, id DESC`，只返回分页结果且不选择或返回 `raw_json`；详情接受 Node writer 当前允许的任意单 path segment 自定义 ID，返回同一摘要字段和必需 `rawJson`，不存在返回 `404 { message: "运行日志不存在" }`。固定 `/facets`、`/runtime`、`/grep-options` 和 `/grep` 都在 `/{id}` 前显式注册。
- `/facets` 返回 `retentionDays/earliestIndexedAt/latestIndexedAt/totalIndexed/levels/events`，以及部署开关 `indexEnabled`；当 `JUHE_AI_RUNTIME_LOG_INDEX_ENABLED=false` 时额外返回 `unavailableReason=index_disabled`，但继续读取历史 facet 数据，不隐藏既有索引。`/runtime` 在 Go 尚未接管 Node worker / DB service 运行态时显式返回 unavailable 布尔字段，不伪造队列明细，也不返回 `indexEnabled`（与 Node `/runtime` 契约一致）。`/grep-options` 与 `/grep` 由独立 Go 文件读 service 提供，复用 `JUHE_AI_LOG_DIR/JUHE_AI_LOG_FILE_ENABLED/JUHE_AI_LOG_RETENTION_DAYS/JUHE_AI_LOG_MAX_FILES`，优先使用 `JUHE_AI_RG_PATH`，留空时通过 `exec.LookPath` 查找 `rg`；不接管 writer、cursor、轮转或 retention 执行。
- Go 与 Node 共用 `JUHE_AI_RUNTIME_LOG_INDEX_ENABLED` 部署开关，解析 `true/false/1/0/yes/no/on/off`（大小写不敏感），仅在变量完全未设置时默认 `true`；显式空值或非法值启动失败。首尾裁剪严格对齐 Node `rawStringConfig(...).trim()` 的 ECMAScript 空白语义：`U+FEFF` 会裁剪，`U+0085` 保留并导致非法值。该开关只影响 facets 的索引启停标记和 Node 侧索引写入，不关闭日志文件或 grep。
- 请求上下文上限为 120 秒；HTTP 响应继承 `Cache-Control: no-store`，依赖错误只返回通用中文 500，不回显 PostgreSQL、Cookie 或内部错误。
- migration `000045` 在 fresh Goose schema 中完整保留 Node writer 继续运行所需的 `runtime_logs`、file cursor、facet 三张表及其索引，`000068` 为既有数据库补 `truncation_generation`；Go 管理 API 读取 `runtime_logs` 和预聚合 facet，独立 retention store 只按完成条件清理过期 cursor，不写 cursor、不引入全文检索扩展，也不接管 writer。
- Go runtime log retention 仅在 `JUHE_AI_RUNTIME_LOG_INDEX_ENABLED=true` 时组装。Node cleanup 子 owner 未停止时 `GoExclusiveIndexCleanupOwner` 默认 false，Go 索引删除 fail-closed、结果标记 deferred，当前 app 又未接 CLI/supervisor，因此不形成双 cleanup owner。独占门禁开启后，保留天数读取 `runtimeLogIndexRetentionDays`，缺失默认 14、范围 1..90；一次运行固定 cutoff，索引按 `time ASC, id ASC` + `FOR UPDATE SKIP LOCKED` 小批暂时删除。Go 多实例用事务级 try-advisory 去重，确有删除后才对 `current` summary 行执行 `FOR UPDATE NOWAIT`；Node importer 当前在同一事务内先写 summary、再写 level/event，因此该行是 importer 共存期的跨运行时串行点。不再使用会阻塞 Node 常规写锁的 facet 表锁。锁竞争或 25ms/1s/1.5s 保护边界触发时整批回滚、结果标记 deferred，周期任务下一轮重试；成功批次内计数不小于零，summary earliest/latest 与受影响 event latest 必要时从剩余索引重算。cursor 仅删除 `updated_at < cutoff`、`cursor_offset >= file_size`、`last_error_message IS NULL` 的完成行，并按 `updated_at ASC, log_file ASC` 小批处理。
- app 入口支持单次或周期运行、默认每批 1000 / 每轮 20 批和满批间 25ms 可取消暂停；共享 `cmd/juhe-ai-worker` 尚未接线，真实 PostgreSQL 下 Node importer 与 Go cleanup 并发 smoke 后置，不能记录为生产接管。
- Node writer 写入前把合法 `time/createdAt` 统一为 `Date#toISOString()`，非法或缺失值复用同一个当前时间兜底，保证 PostgreSQL `text` 时间列的排序、范围筛选和 Go reader 结果稳定。
- Node writer 在写入前把 `raw_json` 限制为 128KB，Go 详情只读取单条受限 payload；列表不读 payload，不读取日志文件，不做全文件 `split`、扫描或请求内聚合。
- 增量反代可把列表、详情、`/facets`、`/runtime`、`/grep-options` 和 `/grep` 一并指向 Go opt-in；management 整体 owner 切换到 Go 前仍需真实前端 smoke，并确认目标主机存在可执行 `rg` 或已显式配置 `JUHE_AI_RG_PATH`。

### 公开接口日志列表与详情

- 两条路径只允许 `admin` / `super_admin`，使用只读 session 鉴权，不更新 `system_sessions.last_seen_at`，并经过管理端用户读限流；匿名保持 `401`，普通用户保持 `403`，所有响应继承 `Cache-Control: no-store`。

- 本批不新增索引。integration `EXPLAIN` 只验证 fresh Goose 已有的 `idx_public_api_logs_created` 和 `idx_public_api_logs_source_created`；`traceId`、`clientIp` 等筛选已覆盖功能语义，但没有本批 `EXPLAIN` 索引证据。

### 审计日志列表与详情

- 只允许 `admin` / `super_admin`，使用只读 session、不 touch，并经过管理端读限流；匿名、普通用户、依赖错误和 `no-store` 边界沿用现有管理 API 契约。
- 列表与详情请求上下文上限均为 120 秒，对齐 Node audit router；客户端取消会向并行 PostgreSQL 子查询传播。
- query 对齐 Node 当前列表：`page/pageSize`、traceId / clientIp C 排序前缀、精确 errorGroupId / outcome / statusCode / path / model / systemAccountId / apiKeyId / groupId / accountId / trafficSource，以及 createdAt 起止范围。path 先移除可选 HTTP method 和 query；无效枚举和状态码忽略。
- 列表 SQL 只选择摘要列并关联系统账户、API Key、分组和账户名称，固定 `created_at DESC, id DESC`、最多 1000 条可见窗口、多取一行计算 `hasMore`，不执行 `COUNT`，不读取 payload。
- 详情按原始 `{id}` 查询主记录，不存在返回 `404 { message: "审计日志不存在" }`；attempts 固定按 `attempt_index ASC, id ASC`，payload refs 固定按 `sequence_index ASC, id ASC`，错误组缺失按可选字段省略。`attempts` / `payloads` 始终返回数组。
- 详情只返回 payload ref 元数据、hash、大小、捕获状态和 `hasHeaders/hasBody`；`/{id}/payloads/{payloadId}` 仍未迁移，不读取 blob 文件或 header/body 原文。attempt 的 proxy / upstream URL 保留凭据和 query 原文，只对齐 Node 当前首尾 ECMAScript 空白语义，不增加脱敏或日志清洗。
- `000069_w6_audit_logs_read_schema.sql` 保留 Node writer 所需五张审计表、外键和索引；Down 为 no-op。该 schema 只是共存基础，不改变 Node 单写 owner。
- `/audit-logs/{id}` 已注册到 Go；`/search-hot`、`/runtime`、`/error-groups*` 和 payload 原文路径在 Go 明确保持 404，仍由 Node 处理。反向代理必须按精确路径区分列表 / 详情和这些未迁移子路径，不得把整个 `/audit-logs/*` 前缀提前切给 Go。

### 账户用量与 AI 性能统计

- Go opt-in 已覆盖管理端 / 个人端 `account-usage`、`account-usage/summary`、`account-usage/trend`、`ai-performance`、`ai-performance/series`、`ai-performance/accounts` 共十二条 GET；管理端只允许管理员并支持全局 / 指定系统账户，个人端强制当前登录账户并忽略 `systemAccountId`。
- 全部路由复用 System API IP read limiter、认证用户 read limiter、只读 session 和 `Cache-Control: no-store`，不 touch `system_sessions.last_seen_at`。依赖错误只返回通用 500；AI 性能日期格式和 account options limit 保持 400 边界。
- 账户用量列表固定 31 天最大范围、默认最近 31 天、`pageSize=10`、最大 200、1000 行 progressive window、多取一行计算 `hasMore`；排序固定为请求数、费用、输入输出 token、最后使用时间和账户 ID。显式账户最多 50 个并与当前页去重合并，trend 最多 10 个。列表不再查询或返回 summary；`includeSummary` 即使为 `false` 也按 Node 契约返回 400，summary 由独立窄接口只读一次范围窗口。
- 账户用量默认列表和显式账户回填不生成 keyword 的可选参数 `OR`、来源账户 JOIN 或分组名称 EXISTS；只有实际存在 keyword 时才追加对应谓词，避免 PostgreSQL generic plan 为最常用的无筛选路径保留搜索分支。
- AI 性能 base 默认读取最新 `last7d/request_count` 排名前 10，只返回 `range/summary/accounts/hourlySeries`，并拒绝任何 `accountIds` / bracket 变体；series 只返回 `range/accounts/hourlySeries`，要求 1..20 个重复 `accountIds=value` 或 `accountIds[]=value`，拒绝空值、CSV、21 个值及未知 bracket key。不可见账户由 reader 静默省略。options 默认 / 最大 50，名称采用 NFKC 后大小写敏感前缀，显式选择与搜索结果去重。小时序列在服务层补齐范围内每个 24 小时桶，平均值和最大值只在对应样本 count 大于零时返回。
- PostgreSQL reader 只读 `usage_scope_range_windows`、`usage_rank_snapshots`、`usage_stats_daily`、`usage_stats_hourly`、`ai_performance_summary_windows` 和业务 metadata 表；不读取 `juhe_usage.usage_records`，不执行请求内 `SUM/COUNT/GROUP BY`。list / summary、base / series 已分别使用独立 store 方法，避免渐进接口退化为先查宽结果再裁剪。
- 连续 migration `000088_w6_progressive_stats_read_catalog.sql` 已把 fresh Goose 缺失的 `usage_stats_hourly`、`usage_rank_snapshots`、`ai_performance_summary_windows`、`usage_scope_range_windows` 及 Node 同名关键索引纳入 catalog，`CurrentSchemaVersion=88`。DDL 使用 `IF NOT EXISTS` 兼容 Node 已建表，Down 明确 no-op，避免回滚误删共享派生数据；它只接管 schema catalog，不接管数据 writer。
- Node stats worker 继续是这些预聚合表的唯一 writer。本批未修改 owner manifest、未启动 Go stats writer、未切生产流量。真实 fresh Goose apply、Node writer -> Go reader、custom / generic plan `EXPLAIN`、真实 listener / browser、反向代理切换与回滚仍是生产接管硬门禁。

### 统计 overview

- 管理路径 admin-only，可用 `systemAccountId` 选择单个系统账户；缺失、空值或 `all` 使用 Node 的 `global` scope。自助路径强制当前系统账户，不能由 query 越权改写。
- `startDate/endDate` 只接受单个 `YYYY-MM-DD` 值；服务复用 `usage-window` 的统计时区、当天与最多 31 天边界，输出保持 Node 的 summary、hourly trend、model distribution 和 errors DTO。
- summary 只对 `juhe_stats.usage_stats_daily` 中 `(system_account_id, scope_type='system_account', scope_id=system_account_id, stat_date)` 的有界日期范围执行聚合，不读取 `usage_overview_summary_windows`，不扫描 `usage_records`。
- trend、model 和 error 只读 `juhe_stats.usage_overview_trend_windows`、`usage_model_rank_windows`、`usage_error_rank_windows`，分别固定 744 / 10 / 10 行上限，不回退日表或明细聚合。
- schema 集成门禁是本切片的硬依赖：三张 overview / rank window 表及 lookup 索引必须由 schema owner 在统一 migration 中落地，并在 fresh Goose 和 Node writer -> Go reader PostgreSQL smoke 中证明字段、主键、排序与 Node 一致。当前代码不得以“路由已编译”宣称可部署。
