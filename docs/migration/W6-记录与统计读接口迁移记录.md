# W6 记录与统计读接口迁移记录

## 当前范围

W6 当前 Go opt-in 范围包含以下互不扩大的只读切片：

- `GET /__aisys__/api/stats/usage-window`
- `GET /__aisys__/api/my-stats/usage-window`
- `GET /__aisys__/api/usage-records`
- `GET /__aisys__/api/usage-records/{id}`
- `GET /__aisys__/api/my-usage-records`
- `GET /__aisys__/api/my-usage-records/{id}`
- `GET /__aisys__/api/runtime-logs`
- `GET /__aisys__/api/runtime-logs/facets`
- `GET /__aisys__/api/runtime-logs/runtime`
- `GET /__aisys__/api/runtime-logs/{id}`
- `GET /__aisys__/api/public-api-logs`
- `GET /__aisys__/api/public-api-logs/{id}`
- `GET /__aisys__/api/audit-logs`
- `GET /__aisys__/api/audit-logs/search-hot`
- `GET /__aisys__/api/audit-logs/{id}`

两条路径读取 `juhe_business.system_settings` 中 `sys_admin / usageStatsTimezone`，返回统计时区当天向前包含当天的固定 31 天窗口：

```json
{
  "data": {
    "timezone": "Asia/Shanghai",
    "startDate": "2026-06-10",
    "endDate": "2026-07-10",
    "days": 31,
    "maxDays": 31
  }
}
```

运行日志列表只读取 Node 生产 writer 写入 `juhe_dataset.runtime_logs` 的轻量索引列，详情才按单个 ID 读取 `raw_json`。Go 同步提供仅返回索引筛选信息的 `/runtime-logs/facets` 和轻量运行态可用性 `/runtime-logs/runtime`；依赖 Node 日志目录与搜索运行态的 `/runtime-logs/grep-options`、实际 grep 文件扫描、日志文件增量导入、索引写入、facet 生产和保留清理仍由 Node 负责。

公开接口日志列表只读取 `juhe_dataset.public_api_logs` 的摘要列，不选择 `request_data_json` / `response_data_json`；详情才按单个 ID 单行读取两个有界 payload。两条管理读接口已经进入 Go opt-in，但写入 owner、保留清理、生产切流和 Node 路由删除不随本读切片自动接管。

使用记录四条管理 / 自助读路径只读 Node 当前单写的 `juhe_usage.usage_records`；列表一次关联名称并使用 progressive window，详情按 ID 读取已保存的 request / response snapshot。账户关键字已按 Node 顺序覆盖自有账户、授权实例、直接账户授权和启用的分组授权；四段各自先排序并限制 200，再按账户 ID 去重和执行最终 200 截断。标准 `usage_YYYYMMDD_sN_*` 详情 ID 已增加 UTC 单日分区裁剪。Node 继续拥有 schema 分区、写入队列、writer、首屏 Redis 缓存和页面增量发布，真实 Node writer -> Go reader 与查询计划仍是切流前缺口。

审计日志管理员列表、热搜索和详情已经进入 Go opt-in。列表只选择 `juhe_dataset.audit_logs` 摘要列和业务名称；详情先按原始 ID 读取同一摘要，再并发读取 attempts、可选 error group 和 payload refs 元数据。热搜索只读 Node writer 生成的 `audit-hot-*.ndjson` 镜像，使用 Go 原生有界逐行扫描后按命中 ID 回 PostgreSQL 取摘要，不读取 payload blob，也不复制 Node 的 `rg` 子进程依赖。Node 继续拥有审计捕获、Redis Stream / IPC、ingest writer、payload 原文读取、error group 列表 / events、热搜索镜像写入、runtime 和保留清理。

## 契约与边界

- 管理侧只允许 `admin` / `super_admin`；个人侧允许任意已认证系统账户。
- 两条路径都使用只读 session 鉴权，不更新 `system_sessions.last_seen_at`。
- 查询参数不参与窗口计算；个人侧不会接受 `systemAccountId` 改写全局统计窗口。
- 时区校验兼容 Node `Intl.DateTimeFormat` 的大小写不敏感 IANA 名称和必要历史别名，并显式拒绝 Go-only 的 `Local` / `Factory`；响应保留配置原文返回，服务内缓存已验证时区 60 秒，避免每次请求读取 PostgreSQL。
- 配置缺失、空字符串、非法 JSON 或非法 IANA 时区均返回通用 `500`，不静默回退 UTC。
- 请求路径只读取系统设置，不读取 `usage_records`、统计日表或 range window，不执行 `SUM`、`GROUP BY` 或前端聚合。
- 当前生产 router 默认关闭；只有显式设置 `JUHE_AI_MANAGEMENT_API_ENABLED=true` 才注册 Go 路径。

### 使用记录列表与详情

- 管理路径 admin-only，自助路径强制当前系统账户；均使用只读 session、不 touch，并经过管理端读限流。
- 列表最多 1000 条可见窗口，固定 `created_at DESC, id DESC`、多取一行计算 `hasMore`，不执行 `COUNT/SUM/GROUP BY`；管理员 DTO保留系统账户字段，自助 DTO不允许 query 改写 owner。
- 已补齐授权账户名称的 Node 四来源优先级、按账户 ID 去重和 200 条上限语义；标准记录 ID 按日期生成 `[start, end)` 分区条件，无效日期或旧格式保持 ID-only 回退。详情同时对齐 snapshot endpoint 回退、ECMAScript 空白判定、非空 snapshot 必须为 JSON 对象、空对象原样返回、显式 `modelMappingApplied: false` 和列表筛选门禁不拦截详情。真实 PostgreSQL 多分区 `EXPLAIN`、Node writer -> Go reader 与生产切流仍必须完成。

### 运行日志列表、详情与渐进辅助读

- 两条路径只允许 `admin` / `super_admin`，使用只读 session 鉴权，不更新 `system_sessions.last_seen_at`，并经过管理端用户读限流。
- 列表保持 Node 当前宽容 query 语义：`page/pageSize` 非整数时使用默认值，`pageSize` 固定 `1..100`，页码按最多 1000 条可见记录的窗口截断；读取 `pageSize + 1` 判断 `hasMore`，`total` 是 progressive upper bound，不执行 `COUNT(*)`。
- 支持 `traceId` 大小写敏感 C 排序前缀、精确 `level/event`、`startAt/endAt` 和只匹配 `message` 的字面 keyword；keyword 未提供有效时间边界时自动限定最近 6 小时，`%/_/\\` 不作为调用方通配符。
- PostgreSQL 列表 repository 只为实际存在的筛选条件生成白名单参数化谓词，不保留 `参数为空 OR 条件` 形式；默认列表、trace 前缀、level、event 和 keyword + 时间窗口都必须在 `force_generic_plan` 下保留可验证的索引路径。
- query 首值、十六进制 / 二进制 / 八进制 / 指数整数、ECMAScript `trim()` 空白、合法 RFC3339、year-only、year-month、纯日期、无秒本地时间、无冒号 offset 和反向时间范围按 Node 当前语义归一化；ANSIC 无时区文本按本机时区解释，不得用更宽的 Go `strings.TrimSpace` 把 `U+0085` 等非 ECMAScript 空白误删。
- 列表固定按 `time DESC, id DESC`，只返回分页结果且不选择或返回 `raw_json`；详情接受 Node writer 当前允许的任意单 path segment 自定义 ID，返回同一摘要字段和必需 `rawJson`，不存在返回 `404 { message: "运行日志不存在" }`。固定 `/facets`、`/runtime` 在 `/{id}` 前注册；尚未迁移的 `/grep-options` 和 `/grep` 在 Go 返回 404。
- `/facets` 返回 `retentionDays/earliestIndexedAt/latestIndexedAt/totalIndexed/levels/events`，以及部署开关 `indexEnabled`；当 `JUHE_AI_RUNTIME_LOG_INDEX_ENABLED=false` 时额外返回 `unavailableReason=index_disabled`，但继续读取历史 facet 数据，不隐藏既有索引。`/runtime` 在 Go 尚未接管 Node worker / DB service 运行态时显式返回 unavailable 布尔字段，不伪造队列明细，也不返回 `indexEnabled`（与 Node `/runtime` 契约一致）。`/grep-options` 与 `/grep` 共同依赖 Node 日志文件和搜索运行态，迁移时作为同一切片处理。
- Go 与 Node 共用 `JUHE_AI_RUNTIME_LOG_INDEX_ENABLED` 部署开关，解析 `true/false/1/0/yes/no/on/off`（大小写不敏感），仅在变量完全未设置时默认 `true`；显式空值或非法值启动失败。首尾裁剪严格对齐 Node `rawStringConfig(...).trim()` 的 ECMAScript 空白语义：`U+FEFF` 会裁剪，`U+0085` 保留并导致非法值。该开关只影响 facets 的索引启停标记和 Node 侧索引写入，不关闭日志文件或 grep。
- 请求上下文上限为 120 秒；HTTP 响应继承 `Cache-Control: no-store`，依赖错误只返回通用中文 500，不回显 PostgreSQL、Cookie 或内部错误。
- migration `000045` 在 fresh Goose schema 中完整保留 Node writer 继续运行所需的 `runtime_logs`、file cursor、facet 三张表及其索引，`000068` 为既有数据库补 `truncation_generation`；Go 读取 `runtime_logs` 和预聚合 facet，不读取或接管 file cursor，不引入全文检索扩展，也不接管 writer。
- Node writer 写入前把合法 `time/createdAt` 统一为 `Date#toISOString()`，非法或缺失值复用同一个当前时间兜底，保证 PostgreSQL `text` 时间列的排序、范围筛选和 Go reader 结果稳定。
- Node writer 在写入前把 `raw_json` 限制为 128KB，Go 详情只读取单条受限 payload；列表不读 payload，不读取日志文件，不做全文件 `split`、扫描或请求内聚合。
- 增量反代必须精确区分已进入 Go opt-in 的列表、详情、`/facets`、`/runtime` 和仍保留在 Node 的 `/grep-options`、`/grep` 文件扫描；management 整体 owner 切换到 Go 前仍需真实前端 smoke。

### 公开接口日志列表与详情

- 两条路径只允许 `admin` / `super_admin`，使用只读 session 鉴权，不更新 `system_sessions.last_seen_at`，并经过管理端用户读限流；匿名保持 `401`，普通用户保持 `403`，所有响应继承 `Cache-Control: no-store`。
- 列表保持 Node 当前 query 语义，支持 `traceId` 前缀、`sourceRefId` / `path` / `statusCode` 精确匹配、`result=success|failed|all`、`clientIp` 前缀、`startAt/endAt`、`page/pageSize`；筛选共同使用 AND。`pageSize` 最大 100，最多 1000 条可见记录，使用 `pageSize + 1` 和 progressive `total/hasMore`，不执行 `COUNT(*)`。
- 列表 SQL 只选择摘要列，固定按 `created_at DESC, id DESC` 稳定排序，不读取或返回 `request_data_json` / `response_data_json`。详情按原始 `{id}` 单行 `LIMIT 1` 读取摘要和两个 payload，不扫描列表；不存在返回 `404 { message: "公开接口日志不存在" }`。
- 详情只解析已保存的有界 JSON。W1b 写入侧的 query/body/response 在捕获预算内保留原值；管理读接口不再做二次脱敏。`Authorization`、Cookie 和作为 Bearer 凭据传入的来源 token 本来就不在快照 headers 捕获范围内，headers 只包含 `contentType` / `contentLength`。
- Node PostgreSQL 旧结构与 fresh Goose 不兼容：Node 旧表的 `is_test_token` / `success`、`duration_ms`、三个时间字段分别使用 `integer` / `text` 体系，Go `000003` 使用 `boolean` / `bigint` / `timestamptz`。生产切流前必须离线完成结构和数据同步，并确定单一写入 owner；Go reader / writer 不增加旧结构运行时兼容，也不允许 Node / Go 双写同一张表。
- 本批不新增索引。integration `EXPLAIN` 只验证 fresh Goose 已有的 `idx_public_api_logs_created` 和 `idx_public_api_logs_source_created`；`traceId`、`clientIp` 等筛选已覆盖功能语义，但没有本批 `EXPLAIN` 索引证据。

### 审计日志列表、热搜索与详情

- 只允许 `admin` / `super_admin`，使用只读 session、不 touch，并经过管理端读限流；匿名、普通用户、依赖错误和 `no-store` 边界沿用现有管理 API 契约。
- 列表与详情请求上下文上限均为 120 秒，对齐 Node audit router；客户端取消会向并行 PostgreSQL 子查询传播。
- query 对齐 Node 当前列表：`page/pageSize`、traceId / clientIp C 排序前缀、精确 errorGroupId / outcome / statusCode / path / model / systemAccountId / apiKeyId / groupId / accountId / trafficSource，以及 createdAt 起止范围。path 先移除可选 HTTP method 和 query；无效枚举和状态码忽略。
- 列表 SQL 只选择摘要列并关联系统账户、API Key、分组和账户名称，固定 `created_at DESC, id DESC`、最多 1000 条可见窗口、多取一行计算 `hasMore`，不执行 `COUNT`，不读取 payload。
- 详情按原始 `{id}` 查询主记录，不存在返回 `404 { message: "审计日志不存在" }`；attempts 固定按 `attempt_index ASC, id ASC`，payload refs 固定按 `sequence_index ASC, id ASC`，错误组缺失按可选字段省略。`attempts` / `payloads` 始终返回数组。
- 详情只返回 payload ref 元数据、hash、大小、捕获状态和 `hasHeaders/hasBody`；`/{id}/payloads/{payloadId}` 仍未迁移，不读取 blob 文件或 header/body 原文。attempt 的 proxy / upstream URL 保留凭据和 query 原文，只对齐 Node 当前首尾 ECMAScript 空白语义，不增加脱敏或日志清洗。
- `/audit-logs/search-hot` 保持最近一小时窗口、最多 10 个关键字、单关键字 2..128 字符、最多 100 条结果和单实例 1 个并发搜索。扫描最多检查 2000 个目录项和 2000 条命中行，单行按 20000 个 Unicode 字符及 80000 字节双重限制，请求内扫描最多 15 秒；超限或取消返回显式截断结果，不降级成伪造空列表。
- Go 热搜索只在 `JUHE_AI_AUDIT_HOT_SEARCH_ROOT` 显式指定共享只读镜像目录时可用。不得从 Node 相对 `JUHE_AI_DATASET_DATABASE_PATH` 推断目录，因为 Node 与 Go 的进程工作目录不同会把同一相对路径解析到不同位置并伪造空结果；未配置时返回 `available=false`。已配置目录不存在视为当前窗口没有镜像；目录不可读返回 `available=false` 的通用消息，不暴露宿主路径。
- 本切片没有照搬 Node 的 `@vscode/ripgrep` 进程模型：Go 使用上下文可取消的流式逐行读取，避免额外可执行文件和子进程生命周期，同时保留 OR 关键字、大小写不敏感、按 `createdAt DESC, id ASC` 去重排序和超限语义。Node 继续是镜像唯一 writer 和 retention owner。
- `000069_w6_audit_logs_read_schema.sql` 保留 Node writer 所需五张审计表、外键和索引；Down 为 no-op。该 schema 只是共存基础，不改变 Node 单写 owner。
- `/audit-logs/search-hot` 与 `/audit-logs/{id}` 已注册到 Go；`/runtime`、`/error-groups*` 和 payload 原文路径在 Go 明确保持 404，仍由 Node 处理。反向代理必须按精确路径区分已迁移路径和这些未迁移子路径，不得把整个 `/audit-logs/*` 前缀提前切给 Go。
