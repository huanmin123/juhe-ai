# 模块迁移顺序与减法清单

## 1. 使用方式

本文件是后续迁移执行的主清单。每迁移一个模块，都必须更新状态、Go owner、Node 删除证据和验证记录。

状态建议：

- `未开始`：尚未进入迁移。
- `契约固定`：已生成当前 Node 行为契约、fixture 或测试清单。
- `Go 实现中`：Go 代码开发中。
- `待删除 Node`：Go 已通过测试，但 Node 旧代码还未删。
- `已接管`：Go 是唯一 owner，Node 旧入口已删除。
- `阻塞`：存在设计、数据、测试或部署阻塞。

## 2. 迁移波次

| 波次 | 模块 | 迁移原因 | Go 接管范围 | Node 删除范围 | 必须验证 |
| --- | --- | --- | --- | --- | --- |
| W0 | Go 工程基线 | 后续模块迁移的共同基础 | 配置、日志、统一响应、错误、测试工具、健康检查 | 无业务删除 | `go test ./...`、Windows / Linux / macOS 构建基线 |
| W1 | 公开接口 | 路径少、业务副作用少、适合先试水 | `/__aipublic__/*`、公开设置、公开资源读取 | Node 公开接口 route/service/log 写入入口 | 公开接口契约、权限、日志、分页和错误语义 |
| W2 | 管理端只读辅助接口 | 风险低，能快速建立前端联调方式 | providers、models、proxy options、account/group/API Key options | Node 对应只读 route/service | 登录态、普通用户访问边界、空数据和中文错误 |
| W3 | 登录与系统账户 | 管理接口基础能力 | 登录、会话、系统账户、验证码/限频边界 | Node auth/system-accounts route/service/session store | 密码、session、权限、失败限制、安全日志 |
| W4 | 团队与统一授权 | 权限和调度前置事实 | 系统团队、授权 grant、授权归还、授权到期 | Node teams/authorization route/service/store | 权限矩阵、授权范围、过期和分页 |
| W5 | 供应商、账号、分组、API Key、策略路由、代理、设置 | 后台核心 CRUD | 管理 CRUD、字段校验、敏感字段展示、路由策略绑定 | Node 对应模块 route/service/store 和测试命令 | CRUD、权限、敏感字段脱敏、稳定排序、存储 adapter |
| W6 | 使用记录、审计、日志和统计读 API | 为 worker 和网关迁移铺路 | 列表、详情、窗口查询、聚合缓存读取 | Node 记录类读 route/service | cursor/window、权限、无实时扫描、分页稳定 |
| W7 | ingest / stats / ops worker | 移除 Node worker 和 IPC 胶水 | 使用记录写入、审计、日志索引、统计增量、账号测试、代理检测、OAuth 保活 | Node worker、temporary maintenance worker、相关 IPC | 游标、重试、队列上限、任务租约、维护脚本 |
| W8 | 存储 adapter 和 schema | 消除 Node storage 层和双模式维护成本 | PostgreSQL schema / seed / store、Redis cache / state / queue、事务和数据加密 | Node storage adapter、DB service、SQLite schema、SQLite 配置、usage shard 文件模式和双模式分支 | 新库初始化、PG/Redis smoke、数据加密、无 SQLite 运行引用 |
| W9 | 网关准备层 | 为真实转发降风险 | API Key 校验、设置、配额快照、运行态缓存、候选账号读取 | Node 网关 preflight 分层旧代码 | 缓存失效、权限、配额、候选过滤、运行态 |
| W10 | 真实中转网关 | 最核心链路，最后迁移 | `/*`、`/v1/*`、OpenAI / Anthropic / Gemini / hybrid、SSE、调度、审计和 usage | Node gateway 主链路、协议 adapter、响应检查、重试逻辑 | mock AI、真实 e2e、SSE、backpressure、取消、性能报告 |
| W11 | 发布收尾 | 正式抛弃 Node 后端 | Go 发布包、Docker、服务化、备份恢复、文档 | `backend/` 后端源码、Node 后端脚本、后端依赖和 engine 约束 | 全量构建、安装、部署、回滚和 smoke |

## 4. 单模块删除门禁

一个模块只有同时满足以下条件，才能把状态改为 `已接管`：

- Go route/job/script 已经是正式入口。
- 当前模块 Node route/service/store/script/test 命令已删除。
- 已迁移模块不能继续引用 SQLite adapter、SQLite 环境变量、usage shard 文件写入或 standalone / performance 模式分支。
- 前端或调用方不再引用旧路径、旧字段或旧错误结构。
- `rg` 检查旧模块名、旧 route、旧测试命令和旧脚本入口，只剩文档历史引用或无结果。
- Go 单元测试、API 契约测试、权限测试和必要的 smoke 已通过。
- 文档更新到 `docs/functions/`、`docs/develop/`、`docs/deploy/` 或本目录对应文件。

## 5. 网关专项门禁

真实中转网关迁移前，必须先完成：

- 管理接口、存储 adapter、worker 和统计/审计写入已经由 Go 接管或有明确 Go owner。
- API Key、路由策略、分组、账号候选、配额和运行态缓存的 Go 读取路径已通过压力验证。
- OpenAI Chat / Responses、Anthropic Messages、Gemini native、hybrid bridge 的 mock AI 回归已准备好。
- SSE 增量解析、下游 backpressure、客户端取消、上游超时和已写出后的失败语义有专项测试。
- 使用记录、审计、账号副作用和统计入队都不阻塞已可返回的响应。
