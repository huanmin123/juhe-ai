# 模块迁移顺序与减法清单

## 1. 使用方式

本文件是后续迁移执行的主清单。每迁移一个模块，都必须更新状态、Go owner、Node 删除证据和验证记录。

状态建议：

- `未开始`：尚未进入迁移。
- `契约固定`：已生成当前 Node 行为契约、fixture 或测试清单。
- `Go 实现中`：Go 代码开发中。
- `待删除 Node`：Go 已通过测试，但 Node 旧代码还未删。
- `已接管`：Go 是唯一 owner，Node 旧入口已删除。
- `阻塞`：存在设计、数据、测试或部署阻塞。

## 4. 单模块删除门禁

一个模块只有同时满足以下条件，才能把状态改为 `已接管`：

- Go route/job/script 已经是正式入口。
- 当前模块 Node route/service/store/script/test 命令已删除。
- 已迁移模块不能继续引用 SQLite adapter、SQLite 环境变量、usage shard 文件写入或 standalone / performance 模式分支。
- 前端或调用方不再引用旧路径、旧字段或旧错误结构。
- `rg` 检查旧模块名、旧 route、旧测试命令和旧脚本入口，只剩文档历史引用或无结果。
- Go 单元测试、API 契约测试、权限测试和必要的 smoke 已通过。
- 文档更新到 `docs/functions/`、`docs/develop/`、`docs/deploy/` 或本目录对应文件。

## 5. 网关专项门禁

真实中转网关迁移前，必须先完成：

- 管理接口、存储 adapter、worker 和统计/审计写入已经由 Go 接管或有明确 Go owner。
- API Key、路由策略、分组、账号候选、配额和运行态缓存的 Go 读取路径已通过压力验证。
- OpenAI Chat / Responses、Anthropic Messages、Gemini native、hybrid bridge 的 mock AI 回归已准备好。
- SSE 增量解析、下游 backpressure、客户端取消、上游超时和已写出后的失败语义有专项测试。
- 使用记录、审计、账号副作用和统计入队都不阻塞已可返回的响应。

W10 必须按这些阻断门禁推进：

| 门禁 | 必须证明 |
| --- | --- |
| 契约冻结 | `/*`、`/v1/*`、`/__aisys__/*` 和 `/__aipublic__/*` 路径归属、认证前 body 读取边界、header 白名单和错误结构已固定 |
| Mock 全矩阵 | OpenAI Chat / Responses、Anthropic Messages、Gemini native、Hybrid、协议允许 / 禁止方向、JSON / SSE、usage、工具、图像、坏 SSE 都有 mock 回归 |
| 响应检查和错误兜底 | Chat / Responses JSON / SSE 污染、畸形 SSE、Codex compact、普通客户端不可见 Codex 专用错误码、非 2xx 和 SSE 内失败都通过 |
| Side effects / 队列 | usage、audit、operation / public logs、账号副作用、统计入队在 Asynq 队列积压、worker 停止、重试和 dead / archived 情况下不阻塞已可返回响应 |
| 生命周期和压测 | 慢客户端、半帧 SSE、大事件、客户端断开、上游 cancel、goroutine / FD / 内存、pprof 和 backpressure 都有验证 |
| 真实 smoke | OpenAI-compatible、Anthropic、Gemini、Codex / Claude Code / Gemini CLI 代表性真实请求按凭据可用性执行或记录未覆盖原因 |
| 灰度切换 | 按 API Key、系统账户或独立端口 canary；定义失败阈值、快速停止和回退步骤 |
| Node 删除证据 | W10 成功后统一删除 Node gateway 主链路、preflight、协议 adapter、响应检查和重试旧实现 |
