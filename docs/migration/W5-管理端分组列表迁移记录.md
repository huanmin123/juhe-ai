## 当前切片

本切片只包含：

- `GET /__aisys__/api/groups`
- `GET /__aisys__/api/my-groups`

两条路径只在 `JUHE_AI_MANAGEMENT_API_ENABLED=true` 时注册，默认生产 server 不挂载。

本切片不迁移分组详情、更新、删除、授权分组本地配置写入、授权归还或 stats worker owner。

## 中间件与权限

Go 路由沿用当前管理 API 链路：

1. system API IP read limiter；
2. 只读 session 鉴权，不 touch session；
3. authenticated user read limiter；
4. `/groups` 执行 admin-only；
5. `/my-groups` 强制 self scope；
6. handler 返回 `Cache-Control: no-store`。

权限与作用域：

- `/groups` 只允许 `admin` / `super_admin`。
- `/groups` 不传 `systemAccountId`、传空值或传 `all` 时返回全部 owner 分组，不展开某个 grantee 的授权视图。
- `/groups?systemAccountId=<id>` 返回该系统账户拥有的分组与授权给该账户的分组。
- `/my-groups` 忽略外部 `systemAccountId`，固定返回当前账户拥有的分组与授权给当前账户的分组。
- 管理员访问 `/my-groups` 时也只能看到自己的 self scope。

未登录或 session 无效返回 `401`；普通用户访问 `/groups` 返回 `403 { "message": "需要管理员权限" }`；内部依赖错误统一返回通用 `500`。

## 查询与分页

列表只读取：

- `page`
- `pageSize`
- `/groups` 的 `systemAccountId` 作用域

`keyword`、`providerCode`、`ids`、`manageableOnly`、`preferDefault` 等 options 查询参数不属于列表契约，传入时忽略，不返回 `400`。

参数规则：

- `page` 默认 `1`，最小 `1`。
- `pageSize` 默认 `50`，范围 `1..500`。
- 无法转成有限整数的值按未传处理。
- 最大页码为 `floor(1000 / pageSize)`；超出时静默截断到最大页码。
- 主查询读取 `pageSize + 1` 行。
- `hasMore = rows.length > pageSize`。
- `total = (page - 1) * pageSize + items.length + (hasMore ? 1 : 0)`。
- 不执行 `COUNT(*)`；`total` 是当前窗口的渐进上界，不是精确总数。

## 可见性与稳定排序

主查询按 owner 与 authorized 两类行组成统一窗口：

- owner 行直接读取 `groups`。
- authorized 行读取当前 grantee 的 `resource_authorizations` 与 `group_authorization_settings`。
- 授权状态 `active`、`paused`、`expired` 继续可见；`revoked`、`returned` 不可见。
- authorized 行允许本地覆盖 `enabled`、`groupType`、`schedulingPolicy`；名称、供应商和说明仍来自 owner 分组，`isDefault=false`。
- 管理端全局列表不传目标账户时只返回 owner 视图，不能为每个用户展开重复授权行。

排序固定为：

```text
effective_updated_at DESC, id DESC
```

owner 行的 `effective_updated_at` 来自分组；authorized 行优先使用 grantee 的 `group_authorization_settings.updated_at`，因此本地设置变化会改变列表顺序。所有 SQL 必须保留 `id DESC` 唯一兜底。

## 响应契约

顶层响应：

```json
{
  "data": {
    "items": [],
    "total": 0,
    "hasMore": false,
    "page": 1,
    "pageSize": 50,
    "runtimeSnapshot": {
      "accountConcurrencyAvailable": true
    }
  }
}
```

当前 progressive list 不返回 `accountIds`，因此不触发 server account concurrency snapshot；`runtimeSnapshot.accountConcurrencyAvailable` 固定为 `true`。旧的“分组列表并发快照不可用”Node 回归与当前源码不一致，不能作为 Go 验收依据。

列表项包含：

- `id`
- 管理端 owner 视图的 `systemAccountId/systemAccountName`
- `ownerSystemAccountId/ownerSystemAccountName`
- `name/providerCode/description/enabled/isDefault/groupType/schedulingPolicy`
- `accountStats`
- `accessType`
- authorized 行的 `groupAuthorizationId/authorizationStatus/authorizationExpiresAt/authorizationLimits`
- `permissions`
- `accountCount`
- 可选 `authorizationSourceSummary`

列表明确不返回：

- `accountIds`
- 完整 `authorizationSources`
- 账户详情
- `createdAt/updatedAt`
- 实时账号并发明细

`accountCount` 规则：

- owner 行使用预聚合 `accountStats.total`。
- authorized 行固定为 `0`。

`authorizationSourceSummary`：

- `activeSourceCount`：active 来源数量。
- `hasManual`：存在 active manual 来源。
- `hasTeam`：存在当前或历史 team 来源。
- `teamNames`：active team 来源的去重团队名。

## 统计与存储边界

列表请求路径禁止读取 `usage_records` 明细，禁止实时 `SUM/GROUP BY`，也禁止扫描 `group_accounts` 重新计算统计。

Go migration `000026` 必须先补当前 Node 正式统计结果表：

- `juhe_stats.group_account_stats`
- `juhe_stats.usage_stats_totals`
- `juhe_stats.usage_stats_daily`
- `juhe_stats.stats_job_state`

表结构、主键和索引按 Node 当前 PostgreSQL schema 精确迁移，不增加运行时兼容分支。`juhe_business.group_account_stats_dirty` 只是脏标记表，不能替代结果表。

列表批量读取：

- `group_account_stats`：按当前页 `group_id` 批量读取账户状态、可用数和并发摘要。
- `usage_stats_totals`：按单个 `system_account_id + scope_type` 与当前页 `scope_id[]` 批量读取累计用量。
- `usage_stats_daily`：增加当前 `usageStatsTimezone` 下的 `stat_date`，批量读取今日用量。
- 授权来源摘要：按当前页授权 ID 批量读取 source/team，不做 N+1。

用量 key：

| 视图 | `system_account_id` | `scope_type` | `scope_id` |
| --- | --- | --- | --- |
| owner group | 分组 owner | `group` | `group.id` |
| authorized group | 分组 owner | `group_authorization` | `authorization.id` |

`stat_date` 是按系统设置 `usageStatsTimezone` 生成的 `YYYY-MM-DD` 文本。统计行缺失时返回零摘要，不回扫明细；查询失败时返回通用 `500`，不能把依赖失败伪装成零值。

`UsageSummary` 需要补 Node 当前 `lastUsedAt` 字段；`totalTokens` 由 `inputTokens + outputTokens` 计算，不新增数据库列。

## 共存期与最终 worker

共存期：

- Go API 读取 PostgreSQL 统计结果表。
- Node stats worker 保持 `group_account_stats` 与 usage aggregation 的唯一 writer。
- Go 不消费同一 dirty 行，不推进同一 `stats_job_state` cursor。
- Node / Go 必须连接同一 PostgreSQL，使用一致的 `usageStatsTimezone`。

生产切流前必须验证 Node 写入后 Go 列表可见、统计 freshness 和失败边界。

独立 Go 接管前还必须迁移：

- group-account-stats dirty 增量 worker；
- usage aggregation cursor worker；
- 有界批次、幂等重试和事务推进 cursor；
- `__all__` 全量脏标记与离线重建；
- lag / freshness 观测；
- Node/Go 单 writer 切换与 Node stats worker 删除证据。

只完成列表读 API 不能下线 Node stats worker。

## 删除门禁

满足以下条件前不得删除 Node 分组列表：

- Go 两条列表路由完成实现与非 Docker 回归。
- fresh Go migrations 能创建列表依赖的统计结果表。
- 真实 PostgreSQL 中 owner/authorized、统计、来源摘要和分页 smoke 通过。
- 前端分组页连接真实 Go 后端 smoke 通过。
- 反向代理完成单 owner 切流和回滚验证。

满足以下条件前不得删除 Node stats worker：

- Go group-account-stats 与 usage aggregation worker 完成；
- 游标、重试、重建、lag/freshness 和单 writer 门禁通过；
- Node worker 入口、supervisor 和静态引用删除证据完成。
