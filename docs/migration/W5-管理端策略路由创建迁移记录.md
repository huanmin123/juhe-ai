# W5 管理端策略路由创建迁移记录

> 本文记录管理端与个人端策略路由创建接口的 Node 当前契约、Go opt-in 实现和删除门禁。当前代码已实现，但真实 PostgreSQL smoke 因本机 Docker 不可用而 `SKIP`；不表示生产流量已切到 Go，也不表示 Node 路由、repository 或测试可以删除。

## 基本信息

  - `POST /__aisys__/api/my-route-strategies`
- 当前 Node owner：`backend/src/modules/route-strategies/route-strategies.routes.ts`、`backend/src/storage/route-strategy.repository.ts`
- 目标 Go owner：`backend-go/internal/modules/managementroutestrategies/`、`backend-go/internal/httpapi/`、`backend-go/internal/store/postgres/`
- 当前状态：Go opt-in 已实现，真实依赖待复跑，未生产接管

## 权限与传输

- 管理端路由只允许 `admin` / `super_admin`；未传或传 `systemAccountId=all` 时使用当前管理员，传具体 ID 时为目标账户创建。
- 个人端强制使用当前 session 的系统账户 ID，忽略 query 中伪造的 `systemAccountId`。
- 管理端响应包含 `systemAccountId/systemAccountName`，个人端响应隐藏这两个字段。
- 两条路由都受 `JUHE_AI_MANAGEMENT_API_ENABLED` opt-in 保护，默认不注册。
- JSON body 上限为 `256 KiB`，只接受 JSON object；未知字段、错误类型、重复 query、空 owner 和非 `identity` 的 `Content-Encoding` 显式拒绝。
- 写请求经过鉴权前 IP write limiter、写鉴权与 session touch、已认证用户 write limiter 和 mutation guard；管理端在 mutation guard 前完成 admin 校验。

## 创建契约

目标系统账户只要求存在，不要求为 active。名称 trim 后不能为空，说明 trim 后为空时保存为 `null`。`mode` 缺省为 `normal`，`status` 缺省为 `active`；显式空字符串、零值或错误类型不能被当成未传。

支持五种模式：

- `normal`：必须且只能绑定一个 active 分组；只接受普通路由配置。
- `hybrid_smart`：至少一个 active 分组；必须提供完整、连续覆盖等级的混合评分配置。
- `weighted`：至少一个 active 分组；每个 weight 为 `1..100`。当前 Node 创建接口不强制至少两个分组，也不校验权重总和，Go 不额外发明限制。
- `failover`：至少两个绑定；按 priority 排序后的首个绑定必须 active，并至少有一个 active 备用绑定。
- `round_robin`：至少一个 active 分组。当前 Node 创建接口不强制至少两个分组。

所有模式共同要求：

- 最多 20 个绑定。
- group ID 不重复。
- active 绑定的 priority 不重复。
- priority 为正整数，weight 为 `1..100`，status 只允许 `active/disabled`。
- active 绑定不能指向已停用分组。
- 可绑定自有分组或有效授权给目标账户的分组。
- 同一目标账户下名称唯一，冲突返回 `409`。

## 授权与事务

授权分组读取必须在创建事务内完成。PostgreSQL 使用稳定顺序锁定：

1. `groups`
2. `resource_authorizations`
3. `group_authorization_settings`

查询通过依赖的 `MATERIALIZED` CTE 分阶段 `FOR UPDATE`，避免授权状态、到期时间或本地 enabled 设置在校验与写入之间变化。授权必须为 active、未过期，且目标账户的本地设置有效；否则按不可绑定分组处理。

策略主表与全部绑定在同一事务中写入。事务失败不返回部分结果，也不执行运行态失效。

## 写后副作用

事务提交后使用脱离客户端取消、最长 5 秒的 context best-effort 执行网关运行态失效，reason 固定为：

```text
route_strategy_created
```

失效失败只记录结构化 warning，不回滚已经提交的创建结果。

操作日志固定为：

- module：`route_strategies`
- action：`create`
- key：`route_strategies.create`
- summary：`创建策略路由：<name>`
- changes：`name/mode/status/groupBindings/normalRoutingConfig/hybridRoutingConfig`

说明字段不进入 changes，避免日志无界膨胀。管理端 viewer owner 使用目标账户，个人端使用当前账户。

## 前端契约证据

`frontend/scripts/regression/route-strategy-create-api-regression.ts` 固定：

- 管理端使用 POST 并只在需要时传 owner query。
- 个人端使用 `/my-route-strategies` 且不传 owner query。
- scoped delegation 不改变 body 契约。
- `normalRoutingConfig` 与 `hybridRoutingConfig` 的显式 `null` 保持 presence，不被请求层删除。

## 删除门禁

以下条件全部满足前，不能删除 Node 创建接口：

1. 健康 Docker/testcontainers 或独立环境中真实 PostgreSQL smoke 通过。
2. 前端策略路由创建页面连接真实 Go 后端完成管理 / 个人 smoke。
3. Node 与 Go 对当前 strict JSON、五模式、授权分组、重复名称、operation log 和失效契约的对照回归通过。
4. 反向代理按两条 POST 路径切到 Go 单 owner，并验证回滚。
5. 生产观测确认错误率、延迟、连接池和失效失败告警正常。
6. 删除对应 Node route/store/test 后提供 `rg` 静态证据。

## 当前结论

管理端策略路由创建已经形成 Go service、HTTP、router/app、PostgreSQL 事务复用、授权锁、前端 request-capture 和 integration smoke 代码。真实 PostgreSQL、前端真实 Go 后端联调、生产切流、回滚和 Node 删除仍未完成，因此状态保持 Go opt-in。
