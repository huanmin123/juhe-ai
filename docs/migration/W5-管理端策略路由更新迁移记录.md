# W5 管理端策略路由更新迁移记录

> 本文记录管理端与个人端策略路由更新接口的 Node 当前契约、Go opt-in 实现和删除门禁。当前代码、前端请求捕获和 PostgreSQL integration smoke 代码已完成，但本机 Docker 不可用，目标 smoke 输出 `SKIP`；不表示真实 PostgreSQL 已通过、生产流量已切到 Go，或 Node 路由与 repository 可以删除。

## 基本信息

- 接口：
  - `PATCH /__aisys__/api/route-strategies/{id}`
  - `PATCH /__aisys__/api/my-route-strategies/{id}`
- 当前 Node owner：`backend/src/modules/route-strategies/route-strategies.routes.ts`、`backend/src/storage/route-strategy.repository.ts`
- 目标 Go owner：`backend-go/internal/modules/managementroutestrategies/`、`backend-go/internal/httpapi/`、`backend-go/internal/store/postgres/`
- 当前状态：Go opt-in 已实现，真实依赖待复跑，未生产接管
- 关联计划：`../plans/计划-20260706T071505000Z-Node转Go渐进减法迁移.md`

## 权限与传输

- 管理端允许 `admin` / `super_admin` 全局按 ID 更新，也允许通过 `systemAccountId` 收窄目标 owner；普通用户返回 `403`。
- 个人端强制使用当前 session 的系统账户 ID，不属于当前用户或不存在的策略统一返回 `404 { "message": "策略路由不存在" }`。
- 管理端响应包含 `systemAccountId/systemAccountName`，个人端响应隐藏 owner 字段。
- 两条路由都受 `JUHE_AI_MANAGEMENT_API_ENABLED` opt-in 保护，默认不注册。
- JSON body 上限为 `256 KiB`；未知字段、错误类型、尾随 JSON、空 ID 和非 `identity` 的 `Content-Encoding` 显式拒绝。管理端严格校验 `systemAccountId` query；个人端忽略 query 中伪造、空白或重复的 owner 参数。
- 请求体传输语法在鉴权前解析；写请求经过鉴权前 IP write limiter、写鉴权与 session touch、已认证用户 write limiter。该接口按当前 Node 契约不增加进程内 mutation guard。
- handler 在完整业务 schema 校验前读取一次可见的更新前摘要，保证合法但不存在的请求返回 404，同时保持非法配置优先返回 400 的 Node 错误顺序。

## 局部更新契约

支持独立 presence 的字段：

- `name`
- `description`
- `mode`
- `status`
- `groupBindings`
- `normalRoutingConfig`
- `hybridRoutingConfig`

名称 trim 后不能为空；说明 trim 后为空保存为 `null`。空对象返回 `400 { "message": "策略路由参数无效" }`；至少存在一个合法字段但归一化后不产生实际变化的请求返回当前详情，不制造额外数据库变更。

模式和绑定规则与创建接口保持同一当前契约：

- `normal`：必须且只能绑定一个 active 分组。
- `hybrid_smart`：至少一个 active 分组，并要求完整、连续覆盖等级的混合评分配置。
- `weighted`：至少一个 active 分组，每个 weight 为 `1..100`；不额外要求至少两个分组或权重和为 100。
- `failover`：至少两个绑定，首个优先级绑定 active，并至少有一个 active 备用绑定。
- `round_robin`：至少一个 active 分组；不额外要求至少两个分组。

所有显式提交的 `normalRoutingConfig` 与 `hybridRoutingConfig` 都先执行完整独立校验，再按最终模式决定持久化投影。`cost_first` 不会跳过显式 `speedFirstConfig` 的结构校验。绑定最多 20 个，group ID 不重复，active priority 不重复；active 绑定不能指向停用分组，只能使用目标 owner 自有分组或当前有效授权分组。

## 事务与并发

- 目标策略行、目标 owner 和当前绑定在同一 PostgreSQL 事务内读取并锁定。
- 授权分组读取复用稳定的 `groups -> resource_authorizations -> group_authorization_settings` 锁顺序。
- 更新前详情、名称唯一性判断、配置归一化、策略主表更新和绑定整体替换都基于事务内锁定快照。
- 绑定替换失败、唯一约束失败或 commit 失败时不返回部分更新，也不执行运行态失效。
- 提交失败后的响应不能带出未提交的新详情。

## 写后副作用

事务提交后 best-effort 发布网关运行态失效，reason 固定为：

```text
route_strategy_updated
```

失效失败只记录结构化 warning，不回滚已经提交的业务结果。跨进程 Node 网关消费该 topic 时还必须清理普通路由 speed-first 延迟降级运行态；该运行态互操作需要独立回归和生产观测，不能由本接口单元测试替代。

操作日志固定为：

- module：`route_strategies`
- action：`update`
- key：`route_strategies.update`
- summary：`更新策略路由：<name>`
- changes：`name/description/mode/status/groupBindings/normalRoutingConfig/hybridRoutingConfig`

`groupBindings` 只记录业务字段，不记录内部 binding ID；配置 changes 使用规范化后的安全 JSON。管理端 viewer owner 使用目标账户，个人端使用当前账户。operation log 入队失败不覆盖业务成功。

## 前端契约证据

`frontend/scripts/regression/route-strategy-create-api-regression.ts` 同时固定创建与更新请求契约，其中更新部分覆盖：

- 管理端显式 owner 更新传 `systemAccountId`，scoped delegation 保持同一 owner query；全局省略 query 的行为由 Go HTTP/service 测试覆盖。
- 个人端使用 `/my-route-strategies/{id}` 且不传 owner query。
- scoped delegation 不改变 PATCH body。
- `description`、`normalRoutingConfig` 和 `hybridRoutingConfig` 的显式 `null` 保持 presence，不被请求层删除。

## 删除门禁

以下条件全部满足前，不能删除 Node 更新接口：

1. 健康 Docker/testcontainers 或独立环境中真实 PostgreSQL smoke 通过。
2. Node 发布 `route_strategy_updated` 与 Go 发布同一 topic 后，跨进程普通路由 speed-first 运行态失效回归和真实 Redis 观测通过。
3. 前端策略路由编辑页连接真实 Go 后端完成管理 / 个人 smoke；临时资源创建和清理流程必须安全。
4. Node 与 Go 对 strict partial JSON、五模式、授权分组、错误优先级、operation log 和失效契约的对照回归通过。
5. 反向代理按两条 PATCH 路径切到 Go 单 owner，并验证回滚。
6. 生产观测确认错误率、延迟、连接池、锁等待和失效失败告警正常。
7. 删除对应 Node route/store/test 后提供 `rg` 静态证据。

## 当前结论

管理端策略路由更新已经形成 Go service、HTTP、router/app、PostgreSQL 事务、前端 request-capture 和 integration smoke 代码。真实 PostgreSQL、前端真实 Go 后端联调、跨进程运行态真实 Redis 验证、生产切流、回滚和 Node 删除仍未完成，因此状态保持 Go opt-in。
