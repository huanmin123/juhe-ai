## 2. 开发环境目标

迁移完成后的本地开发依赖：

- 迁移时重新确认的最新稳定 Go 版本。
- pnpm 继续用于前端 Vue 3 构建和类型检查。
- PostgreSQL 是唯一事实库。
- Redis 是唯一短 TTL cache、运行态 state 和队列基础设施。
- PowerShell 7 作为 Windows 默认命令示例。

目标命令示例：

```powershell
go version
go test ./...
go test ./... -race
go run ./cmd/juhe-ai server
go run ./cmd/juhe-ai-worker stats
go build -o .\dist\juhe-ai.exe .\cmd\juhe-ai
pnpm --filter juhe-ai-frontend build
```

命令名称以实际 Go 目录落地为准；落地前不要把这些示例写入当前运行手册的正式启动步骤。

## 3. 过渡运行方式

渐进迁移需要一段过渡期，但必须保持单 owner：

- 按路径或模块分流时，同一路径只允许 Node 或 Go 其中一个处理。
- Go 接管某个路径后，Node 对应 route/service 必须删除。
- 过渡入口可以是本地开发代理、测试环境反向代理或 Go edge server，但不能成为长期双后端架构。
- 生产切换前，每个已迁移模块必须有独立 smoke 和删除证据。

推荐过渡顺序：

1. Node 继续承载未迁移路径，Go 先承载公开接口。
2. Go 扩展到后台读接口和写接口。
3. Go 接管 worker 和存储 owner，删除 DB service。
4. Go 接管网关，Node 后端退出。

## 4. 构建目标

最终发布包应收敛为：

```text
release/
  juhe-ai(.exe)
  juhe-ai-worker(.exe)        # 如保留独立 worker 命令
  frontend-dist/
  .env.example
  scripts/
  docs/
```

构建规则：

- 前端继续用 Vite 构建静态资源。
- 后端用 `go build` 生成平台二进制。
- Go 后端不引入 SQLite driver，构建流程不再包含 SQLite / CGO 发布差异。
- 发布包不再包含 Node 后端 `dist/`、`node_modules` 或 TypeScript 后端编译产物。
- 后端 Node engine 约束在最终收尾阶段删除；前端构建仍保留 Node / pnpm 要求。

## 5. Docker 目标

最终 Docker 构建应使用多阶段：

1. Node/pnpm 阶段构建前端。
2. Go 阶段构建后端二进制。
3. runtime 阶段只复制 Go 二进制、前端静态资源、配置示例和必要证书/时区数据。

Docker 文档需要重新确认：

- PostgreSQL 数据卷、初始化、备份和恢复。
- Redis cache / state / queue 连接、持久化边界和容量配置。
- 健康检查路径。
- 代理访问宿主机的方式。
- 日志输出和文件保留策略。

## 6. 常驻运行目标

Linux、Windows、macOS 的服务化文档需要在 Go 后端落地后同步调整：

- Linux：systemd 直接运行 Go 二进制，配置 `Restart=on-failure`、工作目录、环境文件和健康检查。
- Windows：PowerShell 启动脚本或 Windows Service 运行 Go `.exe`，保留数据目录和日志目录。
- macOS：launchd 运行 Go 二进制，保留工作目录、环境变量和日志路径。
- watchdog：继续只负责主服务整体不可用恢复；Go 内部 worker lifecycle 由主程序或进程管理策略看护。

## 7. 配置与数据

- 产品级环境变量名称尽量保持稳定，例如端口、PostgreSQL、Redis、代理和密钥相关配置。
- Node 专用环境变量、Node 版本预检、`node:sqlite` 预检和 `tsx` 开发命令在最终阶段删除。
- SQLite 路径类环境变量、usage shard 根目录、standalone / performance 模式开关在最终阶段删除。
- 本地数据仍按当前 schema 处理；迁移期间如果 schema 调整，源码只保留当前 schema，既有数据由离线脚本或人工方案处理。
- 数据备份、恢复和迁移说明必须覆盖 PostgreSQL 事实库、Redis 可丢弃运行态 / 队列边界，以及从旧 SQLite 数据域离线导出到 PostgreSQL 的一次性路径。

## 8. 回滚边界

减法迁移不保留同一模块的长期双实现，因此回滚应以发布包和数据备份为单位：

- 模块生产切换前，保留上一版可运行发布包和数据备份。
- 切换失败时，停止当前版本，恢复同一数据契约下的上一版发布包和配置。
- 如果 schema 已按当前最优方案调整，不能依赖运行时代码自动回滚旧 schema；必须有明确的离线恢复或重新初始化方案。
- 网关迁移阶段必须有单独的灰度、压测、真实上游 smoke 和快速停止方案。
