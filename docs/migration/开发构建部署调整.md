## 2. 开发环境目标

迁移完成后的本地开发依赖：

- 迁移时重新确认的最新稳定 Go 版本。
- pnpm 继续用于前端 Vue 3 构建和类型检查。
- PostgreSQL 是唯一事实库。
- Redis 是唯一短 TTL cache、运行态 state 和队列基础设施；cache / state / queue 必须使用不同 DB 或不同实例，并统一使用 `JUHE_AI_REDIS_NAMESPACE` 管理 key 前缀。
- PowerShell 7 作为 Windows 默认命令示例。

目标命令示例：

```powershell
Set-Location backend-go
go version
go test ./...
go test ./... -race
go test -tags=integration ./...
goose -dir db/migrations postgres $env:JUHE_AI_POSTGRES_URL up
go run ./cmd/juhe-ai server
go run ./cmd/juhe-ai-worker stats
go build -o .\dist\juhe-ai.exe .\cmd\juhe-ai
go run ./cmd/juhe-ai-maintenance w0-smoke
go run ./cmd/juhe-ai-maintenance w1a-public-settings-smoke
go run ./cmd/juhe-ai-maintenance w1b-public-api-smoke
Set-Location ..
pnpm --filter juhe-ai-frontend build
```

当前仓库根目录没有 `go.work`，Go 命令必须在 `backend-go/` 下执行，或显式使用 `go -C backend-go ...`。命令名称以实际 Go 目录落地为准；落地前不要把这些示例写入当前运行手册的正式启动步骤。

当前 W1a Go server 启动路径已经依赖 `JUHE_AI_POSTGRES_URL` 和 `JUHE_AI_REDIS_STATE_URL`：PostgreSQL 承载公开设置和系统设置，Redis state 承载系统 API IP 读限流。缺少 Redis state 时 server 应 fail-fast，不能静默退回进程内限流作为生产路径。

当前 W1b `/__aipublic__` 生产挂载由 `JUHE_AI_PUBLIC_API_ENABLED` 控制，默认必须保持 `false`。显式设置为 `true` 时，Go 主 server 才会注册 `/__aipublic__` 和 `/__aipublic__/*`；同时要求 `JUHE_AI_POSTGRES_URL`、`JUHE_AI_REDIS_STATE_URL`、`JUHE_AI_REDIS_QUEUE_URL`、不少于 32 字符的 `JUHE_AI_SECRET`、当前 Go migration 和 `juhe-ai-worker ingest` 均已准备好。该开关只用于灰度验证，不等于 W1b 正式接管；回滚优先关闭该开关并恢复反向代理 owner。

当前 W2 `GET /__aisys__/api/proxies/options`、`GET /__aisys__/api/system-accounts/options`、`GET /__aisys__/api/authorization-options/grantee-accounts`、`GET /__aisys__/api/my-authorization-options/grantee-accounts`、`GET /__aisys__/api/authorization-options/grantee-groups`、`GET /__aisys__/api/my-authorization-options/grantee-groups`、`GET /__aisys__/api/providers/options`、`GET /__aisys__/api/providers/models/options`、`GET /__aisys__/api/providers/{code}/models`、`GET /__aisys__/api/route-strategies/options`、`GET /__aisys__/api/my-route-strategies/options`、`GET /__aisys__/api/groups/options`、`GET /__aisys__/api/my-groups/options`、`GET /__aisys__/api/groups/account-options`、`GET /__aisys__/api/my-groups/account-options`、`GET /__aisys__/api/accounts/options`、`GET /__aisys__/api/my-accounts/options`、`GET /__aisys__/api/accounts/tags` 和 `GET /__aisys__/api/my-accounts/tags` 已完成 Go schema / 既有表复用、store / service / handler、`requireAuth` 级会话鉴权基线，以及 admin / self 作用域；其中系统账户 options 已覆盖 admin-only 轻量字段白名单，authorization grantee accounts / grantee groups 已覆盖 admin / my 双路径轻量字段白名单，分组 options / account-options 已覆盖 owner + 授权组只读 union，账户 options 已覆盖 owner + 授权账户只读 union、owner `tagIds` 过滤和名称包含搜索，账户 tags 仍是 owner-only 只读。生产 server 由 `JUHE_AI_MANAGEMENT_API_ENABLED` 控制，默认必须保持 `false`；显式设置为 `true` 时，Go 主 server 才会注册当前已迁移 W2 后台只读路由，并且必须先经过 `juhe_ai_session` -> `system_sessions.token_hash` 的管理端会话鉴权。该开关只用于灰度验证，不等于 W2 正式接管；系统账户完整管理、authorization grantee teams、授权来源 / grant / 授权写接口和标签写接口仍未迁移，不要通过反向代理绕过 Node 当前 owner，也不能据此删除 Node 对应后台 route / service。

W1b 真实依赖灰度验证入口是 `go run ./cmd/juhe-ai-maintenance w1b-public-api-smoke`。该命令要求 PostgreSQL、Redis state、Redis queue、`JUHE_AI_SECRET` 和已启动的 `juhe-ai-worker ingest`，通过本地 `httptest` 验证默认 router guard、显式 opt-in mount、临时内置测试 token、真实 public API log 入队和 worker 写 PG。它不启动生产 HTTP 监听端口，输出中 `takeoverEvidence=false`；通过不代表反向代理已切流，也不代表 Node `/__aipublic__` 可删除。

如部署在 Caddy / Nginx / 隧道之后，必须显式配置 `JUHE_AI_TRUST_PROXY`；未启用时 IP 限流按 Go server 直连 socket 地址计数，可能只看到反代出口。开启后 diagnostics 的 loopback 判断也使用解析后的客户端 IP，避免公网请求经本机反代误入 metrics / pprof。

W1a 真实依赖验证入口是 `go run ./cmd/juhe-ai-maintenance w1a-public-settings-smoke`。该命令验证真实 PostgreSQL 公开设置 / 限流设置读取、HTTP route 响应和 Redis state 限流路径，不能用普通 health 的 `skipped` 状态替代。

Go 健康检查返回 HTTP 200 时，JSON 中仍可能是 `status=degraded`。部署 smoke、反向代理健康检查和 watchdog 不能只看 HTTP 状态码，必须解析 `success`、`status` 和 `dependencies`。`/__aisys__/metrics` 与 `/__debug/pprof` 只属于受控诊断入口，默认由 loopback / 反代规则保护，不能作为公网 API 暴露。

PowerShell 健康检查示例：

```powershell
$h = Invoke-RestMethod http://127.0.0.1:3000/__aisys__/health
if (-not $h.success -or $h.status -ne 'ok') { throw ($h | ConvertTo-Json -Depth 8) }

$api = Invoke-RestMethod http://127.0.0.1:3000/__aisys__/api/health
if (-not $api.success -or $api.status -ne 'ok') { throw ($api | ConvertTo-Json -Depth 8) }
```

系统指标迁移的部署边界见 [Go 迁移指标与观测规划](Go迁移指标与观测规划.md)：迁移完成后系统监控必须改用 Go runtime、PG/Redis/Asynq、worker lag 和统计新鲜度指标，不再用 Node `eventLoopLagMs`、`db-service` 或 SQLite 文件体积判断 Go 服务健康。

## 3. 过渡运行方式

渐进迁移需要一段过渡期，但必须保持单 owner：

- 按路径或模块分流时，同一路径只允许 Node 或 Go 其中一个处理。
- Go 接管某个路径后，Node 对应 route/service 必须删除。
- 过渡入口可以是本地开发代理、测试环境反向代理或 Go edge server，但不能成为长期双后端架构。
- 生产切换前，每个已迁移模块必须有独立 smoke 和删除证据。
- W1b `JUHE_AI_PUBLIC_API_ENABLED=true` 只允许用于显式灰度；同一公网 `/__aipublic__/*` 不能同时由 Node 和 Go 作为正式 owner。
- W1b `w1b-public-api-smoke` 只作为本地 httptest + 真实依赖灰度验证，不能替代真实监听端口、反向代理切流、生产流量观测和 Node 删除证据。
- W2 `JUHE_AI_MANAGEMENT_API_ENABLED=true` 只允许用于显式灰度；同一公网 `/__aisys__/api/proxies/options`、`/__aisys__/api/system-accounts/options`、`/__aisys__/api/authorization-options/grantee-accounts`、`/__aisys__/api/my-authorization-options/grantee-accounts`、`/__aisys__/api/authorization-options/grantee-groups`、`/__aisys__/api/my-authorization-options/grantee-groups`、`/__aisys__/api/providers/options`、`/__aisys__/api/providers/models/options`、`/__aisys__/api/providers/{code}/models`、`/__aisys__/api/route-strategies/options`、`/__aisys__/api/my-route-strategies/options`、`/__aisys__/api/groups/options`、`/__aisys__/api/my-groups/options`、`/__aisys__/api/groups/account-options`、`/__aisys__/api/my-groups/account-options`、`/__aisys__/api/accounts/options`、`/__aisys__/api/my-accounts/options`、`/__aisys__/api/accounts/tags` 或 `/__aisys__/api/my-accounts/tags` 不能同时由 Node 和 Go 作为正式 owner，且 Go 入口必须保留管理端会话鉴权 middleware；系统账户 options 只覆盖轻量只读下拉，不覆盖系统账户完整管理；authorization grantee accounts / grantee groups 只覆盖用户授权对象候选和授权目标分组候选，不覆盖 grantee teams 或授权写接口；分组 options / account-options 已覆盖 owner + 授权组只读 union，账户 options 已覆盖 owner + 授权账户只读 union，但不覆盖授权来源 / grant / 授权写接口；账号标签只读接口不覆盖标签写接口。

推荐过渡顺序：

1. Node 继续承载未迁移路径，Go 先承载公开接口。
2. Go 扩展到后台读接口和写接口。
3. Go 接管 worker 和存储 owner，删除 DB service。
4. Go 接管网关，Node 后端退出。

## 4. 构建目标

最终发布包应收敛为：

```text
release/
  juhe-ai(.exe)
  juhe-ai-worker(.exe)        # 如保留独立 worker 命令
  frontend-dist/
  .env.example
  scripts/
  docs/
```

构建规则：

- 前端继续用 Vite 构建静态资源。
- 后端用 `go build` 生成平台二进制。
- Go 后端不引入 SQLite driver，构建流程不再包含 SQLite / CGO 发布差异。
- 发布包不再包含 Node 后端 `dist/`、`node_modules` 或 TypeScript 后端编译产物。
- 后端 Node engine 约束在最终收尾阶段删除；前端构建仍保留 Node / pnpm 要求。

## 5. Docker 目标

最终 Docker 构建应使用多阶段：

1. Node/pnpm 阶段构建前端。
2. Go 阶段构建后端二进制。
3. runtime 阶段只复制 Go 二进制、前端静态资源、配置示例和必要证书/时区数据。

Docker 文档需要重新确认：

- PostgreSQL 数据卷、初始化、备份和恢复。
- Redis cache / state / Asynq queue 连接、持久化边界和容量配置。
- 健康检查路径。
- 代理访问宿主机的方式。
- 日志输出和文件保留策略。

最终 Docker 目标必须收敛为 PostgreSQL + Redis 默认运行方式：当前 Node standalone 的单容器 Compose、SQLite volume、Node entrypoint 和 `check-node-sqlite` 只作为迁移前事实保留；W11 收尾时应决定是否把当前 `compose.performance.yml` 升级为默认 Compose，并删除 standalone env 语义。

## 6. 常驻运行目标

Linux、Windows、macOS 的服务化文档需要在 Go 后端落地后同步调整：

- Linux：systemd 直接运行 Go 二进制，配置 `Restart=on-failure`、工作目录、环境文件和健康检查。
- Windows：PowerShell 启动脚本或 Windows Service 运行 Go `.exe`，保留数据目录和日志目录。
- macOS：launchd 运行 Go 二进制，保留工作目录、环境变量和日志路径。
- watchdog：继续只负责主服务整体不可用恢复；Go 内部 worker lifecycle 由主程序或进程管理策略看护。

服务化文档必须按最终进程拓扑分别覆盖 `server`、`ingest-worker`、`stats-worker`、`ops-worker` 和 maintenance 命令，说明健康检查、重启退避、shutdown drain 和 worker lag 观测；如果选择由 server 看护 worker 子进程，也必须在各平台文档中写清楚被看护进程、退出码和重启上限。

watchdog 的 Go 目标规则：

- 连续失败阈值基于 health JSON，而不是 HTTP 200。
- 只在本地服务整体不可用或关键依赖持续不可用时重启 juhe-ai；公网域名、证书、上游模型、单个账号或队列积压不能直接触发整栈重启。
- CPU 高、GC 抖动、队列积压或统计滞后优先告警和记录指标，不自动重启。
- watchdog 日志必须记录 health JSON 摘要、失败次数、冷却时间、PID 和重启结果。

## 7. 配置与数据

- 产品级环境变量名称尽量保持稳定，例如端口、PostgreSQL、Redis、代理和密钥相关配置。
- Node 专用环境变量、Node 版本预检、`node:sqlite` 预检和 `tsx` 开发命令在最终阶段删除。
- SQLite 路径类环境变量、usage shard 根目录、standalone / performance 模式开关在最终阶段删除。
- 本地数据仍按当前 schema 处理；迁移期间如果 schema 调整，源码只保留当前 schema，既有数据由离线脚本或人工方案处理。
- 数据备份、恢复和迁移说明必须覆盖 PostgreSQL 事实库、Redis 可丢弃运行态 / 队列边界，以及从旧 SQLite 数据域离线导出到 PostgreSQL 的一次性路径。

环境变量删除矩阵：

| 类型 | 最终状态 |
| --- | --- |
| 端口、host、secret、cookie、安全和代理配置 | 保留或按 Go 命名收敛 |
| `JUHE_AI_POSTGRES_URL`、Redis cache/state/Asynq queue URL、`JUHE_AI_REDIS_NAMESPACE` | 保留为正式配置；Go 配置层拒绝 Redis cache / state / queue 指向同一个 Redis DB |
| `JUHE_AI_PUBLIC_API_ENABLED` | W1b 迁移期保留为 Go 主 server `/__aipublic__` opt-in guard，默认 `false`；正式接管完成并删除 Node 后，再决定是否保留为安全开关 |
| `JUHE_AI_MANAGEMENT_API_ENABLED` | W2 迁移期保留为 Go 主 server `/__aisys__/api/*` 管理端只读 opt-in guard，默认 `false`；显式开启只允许灰度验证已迁移路径，不能绕过会话鉴权或代表正式接管 |
| `JUHE_AI_SECRET` | 保留为敏感数据加密和签名密钥；开启 Go W1b public API 时必须显式配置且不少于 32 字符，AI 账户上游凭据依赖它稳定解密 |
| `JUHE_AI_DATABASE_PATH`、dataset / stats / usage catalog 路径、usage shard root | 删除；Go 启动遇到这些旧变量应告警或 fail-fast，避免误以为 SQLite 可用 |
| `JUHE_AI_RUNTIME_MODE`、`JUHE_AI_DATABASE_DRIVER`、`JUHE_AI_CACHE_DRIVER`、`JUHE_AI_RUNTIME_STATE_DRIVER`、`JUHE_AI_QUEUE_DRIVER` | 删除双模式开关；Go 只有 PG/Redis 正式模式 |
| `JUHE_AI_DB_SERVICE_*`、`JUHE_AI_PROCESS_ROLE`、Node preflight 相关变量 | 随 DB service / Node worker 删除 |

## 8. 回滚边界

减法迁移不保留同一模块的长期双实现，因此回滚应以发布包和数据备份为单位：

- 模块生产切换前，保留上一版可运行发布包和数据备份。
- 切换失败时，停止当前版本，恢复同一数据契约下的上一版发布包和配置。
- 如果 schema 已按当前最优方案调整，不能依赖运行时代码自动回滚旧 schema；必须有明确的离线恢复或重新初始化方案。
- 网关迁移阶段必须有单独的灰度、压测、真实上游 smoke 和快速停止方案。
