## 当前切片

本切片只包含：

- `PATCH /__aisys__/api/groups/{id}`
- `PATCH /__aisys__/api/my-groups/{id}`

两条路径只在 `JUHE_AI_MANAGEMENT_API_ENABLED=true` 且完整注入管理鉴权、PostgreSQL store、shared cache invalidator 和 gateway runtime invalidator 时注册。请求使用 strict partial JSON，body 上限为 `256 KiB`；空对象、未知字段和类型错误均返回 `400`。JSON transport parser 位于 system API IP limiter 后、写鉴权 touch 和 authenticated user limiter 前；非法 JSON / 超限 body 因此在鉴权前返回 `400` / `413`，但仍消耗 IP limiter 窗口。

本切片不包含分组删除、前端生产入口切换、生产单 owner 切流或 Node 路由删除。

## 权限与字段边界

- `/groups/{id}` 只允许 `admin` / `super_admin`；省略 `systemAccountId` 或使用 `all` 时进入全局 owner 管理作用域，指定账户时按该账户可见的 owner / authorized 关系更新。
- `/my-groups/{id}` 强制当前 session 账户作用域，不接受 query 参数扩大作用域；真实 actor role 保留在操作日志中。
- 路径 `{id}` 保持原值查询，不做 trim。
- owner 可更新名称、描述、供应商、启用状态、分组类型和调度策略。
- authorized grantee 只能更新本地 `enabled`、`groupType` 和 `schedulingPolicy`；修改 owner 字段返回明确的 `400`。
- 默认分组保持只读。
- provider 先做存在性校验，再查目标分组，保持 Node 的错误优先级。
- 名称唯一冲突按最终合并后的名称返回。

调度策略按锁后读取到的当前分组类型与完整策略合并：切换到 `personal` 清空策略，从 `personal` 切换到 `high_concurrency` 且未显式提交策略时使用当前完整默认策略，原本已是 `high_concurrency` 且未提交策略时保留现有策略；显式策略只接受当前 5 个可写字段及固定范围。

## 存储与并发边界

- owner 更新在单个 PostgreSQL 事务中锁定目标分组和相关绑定。
- provider 变化时，只允许分组没有当前有效绑定账户；已删除、禁用或授权失效的账户不构成阻断。
- owner 禁用分组时检查所有 owner / grantee 作用域中的有效路由策略绑定。
- authorized grantee 禁用本地分组时只检查当前 grantee 的有效路由策略绑定。
- 路由策略保护查询固定 `LIMIT 101`；超过 100 条时拒绝更新，避免请求路径无界读取。
- authorized 本地设置使用 `group_authorization_settings` upsert，不修改 owner 分组记录。
- migration `000032_w5_authorized_group_route_bindings.sql` 允许授权账户把可见分组绑定到自己的路由策略，同时用复合外键保持 owner 关系完整。
- 成功写入后重新读取完整详情，保证 owner / authorized 响应与详情接口一致。
- PATCH 不增加进程内 mutation guard；Node 当前 group PATCH 也未使用该 guard。重复提交和跨进程并发以 PostgreSQL 行锁、唯一约束和事务内锁后重算为准。

## 写后副作用

- owner 更新递增 `lookup:group` shared cache version，并发布 runtime reason=`group_updated`。
- authorized 本地设置不改 owner 分组 lookup，只发布 runtime reason=`group_authorization_settings_updated`。
- 成功请求 best-effort 写入 operation key=`groups.update`；失败写入不产生日志。
- cache、runtime 和 operation log 副作用均在数据库提交后执行，不把外部依赖失败伪装成数据库回滚。
