# F1：运行日志索引与保留（Go 直接完整接管）

> 决策日期：2026-08-09。本文记录当前工作区的直接接管规则；历史的 Node/Go owner 开关、灰度、双写和 Node 回退流程均不再适用于 F1。

## 结论

F1 是首个完整迁移单元。常驻 Go `jobs` 项目的 `projects/jobs/internal/runtimelog` 直接、唯一地承担运行日志文件发现、JSONL 解析、索引写入、cursor、facet 和保留清理。Node 的 F1 importer、scheduler、retention、writer、cursor 和 schema 初始化已从活跃源码移除，原文件及专属 Node 回归已整体归档至 [migration-backup/node/runtime-log-index-retention](../../migration-backup/node/runtime-log-index-retention)。F1 独立持有 Store、schema 和 owner lease，并与 gateway 项目独立部署。

Node 只保留两类不属于 F1 owner 的能力：

- 仍未迁移 Node 功能产生 JSONL 日志与常规文件轮转；
- runtime-logs routes、grep 和只读 query repository 读取 Go 产生的表，继续服务现有管理页面。

## 完整功能边界

输入是 Node 已落盘的 JSONL 文件；输出是 runtime_logs、runtime_log_file_cursors、facet 表及完成后可删除的轮转文件。F1 不改变网关请求、账户状态、供应商调用、业务主流程或管理 HTTP 路由。

Go 在 sqlite 与 postgres 两种存储模式下均可启动：

- SQLite：Go 直接持有 F1 专用 `JUHE_AI_RUNTIME_LOG_DATABASE_PATH` 文件的唯一写入权，启动时强制 `journal_mode=WAL` 和 `busy_timeout=5000`；业务库只读读取 runtimeLogIndexRetentionDays，Node 只读 F1 专用库；
- PostgreSQL：Go 直接向 juhe_dataset 事务写入，业务设置从 juhe_business.system_settings 只读读取；Redis 不参与 F1。

同一轮 `RunOnce` 按既有发现排序逐文件导入，不为每个日志文件创建 goroutine：所有文件提交都会校验同一 F1 owner lease，PostgreSQL 下并发事务会争用同一 lease 行并造成无收益的锁等待。该串行边界不引入 Redis Stream、Asynq、任务队列、常驻通用 worker pool 或迁移层业务限速。SQLite 仍遵守单连接、单 writer；PostgreSQL 仍遵守连接池与事务边界。Kubernetes 的 juhe-ai 运行契约通过 `JUHE_AI_RUNTIME_LOG_POLL_INTERVAL=5s` 限制周期扫描；源码未配置该变量时的通用默认值不因此改变。

SQLite 的 F1 事实库固定为独立的 `JUHE_AI_RUNTIME_LOG_DATABASE_PATH`，不得与 Node 的业务、数据集目录、usage catalog、stats、Codex Context shard，或 F2 的 `JUHE_AI_TABLE_MONITOR_DATABASE_PATH` 指向同一个物理文件，即使路径名称不同或通过 hard link/symlink 指向同一文件。Go 正常 indexer 只打开专用运行日志库和业务设置只读库；其他 Node SQLite 路径与 shard root 仅用于启动时的物理冲突验证。Node 只读专用运行日志库，继续独占业务数据集中的审计、操作日志、公开接口日志和模型检测写入。路径缺失、路径冲突或 Go 尚未建表时必须显式失败，不能回退 dataset 或返回伪空结果。

### 旧 SQLite 数据一次性迁移

已有 Node F1 索引数据必须在首次启动 Go indexer 前离线迁移：停止 Node 和 Go indexer，保留原 dataset 文件作为回滚对照，再使用同一个 Go 二进制执行下列命令。该命令不是运行期开关，正常常驻 indexer 不会自动读取、附加或复制旧 dataset。

```powershell
go run ./projects/jobs/cmd/juhe-ai-jobs --migrate-runtime-log-legacy-sqlite
```

迁移命令要求 F1、F2 与全部 Node SQLite owner 路径均已配置，拒绝同文件路径，预检源库完整性和所有 F1 表；复制后逐表校验数量、主键和字段值，并执行目标库 `integrity_check`。任一步失败都保留源文件和目标文件供排查，不启动常驻 indexer，也不得改由 Node F1 接手。

## 唯一写入保证

runtime_log_index_owner_leases 是 Go 内部多实例协调表，不是 Node/Go 切换开关。lease 带单调 fence_token：Go 在每个 SQLite 或 PostgreSQL 写事务中同时校验 owner、token 与未过期 lease；失租的旧进程不能提交 records、cursor、facet 或 cleanup。它不提供 Node 回退路径，因为 Node F1 活跃实现已删除。

## 归档与恢复

归档清单、原始路径、SHA-256 和恢复方式见 [manifest.json](../../migration-backup/node/runtime-log-index-retention/manifest.json)。恢复只能从归档整体恢复 Node F1，不能挑出单个函数重新接入活跃 Node 路径。

### PostgreSQL adapter 真实 smoke

在 `backend-go` 工作目录执行。`JUHE_AI_RUNTIME_LOG_POSTGRES_SMOKE_URL` 必须是专用、可销毁的 PostgreSQL 数据库，并且运行前 `juhe_dataset` 中所有 F1 表必须为空。测试会先初始化并检查 schema，真实验证 owner lease/fence、record、cursor、facet 和保留清理，再经 adapter 清理测试数据；不得把生产、共享或非空数据库用于该命令。

```powershell
$env:JUHE_AI_RUNTIME_LOG_POSTGRES_SMOKE_URL = 'postgres://<user>:<password>@<host>:5432/<database>?sslmode=disable'
$env:JUHE_AI_RUNTIME_LOG_POSTGRES_SMOKE_REQUIRED = 'true'
rtk go test -race ./projects/jobs/internal/runtimelog -run '^TestPostgresRuntimeLogAdapterSmoke$' -count=1
```

缺少 URL 且未强制时为显式 `skipped`，不是通过；`JUHE_AI_RUNTIME_LOG_POSTGRES_SMOKE_REQUIRED=true` 时缺 URL，以及 URL 无法连接、schema 或断言失败，都会失败。
