## HTTP 契约

### 共用边界

| 项 | 内容 |
| --- | --- |
| 路径 | `GET /__aisys__/api/settings`、`PATCH /__aisys__/api/settings` |
| 启用条件 | 仅在 `JUHE_AI_MANAGEMENT_API_ENABLED=true` 时注册 |
| 登录态 | 必须携带有效管理端 session |
| 权限 | 只允许 `admin` / `super_admin`；普通 `user` 返回 `403` |
| 响应 | 成功时返回 `{ "data": { ...完整系统设置... } }` |
| 缓存头 | 保持 system API 全局 `Cache-Control: no-store` |

### GET

- 使用只读 session 鉴权，不 touch `system_sessions.last_seen_at`。
- 进入 IP read 每分钟 / 10 秒 burst 和 authenticated user read limiter。
- 中间件顺序固定为 system API IP read limiter -> 只读 session 鉴权 -> authenticated user read limiter -> handler；GET 不经过 JSON parser，也不使用 touch 鉴权。
- 只读取 `juhe_business.system_settings` 中 `system_account_id='sys_admin'` 且位于当前白名单的行。
- 必须返回全部白名单字段；缺字段、重复字段、未知字段、非法 JSON 或非法值统一视为服务端存储错误，对外返回通用 `500`。
- 查询和响应都不包含内部固定常量，例如 data-retention worker 的批大小、批次数或固定启用标记。

### PATCH

- 使用写 session 鉴权并按现有 60 秒规则 touch 当前 session。
- 进入 IP write 每分钟 / 10 秒 burst 和 authenticated user write limiter。
- 中间件顺序固定为 system API IP write limiter -> `256 KiB` JSON parser -> 写 session 鉴权 / touch -> authenticated user write limiter -> handler。malformed JSON 或超限 body 会在 auth、touch 和用户 limiter 前分别返回 `400` / `413`，但仍已经过 IP limiter。
- 请求体必须是单个 JSON object，最大 `256 KiB`，至少包含一个白名单字段；拒绝未知字段、`null`、错误类型、空对象、顶层非对象和尾随 JSON。
- 请求体超过上限时返回 `413 { "message": "请求体过大" }`；其他 body 结构错误返回 `400`。
- 整数字段必须是 JSON 整数并满足对应闭区间；不接受浮点数、字符串数字、布尔值或自动截断。
- 成功响应返回事务提交后的完整系统设置快照，而不是只返回本次提交字段。
- Go 目标运行时只有 PostgreSQL，因此任何包含 `usageStatsTimezone` 的在线 PATCH 都返回 `400`：
  `PostgreSQL 模式下暂不支持在线修改统计时区，请停机后通过离线迁移 / 重建流程调整`。

## 存储与事务

- GET 使用固定白名单 `IN (...)` 和 `ORDER BY key ASC`，读取行数上界等于白名单长度。
- PATCH 在单个 PostgreSQL 事务中锁定全部当前白名单行，锁顺序固定为 `ORDER BY key ASC FOR UPDATE`。
- 锁定快照必须先完成完整性和当前值校验，再按稳定 key 顺序只更新请求实际提供的字段。
- `value_json` 保存标准 JSON；整数与 decimal 字段保存 JSON number，统计时区保存 JSON string。
- decimal 接受合法 JSON 数字的整数、小数和指数形式，并规范化为普通 JSON number；例如 `1.0` 与 `1e1` 分别规范化为 `1` 与 `10`。`null`、布尔值、字符串、数组、对象、NaN、Inf 和越界值均拒绝。
- 任一读取、校验、更新或提交失败都回滚，不允许部分字段成功。
- migration `000024_w5_system_settings.sql` 为 fresh PostgreSQL schema 初始化原 53 项设置；migration `000034_w5_gpt_service_tier_settings.sql` 增量 seed `gptPriorityPriceMultiplier=2` 与 `gptFlexPriceMultiplier=0.5`。两者均使用 `INSERT ... ON CONFLICT DO NOTHING`，不会覆盖已有值；运行时代码不为缺失 seed 自动补种。
- 当前 schema 之外的数据不做运行时兼容、自动补种或双读双写；缺失 seed 由部署迁移阶段处理。

### 统计时区 seed

- goose 执行 `000024` 时，`usageStatsTimezone` 优先使用 `JUHE_AI_USAGE_STATS_TIMEZONE`；未设置或为空时回退 PostgreSQL `TimeZone`，仍为空时回退 `UTC`。
- PowerShell 执行 migration 前应显式设置部署使用的 IANA 时区，例如 `$env:JUHE_AI_USAGE_STATS_TIMEZONE = 'Asia/Shanghai'`；示例值必须替换为实际部署 IANA 时区。
- Node / Go 共存期，seed 时区必须与 Node `Intl` 运行时实际使用的部署时区一致，避免统计自然日、周、月窗口在两个运行时之间错位。
- PostgreSQL 模式在线禁止修改 `usageStatsTimezone`；需要调整时必须停机，通过离线 migration / 统计窗口重建流程处理。

## 写后副作用

PostgreSQL 提交成功后执行以下 best-effort 副作用，任何副作用失败都不能把已提交业务写误报为失败：

1. 写 Node 兼容 `settings:system` shared cache version，使 Node settings repository 丢弃旧 Redis shared cache。
2. 发布 `gateway_runtime_cache` 失效事件，reason 固定为 `settings_updated`，使 Node gateway 清理运行时设置缓存。
3. 通过统一管理 operation log 入口入队 `settings.update`：
   - `module=settings`
   - `action=update_settings`
   - `resourceType=system_settings`
   - `resourceId=system`
   - `resourceName=系统运行设置`
   - `summary=更新系统运行设置`
   - `visibilityScope=all_users`
   - `detailLevel=summary`
4. `changes` 只包含本次提交且实际变化的字段；成功但值未变化时仍入队，`changes=[]`。
5. decimal 设置在 operation log changes 中保持 JSON number，不序列化为字符串。
6. changes 继续受 `operationLogMaxChangesPerRecord`、字符串 / 序列化值截断和 `__truncated__` 规则约束。
