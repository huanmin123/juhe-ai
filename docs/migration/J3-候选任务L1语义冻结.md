# J3 候选任务：L1 语义冻结

> 基线：`master@982468590`，2026-08-21。本文是语义冻结和取证记录，不是实现授权；没有任何 Node/Go 代码、schema、配置或部署变更。
>
> 证据等级：**已证实**表示可由当前仓库源码/回归脚本直接核对；**未证实**表示尚未形成后台接管契约，不能据此创建 Go jobs 或声称已迁移。
>
> **状态覆盖说明（2026-08-23）：** 本文是迁移前 L1 历史冻结，J3a 已由现行完整契约升级为 Go 独占执行/投影/业务写回；本文中的“Node DB-service 唯一 writer / Node projector”仅保留为历史基线，不是当前运行或部署指令。

## 1. 冻结结论

1. J3a 推荐为**代理延迟检测**。它有独立 `proxy_profiles` 事实、无需账户凭据、固定批次、单代理 PostgreSQL lease、`config revision + observed time` CAS 形态和现有手动入口，耦合面最小。
2. J3b 为**模型检测**，J3c 为**质量检查**；二者不得合并为万能 worker。模型检测是直接上游诊断与模型语义判定，质量检查还包含统计刷新、失败前置确认和质量状态投影。
3. “账号复制”目前只证明管理端上下文读取，不存在已证实的后台复制校验任务；本批裁定为**不进入 J3**，列为产品/历史路线图术语澄清项，不设计 jobs。
4. SQLite 模式下现有 Node DB-service 是唯一业务 writer；Go 不得直接写同一 SQLite business DB。若以后迁移 credential-requiring task，必须使用 jobs input/outcome Store 与 Node projector，不能照搬当前 Go -> DB-service 写入。

## 2. 最近模型检测语义变更

- 不再有固定 25 秒总时限。`diagnostic-task-boundary-regression.ts:52-56` 明确禁止 `modelCheckHttpRunDeadlineMs`/`AbortSignal.timeout`，并要求模型检测使用长预算专用 DB-service HTTP proxy。
- “无固定 25 秒总 deadline”不等于可承诺无限运行：专用 DB-service HTTP proxy 使用可配置的 `chatTimeoutMs`，默认 `15 * 60_000`（`backend/src/config/runtime.ts:606-609`），并由 `backend/src/server.ts:78-84,264-265` 注入模型检测 proxy。该值传给 `upstream.setTimeout`（`backend/src/modules/db-service/db-service-http-proxy.ts:79-96`），因此是 socket idle timeout，不是 handler 的绝对总时限；超时仍应保留 proxy 504/上游状态语义。
- 专用 proxy 保留包装 HTTP 状态与上游状态：`db-service-http-proxy.ts:63-78` 将上游 `statusCode` 写回响应，`db-service-http-proxy.ts:79-119` 区分超时、代理失败和已发送响应；模型检测不能把 proxy 504 或上游非 200 混成同一种结果。
- SSE 先写 `connected`，随后每 10 秒以 `: heartbeat` 保持活动：`model-checks.routes.ts:435-455`；它可防止空闲 socket 超时，但不承诺请求无限运行。回归约束见 `diagnostic-task-boundary-regression.ts:53-58`。
- Token integrity 的专用探针在同一轮 `attemptCount >= 2 && statusCode !== 200` 时终止该 token integrity 后续 padding/round（`model-checks-token-probes.ts:47-58,100-103`），但服务层把非 token 项单独过滤后才决定是否提前结束（`model-checks.service.ts:487-505`）；因此两轮尝试失败不再终止其他探针。

## 3. 架构硬约束（所有 J3）

- Go `jobs` 禁止调用 Node、Go `gateway`、Node IPC、Redis Stream、Node DB-service、gateway HTTP；诊断必须直接请求目标上游或代理目标 URL。
- SQLite 单 writer：Node 业务 DB-service 负责业务写；Go 只写自有 jobs Store。PG 使用冻结 schema、最小权限、短事务，以及 `statement_timeout`/`lock_timeout`；不得由 jobs 修复业务 schema。
- Node 只发布输入并投影结果；结果需带 `input/config revision`、`observed_at`、稳定幂等键和 owner lease fence。未知、取消、stale、包装代理错误不得静默 fallback。
- L2/L3/L4 门禁必须包含真实 dev PG/PgBouncer/Docker/Redis、SQLite、Node -> Go -> Node 闭环；Jenkins test 必须与同一 release GitOps 生产切换。切换前要完成 Node active-path-zero、旧 owner backup + manifest + revert 演练。

## 8. J3c 质量检查（后续高耦合）

质量检查必须拆开记录三类本质不同的工作：

1. **`stats-worker` `account-quality-refresh`**：从 usage 窗口重算 EWMA、成功率、quality score，并清理旧行（`account-quality.repository.ts:106-180`）；属于统计 writer。
2. **`ops-worker` `account-quality-failure-precheck-queue`**：对近期失败账户执行 API Key pool diagnostic，成功则保留状态，确认失败才经 DB-service 标记 temporary unavailable（`account-quality-failure-precheck.service.ts:113-228`）；属于账户可用性状态 writer。
3. **模型检测本质的 scheduled/recovery/health-sync**：`model-quality-scheduled-check`、`model-quality-recovery`、`model-quality-health-sync-retry` 写模型检查、账户 enforcement 和统计小时表（registry:327-365）；属于模型检测/质量投影，不应被误写成单一 stats refresh。

## 9. L2/L3/L4 严格门禁与切换清单

### L2：契约与隔离实现

- 冻结 provider、schema、输入/输出版本、资格、lease、fence/CAS、幂等和错误矩阵；PG role 仅 `SELECT` 业务候选和 jobs schema 所需最小权限。
- 真实 dev PG + PgBouncer + Docker + Redis namespace 与可销毁 fixture；验证 statement/lock timeout、并发、重启、单条失败隔离。
- SQLite 仅 Node writer（历史边界）；当前 J3a Go owner 只写 PostgreSQL business-result，Node 不再拥有 J3a writer。

### L3：闭环与候选发布

- Node 输入发布 -> Go jobs lease/probe/outcome -> Node projector（历史方案）；当前闭环为 Go result projector -> 管理读模型，重复 input/outcome、revision 漂移、lease 过期、取消和恢复均由 Go 契约承载。
- candidate release 只在隔离 dev 运行；健康检查同时覆盖 Node、Go jobs、DB-service、PG/PgBouncer、Redis；不得以 HTTP 200 或二进制存在代替功能证据。
- Jenkins test 必须针对与生产切换相同的 release artifact；GitOps 变更前保存 Node active-path-zero 扫描、旧 owner backup/manifest/revert。

### L4：生产切换

- 同一 release 经 Jenkins 门禁后，以 GitOps 切换 owner；Node scheduler、queue/IPC、writer、cleanup、启动器和部署入口全部 active-path-zero。
- 保留旧 Node 版本、配置 manifest、数据库/Store 备份、lease/outcome 游标和一键 revert；先小批量观察 freshness、错误、stale、lease busy，再扩大。
- 任一未知、数据漂移、双 writer、结果无法投影或回滚失败立即停止，不添加 fallback/双写/共享队列。
