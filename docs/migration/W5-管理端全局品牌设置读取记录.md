## 当前契约

### 共用边界

| 项 | 内容 |
| --- | --- |
| 启用条件 | 仅在 `JUHE_AI_MANAGEMENT_API_ENABLED=true` 时注册；默认管理 API 关闭，生产 server 不注册该路径 |
| 登录态 | 必须携带有效管理端 session |
| 权限 | GET 与 PATCH 都只允许 `admin` / `super_admin`；普通 `user` 返回 `403 { "message": "需要管理员权限" }` |
| 响应 | 成功时精确返回 `{ "data": { "appName": string, "appIcon": string } }`，不附加其他全局设置或系统设置字段 |
| 缓存头 | GET 与 PATCH 都返回 `Cache-Control: no-store` |

成功 DTO 固定为：

```json
{
  "data": {
    "appName": "聚合 AI",
    "appIcon": "/__aisys__/brand-icon.svg"
  }
}
```

### GET 读取

- 使用只读 session 鉴权，不更新 `system_sessions.last_seen_at`。
- 进入 system API IP read 两个 fixed-window：每分钟 `600`、每 10 秒 burst `120`；认证成功后进入系统账户 user read 每分钟 `300`。
- 复用 W1a `publicsettings.Service`、`port.PublicSettingsReader` 和 `postgres.Store.PublicGlobalSettings`，只读取 `juhe_business.global_settings` 中 `appName` / `appIcon`。
- `appName` / `appIcon` 缺字段、非法存储值、reader 读取失败、依赖缺失或内部上下文异常统一返回通用 `500 { "message": "服务器内部错误" }`。

### PATCH 更新

- 使用写 session 鉴权；成功鉴权后按 60 秒窗口 touch 当前 `system_sessions.last_seen_at`。
- 进入 system API IP write 两个 fixed-window：每分钟 `180`、每 10 秒 burst `40`；认证成功后进入系统账户 user write 每分钟 `120`。
- 请求体必须是单个 JSON object，最大 `256 KiB`；只允许 `appName`、`appIcon`，至少提交一个字段。
- 请求体超过上限时返回 `413 { "message": "请求体过大" }`；其他 body 结构错误返回 `400`。
- `appName` / `appIcon` 必须是非空字符串，服务端 trim 后写入；拒绝 `null`、非字符串、空白字符串、未知字段、空对象、顶层非对象和尾随 JSON。
- 成功响应返回事务提交后的完整 `appName` / `appIcon`，包括未在本次请求中修改的另一字段。

请求示例：

```json
{
  "appName": "新的系统名称",
  "appIcon": "/assets/new-brand.svg"
}
```

## 写入与副作用

### PostgreSQL 事务

- `postgres.Store.UpdateGlobalSettings` 在单个事务内锁定 `appName` / `appIcon` 当前行，锁顺序固定为 `ORDER BY key ASC FOR UPDATE`。
- 锁定后先验证两行都存在且 `value_json` 是非空 JSON 字符串，再只更新请求实际提供的字段。
- `value_json` 继续保存 JSON 字符串文本，`updated_at` 使用 service 注入时钟；任一读取、校验、更新或提交失败都回滚事务。
- `000023_w5_operation_log_settings.sql` 为当前 Go schema 种入 `operationLogMaxChangesPerRecord=100`；运行时代码不为缺失设置提供兼容回退。
- 本切片不新增表、字段或索引，也不保留 Node / 旧数据库兼容分支。

### 共享缓存失效

- PostgreSQL 提交成功后，通过 `gatewaycache.SystemAccountInvalidator` 写 Node 兼容的 `settings:global` shared cache version。
- 生产 namespace 下 key 为 `juhe-ai:juhe-ai:cache-version:settings:global`；version value 与 `30 天` TTL 协议由 `gatewaycache` 现有单测固定。
- 缓存失效是事务外 best-effort 副作用：Redis 写失败不能把已提交的 PostgreSQL 更新误报为失败，也不能触发业务重试造成重复写。
- W5 integration smoke 验证真实 Redis 中 shared cache version key 已写入；TTL 精确协议不在 integration 重复断言。

### Operation log

- 每次 PATCH 成功更新后都入队 `settings.update_global` operation log，包括 before / after 完全相同的成功请求。
- 固定为 `module=settings`、`action=update_global`、`resourceType=global_settings`、`resourceId=global`、`detailLevel=summary`、`visibilityScope=all_users`。
- changes 只记录实际变化的 `appName` / `appIcon` before / after；没有实际变化时仍入队，`changes` 固定为空数组。
- 入队统一通过 [BUG-0044](../bug/问题-0044-Go管理操作日志未统一执行Node清洗规则.md) 的共享管理操作日志入口；该入口已同时覆盖账户标签、资料、系统账户、团队、授权和代理等已迁移管理写 handler。
- 入队前读取 `operationLogMaxChangesPerRecord`，按 Node 规则把字符串 before / after 截断到 200 字符，非基础类型序列化后最多保留 500 字符，敏感值归一化为 `未设置/已变更`；超过配置条数时追加 `__truncated__` 汇总项。
- operation log 入队失败不覆盖业务成功。
- W5 integration smoke 使用真实 PostgreSQL store 读取 operation log 设置，并用可解码 enqueue stub 验证 handler 实际生成 `all_users` summary payload；该用例不启动 ingest worker，不把 operation log 写入 PostgreSQL。真实 queue -> ingest worker -> `juhe_dataset.operation_logs` 入库继续由既有 handler / queue 单测、W3 operation-log integration 和后续生产接管验证覆盖。

## 错误边界

| 场景 | 响应 |
| --- | --- |
| 未登录、session 无效或过期 | 管理鉴权中间件返回 `401` |
| 普通用户访问 GET / PATCH | `403 { "message": "需要管理员权限" }` |
| PATCH body 非法、为空、字段类型错误、未知字段或尾随 JSON | `400` 中文错误 |
| PATCH body 超过 `256 KiB` | `413 { "message": "请求体过大" }` |
| IP / 用户 read 或 write 超限 | `429`，带 `Retry-After` |
| GET 存储值缺失 / 非法或读取失败 | 通用 `500 { "message": "服务器内部错误" }` |
| PATCH 当前值缺失 / 非法、事务读取 / 更新 / 提交失败 | 事务回滚并返回通用 `500 { "message": "服务器内部错误" }` |
| PostgreSQL 已提交后 Redis cache version 写失败 | PATCH 仍返回成功；失效失败为 best-effort 运维风险 |
| PostgreSQL 已提交后 operation log 入队失败 | PATCH 仍返回成功；日志失败不改变业务事实 |

HTTP 响应不得泄露 PostgreSQL、Redis、配置、存储原值或内部错误文本。
