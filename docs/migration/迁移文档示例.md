# 迁移文档示例

> 本文展示单个模块迁移记录的推荐写法。后续如果某个模块需要独立长文档，可以复制本结构并替换内容。

## 示例：公开设置接口迁移

## 基本信息

- 模块：公开设置接口
- 状态：示例
- 迁移波次：W1 公开接口
- 当前 Node owner：`backend/src/modules/settings/` 中公开设置 route/service
- 目标 Go owner：`backend-go/internal/modules/publicapi/`
- 关联功能文档：`docs/functions/核心功能设计.md`
- 关联计划：`docs/plans/计划-0081-Node转Go渐进减法迁移.md`

## 当前契约

| 项 | 内容 |
| --- | --- |
| 路径 | `GET /__aisys__/api/settings/public` |
| 认证 | 不需要后台登录态 |
| 成功响应 | 返回公开品牌、站点配置和登录页公开字段 |
| 错误响应 | 读取失败时返回统一错误结构和中文摘要 |
| 敏感边界 | 不返回系统密钥、上游凭据、代理密码或内部开关 |

## 前置依赖

- Go 工程与 PG/Redis 基线已完成。
- 当前接口 fixture 已固定。
- PostgreSQL seed 中已有公开设置默认值。
- Redis cache 失效规则已定义或明确不使用缓存。

## Go 实现范围

- 新增 Go route、DTO、service 和 store port。
- 复用当前公开设置字段契约，字段调整必须先更新功能文档。
- 读取路径必须有超时、错误摘要和结构化日志。
- 不把 Node 旧 repository 包装成 Go 调用。

## 配置与存储变化

- PostgreSQL：读取当前公开设置表或等价当前 schema。
- Redis：如使用公开设置短缓存，必须定义 TTL、失效事件和降级行为。
- 环境变量：不新增 SQLite 路径、standalone / performance 模式或 Node DB service 配置。

## Node 删除范围

- 删除 Node 公开设置 route。
- 删除 Node 公开设置 service 中仅服务该路径的函数。
- 删除 package scripts 中该模块专用测试入口，或替换为 Go 测试入口。
- 使用 `rg "settings/public|list_public_global_settings|public settings" backend/src` 检查旧路径和旧函数名，只允许未迁移模块或文档历史引用。

## 测试项

| 测试类型 | 验证方式 | 预期 |
| --- | --- | --- |
| API 契约 | `go test ./... -run PublicSettings` | 字段、状态码和错误结构符合当前契约 |
| 权限 | 未登录请求公开设置 | 可以读取公开字段，不泄露敏感字段 |
| 空数据 | 新库默认 seed 后读取 | 返回默认公开设置 |
| 删除验证 | `rg "settings/public|list_public_global_settings" backend/src` | 不存在已迁移 Node route 入口 |
| 前端联调 | 打开登录页和公开设置依赖页面 | 页面文案和字段正常 |

## 灰度与回滚

- 灰度方式：本地或测试环境只把该路径转给 Go，其他路径仍走当前 owner。
- 回滚方式：恢复上一版 route owner 和发布包；不做双读双写。
- 失败阈值：字段缺失、敏感字段泄露、登录页不可用或错误结构不一致时立即回退。
