# W10 网关上游请求与流式中转核心迁移记录

## 范围

本批只迁移网关传输层的可复用 Go 核心，不注册生产路由，也不改变 `deploy/owner-manifest.json` 的 gateway owner。实现位于：

- `backend-go/internal/modules/gatewayupstream`：从已解析的请求形状、候选账号、真实资源协议和凭据构造有界 `http.Request`。
- `backend-go/internal/modules/gatewaystreamrelay`：在已建立的 source/sink 之间执行同步、可取消、有界的流式中转。
- `backend-go/internal/modules/gatewaydispatch`：把一次已选候选接到注入的 `http.Client`，提供响应 body 有界读取/关闭和 relay 适配；不持有候选、retry 或 owner 状态。
- `backend-go/internal/modules/gatewaycodexresponses`：把 Codex Responses JSON / stream contract 作为可选检查 seam 接入；流式拥有有界完整帧预提交检查与 R0 ID 字节重写，非流式拥有有界 JSON R0 修复，不拥有账户、候选、retry 或生产路由。
- `backend-go/internal/modules/gatewayresponse`：取得一次 dispatch response 的 body 所有权，实际组合 `ReadBody -> JSON guard -> downstream sink` 或 `NewInspector -> Relay`，并返回 typed retry、usage/audit 和 commit handoff；不持有候选列表、账户策略或 HTTP listener。

## Go 原生决策

- 不复制 Node 的隐式 header / body 传播。请求构造器只复制通过校验的语义 header，清除 hop-by-hop、客户端认证、代理、追踪和内部路由 header，并在 Go 的 `http.Request` 上显式设置 host、content length、context 和可重试 body。
- 不让请求构造器负责 SSRF、代理选择、重试或 response inspection。候选资源协议决定 URL 拼接和认证位置，网络策略、retry planner 和协议 inspector 保持独立接口，避免把未迁移的 Node 运行时耦合进核心。
- 不使用后台 goroutine 搬运流。relay 让一次成功 sink write 完成后才读取下一块 source，直接把客户端取消和背压传入 source/sink；这样不会因 detached goroutine 造成连接泄漏或无界 channel。
- 64 MiB body/stream cap、idle timeout、total timeout 和 bounded inspector handoff 都是 Go 侧的硬边界；首字节已写出后 `RetryAllowed=false`，客户端取消不归因到账号上游。

## 契约覆盖

- OpenAI-compatible、Anthropic Messages、Gemini native、OpenAI OAuth/Codex 和授权资源协议的 URL / auth 选择。
- body 所有权、`GetBody`、content-length、敏感 header 清洗、非法 URL/credential/header、Gemini key query 清理和 stream `alt=sse`。
- 流式成功、首字节前上游超时可重试、客户端取消不可重试、首字节后失败不可重试、sink 背压、部分写、64 MiB 超限、缺终态、终态失败和 usage/audit 终态交接。
- dispatch seam 覆盖 transport error 保真、非 2xx 响应透传、body 超限、close/read error 可 `errors.Is` 识别、HTTP status 到 usage handoff 的传递和 response body 必须关闭。
- response handler 覆盖显式 raw-upstream / gateway-bridge checkpoint、JSON safe/strict/shadow、SSE keepalive、partial write、initial commit、协议首字节前换候选 handoff，以及完整 HTTP 失败响应默认透明转发。只有调用方显式标记 `explicit_policy` 时，401 / 429 / 5xx 才进入 Go 状态/错误分类，避免 generic vendor 响应隐式轮 Key。这里的 `explicit_policy` 只是分类 opt-in，不等于 Node `decideAccountErrorPolicy` 已命中的 `retry_next / skip_account` 动作；真实账户策略尚未迁移，后续必须用独立 typed action 接线。

## Go Codex Responses contract 批次

- `backend-go/internal/protocols/codexresponses` 已新增纯 Go contract registry、JSON validator 与 stream state：登记 17 类当前 Node item、ID 前缀 / event stage / 字段类型、工具调用与输出关联、`request_history` 外部历史例外、unknown / R0 / R2 分类、32 条有界诊断、流式 `added -> delta -> done -> completed` identity consistency 和 `CommitState` / late-violation 语义。
- 这批按 Go 方式实现为无副作用校验包，不复制 Node 的 repair executor、账户策略、SQLite history sanitizer、SSE interceptor 或 HTTP owner。`timeout_ms` 遵循 JS safe integer 上限；JSON trailing value、数组 / 对象类型和 tool correlation 在入口处 fail-closed。
- `gatewaycodexresponses.Inspector` 已作为 relay 可选 transform inspector 接线：shadow 保持 byte-for-byte 透传；strict 与 safe repair 在任意 chunk boundary / EOF pending 下先缓冲完整 SSE frame，再决定下游提交。safe repair 只执行 contract 明确允许的 R0 `item.id` / `item_id` / `response.output[index].id` 重写，added / delta / done / completed 复用同一随机 client ID；R2、生成 ID 超限 / 冲突或重写失败均 fail-closed。被修复帧保留原 `event/id/retry/comment/extension` 行和换行形式，只替换 data JSON；未修复帧原字节透传。
- `gatewaycodexresponses.InspectJSON` 已补齐非流式 guard：先检查 response / compact envelope，再复用 Go validator；shadow / strict 保留原始 body，safe repair 只在未语义提交且 provenance 为 `raw_upstream` / `gateway_bridge` 时替换 output item 的 R0 ID，使用随机、有界、避免碰撞的 typed ID，重编码后再次校验。R2、unknown、request-history 修复、生成失败、超限或 post-validation 失败均不改 body 并 fail-closed；结果携带有界诊断、`repaired_safe` / `repaired_bridge`、rule ID 和 Go `CommitState` retry 语义。Go 采用结构化 JSON 重编码，保证未知字段的语义保真，不承诺 clean 路径字节重排。
- `gatewayresponse.Handler` 已把上述 guard 接入可调用的 response runtime seam。typed checkpoint 无公开字段，调用方只能通过 raw-upstream / gateway-bridge 构造器声明来源；2xx strict / safe 协议失败通过 `gatewayretry.ResponseSignal` 驱动下一候选，完整 HTTP 响应则通过 `ResponseDisposition` 默认透明写入下游。`explicit_policy` 当前只开启 Go classifier，不冒充 Node 账户策略动作。OpenAI-compatible 非流式 usage 使用与 SSE 相同的字段归一化，guard handoff 只保留有界 outcome / rule / diagnostic code，不复制正文。
- Go 有意比 Node 收紧 transport-only retry：只要任意下游字节已经写出，relay 就禁止换号；`late_violation` 仍按 semantic commit 标注。该差异避免 heartbeat 已暴露后重复流，但可能牺牲 Node 允许的 heartbeat 后透明重试，生产 owner 接线前不得写成完全等价。
- 该接线不代表已注册 Go listener、接管 Codex Responses production owner 或删除 Node firewall；仍需真实 gateway-bridge marker、账户策略读取、usage/audit explanation、上游 smoke 和 canary / rollback 证据。
