# W10 网关上游请求与流式中转核心迁移记录

## 范围

本批只迁移网关传输层的可复用 Go 核心，不注册生产路由，也不改变 `deploy/owner-manifest.json` 的 gateway owner。实现位于：

- `backend-go/internal/modules/gatewayupstream`：从已解析的请求形状、候选账号、真实资源协议和凭据构造有界 `http.Request`。
- `backend-go/internal/modules/gatewaystreamrelay`：在已建立的 source/sink 之间执行同步、可取消、有界的流式中转。
- `backend-go/internal/modules/gatewaydispatch`：把一次已选候选接到注入的 `http.Client`，提供响应 body 有界读取/关闭和 relay 适配；不持有候选、retry 或 owner 状态。
- `backend-go/internal/modules/gatewaycodexresponses`：把 Codex Responses JSON / stream contract 作为可选检查 seam 接入；流式拥有有界完整帧预提交检查与 R0 ID 字节重写，非流式拥有有界 JSON R0 修复，不拥有账户、候选、retry 或生产路由。
- `backend-go/internal/modules/gatewayresponse`：取得一次 dispatch response 的 body 所有权，实际组合 `ReadBody -> JSON guard -> downstream sink` 或 `NewInspector -> Relay`，并返回 typed retry、usage/audit 和 commit handoff；不持有候选列表、账户策略或 HTTP listener。

## Go 原生决策

- 不复制 Node 的隐式 header / body 传播。请求构造器只复制通过校验的语义 header，清除 hop-by-hop、客户端认证、代理、追踪和内部路由 header，并在 Go 的 `http.Request` 上显式设置 host、content length、context 和可重试 body。
- 不让请求构造器负责 SSRF、代理选择、重试或 response inspection。候选资源协议决定 URL 拼接和认证位置，网络策略、retry planner 和协议 inspector 保持独立接口，避免把未迁移的 Node 运行时耦合进核心。
- 不使用后台 goroutine 搬运流。relay 让一次成功 sink write 完成后才读取下一块 source，直接把客户端取消和背压传入 source/sink；这样不会因 detached goroutine 造成连接泄漏或无界 channel。
- 64 MiB body/stream cap、idle timeout、total timeout 和 bounded inspector handoff 都是 Go 侧的硬边界；首字节已写出后 `RetryAllowed=false`，客户端取消不归因到账号上游。

## 契约覆盖

- OpenAI-compatible、Anthropic Messages、Gemini native、OpenAI OAuth/Codex 和授权资源协议的 URL / auth 选择。
- body 所有权、`GetBody`、content-length、敏感 header 清洗、非法 URL/credential/header、Gemini key query 清理和 stream `alt=sse`。
- 流式成功、首字节前上游超时可重试、客户端取消不可重试、首字节后失败不可重试、sink 背压、部分写、64 MiB 超限、缺终态、终态失败和 usage/audit 终态交接。
- dispatch seam 覆盖 transport error 保真、非 2xx 响应透传、body 超限、close/read error 可 `errors.Is` 识别、HTTP status 到 usage handoff 的传递和 response body 必须关闭。
- response handler 覆盖显式 raw-upstream / gateway-bridge checkpoint、JSON safe/strict/shadow、SSE keepalive、partial write、initial commit、协议首字节前换候选 handoff，以及完整 HTTP 失败响应默认透明转发。只有调用方显式标记 `explicit_policy` 时，401 / 429 / 5xx 才进入 Go 状态/错误分类，避免 generic vendor 响应隐式轮 Key。这里的 `explicit_policy` 只是分类 opt-in，不等于 Node `decideAccountErrorPolicy` 已命中的 `retry_next / skip_account` 动作；真实账户策略尚未迁移，后续必须用独立 typed action 接线。

## Go Codex Responses contract 批次

- `backend-go/internal/protocols/codexresponses` 已新增纯 Go contract registry、JSON validator 与 stream state：登记 17 类当前 Node item、ID 前缀 / event stage / 字段类型、工具调用与输出关联、`request_history` 外部历史例外、unknown / R0 / R2 分类、32 条有界诊断、流式 `added -> delta -> done -> completed` identity consistency 和 `CommitState` / late-violation 语义。
- 这批按 Go 方式实现为无副作用校验包，不复制 Node 的 repair executor、账户策略、SQLite history sanitizer、SSE interceptor 或 HTTP owner。`timeout_ms` 遵循 JS safe integer 上限；JSON trailing value、数组 / 对象类型和 tool correlation 在入口处 fail-closed。
- `gatewaycodexresponses.Inspector` 已作为 relay 可选 transform inspector 接线：shadow 保持 byte-for-byte 透传；strict 与 safe repair 在任意 chunk boundary / EOF pending 下先缓冲完整 SSE frame，再决定下游提交。safe repair 只执行 contract 明确允许的 R0 `item.id` / `item_id` / `response.output[index].id` 重写，added / delta / done / completed 复用同一随机 client ID；R2、生成 ID 超限 / 冲突或重写失败均 fail-closed。被修复帧保留原 `event/id/retry/comment/extension` 行和换行形式，只替换 data JSON；未修复帧原字节透传。
- `gatewaycodexresponses.InspectJSON` 已补齐非流式 guard：先检查 response / compact envelope，再复用 Go validator；shadow / strict 保留原始 body，safe repair 只在未语义提交且 provenance 为 `raw_upstream` / `gateway_bridge` 时替换 output item 的 R0 ID，使用随机、有界、避免碰撞的 typed ID，重编码后再次校验。R2、unknown、request-history 修复、生成失败、超限或 post-validation 失败均不改 body 并 fail-closed；结果携带有界诊断、`repaired_safe` / `repaired_bridge`、rule ID 和 Go `CommitState` retry 语义。Go 采用结构化 JSON 重编码，保证未知字段的语义保真，不承诺 clean 路径字节重排。
- `gatewayresponse.Handler` 已把上述 guard 接入可调用的 response runtime seam。typed checkpoint 无公开字段，调用方只能通过 raw-upstream / gateway-bridge 构造器声明来源；2xx strict / safe 协议失败通过 `gatewayretry.ResponseSignal` 驱动下一候选，完整 HTTP 响应则通过 `ResponseDisposition` 默认透明写入下游。`explicit_policy` 当前只开启 Go classifier，不冒充 Node 账户策略动作。OpenAI-compatible 非流式 usage 使用与 SSE 相同的字段归一化，guard handoff 只保留有界 outcome / rule / diagnostic code，不复制正文。
- Go 有意比 Node 收紧 transport-only retry：只要任意下游字节已经写出，relay 就禁止换号；`late_violation` 仍按 semantic commit 标注。该差异避免 heartbeat 已暴露后重复流，但可能牺牲 Node 允许的 heartbeat 后透明重试，生产 owner 接线前不得写成完全等价。
- 该接线不代表已注册 Go listener、接管 Codex Responses production owner 或删除 Node firewall；仍需真实 gateway-bridge marker、账户策略读取、usage/audit explanation、上游 smoke 和 canary / rollback 证据。

## 2026-07-24 downstream commit 与请求元数据批次

- 新增 `gatewaydownstream.HTTPWriterSink`，以 `Stage -> Commit -> Write -> Snapshot` 管理响应状态。`WriteHeader` 本身即 transport commit；即使 flush 或首个正文写入失败、正文为零字节，也禁止跨账户重试。JSON 在 guard 后计算最终长度，透明失败响应保留状态和业务头，显式账户策略在提交前返回，SSE 延迟到首个输出或空流完成才提交。
- 响应头使用静态 hop-by-hop / 内部供应商 denylist、动态 `Connection` token 和 128 字段 / 64 KiB 上限；提交时先清除 writer 上已有的非网关自有头，避免 middleware 残留 `Set-Cookie`、旧 `Content-Length` 或传输头。网关自有 request/trace/timing/CORS 头采用严格 allowlist 保留。
- Go 不照搬 Node 总是删除 `Content-Encoding` 的行为。标准 `net/http.Transport` 自动解压时已移除该头；自定义 transport 返回仍编码的 opaque 失败正文时，Go 保留端到端编码头并以实际缓冲字节重算长度。JSON/SSE 因需要解析或流式规范化，只允许无编码或 `identity`；仍带 gzip/br 等编码时 fail-closed，不能删除 header 后把压缩字节误当结构化正文。
- `protocols/gateway.ScanRequestMetadata` 对原始 JSON 做一次有界完整扫描，区分 unscanned、absent、explicit false/true、null、invalid 和 scan-limit-exceeded；重复 `store`、非法类型、非法 JSON/UTF-8、trailing value 和超限全部拒绝重放。扫描结果已接入 typed `RequestShape` 与 replay classifier，但生产 listener/body admission 尚未迁移，不能描述为生产解析已接线，也不得在每次 attempt 重复扫描。
- 本批仍不注册 Go gateway route、不修改 owner manifest。HEAD 的无正文语义须由未来 listener 向响应计划传递 method fact；该门禁完成前不能把 downstream adapter 描述为生产 owner。

## 2026-07-24 account policy PostgreSQL writer 批次

- `gatewayattemptloop.PolicyMutation` 已从整份 hydrated candidate 收敛为脱敏 typed facts，只携带 target/source 身份、target status、双 `config_revision/dispatch_revision`、规则动作、有界 reason/trace 和时间；凭据、代理、模型、API-key runtime、上游正文及原始错误 message 不进入 writer。调用方必须提供稳定 `MutationID`，attempt 层以绑定账户、分组、授权、双 revision、status、action 和 rule 的 canonical SHA-256 生成有界 transition，支持 outbox 幂等重放。

- snapshot projector 直接产出 Go 运行态：`reliability = 5m*0.6 + 10m*0.3 + 30m*0.1`，`confidence = min(1, qualityAttempts10m/10)`，`effectiveReliability` 向 `0.5` 收缩；`cold/warming/known` 和 `healthy/uncertain/unhealthy/unknown` 保持 deterministic。首字 EWMA 采用 `alpha=0.4`，P95 使用 8 桶上界 `1/2/5/10/20/30/60s/+inf`；对既有 selector 暴露 `SelectorSnapshot()`，因此可继续复用纯排序契约，而不把 Redis/Lua 写链搬进来。
- 新增 `Lifecycle`：`StartLifecycle -> MarkFirstByte -> RecordTerminal`。first byte 只认首个非负 transport duration，terminal 为 first-wins；如果调用方传了无效内部参数，lifecycle 不永久封死 receipt，允许修正后重试。当前 lifecycle 不启动 goroutine、不重试写入、不反向影响请求结果。
- `gatewayattemptloop` 新增默认关闭的泛化 `AttemptObserver` seam。observer 只收到脱敏值对象：随机 UUID attempt ID、attempt/index、account runtime、protocol profile、text/image lane、SHA-256 model bucket、时间与有界 terminal 摘要；不会收到 `Candidate`、`CredentialSet`、明文 API Key、请求体或错误 message。外部 executor 违反 `AttemptResult` 契约时，loop 先拒绝 Run，并只向 observer 发 `valid=false / invalid_attempt_result` 的中性终态，禁止未来 quality adapter 把伪成功写为健康样本。`HTTPExecutor` 在真实下游首字节可见时才触发 callback，且通过 `sync.Once` 保证每次实际 execute 最多一个 first-byte 事件。该 seam 未在 app/listener 中装配，因此不代表 Go 已接管 hot-quality writer 或 gateway owner。
- 这批有意不机械复制 Node 的 Redis/Lua、same-tier exploration、confirmation-only shared quality、reservation/settlement 和共享 route cursor。Go 先迁入 request-local lifecycle 与纯内存投影，后续再决定 Redis adapter、生产 owner epoch 和 Node drain；多实例共享状态、真实 listener、circuit/hot-quality writer、semantic retry 和 same-account reservation 继续后置。

## 2026-07-26 request-local hot-quality adapter

- 新增独立 `gatewayhotqualityadapter.Observer`，实现 `gatewayattemptloop.AttemptObserver`，但只能由调用方显式注入；app、listener、Redis 和候选排序均不默认构造它。adapter 的活动 lifecycle 上限为 `512`、默认 TTL 与 store 的 `60m` attempt identity 窗口对齐，以 mutex 保护；完成 terminal 后立即释放，若 store 已报告 identity 过期也立即释放，暂时无法落账的其他 terminal 才在 TTL 内保留供重试，避免常驻 map 无界增长。
- observation scope 以 Node 运行态语义收敛：授权账户使用 `accountId:authorized:systemAccountId:groupId:authorizationId`，绑定上下文缺失则拒绝观测；有资源账户时 protocol profile 优先使用资源侧 profile 或资源 code/version，其他情形使用 local profile；lane 复用 `ResolveRequestLane`；model 先 trim/lower-case，空、控制字符或超过 256 bytes 统一为 `unknown` 后再 SHA-256 分桶。adapter 仍只接收这些脱敏 hint，绝不取得 Candidate/credential/raw model。
- terminal 归因刻意保守：`success` 记 `completed_response`，`client_lifecycle` 记 `client_cancellation`，`valid=false` 和其他无 typed disposition 的失败统一记 `unknown`。不得从 status 或 ErrorCode 字符串猜测 timeout/read/interruption/incomplete/explicit policy，避免把 opaque 或 gateway 失败错误写进账户质量分母；后续须先在 executor 形成 typed terminal disposition 与 confirmation eligibility，再扩张映射表。
- adapter 的测试覆盖 direct/授权 scope、首个可见字节、重复回调、invalid/client/upstream 中性终态、活动上限、并发回调及 attempt-loop 注入。它只验证单进程内存契约，不是生产 hot-quality owner。

## 2026-07-26 通用 SSE 预提交语义批次

- `gatewaystreamrelay.NewSSEPreCommitInspector` 是每次 relay 独占的 256 KiB gate：只用标准 SSE framing 识别非空 `data:` payload，不解析 event 名、JSON、供应商状态码或错误文本。注释、heartbeat、metadata、未知字段和空 `data:` 在语义证据前不写 downstream；一旦发现 payload，原样一次性 flush 已保留的同事件 framing，并且之后不再允许 retry 拼接其他账户。
- 已保持 Node 的关键边界并采用 Go 的同步 relay 实现：完成的纯非语义 event 会被丢弃且不计入预提交容量；无终止的大 metadata/空 data framing 超过上限返回本地 `stream_precommit_buffer_exceeded`，不归因为账户传输失败；超大非空 `data:` 直接成为语义输出而不被 metadata 上限误杀。EOF 前没有证据返回 `stream_precommit_evidence_missing`，没有下游 header/body，可安全保留上层 retry。
- 回调现拆为 transport header commit、首个下游字节和 `OnFirstSemanticOutput`。`HTTPExecutor` 仅在最后者解除 first-byte deadline 并触发 attempt/hot-quality 首字观测；JSON body 的首次真实写入同时满足该语义。这样 heartbeat 或 header 不会伪造可见首字。
- `gatewayresponse` 的 generic stream 现在默认装配该 gate，且不再在无下游字节的成功 relay 后强制提交空 SSE header。Codex Responses 仍使用自身 protocol inspector；本批不假称通用终态校验、生产 listener、Redis owner 或 Node gateway takeover 已完成。

## 2026-07-26 流式终态 disposition 批次

## 2026-07-26 route shared-state transition 批次

- `gatewayroutecoordination.Advance` 把一份完整 route snapshot 与可序列化 `SharedState` 变成 `Plan + next SharedState`；round-robin 推进 sequence，weighted 使用现有稳定 tie-break 的 smooth-weight debt，normal/failover/hybrid 不推进状态。MemoryStore 已改为复用这一个转换，因此未来共享存储不再复制路由决策。
- semantic revision 覆盖 scope、mode、完整 bindings、权重与启用状态。revision 不一致时无条件清空 sequence 与 debt，避免配置、权重或 enabled 变化后复用旧分布；动态模式原子持久化 next state，pass-through mode 删除残留动态 state。测试覆盖 revision reset、连续轮询和 pass-through 不推进。
- Node Redis weighted 使用计数桶而 standalone 使用 smooth weighted；此处有意统一采用 Go 的 smooth-weight state，改善跨实例 fallback 顺序一致性，而不是照搬两套 Node 算法。Go keyspace 将保持独立 namespace，迁移并存期绝不与 Node 的旧 Redis key 双 writer。
- 本批尚未实现 Redis Lua/CAS adapter、Redis client 装配、listener 注入或 Node owner 迁移；account circuit、hot-quality、session affinity、slot lease 和 API-key rotation 各有独立 lifecycle/side effect owner，不能借路由状态批次一并接管。

## 2026-07-26 route Redis shared-store adapter 批次
