# W10 网关上游请求与流式中转核心迁移记录

## 范围

本批只迁移网关传输层的可复用 Go 核心，不注册生产路由，也不改变 `deploy/owner-manifest.json` 的 gateway owner。实现位于：

- `backend-go/internal/modules/gatewayupstream`：从已解析的请求形状、候选账号、真实资源协议和凭据构造有界 `http.Request`。
- `backend-go/internal/modules/gatewaystreamrelay`：在已建立的 source/sink 之间执行同步、可取消、有界的流式中转。
- `backend-go/internal/modules/gatewaydispatch`：把一次已选候选接到注入的 `http.Client`，提供响应 body 有界读取/关闭和 relay 适配；不持有候选、retry 或 owner 状态。

## Go 原生决策

- 不复制 Node 的隐式 header / body 传播。请求构造器只复制通过校验的语义 header，清除 hop-by-hop、客户端认证、代理、追踪和内部路由 header，并在 Go 的 `http.Request` 上显式设置 host、content length、context 和可重试 body。
- 不让请求构造器负责 SSRF、代理选择、重试或 response inspection。候选资源协议决定 URL 拼接和认证位置，网络策略、retry planner 和协议 inspector 保持独立接口，避免把未迁移的 Node 运行时耦合进核心。
- 不使用后台 goroutine 搬运流。relay 让一次成功 sink write 完成后才读取下一块 source，直接把客户端取消和背压传入 source/sink；这样不会因 detached goroutine 造成连接泄漏或无界 channel。
- 64 MiB body/stream cap、idle timeout、total timeout 和 bounded inspector handoff 都是 Go 侧的硬边界；首字节已写出后 `RetryAllowed=false`，客户端取消不归因到账号上游。

## 契约覆盖

- OpenAI-compatible、Anthropic Messages、Gemini native、OpenAI OAuth/Codex 和授权资源协议的 URL / auth 选择。
- body 所有权、`GetBody`、content-length、敏感 header 清洗、非法 URL/credential/header、Gemini key query 清理和 stream `alt=sse`。
- 流式成功、首字节前上游超时可重试、客户端取消不可重试、首字节后失败不可重试、sink 背压、部分写、64 MiB 超限、缺终态、终态失败和 usage/audit 终态交接。
- dispatch seam 覆盖 transport error 保真、非 2xx 响应透传、body 超限、close/read error 可 `errors.Is` 识别、HTTP status 到 usage handoff 的传递和 response body 必须关闭。
