# W10 网关上游请求与流式中转核心迁移记录

## 范围

本批只迁移网关传输层的可复用 Go 核心，不注册生产路由，也不改变 `deploy/owner-manifest.json` 的 gateway owner。实现位于：

- `backend-go/internal/modules/gatewayupstream`：从已解析的请求形状、候选账号、真实资源协议和凭据构造有界 `http.Request`。
- `backend-go/internal/modules/gatewaystreamrelay`：在已建立的 source/sink 之间执行同步、可取消、有界的流式中转。
- `backend-go/internal/modules/gatewaydispatch`：把一次已选候选接到注入的 `http.Client`，提供响应 body 有界读取/关闭和 relay 适配；不持有候选、retry 或 owner 状态。
- `backend-go/internal/modules/gatewaycodexresponses`：把 Codex Responses JSON / stream contract 作为可选检查 seam 接入；流式拥有有界完整帧预提交检查与 R0 ID 字节重写，非流式拥有有界 JSON R0 修复，不拥有账户、候选、retry 或生产路由。
- `backend-go/internal/modules/gatewayresponse`：取得一次 dispatch response 的 body 所有权，实际组合 `ReadBody -> JSON guard -> downstream sink` 或 `NewInspector -> Relay`，并返回 typed retry、usage/audit 和 commit handoff；不持有候选列表、账户策略或 HTTP listener。
- `backend-go/internal/modules/gatewayhttpcompletion`：为未来 HTTP listener 提供一次性下游终态观察器；handler owner 显式完成或 request context 取消均收口到同一 terminal，不注册路由、不写响应。

## Go 原生决策

- 不复制 Node 的隐式 header / body 传播。请求构造器只复制通过校验的语义 header，清除 hop-by-hop、客户端认证、代理、追踪和内部路由 header，并在 Go 的 `http.Request` 上显式设置 host、content length、context 和可重试 body。
- 不让请求构造器负责 SSRF、代理选择、重试或 response inspection。候选资源协议决定 URL 拼接和认证位置，网络策略、retry planner 和协议 inspector 保持独立接口，避免把未迁移的 Node 运行时耦合进核心。
- 不使用后台 goroutine 搬运流。relay 让一次成功 sink write 完成后才读取下一块 source，直接把客户端取消和背压传入 source/sink；这样不会因 detached goroutine 造成连接泄漏或无界 channel。
- 64 MiB body/stream cap、idle timeout、total timeout 和 bounded inspector handoff 都是 Go 侧的硬边界；首字节已写出后 `RetryAllowed=false`，客户端取消不归因到账号上游。

## 契约覆盖

- OpenAI-compatible、Anthropic Messages、Gemini native、OpenAI OAuth/Codex 和授权资源协议的 URL / auth 选择。
- body 所有权、`GetBody`、content-length、敏感 header 清洗、非法 URL/credential/header、Gemini key query 清理和 stream `alt=sse`。
- 流式成功、首字节前上游超时可重试、客户端取消不可重试、首字节后失败不可重试、sink 背压、部分写、64 MiB 超限、缺终态、终态失败和 usage/audit 终态交接。
- dispatch seam 覆盖 transport error 保真、非 2xx 响应透传、body 超限、close/read error 可 `errors.Is` 识别、HTTP status 到 usage handoff 的传递和 response body 必须关闭。
- response handler 覆盖显式 raw-upstream / gateway-bridge checkpoint、JSON safe/strict/shadow、SSE keepalive、partial write、initial commit、协议首字节前换候选 handoff，以及完整 HTTP 失败响应默认透明转发。只有调用方显式标记 `explicit_policy` 时，401 / 429 / 5xx 才进入 Go 状态/错误分类，避免 generic vendor 响应隐式轮 Key。这里的 `explicit_policy` 只是分类 opt-in，不等于 Node `decideAccountErrorPolicy` 已命中的 `retry_next / skip_account` 动作；真实账户策略尚未迁移，后续必须用独立 typed action 接线。

## Go Codex Responses contract 批次

- `backend-go/internal/protocols/codexresponses` 已新增纯 Go contract registry、JSON validator 与 stream state：登记 17 类当前 Node item、ID 前缀 / event stage / 字段类型、工具调用与输出关联、`request_history` 外部历史例外、unknown / R0 / R2 分类、32 条有界诊断、流式 `added -> delta -> done -> completed` identity consistency 和 `CommitState` / late-violation 语义。
- 这批按 Go 方式实现为无副作用校验包，不复制 Node 的 repair executor、账户策略、SQLite history sanitizer、SSE interceptor 或 HTTP owner。`timeout_ms` 遵循 JS safe integer 上限；JSON trailing value、数组 / 对象类型和 tool correlation 在入口处 fail-closed。
- `gatewaycodexresponses.Inspector` 已作为 relay 可选 transform inspector 接线：shadow 保持 byte-for-byte 透传；strict 与 safe repair 在任意 chunk boundary / EOF pending 下先缓冲完整 SSE frame，再决定下游提交。safe repair 只执行 contract 明确允许的 R0 `item.id` / `item_id` / `response.output[index].id` 重写，added / delta / done / completed 复用同一随机 client ID；R2、生成 ID 超限 / 冲突或重写失败均 fail-closed。被修复帧保留原 `event/id/retry/comment/extension` 行和换行形式，只替换 data JSON；未修复帧原字节透传。
- `gatewaycodexresponses.InspectJSON` 已补齐非流式 guard：先检查 response / compact envelope，再复用 Go validator；shadow / strict 保留原始 body，safe repair 只在未语义提交且 provenance 为 `raw_upstream` / `gateway_bridge` 时替换 output item 的 R0 ID，使用随机、有界、避免碰撞的 typed ID，重编码后再次校验。R2、unknown、request-history 修复、生成失败、超限或 post-validation 失败均不改 body 并 fail-closed；结果携带有界诊断、`repaired_safe` / `repaired_bridge`、rule ID 和 Go `CommitState` retry 语义。Go 采用结构化 JSON 重编码，保证未知字段的语义保真，不承诺 clean 路径字节重排。
- `gatewayresponse.Handler` 已把上述 guard 接入可调用的 response runtime seam。typed checkpoint 无公开字段，调用方只能通过 raw-upstream / gateway-bridge 构造器声明来源；2xx strict / safe 协议失败通过 `gatewayretry.ResponseSignal` 保留 typed 失败原因并向客户端暴露当前失败，不驱动下一候选；完整 HTTP 响应则通过 `ResponseDisposition` 默认透明写入下游。`explicit_policy` 当前只开启 Go classifier，不冒充 Node 账户策略动作。OpenAI-compatible 非流式 usage 使用与 SSE 相同的字段归一化，guard handoff 只保留有界 outcome / rule / diagnostic code，不复制正文。
- Go 有意比 Node 收紧 transport-only retry：只要任意下游字节已经写出，relay 就禁止换号；`late_violation` 仍按 semantic commit 标注。该差异避免 heartbeat 已暴露后重复流，但可能牺牲 Node 允许的 heartbeat 后透明重试，生产 owner 接线前不得写成完全等价。
- 该接线不代表已注册 Go listener、接管 Codex Responses production owner 或删除 Node firewall；仍需真实 gateway-bridge marker、账户策略读取、usage/audit explanation、上游 smoke 和 canary / rollback 证据。

## 2026-07-24 downstream commit 与请求元数据批次

- 新增 `gatewaydownstream.HTTPWriterSink`，以 `Stage -> Commit -> Write -> Snapshot` 管理响应状态。`WriteHeader` 本身即 transport commit；即使 flush 或首个正文写入失败、正文为零字节，也禁止跨账户重试。JSON 在 guard 后计算最终长度，透明失败响应保留状态和业务头，显式账户策略在提交前返回，SSE 延迟到首个输出或空流完成才提交。

## 2026-07-24 account policy PostgreSQL writer 批次

- `gatewayattemptloop.PolicyMutation` 已从整份 hydrated candidate 收敛为脱敏 typed facts，只携带 target/source 身份、target status、双 `config_revision/dispatch_revision`、规则动作、有界 reason/trace 和时间；凭据、代理、模型、API-key runtime、上游正文及原始错误 message 不进入 writer。调用方必须提供稳定 `MutationID`，attempt 层以绑定账户、分组、授权、双 revision、status、action 和 rule 的 canonical SHA-256 生成有界 transition，支持 outbox 幂等重放。

1. listener 只能拥有一次 client cancellation、原始 request body、下游 `http.ResponseWriter` 和最终 HTTP close。`ReadGatewayResponsesInbound` 已经是一次性、64 MiB 有界 body read 和 protocol preparation seam；它的 `RawBody` 只能进入一次后续 upstream preparation，不得被二次解析或替换为可重放的 HTTP body。
2. API Key 的提取、认证和 preflight 必须在 listener 内恰好完成一次，并把 canonical、非秘密的 preflight output 传给 route planning。`gatewayrouteplan.BuildFromPreflight` 已提供该单次调用边界：listener 必须调用它而非 convenience `Build`，不能再次 Resolve preflight 或多推进 shared route state。
3. model、stream、Codex metadata 与 protocol preparation 只从有界 ingress facts 取得。model 到 image/text lane 的升级、endpoint family 和 candidate window 均必须在同一 immutable input 上裁决；未经这一裁决不得以默认 text lane 选择 text body limit、timeout 或 slot 策略。
4. `gatewaybodyadmission` 只能在拥有认证 scope、route mode/scheduling preference、候选容量和最终 lane 后 acquire；request cancellation、响应 close、所有正常/异常 terminal 都必须幂等 release。现有 Node 是 pre-body admission，而 Go 现有候选窗口又依赖 body 中 model；在补出单次 preflight/candidate-capacity snapshot 与 image-upgrade 反证前，禁止把它接到 listener，也禁止用“body 后 admission”伪称等价。
5. listener 必须创建一个 request-local `gatewayrequestlifecycle.Lifecycle`，在每个实际 executor 调用前获得新的 opaque attempt generation；sink transition、candidate retry 与 terminal 都只能由该代次报告。`gatewayattemptloop` 仍独占 group 保序、candidate/API Key rotation 和 policy mutation，listener 不得自行重新排序或替换 candidate。
6. timeout 只能从单一 `GatewayTimeoutProfile` 映射到 wall、attempt first-byte、idle、total 和 uncommitted-attempt lifetime，并以同一 request `AcceptedAt` 创建 `gatewayrequestwall.Budget`。`FromLaneSettings`、`DisableTotalTimeout`、all-stream disabled 和 image wall preflight projection 已具备纯 core；listener 仍必须在 lane 最终确定后一次性映射，且不得自行补默认、重置 acceptedAt 或把 Chat image tool total 混入 relay。`FirstByteTimeout=0` 只表示本 attempt 不建首字节 timer；它不能代表 Node `timeoutsDisabled`，更不能静默移除 Go relay 的 idle/total 硬边界。
7. Codex compact keepalive 只能在 canonical Responses SSE、显式 runtime opt-in 和已验证 client profile 同时成立时由 listener 写入精确帧 `data: {\"type\":\"juhe_ai.keepalive\"}\\n\\n`。它必须记为不可伪造的 `transport-only/codex-keepalive` provenance，绝不能由上游 payload、普通 comment、任意下游字节或调用方 bool 伪造，且不得变成 semantic commit。
8. same-response candidate retry 是独立于 generic relay 的窄分支：仅 keepalive provenance、transport committed、semantic 未 committed、response 仍开放、未完成、非 gateway-local/downstream failure 且存在 typed error code 时才可尝试。任何语义提交、普通 transport byte、response close、client cancel 或 local/downstream failure 都是 hard fence；不能放宽通用 `Committed`、`RetryAllowed` 或 `gatewaystreamrelay` 的默认 terminal disposition。
9. response/attempt/lifecycle/usage/audit/slot lease 的 terminal 以 first-terminal-wins 收口；成功前必须已有 transport 或 semantic commit，失败终态不得覆盖已成功/关闭的 response。每条 retry、取消、超时和 response close 路径均须证明 lease/slot 恰好释放一次。

当前第 7-9 条仍只冻结 canonical `POST /v1/responses` 的 listener 入口；它不授权注册 Gemini path。下一 listener implementation batch 必须在同一 contract 内补充“候选耗尽且无语义输出”的 typed terminal writer 绑定：只能复用 `gatewaystreamrelay.EncodeControlledFailureEvent` 已有的私有 `TerminalDisposition`，且只允许精确的 Codex Responses、Claude Code Messages、GeminiCLI GenerateContent/Interactions SSE 画像。generic/unknown stream 继续只能断开，不能凭路径或 header 猜测补发事件；Gemini 空 SSE 的 `UNAVAILABLE` 不得作为泛化 retry 放宽或路由 owner 接管声明。

实施前验收必须新增 mock 级反证：重复 preflight 不推进 route state、image upgrade 不获取 text admission、取消/close 不泄漏 waiter 或 lease、zero first-byte 不删除 wall/idle/total、keepalive 不能伪造语义提交、普通 transport byte 不允许 retry、上述精确 keepalive 条件允许同一开放 response 的一次候选切换。随后才允许 isolated PostgreSQL、Redis 与 upstream smoke；仍不得修改 `deploy/owner-manifest.json`、声明 canary/owner、删除 Node 或注册 production gateway route。

## 2026-08-03 staged-ingress 协议阻塞审计（取代直接 listener 实施入口）

### 已核验事实

- `ReadGatewayResponsesInbound` 只有在一次性完整读取最多 64 MiB request body 后，才能获得 model 和相关 metadata；现有 `gatewayrouteplan.BuildFromPreflight` 需要 model，而 `gatewaybodyadmission` 的 admission 判断又需要最终 lane 和 candidate capacity。
- Node canonical Responses lane 的输入并不只有 model/stream：任意顶层位置的 `type`、`tools`、`tool_choice`、`generationConfig` 或 `generation_config` 都会参与；工具内部还会以嵌套 image tool、`responseModalities` 与 image MIME 影响结果。当前重复 JSON key 不会被拒绝，存在覆盖和 alias 优先级效果。
- 最终 lane 仍可在候选 model mapping/catalog 之后升级为 image；image 权限不足时，auto tool 又可降级为 text。因此 wire body 中较早看见的字段不是可直接用于 admission 的最终 lane 事实。
- `ClaimingExecutor` 仍未注册到 listener，也没有 Go listener 或 production response owner；它不填补上述 ingress/admission 顺序缺口。

### 当前判断与实施结论

- 现有 Node 行为没有一个固定、有界、可强制早出现的 wire envelope，能够在读取 body 前同时产出最终 lane、candidate capacity 和所有 admission 输入。因此不得为 Go staged ingress 或 listener 签发 `ImplementationContract`。
- 不得把 body 后 admission 伪称为 Node pre-body admission 的等价实现；也不得在未知或稍后可升级/降级的 lane 上默认 text。此结论取代本文件此前把未注册 listener 视为可直接实施的入口；此前 core/timeout/claim 记录仍是已存在的前置原语，不是 listener 接线授权。

### 2026-08-03 W10 ingress `ImplementationContract`（用户确认，fail-closed）

本节取代上方“尚未冻结”的前置条件。用户已明确授权按现行 Node 行为的参与字段与处理顺序冻结 W10 ingress，并要求任何重复字段、alias 冲突、未知工具、mapping/catalog snapshot 缺失均 fail-closed；不得以 Go JSON parser、隐式 alias 优先级或默认 text lane 替代该决定。

**范围与非目标：** 本契约只授权纯 Go 的完整 request-body 解析、immutable ingress snapshot、final-lane projection 与 admission mock。它不授权 HTTP listener/route 注册、提前读取 body、账户选择、slot/lease、真实 upstream、owner manifest、canary、drain 或 Node 删除。Node 仍是唯一 production owner。现有 Node 对 JSON duplicate key 的“后值覆盖”只是本次收紧所依据的历史事实，不是 Go 的兼容目标；Go 拒绝此类请求是经用户确认的安全语义。

1. **lane 输入、顺序与 final lane。** `model`（非空 string）、`stream`（可选 bool）、endpoint/model 的 image hard signal、任意顶层 `type`、`tools`、`tool_choice`、唯一的 `generationConfig` 或 `generation_config` 都必须进入同一 parsed request snapshot。初始 lane 先由 endpoint/model hard signal 与 body image signal 共同给出；随后同一个 immutable mapping/catalog snapshot 只能将 text 升级为 image，不能把已有 image 信号降成 text；最后才应用 image permission 的已定义 auto-tool downgrade。admission 只能消费该 final lane 和同一 snapshot 的 candidate capacity，不能以 body 中较早观察到的 lane 或缺省 text 准入。
2. **body 边界、duplicate 与 alias。** 本阶段不存在“可在读取前强制出现”的 wire envelope。输入必须是一个完整、有界的 JSON object；syntax 非法、根不是 object、`model` 缺失/类型错误、受检查字段类型错误、任一 object 内 duplicate key 都拒绝。`generationConfig`/`generation_config` 同时存在即为 alias 冲突并拒绝，即使值相同；同一 config 内 `thinkingConfig`/`thinking_config`、`responseModalities`/`response_modalities`、`responseMimeType`/`response_mime_type` 同时存在也同样拒绝。不得使用“最后值覆盖”或 camelCase 优先级。
3. **工具、嵌套与 image 信号。** `tools` 与 object 形态 `tool_choice.tools` 按 Node 现有的最多四层嵌套检查；超过边界、非预期 container、空 type 或未知 type 一律拒绝。工具 type 的允许集合及其 image 属性必须来自同一 immutable catalog snapshot，不能由本地 fallback 推断。顶层 `type=image_generation`、`tool_choice=image_generation`、`tool_choice.type=image_generation`，以及 `tool_choice=required` 且仅存在 image tools，均为 forced image；任意已知 image tool、`responseModalities` 包含 `IMAGE`（大小写无关）或 image MIME 则为 image 倾向。`responseModalities`/MIME 不是 auto tool，不能被权限降级删除。
4. **mapping/catalog snapshot。** final projection 必须持有非空 revision、明确 model、明确 candidate capacity、完整 tool catalog 与一项确定的 model lane decision；其中任一项缺失、model 不匹配、decision 未知或相互冲突即拒绝。snapshot 是一次 preflight 的不可变值，后续 mapping/catalog 刷新不能改变本 request 的 lane/capacity；mapping 只能 upgrade 为 image，不能覆盖显式 image 信号。`candidateCapacity=0` 是已知的 admission 输入，不等同于 snapshot 缺失，交由后续 mock 返回不可准入。
5. **image permission 与降级。** image permission 为 false 时，只有“非 hard endpoint/model、没有 forced image、没有 modalities/MIME image signal，且 image 仅来自可移除的 auto image tool”的请求允许移除全部 image tools 后以 text lane 继续；请求 snapshot 必须记录被移除数量与 downgrade reason。顶层 type、forced tool choice、required-only image tool、image endpoint/model、image MIME/modalities 或缺少 snapshot 均不得降级，返回明确拒绝。未知 permission 状态也拒绝，绝不默认允许或默认 text。

**核心不变量：** `Parse -> Finalize(snapshot) -> admission mock` 三步只传递不可变值；任何错误都不返回部分 snapshot，不能进入 route/candidate/transport。Go core 不读取数据库、不 materialize 账户、不改变 request body，也不把 output 接到 listener。

**错误分类：** `invalid_json`、`top_level_not_object`、`duplicate_json_key`、`generation_config_alias_conflict`、`generation_config_field_alias_conflict`、`model_required`、`invalid_stream`、`invalid_generation_config`、`invalid_generation_config_field`、`invalid_tool_definition`、`invalid_tool_choice`、`tool_depth_exceeded`、`unknown_tool_type`、`snapshot_missing`、`snapshot_revision_missing`、`snapshot_model_missing`、`snapshot_model_mismatch`、`candidate_capacity_unknown`、`tool_catalog_incomplete`、`snapshot_mapping_lane_invalid`、`image_permission_denied`、`admission_finalization_required` 与 `admission_capacity_unavailable` 必须可由调用方区分；不返回模糊的成功或 fallback。

## 2026-08-04 W10 高并发 client-IP slot 的执行边界

- pre-lease 只允许 `ready`、`fallback` 与内部 `queue` 三种形状；`queue` 必须要求后续阶段，`ready`/`fallback` 不得要求后续阶段，其他或矛盾形状一律在 acquire 前 fail-closed。`ClientIPAcquirer` 是该执行 seam 的必需依赖；被拒绝的 decision 原样随 typed result 返回，不会 queue、claim 或上游 attempt；driver 失败、已取得受限 slot 却缺 lease、或被拒绝却携带 lease 也全部 fail-closed。这样 future listener 才能按三协议事实编码 429/取消，而执行层不会伪造响应。
- 对实际 acquired lease，`Run` 覆盖 all-busy queue、refresh、claim、attempt、fallback、busy 和 error 的整个同步执行范围，并以一次 `defer` 释放；这与 Node 在 fallback/abort/exception/response terminal 的 once-only release 意图一致。跨 route-group fallback 的重新 acquire、HTTP finish/close 订阅、client-IP audit metadata 和最终 response writer 仍必须由完整 listener owner 实现，当前不注册任何路由。
- 定向 normal/`-race` 覆盖 initial fallback 的零 acquire、fallback miss 的 `prepare -> client-IP -> queue/refresh` 顺序、拒绝 slot 的零后续阶段/零 claim、malformed pre-lease/driver decision 的 fail-closed 与 successful attempt 后 state 归零；并已复跑 high-concurrency orchestration、client-IP、attempt-loop 相邻模块。本项不改变 Redis runtime-driver selection、production owner 或 Node gateway 的唯一生产归属。

## 2026-08-04 W10 attempt-loop 到 request lifecycle 的 generation handoff

## 2026-08-04 W10 当前 group execution owner

- Node route owner 只在当前 prepared group 内执行 queue/claim/attempt；当它决定换 group 时，必须完整 prepare 目标 group 并取得 target client-IP decision 后才释放来源 client-IP lease。`gatewaycurrentgroupexecution` 因此只接受 `BuildFromOrchestration` 的 finalized `Execution`，并且只消费第一条 non-empty batch。legacy `Build` 没有 final lane/request shape proof，会被拒绝。

## 2026-08-04 W10 finalized execution 的 request lifecycle owner
