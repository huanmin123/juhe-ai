# J2：账户余额刷新完整迁移契约

> 状态：L2 Go jobs 实现与 Node 只读投影适配已落地，2026-08-19。默认仍 fail-closed：生产 owner 未切换，Node scheduler 未停止；启用前必须完成本文件第 6 节的独立发布验收。

## 1. 目标与边界

J2 迁移的是账户上游余额刷新完整功能：周期候选、首次健康成功后的自动探测补偿、手动刷新共用的直接上游查询、账户级租约、快照与下一次刷新时间的 CAS，以及失败/不支持结果的可观察性。

J2 不包含账号健康状态、冷却复测、OAuth token 刷新、模型质量检查、余额配置写接口、网关请求生命周期、用量/统计 writer 或 Gateway runtime。余额结果不得修改 `accounts.status`、健康失败窗口或 circuit 状态，也不得生成 usage record。

管理端的 `/balance/test-draft` 是不持久化的同步草稿校验接口，不属于 J2 后台 owner 范围，继续由 Node 管理接口直接执行，不经过 Go jobs bridge。

## 2A. 本轮实现对象

- Go `backend-go/projects/jobs/internal/accountbalance/` 已提供 jobs Store、owner/account lease fence、幂等 outcome、CAS snapshot、直接 HTTP、凭据 envelope、五种 builtin/custom adapter、周期/首次探测/手动 runner、45 秒默认 cycle budget 和 bounded concurrency。周期轮次先补偿 `enabled + next_refresh_at IS NULL` 的遗失调度，再处理到期候选；读取会有界超额扫描，隔离坏凭据/配置/代理行而不饿死后续账户。Go-owner 只允许 PostgreSQL jobs Store；它必须与 Node outcome projector 指向同一个 `juhe_jobs` 数据库。启用时必须显式设置 `JUHE_AI_ACCOUNT_BALANCE_JOBS_OWNER=go`；Go jobs 同时提供受控 `/account-balance/manual` bridge。
- `backend-go/projects/jobs/cmd/juhe-ai-jobs` 仅在 `JUHE_AI_ACCOUNT_BALANCE_ENABLED=true` 且 J2 专用配置完整时装配该服务；`/health` 独立报告 `accountBalanceEnabled/accountBalanceReady`。
- Go PG direct-input 只读 `juhe_business.accounts/proxy_profiles`，不写业务库；Node 新增 `account-balance-jobs-outcome.repository.ts` 与 `account-balance-jobs-projector.service.ts`，只读取已 `committed` 的 jobs outcome 并按 `systemAccountId + configRevision + expectedNextRefreshAt` 做业务/统计投影。周期 builtin 成功会将实际 adapter 回写为 `preferredBuiltinAdapter`；manual 不使用周期的 `nextRefreshAt` fence。
- Node `account-balance-handover.ts` 提供默认关闭的 owner gate；显式 Go owner 模式会停止 Node J2 scheduler/recovery、禁止旧 writer/cleanup/IPC 写入口，并把手动刷新发送到 Go bridge。没有完整部署 gate 时仍不得设置 owner=go。

## 2. 当前 Node 行为（取证基线）

- `backend/src/modules/background/background-jobs.ts` 每分钟调度 `account-balance-refresh`，另有 `account-balance-auto-detect-recovery` 补偿首次探测意图。
- `account-balance-refresh.job.ts` 先读取 recovery 候选，再读取到期候选；批次、单候选 deadline、取消、运行预算和可调用 runtime 状态过滤均在本轮内固定。runtime snapshot 不可用时旧 Node 实际按「全部可调用」继续处理；Go 直接 owner 不读取 Gateway/Redis/IPC runtime state，固定遵循这一不可用分支，既不伪造 runtime 过滤，也不把候选误记为上游失败。
- `account-balance-query.service.ts` 对每个账户使用独占 lease；lease 忙返回 `lease_busy`，不发上游请求。租约覆盖自动刷新、首次探测和手动刷新。
- 当前周期刷新结果枚举为 `refreshed`、`lease_busy`、`stale`、`failed`、`unsupported`。`stale` 表示配置/刷新代次 CAS 失败或候选 deadline 到期；不能自动覆盖新配置。
- 自动刷新只有在账户仍为 `active + schedulable + api_key + balance_query_enabled`、未删除且非授权实例时才允许提交。配置 revision、配置 JSON 和 `balance_query_next_refresh_at` 共同构成写回 fence。

## 3. 候选与输入

Go service 的启动门禁使用 `JUHE_AI_ACCOUNT_BALANCE_ENABLED`、`JUHE_AI_ACCOUNT_BALANCE_JOBS_OWNER=go`、`JUHE_AI_ACCOUNT_BALANCE_OWNER_ID`、`JUHE_AI_ACCOUNT_BALANCE_STORE=postgres`、`JUHE_AI_ACCOUNT_BALANCE_POSTGRES_URL`、`JUHE_AI_ACCOUNT_BALANCE_INPUT_POSTGRES_URL`、`JUHE_AI_ACCOUNT_BALANCE_CREDENTIAL_SECRET`、32 字节以上的 `JUHE_AI_ACCOUNT_BALANCE_JOBS_HTTP_SECRET` 及专用 lease/timeout/batch 参数；`JUHE_AI_ACCOUNT_BALANCE_RECOVERY_BATCH_SIZE` 不得超过 batch，`JUHE_AI_ACCOUNT_BALANCE_CYCLE_BUDGET` 必须不短于单探测且被 owner lease 覆盖。未设置 `ENABLED=true` 时不打开 J2。Node 手动 bridge 使用 `JUHE_AI_ACCOUNT_BALANCE_JOBS_HTTP_URL` 和 Bearer HTTP secret，并要求独立验收后同时显式设置 `JUHE_AI_ACCOUNT_BALANCE_JOBS_COMMAND_WIRING_READY=true`、`JUHE_AI_ACCOUNT_BALANCE_JOBS_INPUT_RESULT_READY=true`、`JUHE_AI_ACCOUNT_BALANCE_JOBS_PROJECTION_READY=true` 与 `JUHE_AI_ACCOUNT_BALANCE_JOBS_NODE_OWNER_DRAINED=true`；projection 必须启用，且 `JUHE_AI_ACCOUNT_BALANCE_JOBS_OUTCOME_POSTGRES_URL` 必须与 jobs Store 指向同一 PostgreSQL 数据库。其凭据 secret 必须与 Node `encryptJson` 使用的 `JUHE_AI_SECRET` 对齐。jobs Store 使用独立 `juhe_jobs.account_balance_*` 表，不能指向 Node 业务 SQLite。

候选至少包含：`accountId`、`systemAccountId`、`configRevision`、已解密凭据引用、余额查询配置、`nextRefreshAt`、可选 `proxyProfileId`。余额查询只允许单个有效 API Key；多 Key 账户必须保持关闭并返回现有中文原因，不得静默选择第一个 Key。

配置为严格 JSON：

- `adapter=builtin`：可选 `preferredBuiltinAdapter`，默认刷新周期 5 分钟；
- `adapter=custom`：必须提供同源相对 `path`，以及 `remainingPointer` 或成对的 `totalPointer + usedPointer`，可选正数 `divisor`；
- 周期范围 `1..10` 分钟；未知枚举、跨源路径、非法 JSON Pointer 或不完整配置必须成为可观察的确定性失败。

凭据只能来自已审计的加密引用解析；不得将明文 key 写入日志、错误、指标、任务事实或测试产物。授权实例、非 API Key 账户和已撤销/不可调度账户不得进入 J2 候选。

## 4. 直接上游诊断适配器

Go `jobs` 只能使用账户自身 `base_url`、代理和 API Key 直接请求真实上游；禁止调用 Node、Go `gateway`、Gateway HTTP、IPC、Redis Stream 或网关协议桥接。请求为单次 `GET` JSON，禁止重定向，响应上限 256 KiB，继承账户候选 deadline 与取消信号。

首个冻结适配器及其解析规则：

| 适配器 | 关键字段 | 结果口径 |
| --- | --- | --- |
| `sub2api` | `unit=USD`，`remaining`/`balance` | 钱包/订阅余额；订阅 `-1` 为 `unlimited` |
| `newapi` | `data.total_available`、`data.unlimited_quota` | quota 按 `quota_per_unit` 换算；无限 quota 为 `unsupported` |
| `openai_billing` | billing subscription + usage | `hard_limit_usd - total_usage/100`；无限硬额度为 `unsupported` |
| `litellm` | `info.max_budget - info.spend` | budget 美元余额；缺预算为 `unsupported` |
| `user_balance` | `balance` | wallet 美元余额 |
| `custom` | JSON Pointer | 余额或总额减已用，再按正数 divisor 换算 |

所有金额计算使用十进制定点语义；禁止浮点累积误差。无法识别单位、字段或 JSON 结构必须是确定性 `unsupported`/解析失败，不能回退其他适配器（除非 `builtin` 的既有有界探测顺序明确允许）。网络、超时和取消保持 transient 失败，不伪装成余额为零。

Go J2 direct HTTP 支持冻结 proxy profile 的 HTTP/HTTPS 与 socks5/socks5h（均含认证）。`socks5` 在本地解析目标，`socks5h` 将主机名交给代理解析；缺失、禁用或未知类型的 proxy profile 仍拒绝候选，绝不静默直连。

## 5. 快照、CAS 与失败语义

快照状态保留 `pending`、`refreshing`、`fresh`、`unlimited`、`unsupported`、`failed`，并可带 `remainingUsd`、原始值/单位、basis、错误和最后尝试/成功时间。自动刷新 transient 失败最多累积三次；未达到阈值时保留已有 fresh/unlimited 快照，达到阈值才进入 `failed`。确定性不支持结果不覆盖健康状态，只更新余额快照和下一次刷新时间。

提交必须在短事务内按 `accountId + configRevision + expectedConfig + expectedNextRefreshAt` CAS；快照与账户配置/下一次刷新时间在 PostgreSQL 中原子提交。Go jobs Store 的本地 prior-snapshot CAS 字段与对外 outcome 的业务 input fence 严格分离，绝不把本地 `input/config` 代次泄漏给 Node projector。自动 periodic/first-probe outcome 带冻结 `expectedNextRefreshAt`（recovery 的显式 `null` 也要保留）；manual outcome 不带该业务 due fence。首次写入 outcome 先标记为未提交，只有 snapshot CAS 成功才在同一事务标记 `committed`；投影器不会读取未提交 stale outcome。重复 `requestId` 只以不可变 outcome 身份判定幂等，后续刷新推进当前 snapshot 不得把原已提交请求变成 stale。CAS 失败只返回 `stale`，不得重试旧结果、回退 Node 或改写新配置。Go-owner handover 不支持 SQLite jobs Store：Node projector 只读取同一 PostgreSQL `juhe_jobs` source，任一 SQLite/mismatched source 配置必须在启动前拒绝。

## 6. Owner 与切换门禁

当前生产尚未切换 owner；代码路径在显式 `JUHE_AI_ACCOUNT_BALANCE_JOBS_OWNER=go` 时由 Go 接管周期/首次探测/lease/upstream/outcome，Node 只做 outcome 投影与手动 bridge，并停用旧 scheduler、recovery、writer、cleanup。Go 只有在以下证据全部具备后才能接管发布：

1. PostgreSQL `juhe_jobs` J2 表、业务/统计只读授权、候选与快照事务 CAS、`committed` outcome 过滤和 cursor 表迁移；
2. J2 只以 PostgreSQL source 运行 Node outcome projection，且实际 Go jobs 配置、input source、Node drain 与 projector readiness 都已通过 handover gate；
3. 所有适配器的成功、无限、单位错误、JSON 错误、超时、连接中断、取消、代理和多 Key fixture；
4. Node→Go→Node 读回、重启恢复、lease fence、单条失败隔离和候选 deadline 证据；
5. Node scheduler、recovery、IPC/queue、余额 writer、旧快照清理和部署入口清零后，完整归档 manifest 与可回滚 owner 证据。

在这些门禁完成前，J2 Go service 只能以显式 opt-in 运行于隔离 dev；不得在发布配置中打开生产 owner，不得停止 Node scheduler，不得添加 Node fallback、双写或共享队列。Node outcome projector 只能在独立 db-service 进程完成 source fence、游标和回滚演练后注册。
