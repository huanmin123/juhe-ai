# BUG-0317 F3 审计租约失租后被自身采集续活，健康检查持续 503

- 严重程度：P1（健康检查持续 503，监控把站点看成宕机；审计采集在 I/O 窗口丢弃）
- 发现时间：2026-10-14 22:04
- 发现方式：生产巡检（BUG-0313 重启后 8 小时复核）
- 模块：后端 / 网关 / F3 audit owner 租约 / F4 operation-log 同构面
- 关联计划：无

- 责任人：AI

## 问题概述

- 现象：2026-10-14 13:49 整机重启后，gateway `/health` 与 Caddy 健康检查从 13:56 起持续 503。健康体只有 `auditLogReady=false`，其余 owner 组件均为 true。F3 audit owner 每 30 秒重试接管，连续失败 365 次以上，原因都是「重启后 F3 audit owner lease 仍被其他 owner 持有 (owner e05f1c02c71c)」。
- 期望：进程失租后应在租约过期后重新接管，健康检查恢复 200。
- 实际：租约行 `owner_id=e05f1c02c71c`、`fence_token=321` 一直未过期。容器 hostname 也是 `e05f1c02c71c`，日志里的「其他 owner」就是当前容器自己。
- 影响范围：监控/拨测全红；审计主数据仍在落库，但 I/O 饱和窗口内 lease 续约超时丢了 141 条采集、72 条持久化失败。`/v1` 主链不受这条 503 阻断。

## 复现步骤

1. gateway 持有 F3 owner 租约，采集路径按每条记录用 keeper 的 `{owner_id, fence_token}` 续约。
2. 续约连续失败超过 2×TTL（默认 60 秒），keeper 放弃所有权。
3. keeper 失租后 `Lease()` 仍返回旧快照。采集路径继续用同一 owner/fence 续约成功，`lease_until` 永不落回过去。
4. owner 组件 `reacquire` 只抢已过期行，于是每 30 秒失败一次，`/health` 保持 503。

生产当场恢复：把 `juhe_dataset.audit_log_owner_leases` 中 `lease_key='f3-audit-log-persistence'` 的 `lease_until` 置为当前时间。60 秒内 fence 321→322，日志出现「F3 audit owner lease 已重新获取」，gateway 与 Caddy 均恢复 healthy。

## 根因分析

两条路径互相喂活：

1. `AcquireOwnerLease` 的冲突分支只在 `lease_until <= now()` 时接管。owner_id 是进程身份（默认 hostname，同一容器跨整机重启不变），所以「等过期」对同一进程的失租恢复并不成立。
2. 失租后 `LeaseKeeper.Lease()` 仍返回旧 `{owner_id, fence_token}`。F3 producer 每条记录调用 `RenewOwnerLease`，谓词按 owner 与 fence 匹配，续约成功，把已丢失的行永久续活。
3. 日志文案 `(owner %s)` 打印的是获取方自己的 owner_id，不是行内持有者，排障时会误判成「另一个进程持有」。

F4 operation-log 的 keeper、producer 与 acquire SQL 同构，本次没有在生产触发，但同一输入会走到同一死锁，所以同批修复。

## 修复方案

- 获取侧：F3/F4 的 PostgreSQL 与 SQLite acquire 冲突分支增加 `OR owner_id = excluded.owner_id`。同 owner 的未过期行直接接管并递增 fence；旧世代写入被 fence 拒绝。跨 owner 仍必须等过期，BUG-0228 的双 owner fail-fast 契约不变。
- 发放侧：F3/F4 keeper 在 `lostErr != nil` 时 `Lease()` 返回零租约。采集、热搜索与手动清理路径已拒绝空 owner 或非正 fence，失租世代不能再续活旧行。`fatal()` 在写 `lostErr` 之前读取租约，终态日志仍带真实身份。
- 测试：
  - `TestSameOwnerReacquiresUnexpiredLease`（F3/F4）：同 owner 未过期接管并递增 fence，旧 fence 续约被拒，异 owner 仍拒绝。
  - `TestLostKeeperLeaseIsZero`（F3/F4）：0 行续约终态后 `Lease()` 为零租约。
  - 启动冲突场景 `TestW1MBootF4OwnerPrivateLeaseLifecycle` 的进程 2 改为 `w1m-f4-rival`，保证测的是跨 owner 冲突，而不是被新分支直接接管。
