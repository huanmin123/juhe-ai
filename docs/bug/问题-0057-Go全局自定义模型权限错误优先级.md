## 问题概述

Go 普通用户创建全局自定义模型时，在部分无效请求组合中先执行请求能力或价格值域校验并返回 `400`。Node 当前契约会先拒绝普通用户的全局作用域写入并返回 `403`。

该差异只存在于已迁移 Go 自定义模型写接口。期望顺序是先完成 provider、scope 和请求结构合法性判断，再执行全局作用域权限判断；无权限调用者不应先获得后续能力或价格规则的校验结果。

## 根因分析

- Go service 在构造能力和价格保存输入之后才判断普通用户是否允许创建全局模型。
- 原测试分别覆盖权限拒绝和能力校验，没有覆盖“普通用户 + 全局 scope + 非 GPT 能力字段”这种组合输入。
- 单项测试均通过，但组合场景暴露了 Node/Go 错误优先级漂移。

## 修复方案

- 保留 provider、scope 和结构合法性校验的既有顺序。
- 将普通用户全局模型权限判断提前到能力和价格值域校验之前。
- 增加普通用户创建全局 Anthropic 模型并提交 GPT 请求能力字段的组合回归，固定返回权限错误。
- 不改变管理员全局模型、普通用户个人模型和合法能力输入的现有行为。

## 防复发要求

- 权限、结构和业务值域存在多个失败条件时，必须增加组合输入测试固定错误优先级。
- 无权限调用者不需要知道的业务规则应在权限通过后再校验。
- Node/Go 对齐不能只比较状态码集合，还要比较同一组合请求最终选择的错误。

## 完成总结

Go 自定义模型写接口已与 Node 当前全局作用域权限错误优先级一致。真实 PostgreSQL smoke、生产切流和 Node 自定义模型写路径删除仍按 PLAN-0081 后续门禁推进。
