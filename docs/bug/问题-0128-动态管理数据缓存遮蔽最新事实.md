# BUG-0128 动态管理数据缓存遮蔽最新事实

## 基本信息

- 编号：BUG-0128
- 状态：已修复（自动化、构建与隔离 Browser 验证）
- 严重程度：P1
- 发现时间：2026-07-27
- 发现方式：用户反馈与本地筛选/刷新验证
- 模块：前后端 / 使用记录 / 动态详情 / 模型选项 / 表监控 / 页面生命周期 / 上游错误诊断
- 关联计划：PLAN-20260727T090521327Z
- 关联 bug：无

## 问题概述

- “我的使用记录”首屏可命中最长 36 小时的后端热列表，手动刷新仍可能得到旧响应；请求来源默认筛选还会隐藏非网关记录，容易被误判为新记录丢失。
- 管理页面默认 `KeepAlive`，动态页面返回时可能长期保留旧组件实例；代理选项还有跨页面会话结果缓存。
- 表监控历史上曾在后台物化快照之上叠加 30 秒进程内响应缓存；该实现已删除。当前为降低管理员首屏重查询成本，仅对默认首页采用可观测的 10 分钟 fresh / 最长 1 小时 stale SWR，且支持 `refresh=true` 旁路。
- 账户与日志等动态详情存在 5 秒前端结果缓存，模型检测账户选项和聊天模型列表分别存在 10 秒、30 秒结果缓存。
- 完整非 `2xx` 上游响应在使用记录中被固定写成“上游返回非成功 HTTP 响应”，真实 `message/code/type` 被覆盖。

## 根因与修复

- 删除使用记录首屏缓存、写入侧发布、Redis 预热任务、预热候选查询和旧专项测试；列表路由每次直接调用当前 repository。
- 页面组件缓存改为路由显式 opt-in，仅保留确实需要恢复长会话的 AI 问答；筛选、分页、排序继续由页面状态缓存保存。
- 删除代理选项跨页面结果缓存，只保留相同在途请求合并；删除表监控旧的 30 秒进程内响应缓存，仍读取后台最新物化快照；后续为默认首页增加有界 SWR，搜索、翻页和趋势历史仍直读。
- 删除动态详情结果缓存；模型检测账户选项与聊天可用模型只保留相同在途请求合并，上一批完成后的下一次读取必定访问后端事实源。
- 统计日期窗口保留 60 秒稳定元数据缓存，但修正个人/管理作用域，并让显式刷新强制绕过。
- 完整非 `2xx` 使用协议解析器提取真实上游错误；无结构化字段时使用有界正文摘要。错误码和消息脱敏，消息最多 1000 字符，诊断清洗输入最多 4000 字符。

## 验证

- 前后端 `typecheck`、完整 build、使用记录查询防护、统计窗口、表监控、代理选项、后台任务注册和上游 opaque 错误回归通过。
- 隔离 Browser 在桌面点击刷新后捕获新的使用记录 GET 与 HTTP 200；写入唯一最新记录后再次刷新，记录成为首条。
- 1280px 与 390px 页面均显示该最新记录，无横向溢出、遮罩残留或控制台 warning/error。
- Browser 不支持当前移动视口的真实 touch 注入；移动下拉刷新由源码契约回归覆盖，未伪记为真实手势通过。
- 隔离 Browser 连续两次展开模型检测的目标账户下拉，两次均捕获独立的 `/my-model-checks/account-options` 请求，且控制台无 warning/error。
- 隔离库没有可创建聊天会话的默认 API Key，聊天模型下拉未做伪造页面通过；前后端模型列表、能力读取、并发合并、取消与懒加载由专项回归覆盖。

## 下次遇到

- 先区分“记录尚未落库”“页面筛选隐藏”“响应缓存陈旧”三类问题，再检查列表请求是否真实发出。
- 高频事实 API 不应叠加脱离写入失效链路的响应缓存；需要性能优化时优先使用索引、分页、分片、读 worker 或权威预聚合。
- 上游错误诊断必须保留真实语义，但任何错误文本进入使用记录前都要脱敏和限长。
