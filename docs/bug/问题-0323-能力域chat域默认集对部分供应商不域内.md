# 问题-0323：能力域 chat 域默认集对 volcengine/qwen/hybrid 不 ⊆ 域允许集

- 优先级：P3（响亮失败，无静默数据风险）
- 状态：已修复（2026-10-16，用户裁决根治；同日 D6 废除交付独立复审发现并登记）
- 引入基线：能力域拆分 M2（2026-10-12 交付），非 2026-10-16 D6 废除交付引入。

## 修复结果（2026-10-16）

`DefaultEndpointModesForDomain` chat 分支改为与域 lane 集、词表双重求交：现行默认本就域内的供应商（openai 族/gemini/anthropic/glm）逐项不变（I3 口径收窄为「现行默认域内的逐项不变」）；现行默认不含对话值的供应商（volcengine/qwen 缺省 `video_get`）落词表内基础对话对 `["chat_json","chat_sse"]`；hybrid 收敛为域内允许集（并集序保序）。前端镜像 `accountCapabilityDomains.ts` 同一收敛点同步。I3 pin 测试（`TestM2ChatDomainLegacyDefaultsPin` 与前端对应用例）按新口径重写；volcengine×chat PATCH 删键用例从 400 翻转为 200 重置 `["chat_json","chat_sse"]`；新增 volcengine chat 缺省 modes 创建 201 用例。验证：`go test ./internal/accounts/... -count=1` 全绿 + 前端 vitest accounts 140 用例全绿。原「现状语义」小节保留作历史记录。

## 现象（历史）

`accountscore.DefaultEndpointModesForDomain` 的 chat 分支（`backend-go/projects/gateway/internal/accounts/accountscore/capabilityallowed.go`，`case CapabilityDomainChat`）只把「现行（chat 时代）写侧默认集」与**供应商写侧词表**求交，不与 chat 域 lane 集（13 值锚集）求交；其余三域（video/audio/image）均与 lane 集求交。由此对部分供应商组合，chat 域默认集不是域内值：

- volcengine / qwen：现行缺省为 `video_get` → chat 域默认集 = `["video_get"]`，越界；
- hybrid：现行缺省为全词表并集 → chat 域默认集含全部媒体值，越界。

## 影响（历史，修复前）

1. **新建**：这三类组合创建 chat 域账户若不显式携带 `supported_endpoint_modes`，缺省播种（`write.go` 用 `DefaultEndpointModesForDomain`）与新建「声明 ⊆ 域允许集」严格校验冲突 → 400。现状语义 = 操作者必须显式声明对话能力才能建户（响亮失败，可绕过）。
2. **编辑删键**：2026-10-16 D6 废除交付的 PATCH 删键（null）路径按域默认集重置后走同一严格校验，volcengine×chat 组合 null 删键返回 400「账户能力域对话不支持上游接口能力：video_get」。

无静默数据风险：越界值不会落库。

## 根因

chat 分支为满足 I3 pin（「chat 域缺省与现行归一化默认逐项一致」）直接复用 `legacyDefaultEndpointModes`，而该现行默认对媒体优先供应商（缺省媒体值）与「对话域 lane 集」在 v8-A 对话域纯粹化后不再天然相容；video/audio/image 三域分支无此历史包袱，均按 lane 求交。
