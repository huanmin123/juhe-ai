# BUG-0238：管理面账户编辑明细接口回显明文凭据

- 状态：已回退（2026-09-30 同日用户二次裁定整体回退，随 BUG-0253 实施；未发布，无线上影响）
- 定性：安全契约收紧（用户新契约，非回归修复）
- 引入：Node 时代既有行为，Go 迁移忠实移植（`projectEditableCredentials` 注释自述 "editing reads full credentials"）
- 契约决策：用户 2026-09-30 裁定（三轮收敛终版）——明细接口不得返回明文凭据，敏感字段返回**加密占位内容**（密码框自然显示为遮挡态）；点击眼睛时通过独立 reveal 接口取回**真实完整**凭据（含多 Key 池全部 `api_keys`）。

## 1. 现象与影响面

- `GET /__aisys__/api/accounts/{id}`、`GET /__aisys__/api/accounts/{id}/edit-basic`（及 `my-accounts` 对应路由，admin/self 两面）经 `projectEditableCredentials`（`backend-go/projects/gateway/internal/accounts/list.go`）把白名单凭据键**明文**返回。
- 前端编辑抽屉打开即调用 `editBasicDetail`，明文 `api_key`/`api_keys`/`access_token`/`refresh_token`/`client_secret` 每次都到达浏览器；`AccountApiKeySection.vue` 的 `a-input-password`（自带眼睛）只是纯前端遮挡，无安全意义。
- 验收套件 `TestAcceptanceManagementBackbone/accounts` 的断言（"明细不得回显明文密钥"，迁移期写入）自引入起从未跑绿——Node 实际行为同为明文回显（`migration-backup-1` 终档 `account-edit-basic.repository.ts` 已核实），该断言表达的即本契约。
- 不受影响：列表接口（`credential_mask` 既有掩码）、`clone-context`（只回 Key 数量/策略/权重，已核实无明文）。

## 2. 契约（用户裁定终版）（已废止，2026-09-30 整体回退）

敏感键集合：`api_key`、`api_keys`、`access_token`、`refresh_token`、`client_secret`。非敏感键（`base_url`、`supported_endpoint_modes`、`api_key_strategy`、`api_key_weights`、`client_id`、`quota_project_id`、`oauth_type`、`project_id`、`tier_id` 等）不受本契约影响，原值返回。

1. **明细返回加密占位**：`edit-basic` / `detail` 响应中，敏感键的值替换为统一密文占位符 **`__ENCRYPTED__`**（`api_keys` 数组逐项替换为该占位符；字段因此"有内容"，密码框自然显示为遮挡圆点，无需 placeholder 提示机制）。响应新增顶层布尔 `credentialsMasked: true`（存在任一敏感键被替换即 true）。占位符字面量以前后端共同常量固化于本契约，两端一致。
2. **按需解密（reveal）**：新增 `POST /accounts/{id}/reveal-credentials`（含 `my-accounts` 版本），权限与 403/404 语义同 detail（admin 全量、owner 作用域、授权实例行 403）；返回完整明文 `projectEditableCredentials` 投影（**含全部 `api_keys` 池真实值**）与 `configRevision`；响应带 no-store。
3. **审计**：reveal 写操作日志（`module=accounts`、`action=reveal_credentials`、`OperationKey=accounts.reveal_credentials`、Summary "查看账户凭据明文：<账户名>"），`Changes` 只记被查看的敏感键名，不记值。
4. **占位防回写（前后端双保险）**：
   - 后端 PATCH 通道（`applyAccountCredentialsPatch` / `mergeAccountCredentialsForUpdate` 入口）：requested 中敏感键值 `=== __ENCRYPTED__` → 该键视为未修改、剔除（走既有 preserve 保留现值）；`api_keys` 数组先滤除占位项，滤后为空数组 → 视为省略该键，滤后非空 → 以滤后数组为新值。
   - 前端保存 payload 同规则：单键值仍为占位 → 省略；`api_keys` 滤占位后为空 → 整体省略（含 `api_key_weights` 同步省略）；用户实际输入的值（≠占位）照常提交。
5. **前端交互**：编辑表单敏感字段加载为占位值（密码框显示圆点，`api_keys` 池保留真实行数以维持权重列与运行时状态标签，每行占位）；点击眼睛（`a-input-password` 的 `update:visible` 事件，ant-design-vue 4.2.6 无 `visibilityChange` 事件名，首次可见且 `credentialsMasked && !credentialsRevealed`）调用 reveal，以真实值替换全部敏感字段（池任一行眼睛触发一次全量替换）；textarea 型 token 字段（OAuth 编辑态）以"查看明文"按钮触发（无眼睛可点）；失败走现有错误消息模式。
6. **边界与后续处理**：`POST /accounts/export` 为管理员主动导出迁移场景（含凭据属导入恢复语义，且**无操作日志审计**），处置方式**已结案（2026-09-30 随整体回退）**：保留明文导出 + 保留 m09 导出审计增强（`bug0238_export_audit_test.go`），随回退保留；OAuth 授权/换 token 流程的轮换回执只返回 id/configRevision/updatedAt（新凭据直接加密入库，不出网关）。**2026-09-30 全库明文扫描与收尾（同批实施）**：`GET /accounts/{id}/oauth-reauthorization-context` 对 ai_studio 型 google_oauth 返回明文 `clientSecret`（m11_reads.go）——已按本契约同款修复（有值返回 `__ENCRYPTED__` 占位、gemini 授权流 body 占位识别回退存储现值/env，占位常量导出为 `accounts.CredentialCipherPlaceholder` 跨包复用，`bug0238_oauth_reauth_context_test.go` 与 `oauthmgmt/bug0238_client_secret_placeholder_test.go` 固化）；其余面核实安全：API Key 列表/详情仅 keyPrefix/keySuffix 掩码（key_hash 存储不可逆，创建一次性展示为设计语义）、操作日志 safeChange 敏感容器只写"已设置/已变更"标记、test-options 凭据仅派生 endpoint modes、runtime reset 为内部投影、代理 profile 与系统账号无敏感响应字段。

## 3. 验收标准（已废止，2026-09-30 整体回退）

- `TestAcceptanceManagementBackbone/accounts` 转绿（明细无明文）。
- 新增验收/单测：reveal 返回完整明文（多 Key 池逐项）+ 审计日志生成 + 占位值 PATCH 提交后存储凭据不变（含 api_keys 混合占位过滤语义）。
- 前端：占位态渲染、眼睛 reveal、占位过滤不提交；typecheck/test 绿。

## 4. 关联

- 发现路径：GPT-6.1 Sol 发布前全量测试（2026-09-30），基线对照确认非该批引入。
- 契约演进：v1 掩码值入表单 → v2 空值+placeholder 提示 → v3（终版）加密占位内容+眼睛 reveal——均用户裁定，v3 理由：密码框对非空值本就遮挡，字段"有内容"最直观，无需额外提示机制。

## 5. 2026-09-30 全面审查补充

- 同日全面审查（多子代理复审+主代理核验）发现占位态前端回归缺口两处 P1：草稿测试载荷携带占位符（`accountDraftTestPayload.ts` 回填链无占位过滤，不 reveal 直接测试会把 `__ENCRYPTED__` 发给 `POST /accounts/{id}/test`）、多 Key 池"占位行+新输入"混合保存静默截断（`accountCredentials.ts` `buildApiKeyCredentials` 剔占位后单键提交，未揭示真实 Key 被删除）——已按 BUG-0243 立案修复（另含三项 P3 呈现/交互收尾项）。
- `oauth-reauthorization-context` 的 `clientSecret` 占位语义经复核闭环无明文回显：`oauthmgmt/plans.go` `geminiBodyClientSecret` 识别占位值后回退存储现值/env，不构成新的明文面。

## 6. 回退记录（2026-09-30）

- **触发原因**：用户 2026-09-30 当日二次裁定整体回退。落地当日全面审查即产出 BUG-0243 两项 P1（草稿测试载荷携带占位符、多 Key 池混合保存静默截断）与三项 P3；用户在编辑弹窗实测又发现第三类缺口（BUG-0253：api_key 账户编辑态未 reveal 直接点"测试"，0243 守卫把占位符从载荷过滤后无 `api_key`，后端 `NormalizeAccountCredentialsForWrite` 400「API Key 不能为空」，OAuth 有测试守卫而 api_key 没有，用户直接撞后端裸错误）。单管理员自托管形态下，占位/reveal 契约的安全收益不抵维护成本与持续扩大的回归面。
- **回退范围**：明细接口恢复直接回显明文凭据；`__ENCRYPTED__` 占位回显与 `credentialsMasked` 标记、`POST /accounts/{id}/reveal-credentials`（含 my-accounts 版本）与 reveal 审计、PATCH 占位识别防回写（回退后 PATCH 不再特判 `__ENCRYPTED__` 字面量输入，恢复 0238 前行为）、m11 clientSecret 占位（`oauth-reauthorization-context` 占位与授权流占位识别回退、`CredentialCipherPlaceholder` 常量族）、oauthmgmt 占位识别、前端占位态 + 眼睛 reveal 链路 + 占位过滤守卫（含 BUG-0243 问题 1/2/3 守卫与 4/5 交互实现）全部移除。
- **保留项**：`POST /accounts/export` 明文导出语义与 m09 导出审计增强（`bug0238_export_audit_test.go`）保留（§2.6 决策以此结案）；`EncryptJSON` 存储封套（`credentials_encrypted` 加密存储）与账户列表 `credential_mask` 掩码保留。回退不波及（逐一核实）：平台 API Key keyPrefix/keySuffix/key_hash、clone-context、OAuth 轮换回执、操作日志 safeChange、代理 profile 加密、jobs/maintenance 凭据路径。
- **反转依据**：回到 BUG-0162 于 2026-09-28 的契约回正裁决形态——`docs/architecture/backend/README.md` 存储契约"列表只展示掩码，编辑和测试按权限读取完整凭据"；acceptance `management_backbone_test.go` 的"明细不得回显明文密钥"断言（迁移期写入、Node 时代从未跑绿）按新契约反转为"明细按权限回显完整凭据"。实施详情见 BUG-0253。
