# BUG-0197：用量统计 caller_account 视角元数据水合占位符参数多传（PG 500 / SQLite 丢行）

- 状态：已修复（待发布）
- 域：gateway `internal/statreads`
- 发现：2026-09-27（生产"用量统计"页加载失败取证）

## 现象

生产管理后台"用量统计"页（UsageStatsView）加载失败（接口 500，前端 toast「用量统计加载失败」）。触发视角：`scopeType=caller_account` 且结果行非空——admin 在页面选了"系统账户"筛选，或 `/my-stats` 自视角调用。影响端点：`/stats/account-usage`（列表）与 `/stats/account-usage/trend`。

## 根因

`internal/statreads/accountusage.go` `loadAccountUsageMetadataRows` 的 caller_account 分支，`headParams` 传 4 个参数（`viewerID, viewerID, now, viewerID`），而 SQL 文本只有 3 个 `?`——SELECT 列的 CASE 占位符（`system_account_id = ?`）在文本上位于 JOIN 两个占位符（grantee、expires_at）之前，正确参数恰为 3 个。

多出的第 4 个 viewerID 顶进 chunk 的 `IN` 绑定序列首位：

- SQLite（开发/standalone）：每个 chunk 末位账户 ID 被静默丢弃——数据悄悄缺失，无任何报错；
- PostgreSQL（生产）：参数个数与占位符不匹配，pgx 直接报错 → `writeReadError` 统一 500。

该缺陷被既有测试 `wd_statreads_handlers_test.go` 以注释「行为存疑」的形式明文固化为断言（断言 acct-inst 不出现在结果中），属 Node→Go 迁移带入、从未正确工作。与 BUG-0177、41cb24e95、b0ff7ff3c、87ecc033a 同属 PG 方言移植缺口族。

## 修复

- `accountusage.go`：`headParams` 收敛为 3 参（`viewerID, viewerID, now`），并留占位符顺序约束注释（CASE 最前、JOIN 随后、chunk IN 最后）。
- `wd_statreads_handlers_test.go`：断言反转为修复后契约——授权实例账户 acct-inst 必须出现在页面行中（SQLite 下此前被静默丢弃）。

## 验证

- `go test ./internal/statreads/ -count=1` 全绿（含反转后的水合断言）。
- 全量方言审计（2026-09-27 取证）：statreads 其余全部端点（usage-window、usage-overview 五端点、account-usage options/summary、ai-performance、ai-health、usage-records、systemmetrics）PG 路径逐条核对无同族缺口；三方表契约（maintenance DDL / jobs 写入 / gateway 读取）一致。

## 遗留与关联

- 若修复发布后"用量统计"仍加载失败，按取证结论排查两个运行时候选：① 生产库 schema 落后（缺窗口快照表族 / `success_cost_usd` 列）——发布流程的 `maintenance --ensure-schema`（幂等加法）即收敛；② `juhe_business.system_settings` 缺 `usageStatsTimezone` 行（Go seed 预置 Asia/Shanghai）。
- 排除项：AI 健康页独立 pgx 连接依赖 `JUHE_AI_ACCOUNT_HEALTH_JOBS_OUTCOME_POSTGRES_URL`，仅影响 ai-health 端点，与本缺陷无关。
