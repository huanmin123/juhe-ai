# BUG-0119 Node 页面数据删除残留与网关可靠性回归

## 问题定义

- 影响范围：Node 后端、Vue 前端、网关失败收尾和 Redis 队列。
- 触发条件：`7ec74dc` 删除页面数据变更实现后，仍运行页面、账户、网关或构建验证。
- 实际行为：前后端保留对已删除模块的导入，类型检查和部分运行路径失败；网关失败路径还存在非幂等重放、用量事实丢弃和 Redis 故障边界缺口。
- 期望行为：退役页面数据确认机制后，所有调用、测试和文档同时移除；网关不重放不可证明幂等的请求，完成请求的用量事实可恢复，Redis 故障受有界处理。

## 根因与修复边界

- 根因是并行分支仅合入了删除实现的子集，没有同步移除调用方、回归入口和文档。
- 本次只修复当前 Node 与前端交付链，不修改 Go 迁移代码。
- 页面数据机制按当前减法方向彻底移除，不恢复已退役的 IPC 或确认接口。

## 验证标准

- `pnpm typecheck` 与 `pnpm build` 通过。
- 定向网关、Redis、页面资源恢复与用量收尾回归通过。
- Node 本地服务启动后，管理前端和健康接口可访问。

## 修复结果

- 已移除前后端 page-data 调用、失效脚本和 package 入口，直接请求路径通过全量类型检查与构建。
- 网关 opaque 失败不再改变账户状态；不可证明幂等的 POST 不会跨账号重放；usage 收尾改为有界背压而非丢弃。
- Redis 断线、API Key 失效、队列 fence、drain 和会话亲和失败边界均已补回归。
