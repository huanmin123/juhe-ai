# BUG-0113 同值保存误清余额快照并丢失刷新计划

## 基本信息

- 状态：已修复（待生产验证）
- 严重程度：P1
- 模块：AI 账户、余额查询、ops-worker、前端
- 发现日期：2026-07-16
- 需求来源：Codex 会话 `019f6981-fefe-7f51-94d2-86cc841e63a1`
- 关联 bug：BUG-0066、BUG-0069、BUG-0073、BUG-0075

## 现象

账户完整编辑后，列表可能长期显示“剩余：待查询”。生产只读核查发现已开启余额查询的账户存在快照缺失且刷新时间为空，现有 worker 不会领取。

## 触发条件

1. 前端完整表单提交未变化的 `balanceQueryEnabled` 和 `balanceQueryConfig`。
2. 后端按字段是否出现重置 `balance_query_next_refresh_at` 并清理旧快照。
3. 账户同时处于非活动状态，或历史状态已形成“无快照且刷新时间为空”。

## 根因

余额快照刷新代次由 `balance_query_next_refresh_at` 与快照 `next_refresh_after` 共同标识，但保存链路没有比较真实余额查询身份。字段出现即被当作配置变化，导致同值保存也创建新代次、屏蔽并异步删除旧快照。worker 只领取非空到期时间，无法修复历史缺失计划。

## 修复

- 使用启用状态、规范化配置、供应商、账户类型、API Key 指纹、规范化 Base URL 和代理 ID 比较余额查询身份；Base URL 保留路径，只忽略 query、hash 和尾斜杠。
- 同值保存及无关字段修改保留快照和刷新时间；真实身份变化才清理旧快照并立即调度。
- 普通编辑和批量代理编辑使用相同身份边界。
- worker 每轮为自愈保留最多 10 个名额；SQLite 与 PostgreSQL 都使用有界 ID 游标轮转扫描，排除已有 `unsupported` 当前快照的暂停账户，避免正常 backlog 或前缀异常账户造成永久饥饿。
- 前端隐藏所有中间态，只展示最终余额、不限额或余额查询失败。

## 防复发要求

- 不得用请求字段 presence 判断余额配置是否变化。
- 新增影响上游余额请求目标的字段时，必须同步纳入统一余额查询身份 helper。
- 自愈查询必须保持有界批次，不得扫描全量账户或反复唤醒暂停账户。
