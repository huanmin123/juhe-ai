# BUG-0200：管理列表缺失余额字段，余额整行不渲染

## 现象

2026-09-27 管理端反馈"账户余额没有了"：账户列表所有行（含已开启余额查询的账户）的用量列内都不渲染余额行与刷新图标。生产核对：`juhe_business.accounts` 中 `balance_query_enabled=1` 有 480 个账户，`juhe_jobs.account_balance_snapshots` 68 个 `fresh` 快照分钟级新鲜（用户截图中的 shenwenai/zeekai/geiliapi 系列全部在列）——**余额数据是活的，页面一行都不显示**。

## 根因

Go 迁移把 Node 管理列表投影的三个余额字段整体丢失：

- 归档 Node 列表投影携带 `balanceQueryEnabled / balanceQueryNextRefreshAt / balanceSnapshot`（`account-status-snapshot.service.ts:254-279`，`account-list-availability-projection.repository.ts:1707-1746`）；
- Go `backend-go/projects/gateway/internal/accounts/list.go` 的 `ListItem` 结构无任何余额字段，注释声明 runtime overlays "stay omitted"，且全 gateway 无叠加实现；
- 前端 `AccountUsageCell.vue:16` 以 `v-if="account.balanceQueryEnabled"` 渲染余额行，字段缺失即整行不渲染——影响所有账户，与是否开启无关。

## 修复

`backend-go/projects/gateway/internal/accounts/`：

- 列表 SQL 增读 `balance_query_enabled / balance_query_next_refresh_at` 两列（listRow/scanListRow/newListItem 链路）；
- 新增 `accountsbalance/list_snapshot.go`：`LoadRelayBalanceSnapshotRecords` 按页账户 ID 900 分块批量读 `juhe_stats.account_usage_snapshots`（kind='relay_balance'）；`ListPage` 水合阶段叠加 `balanceQueryEnabled`（指针，仅 true 输出）/`balanceQueryNextRefreshAt`（owner 行）/`balanceSnapshot`（启用且 `BalanceSnapshotMatchesConfiguration` 匹配才携带；白名单投影 `AccountBalanceSnapshotPublic` 天然剥离 `keyBalances`）；authorized 视图三字段均不输出；stats 读失败降级为不带快照、不失败页面（event `account_balance_snapshot_hydrate_failed`）。

## 验证

- 新增 5 个测试（admin/self 视图叠加、空 stats 表降级、configRevision 不匹配不带、authorized 隐藏、分块边界）全部 PASS；`go test ./internal/accounts/` 除 2 个 HEAD 既有 anthropic 失败（与本修复无文件交集）外全绿。
- 生产 `juhe_stats` relay_balance 行数为 0 时读端空值降级正确；写入方见 BUG-0203 投影任务，发布后快照自动出现。

## 状态

已修复，待发布。
