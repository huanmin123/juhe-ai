## 问题概述

- 现象：Mac 生产活动期间，`福利` 分组承接大量 Codex / Claude CLI / opencode / Cherry Studio 等客户端请求，网关主链路未崩溃，但后台复测、审计、使用记录快照和运行日志在高并发下出现明显放大。
- 期望：真实网关请求高峰时，主链路、统计聚合、后台复测、审计捕获和日志索引都应保持可控；无效账号不应被反复复测，正常 backpressure 不应刷 warn，记录链路不应因大请求持续膨胀。
- 实际：网关主进程、DB service 和统计 worker 仍可用，但暴露出冷却复测空转、worker event loop lag 偏高、审计 payload 增长快、usage snapshot 偏大、launchd stdout 日志膨胀和 backpressure warn 过敏。
- 影响范围：生产 Mac 单机部署；高并发活动；大 body / 长流式请求；冷却账号恢复复测；日志搜索和审计排障链路。

## 根因分析

- 表象：请求高峰下错误率上升、日志增长快、worker CPU 和 event loop lag 升高。
- 真实根因：
  - 冷却账号复测对不可自愈错误缺少硬状态收敛或长退避，401 `token_invalidated` 仍进入每分钟复测和短重试循环。
  - 使用记录请求快照会保存较完整的请求摘要；大量 50KB 级请求在 `usage_records` 内持续放大记录域。
  - 原始审计固定开启，成功采样 10%，失败和 `success_after_retry` 全量捕获；大 body、长流式和重试场景会快速增加 audit blob。
  - 修复前 backpressure 只要触发高水位就写 warn 和 drained 两条日志，但现场 drain 最大只有 1ms，属于正常瞬态，不应按异常日志处理。
  - 修复前生产环境 `JUHE_AI_LOG_CONSOLE_ENABLED=true`，高频结构化日志会同时进入文件日志和 launchd stdout。
- 为什么会发生：
  - 设计上优先保证排障完整性和复测一致性，但缺少高并发活动下的降噪、采样、熔断和退避策略。
  - 后台任务共用 worker 事件循环，复测、审计落库、日志索引和统计聚合在高峰时互相挤压。
- 代码确认：
  - 修复前 `backend/src/storage/repositories.ts` 的 `listAccountsDueForCooldownRetest` 会持续捞取 `rate_limited` / `temporary_unavailable` 且 `cooldown_until <= now` 的账号；本次策略调整后只允许 `temporary_unavailable` 进入后台复测。
  - `backend/src/modules/background/cooldown-account-retest.service.ts` 的复测失败路径只返回 `false`，进入 3s / 10s / 30s 队列重试；重试耗尽后保留冷却状态，等待下一轮 60 秒调度。
  - `backend/src/modules/gateway/policy/policy/account-error-policy.service.ts` 对未匹配错误策略的 401 只返回 `none` 和“未配置处理策略的上游状态码 401”，不会自动转入 `error` 或 `disabled`。
  - 修复前 `backend/src/modules/gateway/upstream/body.ts` 只要 `res.write` 返回 false 就先写 `gateway_response_backpressure_started` warn，即使 drain 等待只有 0 到 1ms 级别也会产生 warn；本次已改为等待结束后按 drain 时长分级记录。

## 修复方案

- 修改点：
  - 冷却复测：不依赖错误码白名单判断不可自愈；只允许 `temporary_unavailable` 进入后台复测，`rate_limited`、`error`、`disabled` 等其他状态不复测。
  - 冷却复测：连续失败前 3 次做短重试确认，第 4 次失败开始按 `defaultTemporaryUnschedulableMinutes` 起步指数退避，每轮失败翻倍更新 `cooldown_until`。
  - 冷却复测：新增系统配置 `cooldownAccountRetestMaxBackoffHours`，默认 24 小时；下一次退避超过上限时把账号转为 `error` 并退出自动复测。
  - 冷却复测：保留最后测试 HTTP 状态、错误码、错误摘要和连续失败次数，前端账户页需要可见。
  - 冷却复测：根据近期真实请求量或 worker lag 继续考虑自限速；活动高峰不主动抢真实网关流量。
  - 使用记录：`request_snapshot_json` 和 `response_snapshot_json` 增加大小上限和摘要化策略，避免把 50KB+ 请求长时间写入明细表；本项不并入当前上线批次。
  - 审计：本轮先不改审计 payload 捕获策略，保留完整排查能力，依赖现有清理机制控制保留周期。
  - 日志：backpressure drain 等待小于 50ms 时降为 debug；只有明显等待时写 warn。
  - 日志搜索索引：重建任务在源表与索引行数已经对齐时把游标推进到源表最新行、标记完成并清空 `lag_seconds`，不再重复写已索引行，避免重建任务误报滞后并减少记录域 WAL 放大。
  - 部署：发布包 `start.sh` 生产默认关闭 console 日志输出，保留文件日志滚动。
- 行为影响：
  - 冷却复测收敛会减少无效账号自动恢复机会，但能避免无效凭据持续打上游。
  - 审计 payload 本轮不做摘要化或降采样，不减少完整请求体可见性。
- 发布异常处理：
  - 冷却复测不是可关闭项，系统设置只呈现 `cooldownAccountRetestMaxBackoffHours` 这个时间上限。
  - 审计和使用记录摘要化不在本次上线批次内；日志降噪已经作为固定运行策略处理，不新增系统配置开关。
