# BUG-0326：语音上游 4xx 业务拒绝被派发耗尽渲染为 503 可重试（语义错乱）

## 现象

`POST /v1/audio/speech`（volcengine seed-audio-1.0）发送过短文本（如「今天天气怎么样」7 字）→ 真实上游返回 HTTP 400 + `{"code":40402002,"message":"TTSInvalidText:ReadableTextRatioTooLow"}`（可读字符率业务校验拒绝）→ 网关最终响应 **503** `{"error":{"code":"upstream_retryable_error","message":"上游暂时不可用，请重试","type":"service_unavailable"}}`。

客户端视角错乱：文本太短是**请求参数问题**（不可重试、改请求即可修复），却收到「暂时不可用，请重试」——重试永远失败；且 HTTP 状态码 503 掩盖了 4xx 语义（监控/告警把客户端错误计为服务端故障）。

- 复现：隔离实例 gw-v7（2026-10-17），短文本 → 上游 `gateway_upstream_response_failed status:400` → `gateway_dispatch_exhausted` → 503。
- 长文本同请求 → 200 正常（链路本身健康）。

## 根因

语音（speech）请求的上游非 2xx 响应统一进入派发 attempt 失败通路（`gateway_upstream_attempt_failed` → 重试 → 耗尽 → 503 `upstream_retryable_error`），没有对上游 **4xx（确定性客户端错误）与 5xx/网络（可重试）** 分级：上游已明确表达 400 语义，网关却按可重试故障处理并耗尽重试预算。

chat 链对上游 4xx 有透传/快速终止语义；speech 链缺失同款分级（历史语音测试未触发过上游 4xx，行为从未被钉住）。

## 修复设计（2026-10-23 实施批，以下为已实施口径）

- 音频同步 lane（LaneAudio：speech 与 STT 同步端点族，含火山 create/unidirectional 两出站面）失败派发按状态码分级，分级词表落在失败派发器短路面（`chain_media_video.go` `chainAudioSyncBusinessRejectionStatus` / `chainMediaSyncAudioRejectionShortCircuit`，消费点 `chain_ports.go` `HandleFailedUpstreamResponse`，与媒体创建参数短路同位：审计尝试与 usage 失败记录落账之后、SkipAccount 决策之前）：
  - **确定性业务拒绝 4xx → 短路透传（ReturnResponse）**：400/404/409/413/415/422 等保留集之外的 4xx，客户端拿到上游真实状态码与错误信封，不换账户、不进重试循环（attemptCount=1），不触发账户错误策略状态变更与健康检查探测（换账户原样重演，状态归因会误伤账户）；透传响应经专用音频透传渲染臂原样转发。
  - **保留集 → 维持既有失败派发语义**：401（凭据失效，账户级熔断/temporary_unavailable 状态机）、403（显式策略 / `system.upstream_insufficient_quota` 语义）、407（上游代理鉴权）、408（上游请求超时）、429（受理前限流——换账户重试，mock 契约 §3.2.4 既有钉面）不透传，维持候选切换 + 耗尽 503。
  - **5xx/网络错误**：维持既有重试 + 派发耗尽 503，不变。
- 实施中补上的档案缺口（原设计未写全，按最贴近档案意图落地）：短路 ReturnResponse 的非 2xx 若进通用响应管道，chat 语义的响应检查会把上游业务拒绝改写成 502 `response_inspection_failed`（媒体创建参数短路当年同款问题）。故在 `chain_v1.go handleUpstreamResponse` 增设音频透传渲染臂 `handleAudioSyncUpstreamErrorPassthrough`（与视频创建 `handleVideoCreateUpstreamErrorPassthrough` 同构：真实状态码 + 上游错误体直写，不进 JSON 检查/协议校验管道）；诊断/非网关流量的同类透传响应同臂受益（其 ReturnResponse 契约本就要求观察上游真实终态）。
- 429 归属决议：档案「参数/配额类 4xx 透传」未覆盖 429；429 维持既有换账户重试（限流对单账户有意义、跨账户配额独立，且 mock 契约与既有测试把 429 钉在换账户语义上），不进透传集。
- 审计/usage 口径（对齐 `docs/functions/AI账户错误语义与状态变更边界.md`）：短路臂在审计尝试与 usage 失败行落账之后返回，失败事实（真实状态码 + `success:false`）照落，完成归因维持 `opaque_upstream` 族；不改任何账户状态语义。
- 验收标准（已由测试钉住，`cmd/juhe-ai-gateway/chain_media_audio_bug0326_test.go`）：上游 400 业务拒绝 → 客户端收到 400 + 上游错误信封、attemptCount=1（第二候选零出站）、usage 失败行带真实状态码；上游 500 → 换候选重建成功；401/403 → 客户端仍拿耗尽 503 `upstream_retryable_error`（不透传）；429 → 换账户重试成功。
