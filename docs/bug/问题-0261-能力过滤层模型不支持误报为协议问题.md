# BUG-0261：能力过滤层模型不支持误报为协议问题

- 状态：代码修复完成（2026-10-02，用例四臂覆盖；gatewaydispatch 整包绿），已发布（2026-10-02 00:15 gateway 单进程 151be9cf，md5 闭环，详见私有 runbook 发布记录）。

## 1. 现象（生产报障事实）

2026-10-01 深夜巡检发现 19 条 `/v1/responses` 503（`errorCode=model_unsupported`），errorMessage 为「当前分组无账户支持请求路径或客户端协议」。经审计库 `juhe_dataset.audit_logs.model` 取证，请求模型分别为：

- `deepseek-v4-pro-fast`（key_1782874124863，ZCode 客户端，23:53-23:57 共 11 次；分组内 cdn.sta1n.cn 只配置了 `deepseek-v4-pro`）
- `gpt-6.1-sol`（key_1789961758471，Codex Desktop，00:00-00:01 共 8 次；分组内唯一账户「极刻-work」只配置 gpt-5.4/5.5/5.6 系；用户自行切回 gpt-5.6-terra 后恢复，同 key 当日 gpt-5.6-terra 成功 221 次）

**503 拒绝本身是正确行为**（用户请求了分组内未配置的模型名）；缺陷在错误文案把模型问题误报为「请求路径或客户端协议」问题，客户端用户与运维排障都无法从报错定位真实原因。

## 2. 根因

候选链的能力过滤层（`gatewaydispatch/candidatefilter.go`）在整组账户被跳过时用 `requestCapabilityMismatchMessage(reason)` 生成文案；而 driver 能力判定链（`cmd/juhe-ai-gateway/chain_driver.go` `gatewayRequestCapabilityMismatchReasonFor` 末段）会在账户支持模型列表不含请求模型且无映射时返回 `model_unsupported`——该 reason 落入能力过滤的泛化文案分支。模型过滤层本有精确文案（`candfilters.go`「当前分组无账户支持请求模型：X"），但请求在能力过滤层就被终结，永远到不了那里。

## 3. 影响面

所有「请求模型不在分组内任何账户支持列表且无映射」的请求的错误响应文案；行为（503 + errorCode）不变，仅 errorMessage 误导。生产当晚 19 条实证；排障成本被显著放大（本案从告警到定案需绕道审计库取 model 字段）。

## 4. 修复契约

`requestCapabilityMismatchMessage(reason, requestedModel)`：reason 为 `model_unsupported` 且 requestedModel 非空时，返回与模型过滤层一致的「当前分组无账户支持请求模型：X」；模型为空时保持泛化文案（driver 判定可能在无模型请求下因其他原因返回该 reason 的场景不误伤）。anthropic 分组文案与其余 reason 行为不变。

## 5. 生产处置

无需数据修复（拒绝行为正确）。两个报障用户的处置属运营决策：是否把 `deepseek-v4-pro-fast` 加入 cdn.sta1n.cn、`gpt-6.1-sol` 加入极刻-work 支持列表由账户主人决定（gpt-6.1-sol 已在系统目录，2026-09-30 收录）。

## 6. 验收标准

- reason=model_unsupported + 模型非空 → 文案「当前分组无账户支持请求模型：X」。
- reason=model_unsupported + 模型空白 → 泛化协议文案不变。
- anthropic 分组与其余 reason → 文案不变。
- `TestRequestCapabilityMismatchMessage` 四臂断言全绿；gatewaydispatch 整包回归绿。

## 7. 关联

- 文案对齐源：`gatewaydispatch/candfilters.go`（模型过滤层 `GatewayModelFilterFailureMessage`）
- 拒绝判定源：`cmd/juhe-ai-gateway/chain_driver.go` `gatewayRequestCapabilityMismatchReasonFor`（模型列表检查段）
- 生产取证路径：`juhe_dataset.audit_logs`（`model` + `error_code` + `user_agent` 列）
