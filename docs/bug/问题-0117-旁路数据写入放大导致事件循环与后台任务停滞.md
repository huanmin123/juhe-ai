# BUG-0117 旁路数据写入放大导致事件循环与后台任务停滞

## 基本信息

- 编号：BUG-0117
- 状态：修复中，代码与本地回归完成，待生产拓扑切换和稳定观察
- 严重程度：P0
- 发现时间：2026-07-21
- 模块：后端 / 网关 / ingest-worker / 审计 / 运行日志索引 / PostgreSQL
- 关联计划：PLAN-0149、PLAN-20260725T232043094Z

## 问题概述

生产在高并发、大请求体和高频日志场景下出现主进程 RSS、external Buffer 与事件循环延迟显著升高，后台任务和“我的使用记录”停止推进；服务重启后恢复。2026-07-26 再次现场取证时，主 Node 事件循环延迟最高约 `5.682s`、RSS 约 `1.06GB`，Redis queue 服务本身仍健康，但 node-redis 5 秒命令超时导致大量 usage `XADD` 失败，旧 producer client 未被淘汰重建，performance 又没有持久补偿，因此使用记录直接形成缺口。随后只读预检又确认旧 release 的同一个 DB service PID 先报告 PostgreSQL transaction client 并发 query warning，随后收到 `idle-in-transaction timeout`；该连接的异步 `error` 没有被事务边界接管，因而升级为 uncaught exception 并退出。父进程随后出现 IPC `EPIPE`，这会直接形成“本地数据库服务暂时不可用”的窗口。日志能证明这些事件属于同一故障链，但不能仅凭日志顺序断言并发 query 是服务端 idle timeout 的唯一成因。

## 证据与边界

已确认大 JSON、重试阶段日志和同进程旁路工作共同放大主事件循环；Redis queue 并非当时的首个故障点，`XADD` 超时是事件循环停顿后的连锁反应。DB service “暂时不可用”既包含主服务重启准备期，也包含事务 client 被并发使用后由 PostgreSQL 主动终止连接的独立故障；旧网关热路径缺少进程内最后有效运行快照，又进一步放大了 DB service 抖动对客户端的影响。尚无证据把单一旁路认定为唯一根因，因此修复同时覆盖故障域隔离、事务连接安全、客户端自愈和有界降级。

`usage_records` 是核心业务事实源，必须继续写入；统计、额度、成本和账户质量不能因止血被关闭。

## 修复方案

- 保留既有审计 / 运行日志部署止血开关，不把长期方案建立在永久关闭业务事实上。
- performance 在同一台 Mac 拆为 Nginx + 3 Gateway + 2 Usage + 2 Log + 1 Stats + 1 Ops；standalone 仍为现有单 server 拓扑。
- Redis producer 遇到超时、断连和连接代际失效时淘汰缓存 client 并单飞重建；consumer 使用独立 client 并可恢复。
- usage `XADD` 失败进入 release 外本机 durable spool，保留稳定 ID；primary Usage worker 在 Redis 恢复后重放，数据库唯一约束吸收 ACK 不确定导致的重复。
- performance 正常网关阶段详情按 trace 稳定采样并在日志待写压力下暂停；失败和终态摘要保留。
- 网关敏感鉴权 / 路由运行时使用有硬过期的进程内最后有效快照；Redis cache 读写失败退化为 miss / best-effort，不能覆盖已经取得的事实源结果。
- PostgreSQL pool 保持普通查询并发；只有显式事务借出的单连接按调用顺序串行 query，并让嵌套事务共享同一序列，避免 repository 内的 `Promise.all` 重叠协议消息或让 `COMMIT` 越过尾部查询。事务连接的异步 `error` 在本事务内拒绝并被带 error 释放，禁止坏连接回池或升级为进程 uncaught exception。
