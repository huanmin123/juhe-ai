# BUG-0253 编辑态草稿测试未揭示凭据即失败与 BUG-0238 契约整体回退

## 基本信息

- 编号：BUG-0253
- 状态：已修复（2026-09-30，随 BUG-0238 契约整体回退实施；未发布，无线上影响）
- 定性：契约反转（用户 2026-09-30 当日二次裁定整体回退，非单点回归修复）
- 严重程度：P1（编辑态 api_key 账户"测试"功能可用性受损，用户直接撞后端裸 400）
- 发现时间：2026-09-30
- 发现方式：用户编辑弹窗实测（BUG-0243 修复交付后的同日验证）
- 模块：前端 views/accounts（草稿测试载荷链路）+ 后端 accounts（`write.go` / `test_dispatch_routes.go` 草稿快照链路）
- 关联 bug：BUG-0238（占位契约引入方与回退对象）、BUG-0243（占位契约落地后的前端回归，随本回退关闭）、BUG-0162（回退所恢复的 2026-09-28"编辑和测试按权限读取完整凭据"裁决形态出处）、BUG-0175（账户域迁移核对批次——"迁移期验收断言与实现长期不一致"形态的背景）

## 问题概述

- 现象：编辑弹窗中 api_key 型账户在**未点眼睛 reveal** 的密文占位态下直接点"测试"，请求载荷无 `api_key`，后端 `NormalizeAccountCredentialsForWrite`（`write.go:208`，经 `test_dispatch_routes.go` 草稿快照链路）返回 400「API Key 不能为空」——用户绕过前端提示直接撞后端裸错误。
- 期望：编辑态不 reveal 直接测试可用（0238 契约自身的完整性要求）；占位态任何出站载荷不携带占位符（BUG-0243 目标）。
- 实际：OAuth 账户草稿测试有测试守卫，api_key 账户没有——这是占位契约落地后继 BUG-0243 两项 P1 之外暴露的**第三类缺口**（守卫覆盖不对称），说明占位语义的回归面在前端各凭据消费点无法收敛收口。
- 处置：用户 2026-09-30 当日二次裁定 **BUG-0238 契约整体回退**，本条随回退批次实施修复。

## 复现步骤（回退前）

1. 打开任一 api_key 型已有凭据账户的编辑弹窗（不点眼睛 reveal，字段显示占位遮挡态）；
2. 直接点"测试"——0243 修复的占位回填过滤把 `__ENCRYPTED__` 从草稿测试载荷剔除，载荷因此无 `api_key`；
3. 后端 `NormalizeAccountCredentialsForWrite` 判定凭据缺失，返回 400「API Key 不能为空」，编辑弹窗透出后端裸错误。

## 根因链与根因分析

根因链（三层叠加）：

1. **0238 占位回显**：明细接口把敏感凭据键替换为 `__ENCRYPTED__` 占位符，编辑表单加载即占位态。
2. **0243 占位视同缺失**：草稿测试载荷守卫（`accountDraftTestPayload.ts` 占位回填过滤）为满足"占位符不得作为真实凭据出站"（0243 问题 1）把占位符从载荷中剔除——剔除后载荷即无 `api_key`。
3. **后端裸错误**：`test_dispatch_routes.go` 草稿快照链路把无 `api_key` 的载荷送入 `NormalizeAccountCredentialsForWrite`（`write.go:208`）直接 400「API Key 不能为空」；OAuth 账户有测试守卫提前拦截，api_key 账户没有，用户直接撞裸错误。

真实根因：占位契约把"凭据真实值"从编辑态读路径抽走，但"测试"链路**需要真实凭据**——0238 只为"保存"链路设计了占位防回写，0243 只为"测试载荷不携占位"修补过滤，两者拼起来恰好把"占位态测试"做成不可能：要么发占位符（0243 问题 1 的 401 误判），要么发空（本条的 400 裸错误）。守卫逐点补丁无法闭环，属契约结构性缺陷而非单点实现遗漏。

为什么会发生：0238 契约三轮收敛聚焦"编辑抽屉打开时明文不落浏览器"单一目标，未对"测试/余额查询等出站消费点需要真实凭据"的完整交互面做契约级推演；落地当日全面审查（0243 两 P1 + 三 P3）与用户实测（本条第三类缺口）接连暴露，证明该契约在本项目形态下的维护成本超出收益。

## 修复方案（BUG-0238 契约整体回退）

用户 2026-09-30 裁定：明细接口恢复直接回显明文凭据（回到 BUG-0162 于 2026-09-28 的裁决形态——`docs/architecture/backend/README.md` 存储契约"列表只展示掩码，编辑和测试按权限读取完整凭据"）。

### 回退范围（全部移除）

- 明细接口（`GET /accounts/{id}`、`/accounts/{id}/edit-basic`，含 my-accounts，admin/self 两面）的 `__ENCRYPTED__` 占位回显与 `credentialsMasked` 标记——恢复 `projectEditableCredentials` 直接回显完整凭据。
- `POST /accounts/{id}/reveal-credentials`（含 my-accounts 版本）及 reveal 操作日志审计。
- PATCH 通道占位识别防回写（requested 敏感键 `=== __ENCRYPTED__` 视为未修改、`api_keys` 滤占位语义）——回退后 PATCH 不再特判 `__ENCRYPTED__` 字面量输入（0238 前行为）。
- m11 clientSecret 占位：`oauth-reauthorization-context` 的 `__ENCRYPTED__` 占位与授权流占位识别回退、`accounts.CredentialCipherPlaceholder` 占位常量族。
- oauthmgmt 占位识别（`geminiBodyClientSecret` 占位值回退存储现值/env 语义）。
- 前端占位态渲染、眼睛 visibility-change 触发 reveal 链路、保存占位过滤双保险，及 BUG-0243 问题 1/2/3 的守卫（占位回填过滤、混合行保存守卫、占位态策略守卫）与问题 4/5 的交互实现——随占位契约撤销一并移除。

### 回退不波及（逐一核实，均维持现状）

- `EncryptJSON` 存储封套（`credentials_encrypted` 加密存储语义）。
- 账户列表 `credential_mask` 既有掩码（列表面不回显明文，不受回退影响）。
- 平台 API Key 的 keyPrefix/keySuffix 掩码与 `key_hash` 存储。
- `clone-context`（只回 Key 数量/策略/权重，本无明文）。
- OAuth 轮换回执（只返回 id/configRevision/updatedAt，新凭据直接加密入库，不出网关）。
- 操作日志 `safeChange` 敏感容器只写标记语义。
- 代理 profile 加密与 jobs/maintenance 凭据路径。

### 保留项

- `POST /accounts/export` 明文导出语义保留——BUG-0238 §2.6"待用户裁定"的 export 决策以**保留明文导出 + 保留 m09 导出审计增强**（`bug0238_export_audit_test.go`）结案，随回退保留。
- 0243 批顺带删除的三个前端零调用死导出（`currentAccountCredentials`/`accountFormApiKeysChanged`/`accountFormApiKeyRuntimeChanged`）**不随回退恢复**（死代码删除与占位契约无关）。

### 触发原因（用户裁定依据）

- BUG-0243 两项 P1（草稿测试载荷携带占位符、多 Key 池混合保存静默截断）+ 本条第三类缺口（api_key 编辑态不 reveal 直接测试 400）。
- 单管理员自托管形态下，占位/reveal 契约的安全收益不抵其维护成本与回归面。

## 验收标准

- 明细接口（detail / edit-basic / my-accounts 两面）按权限回显完整明文凭据，响应无 `credentialsMasked`、无 `__ENCRYPTED__` 占位。
- 编辑弹窗打开即有真实凭据，不 reveal 直接点"测试/余额查询"可用（本条现象消除）。
- acceptance `management_backbone_test.go` 的"明细不得回显明文密钥"断言（迁移期写入、Node 时代从未跑绿）按新契约**反转**为"明细按权限回显完整凭据"。
- 前后端相关测试全绿（accounts 包、oauthmgmt、前端 vitest 全量）。
