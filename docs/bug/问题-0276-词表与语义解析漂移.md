# 问题-0276：endpoint family 词表与 usage_semantic 解析漂移

- 编号：BUG-0276
- 状态：已修复（2026-10-03），待发布
- 发现：BUG-0269 后的全量排查（双实现漂移审计）。

## 现象与根因

1. **Gemini `:countTokens` 被归入 `messages` 族**：`requestMappingSourceFamilyOf`（`chain_driver.go`）把 `:countTokens` 返回 `"messages"`，而 Node `gatewayRequestEndpointFamily` 返回 `count_tokens` 且不在 `isAccountModelMappingSourceEndpointFamily` 允许集（映射恒不命中）。Go 归入合法源族后，countTokens 请求可命中 messages 族映射并错误改写上游 URL/body、family 记错。触发条件苛刻（需要消息族映射且路由到混合账户），属词表漂移而非已发生事故。
2. **`usage_semantic` 对第三方 anthropic 档案解析为 openai**：`chainUsageSemanticResolver` 只按 providerCode 分派（anthropic/gemini/hybrid），`profile_deepseek_anthropic_v1` / `profile_glm_coding_anthropic_v1`（ProviderCode=deepseek/glm + ProtocolCode=anthropic）落 openai；Node registry 按协议驱动返回 anthropic（回归脚本 `third-party-anthropic-profiles-regression.ts` 断言）。BUG-0269 把该解析器扩到成功路径后影响面扩大到全部成功记录。

## 修复

1. `requestMappingSourceFamilyOf` 的 `:countTokens` 返回 `"count_tokens"`（字面量 + 注释：不在映射源族允许集，映射不参与 countTokens，记账 family 同源）；词表钉住测试同步。
2. `chainUsageSemanticResolver` 先按 `profile.ProtocolCode` 归一（anthropic/anthropic_v1→anthropic；gemini/gemini_v1beta→gemini），再走 providerCode 分支（hybrid 档案覆盖保留）；既有钉桩按新契约回正，补 deepseek-anthropic / glm-anthropic / gemini 用例。

## 测试

`w1_driver_arms_test.go` countTokens 期望回正；`chain_usage_wiring_test.go` 语义用例扩展。
