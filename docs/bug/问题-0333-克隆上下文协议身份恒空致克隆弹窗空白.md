## 问题概述

- 现象：生产环境对任一已有 AI 账户点击「克隆」，弹窗只有供应商摘要与账户类型，凭证区、健康检查区整块空白，「创建」按钮禁用；新建与编辑入口（BUG-0332 修复后）不受影响。
- 期望：`GET /accounts/{id}/clone-context` 返回源账户当前协议身份（`providerProtocolProfileId`），前端 `hasAccountType = Boolean(providerCode && providerProtocolProfileId && type)` 成立，凭证区正常渲染并允许提交。
- 实际：clone-context 恒返回 `providerProtocolProfileId: ""`，`hasAccountType` 恒假，克隆表单不渲染凭证区且创建禁用。
- 影响范围：管理端「账户克隆」详情回显（`FindCloneContext` 服务面）；编辑详情（BUG-0332 已修复）与新建账户不受影响。

## 复现步骤

1. 登录生产，进入「我的账户」，选择任一已有账户（用户截图为 DeepSeek 账户）点击「克隆」。
2. 观察克隆弹窗：账户类型之下凭证区整块空白，「创建」按钮禁用。
3. 直接请求 `GET /__aisys__/api/accounts/{id}/clone-context`，响应 `providerProtocolProfileId` 为空字符串。

## 环境信息

- 分支 / 版本：生产 gateway 构建自含 BUG-0332 修复（`d2bfd8c53`）之后的版本。
- 数据状态：生产 `juhe_ai` 库，`account_connections` 为当前连接契约。
- 浏览器 / 系统 / Node 版本：不适用。
- 是否稳定复现：是（用户截图稳定复现；`'' AS provider_protocol_profile_id` 占位使该字段对所有账户恒空）。

## 根因分析

- 表象：克隆上下文 DTO 的 `providerProtocolProfileId` 恒为空，前端克隆表单判定为不完整配置。
- 真实根因：B4（`3b4dd5cb9`）退役 `provider_protocol_profiles` 表后，`clone.go` 的 `readCloneContextOnce` SELECT 里保留 `'' AS provider_protocol_profile_id` 硬编码占位，且克隆链路读侧从未迁移到新契约。与 BUG-0332 完全同款：账户真实协议身份已由 `accounts.health_check_connection_id` → `account_connections.connection_preset_code` 承载，读侧未据此推导 legacy profile id。
- 为什么会发生：BUG-0332（`d2bfd8c53`）的修复只覆盖 `FindEditBasicDetail` 编辑详情读面；克隆读面（`FindCloneContext`）是同族占位的另一处漏网，当时未同步排查克隆入口，导致克隆弹窗空白在编辑修复上线后仍然存在。

## 修复方案

- 修改点：
  - `backend-go/projects/gateway/internal/accounts/clone.go`：`readCloneContextOnce` SELECT 保留 `'' AS provider_protocol_profile_id` 占位（列已退役，作扫描目标），其后带出 `accounts.health_check_connection_id` 与关联子查询 `current_health_check_preset`（`account_connections.connection_preset_code`，写法与 `list.go` 的 BUG-0332 修复同源）；扫描后经 `exactkeyprobe.ConnectionPresetProfileID` 推导 `providerProtocolProfileId`，命中时覆盖占位空值。
  - `backend-go/projects/gateway/internal/accounts/accounts_test.go`：`TestAccountCloneContext` 在「创建账户 → 拉取 clone-context」既有用例中增加断言 `providerProtocolProfileId == "profile_gpt_openai_v1"`（与 BUG-0332 给编辑详情加的断言同款）。
- 行为影响：克隆上下文恢复协议身份回显，克隆弹窗凭证区恢复渲染、创建恢复可用；未命中连接 preset 的账户（如历史无健康检查连接）仍返回空，前端按既有不完整配置路径拒绝提交，不改变写侧契约。
- 发布异常处理：与 gateway 同批发布；回滚需回退 `clone.go` 与对应镜像。

## 下次遇到

- 先查什么：对应读面 DTO 的 `providerProtocolProfileId` 是否非空；`accounts.health_check_connection_id` 是否指向有效连接行；`account_connections.connection_preset_code` 是否在 `ConnectionPresetProfileID` 映射内。
