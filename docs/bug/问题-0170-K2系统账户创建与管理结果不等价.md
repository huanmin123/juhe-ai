## 基本信息

- 编号：BUG-0170
- 状态：待修复

- 发现方式：自查（已提交 Git 历史审计、独立复审）

- 关联 bug：BUG-0152、BUG-0169

## 问题概述

- 现象：K2 Go system-account CRUD 只实现账户行的核心读写，遗漏 Node 创建账户时必须同时完成的资源初始化，并改变了 null、选项、PATCH 回执、审计与缓存失效结果。
- 期望：通过系统账户接口创建、清除或更新账户后的数据库资源、管理 UI 回执、操作日志和网关运行态应与 Node 一致。
- 实际：
  1. Node 在同一事务中创建 `system_accounts`、默认 groups、默认 route strategies、默认 API keys 和 chat API key；Go `AccountStore.Create` 只插入 `system_accounts`。新建账户不会获得 Node 默认可用的路由和密钥资源。
  2. `requestLimits:null` 在 Go 的 PATCH 解析中仍被映射为空结构，随后不会写入 SQL `NULL`，因此无法清除已有限制；`aiAccountLimit:null` 被改写为 `0`，Node 则归一化为 SQL `NULL`。Go profile 的 raw request-limits 读取和非空写入校验已在 `76c352987` 对齐，但 nullable 清除仍待修复。
  3. 历史 Go `/system-accounts/options` 曾把 `username` 作为 `name`，在同时提供 IDs 与 keyword 时忽略 keyword，并使用任意子串匹配；Node 返回 `display_name`、叠加两个过滤条件且只做大小写不敏感的精确/前缀匹配。上述 options 差异已由 `821cc210e` 修复。
  4. 历史 Go PATCH 最终只返回 `id/updatedAt`，导致字段 delta 全部丢失；该回执差异已由 `6bc723f2b` 补齐非 nullable 变更字段（名称、角色、状态、改密标记、图像开关、AI 账户限制和非空请求限制）。显式 nullable 清除、操作日志 scope/viewer 仍待修复；Node 将 scope 归给目标账户并设置对应 viewer。
  5. Node 在 status、image-generation 和 request-limit 变更后通知 gateway runtime 与 API Key validation cache，并在后者失败时反馈标志；Go 没有失效依赖或调用，已禁用账户或新限制可能在运行实例中继续生效旧值。
  6. description 长度、PATCH 密码最小长度等仍比 Node schema 宽松；此处不是 Go 取消 Node 人为并发限制，而是管理数据合法性和最终持久化结果改变。
- 影响范围：新用户创建后无法按 Node 默认路径使用管理资源；管理页出现错误名称或陈旧行；限制清除、禁用和策略变更不能可靠传播到网关；不合法数据可能进入业务库。

## 根因与证据

- Node 创建副作用：`backend/src/storage/system-accounts.repository.ts` 的 async create 在一个 client transaction 中依次调用 `ensureDefaultBuiltInGroupsForSystemAccountAsync`、`ensureDefaultRouteStrategiesForSystemAccountAsync`、`ensureDefaultApiKeysForSystemAccountAsync`、`ensureChatApiKeyForSystemAccountAsync`。
- Go 创建：`backend-go/projects/gateway/internal/authsys/store_accounts.go` 的注释和 SQL 都表明只插入账户行，并把关联资源留给未被调用的其他 slice。
- Node options：同一 repository 查询 `display_name`；Go `ListOptions` 查询 `id,username,status`。
- Go null/回执/日志/缓存代码位于 `authsys/app.go` 和 `store_accounts.go`；Node 的管理路由与 repository 在 `backend/src/modules/system-accounts/`、`backend/src/storage/system-accounts.repository.ts`。
- 当前 Go 生产入口尚未装配 K2（BUG-0152）；本记录评估的是入口修复后 Go 实现本身仍会产生的确定性差异。

## 修复与验证

- 已完成切片：`821cc210e` 对齐 `/system-accounts/options` 的 `display_name`、IDs+keyword 联合过滤、去重和精确/前缀关键词语义，并加入 HTTP 回归测试。
- 未完成范围：将默认资源 bootstrap 纳入同一账户创建事务或采用已验证的等价协调器；显式建模 nullable 字段；补齐 operation-log scope/viewer 和失效回执 DTO；接入必需缓存失效，失败语义与 Node 对齐；按 Node schema 验证日期和字段边界。
- 必需验证：SQLite 与 PostgreSQL fresh/upgrade 创建账户后资源集合断言；null 清除 golden；options 联合过滤；前端列表增量更新；禁用/请求限制后跨实例 runtime 与 API Key cache 行为；操作日志目标可见性。
- 当前验证：现有 `authsys_test.go` 仅覆盖内存 SQLite 中的窄 CRUD，未覆盖上述资源、nullable、缓存、日志或前端契约。

## 完成总结

- 结论：K2 system-account 管理不是可独立下掉 Node 的完整迁移；必须先完成关联资源、回执和运行态副作用，才可进行唯一 owner 切换与物理归档。
