# BUG-0173 Go 运行时生产安全门禁缺失与信号错位

## 基本信息

- 编号：BUG-0173
- 状态：已修复（2026-09-06 从头复查波次，含独立复审 blocker 修正）
- 严重程度：P1（门禁缺失）/ B1 信号错位在提交前被复审拦截
- 发现时间：2026-09-06（配置完整性取证）
- 发现方式：Node→Go 迁移从头复查（8 代理取证 + 独立复审）
- 模块：后端 / 网关 / 运行时配置
- 关联报告：`docs/reports/Node到Go迁移从头复查报告-20260906.md`

## 问题概述

- 现象：Node 归档 `config/runtime.ts`、`development.ts` 中的生产安全门禁在 Go 运行时整体缺失：`JUHE_AI_SECRET` 无生产强度校验、`JUHE_AI_COOKIE_SECURE` 恒默认 false、`JUHE_AI_DEV_AUTO_LOGIN_USERNAME` 无生产禁用门、`JUHE_AI_ALLOWED_ORIGINS` CORS 契约零消费、`LOG_MAX_FILES/LOG_RETENTION_DAYS` 越界静默 clamp（Node 为 fail-fast）；另有死配置 `JUHE_AI_QUEUE_DRIVER`/`JUHE_AI_REDIS_QUEUE_URL` 强制部署配置永不被消费的队列 URL。
- 追加（复审 B1）：首次实现把生产信号读成 `JUHE_AI_NODE_ENV`，与 Node 基线（`runtime.ts:979-980` 读 `NODE_ENV`）、同进程既有读取点（`operationlog/config.go:192`、`auditlog/input_server.go:71`）、部署事实（`docs/deploy` 与生产 Pod env 均设 `NODE_ENV`，无 `JUHE_AI_NODE_ENV`）三方不符——按现有生产环境部署时全部新门禁不会触发，且 cookie Secure 相对 Node 时代回退。复审同时指出错误文案写 `NODE_ENV` 而检查的却是别的变量，自相矛盾。

## 根因与证据

- 门禁缺失根因：迁移期 Go 组合根只迁移了「当时代码消费的 env 范围」，安全门禁未被任何切片认领（配置完整性代理 A8 清单 a1-a3）。
- 信号错位根因：实现代理以 `runtime.go` 原有的 `JUHE_AI_NODE_ENV`（ChatToolEnvironment）为生产信号锚点，未回查 Node 原文与部署事实；初版测试用同一错误变量自证，掩盖偏差。独立复审以三方交叉（归档原文/同进程读取点/Pod env 快照）定案。

## 修复记录（2026-09-06）

- 生产信号统一为 `NODE_ENV`（`productionRuntime()`，runtime.go）；`ChatToolEnvironment` 保留 `JUHE_AI_NODE_ENV` 显式覆盖、未设回落 `NODE_ENV`；`JUHE_AI_SECRET` 生产 ≥32 位非默认校验、`JUHE_AI_COOKIE_SECURE` 生产默认 true、`JUHE_AI_DEV_AUTO_LOGIN_USERNAME` 生产禁用。
- `JUHE_AI_COOKIE_SECURE` 对齐 Node `strictBooleanConfig`（true/1/yes/on、false/0/no/off、非法值 fail-fast）；LOG 越界对齐 `numberConfig` 的 Math.trunc 语义（"10.5"→10）。
- `JUHE_AI_ALLOWED_ORIGINS` CORS 中间件接入主 listener 管理面前缀（`/__aisys__`、`/__aipublic__`、`/__aidelegated__/v1`；无 Origin 请求与 /v1 链字节级不变）。注意：归档 Node 生产链定义了 origin 契约但从未挂载 CORS——Go 挂载属主动加固决策（报告 §7-D12），生产启动强制显式 allowlist。
- 删除 `JUHE_AI_QUEUE_DRIVER`/`JUHE_AI_REDIS_QUEUE_URL` 死配置面（含 performanceHints 隐式翻转）。
- 附带（复审 minor）：代理测试诊断槽容量接 `JUHE_AI_BACKGROUND_DIAGNOSTIC_TASK_MAX_IN_FLIGHT`（默认 5、钳位 1..1000）。
