## 问题概述

- 现象：新账户余额自动探测没有稳定表现为“仅支持时自动开启”，手动开启后还可能长时间停在待查询。
- 期望：只有明确返回余额或账户级不限额时才自动开启；未命中保持关闭。
- 实际：统一内置查询器正常返回 `status='unsupported'` 时，自动探测服务仍构造命中结果并执行开启。
- 影响范围：首次激活自动探测和一次性余额回填；手动开启与周期刷新不使用该命中函数，但页面现象容易混淆。

## 复现步骤

1. 构造合格的物理单 Key 自动探测候选。
2. Mock `queryBuiltinAccountBalance()` 返回 `{ adapter, snapshot: { status: 'unsupported' } }`。
3. 调用 `detectAccountBalanceAdapter()`。
4. 旧实现返回非空命中，后续 `autoDetectAccountBalanceCandidate()` 会尝试开启。

## 根因分析

- 表象：自动开启看似没有按“支持能力”工作，列表又可能只显示待查询。
- 真实根因：自动探测服务把“查询 Promise 正常返回”当成“能力命中”，没有检查返回快照状态。
- 为什么会发生：原回归用抛异常模拟全部不支持，而真实统一查询器会正常返回 `unsupported`；测试替身与生产契约不一致。

## 修复方案

- 修改点：自动探测仅接受 `fresh`、`unlimited`；其他快照状态返回未命中。
- 行为影响：不支持、失败和中间态账户保持关闭，不写自动探测失败快照；成功路径不变。
- 发布异常处理：回退到前一构建即可，无 schema 和历史数据变更。

## 下次遇到

- 先核对生产函数的返回联合类型，不要用抛异常替代所有失败或不支持状态。
- 重点检查“Promise 成功”和“业务成功”是否被混为一谈。
- 状态机回归必须覆盖每个可返回状态，而不是只覆盖成功和异常。
