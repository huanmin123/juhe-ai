# BUG-0255：人工测试支持列表外模型被 resolveTestModel 成员校验拒绝

- 状态：已上线（随 10-01 22:55 发布）
- 定性：代码违反既有设计契约（按"文档回正代码"处置，非契约变更）
- 发现方式：用户生产实测报障（2026-10-01，0253 回退发布后验证账户测试链路时）

## 1. 现象

账户列表行「更多 → 测试」弹窗选择**供应商目录内、但未加入该账户 supportedModels** 的模型点「开始测试」，任务失败返回：

```
账户测试失败：账户检查模型不在支持模型列表中：<model>
```

## 2. 根因

人工测试链路两层校验语义不一致：

- **派发层**（`ResolveAccountManualTestSelection` → `AccountManualTestModelCapabilities`）只按**供应商模型目录**校验（`IsAccountManualTestModel`），允许测试目录内任意模型——与设计契约一致。
- **执行层**（`manualtest.Executor.resolveView` 保存账户路径）把 `task.Model` 覆写进 `view.HealthCheckModel` 而未钉 `ProbeModelOverride`；探针 `resolveTestModel`（`accountprobe/probe.go`）的回退分支对 `HealthCheckModel` 做 `SupportedModels` 成员校验，支持列表外模型直接失败。

同形问题在熔断恢复探测路径已于 2026-09-25 用 `ProbeRequest.ProbeModel` 钉住显式分支修复（`worker_circuit_jobs.go` `circuitRecoveryProbeRequest`，用户拍板），人工测试 executor 路径漏掉同款处理。

## 3. 契约依据

`docs/functions/AI账户检查模型与人工测试设计.md`：

> 不受账户 `supportedModels` 限制，允许用户验证尚未加入账户支持模型的供应商模型。

代码与文档冲突，按项目规则以文档为准回正代码；无需改文档。

## 4. 修复

`backend-go/shared/platform/accounttest/manualtest/executor.go` `resolveView` 保存账户路径：`task.Model` 非空时同时设置 `view.ProbeModelOverride`（走 `resolveTestModel` 显式分支，跳过成员校验）与 `view.HealthCheckModel`（保持结果信封 `model` 字段展示本次测试模型）。

边界保持：后台健康检查/激活检查路径不受影响，仍走回退分支 + 成员校验（继续保护后台配置错误不被静默测试）；草稿测试（编辑弹窗）路径的检查模型仍受派发层表单支持列表校验（保存契约镜像，不变）。

## 5. 验证

- 新增 `TestExecutorSavedAccountModelOutsideSupportedList`（`executor_test.go`）：保存账户 + `task.Model` 为支持列表外目录模型 → 上游请求携带该模型、结果信封 `model` 一致。红绿闭环：修复前该用例复现生产原错误文案（`账户测试失败：账户检查模型不在支持模型列表中：gpt-catalog-only`），修复后通过。
- `go test ./accounttest/manualtest/... ./accounttest/accountprobe/...` 全绿。
- 生产验证：发布后在账户列表对该账户选目录内支持列表外模型人工测试，应直接执行。
