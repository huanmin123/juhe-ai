# 问题-0324：自定义模型 mode 词表错配，个人自定义模型从域过滤「支持模型」下拉整表消失

- 优先级：P2（核心管理功能失效：所有用户的对话/图像类自定义模型自 2026-10-13 起在任何「支持模型」下拉不可见；无静默数据风险——存储值不变，仅读面过滤错误）
- 状态：已修复（2026-10-17，待发布）
- 引入基线：能力域拆分 v8-C 模型选择器按域过滤（2026-10-13，`docs/plans/计划-20261011T141004000Z-AI账户能力域拆分.md` 同日条目）

## 现象

用户（huanmin，self 视图）2026-10-16 在 DeepSeek 供应商模型目录新增个人自定义模型 `deepseek-v4-1-flash-260910`（`mode=text`、启用），随后「添加 AI 账户 → 支持模型」下拉（请求 `providerCode=deepseek&modes=chat&modes=responses&systemAccountId=<本人>`，服务端 200）只返回 4 条启用内置行；目录中两条「个人·启用」自定义行（`deepseek-v4-1-flash-260910`、`deepseek-ai/DeepSeek-V4-Pro-0813`）全部缺席。模型目录弹窗显示正常（前端 `categoryFromModeAlias` 对两套词表做了显示归一），形成「目录有、下拉无」。

## 影响（修复前）

- `custom_provider_models` 中 `mode='text'`（对话/编码类）与 `mode='image'`（图像类）的自定义行，在一切带 `modes` 域过滤的调用面不可见：`GET /providers/models/options`（添加/编辑 AI 账户、API Key 表单、批量编辑等的支持模型候选）与 `GET /providers/models/options/provider-codes`（v8-D 媒体域默认供应商收敛）。2026-10-17 生产实测：全表共 218 行——216 行 `text` + 2 行 `image`（scope 全部为 `personal`，无 global 行、无 audio/video 行）——即生产 **100% 自定义模型**在域过滤下拉不可见，2026-10-13 起持续至今。
- 语义上 `mode='audio'`/`mode='video'` 的自定义行因两套词表同形（`audio`/`video` 值相同）不受该缺陷影响（生产实测为 0 行）。
- 缺省（不带 `modes`）调用不过滤，不受影响；内置表行为不变。

## 根因

v8-C 的双 SQL `mode IN (...)` 域过滤对 `custom_provider_models` 沿用内置表六值目录词表（`chat/responses/embedding/audio/video/image_generation`），而自定义模型写入链只产出**另一套四值 UI 分类词表** `text/image/audio/video`（Node 时代契约：后端 `parseCustomModelBody`/`normalizeCustomModelCapabilities` 枚举固定 + 前端表单四分类 tab 原样提交）。`mode IN ('chat','responses')` 与 `mode='text'` 永不匹配——对话类全灭；`image_generation` 与 `image` 同理。

放大因素：

1. `catalog.go` `ProviderCatalogModeValues` 与前端 `accountCapabilityDomains.ts` `DOMAIN_MODEL_MODES` 的注释均**错误声称** custom 表与内置表同为六值词表，把错误假设写成了契约。
2. v8-C 定向测试 `v8c_domain_model_modes_test.go` 用裸 SQL 插入 `mode='chat'` 的 custom 行——这是写入枚举**产不出**的值，测试在假数据上通过，真实数据（`text`）全军覆没。

## 修复结果（2026-10-17）

按「错误的假设只存在于读取谓词一处」收敛，custom 谓词按表翻译（无数据迁移、不动写入/计价链）：

- `catalog.go` 新增 `appendCustomCatalogModeFilter`：先把六值域白名单翻译成 custom 四值词表（`chat`/`responses`→`text`、`image_generation`→`image`、`audio`/`video` 原样；无映射值如 `embedding` 翻译后为空集，渲染恒假 `1 = 0`），再套用 `mode IN`。应用于 custom 两处调用点（`listCustomModelOptions`、`ListProviderModelOptionProviderCodes` custom 分支）；内置表两处保持六值原样。
- 文档与注释同步为显式双词表映射契约（本文档、计划文档 v8-C 勘误条目、`接口契约与权限矩阵.md` options/provider-codes 语义、上述两处代码注释）。
- `v8c_domain_model_modes_test.go` 种子改为写路径真实可产出值，补个人 scope 归属过滤、图像域、`embedding` 空集断言。
- 存储值不变，**无数据迁移**；写入/计价/账户测试可用性判断链零改动。

验证：`go test ./internal/providers/ -count=1` 全绿（含重写后的 v8-C 用例与 v8-D 聚合用例）。
