## 问题概述

- 现象：M06 Go routestrategies 覆盖基础 CRUD、五种 mode、绑定和 CAS，但未覆盖 Node/前端的 options、edit-basic、speed-first-runtime 端点。
- 期望：路由策略完整迁移应包含 authorized 分组绑定、speed-first 运行态清理、API Key validation cache 失效及严格参数语义。
- 实际：
  1. Go 缺少上述三个端点，authorized 分支仍未实现。
  2. PATCH/DELETE 只做通用 runtime invalidation，没有 Node 的 speed-first runtime 清理；PATCH 也未触发独立 API Key validation cache 失效。
  3. Go 对 `mode/status:null` 按未提供处理，Node enum schema 返回 400；非法请求结果偏离。
  4. `routestrategies` 未在 gateway main 发现生产挂载，Node owner 和源文件仍保留。
- 端点矩阵取证：历史 Node `route-strategies.routes.ts` 注册了 admin/self 两套 `GET /route-strategies/options`、`GET /:id/edit-basic`、`GET /:id/speed-first-runtime`，前端 `routeStrategiesApi` 与 `myRouteStrategiesApi` 直接调用这些路径；列表还在每页结果上补充 `speedFirstLatencyRuntime`。历史 Go `routes.go` 仅注册列表、详情、CRUD 五类路径，没有 `/options`、`/{id}/edit-basic` 或 `/{id}/speed-first-runtime`，因此 API Key 编辑器、策略编辑弹窗和速度运行态抽屉都会请求未实现端点。
- 配置读取完整性取证：历史 Node `parseRouteStrategyRuntimeConfigJson` 对空值返回空配置，但对非法 JSON 或 `normalRoutingConfig`/`hybridRoutingConfig` 的非法子项直接抛错；`routeStrategyListItemFromRow`、`routeStrategySummaryFromRow` 和 edit-basic 投影均直接调用该解析器，读取损坏行会进入路由错误处理。历史 Go `parseStoredConfig` 虽能产生解析错误，但 `newListItem` 的 `listItemNormalConfig` 会把错误静默改成 `cost_first`，`newDetail` 会把 normal/hybrid 都清空后再补普通默认值；因此同一损坏 `config_json` 在 Go 列表/详情中仍返回 200 成功载荷，既隐藏存储损坏，也与 Node 的失败结果和配置内容不一致。
- 存储模式/状态完整性取证：历史 Node 的列表、详情、edit-basic 和 options 投影都会调用 `normalizeRouteStrategyMode`/`normalizeRouteStrategyStatus`，空值按 `normal`/`active` 补齐，未知值直接抛错；历史 Go `newListItem`、`newDetail` 将 `row.mode`/`row.status` 原样写入响应，`ListPage` 只校验查询参数，不校验返回行。历史 `route_strategies` 表仅有 `NOT NULL/DEFAULT`，没有 mode/status 枚举 CHECK，因此空字符串或未知值脏行会在 Go 200 响应中透传，而 Node 会规范化或进入错误处理。
- 绑定权重完整性取证：历史 Node `appendRouteStrategyBindingRows` 对每条读取到的 `weight` 调用 `normalizeApiKeyGroupBindingWeight`，除缺失/NULL 默认 1 外，非整数或不在 1–100 的值直接抛错；历史 Go `scanBindingRow` 只检查 `priority`、`status` 和 `groupEnabled`，未检查 `weight`，因此历史脏 `route_strategy_groups.weight` 会被原样返回到详情、列表预览及 PATCH 当前投影，结果与 Node 的错误语义不一致。
- 创建/PATCH 的 null 输入契约取证：历史 Node schema 对 `mode`、`status`、绑定项的 `priority/weight/status` 以及普通/混合配置的非 nullable 子字段使用 `.optional()`，显式 `null` 必须 400；只有顶层 `normalRoutingConfig`/`hybridRoutingConfig` 明确允许 `null` 清除。历史 Go `parseMutationFields` 和 `parseBindingItem` 以 `raw != nil` 跳过这些 null，再由 `normalize*` 补默认值（例如 `mode:null`、绑定 `weight:null`、`schedulingPreference:null`），会错误成功并写入不同结果。
- `systemAccountId` 作用域查询校验取证：历史 Node 详情、edit-basic、speed-first-runtime、PATCH、DELETE 路由先调用 `parseRequestScopeQuery`，显式空值（如 `?systemAccountId=`）按 schema 400；历史 Go `adminScope` 只 trim 并把空值当作未过滤范围，`find/patch/remove` 均未执行同等校验。管理员请求同一空 scope 时，Go 可能跨账户读写或返回资源，Node 会在业务查询前拒绝。
- PATCH `expectedUpdatedAt` 时间规范化取证：历史 Node `rfc3339InstantSchema` 接受 `Z` 或数值 offset，并在进入 repository 前 canonicalize 为 UTC 毫秒；历史 Go 处理器只用 `time.Parse` 验证后把原始字符串传给 `Store.Patch`，Store 直接以该字符串做 `updated_at = ?` CAS。同一版本用 `2026-01-01T08:00:00+08:00`、不同小数位等等价 RFC3339 表示时，Node 会成功，Go 因字符串不等而返回不存在/版本冲突，功能结果偏离。
- 列表分页数字查询取证：历史 Node `integerQueryValue` 使用 `Number(trimmed)` 后接受所有整数表示（如 `1e2`、`1.0`），再由分页规范化器限幅；历史 Go `queryInt` 使用 `strconv.Atoi`，同样输入会被判定无效并回退默认 page/pageSize（例如 Node `pageSize=1e2` 得 100，Go 得默认 50），分页结果和页边界不一致。
- 描述长度边界取证：历史 Node 请求 schema 的 `z.string().trim().max(200)` 按 JavaScript UTF-16 `String.length` 计数；历史 Go `parseMutationFields` 与 `nullableDescription` 使用 `len([]rune(...))`。因此包含 astral emoji 等代理对字符时，同一描述可能在 Node 超过 200 而 Go 仍接受，创建/PATCH 的 400 与持久化结果不一致。
- 变更异常状态码取证：历史 Node create 捕获未分类异常后统一以 400 返回（重复名称例外 409）；PATCH 对 API Key validation 失效返回 500、版本冲突 409/不存在 404，其余异常仍返回 400；DELETE 不存在 404、其余异常返回 400。历史 Go `writeMutationError`/删除处理对未分类错误统一返回 500，仅显式 `ValidationError`/冲突类型映射 400/409，依赖或数据库异常下客户端状态码与 Node 不一致。
- create 操作日志字段取证：历史 Node create 固定写入 `name/mode/status/groupBindings/normalRoutingConfig/hybridRoutingConfig` 六个 `safeChange`，配置未设置时也保留“未设置”审计项，并使用 Zod 解析后的绑定输入；历史 Go 仅对非 `cost_first` 普通配置、或实际传入的混合配置追加字段，`summarizeBindings` 还会把省略的 priority/status 以解析默认值写入。相同创建请求的 operation log 变更字段数量和 before/after 内容因此不同，影响审计追溯。
- 分组绑定并发锁取证：历史 Node PostgreSQL create/PATCH 调用 `loadRouteStrategyBindableGroupsAsync(..., lockRows=true)`，查询带 `FOR UPDATE OF groups`，确保“分组启用且可绑定”的检查与策略绑定写入在同一事务内串行；历史 Go `normalizeBindings` 的 `loadBindableGroups` 查询没有任何行锁。并发停用/删除分组时，Go 可能基于旧的 enabled/canBind 快照提交 active 绑定，Node 会等待并在锁后重新按最新状态判定，最终策略可用性不一致。
- 影响范围：前端运行态/编辑页面不可用；授权绑定、策略变更后的网关和 API Key 校验可能继续使用旧状态；null 请求被错误接受。

### 2026-09-05：路由策略 PostgreSQL 关键字范围未固定 Node 的 `C` 排序规则

- Node 基线：历史 `buildRouteStrategyFiltersForClient` 在 PostgreSQL 分支对策略名关键字使用 `(route_strategies.name COLLATE "C" >= lower AND route_strategies.name COLLATE "C" < upper)`；SQLite 分支才使用未显式指定排序规则的范围比较。`textPrefixUpperBound` 只负责生成上界，比较本身仍由 Node 明确固定为 `C` 排序（`backend/src/storage/route-strategy.repository.ts`）。
- Go 实现：历史 `backend-go/projects/gateway/internal/routestrategies/store.go` 的 `keywordFilter` 对 SQLite/PostgreSQL 统一生成 `(route_strategies.name >= ? AND route_strategies.name < ?)`，没有按数据库驱动补充 `COLLATE "C"`，且列表查询沿用同一过滤器。
- 结果偏差：当 PostgreSQL 数据库默认 collation 不是 `C` 时，同一关键字的范围边界、大小写/重音字符排序和命中集合可能与 Node 不同；例如包含非 ASCII 或大小写临界名称时，Go 可能漏掉 Node 命中的策略，或返回 Node 不会命中的策略。该偏差发生在已迁移的策略列表读路径，不是纯 SQL 形式差异。
- 结论：这是已提交 M06 PostgreSQL 关键字过滤的确定性契约缺口，当前仅记录，未修改 Go 代码。

## 修复与验证

- 修改点：按完整端点矩阵补齐 options/edit/runtime/authorized，恢复 speed-first 与 API Key validation 失效，严格拒绝 null/unknown，完成真实 gateway/PG/Redis/前端回放后再摘除 Node。
- 当前验证：正常 mode/绑定/CAS 的源码结构基本覆盖，但缺失功能和副作用未验证。
- 新增未修复子项：损坏或非法 `config_json` 的读取必须保持 Node 的错误可见性，不能在列表/详情中静默回退默认配置；需要补充 malformed JSON、非法普通配置和非法混合配置的 Node/Go 回放测试。
- 新增未修复子项：列表/详情等读模型必须复用 Node 的 mode/status 规范化和脏值失败语义，不能直接透传未知或空存储值；需要补充脏 mode、脏 status 与默认值回放测试。
- 新增未修复子项：路由策略绑定读模型必须对 `weight` 执行 Node 同等的 1–100 整数完整性校验；需要补充 0、101、非整数脏行的列表/详情/PATCH 回放测试。
- 新增未修复子项：创建/PATCH 必须区分“缺失”和显式 `null`，仅保留 Node 明确允许清除的两个顶层配置字段；需要覆盖 mode/status、绑定字段和配置子字段的 null 400 回放测试。
- 新增未修复子项：详情、编辑、运行态和写端点必须复用 `parseRequestScopeQuery` 的空/非法 `systemAccountId` 400 语义，并保持 self 路径的强制当前用户作用域。
- 新增未修复子项：PATCH 必须先将 `expectedUpdatedAt` 规范化为 UTC 毫秒再做 CAS，并覆盖等价 offset、不同小数位、非法/无时区输入回放。
- 新增未修复子项：列表分页参数应保持 Node 的整数数字字符串兼容范围，至少覆盖十进制、小数零尾和科学计数法输入的回放。
- 新增未修复子项：描述长度校验需与 Node 的 UTF-16 code-unit 语义一致，补充 emoji/代理对边界回放。
- 新增未修复子项：create/PATCH/DELETE 的异常状态码矩阵需按 Node 路由契约回放；至少覆盖未包装存储错误、版本冲突、资源不存在和 validation-cache 失效。
- 新增未修复子项：create operation log 应保留 Node 的六字段审计项及输入 presence，补充 cost_first、weighted、hybrid 和省略绑定可选字段的日志回放。
- 新增未修复子项：PostgreSQL 绑定写入必须恢复 Node 的分组行锁并补并发回放（route create/PATCH 与 group disable/delete 交错），验证不会提交基于旧 enabled 状态的 active 绑定。
- 新增未修复子项：路由策略 PostgreSQL 关键字过滤必须按 Node 在 PG 分支的 `COLLATE "C"` 生成范围条件，并补充 ASCII、大小写、重音和非 ASCII 前缀的 Node/Go 命中集合回放；不能用默认 collation 下的结果替代。
- 结论：M06 不能视为完整路由策略功能迁移。
