# BUG-0144 多供应商模型目录探针被本地能力过滤拒绝

- 编号：BUG-0144
- 状态：已修复
- 严重程度：P1
- 发现时间：2026-07-31
- 发现方式：用户反馈与代码审计
- 模块：后端 / 网关 / 供应商驱动 / 用户显式账户模型同步
- 关联计划：无
- 关联 bug：BUG-0143
- 责任人：待定

## 问题概述

- 现象：Gemini、DeepSeek、GLM 账户在用户显式执行受控模型目录同步时，网关返回“当前分组无账户支持请求路径或客户端协议”，无法取得该账户上游模型列表。
- 期望：服务端发起的受控目录探针应仅使用该账户的凭据和 Base URL 请求对应上游模型目录；客户端请求模型目录仍返回本地目录。
- 实际：Gemini URL helper 对全部模型列表请求返回空候选；DeepSeek 和 GLM 的 API Key 驱动只声明 Chat 请求能力。驱动注册表在 URL 候选为空时先拒绝请求，导致后续目录探针不能到达上游。
- 影响范围：Gemini native / 混合供应商 Gemini profile、DeepSeek OpenAI-compatible、通用 GLM / GLM Coding OpenAI API Key 的用户显式账户目录同步；不影响本地公共模型目录，也不再作为测试、激活、健康或恢复的前置条件。

## 复现步骤

1. 创建上述任一 API Key 账户并填写有效 Base URL 与凭据。
2. 从账户表单显式点击模型目录同步。
3. 观察请求在本地能力筛选阶段被拒绝，未发送至账户上游。

## 根因分析

- 表象：账户模型目录探针被当作普通客户端模型列表请求或 Chat-only 账户的无效请求。
- 真实根因：显式目录同步服务已在服务端给模型目录请求加上内部探针标记，但 Gemini、DeepSeek、GLM 的 ProviderDriver 没有把这个受控场景转换为可选上游 URL 和可支持的账户能力；注册表的 URL 非空前置检查因此提前拒绝。
- 为什么会发生：本地公共模型目录和受控上游探针共享相同的 HTTP 路径，驱动实现只覆盖了“公共目录必须本地处理”或“账户只支持 Chat”的一侧，缺少对服务端来源的精确区分。

## 修复方案

- Gemini：仅已标记的 Gemini native 或混合 Gemini 模型目录探针构造上游 `/v1beta/models` URL；混合驱动先按 Gemini 模型路径分支，错误方法不再落入 OpenAI URL 构造；Code Assist / Google One runtime 继续不支持该探针。
- DeepSeek：仅已标记的 OpenAI API Key `GET /models` 或 `GET /v1/models` 通过账户能力筛选并转发到上游 `/v1/models`。
- GLM：仅已标记的 OpenAI API Key 模型目录探针通过能力筛选，并按账户 Base URL 保留 `/api/paas/v4` 或 `/api/coding/paas/v4` 后追加 `/models`。
- 公共网关模型列表不改变：未标记请求、错误 HTTP 方法、错误路径和不兼容 OAuth 仍不会转发到上游。

## 下次遇到

- 先查什么：先确认显式目录同步服务是否已给目录请求加内部标记，再检查 ProviderDriver 的 URL 构造和 `accountSupportsRequest` 是否同时放行。
- 重点看什么：不能只看 driver 的能力声明；注册表会先要求存在上游 URL 候选。还要分别验证 API Key、OAuth、正确方法、正确路径和公共客户端请求。
- 如何避免误判：新增供应商或协议档案的目录同步时，必须添加“已标记受控探针可转发、未标记请求不转发”的隔离回归。

## 完成总结

- 完成时间：2026-07-31
- 结论：Gemini、DeepSeek、GLM 已在不改变公共模型目录语义的前提下支持受控账户模型目录探针。
- 后续建议：新增 ProviderDriver 的模型目录能力时，复用该受控探针边界并在驱动级回归中覆盖。
