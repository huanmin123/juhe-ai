# BUG-0358 火山语音连通性探针路径、凭据与请求体三处失配

## 基本信息

- 编号：BUG-0358
- 状态：已修复待发布（2026-11-06）
- 严重程度：P1
- 发现时间：2026-11-06
- 发现方式：用户提供真实火山凭据做全供应商真机测试 + 上游响应取证
- 模块：后端 / 账户探针 / 媒体域连通性探测（`shared/platform/accounttest/accountprobe`）
- 关联计划：无
- 关联 bug：BUG-0355 / BUG-0356（同期探针缺陷）
- 责任人：网关维护者

## 问题概述

- 现象：火山语音账户（`speech_token`）人工测试失败；直接请求 `POST https://openspeech.bytedance.com/api/v3/tts/create` 空体返回 `403 / 45000030「extract request resource id: fail to convert model to resource_id」`。
- 期望：连通性探测验证 `speech_token` 有效——带 `model` 时上游返回 `400 / 45001116「text_prompt is required」`（穿过授权层，证明密钥有效）。
- 实际：探针三处失配导致无法穿过授权层：
  1. **URL**：探针打 `{账户 base_url}/tts/create`，而火山语音域固定为 `https://openspeech.bytedance.com/api/v3/tts/create`（账户 base 是 ark `/api/v3`，两者不同域）；
  2. **凭据**：探针用账户 `api_key` 作 `Authorization: Bearer`，语音域要求 `X-Api-Key: <speech_token>`（与 ark API Key 相互独立）；
  3. **请求体**：空体缺 `model`，上游无法解析 resource_id（45000030），永远到不了参数校验层。
- 影响范围：所有 volcengine 语音域（`audio_speech`）账户的人工测试与连通性判定；真实语音转发走链上层固定域分支，不受影响。

## 复现步骤

1. 直接请求：`POST https://openspeech.bytedance.com/api/v3/tts/create`，头 `X-Api-Key: <speech_token>`，body `{}` → `403 / 45000030`。
2. 同请求 body 改为 `{"model":"seed-audio-1.0"}` → `400 / 45001116 text_prompt is required`（密钥有效）。
3. 经探针（修复前）→ 失败；修复后 → `密钥连通性验证通过（上游 HTTP 400）`。

## 环境信息

- 分支 / 版本：当前工作区（Go gateway，未发布）
- 上游：火山引擎 `openspeech.bytedance.com`（语音域）、`ark.cn-beijing.volces.com/api/v3`（视频域）
- 是否稳定复现：是

## 根因分析

- `probe_connectivity.go` 的 `buildConnectivityRequest` 对 `audio_speech` 只做 `JoinUpstreamURL(view.BaseURL, "/tts/create")` 并留空 body，认证统一走 `upstreamAuthStrategy`（volcengine → Bearer）。
- 该实现取自 2026-11-01 连通性探测裁决时的假设：audio_speech 只服务 volcengine_openspeech 模板、空体即可穿授权层。2026-10-17 TTS 迁移后上游改为「缺 model 无法解析 resource_id」，空体形态失效；同时火山语音域与 ark base 分属两个域，探针没有承接链上层已有的固定域分支。
- 真实语音转发路径（`gatewaymedia/volcengine_tts.go` 返回 `/api/v3/tts/create` + 链上固定 host + `X-Api-Key: speech_token`）一直正确，缺陷只在探针构造。

## 修复

- `buildConnectivityRequest`：volcengine 的 `audio_speech` 改用固定语音域 `openspeech.bytedance.com` + `/api/v3/tts/create`，不再读账户 ark `base_url`；认证改 `X-Api-Key: speech_token`（缺失显式失败）；`audio_speech` 请求体统一携带 `{"model":<model>}`（其他供应商行为不变：OpenAI `/audio/speech` 带 model 仍因缺 input 返回 400）。
- 固定域通过包级变量 `volcengineSpeechBaseURL` 注入，测试可替换为本地 mock。
- 回归：新增 `TestConnectivityProbeVolcengineSpeech`（固定域、`X-Api-Key`、model body、不得走 Bearer、400 判通过）；删除旧的「空体 + base 拼接」断言（`probe_audio_test.go`）。

## 验证记录

- 单测：`go test ./accounttest/accountprobe/ -count=1` 全绿；`gofmt -l` 无输出、`go vet` 通过。
- 真实上游（2026-11-06，一次性探针测试跑完即删）：
  - `volc-video-create`（视频 Key，`ark.cn-beijing.volces.com/api/v3`）→ 通过，HTTP 404，105ms；
  - `volc-audio-speech`（语音 Key 作为 `speech_token`）→ 通过，HTTP 400，70ms。
- 凭据侧结论（2026-11-06 复测修正）：用户提供的 `ark-50340c11…` 是套餐形态 Key，`GET /api/v3/models` 返回 53 个可用模型；`chat_sse`/`chat_json`（`doubao-seed-2-1-pro-260915`）、`video_create`、`images_json` 四种探针全部通过（2.2s / 3.0s / 30ms / 168ms）。此前 chat 401 是认证组合用错（Bearer 只测过另一把 Key、本 Key 只试过 `X-Api-Key`），不是密钥失效；`X-Api-Key` 打 chat 确实 401，ark 对话/视频面统一用 Bearer。语音 Key 有效；`ark-68f9e436…` 对所有端点 401，需控制台核对。

## 附带发现（不纳入本修复）

- 非 volcengine 供应商的 `audio_speech` 连通性探针仍打 `/tts/create`（OpenAI 无此端点），当前无此类账户在役；如后续开放 OpenAI 语音账户人工测试，需按供应商分派端点。
