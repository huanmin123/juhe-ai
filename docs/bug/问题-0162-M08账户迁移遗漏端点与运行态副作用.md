## 问题概述

- 现象：M08 Go accounts 只实现核心列表、详情、创建、编辑、锁定族、标签和删除；Node/前端仍有高级详情、clone、runtime reset、批量、导入导出、余额/测试、模型目录、分组绑定、OAuth 重新授权等能力。
- 期望：账户功能完整迁移后，所有端点、状态机、凭据策略、删除清理、缓存/运行态和初始健康探针与 Node 结果一致，才允许归档 Node。
- 实际：
  1. Go 路由缺少上述大量端点，owner manifest 仍为 `missing`，Node `/accounts`、`/my-accounts` 仍挂载。
  2. Go 删除未撤销账户作为资源拥有者的 authorization/grant/source，未写 health tombstone outbox，也未刷新 group stats、lookup/authorization/runtime/cache。
  3. Go ENGAGED 锁配置更新始终复用旧 deadline 并清空 retry lease；Node 会按新的 death timeout 重新计算 deadline，无配置变化时保留 lease。
  4. Go create/patch 没有 Node 的凭据归一化、deprecated 字段清理、provider policy 校验和完整运行态副作用；create 也没有 dispatch 初始 health check。
  5. Go edit-basic 对凭据主动 mask，Node sanitizer 不 mask，返回结果存在产品可观察偏差（需产品确认是否有意安全加固）。
- 影响范围：账户管理页面功能缺失；删除后授权和缓存可能继续生效；锁定恢复时间/租约漂移；新建或修改账户的健康状态与网关运行态不更新。

## 根因与证据

- Go 路由：`backend-go/projects/gateway/internal/accounts/routes.go`。
- Node 路由/前端：`backend/src/modules/accounts/accounts.routes.ts`、`frontend/src/api/domains/accounts.ts`。
- 删除清理：Node `backend/src/storage/account-delete-cleanup.repository.ts`；Go `backend-go/projects/gateway/internal/accounts/delete.go`。
- 锁状态机：Node `backend/src/storage/account-lock.repository.ts`；Go `backend-go/projects/gateway/internal/accounts/lock.go`。
- 凭据与副作用：Node `account-credentials-normalization.ts`、`account-management-patch.repository.ts`、`accounts.routes.ts`；Go `write.go`、`patch.go`、`routes.go`。

## 修复与验证

- 修改点：以 Node/前端完整端点矩阵为基线拆分后续切片；先补删除授权撤销、health tombstone、缓存/运行态失效、锁状态机和凭据 golden，再补余下端点与初始探针；统一唯一 owner 后才归档 Node。
- 当前验证：Go SQLite 包内测试不能证明 PostgreSQL、Redis、worker、runtime 和前端行为；未执行真实 gateway 或浏览器验证。
- 结论：M08 是核心 CRUD 实现，不是完整账户功能迁移。
