# 问题-0309 定时检查间隔下限自 1 收紧为 5 分钟

- **编号**：BUG-0309
- **日期**：2026-10-11
- **级别**：P3
- **状态**：已修复（2026-10-11 提交 `e4f3cd8e8`，随 gateway 发布生效）
- **定性**：契约收紧（用户裁决），非运行缺陷。旧下限 1 分钟允许把定时模型检测配置到每分钟一次，过频检测放大上游成本与配额消耗；实测 5 分钟已足够灵敏（J3a/J3b 调度粒度与恢复周期均在 10 分钟档）。

## 现象与动机

模型检测「定时检查」的 `interval_minutes` 原契约是 `1..10080` 整数分钟（默认 60）。下限 1 意味着可配置每分钟对上游发起一整轮探针（quick 档也有十余族请求），误配置即放大上游成本。用户裁决：下限收紧为 5 分钟，上限 10080 保持不变。

| 后端校验 | `backend-go/projects/gateway/internal/modelcheckowner/business_quality_management.go` | `validateSchedule`（create）与 `validateSchedulePatch`（patch）同源收紧：`< 1` → `< 5`，错误文案同步为「定时检查间隔必须是 5 到 10080 的整数分钟」 |
| 前端 | `frontend/src/views/model-checks/ModelQualitySchedulesModal.vue` | 检查间隔输入 `:min="1"` → `:min="5"`，validator `value >= 1` → `value >= 5`，提示文案同步；同提交移除「计划状态」冗余标签（启用/暂停开关行已自明） |
| 文档 | `docs/functions/模型检测设计.md` §5.7 | 配置链路契约更新为 `5..10080`（默认 60 不变，注明 2026-10-11 收紧） |

## 影响与存量

- 已存在的 interval<5 计划**不会被自动修改**：校验只在 create/patch API 入口生效，调度完成回写不受影响；需要收紧的存量计划在页面上重新保存一次即可（保存时按新契约校验）。
- 无数据迁移、无 schema 变更。

## 教训

- 收紧数值契约时，同包测试往往有多处旧下限断言散落（本次 3 个文件 4 处），必须全库扫描 `interval=1`/`< 1` 一并同步，否则测试在旧断言处红而非新行为处红。
- 完成回写路径与 API 入口校验的边界要分开断言：收紧入口校验不等于收紧存量数据兼容语义。
