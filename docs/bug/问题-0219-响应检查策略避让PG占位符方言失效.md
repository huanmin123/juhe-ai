# BUG-0219 响应检查策略账号避让在 PG 生产方言下恒失效

## 基本信息

- 编号：BUG-0219
- 状态：已修复（待发布）
- 严重程度：P0
- 发现时间：2026-09-28
- 发现方式：自查（迁移后整体深度复审，gateway 核心链路指纹扫描）
- 模块：后端 / 网关 / 响应检查 / 账号避让 / PG 方言
- 关联计划：无
- 关联 bug：BUG-0177（manualtestrepo 全部 SQL 用 `?`，PG 42601，同款缺陷家族）
- 责任人：主代理（复审交付）

## 问题概述

- 现象：配置类响应检查策略（`configured_response_policy`）命中 `runtime_avoidance`/`avoid_account_ttl` 动作时，账号避让在生产从未生效，且每次命中只留下一条 Warn 日志（"响应检查策略运行时副作用失败已隔离"）。
- 期望：dirty 标记写入 `account_list_availability_dirty`，jobs 消费后刷新可用性投影，同时 Redis 避让状态写入并抑制账号。
- 实际：dirty 写入事务内家族展开 SELECT 使用 `?` 占位符，pgx 原样下发报 42601 语法错误；失败向上传播导致 Redis 避让、进程内缓存、invalidate 全部不执行，最终被 finalize 记 Warn 吞掉。
- 影响范围：生产唯一形态（国内单机 Docker + PG）下全部配置类响应检查策略的账号避让动作，自 2026-09-09（commit 37ec59f0f 引入该查询）至今。

## 复现步骤

1. PG 模式部署，配置响应检查策略含账号避让动作。
2. 触发一次命中该策略的请求。
3. 观察日志：出现"响应检查策略运行时副作用失败已隔离"Warn；`account_list_availability_dirty` 无新行，Redis 无避让键。

## 环境信息

- 分支 / 版本：master（2026-09-28 工作区）
- 数据状态：PG 生产形态；SQLite 模式不受影响（`newChainListAvailabilityDirtyMarker` 仅 pgDialect 启用）
- 是否稳定复现：是（PG 方言下确定性失败）

## 根因分析

- 表象：策略避让动作无效果，只有隔离 Warn。
- 真实根因：`chain_dispatch.go` 的 `newChainListAvailabilityDirtyMarker` 家族展开 SELECT 用 `?` 占位符，而 gateway pgpool 无驱动层 `?`→`$n` 改写（jobs 侧有 rewriteDriver，gateway 侧组合根各文件靠手动 `bind()` 改写），该文件无 bind 且同函数其他语句（advisory lock `$1`、upsert `$1..$6`）均正确，属单点遗漏。
- 为什么会发生：测试族（w1_dispatch_tail_test.go）在 SQLite 上模拟 PG 方言（注册 `pg_advisory_xact_lock` no-op），SQLite 同时接受 `?` 与 `$n`，占位符方言差异正是该模拟的盲区——与 BUG-0177 根因（"PG 路径自 Go 迁移以来从未被真实执行过"）同构。

## 修复方案

- 修改点：`chain_dispatch.go:920-922` 两个 `?` 改为 `$1`、`$2`（一行，与同函数风格一致）；新增 `w0219_dirty_marker_pg_gate_test.go` 按 0177 先例补真实 dev PG 门禁化回归（复用 `w1g2CoverPostgres` 临时子库，env 缺失或 PG 不可达自动 Skip，种子行 w0219 前缀事后清理；断言采用相对基线 generation +1，对权威 schema 账户表 AFTER INSERT 触发器在场与否稳定）。
- 行为影响：占位符方言修复，无行为语义变化；生产 PG 下 dirty 标记链路由恒失败转为正常。
- 发布异常处理：无需数据修复；dirty 标记从发布时刻起正常累积，历史缺失的避让不回补（策略避让是运行态行为）。
