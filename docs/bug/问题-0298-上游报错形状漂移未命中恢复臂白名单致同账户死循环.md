# BUG-0298 上游报错形状漂移未命中恢复臂白名单致 Codex 会话同账户死循环

## 基本信息

- 编号：BUG-0298
- 状态：已修复（待发布）
- 严重程度：P2
- 发现时间：2026-10-08
- 发现方式：用户反馈（生产用户 huanmin Codex 会话连续失败，trace `bab0a5b5-9cc0-455f-b1f0-63ee83bc7d91`）
- 模块：网关
- 关联计划：无
- 关联 bug：BUG-0289（同一恢复臂；本 bug 是其触发判定在生产报错形状漂移下的失效）
- 责任人：待定

## 问题概述

- 现象：用户 huanmin 的 Codex Desktop 会话（上游账户 `sub.geiliapi.com-gpt`，模型 `gpt-6.1-sol`，`/v1/responses` 流式）自 13:40:56 起连续失败（截图约 10 连败），日志记录 `error_code=upstream_retryable_error`（"上游流式响应在输出前失败，请重试"），0 token、每轮 4-7 秒。同账户 13:40:39 之前连续成功（单请求 613KB 也可），同窗口其他账户正常。
- 期望：上游拒绝加密续上下文时，BUG-0289 恢复臂自动清理重放或按既有规则换号，用户会话不中断。
- 实际：上游本次以 `response.failed(code=invalid_request, message="The request could not be processed. Please check the request parameters.")` 拒绝——与 2026-10-07 同型失败的 `encrypted_context_invalid`（"The upstream could not validate encrypted continuation context. Rebuild the conversation context in the client."，audit 档案可查）属同一拒绝的形状漂移。恢复臂白名单未命中 → 既有两分支判否 → 失败以"请重试"文案交回客户端，Codex 同上下文自动重试 → 死循环。
- 影响范围：所有携带加密续上下文的 Codex `/v1/responses` 会话在报错形状漂移期间的可用性；不影响正常请求与非 Codex 流量。

## 复现步骤

1. Codex 会话携带上一轮 `encrypted_content`（compaction / reasoning / agent_message 等）。
2. 上游中转背后的生成会话轮换，无法验证该加密状态，以 `200` SSE `response.failed` 拒绝，报错形状为 `invalid_request` 通用参数文案（而非白名单四码）。
3. 网关恢复臂白名单未命中，失败以"请重试"交回客户端，Codex 原样重试，循环复现。

## 环境信息

- 分支 / 版本：生产 `juhe-ai-single-server:gateway`（2026-10-08 08:05 构建，含 BUG-0289 修复）。
- 数据状态：审计 `audit_logs` 该账户 2026-10-07 15:04-15:16 十次 `encrypted_context_invalid`、2026-10-08 01:06/06:03/07:17 同码失败（旧形状），13:41 起全部 `invalid_request` 形状（新形状），失败面相同（200 流内、输出前）。
- 是否稳定复现：形状漂移后对该会话稳定复现。

## 根因分析

- 表象：恢复臂"没生效"。
- 真实根因：恢复臂触发判定绑定上游报错文案白名单（四精确码 + "could not be decrypted/validate" 启发）。报错文案是上游实现细节，会漂移；本次同一拒绝改报泛化 `invalid_request`，白名单未命中即失明。
- 为什么会发生：白名单机制把"是否可救"绑定在"上游怎么说"上，而上游报错形状无契约约束；判定应绑定网关自己一侧可验证的结构事实（失败面、协议族、请求体含可清理加密内容），失败归因交由动作结果与审计。

## 修复方案

- 修改点（最小改动，沿用既有通道）：
  1. `finalizeStreamFailure` 增加一个分支：加密上下文信号未命中时，openai 协议 + `/responses` 端点族内、检查拦截命中且预提交（未语义提交）的流失败，复用既有 pre-commit 换号通道（同谓词 `ShouldRetryPreCommitStreamFailureOnServer`、同 verdict、同重试预算），排除当前账户试后续候选。该失败与账户绑定——加密续状态仅生成它的上游会话可验证，换号即可能解开。
  2. 边界守卫：恢复臂已改写恢复终态文案（信号命中但无可清理内容）的失败维持终态不换号；白名单命中面维持清理重放优先（BUG-0289 位置不变）；非 openai 协议 / 非 `/responses` 请求行为不变。
  3. 会话级避让（优化①）：换号被接受时解除失败账户的会话亲和并记录来源级短 TTL 避让（复用既有来源级失败避让管线，含后台探活）——该失败与“来源×账户”绑定而非账号全局故障，同一会话的后续请求把该账户排到同层候选之后，不再反复先撞它；避让不写账户健康/熔断状态（预提交零输出失败契约不变），协作方未装配时显式降级。
  4. 同签名即停（优化②）：连续两次换号失败且上游错误码+文案完全一致判定同源，停止级联候选，走既有耗尽契约——整池同源故障时最多多花一次尝试，不做无谓级联。
- 行为影响：形状漂移类失败从"客户端同账户死循环"变为"服务端换号一次救回"；换号受既有 attempt 预算约束，预算耗尽仍走既有耗尽终态。usage/audit 错误码归因通道不变。
- 发布异常处理：随网关常规发布；无需数据修复，无配置变更。
