# BUG-0304 用量溢出落盘失败仍确认接收并删除源文件

- 严重程度：P2
- 发现时间：2026-10-09

- 关联：[全面审查复核与残留问题报告](../reports/全面审查复核与残留问题报告-2026-10-09.md)、BUG-0175 D-72

## 结论与触发条件

writer 内存队列已满，同时 overflow spool 写入失败时，`Writer.Enqueue` 仍返回 nil。`Drainer.DrainOnce` 将其当成接收成功，删除 gateway 已持久化的源文件；该条记录既未进入内存队列，也未持久化到 overflow spool，之后无法重放。

生产装配为实际可达路径：`cmd/juhe-ai-jobs/worker_assembly.go:955–966` 注入 `WithOverflowSpool`，第 983–985 行的 overflow replay 与第 1007–1009 行的 gateway drain 都使用同一个 writer。队列默认上限为 10,000 条或 64 MiB。实际触发还需要溢出落盘失败，例如目录权限、磁盘空间或文件写入/rename 失败；本轮没有证据表明生产已发生记录丢失。

## 根因及契约冲突

- `internal/usagespooldrain/drain.go:20–26` 与 `Enqueuer` 接口注释明确 nil 表示已进入内存队列、成功溢出落盘或幂等重复；失败应保留文件待重试。
- `internal/usagewriter/writer.go:267–277` 在队列满时尝试 overflow spool，无论成功还是失败都返回 nil；`spoolOverflow` 在失败时登记 `DroppedDispatchCount` 并记录日志，将丢弃视为终态。
- drain 第 257 行只检查非 nil 错误，第 263 行随后删除源文件。两组件对 nil 的含义不同，交接点无法区分“接受”与“终态丢弃”。

先前审查因为 writer 自身注释与测试明确规定 best-effort 丢弃，将这一候选排除；这个判断遗漏了 durable 源文件消费者的独立契约。本轮修正：writer 的通用投递约定不能证明 drain 在投递失败时应删除原本可以保留重试的源记录。

该问题不是进程崩溃造成的“入内存后、落库前”已知窗口：整个丢弃可在进程持续运行时发生。`docs/functions/SQLite存储说明.md:151/452` 对 spool 稳定 ID 重放的描述也未允许这条交接失败删除路径。

## 组合复现

2026-10-09 用 Go `-overlay` 在系统临时目录扩展现有 `internal/usagespooldrain/drain_test.go`，仓库源码和测试文件均未写入。使用真实 Writer、真实 FileOverflowSpool、真实 Drainer；没有启动 writer flush，也不使用数据库或真实业务数据：

1. writer 配置 `QueueMaxItems=1`、`QueueMaxBytes=65536`、`BatchSize=10`，先 Enqueue 一条合法记录占满队列。
2. overflow spool 的 Directory 指向临时目录中一个已存在的普通文件，`MkdirAll` 必定失败，稳定替代真实磁盘/权限故障。
3. 用既有 `gatewaySpoolFile` helper 写入第二条合法记录，调用 `DrainOnce`。
4. 检查源路径、writer 计数和返回结果。

执行命令（jobs 模块、`GOMAXPROCS=2`）：

```text
go test -p 1 -overlay <临时 overlay.json> ./internal/usagespooldrain -run '^TestReviewDurableSourceDeletedAfterOverflowFailure$' -count=1 -v
```

实际输出：

```text
processed=1 error=<nil> source_deleted=true dropped_dispatch=1 written=0
```

复现断言按上述错误行为编写，因此测试 PASS 表示缺陷被复现，不表示已经修复。另运行现有 `TestWriterOverflowSpoolFailureCountsDispatchDrop` 通过，证实返回 nil 的 writer 行为目前正被单组件测试锁定。

## 限定与排除

- oversize 分支也丢弃返回 nil，但本轮未证明正常 gateway 输入能超过 writer 的 64 MiB 预算，不作为已确认生产触发条件。
- overflow replay 与 writer 使用同一目录，Persist 采用时间戳、PID、UUID 新路径；没有证据支持“覆盖同一文件后又删除”的额外缺陷。
- 本问题的失败日志与丢弃计数仍存在，不能描述为完全无报错的静默丢失。

## 待修复方案与验收

交接端口应明确区分已接收与未接收。至少在 durable replay 路径中，队列满且溢出落盘失败必须保留源文件并返回可重试失败；不要仅修改计数或把 nil 改写成另一种成功状态。根治时同时核对 gateway drain 和 overflow replay，避免只修一侧。

不在本次文档任务中裁决所有 writer 调用方是否改变 best-effort 语义，也不将当前已接受的内存窗口扩大为零丢失承诺。后续实现需验证：正常入队、溢出持久化成功、溢出失败保源、重试恢复、稳定 ID 幂等和停机排空。实施记录见下节。
