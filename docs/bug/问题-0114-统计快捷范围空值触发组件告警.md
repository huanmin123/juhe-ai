# BUG-0114 统计快捷范围空值触发组件告警

## 基本信息

- 模块：前端 / 统计概览 / 系统指标 / Ant Design Vue

## 问题概述

- 现象：进入统计概览时，浏览器控制台连续输出 `ASegmented value=undefined` 的 Vue prop 类型告警。
- 期望：自定义日期不匹配任何快捷范围时，不选中“今天 / 近7天 / 近1月”，同时控制台保持安静。
- 实际：页面把 `undefined` 显式传给 `a-segmented` 的必填 `value`；直接省略该 prop 又会触发 `Missing required prop: value`。
- 影响范围：统计概览与系统指标两个复用相同快捷范围写法的页面；数据请求和页面交互未中断，但告警污染开发排障信号。

## 复现步骤

1. 在开发环境进入统计概览，并让当前日期范围不匹配任一快捷范围。
2. 观察浏览器控制台。
3. 控制台稳定出现 `Expected String | Number, got Undefined`。

## 根因分析

- `quickRangeValue` 合法返回 `undefined`，用于表示当前日期是自定义范围。
- Ant Design Vue 的 `Segmented.value` 是必填且运行时只接受字符串或数字；显式 `undefined` 和完全省略都不符合组件合同。
- 原回归只验证日期计算和刷新顺序，没有挂载组件或固定该受控值边界，因此构建与类型检查无法发现运行时告警。

## 修复方案

- 统计概览与系统指标统一传入 `quickRangeValue ?? ''`。
- 空字符串不是任何快捷选项的值，保持“无选中”语义，同时满足 `Segmented` 的必填字符串合同。
- 在既有统计日期窗口回归中固定两个页面的绑定方式，防止重新传入 `undefined`。

## 下次遇到

- Vue 类型检查不能替代第三方组件运行时 prop 校验；浏览器验收必须检查 error / warn。
- 受控组件用“未选中”状态时，先确认组件是否允许 `undefined`、`null` 或缺失 prop。
- 如果 prop 必填且只接受标量，使用不会命中任何 option 的同类型哨兵值，并为该边界补回归。

## 完成总结

- 完成时间：2026-07-17
- 结论：两个统计页面已统一使用空字符串表达无快捷范围，浏览器复验无告警。
- 后续建议：新增受控选择组件时，继续把无选择状态纳入运行时浏览器验收。
