# BUG-0243 账户编辑密文占位态的前端回归缺口

## 基本信息

- 编号：BUG-0243
- 状态：已修复（2026-09-30 批次）
- 严重程度：P1（两项）+ P3（三项）
- 发现时间：2026-09-30
- 发现方式：全面审查（多子代理复审+主代理核验）
- 模块：前端（views/accounts）
- 关联计划：无
- 关联 bug：BUG-0238（占位符契约引入方；本条为该契约落地后的前端回归）
- 责任人：待定

## 问题概述

- 现象：编辑弹窗在密文占位态（未 reveal）下，测试/余额查询与保存链路存在占位符被当真实值处理的回归，共五项。
- 期望：占位符在任何出站 payload 中都不作为真实凭据提交；占位态下的非凭据修改正常生效；呈现层不暴露占位符字面量。
- 实际：见问题清单（1/2 为 P1，3/4/5 为 P3）。
- 影响范围：账户编辑弹窗（views/accounts）的测试、余额查询、多 Key 池保存、OAuth 呈现与 reveal 交互。

## 问题清单

1. P1：草稿测试/余额查询回填占位符当真实凭据——`accountDraftTestPayload.ts` `accountDraftTestCredentials`（约 :142-169）的 `preserveCredentialText` 用 `hasCredentialText`（仅判非空）回填 detail 凭据，`__ENCRYPTED__` 通过；该文件无占位过滤。编辑弹窗不 reveal 直接点"测试/余额查询"会把占位符发给 `POST /accounts/{id}/test`，上游 401 误判凭据失效。
2. P1：多 Key 池"占位行+新输入"混合保存静默截断——`accountCredentials.ts` `buildApiKeyCredentials`（约 :79-101）占位行剔除后 `keptKeys.length===1` 只提交 `api_key`，后端 replacesWithSingleKey 删除 api_keys/策略/权重，未揭示的真实 Key 被静默删除。
3. P3：占位态下仅改策略/权重/删除占位行，保存提示"未检测到账户修改"（修改被静默丢弃）。
4. P3：OAuth 账户 token 字段为 textarea，`__ENCRYPTED__` 以明文可见（呈现层）。
5. P3：reveal 与高级配置加载交错时基线被重置回占位态致无谓明文重提交；reveal 全量替换丢弃用户已输入新值。

## 复现步骤

1. 打开任一已有凭据账户的编辑弹窗（不点眼睛 reveal）；
2. 直接点"测试"或"余额查询"——payload 携带 `__ENCRYPTED__`（问题 1）；
3. 多 Key 池账户：保留若干占位行并新输入一行真实 Key，保存——池被截断为单键、未揭示的真实 Key 被删除（问题 2）；
4. 占位态仅调整 api_key_strategy/权重或删除占位行后保存——提示"未检测到账户修改"（问题 3）。

## 环境信息

- 分支 / 版本：master
- 数据状态：问题 2 触发时服务端 replacesWithSingleKey 已执行，未揭示的真实 Key 需重新录入
- 是否稳定复现：是

## 根因分析

- 表象：占位符在后端 PATCH 通道有防回写（BUG-0238 契约第 4 条），但前端出站链路未同步建立占位语义。
- 真实根因：0238 前端实现只在保存 payload 一处过滤占位；`accountDraftTestPayload.ts` 与 `accountCredentials.ts` 的派生链各自以"有值"判断凭据，未识别占位符常量。
- 为什么会发生：占位符契约（BUG-0238）引入后回归面扩大，前端各凭据消费点未逐一收口。

## 修复方案

- 1/2/3 本批修复：占位回填过滤（测试/余额查询载荷不携带占位符）+ 混合行保存守卫（占位行与新输入并存时不得降级单键提交）+ 占位态策略/权重守卫（占位态下非凭据修改可保存）。
- 4/5 交互收尾项视工作量同批或另列（由前端修复代理返回实际范围）。

## 验证结果

- 修复落点：
  - `accountDraftTestPayload.ts` `hasCredentialText` 增占位过滤——单点覆盖 preserve 输出侧/源侧回填与 `hasOAuthTestCredential`，测试与余额查询两路径共同出口；
  - `accountCredentials.ts` 新增 `accountApiKeyPoolBaseline` + `validateAccountApiKeyCipherRows` 纯函数守卫（混合行阻断；纯占位池行数/策略/权重变化阻断；无占位或结构未变放行），接入 `useAccountEditSaveFlow.ts` 主保存与基础编辑两处校验链；
  - 删除三个零调用死导出及连带私有符号。
- 新增 `accountDraftTestPayload.test.ts` 7 用例 + `accountCredentials.test.ts` 增 11 用例——通过；`vue-tsc` exit 0；vitest 全量 75 文件 893 用例全绿。
- 追加批次（同日）：修复两个预存回归脚本断言失配（实际引入提交 `f42c5f42b` 的 Grok/代理配置演进，非 0238 批）——`account-edit-save-flow-regression.ts` 断言更新为含 `oauthDefaultsAllowed` 条件；`account-gpt-request-overrides-regression.ts` 用例补 `proxyProfileId` 前置必填；两脚本均绿。
