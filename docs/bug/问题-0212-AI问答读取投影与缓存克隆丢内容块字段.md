# BUG-0212：AI 问答读取投影与前端缓存克隆丢内容块字段

- 编号：BUG-0212
- 状态：修复中（批次1 实施中，待发布验证）
- 发现：2026-09-28，批次1 复审：刷新页面或缓存命中后助手消息与流式结束时不一致

## 现象

- 刷新页面或前端 IndexedDB 缓存命中后，正文块丢失、块顺序错乱——`output_text` / `reasoning` / `tool_call` 的 `order` 未随读取链路返回。
- 工具明细消失：`tool_call` 的 `item` / `blockId` 丢失，工具过程块刷新后无法回放。
- 图片元数据消失：`output_image` 的 `mimeType` / `width` / `height` / `revisedPrompt` 丢失，图片块退化。

两层叠加：后端 REST 读取投影丢一层，前端 IndexedDB 克隆再丢一层——同一条消息在实时 SSE 链路字段完整，刷新或缓存命中后不完整。

## 根因

- 后端 REST 读取投影（消息列表/详情序列化）没有完整映射 `content_blocks_json` 的全部字段：三类内容块的 `order`、`tool_call` 的 `item` / `blockId`、`output_image` 的 `mimeType` / `width` / `height` / `revisedPrompt` 在投影层被丢弃。
- 前端把消息写入/读出 IndexedDB 展示缓存的克隆逻辑只复制部分字段，构成第二层丢失。
- SSE 实时链路与读取链路字段集不一致，且没有“读取投影字段集 = 写入字段集 = 前端缓存克隆字段集”的契约测试，缺口长期不可见。

## 修复

- 后端读取投影补齐全部内容块字段（`output_text` / `reasoning` / `tool_call` 的 `order`；`tool_call` 的 `item` / `blockId`；`output_image` 的 `mimeType` / `width` / `height` / `revisedPrompt`）。
- 前端 IndexedDB 克隆同步保留同一字段集。
- 文档契约同步（`docs/functions/AI问答设计.md` 持久化投影区）：读取投影完整恢复内容块字段，前端本地缓存同集保留。

## 验收

- 同一轮生成结束后刷新页面，消息内容块（含顺序、工具明细、图片元数据）与流式结束时一致。
- 清空本地缓存走纯 REST 读取与缓存命中走本地克隆两条路径，渲染结果一致。

## 教训

- 内容块的“写入字段集”“读取投影字段集”“前端缓存克隆字段集”三处必须显式对齐并锁定测试；任何一侧新增字段都要同时核对另外两侧。
- “实时链路正常 + 刷新后异常”时第一时间怀疑读取投影与本地缓存克隆两层，而不是生成链路。
