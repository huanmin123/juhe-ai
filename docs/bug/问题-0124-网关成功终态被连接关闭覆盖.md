# BUG-0124 网关成功终态被连接关闭覆盖

## 基本信息

- 编号：BUG-0124
- 状态：已修复
- 严重程度：P2
- 发现时间：2026-07-23
- 模块：后端 / 网关 / 请求上下文 / 运行日志 / 前端日志搜索
- 关联 bug：BUG-0027
- 关联计划：PLAN-0166-20260723T233206838Z

## 问题概述

- 现象：上游协议终止成功、HTTP 状态为 `200`，但连接随后触发 `close` 时，timing summary 被写成 `aborted`；点号事件同时在日志搜索显示为“未映射运行事件”。
- 影响：成功请求被误判为中断，告警和耗时分析口径失真；阶段日志数量大时有效异常更难发现。

## 根因

- 请求上下文只使用 `res.writableEnded` 判断 `close`，不知道流式协议解析器已经确认成功终止。
- `close` 分支直接调度 `aborted` 汇总，可能早于流式收尾分支完成。
- 前端事件映射主要使用下划线事件名，未覆盖新增的点号事件契约。

## 修复方案

- 在请求上下文登记协议终态，成功终止后的 `close` 按成功汇总且不写提前关闭告警。
- 保持真正提前关闭仍为 `aborted`。
- 补齐点号事件精确映射与兜底前缀。
- 同步收敛逐阶段和 DB service 成功日志，避免同根因的运行日志刷屏复发。

## 验证记录

- 原始 logger 探针覆盖协议成功终态、协议失败终态和无协议终态三种 close：分别得到 `success`、`expected_failure`、`aborted`，前两种没有 `http_request_closed` 告警。
- 网关响应生命周期与 response inspection gateway E2E 回归通过。
- 隔离日志搜索页面按固定 trace 检索时显示“网关请求阶段”和“网关请求耗时汇总”，未出现“未映射运行事件”。
- 桌面与移动 Playwright 页面验证通过，无控制台 / 页面异常。

## 完成总结

- 完成时间：2026-07-24。
- 流式检查器把真实协议终态写入请求上下文；HTTP close 只在没有协议终态时代表客户端中断。
- timing summary 继续依靠单次写入门禁，finish / close 竞态不会产生重复汇总。
