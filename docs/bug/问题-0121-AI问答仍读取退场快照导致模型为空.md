# BUG-0121 AI 问答仍读取退场快照导致模型为空

## 基本信息

- 编号：BUG-0121
- 状态：已修复
- 严重程度：P1
- 发现时间：2026-07-23
- 发现方式：用户反馈与源码链路核对
- 模块：AI 问答 / API Key / 动态模型目录 / 前后端
- 关联 bug：BUG-0118、BUG-0115
- 关联计划：PLAN-20260723T042256730Z

## 问题概述

- 现象：新建 AI 问答会话后模型选择器没有文字，展开下拉仍为空。
- 期望：模型列表按会话 API Key 路由策略绑定的供应商合集动态生成，并默认选择第一项。
- 实际：Chat 路由仍读取 `chat_list:*` / `chat_model:*` 发布快照；当前对外模型目录已经改为动态聚合后，该旧链路可以稳定返回空数组。

## 根因分析

- BUG-0118 曾通过数据库约束和重建恢复旧聊天快照，但没有迁移 AI 问答的事实来源。
- PLAN-0152 已将认证 `/v1/models` 改为按 API Key 的全部 active 路由绑定动态聚合供应商目录；Chat 模块没有同步迁移。
- 新会话前端只使用创建响应中的 `defaultModel`，模型列表又按展开懒加载。后端默认模型和列表同时为空时，选择器只剩箭头。
- Chat 创建入口还通过“默认 GPT API Key”猜测内置客户端 Key，与用户需要的独立可配置 AI 对话 Key 不一致。

## 修复方案

- 新增每用户唯一的 AI 对话专用 Key 身份，默认绑定 GPT 路由但允许后续换路由。
- 模型列表复用 `listClientModelCatalogAsync(systemAccountId, providerCodes)`；能力详情从相同当前供应商目录聚合。
- 新会话持久化和返回动态列表第一项，后续恢复 `lastModel`。
- 增加后端、前端和迁移回归，防止再次引入发布快照读取。

## 验证记录

- Node/Go 类型检查、构建、动态模型目录契约、专用 Key 管理和前端模型懒加载回归均通过；Browser 插件当前不可用，真实登录态交互待环境补验。

## 下次遇到

- 同时对比 Chat 模型接口与认证 `/v1/models` 的事实来源，不要只检查快照表是否有数据。
- 默认值为空和下拉为空同时出现时，先检查创建接口与列表接口是否共享同一目录服务。
