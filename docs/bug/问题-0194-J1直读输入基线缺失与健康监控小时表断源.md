## 问题概述

- 现象：生产 AI 健康监控页恒为空（`juhe_stats.account_health_hourly` 0 行），而 J1 配置为启用（`accountHealthEnabled=true`，输入源 postgres）。
- 期望：健康探针按账户调度执行，小时条带有数据，页面可见。
- 实际：两层断裂（见根因）。
- 影响范围：AI 健康监控读面（`/my-stats/ai-health`、`ai-health/hour-detail`，只读 `account_health_hourly`，见 `statreads/aihealth.go`）。

## 根因分析

### 第一层：直读候选 INNER JOIN 输入版本表，基线无人播种（已修复）

`account_health_jobs_input_versions` 只在事件驱动路径被惰性创建（gateway 账户写入/授权扇出 `authz/downstream.go`、`accounts/write.go`；jobs OAuth 刷新扇出 `oauthrefresh/healthfanout.go`）。而 J1 直读候选 SQL 对该表做 **INNER JOIN**（`direct_input_reader.go:420`、`direct_input_reader_sqlite.go:740`）。全新部署或整库迁移的账户从不经过事件路径 → 表恒空 → 候选恒空 → J1 无探针可发（outcomes/outbox/current_state 全 0；1099 个账户 `next_health_check_at` 已到期仍不执行）。

**修复（2026-09-26 已上线）**：
- 生产应急：受控幂等回填 1517 行基线（`INSERT...SELECT...ON CONFLICT DO NOTHING`，镜像读取器静态白名单 provider_code×type×未删除；目标表 0 行无可备份内容）。回填后 J1 立即开转（outcomes 23:26 起持续增长，331→397+）。
- 治本：jobs 启动路径自动播种——`accounthealth.EnsurePostgresDirectInputBaseline`（PG 分支 CheckContract 后调用，fail-fast）+ `EnsureSQLiteDirectInputLayout` 尾部补 SQLite 侧播种（`direct_input_baseline.go`，两方言共用核心；基线版本=1 与事件首尝预留一致，幂等不覆盖既有行）。部署后启动日志 `J1 直读输入基线播种完成 seeded=0` 验证幂等。

### 第二层：account_health_hourly 的聚合源在 go-only 形态不存在（待实施）

PG statsagg 对该表的聚合只吃 `traffic_source='account_health_check'` 的使用记录（`statsagg/aggregate.go:683` addPostgresAggregatedAccountHealthEntry）。但 Go 三项目形态下 J1 探针是 **jobs 直连上游执行**（`accounthealth/probe.go` ProbeOpenAI：解密凭据 + 账户 BaseURL 直发，不经网关、不产生任何使用记录）。Node 单体时代探针在同进程内会写 `account_health_check` 使用记录，迁移后这段副作用丢失 → 即使探针全部正常，`account_health_hourly` 仍恒空。

## 修复方案（第二层，已实施）

读模型回归 J1 真相：由 J1 outcome 投影器在 drain 每个 outcome 时，把探针观测按 `(account_id, stat_hour)` upsert 进 `account_health_hourly`（2026-09-26 已实施上线）。

- `accounthealth/hourly_strip.go`：`AccountHealthHourlySink` 写入窄口 + `recordAccountHealthHourlyObservation`（outcome→观测转换：`complete_success`→success，其余→failure，`stale` 跳过；provider_code/system_account_id 由业务库按 account 补齐，账户已删除跳过）。
- `cmd/worker_health_hourly.go`：组合根双模 stats 句柄适配器（pgpool/openSQLite 与 businessDB 同约定；stat_hour 用 `LoadUsageStatsLocation` 统计时区，与读面 aihealth.go 同口径；newest-wins upsert，last_observed_at 统一毫秒 UTC 文本使文本比较即时间序）。
- `worker_health_projection.go`：装配接线（stats 家族缺席时 Hourly 为 nil，条带跳过并 warn，主投影职责不受影响）。
- 写失败按 warn 继续（条带为派生数据，由同账户下一轮观测自愈），不阻塞 current_state 投影与游标推进。
- 备选方案 B（Node 全对齐，暂不采用）：jobs 侧给探针流量补记使用记录（复用 usagewriter）。影响统计口径（探针流量计入 usage_records 及全部下游统计），需要单独契约决策。
