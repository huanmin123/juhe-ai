# BUG-0210：AI 问答内置工具能力静态兜底缺失——chat 面目录链未移植 toBuiltInCatalogItem，工具与模态恒空

- 编号：BUG-0210
- 状态：已修复（待发布）
- 发现：2026-09-28，用户反馈 AI 问答中 GPT 系模型被问实时信息时明确回答“无法联网查询”；抓包确认发往上游的请求无 `tools` 字段

## 现象

- GPT 等内置模型提问实时信息无法查询：回答直说不能访问网络，请求体无 `tools` 字段（web_search 永不注入）。
- 会话工具能力面板仅含 `web_search` 与 `generate_image` 两项且恒“不可用”；`diagnostic_echo` 不在面板——它是 dev/test 开关下经 function_calling 门控的内部注入工具，此前因 `function_calling` 恒空而永不注入。
- 图片输入被拒：`inputModalities` 恒空，前端按“仅凭 Responses 协议可用不能推导图片能力”的契约拒绝图片输入。
- 协议偏好退化：需要搜索的模型不再偏好 Responses 协议。

## 根因

数据源缺失，属 Node→Go 迁移遗漏：

- 数据库 `provider_model_catalog` 表本无 `supported_tools` / `input_modalities` / `output_modalities` 列。Node 时代目录读取链 `toBuiltInCatalogItem` 用“本地官方能力快照”（静态定价表）兜底填充这三个字段——文档既有契约（AI问答设计 8.5“上游可用模型 ID 与本地官方能力快照”）一直按此口径描述。
- Go 迁移时该兜底只接到了管理面：`internal/providers/catalog.go` 的 `ApplyBuiltInStaticDerivedFields`。chat 面目录读取链（`chain_catalog.go` `ListProviderModelCatalog` → runtimecache 目录缓存 → chat 模型选项与工具能力解析）未移植，`SupportedTools` 与输入/输出模态恒空。
- 管理面可对照：管理面目录同一模型的工具/模态字段有值、chat 面恒空——两侧不一致指向数据源缺口，而非上游能力变化。
- 8.6 的注入判定规则本身没有问题：“只有模型目录明确声明 web_search 且最终走 Responses 才注入”照常工作，只是“目录声明”因数据源缺失恒为空。

## 修复

- chat 面目录读取链补同一份静态兜底，与管理面 `ApplyBuiltInStaticDerivedFields` 同源（静态定价表的 `supported_tools` / `input_modalities` / `output_modalities`）；行为对齐文档既有契约（“本地官方能力快照”），注入判定规则不变，同名多候选取保守交集的规则不变。
- 补真实数据链回归测试：锁定 chat 面目录行经兜底后 GPT 系模型 `SupportedTools` 与模态非空，而不是 mock 直接塞能力数据。

## 影响面

- `internal/gatewaypreauth/preflighthelpers.go` 的 `accountModelsTargetImage` 车道判定消费共享目录行的 OutputModalities，修复后静态含 image 输出模态的内置模型在 DB 行未表态时可能被判入 image 车道（与 Node 行为对齐、只放宽 OR 门，属修复的正确传导）。

## 验收

- 真实数据链回归测试通过：chat 面目录读取内置 GPT 模型后工具/模态字段非空；同名多候选保守交集与空白目录行为不回归。
- AI 问答工具能力面板对 GPT 系模型恢复真实可用性展示；Responses 渠道命中目录声明时请求携带 `tools`（web_search 注入恢复）。
- 管理面目录行为不变（同源兜底，无双重叠加）。

## 教训

- 迁移“读取链派生字段”必须按链路逐条清点，不能只对齐一处调用面；同一兜底在管理面已移植时，“两侧同模型字段不一致”是最快的定位信号。
- Mock 直接塞能力数据的既有用例掩盖了数据源缺失：mock 绕过了“真实目录行 → 派生链”，测试全绿而生产行为恒空。能力类用例必须至少保留一条走真实数据源（真实目录行 SQL / 真实兜底链）的回归。

## 状态

已修复（chat 面补同源静态兜底 + 真实数据链回归测试），待发布。

## 发布注意

- 生产 cacheDriver 为 redis 时，共享目录缓存键 `gateway:provider-model-catalog` TTL 24h 且发布重启不清缓存；发布后需清理该键（或触发一次任意目录保存）让修复立即生效，否则最长 24h 内旧无能力条目继续命中、修复看似无效。
