# BUG-0115 AI 问答模型列表重复扫描账户

## 基本信息

- 编号：BUG-0115
- 状态：已修复，待生产验证
- 严重程度：P1
- 发现时间：2026-07-17
- 发现方式：用户反馈与生产耗时采样
- 模块：前后端 / AI 问答 / 模型目录 / API Key / 性能
- 关联计划：PLAN-0101
- 关联 bug：无

## 问题概述

- 现象：创建或切换会话时模型列表可能需要数百毫秒到十余秒，账户增加后冷请求持续变重。
- 期望：模型下拉只读取 API Key 路由供应商和已有模型目录缓存，不随账户数增长；新建会话无需重复选择 API Key。
- 实际：原实现先内部请求 `/v1/models`，随后再次校验 Key、加载每个分组的账户快照并逐模型判断协议能力；前端每次切换会话都会触发加载。
- 影响范围：AI 问答新建、页面首次进入、会话切换和模型下拉。

## 根因分析

- 表象：虽然已有 5 秒模型结果缓存，但缓存过期后仍出现明显延迟。
- 真实根因：缓存只减少短窗口重复请求，没有移除内部网关预检和账户 hydration；生产 Redis 模式下账户快照没有跨进程共享命中，冷路径仍经过 DB service。
- 为什么会发生：模型列表把“稳定目录能力”和“账户实时可调度性”混在同一读取链路，且前端把会话选择等同于模型配置刷新。

## 修复方案

- 后端通过绑定 Key 的共享网关快照取得有效 `provider_code` 合集，使用共享供应商模型目录直接构建 `ChatModelOption`。
- 模型列表删除内部 `/v1/models` 和账户快照读取；账户状态、模型限制与协议能力继续在真实发送阶段校验。
- 会话创建允许省略 `apiKeyId`，服务端精确绑定当前用户默认 GPT API Key；前端删除 Key 选择弹窗与 Key 列表预取。
- 前端按 API Key 缓存模型列表，切换会话复用快照；新建会话刷新一次，下拉展开只在缓存过期时刷新。
- 无数据库字段变化，无需重建业务库、非业务库或 Redis。
