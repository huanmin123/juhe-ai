- 模块：网关（审计日志 F3 / gatewayusage 捕获装配）

## 问题概述

- 现象：生产审计日志详情只有请求元数据，请求体/响应体内容恒显示未抓取（`hash_only`/`summary_only`）。
- 期望：审计日志开启即捕获请求/响应正文（单一开关语义），详情页可查内容。
- 实际：元数据全量落库（refs 599），正文 blob 仅 28（失败面/早期零星），成功请求正文永不捕获。
- 影响范围：审计日志读面全部 payload 详情；审计核查能力形同虚设。

## 根因分析

- 真实根因：**生产设置适配器装配缺失**。`chain_ports.go` 的 `auditSettingsSourceAdapter.ReadAuditLogSettings()` 构造 `gatewayusage.AuditLogSettings` 时从不赋值 `FullBodyCaptureEnabled`（恒 false），而 `gatewayusage/audit_capture.go:318` 以 `settings.FullBodyCaptureEnabled && !metadataOnly` 决定 `capturePayloadBodies`——审计主开关（2026-09-21 起恒 true，开关已移除）永远无法传导到正文捕获。字段、消费点、blob 存储与 GC 面全部就绪，唯独生产适配器这一处装配缺失（与 BUG-0193/0194/0195 同族：消费面齐全、生产者/装配缺失）。
- 伴随口径：成功请求正文有分层保留设计（`successHotRetentionHours=1` 热窗口后按 `successSampleRate` 稳定采样长期保留，默认 0.1；失败/问题请求恒全量保留 7 天）——即使修复装配，默认配置下成功正文 1 小时后仅 10% 长期可见。

## 修复方案

- `chain_ports.go`：适配器 `FullBodyCaptureEnabled: enabled`——审计主开关与正文捕获一致（单一开关语义，独立开关不存在）；关闭态两者同关。成功流量的分层保留仍由 `SuccessSampleRate` / `SuccessHotRetentionHours` 承载。
- 生产实例配置：`JUHE_AI_AUDIT_LOG_SUCCESS_SAMPLE_RATE=1`（成功正文 100% 长期保留，1 小时热窗口退化为纯延迟；失败面本就全量）。采样率属实例口径选择，代码默认 0.1 保持设计文档（`docs/functions/原始审计日志设计.md`）不变。
- w1 端口臂测试补 FullBodyCaptureEnabled 跟随断言（开/关两臂）。
