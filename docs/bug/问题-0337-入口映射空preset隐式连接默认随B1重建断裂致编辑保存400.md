# BUG-0337 入口映射空 preset 隐式连接默认随 B1 重建断裂致编辑账户保存 400

## 基本信息

- 编号：BUG-0337
- 状态：已修复待发布（2026-10-24）
- 严重程度：P1
- 发现时间：2026-10-24 01:33（生产）
- 发现方式：用户按待办 T51 完成判定做生产实机验证（编辑账户扩支持模型 + 新增模型别名）时报「请求参数无效」
- 模块：后端 / 管理面 / 账户入口映射
- 关联：B1 断点批（连接 preset 化，2026-10-22 结构重建）、BUG-0335（同账户编辑保存的另一处缺陷，已修复）

## 现象

生产编辑 AI 账户（acc_c339f2160fa88c75，DeepSeek Chat API Key）：扩支持模型
`deepseek-v4.1-flash-1017` 并新增映射 `deepseek-v4.1-flash → deepseek-v4.1-flash-1017`，
保存返回 400 `{"message":"请求参数无效"}`，三次重试均复现（01:33:29 / 01:33:50 / 01:34:43）。
前端 toast 无归因信息。

## 根因

两层叠加：

1. **空 preset 隐式默认断裂（主因）**：常规账户面的映射载荷从不携带
   `targetConnectionPresetCode`（前端 `normalizeAccountModelMappings` 不构造该字段，
   编辑对话框无连接选择器；后端 `normalizeModelMappingBody` 接受该字段但收不到）。
   B1 断点批前全部 `account_connections.connection_preset_code` 为空串，空 preset 在
   `resolveEntryConnectionID` 按 `connection_preset_code = ''` 恰好隐式命中账户唯一
   legacy 连接；B1 后连接行都携带真实 preset code（本例 `deepseek_openai_v1`），空
   preset 恒 0 行 → `ValidationError{"mapping_target_unsupported: connection preset
   \"\" resolves to no enabled account connection"}`。2026-10-22 结构重建的 280 条
   存量映射全部由导入链写入（连接显式解析），UI 建映射自此从未成功，本次首次撞上。
2. **localize 吞掉归因（放大器）**：kernel localize 对非中文 400 文案统一改写为
   「请求参数无效」（Node parity 契约），英文 ValidationError 原文从响应侧不可见，
   用户与排障都无法直接定位。

## 修复

`resolveEntryConnectionID`（entry_mappings.go）空 preset 回退：查询账户全部启用连接——
恰一条 → 隐式命中（恢复 B1 前单连接隐式默认 UX）；零条 → 中文 400
「账户没有启用的上游连接」；多条 → 中文 400 列出全部候选 preset
（中文文案过 localize 不被改写，用户/排障可归因）。显式 preset 两臂逐字节不变。
2026-10-24 生产实测全库 0 个多启用连接账户，单连接回退覆盖全部现状；
`createPayload` 自带的健康检查连接是常规创建链的唯一连接，映射落库回退命中。

## 验证

- 新增回归 `bug0337_entry_mapping_connection_default_test.go` 四例：单连接回退落库
  （target_connection_id 命中）、多连接中文 400 列候选、显式 preset 两臂逐字节不变、
  零连接中文 400。
- `TestCreateWiresModelMappingCatalogAssertion` 第三子例按新契约改为正向断言
  （wiring create 的唯一启用连接下空 preset 映射回退落库健康检查连接）。
- `go test ./internal/accounts/ -count=1` 全包绿（46.7s）；`go vet` 绿。

## 预防与观察

- 前端对多连接账户的映射连接选择器（显式 `targetConnectionPresetCode`）不在本批：
  现状无多连接账户，后端中文错误已可归因；待多连接候选展开（待办 B4③）立项时同批。
- 后续排查同类「请求参数无效」时，先查 localize 改写前的原文：管理面 400 产生点
  的英文文案都会被吞，优先在 store 层断言或日志取证。
