## 问题概述

- 现象：系统指标统计页"进程状态"卡 jobs 段恒显示红色"不可达"。
- 期望：透出 jobs /health 真实载荷（ownerMode、各项 ready）。
- 实际：gateway statreads 的 health-snapshot 路由按 `JUHE_AI_JOBS_HEALTH_LISTEN_ADDRESS` 派生抓取 URL；生产 gateway 容器该 env 未配置 → URL 空 → jobs 段降级 `available:false`（前端渲染"不可达"）。且 jobs 健康监听校验强制 loopback（`0.0.0.0` 启动即失败），容器部署下即使配置也无法跨容器抓取——双重装配缺口。

## 根因分析

1. daa90d10d（2026-09-27 23:19 发布）上线系统指标页时，compose 未补 gateway 侧抓取地址配置——功能与部署配置脱节（与 BUG-0193 容器 WORKDIR 同类"上线漏配置"形态）。
2. jobs 的 `validateLoopbackListenAddress` 强制 loopback，与容器化跨容器抓取的需求冲突；该约束在单进程/裸跑形态下合理，容器形态下过严。
3. 处置过程中的事故留痕：首次修复直接配 `0.0.0.0:3305` 使 jobs 进入重启循环（旧校验拒绝），已立即回滚恢复，再走代码修复路径——配置变更前先核对接收端约束的教训。

## 修复方案

- 代码（jobs `main.go`）：`validateHealthListenAddress` 放宽——格式校验保留，host 允许空/`0.0.0.0`/`[::]`/任意 IP（默认值仍 `127.0.0.1`）；主机名字符串仍拒绝。安全边界：compose 无 ports 映射，健康端口仅容器网络可达，不构成公网暴露。
- 配置（`docker/single-server/compose.yml`，同一变量两容器不同值）：gateway `JUHE_AI_JOBS_HEALTH_LISTEN_ADDRESS=juhe-ai-go-jobs:3305`（容器名视角）；jobs `0.0.0.0:3305`（全接口监听）。
- 发布：`deploy.sh jobs`（17:45）+ compose up gateway。
