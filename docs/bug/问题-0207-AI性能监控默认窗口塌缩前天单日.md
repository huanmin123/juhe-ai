# BUG-0207：AI 性能监控默认日期窗口塌缩为前天单日

- 编号：BUG-0207
- 状态：已修复（2026-09-28 07:14 已发布生产，gateway `7b6d6af5`，提交 `907d01a09`）
- 发现：2026-09-28，用户报告「AI 性能监控点击重置，日期强制跑到了 26 号」（操作当天 2026-09-28，重置后显示 `2026-09-26 → 2026-09-26`）
- 影响面：`/api/{my-stats,stats}/ai-performance` 与 `/ai-performance/series`（gateway statreads 族）无 `startDate`/`endDate` 参数时的默认窗口

## 现象

- AI 性能监控页**不携带日期参数**请求基础数据（首次进入页面或点击「重置」都会触发），响应 `range` 恒为 `[today-2, today-2]` 单日（`days: 1`），而非设计上的默认 3 天窗口 `[today-2, today]`。
- 前端 `syncDateRangeFromResponse` 会把选择器同步到该塌缩区间，用户在 28 日看到的就是 `2026-09-26 → 2026-09-26`：起点"跳回 26 号"且终点不是今天。
- 手动选择日期（显式携带参数）不受影响。

## 根因

`backend-go/projects/gateway/internal/statreads/usageoverview.go` 的 `normalizeStatsDateRange` 把 Node 原版回退链错译为顺序传染：

Node 权威实现（migration-backup `stats.routes.ts:1187-1197`）：

```ts
const startDate = input.startDate ?? input.endDate ?? defaultRange.startDate // today-2
const endDate   = input.endDate   ?? input.startDate ?? defaultRange.endDate // today
```

回退链只引用**原始入参**，全空时 endDate 落到 `defaultRange.endDate`（今天）。

Go 版实现（缺陷形态）：

```go
if startDate == "" { startDate = endDate }
if startDate == "" { startDate = defaultStart }
if endDate == ""   { endDate = startDate }   // 全空场景：被已填充的 startDate=today-2 传染
if endDate == ""   { endDate = defaultEnd }  // 死代码
```

全空请求时 `endDate` 先被已填充的 `startDate`（`today-2`）占据，`defaultEnd`（今天）永远不可达，默认窗口塌缩为 `[today-2, today-2]`。

同文件另两个同形函数不受影响（行为与 Node 等价）：

- `normalizeSystemMetricsDateRange`：`defaultStart == defaultEnd == today`，传染后仍为 `[today, today]`；
- `normalizeUsageOverviewDateRange`：全空走 `fixedUsageStatsDefaultRange` 早退分支，半参数回退与 Node 一致。

## 复现与取证

- 本地隔离环境（gateway 8181 SQLite 零配置 + vite 5177）真实浏览器复现：首次进入 AI 性能监控页即显示 `2026-09-26 → 2026-09-26`（当天 2026-09-28），页面内 `credentials:'omit'` 直调 `/api/my-stats/ai-performance` 返回 `range={startDate:"2026-09-26", endDate:"2026-09-26", days:1}`，同会话 `/api/my-stats/usage-window` 返回 `endDate:"2026-09-28"`（元数据链路正确，排除时区配置因素）。
- 生产日志（2026-09-28 06:45-06:47，用户操作时段）核对：存在多条无参数 `ai-performance` 请求，以及用户手动纠正的显式 `startDate=2026-09-26&endDate=2026-09-28` 请求，与"重置→看到塌缩区间→手动选 26→28 纠正"的行为链吻合。

## 修复

对齐 Node 回退链语义：回退只引用原始入参，互不传染。

- 全空：`[defaultStart, defaultEnd]` = `[today-2, today]`（3 天默认窗口，与前端 `DEFAULT_RANGE_DAYS=3` 口径一致）；
- 只传 `startDate`：`[startDate, startDate]` 单日（保持原行为）；
- 只传 `endDate`：`[endDate, endDate]` 单日（保持原行为）。

同时修正函数头注释：默认窗口是 `today-2..today`（3 天），非 "yesterday..today"。

## 验收

- `TestW11GDateRangeDefaultArms` 补全空分支断言：`normalizeStatsDateRange(ctx, "", "")` 必须（fixture now=2026-09-04 UTC）返回 `StartDate=2026-09-02, EndDate=2026-09-04`；既有半参数断言保持不变（锁定原契约）。
- 2026-09-28 07:14 已发布生产（gateway `7b6d6af5`，md5 三点闭环 + healthy + 公网 200 + ensure-schema 幂等 + 新容器 ERROR=0）。修复行为在本机同构建隔离环境三重验证：无参数 API 返回 `[today-2, today] days=3`、页面首载与点击重置后选择器显示 `2026-09-26 → 2026-09-28`（修复前同环境首载即 `26→26`）。
