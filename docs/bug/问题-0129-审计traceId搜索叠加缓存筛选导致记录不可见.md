# BUG-0129 审计 traceId 搜索叠加缓存筛选导致记录不可见

## 基本信息

- 编号：BUG-0129
- 状态：已修复（待完整隔离预演）
- 严重程度：P1
- 发现时间：2026-07-27
- 发现方式：用户反馈并以真实 traceId 核对生产审计记录
- 模块：前端 / 审计日志 / 筛选状态缓存
- 关联计划：PLAN-20260726T172021035Z

## 问题概述

- 现象：管理员确认审计记录真实存在，但在审计列表手工输入 traceId 后无法找到。
- 根因：页面会恢复上次缓存的用户、AI 账户、结果、路径、状态码和来源筛选；手工 traceId 与这些条件一起下发并由后端按 `AND` 查询。只要任一旧条件不匹配，目标记录就不可见。
- 边界：后端 traceId 查询和管理员跨用户权限正常；最近内容搜索只覆盖最近一小时，不是持久 trace 定位入口；进行中的请求要等 HTTP `finish/close` 后才会异步进入审计队列。

## 修复方案

- 审计列表的主搜索框将非空 traceId 定义为直接定位键，只下发 traceId 和分页参数。
- 点击搜索时同步清空界面中的高级筛选及其选中项，避免显示状态与实际请求不一致。
- 后端继续保留 traceId 与其他字段组合查询能力，不改变管理 API 契约。

## 验证记录

- 筛选回归覆盖缓存用户、AI 账户、结果、路径、状态码和来源后再输入 traceId，确认请求只携带 traceId。
- 完整隔离预演必须通过真实管理页面确认目标 trace 可见，并确认审计与运行日志索引开关均为启用状态。

## 完成总结

- 完成时间：待完整隔离预演后填写。
- 结论：代码层已消除缓存高级筛选遮蔽 traceId 的路径，生产切换仍受完整本地预演门禁约束。
