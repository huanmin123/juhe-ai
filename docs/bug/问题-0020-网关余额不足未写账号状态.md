# BUG-0020 网关上游错误未写账号状态

- 发现方式：用户反馈 / 现网排查
- 模块：后端 / 网关 / 账号错误策略 / worker
- 关联计划：无

- 责任人：待定

## 问题概述

- 现象：Mac 现网 `huanmin` 用户的 `suocode` AI 账户上游已经返回账户不可用类错误，但账户列表状态仍显示正常；直到管理员手动测试后才变成临时不可调用。
- 期望：真实网关请求只要已经命中上游账号并发生上游错误，就写当前命中的账号状态，并保留真实上游错误摘要供排障；后续账号成功只能救回本次请求，不能掩盖前序账号失败。
- 实际：旧实现里真实 `gateway` 非 `2xx` 和请求异常主要只做本地短 TTL 屏蔽和切号，默认不写持久账号状态；手动账号测试有额外兜底，所以手动测试后状态才变化。
- 影响范围：真实网关流量中未配置账号错误规则的上游失败账号；非 `2xx` 响应、请求异常、非流式正文中断和流式失败都可能让账户页状态滞后。

## 复现步骤

1. 创建未配置 `credentials.error_handling_rules` 的 OpenAI API Key 账户，并绑定到分组和 API Key。
2. 让上游对真实网关请求返回任意非 `2xx` 或请求异常。
3. 旧实现返回网关统一兜底错误，但账户仍保持 `active`。
4. 手动测试同一账户后，账户才被写入 `temporary_unavailable`。

## 环境信息

- 分支 / 版本：Mac 现网 release `20260603-105949`
- 数据状态：`suocode` 账户 `acc_1780364282687_e0afd552` 在真实 `gateway` 使用记录中已有多次上游失败；质量缓存已有上游错误摘要。
- 系统：macOS 服务，server / db-service / worker 三进程运行
- 是否稳定复现：是

## 根因分析

- 表象：真实请求已经看到上游账号错误，但账户持久状态没有变化。
- 真实根因：
  - `handleFailedUpstreamResponse` 旧路径没有把所有真实 `gateway` 上游失败统一接入账号错误写入。
  - 请求异常、非流式已输出后正文中断和流式失败仍存在只做运行态避让或阈值处理的路径。
  - 后台冷却复测还暴露出 worker 角色误走 server 专用 DB service IPC 的问题，失败摘要出现 `worker 角色不能本地执行 DB service 操作：read_gateway_settings`。
- 为什么会发生：此前为了避免状态码白名单误伤，把未知上游失败降级为本地屏蔽，但这让账户页和恢复通道无法得到真实账号失败事实；同时部分网关异步读路径没有区分 server 与 worker 的运行边界。

## 修复方案

- 修改点：
  - 真实 `gateway` 和 `manual_account_test` 的非冷却复测流量都执行账号错误写入；`cooldown_retest` 仍由复测任务自身负责状态写回。
  - 非 `2xx` 响应、上游请求异常、非流式已输出后正文中断和流式失败都写当前命中账号状态；未命中显式账号规则时默认写 `temporary_unavailable`。
  - 不按状态码、错误码或错误文案写代码内置判断；状态码和上游错误体只作为诊断摘要、审计字段和用户显式账号规则输入。
  - worker / db-service 角色读取网关设置、分组访问元数据、账号候选和额度检查时走本地 SQLite 允许路径；server 仍使用 DB service 或 worker 推送的被动快照。
  - 冷却复测成功后由 worker 显式清理账户失败状态，避免通过网关请求副作用队列误走 server IPC。
  - 补充回归测试和功能文档，固定“命中上游账号后的错误都写当前账号状态”的边界。
- 行为影响：真实网关流量只要命中上游账号并发生上游错误，就把当前命中账户写成临时不可调用；后续账号成功只救回本次请求，不清除前序账号的本次失败状态。
- 发布异常处理：如果出现误伤，应先确认是否真实命中了上游账号、是否客户端取消或本地错误；不要回退到状态码、错误码或错误文案硬编码判断。

## 下次遇到

- 先查什么：账户 `usage_records` 中真实 `gateway` 来源的上游 `status_code/code/message`，再查 `accounts.last_error_*` 和操作日志是否只有手动测试写入。
- 重点看什么：真实网关上游失败是否调用账号错误写入；客户端取消、本地 JSON 错误、API Key / 授权 / 额度失败这类未命中上游账号的路径不应写账号状态。
- 如何避免误判：不要用状态码、错误码或错误文案硬编码判断账号状态；只看是否真实命中上游账号后发生错误，以及用户是否显式配置了账号规则。

## 完成总结

- 完成时间：2026-06-03
- 结论：真实网关上游错误已统一写入当前命中账号状态；worker 冷却复测不再因 DB service IPC 边界失败。
- 后续建议：新增账号规则时只能走用户显式配置或通用上游失败链路，不要恢复状态码、错误码或错误文案白名单。
