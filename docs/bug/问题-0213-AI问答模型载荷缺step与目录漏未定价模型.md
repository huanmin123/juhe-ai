# BUG-0213：AI 问答模型能力载荷缺 step 与 chat 面目录漏未定价模型

- 编号：BUG-0213
- 状态：已上线（随 09-28 16:00 发布；批次1 已收官）
- 发现：2026-09-28，批次1 复审：生成参数滑块步长退化；生产 5 个未定价模型从 chat 模型列表消失

## 现象

- 生成参数弹窗滑块步长退化：`generationParameters` 载荷未透出 `step`，前端滑块无法按模型真实步长调整，只能退化为自行猜测的步长。
- 生产 5 个未定价模型从 chat 模型列表消失：chat 面模型目录聚合未携带 `IncludeUnpriced`，静态定价表没有定价记录的模型被过滤，用户无法选中发送。

## 根因

- `generationParameters` 载荷构造遗漏 `step` 字段；`step` 与 min/max 是同级契约字段，不是可选项，缺失即造成前端滑块行为退化。
- Go 迁移后 chat 面目录聚合默认只返回已定价模型；Node 语义 `includeUnpriced: true`（chat 面与计费解耦）未随迁移传给目录服务，未定价模型被静默过滤。

## 修复

- `generationParameters` 透出 `step`（数值参数载荷统一携带），前端滑块按载荷步长渲染。
- chat 面目录聚合请求携带 `IncludeUnpriced: true`，对齐 Node `includeUnpriced` 语义；未定价模型回到 chat 模型列表，计费事实仍由网关使用记录链路维护，chat 面与计费解耦。

## 验收

- 参数弹窗滑块按模型能力载荷的 `step` 移动，不再出现步长退化。
- 生产未定价模型（5 个）在 chat 模型列表恢复可见、可选中发送。

## 教训

- 能力载荷字段清单要以文档契约为准逐项核对：`step` 与范围（min/max）同级，迁移或新增数值参数时最容易漏的是“元数据字段”而不是参数本身。
- “chat 面与计费解耦”这类反直觉的默认参数（`includeUnpriced`）最容易在迁移中丢失；跨端目录过滤口径差异必须在迁移时显式裁决并写入契约。
