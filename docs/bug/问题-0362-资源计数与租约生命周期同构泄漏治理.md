# BUG-0362：资源计数/租约生命周期同构泄漏治理（在途额度、realtime 连接、key-model capacity、账户锁预约）

- 级别：P1（在途额度/realtime 连接残留会直接造成 429；同根因批量治理）
- 状态：已修复并随 v2026.11.13-3 上线（2026-11-13 01:50，commit 5ec5af739，gateway+jobs 同批）；观察期至 2026-11-20
- 登记：docs/待办与阻塞事项.md #T207（剩余不同族风险的独立跟踪）

## 背景

BUG-0361（账户并发槽）根治后，对 gateway/jobs 全部 Redis 运行态资源做同构扫描。判据：计数器/占位 + 调用方释放 + 异常路径永久偏高 + 兜底 TTL 被续期 + 无对账。确认 2 个「高」同构缺陷与 2 个计数漂移/预留未归还项：

1. **H1 API Key/授权在途额度预留**（`internal/gatewayquota`）：HASH 以 scopeToken 为字段累计成本、ZSET 以 scopeToken 为成员记到期；同 scope 任意新预留都把该 scope 分数重写为 now+30m，单个泄漏预留被同 scope 流量永久续命；release 按聚合成本相减（重复/迟到释放会多减），单次 3s 失败只打日志；65s 延迟释放与 30m 兜底都是进程内定时器，发布/崩溃即丢。生产 4 个 API Key 启用了额度，残留会直接导致 429。
2. **H2 realtime 每 API Key 连接计数**（`cmd/juhe-ai-gateway/chain_realtime*.go`）：STRING `INCR`/`DECR` + 10m TTL，任一存活连接每 20s ping 都 `PEXPIRE` 整键；某会话 DECR 丢失后，其他连接的 ping 会永久续住残留，最终让新 WS 连接稳定 429。
3. **M1 key-model capacity 计数漂移**（gateway `key_model_runtime/redis.go`、jobs `keymodelrecovery/redis_store.go`）：recordFailure 在 state 已存在（含 CLOSED 复用同一 key）时仍 `INCR`；cleanClosed 在 state 被外部删除时只 `ZREM` 不 `DECR` → 容量计数只增不减。
4. **L1 账户锁重试预约**（`gatewaydispatch/upstreamdispatch.go`）：等待被中止（aborted）出口直接返回，未归还 `AcquireRetryLeaseAsync` 预约的 60s 租约，该账户下一次失败重试被延后约 1 分钟。

## 修复

- **H1**：每次 reserve 生成唯一 `reservationToken`；每个 scope 的 ZSET 成员为 `<scopeToken>|<reservationToken>`（score=本预留自己的到期），entries HASH 记录成员→成本，scope 聚合 HASH 只用于限额判定。reserve 只新增自己的成员，不再续期同 scope 其他预留；release 按成员存在性精确扣减（重复/迟到释放 no-op）；过期清理逐成员扣减；release 失败按 0/250ms/1s 退避重试 3 次。旧数据兼容：裸 scopeToken 成员按 legacy 整 scope 归零清理。
- **H2**：每连接生成 `sessionToken`，ZSET `:slots` member=token、score=租约到期；acquire=清理过期 + ZCARD 判定 + ZADD；release=幂等 ZREM；refresh 只续自己的 token 且过期不复活。计数=ZCARD，残留不再被其他连接 ping 续命。
- **M1**：recordFailure 仅在新 state（raw 不存在）时 `INCR`；cleanClosed 对 state 缺失的成员同样 `DECR` 并夹 0（gateway 与 jobs 两份脚本同改）。
- **L1（复核后不成立，未改代码）**：生产实现下 `accountLockWaitAborted` 出口的 `lockLease.Allowed=false` 且 `LeaseID` 恒为空（预约写失败/已有租约），无预约可归还；真正持有预约的 aborted/wall 分支在第二个 wait 块（`upstreamdispatch.go:878-890`）已有 `abandonActiveAccountLockReservation`。新增调用已回退，避免留下 no-op 的虚假修复。
