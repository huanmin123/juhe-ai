## 问题概述

- 现象：Go 的账户标签替换会递增 `config_revision`，但不刷新账户 `updated_at`。
- 期望：标签属于账户配置；标签替换应在同一事务、同一账户更新中同时推进 revision 和修改时间。
- 实际：标签已经变化但账户仍保留旧修改时间，和 Node 当前行为不一致。
- 影响范围：已迁移的 `/accounts/{id}/tags` 与 `/my-accounts/{id}/tags`；依赖账户修改时间排序、展示或增量读取的链路可能得到旧值。

## 根因分析

- Go 标签写入迁移时只同步了用于缓存失效的 `config_revision`，遗漏了 Node 后续补充的账户修改时间语义。
- 标签关联表写入和账户 revision 更新位于同一事务，但账户更新语句没有设置 `updated_at = now()`。

## 修复方案

- 在标签替换事务中的账户 `UPDATE` 同时执行 `config_revision = config_revision + 1` 和 `updated_at = now()`。
- 不新增额外查询或运行时兼容分支，继续保持单条账户更新。
- 增加 SQL 契约测试，防止后续只保留 revision 而再次遗漏修改时间。
