# BUG-0264：题库未执行误报满分

- 状态：已修复（2026-10-02，待发布）
- 定性：Go 实现聚合语义缺陷——题库家族未执行任何作答题时，`resultSummary.customQuiz.score` 仍按初始化满分 31 展示
- 发现方式：代码取证（`modelcheckowner/custom_quiz.go` 聚合初值）+ 生产 run 数据盘点（约 106 条历史）

## 1. 现象

配置了题库（customQuestionIds）的检测 run，在题目全部不可用（解析后为空，家族产出单条 `quiz_questions_unavailable` skipped 项）或全部请求失败转 skipped 时，`result_summary_json.customQuiz` 仍显示 `score: 31`（满分）——未执行的题库环节被展示为满分通过。生产约 106 条历史 run 带该形态。

## 2. 根因

`modelcheckowner/custom_quiz.go` `buildCustomQuizSummary` 的聚合初值：

```go
aggregate := quizAggregate{Enabled: true, MaxScore: modelcheckprobe.QuizMaxPool, Score: modelcheckprobe.QuizMaxPool, ...}
```

初始化即 `Score=31`，循环内只对 failed 且参与扣分的项累加 `Deduction`，末尾统一 `Score = QuizMaxPool - Deduction`。当执行项为空（全部 skipped）时 `Deduction=0`，Score 维持初值 31。初值语义把"未扣分"与"满分通过"混同——没有区分"执行了且全对"与"根本没做"。

## 3. 修复

`modelcheckowner/custom_quiz.go`：

1. `quizAggregate` 增加 `Executed bool`（json tag `executed`）：存在任何实际执行（作答且拿到 pass/fail/invalid 判定）的题为 true；skipped（题目不可用、请求失败）与异常 verdict 不算执行。
2. 聚合初值不再预置 Score=31；有执行题时 `Score = 31 - Deduction`（下限 0，扣分口径不变），**未执行时 Score 固定为 0**；`MaxScore` 保持 31 作为展示分母。

前端可在 `executed=false` 时区分展示"未执行"与"满分"；`items[]`/`deduction` 契约不变。历史 run 的已落库 `result_summary_json` 不回填不伪造（沿用本包旧历史不回写惯例）。

## 4. 验证

- 单测（`qb_runtime_quiz_test.go`）：
  - `TestBuildCustomQuizSummary`：空题库 unavailable 单项 → `score=0, executed=false, maxScore=31`；全部请求失败转 skipped → 同前；有执行题 + skipped 混合 → `executed=true` 且扣分口径维持既有（31-16=15 等）；Deduction 超池（40 分题）clamp 到 0 且 executed=true。
  - `TestQBRuntimeRunsCustomQuizFamily`（端到端 durable 断言）：两题一 fail 一 pass → durable `customQuiz.score=15` 且 `executed=true`。
  - `TestQBRuntimeScheduledCarriesFrozenQuestions`：题目 id 全部失效 → durable `customQuiz.score=0` 且 `executed=false`。
- `go test ./internal/modelcheckowner/ -count=1` 全绿（60.0s，ok）。
- 未做前端展示验证（`executed` 字段的前端消费不在本次范围）。
