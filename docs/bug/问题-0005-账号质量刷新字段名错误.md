# BUG-0005 账号质量刷新字段名错误

## 基本信息

- 编号：BUG-0005

- 关联计划：无

## 问题概述

- 现象：macOS 部署后后台 worker 周期性输出 `background_account_quality_refresh_failed`。
- 期望：账号质量刷新任务能从 `account_quality_minute_stats` 汇总最近窗口数据，并写入 `account_quality_scores`。
- 实际：刷新任务查询了不存在的 `latest_error.error_message` 字段，SQLite 返回 `no such column: latest_error.error_message`。
- 影响范围：账号质量分、最近错误信息和基于质量分的调度参考可能无法及时刷新；主服务健康检查和普通请求不直接失败。

## 复现步骤

1. 准备包含账号和 `account_quality_minute_stats` 分钟桶样本的数据库。
2. 执行 `refreshAccountQualityFromUsage(10)`。
3. 修复前触发 `no such column: latest_error.error_message`。

## 环境信息

- 分支 / 版本：2026-05-13 macOS 发布包
- 数据状态：生产共享 SQLite 数据，存在账号质量分钟桶样本
- 系统 / Node 版本：macOS LaunchDaemon 运行环境
- 是否稳定复现：是

## 根因分析

- 表象：后台 worker 账号质量刷新任务失败。
- 真实根因：`account_quality_minute_stats` 的错误信息字段名是 `last_error_message`，刷新查询误写为 `error_message`。
- 为什么会发生：质量分钟桶表和通用错误统计表都有错误信息字段，但命名不同，缺少覆盖刷新聚合路径的回归脚本。

## 修复方案

- 修改点：`backend/src/storage/account-quality.repository.ts` 中最新错误子查询改为读取 `latest_error.last_error_message`。
- 回归保障：新增 `backend/src/scripts/regression/account-quality-refresh-regression.ts` 和 `pnpm --filter juhe-ai-backend test:account-quality-refresh`，覆盖分钟桶样本刷新到质量分表的路径。
- 兼容影响：只修正查询字段名，不改 schema，不迁移历史数据。
- 回滚方式：回滚本次代码发布；不涉及生产数据变更。
