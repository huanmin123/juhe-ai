## 问题概述

- 现象：生产「添加 AI 账户」表单中触发测试模型候选加载（选择/展开「测试」区模型下拉）时，接口返回 500「服务器内部错误」；编辑既有账户的人工测试模型选项同源受影响。
- 期望：草稿/已存账户的测试模型候选正常返回，当前选中模型置顶。
- 实际：`POST /__aisys__/api/my-accounts/test-draft-options` 等接口 500，gateway 日志报 `accounts test slice internal error — ERROR: column "model" does not exist (SQLSTATE 42703)`（2026-10-23 09:25–11:55 至少 12 次）。
- 影响范围：所有带 `selectedIds` 的测试模型候选请求——创建向导草稿测试（前端恒传当前/默认模型置顶）、已存账户 `GET /{id}/test-options`；不带 `selectedIds` 的调用不受影响。

## 复现步骤

1. 生产管理端打开「添加账户」，选定供应商与凭证后展开测试模型候选（或编辑任一账户的测试模型下拉）。
2. 前端 `useAccountTestModels` 携带 `selectedIds`（当前选中/默认模型）请求 `test-draft-options` / `test-options`。
3. 后端目录查询 ORDER BY 引用不存在的 `model` 列，PG 42703 → 500。

## 环境信息

- 分支 / 版本：生产 gateway 运行含 B4 ⑧ models 单表合并（`ae5c89b6e`，2026-10-19）后的构建。
- 数据状态：`juhe_business.models` 单表物理列 `public_model`。
- 是否稳定复现：是（凡 `selectedIds` 非空即 500，PG 环境必现；SQLite 不复现）。

## 根因分析

- 表象：`AccountManualTestOptionsWithTotal` → `ListBuiltInTestCatalogOptions` / `ListCustomTestCatalogOptions` / `ListAccountSupportedTestCatalogOptions` 三臂共享的置顶排序子句 `testSelectedOrderClause` 输出 `CASE WHEN model IN (...) THEN 0 ELSE 1 END, ` 拼进 ORDER BY。
- 真实根因：`SELECT public_model AS model` 的别名在 PG 的 ORDER BY 中只能独立引用、不能出现在表达式内；表达式里的 `model` 按 FROM 表解析，而 models 单表（B4 ⑧，`ae5c89b6e`）物理列是 `public_model`，即报 SQLSTATE 42703。同函数的 WHERE 阶段文本过滤已在并表时改为 `public_model`（附注释警示），共享排序子句被遗漏。
- 为什么会发生：子句自 Node→Go 迁移（`eb38f7792`，2026-09-06）即存在，彼时旧目录表有物理 `model` 列可解析；10-19 并表后 PG 上必炸，但本地/单测跑 SQLite（ORDER BY 别名表达式宽松解析）无感，直到生产暴露。

## 修复方案

- 修改点：
  - `backend-go/projects/gateway/internal/accounts/accountstest/options_service.go` `testSelectedOrderClause`：`model` → 物理列 `public_model`（三臂共享，一处修复全链生效），注释锁定 PG 别名/表达式约束。
  - 新增 `options_service_order_clause_test.go` 回归单测：置顶子句必须引用 `public_model`、不得出现 `CASE WHEN model`。
- 行为影响：仅排序 SQL 列名修正，语义不变（已选模型置顶）；无数据迁移、无契约变化。
- 发布：随下次 gateway 发布生效；回滚回退该提交即可。

## 下次遇到

- 先查什么：gateway 日志 `accounts test slice internal error` 的具体 PG 错误码；42703（列不存在）优先排查 SQL 引用列 vs 表结构（含 SELECT 别名在 ORDER BY 表达式中的使用）。
- 重点看什么：目录/选项类查询是否有多臂共享的 SQL 片段（排序/过滤子句构造器）——并表、改名批次必须全量检索这些片段。
- 如何避免误判：本地/单测通过不代表 PG 可用——涉及 SQL 方言差异（别名解析、排序语义）的语句要以 PG 实测为准。

## 完成总结

- 完成时间：2026-10-23（修复与验证完成，待发布）

- 后续建议：accountstest 目录读面其余 SQL 已核对无同型引用（`CollectTestCatalogCandidates` 等均用物理列）；同类风险集中在「多臂共享 SQL 片段构造器」，后续批次改造表结构时应把这些构造器纳入必查清单。
