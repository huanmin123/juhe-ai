- 模块：后端 / Go / 公开接口 / AI 账户 / 默认测试模型 / PostgreSQL

- 责任人：主 agent / 维护者

## 问题概述

- 现象：账户已有 `default_test_model=A` 时，通过 Go 公开接口把 `supportedModels` 改成不含 A 的集合，数据库仍保留 A。
- 期望：对齐 Node `updateAccount` / `updateAccountAsync`。只有支持模型集合实际变化时检查账户默认测试模型；新集合不包含该模型时清为 `NULL`，仍包含时保留。
- 实际：旧 Go 只替换 `account_supported_models`，不维护 `accounts.default_test_model`。
- 影响范围：已迁移的 `POST /__aipublic__/account/update`。

## 根因分析

- W1b 公开账户最初迁移时尚未包含账户级默认测试模型字段。
- 当前 Node 已把 `defaultTestModel` 纳入账户存储、测试和导入导出契约，但 Go 公开账户更新仍按旧字段集合执行。
- 如果不清理失效值，管理详情、导出和后续账户测试模型解析会得到不属于支持模型集合的默认模型。

## 修复方案

- `PublicAccountUpdateInput` 新增内部 `SupportedModelsChanged` 标记。
- service 只在 trim / 去重后的模型集合与现有集合实际不同时：
  - 执行 owner 模型目录校验。
  - 标记 store 更新模型集合。
- PostgreSQL 更新 SQL 在同一事务中：
  - 未改变模型集合时保持 `default_test_model`。
  - 新集合包含现有默认模型时保持原值。
  - 新集合不包含现有默认模型时写 `NULL`。
- 只有模型集合实际变化时才替换 `account_supported_models`，无序等价集合不重写。
- `default_test_model` 仅用于内部一致性，不进入公开账户响应。

## 下次遇到

- 模型集合变化时同时检查所有引用该集合的默认值、映射和测试偏好。
- 区分字段“显式提交”和“标准化后实际变化”，避免无序等价数组触发无意义写入。
- 内部一致性字段可以参与 store 更新，但不能因此扩大公开 API 响应。
