## 问题概述

- 现象：账户已有 `default_test_model=A` 时，通过 Go 公开接口把 `supportedModels` 改成不含 A 的集合，数据库仍保留 A；首次修复后，只有模型集合实际变化才清理，普通备注更新无法自愈既有不一致数据。
- 期望：对齐 Node `updateAccount` / `updateAccountAsync`。每次账户更新都根据最终支持模型集合检查默认测试模型；不包含时清为 `NULL`，仍包含时保留。
- 实际：旧 Go 最初只替换 `account_supported_models`；首次修复又把 `accounts.default_test_model` 清理错误地绑定到 `SupportedModelsChanged`。
- 影响范围：已迁移的 `POST /__aipublic__/account/update`。

## 根因分析

- W1b 公开账户最初迁移时尚未包含账户级默认测试模型字段。
- 2026-07-10 的 Node 提交 `4f32fe11e` 已把 `defaultTestModel` 纳入普通账户更新，并在请求省略 `supportedModels` 时也按最终模型集合自愈不一致值；该提交晚于 Go 首次修复和原计划口径。
- 如果不清理失效值，管理详情、导出和后续账户测试模型解析会得到不属于支持模型集合的默认模型。

## 修复方案

- `PublicAccountUpdateInput` 新增内部 `SupportedModelsChanged` 标记。
- service 只在 trim / 去重后的模型集合与现有集合实际不同时：
  - 执行 owner 模型目录校验。
  - 标记 store 更新模型集合。
- PostgreSQL 每次普通账户更新都根据 service 传入的最终 `supportedModels` 检查 `default_test_model`：
  - 最终集合包含现有默认模型时保持原值。
  - 最终集合不包含现有默认模型时写 `NULL`，包括仅更新备注或显式提交无序等价模型集合的场景。
- 只有模型集合实际变化时才替换 `account_supported_models`，无序等价集合不重写。
- `default_test_model` 仅用于内部一致性，不进入公开账户响应。

## 复发记录

- 时间：2026-07-10。
- 环境：`feature/20260706-go`，对照 `ddbb3d3d..HEAD` 的 Node 变更。
- 现象：Go 首次修复只在 `SupportedModelsChanged=true` 时清理，未同步提交 `4f32fe11e` 新增的普通更新自愈语义。
- 关联处理：Go SQL 移除清理条件中的 `supported_models_changed`，sqlc 参数同步删除；该标记继续只控制模型目录校验和绑定重写。

## 下次遇到

- 模型集合变化时同时检查所有引用该集合的默认值、映射和测试偏好。
- 区分“数据一致性自愈”和“模型绑定重写”：前者可在每次账户更新执行，后者仍只在字段实际变化时执行。
- 内部一致性字段可以参与 store 更新，但不能因此扩大公开 API 响应。

## 完成总结

- 完成时间：2026-07-10。
- 结论：Go 公开账户每次更新都会保证账户默认测试模型属于最终支持模型集合，同时保持无序等价模型不重写绑定和公开响应脱敏边界。
