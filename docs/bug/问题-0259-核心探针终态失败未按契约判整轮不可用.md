# BUG-0259：核心探针终态失败未按契约判整轮不可用

- 状态：已修复（2026-10-01，待发布；BUG-0257 在途改动不冲突，本修复不触碰其 qualityDecision v2 写入逻辑）
- 定性：Go 实现与《模型检测设计.md》§1.2 契约偏差——整轮不可用判定覆盖面窄于契约
- 发现方式：真实 E2E 复现（tool_calling 探针 3 次尝试均 10 秒超时后，run 仍判达标）

## 1. 现象

E2E 中 tool_calling 探针三次尝试全部超时（10s×3，重试边界耗尽、`terminalFailure` 证据落库），套件按 §1.2 提前截断后续探针（题库环节被家族截断未执行），但 run 最终仍为 `completed`、100 分、`level=likely`，被判"达标"并具备进入正常质量评分 / 处罚路径的资格——与 §1.2 "任一必需探针第三次仍非 HTTP 200 时，立即终止整个 run……结论为不可用 / 未验证……不得处罚"的契约不符。

## 2. 根因

`backend-go/projects/gateway/internal/modelcheckprobe/summary.go` 的整轮不可用判定只认 `protocol_basic`（basic 失败或无 success 证据 → `unavailable`）；`suite.go` 对 stream / structured / tool 的终态失败虽已提前截断后续探针并保留 skipped 证据，但 `SummarizeChecks` 对这些终态失败项照常走普通评分阶梯（终态项 skipped 不进分母，部分证据反而得满分），level 与处罚路径不受影响。证据字段本身已正确：`evaluation.go` 的 `requestFailureEvaluation` 对全部核心探针统一写入 `requestFailure` + `terminalFailure`（重试边界耗尽时），仅 summary 汇总层未消费。

## 3. 修复

- `modelcheckprobe/summary.go`：新增 `hasTerminalCoreProbeFailure`，任一目标侧核心协议探针（protocol_basic / protocol_stream / responses_stream / structured_output / tool_calling，responses_stream 为 Responses 协议下流式终态探针的实现 kind）带 `requestFailure` 且 `terminalFailure` 证据即返回 `SummaryResult{"unavailable", score, 100, "目标模型链路不可检测或上游不可用"}`。既有 basic 分支行为与消息不变；可信对比账户（`trusted_comparison.*` 前缀项）自身的终态失败仍走 comparison 聚合的 uncertain 路径，不把目标判成不可用；skipped / excluded 证据原样保留不改 items。
- 抑制链路核实无代码改动：`modelcheckowner/runtime.go` 的 `hasTerminalEvidence`（:714-730）本就接受任何族的 `terminalFailure` 证据（仅排除 token_integrity），核心探针终态失败 → `modelCheckUnverified=true` → `qualityDecision.result='not_triggered'`、`qualityDecisionSuppressedReason='未形成质量判定证据'`、`triggered=false`、不处罚、不写质量健康失败统计；本修复补测试锁定该链路，未触碰 BUG-0257 的 qualityDecision v2 字段写入逻辑。
- 题库环节例外（§5.7）保持不变：custom_quiz 不在核心协议探针集合内，题库失败不触发本条的整轮 unavailable 判定；题库自身的终态请求失败经家族 terminal 包装会带 `terminalFailure` 证据，走 runtime 既有任意族抑制（`modelCheckUnverified=true`，整跑不扣分不处罚），与 §5.7"整跑失败不扣分"契约一致。
- 契约精确化同步《模型检测设计.md》§1.2：在"同一探针第三次仍为非 200"条目后补充"必需探针即核心协议探针（protocol_basic / protocol_stream / structured_output / tool_calling）；题库环节自身的请求失败按 §5.7 处理，不触发整轮终止"。

## 4. 验证

- `modelcheckprobe`：新增 `TestSummarizeChecksMarksCoreProbeTerminalFailureUnavailable`（tool / structured / protocol_stream / responses_stream 四臂终态失败 → unavailable）、`TestSummarizeChecksRequiresTerminalFlagForUnavailable`（仅 requestFailure 不判不可用）、`TestSummarizeChecksQuizRequestFailureStaysScoredRun`（§5.7 题库例外不判不可用且分数层级不受影响）、`TestSummarizeChecksTrustedComparisonTerminalCoreStaysUncertain`（可信对比终态失败保持 uncertain）；既有 basic 行为用例（`TestSummarizeChecksMarksFailedBasicUnavailableEvenWhenOtherCoresAnswer` 等）保持绿。
- `modelcheckowner`：新增 `TestHasTerminalEvidenceCoversNonBasicCoreProbes`（四个核心探针终态失败抑制；无 terminalFailure 的请求失败证据不抑制——题库真实终态失败带 terminalFailure，走任意族抑制）与 `TestRuntimeSuppressesQualityDecisionOnCoreProbeTerminalFailure`（runtime 全链：tool 3× 非 200 → run completed 且 level=unavailable、`modelCheckUnverified=true`、decision `not_triggered`+抑制原因、`account_quality_health_hourly` 零写入、处罚零调用）。
- `go build ./...` 与 `go test ./internal/modelcheckprobe/... ./internal/modelcheckowner/ -count=1` 全绿，gofmt 无差异。
