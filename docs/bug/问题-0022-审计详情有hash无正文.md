## 问题概述

- 现象：审计详情里部分 payload 只有 Headers / Body hash、大小或 blob 引用，打开原文时没有正文；指定 AI 账户 `jingyuqingfeng` 在用量记录里有成功请求，但审计列表查不到对应记录。
- 期望：详情页能区分“按审计策略未保存正文”“blob 文件缺失”“blob 元数据缺失”；文档明确常规备份和历史数据不保留审计原文；目标账号排查时能解释成功采样口径。
- 实际：历史备份目录只带出了数据集目录库和 usage shard，没有带出 `data/audit/blobs`，这是备份口径内的预期结果；前端原来只显示空内容，不能明确指出文件缺失。
- 影响范围：线上排障、离线取证、审计详情阅读、最近 1 小时热保留原文恢复判断。

## 根因分析

- 表象：详情页“有 hash 没正文”，容易被误判成审计写入丢内容。
- 真实根因：审计 payload 正文外置在 `data/audit/blobs/`，数据集目录库只保存 `storage_key`、hash、大小和压缩信息；历史备份按设计不保留审计原文，因此离线历史数据无法读取正文。
- 为什么会发生：payload API 没有把 `file_missing` / `metadata_missing` 状态返回给前端，导致符合备份口径的“无历史审计原文”在页面上表现成空内容。
- 账号补充：`jingyuqingfeng` 的 6 条用量记录都是 2026-06-08 的 200 成功请求，普通成功请求默认只做 10% 稳定采样，未进入审计不等于写入失败。

## 修复方案

- 修改点：payload 读取返回 `headersStorageStatus` / `bodyStorageStatus`；异步批量写入遇到已有 blob 元数据但文件缺失时补写文件；前端详情显示“可读取 / 文件缺失 / 元数据缺失 / 未保存”；部署指南明确常规备份和历史数据不包含审计 payload 文件，仅当前现场排障需要时才临时复制。
- 行为影响：已有 API 字段向后增加；列表仍按 DB 引用显示是否有 Headers / Body，打开原文后显示实际文件状态。
- 发布异常处理：历史备份没有审计 blob 属于预期，不能也不需要恢复历史审计正文；新代码不能凭 hash 反推出历史正文。若正在排查当前现场且文件仍存在，只能从当前服务器运行目录临时复制。
