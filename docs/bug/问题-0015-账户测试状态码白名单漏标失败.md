## 问题概述

- 现象：Mac 服务器上 `tid=9ff907f4-26c5-4ca8-a853-55790628e4bd` 的授权账号手动测试失败，但被授权人视角的账号状态没有进入失败状态。
- 期望：授权给当前用户的账号在当前用户分组里测试失败时，应写当前用户的授权绑定本地状态；所有者物理账号不应被改动。
- 实际：上游返回 HTTP 400、错误码 `key_switch_cooldown`，测试结果失败，但路由层状态码白名单没有包含 400，因此没有写入本地临时不可调用。
- 影响范围：手动账号测试，尤其是授权账号隔离后的被授权人视角；上游返回非白名单状态码时会漏标失败。

## 复现步骤

1. 所有者把 OpenAI API Key 账号授权给其他系统账户。
2. 被授权人把该账号加入自己的分组，并由管理员带 `systemAccountId=<被授权人>` 触发账号测试。
3. Mock 上游返回 HTTP 400，payload 包含结构化错误码 `key_switch_cooldown`。
4. 观察被授权人视角账号状态是否进入 `temporary_unavailable`，所有者物理账号是否仍为 `active`。

## 根因分析

- 表象：HTTP 400 被当成“不需要标记账号失败”的结果。
- 真实根因：`shouldMarkAccountTestFailureAsTemporaryUnavailable` 使用写死 HTTP 状态码白名单决定是否写账号失败状态，同时用中文 message substring 判断配置类失败。
- 为什么会发生：2026-05-22 的 `fa357bfd` 在补授权账号隔离与测试失败自动临时不可调用时引入了状态码白名单；授权隔离本身方向正确，但失败资格判断不应写在路由层状态码分支里。

## 修复方案

- 修改点：
  - 账号测试结果新增 `accountFailureEligible`，由测试服务按结构化异常类型决定是否允许写账号失败。
  - 路由层不再判断具体 HTTP 状态码，也不再用中文 message substring 排除失败；只看 `success`、账号当前状态、调度资格和 `accountFailureEligible`。
  - 配置类失败、用户取消测试不写账号失败；超时、上游非成功响应、流式失败仍可写失败。
  - 授权账号测试失败只写被授权人的授权实例账户行，不改授权方原账户。
  - 后台冷却复测遇到 `accountFailureEligible=false` 的失败时不累计失败预算。
  - 前端不再用 `lastErrorMessage.includes('账户套餐已过期')` 推导账户到期，后端过期状态统一写 `last_error_code='account_expired'`。
  - 新账号不再默认写入账户自身 `credentials.error_handling_rules`；账号错误策略只作为可编辑的按需配置，不作为路由层通用状态码白名单。
- 行为影响：已有账号内显式配置的错误处理策略继续生效；未配置策略的未知上游失败只记录并切号，不默认冷却账号。
- 反向风险：恢复账号测试路由状态码白名单逻辑或重新启用账号默认错误策略，会重新引入 400 等非白名单失败漏标和账号默认冷却过重的问题。

## 复发记录

- 时间：2026-05-29
- 环境：Mac 生产，账号 `free4`，所有者 `天才程序员`，被授权人 `huanmin`，分组 `福利`
- 现象：授权账号手动测试连续收到上游 HTTP 503 / `api_error` / `Service temporarily unavailable`，前一版分散授权运行态曾把失败写入 `group_accounts.local_status = temporary_unavailable`，但冷却到期后列表又按有效状态显示为“正常”，tooltip 仍保留“账户测试失败”原因。
- 根因：分散授权运行态把授权账户运行态拆到 `group_accounts.local_*`，读取时又把已到期的 `local_cooldown_until` 折算成 `active`，导致列表、状态筛选和网关调度口径提前恢复。
- 关联处理：当前授权实例模型已改为测试失败写实例 `accounts.status / cooldown_until / last_error_*`，不写授权方原账户，也不再把 `group_accounts.local_*` 作为运行态事实。

## 下次遇到

- 先查什么：`manual_account_test` 使用记录、原始审计 payload、`accountFailureEligible`、`accountStatusChanged`、授权实例账户状态字段。
- 重点看什么：不要只看 HTTP 数字；要确认失败是否是配置类、取消类、上游失败类，以及写入目标是授权实例还是授权方原账户。
- 如何避免误判：账号状态副作用不能靠状态码白名单、错误类型字符串或中文文案 substring 决定；需要由测试服务输出结构化失败资格。
