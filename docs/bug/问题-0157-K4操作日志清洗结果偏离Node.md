## 问题概述

- 现象：Go `operationlog.SafeChange` 对敏感字段统一写入 `After: "已变更"`，结构化值超过 500 字节时追加 `...`。
- 期望：与 Node `safeChange`/`normalizeSafeValue` 的审计可见值一致；敏感字段被清空时应显示“未设置”，结构化 JSON 截断不追加额外字符。
- 实际：已设置的 token/key/password 被清空时，Go 仍记为“已变更”；长结构化 changes 的日志正文与 Node 不同。
- Go `authsys.OperationLogProducerSink` 还固定 `DetailLevel: "summary"`；Node system-account 操作通过 viewer 默认 `detailLevel=full`，导致 Go 的详情查询看不到 Node 应返回的 changes。
- 影响范围：操作日志审计和回放对账出现差异，影响凭据变更追溯。

## 根因与证据

- Go：`backend-go/projects/gateway/internal/operationlog/producer.go` 的 `SafeChange`/`truncateForLog`。
- Node：`backend/src/modules/operation-logs/operation-log.service.ts` 的 `safeChange`/`normalizeSafeValue`，以及 `system-accounts.routes.ts` 的 full viewer。
- 当前提交只覆盖普通摘要，没有覆盖敏感字段清空和长结构化 changes。

## 已确认子项：普通变更值被 Go 字符串化

- 对照事实：Node `normalizeSafeValue` 对 `null`、number、boolean 原样保留；只有字符串按 200 字符截断，结构化值才 JSON 序列化为字符串。`safeChange('enabled', '启用', false, true)` 会产生布尔类型的 `before`/`after`。
- 历史 Go：`SafeChange` 对非敏感字段统一调用 `truncateForLog`；该函数除字符串外都返回字符串（例如 `json.Marshal(false)` 后得到 `"false"`），`nil` 也被映射为空字符串。
- 可观察结果：同一启用开关或数值配置变更，Node 操作日志 JSON 保留 `false/true` 或数值，Go 记录为带引号的 `"false"/"true"` 或数字文本；前端类型渲染、审计 JSON 对账和按类型检索会出现差异。
- 证据范围：Node 历史 `operation-log.service.ts` 第 181–239 行；Go 证据为提交 `d2f63e70b` 的 `producer.go` 第 67–112 行，历史测试仅覆盖字符串截断。该结论不依赖当前未提交工作区。
- 修复门槛：保留 Node 对 null/number/boolean 的原生类型，继续保持字符串与结构化值的各自截断规则，并补充布尔、整数、小数、null、结构化值的 JSON golden。

## 修复与验证

- 修改点：冻结 Node 清洗 golden，按字段为空/非空和结构化长度补齐 Go 清洗规则及测试。
- 当前验证：未执行跨实现日志对照；K4 仍未完成真实入口接线。
- 结论：K4 审计结果存在稳定可观察偏差，待修复。
