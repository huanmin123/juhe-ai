# BUG-0258：单账户编辑调度字段未同步分组绑定

- 状态：代码已修复（2026-10-01，5 用例红绿闭环 + accounts 整包绿 + 独立复审六项全 PASS）；生产存量数据已修复（2026-10-01，备份表 `group_accounts_backup_b0258` 7 行 → 对齐后不一致 0 行，网关缓存 60s 内自然刷新恢复正确排序）；已发布（2026-10-01 22:55 随 gateway/jobs 上线，gateway 807cfc46d9cb0019aeda915435209e10，md5 三点闭环，发布详情见私有 runbook 发布记录；BUG-0257 在途改动经 stash 隔离未入产物）。
- 定性：代码违反既有设计契约（Go 迁移丢失 Node 归档分支，按"文档回正代码"处置，非契约变更）
- 发现方式：用户生产报障（2026-10-01 17:15）

## 1. 现象（生产报障事实）

2026-10-01 17:15 用户 804298280@qq.com 反馈「超级优先和锁死不生效」：在管理面「编辑账户」弹窗为账户开启超级优先后，调度行为完全不变。

调用日志证据（同日）：绑定序在前的麻豆科技（上游持续 403 一整天）仍然永远首发 64 次；开启超级优先且持续 200 的 API智纽 仅被兜底调用 15 次——排序完全按绑定行旧快照执行，账户级新设置未参与调度。操作日志证实用户走 `accounts.update`（单账户编辑弹窗 PATCH）反复设置超级优先，即修改已成功落账户表、只是调度不认。

## 2. 根因

网关调度候选排序只读分组绑定级字段：`backend-go/projects/gateway/cmd/juhe-ai-gateway/chain_accounts.go:511-516` 的 ORDER BY（`group_accounts.local_fallback_enabled ASC, local_super_priority_enabled DESC, local_priority ASC`），以及 `chain_accounts_secret.go:125,174` 的候选快照合成（`dispatchPriority/dispatchSuperPriorityEnabled/dispatchFallbackEnabled` 取 `row.Local*` 列）。

管理面单账户 PATCH（`backend-go/projects/gateway/internal/accounts/patch.go`）修改 `priority/superPriorityEnabled/fallbackEnabled` 时只写 accounts 表，不同步 group_accounts 绑定的 `local_*` 快照。Node 时代同文件（git 历史 `18b46944e:backend/src/storage/account-management-patch.repository.ts`）有两个分支：

```ts
if (groupChanged && requestedGroupId) {
    await replaceGroupBindingInClient(...)   // Go 已移植：patch.go replaceGroupBinding（仅在 groupChanged 时调用）
} else if (dispatchBindingChanged) {         // Go 缺失这一分支！
    await client.execute(`
      UPDATE group_accounts
      SET local_priority = ?, local_super_priority_enabled = ?, local_fallback_enabled = ?, updated_at = ?
      WHERE account_id = ? AND system_account_id = ? AND enabled = 1
    `, [nextPriority, nextSuperPriority ? 1 : 0, nextFallback ? 1 : 0, now, row.id, row.system_account_id])
}
```

其中 `dispatchBindingChanged = currentPriority !== nextPriority || currentSuperPriority !== nextSuperPriority || currentFallback !== nextFallback`（归档 :494-516 派生、:829-845 执行）。Go 迁移只移植了 groupChanged 分支，else-if 臂丢失——单账户编辑的调度三字段改动永远不落绑定快照，绑定 `local_*` 残留创建时值，排序永远按旧值。

## 3. 影响面

- **受影响**：单账户编辑路径 `PATCH /accounts/{id}` 与 `/my-accounts/{id}` 的 `priority / superPriorityEnabled / fallbackEnabled` 三字段——只改账户级，调度不认，绑定 local 残留创建时快照。
- **不受影响**：批量编辑路径（`backend-go/projects/gateway/internal/accounts/accountstransfer/batch.go:509-518` 已有同款绑定同步）；m11 授权实例路径（`m11_authorized_dispatch.go`）已有同步；换组（`groupId` 变化）走 `replaceGroupBinding` 删除重建绑定、local 随重建写入，不受此缺陷影响。

## 4. 修复契约

- `patch.go` 在三个调度字段分支处收集 next 终值（`nextPriority/nextSuperPriority/nextFallback`：取输入或行内现值），按 Node 同款三值比较派生 `dispatchBindingChanged`。
- `groupChanged` 为 false 且 `dispatchBindingChanged` 为 true 时，在同一事务 `tx` 内执行 Node 同款 UPDATE（对齐归档 :835-845）：

```sql
UPDATE group_accounts
SET local_priority = ?, local_super_priority_enabled = ?, local_fallback_enabled = ?, updated_at = ?
WHERE account_id = ? AND system_account_id = ? AND enabled = 1
```

参数对齐 Node：`nextPriority`、`boolInt(nextSuper)`、`boolInt(nextFallback)`、`nowISO`、`row.id`、`row.systemAccountID`。
- 换组时仍走既有 `replaceGroupBinding`（删除重建语义不变），但入参由行内旧值改为 next 终值（对齐归档 :830-834 传 next 值——修复前 Go 传 `row.priority/row.superPriorityEnabled/row.fallbackEnabled` 行内旧值，换组与调度字段同改时新绑定会落旧值）。
- `PatchResult` 新增 `DispatchBindingChanged bool`（`json:"-"`，供提交后联动判定）。
- stats 联动（对齐 Node `applyAccountPatchPostCommitEffects`：`groupStatsAffected: groupChanged || dispatchBindingChanged` → `refreshGroupAccountStatsAfterWriteAsync({accountIds:[id], reason:'account_management_patch'})`）：`finishPatchSideEffects` 补 `markBatchGroupStatsDirty(ctx, []string{id}, account_management_patch)`，失败 Warn（事件名 `account_management_patch_stats_refresh_failed`），统计通道独立于 CacheInvalidator（同批量路径先例）。

## 5. 生产数据修复方案（存量）

存量绑定的 `local_*` 与账户级不一致的行需对齐账户级现值（代码修复发布后新编辑自然同步；存量靠一次性数据修复，属本仓库 AGENTS.md 允许的受控数据修复——执行前先备份）。生产为 PG。

**对齐范围只限自有账户绑定**：`ga.system_account_id = a.system_account_id AND a.authorization_instance_source_account_id IS NULL`。授权实例绑定（`m11_authorized_dispatch.go` 的 bindingSets 路径）的 `local_*` 是使用方独立配置，且该路径从不更新实例行的账户级三列（实例行三列只是来源账户的复制快照）——全表无条件对齐会破坏使用方配置，必须排除。Node patch 的 UPDATE 天然安全（`WHERE system_account_id = 被编辑账户 owner`，编辑面只允许 owner 编辑自有账户），一次性存量修复须自带该排除条件。

```sql
-- 1) 先备份受影响行（按运维手册留档）
CREATE TABLE group_accounts_backup_b0258 AS
SELECT ga.*
FROM group_accounts ga
JOIN accounts a ON a.id = ga.account_id
WHERE ga.enabled = 1
  AND ga.system_account_id = a.system_account_id
  AND a.authorization_instance_source_account_id IS NULL
  AND a.deleted_at IS NULL
  AND (ga.local_priority <> a.priority
    OR ga.local_super_priority_enabled <> a.super_priority_enabled
    OR ga.local_fallback_enabled <> a.fallback_enabled);

-- 2) 对齐账户级现值（条件与备份完全一致）
UPDATE group_accounts ga
SET local_priority = a.priority,
    local_super_priority_enabled = a.super_priority_enabled,
    local_fallback_enabled = a.fallback_enabled,
    updated_at = NOW()
FROM accounts a
WHERE ga.account_id = a.id
  AND ga.enabled = 1
  AND ga.system_account_id = a.system_account_id
  AND a.authorization_instance_source_account_id IS NULL
  AND a.deleted_at IS NULL
  AND (ga.local_priority <> a.priority
    OR ga.local_super_priority_enabled <> a.super_priority_enabled
    OR ga.local_fallback_enabled <> a.fallback_enabled);
```

执行前先跑备份建表的 SELECT 核对受影响行数与预期（如报障账户 API智纽 应在列），执行后抽查该账户绑定与调度行为。

## 6. 验收标准

- 单账户 PATCH 开/关超级优先（或改 priority/fallback）后：`accounts` 级与 `group_accounts` 绑定级三列同步为同一终值，调度排序按新值生效。
- 未触及调度字段的 PATCH（如只改 notes）不动绑定行（值与 updated_at 均不变）。
- 换组 + 调度字段同改：走 replaceGroupBinding 删除重建，新分组绑定跟随 next 终值。
- `result.DispatchBindingChanged` 随三字段终值变化正确翻转（含同值提交为 false 的臂）；`groupChanged || dispatchBindingChanged` 时落 `group_account_stats_dirty` 脏标记（reason=account_management_patch）。
- 包内测试 `TestBug0258*` 全绿；红绿闭环已验证（同步分支禁用时主用例失败于绑定列断言）。

## 7. 已知残留（范围外，另行任务）

- **Go 单字段提交可致 super/fallback 共存落库**：Node 归档 :505-507 对"单开 super（fallback 未传）且行内 fallback=1"做自动让位归一化（nextFallback 压 false 一并落库）；Go patch.go 仅在"显式双输入同真"时拒绝，单字段提交可落库 super=1 + fallback=1 共存。本次修复的绑定同步忠实镜像该落库终值（绑定与账户级保持一致，不引入新矛盾）；前端编辑弹窗同提交两显式值不受影响。严格对齐 Node 让位语义另行开问题处理。
