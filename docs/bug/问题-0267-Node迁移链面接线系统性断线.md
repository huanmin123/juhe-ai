### 2.2 codex 压缩 SSE 派发等待期保活缺席（chain_v1_loop.go）

- 病灶：Node routes.ts:1229-1239 对流式 codex 压缩请求（`shouldKeepCodexCompactSseAliveDuringUpstreamWait`：requestStream + codex + codexCompactionExpected + responses_sse）在每轮 fetch 前挂 10s 间隔的 compaction 保活心跳并立即 Start；Go 的 `HeartbeatDeps.EmitCodexCompactionKeepalive` 字段与 chunk 逻辑齐全（heartbeat.go:142）但生产零接线——压缩请求在上游长等待期无保活块，客户端/中间层可能空闲断连（BUG-0266 场景的伴生暴露）。
- 修复：`v1DispatchLoop.compactWaitHeartbeat` 字段 + `startCompactSseWaitHeartbeat`（挂载条件提取为 `shouldKeepCompactSseAliveDuringUpstreamWait`，10s 间隔，共享 `loop.waitCommitState` 单实例）/ `stopCompactSseWaitHeartbeat`（Stop 幂等）；run 循环每轮 fetch 前 Start、fetch 返回即停（比 Node 的 finally 兜底收得更紧，避免与真实流数据交错），run 收尾 defer 兜底（对齐 Node :2640）。
- **复审竞态修复（在制品回归，独立复审发现）**：初版与既有预算等待心跳（D-120，15s，budget observer 边沿驱动）并存——两个心跳 goroutine 并发写同一 TrackingWriter / DownstreamCommitState 是真实 data race（10s/15s LCM=30s 必重叠；Node 靠单线程事件循环天然串行，Go 的 goroutine 形态必须显式处理）。修复为**压缩场景收敛单心跳**：`chain_v1.go` 心跳装配处满足 `shouldKeepCompactSseAliveDuringUpstreamWait` 时不挂 budget observer（compact 心跳覆盖整个 fetch 窗口含等待期，是预算心跳等待期职责的超集）；非压缩路径不变。测试侧同批修复 `-race` 必挂的裸轮询 recorder 写法（signalingResponseWriter 同步点替代）。三画像门同时收敛为复用 `gatewaycodex.GatewayClientAllowsUpstreamSemanticInterpretation`（消除字面量双份维护）。
- 测试：`TestV1CompactSseWaitHeartbeat`（挂载并写出首个保活块 + 生命周期置空 / 非压缩 / 非流式 / 非 codex / 非 responses_sse 五个分支，`-race` 通过）。

### 2.3 半开探测租约链面零消费（chain_v1_loop.go）

- 病灶：引擎 `ReleaseHalfOpenLease` / `ConfirmHalfOpenSuccess` 已带出（upstreamdispatch.go:60-61），Node 消费点 routes.ts:2484（protocolValidatedSuccess 确认）/ :2494 / :2520（finally 释放）在 Go 链面零调用——`keepConcurrencySlot=true` 时引擎 `releaseTransientState` 不释放、所有权移交链面后无人消费，选中 2xx 尝试若持有半开认领，租约悬挂至 180s TTL（localSuppressionHalfOpenLeaseMs），刚成功服务请求的健康账户被压在 half-open 排除态且不可再认领。
- 修复：响应轮 defer 补 `ReleaseHalfOpenLease()` 兜底（与 ReleaseAccountLockRetryLease 同位；defer 内注释标注顺序敏感点——本 defer 先于 Confirm 执行与 Node 相反，当前无害，未来接入带真实 CompleteSuccess 的租约时需调整为 Confirm 先行）；`confirmProtocolSuccessSideEffects` 补 `ConfirmHalfOpenSuccess()` 调用（nil 检查；gateway 流量的回调受 automaticAccountStateMutationAllowed 门约束为 no-op，对齐 Node 调用形态）。双结算安全由引擎侧 leaseID 匹配的幂等释放保证（suppression.go，二次调用 no-op）。
- 测试：`TestV1HalfOpenLeaseConfirmOnProtocolSuccess`（协议成功确认 / 未验证不触碰）；释放兜底在 run 循环响应轮 defer 内内联、engine 为具体类型不可 mock，当前无断言级覆盖（如实声明），由 confirm 测试 + 引擎回调幂等语义共同保证行为面。
