# BUG-0267：Node→Go 迁移链面接线系统性断线（BUG-0266 同型排查）

- 状态：部分修复（2026-10-02：P0 三项已修复；其余登记待裁决/另行任务）
- 定性：Go 迁移系统性缺口——引擎/预检层的判定与结构均已移植，但 Node routes.ts 主循环的链面消费接线多处未迁移；与 BUG-0266 同型（判定在、结构在、接线断，常被兜底冗余掩盖且测试全绿）
- 发现方式：BUG-0266 修复后的同型排查（双取证角色以 Node routes.ts 逐字段消费点对照 Go chain 层传导链）

## 1. 排查方法与范围

以 Node 权威源码（F:/juhe-node-temp 迁移备份，release dist 交叉验证）的 routes.ts 主循环为基准，逐字段对照 Go 的 `UpstreamDispatchResult` 消费、`DispatchContext`/`RouteAction` 字段消费、`RequestCoordinationContext` 赋值、响应层入参来源。共发现 13 处差异，分三级如下。

## 2. P0 已修复（2026-10-02，与本档案同批交付）

### 2.1 ClientStrategyView 投影断线（chain_v1.go clientStrategyViewOf）

- 病灶：`InterpretSemantics` 为死逻辑恒 `true`（`if profile == "" { true }` 两臂同值）；`CodexCompactionExpected` / `RetryPreCommitProtocolError` / `AllowClientSourceAccountAvoidance` 三字段从不赋值（恒 false）。数据源 `strategy.Opaque`（G18 冻结上下文，gatewaycodex/strategy.go:93-109）齐全，chain_v1_streamretry.go 已有读取示范但投影未接。
- 行为影响：普通 openai 兼容客户端的上游响应语义解释被错误启用（Node 仅 codex/claude_code/gemini_cli 三画像开，client-profiles/strategy.ts）；codex 压缩请求的非流式缓冲臂（nonstreamgate.go:42）恒不触发；预提交协议错误重试信号在响应层恒走另一臂。
- 修复：投影源改为 Opaque 携带的完整 G18 上下文；`InterpretSemantics` 按三画像门（`clientProfileAllowsSemanticInterpretation`）；Opaque 缺失时压缩期望/重试信号 fail-closed（解释门仍按 ClientProfile 判定）。
- 测试：`chain_v1_node_contract_test.go` `TestV1ClientStrategyViewProjection`（全投影 / 三画像门正反例 / 非 protocol_error 信号不映射 / Opaque 缺失 fail-closed）。

### 2.2 codex 压缩 SSE 派发等待期保活缺席（chain_v1_loop.go）

- 病灶：Node routes.ts:1229-1239 对流式 codex 压缩请求（`shouldKeepCodexCompactSseAliveDuringUpstreamWait`：requestStream + codex + codexCompactionExpected + responses_sse）在每轮 fetch 前挂 10s 间隔的 compaction 保活心跳并立即 Start；Go 的 `HeartbeatDeps.EmitCodexCompactionKeepalive` 字段与 chunk 逻辑齐全（heartbeat.go:142）但生产零接线——压缩请求在上游长等待期无保活块，客户端/中间层可能空闲断连（BUG-0266 场景的伴生暴露）。
- 修复：`v1DispatchLoop.compactWaitHeartbeat` 字段 + `startCompactSseWaitHeartbeat`（对齐 Node 挂载条件，10s 间隔，共享 `loop.waitCommitState` 单实例）/ `stopCompactSseWaitHeartbeat`（Stop 幂等）；run 循环每轮 fetch 前 Start、fetch 返回即停（比 Node 的 finally 兜底收得更紧，避免与真实流数据交错），run 收尾 defer 兜底（对齐 Node :2640）。
- 测试：`TestV1CompactSseWaitHeartbeat`（挂载并写出首个保活块 + 生命周期置空 / 非压缩 / 非流式 / 非 codex 四个负例）。

### 2.3 半开探测租约链面零消费（chain_v1_loop.go）

- 病灶：引擎 `ReleaseHalfOpenLease` / `ConfirmHalfOpenSuccess` 已带出（upstreamdispatch.go:60-61），Node 消费点 routes.ts:2484（protocolValidatedSuccess 确认）/ :2494 / :2520（finally 释放）在 Go 链面零调用——`keepConcurrencySlot=true` 时引擎 `releaseTransientState` 不释放、所有权移交链面后无人消费，选中 2xx 尝试若持有半开认领，租约悬挂至 180s TTL（localSuppressionHalfOpenLeaseMs），刚成功服务请求的健康账户被压在 half-open 排除态且不可再认领。
- 修复：响应轮 defer 补 `ReleaseHalfOpenLease()` 兜底（与 ReleaseAccountLockRetryLease 同位）；`confirmProtocolSuccessSideEffects` 补 `ConfirmHalfOpenSuccess()` 调用（nil 检查；gateway 流量的回调受 automaticAccountStateMutationAllowed 门约束为 no-op，对齐 Node 调用形态）。
- 测试：`TestV1HalfOpenLeaseConfirmOnProtocolSuccess`（协议成功确认 / 未验证不触碰）；释放兜底在 run 循环 defer 内由既有链路测试执行覆盖。

## 3. 已登记未修（按处置分类）

### 3.1 修复面大、另行任务（P1）

- **FirstTokenMs 基准错配**：`chain_v1_loop.go` 传请求级 `l.startedAt`，Node routes.ts:1574 传 attempt 级 `attemptStartedAt`；影响 speed-first 假慢采样/错误降级与热质量首字样本系统性偏大（chain_v1.go:536 B1 注释已自认同坑但只修了 DeadlineStartedAtMs）。修复需响应层 input 拆双字段（Node :2468 请求级与 :1574 attempt 级并存）并回归两条消费链测试。
- **keyModelAttempt 选中轮终态不结算**：`ReportCompleteSuccess` 全仓无调用（keymodelattempt.go:271），Node routes.ts:1871-1877 的 post-verdict 结算块未移植；main-probe fence / 失败预算 claim / J1 confirmation 在 2xx-后-body-失败场景全丢。与 3.2 第一项修法绑定（可一并收口）。
- **响应期 body 传输失败的账户锁记录缺失**：`AccountLockObservation` 带出零消费，Node routes.ts:1813-1823 的 `recordAccountLockFailureAsync('upstream_body_transport_failure')` 未移植（成功侧 ConfirmAccountLockSuccess 已对齐）。

### 3.2 有意偏差 vs Node 契约冲突、需裁决

- **circuit 帧完成结算时点**：Go 在 `response.OK()` 即 ReportFramingComplete（attemptoutcomes.go:49，R2 注释自认有意改动），Node routes.ts:1866 在 body 处理完成后——2xx 后 body 中途死亡在 Go 被记成治愈证据（方向性错误）。裁决方向后与 keyModelAttempt 结算块一并移植或留档说明。
- **hybridRoute 质量检查整族未迁移**：nonstreamgate.go:33 注释自认缺席；是否缺陷取决于混合智能路由是否启用（AGENTS.md 保留架构空间、Go 未实现），需产品裁决。
- **WaitForRecoverableFailures 恒 true**：chain_v1_loop.go:225 硬编码，Node :1279-1281 动态（多分组未耗尽回退跳数时 false——先切组后等待）；无注释声明有意。低影响（终态收敛、审计轨迹不同）。
