- 责任人：主 agent / 维护者

## 问题概述

- 现象：Go `GET /providers` 和 `GET /providers/options` 把当前系统账户的默认测试模型偏好写进默认协议档案的 `protocolProfiles[].defaultTestModel`。
- 期望：
  - 顶层 `defaultTestModel` 表示当前用户偏好；没有偏好时回退系统默认。
  - `systemDefaultTestModel` 始终表示供应商原始系统默认。
  - `protocolProfiles[].defaultTestModel` 始终保持各协议档案事实。
- 实际：旧 Go 没有 `systemDefaultTestModel`，并直接改写默认协议档案字段，前端无法区分用户配置和系统 / 协议事实。
- 影响范围：已迁移的供应商全量列表和供应商 options。

## 根因分析

- Node 当前 `providerWithDefaultTestModelPreference` 已明确拆分用户偏好、系统默认和协议档案默认。
- Go PostgreSQL mapper 复用了旧逻辑：读取用户偏好后，先改写默认协议档案，再从该档案生成顶层字段。
- 这会让调用方误以为供应商协议档案本身已经变更，也无法在用户偏好无效或不适用于当前账户时得到正确系统回退值。

## 修复方案

- `ManagementProviderOption` 和 JSON DTO 新增 `systemDefaultTestModel`。
- PostgreSQL mapper 不再修改 `ProtocolProfiles`。
- 顶层 `defaultTestModel` 使用 trim 后的用户偏好；为空时回退默认协议档案的系统默认。
- `systemDefaultTestModel` 固定读取默认协议档案原始 `defaultTestModel`。
- `GET /providers` 和 `GET /providers/options` handler 测试同时固定三层字段。
- 自定义模型 catalog、默认测试模型写接口和协议档案 seed 不在本次修改范围内。

## 下次遇到

- 不要把用户偏好写回系统定义或协议档案 DTO。
- 对带回退的配置至少同时测试“用户值”“系统值”和“来源事实”三个字段。
- 前端需要回退值时，应由 API 明确提供系统默认，不能从已被用户偏好覆盖的对象反推。
