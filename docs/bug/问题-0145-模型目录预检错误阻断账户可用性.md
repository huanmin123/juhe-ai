# BUG-0145 模型目录预检错误阻断账户可用性

- 状态：已修复（本地回归通过）

- 关联 bug：BUG-0143、BUG-0144
- 责任人：待定

## 问题概述

- 现象：部分上游可处理已配置模型的真实生成请求，但没有开放模型目录。人工测试、草稿测试、激活、健康或恢复探针先请求上游 `/models`，目录 `404`、超时或不兼容后直接结束，账户无法使用。
- 期望：账户可用性只由已配置模型和精确请求形态的真实协议请求判断。目录同步是用户选择的补全操作，失败不影响保存、测试、激活、恢复或调度。
- 实际：通用诊断包装器和草稿测试队列把模型目录预检当作强制门禁；账户弹窗还会在打开或凭据变化后静默同步。

## 根因分析

- BUG-0143 / BUG-0144 解决的是“显式目录同步在 driver 被错误拒绝”，没有改变目录本身并非所有上游都提供的事实。
- 自动可用性检查复用了目录发现实现和成功缓存，把可选能力误建模成账户实际 endpoint 的前置条件。

## 修复方案

- 删除 `testOpenAIAccountWithDiagnosticRetries` 和草稿测试队列中的目录预检、缓存和错误终止路径。
- 保留 `discoverAccountUpstreamModels()`、`models_catalog`、内部 marker 与供应商 driver，仅供用户显式同步上游模型。
- 删除账户编辑页静默同步的 timer、watcher 和 `silent` 调用；保留用户点击、AbortController 和关闭弹窗取消请求。
- 以 Mock 回归固定 `/v1/models` 返回 `404` 时，已保存人工测试与后台健康检查仍成功，自动目录命中为 `0`。

## 下次遇到

- 先区分用户显式目录同步和账户可用性检查，不能仅因两者共享 `/models` 路径就复用门禁。
- 先验证真实生成或图片 endpoint 的协议成功，再判断账户是否可测试、激活或恢复。
- 目录相关回归必须同时覆盖受控转发、客户端本地目录和自动检查零目录命中。
