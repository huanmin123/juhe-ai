# BUG-0205：J3b 账户模型映射查询对 integer 列使用布尔字面量，PG 直达 42883

## 现象

2026-09-27 生产实测：管理后台「模型检测」页面选择账户后选择模型即报错，gateway 日志：

```
read J3b account model mapping: ERROR: operator does not exist: integer = boolean (SQLSTATE 42883)
```

## 根因

`backend-go/projects/gateway/internal/modelcheckowner/business_models.go` 的 `resolveConfiguredUpstreamModelMapping` 映射查询 PostgreSQL 分支（`cf4829832`，2026-09-21 引入）写了 `enabled=TRUE`，而权威 schema 中该列在双方言均为 integer：

- maintenance `pg_schema_business_tables.go`：`account_model_mappings.enabled integer NOT NULL DEFAULT 1`；
- SQLite schema 与全部测试 fixture 同为 `enabled INTEGER`。

PostgreSQL 对 `integer = boolean` 无隐式转换操作符，直达 42883。包内既有测试（`business_models_test.go` / `wb_dialect_test.go`）全部走 SQLite 分支（`postgres=false`），PG 分支 SQL 文本从未被执行，故引入时未被暴露——与 w20a 已把调用点布尔字面量统一为 0/1 的方向一致，此处是漏网之鱼。

## 排查（同类雷全库核查）

对仓库全部 `=TRUE` 布尔字面量逐处核对生产实际列类型：

| 位置 | 列 | 生产类型 | 结论 |
| --- | --- | --- | --- |
| `business_models.go:85`（本问题） | `account_model_mappings.enabled` | integer | **42883 必炸，已修复** |
| `model_limits.go:41` / `settings.go:214` | `custom_provider_models.catalog_visible` 等 | boolean | 正确 |
| `accountbalance/store.go:721`、`proxylatency/store.go` | `*.committed` | boolean | 正确 |
| `proxylatency/direct_input_reader.go:313` | `proxy_profiles.enabled` | boolean | 正确 |

`juhe_business` 下其余 `enabled` 列（accounts/groups/providers 等）均为 integer，当前查询均使用 `enabled=1` 形态。

## 修复

- PG 分支 `enabled=TRUE` → `enabled=1`（与 SQLite 分支及 w20a 约定统一），源码注释标注双方言 integer 列契约；
- 新增录制驱动契约测试 `TestResolveConfiguredUpstreamModelMappingPostgresQueryUsesIntegerEnabledLiteral`（对齐 BUG-0204 `wfix_balance_due_fence_test.go` 的 fenceRecorder 模式）：不依赖真实 PG，锁定 `postgres=true` 实际发送的 SQL 文本必须含 `juhe_business.` 前缀、`$1` 占位符与 `enabled=1`，且禁止 `TRUE` 字面量。

## 验证

- `go test ./internal/modelcheckowner/ -run 'TestResolveConfiguredUpstreamModelMapping'` 全绿（含新契约测试）；
- 修复前该路径生产 100% 复现（用户实测），修复后随发布验证。

## 状态

已修复，2026-09-27 23:19 发布；发布后 gateway 日志 42883 零出现。
