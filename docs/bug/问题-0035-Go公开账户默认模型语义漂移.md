# BUG-0035 Go 公开账户默认模型语义漂移

- 模块：后端 / Go / 公开接口 / AI 账户 / PostgreSQL / 网关
- 关联计划：[PLAN-0081 Node 转 Go 渐进减法迁移](../plans/计划-0081-Node转Go渐进减法迁移.md)
- 关联 bug：无
- 责任人：主 agent / 维护者

## 问题概述

- 现象：W1b Go `POST /__aipublic__/account/add` 曾把未提交 `supportedModels` 和显式提交 `supportedModels: []` 都折叠为空列表；显式 `supportedModels: null` 也会被错误接受；更新账户时只有显式提交该字段才校验模型列表，旧空模型账户可通过修改其他字段继续保留空列表。
- 期望：对齐 Node 当前契约。新增时省略 `supportedModels` 继承 `providers.default_supported_models_json`；显式空数组返回 HTTP `400` 和固定中文消息；显式 `null` 返回数组类型错误；更新时始终校验最终模型列表。
- 实际：旧 Go HTTP / service 契约无法完整区分字段省略、显式空数组和 `null`，service 也没有读取 provider 默认支持模型或对更新后的最终模型列表执行非空校验。
- 影响范围：Go W1b 公开账户新增 / 更新、`account_supported_models` 写入、Node gateway 后续读取 Go 写入的账户。空支持模型可能被 Node gateway 解释为不限制模型，导致账户参与本不应命中的模型调度。

## 复现步骤

1. 使用 `gpt` 或 `openai` provider，其 `default_supported_models_json` 包含当前默认 GPT 模型。
2. 调用旧 Go `POST /__aipublic__/account/add`，省略 `supportedModels`。
3. 检查新增账户的支持模型，旧 Go 会写为空列表，而 Node 会继承 provider 默认模型。
4. 再调用旧 Go 接口并显式提交 `supportedModels: []`，旧 Go 仍按空列表创建；Node 会返回 HTTP `400` 和固定中文错误。

## 环境信息

- 分支 / 版本：当前工作区，W1b Go opt-in 实现阶段。
- 数据状态：当前 Go migration 的 `providers.default_supported_models_json` seed；`gpt` / `openai` 默认模型包含 GPT-5.6 系列。
- 浏览器 / 系统 / Node 版本：不适用；服务端 HTTP / service / PostgreSQL 契约问题。
- 是否稳定复现：是，旧实现由字段解析和 service 默认值处理决定。

## 根因分析

- 表象：Go 创建的公开账户支持模型为空。
- 真实根因：
  - HTTP 层使用普通 `[]string` 接收 `supportedModels`，丢失“字段是否出现”的信息，无法区分省略和显式空数组。
  - HTTP optional 数组解析曾把显式 `null` 当作字段省略，绕过 Node 的数组类型约束。
  - service 直接归一化请求列表，没有在字段省略时继承 provider 默认模型，也没有对最终模型列表执行非空校验。
  - 更新路径曾只在显式提交 `supportedModels` 时归一化和校验，无法阻止旧空模型账户通过无关字段更新继续保留空列表。
  - provider profile 查询只读取协议档案，没有联表返回 `providers.default_supported_models_json`。
  - fresh Go seed 虽包含 GPT-5.6 默认模型，但缺少面向 W1b 公开账户语义的静态门禁，后续 seed 漂移可能再次破坏默认继承。
- 为什么会发生：W1b 迁移只对齐了 `supportedModels` 的 JSON 类型和模型替换写入，没有把 Node repository 中“字段存在性决定默认继承”的业务语义带入 Go。
- 校验顺序：Node 公开账户新增先检查目标分组内同供应商、同协议档案、同名账户，再进入账户创建和支持模型校验。因此重复名称必须继续优先返回冲突，不能被显式空模型的 `400` 覆盖。

## 修复方案

- 修改点：
  - HTTP 层使用 `StringListValue` 保留三态：字段省略、显式空数组、显式非空数组。
  - HTTP 层对显式 `supportedModels: null` 返回 `supportedModels 必须是数组`，不调用 service。
  - service 在字段省略时使用 provider profile 携带的 `DefaultSupportedModels`；字段出现时使用调用方提交值。
  - service 对新增和更新的最终归一化模型列表都执行非空校验，显式空数组、空 provider 默认值和旧空模型账户的无关字段更新都返回固定中文业务错误。
  - provider profile SQL 联表 `providers`，读取并解码 `default_supported_models_json`。
  - 增加 GPT-5.6 seed 静态 guard，固定 `gpt` 和 `openai` fresh seed 至少包含 `gpt-5.6-sol`、`gpt-5.6-terra`、`gpt-5.6-luna`。
  - 保持重复名称检查优先于支持模型非空校验。
- 行为影响：
  - 省略 `supportedModels` 不再写空列表，而是继承 provider 当前默认模型。
  - 显式 `supportedModels: []` 不创建账户，返回 HTTP `400`。
  - 显式 `supportedModels: null` 返回数组类型错误。
  - 更新省略该字段时保留并重新校验当前非空列表；当前列表为空则拒绝更新且不写 store。
  - 非空数组继续执行 trim、去空和去重后写入。
  - 不增加旧数据兼容、双读双写或运行时迁移逻辑。
- 发布异常处理：如果真实 PG / Docker 验证发现默认模型未继承或错误优先级不一致，保持 `JUHE_AI_PUBLIC_API_ENABLED=false`，不得将 W1b 切流到 Go，也不得删除 Node 公开账户实现。
