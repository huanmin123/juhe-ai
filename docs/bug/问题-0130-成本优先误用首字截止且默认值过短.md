# BUG-0130 成本优先误用首字截止且默认值过短

- 状态：已修复（待生产验证）
- 优先级：P1
- 影响范围：Node 网关 / 策略路由 / 前端
- 发现时间：2026-07-27

## 现象

普通路由把 `firstByteDeadlineMs` 当成成本优先和速度优先的公共逻辑，成本优先请求也会创建首字 timer；前端始终展示该字段且默认仅 10 秒。

## 根因

领域配置未按调度偏好区分字段所有权，网关预检只按文本 lane 判断，前端保存也向成本优先 payload 写入首字截止。

## 修复

- `RouteStrategyNormalRoutingConfig` 改为判别联合：成本优先不拥有首字截止，速度优先必须拥有该字段和专属配置。
- 旧成本优先配置中的首字字段在规范化时安全丢弃，不需要数据库迁移；旧速度优先别名仍兼容读取。
- 网关只为速度优先可重放文本创建首字截止快照。
- 前端仅在速度优先时展示和保存该字段，默认改为 30 秒。

## 验证

- 领域归一化、repository、网关 deadline、前端表单和类型回归覆盖成本优先排除、速度优先默认 30 秒及旧配置兼容。
