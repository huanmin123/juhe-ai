# BUG-0134 模型检测基础连通性重复计分

- 状态：已修复（待生产验证）
- 优先级：P1
- 影响范围：后端 / 前端 / 模型检测 / 质量处罚
- 发现时间：2026-07-27

## 现象

模型检测详情把 `Responses 非流式调用可用` 展示为最高 20 分的能力项；成功但输出证据不完整时会出现“需关注，15/20”。开启可信对比后，对比账户自己的原始探针分数也会加入目标账户总分，对比账户返回模型名异常还可能直接把目标账户判为可疑。

## 根因

- 基础非流式请求同时承担链路资格预检、模型字段诊断和可信度计分，重复计算了其他行为与协议探针已经覆盖的事实。
- 汇总逻辑把所有检测项放进同一评分集合，并对所有检测项统计模型不匹配，没有区分目标证据、可信账户原始证据和派生对比证据。
- 详情页直接展示历史检测项，没有兼容过滤已落库的成功基础预检。

## 修复

- 基础非流式请求继续作为低成本连通预检；成功且模型字段正常时不生成检测项、不计分、不进入证据完整度。
- 基础请求失败时保留未计分诊断并判本次运行不可检测；请求成功但响应模型不匹配时保留未计分硬异常。
- 总分只统计目标账户检测项及可信对比的两个派生项，可信账户原始探针只作为对比输入；模型不匹配硬判只扫描目标账户。
- 详情页隐藏历史上请求成功且没有模型不匹配的基础项，失败和错模型诊断仍然展示。

## 验证

- 请求失败评分回归：基础成功分数和分母均为 0，可信账户原始失败不改变目标得分和级别。
- 探针重试回归：瞬态错误恢复后基础成功项不落报告，持续失败仍保留并判 `unavailable`。
- 严格模型匹配回归：错误模型仍判 `suspicious`，合法映射不误报。
- quick/full 与可信对比完整回归：成功基础项不生成，目标评分和对比结论正常。
