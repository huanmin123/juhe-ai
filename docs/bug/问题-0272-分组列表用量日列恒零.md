# 问题-0272：分组列表"用量(日)"列恒 0

- 编号：BUG-0272
- 状态：已修复（2026-10-03），待发布
- 发现：BUG-0269 后的全量排查（UI←数据源可达性审计）。

## 现象

管理面/用户面分组列表"用量(日)"列恒显示 0/0/$0：前端 `groupPageConfig.ts:62` 列存在、`groupDisplay.ts` 读 `stats.todayUsage`；Go `AccountStats.TodayUsage/Usage` 从未被真实 hydrate。且 `group_account_stats` 行存在时 `accountStatsFromGroupRow` 整体替换空形状，连零值 key 都缺失（Node 恒返回 emptyAccountUsageSummary 形状）。

## 根因

`internal/groups/stats_reader.go` 注释自认"TodayUsage/Usage 由 usage-summary hydrate 单独供给，这里保持零值"，但该 hydrate 在 Go 从未实现（`rg loadGroupUsageSummaries` 仅命中注释）。文档契约早已存在：`docs/functions/统计指标与分层聚合设计.md:40/496-497`（分组维度 `group`/`group_authorization`；累计读 `usage_stats_totals`、今日读 `usage_stats_daily`）——按"文档优先"回正代码。

## 修复

- 新增 `internal/groups/usage_reader.go`：`GroupListUsageSummaries(ctx, scopes, statDate)`，Node `usage-summary-loaders.ts` 语义移植（daily+stat_date / totals 双分支；14 列 VALUES LEFT JOIN + COALESCE；`totalTokens=input+output`；成本列用 `total_cost_usd` 与 Node group loader 同口径；缺行 13 键全零空形状；`lastUsedAt` 仅非 null 出现；复用 `GroupAccountStatsDBReader` 的 `table()/bind()` 双驱动惯例）。
- `store.go`：`WithUsageSource` 端口（nil 零值降级）；`ListPage`/`FindDetail` hydrate；scope 三元组（自有=`group`/分组 ID、授权=`group_authorization`/授权 ID，system_account_id 恒取分组所有者）；`accountStatsFromGroupRow` 改为先铺空摘要再填计数。
- 有意偏差（注释写明）：统计时区缺失/非法回退 UTC（对齐账户面，Node 抛错）；hydrate 失败 warn+空投影（对齐既有 D-38 降级策略）。

## 测试

`usage_reader_pg_dialect_test.go`（ATTACH fixture、daily/totals 分支、跨日隔离、13 键空形状 JSON 键集）、`usage_hydrate_test.go`（today/total、scope 三元组、nil source、失败降级、行存在时 key 非 nil）。集成轮修正：`newUsageHydrateFixture` 补 `resource_authorizations`（真实列形）/`group_authorization_settings`/`group_account_stats`——ListPage/FindDetail 的授权臂 UNION 查询 prepare 需要这三张表，最小夹具缺表导致四个守卫全红；测试种子对齐读取器产物契约（`totalTokens=input+output` 在 `usage_reader.go` 读取器内推导，投影层直通不复算）。
