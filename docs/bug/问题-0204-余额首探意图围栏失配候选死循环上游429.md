# BUG-0204：余额首探意图围栏失配，16 候选被 10 秒级重探 18 小时、上游 429

## 现象

2026-09-27 生产排查"上游余额查询都失败"：

- jobs 日志 `J2 首次余额探测完成 seen:16 executed:16` 每约 10 秒一轮，持续 18 小时以上（`.env` 未配 `JUHE_AI_ACCOUNT_BALANCE_SCAN_INTERVAL`，默认 5s + 抖动）；
- 16 个候选（`balance_query_enabled=0 && balance_query_config_json='{}'` 且到期）的 `balance_query_next_refresh_at` 全部卡在 `2026-09-26T15:26:25Z` 附近不前进；
- 上游被打出 `HTTP 429`（mad.myddns.me 系全部账户）与"余额上游响应不是有效 JSON"（modelgate.app），用户手动测试余额即"查询都失败"；
- 补偿任务 `account-balance-auto-detect-recovery` 08:40–08:45 六轮全部 `selectedCount:2 staleCount:2 outcome:partial`——意图永不收口。

## 根因

`backend-go/projects/jobs/cmd/juhe-ai-jobs/worker_balance_detect.go` 把 `time.Time` 参数直接与业务库 TEXT 列 `balance_query_next_refresh_at`（存 RFC3339Nano UTC 文本）做等值围栏（`CommitDetectionDue` / `EnableDetectedQuery` 的 `AND balance_query_next_refresh_at = ?`，`ListDueCandidates` 的 `<= / > / =` 比较）。驱动端按文本比较，格式永不相等：

- `CommitDetectionDue` 恒 0 行命中 → unsupported 无法收口、retry 无法延后 → 意图永久到期；
- J2 首探循环（`LoadFirstProbe` 读侧用 `::timestamptz` cast 比较，能选中）每轮把 16 个候选全部重探；
- 首探 outcome 的使能链注释指定由本补偿任务推进（J2 不推进 first_probe due），补偿失配即闭环断裂。与 BUG-0196 遗留 #4（非 RFC3339 存量值）同属 due 列格式家族。

## 修复

`worker_balance_detect.go`：

- 新增 `balanceDueText`（RFC3339Nano、UTC、毫秒截断，范式对齐 `business_due.go`）与 `balanceDueColumn(postgres)`（PG 返回 `balance_query_next_refresh_at::timestamptz`，SQLite 返回裸列）；
- `CommitDetectionDue` / `EnableDetectedQuery`：PG 围栏改 `AND balance_query_next_refresh_at::timestamptz = ?`（参数仍 `time.Time`）；写入值（next、updated_at——两列均为 TEXT）统一预格式化文本；NULL 收口语义保持；
- `ListDueCandidates`：PG 分支 due 过滤与游标比较统一 `::timestamptz` cast；SQLite 分支写入与比较同格式文本等值。

## 验证

- 新增回归：纳秒/毫秒两种存储精度围栏命中、毫秒截断写入后二次围栏命中（往返恒等）、收口 NULL、PG fence SQL 文本契约断言；余额族 15 个既有测试 + 新增全部 PASS（`go test ./cmd/juhe-ai-jobs/ -run 'TestBalance|TestWorkerBalanceDetect'`）。
- 发布后预期：补偿任务 staleCount 归零，unsupported 候选被收口（due 清空）、fresh 候选被 enable，J2 首探 seen 降至 0，上游 429 消失。

## 状态

已修复，待发布。

## 遗留（复审 Minor，不漏选候选，非阻塞）

`ListDueCandidates` 的 `ORDER BY balance_query_next_refresh_at ASC` 仍是 TEXT 排序（毫秒截断后同秒内 RFC3339Nano 变长小数的文本序与时间序非严格一致）；游标条件为时间序比较且 `selectedIDs` 去重，不会漏选候选，仅同秒内分页邻接次序非严格时序，后续 PG 分支可一并 `ORDER BY ...::timestamptz`。
