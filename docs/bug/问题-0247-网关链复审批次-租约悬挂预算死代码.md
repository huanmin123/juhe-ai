## 问题概述

- 现象：gatewaydispatch 复审确认五项——重试租约回调生产零消费、并发等待预算永不递减、三处死代码/死分支/死赋值、每次尝试全量 body 拷贝、流式管道每 chunk 双重解析。
- 期望：租约与预算按设计生效，无死代码，热路径无无谓拷贝。
- 实际：见内容清单。
- 影响范围：gateway 派发链（账户锁重试租约、并发等待预算、transport 与流式管道性能面）。

## 内容清单

1. P2：`ReleaseAccountLockRetryLease` 回调生产零消费——attemptoutcomes.go:58/:112/:184/:210 构造并入结果但 chain 层无人调用；upstreamdispatch.go:591/:780 摘走后引擎出口 defer 也无法兜底。"被选中但未协议验证成功"路径重试租约悬挂至 5 分钟（chain_account_locks.go:47 lease 300s），同账户请求空耗墙钟预算；ReturnResponse 分支还缺 ConfirmAccountLockSuccess 字段。
2. P2：`concurrencyRetryWaitBudgetMs` 永不递减——enginehelpers.go:56-58 恒等返回；dispatchsingle.go:143-155/:201-210 丢弃 waitedMs；upstreamdispatch.go:943/:964/:985 三处"重置"成死写。请求级累计预算退化为每次获取独立预算；Node 原语义待 git 历史对照。
3. P3：gatewayupstream 非流式 Reader 管道族死代码（body.go:142-355 仅测试触达）；dispatchsingle.go:444-446 不可达分支；upstreamdispatch.go:907 死赋值。
4. P3：transport.go:487-492 每次尝试 `strings.NewReader(string(body))` 全量拷贝（应 bytes.NewReader）。
5. P3：流式管道每 chunk 双重解析与字符串拷贝（pipe.go:203/:230 + inspector PushText）——大流量再优化项。

## 复现步骤

1. 代码走查确认各调用点（零生产调用的回调与恒等返回的预算函数为静态事实）；
2. 运行时观察面：账户被选中但未协议验证成功后 5 分钟内，同账户请求仍受悬挂的重试租约约束（现象幅度待生产观测确认，本条以代码证据立案）。

## 环境信息

- 分支 / 版本：master
- 数据状态：不涉及数据损坏；租约悬挂为运行态时序问题
- 是否稳定复现：静态事实稳定；运行时影响幅度未量化

## 根因分析

- 表象：多个设计机制未接线或退化。
- 真实根因：见内容清单各项——回调构造后无 chain 层消费方、预算函数恒等返回叠加调用点丢弃 waitedMs、死分支/死赋值、`strings.NewReader(string(body))` API 误用、流式管道双重解析。
- 为什么会发生：迁移与 R3 拆分期多轮改造后的半接线状态遗留；Node 原语义需 git 历史对照后定论。

## 修复方案

- 1：chain 层消费重试租约回调（含 ReturnResponse 分支补 ConfirmAccountLockSuccess 字段）。
- 2：按 Node 原语义对照后恢复预算递减，或按文档先行原则裁决契约后实现。
- 3：死代码/死分支/死赋值清理。
- 4：改 `bytes.NewReader(body)` 消除全量拷贝。
- 5：作为大流量性能优化项单独排期。
