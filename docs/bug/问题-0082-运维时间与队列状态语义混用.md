# BUG-0082 运维时间与队列状态语义混用

## 基本信息

- 编号：BUG-0082
- 状态：已修复（待生产验证）
- 严重程度：P2
- 发现时间：2026-07-14
- 发现方式：用户反馈与生产只读排查
- 模块：前端 / AI 账户 / 使用记录 / 后台任务 / 队列
- 关联计划：PLAN-0096
- 关联 bug：无

## 问题概述

- 账户 tooltip 把主动健康检查、健康成功信号、周期健康计划和冷却复测拼成一条时间线；非候选状态仍显示过期“排队中”。
- PG 真实成功只更新成功信号、不顺延下次健康复核，与 SQLite 和设置说明不一致。
- 后台任务有 lastError 仍显示“空闲”；队列把累计失败永久当当前异常；“时间”列混用下次运行和最近写入成功。
- Go RFC3339Nano 的 4-9 位小数又会被前端严格解析误报时间格式异常。

## 根因与修复

- tooltip 改为“最近主动健康检查 / 最近健康成功信号 / 下次健康复核”，只有 active / pending_test 显示周期计划；冷却态只显示冷却复测，停用 / 异常隐藏未来计划。
- PG usage 副作用复用间隔和稳定 jitter 顺延计划；设置读取使用 60 秒进程快照、显式失效和失败短退避，不给每批成功 usage 增加 Redis RTT。
- 历史 24 小时冷却计划不会因代码升级自动改写；发布时只对仍满足系统生成计划精确条件的记录做有备份、可对账的缩短，避免把展示修复误当成历史数据已恢复。
- 任务显示“上次失败”；队列拆当前异常和历史“曾失败”；调度 / 写入单元格明确时间来源。
- 时间解析支持合法 RFC3339 1-9 位小数和时区偏移，仍拒绝非法日期和无时区文本。

## 下次遇到

- 时间字段必须标注事实来源和是否仍可执行；不能把旧计划、被动信号和主动任务拼成同一时间轴。
- 累计失败只能作为历史诊断，当前异常必须由 backlog、lastError 或当前运行事实决定。
