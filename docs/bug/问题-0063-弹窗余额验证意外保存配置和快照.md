# BUG-0063 弹窗余额验证意外保存配置和快照

## 现象

新增或编辑 AI 账户时，余额配置区域使用“保存并查询”交互。编辑已有账户点击后，后端会立即保存当前余额配置、删除旧余额快照并执行正式刷新；新增账户则不能在保存前验证。

## 根因

弹窗验证复用了正式账户余额刷新接口。该接口为了让未开启账户也能查询，接收 `balanceQueryConfig` 后直接写账户配置并清理快照，导致“临时测试”和“保存配置/正式刷新”职责混在一起。

## 修复

- 新增独立草稿余额测试接口，接收当前未保存账户草稿与余额查询配置。
- 草稿测试复用当前 Base URL、单 API Key、账户代理和适配器，但不领取正式刷新租约、不写账户配置、不写调度时间、不删除或保存余额快照。
- 新增和编辑表单统一调用草稿测试接口；正式刷新接口不再接收临时配置。
- 弹窗移除结果卡片与“保存并查询”，简化为“仅验证当前配置，不会保存”和“测试查询”按钮；结果只通过顶部消息提示。
- 用户点击账户保存后才持久化余额配置，后续查询由后台任务或列表正式刷新完成。

## 验证

- 前端余额专项回归通过，确认弹窗不保留测试结果、不调用正式刷新接口。
- 后端余额专项回归通过，确认草稿测试不写正式余额快照，余额路由不再保存配置或删除快照。
- `pnpm typecheck` 和 `pnpm build` 通过。
- 本地真实组件渲染验证中，“测试查询”只显示顶部“余额查询成功：$7.31”，表单内结果 Alert 数量为 `0`；375px 移动宽度无横向溢出。

## 下次遇到

- 所有“测试/验证”按钮先明确是否允许改变持久化状态；默认应无副作用。
- 草稿验证应使用独立 endpoint 和草稿 DTO，不能为了复用正式写接口增加隐式保存分支。
- 正式刷新只读取已保存配置；配置写入只能发生在账户保存流程。
