# BUG-0094 AI 问答初始化失败遗留活动轮次

## 基本信息

- 状态：已修复（回归验证）
- 严重程度：P1
- 模块：后端 / AI 问答 / 事务 / SSE
- 发现时间：2026-07-13
- 关联计划：PLAN-0103

## 现象与触发条件

历史实现先在事务中接受用户消息和 streaming 助手占位，再执行上下文读取或请求体构造；这些步骤在 `message.started` 前失败时，可能遗留 `active_turn_id` 和永久 streaming 助手消息，阻塞后续发送。

## 根因

旧路径把仍可能失败的异步初始化放在“接受轮次”之后，只处理上游流错误，没有让接受事实与 generation runner 的所有权同步建立。

## 修复与验证

当前路由已把历史读取、上下文压缩、transport 构造和请求体字节预算全部移到 `acceptChatTurn` 前；接受成功后在外层路径不再执行任何 `await`，而是同步调用 `registry.start(runner)`。登记失败会直接调用 `failChatTurn`，返回 `409 chat_stream_conflict`，不发起额外上游请求；登记成功后的生成失败由 runner 内部统一终结。原先只被回归脚本直接调用、生产路径没有引用的 `initializeAcceptedChatTurn` helper 已删除。

`chat-routes-contract-regression.ts` 使用 TypeScript AST 定位 stream 路由中的 `acceptChatTurn` 与 `registry.start`，跳过 runner 内部嵌套函数，并断言两者之间的外层路径不存在 `AwaitExpression`，避免源码排版变化使门禁失真。

## 防复发

凡是在持久化“活动状态”后还会执行的可失败准备，应优先移到接受事务之前。接受后必须同步建立后台 runner 所有权；无法建立时立即终结本轮并清除活动状态，不能继续调用上游或伪报已收口。
