# BUG-0094 AI 问答初始化失败遗留活动轮次

## 基本信息

- 状态：已修复（回归验证）
- 严重程度：P1
- 模块：后端 / AI 问答 / 事务 / SSE
- 发现时间：2026-07-13
- 关联计划：PLAN-0103

## 现象与触发条件

服务端已在事务中接受用户消息和 streaming 助手占位后，如果上下文读取或请求体构造失败，路由会在 `message.started` 前退出，可能遗留 `active_turn_id` 和永久 streaming 助手消息，阻塞后续发送。

## 根因

“接受轮次”和“初始化上游请求”是两个阶段，旧路径只处理上游流错误，没有为接受后的初始化失败提供统一终结边界；终结本身失败时还可能覆盖原始错误。

## 修复与验证

新增 `initializeAcceptedChatTurn`：初始化失败时先把已接受轮次终结为 `chat_initialization_failed`；若终结也失败，抛出同时保留两个 cause 的 `AggregateError`。repository 与 route contract 回归覆盖初始化失败、终结失败和后续可再次发送。

## 防复发

凡是在持久化“活动状态”后还会执行可失败步骤，都必须定义补偿终结；补偿失败不能吞掉原始错误，也不能伪报已收口。
