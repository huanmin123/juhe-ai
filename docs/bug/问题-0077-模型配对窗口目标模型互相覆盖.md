# BUG-0077 模型配对窗口目标模型互相覆盖

## 问题概述

- 现象：同一账户的 Sol、Terra、Luna 使用同一个三模型 `pair_key`，三个 target model 的 paired 距离和 LOO 区间依次覆盖同一窗口行。
- 期望：`pair_key` 表示对照模型集合，`requested_model` 表示本次计算的目标模型；两个维度必须同时保留。
- 实际：表主键和 upsert 冲突键没有 `requested_model`，最终窗口值取决于账户模型遍历顺序。
- 影响范围：本批首次上线的 `model_paired_similarity_windows` 预聚合事实；账号 latest 本身按模型分行，未受覆盖影响。

## 根因分析

- paired 计算以 `requestedModel` 为目标，`pairedDistance`、群体 LOO 中位数、MAD 和 Q10 都是 target-specific。
- 存储表却只用 `(account, population, pairKey, featureVersion)` 标识行，把同一个模型集合误当成单一目标结果。
- 这是存储主键维度缺失，不应通过调整遍历顺序掩盖。

## 修复方案

- SQLite 当前 schema 增加非空 `requested_model`，并纳入 paired window 主键。
- PostgreSQL schema 继续由同一 schema 源生成，保持列和主键一致。
- upsert 写入目标模型，并把 `requested_model` 纳入 `ON CONFLICT`。
- 回归固定同一账户、同一三模型 `pair_key` 必须同时存在 Sol、Terra、Luna 三行。
