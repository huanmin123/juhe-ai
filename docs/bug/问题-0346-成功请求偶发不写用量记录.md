# BUG-0346 成功请求偶发不写用量记录（审计 finalized/complete 但 usage_records 无行）

## 基本信息

- 编号：BUG-0346
- 状态：待修复
- 严重程度：P2
- 发现时间：2026-11-03
- 发现方式：自查（审计与用量记录按 trace 对账）
- 模块：网关（成功终局记账）
- 关联计划：无
- 关联 bug：无
- 责任人：网关维护者

## 问题概述

- 现象：部分 trace 在审计表为 `success` / `finalized` / `complete`、`attempt_count>=1`、`final_status_code=200`，但 `usage_records` 无任何对应行。
- 期望：成功完成的上游尝试必须写一条用量记录（[模型价格与用量统计口径](../functions/模型价格与用量统计口径.md) §2「成功完成的上游尝试在写入使用记录时按同步定价目录估算」）。
- 实际：该 trace 完全无用量行，客户端请求与成本事实丢失。
- 影响范围：极低频（近 7 天 1 条确认案例），但一旦命中即整条丢失，且无告警。

## 复现步骤

1. 发起一次 chat 请求，上游正常返回 200 并完成。
2. 审计行写入 `success` / `finalized` / `complete`。
3. 查 `usage_records`：无该 `trace_id` 的行。

## 环境信息

- 分支 / 版本：Go 网关（`backend-go/projects/gateway`），生产国内单机 Docker 现行版本。
- 数据状态：近 7 天 8 条成功 trace 无用量行；其中 7 条为 `capture_status='metadata_only'`、`attempt_count=0`（采样审计，无真实上游尝试，属预期不记账）；**1 条为 `complete` + `attempt_count=1` + `200`，属真实缺口**。
- 是否稳定复现：否（低频偶发）。

## 根因分析

- 表象：审计完整但用量缺失。
- 真实根因：**未定位**。已排除：
  - 不是采样（`capture_status='complete'`，非 `metadata_only`）；
  - 不是内部通道抑制（`api_key_id` 为空才是内部通道；该 trace 的 `api_key_id` 为空，**这一点需重点复核**——见下）；
  - 不是探针流量（`traffic_source='gateway'`）。
- 关键线索：该 trace（`b0ba6b29-6b88-4179-a3b0-9f370a44d790`，2026-11-02 22:08:34，`gpt-6-luna`，`/v1/chat/completions`，attempt 1 次 200、`duration_ms=5158`）的 `api_key_id` 为空、`system_account_id='sysacc_1777763935822_2461196e'`。`api_key_id` 为空同时是「内部通道（AI 问答免 Key 直调）」的特征（`chain_v1.go:183` 置 `req.SuppressUsage = true`），而内部通道按设计**丢弃**全部用量记录（`gatewaypreflight`/`chain_usage.go:127` 抑制闸口）。因此该条更可能是「内部通道正常抑制」而非缺陷——但审计行未带任何抑制标记，无法从数据面区分，属可观测性缺口。
- 待确认：是否存在「非内部通道 + api_key 为空 + 成功 + 无用量」的组合。

## 修复方案（待确认后定）

- 第一步（取证，不改行为）：确认该 trace 是否属内部通道。判定方式：查 `system_account_id` 是否配置了内部通道（AI 问答免 Key）身份，或补审计字段。
- 第二步（可观测性）：审计行增加 `suppress_usage` / `internal_channel` 标记，使「按设计不记账」与「意外丢记录」在数据面可区分——当前二者都表现为「无用量行」。
- 第三步（如确认是缺陷）：在 `chain_usage.go` 的成功记账入口补「已抑制 vs 未抑制」的计数与告警，并对 `api_key_id` 为空但非内部通道的路径显式拒绝/告警。
