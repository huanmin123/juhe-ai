## 问题概述

- 现象：账户、API Key 及多个管理弹窗在用户没有展开下拉时请求候选全集；列表、编辑和 PATCH 又复用宽摘要，读取和覆盖大量无关字段。
- 期望：列表只取显示字段；编辑只取表单字段；候选只在下拉交互时加载；保存只提交并更新实际变化字段。
- 实际：前端首开预取 options，Node 经常完整查询后裁剪；单字段修改仍触发宽校验、全列 UPDATE、关联表重写和大范围缓存失效。
- 影响范围：页面延迟、数据库 / DB service / stats 负载、JSON 解析、Vue 响应式成本、并发丢更新风险及统计域故障对写接口的放大。

## 复现步骤

1. 打开“我的 AI 账户”新增弹窗，不操作任何控件。
2. Network 可见分组和供应商模型 options；代码还会预取标签和刷新供应商定义。
3. 打开 API Key 新增或编辑弹窗，可见策略路由 options。
4. 仅修改 API Key 说明，Node 仍读取多次完整摘要、全列更新并重建额度窗口。

## 根因分析

- 表象：页面为了默认值和回显提前加载下拉数据。
- 真实根因：`Summary` 同时承担列表、编辑、运行态、options 和写入结果；前后端没有把“场景所需字段”落实到 repository 和写命令。
- 为什么会发生：历史 DTO 分层只在类型 / sanitizer 层部分落地，查询仍物化完整对象；PATCH 虽字段可选，前端仍发全表单，后端仍按完整 next 快照写回。

## 修复方案

- 修改点：按 [设计文档](../superpowers/specs/2026-07-28-Node管理接口按需读写设计.md) 拆分场景 DTO、用户引用缓存、交互按需 options 与字段级写入。
- 行为影响：首开请求减少；默认资源由缓存或 Node 当前事实解析；编辑保存增加版本冲突保护。
- 发布异常处理：缓存失败不阻塞弹窗；options 可在用户展开时重试；PATCH 冲突明确提示刷新后重试。

## 修复范围说明

- 本次只修改 Node 后端与 Vue 前端；Go 不修改、不对齐，也不纳入验收。
- 人工测试批量模型接口严格返回 `{ id, name }`；请求形态只由当前模型 capabilities 接口按交互返回。
- `configRevision` 对任何真实业务变化都推进；运行态、探针、额度窗口和缓存副作用仍按变化字段分类，展示字段不得触发无关副作用。
