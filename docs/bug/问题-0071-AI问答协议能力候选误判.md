# BUG-0071 AI 问答协议能力候选误判

## 基本信息

- 状态：已修复（Mock 验证）
- 严重程度：P1
- 模块：后端 / AI 问答 / 网关 / 协议能力
- 发现时间：2026-07-13
- 关联计划：PLAN-0094

## 现象与触发条件

API Key 同时能枚举到候选账户，但目标模型实际只支持 Chat Completions 时，聊天传输层可能把候选非空误认为 Responses 可用，导致选择错误协议或无法正常对话。

## 根因

协议探测只检查候选数组长度，没有验证账户 `supportedEndpointModes`，也没有把本轮模型映射后的上游端点族纳入判断。候选筛选与协议能力不是同一个事实。

## 修复与验证

按 `chat_completions`、`responses` 分别加载候选，并逐账户校验实际端点模式；存在启用的模型映射时，以映射后的上游端点族为准。`test:chat-transport` 覆盖直接能力以及 Responses 到 Chat、Anthropic Messages、Gemini GenerateContent 的映射，`test:chat-gateway-mock-ai` 通过独立 Chat-only / Responses 账号验证两条完整 HTTP 链路。

## 防复发

任何协议路由都必须区分“候选可见”“模型可映射”“端点真实支持”三层事实；不能用候选非空替代能力判断。
