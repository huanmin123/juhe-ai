# BUG-0071 AI 问答协议能力候选误判

## 基本信息

- 状态：已修复（Mock 与浏览器验证）
- 严重程度：P1
- 模块：后端 / AI 问答 / 网关 / 协议能力
- 发现时间：2026-07-13
- 关联计划：PLAN-0094、PLAN-0095

## 现象与触发条件

API Key 同时能枚举到候选账户，但目标模型实际只支持 Chat Completions 时，聊天传输层可能把候选非空误认为 Responses 可用，导致选择错误协议或无法正常对话。

## 根因

协议探测只检查候选数组长度，没有验证账户 `supportedEndpointModes`，也没有把本轮模型映射后的上游端点族纳入判断。候选筛选与协议能力不是同一个事实。

## 修复与验证

按 `chat_completions`、`responses` 分别加载候选，并逐账户校验实际端点模式；存在启用的模型映射时，以映射后的上游端点族为准。`test:chat-transport` 覆盖直接能力以及 Responses 到 Chat、Anthropic Messages、Gemini GenerateContent 的映射，`test:chat-gateway-mock-ai` 通过独立 Chat-only / Responses 账号验证两条完整 HTTP 链路。

## 防复发

任何协议路由都必须区分“候选可见”“模型可映射”“端点真实支持”三层事实；不能用候选非空替代能力判断。

## 复发记录：模型列表暴露不可路由模型

- 时间：2026-07-13
- 现象：`/my-chat/conversations/:id/models` 显示 `gpt-5.6-sol`，但绑定账户只支持 `gpt-5.5`；发送后网关返回 `unsupported_model`。
- 根因：调度候选窗口为了排序会把精确模型候选与普通候选合并，真正网关随后还会按 `supportedModels` 和模型映射过滤；聊天能力探测只验证端点模式，没有复用模型约束。
- 修复：聊天传输账户能力同时校验 `supportedModels`；直接请求必须命中模型，映射请求必须让 `upstreamModel` 命中支持列表。模型列表和发送入口共用同一判断。
- 验证：`test:chat-transport` 覆盖受限模型和跨协议映射，`test:chat-gateway-mock-ai` 验证模型列表不再暴露不可路由项，浏览器实际新建 Mock Key 会话只显示 `gpt-5.5` 并成功完成图片对话。
