# BUG-0256：模型检测管理面未授权报错吞没真实原因与 dev 自动登录缺失

- 状态：已修复（2026-10-01，待发布验证）
- 定性：行为缺陷修复 + 契约对齐（鉴权失败错误契约、cookie 语义、dev 自动登录覆盖面均对齐主面 authsys 既有行为，非新契约；设计文档已同步）
- 发现方式：用户生产报障（2026-10-01，「生产上管理员不能访问模型检测、普通用户可以」）+ 本地隔离实例复现（自动登录形态下 J3b 面全 401）

## 1. 现象

双场景：

- **生产误判**：管理员访问模型检测页，接口返回笼统文案「模型检测管理请求未授权」，用户据此误判为「管理员没权限」；同库同会话源的主管理面页面正常，普通用户自助面正常。
- **本地隔离实例全 401**：隔离开发实例按 `JUHE_AI_DEV_AUTO_LOGIN_USERNAME=admin` 自动登录形态启动时，模型检测管理面与自助面全部 401，而主面页面可用（模型检测页无法在标准隔离实例上联调）。

## 2. 取证

生产（只读取证，未做任何写操作）：

- **env / 部署链**：J3b 认证器（`modelcheckauth`）与主面 authsys 共用同一业务库 `system_sessions` / `system_accounts`，未配置独立账户源；生产部署、库、角色均正常，`sys_admin` 为 `super_admin`——排除部署与角色配置问题。
- **DB 会话时间线**：admin 会话最后活动 2026-09-29 17:22，报障当日无新 admin 登录；报错发生时请求未携带有效会话（旧标签页 / 失效 cookie 场景）。
- **未认证请求实测**：生产对管理面与主面同发未认证请求，两面均 401——「普通用户可以」实为普通用户持有有效会话，非角色差异。
- **日志缺口**：管理面请求不落任何访问日志（Caddy 无 access log，网关访问日志只覆盖 `/v1` 链），事后无法回放报错时刻状态码，只能靠 DB 会话时间线旁证。

代码链（缺陷定位）：

- `modelcheckowner/http.go` `ServeHTTP` 把所有鉴权失败统一写成 401/403 + 笼统文案「模型检测管理请求未授权」，无凭证、令牌非法、会话过期、角色不足四类原因对外不可区分。
- `modelcheckauth/auth.go` `resolveToken` 取 Cookie 头里**第一个** `juhe_ai_session`；主面 `authsys.ParseCookie` 组装同名 map 为 **last-wins**——重名 cookie 时两面对同一请求判定不同。
- J3b 两面 `Authorize`（`modelcheckowner/http.go` `NewAdminAuthorize`/`NewSelfAuthorize` → `Authenticate`）无 dev 自动登录回退；主面 `authsys` sessionMiddleware 在无凭证时按 `JUHE_AI_DEV_AUTO_LOGIN_USERNAME` 注入开发身份（生产 fail-fast 门禁在 `cmd/juhe-ai-gateway/runtime.go` 已有）。

## 3. 根因

1. **鉴权失败原因被吞没**：J3b 自立笼统文案，401（会话问题）与 403（角色问题）混成同一句话——生产误判由它直接放大，也是事后排障只能靠 DB 时间线旁证的直接原因。
2. **cookie 解析分叉**：first-wins 与主面 last-wins 不一致，重名 cookie 请求两面判定不同，属与主面契约偏离。
3. **dev 自动登录未覆盖 J3b 面**：本地隔离实例（自动登录形态）下 J3b 两面恒 401，模型检测页无法在标准隔离实例上使用，进一步放大「模型检测打不开」的困惑。

## 4. 修复

三条对应根因，契约同步落 `docs/functions/模型检测设计.md`：

1. **鉴权失败错误契约对齐主面 authsys sessionMiddleware**：

   | 场景 | 状态码 | 文案 / code |
   | --- | --- | --- |
   | 无凭证（`ErrLoginRequired`） | 401 | 请先登录 |
   | Authorization 头格式非法（`ErrInvalidToken`） | 401 | 访问令牌无效或已过期 |
   | 会话不存在 / 过期（`ErrSessionExpired`） | 401 | 登录会话已过期 |
   | 已认证但角色非 admin/super_admin（`ErrForbidden`，仅管理面） | 403 | 需要管理员权限 |
   | must_change_password（`ErrMustChange`） | 403 | code `must_change_password`（行为不变） |
   | 其余未预期错误（如 DB 故障） | 500 | 服务器内部错误 |

2. **cookie 解析统一 last-wins**：两面 `juhe_ai_session` 解析与主面 `authsys.ParseCookie` 一致取最后一个同名 cookie；同名 cookie 值为空或解码失败立即按无凭证拒绝（fail-closed），不继续尝试更早的同名 cookie。

3. **dev 自动登录覆盖 J3b 两面**：与主面同一 `JUHE_AI_DEV_AUTO_LOGIN_USERNAME`、同一生产 fail-fast 禁用门禁（不新增环境变量）；仅在请求完全无凭证时回退注入配置用户名对应 active 账号的开发身份（不建会话，不做 must_change_password 拦截，与主面 developmentAutoLogin 一致）；有凭证但无效 / 过期时不回退，保持真实错误；管理面回退后仍要求 admin/super_admin 角色（否则 403「需要管理员权限」），自助面接受任意 active 账号。

## 5. 验证

- 定向回归（backend-go/ 下）：`go test ./projects/gateway/internal/modelcheckauth/... ./projects/gateway/internal/modelcheckowner/... -count=1`，覆盖错误映射、last-wins、dev 回退与不回退边界。
- 隔离实例端到端：
  - 未配 dev env 时，无 cookie 访问 `/__aisys__/api/model-checks/options` → 401「请先登录」；
  - 配 `JUHE_AI_DEV_AUTO_LOGIN_USERNAME=admin`（admin 角色为管理员）时，无 cookie 访问同路径 → 200；
  - 携带无效 Authorization 头访问 → 401「访问令牌无效或已过期」（不回退 dev 身份）。
- 真实管理员登录端到端（2026-10-01 已完成，隔离实例 + 浏览器）：真实密码登录（admin 首登改密后）建立真实 `juhe_ai_session` 会话，浏览器内访问 `/__aisys__/model-checks` 管理页完整渲染（模型选项、历史列表数据正常加载），无登录页跳退；后端日志整个会话零 `j3b_auth_denied`（仅无 cookie 对照组 1 条）。
- 生产验证（发布后）：旧标签页重试应看到明确文案（「登录会话已过期」或「请先登录」），重新登录后管理面可用。

## 6. 遗留观察项

两项收尾已随本交付完成（2026-10-01）：

- **cookie 残余统一 last-wins**：`modelcheckauth` 包内最后一个 first-wins 解析（独立 listener `/auth/` 登录面的 `cookieToken`）已删除手写循环，改为委托 `resolveToken` 的 cookie 分支；三处入口（管理面 / 自助面 / `/auth/` 登录面）last-wins + fail-closed 语义完全一致。
- **鉴权拒绝已落进程日志**：J3b 面鉴权拒绝（must_change_password、空 actor id、各哨兵 401/403 与 500 兜底）现以结构化 Warn 日志输出（`event=j3b_auth_denied`，含 method/path/status/reason/remote，不记录任何 token/cookie 值），排障不再只能靠 DB 会话时间线旁证。

仍开放：全量管理面访问日志（Caddy access log 或网关通用管理面请求日志）是否补充属另行任务——现仅鉴权拒绝有日志，正常请求与鉴权通过后的 4xx/5xx 仍无访问日志可回放。
