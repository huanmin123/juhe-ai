## 问题概述

- 现象：BUG-0330 修复表单渲染后，新建账户点击「创建」会被后端 400 拒绝：`创建载荷缺少 connections：必须显式提交非空连接集合（connectionPresetCode/baseUrl/endpointModes/enabled）`；基础编辑固定发送 `healthCheckModel` + `healthCheckEndpointMode` 两项、高级编辑在健康检查字段变化时增量只含子集，均报 `健康检查三件套（healthCheckConnectionPresetCode、healthCheckEndpointMode、healthCheckModel）必须同时出现或同时省略`。
- 期望：新建/编辑账户按目标契约提交 `connections[]` 与 `healthCheckConnectionPresetCode`。
- 实际：前端 `buildAccountSavePayload` 仍发送 `providerCode/type/credentials(base_url/supported_endpoint_modes)` 旧形状；`buildAccountUpdatePayload` 只发送健康检查三件套中的两项，`buildAccountBasicEditSnapshot` 也没有 preset。
- 影响范围：生产对话域 API Key 账户的新建与编辑（`POST /accounts`、`POST /my-accounts`、`PATCH /accounts/{id}`）。账户列表、人工测试、克隆上下文读取不受影响。

## 复现步骤

1. 打开「添加账户」，选择供应商并填写凭证与支持模型。
2. 点击「创建」。
3. 后端返回 400「创建载荷缺少 connections」。

## 根因分析

- 表象：创建请求体没有 `connections`；完整编辑 PATCH 只有 `healthCheckEndpointMode` 与 `healthCheckModel`。
- 真实根因：B4 收尾（`3b4dd5cb9`，2026-10-19）把创建链改为 `resolveConnectionSet` 强制非空连接集合，健康检查三件套强制同现；同批只完成了后端契约与 `providerProtocolProfileId` 停发，前端载荷迁移（§9.3 新契约）未完成。`accountSavePayload.ts` 的 `AccountSavePayload` 类型没有 `connections`/`healthCheckConnectionPresetCode` 字段。
- 为什么会发生：发布节奏先落后端、后落前端；`accountSavePayload` 的注释按「后端已接受新契约」描述，但实际建户请求仍走旧形状。

## 修复方案

- 修改点：
  - `frontend/src/shared/providerProtocol.ts` 新增 `connectionPresetCodeForProfile`：协议档案 id → 连接预设 code 的过渡映射（覆盖九家厂商 14 个档案；hybrid 无 preset 不在映射内）。
  - `frontend/src/views/accounts/accountSavePayload.ts`：`AccountSavePayload` 增加可选 `connections` / `healthCheckConnectionPresetCode`；`buildAccountSavePayload` 按当前档案、Base URL、`supportedEndpointModes` 生成单连接行（`enabled: true`），健康检查连接复用同一 preset；`buildAccountUpdatePayload` 补发 `healthCheckConnectionPresetCode`。
  - `frontend/src/views/accounts/accountEditPatch.ts`：基础编辑快照按档案补齐健康检查连接 preset（模型为空时三件套整体省略）；高级编辑差量命中任一健康检查字段时补齐三件套当前值，避免部分字段 PATCH 被 400。
  - `frontend/scripts/regression/account-edit-save-flow-regression.ts` 增加创建载荷 `connections` 与健康检查 preset 断言。
- 行为影响：API Key 新建/完整编辑恢复；OAuth 托管创建走独立端点不受影响；`connections` 只在创建载荷出现，PATCH 仍不整集合替换。
- 发布异常处理：与 BUG-0330 同批发布前端；若回滚需同时回退两处。
