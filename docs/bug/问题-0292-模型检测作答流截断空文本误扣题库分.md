# 问题-0292：模型检测作答流被首轮预算截断，空文本交裁判误扣题库满分

## 基本信息

- 编号：BUG-0292
- 状态：已修复，待发布
- 严重程度：P1（生产确定性误扣题库满分并联动质量处罚面；慢流/长作答账户每次检测必现）
- 发现时间：2026-10-07
- 发现方式：生产检测记录取证（作答流活跃输出被截断）+ 代码/文档契约比对
- 模块：`gateway/internal/modelcheckprobe`（probe.go 传输层读取 × retry.go 定论判定 × quiz.go 题库评分边界）
- 关联文档：`docs/functions/模型检测设计.md`（§1.2 读取完整性条款、§5.7 题库两跳契约）

## 问题概述

- 现象：模型检测题库（custom_quiz）作答请求收到 HTTP 200 后流式持续输出，生产实测约 47KB 活跃输出在首轮 attempt 预算（当时为 10s，现 20s/30s/40s）到点被中断读取；已读数据被整体丢弃，`Output` 为空但 `HTTPStatus=200` 保留。该"空文本 200"被当作质量定论不重试，空 Output 被注入裁判请求，裁判判 `fail` → 该题 `failed` 0 分；单题权重 31（`QuizMaxPool`）→ 环节扣满 31 分，并按 §5.7 联动质量判定与处罚阈值。
- 期望：作答流仍在活跃输出时被探针自身预算截断，属于传输面请求失败（本级预算到点），不是模型作答质量失败——应保留已读部分作为证据、按重试阶梯晋级更大预算重试；重试耗尽仍不完整时按请求失败终态（题库族 → skipped + `excludedFromScoring` + 家族 terminal，不扣分）。
- 实际：读取中断丢弃已读数据 + 200 即定论不重试 + 200 非家族终态三重叠加，把"没读完"伪造成"答错了"，部分输出甚至空文本直接进入评分与裁判链。
- 影响范围：custom_quiz 作答/裁判两跳（误扣满分 + 处罚联动）；核心协议探针与各家族的同类截断同样被 200 定论挡住晋级（重试阶梯对"HTTP 200 但读不完整"完全不生效）。

## 根因分析

根因链（修复前锚点）：

1. `probe.go:562-570`：`io.ReadAll` 出错时整体丢弃已读数据（生产实测约 47KB），`Output` 空、`HTTPStatus=200` 保留、`ErrorMessage="J3b upstream response read failed"`。
2. `retry.go:90-95`：定论分支 `result.HTTPStatus == http.StatusOK` 视 200 为质量定论，不区分响应体是否完整读取——阶梯晋级对截断态完全不生效。
3. `retry.go:104-110`：`isTerminalProbeFailure` 对 200 一律返回 false → 家族不 terminal，题库主循环继续走评分路径。
4. `quiz.go:87-94`：作答 hop 不检查 `result.Success`/`ErrorMessage`，把空 Output 直接注入 `quizGradingRequest`。
5. `quiz.go:196-216`：裁判对空答案判 `fail` → `failed` 0/该题满分。
6. `summary.go:26-30` + `quiz.go:15`：`failed` 且无 `excludedFromScoring` → 扣 Σ(分值−得分)，单题即扣满 31 分。

## 与 BUG-0287 的同构关系与边界

- 同构：`shared/platform/accounttest/accountprobe/probe.go:537-565/:612-672`（BUG-0287 修复）已确立同一根因的三分流形态——分块 Read 循环保留已读体、中断/到点均返回部分体、本级预算到点 + 缺证据 + 无可解析上游错误码 → 改判探针超时晋级阶梯、真实中断保持 read_incomplete、已读内容语义成功可胜出；参考测试 `probe_budget_timeout_test.go`。
- 边界：BUG-0287 只修了 accountprobe（账户测试/健康检查面）；modelcheckprobe 的同形态读取路径未移植（89fe9b8ed 只同步了本包 retry.go 的阶梯数值 20/30/40），且 modelcheckprobe 的消费面后果不同——accountprobe 是负向证据记冷却，modelcheckprobe 题库族是误扣分进评分。

## 修复方案（三层）

1. **传输层（probe.go `Execute`）**：`io.ReadAll` 改分块读取循环（对齐 accountprobe `readUpstreamWithClient` 形态），读错误与本级预算到点都保留已读 buffer；readErr 时先对已读体跑 `parseResponseDetailed`——已读内容语义完整（完整可解析 JSON，或 SSE 流已出现终态事件，复用 `isResponseTerminalEvent`）且无流内失败信封 → 按完整响应正常判定（覆盖"终态事件已收到但连接未干净关闭"）；否则 `Result.Incomplete=true`（新增字段：响应体未完整读取，传输面失败，非质量定论），Output 填尽力解析的部分文本（排障证据，非判分输入），ErrorMessage 分类对齐 Do 阶段（预算到点 → `J3b probe timed out`，其余 → `J3b upstream response read failed`）。超限分支与完整读取路径行为不变。
2. **重试层（retry.go）**：200 定论收敛为 `HTTPStatus == 200 && !Incomplete`——Incomplete 200 消耗阶梯晋级下一级更大预算；`isTerminalProbeFailure` 同步收敛，末轮 Incomplete 200 判家族 terminal（对齐 §5.7/§1.2 请求失败口径），完整 200 语义失败仍非 terminal 不回归。
3. **评分边界（quiz.go）**：`quizRequestFailureEvaluation` 在 `result.Output` 非空（部分作答文本）时 evidence 增加 `answerExcerpt`（复用既有摘录函数）——证据留存对齐 BUG-0287"部分体保留"精神，不参与判分。题库主循环经核实零改动即正确：修复后 Incomplete 结果只可能以末轮（terminal）形态逃出 `ExecuteWithRetry`，`familyTerminal()` 必然命中，`quizRequestFailureEvaluation` 走 skipped + `excludedFromScoring`，不再把空 Output 送裁判。

## 裁决：明确不做 idle（无进展）超时

本次只按"本级预算到点/读错误"两个截断源处理，不新增"流式空闲 N 秒无新字节即判失败"的 idle 超时：探针已有明确的本级总预算（20/30/40s）兜底，idle 超时会引入第二个可调超时维度（N 取值无契约依据、与阶梯总预算叠加后语义难解释），且生产案例是"活跃输出被总预算掐断"，不是"静默挂起"；维持单一预算口径，慢流由阶梯晋级覆盖。

## 后续观察
