# BUG-0325：无效模型派发耗尽报「路径或客户端协议」错误（503，语义错乱）

- 状态：已修复（2026-10-17）
- 级别：P2（错误语义与可重试性双重错乱，排障方向误导；功能本身有兜底响应不挂）
- 发现：2026-10-17 火山方舟全协议真实网关测试（F 批健壮性负例）

## 现象

向 `/v1/chat/completions`、`/v1/audio/speech` 等统一面发送**分组内无任何账户声明**的模型名（如 `not-a-real-model`），网关返回：

```
HTTP 503
{"error":{"code":"endpoint_mode_unsupported","message":"当前分组无账户支持请求路径或客户端协议","type":"service_unavailable"}}
```

客户端与排障者得到的信息是「请求路径或客户端协议不支持」——与真实原因（模型不被任何账户支持）完全无关；503 `service_unavailable` 还暗示可重试，实际重试无益。

## 根因（两层折叠叠加）

1. **per-account 原因折叠**：`gatewaydispatch/candfilters.go` 的 `FilterGatewayAccountsByRequestCapability` 逐账户调用 driver 能力判定（`gatewayRequestCapabilityMismatchReasonFor`，真实原因可能是 `model_unsupported` / `endpoint_mode_unsupported` / 协议门等），但 `AccountSkip.Reason` 被统一折叠为常量 `CapabilitySkipReasonMismatch`——真实原因在过滤器出口即丢失。
2. **全拒聚合取第一个**：全拒后 `result.Reason = driver.GatewayRequestCapabilityMismatchReason(req, accounts)`（`chain_driver.go`）返回**候选顺序第一个账户**的 reason——混编能力域分组（chat/video/audio/image 同组）的第一个账户往往不是被模型拒绝的那个，于是 `model_unsupported` 的特判文案（`candidatefilter.go requestCapabilityMismatchMessage` 的「当前分组无账户支持请求模型：X」）永远轮不到，落到通用分支文案 + 503。

## 修复设计（文档先行声明目标行为）

- `FilterGatewayAccountsByRequestCapability` 的 `AccountSkip.Reason` 带出**逐账户真实 driver reason**（不再折叠）。
- 派发候选耗尽（capability 全拒）时聚合 Skipped reasons：
  - **全部为 `model_unsupported`** → 网关本地终态 **HTTP 404**，`error.code = "model_not_found"`，`error.type = "invalid_request_error"`，message = `当前分组无账户支持请求模型：<请求模型名>`（与既有 `GatewayModelFilterFailureMessage` 选组层文案对齐）——OpenAI 语义对未知模型即 404 `model_not_found`。
  - 否则（存在模型以外的拒绝原因，如端点模式/协议门）→ 维持现状：503 + 第一个 reason 对应的既有文案（混编组的路径/协议语义不受影响）。
- 模型过滤层（`FilterGatewayAccountsByRequestedModel` 之后的耗尽分支）与选组层（`gatewayrouting.GatewayModelFilterFailureMessage`）已有模型区分文案，本次核对状态码与错误码后一并对齐 404 `model_not_found`（若选组层已如此则不动）。
- 不改变任何成功链路、回退链路与重试链路行为；不触碰 gatewayrouting / chain_driver / gatewaypreauth（过滤层之外的文件）。

## 验收标准

1. 分组内账户均声明其他模型、请求无效模型 → 404 + `model_not_found` + message 含模型名。（已满足，见修复记录与 cmd 包跟进）
2. 混编组中存在端点模式/协议拒绝的账户组合 → 维持 503 原语义（不回归）。
3. 既有全链/门控测试零回归（`gatewaydispatch` 包 + `acceptance` 门控套件）。

## 修复记录

（2026-10-17 回填。改动全部在 `backend-go/projects/gateway/internal/gatewaydispatch/` 包内，未触碰 gatewayrouting / chain_driver.go / gatewaypreauth / cmd 包生产代码。）

### 改动文件清单

- `internal/gatewaydispatch/candfilters.go`：`FilterGatewayAccountsByRequestCapability` 的 `AccountSkip.Reason` 改为带出逐账户真实 driver reason——新增 `capabilitySkipReasonForAccount`，经 `ProviderDriver.GatewayRequestCapabilityMismatchReason` 复数端口的单元素切片形态取单账户细分（接口签名与 cmd 实现不动）；driver 单账户判空时回退 `CapabilitySkipReasonMismatch` 常量（client-compatibility 门形态，审计明细 reason 恒非空）。常量保留。
- `internal/gatewaydispatch/candidatefilter.go`：新增 `capabilityModelNotDeclaredFailure`（2026-10-17 修订判据，替换首版 `capabilityAllModelUnsupportedFailure`）——能力全拒时对能力过滤前的**候选全集重跑模型过滤**（`FilterGatewayAccountsByRequestedModel`，与派发后段同一匹配口径），过滤后无任何幸存账户 → 本地终态 HTTP 404，`error.code = "model_not_found"`，`error.type = "invalid_request_error"`，message = `当前分组无账户支持请求模型：<请求模型名>`；存在模型声明命中但被端点/协议拒绝的账户（模型过滤有幸存者）或 requestedModel 为空时维持 503 + `requestCapabilityMismatchMessage` 现状。**修订原因**：首版「Skipped 全部为 model_unsupported」的词面全等判据在混编组失准——chat+video 混编分组请求无效模型时视频账户以 endpoint_mode_unsupported 被拒，词面不全等 → 漏判 404（真实复现：volctest 混编分组 `/v1/chat/completions` model=gpt-never 仍 503）；「全组模型过滤空」判据不依赖 reason 词面，语义为主因分级（模型无效=请求级参数错误 404；模型命中但路径不符=路径语义 503）。顺路把模型过滤层耗尽分支（`FilterGatewayAccountsByRequestedModel` 之后）的渲染从 503 + `unsupported_model`/`missing_model` 对齐为 404 + `model_not_found` + `invalid_request_error`（文案 `GatewayModelFilterFailureMessage` 不变）；`RequestFallback` 的内部 reason 不变。
- `internal/gatewaydispatch/w1b_dispatch_decision_test.go`：`w1bCapabilityDriver` fixture 补齐与 bool 同源的复数 reason 覆写（支持 ⟺ reason 空，镜像 chain driver 端口契约），断言不变。
- `internal/gatewaydispatch/pipeline_test.go`：`TestFilterCandidatesUnsupportedModelMessage` 断言随新契约更新为 404 + `model_not_found`。
- `internal/gatewaydispatch/bug0325_capability_mismatch_test.go`（新增）：过滤器出口逐账户 reason 与判空回退、全模型拒绝 404 契约、混编（模型声明命中但端点拒）503 不回归、混编+模型全组未声明 → 404（真实复现钉）、部分拒绝正常放行五组测试。
