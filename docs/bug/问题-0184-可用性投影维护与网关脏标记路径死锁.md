# 问题-0184：account_list_availability 投影维护与网关脏标记路径 PG 死锁

- 发现时间：2026-09-26（国内单机生产 103.36.63.105 首日复检）
- 影响面：`account-list-availability-projection-maintenance` 后台任务反复失败重试（最多连续失败 18 次，约 30s 一轮）；可用性投影更新偶发延迟。任务有退避重试自愈，非永久性故障，但属于真实并发缺陷。
- 非迁移引入：代码与老 K8s 生产同源，老生产同样存在，只是本次单机日志复查时首次显性记录。

## 现象

- jobs 日志反复出现 `jobsched_run_failed ... ERROR: deadlock detected (SQLSTATE 40P01)`（`account-list-availability-projection-maintenance`，consecFail 最高 18）。
- 同族死锁也出现在 `J3a proxy execution failed ... 写入 J3a Go proxy state 失败`。
- 另有 3 条 `账户列表投影 acc_xxx generation N 无法确认删除`（同族或独立 fence 问题，待定位）。

## 死锁对立双方（PG 日志 24h 聚合）

- 一方（jobs 维护任务，351 次）：
  `... WHERE account_id = $1 AND generation = $2 AND claim_token = $3`（投影 claim/fence 更新）与
  `DELETE FROM juhe_business.account_list_availability_dirty`（脏标记清理）
- 另一方（gateway 运行时写入，348/220/65 次）：
  `INSERT INTO juhe_business.account_list_availability_dirty (...)`（脏标记写入，伴随 accounts↔authorizations 联表查询）与
  `UPDATE juhe_business.account_list_availability_projection_viewer_health ... WHERE viewer_system_account_id IN (SELECT DISTINCT accounts.system_account_id FROM accounts ...)`（viewer 健康扫描更新）

即：**gateway 写入路径与 jobs 维护路径对 `account_list_availability_dirty` / 投影表 / `accounts` 的加锁顺序不一致**，事务并发时形成死锁环。规模放大因素：accounts 2143 行，viewer_health 更新按 system_account 全量扫描。

## 修复记录（2026-09-26 已实施并上线）

按方向 3 落地：jobs 侧 `circuitstore.ApplyClaims` 不再在单一大事务里按 claim 到达顺序写多行（与 gateway 按 accounts 扫描顺序的批量写形成加锁顺序相反的环），改为：

1. 先按 `Claim.AccountID` 排序，保证与 gateway 侧 accounts 扫描同序；
2. 每个 claim 独立短事务（`applyOneClaim`：BeginTx → 按 account_id/generation/claim_token 读 dirty 行 → upsert 投影 → 删 dirty 行 → Commit），单事务最多持有一行锁，锁窗口从"全部 2143 账户批量"缩到单行，从结构上消除环；
3. 语义保持：stale generation 覆盖仍然报错（`账户列表投影 %s generation %d 被更高版本覆盖`），由既有测试 `TestW13g5ListApplyClaimsStaleGenerationArm` 守卫；`ApplyDeletionClaim` 本就是单 claim 短事务，未改。

gateway 侧（`chain_dispatch.go` 脏标记批量写、viewer_health 批量更新）未改动：其本身语义正确，环的消除以 jobs 侧足够。

验证：

- `go build ./...` 通过；`go test ./internal/circuitstore/...` ok（16.4s，含 stale-generation 守卫用例）；jobs 全量 `go test ./...` 无失败。
- 生产基线：修复前 2h 内 94 条 `40P01` 死锁日志（约 76s 一条），维护任务最高连续失败 18 次。
- 部署核验：本地构建产物、服务器 `/opt/juhe-ai/build/bin`、运行镜像内三处 md5 一致（`fca29636…`），确认线上运行的是修复版二进制。
