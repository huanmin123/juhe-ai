## 问题概述

- 现象：授权列表中资源授权显示“生效中”，但被授权人的账号列表显示“授权暂停”，并提示账户当前不可用。
- 期望：授权从暂停恢复为生效后，被授权人的运行态授权也恢复为 `active`，账号可参与分组调度。
- 实际：`resource_authorization_grants.status` 已是 `active`，但 `resource_authorizations.status` 仍保留 `paused`。
- 影响范围：被暂停后重新恢复的账户授权；网关候选、账号列表和授权状态提示会按运行态授权判定为不可用。

## 复现步骤

1. 资源所有者创建账户授权给另一个系统账户。
2. 将该授权暂停，再恢复为生效。
3. 被授权人查看账号列表或使用绑定该账户的分组调用网关。

## 环境信息

- 分支 / 版本：Mac 生产包 `20260527-001707` 及本地开发分支
- 数据状态：生产样例 `free4` 的 grant 为 `active`，runtime 为 `paused`
- 浏览器 / 系统 / Node 版本：macOS 生产服务，Node 22
- 是否稳定复现：是

## 根因分析

- 表象：授权管理页和账号列表对同一资源显示不同状态。
- 真实根因：恢复授权时写入了 `resource_authorization_grants.status = active`，但同步运行态授权时 `upsertResourceAuthorizationForUser` 对已有 `paused` 的用户级运行态授权继续保留 `paused`。
- 为什么会发生：授权模型分为业务操作记录 `resource_authorization_grants` 和用户运行态授权 `resource_authorizations`。恢复流程只恢复了前者，后者在重新 upsert 时错误继承旧暂停状态。

## 修复方案

- 修改点：`backend/src/storage/resource-authorization-write-state.repository.ts` 中用户级授权 upsert 只在过期时置为 `expired`，否则恢复为 `active`。
- 回归补充：`backend/src/scripts/regression/authorization-return-regression.ts` 增加“暂停后恢复授权必须同步恢复运行态授权状态”的断言。
- 生产止血：将 `free4 -> huanmin` 对应 `resource_authorizations` 记录从 `paused` 修正为 `active`，并确认 grant、来源账户、本地分组绑定均为可用。
- 兼容影响：恢复 active 会让被授权账号重新参与调度；仍过期的授权继续保持 `expired`。
- 回滚方式：回滚代码改动；如需撤销生产止血，可通过授权管理重新暂停该授权。
