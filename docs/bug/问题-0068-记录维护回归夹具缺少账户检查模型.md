# BUG-0068 记录维护回归夹具缺少账户检查模型

## 现象

`test:record-maintenance-queue` 在进入数据维护断言前失败，SQLite 报错 `accounts.health_check_model` 违反 NOT NULL，导致使用记录清理队列回归无法执行。

## 根因

账户当前 schema 已把 `health_check_model` 设为必填字段，但该回归仍使用旧的手写 `INSERT INTO accounts` 测试夹具，没有同步当前字段契约。

## 修复与验证

- 测试夹具显式写入当前 GPT 默认检查模型 `gpt-5.5`，不修改生产代码或业务行为。
- `pnpm --filter juhe-ai-backend test:record-maintenance-queue` 已复跑通过，覆盖 server/DB service 只投递、临时 maintenance worker 执行和统计安全游标保护。

## 下次遇到

- 当前 schema 新增必填字段时，要搜索测试中的手写 `INSERT`，不能只更新 repository 创建路径。
- 清理/队列测试在断言业务行为前，应先确保 fixture 能按当前 schema 成功创建。
