## 问题概述

- 现象：W1b Go 公开账户新增和更新只对 `supportedModels` 做 trim、去重和非空校验，没有确认模型是否属于目标账户 owner 可见、启用且可计价的供应商模型目录。
- 期望：对齐 Node 当前契约。非 `hybrid` 账户只能选择 active、可计价、可见且未下线的内置模型、全局自定义模型和当前 owner 的个人自定义模型；其他 owner 个人模型、停用模型、不可计价模型和未知模型必须拒绝。
- 实际：旧 Go 会把任意非空字符串写入 `account_supported_models`，其他 owner 私有模型和无效模型也可能进入账户调度事实。
- 影响范围：Go W1b `POST /__aipublic__/account/add`、`POST /__aipublic__/account/update`、账户支持模型存储和后续网关候选过滤。

## 复现步骤

1. 在 Go W1b 公开账户接口中提交 `supportedModels: ["不存在的模型"]`。
2. 旧实现只执行字符串归一化和非空校验。
3. 新增或更新成功，未知模型被写入 `account_supported_models`；Node 同请求会返回 `账户支持模型不在供应商模型目录中：不存在的模型`。

## 环境信息

- 分支 / 版本：`feature/20260706-go`，W1b Go opt-in 实现阶段。
- 数据状态：Go fresh PostgreSQL migration 已包含内置模型目录、全局 / 个人自定义模型和价格字段。
- 浏览器 / 系统 / Node 版本：不适用；服务端 service / PostgreSQL 契约问题。
- 是否稳定复现：是。

## 根因分析

- 表象：Go 可以保存目录外模型。
- 真实根因：
  - W1b `publicaccounts.Service` 没有注入模型目录 reader。
  - Add / Update 只调用 `normalizeSupportedModels`，没有复用 `managementprovidermodels.Service.Models` 的 owner 作用域、active、shutdown、同名覆盖和价格解析规则。
  - 既有 smoke 使用了目录中不存在的模型字符串，反而掩盖了缺失校验。
- 为什么会发生：公开账户纵切面迁移时只迁移了支持模型关系表写入，没有把 Node `normalizeAccountSupportedModelsForProviderAsync` 的目录成员校验和 update 未变化短路带入 Go。

## 修复方案

- 修改点：
  - 给 `publicaccounts.Options` 注入窄 `ProviderModelReader`，生产装配复用 `managementprovidermodels.Service`。
  - Add 在重复名称和凭据校验之后，按目标 `systemAccountId + providerCode` 查询 active、可计价目录并拒绝目录外模型。
  - Update 仅在显式提交且归一化后的集合与当前集合无序不同时查询目录；省略或无序相同继续按 Node 语义短路，但最终非空校验仍执行。
  - `hybrid` 保持 Node 语义，只绕过目录成员校验，不绕过数组格式和最终非空。
  - 保持 update 凭据校验优先于模型目录错误；目录校验失败时不调用 store，账户名称、凭据和模型列表保持不变。
  - direct PostgreSQL smoke 增加内置、全局、owner 个人、其他 owner 个人、停用、不可计价、未知、hybrid 和失败原子性矩阵；shell E2E 的旧未知模型 fixture 改为真实内置模型。
- 行为影响：
  - 非 `hybrid` 新增和真实模型变更不再接受目录外模型。
  - 错误固定为 `账户支持模型不在供应商模型目录中：<最多 5 个模型>`。
  - 不新增 schema、迁移兼容、双读双写或旧数据自动清洗。
- 发布异常处理：如果真实 PostgreSQL / Docker 验证发现 owner 作用域、价格过滤或 update 原子性不一致，保持 `JUHE_AI_PUBLIC_API_ENABLED=false`，不得把 W1b 公开账户切流到 Go。
