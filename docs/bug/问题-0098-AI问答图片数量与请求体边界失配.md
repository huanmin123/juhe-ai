# BUG-0098 AI 问答图片数量与请求体边界失配

## 基本信息

- 状态：已修复（HTTP 与前端回归）
- 严重程度：P1
- 模块：前后端 / AI 问答 / 图片 / 请求体安全
- 发现时间：2026-07-13
- 关联计划：PLAN-0103

## 现象与根因

编辑器允许单张 10 MiB，但 System API 通用 JSON 上限只有 256 KiB；同时多选文件并发读取会让 5 个任务都看到“当前 0 张”，突破最多 4 张。若简单扩大全局 parser，匿名请求又可在认证前占用大内存。

## 修复与验证

统一为最多 4 张、单张 4 MiB；多选和粘贴进入同一串行队列并按剩余槽位截断。`/my-chat` 独享 24 MiB parser，且顺序固定为认证、登录用户限流、DB service 准入控制、JSON 解析；其他 System API 仍为 256 KiB。图片节点直接复用快照 Data URL 作为 `img.src`，不创建只在组件卸载时释放的 Blob URL；提交/清空切断 UndoRedo 历史和旧图片读取代次。相邻文本块合并，4 图交错文字的 9 块契约由真实 HTTP Mock 覆盖。

## 防复发

文件数量、单文件上限、Base64 膨胀后的路由上限和认证顺序必须作为同一契约设计；不能只改其中一层。
