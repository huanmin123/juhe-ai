# BUG-0062 余额刷新后列表金额不立即更新

## 现象

AI 账户列表点击某一行的余额刷新图标后，上游查询成功并提示“余额已更新”，但该行金额仍显示旧值。只有刷新整张列表或重新加载页面后才显示最新余额。

## 触发条件

- 当前页账户列表由 `useResponsivePagedList` 的 `shallowRef<AccountSummary[]>` 保存。
- 余额刷新成功后直接修改数组内部对象的 `account.balanceSnapshot`。

## 根因

`shallowRef` 只跟踪 `.value` 本身的替换，不递归跟踪数组内部对象字段。原实现虽然已经拿到最新快照并改写了普通对象，但没有替换列表数组或目标行对象，因此 Vue 不会通知表格和移动列表重新渲染。

## 修复

- 新增账户列表余额快照替换函数：命中时创建新数组并只替换目标账户对象，未命中时保留原数组。
- 列表刷新和编辑弹窗“保存并查询”统一通过 `useAccountListData` 的更新入口写回当前页。
- 不调用列表全量刷新接口，不改变分页、筛选、排序、选择状态或其他行对象。
- 回归测试同时验证数组引用、目标行引用和非目标行引用，并禁止视图重新出现深层直接赋值。

## 验证

- `pnpm --filter juhe-ai-frontend test:account-balance-query` 通过。
- `pnpm typecheck` 和 `pnpm build` 通过。
- 本地真实组件渲染验证中，点击刷新图标后金额从 `$4.79` 立即变为 `$7.31`，列表加载次数保持 `1`。
- 375px 移动宽度无横向溢出，余额行和刷新入口正常渲染。
- 生产 release `20260712-1043-balance-ui-d0f5e7c87` 已发布，公网前端哈希与目标 release 一致且浏览器无控制台错误。

## 下次遇到

- 接口成功但 Vue 页面不更新时，先确认数据源是 `ref`、`shallowRef` 还是 `reactive`。
- 对 `shallowRef` 内部数组/对象的局部更新，必须替换 `.value`，不能只做深层字段赋值。
- 回归测试不能只断言“没有全量刷新”，还要断言目标行通过响应式数据源被替换。
