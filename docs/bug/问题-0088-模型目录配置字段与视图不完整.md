# BUG-0088 模型目录配置字段与视图不完整

- 状态：已上线（自动验证通过，登录后角色页面待人工抽查）
- 严重程度：P1
- 模块：模型目录 / 前端 / Node / Go / PostgreSQL / SQLite
- 发现日期：2026-07-15

## 现象

- 新增自定义模型时，某供应商没有现成同类记录就无法选择用途、服务等级或思考级别。
- 默认思考级别在创建、模板复制和编辑链路中被清空。
- 服务档位缺少 1h 缓存写入价格，目录没有展示档位价格；移动端缺少标准缓存写入。
- 管理员从“我的模型”进入仍看到价格输入，和普通用户视图不一致；内置模型价格编辑错误显示个人作用域。
- Go 管理目录的内置模型 ID 为空，前端无法提供编辑价格操作。

## 根因

- 前端把表单候选从当前目录记录动态推导，首个同类模型形成自我依赖。
- Node/Go 写入契约与已经存在的 `defaultReasoningEffort` 读模型不一致。
- 价格权限只检查管理员身份，没有同时检查当前是否为管理入口。
- 前后端各自维护字段投影，缺少创建、模板、无关 PATCH、显式清空和角色矩阵回归。

## 修复

- “配置模板”直接选择当前可见已有模型作为配置来源，不建立独立模板实体；完整带入能力、上下限和可信价格。
- 用途按供应商能力和当前目录事实提供合法下拉项；服务等级与思考级别只允许选择已确认候选，不开放任意标签输入。
- `defaultReasoningEffort` 支持 `string | null`，贯通 Node、Go、模板复制、无关 PATCH 保留、显式清空和前端展示。
- 桌面和移动目录统一展示标准价格、缓存读写、1h 缓存写入、各服务档位价格及默认思考级别。
- 管理员只有在管理入口可编辑价格；“我的模型”与普通用户一致。空值分别显示“仅标准”“不支持”“官方未公布”。
- 内置目录返回稳定真实 ID；自定义模型写后缓存同步失败保留主写成功，并记录带 traceId 的结构化告警，不以 503 伪装为数据库未保存。

## 验证

- 前端配置复制、角色矩阵、formatter、类型检查和生产构建。
- Node 模型目录、模板写入、cache sync 错误和生成器 snapshot 回归。
- Go 创建、模板复制、无关 PATCH、显式 null、内置价格 PATCH 和 PostgreSQL repository 回归。
- 生产按管理员管理入口、管理员“我的模型”和普通用户三种入口逐项验收。
- 2026-07-16 临时库与生产库迁移、精确 SQL、生产前端 hash、登录页 API 请求和 60 秒稳定验收通过；三种登录后角色入口因无可复用登录态且需要验证码，未代替用户登录，保留人工视觉抽查。

## 防复发

- 新表单枚举不能仅从已有业务行推导；必须允许创建第一个合法模型。
- 同一模型事实由统一 API 契约返回，权限差异只控制操作，不隐藏字段。
- 新增模型字段必须同时覆盖 Node、Go、数据库、模板复制、前端桌面/移动和缓存失效。
