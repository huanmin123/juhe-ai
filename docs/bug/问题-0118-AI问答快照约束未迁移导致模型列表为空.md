# BUG-0118 AI 问答快照约束未迁移导致模型列表为空

## 基本信息

- 编号：BUG-0118
- 状态：已修复并完成生产验证
- 严重程度：P0
- 发现时间：2026-07-22
- 发现方式：用户反馈与生产接口复现
- 模块：AI 问答 / PostgreSQL / 模型目录 / 迁移 / 发布
- 关联计划：PLAN-0101
- 关联 bug：BUG-0115
- 责任人：AI

## 问题概述

- 现象：生产 AI 问答会话可以创建，但模型选择为空，输入区无法发送。
- 期望：会话绑定默认 GPT API Key 后返回该路由可用的 GPT 模型列表和默认模型。
- 实际：会话与 API Key 绑定正常，`GET /__aisys__/api/my-chat/conversations/:id/models` 返回 `200` 和空数组。
- 影响范围：生产全部系统账户的 AI 问答模型列表；已有公开 `/v1/models` 宽快照不受影响。

## 复现步骤

1. 使用有效生产 session 读取自己的 AI 问答会话，确认会话绑定启用的默认 GPT API Key。
2. 请求会话模型列表接口。
3. 接口稳定返回 `200`，但 `data` 为空。

## 环境信息

- 生产 release：`20260722-provider-enabled-integer-267024632-r2`
- 数据状态：GPT 内置模型目录存在 82 条；发布快照仍只有旧 `variant='chat'`。
- 生产存储：PostgreSQL + Redis
- 是否稳定复现：是

## 根因分析

- 当前代码把旧的 OpenAI `chat` 宽快照拆成 `chat_list:<provider>` 和 `chat_model:<provider>:<modelId>`。
- 已应用过的 `gateway_model_catalog_snapshots` 表仍保留旧 CHECK，只允许 `default`、`codex`、`chat`。
- 历史 migration `000059` 后来虽然改成了新 CHECK，但 `CREATE TABLE IF NOT EXISTS` 不会修改生产已存在表的约束；没有新的前向 migration 承接该变化。
- 当次发布明确没有执行 post-migration 快照重建，verify 只检查表和权限存在，没有检查 variant 约束或 `chat_list:gpt`。
- 当前读取函数把“新快照不存在”转换为空数组，最终形成无报错的空白页面。直接重建时 PostgreSQL 以 SQLSTATE `23514` 拒绝 `chat_list:gpt`，确认约束是根因。

## 修复方案

- 新增 migration `000070_w2_gateway_model_catalog_chat_snapshot_variants.sql`：删除可重建的旧 `chat` 行，替换 CHECK，并投递一次 `all` dirty-generation 重建请求；Down 保持非破坏性，避免回退到已经使用拆分 variant 的 schema 69 运行时代码时重新制造故障。
- Node 与 Go schema version gate 同步推进到 `70`。
- 快照契约回归要求必须存在独立前向迁移，且迁移必须允许 `chat_list:*` / `chat_model:*` 并投递全量重建。
- 生产先在事务内预演并回滚，再正式替换约束；随后使用现有维护入口重建全局与全部启用用户快照。
