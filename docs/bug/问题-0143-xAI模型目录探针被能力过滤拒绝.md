# BUG-0143 xAI 模型目录探针被能力过滤拒绝

- 关联计划：无
- 关联 bug：无
- 责任人：待定

## 问题概述

- 现象：xAI API Key 账户在用户显式同步模型目录时，被提示当前分组没有账户支持该请求路径或客户端协议。
- 期望：服务端内部发起的模型目录检查能由 xAI API Key 账户请求上游 `GET /v1/models`。
- 实际：xAI driver 仅认可 POST Chat Completions 与 POST Responses，请求在本地候选能力过滤时被拒绝，未发送上游。
- 影响范围：xAI API Key 账户的用户显式模型目录同步；普通客户端网关请求和 Grok OAuth 不在放行范围。

## 复现步骤

1. 创建或编辑一个 xAI API Key 账户。
2. 点击账户表单中的“同步上游模型”触发服务端模型目录检查。
3. 观察 `GET /v1/models` 在候选能力筛选前后被本地拒绝。

## 根因分析

- 表象：账户已配置 API Key，但模型目录检查被报告为不支持的请求路径。
- 真实根因：xAI driver 的 `buildUpstreamUrls` 与 `accountSupportsRequest` 均只按公开 Chat / Responses 请求路径判断，没有识别账户模型同步服务通过 `WeakSet` 添加的内部模型目录标记。
- 为什么会发生：模型目录检查不是对外网关能力，却复用了网关候选筛选流程；xAI driver 未像同类 API Key driver 一样为该受控流程定义窄例外。

## 修复方案

- 修改点：仅当请求带有内部模型目录标记且账户类型为 `api_key` 时，xAI driver 构造上游 `GET /v1/models` URL 并报告账户可承接；其余请求继续走原有 Chat / Responses 判定。
- 行为影响：用户显式账户模型同步可读取 xAI API Key 的上游模型目录；未标记客户端 `GET /v1/models` 仍被拒绝，Grok OAuth 仍仅支持 Responses。
- 发布异常处理：无需数据迁移；若异常可仅回滚 xAI driver 的受控探针例外，既有 Chat / Responses 与 OAuth 路径不受数据影响。

## 下次遇到

- 先查什么：账户模型同步服务是否以内部模型目录标记构造受控请求，以及供应商 driver 是否显式处理该标记。
- 重点看什么：模型目录同步是服务器诊断流程，不等同于向客户端开放 `/models` 网关路由。
- 如何避免误判：同时验证标记 API Key 放行、未标记请求拒绝和 OAuth 拒绝，避免扩大供应商的公开协议边界。
