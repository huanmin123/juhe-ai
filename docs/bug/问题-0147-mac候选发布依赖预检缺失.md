# BUG-0147 mac 候选发布依赖预检缺失

## 状态

待修复，阻断 macOS temporary 候选槽启动和任何切流。

## 现象

以当前线上提交 `f214983f7` 在 Mac 上进行不切流预演时，候选归档本身、空 PostgreSQL 数据库和独立端口预检均通过，但生产依赖安装无法在有界时间内完成：

- 常规 `pnpm install --prod --frozen-lockfile` 超过 5 分钟仍未完成；
- `pnpm install --prod --frozen-lockfile --offline` 在 22 秒内明确失败，提示本机 store 缺少 `gpt-tokenizer` 的 tarball；
- 默认 `node` 是 25.x，而该线上提交声明只支持 Node 22.x 或 24.x 的受限版本区间；当前线上服务实际由 Node 22 路径运行。

候选没有启动 Node、Redis、Nginx 或外层路由；临时目录和空数据库已删除，生产 `current` 提交未变化。

## 根因

发布流程没有把“目标机器可离线安装生产依赖”和“用于安装/运行的 Node 二进制满足项目 engines”设为候选启动前的硬门禁。直接执行在线安装会把网络或 store 不完整问题伪装成服务启动等待，无法在短时间内得到可操作结论。

预演辅助脚本还暴露两个实现错误：空查询作为裸 `set -e` 管道会被误判失败，且解压后未先进入 release 目录就执行 `pnpm`。两处均已在本次预演控制逻辑中修正，不能回流到正式脚本。

## 修复要求

1. 在任何 temporary release 解压后、创建数据库或启动 Redis/Node 前，使用目标 release 目录执行有时限的 `pnpm install --prod --frozen-lockfile --offline` 预检；缺包时明确报出包名并停止。
2. 部署控制器必须接受并记录显式 `--node-bin`，校验其版本为项目支持的 Node 22.x 或 24.x；不得隐式选择 PATH 中的 Node 25.x。
3. 在线依赖安装必须有独立、短时、可取消的阶段超时和结构化阶段日志；超时后只清理候选资源，不能继续尝试启动服务或切换入口。
4. 只有依赖与 Node 预检通过后，才允许创建 temporary PostgreSQL/Redis、启动 1 control + 3 gateway + workers、执行 health/日志/基础接口验证。

## 验证证据

- 本地从固定线上提交构建的 tar 包通过 source commit、包内容和发布校验器验证。
- Mac 预检确认 temporary 端口、LaunchDaemon label 和目录均未占用，PostgreSQL 直连可用。
- 离线依赖预检稳定复现缺少 `gpt-tokenizer` tarball；未出现候选监听或生产路由变更。
- 清理后复核候选目录、临时数据库、候选进程均不存在，`current` 仍指向 `f214983f7`。

后续的运行态预演仅将候选目录的 `node_modules` 显式链接到同一 `f214983f7` 线上 release 的现有依赖树，并固定使用线上 Node 22 二进制。该方法验证了候选进程、PostgreSQL、Redis、Nginx 和接口路径，但不执行 `pnpm install`，不能视为本 Bug 的修复或替代正式发布依赖门禁。

## 影响和后续

在 BUG-0147 修复且目标机缓存/Node 路径准备完成之前，禁止启动 temporary 槽，也禁止执行 `performance-handover-controller.sh --apply`、`temporary-cutover.sh --apply` 或任何外层 Nginx 路由切换。
