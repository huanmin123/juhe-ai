## 问题概述

- 现象：非对话媒体请求（视频/音频/生图）计价正常，但所有文本成功请求（`/v1/chat/completions`、`/v1/responses`、`/v1/messages`）落库 `cost_usd=0` 且 `usage_missing=1`，即使目录行有完整 input/output token 价。
- 期望：无 `media_pricing_json` 的文本模型按 token 价正常估算成本，`usage_missing=0`。
- 实际：`MediaPricingInvalid` 被错误置真，`BuildCostBreakdown` 整行拒绝 token 计价；同步计费分支按「非法媒体模板」显式落 0 + `usage_missing`。
- 影响范围：所有 `models.media_pricing_json IS NULL` 的文本/embedding 行（生产绝大多数文本模型）；若随发布上线，全部文本流量成本为 0、统计与额度失真。媒体行因有真实模板不受影响，因此常规媒体测试无法发现。

## 复现步骤

1. dev 环境从 revision 23 升级到 26，`models` 文本行保持 `media_pricing_json=NULL`。
2. 通过网关发起 `POST /v1/chat/completions`（gpt-6.2-astra 等），上游 200 且有 token usage。
3. 查询 `juhe_usage.usage_records`：`input_tokens/output_tokens` 正常，`cost_usd=0`、`usage_missing=1`；`cost_breakdown_snapshot_json` 中 `accountChargeUsd` 为 0。
4. 同一时刻媒体请求（`/v1/audio/speech`、`/v1/images/generations`、`/v1/video/generations`）成本正常，形成「媒体有价、文本全零」的对照。

## 根因分析

- 表象：文本行 `cost_usd=0`、`usage_missing=1`，目录价格明明存在。
- 真实根因：`scanCatalogRows` 把 SQL NULL 列写入行 map 时保留了 `nil`。`json.Marshal` 将其序列化为 `"mediaPricing":null`，反序列化到 `json.RawMessage` 后得到 4 字节 `null`（`len(item.MediaPricing) > 0` 为真），随后 `mediapricing.Parse` 返回 `ErrEmpty`（`media pricing is empty`）。旧代码把**所有非 nil 解析错误**都当作非法模板，置 `HasMediaPricing=false` / `MediaPricingInvalid=true`。`pricing.BuildCostBreakdown` 对 `MediaPricingInvalid` 行整行返回 nil；`chain_usage.go` 的非法模板分支再显式写 `CostUsd=0` + `UsageMissing=true`。
- 为什么会发生：目录扫描的行对象语义应是 Node 的「列缺失 = undefined」，但 `nil` 经 JSON 往返变成了显式 `null`；同时 `mediapricing.ErrEmpty` 在契约中是「无模板、继续 legacy/token 计价」，实现却与「非法模板」合并处理。媒体行有真实 JSON，所以测试一直正常；文本行默认 NULL，缺陷面最大。

## 修复方案

- 修改点（`backend-go/projects/gateway/cmd/juhe-ai-gateway/chain_catalog.go`）：
  - 抽出 `catalogRowFromValues`：SQL NULL 列直接跳过，不写进行对象 map，恢复 Node `undefined` 语义。
  - 抽出 `catalogItemFromRow`：解码后把空字节、`null`、带引号空串归一为「无模板」；`mediapricing.ErrEmpty` 只清空模板标志，不再置 `MediaPricingInvalid`。
  - 结构非法（如 `{}`、缺 version/unit/baseUsd）仍按 AC-016 置 `MediaPricingInvalid`，不回落 legacy。
  - 新增 `chain_catalog_media_pricing_test.go`：SQL NULL 键缺失、JSON null、空串三种「无模板」形态均保留 token 计价；非法模板仍拒绝。
- 行为影响：`media_pricing_json` 为 NULL/空串的行恢复 token/legacy 计价；非法模板行的 0 成本 + `usage_missing` 契约保持不变。
- 发布异常处理：代码修复；本批目录缓存键已升至 `v3:`，旧 `v2`/无前缀条目不会被命中，无需删除 Redis 键或额外操作。

## 下次遇到

- 先查什么：先对比媒体与文本请求的 `cost_usd`；若媒体正常、文本全零，优先检查文本行 `media_pricing_json` 是否 NULL 以及 `MediaPricingInvalid` 是否为真。
- 重点看什么：SQL NULL 经 `map[string]any` + `json.Marshal` 往返后的 `json.RawMessage` 是 `null` 而非空；`mediapricing.ErrEmpty` 必须与 `ErrInvalid` 分开处理。
- 如何避免误判：不要因为「目录列表能看到价格」就排除计价目录问题；列表读面与运行时缓存扫描是两个路径，缓存层的标志位可能已污染。
