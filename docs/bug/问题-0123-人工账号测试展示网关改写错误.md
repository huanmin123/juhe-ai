# BUG-0123 人工账号测试展示网关改写错误

## 基本信息

- 编号：BUG-0123
- 状态：已修复（定向回归与类型检查）
- 严重程度：P2
- 发现时间：2026-07-23
- 发现方式：用户反馈
- 模块：后端 / AI 账户 / 网关 / 人工测试
- 关联计划：无
- 关联 bug：无

## 问题概述

- 现象：Responses SSE 人工账号测试失败时，终端区域展示 `upstream_retryable_error` 和“上游流式响应在输出前失败，请重试”。
- 期望：完整诊断展示最后一次真实上游响应正文、响应头、错误码和错误文案。
- 实际：测试服务虽然已经取得 `UpstreamAttempt` 原始诊断，但 `responseText` 和 `responseHeaders` 固定读取内存网关的下游响应，因此展示了网关面向普通客户端生成的重试错误。
- 影响范围：账户所有者或管理员查看人工测试完整失败诊断时可能误判上游实际错误；授权账户 limited 诊断不受影响。

## 复现步骤

1. 对使用 Responses SSE 的 GPT API Key 账户执行人工测试。
2. 让上游在下游输出前返回失败，触发网关客户端重试错误改写。
3. 查看测试终端和完整 JSON，`responseText` / `responseHeaders` 来自网关下游，而 `message` 可能已经来自上游诊断。

## 根因分析

- 表象：前端终端展示了项目自己的错误事件。
- 真实根因：`account-test.service.ts` 对消息解析优先使用 `diagnosticLastAttempt.responseBodyText`，但最终结果正文和 header 仍固定使用 `MemoryGatewayResponse`，同一个结果对象混用了上游诊断和下游客户端响应两个来源。
- 为什么会发生：人工测试复用了真实网关链路，但结果组装没有显式区分“网关对客户端的最终响应”和“人工诊断需要展示的真实上游尝试”。

## 修复方案

- 新增人工测试响应诊断选择器：只要最后一次真实上游尝试捕获到非空正文，就使用该正文和上游 header；未捕获正文时保留下游兜底，避免空结果。
- SSE 错误码解析同时支持 JSON 响应和 `data:` 事件，确保 `response.failed.response.error.code` 能写入测试结果。
- 不改变真实网关对普通客户端的重试错误语义，也不改变 limited 诊断裁剪和 256KB 响应预览上限。

## 下次遇到

- 同时检查 `AccountTestResult.message/errorCode` 与 `responseText/responseHeaders` 的来源是否一致。
- 网关复用场景必须明确区分真实上游诊断和面向客户端的改写响应。
- 流式错误码不能只对整段正文执行一次 `JSON.parse`，需要解析 SSE `data:` payload。
