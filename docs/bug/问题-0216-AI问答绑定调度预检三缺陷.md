# BUG-0216：AI 问答绑定调度预检三缺陷（normal 路由不感知绑定作用域、可恢复等待被短路、停用专用 Key 500 不对称）

- 编号：BUG-0216
- 状态：已修复（待发布验证）
- 发现：2026-09-28，批次2 复审：`group` / `account` 绑定模式会话的发送预检链三处与绑定契约不符

## 现象

- normal 路由不感知绑定作用域：chat 调度覆盖注入候选后仍执行 Key 路由策略的 normal 路由判定——`group` / `account` 会话的鉴权主体是专用对话 Key，其路由策略与绑定对象无关；专用 Key 未命中 normal 路由绑定（如策略为空或绑定不在目标范围）时，发送在预检即被拒绝，绑定分组/账户本身可用也无法送达。
- 可恢复等待被短路：外部 `/v1` 请求在候选账户临时冷却时进入可恢复等待（等待候选恢复或超时），chat 绑定作用域路径没有接入同一机制——候选冷却时立即失败，绑定会话的可用性低于外部直连。
- 停用 Key 500 不对称：`group` / `account` 模式创建会话时若专用对话 Key 处于停用/过期状态，服务端返回 500；`api_key` 模式绑定对象不可用是 400 `chat_invalid_request`（用户可恢复输入错误），同一类用户状态错误在两种模式间返回码不一致。

## 根因

- 预检链复用了外部 `/v1` 的完整判定序列：调度覆盖只收敛候选账户，没有跳过 Key 策略 normal 路由判定；分组归属实际按会话绑定记账，该判定对绑定会话是多余且错误的。
- 可恢复等待只在常规候选解析路径生效，chat 覆盖候选注入路径（`CandidateAccounts` 注入 + 绑定作用域收敛）未接入。
- `EnsureChatAPIKey` 幂等重建后 Key 仍缺失/停用/过期被归入服务端错误（500）；它实际是可恢复的用户状态错误（可在 API Key 页面恢复）。

## 修复

- chat 调度覆盖候选注入时跳过 Key 策略 normal 路由判定：分组归属按会话绑定记账；外部 `/v1` 语义不变。
- chat 绑定作用域接入与外部 `/v1` 同款可恢复等待：`group` 模式作用域为绑定分组，`account` 模式为启用分组全集 + 目标账户收敛；候选冷却时进入可恢复等待而非立即失败。
- 专用 Key 停用/过期返回 400 `chat_invalid_request`（文案"专用对话 Key 已停用或过期，请在 API Key 页面恢复后重试"），与 `api_key` 模式对称；装配缺失、查询失败等服务端问题保持 500。

## 验收

- `group` / `account` 会话在专用 Key 路由策略为空或不含目标时仍能正常发送，命中绑定分组/账户；外部 `/v1` 的 normal 路由判定行为不变。
- 绑定作用域候选全部冷却时发送进入可恢复等待，候选恢复后继续；与外部 `/v1` 同参数下行为一致。
- 停用专用 Key 后新建 `group` / `account` 会话返回 400 与提示文案；装配缺失场景仍 500。

## 教训

- 复用外部链路做"内部直驱"必须逐判定审查语义：候选收敛之后，哪些判定对新作用域是噪声（normal 路由）、哪些是缺项（可恢复等待），不逐一核对就会同时引入误拒与降级。
- 返回码分类按错误归属而不是按代码位置：同一个"绑定/鉴权对象不可用"，用户可自行恢复就是 400，只有真正的服务端装配/查询问题才是 500。

## 状态

已修复（normal 路由跳过 + 绑定作用域可恢复等待 + 停用 Key 400 对称），待发布验证。
