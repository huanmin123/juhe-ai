# BUG-0211：AI 问答流式体验断裂——SSE 收集器全量缓冲叠加客户端断开即取消生成

- 编号：BUG-0211
- 状态：修复中（批次1 实施中，待发布验证）
- 发现：2026-09-28，批次1 复审：用户反馈流式期间页面无增量、连接断开后生成被取消，与“服务端跑完 + 重附恢复”契约不符

## 现象

- 页面收不到增量：发送后长时间停留在“思考中”，正文在整段响应结束后一次性出现——SSE 收集器用 `io.ReadAll` 把上游响应全量缓冲后再解析，增量事件在整段响应结束前无法到达前端，流式体验完全丧失。
- 断开即取消：客户端网络抖动或页面刷新断开 SSE 连接时，生成被立即终止——runner 的执行 context 直接挂载 HTTP 请求 context，请求 context 随连接关闭而取消，上游生成中途停止；刷新后确权只能看到取消/失败终态，违背“服务端跑完 + 重附恢复”契约。

## 根因

- 收集器把“有界收集”实现成“全量缓冲后再解析”：单事件 `64 KiB`、事件数预算等内存边界本意是 DoS 防护，却把转发时机推迟到整段响应结束，增量语义被边界实现吞掉。
- runner 生命周期错误耦合请求生命周期：客户端断开是传输层事件，不应传导为模型请求取消；“服务端跑完 + 重附恢复”契约要求 runner 与请求 context 脱钩，生成由轮次生命周期而不是连接生命周期决定。

## 修复

- 收集器改增量解析：每收到一个上游 SSE 事件即解析并转发下游（投影、持久化推进与前端 SSE），内存边界照常生效（单事件、事件数、累计内容上限），只在整段响应结束时收口终态。
- runner 脱钩：runner 执行使用独立 context，客户端断开只停止向该连接写响应；生成继续执行到终态并按有界内容推进持久化，重附恢复同轮。显式 stop / 取消请求仍按取消契约落库 `canceled`。

## 验收

- 长回答流式期间页面按事件增量渲染，不再整段结束后一次性出现。
- 流式期间断开（刷新、网络抖动）后重附或确权，同一轮继续生成并到达服务端权威终态，已流出内容不丢失。
- 显式 stop 行为不回归（仍落库 `canceled`，参见既有取消契约）。

## 教训

- “有界缓冲”与“增量转发”是两个正交需求：边界防护不能吞掉流式语义。SSE 链路改造必须端到端验证“首个增量事件的延迟”，而不是只验证最终结果正确。
- 服务端 runner 的生命周期锚点是轮次而不是连接：任何把请求 context 透传进生成执行的路径，都会把传输抖动放大为生成失败。
