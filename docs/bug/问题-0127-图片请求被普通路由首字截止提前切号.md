# BUG-0127 图片请求被普通路由首字截止提前切号

## 基本信息

- 编号：BUG-0127
- 状态：已修复
- 严重程度：P1
- 发现时间：2026-07-25
- 发现方式：用户反馈与真实请求日志排查
- 模块：Node / 网关 / 图片生成 / 普通路由 / 账户切换 / AI 对话
- 关联计划：PLAN-0169-20260724T220000000Z
- 关联 bug：BUG-0126

## 问题概述

- 图片请求遇到首个账户 403 后确实切换到了可用的 `zeekai-image` 账户，但该 attempt 在约 10 秒仍无响应头时被本地提前中止。
- 网关随后继续切到第三个账户并最终返回 403，使前端看起来像是图片账户没有参与故障切换。
- 图片生成首响应允许合法长耗时，不能复用普通文本路由默认 10 秒的首字截止。

## 根因与修复

- 根因是公共首字截止在 dispatch 阶段没有按最终 `requestLane` 限定，导致 `image` lane 同时受图片 600 秒首响应超时和普通路由 10 秒截止约束，实际由更短的 10 秒先触发。
- 普通路由首字截止现仅对 `text` lane 创建；`image` lane 使用 `imageFirstResponseTimeoutSeconds`、图片未提交 attempt 上限和既有 transport 失败切换逻辑。
- AI 对话发起的内部图片网关请求同步透传聊天 `x-trace-id`，前端给出的 Trace ID 可以直接查到图片账户的全部 attempt。

## 验证

- `pnpm --dir backend test:normal-route-first-byte-deadline`
- `pnpm --dir backend test:chat-image-generation`
- `pnpm --dir backend typecheck`

## 下次遇到

- 先按聊天 Trace ID 检查同一次图片请求的账户 attempt 顺序、`first_byte_timeout` 和最终非 2xx。
- 图片账户在约 10 秒被终止时，优先核对是否误用了普通路由首字截止；图片自身默认首响应超时为 600 秒。
