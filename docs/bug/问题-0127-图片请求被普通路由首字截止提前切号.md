# BUG-0127 图片请求被普通路由首字截止提前切号

## 基本信息

- 编号：BUG-0127
- 状态：已修复
- 严重程度：P1
- 发现时间：2026-07-25
- 发现方式：用户反馈与真实请求日志排查
- 模块：Node / 网关 / 图片生成 / 普通路由 / 账户切换 / AI 对话
- 关联计划：PLAN-20260724T220000000Z
- 关联 bug：BUG-0126

## 问题概述

- 图片请求遇到首个账户 403 后确实切换到了可用的 `zeekai-image` 账户，但该 attempt 在约 10 秒仍无响应头时被本地提前中止。
- 网关随后继续切到第三个账户并最终返回 403，使前端看起来像是图片账户没有参与故障切换。
- 图片生成首响应允许合法长耗时，不能复用速度优先文本路由默认 30 秒的首字截止。

## 根因与修复

- 根因是公共首字截止在 dispatch 阶段没有按最终 `requestLane` 限定，导致 `image` lane 同时受图片 600 秒首响应超时和普通路由 10 秒截止约束，实际由更短的 10 秒先触发。
- 普通路由首字截止、速度慢样本和 `latency_degraded` 现仅对 `text` lane 创建；`image` lane 使用图片专用首响应、idle、未提交 attempt 和整请求墙钟。
- 通用网关新增 `imageRequestWallTimeoutSeconds`，默认 3600 秒、范围 60–86400 秒。它只在候选切换决策点限制继续派发，不机械中断仍处于图片专用时限内的在途 attempt；直接图片和账户模型映射升级后的图片都使用该墙钟，且扩展时不重置原请求接收时间。
- AI 对话图片工具的整体执行时限改为系统设置 `chatImageGenerationTotalTimeoutSeconds`，默认从 600 秒提升为 900 秒；该总时限与单账户首响应超时独立。
- AI 对话发起的内部图片网关请求同步透传聊天 `x-trace-id`，前端给出的 Trace ID 可以直接查到图片账户的全部 attempt。
- 后续复查撤回了曾加入通用网关的 `403 + permission_error + 固定上游文案` 图片切号特判。当前所有请求的完整 HTTP 非 `2xx`、transport、timeout 和未提交正文中断均按内容无关的统一候选规则切号；显式账户错误策略只负责配置的状态动作，不决定是否允许切号。

## 下次遇到

- 先按聊天 Trace ID 检查同一次图片请求的账户 attempt 顺序、`first_byte_timeout` 和最终非 2xx。
- 图片账户在约 10 秒被终止时，优先核对是否误用了普通路由首字截止；图片自身默认首响应超时为 600 秒。
- 完整 HTTP 错误的候选切换不需要配置账户错误策略，也不得依赖网关内建状态码、错误类型或供应商文案；只有希望改变账户持久/共享状态时，才使用用户显式策略。
