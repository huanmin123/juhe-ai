## 问题概述

- 现象：切换菜单时偶发短暂卡顿，表监控、统计页面、统计列表和 AI 账户页面更明显。
- 期望：菜单切换先快速完成应用壳和页面框架响应，重表格和图表不阻塞导航首帧。
- 实际：首次进入重页面时，路由 chunk 下载、表格 DOM 创建和测量、图表初始化、页面派生计算可能挤在同一段主线程任务里。
- 影响范围：所有菜单路由，重页面集中在统计、账号、授权统计、用量、日志、审计和表监控。

## 复现步骤

1. 登录后台并在用户模式 / 管理模式下连续切换多个菜单。
2. 打开统计概览、AI 账户管理、用量统计、AI 性能监控、操作日志或表监控。
3. 观察首次进入或缓存被淘汰后重新进入时是否有短暂卡顿。

## 根因分析

- 表象：切换菜单时页面似乎“卡一下”，尤其是列表、统计图和表监控。
- 真实根因：多个重任务叠在导航关键路径，包括首次加载异步组件 chunk、Ant Design Vue 宽表格同步创建和测量 DOM、ECharts 初始化和 resize、AI 账户页行级派生数据反复数组查找，以及 KeepAlive 缓存上限偏小导致重页面被淘汰后反复冷启动。
- 补充根因：二次复查发现部分细节会影响长期运行，包括隐藏工具栏仍监听 resize、CodeMirror 延迟格式化任务未收口、页面状态缓存 / 提交锁 / 搜索防抖存在短 timer、账号测试请求切走页面后未主动 abort、公告轮询缺少防重入。
- 为什么会发生：页面数量增加后，原先单页局部可接受的同步工作在菜单切换场景叠加；同时隐藏页生命周期没有统一释放 observer / resize / timer / 实例，多缓存页面下会放大后续布局成本和内存占用。

## 修复方案

- 修改点：新增 `DeferredRender`；通用 `ResponsiveDataList` 延迟表格挂载并在 deactivated 释放 observer / resize；重菜单 `meta.heavy` 空闲分批预加载；统计和表监控图表按激活状态渲染并在隐藏时释放实例；AI 账户页常用派生关系改为 `Map/Set`；工具栏、代码查看器、页面状态缓存、提交锁、移动分页、搜索防抖、账号测试请求、公告轮询和路由预加载批次补齐生命周期收口。
- 行为影响：不改变接口、权限、分页、筛选和统计口径；页面内容会在导航后一到两帧内挂载重表格或图表。
- 发布异常处理：如具体页面激活后空白，优先修正该页面的延迟渲染生命周期；必要时针对当前页面关闭 `deferTableMount` 或重菜单标记，不恢复旧页面加载模型。

## 下次遇到

- 先查什么：先查新增菜单是否有直接 `a-table`、ECharts 初始化、首屏大数组 `find/filter/reduce`、`keepAlive: false`、同步读取大 payload、未清理 timer / listener / observer / AbortController。
- 重点看什么：路由 chunk 是否冷启动、表格是否在导航同帧挂载、隐藏页是否还有 resize / observer / timer、图表或编辑器实例是否在隐藏页保留、详情抽屉是否首屏预渲染。
- 如何避免误判：不要只看接口耗时；前端主线程 DOM、layout、chart init 也会造成短暂卡顿。
