## 背景与清单

BUG-0361（并发槽）/BUG-0362（在途额度/realtime 连接/capacity）治理后，按「计数器/占位 + 调用方释放 + 异常路径永久阻塞或丢失 + 无对账」判据扫描出的**不同问题族**风险（T207 C1-C12），本批全部收口：

| # | 缺陷 | 根因 | 影响 |
| --- | --- | --- | --- |
| C1 | record_maintenance 毒丸行队头阻塞 | `drain.go` 单行失败即 return；未知 type/非法参数是确定性失败且永不消失；无 attempt cap/dead-letter/保留清理；gateway 投递端不校验 kind | 账户/用量清理与快照任务族永久停摆 |
| C2 | usage 死信内存环 | 写库连续失败 10 分钟后整批移入仅 100 条内存环并丢弃；溢出 spool 落盘失败直接丢弃；jobs 探针用量走 best-effort Enqueue | 用量/计费记录永久缺失 |
| C3 | J1 投影 observed_at 游标 | 以逻辑时间单调推进游标，并发两探针时晚到的旧行永久跳过（BUG-0345 同族） | 账户健康/冷却状态延迟 |

## 修复

### C1 record_maintenance 毒丸队列（jobs + gateway）

- `record_maintenance_jobs`（`juhe_dataset`，gateway/jobs 双侧运行时自建表，不在 maintenance ensure 清单）加列 `attempt_count`/`next_attempt_at_ms`/`status`（`pending|failed`），双侧建表与加列 DDL 逐字一致；运行时自升级，不占 revision。
- Dequeue 只取 `status='pending' AND next_attempt_at_ms<=now`（排序仍 created_at，FIFO 保持）；瞬时失败（执行/删行）按指数退避（60s/300s/900s/3600s 封顶）保留 pending 并继续后续行——不再队头阻塞；确定性失败（未知 kind、非法参数、snapshot_json 损坏）执行前预判置 `failed` 终态隔离，ERROR 带载荷摘要，不再重试；结算记账失败上抛中止本轮防活锁。
- 投递端（gateway `dispatch.go`）与执行端（jobs `retention`）共用 `shared/platform/recordmaintenance/kinds.go` 白名单校验 kind，非法 kind 投递端直接拒绝并 ERROR（毒丸不入库）。
- 保留清理：`CleanupJobsBefore` 按 created_at 35 天滚动批删（含 pending/failed），挂入 jobs `data-retention-cleanup` 节拍；生产者停止后表最终归零。

### C2 usage 死信落盘保留（shared usagewriter + jobs）

- `deadLetterBatch`：spool 装配时整批先逐条 `spool.Persist`，全部成功才出队清 pending；任一失败整批保留队列（不计死信终态、不重置失败预算），deferred 计数 + WARN，flushCycle 按固定退避重试。spool 未装配（Node 内存形态）语义不变。
- `spoolOverflow`：Persist 失败不再丢弃，记录强制回队补偿暂存（`admitTailLocked`）下轮冲刷重试写库；`droppedDispatchCount` 计数名与 json 键保留、语义改为「延迟重试」。**已知边界（终审 m2）**：写库与 spool 落盘同时持续失败（如磁盘满同机打断两者）时强制回队无上界，内存队列可能在 OOM 后整体丢失——容量盲区为设计取舍，磁盘故障场景下以稳定性裁决优先；另部分成功重试轮会对已落盘 items 重复生成 spool 文件（回放侧 ON CONFLICT 幂等，仅磁盘冗余）。
- **gateway 主生产 writer 已收口（终审 M1，2026-11-13 用户授权接线，随下次发布生效）**：终审时 gateway 装配**没有** `WithOverflowSpool`——T188（2026-11-09 用户裁决）起 gateway 直投 PG 是全部生产用量记录的主路径，PG 连续失败 10 分钟或队列持续满溢时 gateway 侧用量记录按 T188 既定的「有界异步直投、溢出终态丢弃」行为丢失。2026-11-13 用户授权后接线（`chain_usage_writer.go` `newUsageWriterDeliverer`）：复用共享 `FileOverflowSpool`（新增 `InstanceDirectory` 字段，gateway 装配设 `gateway`，jobs 装配空值回落 `jobs` 不变），溢出落盘 `<DATA_DIR>/usage-record-overflow-spool/gateway/<UnixMilli>-<pid>-<uuid>.json`；溢出记录在 `Enqueue` 内已 normalize（稳定 id/createdAt），jobs `usagespooldrain.Drainer` 扫描同一 DATA_DIR 根下全部实例子目录（含 `gateway/`）幂等回放 `EnqueueDurable`（ON CONFLICT DO NOTHING），回放链路无缺口。Persist 失败按 T207-C2 语义回队延迟重试，不丢记录；不加 env/配置项/开关，`MaxWriteAttempts` 与 10 分钟死信语义不变。**多节点滞留语义**：单机 compose（`docker/single-server`）gateway 与 jobs 的 data/ 同一宿主目录，回放闭环；多节点/不同源形态（如 `docker/cluster` 各节点本地盘）gateway 溢出文件滞留本节点——文件 temp+rename 原子落盘不丢、无自动清理，但 jobs 扫描不到，需手工把 `gateway/` 子目录复制到 jobs 可见的同根 `usage-record-overflow-spool/` 下等待回放或按文件内记录手工入库。gateway 停机收尾与 jobs 对齐：`FileOverflowSpool` 无状态无需 close，`writer.Close` 有界排空内存队列，已落盘文件由 jobs Drainer 在其运行节拍内回放。装配行为回归测试见 `cmd/juhe-ai-gateway/chain_usage_writer_spool_test.go`。
- 死信复用既有 `FileOverflowSpool`（`DATA_DIR/usage-record-overflow-spool/jobs/`），与 `usagespooldrain.Drainer` 同目录装配，回放链路无缺口。
- jobs 探针用量 `worker_health_usage.go` 改 `EnqueueDurable`（队满+spool 失败返回错误而非静默 nil；探针源无持久文件保留能力，失败 warn 留痕为 durable 契约既定语义）。

### C3 J1 投影消费水位（jobs accounthealth）

- `juhe_jobs.account_health_outcomes`（jobs 属主运行时自建表）加列 `projection_consumed_at`（text 水位标记）+ 部分索引 `(observed_at, outcome_id) WHERE projection_consumed_at IS NULL`；运行时自升级，不占 revision。
- 投影查询改为「`projection_consumed_at IS NULL` 的最旧行」；投影写入与打标同事务（五条提交路径全覆盖）；批循环取「下一个未消费」直到空批。晚到旧行不再被逻辑时间游标跳过。
- 存量自举：`bootstrapProjectionConsumption` 按旧游标结算 `observed_at <= 游标` 的行（SKIP LOCKED，5000 行/轮循环至收敛，超 200 轮报错停投影由人工核对积压规模；同一次结算打标值一致，幂等）；部署前已被旧游标越过的晚到行不回放（与 BUG-0345 同款取舍），部署后的晚到行必被消费。
- 重放安全：投影本身 receipt 幂等（`findReceipt` 命中跳过），水位打标同值覆盖；并发 drain 下业务效果 exactly-once、工作量 at-least-once。游标读取面保留作诊断。

### C4/C6/C11 租约续租与归还（shared + jobs）

- C4：`accountbalance/runner.go` 新增 `startOwnerLeaseRenewal` 续租协程（TTL/3 下限 5s），失租置原子标志并停止输入循环。
- C6：`proberepo` 新增 `ReleaseProbeClaim`（compare-delete）；`accountquality/cooldown.go` probeErr/observation==nil 两异常路径释放 claim。
- C11：`crossprocessstate` 新增 `Renew`（Lua compare-token PEXPIRE）；`oauthrefresh` LockRenewer 可选接口 + TTL/3 续租协程，release 先停续租再 Unlock；jobs `worker_oauth_crossprocess.go` 适配 `Renew` 委托 `EntityOAuthRefreshLock`。

### C5 outbox attempt 上限（jobs + gateway 双侧对齐）

- jobs `circuitstore/controlplane.go`：`outboxMaxAttempts=8`；ReleaseForReplay 事务内 SELECT FOR UPDATE 读 attempt_count，未达上限按 retryDelay 回 pending，达上限置终态 `failed`（claim 面清空、acknowledged_at_ms=now，与 dispatched 同走 ack 保留期回收臂）；Cleanup 臂扩 `status IN ('dispatched','failed')`；ReleaseForReplay 事务化。
- gateway `circuit_control_plane/store.go`：`ReleaseOutboxForReplay` 同构对齐（单 UPDATE 改事务 + 锁行读 attempt_count + failed 终态臂），常量 `outboxMaxAttempts=8` 与 jobs 对齐（两模块独立常量，注释互指）。
- schema：`juhe_business.account_circuit_outbox` 的 status 词表 CHECK 与状态不变式 CHECK 放宽 `'failed'` 终态臂并**具名**（`account_circuit_outbox_status_check` / `account_circuit_outbox_status_invariant`）；新增幂等约束替换 DO 块（`account-circuit-outbox-status-failed-pg-check`）把存量表旧约束按「表 + conkey 列 + 定义文本」定位替换（列级单列锚定 + 表级 `claim_until_ms`/`acknowledged_at_ms` 列组合锚定，排除 transition 校验与已含 failed 的新约束）；相邻 CHECK（event_type/dispatch_revision）不受影响；重复执行幂等。

### C7/C12 观测性与上限对齐（gateway + jobs）

- C7：gateway `key_model_runtime/redis.go` `acquireRecoveryScript` 探针并发上限 100000/100000 → 32/2，与 jobs `keymodelrecovery` 副本对齐（同一 Redis 键空间单一上限口径）。
- C12：realtime 连接位 `refresh` 改返回 `(bool, error)`，槽缺失 WARN（对齐账户并发槽 `slot missing on refresh` 观测面）；新增 count 清理脚本。
