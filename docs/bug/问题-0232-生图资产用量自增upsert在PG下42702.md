# BUG-0232：生图资产用量自增 upsert 在 PostgreSQL 下 42702 歧义——生图提交 100% 失败

## 基本信息

- 编号：BUG-0232
- 状态：已修复（随 2026-09-29 14:2x 发布）
- 严重程度：P1
- 发现时间：2026-09-29
- 发现方式：生产 grok-imagine 生图链路验证（工具错误透传 `ERROR: column reference "asset_bytes" is ambiguous (SQLSTATE 42702)`）
- 模块：网关 / chat 资产持久层（internal/chat/chatassets）
- 关联 bug：BUG-0230（同一验证链带出；0230 修模型收敛，本 bug 是提交层根因）
- 责任人：主代理

## 问题概述

- 现象：生产（PG）生图轮的资产提交事务 100% 失败——`incrementAssetUserUsage` 的 upsert 语句 `ON CONFLICT (system_account_id) DO UPDATE SET asset_bytes = asset_bytes + ?, asset_count = asset_count + 1` 右值自引用未表名限定，PG 报 `column reference "asset_bytes" is ambiguous (SQLSTATE 42702)`；事务回滚后 ObjectStore 回滚删除已写文件，chat-assets 目录残留空分片目录（生产 5 个），轮次以 `image_generation_failed` 终态，主模型重试耗尽 `MaxImageCalls=2` 后降级或失败。
- 期望：PG/SQLite 双方言下资产用量自增正确提交。
- 实际：SQLite（隔离实例）容忍裸列自引用全通，PG 必炸——**生产生图资产落库自该语句上线以来从未成功**（grok-imagine 路径 2026-09-29 首次真实触达）。
- 影响范围：生产全部「assistant_generated」生图资产提交（generate 与 edit 共用提交层）；非生图路径不受影响（该语句唯一调用点）。

## 复现步骤

1. 生产任意会话绑定生图账户触发 generate_image 子调用成功（上游 200 返回 b64）。
2. 资产提交事务在 `incrementAssetUserUsage` 处 42702 失败，回滚；轮次 `image_generation_failed`，chat-assets 出现空分片目录。
3. 服务器 psql 直跑同款未限定语句同样报 42702（2026-09-29 实证）。

## 环境信息

- 分支 / 版本：生产国内单机 Docker go-only（PG），gateway `8b9fd7d0f` 前各版本均含。
- 是否稳定复现：是（PG 下确定性失败；SQLite 不复现）。

## 根因分析

- `internal/chat/chatassets/assets_store.go` 的 `incrementAssetUserUsage`：upsert 右值 `asset_bytes = asset_bytes + ?` 未用表名限定。PG 对 `ON CONFLICT ... DO UPDATE` 的未限定自引用列报 42702（SQLite 同语句合法），方言差异在 SQLite 隔离实例上不可见。
- 全库排查：其余 `ON CONFLICT DO UPDATE` 写入点（accountkeystates×3、accounts×4、apikeys×1）均用 `excluded.` 或表名限定（`quota_hourly_dirty.go` 为正确限定范本），无同类问题。

## 修复

- `incrementAssetUserUsage` 右值改表名限定：`asset_bytes = <table>.asset_bytes + ?`、`asset_count = <table>.asset_count + 1`（`<table>` 经 `ports.Table` 按方言展开 `juhe_chat.chat_user_asset_usage` / 裸名，两方言均合法）。
- 生产 PG 直跑限定写法实证通过（INSERT 0 1）；隔离实例（SQLite）回归通过。
- 测试：新增 `internal/chat/chatassets/assets_store_test.go`（该包首个测试）——双方言固化 upsert 语句形状（禁止未限定自引用回归）。
- 同批关联修复（同链路带出）：BUG-0230 生图模型收敛（`8b9fd7d0f`）。
