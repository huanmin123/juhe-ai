# BUG-0336 自定义模型删除被软删账户悬挂引用外键拦截致 500

## 基本信息

- 编号：BUG-0336
- 状态：已修复（2026-10-24 热修发布）
- 严重程度：P2（管理面自定义模型删除全量不可用，无数据损坏）
- 发现时间：2026-10-24 01:36（用户生产报障）
- 发现方式：用户报障「删除模型的时候报错」（`DELETE /__aisys__/api/providers/deepseek/models/custom_model_*` → 500 服务器内部错误）
- 模块：后端 / providers 自定义模型目录

## 现象

生产删除个人自定义模型恒 500（网关日志 `failureReason`）：

```
ERROR: update or delete on table "models" violates RESTRICT setting of foreign key
constraint "account_supported_models_model_id_fkey" on table "account_supported_models"
```

## 根因（守卫口径 ≠ 外键口径）

- `DELETE /{code}/models/{modelId}` 的绑定守卫（`customProviderModelBindings`）统计支持模型/入口映射引用时 `INNER JOIN accounts … AND accounts.deleted_at IS NULL`——**只统计活账户**，活引用为 0 即放行删除。
- `account_supported_models.model_id` 外键为 RESTRICT，**不区分引用账户是否存活**——软删账户的悬挂引用行同样拦截 `DELETE models`。
- 生产数据（2026-10-24 取证）：`custom_model_1792638461836_1d64dcb1`（deepseek-flash-1）被 2 个软删账户（`deleted_at` 均为 2026-10-22，重建回迁批软删）的 `account_supported_models` 行引用 → 守卫计 0 放行 → FK 23503 兜底 500。
- 定性：既有契约盲区（守卫与 FK 作用域不一致），非本次发布引入；由 10-22 结构重建回迁产生的软删账户悬挂引用数据首次触发。`account_entry_mappings` 复合外键指向 `account_supported_models`，为同一死锁面的第二层。

## 修复（2026-10-24）

`deleteCustomProviderModel` 在同事务、`DELETE models` 之前增加死账户悬挂引用清理臂（与 BUG-0335 对称清理同款「依赖在同事务内一并解决（不是拒绝）」原则）：

1. `account_entry_mappings`：`target_model_id = 模型id` 与 `source_model = 模型名`（子查询在 models 行删除前求值）两类引用，限 `NOT EXISTS`（软删账户与孤儿行同覆盖）——先清 entry_mappings（其复合外键指向 supported_models，先解引用再删被引用行）；
2. `account_supported_models`：`model_id = 模型id` 且账户软删/缺失的行。

守卫语义不变：活账户引用仍在 handler 以 409「模型已绑定 AI 账户…」语义拒绝。

## 验证

- 回归 `TestProvidersDeleteCustomModelCleansDeadAccountReferences`：SQLite `PRAGMA foreign_keys = ON` 真实外键下——死账户三类引用（supported_models / entry_mappings target / entry_mappings source）随删除同事务清理、删除 200；活账户引用模型仍 409。既有 `TestProvidersDeleteCustomModel`（绑定守卫/409 文案逐字）不回归；providers 全包绿。
