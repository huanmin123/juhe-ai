## 问题概述

- 现象：K7 mock upstream 声称覆盖 16 个场景，但 `serve` 记录的请求事实只有 Method、Path、AuthHeader；结构体中声明的 Model、StreamField 没有填充或断言。
- 期望：mock 记录并校验模型、stream 等会改变协议和路由结果的字段，才能作为 Node/Go golden 的证据。
- 实际：即使模型映射或流式标志丢失，16 场景仍可能显示通过，无法发现关键请求契约漂移。
- 影响范围：后续 AI 网关整链迁移可能在错误模型、非流式/流式切换时产生漏测。

## 根因与证据

- 文件：`backend-go/projects/gateway/internal/mockupstream` 及其测试。
- mock response 的缓存头也与 Node 流式基线不同（`Cache-Control` 缺少 `no-transform`、未设置 `X-Accel-Buffering`），是否影响具体 golden 需在接线后确认。
- 现有测试只断言场景结果，不断言完整请求快照。

## 已确认子项：Go mock 不读取 OpenAI body 的 `stream` 字段

- 对照事实：Node 的 OpenAI mock 在读取 JSON body 后以 `body.stream` 决定 Chat/Responses 是否进入 SSE；标准客户端把 `stream: true` 放在 JSON 请求体中，不要求额外 query 参数或 `Accept` 头。
- 历史 Go：`serve2` 只检查 query `stream=true` 或 `Accept` 是否包含 `text/event-stream`，完全不解析请求 body 的 `stream` 字段。对 `POST /v1/chat/completions` 的合法 `{"stream":true}` 请求，若没有这两个辅助信号，会落入非流式 JSON 分支。
- 可观察结果：同一标准 OpenAI 请求在 Node mock 返回分块 SSE（含终止 `[DONE]`），Go mock 返回单个 JSON completion；网关的流式解析、首字节/中途断流和重试测试会被错误地当成非流式成功，无法发现真实协议偏差。
- 证据范围：Node 历史 `chat-gateway-mock-ai-regression.ts` 第 866–899 行先解析 body 并断言 `body.stream`；Go 证据为提交 `020888a7c` 的 `mockupstream.go` 第 147–168 行。该结论不依赖当前未提交工作区。
- 修复门槛：优先读取并校验 JSON body 的 `stream` 布尔值，再按 Node 兼容的 header/query 规则补充协议场景；增加仅 body `stream:true/false`、header 协商和冲突组合的请求/响应 golden。

## 已确认子项：流式 `slow_first_byte` 延迟被 Go 叠加两次

- 对照事实：Node 慢首字节 mock 在请求读取完成后只创建一个定时器，延迟配置时间后写入首个响应 chunk；首字节超时阈值应据此判断。
- 历史 Go：`serve2` 在识别 `ScenarioSlowFirstByte` 时先 `time.Sleep(m.slowDelay)`；若请求进入 SSE，随后 `serveSSE` 又在写首个 chunk 前再次 `time.Sleep(slowDelay)`。流式场景实际等待约 `2 * slowDelay`，非流式场景只等待一次。
- 可观察结果：相同 `slow_first_byte` 配置下，Node 可能刚好在首字节截止内返回，Go 却因额外延迟被误判为首字节超时/传输失败；重试次数、候选切换和质量样本会因此偏离，且测试结果依赖请求是否带流式标志。
- 证据范围：Node 历史 `gateway-quality-priority-real-sample-mock-ai-regression.ts` 第 503–531 行只在 slow 分支设置一次 timer；Go 证据为提交 `020888a7c` 的 `mockupstream.go` 第 106–112、225–227 行。该结论不依赖当前未提交工作区。
- 修复门槛：让每个请求只消耗一次首字节延迟预算，并补非流式/流式、零延迟和刚好跨阈值的耗时 golden；测试需断言首字节时间而非仅状态码。

## 已确认子项：Go Mock 缺少 `/v1/responses` 端点

- 对照事实：Node 的 `chat-gateway-mock-ai-regression.ts` 将 `/v1/responses` 与 `/v1/chat/completions` 一起作为合法 POST 入口，并按 `stream` 字段返回 Responses JSON/SSE 事件；Responses 是迁移总计划 §5.1 明确要求的 OpenAI 协议面。
- 历史 Go：`backend-go/shared/platform/mockupstream/mockupstream.go` 仅对路径后缀 `/chat/completions`、`/models` 和 `/embeddings` 做分支；`/v1/responses` 会落入未知路径并返回 404。16 场景测试也只请求 Chat Completions，没有 Responses 覆盖。
- 可观察结果：任何依赖 Responses 协议的 Go 网关、探针或 golden replay 都会收到上游 404，而历史 Node Mock 会返回合法 Responses 结果；因此协议选择、Responses JSON/SSE 解码、工具事件和失败归因无法得到等价验证，甚至可能被错误记录为上游账户故障。
- 证据范围：Node 历史 `backend/src/scripts/regression/chat-gateway-mock-ai-regression.ts` 第 852–899 行；Go 迁移提交 `020888a7c` 中 `mockupstream.go` 第 147–170 行；迁移总计划 `docs/migration/Node全量清零迁移总计划-20260904.md` §5.1/§5.2。结论不依赖当前未提交工作区。
- 修复门槛：增加 `/v1/responses` 的非流式 JSON、Responses SSE、工具/结构化输出及错误场景，并将请求体 `stream`、响应头和事件序列纳入与 Node 的 golden 对照；不能用 Chat Completions 的 404 代替 Responses 行为。

## 修复与验证

- 修改点：记录并断言 Model、StreamField、关键 headers/body，补齐流式响应头 golden；将 mock 记录纳入 G3 对照报告。
- 当前验证：现有 16 场景不能证明模型/流式字段契约，未执行真实 Node/Go replay。
- 结论：K7 当前测试 harness 覆盖不足，不能作为整链迁移验收证据。
