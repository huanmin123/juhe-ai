# BUG-0120 AI 账户支持模型空缓存长期续期

## 基本信息

- 编号：BUG-0120
- 状态：已修复
- 严重程度：P1
- 发现时间：2026-07-22
- 发现方式：用户反馈与浏览器复现
- 模块：前端 / AI 账户 / 模型目录 / 页面数据缓存
- 关联计划：PLAN-0115
- 关联 bug：BUG-0119
- 责任人：待定

## 问题概述

- 现象：新增 AI 账户时，“支持模型”已经显示默认模型标签，但打开下拉只显示“暂无数据”。
- 期望：每次打开账户支持模型下拉时读取当前供应商模型目录，其他浏览器或会话的模型修改在下一次打开时可见。
- 实际：前端可能直接复用错误空结果；表单打开时没有确定地发起模型候选请求，组件打开事件也不足以作为唯一加载入口。
- 影响范围：AI 账户新增、编辑及克隆入口。

## 复现步骤

1. 保留一份错误的空模型候选状态，同时确保后端模型目录已有可见模型。
2. 打开“我的 AI 账户”并新增 GPT API Key 账户。
3. 点击“支持模型”。
4. 观察下拉显示“暂无数据”，网络中没有 `/providers/models/options` 请求。

## 环境信息

- 分支 / 版本：`master` 与运行中页面数据开发工作树
- 数据状态：SQLite 中 GPT 有 82 个启用且目录可见模型；接口默认窗口返回 50 条，带 7 个已选模型返回 57 条。
- 浏览器 / 系统 / Node 版本：Chromium 150 / Windows / 项目支持的 Node LTS
- 是否稳定复现：是

## 根因分析

- 表象：模型下拉组件没有候选项。
- 真实根因：账户支持模型候选属于写入前事实选择器，却缺少表单生命周期的确定加载；旧实现还允许持久空结果被没有变化的确认结果继续复用。
- 为什么会发生：系统把下拉打开事件当作唯一加载入口，同时用 revision 是否变化代替响应内容是否正确；这无法纠正已经保存的错误空结果。

## 修复方案

- 修改点：账户支持模型候选每次打开表单或切换账户类型时直接请求当前模型目录；保留下拉打开与搜索刷新、in-flight 去重、作用域隔离和逆序响应保护。
- 行为影响：新增、编辑、克隆和账户类型切换都会加载当前候选；重新关闭再打开表单会再次请求，其他会话修改可在下一次打开时可见。
- 发布异常处理：请求失败时沿用现有错误提示，不把失败或空中间态写入持久缓存。

## 下次遇到

- 先查什么：打开表单或下拉时是否真正请求 `/providers/models/options`。
- 重点看什么：数据库和直连接口有数据、页面却无 GET 时，优先排查前端加载生命周期和旧缓存，不先归因于下拉渲染。
- 如何避免误判：删除一个已选模型后再次观察候选；仍无选项即可排除“已选项全部隐藏”。

## 完成总结
