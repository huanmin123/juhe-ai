# BUG-0217：AI 问答批次3 小修四项（toolCapabilities 不感知绑定模式、bind-options 无 no-store、弹窗空态缺失、Caddy my-chat 无显式 flush）

- 编号：BUG-0217
- 状态：已修复（待发布验证）
- 发现：2026-09-28，批次3 复审：绑定模式上线后的四项小缺陷收口

## 现象

- 工具能力不感知绑定模式：会话详情的 `toolCapabilities`（`web_search` / `generate_image` 可用矩阵）恒按会话鉴权 Key 的路由策略分组计算——`group` / `account` 会话的鉴权主体是专用对话 Key，其路由策略与绑定对象无关，工具能力作用域与模型列表/发送作用域错位。
- bind-options 响应无 no-store：`GET /my-chat/conversation-bind-options` 的绑定对象摘要响应缺少显式 `Cache-Control: no-store`，存在被中间层缓存返回陈旧启用状态的空间。
- 弹窗空态缺失：新建会话弹窗的分组/账户下拉为空时直接渲染空白列表，无任何提示，用户无法区分"确实无可绑定对象"与"加载失败"。
- Caddy my-chat 无显式 flush：`/v1/*` 反代块显式配置 `flush_interval -1`，`/__aisys__/api/my-chat/*`（管理面 SSE 流式发送）依赖 Caddy 对 `text/event-stream` 的自动刷新行为，SSE 增量传输存在被反代缓冲的隐患。

## 根因

- `toolCapabilities` 解析器按 Node 版语义读取 `conversation.api_key_id` 对应 Key 的路由策略分组，未随绑定模式设计同步收敛作用域。
- bind-options 端点未显式声明缓存策略；空态文案与反代 flush 属于同批收口的边界缺失，无独立根因。

## 修复

- `toolCapabilities` 按绑定模式计算：`group` 按绑定分组候选聚合、`account` 按绑定账户收敛、`api_key` 按 Key 路由策略分组（与模型列表/发送作用域同口径）。
- bind-options 响应补 `Cache-Control: no-store`，绑定对象摘要不落任何中间层缓存。
- 分组/账户下拉空时显示空态"暂无可绑定对象"。
- Caddyfile 为 `/__aisys__/api/my-chat/*` 反代补 `flush_interval -1`，对齐 `/v1/*`——SSE 增量传输不依赖反代自动行为。

## 验收

- 三种绑定模式的会话详情工具能力分别等于绑定分组聚合、绑定账户、Key 路由策略分组的作用域结果。
- bind-options 响应头带 `Cache-Control: no-store`；空对象列表时弹窗显示空态文案。
- 经生产 Caddy 的聊天流式响应逐 chunk 增量到达，无整段缓冲。

## 教训

- 新增绑定维度后要盘点所有"隐式读 Key 作用域"的读取面：模型列表、能力详情、工具能力、调度都各自取数，漏一处就是作用域错位。
- SSE 路径的每个反代前缀都应显式关闭缓冲，不能依赖代理对 content-type 的启发式行为。

## 状态

已修复（作用域收敛 + no-store + 空态 + 显式 flush），待发布验证。
