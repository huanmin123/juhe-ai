# BUG-0357 AI 账户编辑弹窗代理字段显示裸 proxy id

- 级别/状态：P2（管理面/用户面展示缺陷，不影响 /v1 业务），已修复待发布
- 报告：2026-11-06，用户在 AI 账户编辑弹窗发现「代理」字段显示为 `proxy_1777640812267_3526b278`，而非代理名称；同一账户在列表中显示正常名称。

## 现象与触发条件

- 「AI 账户 → 编辑」弹窗的代理下拉在部分会话显示裸代理 ID，同一账户在列表「代理」列显示名称。
- 「有时」的成因：代理候选按需加载（页面初始化不预取，只有展开代理下拉或输入搜索词才请求 `/proxies/options`）。同一浏览器会话里先展开过任意代理下拉后，名称缓存被预热，后续编辑就显示名称；直接刷新页面后第一次编辑则显示裸 ID。

## 根因

前端展示链路缺少冷缓存下的名称来源，不是后端返回错误：

1. 账户列表行携带代理展示字段（`proxyProfileName/Type/Enabled`，`accounts/list.go` LEFT JOIN `proxy_profiles`），列表列正常显示名称。
2. 编辑弹窗的代理选择只从高级详情拿到 `proxyProfileId`（`AccountAdvancedDetail` 只投影 ID，无名称），而候选列表仅在下拉展开时加载；冷会话下 `CachedSelect` 的已选值占位分支（`label: value`）把裸 ID 当作稳定展示。
3. `AccountsView` 的代理 options scope 早已为编辑选中项准备了 `selectedIds` 回填（`useAccountProxyOptions`），但从未有调用点在打开编辑时触发 `load()`；`openEditAtPath` 拿到列表行后只用于授权账户分支，行内代理展示字段被丢弃。

违反《前端通用组件规范》§3.5：候选未就绪的裸值占位只是过渡态，不得作为最终稳定展示；名称缺失应优先从数据回填、接口返回或组件选中态修正。

## 修复（前端，2026-11-06）

- 新增 `frontend/src/views/accounts/accountProxyDisplay.ts` 的 `rememberAccountProxyLabel`：用列表行经 `accountProxyDisplay` 派生的展示字段，按与候选相同的标签格式（`名称（类型，已停用）`）写入 `proxyLabelCache`；行内无代理 ID 或无名称（代理已删除/不可见）不写入，避免把空名称拼成「（类型）」。
- `useAccountEditForm.openEdit` 在加载编辑详情前调用该回填：列表编辑是唯一存在代理 ID 且缓存可能为冷的入口（创建成功转编辑时缓存由创建时的下拉选择预热）。
- 代理候选仍按需加载，页面初始化不新增任何代理请求；编辑打开后也不会为回填额外请求 `/proxies/options`（列表行数据已足够）。

## 验证

- 单测：`accountProxyDisplay.test.ts` 4 例（行内展示优先、不可用回退、标签格式含停用后缀、无 ID/名称不写入）；`useAccountEditForm.test.ts` 新增 1 例断言 `openEdit` 回填标签（移除调用时该用例实测为红）。
- `npx vue-tsc --noEmit` 通过；`vitest` 相关 27 例通过；`test:account-proxy-options-lazy-loading` 回归通过（仍不预取候选）。
- dev 环境真实页面（管理面 `/accounts/chat`，冷会话整页刷新后直接打开编辑）：打开前无 `/api/proxies` 请求，代理字段显示「本地验证代理（socks5h）」；修复前同一路径显示 `proxy_620601cc1439834b`。验证用代理与账户绑定已还原，代理已删除。

## 已知边界

- 代理已被删除或当前用户不可见时，列表行也没有名称，编辑弹窗仍只能显示裸 ID（无名称可回填）；列表列同样回退「代理已配置」+ 提示，未新增编造名称。
- 代理在列表加载后被重命名时，编辑弹窗先用行内旧名称，展开下拉后由候选标签覆盖为最新名称。
