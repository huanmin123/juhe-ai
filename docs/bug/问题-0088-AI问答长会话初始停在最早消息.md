# BUG-0088 AI 问答长会话初始停在最早消息

## 基本信息

- 状态：已修复（浏览器验证）
- 严重程度：P2
- 模块：前端 / AI 问答 / 长会话 / 虚拟列表 / 滚动
- 发现时间：2026-07-13
- 发现方式：桌面浏览器完整验收
- 关联计划：PLAN-0095
- 关联 bug：无

## 问题概述

切换到已有长会话后，虚拟消息列表默认停在最早一条。用户必须手动滚动到底部；由于没有发生“从底部上滚”的状态转换，跳底按钮也不会出现。

## 根因分析

`selectConversation` 在消息和模型加载完成后只解除 loading，没有等待虚拟列表挂载并调用 `scrollToBottom`。新会话发送路径会主动落底，但历史会话选择路径缺少同样的初始化动作。

## 修复方案

当前会话和 load epoch 仍有效时，先解除加载状态，等待一次 Vue `nextTick`，再让消息列表测量并定位最后一条；`scrollToBottom` 同时重置用户脱离状态和跳底按钮。

## 验证记录

- 80 条虚拟消息会话加载后：`scrollTop=6299`，距底部为 0。
- 用户向上滚动 1800px 后：距底部 1730px，出现“回到底部”悬浮按钮。
- 点击按钮后：距底部恢复为 0，按钮消失并恢复自动跟随。
- 390×844 移动端下输入区、会话按钮和消息滚动互不遮挡。

## 下次遇到

- 长列表初始位置必须在真实虚拟列表挂载后验证，不能只测试纯滚动策略函数。
- 同时检查初始落底、用户上滚、流式追加不抢滚动、跳底恢复四个状态。

## 完成总结

- 完成时间：2026-07-13
- 结论：历史长会话选择路径与新消息发送路径统一以最新消息为默认视点。
