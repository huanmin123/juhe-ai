## 问题概述

- 现象：M04 `authorizations` Go 实现没有接入 gateway，且其路由、owner scope、资源绑定、校验、幂等、DTO 和副作用均未达到 Node 契约。
- 期望：授权创建、查询、修改、撤销、过期、用量和 team/account 绑定必须保持 Node 的权限边界、状态结果、CAS、缓存/统计/健康副作用。
- 实际：
  1. Go 缺少普通用户 self create/update/revoke、usage 聚合和 team/user detail 等 Node 端点。
  2. 历史 Go 实现未用 `?systemAccountId` 做 owner scope 校验，管理员可操作其他 owner 的授权（已修复创建路径；列表/修改/撤销 scope 仍待复核）；account 资源读取了不存在的 `resource_owner_system_account_id` 列，且 `targetGroupId` 未写入 `group_accounts` 绑定，后者还依赖未迁移的授权实例创建链路，当前不能用局部写入冒充完整修复。
  3. team grant fanout 历史实现未排除 owner（已修复）；历史实现对 owner-only 团队仍创建空 fanout grant（已修复）；历史实现 active grant 上限存在 20→21 的 off-by-one（已修复）；历史实现对相同 active 授权未返回 Node 的 `{created:false}` 幂等结果（已修复）；历史实现对 terminal grant 会插入第二条 active 行并返回 `created=true`，现已修复为复用原行并返回 `created=false` + `previousStatus`，变更后的 active 重复请求仍按 Node 返回冲突。
  4. expiresAt/limits/remark 校验放宽，self list 忽略 direction，team member 详情可见性缺失；Summary/usage DTO 缺少前端需要的 effective source、权限、limits、usage 和聚合字段。创建路径的 expiresAt 严格 RFC3339、UTC 毫秒规范化、不得早于当前时间及不得晚于源账户到期时间已在本轮确认并修复。PATCH 首轮对照已确认仍存在：路由/Store 不能区分字段缺失和 JSON `null`，因而不能按 Node 清除 expiresAt/limits；Store 直接写入 expiresAt，遗漏 RFC3339 规范化、过去 expiresAt→expired、expired→active 恢复及账户到期上限规则，并且没有把变更同步到 runtime；相同值 PATCH 仍写入新版本而 Node 返回 unchanged；`?systemAccountId` 管理员 scope 未传入 Store，可能修改筛选 owner 之外的授权。PATCH 保持单独待修复。
  5. 已撤销授权再次撤销返回 404 而 Node 返回 unchanged 200；过期/写入缺少 quota/group/cache/health 副作用。
  6. create 的 `ProcessingTTL: 120_000_000` 在 Go 中为 120ms，Node 默认 120s（BUG-0155）。
- 进一步确认：账号资源 owner 查询使用不存在的 `resource_owner_system_account_id` 列，真实 schema 只有 `system_account_id`；`targetGroupId` 未写入 `group_accounts`，导致账号授权创建失败或丢失绑定。团队 runtime 刷新还未按 resource type/id 精确过滤，可能误激活无关授权。
- 影响范围：授权功能无法完整使用，并存在越权操作、账号授权创建失败、授权来源错误、重复写入和旧缓存继续生效风险。

## 根因与证据

- 当前验证：提交 `5f2341504` 修复相同 active 授权的幂等创建结果；提交 `a1dafba60` 复用 terminal 行并返回 `created=false`、`previousStatus`，新增 returned→active 回归并验证不会产生第二行；提交 `c4b2886e7` 将团队上限判断修正为“新增后不得超过 20”，并覆盖第 20 条允许、第 21 条拒绝；提交 `f8a3c9669` 过滤团队内资源 owner，验证不会生成 owner runtime 行；提交 `25ddb320e` 在 fanout 前拒绝 owner-only 团队并验证不落 grant；提交 `a5ef114ab` 在创建路径强制 owner scope，并覆盖跨 scope 拒绝；后续共享提交 `d6ea6eef1` 带入空 `limits:{}` 与 `NULL` 等价的幂等修复，独立复审通过。本轮对照 Node `normalizeResourceAuthorizationExpiresAtInput`、`validateResourceAuthorizationExpiresAt` 确认历史 Go 创建路径遗漏严格时间输入、未来时间、账户到期上限，并在修复前确认“资源不存在 + 已过期时间”的错误优先级偏差；提交 `46a61aae4` 实施最小创建路径修复并加入回归，独立复审通过。定向 `go test`、`-race`、`go vet` 与 `git diff --check` 均通过；仍仅覆盖窄路径，未覆盖上述权限和跨表副作用。
