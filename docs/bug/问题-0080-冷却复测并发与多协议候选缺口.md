# BUG-0080 冷却复测并发与多协议候选缺口

- 模块：AI 账户 / PostgreSQL / SQLite / ops-worker / 冷却复测
- 关联计划：PLAN-0096
- 关联 bug：BUG-0013

## 问题概述

- PG 冷却失败计数在事务外读取，两个重复探针可同时把 N 写为 N+1，延迟 7 天终态收敛。
- 常规健康检查与冷却候选都曾只接受 OpenAI profile，执行器已支持的 Anthropic / Gemini 等生成协议账户会无法激活或永久停在临时不可调用。
- 候选筛选扩大后旧索引不再匹配谓词与排序，存在大表 filter / sort 风险。

## 根因与修复

- PG 改为事务内 `SELECT ... FOR UPDATE` 后决策和更新；SQLite 用 `BEGIN IMMEDIATE` 串行读改写。
- 常规健康检查和冷却候选统一按八种可检查生成 endpoint mode 收敛，不开放工具、计数、嵌入和文件接口。
- 当前 schema 增加与候选谓词和排序一致的 partial index，并用真实 PG EXPLAIN 门禁验证。
- 对旧版本已经写入的 24 小时未来计划只允许一次性条件化缩短：必须仍是系统生成的长期不可用错误、状态/调度/授权/分组均有效且原始 `cooldown_until = last_at + 24h`。使用行锁和 CAS 更新，并保留修正前快照；人为 `schedulable = 0` 的账户禁止批量恢复。
