## 问题概述

- 现象：`maintenance --seed` 创建 `sys_admin`（username=admin，密码=admin，super_admin），`must_change_password=0`——登录后全局 403 改密 gate（authsys/middleware.go:219）不触发，完全依赖部署者手工改密。
- 期望：固定公开默认密码的初始账户必须被技术强制首登改密。
- 实际：新部署/重置 schema 后到人工改密之间存在管理面完全接管窗口（管理面公网可达）。
- 影响范围：仅新 seed 实例；现有生产已改密且 seed 的 `ON CONFLICT DO NOTHING` 不改写既有行，零影响。

## 根因分析

- 表象：seed 参数第 8 位为 0。
- 真实根因：Go seed 头注释声称移植自 Node 归档 `postgres-seed-defaults.ts`，但归档内不存在任何 seed 文件（`storage/schema/` 目录整个缺失）——不存在可遵循的 Node seed 契约值，置 0 无依据。Node 通用创建路径的 `normalizeSystemAccountMustChangePassword` 对 admin 角色恒 false，但那属"管理界面创建（密码由创建者设定）"场景，不含固定公开默认密码概念，不能类推。
- 裁决依据（写入 pg_schema.go 常量注释）：①归档无 seed 证据；②Node/Go 运行时 403 gate 均无角色豁免（置 1 对 super_admin 同样生效，两侧同型）；③docs/deploy/部署指南.md 现行人工步骤"首次登录立即改密"即系统意图；④固定公开默认密码必须强制更换。裁决：置 1。

## 修复方案

- 修改点：`pg_seed.go`、`pg_schema.go`（EnsurePostgresSeeds 第二调用点）、`sqlite_seed.go` 三处 sys_admin 插入的 must_change_password 置 1；裁决依据全文写入 `pgSeedSystemAccountsInsert` 常量注释；测试断言（sqlite_seed_test、wm_pg_seed_test 及两处 PG smoke）同步扩展 must_change_password=1。
- 行为影响：新 seed 实例首登命中 403 强制改密；现有实例零影响。开发自动登录已核验不受影响——`developmentAutoLogin()` 硬编码 `MustChangePassword: false` 且该路径在 sessionMiddleware 中直接放行不经 gate（middleware.go:186-192/280），隔离开发流程（JUHE_AI_DEV_AUTO_LOGIN_USERNAME=admin）不受 seed 置 1 影响。
- 发布异常处理：不适用（不重跑 seed）。
