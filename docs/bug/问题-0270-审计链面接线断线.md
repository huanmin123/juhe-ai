# 问题-0270：审计链面接线断线（计价/HTTP 完成/首字/上游响应头全空）

- 编号：BUG-0270
- 状态：已修复（2026-10-03），待发布
- 发现：BUG-0269 后的全量排查（四线取证 + 生产只读实证）发现审计面多字段恒空。

## 现象

生产 `juhe_dataset.audit_logs` 13,691 行实测：`pricing_model`、`http_completed_at`、`http_duration_ms`、`first_token_ms` 全 NULL；`audit_payload_refs` 中 `upstream_response` 8,498 条只有 624 条带 headers（对照 `client_request` 9,577/9,577、`upstream_request` 8,864/8,864 全带）。失败尝试（必捕获）与采样成功的上游响应头是排障关键证据，几乎全丢。

## 根因（BUG-0267/0269 同族：结构在、生产构造不喂）

1. `newAuditCapture`（`cmd/juhe-ai-gateway/chain_v1_audit.go`）不传 `AuditCaptureInput.Pricing` / `SyncPricingAllowed` → `auditModelAccounting` 的同步计价门恒关，`pricing_model` 恒空。
2. 不传 `HTTPCompletion` → 审计 finalize 内联 flush，`http_completed_at` / `http_duration_ms` 无源。
3. 生产审计适配器（`preauthAuditCapture` / `chainResponseAuditCapture`）未实现 `gatewayresponse.AuditFinalizeExtender`，响应层算好的 `AuditFinalizeExtras.FirstTokenMs` 被类型断言静默丢弃（只有测试替身实现了扩展面）。
4. `chainResponseAuditCapture.CompleteAttempt` 用 `input.ResponseHeaders.(map[string]any)` 断言，而响应层传入的是 `http.Header`（`map[string][]string`）→ 断言恒失败、headers 吞掉；少量 624 条来自 dispatch 失败分支（传的是 map）。
5. `OffloadPayloadRetention` 未置 true（Node processRole==='server' 语义）。

## 修复

- `chain_v1_audit.go`：注入 `Pricing` / `SyncPricingAllowed`（与 chainFinalizationUsage 同源的 finalization 计价面）、`OffloadPayloadRetention: true`；`CompleteAttempt` 对 `http.Header` 增加类型分支（键形态与审计 payload 既有 `responseHeadersToObject` 产物一致），保留 map 透传。
- 两个适配器实现 `FinalizeExtended`（共用 `finalizeAuditInputOf` 转换 + extras.FirstTokenMs），响应层只调 Finalize/扩展面其一，无双写。串行全量验证轮补齐第二处投影缺口：`extras.AccountID`（`nonstream.go`/`nonstreaminspection.go` 响应层随扩展面传入的账户归属，`gatewayusage` Finalize 消费侧用它覆盖审计行 accountId）此前同样被丢弃——全量跑出守卫测试红后修复。
- 新增每请求 HTTP 完成观测 `gatewayHTTPCompletion`（`cmd/juhe-ai-gateway/chain_http_completion.go`）：请求入口创建、handler 返回 defer 处 complete（对齐"Go 的请求终态=handler 返回"既有注释语义），注入 `AuditCaptureInput.HTTPCompletion`；同一 subject 适配 `gatewayresponse.HTTPCompletionObserver` 接入 `SinkDeps`，失败 usage 的 `CompletedAtMs` 也从"记录时刻"回正为"HTTP 完成时刻"。

## 测试

`chain_audit_observation_gap_test.go`：subject 信号语义（先注册/先完成/幂等/cancel）、启用态审计在完成信号后 flush 且两列落值（修复前恒内联且为空）、attempt/主行 pricing_model、FinalizeExtended 带首字、http.Header 分支带头部、sink 失败行 CompletedAtMs/Model/Stream。集成轮修正：链替身 `auditGapChain` 补接 `usageModelResolver: usageModelResolverAdapter{}`（与 chain_compose.go 同源）——缺省时 `auditModelAccounting` 的 Models 为 nil，映射解析被整体跳过、定价入参回落请求模型，pricing 守卫测试转红后修复。

## 残余项

- `RecordFailedUpstreamAttempt`（死方法）字段已对齐但仍无生产调用方。
- 成功 usage 记账的 request/response 快照写入侧仍缺（BUG-0269 残余，读取侧已退场）。
