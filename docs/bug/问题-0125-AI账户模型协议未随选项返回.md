## 问题概述

- 现象：AI 账户选择纯图片模型后，“检查请求形态”和表单人工测试仍显示 Responses 文本协议。
- 期望：模型选项加载时同时返回协议，选择模型后立即联动为 `Images API`，不再追加能力请求。
- 实际：供应商模型选项与账户测试模型选项只返回 `id/name`；前端依赖后续能力接口，账户表单字段甚至完全没有消费模型协议。
- 影响范围：AI 账户新增、编辑、草稿测试和列表人工测试的协议展示与交互连贯性。

## 根因分析

- 模型目录存储已经包含 `supportedApiProtocols`，但模型选项合并阶段主动裁剪了能力字段。
- 前端选中支持模型后逐个请求能力详情；请求未完成或没有触发时，检查请求形态回退到账户默认 Responses。
- 账户测试模型列表同样裁剪能力，模型切换依赖第二个单模型能力请求。
- 现有回归固化了 `id/name` 轻量契约，只覆盖能力计算函数，没有挂载并验证表单联动。

## 修复方案

- 模型选项响应携带协议及账户表单已消费的其他模型能力。
- 账户测试选项响应携带协议与后端计算后的 `testEndpointModes`。
- 前端直接使用列表响应联动，移除正常流程中的逐模型能力请求。
- 后端提交阶段保留权威校验，避免客户端能力快照过期导致错误执行。

## 验证记录

定向后端 HTTP / 任务边界回归、前端协议联动 / 懒加载回归、前后端类型检查和前端生产构建均通过。隔离开发实例中验证 `gpt-image-2` 在账户新增和人工测试界面均直接显示 `Images API`，切换模型没有追加能力详情请求；详见 `docs/plans/计划-0168-20260724T144653184Z-AI账户模型协议随选项返回.md`。

- UI 联动测试必须断言网络请求数量和选中模型后的实际请求形态，不能只测纯函数。
