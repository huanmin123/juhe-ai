# 问题-0287：探针分级超时在响应体中途到点时不晋级，慢上游 10s 一票终审

## 基本信息

- 编号：BUG-0287

- 严重程度：P2（手动测试对慢上游确定性误报；自动探针对慢而可用的账户记确定性负向证据）
- 发现时间：2026-10-07
- 发现方式：用户手动账户测试报障 + 代码/文档契约比对
- 模块：`shared/platform/accounttest/accountprobe`（executeAttempt 读取中断分类 × 分级阶梯晋级判定）
- 关联文档：`docs/functions/AI账户检查模型与人工测试设计.md`（固定 Key 诊断器阶梯契约）、`docs/functions/账号健康检测设计.md`（健康检查阶梯契约）

## 问题概述

- 现象：手动测试 gpt-6-luna（推理模型，经慢中转）固定报「上游返回 HTTP 2xx，但响应中缺少所选检查协议的完成证据」（`invalid_protocol_success_response`），`firstTokenMs=9284`、`durationMs=10020`；`responseText` 显示流已正常开始（`response.created` → reasoning 完成 → message 开始）。
- 期望：探针分级超时契约「真实上游超时才按 `10s -> 20s -> 30s` 阶梯重测」（人工测试设计/健康检测设计两处权威文档）——慢流应晋级 20s/30s 重测，预算内能读完即成功。
- 实际：一级 10s 预算在响应体中途到点掐断读取后，观测被归为 `read_incomplete` 且 `TimedOut=false`，而阶梯晋级条件只认 `TimedOut=true`——慢流永不晋级，10s 一票终审，报因误导为「缺完成证据」。
- 影响范围：手动测试（诊断误报，不改运行态）；自动探针同链路（激活检查、周期健康、质量确认、冷却复测、速度优先）——慢上游账户在 10s 处确定性失败并被记 `upstream_failure(transport_incomplete)` 负向证据（传输电路、账号冷却、Key 恢复消费该证据），「慢但能用」的账户可能被反复打入冷却。

## 根因分析

- 表象：`invalid_protocol_success_response`。
- 真实根因：Go 移植版 `executeAttempt` 对「HTTP framing 完成但响应体读取中断」（`readUpstreamWithClient` 返回部分响应体 + readErr）的两种子态未分流——
  1. **本级预算到点**（`context.DeadlineExceeded`/超时错误，探针自己掐断）：这是探针侧超时，上游可能正常，只是没读完；
  2. **上游真实读取中断**（连接重置/ unexpected EOF 等非超时错误）：这才是 `read_incomplete` 的本义。
  
  两者都被统一归为 `TransportFailureRead` + `TimedOut=false`（该强制覆盖自 Go 移植初始版本即存在，`b1878b352` 只补了「部分内容已证成功则保留成功」分支），而 `probeFixedKey`/`probePoolDetailed`/`attemptStaged` 的晋级条件均为 `Evidence.TimedOut == true` → 子态 1 永不晋级。
- 为什么会发生：分级阶梯仅对「响应头都未按时到达」（`response == nil` 路径，`classifyAttemptError` 归 `server_diagnostic_timeout`）生效；「响应头到达、流中途被预算截断」走 `classifyResponse` 分类后证据被改写，脱离了超时口径。

## 修复方案

`executeAttempt` 的 readErr 分支三分流（语义成功保留分支不变）：

1. **本级预算到点 + 失败口径为缺证据 + 已读部分无可解析上游错误码** → 改判探针侧超时：`TransportFailureKind=timeout`、`TimedOut=true`，终审 `server_diagnostic_timeout`/「账户测试超时」（与 framing 未完成超时同口径；limited 脱敏为「上游请求失败」），分级阶梯正常晋级。部分响应体、HTTP 200 状态等诊断信息保留。
2. **上游真实读取中断**（非超时错误）→ 维持 `read_incomplete` + `TimedOut=false`，不晋级、不掩盖真实上游故障。
3. **已读部分带明确上游错误语义**（可解析上游错误码，或失败口径已非缺证据）→ 即使是预算到点的截断也不改判，维持原分类不晋级。

- 判据实现：`transportFailureFromError(readErr, timeout).timedOut`（复用既有超时谓词）+ `ErrorCode == invalid_protocol_success_response`（提升为常量 `errorCodeInvalidProtocolSuccessResponse`）+ `parseUpstreamErrorCodeFromBody(部分响应体) == ""`。第三条不可省：非 images 模式下 2xx+错误信封的对外错误码本就统一落缺证据口径，不加该条会把「截断前上游已给出错误」误判成探针超时。
- 明确不修（定性非缺陷）：`DiagnosticTimeoutExhausted` 生产不置位维持现状（阶梯耗尽后的自动结局两种 kind 同为 `upstream_failure`，结局分类不受影响）；非 images 模式错误信封的对外错误码口径维持 `classifyResponse` 既有锁定行为。
