# BUG-0367：探针用量毒批次楔死统计聚合（空 systemAccountId 记录整批拒绝 → 队头永久阻塞）

- 级别：P1（统计面停摆 6.5h+，业务请求不受影响）
- 状态：已修复并上线（2026-11-17，v2026.11.17，commit `61559089b`）
- 关联：#T210（事故主条目，本档案为已上线修复记录）、#T211（告警盲区收口）

## 现象

2026-11-17 09:33 CST 起 `usage-stats-aggregation` / `client-ip-stats-aggregation` / `account-quality-refresh` 全部跳过轮次（`jobsched_run_failed`：「使用记录 ingest 队列已有 N 次写入失败且仍有待处理记录，本轮跳过统计聚合」），统计游标卡死 `usage_stats_aggregation.last_success_at=01:33Z`（9:33 CST），lag 6.5h+；gateway 侧用量落库正常（673-1465 行/时）。用户于 15:5x 发现上报（无告警推送）。

## 根因链（四步）

1. **09:33 PG 瞬时抖动**：`probeUsageWriter.resolveScope`（`jobs/cmd/juhe-ai-jobs/worker_health_usage.go`）账户查询出错时**静默返回**（注释声称「账户已删除时跳过」，代码未实现），探针用量记录以**空 `SystemAccountId`** 入队；
2. `usagewriter.NormalizeUsageRecordInput` 无 `SystemAccountId` 完整性规则（gateway 路径恒有值，缺口从未暴露）；
3. PG 写入端 `rows.go` 硬校验缺失 `systemAccountId` **整批 1000 条拒绝**，每秒重试永远失败 → 队头永久阻塞（pending 1097 条、flushFailureCount 单边爬升 74→79+）；
4. `jobs/internal/ingestgate` 粘性门控（flushFailureCount>0 且 pending）→ 全部统计聚合跳过轮次。
生产核实：全库 0 条合法空 `system_account_id` 记录；磁盘 spool 文件全部合法——毒记录仅在内存队列。

## 修复（v2026.11.17）

1. `worker_health_usage.go`：`resolveScope` 三态化——`sql.ErrNoRows`（账户已删）→ 跳过补记（nil，无告警噪音）；查询错误 → 返回错误、**不入队**（上游 warn）；解析出空 owner → 拒绝。空 owner 记录绝不再进入队列。
2. `usagespooldrain`：spool 记录准入增加 `systemAccountId` 必填校验，毒文件走既有 `.corrupt` 隔离语义（保留现场、不阻塞后续文件）。
3. 平台归一化未动（避开 ~70 测试夹具），生产方入口双闸 + PG 校验兜底。
4. 测试：探针四态脚本驱动回归（跳过/查询错误拒绝/空 owner 防御拒绝/正常入队）+ drain 毒文件用例 + t207 durable 拒绝语义保留。

验证：jobs build/vet、usagespooldrain+ingestgate+usagewriter 包全量、cmd 定向全绿；上线后 flush 失败 0、门控跳轮 0、游标从 16:33 恢复推进并追平积压、usage 正常。
