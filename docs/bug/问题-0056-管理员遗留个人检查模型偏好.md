## 问题概述

Node `findProviderDefaultHealthCheckModel` 和异步入口对所有目标系统账户都按“个人偏好 > 系统默认 > 协议档案”读取。历史数据中如果 `admin` 或 `super_admin` 仍残留 `provider_default_health_check_models` 个人偏好，该值会覆盖管理员应使用的系统默认。

Go W1b 已在 provider profile 查询中通过目标账户角色排除管理员个人偏好，实际优先级为：

- 普通用户：个人偏好 > 系统默认 > 协议档案。
- 管理员和超级管理员：系统默认 > 协议档案。

因此问题位于仍在生产使用的 Node repository，Go 不需要回退。

## 根因分析

- 健康检查模型与人工测试模型解耦后，管理员默认值已经迁到独立的系统默认表，但 Node 通用读取函数仍无条件查询旧个人偏好表。
- 原回归覆盖了个人偏好、系统默认和协议档案三层值，没有构造管理员遗留个人偏好数据。
- SQLite 同步、SQLite read worker 和 PostgreSQL async 共用逻辑，但缺少角色查询边界，导致三条路径会一致地产生错误结果。

## 修复方案

- 在读取个人偏好前按 `system_accounts.id` 有界查询目标角色，并固定 `LIMIT 1`。
- `admin` 和 `super_admin` 跳过个人偏好；普通用户继续保留现有优先级。
- 无 `systemAccountId` 或未知 ID 时不命中个人偏好，继续回退系统默认和协议档案，与 Go 当前查询一致。
- SQLite 同步入口、SQLite read worker async 和 PostgreSQL async 使用同一规则；PostgreSQL 使用 schema-aware `DatabaseClient`。
- 回归构造 user/admin/super_admin 三类账户和遗留偏好，断言 read worker 实际处理异步读取，并保留 PostgreSQL 查询结构门禁与安全清理。
