# 账号类型统计缓存边界决策

## 背景

GPT 账号当前支持 OAuth 和 API Key 两种创建方式。两者上游链路不同：API Key 账号按公开 OpenAI-compatible API 透传，OAuth 账号走 Codex adapter。调度时同一分组可以同时存在两类账号，失败、冷却、并发饱和或路径能力差异都可能导致同一个本地 API Key 在不同上游账号之间切换。

如果把 OAuth / API Key 账号类型或具体上游账号 ID 写进统计、会话亲和或 prompt cache 隔离键，切号会把同一个客户端身份拆成多份统计和多份缓存，长会话体验会变差，API Key / 分组用量也会难以解释。

## 决策

- 账号类型只影响能力矩阵、上游转发方式、凭据刷新和账号运行态展示。
- 本地统计默认不按账号类型切分；`api_key`、`group`、`system_account`、授权和调用方统计都以本地身份为准。
- 会话亲和 key 只按 `system_account_id + api_key_id + 客户端会话标识` 隔离，不加入 `group_id`、账号类型或上游账号 ID；`group_id` 只作为迁移和排障时的上下文，不参与亲和 key。
- OAuth Codex 写给上游的 `session_id`、`conversation_id` 和 `prompt_cache_key` 也只按同一层本地身份隔离，不加入具体上游账号 ID。
- 网关运行配置缓存按本地 API Key、分组和调用方系统账户缓存账号池，不按 OAuth / API Key 类型拆缓存。
- 账号自身维度统计仍保留，用于账户质量、性能和真实账号总量；这不是账号类型统计分片。

## 影响

- 同一个本地 API Key / 分组下，命中 OAuth 账号或 API Key 账号时，API Key 和分组统计合并到同一本地口径。
- 同一个客户端会话在同一 API Key 下切换分组或上游账号时，尽量保留会话亲和和 prompt cache 连续性；分组仍只通过 API Key 路由和候选池边界约束实际可用账号。
- 前端可以展示账号类型，也可以把账号类型作为账户列表筛选条件；默认业务统计、额度和缓存不能新增 `oauth`、`api_key` 或 `account_type` scope。
- 混合分组仍要尊重路径能力差异：OAuth 不支持的路径可以由同组 API Key 账号承接；如果没有可用账号，网关返回本地错误，不做重型协议翻译。

## 验证

- `test:usage-stats-batch-statement` 覆盖同一 API Key / 分组下 OAuth 和 API Key 账号命中后的统计合并。
- `test:session-affinity` 覆盖亲和 key 的本地身份边界、跨账号类型亲和排序，以及非绑定账号失败不误删当前会话亲和。
- `test:openai-oauth-codex-adapter` 覆盖 OAuth Codex session / prompt cache key 不随上游账号切换变化。
- `test:gateway-runtime-cache` 覆盖网关运行配置缓存的本地 API Key / 分组账号池缓存和失效链路。
