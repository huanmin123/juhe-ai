# 上游探针请求信封统一设计（系统探针唯一构造源）v3

- **状态**：v3 契约已按用户“把剩余的改完”指令进入实施（2026-10-12）；F2–F4 最终接线及集成验证按 §9 和关联计划推进，当前状态见验收报告。v2 复审意见及处理见 §0。
- **目标**：让系统发起的账户测试、模型检测、健康/恢复探针共用一条上游 HTTP 请求构造路径；探针内容仍由各探针族定义。
- **驱动事故（脱敏）**：一个 `profile_gpt_openai_v1` 账户在 `responses_sse` 模式下，模型检测首个 `protocol_basic` 请求收到输出预算低于上游最低值的 HTTP 400；同账户账户测试成功。具体生产账户、run 与 trace 标识留在私有运维记录，不进入架构文档。
- **范围边界**：本设计只定义系统生成的探针请求（F2–F5），不声称 `/v1` 用户请求也已使用同一构造源。若“全系统一份”要求还覆盖 `/v1`，须另行设计其透传与热路径边界；本稿不把该目标标记为已完成。

## 1. 现状事实与范围清单

| 面 | 触发场景 | 当前构造位置 | 当前预算事实 |
| --- | --- | --- | --- |
| F1 `/v1` 用户请求 | 客户端调用 | `gatewaydispatch` 请求准备；客户端 payload 原样透传并由网关准备上游目标 | 保留客户端字段。本设计不迁移，也不声称全仓请求构造已统一。 |

| F3 模型检测探针 | 手动或定时 quick/full 检测 | `modelcheckprobe` 的协议 builder、探针族 builder 与 suite | 当前按协议和探针族不同：首个 Responses `protocol_basic` 是 `max_output_tokens=16`；Chat 有 64 下限、Gemini 有 128 下限；采样、身份、Token 完整性及 quiz 另有语义预算。不得把它们误写成一个现有值。 |

| 端点 / 形态 | 已知模式或行为 | 请求体与预算边界 |
| --- | --- | --- |
| OpenAI Chat / Responses、Anthropic Messages、Gemini GenerateContent | JSON 与 SSE；SSE 路径可能带端点专属 query | JSON envelope 与协议必填字段按协议编码；预算字段名因协议而异。 |

## 2. 事故证据链

- **生产记录所述**：账户配置为 `profile_gpt_openai_v1`、`protocol=openai_responses`、`endpointMode=responses_sse`。`protocol_basic` 三次尝试均收到 HTTP 400，错误原文为：`max_tokens=16 is below the minimum the model provider accepts (100); raise it to at least 100`。具体账户、run/trace ID 和原始日志属于私有生产记录。
- **源码可核对**：`suite.go` 为首个 `protocol_basic` 传入预算 16；Responses builder 将它编码为 `max_output_tokens=16`。同一 builder 的其他协议使用不同字段和下限。
- **尚未证实的解释**：错误文本使用 `max_tokens`，而出站 Responses 请求使用 `max_output_tokens`。这说明请求链中存在字段转换或错误规范化的可能，但不能据此断言是上游中转将 Responses 转成 Chat。内部转换路径需独立日志或可复现证据确认。
- **当前能成立的结论**：首个探针请求的输出预算小于该上游实际要求的 100，且 suite 在终止失败后跳过后续核心探针。Mock 应复现“Responses 预算不足返回同类 400、预算提高后请求可继续”的边界；真实供应商内部实现不作为该测试的前提。

## 3. 契约

1. **共享构造规则**：F2–F5 对相同的已解析目标、协议/适配器、`endpointMode` 与 body 编码使用同一请求构造实现。调用方不能另行拼接路径、标准头、认证头或协议 envelope 字段。
2. **探针内容独立**：提示词、schema、tools、图片/音频内容和采样意图由探针族提供；共享构造负责按端点契约编码它们。不同探针的 body 和预算可以不同。
3. **能力判断诚实**：共享构造只避免调用路径之间的请求形状分叉，不保证上游一定支持结构化输出、工具、特定模态或模型能力。未覆盖或上游拒绝时保留真实错误，不静默改写成成功。
4. **用户透传不变**：F1 客户端 body（包括其预算字段）继续原样透传。本设计不授权对 F1 做 body、header 或路由行为改动。
5. **范围声明准确**：实现完成后只能声称“系统生成的探针请求共用构造源”。只有另有设计并完成 `/v1` 迁移，才能声称全仓所有上游请求都只有一个构造源。

## 4. 设计

### 4.1 共享请求构造包

新增 `backend-go/shared/platform/upstreamenvelope`，由一个统一入口生成最终的 `http.Request`。调用方提供已解析的账户/供应商目标、协议 profile、`endpointMode`、认证策略及凭据引用、探针语义 body 和预算类别；不得从各自 probe 包传入已拼好的 URL、认证头或完整 envelope 来绕过共享入口。

共享包负责：

- 根据已解析 profile 与 endpoint catalog 生成 method、URL path/query、标准请求头和适用的认证头；覆盖 SSE、Code Assist、Codex、GLM/gemini-openai 等已登记变体。上游 URL 拼接收敛为导出函数 `JoinUpstreamURL`（`TrimRight(base_url,"/")` + 操作路径，无版本段补插、剥离或去重；Base URL 为版本根语义），envelope 与网关三族、上游模型目录共用同一实现。
- 根据 endpoint 定义验证 JSON、multipart 或音频 body 类型，序列化协议必填字段和预算字段。
- 根据 `endpointMode + probe family + adapter` 应用命名预算策略；不支持该字段的端点或适配器明确声明 `none`，不得用伪造字段兜底。
- 返回可供既有 transport/dispatcher 发送的请求对象；不持有重试、评分、结算、超时、账户选择或网络发送职责。

账户选择、凭据解密、目标供应商/profile 解析和协议转换仍由现有调用链负责。适配器只提供声明式端点、认证及能力描述；不能继续私有构造最终请求。探针族继续提供业务内容，但不得直接写 envelope 字段或序列化完整 HTTP 请求。

认证策略新增显式 `none`（2026-10-12 W2 F3 接线裁决）：供已解析为"本请求不携带凭据"的调用方显式选择（现行取证：modelcheckprobe C 形态 `Options.Headers` 直通，凭据头缺失时请求照发且不写认证头）；`Apply` 对其不写任何头。它不是缺省/兜底——零值策略仍属未选择并显式失败，其余策略空 token 仍无条件 fail-closed。

### 4.2 Endpoint catalog 与测试矩阵

实现前必须从当前 `accountprobe`、`exactkeyprobe`、`modelcheckprobe` 调用点形成完整 catalog。每个已支持条目至少列出 `protocol/profile`、`endpointMode`、HTTP method、path/query、body 编码、SSE/JSON 语义、认证策略、适用预算字段和明确例外。catalog 覆盖 §1 中列出的文本、Interactions、图片生成、音频、Codex、Code Assist 及供应商路径变体。

测试按 catalog 中真实支持的组合逐条覆盖，而非构造“四协议 × JSON/SSE”的虚假笛卡尔积。每个条目断言 method、最终 URL/query、认证和标准头、body 编码、协议必填字段及预算处理；对不支持组合断言明确失败。Multipart、音频响应和不支持预算的适配器各有独立契约测试。

### 4.3 输出预算策略

- **R1 用户请求**：F1 透传预算不进入本包，本设计不更改。
- **R2 系统探针**：使用共享、命名的 `BudgetPolicy`，以 `endpointMode + probe family + adapter` 决定预算字段和值。统一的是字段生成与合法性校验逻辑，不是所有探针请求必须具有相同输出上限。
- **本次故障修正目标**：Responses `protocol_basic` 使用有界预算 1024，避免当前值 16 低于已观测到的 100 下限。F2/F4 当前 1024 语义保持；其它探针族继续按其检测语义声明预算，尤其短采样/Token 统计不能被全局改成 1024。若某端点或适配器不支持预算字段，显式省略。
- **Codex 例外**：Codex 归一化会移除其不接受的 tuning 字段。策略必须表达“无预算字段”，不能要求 Codex 与普通 Responses 请求字面相同。
- **不得静默适配未知最低值**：当前 100 是该事故上游观测，不代表全供应商下限。若上游仍拒绝，保留原始状态与错误，不做无证据的重试改写或预算 fallback。

### 4.4 历史探针预算语义

各探针的输出预算是探针行为的一部分。迁移前需从 `docs/functions/模型检测设计.md` 和当前 builder 核实所有 family 的预算，包括 quick/full、身份、quiz、Token 完整性与 §17 采样统计。集中命名不等于把所有值统一为 1024。

若改变既有探针的预算并影响输出、成本、评分或证据可比性，必须同步更新对应检测契约、探针集版本和历史数据比较规则；不可只改 §1.2 的通用描述。短预算探针应保留其短预算意图，除非单独完成语义重设计和校准。

### 4.5 文档同步门禁

实现前先对照并修正各自领域的权威文档，不由本设计单方面宣布“冲突以本文为准”：

- `docs/functions/模型检测设计.md`：记录按探针族和端点划分的预算策略、quick/full 请求数量、probe set 版本，以及历史证据可比性。
- `docs/functions/Anthropic账号接入.md` 与 `docs/functions/ClaudeCode客户端画像兼容设计.md`：现有账户测试示例仍有 `max_tokens=32000`、`thinking` 或 `effort` 描述；需根据 BUG-0201 与当前 `accountprobe` 的 1024、无 reasoning enhancement 契约裁决并同步。不能仅把 32000 重新解释为“直连形态”。用户真实 Anthropic 请求的 raw passthrough 是另一条契约，需保留。
- `docs/architecture/功能开发指导.md`：新增检查项，要求系统探针使用共享构造入口并更新 endpoint catalog/契约测试。
- 其他 endpoint 专题文档：若矩阵调整其 path、header、body 或模态语义，一并同步。

## 5. 本次范围与非目标

本设计范围是 F2–F5 的系统生成探针构造。F1 `/v1` 客户端请求当前为独立透传链，本次不迁移；“不迁移”不等于永久排除，也不等于全仓已经实现单一构造源。若验收必须字面覆盖所有上游 HTTP 请求，需先补充 `/v1` 的性能边界、请求透传契约和迁移方案，再决定是否纳入代码阶段。

本设计不改模型检测评分、重试、超时、结算、调度、账户健康状态或用户 payload；不改变探针族检测内容，除 §4.3 明确的 Responses `protocol_basic` 预算修正及通过文档裁决的必要调整外，不顺带扩大行为变更。

## 7. 测试、成本与验收

1. **共享构造契约**：对 endpoint catalog 每个实际条目断言 method、URL/query、认证/标准头、body 编码、协议字段和预算策略；覆盖 Codex 无预算、multipart、SSE 与供应商路径变体。
2. **事故回归 Mock**：本地 Mock Responses 上游对输出预算低于 100 的请求返回与事故同类 400，对 1024 请求返回稳定成功。测试确认首个 `protocol_basic` 使用 `max_output_tokens=1024`，并确认请求失败仍保留真实错误；不依赖生产服务或其内部转换实现。
3. **请求数口径**：现有测试中 Responses JSON quick 基线为 11 个逻辑请求；SSE quick 因额外流式终态探针为 12 个。它们不是物理请求总数：HTTP/读取失败可触发最多三次尝试，可信对照会对另一账户执行套件，题库也会增加请求。测试按所选 profile、endpointMode、对照与题库分别断言逻辑请求数，并另测重试上限。
4. **成本口径**：不能用 `11 × 1024` 声称所有 quick run 的固定费用上限。文本预算成本按每个探针 family 的逻辑请求数、预算策略和最大尝试次数估算；图片/音频及无预算适配器单独核算。真实账单还受上游计费和实际输出影响。
5. **生产验证**：本设计不授权或要求本次访问生产。实现和 Mock 验收通过后，只有在另有明确生产操作授权与对应 runbook 时才执行限定 smoke；判据为原预算拒绝不再出现、手动账户测试行为保持、后续能力探针按真实结果评分，不要求两种测试评分相同或强行得到非零分数。
6. **回归范围**：相关 `modelcheckprobe`、`gatewaydispatch` 透传不变性、shared `accounttest` 三包及 jobs `accounthealth`。按项目测试指引运行最小充分集合并记录真实结果；不以文档审查替代实现测试。

## 8. 后续规则

1. 新增系统探针 endpoint 前先登记 endpoint catalog、请求编码、预算策略、认证变体与 Mock 契约；不得在调用方另建最终 HTTP 请求构造器。
2. Node 迁移历史不再作为当前实现 oracle。当前探针请求以本设计经领域文档裁决后的契约和实际 Go 实现为准；发生冲突时先核实证据并更新权威文档，不由单篇设计文档自动覆盖其它契约。
3. 本设计完成实施后，应与 `模型检测设计.md` 及相关账户测试/端点文档同步维护；若未来覆盖 F1，另行更新本节范围与 `/v1` 契约。

## 9. 最终请求矩阵与 F2–F5 接线契约（2026-10-11 裁决）

2026-10-11 取证时，M1–M5 只复用了辅助规则（URL/认证/Accept/预算常量），`upstreamenvelope.Build` 仍无生产调用方，最终请求构造留在各调用方。2026-10-12 F2/F3/F4 已接入 `Build`，旧最终构造退出。本节按账户形态给出唯一目标矩阵，承载接线后的当前契约；矩阵同时吸收八项差异复核（[复核报告](../reports/信封差异与慢查询处置复核报告-2026-10-11.md) §3）的处置。

### 9.1 账户形态维度（矩阵只按形态分列，不按调用面分列）

| 维度 | A. OAuth Codex（`type=oauth` + `profile_gpt_openai_v1`） | B. `codex_responses` 兼容画像（API Key + ClientCompatibility） | C. 普通 API Key（含 GLM/gemini-openai 等 profile） |
| --- | --- | --- | --- |
| URL | `AdapterOpenAIOAuthCodex` 固定上游 + `/responses` | 账户 base（版本根）+ 不含版本前缀的操作路径直拼（GLM 按 9.2 消费 profile，无版本段补插/剥离） | catalog 条目路径规约 |
| 预算 | BudgetNone（归一化删除 tuning 字段） | 保留档案预算字段（**不**自动继承 A 的无预算例外） | 按探针族 BudgetPolicy |
| body 注入 | 删 `codexDeletedFields`；`store=false`、`stream=true`；`gpt-5.6-*` 加 `reasoning.context=all_turns` + `parallel_tool_calls=false` | `store=false`、`include=[reasoning.encrypted_content]`、`reasoning.context=all_turns`、`parallel_tool_calls=false`、`prompt_cache_key=<session>`、`client_metadata`（9.3 身份单源） | 探针族语义 body，无注入 |
| 强制 SSE | 是：`accept: text/event-stream` + `openai-beta: responses=experimental` 由 `Build` 按 Spec 形态统一写入（`openai-beta` 缺省补齐、客户端显式值保留，[OpenAI账号接入](../functions/OpenAI账号接入.md) 透传策略同源） | 按账户 endpointMode，由 `Build` 的 Accept 规则承担，不强制 | 按账户 endpointMode，由 `Build` 的 Accept 规则承担 |
| 身份头 | originator/UA/session-id/thread-id/x-client-request-id/x-codex-beta-features/x-codex-window-id/x-codex-turn-metadata，单源 9.3 | 同 A 的头集合；`X-OpenAI-Internal-Codex-Responses-Lite` 按 9.5 模型条件 | `upstreamidentity.ApplySystemClientHeaders` 既有系统身份 |

### 9.2 八项差异最终处置

1. **Codex 形状**：按 9.1 三形态分列。A 形态 = 共享 `wrapCodexResponses`（与 F3 现规则同源）；B 形态 = `client_metadata`/`prompt_cache_key`/`include` 保留（与身份头共用一次生成的身份，9.3）；普通 API Key 不继承 A 的固定上游/强制 SSE/无预算。
2. **Gemini Interactions `api-revision`**：值固定 `2026-05-20`，作为 `interactions_json/sse` catalog 条目的端点头，由 `Build` 统一写入；F2 现状缺失属缺陷，接线后消除。该值是本地既有契约，官方最新版本另行核实前不变。
3. **JSON 字段顺序**：结构语义为验收对象，最终编码只由共享包负责；调用方不得携带专属顺序逻辑。F2 的普通协议 body builder 一并迁入 `Build` 后，`orderedJSON` 已无生产调用点，随旧构造删除；不得重新引入调用面专属编码器。
4. **multipart**：统一共享包标准库 writer 编码；验收断言字段、文件 bytes/MIME 与 `Content-Type` boundary-body 匹配，不比较随机 boundary 字面值。
5. **GLM 路径**：F2 恢复消费 GLM profile（移除屏蔽），与 F4/共享规则同规：GLM 官方版本根直接作为 base（`https://open.bigmodel.cn/api/paas/v4` 等），操作路径不含版本前缀，`TrimRight(base,"/")` 直拼；运行时不再有“base 含版本根时剥请求路径 `/v1`”的豁免分支，官方根、代理 `/v1` 根等版本根形态入 golden（旧“空根”形态属存量历史值，由 maintenance 迁移命令回填版本根，不在运行时 golden 范围）。
6. **Anthropic `/V1`**：迁移已把 `/V1` base 的结果从 `/V1/v1/messages` 变为 `/V1/messages`——作为已裁决行为变化记录（对齐 Anthropic 原生路径），不再列为双实现差异；回归矩阵覆盖该输入。
7. **Gemini 双斜杠**：普通 API Key 面已收敛为折叠 `/prefix//nested→/prefix/nested`；Code Assist 旧 join 按"独立验证后接线"要求完成实证（2026-10-12：生产 Code Assist base 由 `directBaseURL` 冻结为 `https://cloudcode-pa.googleapis.com`，`//` 输入生产不可达；普通 gemini 面折叠口径 M3 起已上线）后**收敛为折叠口径**，`joinBaseURL` 删除，`//` golden 记录折叠语义——系统内单一 URL 口径。
8. **理论分支顺序**：原历史差异没有完整重建，不能声称历史两种顺序等价或不可达。当前 F2/F3/F4 最终 URL 均交给 `Build`，旧私有路径构造退出；catalog、URL normalization/profile golden 验证当前唯一实现。以消除并行构造路径关闭当前差异，历史可达性仍不作未经证明的判断。

### 9.3 身份单源契约

每次 Codex 形态请求生成**一份**身份值（session/thread/turn/window/installation），由它同时产生 body `client_metadata`（含内嵌 turn metadata JSON）与全部身份请求头。禁止两个构造阶段各随机生成（F2 现状 `probe.go` headers 段与 `applyCodexCompatibilityPayload` 是两套独立 UUID——接线时消除）。`turn_started_at_unix_ms` 按 F4 现值纳入 metadata。身份由调用方生成后经 `Spec` 传入 `Build`（信封不持有时钟/随机源之外的身份状态）。

### 9.4 保留调用方职责与验收门禁

2026-10-12 集成补充：F3 的 `Suite.ProviderProtocolProfileID` 必须经 `Options.ProtocolProfileID` 传入 `Spec.ProtocolProfileID`，不能用空 profile 重建 URL；GLM 官方版本根、代理 `/v1` 根与 Gemini OpenAI 兼容根均需在实际 transport 捕获断言。凭据类型也须从 owner 的 `Target.CredentialType` 贯穿目标及可信对照 Suite/Options；`google_oauth` 选择 `AuthOAuth`，不能仅因头为 Bearer 就丢失 OAuth 类型。适用矩阵为 F2/F4 的 A/B/C 与 F3 的 A/C，B×F3 不适用。A 形态的 `Accept: text/event-stream` 在附加头应用后仍强制生效；`openai-beta` 仍保留显式值。F3 OAuth Codex 最终请求恒为 SSE，因此成功判定须消费 SSE 事件并有 `response.completed` 成功终态；纯 JSON、无事件或仅 delta 不得作为成功评分，流内原始错误优先保留。F3 复用已提供的会话、线程、窗口、installation 身份值，只为缺失值生成身份，turn metadata 从最终身份一次生成，不能在随机身份生成后逐头覆盖造成割裂。

调用方保留：探针内容（提示词/题目/采样语义）、账户与凭据选择、transport、超时、重试、评分、结算。`Build` 独占：method、URL/query、标准与认证头、预算字段、协议 body 编码、适配器包装。探针评分跟随请求编码形态：A 形态恒 SSE 后其响应统一按 SSE 解析（F3 同构；`responses_json`/`responses_sse` 为账户配置模式名，不改变业务检测的 mode 语义），解析选择按请求形态确定，禁止"先试 JSON 失败再试 SSE"的 fallback（2026-10-12 W3 裁决）。

验收（Mock transport 捕获实际发出请求）：同目标/模式/适配器/画像/身份输入下对 F2/F3/F4 比较结构化 body、URL/query 与头（探针内容字段除外，比较范围显式声明）；A/C 覆盖 F2/F3/F4，B 只覆盖 F2/F4，F3-B 为 N/A。另覆盖 Interactions JSON/SSE、GLM 三种 base、multipart、预算例外与错误路径。完成门禁：生产调用图实际到达 `Build`，旧最终构造/适配器包装实现删除，共享包单测全绿不替代此门禁。F1 不在范围内。

外部 HTTP 依赖必须可替换：F2/F3 使用既有 `Options.Client`，F4 使用 `ProbeOptions.Client` 注入 `http.Client`。未注入时仍使用共享连接池；注入时保留输入、代理凭据、URL 校验和请求超时，允许 Mock transport 捕获包括固定 Codex 上游在内的实际请求，不需要真实上游凭据。

F4 Responses SSE 的成功判定须检查整段已读事件：`error`、`response.failed`、`response.incomplete`、嵌套 `response.error` 或明确失败终态优先于 `response.completed`；完成事件前后出现失败都不得判成功，并保留上游 `error.message` 原文。只有合法完成且挑战匹配、没有显式失败证据时才允许完成后的尾部读取错误；未完成或读取超限不得借此成功。F3 同样先识别 JSON 失败信封并保留原始错误，完整失败不归类为流中断重试；JSON 成功体仍不满足 A 的 SSE 成功契约。非 Codex 的 `oauth` 与 `google_oauth` 均按 OAuth 鉴权策略选择协议 Accept。

Gemini 原生模型路径中的 Unicode 与保留字符只编码一次；URL 拼装必须保留模型段的转义边界，不将已经生成的 `%XX` 再编码成 `%25XX`。普通 ASCII 模型的目标路径保持相同。

跨面对照须保留语义输入的边界：C 的 `store` 由探针族提供，F3 基础探针显式 `false`，F2/F4 缺省；对照分别断言这些值，不把缺省改写为 `false`。A 的 `store:false`、`stream:true` 则是共享适配器不变量，必须跨面相同。提示词、图像/音频样本及具体预算数值由探针族选择，比较预算字段规则与适配器例外，并分别断言各面的已声明值。

### 9.5 固定差异值契约（2026-10-12 复审补定）

- **`X-OpenAI-Internal-Codex-Responses-Lite`**：仅当请求的**最终上游模型**（模型映射后）精确等于 `gpt-5.6-sol`、`gpt-5.6-terra` 或 `gpt-5.6-luna` 时设置，值为 `true`；其余模型一律不发送。该条件与 F4 现行实现（`exactkeyprobe` 的 `isCodexResponsesLiteModel`，模型小写化去空白后精确匹配）一致；**A 与 B 形态一致适用**（F4 现行对 OAuth Codex 与兼容画像同函数判断，接线后不丢失），F2 接线后同规。目录扩减模型时本清单随模型目录裁决更新，不做前缀/通配推断。
- **`openai-beta`**：A 形态缺省补 `responses=experimental`；请求已携带该头时保留客户端显式值，不覆盖（[OpenAI账号接入](../functions/OpenAI账号接入.md) 透传策略同源）。由 `Build` 在 A 形态头集合内统一执行。
- **Gemini Interactions `api-revision`**：值 `2026-05-20` 已落 `interactions_json`/`interactions_sse` catalog 条目端点头（`upstreamenvelope/endpoint.go`）；F2 缺失属现状缺陷，接线后由 `Build` 写入路径自然消除——F 计划中该项为**验证项**（golden 断言 catalog 头到达线上请求），不重复实现。
