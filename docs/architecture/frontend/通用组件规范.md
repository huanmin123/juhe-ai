# 前端通用组件规范

> 面向 AI 与维护者。
> 本文记录 `frontend/src/components/` 下可跨页面复用的组件边界。新增页面或改造页面前，应先确认这里是否已有组件可以承接，不要在单个页面重复手写同类下拉、状态标签或响应式列表逻辑。
> 前端架构入口见 [README.md](README.md)，通用样式原则见 [样式规范.md](样式规范.md)，列表响应式规则见 [响应式列表规范.md](响应式列表规范.md)。

## 1. 文件定位

- 本文件回答这些问题：
  - 哪些组件是前端全局通用组件
  - 新页面应该优先复用哪些组件
  - 组件的默认业务语义是什么
  - 什么场景允许继续使用 Ant Design Vue 原生组件
- 本文件只记录跨页面组件约定，不记录单个业务页面的临时实现细节。

## 2. 通用组件目录

- 通用组件统一放在 `frontend/src/components/`。
- 页面私有组件放在对应 `frontend/src/views/<module>/` 目录内。
- 当同一类控件在两个及以上页面重复出现，并且包含相同筛选、状态、权限或响应式规则时，应优先抽到 `frontend/src/components/`。
- 通用组件应保持轻量，不引入全局状态；页面负责加载数据并通过 props 传入。

## 3. 系统主体选择器

### 3.1 组件定位

- 组件：`frontend/src/components/SystemPrincipalSelect.vue`
- 用途：统一选择系统账户、系统团队，或同时选择二者。
- 适用场景：
  - 系统账户筛选
  - 授权对象选择
  - 团队成员添加
  - 后续任何“选择系统账户 / 选择团队 / 选择系统主体”的表单或筛选

涉及系统账户或系统团队选择时，优先使用 `SystemPrincipalSelect`，不要在页面里重新手写 `a-select` options、停用过滤、停用标记或账号展示名格式。

### 3.2 核心 props

| prop | 说明 |
| --- | --- |
| `accounts` | 系统账户列表，由页面调用 `api.systemAccounts.list()` 后传入 |
| `teams` | 系统团队列表，由页面调用 `api.systemTeams.list()` 后传入 |
| `scope` | 选择范围；`system_account`、`team`、`all`，默认 `system_account` |
| `activeOnly` | 是否只显示启用对象，默认 `true` |
| `includeAll` | 是否展示“全部系统账户”选项，常用于筛选 |
| `allLabel` / `allValue` | 自定义全部选项文案和值，默认 `全部系统账户` / `all` |
| `excludedIds` | 需要排除的对象 ID，例如团队成员添加时排除已有成员 |
| `mode` | 透传给 `a-select` 的模式，例如 `multiple` |

### 3.3 启停语义

- 功能性选择默认使用 `activeOnly=true`，只显示启用对象。
  - 示例：新增授权的被授权用户 / 团队。
  - 示例：系统团队添加成员。
- 筛选性选择可以使用 `activeOnly=false`，保留停用对象并在选项文案后显示 `（停用）`。
  - 示例：账户、分组、API Key、使用记录、用量统计里的系统账户筛选。
  - 示例：授权管理按团队来源或被授权用户筛选历史记录。
- 页面不应自行判断“停用对象是否可选”；如果确有例外，先评估是否应扩展 `SystemPrincipalSelect` 的 props。
- 前端过滤只改善体验，后端仍必须校验停用系统账户、停用团队、成员失效和授权失效。

### 3.4 使用示例

筛选系统账户，保留停用对象：

```vue
<SystemPrincipalSelect
  v-model:value="systemAccountFilter"
  :accounts="systemAccounts"
  :active-only="false"
  include-all
  class="toolbar-select responsive-list-inline-filter"
  @change="loadData"
/>
```

新增授权时选择启用团队：

```vue
<SystemPrincipalSelect
  v-model:value="createForm.granteeId"
  :teams="teams"
  scope="team"
  placeholder="选择一个团队"
/>
```

添加团队成员，排除已有成员：

```vue
<SystemPrincipalSelect
  v-model:value="memberForm.systemAccountIds"
  :accounts="systemAccounts"
  :excluded-ids="usedMemberIds"
  mode="multiple"
  placeholder="选择一个或多个系统账户"
/>
```

## 4. 响应式列表组件

- 管理列表优先组合使用：
  - `ResponsiveListToolbar.vue`
  - `ResponsiveDataList.vue`
- 详细规则见 [响应式列表规范.md](响应式列表规范.md)。
- 新列表不要复制断点监听、滚动锁、手机筛选抽屉、下拉刷新或加载更多逻辑。

## 5. 状态标签组件

- 状态展示优先使用 `StatusTag.vue` 或现有模块内状态标签组件。
- 状态颜色必须配合中文文本，不要只用颜色表达状态。
- 复杂状态如 AI 账户状态，可以继续使用模块内封装，例如账户页的 `AccountStatusTag.vue`。

## 6. 新增通用组件规则

- 先确认是否已有组件能通过 props 扩展解决问题。
- 新通用组件要保持输入清晰，不直接请求接口，不隐藏页面级权限逻辑。
- 新通用组件需要同步更新本文，并说明：
  - 组件路径
  - 适用场景
  - 默认语义
  - 关键 props
  - 不适用场景
- 修改通用组件后至少运行：

```powershell
pnpm --filter juhe-ai-frontend typecheck
```
