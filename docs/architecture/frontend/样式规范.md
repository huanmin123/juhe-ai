# 前端样式规范

> 面向 AI 与维护者。
> 适用于 `frontend/` 下所有 Vue 3 + TypeScript + Ant Design Vue 页面。
> 本文件只写项目通用的样式、布局和交互规范；具体业务细节、功能目标和验证用例应放到对应设计文档或运行手册中。
> 前端架构入口见 [README.md](README.md)。

## 1. 文件定位

- 本文件回答这些问题：
  - 前端页面默认应该如何组织
  - Ant Design Vue 如何在项目内保持一致
  - 高密度管理界面如何保证可读和可维护
  - 哪些视觉和交互倾向默认不要引入
  - 修改前端后应如何自检
  - 后台主题令牌（颜色、圆角、字体、阴影）如何定义与引用
- 本文件不记录具体业务流程，不枚举具体模块操作，不替代：
  - [../架构总览.md](../架构总览.md)
  - [../../functions/README.md](../../functions/README.md)
  - [开发运行说明](../../develop/运行说明.md)
  - [开发测试与验证说明](../../develop/测试与验证说明.md)

## 2. 产品取向

- 当前前端是工具型管理界面，不是官网、营销页或展示型作品集。
- 默认目标是：
  - 快速定位信息
  - 快速完成操作
  - 清楚表达状态
  - 降低长期使用负担
  - 保持轻量、稳定、易维护
- 默认不追求“第一眼惊艳”，而追求“一眼看懂、一步能点、状态明确、异常可恢复”。

## 3. 技术与目录事实

- 技术栈：`Vue 3`、`TypeScript`、`Vue Router`、`Ant Design Vue`、`axios`、`dayjs`、`Vite`。
- 入口：`frontend/src/main.ts`。
- 应用布局：`frontend/src/layouts/`。
- 页面视图：`frontend/src/views/`。
- API 请求：`frontend/src/api/`。
- 类型定义：`frontend/src/types/`。
- 全局样式：`frontend/src/styles/global.css`。
- 当前默认不引入复杂全局状态；确有跨页面共享状态需求时，再单独评估。

## 4. 核心原则

- 优先使用 Ant Design Vue 原生组件，不为单页自研基础组件。
- 优先复用全局样式类和现有布局模式，不在每个页面重复写一套视觉规则。
- 信息密度优先于装饰效果。
- 页面结构优先稳定，交互反馈优先明确。
- 视觉效果服务信息表达，不为“高级感”增加维护成本。
- 前端只展示和提交状态，不伪造后端事实。
- 如果样式规范与具体业务流程冲突，优先调整业务页落地方式，不把具体业务细节写回本规范。

## 5. 页面结构

### 5.1 默认结构

- 管理页面优先采用：
  - 页面容器
  - 标题与简短说明
  - 工具栏
  - 筛选区或操作区
  - 主内容区
  - 弹窗或抽屉承载局部任务
- 页面应按区域组织，不要整页堆成一串大卡片。
- 主操作应放在稳定位置，避免用户每次进入页面都重新寻找。

### 5.2 工具栏

- 工具栏默认包含主操作、刷新、筛选、批量操作等入口。
- 操作按钮数量过多时，应分组、收起或使用菜单，不要横向无限堆叠。
- 说明文案应短且靠近相关操作。

### 5.3 主内容区

- 列表型页面优先使用表格。
- 配置型页面优先使用表单分组。
- 详情型内容优先用弹窗、抽屉或展开行，不要让主列表承担过多长文本。

## 6. 样式语言

### 6.1 颜色

- 后台主题为「纸墨澄明」，与登录页同一视觉语言：暖纸底、墨色文字、青灰点缀。
- 主题颜色分两层实现：
  - `App.vue` 的 AntD ConfigProvider 令牌：`colorPrimary` / `colorInfo` `#53696b`、`colorSuccess` `#6f8f7a`、`colorWarning` `#a98548`、`colorError` `#9d5547`、`colorTextBase` `#22282b`、`colorBgLayout` `#f4f4f2`、`colorBgContainer` `#ffffff`、`borderRadius: 10`；Table 组件令牌 `headerBg: #faf9f7`、`rowHoverBg: #f6f8f7`。
  - `frontend/src/styles/global.css` 的 `:root` 下 `--juhe-*` CSS 变量，颜色令牌如下：

| 变量 | 值 | 用途 |
| --- | --- | --- |
| `--juhe-bg` | `#f4f4f2` | 页面底，暖纸 |
| `--juhe-surface` | `#ffffff` | 卡片面 |
| `--juhe-surface-soft` | `#faf9f7` | 表头/次级面 |
| `--juhe-rail` | `#fbfbfa` | 侧栏轨 |
| `--juhe-fg` | `#22282b` | 墨色主文字 |
| `--juhe-fg-soft` | `#3c4447` | 次级文字 |
| `--juhe-muted` | `#8b9190` | 弱化文字 |
| `--juhe-faint` | `#a9aeac` | 最弱文字/占位 |
| `--juhe-border` | `rgba(34,40,43,.10)` | 细边框 |
| `--juhe-border-strong` | `rgba(34,40,43,.24)` | 强调边框 |
| `--juhe-accent` | `#53696b` | 主操作/选中/链接 |
| `--juhe-accent-mid` | `#758789` | 次级强调 |
| `--juhe-accent-soft` | `#edf1f0` | 选中洗底 |
| `--juhe-coral` | `#a6755e` | 暖点缀/待检查态 |
| `--juhe-ok` | `#6f8f7a` | 成功 |
| `--juhe-warn` | `#a98548` | 警告 |
| `--juhe-danger` | `#9d5547` | 错误/危险 |

- 页面与组件必须引用上述令牌（`--juhe-*` 变量或 AntD 令牌），不得硬编码旧主题色（`#1677ff`、`#061a2e`、`#03111f`、`#f5f7fb`）。
- 状态色语义不变，色值随主题低饱和：成功 `--juhe-ok` `#6f8f7a`、警告 `--juhe-warn` `#a98548`、错误 `--juhe-danger` `#9d5547`、待检查（暖点缀）`--juhe-coral` `#a6755e`。
- 状态色只用于成功、警告、错误、禁用、进行中、选中等明确语义。
- 不要用颜色承担唯一语义；关键状态应同时有文字或图标说明。
- 不要默认引入大面积渐变、发光背景、炫彩描边。

### 6.2 卡片、边框、阴影

- 默认使用轻边框、浅背景、适中圆角和弱阴影。
- 具体值：卡片圆角 `--juhe-radius`（12px），输入框等小件 `--juhe-radius-sm`（10px）；细边框用 `--juhe-border`，强调边框用 `--juhe-border-strong`；卡片阴影用 `--juhe-shadow-card`（`0 10px 30px rgba(34,40,43,.05)`）；卡片头 min-height 44px。
- 卡片用于表达区域边界，不用于制造装饰层次。
- 不要多层卡片嵌套；能用标题、间距、分割线解决时，不继续套卡片。

### 6.3 排版

- 标题短，说明直接，标签统一。
- 数字、时间、标识符、路径、URL、密钥片段、错误码等信息应优先保证可读和可复制。
- 避免超大标题、口号式文案和装饰性插画。
- 同类页面的字号、间距和按钮层级应保持一致。
- 字体三栈定义在 `frontend/src/styles/global.css` 的 `:root`：
  - `--juhe-font-display`（"Segoe UI Variable Display","Helvetica Neue","Avenir Next","PingFang SC",sans-serif）：页面与区块标题。
  - `--juhe-font-body`（"Helvetica Neue","PingFang SC","Hiragino Sans GB","Microsoft YaHei",sans-serif）：正文。
  - `--juhe-font-mono`（"JetBrains Mono",ui-monospace,Menlo,Monaco,Consolas,monospace）：数字、ID、时间、代码。

### 6.4 应用壳主题

- 应用壳（顶栏、侧栏、页头）使用「纸墨澄明」主题，与登录页同一视觉语言，布局契约如下：
  - 顶栏桌面端固定 52px，是页面标题与定位的唯一承载（只含全局动作：帮助、公告、用户下拉，与当前页标题小字面包屑位），桌面端不显示副标题描述，内容区不再渲染独立页头（标题/描述/笔刷线页头已移除）；移动端（≤991px）顶栏为 height:auto、min-height 56px，保留菜单触发器与副标题显示（既有移动导航语义）。
  - 全高列表卡高度紧贴壳层：内容区顶部不留页头占位，垂直空间优先给列表内容。
  - 侧栏为暖纸轨 `--juhe-rail` 底 + 墨色文字；选中项使用 `--juhe-accent-soft` 洗底 + `--juhe-accent` 文字 + 左侧 3px 墨→青笔触标记；分组标题为小号雾灰。
  - 状态展示优先「色点 + 文字」，减少大面积色块标签；状态语义不变，仅色值随令牌低饱和化。
  - 卡片头 min-height 44px；全高列表卡（`.responsive-page-card`）过渡期采用公式 `calc(100dvh - 114px)`（桌面）/ `calc(100dvh - 88px)`（≤900px），偏移常量代表壳层占位（顶栏 + 内容区上下 padding），壳层高度任何变更必须同步调整该常量；改为随壳层实测高度派生另立任务处理。

## 7. 表格规范

- 表格必须考虑：
  - 加载态
  - 空态
  - 错误提示
  - 长文本处理
  - 横向滚动
  - 操作列可定位
- 列很多时优先保证可读，不要强行压缩到无法识别。
- 状态字段优先使用 `a-tag` 或等价状态组件。
- 账户类型标签（表格与移动卡片共用语义）按类型着色，使用主题内低饱和彩色洗底（`type-tag-*` 工具类，定义于 global.css）：OAuth 青绿、API Key 珊瑚、Google OAuth 琥珀；不用灰底，也不使用 AntD 亮色预设。
- 需要复制的字段应提供明确复制入口。
- 时间、数量、金额、比例等格式化逻辑应集中处理，不要散落在模板表达式里。

### 7.1 操作列

- 全系统列表操作列统一使用图标化操作，不再直接堆叠“编辑 / 删除 / 更多”等纯文字链接。
- 桌面表格中高频操作优先使用紧凑图标按钮：
  - 编辑：铅笔图标，主色语义，悬浮提示“编辑”。
  - 删除 / 移除：垃圾桶图标，危险色语义，必须保留二次确认。
  - 更多操作：使用 `...` 图标按钮，悬浮提示“更多操作”。
- 移动端卡片底部操作保留“图标 + 中文文字”，保证触达面积和语义清晰；三个及以上操作仍按响应式列表规范收敛。
- 更多菜单内每一项必须带左侧图标，并按动作语义使用轻量色彩：
  - 测试 / 检测：蓝色。
  - 启用 / 恢复：绿色。
  - 停用 / 禁用 / 重置：橙色。
  - 迁移 / 切换 / 调整绑定：蓝紫色。
  - 查看 / 日志 / 详情：灰蓝色。
  - 删除 / 移除：红色。
- 操作列语义映射保持不变；语义色色值随主题令牌低饱和化。
- 图标和颜色只作为辅助语义，菜单项仍必须保留中文文案。
- 列表操作应优先复用通用操作组件，不在页面里重复手写 `a-button`、`a-dropdown` 和菜单图标样式。

## 8. 表单与弹窗

- 一个弹窗只承载一个明确任务。
- 表单字段按语义分组，避免把无关字段堆在一起。
- 必填、默认值、禁用态、错误提示要清楚。
- 保存失败不能清空用户输入。
- 敏感字段应有明确展示策略，不在列表中无意暴露。
- 高风险操作必须二次确认。

## 9. 响应式

- 项目以桌面管理体验为主，但小屏不能完全不可用。
- 小屏优先保护：导航入口、主操作、表格可滚动、弹窗可关闭、表单可提交。
- 响应式样式优先在全局或通用布局层收口，不要每个页面各写一套互相冲突的规则。

## 10. 禁止倾向

- 为单个页面复制一套基础组件样式。
- 为局部视觉效果引入复杂库或重型抽象。
- 用大面积装饰掩盖信息结构问题。
- 不引入大面积渐变；唯一例外是主按钮与顶栏用户头像可使用登录页同源的墨色渐变 `--juhe-primary-grad`（`linear-gradient(135deg,#22282b,#53696b)`），组件内必须以变量引用，不得重复字面量。
- 用刷新、延迟、重复请求掩盖状态同步问题。
- 在前端伪造后端状态或业务判断。
- 在规范文档中固化具体业务细节，导致后续模块无法复用。

## 11. 验证要求

- 纯前端样式或页面改动至少运行：

```powershell
pnpm --filter juhe-ai-frontend typecheck
```

- 如果改动影响 API 类型、请求字段或后端响应，至少运行：

```powershell
pnpm typecheck
```

- 如果改动影响真实业务流程，应按 [开发测试与验证说明](../../develop/测试与验证说明.md) 补充对应验证。

## 12. AI 自检

- 是否复用了 Ant Design Vue 和现有全局样式？
- 是否避免了具体业务细节写入通用规范？
- 是否覆盖加载、空态、错误态和禁用态？
- 是否保护了敏感字段展示边界？
- 是否没有用前端状态替代后端事实？
- 是否运行或说明了必要验证？
- 新增或修改界面颜色时是否引用 `--juhe-*` 变量或 AntD 令牌，且未硬编码旧主题色（`#1677ff` / `#061a2e` / `#03111f` / `#f5f7fb` / `#edf1f7`）？
