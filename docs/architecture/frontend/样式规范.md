# 前端样式规范

> 面向 AI 与维护者。
> 适用于 `frontend/` 下所有 Vue 3 + TypeScript + Ant Design Vue 页面。
> 本文件只写项目通用的样式、布局和交互规范；具体业务细节、功能目标和验证用例应放到对应设计文档或运行手册中。
> 前端架构入口见 [README.md](README.md)。

## 1. 文件定位

- 本文件回答这些问题：
  - 前端页面默认应该如何组织
  - Ant Design Vue 如何在项目内保持一致
  - 高密度管理界面如何保证可读和可维护
  - 哪些视觉和交互倾向默认不要引入
  - 修改前端后应如何自检
  - 后台主题令牌（颜色、圆角、字体、阴影）如何定义与引用
- 本文件不记录具体业务流程，不枚举具体模块操作，不替代：
  - [../架构总览.md](../架构总览.md)
  - [../../functions/README.md](../../functions/README.md)
  - [开发运行说明](../../develop/运行说明.md)
  - [开发测试与验证说明](../../develop/测试与验证说明.md)

## 2. 产品取向

- 当前前端是工具型管理界面，不是官网、营销页或展示型作品集。
- 默认目标是：
  - 快速定位信息
  - 快速完成操作
  - 清楚表达状态
  - 降低长期使用负担
  - 保持轻量、稳定、易维护
- 默认不追求“第一眼惊艳”，而追求“一眼看懂、一步能点、状态明确、异常可恢复”。

## 3. 技术与目录事实

- 技术栈：`Vue 3`、`TypeScript`、`Vue Router`、`Ant Design Vue`、`axios`、`dayjs`、`Vite`。
- 入口：`frontend/src/main.ts`。
- 应用布局：`frontend/src/layouts/`。
- 页面视图：`frontend/src/views/`。
- API 请求：`frontend/src/api/`。
- 类型定义：`frontend/src/types/`。
- 全局样式：`frontend/src/styles/global.css`。
- 当前默认不引入复杂全局状态；确有跨页面共享状态需求时，再单独评估。

## 4. 核心原则

- 优先使用 Ant Design Vue 原生组件，不为单页自研基础组件。
- 优先复用全局样式类和现有布局模式，不在每个页面重复写一套视觉规则。
- 信息密度优先于装饰效果。
- 页面结构优先稳定，交互反馈优先明确。
- 视觉效果服务信息表达，不为“高级感”增加维护成本。
- 前端只展示和提交状态，不伪造后端事实。
- 如果样式规范与具体业务流程冲突，优先调整业务页落地方式，不把具体业务细节写回本规范。

## 5. 页面结构

### 5.1 默认结构

- 管理页面优先采用：
  - 页面容器
  - 标题与简短说明
  - 工具栏
  - 筛选区或操作区
  - 主内容区
  - 弹窗或抽屉承载局部任务
- 页面应按区域组织，不要整页堆成一串大卡片。
- 主操作应放在稳定位置，避免用户每次进入页面都重新寻找。

### 5.2 工具栏

- 工具栏默认包含主操作、刷新、筛选、批量操作等入口。
- 操作按钮数量过多时，应分组、收起或使用菜单，不要横向无限堆叠。
- 说明文案应短且靠近相关操作。

### 5.3 主内容区

- 列表型页面优先使用表格。
- 配置型页面优先使用表单分组。
- 详情型内容优先用弹窗、抽屉或展开行，不要让主列表承担过多长文本。

- 令牌约束的例外（终态清单，2026-10-02 全站清理收敛后确立，新增场景须先在此登记再使用）：

  - **第三方品牌 Logo**：`LoginView.vue` 内的供应商 SVG 填充色（Kimi `#027aff`、DeepSeek `#4D6BFE`、Qwen `#615CED`、豆包 `#1E37FC`/`#A569FF`/`#37E1BE`、GLM `#3859FF`、Gemini `#8E75B2`、OpenAI `#000000`）按品牌规范保留。
  - **图表与 canvas**：ECharts 配置（`aiPerformanceChartOptions.ts`、`usageTrendChartOptions.ts`、`tableMonitorDisplay.ts` 的系列色板与轴色）和 canvas 取色按其自身配色保留；canvas/JS 取色处色值须镜像主题令牌值（如 AiHealthStatusBar 状态色镜像 ok/danger/faint）。
  - **JS 消费的颜色字符串**：AntD 组件 color 类 props（如公告级别 `announcementFormatters.ts` 喂 `a-tag :color`）须为字面量，色值镜像主题令牌；`routeLoadRecovery.ts` 是应用加载失败的自包含兜底浮层（渲染时 global.css 可能未加载），保留字面量并镜像主题值。
  - **令牌定义处**：`App.vue` 的 AntD JS 令牌与 `LoginView.vue` 的局部 `--fg`/`--muted`/`--accent` 等别名定义本身是字面量定义源，合法。
  - **独立子系统**：`frontend/public/help/help.css`（帮助文档静态样式，由 help-content 回归脚本锁定）。
- `App.vue` ConfigProvider 的 JS 主题令牌（`colorPrimary`/`colorTextBase` 等）必须保持 hex 字面量，不得写成 `var(--juhe-*)` 字符串：AntD 在 JS 中以色彩算法从这些基色派生整个色板，`var()` 无法参与该运算，派生色会整体失效变黑（2026-10-02 实际事故）。同理，canvas `fillStyle`、ECharts 等 JS 图表配色消费的颜色字符串也不能用 CSS 变量；这两个 JS 令牌层与 `--juhe-*` CSS 变量层是同值两份的定义，需人工保持同步。
- 文字令牌对比度下限（2026-10-02 确立）：承载信息正文的令牌在白底/`--juhe-surface-soft` 上不低于 WCAG AA 4.5:1——`--juhe-fg` 14.9:1、`--juhe-fg-soft` 10.0:1、`--juhe-muted` 4.8:1；`--juhe-faint`（2.3:1）仅限占位符、装饰性文字等非信息载体。`--juhe-muted` 由 `#8b9190`（3.2:1，不达标）调深至 `#6d7372`，与被替换的旧次级文字 `#64748b`（4.76:1）可读性持平；登录页 `--muted` 局部别名同步。
- 状态色语义不变，色值随主题低饱和：成功 `--juhe-ok` `#6f8f7a`、警告 `--juhe-warn` `#a98548`、错误 `--juhe-danger` `#9d5547`、待检查（暖点缀）`--juhe-coral` `#a6755e`、迁移/切换紫 `--juhe-violet` `#7a6d8f`；配套洗底/浅边令牌 `--juhe-*-soft`/`--juhe-*-line`（ok/warn/danger/violet 四族）用于提示卡、状态胶囊与浅色描边，不得再用 `#fff1f0`/`#f0fdf4`/`#ecfeff` 等预设浅底。
- 状态色只用于成功、警告、错误、禁用、进行中、选中等明确语义。
- 不要用颜色承担唯一语义；关键状态应同时有文字或图标说明。
- 不要默认引入大面积渐变、发光背景、炫彩描边。

### 6.2 卡片、边框、阴影

- 默认使用轻边框、浅背景、适中圆角和弱阴影。
- 具体值：卡片圆角 `--juhe-radius`（12px），输入框等小件 `--juhe-radius-sm`（10px）；细边框用 `--juhe-border`，强调边框用 `--juhe-border-strong`；卡片阴影用 `--juhe-shadow-card`（`0 10px 30px rgba(34,40,43,.05)`）；卡片头 min-height 44px。
- 卡片用于表达区域边界，不用于制造装饰层次。
- 不要多层卡片嵌套；能用标题、间距、分割线解决时，不继续套卡片。

### 6.3 排版

- 标题短，说明直接，标签统一。
- 数字、时间、标识符、路径、URL、密钥片段、错误码等信息应优先保证可读和可复制。
- 避免超大标题、口号式文案和装饰性插画。
- 同类页面的字号、间距和按钮层级应保持一致。
- 字体三栈定义在 `frontend/src/styles/global.css` 的 `:root`：
  - `--juhe-font-display`（"Segoe UI Variable Display","Helvetica Neue","Avenir Next","PingFang SC",sans-serif）：页面与区块标题。
  - `--juhe-font-body`（"Helvetica Neue","PingFang SC","Hiragino Sans GB","Microsoft YaHei",sans-serif）：正文。
  - `--juhe-font-mono`（"JetBrains Mono",ui-monospace,Menlo,Monaco,Consolas,monospace）：数字、ID、时间、代码。

### 6.4 应用壳主题

- 应用壳（顶栏、侧栏、页头）使用「纸墨澄明」主题，与登录页同一视觉语言，布局契约如下：
  - 顶栏桌面端固定 52px，是页面标题与定位的唯一承载（只含全局动作：帮助、公告、用户下拉，与当前页标题小字面包屑位），桌面端不显示副标题描述，内容区不再渲染独立页头（标题/描述/笔刷线页头已移除）；移动端（≤991px）顶栏为 height:auto、min-height 56px，保留菜单触发器；副标题（页面描述）全端隐藏——窄屏下截断省略无信息量，单行标题保持顶栏紧凑（页面上下文由标题与抽屉导航承载）。
  - 全高列表卡高度紧贴壳层：内容区顶部不留页头占位，垂直空间优先给列表内容。
  - 侧栏为暖纸轨 `--juhe-rail` 底 + 墨色文字；选中项使用 `--juhe-accent-soft` 洗底 + `--juhe-accent` 文字 + 左侧 3px 墨→青笔触标记；分组标题为小号雾灰。
  - 状态展示优先「色点 + 文字」，减少大面积色块标签；状态语义不变，仅色值随令牌低饱和化。
  - 卡片头 min-height 44px；全高列表卡（`.responsive-page-card`）过渡期采用公式 `calc(100dvh - 114px)`（桌面）/ `calc(100dvh - 88px)`（≤900px），偏移常量代表壳层占位（顶栏 + 内容区上下 padding），壳层高度任何变更必须同步调整该常量；改为随壳层实测高度派生另立任务处理。

## 7. 表格规范

- 表格必须考虑：
  - 加载态
  - 空态
  - 错误提示
  - 长文本处理
  - 横向滚动
  - 操作列可定位
- 列很多时优先保证可读，不要强行压缩到无法识别。
- 状态字段优先使用 `a-tag` 或等价状态组件。
- 账户类型标签（表格与移动卡片共用语义）按类型着色，使用主题内低饱和彩色洗底（`type-tag-*` 工具类，定义于 global.css）：OAuth 青绿、API Key 珊瑚、Google OAuth 琥珀；不用灰底，也不使用 AntD 亮色预设。
- 行选中底色与行悬浮底色保持一致（`#f6f8f7`，global.css 对 `.page-card` 内 `.ant-table-row-selected` 强制覆盖）；不使用 AntD 由 `colorPrimary` 派生的默认选中底（主色青灰的浅调，视觉过重）。
- 需要复制的字段应提供明确复制入口。
- 时间、数量、金额、比例等格式化逻辑应集中处理，不要散落在模板表达式里。

### 7.1 操作列

- 全系统列表操作列统一使用图标化操作，不再直接堆叠“编辑 / 删除 / 更多”等纯文字链接。
- 桌面表格中高频操作优先使用紧凑图标按钮：
  - 编辑：铅笔图标，主色语义，悬浮提示“编辑”。
  - 删除 / 移除：垃圾桶图标，危险色语义，必须保留二次确认。
  - 更多操作：使用 `...` 图标按钮，悬浮提示“更多操作”。
- 移动端卡片底部操作保留“图标 + 中文文字”，保证触达面积和语义清晰；三个及以上操作仍按响应式列表规范收敛。
- 更多菜单内每一项必须带左侧图标，并按动作语义使用语义令牌：
  - 测试 / 检测：`--juhe-accent`（青灰）。
  - 启用 / 恢复：`--juhe-ok`（低饱和绿）。
  - 停用 / 禁用 / 重置：`--juhe-warn`（低饱和琥珀）。
  - 迁移 / 切换 / 调整绑定：`--juhe-violet`（低饱和紫）。
  - 查看 / 日志 / 详情：`--juhe-accent-mid`（灰青蓝）。
  - 删除 / 移除：`--juhe-danger`（低饱和红）。
- 菜单 hover 态用对应族的洗底令牌（`--juhe-*-soft`），实现见 `RowActions.vue`（row-action-tone-* / row-action-menu-tone-* 全套令牌化）。
- 操作列语义映射保持不变；语义色色值随主题令牌低饱和化。
- 图标和颜色只作为辅助语义，菜单项仍必须保留中文文案。
- 列表操作应优先复用通用操作组件，不在页面里重复手写 `a-button`、`a-dropdown` 和菜单图标样式。

## 8. 表单与弹窗

- 一个弹窗只承载一个明确任务。
- 表单字段按语义分组，避免把无关字段堆在一起。
- 必填、默认值、禁用态、错误提示要清楚。
- 保存失败不能清空用户输入。
- 敏感字段应有明确展示策略，不在列表中无意暴露。
- 高风险操作必须二次确认。

### 8.1 账户表单弹框双形态

「添加 / 编辑 AI 账户」弹框（`AccountEditModal.vue`）按模式呈现两种布局形态，表单状态、校验、payload 与事件语义两种形态完全一致：

- **新建（`editing === false`）→ 三步向导**，弹框宽 720px：
  - 步骤 1「类型与凭证」：供应商/类型选择 + 凭证区（API Key / OAuth，含模型与检查字段）；
  - 步骤 2「归属与调度」：基础信息区（名称、分组、并发、优先级、特权、状态、标签、说明）；
  - 步骤 3「高级配置」：高级折叠区原样内嵌（懒加载契约不变）；
  - 底部按钮在既有「测试 / 取消 / 确定」基础上增加「上一步 / 下一步」纯导航；「确定」只在第 3 步出现（步骤 1/2 隐藏，避免绕过向导直接提交），步骤切换只切换分区可见性（`v-show`，不销毁组件状态），不在步骤切换时触发校验——校验仍由「确定」统一执行；「确定」校验失败时（`validationFailure` 上报）自动把当前步骤切回出错字段所在步骤（归属映射 `accountValidationErrorStep`，与校验消息同文件维护），编辑形态全分区同屏不回跳；
- **编辑（`editing === true`，含授权只读态）→ 单列渐进披露**，弹框宽 860px，单条滚动轴（`form-scroll`），无分区导航：
  - 标题栏（modal `#title` slot，两形态共用，`:title` prop 不再直接绑定——antd-vue `vc-dialog` 中显式 title prop 会覆盖 `#title` slot）：向导态与编辑态 basic 详情加载中显示纯标题文字（`title` prop 同款文案）；编辑态就绪后为静态文字「编辑账户」+ 账户名行内编辑（borderless 输入框，hover/focus 显边框，maxlength 128，授权只读态禁用）+ 类型徽章（小圆角胶囊，`--juhe-primary-grad` 白字，文本 = 供应商名 + 账户类型全称）+ 三态状态 `a-segmented`（可调度 / 待检查 / 停用，切换即置 `statusSelectionExplicit`，授权只读态禁用）；关闭按钮由 modal 自带；编辑态不再渲染 `AccountFormSelector`（类型信息由标题栏徽章承载，向导第一步保留）；
  - **常用配置区**（小节标签 + 提示「90% 的编辑只动这里」）：凭证块（API Key / OAuth / 授权只读三选一逻辑不变）+ 分组块（`AccountBasicInfoSection` 的 `variant="bench"` 输出，仅「加入分组」）；
  - **高级配置区**（小节标签 + 提示「折叠头部直接显示当前值摘要」）：6 张自研折叠摘要卡（受控 open 状态数组，非 `a-collapse`）：调度参数（优先级/并发/特权 + 标签/说明）、策略与代理（请求覆盖 + 策略）、稳定性与锁死（持续恢复探活 + 锁死参数）、余额与到期（到期 + 余额查询）、时间计划、错误与响应规则。卡片头 = 图标 + 卡名 + 当前值摘要文本 + 计数徽标（「默认值」/「已配置 N 项」，N 为卡内非默认项数），不展开也能掌握配置状态；
  - **行为变化**：编辑态打开弹窗即自动加载高级详情（原为展开高级折叠才加载），保存将默认走高级差量路径（`configRevision` 前置校验）；未加载成功时每张卡卡片体保留「加载高级配置」兜底按钮（`advanced-open` 事件）与基础保存 fallback，加载中显示 spin；任一卡首次展开也会再次触发加载（双保险）。授权只读态打开即展开全部摘要卡。
- 两形态共用的结构红线（回归脚本锁定的源码契约，重排布局时必须保留）：多 Key 行渲染 `v-for`、持续恢复探活单行布局（`probe-toggle-row` / `probe-toggle-label` / 帮助图标与「前 10 分钟」文案，编辑态在「稳定性与锁死」摘要卡、向导态在高级折叠内各存一份）、账号模型别名选项构建 `for (const item of props.form.supportedModels)`（`mappingUpstreamModelOptions` 留在 `AccountEditModal.vue`）、错误策略绑定（`:inherited-error-policy-rules` 与 `v-model:error-handling-rule-overrides`）、授权只读凭证块（`credentialItem('supported_endpoint_modes', '上游接口能力'` 及模型映射只读投影）、余额查询开关在标题行右侧（`balance-query-header`）；三态状态单选 `dispatch-status-field` 仍在 `AccountBasicInfoSection` 向导（`variant="full"`）分支，编辑态状态改由标题栏 segmented 承载。
- 子组件（`AccountBasicInfoSection` / `AccountApiKeySection` / `AccountOAuthSection` / 高级区各 section）的字段、事件与内部结构不在双形态外壳的改动范围内；其内部布局整理另行分期。
- 账户类型选择器（`AccountFormSelector` 的 `a-segmented`）实行两级文案：选项只展示接入方式短码（`AccountTypeChoice.tag`），不逐项重复供应商名——供应商名由选择器下方的供应商徽标承载；「供应商 + 接入方式」全称保留在弹框标题（`typeTitle = label`）。短码取值：DeepSeek [OpenAI 兼容 | Claude Code]、智谱 GLM [通用 | Anthropic | Coding]、Google Gemini [Gemini API | OpenAI Chat | Google OAuth]、xAI [OpenAI v1 | Grok OAuth]，其余供应商回退 `accountTypeText`（API Key / OAuth / Google OAuth，与表格类型标签同词汇）。

## 9. 响应式

- 项目以桌面管理体验为主，但小屏不能完全不可用。
- 小屏优先保护：导航入口、主操作、表格可滚动、弹窗可关闭、表单可提交。
- 断点体系（取值契约，新规则不得再引入体系外断点值）：
  - `900px`：列表/工具栏统一形态断点（`ResponsiveDataList` / `ResponsiveListToolbar` 默认值、global.css `.page-toolbar` 与 991px 级全局小屏规则均以此为界）；ip-stats 等历史偏离值已回归 900。
  - `991px`：应用壳层断点（侧栏抽屉化、顶栏移动形态、content padding）。901–991px 区间允许「侧栏抽屉 + PC 表格」组合（抽屉化为表格腾出宽度，属合理形态而非中间态）。
  - `640px`：弹框内部布局断点（表单控件折叠为单列、双形态弹框窄屏形态）。
  - 已登记例外：审计日志详情抽屉内表 `mobile-breakpoint=1024`（抽屉内容宽度受限，平板即需卡片）；其余页面一律 900。
- 工具栏与列表必须同断点切换（响应式列表规范 §2 的中间态禁令）；页面自建工具栏（stats 系/usage-stats/ai-performance 等）同样遵守 900 断点。
- 图表页（stats / usage-stats / system-metrics-stats / ai-performance）移动端筛选模式：高频控件常驻首屏（stats=快捷时间段、usage-stats=指标切换、ai-performance=当前时间范围文案 + 账户 chips），其余筛选（日期范围/用户/添加账户/重置/刷新）收进底部抽屉，入口按钮带「非默认筛选」打点（`'all'` 为全部用户哨兵，判定时须排除）；账户 chips 超 4 条折叠为两行加「展开全部」开关。桌面（>768/900px）维持原单行工具栏不变。AI 健康页已用通用 `ResponsiveListToolbar`，不套用本模式。统计汇总卡移动端两列网格（数字 21px、补充行 11px），保证数据首屏直达。
- 表单工具页（模型检测）移动端模式：紧凑条 = 当前条件摘要（点按开抽屉）+ 主操作按钮（快速检测）常驻；检测条件（系统账户/账户/模型/对比账户）、刷新/重置与质量工具（列设置/题库/定时检查）收进「检测条件」抽屉，抽屉底部保留满宽主按钮——选完条件当场执行。顶栏副标题（页面描述）全端隐藏：窄屏截断省略无信息量。
- 设置页（系统设置）折叠分组模式（2026-10-02 方案 C）：默认全部折叠，分组条 = 组名 + 摘要 + 状态胶囊（「默认」/「N 项自定义」/「N 项已修改」）；展开默认为「标签 ······ 值」展示行（同语义字段归并一行，自定义值琥珀色并附「默认 X」对照，点线引导在 ≤700px 隐藏改为两端对齐），点「编辑此组」才切行式表单（label 左 + 输入右 + 单位后缀），按组保存/取消/恢复默认值，多组可同时编辑各自独立保存；组状态基于服务端 baseline 与出厂默认比对。页面摘要行「共 N 项 · N 项自定义」同步全局口径。字段与分组定义的唯一事实源是 `views/settings/settingsDisplay.ts`（含 section 提交契约映射），不得在视图里散写字段。
- 账户编辑弹框（§8.1）窄屏（≤640px）行为契约：新建向导步骤条收敛为「序号 + 主标题」三步均分（副标题与连接条隐藏）；编辑态折叠摘要卡的头部摘要文本隐藏（`.bench-card-sum` 只留卡名与徽标），标题栏允许换行；内层 `form-scroll` 滚动窗口撤销（`max-height: none`），由 global.css 的 modal-body 统一滚动承接，禁止双层滚动。
- 触控目标：粗触控设备（`(pointer: coarse)`）且窄屏（≤900px）时，主操作按钮（工具栏、弹框 footer、移动卡片操作区、筛选/操作抽屉内）触控目标不低于 44px（global.css 统一规则）；表格行内小按钮不受此规则约束。

## 10. 禁止倾向

- 为单个页面复制一套基础组件样式。
- 为局部视觉效果引入复杂库或重型抽象。
- 用大面积装饰掩盖信息结构问题。
- 不引入大面积渐变；例外只有三处（均为小面积控件，组件内必须以变量引用 `--juhe-primary-grad`，不得重复字面量）：主按钮、顶栏用户头像、账户编辑弹框标题栏类型徽章（§8.1）。
- 用刷新、延迟、重复请求掩盖状态同步问题。
- 在前端伪造后端状态或业务判断。
- 在规范文档中固化具体业务细节，导致后续模块无法复用。

## 11. 验证要求

- 纯前端样式或页面改动至少运行：

```powershell
pnpm --filter juhe-ai-frontend typecheck
```

- 如果改动影响 API 类型、请求字段或后端响应，至少运行：

```powershell
pnpm typecheck
```

- 如果改动影响真实业务流程，应按 [开发测试与验证说明](../../develop/测试与验证说明.md) 补充对应验证。

## 12. AI 自检

- 是否复用了 Ant Design Vue 和现有全局样式？
- 是否避免了具体业务细节写入通用规范？
- 是否覆盖加载、空态、错误态和禁用态？
- 是否保护了敏感字段展示边界？
- 是否没有用前端状态替代后端事实？
- 是否运行或说明了必要验证？
- 新增或修改界面颜色时是否引用 `--juhe-*` 变量或 AntD 令牌，且未硬编码旧主题色（`#1677ff` / `#061a2e` / `#03111f` / `#f5f7fb` / `#edf1f7`）？
