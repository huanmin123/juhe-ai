## 适用边界

- 安装说明回答“拿到项目后需要什么环境、怎么准备、怎么让项目跑起来”。
- 运行说明回答“项目怎么启动、默认访问地址是什么、运行前后要注意什么”。
- 测试说明回答“怎么做代码级检查、接口检查、网关联通、账号测试和烟测”；组合级改动（组合根接线 / 装配顺序 / 端口注入）的验收必须包含 dev 环境真实验证，副作用端口接线必须验证“副作用真的发生”（见测试与验证说明 2.3 / 2.4）。
- 后端测试分层规则回答“功能基线 / 慢基线 / 场景测试 / 性能测试四轨的边界、按改动选测试（`pnpm test:affected`）、基线硬规则、覆盖率 95% 审计目标（独立于基线门禁）、场景测试授权（`JUHE_AI_TEST_EXTERNAL=1`）、测试进程纪律（守卫脚本 `scripts/test-process-isolation-regression.mjs`）、组合根接线守卫与 nil 端口 no-op 登记、测试库复刻生产连接池配置、种子/配置数据不变量守护（§7）”，是测试分层与命令入口的权威来源，开发与测试必须遵守。
- 前端测试分层规则回答“前端逻辑域单测覆盖、前后端契约比对、tsx 回归脚本的分层和运行入口”，并说明真实后端 smoke 属场景测试（需授权）；开发与测试必须遵守。
- 默认执行口径：改完代码跑 `pnpm test:affected`（按 git 改动选包，≤5 分钟）；全量功能基线 `pnpm test:baseline`（fast，15 分钟预算）；真实 PG / 组合根验收 / 前端真实后端 smoke 走 `JUHE_AI_TEST_EXTERNAL=1 pnpm test:scenario -- --flow=pg|acceptance|frontend-smoke`。`pnpm test:daily` 保留为 `test:baseline` 的等价旧入口。
- Mockdata 说明回答“如何给本地 admin 生成可重复使用的完整演示 / 测试数据”。
- Go 迁移调整说明只回答“后端迁移到 Go 期间开发、构建和部署会如何变化”；正式切换前，当前运行命令仍以本目录现有手册为准。
