# 开发运行说明

> 面向 AI 与维护者。
> 本文件只说明如何把项目跑起来以及运行时注意事项；测试步骤、接口样例和烟测细节请放到 [开发测试与验证说明](测试与验证说明.md)。

## 1. 运行前提

- 先完成 [开发环境安装说明](安装指南.md)，确保依赖已安装。
- 后端和前端默认读取项目内 `.env` 文件；后端支持进程环境变量临时覆盖 `.env`，便于隔离库、临时端口和部署平台注入配置。
- Node.js 需要使用官方 LTS，并通过后端运行时预检；预检会验证 `node:sqlite` 可用。
- 默认端口 `3000` 和 `5173` 不应被其他进程占用。
- 复用当前业务库时，`backend/.env` 里的 `JUHE_AI_SECRET` 必须保持稳定；开发环境可留空使用内置开发密钥，`NODE_ENV=production` 时必须配置至少 32 位稳定随机密钥；当前 schema 之外的结构问题按当前 schema 离线修复，不进运行时代码。

## 2. 启动项目

在项目根目录同时启动前后端：

```powershell
pnpm dev
```

只启动后端：

```powershell
pnpm --filter juhe-ai-backend dev
```

后端开发模式需要同时关注九个常驻运行单元：

- Web/网关主进程：监听 `/__aisys__/*` 系统后台静态资源、健康检查和系统 API 反向代理，并承接根路径和 `/v1` 客户端网关入口。
- 默认 background worker 进程：控制 / fallback 角色，保留运行态快照、事件循环采样响应和后续轻量控制入口，不承载统计、写入、探测或维护重活。
- metrics-worker 进程：保留为常驻观测 / 控制响应角色，不直接写统计库；系统采样写入统一由 stats-worker 串行提交。
- ingest-worker 进程：承载使用记录、审计日志、操作日志、公开接口日志和运行日志索引等 append-only 写入，以及运行日志文件增量导入，避免统计重任务拖住写入事实。
- stats-worker 进程：承载系统采样写入、用量增量聚合、IP 聚合、分组账号统计缓存、TopN、概览、范围窗口、授权窗口、系统趋势窗口、账号质量刷新、表监控和统计保留期清理，避免多个 worker 抢写同一个 stats SQLite 文件。
- snapshot-worker 进程：保留为常驻快照隔离角色和后续扩展位，当前不直接写统计库；重窗口刷新由 stats-worker 串行写入。
- probe-worker 进程：承载代理检测、账号质量刷新、OAuth token 保活、手动账号测试、账号级冷却复测和账户内 Key 级冷却复测等外部探测。
- maintenance-worker 进程：承载业务库维护调度协调，授权到期扫描、可用性时间计划同步和过期逻辑删除账号清理通过 DB service typed operation 写业务库。
- DB service 进程：承接系统管理 API、登录态校验、管理面 CRUD、网关高频 SQLite 读写、公开设置读取、运行日志索引查询和账号运行态副作用，降低 Web/网关主进程被同步 SQL 短暂阻塞的风险。

`usage_records_cleanup`、`non_business_data_cleanup`、API Key / AI 账户关联记录清理等维护任务现在由 ingest-worker 本地队列执行 usage shard / dataset 部分，stats 部分投递 stats-worker，不再 fork 临时维护 worker 写 usage shard 或 stats。

`pnpm --filter juhe-ai-backend dev` 会先启动 Web/网关主进程，再由主进程 fork 并看护默认 worker、metrics-worker、ingest-worker、stats-worker、snapshot-worker、probe-worker、maintenance-worker 和 DB service；排查后台任务、管理 API 和网关数据库访问时应确认这些子进程与主进程 PID 不同。DB service 不可用时，系统 API 和网关数据库请求会返回可读错误并等待 supervisor 重启 DB service，不会回退到主进程本地同步执行；使用记录、审计记录、操作日志、公开接口日志、运行日志索引和记录维护只会投递到 ingest-worker IPC 待发送队列，不会因为 worker 未就绪在主进程本地写 SQLite。

只启动前端：

```powershell
pnpm --filter juhe-ai-frontend dev
```

## 3. 默认访问地址

- 前端管理后台：`http://127.0.0.1:5173/__aisys__/`
- 后端系统 API：`http://127.0.0.1:3000/__aisys__/api`
- 后端健康检查：`http://127.0.0.1:3000/__aisys__/health`
- OpenAI 兼容中转入口：`http://127.0.0.1:3000` 或 `http://127.0.0.1:3000/v1`

开发模式下，前端会把 `/__aisys__/api` 和 `/v1` 转发到 `frontend/.env` 中的 `VITE_JUHE_AI_BACKEND_TARGET`。根路径和其他非 `/__aisys__/*` 请求属于客户端网关入口，生产部署时不要再把管理后台挂到 `/`。

## 4. 运行注意事项

- 本地运行优先保持 `JUHE_AI_HOST=127.0.0.1`；需要局域网访问时再改成 `0.0.0.0`。
- DB service 内部系统 API 默认监听 `JUHE_AI_DB_SERVICE_HTTP_HOST=127.0.0.1` 和随机空闲端口 `JUHE_AI_DB_SERVICE_HTTP_PORT=0`；通常不要暴露到公网，也不要固定端口，除非本机排障需要。
- 分离部署或公网访问时，再按实际地址设置 `VITE_JUHE_AI_GATEWAY_BASE_URL`。
- SQLite 默认数据目录是 `backend/data/`，默认包含业务库 `juhe-ai.sqlite3`、统计数据集目录库 `juhe-ai-dataset.sqlite3`、统计结果库 `juhe-ai-stats.sqlite3` 和 usage shard 文件目录。需要查看当前 schema 之外的历史明细时只能停服务后离线处理，不写进源码主路径。
- 需要给本地 admin 生成完整演示 / 测试数据时，先停止正在写库的本地服务，再执行 `pnpm mockdata`；脚本会清理上一批 `造数-` / `mockdata_` 数据并重建近 31 天统计缓存，详细范围见 [Mockdata 造数设计](../functions/Mockdata造数设计.md)。后续新增可复用造数能力统一扩展 Mockdata，不新增散落的 seed / demo 脚本。
- OAuth token 换取、刷新和账号测试优先使用账号绑定代理；`JUHE_AI_OAUTH_PROXY_URL` 只是兜底代理。
- 后端普通运行日志默认写入 `backend/logs/juhe-ai.log`；本地直接运行时也会输出到终端。发布包 `start.sh` 在生产模式下默认设置 `JUHE_AI_LOG_CONSOLE_ENABLED=false`，避免 launchd / systemd / PM2 再额外收集一份高频 JSONL 日志；如需临时观察 stdout，可在启动前显式设置为 `true`。每条请求日志都会带 `traceId`，响应头也会返回 `x-trace-id`。
- Web/网关主进程启动时不直接打开业务库、数据集目录库、usage shard 或统计结果库，也不直接挂载管理 API repository；系统 API 或客户请求链路如果遇到 DB service 未就绪、队列满、请求超时或内部 HTTP 不可用，应按不可用错误排查 DB service supervisor、子进程日志、内部 HTTP 端口和 IPC 队列，不能临时恢复主进程同步读取 SQLite 的 fallback。
- 后台定时任务和手动账号测试不应在 Web/API 主进程事件循环里执行；如果统计聚合、系统采样写入、窗口刷新、账号质量、表监控或统计保留期清理日志不在 stats-worker，OAuth Access Token 保活 / 手动账号测试 / 账号复测日志不在 probe-worker，记录维护和数据集保留期清理日志不在 ingest-worker，业务库维护 typed command 调度不在 maintenance-worker，需要先修正 worker 角色隔离。OAuth Access Token 保活会扫描所有仍存在且快过期的 GPT OAuth 账户，连续 3 次刷新失败会标记为异常；OAuth 额度快照只由真实网关请求或账户测试响应头被动更新，不再有后台主动刷新任务。
- 普通日志默认 `100MB` 滚动，保留 `30` 天、最多 `500` 个历史文件，约束总量约 `50GB`；可通过 `JUHE_AI_LOG_LEVEL`、`JUHE_AI_LOG_DIR`、`JUHE_AI_LOG_MAX_FILE_MB`、`JUHE_AI_LOG_RETENTION_DAYS`、`JUHE_AI_LOG_MAX_FILES` 调整，后端会把保留天数和文件数限制在默认上限内。
- 网关写下游响应时仍尊重 `res.write()` backpressure；短暂 drain 默认只保留 debug 级运行日志，只有等待超过 50ms 时才写 warn，避免把 0 到 1ms 的正常瞬态当成生产告警。
- 管理后台“日志搜索”的索引查询模式只检索最近 3 天写入 SQLite 索引的普通运行日志，支持按索引日志时间范围筛选；超过 3 天的日志即使日志文件仍保留也不会被索引查询搜到。
- 后台 worker 会用数据集目录库中的文件游标追踪当前普通日志文件，只读取上次游标之后新增的完整行；首次看到已有日志文件时从文件末尾开始追新内容，避免本地开发重启时反复全量扫描大日志。
- 管理后台“表监控”只对管理员开放，后台 worker 默认每 10 分钟采样一次业务库、数据集目录库和统计结果库的文件大小、WAL、空闲页、表大小、可推导行数和 1 小时 / 24 小时增长；行数随表游标通过 `dbstat` 滚动写入，不提供精确 `COUNT(*)` 采样分支。采样历史默认保留最近一月，写入统计结果库，不进入业务库；usage shard 文件集合观测仍属于 PLAN-0030 表监控阶段的后续增强项。
- 管理后台“日志搜索”的 `grep 模式` 会由后端调用生产依赖 `@vscode/ripgrep` 提供的 `rg`，在日志目录中按任意关键字搜索当前保留的 `.log` 文件；多关键字按同一行同时命中处理。时间范围只用于筛选参与扫描的日志文件，不读取文件内容判断行时间；默认按文件时间搜索最近 3 天，单次文件时间范围最多 7 天，同一后端进程一次只允许 1 个 grep 搜索，单次 `rg` 搜索 15 秒超时，避免一次扫描过大拖垮服务。如果运行环境找不到 `rg`，接口会直接返回错误提示，不读取服务器 PATH，也不回退到慢速扫描。
- 前端面向中文用户，页面应通过全局 `a-config-provider` 使用中文 locale，避免 Ant Design Vue 默认英文文案出现在界面。
- 启动后先看终端日志里的监听地址和报错信息，不要把具体接口测试矩阵写进本文件。
