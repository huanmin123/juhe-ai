# 开发环境安装说明

> 面向 AI 与维护者。
> 这里说明接手项目后，想让 `juhe-ai` 跑起来需要什么环境、怎么安装、怎么准备项目内配置。

## 1. 目标

- 让新机器或新环境能完成首次安装。
- 让 AI 能快速判断“缺什么、怎么补、补完后怎么启动”。
- 统一说明哪些配置必须放在项目内，而不是依赖系统环境变量。

## 2. 环境要求

- 操作系统：当前仓库默认按 Windows + PowerShell 7 书写命令。
- Node.js：当前 Node 后端过渡期必须使用官方 LTS，当前支持 22.x LTS（>=22.13.0）或 24.x LTS（>=24.11.0），且内置 `node:sqlite` 必须可用；Go 迁移完成后再删除 Node 后端和 SQLite 要求。
- Go：Node 转 Go 迁移 W0 已升级到 `go1.26.5`；需要执行 Go 迁移任务时，先参考 [Go 迁移开发构建部署调整](../migration/开发构建部署调整.md)。
- pnpm：`9.x` 或更高。
- Git：用于拉取代码和提交修改。
- 网络：安装依赖时通常需要能访问 npm registry 或可用代理。

建议先检查：

```powershell
$PSVersionTable.PSVersion
node -v
node -p "process.version + ' LTS=' + (process.release.lts || '非LTS')"
pnpm -v
go version
```

当前 Windows 本机的 Go 迁移工具链已经按 W0 基线配置：

| 工具 | 版本 / 路径 | 用途 |
| --- | --- | --- |
| Go | `go1.26.5 windows/amd64`，`GOROOT=E:\gosdk\go1.26.5` | `backend-go` 编译、测试和发布基线 |
| w64devkit | `E:\tools\w64devkit-2.8.0\w64devkit\bin`，GCC `16.1.0` | Windows `go test -race` C 工具链 |
| Go CLI tools | `C:\Users\Administrator\go\bin` | `sqlc`、`goose`、`golangci-lint`、`govulncheck` |

新开的 PowerShell 7 会读取系统 Machine 环境变量；如果当前终端或 Codex 会话仍继承旧 `go1.23.0`，先在该会话显式前置：

```powershell
$env:GOROOT = 'E:\gosdk\go1.26.5'
$env:Path = 'E:\tools\w64devkit-2.8.0\w64devkit\bin;E:\gosdk\go1.26.5\bin;C:\Users\Administrator\go\bin;' + $env:Path
go version
```

## 3. 首次安装

在项目根目录执行：

```powershell
pnpm install
pnpm --filter juhe-ai-backend check:runtime
```

如果是刚拿到项目，建议先复制项目内配置文件：

```powershell
Copy-Item backend/.env.example backend/.env
Copy-Item frontend/.env.example frontend/.env
```

## 4. 项目内配置

### 4.1 Node 后端过渡配置

编辑 `backend/.env`：

```dotenv
JUHE_AI_HOST=127.0.0.1
JUHE_AI_PORT=3000
JUHE_AI_DB_SERVICE_HTTP_HOST=127.0.0.1
JUHE_AI_DB_SERVICE_HTTP_PORT=0
JUHE_AI_DATABASE_PATH=./data/juhe-ai.sqlite3
JUHE_AI_DATASET_DATABASE_PATH=./data/juhe-ai-dataset.sqlite3
JUHE_AI_RUNTIME_LOG_DATABASE_PATH=./data/juhe-ai-runtime-log.sqlite3
JUHE_AI_USAGE_CATALOG_DATABASE_PATH=./data/juhe-ai-usage-catalog.sqlite3
JUHE_AI_STATS_DATABASE_PATH=./data/juhe-ai-stats.sqlite3
JUHE_AI_USAGE_SHARD_ROOT=./data/usage-shards
JUHE_AI_CODEX_CONTEXT_ROOT=./data/codex-context
JUHE_AI_CODEX_CONTEXT_STATE_SHARD_ROOT=./data/codex-context/state-shards
JUHE_AI_USAGE_SHARD_COUNT=16
JUHE_AI_CODEX_CONTEXT_STATE_SHARD_COUNT=16
JUHE_AI_CODEX_CONTEXT_STATE_WRITER_POOL_ENABLED=true
JUHE_AI_CODEX_CONTEXT_STATE_WRITER_POOL_SIZE=0
JUHE_AI_CODEX_CONTEXT_STATE_WRITER_QUEUE_MAX_ITEMS=5000
JUHE_AI_SECRET=请替换为稳定随机字符串
JUHE_AI_ALLOWED_ORIGINS=
JUHE_AI_COOKIE_SECURE=
JUHE_AI_COOKIE_SAME_SITE=lax
JUHE_AI_TRUST_PROXY=false
JUHE_AI_ALLOW_PRIVATE_UPSTREAM_BASE_URLS=false
JUHE_AI_UPSTREAM_BASE_URL_PRIVATE_ALLOWLIST=
JUHE_AI_OAUTH_PROXY_URL=
JUHE_AI_LOG_LEVEL=info
JUHE_AI_LOG_DIR=./logs
JUHE_AI_LOG_FILE_ENABLED=true
JUHE_AI_LOG_CONSOLE_ENABLED=true
JUHE_AI_LOG_MAX_FILE_MB=100
JUHE_AI_LOG_RETENTION_DAYS=30
JUHE_AI_LOG_MAX_FILES=500
JUHE_AI_LOG_CLEANUP_INTERVAL_MINUTES=60
```

说明：

- `JUHE_AI_DATABASE_PATH` 默认使用项目内 `backend/data/juhe-ai.sqlite3`，只保存系统账户、AI 账户、分组、API Key、授权、设置和公告等业务数据。
- `JUHE_AI_DATASET_DATABASE_PATH` 保存审计、操作日志、公开接口日志和模型检测等数据集目录信息。
- `JUHE_AI_RUNTIME_LOG_DATABASE_PATH` 保存 Go F1 运行日志索引、cursor、facet 和保留清理；Node 只读，且不得与 dataset 文件共用。
- `JUHE_AI_USAGE_CATALOG_DATABASE_PATH` 保存 usage shard 注册表、列表筛选目录和账号 / API Key 到 shard 的去重目录，不保存完整使用记录正文。
- `JUHE_AI_STATS_DATABASE_PATH` 保存统计缓存、额度窗口、账号质量、系统监控、表监控和 `stats_job_state` 等查询结果数据。
- `JUHE_AI_USAGE_SHARD_ROOT` 保存新写入的 `usage_records` 分片 SQLite 文件；`JUHE_AI_USAGE_SHARD_COUNT` 默认 `16`，生产启用后不要直接改小。
- `JUHE_AI_CODEX_CONTEXT_ROOT` 保存 Responses Chat-only bridge 的上下文 payload segment 文件；`JUHE_AI_CODEX_CONTEXT_STATE_SHARD_ROOT` 保存对应的可丢弃关系索引 shard，不属于业务库；`JUHE_AI_CODEX_CONTEXT_STATE_SHARD_COUNT` 默认 `16`。`JUHE_AI_CODEX_CONTEXT_STATE_WRITER_POOL_ENABLED` 控制 DB service 内部 Responses 桥接状态索引 shard writer pool，`JUHE_AI_CODEX_CONTEXT_STATE_WRITER_POOL_SIZE=0` 表示按 shard 数和 CPU 并行度自动取值，`JUHE_AI_CODEX_CONTEXT_STATE_WRITER_QUEUE_MAX_ITEMS` 控制 pool 待处理队列上限。
- 业务库、数据集目录库、使用记录目录库、统计结果库、usage shard 文件和 Responses 桥接状态索引 shard 文件必须指向不同文件，usage shard 根目录、Responses 桥接状态 payload 目录和状态索引 shard 根目录也必须与这些文件路径区分；当前配置只使用上面列出的存储入口。
- `JUHE_AI_DB_SERVICE_HTTP_HOST` / `JUHE_AI_DB_SERVICE_HTTP_PORT` 只用于 DB service 内部系统 API；默认绑定本机并自动选择空闲端口，主进程会代理 `/__aisys__/api/*`，通常不需要修改。
- `JUHE_AI_SECRET` 会影响已加密数据解密，复用当前业务库时必须保持一致；`NODE_ENV=production` 时必须配置至少 32 位稳定随机密钥，不能使用内置开发密钥；当前 schema 之外的数据问题按当前 schema 离线修复或重建。
- `JUHE_AI_ALLOWED_ORIGINS` 开发环境可留空，后端会继续支持本地前端跨域联调；`NODE_ENV=production` 时必须填写后台前端完整 Origin。
- `JUHE_AI_COOKIE_SECURE` 开发环境默认 `false`，方便本地 HTTP 登录；生产环境默认 `true`。
- `JUHE_AI_COOKIE_SAME_SITE` 默认 `lax`；配置为 `none` 时必须同时启用 `JUHE_AI_COOKIE_SECURE=true`。
- `JUHE_AI_TRUST_PROXY` 默认 `false`，本地开发无需修改。
- `JUHE_AI_ALLOW_PRIVATE_UPSTREAM_BASE_URLS` 默认 `false`，账户上游 `Base URL` 会拒绝本机、内网、链路本地和保留地址；只有本地 mock 上游联调或回归测试才临时设为 `true`。
- `JUHE_AI_UPSTREAM_BASE_URL_PRIVATE_ALLOWLIST` 默认留空；确需访问私网上游时，逐项填写精确 IP Origin，例如 `http://192.168.40.199:8317`，多个值用逗号分隔。匹配维度固定为 `scheme + IP + effective port`，账户 Base URL 的路径不参与匹配；不接受域名、路径、查询参数、片段或用户名密码。生产环境不会自动写入该配置，必须由部署人员显式启用。
- 本地 CLIProxyAPI sidecar 联调时，推荐把 `JUHE_AI_UPSTREAM_BASE_URL_PRIVATE_ALLOWLIST` 精确设为 sidecar origin，例如 `http://127.0.0.1:3456`；然后在账户里把 Base URL 填成 `http://127.0.0.1:3456/v1` 或 `http://127.0.0.1:3456/v1beta`。除临时回归外，不建议直接全开 `JUHE_AI_ALLOW_PRIVATE_UPSTREAM_BASE_URLS=true`。
- 上游请求不自动跟随重定向，避免已放行 Origin 通过 30x 跳转到其他私网服务。
- `JUHE_AI_OAUTH_PROXY_URL` 只是 OAuth 刷新和换取的兜底代理，账号代理优先在代理管理页绑定。
- `JUHE_AI_LOG_DIR` 默认使用项目内 `backend/logs/`，普通运行日志会按大小滚动，并按保留天数和最大文件数清理。
- `JUHE_AI_LOG_CONSOLE_ENABLED=true` 适合本地开发直接看终端日志；发布包的 `start.sh` 会在未显式设置时把它改为 `false`，避免守护进程 stdout 日志重复膨胀。

### 4.2 Go 后端配置

Go 后端当前仍处于渐进 opt-in 阶段，具体命令见 [backend-go README](../../backend-go/README.md)。Go 后端不读取 SQLite 路径、DB service 或 standalone / performance 双模式配置；W0 基础依赖使用 `w0-smoke` 验证 PG/Redis/Asynq 基线，W1a 公开设置读接口使用 `w1a-public-settings-smoke` 验证真实 PostgreSQL public settings 读取和 Redis state 原子限流。W5 `GET/PATCH /__aisys__/api/settings` 已进入 Go opt-in，真实依赖与 loopback listener 写 smoke 已有独立记录，但不代表生产接管。

```dotenv
JUHE_AI_POSTGRES_URL=postgres://juhe_ai:password@127.0.0.1:5432/juhe_ai?sslmode=disable
JUHE_AI_REDIS_CACHE_URL=redis://127.0.0.1:6379/0
JUHE_AI_REDIS_STATE_URL=redis://127.0.0.1:6380/1
JUHE_AI_REDIS_QUEUE_URL=redis://127.0.0.1:6381/2
JUHE_AI_REDIS_NAMESPACE=juhe-ai
JUHE_AI_USAGE_STATS_TIMEZONE=Asia/Shanghai
JUHE_AI_TRUST_PROXY=false
JUHE_AI_METRICS_ENABLED=true
JUHE_AI_PPROF_ENABLED=false
```

执行真实依赖 smoke：

```powershell
Set-Location backend-go
go run ./cmd/juhe-ai-maintenance w0-smoke
go run ./cmd/juhe-ai-maintenance w1a-public-settings-smoke
```

未配置上述 URL 时，`w0-smoke` 和 `w1a-public-settings-smoke` 会直接失败；普通 `/__aisys__/health` 在 URL 为空时会把依赖标记为 `skipped`，不能当作真实 PG/Redis/Asynq smoke。cache / state / queue 必须使用不同 Redis 进程的 `host:port`；同一进程不同 DB 不算隔离，生产配置也不要使用 `localhost` 或 `::1` 别名，统一使用 canonical `127.0.0.1` 或实际独立主机名。

启动 Go server 前必须先显式执行 PostgreSQL migration，并配置 Redis state；Go 启动路径不会自动建表或自动迁移：

```powershell
Set-Location backend-go
$env:JUHE_AI_USAGE_STATS_TIMEZONE = 'Asia/Shanghai'
goose -dir db/migrations postgres $env:JUHE_AI_POSTGRES_URL up
go run ./cmd/juhe-ai server
```

`JUHE_AI_USAGE_STATS_TIMEZONE` 示例值应替换为实际部署使用的 IANA 时区。migration `000024_w5_system_settings.sql` 优先使用该变量 seed `usageStatsTimezone`；未设置时回退 PostgreSQL `TimeZone`，再回退 `UTC`。Node / Go 共存期必须让该值与 Node `Intl` 实际部署时区一致；PostgreSQL 在线禁止通过 settings PATCH 修改统计时区。

当前 Go server 已包含 W1a `GET /__aisys__/api/settings/public` 和 W5 `GET/PATCH /__aisys__/api/settings` opt-in 实现；W5 路径只有在 `JUHE_AI_MANAGEMENT_API_ENABLED=true` 时注册。真实 PG/Redis smoke、前端真实 Go 后端 smoke、生产切流和 Node 删除证据未完成前，不能把这些路径视为 Go 已生产接管。

### 4.3 前端配置

编辑 `frontend/.env`：

```dotenv
VITE_JUHE_AI_BACKEND_TARGET=http://127.0.0.1:3000
VITE_JUHE_AI_API_BASE_URL=/__aisys__/api
VITE_JUHE_AI_GATEWAY_BASE_URL=
```

说明：

- 开发时前端会把 `/__aisys__/api` 和 `/v1` 转发到 `VITE_JUHE_AI_BACKEND_TARGET`。
- 分离部署或公网访问时，再按实际地址填写 `VITE_JUHE_AI_GATEWAY_BASE_URL`。
- 烟测专用变量不放在安装说明里，需要时参考 [开发测试与验证说明](测试与验证说明.md)。

## 5. 可移植性

- 项目默认不要求系统环境变量，优先修改项目内的 `.env` 文件；需要临时验证、隔离数据库或部署平台注入时，后端同名进程环境变量会覆盖 `backend/.env`。
- 复制整个项目目录到其他电脑或服务器时，保留 `backend/.env`、`frontend/.env` 和 `backend/data/` 即可继续使用。
- 如果把后端放到反向代理后面，通常仍建议保持 `JUHE_AI_HOST=127.0.0.1`；需要局域网访问时再改成 `0.0.0.0`。
