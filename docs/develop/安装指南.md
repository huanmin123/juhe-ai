# 开发环境安装说明

> 面向 AI 与维护者。
> 这里说明接手项目后，想让 `juhe-ai` 跑起来需要什么环境、怎么安装、怎么准备项目内配置。

## 1. 目标

- 让新机器或新环境能完成首次安装。
- 让 AI 能快速判断“缺什么、怎么补、补完后怎么启动”。
- 统一说明哪些配置必须放在项目内，而不是依赖系统环境变量。

## 2. 环境要求

- 操作系统：当前仓库默认按 Windows + PowerShell 7 书写命令。
- Node.js：必须使用官方 LTS，当前支持 22.x LTS（>=22.13.0）或 24.x LTS（>=24.11.0），且内置 `node:sqlite` 必须可用。
- pnpm：`9.x` 或更高。
- Git：用于拉取代码和提交修改。
- 网络：安装依赖时通常需要能访问 npm registry 或可用代理。

建议先检查：

```powershell
$PSVersionTable.PSVersion
node -v
node -p "process.version + ' LTS=' + (process.release.lts || '非LTS')"
pnpm -v
```

## 3. 首次安装

在项目根目录执行：

```powershell
pnpm install
pnpm --filter juhe-ai-backend check:runtime
```

如果是刚拿到项目，建议先复制项目内配置文件：

```powershell
Copy-Item backend/.env.example backend/.env
Copy-Item frontend/.env.example frontend/.env
```

## 4. 项目内配置

### 4.1 后端配置

编辑 `backend/.env`：

```dotenv
JUHE_AI_HOST=127.0.0.1
JUHE_AI_PORT=3000
JUHE_AI_DB_SERVICE_HTTP_HOST=127.0.0.1
JUHE_AI_DB_SERVICE_HTTP_PORT=0
JUHE_AI_DATABASE_PATH=./data/juhe-ai.sqlite3
JUHE_AI_DATASET_DATABASE_PATH=./data/juhe-ai-dataset.sqlite3
JUHE_AI_STATS_DATABASE_PATH=./data/juhe-ai-stats.sqlite3
JUHE_AI_USAGE_SHARD_ROOT=./data/usage-shards
JUHE_AI_CODEX_CONTEXT_ROOT=./data/codex-context
JUHE_AI_CODEX_CONTEXT_DATABASE_PATH=./data/codex-context/state.sqlite3
JUHE_AI_USAGE_SHARD_COUNT=16
JUHE_AI_SECRET=请替换为稳定随机字符串
JUHE_AI_ALLOWED_ORIGINS=
JUHE_AI_COOKIE_SECURE=
JUHE_AI_COOKIE_SAME_SITE=lax
JUHE_AI_TRUST_PROXY=false
JUHE_AI_ALLOW_PRIVATE_UPSTREAM_BASE_URLS=false
JUHE_AI_UPSTREAM_BASE_URL_PRIVATE_ALLOWLIST=
JUHE_AI_OAUTH_PROXY_URL=
JUHE_AI_LOG_LEVEL=info
JUHE_AI_LOG_DIR=./logs
JUHE_AI_LOG_FILE_ENABLED=true
JUHE_AI_LOG_CONSOLE_ENABLED=true
JUHE_AI_LOG_MAX_FILE_MB=100
JUHE_AI_LOG_RETENTION_DAYS=30
JUHE_AI_LOG_MAX_FILES=500
JUHE_AI_LOG_CLEANUP_INTERVAL_MINUTES=60
```

说明：

- `JUHE_AI_DATABASE_PATH` 默认使用项目内 `backend/data/juhe-ai.sqlite3`，只保存系统账户、AI 账户、分组、API Key、授权、设置和公告等业务数据。
- `JUHE_AI_DATASET_DATABASE_PATH` 保存审计、操作日志、运行日志索引、模型检测和 usage shard catalog 等数据集目录信息。
- `JUHE_AI_STATS_DATABASE_PATH` 保存统计缓存、额度窗口、账号质量、系统监控、表监控和 `stats_job_state` 等查询结果数据。
- `JUHE_AI_USAGE_SHARD_ROOT` 保存新写入的 `usage_records` 分片 SQLite 文件；`JUHE_AI_USAGE_SHARD_COUNT` 默认 `16`，生产启用后不要直接改小。
- `JUHE_AI_CODEX_CONTEXT_ROOT` 保存 Codex Responses Chat-only bridge 的上下文 payload 文件；`JUHE_AI_CODEX_CONTEXT_DATABASE_PATH` 保存对应的可丢弃关系索引，不属于业务库。
- 四个 SQLite 路径必须指向不同文件，usage shard 根目录和 Codex 上下文目录也必须与这些文件路径区分；当前配置只使用上面列出的存储入口。
- `JUHE_AI_DB_SERVICE_HTTP_HOST` / `JUHE_AI_DB_SERVICE_HTTP_PORT` 只用于 DB service 内部系统 API；默认绑定本机并自动选择空闲端口，主进程会代理 `/__aisys__/api/*`，通常不需要修改。
- `JUHE_AI_SECRET` 会影响已加密数据解密，复用当前业务库时必须保持一致；`NODE_ENV=production` 时必须配置至少 32 位稳定随机密钥，不能使用内置开发密钥；当前 schema 之外的数据问题按当前 schema 离线修复或重建。
- `JUHE_AI_ALLOWED_ORIGINS` 开发环境可留空，后端会继续支持本地前端跨域联调；`NODE_ENV=production` 时必须填写后台前端完整 Origin。
- `JUHE_AI_COOKIE_SECURE` 开发环境默认 `false`，方便本地 HTTP 登录；生产环境默认 `true`。
- `JUHE_AI_COOKIE_SAME_SITE` 默认 `lax`；配置为 `none` 时必须同时启用 `JUHE_AI_COOKIE_SECURE=true`。
- `JUHE_AI_TRUST_PROXY` 默认 `false`，本地开发无需修改。
- `JUHE_AI_ALLOW_PRIVATE_UPSTREAM_BASE_URLS` 默认 `false`，账户上游 `Base URL` 会拒绝本机、内网、链路本地和保留地址；只有本地 mock 上游联调或回归测试才临时设为 `true`。
- `JUHE_AI_UPSTREAM_BASE_URL_PRIVATE_ALLOWLIST` 只用于本地开发精确放行某些私网 host，例如 `127.0.0.1`；生产环境不能配置。
- `JUHE_AI_OAUTH_PROXY_URL` 只是 OAuth 刷新和换取的兜底代理，账号代理优先在代理管理页绑定。
- `JUHE_AI_LOG_DIR` 默认使用项目内 `backend/logs/`，普通运行日志会按大小滚动，并按保留天数和最大文件数清理。
- `JUHE_AI_LOG_CONSOLE_ENABLED=true` 适合本地开发直接看终端日志；发布包的 `start.sh` 会在未显式设置时把它改为 `false`，避免守护进程 stdout 日志重复膨胀。

### 4.2 前端配置

编辑 `frontend/.env`：

```dotenv
VITE_JUHE_AI_BACKEND_TARGET=http://127.0.0.1:3000
VITE_JUHE_AI_API_BASE_URL=/__aisys__/api
VITE_JUHE_AI_GATEWAY_BASE_URL=
```

说明：

- 开发时前端会把 `/__aisys__/api` 和 `/v1` 转发到 `VITE_JUHE_AI_BACKEND_TARGET`。
- 分离部署或公网访问时，再按实际地址填写 `VITE_JUHE_AI_GATEWAY_BASE_URL`。
- 烟测专用变量不放在安装说明里，需要时参考 [开发测试与验证说明](测试与验证说明.md)。

## 5. 可移植性

- 项目默认不要求系统环境变量，优先修改项目内的 `.env` 文件；需要临时验证、隔离数据库或部署平台注入时，后端同名进程环境变量会覆盖 `backend/.env`。
- 复制整个项目目录到其他电脑或服务器时，保留 `backend/.env`、`frontend/.env` 和 `backend/data/` 即可继续使用。
- 如果把后端放到反向代理后面，通常仍建议保持 `JUHE_AI_HOST=127.0.0.1`；需要局域网访问时再改成 `0.0.0.0`。
