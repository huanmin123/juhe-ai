# 前端测试分层规则

> 面向 AI 与维护者。本文件是前端测试的强制规则：前端逻辑代码的自动化覆盖、契约打通验证与回归脚本分层以此为唯一依据。后端规则见[后端测试分层规则](后端测试分层规则.md)，操作层面的命令清单见[开发测试与验证说明](测试与验证说明.md)。

## 1. 目标与优先级

1. **前端逻辑代码覆盖率优先**：`src/api`、`src/shared`、`src/composables`、`src/lib`、`src/utils`、`src/config`、`src/directives` 七个逻辑域必须有 vitest 单元测试覆盖。目标语句/行覆盖率 ≥95%（v8 口径），门槛写入 `frontend/vitest.config.ts`；2026-09-16 基线为语句 98.81% / 分支 95.31% / 函数 99.14%（828 用例）。
2. **前后端契约打通其次**：前端 API 调用面必须与 Go gateway 路由注册面对齐，由 `test:api-contract` 静态比对守护。
3. **页面交互不做自动化覆盖要求**：`src/views`、`src/components` 的页面交互不写组件挂载/交互测试；其中的纯逻辑抽到 `composables`/`shared`/`views 内 ts 模块`后按第 1 条覆盖。回归脚本对 views 的验证维持 tsx 源码断言模式，不引入组件渲染测试。

## 2. 测试分层

| 层 | 目的 | 依赖 | 时长预算 | 运行方式 |
| --- | --- | --- | --- | --- |
| 单元测试（vitest） | 逻辑域代码覆盖 | 无真实网络；axios adapter / fetch / 路由 / 存储全部 Mock；happy-dom 环境 | 秒级（全套 <10s） | `pnpm --filter juhe-ai-frontend test:unit`，覆盖率 `test:unit:coverage` |
| API 契约比对 | 前端端点 ⊆ Go 路由注册面（方法+模板参数对齐） | 只读两侧源码静态提取（主 kernel + J3b model-checks 面） | 秒级 | `pnpm --filter juhe-ai-frontend test:api-contract` |
| tsx 回归脚本 | 页面/流程级行为的源码断言回归 | 无真实后端（个别读归档文本或 Go 源码做契约锚定） | 每条 1-5s | `pnpm --filter juhe-ai-frontend test:<主题>`（167 个入口，见 frontend/package.json） |
| 真实后端 smoke | 前端逻辑打到真实 Go gateway | 外部启动的隔离 Go 后端 + 会话 Cookie（环境变量门控） | 分钟级 | `smoke:plan0081-real-go-*`；未设环境变量时快速失败属预期 |

### 2.1 单元测试硬规则

1. **Mock 优先**：axios 用 `http.defaults.adapter` 替换捕获（请求形状断言），fetch 用 `vi.stubGlobal`，定时器用 `vi.useFakeTimers`/`vi.setSystemTime`，环境变量用 `vi.stubEnv`；禁止真实网络请求。
2. **测试文件 co-located**：`src/<域>/<模块>.test.ts`，显式 `import { describe, it, expect, vi } from 'vitest'`，描述用中文；`src/**/*.test.ts` 纳入 `pnpm typecheck`。
3. **测行为不测实现细节**：每个导出的公开函数/方法至少覆盖正常、边界与异常路径；禁止断言空气的凑数用例。
4. **不改业务源码凑绿**：发现疑似缺陷时不修改生产代码，按现状断言并以 `// 行为存疑：<现象>` 注释标注，另行走问题记录（`docs/bug/`）。
5. **不用 Node 专有 API**：测试代码不直接 `import 'node:*'`；需要环境语义时用 vitest 提供的 API。

### 2.2 契约比对规则

1. 提取器从源码解析（前端 `src/api/**` 的 axios/fetch 调用点；Go `internal/**` + `cmd/**` 的 `k.Register` 家族含动态注册表与 J3b `MountScoped` 面），禁止硬编码端点清单导致漂移失真。
2. 前端调用的每个端点必须命中 Go 注册面；差集非空即失败。确认合理的豁免写入 `frontend/scripts/contract/api-contract-allowlist.json` 并注明 reason，禁止为绿灯塞入未定性差异。
3. Go 侧注册而前端未调用的端点仅信息性输出，不失败。

### 2.3 回归脚本规则

1. 入口统一为本地 `tsx --tsconfig tsconfig.json <脚本路径>`（frontend 目录内），不得依赖已归档的 Node 后端（`../backend`、`juhe-ai-backend`）。
2. 脚本为自包含断言脚本（`node:assert/strict`，成功输出一行中文结论，失败非零退出）；断言锚定现役实现（Go 源或前端源），锚点随实现迁移时必须同步改写并保持原契约意图，禁止恒真断言。
3. 两个 IndexedDB 浏览器脚本（`test:chat-local-cache-indexeddb-browser*`）需真实 Chrome，不纳入默认批跑。

## 3. 覆盖率审计规则

1. 口径：`@vitest/coverage-v8`，include 仅逻辑域七目录（见 `frontend/vitest.config.ts`）；`src/types`、`src/views`、`src/components`、`src/scripts` 不纳入统计。
2. 门槛：statements/lines/functions 95、branches 90（低于 2026-09 基线留缓冲）；抬门槛先补测试再改数字。
3. 未达标交付时必须列出未覆盖块清单与原因（防御分支 / 环境不可达 / 待办）。

## 4. 历史注记

- tsx 回归入口在 Node→Go 迁移终局（commit `3f51156e0`）曾因执行器依赖 `../backend` workspace 被整体移除，2026-09-16 恢复为 frontend 本地 `tsx` 依赖；`test:runtime-display-contract` 的目标脚本已随迁移删除，入口不再恢复。
- 单测体系（vitest 3 + happy-dom + coverage-v8）为 2026-09-16 全新建立，Node 归档区（`migration-backup/node/final-archive/`）无可借鉴的前端测试基建；归档区仅作只读契约对照，禁止运行或恢复。
