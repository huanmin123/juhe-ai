# 后端测试分层规则

> 面向 AI 与维护者。本文件是后端测试的唯一分层规范：测试按「功能基线 → 慢基线 → 场景测试 → 性能测试」四条轨道执行，默认只跑功能基线。操作级命令、历史事故与验收细节见[开发测试与验证说明](测试与验证说明.md)；前端规则见[前端测试分层规则](前端测试分层规则.md)。本版于 2026-11-06 按 `test-strategy` 规范重建，取代旧的「日常回归 / 授权外部链路 + 全包 95% 覆盖硬门」执行模型。

## 1. 目标与原则

1. **先保证改动正确，再谈覆盖率**：测试的价值是能钉住可观察行为、失败能定位；不为覆盖率数字写凑数用例。
2. **默认只跑受影响范围**：开发、修复、AI 迭代的默认门禁是 `pnpm test:affected`（按 git 改动选包），不是全量。
3. **外部依赖不进基线**：真实 PostgreSQL / Redis / 上游 / 子进程只在场景测试（需授权）执行；基线必须可在无外部服务的机器上跑通。
4. **测试与生产契约对齐**：测试断言以当前文档契约为准；契约退役（如 hybrid、openai 兼容、SQLite）后，相关测试必须同步删除或改为断言“退役后行为”，不得保留红灯或空转的旧 fixture。
5. **失败即红**：基线失败必须修复或明确登记；禁止用重试、放宽断言或 `t.Skip` 掩盖真实失败。SKIP 不作为验证通过证据。

## 2. 四条轨道

| 轨道 | 目的 | 依赖 | 时间预算 | 默认 | 入口 |
| --- | --- | --- | --- | --- | --- |
| 功能基线（fast） | 纯代码逻辑、分支、边界、契约 | 无外部依赖；test double/httptest/内存桩 | 改动范围 ≤5 分钟；全量 fast ≤15 分钟 | 是 | `pnpm test:affected` / `pnpm test:baseline` |
| 慢基线（slow） | 单包 >10s 的重包（gatewaydispatch、schema、usagewriter 等） | 仍为纯 mock | ≤15 分钟 | 否 | `pnpm test:baseline:slow` |
| 场景测试 | 真实 dev PG/Redis、mock 上游、组合根/子进程 | 真实依赖 | 按 flow | 否，需授权 | `JUHE_AI_TEST_EXTERNAL=1 pnpm test:scenario --flow=...` |
| 性能测试 | 吞吐、并发、延迟、内存 | 专用环境 | 按 SLO | 否 | `go test -bench` / 专项脚本 |

契约测试（前端 API ↔ Go 路由）属于功能基线，由 `pnpm --filter juhe-ai-frontend test:api-contract` 执行。

## 3. 功能基线

### 3.1 按改动选测试（默认）

`pnpm test:affected`（`scripts/test-affected.mjs`）规则：

- 读取工作区 diff 与未跟踪文件（默认对比 `HEAD`，可用 `--base <ref>`）。
- Go 改动：按文件所在目录选包；`-short -count=1 -p 1 -timeout 10m` 串行执行。
- `shared/platform`、`shared/contracts` 改动：除本包外，追加一跳反向依赖（直接 import 该包的项目包）。
- `cmd/**` 变更：不自动跑（组合根/子进程属慢基线/场景），打印 `pnpm test:baseline:slow` 提示。
- 前端改动：跑 `vitest` 单测；`frontend/src/api/**` 改动追加契约比对。
- 文档、脚本、配置变更：不触发测试，输出“未命中”。
- 检测到 `JUHE_AI_TEST_EXTERNAL=1` 时拒绝运行（基线不得连外部依赖）。
- `--dry-run` 只打印选择结果。

### 3.2 基线硬规则

1. **确定性**：禁止真实网络、真实数据库、子进程；时间用注入时钟；不得依赖 `time.Sleep`、轮询等待、墙钟断言或随机值。异步结果用 channel/回调收口。
2. **有意义的断言**：断言状态码、响应体、副作用或错误原文；禁止只调用不断言。
3. **不 mock 被测对象**：mock 只用于外部依赖边界；mock 过度导致“只验证 mock”的用例必须重写。
4. **表驱动 + `t.Run`**；helper 用 `t.Helper()`；资源用 `t.Cleanup` 释放；断言消息用中文。
5. **进程纪律**：一次 `go test` 运行只允许一个测试进程；禁止 `exec.Command` 孵化进程（历史例外清单见 §7）；同一时刻只允许一个 `go test` 进程，统一 `-p 1` 与显式 `-timeout`。
6. **不跑全仓**：禁止 `go test ./...` 跨模块轰炸；跨模块回归分模块串行执行。
7. **失败处理**：发现疑似生产缺陷时，不修改生产代码凑绿；按现状断言并记 `docs/bug/`。测试自身错误（fixture 过期）直接修测试。

### 3.3 全量功能基线

- `pnpm test:baseline`：fast 全量（internal 快包 + 前端 unit + 契约），预算 15 分钟；2026-11-06 本机实测 544.8s（gateway 171.2s / jobs 129.6s / maintenance 58.7s / shared 173.3s / 前端 12.0s），冷缓存需按 15 分钟预算执行。
- `pnpm test:baseline:all`：fast + slow，预算 30 分钟；仅用于发布前、依赖升级、大范围重构收尾。
- 全量基线仍不得连真实 PG/上游；真实依赖走场景测试。
- 已知慢包：gateway `cmd/juhe-ai-gateway` 全量约 691s、jobs `cmd/juhe-ai-jobs` 约 115s、`internal/schema` 约 115s。cmd/acceptance 不进入默认基线。

## 4. 场景测试

- 唯一授权开关：`JUHE_AI_TEST_EXTERNAL=1`；未授权时相关测试 `t.Skip`，**SKIP 不作验证通过证据**。
- 入口：`JUHE_AI_TEST_EXTERNAL=1 pnpm test:scenario --flow=pg|acceptance|frontend-smoke`。
  - `pg`：自动发现含 `pgtestkit` 的测试包，在每测试独立库上执行，结束自动删库。
  - `acceptance`：gateway acceptance（`JUHE_AI_E2E_FULLCHAIN=1`）；真实上游场景另需 `JUHE_AI_E2E_REAL=1` 与 secret。
  - `frontend-smoke`：前端打真实 Go 后端（需 `JUHE_REAL_GO_MANAGEMENT_BASE_URL`/`COOKIE`，脚本级门控）。
- 隔离：场景测试使用 dev 环境或专用隔离库/命名空间，自建自清；禁止连生产、禁止共享可变测试数据；清理失败必须显式报错。
- 场景失败必须按真实失败处理；禁止用重试掩盖 flaky。flaky 用例隔离并记录原因。

## 5. 性能测试

- 触发条件：有明确 SLO/性能目标，或 profile/复杂度分析证明改动影响热点；仅“缓存/序列化/启动”等关键词不构成理由。
- 报告 p50/p95/p99、吞吐、错误率、CPU/内存/GC，不只报平均值；同 commit、同环境、同数据重复测量。
- 不在共享开发机做硬失败门禁；共享 runner 只记录趋势。性能产物按 `docs/reports/README.md` 归档。

## 6. 覆盖率与质量审计（独立于基线）

1. **95% 语句覆盖率仍是项目审计目标**（`go test -cover` / `go tool cover -func`），但不是每次基线的门禁；审计按发布/阶段执行，入口与命令见[测试与验证说明](测试与验证说明.md)。
2. **变更代码优先**：新增/修改代码必须有对应覆盖；改动包的覆盖率不得因本次改动下降。
3. **覆盖率墙处置阶梯**（顺序不可跳步）：设计重构（抽 `run()`、依赖注入、可测函数）→ fixture 注入（pgtestkit/miniredis/假 listener/坏 DSN）→ 删除确凿死臂（留证据注释）→ 经用户确认后登记残余上限。不得把“不好测”直接当豁免。
4. **跨层传导契约**：对“A 层生成 → B 层消费”的关键值（timeout profile、预算实例、客户端策略视图等），必须有来源断言或端到端组合矩阵，不能只靠语句覆盖。
5. **测试质量抽查**：定期抽查是否存在空气断言、过度 mock、只测实现细节、fixture 与实际契约脱节；发现即修。

## 7. 项目特有硬规则

1. **组合根接线守卫**：凡注释声称 composition-root handover 的端口，必须同时有真实装配调用、cmd 装配测试的非 nil 断言、端口定义三件套；单测注入假端口全绿不算接线完成。
2. **种子/配置不变量**：provider 默认模型 ⊆ 模型目录种子、设置键默认值与运行时回退常量一致；改种子必须同批更新守护测试。
3. **测试库复刻生产池配置**：pgtestkit 上复刻与行为相关的连接池上限、事务/语句超时；不得各用例裸写 DSN。
4. **子进程隔离守卫**：`node scripts/test-process-isolation-regression.mjs` 扫描全部 `*_test.go`；任何非例外文件命中子进程模式即失败。例外清单只减不增，新增模仿一律拒绝。
5. **前端契约**：`frontend/src/api` 调用面必须命中 Go `k.Register` 注册面；差集非空即失败；豁免写入 allowlist 并注明 reason。
6. **Windows/资源**：全量 `go test` 单进程、`-p 1`；Windows 下测试脚本默认补 `GOGC=20`、`GOMAXPROCS=1`（`scripts/lib/test-process-env.mjs`），规避提交内存不足导致的 `VirtualAlloc failed` 编译失败（2026-11-06 实测 12 包 build failed，同批包降参数后全部通过）。调用方显式设置这两个变量时以调用方为准；内存不足时先减少并发与范围，不用重试掩盖编译 OOM。

## 8. 命令速查

| 场景 | 命令 | 说明 |
| --- | --- | --- |
| 改完代码，默认 | `pnpm test:affected` | 按 git 改动选包，≤5 分钟目标 |
| 改完代码，先看选什么 | `pnpm test:affected -- --dry-run` | 只打印选择 |
| 全量功能基线 | `pnpm test:baseline` | fast，15 分钟预算 |
| 慢包基线 | `pnpm test:baseline:slow` | gatewaydispatch/schema 等 |
| fast + slow | `pnpm test:baseline:all` | 发布前/大重构 |
| 真实 PG 场景 | `JUHE_AI_TEST_EXTERNAL=1 pnpm test:scenario -- --flow=pg` | 需 dev PG 可达 |
| 组合根/子进程验收 | `JUHE_AI_TEST_EXTERNAL=1 pnpm test:scenario -- --flow=acceptance` | mock 上游 |
| 兼容旧入口 | `pnpm test:daily` | 等价于 `test:baseline` |
| 前端单测 | `pnpm --filter juhe-ai-frontend test:unit` | 全量 <10s |
| 前后端契约 | `pnpm --filter juhe-ai-frontend test:api-contract` | 静态比对 |
| 进程隔离守卫 | `node scripts/test-process-isolation-regression.mjs` | 修改测试后跑 |

## 9. 证据格式

每次测试交付至少记录：

```
命令：<完整命令>
退出码：<0 / 非 0>
结果：pass / fail / skip（数量）
耗时：<秒>
环境：<机器 / commit / workers / 是否 warm 缓存>
未运行：<全量 / 慢基线 / 场景 / 性能及原因>
```

“测试通过”没有命令和输出不算证据；只跑子集时不得表述为全量通过。

## 10. 维护与例外

- 新增测试默认进 fast 基线；单包 warm `-short` >10s 时登记到 `scripts/test-daily-regression.mjs` 的 slow include 清单，并在本文 §3.3 更新。
- 授权链路/场景 flow 新增时，在 `scripts/test-scenario.mjs` 增加 flow 并更新本文 §8。
- 任何测试例外（子进程、真实网络、跳过）必须写明原因、归属与复查条件；无期限例外不允许。
