# 开发测试与验证说明

> 面向 AI 与维护者。
> 本文件承接代码级检查、接口验证、网关联通、账号测试和自动烟测；启动方式和运行注意事项见 [开发运行说明](运行说明.md)。

## 1. 适用场景

- 需要确认代码改动没有破坏类型、构建或关键路径。
- 需要验证后端接口、管理面页面、账号测试、网关转发或使用记录。
- 需要执行自动烟测、回归验证或问题修复后的复现检查。

## 2. 代码级验证

在项目根目录执行：

```powershell
pnpm typecheck
pnpm build
```

如果只改了某一端，也可以先跑对应 workspace 的命令，再按需要补全全量验证。

## 3. 后端接口快速检查

项目已启动后，可用以下命令确认管理面接口可访问：

```powershell
curl.exe http://127.0.0.1:3000/api/health
curl.exe http://127.0.0.1:3000/api/providers
curl.exe http://127.0.0.1:3000/api/accounts
curl.exe http://127.0.0.1:3000/api/groups
curl.exe http://127.0.0.1:3000/api/api-keys
curl.exe http://127.0.0.1:3000/api/proxies
curl.exe http://127.0.0.1:3000/api/settings
```

## 4. 本地网关验证

客户端接入时使用 OpenAI 兼容协议：

- Base URL：`http://127.0.0.1:3000/v1`
- API Key：API 密钥页生成的本地网关密钥
- 常用路径：`/models`、`/responses`、`/chat/completions`

`$LiteKey` 使用 API Key 页面新建后返回的明文密钥，或同步脚本首次输出的 `sync.apiKey`。

本机 `backend/data/juhe-ai.sqlite3`（或 `JUHE_AI_DATABASE_PATH` 指向的数据库）可能已经保存真实 OpenAI 账户、本地网关 API Key 和分组绑定。需要真实联通验证或烟测时，可以优先复用本地数据库里的数据，不必重复创建；但不要把真实密钥写入文档、提交记录、Issue、截图或聊天内容，只在本机命令会话里临时赋值。

如果后端已经启动，可以从管理面接口取第一个启用且可展示明文的本地网关 API Key：

```powershell
$LiteKey = ((Invoke-RestMethod http://127.0.0.1:3000/api/api-keys).data |
  Where-Object { $_.status -eq "active" -and $_.key } |
  Select-Object -First 1).key

if (-not $LiteKey) {
  throw "未找到可用的本地网关 API Key，请确认本地数据库或先在 API Key 页面创建"
}
```

真实上游账户只用于本地联通验证；优先通过账户测试接口、网关请求或 `pnpm test:smoke` 验证可用性，不要直接导出或打印上游账户凭据。账户测试和后台复测必须走本地 OpenAI 网关处理链路，不能在测试服务里单独直连上游；测试产生的请求、token、成本、错误和账号命中记录应和客户请求一样进入使用记录与统计聚合，未产生 token / cost 的失败按 0 token、0 cost 计入请求和错误次数。

```powershell
$LiteKey = "你的本地网关 API Key"

Invoke-RestMethod http://127.0.0.1:3000/v1/models `
  -Headers @{ Authorization = "Bearer $LiteKey" }

$payload = @{
  model = "gpt-5.4-mini"
  input = "只输出 OK"
  max_output_tokens = 16
  stream = $false
} | ConvertTo-Json -Compress

Invoke-RestMethod -Method Post `
  -Uri "http://127.0.0.1:3000/v1/responses" `
  -Headers @{ Authorization = "Bearer $LiteKey" } `
  -ContentType "application/json" `
  -Body $payload
```

流式响应可用 `curl.exe -N` 检查：

```powershell
$streamBody = '{"model":"gpt-5.4-mini","input":"只输出 OK","max_output_tokens":16,"stream":true}'
$bodyFile = New-TemporaryFile
Set-Content -LiteralPath $bodyFile -Value $streamBody -NoNewline -Encoding utf8

curl.exe -sS -N -X POST "http://127.0.0.1:3000/v1/responses" `
  -H "Authorization: Bearer $LiteKey" `
  -H "Content-Type: application/json" `
  --data-binary "@$bodyFile" `
  --max-time 60
```

检查点：`/v1/models` 返回模型列表；非流式 `/v1/responses` 返回完成状态；流式响应能看到完成事件；使用记录能看到 endpoint、token 和成本字段。

发布前真实链路验证不要复用随手抓取的旧 Key；优先由 `pnpm test:smoke` 创建临时分组和临时本地 API Key，完成 `/v1` 请求后自动清理，避免误判账户、分组、API Key 和用量链路。

## 5. OpenAI OAuth 账户验证

前端路径：

```text
http://127.0.0.1:5173/accounts
```

点击 `OpenAI 账户授权`，可选两种方式：

- `手动授权`：生成授权链接，登录完成后复制浏览器地址栏里的 `http://localhost:1455/auth/callback?code=...&state=...` 回调 URL，粘贴回弹窗创建账户。
- `Refresh Token`：直接粘贴已有 OpenAI `refresh_token`，后端刷新成功后创建 OAuth 账户。

后端授权链接接口可用以下命令做冒烟检查：

```powershell
Invoke-RestMethod -Method Post `
  -Uri "http://127.0.0.1:3000/api/openai-oauth/auth-url" `
  -ContentType "application/json" `
  -Body "{}"
```

OAuth token 交换、刷新、账户测试、后台冷却复测和 OAuth 额度快照探测会使用账户绑定代理；网关真实转发也会使用账号绑定代理。OAuth token 交换属于授权协议请求，不计入模型使用统计；账户测试、后台冷却复测和 OAuth 额度快照探测会通过同一套网关模型请求链路计入使用记录。

## 6. 账户与管理面验证

账户列表“更多”菜单里的“测试”会调用后端 `POST /api/accounts/:id/test`，内部构造一次本地 `/v1/responses` 请求并复用正常 OpenAI 网关链路验证账户是否可用；OAuth 账户会在网关准备上游账号时按正常请求规则刷新 token。测试只允许命中当前被测账户，不会静默切到同分组其他账号。

```powershell
$account = (Invoke-RestMethod http://127.0.0.1:3000/api/accounts).data |
  Where-Object { $_.providerCode -eq "openai" -and $_.status -eq "active" } |
  Select-Object -First 1

Invoke-RestMethod -Method Post "http://127.0.0.1:3000/api/accounts/$($account.id)/test"
```

管理面重点检查：

- 账户列表只显示名称、类型、供应商、并发、状态、用量、优先级、最近使用时间和操作。
- `Access/API Key` 与 `Refresh Token` 不在列表展示，只在编辑弹窗展示和修改。
- API Key 页面直接展示完整本地网关密钥，方便复制。
- OAuth 账户如需代理，可在账户编辑弹窗中绑定代理配置；代理不可用时刷新 token 和测试会失败。

## 7. 自动烟测

项目启动后执行：

```powershell
pnpm test:smoke
```

默认会走真实管理流程：先用烟测管理员账号登录，再选择一个启用且可用的 OpenAI 账户，按该账户所属系统账户创建临时分组，临时绑定账户，创建临时本地 API Key，然后用这个 Key 请求 `/v1/models` 和 `/v1/responses`，最后删除临时 Key、恢复账户原分组并删除临时分组。OAuth 账户会使用 Codex 兼容流式请求体，校验代理链路、流式完成事件和使用记录 token/cost 入库。

Codex 或其他 OpenAI 兼容客户端接入本地网关时，Base URL 填 `http://localhost:3000/v1` 或 `http://127.0.0.1:3000/v1` 都可以；API Key 只填 API Key 页面展示的 `sk-...` 明文，不要带 `Bearer ` 前缀，也不要填写上游 OpenAI / 中转供应商的账号密钥。客户端会自动发送 `Authorization: Bearer <API Key>`，如果填错 Key 会返回 `Invalid API key`，如果没有 Bearer 头会返回 `Missing bearer token`。

网关会缓存已通过校验的本地 API Key，重复请求会刷新短 TTL，减少高频调用对 SQLite 的鉴权查询压力；禁用、删除或修改 API Key 会立即清理对应缓存，缓存最长 5 分钟必须重新查库。

需要固定测试账号或模型时编辑 `backend/.env`：

```dotenv
# 只影响 pnpm test:smoke，不影响正常启动和网关转发。
JUHE_AI_BACKEND_URL=http://127.0.0.1:3000
JUHE_AI_SMOKE_ADMIN_USERNAME=admin
JUHE_AI_SMOKE_ADMIN_PASSWORD=admin
JUHE_AI_SMOKE_ACCOUNT_NAME=
JUHE_AI_SMOKE_MODEL=gpt-5.4-mini
JUHE_AI_SMOKE_PROMPT=只输出 OK
```

`JUHE_AI_SMOKE_ACCOUNT_NAME` 留空时自动选第一个启用并且可用的 OpenAI 账号；填写后必须和账户页里的账号名称完全一致。

## 8. 发布前固定验证清单

准备发布前，在项目根目录按顺序执行：

```powershell
pnpm typecheck
pnpm build
pnpm test:scope
pnpm test:proxy-negative
pnpm test:smoke
```

检查边界：

- `pnpm test:scope` 只验证普通用户、管理员用户侧和管理员管理侧接口边界；它使用临时库和脚本种子数据，不等同于真实 OpenAI 网关 smoke。
- `pnpm test:proxy-negative` 验证停用代理、网关 503、失败使用记录和使用中代理不可删除等负向场景；它使用临时库和假上游，不替代真实 OpenAI + 代理链路。
- `pnpm test:smoke` 必须走正规产品流程：登录 -> 管理 API/UI -> 临时分组 -> 绑定账户 -> 本地 API Key -> `/v1` 网关请求 -> 使用记录 / 审计运行态 -> 清理。
- 发布前如本次版本触及团队、授权、分组、API Key 或网关调度，需额外抽查一次多用户团队授权闭环：管理员建临时团队并添加成员 -> 资源所有者把临时账户或分组授权给团队 -> 团队成员绑定到自己的分组或 API Key -> 用本地 API Key 请求 `/v1` -> 在使用记录 / 授权用量 / 审计日志确认调用方、资源所有者和授权 ID -> 收回授权或移除成员后再次请求应被拒绝 -> 清理临时团队、授权、分组和 API Key。
- 发布前仍需人工抽查一次管理面使用记录详情和审计日志检索，确认 smoke 产生的 trace 可用于排障；不要把真实 token、API Key 或上游错误敏感内容写入文档或截图。

## 9. 设置与流熔断验证

系统设置接口不应再返回 `defaultErrorPolicyId`，并应包含临时不可调用和流熔断字段：

```powershell
$settings = Invoke-RestMethod http://127.0.0.1:3000/api/settings
$settings.data.PSObject.Properties.Name -contains 'defaultErrorPolicyId'
$settings.data.defaultTemporaryUnschedulableMinutes
$settings.data.temporaryUnschedulableRetryIntervalSeconds
$settings.data.temporaryUnschedulableRetryAttempts
$settings.data.streamCircuitBreakerEnabled
$settings.data.streamRequestTimeoutSeconds
```

检查点：系统设置页能保存并回显；流式异常达到阈值后账号列表会显示临时不可调用或错误摘要；临时不可调用与限流状态只能通过手动测试成功或冷却到期后的后台复测成功恢复，复测失败会继续保持临时不可调用，不应被“启用账户”按钮手动清掉。
