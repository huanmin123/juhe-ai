# 开发测试与验证说明

> 面向 AI 与维护者。
> 本文件承接代码级检查、接口验证、网关联通、账号测试和自动烟测；启动方式和运行注意事项见 [开发运行说明](运行说明.md)。

## 1. 适用场景

- 需要确认代码改动没有破坏类型、构建或关键路径。
- 需要验证后端接口、管理面页面、账号测试、网关转发或使用记录。
- 需要执行自动烟测、回归验证或问题修复后的复现检查。

## 2. 代码级验证

在项目根目录执行：

```powershell
pnpm typecheck
pnpm build
```

如果只改了某一端，也可以先跑对应 workspace 的命令，再按需要补全全量验证。

## 3. 后端接口快速检查

项目已启动后，可先用以下免登录接口确认服务和公开配置可访问：

```powershell
curl.exe http://127.0.0.1:3000/__aisys__/health
curl.exe http://127.0.0.1:3000/__aisys__/api/health
curl.exe http://127.0.0.1:3000/__aisys__/api/settings/public
```

账户、分组、API Key、代理和系统设置等管理接口需要登录会话 Cookie。手工检查时可以先在前端登录，再从浏览器请求里复制 `juhe_ai_session=...` 到当前 PowerShell 会话；不想手工处理 Cookie 时，优先使用前端页面或 `pnpm test:smoke` 验证关键链路。

```powershell
$AdminCookie = "juhe_ai_session=..."

curl.exe http://127.0.0.1:3000/__aisys__/api/providers -H "Cookie: $AdminCookie"
curl.exe http://127.0.0.1:3000/__aisys__/api/accounts -H "Cookie: $AdminCookie"
curl.exe http://127.0.0.1:3000/__aisys__/api/groups -H "Cookie: $AdminCookie"
curl.exe http://127.0.0.1:3000/__aisys__/api/api-keys -H "Cookie: $AdminCookie"
curl.exe http://127.0.0.1:3000/__aisys__/api/proxies -H "Cookie: $AdminCookie"
curl.exe http://127.0.0.1:3000/__aisys__/api/settings -H "Cookie: $AdminCookie"
```

## 4. 本地网关验证

客户端接入时使用 OpenAI 兼容协议：

- Base URL：`http://127.0.0.1:3000` 或 `http://127.0.0.1:3000/v1`
- API Key：`API Key 管理` 或 `我的 API Key` 页面生成的本地网关密钥
- 通用入口：`/models`、`/responses`；`/chat/completions` 只在当前 API Key 绑定分组能选到 OpenAI API Key / OpenAI-compatible 上游账号时验证。
- OAuth / Codex 边界：GPT OAuth 账号只覆盖 `POST /responses` 和 `POST /responses/compact`（含 `/v1` 前缀），不会把 `/chat/completions` 自动翻译到 Responses。

`$LiteKey` 使用 API Key 页面新建后返回的明文密钥，或同步脚本首次输出的 `sync.apiKey`。

本机 `backend/data/juhe-ai.sqlite3`（或 `JUHE_AI_DATABASE_PATH` 指向的业务库）可能已经保存真实 GPT 账户、本地网关 API Key 和分组绑定；`JUHE_AI_DATASET_DATABASE_PATH` 指向的数据集目录库保存审计、日志索引、操作日志、模型检测事实和 usage shard 元数据，`JUHE_AI_USAGE_SHARD_ROOT` 指向的目录保存新写入的使用记录，`JUHE_AI_STATS_DATABASE_PATH` 指向的统计结果库保存统计缓存、额度窗口和监控历史。三个 SQLite 文件路径必须互不相同，usage shard 根目录也必须与这些文件路径区分。需要真实联通验证或烟测时，可以优先复用本地业务库里的数据，不必重复创建；但不要把真实密钥写入文档、提交记录、Issue、截图或聊天内容，只在本机命令会话里临时赋值。

本地网关 API Key 的列表和更新响应只返回前缀、掩码或空 key，不从管理面列表接口批量取回完整密钥；新建成功响应、页面弹窗和单条复制接口可按资源权限返回完整密钥。需要手工验证时，使用刚创建后保存到当前 PowerShell 会话的 `$LiteKey`、在 API Key 列表复制完整密钥，或使用 `pnpm test:smoke` 自动创建并清理临时本地网关 API Key：

```powershell
if (-not $LiteKey) {
  throw "请先在 API Key 页面新建密钥并把一次性明文保存到当前 PowerShell 会话，或改用 pnpm test:smoke 自动创建临时密钥"
}
```

真实上游账户只用于本地联通验证；优先通过账户测试接口、网关请求或 `pnpm test:smoke` 验证可用性，不要直接导出或打印上游账户凭据。账户测试和后台复测必须走本地 OpenAI 网关处理链路，不能在测试服务里单独直连上游；测试产生的请求、token、成本、错误和账号命中记录应和客户请求一样进入使用记录与统计聚合，未产生 token / cost 的失败按 0 token、0 cost 计入请求和错误次数。

```powershell
$LiteKey = "你的本地网关 API Key"

Invoke-RestMethod http://127.0.0.1:3000/v1/models `
  -Headers @{ Authorization = "Bearer $LiteKey" }

$payload = @{
  model = "gpt-5.4-mini"
  input = "只输出 OK"
  max_output_tokens = 16
  stream = $false
} | ConvertTo-Json -Compress

Invoke-RestMethod -Method Post `
  -Uri "http://127.0.0.1:3000/v1/responses" `
  -Headers @{ Authorization = "Bearer $LiteKey" } `
  -ContentType "application/json" `
  -Body $payload
```

流式响应可用 `curl.exe -N` 检查：

```powershell
$streamBody = '{"model":"gpt-5.4-mini","input":"只输出 OK","max_output_tokens":16,"stream":true}'
$bodyFile = New-TemporaryFile
Set-Content -LiteralPath $bodyFile -Value $streamBody -NoNewline -Encoding utf8

curl.exe -sS -N -X POST "http://127.0.0.1:3000/v1/responses" `
  -H "Authorization: Bearer $LiteKey" `
  -H "Content-Type: application/json" `
  --data-binary "@$bodyFile" `
  --max-time 60
```

检查点：`/v1/models` 返回模型列表；非流式 `/v1/responses` 返回完成状态；流式响应能看到完成事件；使用记录能看到 endpoint、token 和成本字段。如果额外验证 `/v1/chat/completions`，确认本地 API Key 绑定分组内有 API Key 类型或其他 OpenAI-compatible 透传账号可调度。

发布前真实链路验证不要复用随手抓取的旧 Key；优先由 `pnpm test:smoke` 在目标账户当前绑定分组上创建临时本地 API Key，完成 `/v1` 请求后自动清理，避免误判账户、分组、API Key 和用量链路。

如果本地没有真实账户，`pnpm test:smoke` 会自动启动本机 mock OpenAI 上游，并通过 Mockdata 共享夹具生成临时 GPT API Key 类型账号、临时 GPT 分组和临时本地 API Key，再按同一套正规网关流程完成 `/v1/models`、`/v1/responses` 和使用记录校验，结束后清理临时数据。该 fallback 覆盖的是 API Key / mock OpenAI-compatible 透传路径，不代表 OAuth Codex adapter 支持 `/chat/completions`；它不消耗真实 OpenAI 额度，也不污染真实账号。如果设置了 `JUHE_AI_SMOKE_ACCOUNT_NAME`，脚本会严格测试指定账号，不自动 fallback。通用造数职责见 [Mockdata 造数设计](../functions/Mockdata造数设计.md)。

需要额外覆盖 Codex turn 切号策略时，运行 mock smoke：

```powershell
pnpm test:smoke:mock
```

该命令会启动临时 SQLite 业务库、统计数据集目录库、usage shard 目录和统计结果库、本机 mock OpenAI 上游和临时网关实例，自动创建 GPT 分组、两个 GPT API Key 类型假账号和本地网关 API Key，覆盖 Codex turn 前 3 次失败、第 4 次切到备用账号、非 Codex 不切号，以及 Codex profile 下 `context_length_exceeded`、`cyber_policy` 等当前策略边界。它不消耗真实 OpenAI 额度，也不污染 `backend/data/`。

## 5. GPT OAuth 账户验证

前端路径：

```text
http://127.0.0.1:5173/__aisys__/accounts
```

新增 GPT OAuth 账户时，可选两种 OpenAI OAuth 授权方式：

- `手动授权`：生成授权链接，登录完成后复制浏览器地址栏里的 `http://localhost:1455/auth/callback?code=...&state=...` 回调 URL，粘贴回弹窗创建账户。
- `Refresh Token`：直接粘贴已有 OpenAI `refresh_token`，后端刷新成功后创建 OAuth 账户。

已有 GPT OAuth 账户在账户列表“更多”菜单中提供两个排障入口：

- `刷新令牌`：强制使用当前账户保存的 Refresh Token 换取一次 Access Token；成功后账户会刷新凭据，限流中、临时不可调用等软失败状态会恢复可调度，停用和异常不会被这个入口恢复。异常账户前端隐藏刷新入口，后端也会拒绝直接刷新，需要先走“恢复异常”或通过编辑修正凭据。失败会直接显示 OAuth 或代理错误。如果遇到 OpenAI 返回 `refresh_token_reused` 或 “Refresh Token 已被使用”一类提示，但账户仍能继续调用，通常表示另一个请求或后台任务已经先完成刷新并写入了新凭据；后端会在锁内重读账户并优先采用最新凭据。
- `重新授权`：打开独立弹窗复用新增账户的授权流程，可通过授权回调 URL 或新的 Refresh Token 覆盖当前账户 OAuth 凭据；名称、分组、代理和并发不随重新授权修改。异常账户前端隐藏重新授权入口，后端也会拒绝直接重新授权。

后端授权链接接口可用以下命令做冒烟检查：

```powershell
$AdminCookie = "juhe_ai_session=..."

Invoke-RestMethod -Method Post `
  -Uri "http://127.0.0.1:3000/__aisys__/api/openai-oauth/auth-url" `
  -Headers @{ Cookie = $AdminCookie } `
  -ContentType "application/json" `
  -Body "{}"
```

OAuth token 交换、刷新、重新授权和账户测试会使用账户绑定代理；网关真实转发也会使用账号绑定代理。OAuth token 交换、刷新和重新授权属于授权协议请求，不计入模型使用统计；账户测试会通过同一套网关模型请求链路计入使用记录。后台 Access Token 预刷新只做授权保活，会扫描所有仍存在、未删除、有 `refresh_token` 且快过期的 GPT OAuth 账户，不因停用、异常、限流或临时不可调用状态跳过；预刷新成功只写回凭据，不自动恢复普通账户状态；连续 3 次预刷新失败会把账户标记为 `status = error`，异常类型为 `oauth_token_refresh_failed`，后续后台刷新成功只自动恢复这一类刷新异常。真实网关请求只在 Access Token 缺失、过期、过期时间无效或距离过期不超过 5 秒时阻塞刷新；距离过期小于 60 秒但仍超过 5 秒时只触发账号级后台预热并继续当前请求。后台冷却复测固定启用，但只会复测冷却时间到期的 `temporary_unavailable` 和 `rate_limited` 账号；临时状态下的 `cooldown_until` 表示下次后台复测计划时间，不作为账户套餐到期时间展示。账号质量主动探测能力已删除。OAuth 额度快照不再主动探测，只从真实网关请求或账户测试响应头被动更新。

## 6. 账户与管理面验证

账户列表“更多”菜单里的“测试”会调用后端 `POST /__aisys__/api/accounts/:id/test`；用户侧 `我的 AI 账户` 调用 `POST /__aisys__/api/my-accounts/:id/test`，固定使用当前登录用户作用域。创建 / 编辑账户弹窗底部的“测试”复用同一个测试弹窗；新增自有账户会把当前表单生成加密草稿任务并调用 `POST /__aisys__/api/accounts/test-draft` 或 `POST /__aisys__/api/my-accounts/test-draft`，测试成功后保存可直接创建为正常状态；编辑已保存自有账户会把当前表单快照随 `POST /__aisys__/api/accounts/:id/test` 或 `POST /__aisys__/api/my-accounts/:id/test` 提交，测试请求使用未保存输入，测试结果立即影响该已保存账户状态，但配置字段修改仍需保存；授权账户仍按已保存账户测试。管理员在管理侧可通过 `systemAccountId` 代某个用户作用域测试其可见账户。测试内部构造一次本地 `/v1/responses` 请求并复用正常 OpenAI 网关链路验证账户是否可用；API Key 账户会优先参考最近真实请求形态，测试模型按“显式传入、最近真实请求、账户支持模型、默认模型”顺序选择，避免固定测试模型和真实可用模型不一致；API Key 账户的 Responses 测试按当前契约不发送 `max_output_tokens`；OAuth 账户会在网关准备上游账号时按正常请求规则刷新 token，并固定使用 Codex Responses 测试路径。账户测试和后台复测结果携带本地 `traceId`，上游错误文本中的 `request id` 必须保留；排障时本地链路用 `traceId` 查询运行日志、使用记录和审计日志，上游链路用 `request id` 查询供应商日志。管理后台测试弹窗可选择模型；客户端兼容临时选择只适用于 API Key 账户，默认跟随账户配置且不会写回账户，OAuth 账户固定显示 Codex Responses。测试输入由后端使用默认探活输入生成。测试只允许命中当前被测账户，不会静默切到同分组其他账号。账户测试、模型检测和代理检测共享 DB service 诊断任务 in-flight 上限；超过上限会快速返回 `503` 和 `Retry-After`，不会在 DB service 事件循环内排队等待外部探测。账户测试和模型检测展示用响应体只保留 `256KB` 有界预览，异常大响应会标记 `responseTruncated` 并追加截断提示，避免管理接口因为上游异常响应占用过多内存或同步解析大文本。自有账户包含停用和异常状态都可以手动测试；停用账户测试只做诊断，不会恢复或改写停用状态；非停用自有账户测试成功会清理待测试、临时不可调用、限流、异常、不可调度和最近错误状态并恢复正常调度。人工测试失败若确认是被测账号不可用，且不是绑定、凭据读取、取消等配置或操作问题，只会把当前仍为正常状态且可调度的自有账号标记为 `temporary_unavailable` 并写入冷却时间；用户侧授权账户同样只处理当前正常且可调度的本地绑定状态，不修改所有者物理账户。授权账户测试额外要求已绑定到当前用户分组、授权仍有效、额度未耗尽、账户未到期；授权用户只看到脱敏后的测试结果，完整上游响应头、响应体、上游地址、代理、请求体和无状态码内部异常文本等诊断字段仅所有者或管理员可见。显式异常账户也可以通过“恢复异常”清理 `last_error_code`、`last_error_message` 和冷却字段后恢复调度。

```powershell
$AdminCookie = "juhe_ai_session=..."

$account = (Invoke-RestMethod http://127.0.0.1:3000/__aisys__/api/accounts -Headers @{ Cookie = $AdminCookie }).data |
  Where-Object { $_.providerCode -eq "gpt" -and $_.status -eq "active" } |
  Select-Object -First 1

Invoke-RestMethod -Method Post `
  -Uri "http://127.0.0.1:3000/__aisys__/api/accounts/$($account.id)/test" `
  -Headers @{ Cookie = $AdminCookie }
```

管理面重点检查：

- 账户列表只显示名称、类型、供应商、并发、状态、用量、优先级、最近使用时间和操作。
- `Access/API Key` 与 `Refresh Token` 不在列表展示，只在编辑弹窗展示和修改。
- API Key 页面只在新建成功弹窗中一次性展示完整本地网关密钥；列表、详情和后续更新只能看到前缀、掩码或空 key。
- OAuth 账户如需代理，可在账户编辑弹窗中绑定代理配置；代理不可用时刷新 token 和测试会失败。

## 7. 性能综合测试

需要评估本机模拟链路的 QPS、延迟、错误率和资源占用时，可以运行：

```powershell
pnpm test:perf
```

该命令会启动临时 SQLite 业务库、统计数据集目录库、usage shard 目录和统计结果库、本机模拟 OpenAI 上游和临时网关实例，并通过 Mockdata 共享夹具自动创建压测 GPT 分组、GPT API Key 类型账户和本地网关 API Key；测试结束后删除临时数据目录，不消耗真实 OpenAI 额度，也不污染 `backend/data/`。

默认覆盖 `/v1/models`、非流式 `/v1/responses` 和 `/v1/chat/completions` 三类 API Key / mock OpenAI-compatible 场景，按多个并发档位输出：

- `QPS` / `成功QPS`：总吞吐和成功请求吞吐。
- `错误率` / `statusCounts` / `errorCounts`：失败比例、HTTP 状态码和错误分类。
- `latencyMs`：`min`、`avg`、`p50`、`p90`、`p95`、`p99`、`max`。
- `eventLoopDelayMs`：事件循环延迟均值和分位，用于观察 Node 主线程压力。
- `cpu` / `memory`：本进程 CPU 时间、单请求 CPU 均值和内存变化。
- `usageRecordsDelta` / `auditLogsDelta`：本次压测写入临时 usage shard 的使用记录数量，以及写入临时统计数据集目录库的审计日志数量。
- `usageRecordQueueLength` / `auditLogQueueLength`：结束时队列是否清空。

常用调参示例：

```powershell
$env:JUHE_AI_PERF_SCENARIOS = "models,responses,chat,responses_stream"
$env:JUHE_AI_PERF_CONCURRENCY = "25,50,100"
$env:JUHE_AI_PERF_DURATION_SECONDS = "15"
$env:JUHE_AI_PERF_WARMUP_SECONDS = "3"
$env:JUHE_AI_PERF_UPSTREAM_LATENCY_MS = "20"
$env:JUHE_AI_PERF_UPSTREAM_BODY_BYTES = "1024"
$env:JUHE_AI_PERF_REPORT_PATH = "perf-report.json"
pnpm test:perf
```

`JUHE_AI_PERF_REPORT_PATH` 的相对路径按发起 `pnpm` 命令的目录解析，父目录会自动创建。例如在仓库根目录设置为 `reports/perf-limit-report-2026-05-17.json` 时，报告会写入 `F:\sub2api-lite\reports\perf-limit-report-2026-05-17.json`。

可用环境变量：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `JUHE_AI_PERF_SCENARIOS` | `models,responses,chat` | 逗号分隔场景；可选 `models`、`responses`、`chat`、`responses_stream`，其中 `chat` 对应 API Key / mock OpenAI-compatible 的 `/v1/chat/completions` |
| `JUHE_AI_PERF_CONCURRENCY` | `10,25,50` | 逗号分隔并发档位 |
| `JUHE_AI_PERF_DURATION_SECONDS` | `6` | 每个并发档位正式压测秒数 |
| `JUHE_AI_PERF_WARMUP_SECONDS` | `1` | 每个档位预热秒数，不计入结果 |
| `JUHE_AI_PERF_REQUEST_TIMEOUT_MS` | `5000` | 客户端请求超时 |
| `JUHE_AI_PERF_UPSTREAM_LATENCY_MS` | `20` | 模拟上游首响应延迟 |
| `JUHE_AI_PERF_UPSTREAM_BODY_BYTES` | `512` | 模拟上游响应正文规模 |
| `JUHE_AI_PERF_UPSTREAM_ERROR_RATE` | `0` | 模拟上游错误率，范围 `0` 到 `1` |
| `JUHE_AI_PERF_ACCOUNT_COUNT` | `8` | 临时上游账户数量 |

## 8. 自动烟测

项目启动后执行：

```powershell
pnpm test:smoke
```

默认会走真实管理流程：先在脚本进程校验烟测管理员凭据并写入同库短时会话，再选择一个启用且可用的 GPT 账户，在该账户当前绑定分组上创建临时本地 API Key，然后用这个 Key 请求 `/v1/models` 和 `/v1/responses`，最后删除临时 Key。脚本不会解析登录验证码图片，也不会为真实账号临时改绑分组，避免破坏账号已有分组绑定；HTTP 登录、验证码图片和初始改密边界由 `pnpm --filter juhe-ai-backend test:auth-must-change-password-boundary` 覆盖，验证码生成限频由 `pnpm --filter juhe-ai-backend test:captcha-rate-limit` 覆盖。只有本地无可用真实账户且未指定 `JUHE_AI_SMOKE_ACCOUNT_NAME` 时，才会自动创建临时 mock 账号和临时分组，并在结束后清理。OAuth 账户会使用 Codex 兼容流式 `/v1/responses` 请求体，校验代理链路、流式完成事件和使用记录 token/cost 入库；OAuth smoke 不覆盖 `/v1/chat/completions`。

Codex 或其他 OpenAI 兼容客户端接入本地网关时，Base URL 填 `http://localhost:3000`、`http://127.0.0.1:3000`、`http://localhost:3000/v1` 或 `http://127.0.0.1:3000/v1` 都可以；API Key 只填 API Key 页面展示的 `sk-...` 明文，不要带 `Bearer ` 前缀，也不要填写上游 OpenAI / 中转供应商的账号密钥。客户端会自动发送 `Authorization: Bearer <API Key>`，如果填错 Key 会返回 `Invalid API key`，如果没有 Bearer 头会返回 `Missing bearer token`。

当前系统不提供“特征规则”菜单、只读接口或运行时规则表；流式错误处理通过流式拦截策略和客户端能力门控。非 2xx 上游错误响应统一进入账户错误处理策略和兜底确认流程：未命中账户错误处理规则时先同账号短重试，再尝试后续账号；后续账号成功则本次请求救回。所有候选账号都失败时返回网关统一 `service_unavailable` 错误，不再透传最后一个上游错误，也不再维护请求级上游错误签名缓存。

检查点：系统不存在特征规则管理接口；前端菜单不出现“特征规则”入口。上游 `invalid_request_error` 类错误不应首账号直接短路，应由回归覆盖“切号成功”“第三账号救回”“全部账号失败统一兜底”和“本地屏蔽耗尽快速失败”路径。

检查点：系统设置页能保存并回显；流式异常达到阈值后账号列表会显示临时不可调用、限流中或异常摘要；临时不可调用与限流状态可以通过账户列表“更多”菜单的“恢复正常”手动清理冷却与最近错误并恢复调度，也可以通过手动测试成功恢复。冷却到期后的后台复测会自动处理 `temporary_unavailable` 和 `rate_limited`；复测连续失败会按指数退避，单次暂停不超过最大暂停时间，超过 `cooldownAccountRetestMaxBackoffHours` 表达的最长自动恢复观察窗口后转为 `error`，错误码为 `cooldown_retest_max_recovery_exceeded`，之后只能通过“恢复异常”清理异常字段。“启用账户”只用于真正停用的账户，不用于清理临时状态。账户测试是人工诊断与恢复口子；停用账户测试只做诊断，不会自动恢复或改成临时不可调用；非停用自有异常账户手动测试成功可以恢复正常。后台复测、OAuth 刷新成功和网关异步错误处理不能绕过停用硬边界或普通显式异常硬状态。
