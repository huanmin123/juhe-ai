# 开发测试与验证说明

> 面向 AI 与维护者。
> 本文件承接代码级检查、接口验证、网关联通、账号测试和自动烟测；启动方式和运行注意事项见 [开发运行说明](运行说明.md)。

## 1. 适用场景

- 需要确认代码改动没有破坏类型、构建或关键路径。
- 需要验证后端接口、管理面页面、账号测试、网关转发或使用记录。
- 需要执行自动烟测、回归验证或问题修复后的复现检查。

在项目根目录执行：

```powershell
pnpm typecheck
pnpm build
```

如果只改了某一端，也可以先跑对应 workspace 的命令，再按需要补全全量验证。

## 4. 本地网关验证

客户端接入时使用 OpenAI 兼容协议：

- Base URL：`http://127.0.0.1:3000` 或 `http://127.0.0.1:3000/v1`
- API Key：API 密钥页生成的本地网关密钥
- 常用路径：`/models`、`/responses`、`/chat/completions`

`$LiteKey` 使用 API Key 页面新建后返回的明文密钥，或同步脚本首次输出的 `sync.apiKey`。

本机 `backend/data/juhe-ai.sqlite3`（或 `JUHE_AI_DATABASE_PATH` 指向的业务库）可能已经保存真实 OpenAI 账户、本地网关 API Key 和分组绑定；`backend/data/juhe-ai-records.sqlite3`（或 `JUHE_AI_RECORD_DATABASE_PATH` 指向的记录库）保存使用记录、统计、审计、运行日志索引和监控历史。需要真实联通验证或烟测时，可以优先复用本地业务库里的数据，不必重复创建；但不要把真实密钥写入文档、提交记录、Issue、截图或聊天内容，只在本机命令会话里临时赋值。

如果后端已经启动，可以从管理面接口取第一个启用且可展示明文的本地网关 API Key：

```powershell
$LiteKey = ((Invoke-RestMethod http://127.0.0.1:3000/__aisys__/api/api-keys).data |
  Where-Object { $_.status -eq "active" -and $_.key } |
  Select-Object -First 1).key

if (-not $LiteKey) {
  throw "未找到可用的本地网关 API Key，请确认本地数据库或先在 API Key 页面创建"
}
```

真实上游账户只用于本地联通验证；优先通过账户测试接口、网关请求或 `pnpm test:smoke` 验证可用性，不要直接导出或打印上游账户凭据。账户测试和后台复测必须走本地 OpenAI 网关处理链路，不能在测试服务里单独直连上游；测试产生的请求、token、成本、错误和账号命中记录应和客户请求一样进入使用记录与统计聚合，未产生 token / cost 的失败按 0 token、0 cost 计入请求和错误次数。

```powershell
$LiteKey = "你的本地网关 API Key"

Invoke-RestMethod http://127.0.0.1:3000/v1/models `
  -Headers @{ Authorization = "Bearer $LiteKey" }

$payload = @{
  model = "gpt-5.4-mini"
  input = "只输出 OK"
  max_output_tokens = 16
  stream = $false
} | ConvertTo-Json -Compress

Invoke-RestMethod -Method Post `
  -Uri "http://127.0.0.1:3000/v1/responses" `
  -Headers @{ Authorization = "Bearer $LiteKey" } `
  -ContentType "application/json" `
  -Body $payload
```

流式响应可用 `curl.exe -N` 检查：

```powershell
$streamBody = '{"model":"gpt-5.4-mini","input":"只输出 OK","max_output_tokens":16,"stream":true}'
$bodyFile = New-TemporaryFile
Set-Content -LiteralPath $bodyFile -Value $streamBody -NoNewline -Encoding utf8

curl.exe -sS -N -X POST "http://127.0.0.1:3000/v1/responses" `
  -H "Authorization: Bearer $LiteKey" `
  -H "Content-Type: application/json" `
  --data-binary "@$bodyFile" `
  --max-time 60
```

检查点：`/v1/models` 返回模型列表；非流式 `/v1/responses` 返回完成状态；流式响应能看到完成事件；使用记录能看到 endpoint、token 和成本字段。

发布前真实链路验证不要复用随手抓取的旧 Key；优先由 `pnpm test:smoke` 在目标账户当前绑定分组上创建临时本地 API Key，完成 `/v1` 请求后自动清理，避免误判账户、分组、API Key 和用量链路。

如果本地没有真实账户，`pnpm test:smoke` 会自动启动本机 mock OpenAI 上游，并通过 Mockdata 共享夹具生成临时 OpenAI API Key 类型账号、临时分组和临时本地 API Key，再按同一套正规网关流程完成 `/v1/models`、`/v1/responses` 和使用记录校验，结束后清理临时数据。该 fallback 不消耗真实 OpenAI 额度，也不污染真实账号；如果设置了 `JUHE_AI_SMOKE_ACCOUNT_NAME`，脚本会严格测试指定账号，不自动 fallback。通用造数职责见 [Mockdata 造数设计](../functions/Mockdata造数设计.md)。

需要额外覆盖 Codex turn 切号策略时，运行 mock smoke：

```powershell
pnpm test:smoke:mock
```

该命令会启动临时 SQLite 业务库 / 记录库、本机 mock OpenAI 上游和临时网关实例，自动创建分组、两个 OpenAI API Key 类型假账号和本地网关 API Key，覆盖 Codex turn 前 3 次失败、第 4 次切到备用账号、非 Codex 不切号、Codex 终止类错误不切号。它不消耗真实 OpenAI 额度，也不污染 `backend/data/`。

## 5. OpenAI OAuth 账户验证

前端路径：

```text
http://127.0.0.1:5173/__aisys__/accounts
```

点击 `OpenAI 账户授权`，可选两种方式：

- `手动授权`：生成授权链接，登录完成后复制浏览器地址栏里的 `http://localhost:1455/auth/callback?code=...&state=...` 回调 URL，粘贴回弹窗创建账户。
- `Refresh Token`：直接粘贴已有 OpenAI `refresh_token`，后端刷新成功后创建 OAuth 账户。

已有 OpenAI OAuth 账户在账户列表“更多”菜单中提供两个排障入口：

- `刷新令牌`：强制使用当前账户保存的 Refresh Token 换取一次 Access Token；成功后账户会刷新凭据，限流中、临时不可调用等软失败状态会恢复可调度，停用和异常不会被这个入口恢复。异常账户前端隐藏刷新入口，后端也会拒绝直接刷新，需要先走“恢复异常”或通过编辑修正凭据。失败会直接显示 OAuth 或代理错误。如果遇到 OpenAI 返回 `refresh_token_reused` 或 “Refresh Token 已被使用”一类提示，但账户仍能继续调用，通常表示另一个请求或后台任务已经先完成刷新并写入了新凭据；后端会在锁内重读账户并优先采用最新凭据。
- `重新授权`：打开独立弹窗复用新增账户的授权流程，可通过授权回调 URL 或新的 Refresh Token 覆盖当前账户 OAuth 凭据；名称、分组、代理、并发和错误策略不随重新授权修改。异常账户前端隐藏重新授权入口，后端也会拒绝直接重新授权。

后端授权链接接口可用以下命令做冒烟检查：

```powershell
Invoke-RestMethod -Method Post `
  -Uri "http://127.0.0.1:3000/__aisys__/api/openai-oauth/auth-url" `
  -ContentType "application/json" `
  -Body "{}"
```

OAuth token 交换、刷新、重新授权和账户测试会使用账户绑定代理；网关真实转发也会使用账号绑定代理。OAuth token 交换、刷新和重新授权属于授权协议请求，不计入模型使用统计；账户测试会通过同一套网关模型请求链路计入使用记录。后台 Access Token 预刷新只做授权保活，会扫描所有仍存在、未删除、有 `refresh_token` 且快过期的 OpenAI OAuth 账户，不因停用、异常、限流或临时不可调用状态跳过；预刷新成功只写回凭据，不自动恢复账户状态；连续 3 次预刷新失败会把账户标记为 `status = error`，异常类型为 `oauth_token_refresh_failed`。后台冷却复测默认开启，但只会复测冷却时间到期的 `rate_limited`、`temporary_unavailable` 账号；账号质量主动探测能力已删除。OAuth 额度快照不再主动探测，只从真实网关请求或账户测试响应头被动更新。

## 6. 账户与管理面验证

账户列表“更多”菜单里的“测试”会调用后端 `POST /__aisys__/api/accounts/:id/test`，内部构造一次本地 `/v1/responses` 请求并复用正常 OpenAI 网关链路验证账户是否可用；OAuth 账户会在网关准备上游账号时按正常请求规则刷新 token。测试只允许命中当前被测账户，不会静默切到同分组其他账号。账户测试展示用响应体只保留有界预览，异常大响应会标记 `responseTruncated` 并追加截断提示，避免管理接口因为上游异常响应占用过多内存。已停用账户不能执行测试；异常账户可以测试，但测试成功、后台复测、OAuth 刷新成功和网关异步错误处理都不能绕过停用或异常硬状态。异常账户只能通过“恢复异常”清理 `last_error_code`、`last_error_message` 和冷却字段后恢复调度。

```powershell
$account = (Invoke-RestMethod http://127.0.0.1:3000/__aisys__/api/accounts).data |
  Where-Object { $_.providerCode -eq "openai" -and $_.status -eq "active" } |
  Select-Object -First 1

Invoke-RestMethod -Method Post "http://127.0.0.1:3000/__aisys__/api/accounts/$($account.id)/test"
```

管理面重点检查：

- 账户列表只显示名称、类型、供应商、并发、状态、用量、优先级、最近使用时间和操作。
- `Access/API Key` 与 `Refresh Token` 不在列表展示，只在编辑弹窗展示和修改。
- API Key 页面直接展示完整本地网关密钥，方便复制。
- OAuth 账户如需代理，可在账户编辑弹窗中绑定代理配置；代理不可用时刷新 token 和测试会失败。

## 7. 性能综合测试

需要评估本机模拟链路的 QPS、延迟、错误率和资源占用时，可以运行：

```powershell
pnpm test:perf
```

该命令会启动临时 SQLite 业务库 / 记录库、本机模拟 OpenAI 上游和临时网关实例，并通过 Mockdata 共享夹具自动创建压测分组、OpenAI API Key 类型账户和本地网关 API Key；测试结束后删除临时数据目录，不消耗真实 OpenAI 额度，也不污染 `backend/data/`。

默认覆盖 `/v1/models`、非流式 `/v1/responses` 和 `/v1/chat/completions` 三类场景，按多个并发档位输出：

- `QPS` / `成功QPS`：总吞吐和成功请求吞吐。
- `错误率` / `statusCounts` / `errorCounts`：失败比例、HTTP 状态码和错误分类。
- `latencyMs`：`min`、`avg`、`p50`、`p90`、`p95`、`p99`、`max`。
- `eventLoopDelayMs`：事件循环延迟均值和分位，用于观察 Node 主线程压力。
- `cpu` / `memory`：本进程 CPU 时间、单请求 CPU 均值和内存变化。
- `usageRecordsDelta` / `auditLogsDelta`：本次压测写入临时记录库的使用记录和审计日志数量。
- `usageRecordQueueLength` / `auditLogQueueLength`：结束时队列是否清空。

常用调参示例：

```powershell
$env:JUHE_AI_PERF_SCENARIOS = "models,responses,chat,responses_stream"
$env:JUHE_AI_PERF_CONCURRENCY = "25,50,100"
$env:JUHE_AI_PERF_DURATION_SECONDS = "15"
$env:JUHE_AI_PERF_WARMUP_SECONDS = "3"
$env:JUHE_AI_PERF_UPSTREAM_LATENCY_MS = "20"
$env:JUHE_AI_PERF_UPSTREAM_BODY_BYTES = "1024"
$env:JUHE_AI_PERF_REPORT_PATH = "perf-report.json"
pnpm test:perf
```

`JUHE_AI_PERF_REPORT_PATH` 的相对路径按发起 `pnpm` 命令的目录解析，父目录会自动创建。例如在仓库根目录设置为 `reports/perf-limit-report-2026-05-17.json` 时，报告会写入 `F:\sub2api-lite\reports\perf-limit-report-2026-05-17.json`。

可用环境变量：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `JUHE_AI_PERF_SCENARIOS` | `models,responses,chat` | 逗号分隔场景；可选 `models`、`responses`、`chat`、`responses_stream` |
| `JUHE_AI_PERF_CONCURRENCY` | `10,25,50` | 逗号分隔并发档位 |
| `JUHE_AI_PERF_DURATION_SECONDS` | `6` | 每个并发档位正式压测秒数 |
| `JUHE_AI_PERF_WARMUP_SECONDS` | `1` | 每个档位预热秒数，不计入结果 |
| `JUHE_AI_PERF_REQUEST_TIMEOUT_MS` | `5000` | 客户端请求超时 |
| `JUHE_AI_PERF_UPSTREAM_LATENCY_MS` | `20` | 模拟上游首响应延迟 |
| `JUHE_AI_PERF_UPSTREAM_BODY_BYTES` | `512` | 模拟上游响应正文规模 |
| `JUHE_AI_PERF_UPSTREAM_ERROR_RATE` | `0` | 模拟上游错误率，范围 `0` 到 `1` |
| `JUHE_AI_PERF_ACCOUNT_COUNT` | `8` | 临时上游账户数量 |
| `JUHE_AI_PERF_ACCOUNT_CONCURRENCY` | `10000` | 单个临时账户并发上限 |
| `JUHE_AI_PERF_P95_TARGET_MS` | `1000` | 汇总里判断稳定容量的 p95 延迟阈值 |
| `JUHE_AI_PERF_REPORT_PATH` | 空 | 写入 JSON 报告的路径 |

结果边界：

- 这是本机模拟测试，用于评估网关代码路径、SQLite 写入、使用记录队列和审计采样的容量参考。
- 脚本不启动生产形态的独立 DB service / background worker 子进程；正式部署容量仍需在目标机器和目标网络下补测。
- 真实 OpenAI 上游会引入网络延迟、供应商限流、代理质量和真实模型耗时，不能直接用本机模拟 QPS 作为线上承诺。

## 8. 自动烟测

项目启动后执行：

```powershell
pnpm test:smoke
```

默认会走真实管理流程：先用烟测管理员账号登录，再选择一个启用且可用的 OpenAI 账户，在该账户当前绑定分组上创建临时本地 API Key，然后用这个 Key 请求 `/v1/models` 和 `/v1/responses`，最后删除临时 Key。脚本不会为真实账号临时改绑分组，避免破坏账号已有分组绑定；只有本地无可用真实账户且未指定 `JUHE_AI_SMOKE_ACCOUNT_NAME` 时，才会自动创建临时 mock 账号和临时分组，并在结束后清理。OAuth 账户会使用 Codex 兼容流式请求体，校验代理链路、流式完成事件和使用记录 token/cost 入库。

Codex 或其他 OpenAI 兼容客户端接入本地网关时，Base URL 填 `http://localhost:3000`、`http://127.0.0.1:3000`、`http://localhost:3000/v1` 或 `http://127.0.0.1:3000/v1` 都可以；API Key 只填 API Key 页面展示的 `sk-...` 明文，不要带 `Bearer ` 前缀，也不要填写上游 OpenAI / 中转供应商的账号密钥。客户端会自动发送 `Authorization: Bearer <API Key>`，如果填错 Key 会返回 `Invalid API key`，如果没有 Bearer 头会返回 `Missing bearer token`。

网关会缓存已通过校验的本地 API Key，重复请求会刷新短 TTL，减少高频调用对 SQLite 的鉴权查询压力；禁用、删除或修改 API Key 会立即清理对应缓存，缓存最长 5 分钟必须重新查库。

需要固定测试账号或模型时编辑 `backend/.env`：

```dotenv
# 只影响 pnpm test:smoke，不影响正常启动和网关转发。
JUHE_AI_BACKEND_URL=http://127.0.0.1:3000
JUHE_AI_SMOKE_ADMIN_USERNAME=admin
JUHE_AI_SMOKE_ADMIN_PASSWORD=admin
JUHE_AI_SMOKE_ACCOUNT_NAME=
JUHE_AI_SMOKE_MODEL=gpt-5.4-mini
JUHE_AI_SMOKE_PROMPT=只输出 OK
```

`JUHE_AI_SMOKE_ACCOUNT_NAME` 留空时自动选第一个启用并且可用的 OpenAI 账号；填写后必须和账户页里的账号名称完全一致。

检查边界：

- `pnpm test:scope` 只验证普通用户、管理员用户侧和管理员管理侧接口边界；它使用临时库和脚本种子数据，不等同于真实 OpenAI 网关 smoke。
- `pnpm test:proxy-negative` 验证停用代理、网关 503、失败使用记录和使用中代理不可删除等负向场景；它使用临时库和假上游，不替代真实 OpenAI + 代理链路。
- `pnpm --filter juhe-ai-backend test:db-service-system-api-boundary` 和 `test:db-service-system-api-http` 验证系统管理 API 由 DB service 承载，主进程不直接挂载管理路由、不解析管理 API body，DB service 内部 system API 可读取公开设置。
- `pnpm --filter juhe-ai-backend test:db-service-worker-local` 验证 worker / db-service 可本地执行内部 DB 操作，而 server 角色没有 DB service 子进程时必须拒绝本地同步执行。
- `pnpm --filter juhe-ai-backend test:runtime-config-env-override` 验证后端同名进程环境变量优先于 `backend/.env`，便于临时端口、隔离库和部署平台覆盖。
- `pnpm --filter juhe-ai-backend test:account-list-visible` 验证临时种子账户在管理员全量、管理员按系统账户筛选和用户侧账户列表中都可见，并固定页码越界时 `total > 0` 的前端回退契约。

内置特征规则只通过“特征规则”菜单和只读接口展示，不写入 `system_settings`，也不能从页面修改。当前只保留非 2xx 上游错误响应特征规则的只读展示；流式错误码特征规则、流式规则接口和前端流式页签均已下线，不再用“空列表接口”表达未启用状态：


上游错误响应特征规则命中后应原样返回上游错误，不继续扫账号，也不写入账号冷却或本地屏蔽。

检查点：系统设置页能保存并回显；流式异常达到阈值后账号列表会显示临时不可调用或异常摘要；临时不可调用与限流状态可以通过账户列表“更多”菜单的“恢复正常”手动清理冷却与最近错误并恢复调度，也可以通过手动测试成功或冷却到期后的后台复测成功恢复；复测失败会继续保持临时不可调用。“启用账户”只用于真正停用的账户，不用于清理临时状态。账户测试和后台复测作为恢复口子，只适用于 `rate_limited`、`temporary_unavailable` 等软失败状态；`error` 在页面显示为“异常”，测试只做诊断，不能自动恢复，只能通过“恢复异常”清理异常字段。停用账户和异常账户都属于硬状态，不能被测试、后台复测、OAuth 刷新成功或网关异步错误处理自动恢复或改成临时不可调用。
