# 临时管理访问令牌

临时管理访问令牌用于上线预演、故障排查和自动化维护。它不是新的角色，也不绕过现有权限判断；令牌对应申请它的系统账户，所有管理接口继续按该账户的 `admin` / `super_admin` 权限和资源范围执行。

## 申请

调用 `POST /__aisys__/api/auth/temporary-access-tokens`，提交管理员用户名、密码和可选的 `ttlSeconds`：

```json
{
  "username": "admin",
  "password": "<管理员密码>",
  "ttlSeconds": 900
}
```

`ttlSeconds` 默认 900 秒，允许范围为 60 到 3600 秒。申请接口不接受验证码代答；只有 `JUHE_AI_TEMPORARY_ACCESS_IP_ALLOWLIST` 中显式列出的来源 IP 才能申请，未配置白名单时一律返回 `403`。申请接口沿用登录 IP/用户名限流，普通用户、停用账户和要求初始改密的账户不能申请。

生产环境必须在私有 `backend/.env` 中逐项配置白名单，例如：

```env
JUHE_AI_TRUST_PROXY=1
JUHE_AI_TEMPORARY_ACCESS_IP_ALLOWLIST=203.0.113.10,2001:db8::10
```

这里填写实际自动化调用方的固定 IP，不接受域名、CIDR 或通配符。服务位于 Nginx/Caddy 后时，先按实际代理跳数配置 `JUHE_AI_TRUST_PROXY`，否则 Node 会把代理地址误认为调用方，白名单会失去边界意义。

响应中的 `token` 只在这一次响应中返回，调用方必须放在进程内存或受控的临时变量中，不得写入源码、仓库、命令历史或日志：

```json
{
  "token": "juhe_tmp_<opaque>",
  "tokenType": "Bearer",
  "expiresAt": "<ISO-8601>"
}
```

## 使用和撤销

把令牌放入 HTTP `Authorization: Bearer juhe_tmp_<opaque>` 头，即可访问该管理员原本能访问的系统管理接口。令牌过期后由会话校验拒绝，后台过期清理会删除对应记录。

令牌持有者可以立即撤销当前令牌：

```http
POST /__aisys__/api/auth/temporary-access-tokens/revoke
Authorization: Bearer juhe_tmp_<opaque>
```

撤销、申请和后续管理操作继续进入操作日志；日志只记录会话 ID、账户和 trace，不记录 token 原文或密码。

## 边界

- 不把临时令牌放入 Cookie；普通登录 Cookie 会话行为不变。
- `Authorization` 头只接受 `juhe_tmp_` 前缀的临时令牌，普通 Bearer 值不会被当作管理会话。
- 令牌不自动获得 `/v1`、`/v1beta` 等业务网关 API Key 能力。业务接口预演仍需使用已有、范围受限的 API Key 或专用探针账户。
- 不把令牌写入 Nginx、Caddy、LaunchDaemon、发布包或 `.local` 以外的配置文件。
