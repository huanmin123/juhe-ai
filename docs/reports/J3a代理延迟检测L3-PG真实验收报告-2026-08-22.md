## 2026-08-23 受控复验

本轮创建一次性 `juhe_ai_sub2api_dev_j3a_projector` scratch，初始化当前业务 schema 与 `juhe_jobs` schema 后，经 PgBouncer `6432` 运行 `TestPostgresResultProjectorSmoke`，退出码为 `0`；同时以受控 dev 环境运行 `JUHE_AI_ENV_FILE=.local/project-resources/dev/env/shared.env pnpm.cmd run test:proxy-postgres-smoke`，退出码为 `0`，验证现役 Node 代理管理 CRUD、CAS、微秒版本保留、并发合并和索引计划。Go business-result projector 在同一 scratch 的 committed outcome fixture 覆盖：

- Go reader 按 `(stored_at, outcome_id)` 读取并保留微秒级 `observed_at`；
- Go projector applied 路径更新 `test_status/latency_ms/last_test_message/last_tested_at`，不改 `updated_at`；
- config revision 不匹配的 manual 直接 CAS 返回 `stale` 且不写业务状态；该分支按契约不创建 durable receipt/cursor；
- `applied` receipt、cursor 单调推进和重复 outcome replay 均通过；
- 删除对象 `ignored`、无 provider `unknown` 的 manual 直接 CAS 语义均通过；这些分支按契约不创建 durable receipt/cursor；
- applied 后的 `ProjectManualOutbound` CAS 写入 `outbound_ip/outbound_region` 均通过。

本轮同时修复了两项真实环境暴露的问题：PostgreSQL lease takeover 改用数据库 `statement_timestamp()` 判断过期，避免 PgBouncer 客户端时钟微偏导致 successor 误判 busy；Go reader 不再依赖 Go outcome 表中不存在的 `overall_status` 行列，状态继续由严格校验的 JSONB payload 提供。Node J3a outcome reader/projector 与其 fixture 已删除。

Go PG projector 复验入口为 `backend-go/projects/jobs` 下的 `TestPostgresResultProjectorSmoke`（仅通过 `J3A_PG_SMOKE_JOBS_URL` 与 `J3A_PG_PROJECTOR_URL` 接收受控 DSN，退出码 `0`）；该命令插入并清理 committed outcome 与 proxy fixture，durable 断言为 applied/receipt/cursor/replay/outbound，manual stale/deleted/no-target 为直接 CAS 边界断言。Node 侧只保留 `pnpm.cmd --dir backend typecheck` 与 Go-only 路径删除回归，不再有 Node outcome reader/projector 命令。

上述 Go 验证使用受控 committed outcome fixture，证明 Go reader/projector 事务路径，不等同真实生产服务已发布；Node→Go 手动进程联调、active-path-zero、owner handoff、重启和生产/L4 仍未完成。
