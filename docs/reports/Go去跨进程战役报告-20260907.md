# Go 去跨进程战役报告（2026-09-07）

## 1. 裁决与目标

用户裁决：**Go 中跨进程调用完全禁止**——不仅指 Node↔Go，也包括 Go 进程之间的 HTTP 互调。此前迁移期保留的两个 gateway→jobs HMAC 派发桥、无签名 go-runtime-trend GET、gateway 自有的 F3/F4 ingest 监听器（等待已归档 Node 生产者），全部消灭。解决路径：**实现抽取为共享包，两进程各自进程内调用同一实现；持久状态走数据库**（六库架构既有形态，不属于进程通信）。进程健康探测（jobs 3305 `/health`、`/__aisys__/metrics` Prometheus 抓取、deploy 脚本健康轮询）属编排语义，保留。

执行方式：3 个只读代理深度取证 → 5 个写入代理分刀实施（工作树串行，避免组合根文件冲突）→ 独立复审。提交：`7e36e20ba`（用户合入，167 文件 +6343/-7074）+ `d94c7e169`（收尾）。

## 3. 行为变化登记

1. **F3 链路审计采集从「零写入」变为「正常写入」**（缺陷修复；审计量将真实出现，下游 retention/读面按既有配置消化）。
2. 测试派发 503 收窄：仅「gateway 本地队列已停止/契约表缺失」触发；重复派发由「置败 running 任务」改为幂等成功；取消为进程内 CancelLocal（5s 超时尽力而为）。
3. 健康检查派发时延量级不变（主导项均为 J1 5s 扫描周期，省去 HTTP+文件 fsync 净略降）；`JUHE_AI_BACKGROUND_ACCOUNT_HEALTH_CHECK_PROBE_DEADLINE_MS` 改为 gateway 侧读取（写行时定 deadline）；J1 关闭部署时 outbox 行保持 pending 堆积（旧行为 rejected 即弃），J1 启用后消费、过期行走 `request_deadline_elapsed` 终态。
4. trend 端点：store 未启用/无数据时 200+空 items（旧为 503）；外层 role="gateway+jobs"（前端零消费）；若前端未来混绘双 role 需按 item.role 分组（登记）。
5. 余额手动刷新/草稿测试：PG 模式且 `juhe_jobs.account_balance_*` 可用时真实执行（200 快照/409 lease_busy/409 配置已变化）；SQLite 模式端口 nil 维持既有 500/降级快照契约（与周期 runner 的 PG 限定一致）；**部署前提**：gateway 业务角色需具备 juhe_jobs schema owner 权限，否则 CheckSchema 失败降级并 Warn。
6. 模型目录刷新：从恒 400 变为全模式可用（真实上游拉取+本地目录比对）；失败仍 400 同文案前缀。
7. turn-avoidance 探活的 fence 结算不对称现状保持（runner 不回写 gateway 侧探活状态），未新增行为。
