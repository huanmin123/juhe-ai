# 可靠统计与读写隔离压测报告（2026-07-05）

## 摘要

- 测试目标：验证热统计拆分、PostgreSQL 连接边界、Redis state/cache/Stream 和 System API 读写混合负载在真实测试环境下是否稳定。
- 测试环境：真实测试栈，PostgreSQL 经 PgBouncer 访问，Redis 分 cache / state；本轮队列 smoke 复用 state Redis 作为 queue。
- 原始产物：
  - `reports/performance-gateway-persistence-readiness-20260705T070332Z.json`
  - `reports/performance-system-api-load-real-env-20260705T0709.json`
- 结论：本轮通过。System API 30 秒、50 并发、15% 写请求压测 5477 次请求全部成功，整体 p95 为 517.97ms，PG 死锁 0，锁等待采样无持续堆积。

## 前置修正

- 测试库缺少新系统设置 `usageHotWindowRefreshIntervalSeconds`，导致 `/__aisys__/api/settings/public` 在限流中读取系统设置时报 500；已通过 `postgres:init-schema` 补齐当前 schema 和默认 seed。
- PgBouncer 拒绝 `statement_timeout` 等 startup parameter；已改为 PostgreSQL 连接建立后执行 `SET statement_timeout / lock_timeout / idle_in_transaction_session_timeout`，保留 `application_name` 作为连接角色标识。
- System API 压测脚本的账号夹具缺少当前必填的 `providerProtocolProfileId`，并使用了不符合当前上游 URL 策略的测试地址；已更新为默认 GPT/OpenAI 协议档案和允许的 OpenAI Base URL。

## 结论与边界

- 当前改造后，真实测试环境下管理读写混合负载没有进入秒级稳定慢；列表、详情和 options 接口 p95 均在 600ms 内。
- 本轮验证的是 System API 管理接口读写混合负载，不代表真实外部上游网关 SSE 容量；网关容量继续以独立 gateway load 报告为准。
- `GET /groups` 和 `PATCH /accounts/:id` 是本轮相对较慢的管理操作，后续如果继续压高并发，应优先观察这两类接口的 SQL 计划和缓存命中。
- Redis 仍按上线流程处理：不备份，清理前必须停服务并确认 Stream pending / lag 为 0。
