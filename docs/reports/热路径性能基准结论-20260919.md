## 3. 画像热点排序

### 3.1 已证实结论①：dispatch 全链瓶颈在传输层，进程内逻辑非热点

- **数据来源**：`DispatchFetchFirstAvailableUpstreamHappyPath` 339.6µs 全链基准 vs `DispatchFilter…` 5.4µs、`DispatchPrepare…` 16.3µs 分段基准（README 表）。
- **占比**：进程内 filter（5.4µs，~1.6%）+ prepare（16.3µs，~4.8%）合计 21.7µs，**< 全链 7%**；其余 ~93% 耗时在 loopback HTTP 传输（真实 socket 往返）。
- **方向性佐证（登记为补充证据，非正式结论）**：2026-09-19 补采的 `dispatch_fetch_cpu.prof`（负载条件未登记）top flat 为 `runtime.cgocall` 44.28%、`runtime.semasleep` 11.33%，业务函数未进入 flat top；`dispatch_fetch_mem.prof` top flat 为 `bufio.NewWriterSize` 14.69% + `bufio.NewReaderSize` 13.74%（读写缓冲合计 28.4%）、`net/http.(*Transport).dialConn` 在列。两画像与"传输/网络栈主导"方向一致。
- **定性**：传输层 = 热点；进程内 dispatch 逻辑（filter/prepare/normalize/override）= 非热点。**推断（明确标注）**：在进程内 dispatch 逻辑上做优化，全链收益上限 <7%。

### 3.2 已证实结论②：SSE 泵 CPU 被 scheduler 原语主导

- **数据来源**：`response_sse_cpu.prof`（`PipeUpstreamStreamOpenAIChatSSE`，10s benchtime、420k 次迭代；本档 pprof 复核值）。
- **占比**：`runtime.semawakeup` 14.27% + `runtime.semasleep` 12.09% + `runtime.lock2` 3.66%（flat）≈ **30%**（README 登记口径 ~26%，同一量级；差异为不同时点 -top 快照）。
- **根因（README 定性，本档沿用）**：每分片 `time.After` + select 竞速的 goroutine 停靠成本。
- **对照实验**：TimeoutsDisabled 对照基准 28,241→25,715 ns/op（-2.9µs/op，约 -10%）、B/op 19,035→17,199（-1.8KB）、allocs/op 219→190（-29）。
- **定性**：热点。这是 CPU 画像第一大项。

### 3.3 已证实结论③：SSE 泵分配热点排序（alloc_space 占比）

**数据来源**：`response_sse_mem.prof`（本档 pprof 复核，与 README 登记一致）。

| 排名 | 热点 | flat 占比 | 定性 |
| --- | --- | ---: | --- |
| 1 | 每分片管道结构合计（`gatewayresponse.newStreamPipe` 7.68% + `newPendingRead` 5.69% + `LimitedCapture.Buffer` 5.32%） | ~18.7%（README ~18.5%） | 热点（合计口径第一） |
| 2 | `gatewayopenai.copyCounts` | 10.20% | 热点 |
| 3 | `encoding/json.(*decodeState).objectInterface`（flat 7.97%，cum 8.82%） | ~8.0% | 热点（分配侧） |
| 4 | `bytes.growSlice` | 5.56% | 次要热点 |
| 5 | `regexp.(*bitState).reset` | 4.53% | 次要热点 |

单点 flat 最大项是 `copyCounts`（10.20%）；按同源结构合计则每分片管道结构居首。JSON 编解码（objectInterface ~8.0%）在泵内已量化，但**链路级 JSON 占比（评估 A6 要求的量化口径）仍需 dispatch_fetch 空载画像到位后合并结论**——该合并结论未证实，不在此给出。

### 3.4 已证实结论④：chat 双协议 SSE 收集为 chat 包分配热点

- **数据来源**：chat 基准交付汇报（`BenchmarkChatCollectOpenAIChatSseContentToolUsage`、`BenchmarkChatCollectChatResponsesSseCompleted`）。
- **数值**：Chat 收集全链 57µs / **619 allocs/op**；Responses 收集全链 78µs / **927 allocs/op**。两者覆盖字节读取、事件切分、JSON 解析、内容累计、工具参数拼接、usage 提取全链，是 chat 包覆盖面最宽的两个基准，登记为 chat 分配热点。
- **限制**：数字未落盘、且为并行负载初测；收集链内部逐函数占比未画像（仅有 allocs 总量），内部热点排序未证实。其余 4 个 chat 基准（图像剥离、transport 组装、工具事件投影、checkpoint 序列化）数字未存档，**不定性**。
