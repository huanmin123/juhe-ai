## 适用边界

- 本目录只放人工可读、需要长期回看的 Markdown 报告。
- 顶层 `reports/` 只放脚本生成的 JSON、log、cpuprofile、临时采样结果等原始产物。
- 需求推进过程仍写在 `docs/plans/`；报告只沉淀测试范围、环境、数据、结论、边界和后续建议。
- 部署步骤、启动命令、备份恢复和生产配置仍写在 `docs/deploy/`；报告可以链接部署文档，但不要承载操作手册。
- 功能行为、接口契约、存储口径和长期设计仍写在 `docs/functions/` 或 `docs/architecture/`；报告中的结论如果变成长期规则，需要同步回对应设计文档。

## 命名规则

- 报告文件名建议使用 `主题报告-YYYY-MM-DD.md`，同一主题多轮报告用日期区分。
- 报告正文必须写清测试日期、环境、命令或入口、原始产物路径、结论边界和不适用范围。
- 不写真实连接串、密码、token、用户隐私或完整敏感 payload。
- 引用原始产物时使用仓库根目录相对路径，例如 `reports/perf-limit-report-2026-05-17.json`。
