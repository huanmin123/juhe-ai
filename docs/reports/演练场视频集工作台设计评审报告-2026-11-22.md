# 演练场视频集工作台设计评审报告

审阅日期为 2026-11-22。评审结论为 **v0.9 需要修订后再实施**。素材由用户在外部工具准备，工作台负责接收、组织并按分镜调用视频模型，用户逐镜下载后在线下剪辑。首要验收目标是用户已有可用 Key 时，打开视频页，写一句画面描述就能生成第一镜。有现成资源的人，可以明确指定模型怎样使用每份素材。[被审设计 §1、§7、§10](../functions/演练场视频集工作台设计.md)

## 1. 用户打开页面后看到什么

以下为拟议交互。以桌面端进入一个空视频集为例，方括号表示可操作控件，数值仅示意已验证合法的一组默认值。

```text
视频生成                                      [我的视频集]
当前视频集：未命名                            [更换 API Key]

描述这个镜头
┌────────────────────────────────────────────────────┐
│ 小船穿过清晨的薄雾，镜头贴近水面缓慢向前。             │
└────────────────────────────────────────────────────┘
[＋ 添加素材]     [Seedance ▾]    [5 秒 ▾]    [16:9 ▾]
[720p ▾]          [生成声音：关]                 [生成分镜]

本集分镜
生成后在这里预览、下载，或继续创建下一镜。
```

- **第一次生成**。进入页面就能写提示词。在当前 Key 可用的文生视频型号中优先选已验证的 Seedance，显示实际型号。已有明确选择时沿用该选择。当前 Key 缺少 Seedance 时显示可用的其他文生型号，缺少全部视频候选时说明原因并保留输入。第一次提交只产生一个集、一个分镜和一次生成请求。集可自动命名并改名。已有集内提交直接追加分镜。
- **加现成素材**。允许在分镜里直接上传、拖入文件或从本集选已有素材。缩略图旁显示用途，例如「用作首帧」「参考外观」，音频可试听。角色、场景、道具是可选整理标签，文件名可作初始名称。选了多张参考图时，显示与提示词一致的素材编号，方便用户写清“图 1 的人物走进图 2 的场景”。仅编号已不足以消除歧义时再请用户选择用途。
- **改参数**。时长和画幅给常用选择，分辨率和生成声音可放同一设置行。窄屏折叠为一个可展开的参数摘要。固定值显示文字，例如「固定有声」；只有实际可控的项才显示开关。每次生成前都能看到本次模型、时长、画幅和声音状态。切模型原样保留提示词和集内文件，就地标出哪份素材或哪个选项有冲突，让用户改回模型、改参数或将素材移出本次生成。
- **连续做几镜**。结果区按分镜顺序展示。完成卡片的主动作是播放和下载，另有「再生成一版」和有条件出现的「用尾帧创建下一镜」。素材库、剧本备注和批量操作放在集内次级入口。完成卡片能说明用了哪一版模型、哪些素材及哪些参数。

当前页的 `canCreate` 已只要求提示词、Key 和模型。v0.9 §7 则先要求建集命名，进入详情后依次展示剧本、素材和分镜，再打开长表单。§10 的演示路径也从贴剧本、传图和音频开始。这会丢失现有页面最容易上手的一条路径。[现有视频页](../../frontend/src/views/playground/PlaygroundVideoView.vue) [现有模型选择逻辑](../../frontend/src/views/playground/usePlaygroundCatalog.ts)

## 2. 生成方式决定哪些素材可以一起用

| 用户想得到什么 | 分镜编辑器怎么让用户表达 | 送给模型的内容 |
| --- | --- | --- |
| 凭描述生成 | 直接写提示词 | 提示词及生效参数 |
| 从指定画面开始 | 添加图片，选「用作首帧」 | 显式首帧。需要约束结束画面时，仅在已接入首尾帧模式下增加尾帧槽 |
| 参考人物或场景 | 添加图片，选「参考外观」 | 参考图及其稳定顺序。第一张参考图也保持参考图角色 |
| 参考一段声音 | 选取音频并指定「发送给模型」 | 根据具体型号校验伴随素材、音频数量和总时长。出片有声或静默另行显示 |
| 给线下剪辑留配音 | 把音频留在集内，或给分镜标记「仅供剪辑」 | 只发送用户指定参与生成的素材。改剪辑音轨可单独保存 |
| 延续上一镜 | 从已完成的上一镜点击「用尾帧创建下一镜」 | 固定引用具体结果的尾帧，按新分镜的首帧能力校验。尾帧已过期时可手选替代图 |

v0.9 §4.3 把 `images[0]` 解释为首帧，§7.3 又允许无首帧、只选参考图。建议保留现有单图请求的意义，为新增的多素材请求显式表达用途。火山将指定首帧、指定首尾帧和多模态参考规定为互斥的输入方式。精确锁定开场和用人物照参考长相是两种结果，界面要能让用户选对。尾帧续接同样遵守首帧模式的组合限制。[现有单图解析](../../backend-go/projects/gateway/internal/gatewaymedia/videoparams.go) [火山方舟创建视频生成任务 API](https://docs.volcengine.com/docs/ark/create-video-generation-task-api?lang=zh)

v0.9 §2 将绑定音频的镜头都视为角色对白，并承诺音色完全一致，§11 又把口型质量列为待验证。旁白、节奏参考和角色对白对画面的要求不同。「参考音频」「生成声音」「仅供剪辑」应有独立语义。建议沿用草案对可控型号的静默默认，并显示「生成声音：关」。开启后清楚显示本次输出有声。若在静默输出下使用音频参考，只有具体型号已验证该组合、且能说明音频对画面的作用时才开放。单纯替换剪辑音轨可以保留已有画面；用户要求改变已生成画面的嘴型时，应走新的生成或线下对口型流程。口型和音色还原度需要真实样片验收。[设计 §2、§11](../functions/演练场视频集工作台设计.md) [火山方舟生成声音参数](https://docs.volcengine.com/docs/ark/create-video-generation-task-api?lang=zh)

## 3. Seedance 优先怎样落地

已有七类视频适配器，任务创建、状态查询和内容获取可以复用。今天的统一输入只收一张图，火山创建代码能写入提示词和单张图，其公共能力声明把生成声音开关置为不支持。多参考、音频参考、输出声音开关与尾帧回传均需核对实际出站和回包。这直接决定首发能点亮哪些控件。[适配器注册](../../backend-go/projects/gateway/internal/gatewaymedia/videoadapter.go) [统一输入解析](../../backend-go/projects/gateway/internal/gatewaymedia/videoparams.go) [火山适配器](../../backend-go/projects/gateway/internal/gatewaymedia/volcengine_video.go)

| 具体差异 | 对设计的影响 |
| --- | --- |
| 只有一段音频 | 火山文档允许 Seedance 2.5 系列在多模态参考模式下只带音频；2.0 系列要求至少一份视觉参考。首发若只接图片作视觉参考，2.0 的提示应直接说「请添加一张参考图」 |
| 同一系列的不同型号 | 火山文档给 2.5 标准版的参考图和音频上限分别为 30 张和 10 段，Flash 为 10 张和 5 段。2.0 标准版、Fast、Mini 的分辨率也有区别。草案中按前缀共用的上限和画质不能直接用作表单 |
| 多份素材一起提交 | 火山规定 2.0 所有参考音频合计至多 15 秒，2.5 系列合计至多 30 秒，整个请求还有 64 MB 限制。上传成功只表示素材已保存，组成分镜时还要按数量、总时长及编码后请求大小校验 |
| 4K | v0.9 §5 开放 4K 且复用现有换算，但当前火山适配器把短边达到 900 像素的尺寸统一映射为 1080p。开放 4K 的条件是所选型号、出站分辨率、结果展示和计费档位均对得上 |
| 真人角色照 | 火山文档对含真人人脸的参考图和视频设置了专门的素材输入路径。普通上传的「角色」标签无法使任意真人照片都能送入模型。用户选择相关用途时应能看到具体限制和上游拒绝原因 |
| 已备好的参考视频 | Seedance 有视频参考输入，而 v0.9 的素材表只接图片和音频。建议首发保留图、音频和尾帧续接，让首发支持范围在添加素材时可见；素材类型与用途分开建模，以便后续接收用户已有的视频片段 |

以上厂商规格来自火山的创建任务文档。项目目录已经分别列出 2.5、2.0、2.0 Fast、2.0 Mini 等具体 ID。[火山方舟创建视频生成任务 API](https://docs.volcengine.com/docs/ark/create-video-generation-task-api?lang=zh) [项目火山模型目录](../../backend-go/projects/gateway/internal/pricing/catalogdata/volcengine.json)

上传单件素材和提交整镜请求还各有本地大小限制。现行演练场的参考图上传路由有专门的请求体上限，普通会话路由默认 256 KiB。视频生成请求使用网关文本档，默认 16 MiB。若把一段 15 MiB 音频编码成 Base64，单音频就约 20 MiB。设计应说明可用的素材传递方式与整镜预算，并用实际大小验证两个环节，避免页面接受一段音频后在生成时才出现 413。[演练场上传路由](../../backend-go/projects/gateway/internal/playground/routes.go) [网关限额](../../backend-go/projects/gateway/internal/gatewaybody/body.go) [请求分类](../../backend-go/projects/gateway/internal/gatewaybody/middleware.go)

**其他模型沿用同一个编辑器。** 建议由服务端对当前 Key 的候选返回具体型号、生成方式、必需的输入及允许的参数组合。前端据此展示，提交前后用同一套规则校验。已验证支持纯提示词的旧型号可以继续提供基础入口。仅支持图生的型号在用户选图后才适用。只对当前型号实际接通的扩展能力开放控件，用户明确选择的档位无法表达时要求重选。

仓内已有可复用的差异处理。例如 GLM 把公共声音开关写入 `with_audio`，xAI 写入 `generate_audio`。通义目录有具体的 `wan2.7-t2v` 行，不能仅凭 `wan2.7-*` 就给它开放另一个图生型号的图像输入。草案自己的 Veo 时长为 4、6、8 秒，§7.3 全局固定 5、10、15 秒按钮会给出三个无效选项。[GLM 适配器](../../backend-go/projects/gateway/internal/gatewaymedia/glm_video.go) [xAI 适配器](../../backend-go/projects/gateway/internal/gatewaymedia/xai_video.go) [通义目录](../../backend-go/projects/gateway/internal/pricing/catalogdata/qwen.json) [设计 §5、§7.3](../functions/演练场视频集工作台设计.md)

## 4. 开工前应补齐的结果行为

| v0.9 中的缺口 | 建议的可观察行为 |
| --- | --- |
| §4.1 只允许草稿发起生成，§7.2 在完成卡片提供「重新生成」 | 一个分镜可留下多次生成记录。点击「再生成一版」沿用原提示词、素材和参数，建立新的付费任务，旧版仍可在链接有效期内下载。双击同一次提交或网络重试只受理一次 |
| §4.4 按当前排序决定「上一镜」，§3.4 中尾帧又会过期 | 选择时固定来源分镜、结果版本和尾帧。重排或上一镜出新版后，既有草稿仍指向原选择。生成前提示失效，并保留其余编辑内容 |
| §4.1 批量遇到上限返回错误，§7.2 没交代哪些已受理 | 若保留批量，逐镜反馈已提交、需等待尾帧、达上限待提交或参数需修正。再点只提交尚未受理的镜头。第一版可先交付逐镜流程 |
| §7.2 对在途任务统一提供取消，§4.1 同一个删除动词还承担删除记录 | 按实际能力显示「取消生成」或说明「只能在本地取消，上游可能继续运行」。按钮明确提示结果。当前火山适配器只支持本地取消 |
| §3.4 将完成时间加 24 小时作为各家的统一失效时刻，状态靠客户端回来轮询 | 优先展示可信的上游有效期。仅有估计时用「预计有效，请及时下载」，无法确定时仍允许尝试播放或下载。鉴权、网络故障与已确认过期分别反馈；保留分镜记录，提供单独的再生成操作 |

相关证据见 v0.9 §3.3、§3.4、§4.1、§6、§7.2 及网关取消分支。[被审设计](../functions/演练场视频集工作台设计.md) [真实取消处理](../../backend-go/projects/gateway/cmd/juhe-ai-gateway/chain_media_video.go)

## 5. 定稿时可演示的五个场景

1. **空工作台出第一镜**。已有可用 Key，只填一句提示词，直接生成。刷新后找得到同一分镜，可预览和下载。请求没有图、音频或剧本，历史里只有一次受理记录。
2. **一张图，两种用途**。同一张图分别用作首帧、外观参考。核对请求角色和界面摘要。若选了互斥组合，在提交前展示冲突和改法。
3. **一段台词，三种选择**。在 2.0 只加音频时提示补视觉参考；在已接通的 2.5 音频参考模式能提交；切至仅做线下剪辑时仍可试听、下载，生成请求不带该音频。声音输入、输出开关及产物音轨分别核对。
4. **换模型不丢稿**。从带多参考的 Seedance 切到一个只接通基础文生的型号。提示词和素材仍在，不适用的选项明确标出，用户移出本次生成后可提交。切回可继续使用已有素材。用只有其他视频型号的 Key 也能完成纯提示词流程。
5. **连拍和再生成**。第一镜完成后用其真实尾帧开第二镜，随后重排分镜、给第一镜重生成一版。第二镜仍引用原画面。原文件过期后保持记录可见，新生成失败仍能查看旧记录。

本次核查基于 2026-11-22 工作区设计稿、现行前后端源码和火山方舟官方参数说明。取证入口为 CodeGraph、当前工作区文件和公开文档。当前工作台处于设计阶段，线框尚未经过页面可用性验证，亦未发起付费生成或取得口型、音色和画质样片。上述五个场景是验收建议。
