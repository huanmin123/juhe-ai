## 2. 成功成本治理

历史回填退出 maintenance PG/SQLite schema 和 jobs statsverify 的常规 ensure 路径。唯一执行者为 `--apply-success-cost-backfill`，用六表精确 TEXT 主键游标，每批最多 5000 行；批 UPDATE、谓词重判和 marker CAS 同事务。六 marker 完成后再次执行只读 marker，不查询事实表。

复审补正了四处遗漏：缺失 marker 也列入待办；SQLite dry-run/probe 只读打开且不创建主库或父目录、不改 journal、不写事实或 marker，并正常读取已提交 WAL；CAS/RowsAffected 失败回滚当前批并保留错误；维护窗口先停 jobs，再安装 maintenance、ensure 和回填，完成核验后才启动新版 jobs。SQLite 自身可能创建、更新或清理必要的 WAL/SHM 协调文件，本命令不主动 checkpoint，不使用会忽略 WAL 的 immutable 连接。旧写者回滚运行后完成态失效，再升级须在停写窗口重置六 marker 并完整重跑。

真实 PG 回填的最终结果：分钟表 240000 行、48 批，命中 239998 行；其余五表各 6001 行、2 批，各命中 5999 行。未命中的两行分别为混合错误行和已经等值的行，保留原值。最长批事务为分钟表 530ms，其余五表不超过 176ms。测量范围为 `BEGIN` 开始到 `COMMIT` 完成，包含主键扫描、UPDATE、marker CAS 和客户端往返，不等同于纯行锁持有时间。

真实扣减夹具从生产 schema 清单筛取六目标表及全部列迁移，验证 totals 与五桶的错误数归零补正、普通成功扣减、历史纯成功错行、混合行不补正、全零删除与事务回滚。SQLite 5001 行夹具在第二批注入真实失败，确认首批已提交游标保留、失败批回滚，重跑完成；预置 PG 游标的续跑测试另行验证游标读取，不把它作为实际中断证明。

## 3. 共享信封最终接线

F2 账户测试、F3 模型检测、F4 健康/恢复探针的最终 HTTP 请求由 `upstreamenvelope.Build` 构造。三形态保留不同契约：A OAuth Codex 强制 SSE、`store:false`、无预算；B `codex_responses` 兼容画像保留预算，并使头/body 使用同一身份；C 普通凭据保留探针族语义输入。B 不适用 F3。

集成补正包括 F3 `Suite → Options → Spec` 的 profile/credential type 传导、已提供身份的单源补齐、共享 A 形态在 extras 后强制 SSE Accept，以及 A 只按 SSE completed 终态评分。F4 增加与 F2/F3 一致的可替换 HTTP 依赖边界，支持实际入口 Mock 捕获，不通过真实上游网络测试固定 Codex URL。

Mock 跨面比较声明排除提示词、样本、随机身份字面值和探针预算数值，分别检查这些面的内部不变量。C 的 `store` 是已声明的语义差异（F3 false，F2/F4 缺省），A 的 store/stream 是必须相同的共享不变量。GLM 三 base、Gemini profile、Interactions revision、音频 multipart、Lite 头与错误路径由相应调用面回归覆盖。

## 4. 表监控读取结构

PostgreSQL 概览先选择各组最新快照的窄 `id`，物化后按主键读取几百行宽字段，再排序分页。总数仍从窄角色/表名分组计算。复用既有最新索引和主键，没有增加应用缓存、索引或持久投影；SQLite、采样频率与保留期未改变。

真实测试对照迁移前 SQL，并以独立预期验证空库、同时间 ID 决胜、未知角色、NULL、跨角色同名表、关键词转义和分页。性能子集为 300000 行、400 个表键，另有 15 行小夹具（合计 300015 行、414 个键）；数据库快照性能子集为 3750 行，含小夹具合计 3754 行。表 relation 含索引为 144334848 字节，约 137.6MiB，明显小于历史生产观察的 2.2GB。

| 场景 | 新读取 p95 | 旧读取 p95 |
| --- | ---: | ---: |
| 首页，更新前 | 81.10ms | 111.53ms |
| 关键词，更新前 | 202.15ms | 未测 |
| 最新行更新后首页 | 87.50ms | 112.09ms |

每项为单连接、20 轮、pageSize=50、暖态的 `loadOverviewPostgres` 调用，包含三条 SQL 和 DTO 组装，没有应用缓存；不是 HTTP 延迟或生产首屏。所有已测场景达到隔离验收 p95 < 1 秒。原始 SQL、执行计划和样本见 `reports/tablemonitor-overview-pg-2026-10-12.json`。

计划仍扫描历史窄索引再按 414 个最新 ID 回表；关键词可选择并行 Seq Scan 与窄排序。更新前 index-only 阶段 Heap Fetches=0，更新后为 16805，不能保证零 heap fetch。单条带 instrumentation 的 EXPLAIN 耗时 810.091ms 与调用 p95 分开统计，不据此推断线上 577 秒已经消失。

tablemonitor 单元覆盖率 95.9%，真实 PG 验证通过；独立只读复审未发现查询语义 blocker，提出的测试格式和测量口径已修正。隔离表监控库与 profile 已清理。
