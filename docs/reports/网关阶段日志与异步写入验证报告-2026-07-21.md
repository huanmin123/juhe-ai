# 网关阶段日志与异步写入验证报告（2026-07-21）

## 验证结论

- 网关请求已能按同一 `traceId` 重建“入口 -> 分组权限 -> 客户端画像 -> 候选账户 -> 模型能力 -> 账号运行态 -> 配额/容量 -> 上游派发 -> 下游响应”的阶段时间线。
- Node 文件/控制台日志使用有界双优先级队列和独立 writer worker；批量消息、批量文件写、失败预留容量、worker ACK、关闭 drain、轮转清理和 runtime-log line 回传均有回归证据。
- Go 日志使用有界异步 `slog.Handler`，HTTP 入口统一关联 `traceId/requestId`；Node HTTP、DB service IPC、worker 和 Go HTTP 共享 `version/service/role/event` 基础字段。
- 最终 5 秒、并发 10、mock 上游 5ms 的 info 压测结束时：`pendingEvents=0`、`pendingBytes=0`、`normalDropped=0`、`failureDropped=0`、`destinationErrors=0`。
- 热请求本地路由链路不是当前主要耗时来源；上游派发阶段 p50 20ms、p95 36ms。preflight 热路径 p50/p95 均为 1ms，但冷启动样本最大 1373ms，后续生产复现慢请求时应先区分冷启动、缓存构建和真实存储访问。

## 环境与范围

- 本机：Windows / Node.js 22 / pnpm，SQLite + memory 单机 mock 网关。
- 请求：`POST /v1/chat/completions`，8 个 mock 账户，并发 10，上游固定延迟 5ms，metadata-only 审计。
- 真实依赖：`192.168.1.203` 测试 PostgreSQL 与 Redis cache/state/queue；连接串只从本机密码文件临时注入，未写入代码、文档或 Git。
- 未调用真实模型，不产生模型额度费用；未执行生产部署、重启或切流。
