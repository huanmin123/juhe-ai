# 网关阶段日志与异步写入验证报告（2026-07-21）

## 当前结论

- 网关请求已能按同一 `traceId` 重建“body 接收/捕获 -> handler -> 分组权限 -> 客户端画像/协议 -> 候选账户 -> 模型能力 -> 账号避让 -> 配额/容量 -> IP/账号并发 -> 上游准备/fetch/首输出/body -> 下游 finish -> audit finalize”的阶段时间线。
- Node Pino 在主线程完成字段组装和 JSON 序列化，再通过异步 `fs` stream 将完整 JSONL 顺序追加到角色日志文件。角色文件是 runtime-log 的唯一 durable spool；Node 主日志不采样、不按索引队列丢行。
- `ingest-worker` 是唯一 runtime-log consumer：按 file identity + truncation generation + byte cursor 有界读取当前及轮转文件，批次索引成功后才推进 cursor。业务进程不做 runtime-log `JSON.parse`、hash、Redis XADD 或 IPC line 回传。
- Go 日志使用 normal/failure/emergency 三类有界异步 `slog.Handler` 通道。failure 与 emergency 同时饱和时不阻塞业务，累计 `failureDropped`，并在 drop summary 中保留最后一条有界现场；这不是“每条失败永久无损”的承诺。
- merged tree 最终 r12：5 秒压测 + 1 秒预热、并发 10、mock 上游 5ms，共 1,535/1,535 成功，QPS 306.16、p50 27.375ms、p95 90.740ms、p99 103.926ms、CPU/request 0.8958ms、event-loop p99 78.512ms；error/drop 均为 0。

## 失败现场

- mock 上游 100% 错误的 failure r2 返回 HTTP 503。日志保留 42 个已执行阶段和 4 次上游尝试；`upstream.dispatch.failed` 为 `expected_failure`、`reasonCode=upstream_accounts_exhausted`，`audit.finalize` 保留 `statusCode=503`、`errorPhase=dispatch`、`errorCode=upstream_retryable_error`、`attemptCount=4`。
- 不可预知 Node 异常同时写 `gateway.request.stage` info 和 `gateway.request.failure` error，现场有界保留 Error/cause/stack、阶段摘要和队列/重试快照。
- Go failure 先进入 failure lane，再进入 emergency lane；两者同时满时只保证 `failureDropped` 累计值和 `lastFailure` 有界快照最终出现在 `system_log_drop`。此退化边界由饱和测试固定。

## Runtime-log 架构与门禁

当前唯一架构：

```text
Node Pino role logger -> role JSONL durable spool -> ingest-worker file cursor consumer -> SQLite/PostgreSQL runtime_logs
Go slog -> bounded normal/failure/emergency lanes -> configured Go log destination
```

明确不存在：runtime-log Redis Stream producer/consumer、主进程逐行 parse/hash、IPC line 回传、`AsyncLogPublisher` 或独立 writer worker 可丢主日志的旧路径。Redis 仍服务使用记录、审计、操作日志和公开接口等其他事实队列。

最新 master 合并后的验证证据：

- Node `pnpm typecheck`：通过，exit 0。
- Node `pnpm build`：通过，exit 0；仅有既有 Vite 大 chunk 告警。

- Go `go test ./... -count=1`：首次因 migration schema 名硬编码失败；修复根因后通过，exit 0。
- Go `go vet ./...`：通过，exit 0。
- 网关 timing、关联失败现场和 Go failure/emergency 专项回归通过。
