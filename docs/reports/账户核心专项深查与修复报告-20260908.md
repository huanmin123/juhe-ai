# 账户核心专项深查与修复报告（2026-09-08）

## 1. 背景与范围

用户指令：网关调度、AI 账户管理、探活、协议支持/转换/映射、账户状态——围绕 AI 账户的全部核心机制做最深一轮排查。基线 `3f524b4ee`（含用户并行会话的探针对齐三连提交与模型匹配大小写提交）。

方法：5 个只读代理与 Node 归档做**行为级**比对（调度决策矩阵 / 状态机与 Key 池 / 探活全家 / 协议层 / 去跨进程新缝与耦合不变量），主代理再做两轮独立全仓扫描交叉验证。发现以 `docs/bug/问题-0174-账户核心专项深查缺陷清单.md` 总册立案：**5 blocker + 10 major + 12 minor**。

## 2. 深查结论（修复前）

核心三环都存在真伤，其中两项让「失败→冷却→重测→恢复」这一账户生命周期主循环处于断裂状态：

1. **Key 指纹算法分裂（B-1）**：调度链用裸 sha256，其余四处用 HMAC(secret,key)——失败路径的 Key 级状态写全部静默落空。
2. **ENGAGED 锁运行链空实现（B-2）**：管理面状态机完整但组合根从未接线，恒「视为未锁」。
3. **Key 轮转策略族缺失（B-3）**：无 failover/round_robin/weighted，恒选第一把可用。
4. **跨协议转换器未移植（B-4）**：映射许可表放行但 body 不转换，配置了转换的账户必然上游 400。
5. **裸 /v1beta/interactions 不识别（B-5）**。
6. **探活恢复闭环断裂（M-1，三代理交叉证实）**：J1 outcome 只写 jobs 库，业务 accounts 行无人投影——冷却成功账户停留 temporary_unavailable 无法回归轮换；57535d3ad 的恢复尊重时间计划无继任。
7. **skipAccount 作用域错误（M-2）**：一坏账户带崩整组。
8. 协议认证头三处不符（M-4/5）、Gemini 错误体弱化（M-6）、池隔离谓词三层不一致（M-7）、创建路径后链缺失（M-8，同时导致新建账户对探活不可见）、运行态键双格式（M-9）、fence 结算断裂（M-10）等。

同时确认了三类**一致**面：调度决策矩阵（失败派发真值表/错误策略叠加/流式分叉/turn-avoidance）逐格对齐；探针执行（endpoint mode/头/代理档案/超时梯）与三个并行对齐提交全部有归档依据；J1 调度/CAS/队列/电路六域语义一致。
