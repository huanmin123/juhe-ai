# Node 到 Go 迁移从头复查报告（2026-09-06）

## 1. 背景与目标

迁移本体与 Node 归档完成后（基线提交 `b6fbefbe6`），用户要求「环境从头开始的复查」：是否遗漏、结果是否与 Node 一致（不要求代码语义相同，但结果必须一致）、以及质量把控。复查以七条迁移规则为准绳：

1. Node 单线程时代的人为并发限制在 Go 中应放宽（设很大值）；
2. Node 写法不必拘泥，Go 惯用方式优先，业务结果一致即可；
3. 迁移必有熵增，需反复核对反复测试，防「自信无问题、实际偏移大」；
4. 代码质量优先：复用、公共模块、设计模式，降重复与维护成本；
5. Node 有缺陷的写法不必忠实复刻，结果一致即可；
6. 最重要：禁止 Node 调 Go、Go 调 Node 及跨进程调用；
7. 单一职责、高内聚低耦合，单文件不揽多事。

## 2. 方法与规模

三波多代理并行（编排遵循 `orchestrate-model-workflow`，全部在 master 工作区、未建分支）：

- **取证波（8 个只读代理）**：跨进程调用审计（规则 6）、并发限制盘点（规则 1）、HTTP 路由完整性、后台任务完整性、服务/共享/领域层映射、质量审计（规则 4+7）、前端调用面 vs Go 路由面跨端一致性、配置完整性。
- **核验波（3 个只读代理）**：对 17 份「待修复」在案缺陷做当前态三值裁决（文档写于迁移期，部分子项已修但状态未同步，不能照单全收）。
- **修复波（9 个写入代理，写入范围互不重叠）** + 主代理集成验证 + 1 个独立复审。

基线核验：HEAD `b6fbefbe6`、工作树干净、三模块 build/vet 全绿。

## 3. 结论总览

- **运行时活代码不存在任何 Node↔Go 互调或 Go→Node 调用**（规则 6 核心，事实级确认）；存在少量编排/部署层残留与一处需裁决的 Go↔Go 无签名只读调用（见 §7）。
- **管理面曾存在 8 类「前端真实调用、Go 无路由」的用户可感知断裂**（公告公开面、设置分区、授权用量聚合、Key 池重验证、代理测试、管理面授权归还/用量、账户草稿测试-后勘误为已存在、模型检测主入口路由-属部署域）。本轮修复了其中全部迁移职责内的部分。
- **在案 17 份开放缺陷**经当前态核验：10 份代码层已修复（仅文档状态滞后），本轮再修复 5 份，剩 2 份为「修复中」（0162/0165 各有明确剩余项与裁决依赖）。
- **规则 1 落地**：放宽 6 处 Node 时代收紧默认值（探针并发 8→512、jobs PG 池 8→50、用量收尾并发 32→5000、Codex 分片 4→16、chat 会话上限 30→50+SSE env 恢复）；B 类「仍有业务意义」限制清单化保留（上游保护、防雪崩、安全阀）。
- **配置面**：补齐 5 项生产安全门禁（secret 强度、cookie secure、dev-autologin 禁用、CORS 接线、log 越界 fail-fast）+ 删除 1 组死配置（QUEUE_DRIVER）。
- **质量（规则 4+7）**：完成审计与排序（大文件 top30、跨项目重复热点、schema 多拷贝无机器对账），本轮只做零星修复，结构性重构登记为后续独立波次（见 §8）。
