## 3. 质量门

### 3.1 每工作包门禁

- 每个 WP 交付固定节奏：实现 → `go build`/`go vet` → 包级 `go test`，关键包加 `go test -race` → 主 Agent 统一复验后逐包提交登记。 golden 先录制后实现（G0），测试/文档/复查与实现四线并行。
- 移植即对照：每包以 Node 源码为行为参照逐项对照路由、鉴权、DTO、副作用与失败路径；中文编码、时钟冻结、revision 递增、单位混淆等移植缺陷在包内即发现即修（例：M04 中文双重编码、P04 ms/ns 混淆致授权码 born-expired、G02 tier 正则）。

### 3.2 审计修复循环（双重确证协作模式）

- **审计线一**（`docs/plans/计划-20260904T071852927Z-已提交Go迁移功能审计与缺陷修复.md`）：范围 af841ce7..M08（K1-K7、S-SQ、S-PG、M01、M03-M08），产出 `docs/bug/问题-0152` ~ `问题-0171` 共 20 份逐项缺陷登记，修复随切片提交。
- **审计线二**（`docs/reports/Node-Go迁移独立审计报告-20260905.md`）：覆盖 M09 后全部波次与宏观完整性矩阵；15 个子代理（8 取证 / 6 独立复核 / 4 写入 / 1 终审），双重确证并修复 9 类缺陷（授权配额 fail-open、调度默认值偏离、team 授权实例跨成员可见、accounts 列表授权过滤、ipstats SQLite 数据源错位、ipstats detail 水合、操作日志 VisibilityScope 回填、pricing 文档失真、误导性文案），独立终审 7/7 PASS；确证未修复项登记 `docs/bug/问题-0172`（T1-T9，其中 T1/T4/T5 已随后续切片修复）。
- **逐包审计记录**：`docs(K1)/docs(K4)/docs(K6)/docs(K7)/docs(M03)/docs(M08)` 等大量独立提交逐包记录候选偏差与复核结论，可按提交历史追溯。
- **X05 端到端验收**：acceptance 黑盒套件（fresh SQLite 启动/认证流/管理面 CRUD 八域主干/公开面 OIDC+PKCE/网关链/chat/jobs 冒烟+PG 门控变体）发现 4 个真实产品缺陷（F4 操作日志租约自毁、seed 管理员密码哈希不兼容、`account_model_mappings` 复合主键漂移致 `/v1` 全量 500、jobs `/health` 字段错位），全部修复后全套 66s 全绿。

## 5. 已知遗留与平台侧待办

以下各项均有代码或文档证据，按影响排序；它们不阻塞 go-only 运行，但属于如实登记的边界（X06 收场时点快照；2026-09-06 审查即修复五波后其中多项已解除，逐项终态见 §8.3）：

1. **hybrid 混合智能路由协作者未全装配**：`gatewayhybrid.AuxiliaryDispatcher`（辅助派发端口）在组装根无赋值；Redis 模式下仅装配 `SharedJSONCache`（`gateway:hybrid-scoring-result`）与 `RuntimeStateStore`（`gateway-hybrid-route-affinity`）两个协作者（`cmd/juhe-ai-gateway/chain_runtime.go`、`chain_compose.go`）。纯路由评分/亲和主路径可用，辅助派发语义未激活。
2. **PG 统计扣减链显式报错**：`jobs/internal/cleanuprepo` 的 api-key/account retry 扣减链仅 SQLite 生效，PG 模式显式报错登记（提交 `20e033ec4`），不静默跳过。
3. **限流 Redis 拓扑等价继承**：Go 两级限流沿用与 Node 相同的共享单实例 Redis Lua 多桶键空间（PLAN.md K3/G07 行；迁移期与 Node 互通验证），未引入集群化扩展。
4. **WebP 有损编码待决策**：chat 图片管线预览编码为自写 VP8L 无损 WebP 编码器（`cmd/juhe-ai-gateway/chain_chat_images.go`，`x/image/webp` 仅解码器故自研；round-trip 验证过）；有损编码（体积更小）未实现，是否引入待决策。
5. **table-monitor 非业务数据 cleanup POST 未移植**：W6 记录约定该写操作 Node-owned（gateway 无 record-maintenance worker channel，见 `internal/tablemonitor/store.go` 头注与 `compose.go` 挂载矩阵注释）；Node 归档后该 POST 返回 404，属显式接受的降级。
6. **jobs 11 项 go-partial 显式登记**：3 个 scheduled job（account-circuit-control-plane-maintenance、account-list-availability-projection-maintenance、account-circuit-recovery）缺 Redis CircuitStore 等跨模块依赖未接线（`cmd/juhe-ai-jobs/worker_partial_jobs.go` 缺口清单，启动日志与 `/health` 可观测，硬门禁保证不进调度循环）；其余为队列 IPC 按计划消灭与网关域单实现依赖登记。
7. **问题-0172 未闭项**：T2（OAuth 轮换/账户写路径 inval 未注入、跨进程失效协议不兼容——go-only 下影响降级为 Go 自身缓存失效缺口）等按 `docs/bug/问题-0172-第三方独立审计M09后迁移缺陷清单.md` 跟踪。
8. **平台侧待办**（不在本仓库内，见 `docs/migration/部署go-only双轨开关.md` §6）：平台仓库（k8s-juhe）overlay 仍声明 `juhe-ai` Node 容器，需切 go-only 双容器拓扑后 Jenkins `'-'` 哨兵才与运行态一致；owner lock（`run-with-owner-lock.mjs`）无 Go 等价包装，go-only 下该保护被启动脚本显式拒绝；`docker/compose.performance.yml` 的 go-only 高性能变体未落地；主机侧如有 PM2/systemd 生态文件需改为直接拉起两个 Go 二进制；Mac LaunchDaemon / 八台 Edge 常驻定义在 `.local/project-resources/prod/` 私有资料中。

### 8.3 装配断线系统性模式（教训与门禁建议）

六波审查反复命中同一类缺陷：**包级交付绿不等于运行接管成立**。实例均有提交证据：

1. T6（问题-0172 原文）：jobs 九包「代码归属成立、运行接管不成立」——`jobs/internal` 九包无非测试 import，组合根未装配；
2. V2（`e8ff71490`）：`PrepareAPIKeyGroupFallbackDispatchContext` 全仓无调用者——多分组回退整条链是死代码，包级测试却全绿；
3. F 系列（`96606f901`）：TrafficRuntimeMigrator 未接线（「迁移流量」只改状态）、settings 驱动调度间隔断线（8 个 job 不消费设置）、port 契约缺 ExcludedAccountIDs 字段——组合根装配、配置消费、契约字段三层各自断线；
4. D1（`4a78f7008`）：engine 的 RetryUpstream 结果在 `/v1` 链无消费——换号循环/排除集维护/耗尽 503 出口断线（`chain_v1.go` 接线+`chain_v1_retry_test.go` 补链路测试）。

共性根因：port/适配器在包内以 mock 或 nil port 通过测试，组合根（`compose.go`/`worker_assembly.go`）不在任何包级测试覆盖内，「实现存在」与「请求可达」之间缺少断言。门禁建议（部分已在收口波兑现，供后续维护沿用）：

- port 必须有组合根消费证据，或显式 nil 登记（nil 安全+装配口径，如 runtime-reset「6 装配 3 登记」）；
- 切片收口前对关键导出函数做全仓调用者检查（V2 模式的 grep 断言）；
- jobs 侧 `scheduleWiredJob` 硬门禁：非 GoWired 不进调度循环，启动日志与 `/health` 可观测（`worker_partial_jobs.go`，已兑现）；
- acceptance 黑盒覆盖接线后的路径（如双分组回退 e2e，`e8ff71490` 已兑现）；
- 配置消费边界测试（settingsNumber 边界族，F3-1 修复时成文）。

### 8.5 第六轮 P0 transport 生命周期缺陷（2026-09-06，`73ace1f4d`）

- **缺陷**：`gatewaydispatch/transport.go` 的 `RequestUpstream` 以 `defer requestCancel()` 在函数返回时取消上游请求上下文，超过传输内部缓冲（约 4KB）的响应体在调用方后续 `Read` 时报 context canceled——所有大体积响应与长 SSE 流被截断；既有小响应体测试全部通过，缺陷被掩盖。
- **发现渠道**：G16 failure-dispatch 接线（`4a78f7008`）的端到端代理测试上报，非 2xx+SSE 与大数据量场景在真实传输路径复现截断。
- **根修方式**：对齐 Node 语义（headers 到达只停相位定时器，`responseReceived` 自守卫已存在；request handle 在响应结束时销毁）——cancel 所有权从 `RequestUpstream` 栈帧移入 body 包装器 `newSlotReleasingBodyWithCancel`：EOF/Close 时 `cancelOnce`+`releaseOnce`，错误路径显式 cancel。
- **回归测试**：`TestRequestUpstreamLargeBodyReadableAfterReturn`（64KB 响应体返回后完整读取）与 `TestRequestUpstreamSSEStreamReadableAfterReturn`（40 事件 SSE 流返回后全量消费）入 `transport_test.go`，修复前两者必截断。
- **transport 遗留登记**：组合根 `chainFailureDispatcher`（`cmd/juhe-ai-gateway/chain_ports.go` 头注）暂不挂载两类需协作者的深分支——codex encrypted-content compatibility recovery（`retry_with_compatibility_recovery`，engine 端口已在 `attemptoutcomes.go` 消费）与账户错误策略服务（Node `decideAccountErrorPolicy`：explicit_policy failureKind/keyScoped 策略动作/请求失败健康检查派发）——组合根接线待续，显式登记为缺口。
