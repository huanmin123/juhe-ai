# 计划-20261003T065859991Z：模型检测窗口聚合/预聚合管线

- 计划 ID：PLAN-20261003T065859991Z

- 需求来源：BUG-0273 残余登记（运行期投影批次的 deferred 项）；BUG-0277/BUG-0278 同轮全量排查后的立项裁决
- 执行者：待主代理排期指派

## 需求目标

把模型检测 Token 诚信与身份维度的证据源从"单 run 运行期投影"升级为设计文档定稿的"窗口聚合/预聚合管线"：gateway 进程内模型检测 owner 域按已确认游标增量消费 observation，写入 7 张只预置了 schema、当前没有任何 Go 写入方的 stats 预聚合表；TrustReport 与读侧（API / repository / 前端详情页）切换为只读预聚合结果，不再依赖单 run 证据，也禁止实时扫描 observation。

当前的有界偏差（BUG-0273 修复批次登记）：`usage_integrity_status` 只来自单 run 运行期证据，不是跨 run 窗口累计；Token slope / intercept 置信区间、固定 intercept 基线、身份特征与 paired 距离的窗口预聚合缺失。

## 目标契约（权威文档）

目标语义已在 `docs/functions/模型检测设计.md` 定稿，本计划是实现该契约，不新造语义：

- §15.3（:739）：owner 域按 `(created_at, id)` 游标增量刷新 Token 窗口、固定 intercept cohort 版本、按独立上游桶塌缩的身份特征、LOO median / MAD / 分位基线、paired 距离和账号 latest。
- §15.9（:953）：目标形态=所有窗口由 owner 域按已确认游标增量构建；API、repository 查询和前端页面只读最新预聚合结果，禁止实时扫描 observation、模型检测明细、审计日志或 usage shard 聚合；读侧只 merge latest。
- §15.9（:955）：7 张 stats 表清单——`model_token_integrity_windows`、`model_token_integrity_rounds`、`model_token_intercept_baseline_versions`、`model_trust_window_sources`、`model_identity_source_features`、`model_identity_baseline_versions`、`model_paired_similarity_windows`——已预置 schema，属窗口预聚合待补批次的目标表（另有 `model_account_trust_results` 的 latest 投影已落地）。
- §15.9（:959）：固定 intercept 聚合到 `model_token_intercept_baseline_versions`，上游桶折叠、`calibration_pending` 版本、`strong_gate_enabled` 恒 0、离线校准入口切 `active` 的语义。
- §15.8.3：校准前阈值不得宣称"可稳定检测 5% 灌水"，阈值转产品阈值前必须经诚实 mock 与比例灌水样本校准。

## 范围边界

### 范围内

1. gateway owner 域增量 worker：按 `(created_at, id)` 已确认游标增量读取 `model_check_observations`（dataset 库），驱动窗口预聚合。
2. 7 张 stats 表写入器：`model_token_integrity_windows` / `model_token_integrity_rounds` / `model_token_intercept_baseline_versions` / `model_trust_window_sources` / `model_identity_source_features` / `model_identity_baseline_versions` / `model_paired_similarity_windows` 的 UPSERT / 幂等写入与游标、receipt 事务边界（对齐 owner 域既有 projector 模式）。
3. TrustReport 证据源从单 run 切窗口：详情面分项证据改由窗口预聚合结果合成，单 run 运行期投影降级或保留为兜底（切换方式在实现时按设计文档 §15.3/§15.9 裁决并回正文档）。
4. 阈值口径裁决（0.8 vs 0.5）：窗口切换后相关阈值取值口径需裁决（当前文档/代码均未固化该口径），裁决结论必须回正 `docs/functions/模型检测设计.md`；校准前不得输出强结论（`strong_gate_enabled` 恒 0 语义不变）。
5. 读侧切换：模型检测详情 API / repository / 前端详情页改为只读 `model_account_trust_results` 等预聚合结果，窗口证据在详情页可见；不扫描 observation。
6. retention 登记更新：`backend-go/projects/maintenance/internal/j3bmodelcheck/inventory.go` 的 `LegacyFactRetain` 登记（:152-157 六表：`model_token_integrity_windows` 等）在 Go 写入方就绪后更新 disposition 与 `RetentionWhy`。

### 非目标

- 不改探针执行链：检测 run 的发起、探针执行、评分、处罚恢复、调度链路全部不动。
- 不新增 observation 字段或 schema 变更（7 表 schema 已预置；如实现中发现 schema 缺口，先回设计文档裁决再另批处理）。
- 不做历史存量 observation 的离线回填（窗口从启用后的增量开始累计；是否回填另行裁决）。

## 风险与注意事项

- 窗口聚合是统计口径变更：切换期间新旧证据源并存可能造成详情页数值跳变，需在切换批次明确过渡语义。
- 身份维度证据已随通用套件 v5 退役（§15.3），窗口管线不得复活七类 canary 证据或评分。
- 校准前不得宣称检测能力（§15.8.3）；强判开启必须走离线校准入口。
- owner 域为 gateway 进程内职责，禁止把窗口 worker 放进 jobs 进程（与现行架构基线一致）。
