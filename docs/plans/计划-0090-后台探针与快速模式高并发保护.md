# PLAN-0090 后台探针与快速模式高并发保护

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 消除冷却复测头部阻塞，并让“普通路由 + 快速模式 + 高并发分组 + 大上下文”在保留有界等待语义的同时，不堆积完整请求体、不发生无目标切号和额度并发超发。

**Architecture:** ops-worker 冷却复测使用有界复合游标补充队列，任何非完整成功结果都写失败退避并推进下次时间。网关在 `preResolveGatewayRuntime` 之后、`express.raw` 之前对 `normal/speed_first` 高并发分组发放轻量入场租约，等待请求依靠 TCP backpressure 保留在客户端。确认慢切号前同时申请路由级迁移预算和目标账号真实并发槽；请求派发前根据模型价格和请求规模原子预占 API Key 在途成本。

**Tech Stack:** Node.js 22、TypeScript、Express、SQLite/PostgreSQL、Redis runtime state、现有账号并发槽、retry queue、模型价格和额度快照。

---

## 问题证据

- 生产库曾有 246 个已逾期冷却账户，目标账户逾期数小时仍为复测 0 次。
- 冷却查询固定按 `cooldown_until` 取头部小窗口；`accountFailureEligible === false` 时不更新 `cooldown_until`，同一批账户每轮重复占位。
- 网关先由 `express.raw` 读完请求体，后在 dispatch preparation 中进入高并发队列；队列元数据轻量，但请求调用栈仍持有 `rawBody`。
- 首字 deadline 回调只确认“剩余候选存在”，即中止当前上游；没有在中止前保留替补账号并发槽。
- 当前 API Key 额度只读后台统计快照并带 5 秒缓存，没有在途请求成本预占。

## 确定边界

- 后台系统探针只认完整成功与失败；状态码、错误码和错误分类只用于日志和展示。
- 普通用户请求仍保留本地参数错误边界，不因用户发错 JSON、模型名或上下文超限直接写坏账号。
- 入场排队只对 `normal + speed_first + high_concurrency` 生效；个人分组、成本优先和其他路由模式不变。
- 入场容量按当前分组唯一并发事实账号的硬并发上限求和；队列总量、单 Key 上限和等待时间继续使用分组策略。
- 确认慢切号共享预算固定为同一 `系统账户 + 路由策略 + 分组 + 慢账号` 同时 2 个迁移，不新增用户配置。
- 在途成本使用 `ceil(rawBodyBytes / 4)` 估算输入 token；输出 token 优先读 `max_output_tokens/max_tokens`，缺省按 4096；无定价模型不伪造成本。
- 在途预占在响应结束后延迟 65 秒释放，覆盖生产 60 秒统计快照窗口；进程退出时请求也同时结束，本地在途状态可清空。
