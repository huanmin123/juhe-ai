## 5. 裁决点

### 裁决点 1（已落定 2026-10-10：方案 A）：生图最终图片 URL 的安全策略

[BUG-0296 档案](../bug/问题-0296-DialGuard装配条件恒假连接层SSRF纵深从未生效.md) 的待处理要求：明确生图最终目标的安全策略，并在代理请求发出前执行目标校验；代理地址的合法性不能替代最终目标校验。

**用户裁决（2026-10-10）：采用方案 A**——在生图 URL 下载发送前，用部署级 `URLSecurityConfig`（与 `/v1` 链 `UpstreamURLSecurity` 同源的配置面，含 `JUHE_AI_ALLOW_PRIVATE_UPSTREAM_BASE_URLS` 私网放行裁决）对最终图片 URL 主机做解析校验；HTTP(S) 代理与直连一致执行；SOCKS5H 远端解析场景的本地预检为 best-effort，剩余的解析偏移窗口在问题档案与部署文档如实登记（不宣称消除）。

原候选方案（存档）：

- 方案 A（已采纳）：见上。理由：与 `/v1` 链同一配置面、同一 guard 实现，行为一致可解释；改动集中在下载入口一处；部署侧已有私网放行开关承接"合法私网目标"场景。
- 方案 B（未采纳）：仅拦截私网/保留段字面量与 localhost，不做 DNS 解析校验。改动最小，但域名形态目标可绕过（解析结果不校验），防护强度低于直连路径既有水平。
- 方案 C（未采纳）：维持现状（只校验代理主机）。即接受外部复审问题 1 永远处于"部分修复"状态。

### 裁决点 2（已落定 2026-10-10：改法二）

`usagewriter.Writer.Enqueue` 在队列满且溢出落盘失败时返回 nil，与 `usagespooldrain` 的"返回 nil 即已接收"契约冲突。改法两选一，实施时按最小改动定，验收一致：

- 改法一：`Enqueue` 对"队列满且溢出落盘失败"统一返回错误（全局契约收紧）——须先盘点全部调用方确认无依赖"nil=终态丢弃"的既有行为。
- 改法二：为 durable 交接提供可区分的接收端口（drain 专用），writer 面向其他调用方的 best-effort 语义不变——符合档案"不在本次任务中裁决所有 writer 调用方"的排除边界，默认倾向此改法。

落定依据（实施前调用方盘点）：`Enqueue` 生产调用方恰为两类——两条 durable replay drain（gateway spool 与 overflow replay，共用 `usagespooldrain.Enqueuer` 窄口）与探针旁路补记（`worker_health_usage.go:75`，失败仅 Warn、无重放源、无依赖 nil 的分支）。按改法二落地：新增 `EnqueueDurable` 端口并切换 drain 接口，`Enqueue` 一字未动，探针路径零变化。
