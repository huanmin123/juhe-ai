# 帮助中心可视化与字段级指南计划

- 目标：将普通用户与管理员静态帮助页从页面索引升级为可查阅的字段级操作指南，用可交互 SVG 说明请求链路、配置作用域和排障顺序。
- 授权：实施 `frontend/public/help/` 静态帮助内容、样式、无依赖交互、回归测试与对应维护文档；不修改业务路由、接口、账户数据或生产配置。
- 范围：用户手册、管理员手册、共用帮助样式/脚本、帮助内容回归、使用手册页面设计文档。
- 非目标：不公开 API Key、OAuth token、上游凭据、代理密码或原始审计内容；不把内部客户端画像、协议桥接实现或未暴露配置伪装成用户可操作项。
- 背景与依据：现有帮助页已经覆盖深链和导入契约，但主要以概述和列表呈现，无法让用户理解字段的输入、默认行为、影响范围和失败后果。当前前端表单与校验是字段含义、取值范围和运行行为的事实来源。
- 硬约束：保持 `/__aisys__/help/*` 既有路由、CSP（无内联脚本/事件）、搜索、跳转链接、键盘可访问性、移动目录和现有回归契约；不引入运行时依赖。
- 风险：中。帮助文案一旦偏离实现会误导配置；通过源代码字段核对、回归断言和浏览器交互验证控制。
- 回滚：恢复 `frontend/public/help/` 与帮助回归/维护文档的本次改动即可，不涉及数据或服务端状态。
- 验收：两份手册均有字段级参考、可点击 SVG 流程图、所有角色可见路由深链、清楚的范围/风险/排障路径；桌面和手机可读，搜索和流程交互可用。
- 验证：`pnpm.cmd --filter juhe-ai-frontend test:help-content`、`pnpm.cmd --filter juhe-ai-frontend typecheck`、`pnpm.cmd --filter juhe-ai-frontend build`，以及隔离本地帮助页的桌面/手机浏览器检查。

## 设计决定

1. 内容按“做什么、填什么、何时生效、会影响什么、失败先看哪里”组织，不复制内部设计文档或仅给菜单摘要。
2. 流程图采用内联 SVG：每个节点保持可聚焦，和上方步骤控件共用状态；选择节点后在图下显示该层的职责、输入/输出、实际影响和下一跳。
3. 字段参考采用原生 `details`，避免默认把所有解释挤成长页，同时保留全文搜索和无 JavaScript 时的可阅读性。
4. 管理员页提供完整管理路由索引；高风险配置额外写明作用域、前置条件和观察/回滚路径。
