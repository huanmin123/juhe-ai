# J3a 代理延迟检测 L2 实现

> 计划 ID：`PLAN-20260821T004304961Z`
> 创建时间：2026-08-21T00:43:04.961Z
> 状态：历史 L2 计划快照；当前实现已完成一次性 Go owner 接线。Node scheduler、旧 executor、Node projector 和 Node J3a writer 已删除；后续仅执行 Go owner 的外部 handoff/L3-L4 门禁。

目标是在当前迁移记录中保留 J3a 独立 Go jobs Store、直接代理探测、PostgreSQL 只读输入和 Go result projector 契约。范围不含 J3b/J3c、账号复制、生产部署或 GitOps owner 变更；Node outcome projector 仅为历史设计，不是当前运行路径。

实现顺序是：先完成独立 Go `proxylatency` 域与 SQLite/PG jobs Store 单测；再接入 PostgreSQL 只读候选、Go result projector、手动 bridge 和 owner gate；最后执行 Go/Node adapter 回归。真实 dev PG/PgBouncer/Docker/Redis、Node -> Go manual 进程闭环和 Jenkins/GitOps 是后续 L3/L4 门禁，不作为本计划完成的替代证据。

本批 runtime readiness 约束：仅 `JUHE_AI_PROXY_LATENCY_ENABLED=true`、`JUHE_AI_PROXY_LATENCY_JOBS_OWNER=go` 且配置完整时启用；jobs Store 固定 PostgreSQL，业务输入固定 PostgreSQL 只读事务。runner 顺序为 owner lease → LoadDue → IssueInput → proxy lease → ExecuteIssuedInput；owner lease 续租失败或 fence 丢失立即停止周期，proxy lease 的持久化 `lease_until` 与 issued expiry 共同限定实际 execution context，不能按配置 duration 重新放大，代理失败记录到健康状态且失败周期不 ready，取消时停止并释放 lease。默认关闭不会连接数据库。

Header 模式边界：HTTP forward proxy 请求携带 `accept`、`user-agent`、目标 `host`、`connection: close`、`proxy-connection: close` 与代理认证；HTTPS 经 HTTP(S) proxy 时，`host`、`proxy-connection` 与代理认证只属于 CONNECT 握手，隧道内目标请求只携带 `accept` 与 `user-agent`；SOCKS 隧道同样不得泄漏 forward-proxy 头。

当前已完成第二段的代码契约：独立 SQLite jobs Store 的 owner/proxy lease 与 fence、request replay/payload digest、request 级 execution claim、input draft -> Store-issued durable request identity、持久化深拷贝 snapshot、issued-input expiry/identity transaction fence、脱敏 outcome 元数据，以及 HTTP/HTTPS/SOCKS 探测协议和失败分类。最小 executor 只运行 Store 已签发且由 claim 交付的 input，先核验持久 snapshot 与 live lease，再逐 target 隔离探测；已提交 outcome replay 不再次请求上游，同一 request 并发调用返回 in-flight；512KiB 仅限制收集并持续 drain 到 framing end，CONNECT response header 限制为 64KiB；Node probe 的 `accept`、`user-agent`、`host`、`connection`、`proxy-connection` 与代理认证 header 已冻结；stored `socks5` 与 `socks5h` 均按 Node effective mapping 使用远端 DNS；executor timeout 不越过 issued input expiry/claim window；密码 envelope 只在内存解密，任何首次执行前的 input、凭据、lease、claim 或取消失败均不写 committed outcome。issuer 对 RFC3339 UTC revision、固定 policy、1..15 分钟 TTL、envelope 和唯一 provider target fail-closed；SQLite 测试覆盖 durable input rows、未签发/错版本/过期 outcome、完整重放、successor takeover replay、snapshot TOCTOU、single-flight、expiry-capped probe、full-drain、CONNECT boundary、Node headers、password-only 和 poisoned replay digest。PostgreSQL reader 为只读 `REPEATABLE READ`，保持 Node provider profile 选择和 username-only proxy 语义；尚未执行真实 PostgreSQL/PgBouncer。它不启动 scheduler、不调用 Node，也没有改变任何 owner gate；后续必须先完成真实 PG 验证，才能继续接入投影闭环。
