**Goal:** 修复超限请求审计缺失、跨协议上下文污染、AI 账户健康检查协议不可配置、管理员使用记录空列表和操作日志单字搜索失效，并完成生产发布与反向合并。

- 超限审计不保存请求正文，不新增审计表字段，不提高正文大小限制。

- 不增加 Redis 内存上限，不把大正文或大上下文放入 Redis Stream 消息。

## 设计契约

### 超限审计

`recordDroppedAuditCapture` 在 `gateway_body_rejected` 时写入一条 `client_request` payload：

```ts
{
  partType: 'client_request',
  rawBodySizeBytes: input.bytes,
  contentType: input.contentType,
  captureStatus: 'overflow'
}
```

该 payload 不含 `body` 和 `headers`。审计错误信息记录实际大小、限制值和限制范围，客户端 413 响应契约不变。

### 健康检查协议

新增不可空字段：

```ts
type AccountHealthCheckEndpointFamily =
  | 'chat_completions'
  | 'responses'
  | 'messages'
  | 'generate_content'
```

协议族到健康检查请求形态的映射固定为：

```ts
chat_completions -> chat_json
responses -> responses_json
messages -> messages_json
generate_content -> generate_content_json
```

默认值由供应商协议档案和已启用 JSON 能力决定：OpenAI 官方 GPT 优先 Responses，通用 OpenAI 兼容优先 Chat，Anthropic 使用 Messages，Gemini Native 使用 GenerateContent；首选不可用时使用第一个已启用 JSON 协议族。

### 跨协议上下文

请求预处理阶段只生成不可变的协议无关上下文：

```ts
interface CodexResponsesMaterializedContext {
  canonicalBody: JsonRecord
  resolvedInput: unknown[]
  previousResponseKind: 'none' | 'internal' | 'external'
  internalState?: CodexResponsesChatBridgeRequestState
}
```

`buildPreparedUpstreamRequestParts` 每次 dispatch attempt 根据实际选中的账号和模型映射重新克隆并渲染请求。显式 Responses-to-Chat bridge 使用桥接状态；原生 Responses 使用普通 Responses message；其他协议适配器只接收普通输入项。completion handler 只绑定实际显式 bridge 账号。

### 管理员列表

管理员全用户使用记录请求必须满足：

```ts
systemAccountId === undefined
startAt === 当天开始
endAt === 次日开始
sortBy === 'createdAt'
sortOrder === 'desc'
无 accountKeyword/result/statusCode/clientIp/groupId/model/traceId/trafficSource
```

后端对不满足契约的请求返回 400。前端使用 `dateRangeMode: 'auto' | 'manual'`，自动模式在零点或页面恢复可见时更新当天并重新加载。
