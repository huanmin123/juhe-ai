## 方案概述

### 分类定义

| 类别 | 定义 | 删除前置 |
| --- | --- | --- |
| A 零消费方 | 全仓无调用方，或仅测试自引用；无外部契约、无存量数据依赖 | 直接删 + 同步测试/注释 |
| B 存量数据 | 代码分支存在，可能仍被旧数据/旧缓存命中 | 先做数据预检；零命中或完成迁移后删 |
| C 对外契约 | 外部调用方、公开 API、部署环境或前端仍在依赖 | 先改契约/前端/文档，保留一个发布窗后删 |
| D 一次性工具 | 已完成或已无必要的一次性迁移/退役命令 | 定回滚窗截止日，命令+包+文档+测试整包退役 |
| E 不可删 | 当前持久化格式、产品能力、升级路径、安全门禁 | 只允许换格式/换实现，不按“兼容”直接删 |
| X 缺陷 | 兼容代码已经掩盖了真实行为错误 | 先修缺陷，不按普通清理处理 |

### 判定标准

- A 类必须满足：`rg` 全仓（含测试）无调用，或仅测试以字面量自引用；删除后不需要数据迁移。
- B 类必须满足：能指出具体旧数据形态、写入方已停、读取方仍可能命中；删除前必须有可复核的 SQL 或扫描结果。
- C 类必须满足：能指出仓库外或独立发布面的消费方；删除前必须更新公开契约文档和前端调用。
- D 类必须满足：能指出正式执行分支、完成状态、回滚依赖；未完成正式分支的工具优先裁决是否继续交付。
- E 类任何情况下不得以“清理兼容代码”为由删除。

### 复查方法

1. 读取候选位置的当前源码，确认分支是否仍存在。
2. 用 `rg` 查全仓调用方、测试引用、文档引用和脚本引用。
3. 对照权威文档确认它是“仍生效的契约”还是“已退役的残留”。
4. 数据依赖项标记为“代码级已确认 / 数据级待核查”，并给出预检 SQL 或扫描方式。
5. 只记录当前事实，不把“注释说可以删”当作删除依据。
