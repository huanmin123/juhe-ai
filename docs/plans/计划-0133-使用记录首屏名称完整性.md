# PLAN-0133 使用记录首屏名称完整性

## 基本信息

- 编号：PLAN-0133
- 状态：已验证
- 创建时间：2026-07-18
- 更新时间：2026-07-18
- 需求来源：生产“我的使用记录”首屏显示“已删除或未知”
- 关联模块：使用记录、首屏热缓存、资源名称 lookup、前端展示

## 需求目标

- 首屏热列表缓存必须包含 AI 账户、API Key 和分组名称，不能把存在的资源显示成“已删除或未知”。
- 页面首屏继续纯读 Redis 热缓存，不因名称补齐恢复实时数据库查询。
- 名称 lookup 或缓存写入失败不得影响使用记录数据库事实和队列 ACK。
- 已产生的旧命名空间错误缓存立即失效。

## 根因证据

- 生产 2026-07-18 18:12:51 至 18:13:05 的记录均包含有效 `account_id/api_key_id/group_id`。
- 这些 ID 在 `juhe_business.accounts/api_keys/groups` 中均能关联到名称，对象没有被删除。
- 普通列表路径会按 ID 补齐名称；新上线的首屏热缓存 `summaryFromInput` 只复制 ID，没有写入三个名称字段。
- 前端在“ID 存在但名称为空”时按契约显示“已删除或未知”；分组列因前端另有选项缓存兜底而看似正常。

## 实现

- [x] 首屏缓存投影增加 `apiKeyName/groupName/accountName`。
- [x] 使用记录落库后仅筛选首屏网关候选记录；异步路径复用当前数据库连接，按 900 个 ID 分块直查名称后写入缓存。
- [x] 名称解析和缓存发布收口为 best-effort，不影响数据库事实。
- [x] 缓存切换到 `usage_record_first_page_v2` 新命名空间，旧错误值不再读取。
- [x] 增加名称投影、候选过滤、新命名空间和分块查询约束回归。
- [x] 执行合并后 Node、Go 与发布门禁验证。

## 验收标准

- [x] 有效账户/API Key/分组 ID 的热缓存 summary 包含对应名称。
- [x] 默认首屏继续命中写入驱动的共享缓存。
- [x] lookup/Redis 失败不使已持久化的使用记录批次失败。
- [x] Node、Go 和发布前门禁通过。
