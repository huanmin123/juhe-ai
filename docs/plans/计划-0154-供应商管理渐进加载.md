## 目标

## 已确认现状

- 管理 `GET /providers` 返回完整 `ProviderDefinition[]`，首屏读取全部协议档案、能力、默认支持模型和 scoped 默认检查模型。
- `/providers/options` 的响应已是 `id/code/name/enabled`，但仓储仍先构建完整 definitions 后过滤映射，尚未做到 SQL 轻量。
- `/providers/definitions` 被账户等表单真实依赖，不能通过破坏该契约完成瘦身。
- 个人模型页首屏读取完整 definitions；点击模型目录又先重拉整批 scoped definitions，再读取单 provider 模型目录。
- 多个仅需判断 provider code 是否启用的供应商模块路径仍使用完整列表 `.find/.filter`。

## 范围边界

### 本次拟实施

- Node `ProviderListItem`、`ProviderOption` 窄 SQL、单 provider detail 和启用 code lookup。
- `/providers` admin 权限、detail admin/普通用户停用可见性、现有 scope 权限。
- SQLite 主线程/read worker/PostgreSQL 等价实现。
- Vue 管理列表与个人模型页首屏轻 DTO，点击后并行 detail/models，scope 与请求代次保护。
- `providers.catalog` route/scope cache key、auth revision、写后失效与缓存竞态。
- HTTP/query/worker/PG/前端行为专项回归、权威文档和独立复核。

### 本次不做

- 不修改 `backend-go/`。
- 不修改 schema、供应商驱动、协议桥接、网关调度、计费或账户凭据语义。
- 不新增供应商创建/编辑/启停管理接口。
- 不缩窄 `/providers/definitions`，不迁移真实依赖完整 definitions 的账户表单。
- 不改变模型目录、模型能力、模型写入和默认检查模型写入 DTO。
- 不提交、不推送、不部署、不操作生产。

## 待确认契约

- `GET /providers` 改为 admin-only `ProviderListItem[]`，字段固定为 `id/code/name/parentCode/description/enabled/accountTypes/capabilities/baseUrl/defaultHealthCheckModel/defaultSupportedModels`。
- 管理首屏保持现有账户类型、接口能力、Base URL、默认检查模型和默认支持模型列；后端只读取 provider base、每个 provider 被选中的默认 protocol profile 摘要及 scoped 默认检查模型，不加载全部 profiles 或 endpoint families。
- 个人模型页首屏改用启用 `/providers/options`，只展示名称与模型目录操作。
- 新增 `GET /providers/:code` 完整 detail；admin 可读停用项，普通用户只能读启用项。
- 点击模型目录并行加载单 provider detail 与 models，不再重拉整批 `/providers/definitions`。
- `/providers/options` HTTP DTO 不变，但改为直接窄 SQL；完整 `/providers/definitions` 不变。

以上包含管理列表字段和首屏 UI 取舍，用户确认前不得进入运行时代码实施。

## 验收标准

- 供应商管理和个人模型页首屏不读取完整 ProviderDefinition。
- `/providers/options` 从 HTTP 到 SQL 都是轻量接口。
- `/providers/definitions` 保持完整且真实依赖方无回归。
- 单 provider detail/models 只在点击后加载，且 code/scope/身份/竞态正确。
- 纯 code/enabled 校验不再触发完整 definitions，完整协议校验不被误删。
- Node、SQLite worker、真实 PostgreSQL、前端时序、缓存失效、浏览器和双 Agent 复核证据闭合。

## 风险与注意事项

- `GET /providers` 是明确的 DTO 收窄，不能在未确认时修改代码或伪装成兼容变更。
- 不能只裁剪 HTTP 响应而保留完整 loader；SQL/query guard 是验收必需证据。
- 不能以接口瘦身为由删除 ProvidersView 当前真实展示的账户类型、接口能力、Base URL、默认检查模型或默认支持模型；应收窄为选中 profile 摘要而非改变 UI。
- 不能为了复用 options 而让账户创建/编辑失去 protocol profiles、account types 或 capabilities。
- detail cache 必须包含 target system account，否则默认检查模型偏好会跨用户串值。
- enabled lookup 不能替代允许管理停用供应商的存在性校验，也不能替代完整协议能力校验。
- 当前工作树存在大量并行改动；实施时必须按文件职责协调，禁止整理、回退、提交或覆盖无关差异。
