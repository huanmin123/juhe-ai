## 完成目标

实现系统账户维度的每分钟、每日、每周、每月网关请求限制，支持全局默认、单用户覆盖和整组到期日；用户可在个人信息查看最终限制；网关以进程内同步判断快速失败，Redis 只在后台异步批量协调，不进入请求等待链。

## 关键决策

1. 请求路径只执行同步内存计数，不等待 Redis 或数据库。
2. Redis 每 1 秒后台批量同步，允许约 1～2 秒跨节点短暂超额。
3. 用户覆盖是四窗口可选字段加一个整组到期日；缺失继承、`0` 无限、正整数覆盖。
4. 到期日当天仍有效；次日按 `usageStatsTimezone` 自动继承全局。空日期表示永久有效。
5. Redis 故障继续本机限制，不做全局 fail-closed。
6. 当前交付只收口 Node/Vue，不修改 Go 运行时。

## 代码复查结论

- 需求完整性：全局、用户三态、到期日、个人信息、429、审计、内存 / Redis 和旧库兼容均已覆盖。
- 性能：热路径无 Promise、DB、Redis、HTTP 或用量扫描；容量淘汰为 O(1)，Redis Lua 不执行全实例扫描。
- 边界：到期日使用真实日历日期校验；日期当天有效；整组到期；模型目录和内部探针不计数。
- 可靠性：Redis 后台命令有超时、失败退避和退出排空；容量淘汰与未排空均可观测。
- 设计取舍：不承诺多节点零超额，standalone 重启会丢失本机热计数；两者均为速度优先的明确边界。
- 范围控制：未修改 Go 运行时或扩大历史全链路性能治理范围。
