# PLAN-0088 计费可追溯与上游桶所有者隔离

- 编号：PLAN-0088
- 状态：已完成，待提交评审

- 关联模块：网关 usage / 使用记录 / 模型计费 / 上游桶运行态 / 调度排序 / Codex OAuth 适配

## 目标

- 使用记录持久化客户端请求、实际发往上游、上游响应报告和最终计费采用的服务档位，支持账单追溯。
- 上游不回传 `service_tier` 时，使用实际发往上游的档位计费；上游明确回传时以上游报告为准。
- 1 小时缓存写入价格遵守服务档位精确价格优先、通用倍率兜底的统一规则。
- 上游桶按物理账户所有者隔离，不同所有者的相同代理、Base URL 或供应商失败互不影响。
- 上游桶只调整同优先级候选顺序，不删除候选；全部避让或半开时仍保留完整候选集合。
- Codex OAuth 请求按受控白名单透传客户端设备证明，API Key 路径不透传，审计和 usage 不捕获证明正文。

## 核心契约

- `requested_service_tier`：客户端原始请求声明，缺失时为 `default`。
- `effective_service_tier`：账户覆盖、模型能力和协议适配后实际发往上游的档位。
- `reported_service_tier`：上游响应明确返回的档位，可为空。
- `billed_service_tier`：`reported_service_tier ?? effective_service_tier`，成本计算只使用该字段。
- Priority 与 Flex 平级，不互相降级；账户覆盖不支持时不改写客户端档位。
- 桶所有者使用 `accountOwnerSystemAccountId`，同一物理账户授权给其他用户时仍共享物理账户所有者的运行态。
- 桶不依据 HTTP 状态码、错误码、错误类型或错误文案分类。
- 不保留无所有者旧桶 key 的读取兼容分支；新运行态按最新 key 重新积累。
- `x-oai-attestation` 只允许在 GPT OAuth Codex 请求中由客户端原样提供；服务端不生成、不复用其他请求值、不写入审计或使用记录。

## 验收标准

- 上游不回传档位时，Flex/Priority 仍按实际上游请求档位计费。
- 使用记录可区分 requested/effective/reported/billed 四种档位。
- 不同所有者相同 Base URL 的失败样本不能共同打开桶。
- 同一所有者多个账户可共同触发桶，同一物理账户授权视图共享桶。
- 半开探测时返回数组仍包含全部原候选，且仅调整顺序。
- OAuth 上游可收到合法 attestation；API Key 上游和审计/usage 快照均不可见该字段。
- 本轮只提交代码和本地验证结果，不部署生产。
