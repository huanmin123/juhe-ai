## 方案概述

### 现状门控事实（已核验）

- `ShouldRunJuice`（juice.go:24-26）：`profile=="full" && protocol=="openai_responses" && model ∈ {gpt-5.6-sol, gpt-5.6-terra, gpt-5.6-luna}` → Astra 走 skipped + notApplicable，不扣分。
- `supportsTokenIdentityProbes`（suite.go:463-471）：仅按协议（openai_responses）门控 → Astra 走 Responses 协议时 token_integrity（3 轮）与 identity_observation 已覆盖。
- `pairedIdentityModels`（identity.go:94-105）：仅 gpt-5.6 三变体与 gpt-5.5/5.4 有配对家族；Astra 无兄弟变体，退化为 [自身]。
- 通用族（行为指纹/长上下文/稳定性/结构化/工具/交叉对照）与题库环节对 Astra 全部生效。

### 探针设计方向（B 层）

**观测结论（2026-09-21，已找到稳定内部状态痕迹，B 层解除阻塞）**：对真实 `gpt-6-astra` 上游（神问中转，两条独立 key 通道）执行有界观测（11 个请求），结论：

1. 上游注入约 3.8k token 隐藏系统提示（`prompt_tokens_details.cached_tokens≈3840`），内含具名数值常量，模型可自述：`model generation = 6`、`context budget = 48`、oververbosity 1/4/10、commentary/clarification/sleep 间隔 60s。
2. 内部值算术探针跨通道一致：`generation×2÷2→6`、`context budget+7−7→48`（两通道答案相同）。
3. 合成权威覆盖轮成立：instructions 声明合成 `context budget=87` 为权威后，算术结果服从合成值（Juice 覆盖轮语义可复制，nonce 每次运行随机生成防固定历史应答）。
4. trace + 精确应答轮成立（`Trace <nonce>. Reply with exactly: 32 → 32`）。

**探针设计 v1（`gpt6astra-constants-v1`）**：门控 `profile==full && protocol==openai_responses && model==gpt-6-astra`；四轮：内部值算术×2（期望 6/48，判替换/降智的硬异常信号）、trace 精确应答（随机 nonce）、合成权威覆盖轮（随机合成值）。判分与罚分镜像 `juice.go` 的强/弱异常分类。风险：上游合法调整内部常量会造成全体真账户硬异常——探针带版本号，异常时回退版本名单即 skipped 不扣分；分类阈值实现时对齐 Juice 惯例。

观测边界声明：以上结论基于神问中转（第三方）上游；若中转后端并非真实 Astra，探针锚定的是"该上游的内部指令形态"——这正是检测要固化的目标（上游替换即硬异常）。

参照 GPT-5.6 Juice 的构成逆向 Astra 等价物：

1. **观测**：对真实 Astra 账户发起一组结构化探查请求（指令跟随、内部指令引用、合成权威覆盖类，参照 juice.go 的 6 探针形态），从响应行为中寻找可复现的内部状态痕迹。
2. **候选探针形态**：内部数值算术（找 Astra 的"Juice number"等价物）、trace nonce 一致性、合成权威覆盖（instructions 声明合成记录为权威后模型是否服从）、固定应答精确性。
3. **判分**：找到稳定痕迹后设计算术期望与 coverage 轮，硬异常（响应替换/混用）罚分、弱异常轻罚；找不到稳定痕迹是**有效结论**（记录为"无等价探针"，Astra 降智检测以通用族+题库为准），不得硬造。
4. **门控**：新探针按模型名单门控（新增 Astra 时同步），沿用 notApplicable skip 语义；quick 不跑（与 Juice 一致）。
