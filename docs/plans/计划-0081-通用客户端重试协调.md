## 需求目标

- 背景：生产环境中单个上游账号快速失败后，网关按“每个账号多次原地重试”扫描账号池，服务端隐藏等待与客户端自身重试叠加，导致客户端在服务端返回可重试信号前主动断开。
- 目标：把瞬时波动确认、账号切换和客户端重试协调为分层预算；支持 Codex、Claude Code、Gemini CLI 和普通 OpenAI / Anthropic / Gemini 客户端，不把行为限定在 Codex Responses SSE。
- 交付物：通用客户端重试策略、请求级失败确认预算、协议化最终失败信号、热路径探针移除、回归测试、生产部署和验证记录。

## 方案概述

- 失败确认：真实客户端请求按 `temporaryUnschedulableRetryAttempts` 建立请求级共享确认预算；当前账号失败且预算尚有剩余时原地重试并消费一次，预算不按账号重新发放。
- 账号切换：确认额度用尽后继续扫描当前调度候选，不因具体上游错误内容提前停止，也不为后续账号重复等待。
- 客户端信号：Codex Responses、Claude Code Messages、Gemini CLI 流使用各自协议错误事件；通用客户端在下游未提交时返回协议原生 HTTP `503`，下游已提交且没有可靠失败事件时直接断流。
- 网关错误码：`upstream_retryable_error` 只表示网关已耗尽当前服务端承接能力并建议客户端重新发起请求，不表示对上游错误类型做了分类。
- 快速模式：`speed_first` 只处理已确认的首字慢，不因普通上游失败立即切换，也不改变统一失败确认预算。

## 风险与注意事项

- 返回 HTTP `503` 或直接断流会让不同 SDK 采用自己的退避策略；网关不控制客户端最终重试次数。
- 协议事件只能用于已确认支持该失败事件的客户端画像，不能对未知客户端伪造专用事件。
- 发布异常时回滚到部署前 release，并保留生产日志和审计用于对比。
