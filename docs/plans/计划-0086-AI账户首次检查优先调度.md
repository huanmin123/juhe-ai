# PLAN-0086 AI 账户首次检查优先调度

## 基本信息

- 编号：PLAN-0086
- 状态：已完成
- 创建时间：2026-07-11
- 需求来源：用户反馈新增账户长时间停留在待检查影响使用体验
- 执行者：AI / 维护者
- 关联模块：AI 账户 / 后台任务 / ops-worker / 健康检查 / 系统监控 / 文档 / 验证

## 需求目标

- 新账户保存后优先开始首次后台检查，避免被普通周期复检积压阻塞。
- 保持探针总并发受控，不通过无队列直接请求或新增独立分布式队列放大上游压力。
- 同一账户重复投递时以最新配置和最高请求优先级为准。

## 范围边界

- 单个 ops-worker 内继续使用一个账户健康检查队列。
- 优先级依次为：首次激活、连接配置变更、普通周期复检。
- 队列为高优先级任务保留执行容量，普通复检不能占满全部并发槽。
- 等待中的重复任务更新内容并提升优先级；运行中的重复任务在当前执行结束后追加一次最新任务。
- 不新增数据库字段、Redis 队列、独立 worker 或跨实例协调。

## 验收标准

- 新账户不会排在普通周期复检之后。
- 大量新增时按受控并发分批执行，普通复检不阻塞首次激活。
- 重复 IPC 消息不产生并发重复检查，也不会丢失最新配置检查。
