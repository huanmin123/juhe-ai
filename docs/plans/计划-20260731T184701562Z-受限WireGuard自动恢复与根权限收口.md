# 受限 WireGuard 自动恢复与根权限收口

状态：进行中

## 事故证据

- macOS 主机未在事故时段重启，juhe-ai、Caddy、Nginx、数据库和 Redis 进程仍在运行。
- 8 条 system LaunchDaemon 的 WireGuard 进程显示 `running`，但真实 `utun` 映射的最新握手停止；公网 Edge 到 macOS 的 TCP/TLS 连接超时。
- 网络配置事件发生在 `en0`，与应用服务进程生命周期不一致，故障边界属于 WireGuard / macOS 网络数据面。
- 旧的 7 条 plist 从用户可写的发布目录调用 wrapper；这会让 root LaunchDaemon 执行可被非 root 用户替换的脚本，属于权限与供应链缺陷。
- 203 的逐 Edge TLS nonce probe 是独立验证和告警证据；probe 结果未知时不能归因于 WireGuard，也不能触发恢复。

## 目标与范围

1. 提供 root-only、WireGuard-only 的单次恢复器及 system LaunchDaemon 安装器。
2. 把 8 条受管 WireGuard job 的来源配置原子复制到固定 root-only `/usr/local/libexec/juhe-ai/wireguard-config/<逻辑接口>.conf`（目录 `0700`、配置 `0600`），并在 root-only libexec 固定生成两参数生命周期 wrapper；`/usr/local/etc/wireguard` 仅作迁移输入且不修改其父目录。来源 wrapper 仅作哈希、精确 plist 绑定和回滚元数据，绝不复制或执行，并保留失败回滚。
3. 仅在全部受管 Edge 连续陈旧、默认路由稳定、退出 sleep/wake 宽限、无维护锁且预算允许时执行恢复。
4. canary 恢复必须在前序清理旧映射后重新观察到 `utun` 映射、连续最新握手、收发计数增量和独立 203 probe，再串行恢复其余 Edge；canary 后任一 Edge 失败即停批，后续 Edge 零动作；不要求 macOS 分配不同编号。
5. 保留可轮转的本地结构化运行记录，不记录私钥、凭据或完整配置。

## 非目标

- 不修改 Node、Go、Caddy、Nginx、数据库、DNS、业务数据或前端。
- 不启用历史通用 SSH / HTTP healer，不把单 Edge、DNS、Caddy、Node 或未知 probe 失败归因于 WireGuard。
- 不把真实生产 IP、域名、用户名、密钥、token、SSH fingerprint 或发布路径写入仓库；203 不临时开放明文 Prometheus。

## 回滚与停止

- 安装器 `--apply` 只替换精确 allowlist 内的 plist、wrapper 和配置；bootstrap、kickstart、身份校验或健康门禁失败时恢复原 plist、wrapper、loaded 状态。
- 恢复动作以持久 lease、每 Edge / 全局冷却和窗口预算串行化；canary 失败立即停止，不盲目重启余下 Edge。
- `--remove --apply` 只卸载恢复器 LaunchDaemon，保留状态日志供审计；生产回滚前先验证原 WireGuard job 的 root-only wrapper 和配置仍可运行。

## 验收

- `bash -n` 通过；`--dry-run` 不写 launchd、wrapper、配置或状态。
- 负面模拟覆盖：单 Edge 陈旧、probe unknown、网络变化、sleep/wake 宽限、维护锁、重复 helper、活动 lease、预算耗尽、旧 wrapper/配置不是精确 allowlist、root 所有权和父目录可写，以及 203 mapping 的缺失、重复、额外或重复 `node + public_ip` 指标序列。
- 正面模拟覆盖：全部 Edge 两次连续且样本间隔未过期的陈旧，canary 新映射/握手/传输/203 probe 通过后余下 Edge 串行；canary 或任一非 canary 动作超时或 probe 失败立即停止并记录。203 证据必须经专用 SSH、固定 host key 和只读 forced-command 取得。
- macOS operations 既有验证及新增 WireGuard 定向验证全部通过。
- 生产预检必须由部署人员提供私有 root manifest、probe adapter、现有 plist/config/wrapper 的哈希与回滚副本；本计划不在仓库保存这些值。
