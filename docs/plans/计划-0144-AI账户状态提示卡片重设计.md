## 目标

- 状态提示只展示当前主状态对应的用户信息。
- 检查驱动状态统一展示最近检查、下次计划检查、原因和失败 `traceId`。
- 到期、冷却、策略 TTL 和授权阻断使用对应业务时间或下一步动作，不伪装成检查时间。
- 列表首次加载与 30 秒状态快照整体替换同一 presentation 摘要，消除新旧时间和 traceId 混用。
- 删除状态提示中的数据库、进程缓存、失败计数、来源统计、探针轮次和质量算法说明。

## 验收标准

- 所有 `AccountEffectiveAvailabilityStatus` 都有明确的用户展示规则。
- `runtime.until`、`cooldownUntil`、生命周期和时间计划不会被统一显示为“预计释放”。
- 最近检查 observation 与下次计划 schedule 分离，原因和 `traceId` 只绑定最近 observation。
- 30 秒状态快照能更新和清空 presentation 全部字段，不保留首次列表旧值。
- Key 池最近失败使用非空 `last_failure_at`，稳定按 `key_index + key_fingerprint` 决胜；下次计划只从非空 `next_probe_at` 选择。
- PostgreSQL 和 SQLite 当前 schema 同步包含 Key 运行态 `last_trace_id`。
- memory 与 Redis 运行态用户摘要字段一致，任务丢失时不伪造下次检查。
- 桌面和移动端复用同一状态提示，长原因可换行，traceId 可复制。
- 前后端类型检查、专项测试和构建全部退出码为 0。
