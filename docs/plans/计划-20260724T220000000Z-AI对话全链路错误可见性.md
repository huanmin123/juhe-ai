# PLAN-20260724T220000000Z AI 对话全链路错误可见性

## 目标

- AI 对话过程中任一模型、内部工具、流式解析、编排或持久化错误都向前端提供可诊断详情。
- 错误详情可在实时 SSE、提交状态查询和刷新后的历史消息中保持一致。
- 服务端继续记录完整异常，并用会话 ID、轮次 ID 与 Trace ID 关联。

## 实施清单

- [x] 统一提取、脱敏、单行化并限制公开错误详情长度。
- [x] 生成失败终态写入并发送 `errorCode/errorMessage/traceId`。
- [x] 内部工具失败写日志、发布诊断详情并回灌模型纠错续答。
- [x] 前端接收 `tool.failed/tool.canceled`，默认展开失败详情。
- [x] 失败消息和失败工具旁展示会话 ID、Trace ID，并支持复制诊断信息。
- [x] SQLite 自动补列与 PostgreSQL Goose `000077` 前向迁移。
- [x] 完成全部定向回归、类型检查、构建与最终复查。

## 安全与回滚

- 服务端日志保留完整异常；前端只接收脱敏消息，不返回 stack。
- 必须移除 Authorization、Cookie、API Key、Token、URL 密钥参数和服务端绝对路径，公开详情最多 1200 字符。
- 回滚应用前可先回滚代码；Goose Down 仅删除新 `error_message` 列，不影响消息正文和错误码。

## 验收标准

- [x] 未知内部 `Error.message` 不再被通用文案吞掉。
- [x] 内部工具失败实时出现在前端，刷新后仍可见。
- [x] 用户可复制错误、会话 ID 和 Trace ID。
- [x] 原始密钥、Token、Cookie、上游 URL 和服务端路径不出现在公开诊断。
- [x] Mock 全链路、聊天 repository/SSE/工具/布局、PostgreSQL schema、前后端类型与构建全部通过。
