# 计划-0099 生产自动恢复与模型请求削峰

状态：执行中

## 目标

修正生产 watchdog 把 DB service 局部失败升级为整组重启的问题，并限制已认证模型列表重试风暴。在不改变 PostgreSQL/Redis schema 的前提下，让 DB service 卡死由主进程 supervisor 定向恢复，只有主服务持续不可用时外部 watchdog 才能整组重启。

## 已确认现场

- 2026-07-15 watchdog 共执行 34 次整组终止：API health 单独触发 9 次、双 health 触发 19 次、主 health 单独触发 6 次。
- 生产近 6 小时有 16,462 次 `GET /v1/models`，单 API Key 与 `API Key + client IP` 分钟峰值均为 361，P95 约 176。
- 当前新 release 双 health 正常；本计划不是在未知状态下直接热改生产。

## 设计

### DB service 定向恢复

- `db-service-supervisor` 作为唯一 child owner，直接探测 `127.0.0.1:<DB service port>/__aisys__/api/health`。
- 完整保留 180 秒启动宽限；之后每 15 秒探测，5 秒超时，连续失败 3 次才尝试定向恢复。
- 恢复时只终止当前 supervisor 持有的 child，先 `SIGTERM`，10 秒未退出且 child 对象/PID 仍一致时才 `SIGKILL`；现有 exit listener 负责退避重启。
- DB service 恢复冷却 60 秒，15 分钟最多 3 次；超过预算只记录结构化告警，不杀主服务。
- 主进程关闭时停止探测 timer 和 kill timer，不得在 shutdown 期间重启 child。

### 外部 watchdog

- API health 仅记录和诊断，不再单独触发主进程终止。
- 主 health 连续失败阈值改为 4；达到阈值后采样 3 秒，再执行两次有上限的确认探测，任一次恢复即取消重启。
- PID 变化后的 180 秒启动宽限必须按墙钟完整保留，首次双 health 200 只记录 ready，不提前清零。
- 整组重启设置 180 秒冷却，并使用持久化小状态文件实施“15 分钟最多 1 次”；超限只告警。
- `SIGTERM` 前和 `SIGKILL` 前均核对 launchd PID、进程启动时间和 cwd；任一变化立即放弃。

### 已认证模型列表削峰

- 未认证模型列表保留现有 IP 60 次/分钟规则。
- 认证成功后、进入模型目录/额度/审计重路径前增加 Redis-aware 双桶：`API Key + client IP` 为 20 次/10 秒、60 次/分钟；API Key 全局为 100 次/10 秒、300 次/分钟。
- 429 返回协议兼容错误、`Retry-After` 和结构化审计，不进入目录构建和 usage 成功记录。
- 最终响应建立 30 秒有界缓存，键包含 system account、排序后的 provider codes、响应协议和 OpenAI/Codex 变体；注册到现有 gateway runtime invalidator。
- 返回 `Cache-Control: private, max-age=30`；缓存命中仍保留真实请求审计和 usage 记录，不篡改访问统计。

## TDD 任务

1. 扩展 watchdog regression，先证明 API-only 不整组重启、宽限不提前结束、采样后恢复取消、预算阻断、PID 启动时间/cwd 变化阻断 SIGKILL。
2. 为 DB supervisor 新增策略/进程测试，先证明卡死 child 被定向终止、正常 health 不动作、宽限/冷却/预算有效、shutdown 不重启。
3. 为认证模型列表新增失败测试，覆盖组合桶、全局桶、429 审计、不同 API Key 隔离和 Redis-aware 调用。
4. 为响应缓存新增失败测试，覆盖缓存键隔离、30 秒命中、invalidator 清理和 Codex/OpenAI 响应不串用。
5. 实现最小代码使各组测试转绿，再运行 typecheck、build、相关回归和完整 Node 测试门禁。

## 发布与回滚

- 第一档，无 schema 变化；仍使用临时服务接管。
- watchdog 脚本/plist 在目标 Mac 上执行 `bash -n`、`plutil -lint` 和 regression，通过后版本化备份并在发布窗口 watchdog 已暂停时替换。
- release 回滚与 watchdog 文件回滚相互独立；任何一项失败保持临时候选接管。
- 生产验收固定 60 秒，必须验证主 PID/watchdog PID 不变、API-only 故障不会触发整组动作、`/v1/models` 429 指标可观测。
