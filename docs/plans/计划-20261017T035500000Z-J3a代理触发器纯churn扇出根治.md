# PLAN-20261017T035500000Z-J3a代理触发器纯churn扇出根治

## 基本信息

- 来源：BUG-0313 护航队治理扩展，统一排期批次 1-5（J3a 扇出抑制）（2026-10-17 用户批准按推荐推进，发布除外）。
- 状态：取证完成，方案 A（移除）设计定稿，待实施。

## 取证结论（2026-10-17，全链路）

`proxy_profiles` 的 dirty 触发器扇出是**结构性纯 churn**——账户列表可用性投影管线没有任何环节消费 proxy_profiles：

| 管线环节 | 位置 | proxy 依赖 |
| --- | --- | --- |
| 投影项构建 | `opsjobs/listavailability.go`（`ListMissingScope` 等 port 的 circuitstore 实现） | 无（`rg -i proxy` 全文件零命中；opsjobs 仅 `balancedetect.go` 无关引用） |
| 投影写入 | `circuitstore/listavailability.go` `upsertProjectionTx`（列清单 1007-1043） | 无 proxy 列/payload 来源 |
| 读链/物化 | `circuitstore/listavailability_loader.go` / `listavailability_hydrate.go` | 无 |
| 标记面 | gateway `chain_dispatch.go` 脏标记（账户家族展开，不含 proxy） | 无 |
| 触发面 | `pg_schema_business_tables.go`：`account_list_availability_proxies` 触发器（`AFTER UPDATE OR DELETE`，无 WHEN/列守卫）→ `account_list_availability_proxy_dirty_trigger` → `mark_dirty_proxy` → `mark_dirty_accounts(WHERE accounts.proxy_profile_id = ?)` | 唯一的 proxy 依赖方向：proxy→dirty，反向无消费 |

后果：J3a 每次探测回写 `proxy_profiles`（test_status/last_tested_at/延迟列，无值变化也触发 UPDATE 触发器）→ 该代理绑定的全部账户标脏 → claim → 全量重投影（投影值不变、generation+1）→ viewer health 置 stale → 刷新周期空转。批次 1-4 的 search_terms 指纹跳过只消除了其中词集段，投影行 upsert 仍是 churn。

## 方案（设计定稿，推荐 A）

**方案 A（推荐，根治）**：从 PG schema 移除 proxy 触发器与 `mark_dirty_proxy` 函数。

- schema 语句块（`account-list-projection-pg-dirty-triggers`）删除 `account_list_availability_proxies` 触发器与 `account_list_availability_proxy_dirty_trigger`、`account_list_availability_mark_dirty_proxy` 两个函数定义。
- **存量库清理尾**：从 Go 源删除定义不会卸载已建触发器——语句块尾补 `DROP TRIGGER IF EXISTS account_list_availability_proxies ON proxy_profiles;` 与 `DROP FUNCTION IF EXISTS <两函数签名>;`（幂等，随 ensure-schema 交付）。
- 文档记录与 Node 迁移契约的偏离及依据（本计划取证表）；git 历史可溯 Node 原版同构触发器。

**方案 B（否决）**：WHEN 列守卫（test_status 变化才扇出）——test_status 不进投影，守卫后仍是无意义 churn，只降频率不除根因，不符合"根治优先"。

## 范围边界（非目标）

- 不动其余 22 个触发器（均有真实消费方）。
- 不动 J3a 回写本身（test_status 是代理管理面事实，`proxylatency` 域正常工作）。
- SQLite 测试夹具不受影响（触发器仅存在于 PG schema 预置块）。

## 执行拆解

1. 修改 `pg_schema_business_tables.go`：删触发器 + 两函数定义，块尾补幂等 DROP 清理语句。
2. 文本断言测试：更新/新增——断言语句块**不含** `account_list_availability_proxies`/`mark_dirty_proxy` 且**含** DROP 清理语句。
3. PG 门禁（dev PG）：ensure-schema 同构重放通过；`pg_triggers`/`pg_proc` 确认触发器与函数已从 dev 库卸载。
4. 文档同步：本计划完成总结 + 问题-0313 后续记录补条目；部署文档无需变更（随 ensure-schema 序列交付）。

## 验收标准

- J3a 回写不再产生 dirty 行（PG 门禁：UPDATE proxy_profiles 前后 dirty 计数不变）。
- 触发器与两函数在存量库（dev）卸载且重放幂等。
- 投影管线其余行为零变化（circuitstore/opsjobs 既有测试全绿）。

## 风险与注意事项

- 若未来投影需要消费代理状态（如账户列表展示代理测试态），须恢复触发器并把 proxy 列纳入构建 SQL——两条腿必须同改，本计划为唯一登记处。
