# 第一阶段计划：系统账户权限与 OpenAI 接入

## 目标

做一个更轻量的本地 OpenAI 兼容入口和账号调度后台。用户手里可能有多套中转地址、多组上游账号和多个服务商入口，但客户端来回切换 Base URL、API Key 或服务商会很麻烦，也容易造成历史会话不可见、上下文割裂或配置混乱。第一阶段先让客户端固定使用本服务 `/v1` 和本地 API Key，再由后台按分组选择 OpenAI 账号，并在账号异常、限流或临时不可用时自动切换到其他可用账号。

整体架构先覆盖系统账户、全局设置、供应商、AI 账户、API Key、代理、使用记录、普通运行日志搜索、原始审计日志、系统设置和分组，但第一阶段只落 OpenAI，并先把登录、角色、数据隔离和账户调度闭环做稳。

第一阶段的核心是先把以下轻量闭环做好：

- 系统账户可登录、登出、改密码和分配角色
- 默认管理员账号 `admin/admin` 可初始化，登录后对初始密码状态做一次消息提醒
- OpenAI 供应商可管理，系统名称和系统图标路径等全局设置只允许管理员修改
- OpenAI AI 账户可管理
- OpenAI OAuth 和 API Key 账户都可选填账户套餐到期时间，到期后直接停用并退出调度
- 系统团队可把多个系统账户归纳在一起，用于承接团队级共享使用权
- AI 账户和分组通过统一授权管理授权给系统账户或系统团队，授权只提供使用权，不提供编辑、删除、转授权或查看敏感凭据的权限
- OpenAI API Key 账号可管理
- OpenAI 账号可主动选择归属分组
- API Key 可绑定分组
- API Key 可在统一授权完成后绑定个人授权或团队授权给自己的分组
- 客户端固定连接本地 `/v1` 入口，不需要为了换账号反复修改客户端配置
- 账号异常、限流或临时不可用时按分组自动切换备用账号
- 使用记录和系统设置都要按系统账户隔离，用户只能看到自己的数据和授权给自己的资源
- 授权账户和授权分组的请求日志都按实际调用方记录；账户真实用量按上游账户统一累计，分组真实用量按分组维度统一累计，资源所有者可在授权管理里看授权消耗总量和按系统账户拆分明细，且不包含自己自用消耗
- 普通运行日志必须带 `traceId`，管理员可通过“日志搜索”菜单按最近 3 天索引快速检索同一链路相关日志；搜索不能实时扫描日志文件
- 原始审计日志独立于使用记录，用于记录客户端请求、网关处理、上游请求、上游响应和最终返回的完整链路；完全成功请求默认 10% 保存，非成功和中间重试失败链路全量保存
- 透传、错误处理策略、并发、代理这些能力有清晰的字段和边界
- 前后端接口与 OpenAI 兼容 `/v1` 中转入口先稳定下来
- 对外只兼容 OpenAI 协议；后续提供方也通过 OpenAI 兼容格式接入客户端
- 常用统计和运维监控先走按系统账户隔离的后台聚合缓存，列表和图表不直接实时扫明细表

## 第一阶段范围

### 系统账户管理

- 系统账户列表
- 新增 / 编辑 / 删除 / 停用
- 用户名称和用户账户都必须唯一；创建时同时校验，编辑时用户账户不可修改、用户名称可修改但仍需唯一
- 重置密码、登录后改密提醒、分配角色
- 仅管理员可见和操作
- 管理员视角需要展示系统账户维度和最后登录时间

### 系统团队管理

- 新增 `系统团队管理` 菜单，仅管理员可见
- 团队列表、新增 / 编辑 / 启停、成员维护
- 团队名称必须唯一；创建和编辑都需要校验
- 团队用于归纳多个系统账户，承接团队级资源使用授权
- 团队停用或成员移除后，团队授权立即不可继续生效
- 团队不改变成员自己的 API Key、使用记录和业务数据归属
- 普通用户不能进入系统团队管理页，但统一授权管理可以读取团队摘要用于授权选择

### 登录与权限

- 登录页
- 首次初始化页
- 登录验证码：未登录时先获取短时图形验证码，登录请求必须提交 `captchaId` 和验证码内容
- 登录失败防护：按 IP 做短时限频，按用户名做临时锁定，登录成功后清理失败记录
- 登录态校验、退出登录、当前登录用户信息接口
- 路由守卫和接口鉴权
- 登录成功后对初始密码状态做一次消息提醒，不在顶部常驻标签提示

### 全局设置

- 系统名称和系统图标路径；登录页文案和视觉主题按 [产品与品牌边界](../architecture/frontend/产品与品牌边界.md) 固定
- 仅管理员可编辑
- 未登录页读取全局设置

### 供应商管理

- 内置 OpenAI 供应商
- 展示供应商状态、支持的账户类型和默认基础配置；OpenAI 默认 Base URL 归属供应商定义，固定为官方地址
- 提供“查看模型”操作，展示该供应商的模型版本、上下文窗口和计费价格
- 暂不做供应商插件系统，但数据结构按可扩展方式设计
- 管理员可查看和维护供应商定义；普通用户不能看到供应商管理菜单，创建 AI 账户时只使用后端允许的供应商能力

### 分组管理

- 分组列表
- 新增 / 编辑 / 删除
- 创建系统账户时自动创建 `默认 OpenAI 分组`；已有本地系统账户由离线清洗或重建库补齐，源码不保留启动补丁
- 默认分组不允许删除
- 分组选择所属供应商；账户创建 / 编辑时只可归入同供应商分组
- 管理员视角列表展示分组名称、供应商、系统账户、账户可用数 / 总数、当前并发、今日用量、累计用量、状态和操作，不展开账户名称
- 用户视角展示自己的分组、个人授权给自己的分组和团队授权可用的分组；自有分组不显示系统账户列，授权分组显示“来自授权”和所有者摘要
- 给 API Key 选择分组；统一授权完成后，API Key 也可以绑定个人授权或团队授权给自己的分组
- 第一阶段建议一个 API Key 绑定一个分组，后续再扩展多分组
- 分组列表操作区保留“更多”菜单，但不再提供分散的授权管理入口；授权统一进入 `授权管理` 菜单维护
- 授权分组代表共享该分组内当前全部可共享账户；分组所有者后续新增、移除或停用可共享账户，会动态影响被授权用户通过该分组可用的账户集合
- 授权分组只共享分组所有者自有账户；如果分组里包含别人授权来的账户，不能通过分组授权继续共享给第三方

### AI账户管理

- AI 账户列表
- 新增 / 编辑 / 删除
- 启用 / 停用
- 备注、平台、账号类型等基础信息
- 统一“添加账户”入口：先选供应商，再显示该供应商支持的账户类型，最后显示具体配置
- 添加账户时分组必选，并按供应商默认选中默认分组
- OpenAI OAuth 创建方式
- OpenAI API Key 创建方式
- 账户到期时间：可选，表示套餐/账号购买到期时间；OAuth 与 API Key 都适用，到期后账户自动停用并退出调度
- 代理绑定
- 并发上限
- 优先级
- 供应商级默认透传策略
- 错误处理策略：创建和编辑弹窗内维护账号自己的规则列表，保存到 `credentials.error_handling_rules`
- 账户启停相关的基础标记位；底层保留调度字段，但管理入口统一使用“启用 / 停用账户”语义
- OpenAI OAuth 专属额度进度：列表在本地 token / 成本用量之外，单独展示上游 `5h` 与 `7d` 窗口进度、预计恢复时间、快照更新时间和后台刷新状态
- OAuth 额度快照不提供手动刷新按钮，统一由真实请求被动更新和后台定时器维护
- 账户测试动作
- 更多下拉动作：测试、迁移流量、停用/启用、切换客户端等；迁移流量用于把当前命中源账户的客户端会话切到同分组目标账户，并把源账户默认改为临时不可调用，也可指定为停用账户；不再提供分散的授权管理入口，授权统一进入 `授权管理` 菜单维护
- 授权账户在被授权用户的账户列表中展示为“来自授权”，可加入自己的同供应商分组并参与调度；如果账户所有者已停用主账户，被授权用户不能自行启用，只能看到停用提示并联系所有者处理，且不能编辑、删除、查看敏感凭据、修改代理/并发/错误策略或继续转授权
- 账户列表不展示 `Access/API Key` 与 `Refresh Token`；这两个字段只在编辑弹窗中查看和修改
- 管理员视角列表额外展示系统账户列和筛选条件；用户视角只展示自己的数据，不显示系统账户列

### API Key 管理

- API Key 列表
- 新增 / 编辑 / 删除
- 启用 / 停用
- 复制密钥
- 归属分组
- 展示累计用量，不按自然日重置
- 新增和编辑时支持请求次数额度限制：n 小时额度、日额度、周额度、月额度和总额度；日额度每日 0 点重置，周额度每周一 0 点重置，月额度每月 1 号 0 点重置，总额度按累计统计判断
- API Key 额度判断读取后台统计缓存，网关不实时扫描使用记录；统计和校验缓存可能允许轻微超额，统计追平后的下一次请求返回“额度已用完，请联系管理员提升额度”
- 过期时间、备注、权限范围
- 删除 API Key 时同步删除这把密钥产生的使用记录、原始审计日志、API Key 维度统计缓存，并从调用方、账户、分组、授权、模型和错误等相关聚合统计里扣除这把密钥的历史消耗
- 管理员视角额外展示系统账户列；用户视角只显示自己的 API Key

### 代理管理

- 代理列表
- 新增 / 编辑 / 删除
- 支持 HTTP、HTTPS、SOCKS5、SOCKS5H 基础字段
- 支持按全部已启用供应商默认地址测试代理，并在列表展示最近检测状态、检测时间和延迟
- 后台 worker 默认每 1 分钟批量刷新启用代理的最近延迟
- 代理是服务器级全局资源，不按系统账户隔离
- 只有管理员可看到代理管理菜单并维护代理
- 管理员可在 AI 账户上选择绑定代理；普通用户不能看到或修改代理绑定

### 使用记录

- 记录 API Key、分组、账号、接口、模型、状态码、IP、首 token、总耗时、错误摘要、token 和成本；每一次上游尝试都会入库，包含重试失败
- 授权账户或授权分组调用时，使用记录按实际调用方 `system_account_id` 入库，同时冗余资源所有者、访问类型、统一授权 ID 和授权对象类型，用于日志隔离、真实资源总量和授权消耗聚合
- 被授权用户只查看自己 API Key 产生的请求日志；资源所有者在授权管理里只能查看授权消耗总量和按系统账户拆分的聚合明细，不查看对方请求快照和业务内容
- 从 OpenAI 响应解析 `usage.input_tokens`、`usage.output_tokens`、`usage.input_tokens_details.cached_tokens`
- 轻量计费按 OpenAI 官方价格表估算，未覆盖模型只记录 token 不强行猜价格
- 失败记录可在操作列查看请求快照、网关返回和上游响应日志
- OpenAI OAuth 的上游额度快照不写入 `usage_record`，而是作为按 `system_account_id + account_id` 隔离的账号运行态保存；来源优先使用真实转发响应头，被动更新 `5h` / `7d` 使用百分比和 reset 时间
- 管理员视角显示系统账户列并支持按系统账户筛选；用户视角只看自己的记录，不显示系统账户列

### 原始审计日志

- 新增管理员可见的 `审计日志` 菜单，用于排查客户端行为变化、请求头差异、上游供应商校验变化、流式中断和网关兼容问题。
- 原始审计日志和使用记录分表管理；使用记录关注 token、成本、耗时和统计，原始审计日志关注完整请求过程。
- 保存完整客户端请求、网关实际上游请求、每次上游响应、网关最终返回和链路终态；原文不脱敏、不截断、不改写。
- 完全成功且没有中间失败尝试的请求默认按 `10%` 采样保存。
- 非成功请求、客户端中断、SSE 中断、上游失败、网关失败、以及中间上游尝试失败但最终切换账号成功的请求全部保存。
- 网关请求链路不能同步写审计表；请求处理中只维护内存捕获上下文，请求结束、失败或客户端中断后才计算终态并入队。
- 审计队列由独立后台 worker 进程每隔一段时间或达到批量阈值后批量写入 SQLite；允许系统重启、进程崩溃或队列溢出导致待写审计记录丢失。
- SSE 和其他流式响应不能按 chunk 实时写库，必须等流自然结束、失败、超时或客户端断开后，以终态记录进入队列。
- 队列满或单请求捕获超过上限时不能阻塞正常请求；允许丢弃审计记录并记录丢弃计数，供管理员在运维监控查看。
- 第一阶段仅管理员可查询审计日志；普通用户和授权资源所有者不能查看完整原始请求或响应内容。

### 日志搜索

- 新增管理员可见的 `日志搜索` 菜单，用于排查普通运行日志、错误日志和后台任务日志。
- 搜索入口支持 `traceId`、日志级别、事件名、HTTP 方法、路径前缀、状态码、客户端 IP、时间范围和关键字。
- 普通运行日志继续写入 `backend/logs/juhe-ai.log` 并按文件策略滚动；搜索只查询 SQLite 索引表，不在接口里 grep 日志文件。
- SQLite 运行日志索引固定只保留最近 3 天；超过 3 天的日志即使文件还在，也不会出现在日志搜索结果里。
- 索引写入使用内存队列和批量落库，索引失败不能阻塞业务请求，也不能通过普通 logger 递归打日志。

### 统计概览与运维监控

- 账户、分组和 API Key 列表中的用量字段统一读缓存，不再实时汇总 `usage_records`
- 统计缓存按 `system_account_id` 分区；统计概览与运维监控菜单只对管理员开放，用户只在账户、分组和 API Key 列表里看到自己名下的用量字段
- 统一授权统计口径保持单一：调用方明细归实际 API Key 所属系统账户；真实资源口径按 `account_id` / `group_id` 统一累计；授权消耗按“资源 × 用户”聚合，团队视图只是团队成员用户用量的筛选汇总，且不包含资源归属人自用消耗
- 统计缓存至少覆盖列表和授权所需的今日用量口径，以及统计概览所需的近一天、近三天、近一周、近一月监控窗口口径：有效请求、Token、平均响应时间、错误率、模型分布、Token 趋势和成本趋势
- 后台定时任务在独立 background worker 进程内按系统账户和增量游标汇总明细数据，生成按天、按小时和按维度的聚合结果，不占用 Web/API 主进程事件循环
- 系统监控至少采样 CPU、内存、RSS、Heap、事件循环延迟、数据库文件大小和统计滞后；主机级监控默认仅管理员可见
- 运维监控可展示原始审计日志队列长度、队列体积、最近批量落库时间、最近错误和丢弃计数
- 运维监控或日志搜索页面可展示运行日志索引队列长度、最近成功落库时间、最近错误、丢弃计数和索引范围
- 监控图和运维概览页都只读采样表，不直接扫原始请求明细

### 系统设置

- 全局设置和用户级系统设置分层
- 全局设置只包含系统名称和系统图标路径，只有管理员可改；登录页标题由系统名称派生为“系统名称 + 管理平台”，角标、副标题和首页样式不做配置项，详见 [产品与品牌边界](../architecture/frontend/产品与品牌边界.md)
- 用户级系统设置按系统账户隔离
- 临时不可调用、流熔断和默认代理策略的配置占位；不配置供应商 Base URL；账号并发创建默认值固定为 `20`
- 新建账号默认带入账号内嵌错误规则；未命中规则的上游错误统一把当前账号标记为临时不可调用并切换账号
- 密钥显示：本地网关 API Key 完整展示并支持复制；账户密钥只在编辑弹窗里展示
- 账户凭据唯一性：上游账户的 `API Key`、OpenAI OAuth `refresh_token` 和无 refresh token 时兜底使用的 `access_token` 必须在数据库底层全局唯一，不能被其他系统账户重复添加
- 流熔断与账号处理：支持请求熔断时间、流空闲超时、失败阈值、短暂重试间隔和全局临时不可调用时长；达到阈值后一律临时不可调用
- 统计配置占位：保留统计采样间隔、缓存保留时长和统计任务滞后阈值等系统项
- OAuth 快照配置占位：保留后台刷新间隔、快照过期时间、失败退避和每系统账户刷新并发等系统项
- 原始审计日志配置占位：保留启停、成功采样率、队列上限、批量落库间隔、批量大小和保留天数等系统项

- 提供前端需要的枚举、状态和配置字典

## 设计原则

### 透传

- 透传应该是账号能力的一部分，而不是临时页面配置。
- 前端不提供透传开关；透传默认全局启用，并由供应商策略决定具体实现。
- 透传时，后端尽量按客户端原始请求转发，不做 body 填充、默认内容追加或无关改写。
- 后端仍可做必要的本地鉴权、上游认证替换、协议安全头剔除、会话隔离、流式转发和错误兜底；这些作为供应商适配器内部细节，不在 UI 暴露。

### 错误处理策略

- 错误处理不能只有“成功 / 失败”两种状态。
- 需要支持按状态码、错误码、错误类型、关键词和优先级做账号级规则化处理。
- 处理动作只保留限流、临时不可调用和错误；只有显式错误规则才把账号置为错误。

### 并发

- 并发应该能区分“配置上限”和“当前占用”。
- 账号详情里最好能看到限制值和运行态。
- 后续网关层接入时，才真正按并发规则做调度。

### 代理

- 代理建议独立成一个配置实体，不要直接写死在账号请求里。
- 账号只负责绑定代理，实际请求时再解析代理地址。
- 这样后续更容易复用、切换和排查。

## 建议的数据对象

- `system_account`：系统登录账号与角色
- `session`：登录会话
- `global_setting`：平台全局设置
- `provider`：供应商定义
- `account`：上游 AI 账号主表，包含 `system_account_id`
- `group`：账号分组，包含所属 `provider_code`
- `group_account`：分组与账号关联
- `api_key`：对外访问密钥
- `proxy_profile`：代理配置
- `usage_record`：使用记录
- `runtime_logs`：普通运行日志搜索索引主表，固定保留最近 3 天
- `runtime_log_search`：普通运行日志 FTS5 搜索索引
- `audit_logs`：原始审计日志主表，保存可检索元数据
- `audit_log_attempts`：原始审计日志上游尝试表
- `audit_log_payloads`：原始审计日志完整原文 payload 表
- `system_teams`：系统团队基础信息
- `system_team_members`：团队成员关系
- `resource_authorizations`：统一资源授权，支持 AI 账户 / 分组授权给系统账户 / 团队
- `usage_stats_totals`：按 `system_account_id + scope_type + scope_id` 的累计统计缓存
- `usage_stats_daily`：按 `system_account_id` 隔离的天级统计缓存
- `usage_stats_hourly`：按 `system_account_id` 隔离的小时统计缓存
- `usage_model_daily`：按 `system_account_id` 隔离的模型分布统计缓存
- `usage_model_hourly`：按 `system_account_id` 隔离的小时模型分布统计缓存
- `usage_error_daily`：按 `system_account_id` 隔离的错误分布统计缓存
- `usage_error_hourly`：按 `system_account_id` 隔离的小时错误分布统计缓存
- `system_metrics_sample`：系统监控采样数据，包含 CPU、内存、进程、事件循环、网络吞吐和数据库大小
- `system_metrics_hourly`：系统监控小时聚合数据，支持性能与网络带宽趋势图
- `stats_job_state`：统计任务游标与状态
- `account_usage_snapshot`：按 `system_account_id + account_id` 隔离的账号级上游额度快照，第一阶段只用于 OpenAI OAuth 的 Codex `5h` / `7d` 进度和后台刷新状态
- `system_setting`：系统设置，按系统账户隔离
- `error_passthrough_rule`：错误透传策略

## 建议里程碑

1. 建好登录、系统账户和全局设置基础能力
2. 固化 OpenAI 供应商与账户类型定义
3. 实现分组、AI 账户、API Key、代理基础 CRUD
4. 再补筛选、详情、状态切换和复制能力
5. 补齐系统团队管理、团队成员维护和授权对象选择
6. 补齐统一授权管理、授权账户分组绑定、授权分组 API Key 绑定和授权消耗聚合
7. 补齐透传、错误策略、并发、代理字段和 OAuth 额度快照
8. 接入统计缓存、系统监控和 OpenAI 兼容 `/v1` 中转轻量调度逻辑
9. 接入普通运行日志搜索索引、3 天清理、管理员日志搜索页
10. 接入原始审计日志的终态捕获、内存队列、批量落库和管理员检索页

## 第一阶段完成标准

- 默认管理员账号可以登录、改密码、查看全部系统账户和全部业务数据
- 用户登录后只能看到自己的 AI 账户、个人或团队授权给自己的 AI 账户、自己的分组、个人或团队授权给自己的分组、自己相关的统一授权记录、API Key、使用记录和系统设置，不能看到供应商、代理管理、系统团队管理、日志搜索和审计日志菜单
- 系统账户管理页只能被管理员访问
- OpenAI OAuth 账号可以完整增删改查
- OpenAI API Key 账号可以完整增删改查
- OAuth 和 API Key 账号均支持可选账户到期时间；未填写不过期，已过期账号不能参与调度或被恢复为正常
- 授权统一在 `授权管理` 菜单维护，所有登录用户可进入；普通用户只能查看和操作自己相关授权，管理员可查看全部；支持把自有 AI 账户或分组授权给系统账户或系统团队
- 被授权 AI 账户可加入自己的同供应商分组并参与调度；不能编辑、删除、查看敏感凭据、修改配置或继续转授权
- 被授权分组只能被绑定到自己的 API Key 并用于调度，不能编辑、删除、增删账户、调整权重、修改配置或继续转授权
- 同一用户对同一 AI 账户或分组同时拥有个人来源和团队来源时，只展示一个有效资源，不出现重复账户或重复分组；团队只做批量授权来源，最终有效授权仍按用户绑定
- 授权管理可以查看每个被授权用户在资源上的消耗；团队筛选展示成员用户用量去重汇总，且不包含资源归属人自己的自用消耗
- 用量统计菜单从统计缓存读取账户多日用量；多日窗口按天级累计缓存相加，总用量读取累计缓存，不允许页面请求临时回扫明细表
- 账户创建入口不写死成多个 OpenAI 按钮，可按供应商能力渐进展示类型与表单
- 账户创建时必须选择归属分组，并默认带入该供应商默认分组
- API Key 可以完整增删改查
- API Key 可以绑定自有分组；统一授权完成后也可以绑定个人授权或团队授权给自己的分组
- API Key 页面展示本地网关 Base URL，默认 `http://127.0.0.1:3000/v1`
- API Key 新增和编辑页可以配置 n 小时、日、周、月和总请求次数额度；额度命中时网关在上游调度前返回 429
- 代理可以由管理员完整增删改查并绑定到账户
- 页面能展示基础状态和配置字段
- OpenAI OAuth 账户能单独展示上游 `5h` / `7d` 额度进度；API Key 账户仍只展示本地请求、token 和成本用量
- 账户、分组和 API Key 列表中的今日有效请求、今日 Token、平均响应和错误率不再实时汇总
- 统计缓存、OAuth 额度快照和使用记录都按系统账户隔离；授权账户和授权分组调用需要额外冗余资源所有者、统一授权 ID 和授权对象类型，便于真实资源总用量和授权消耗聚合
- 管理员视角可看到所有列表的系统账户列，用户视角自有数据不显示归属列，授权账户和授权分组显示来源、所有者摘要和个人 / 团队授权来源
- AI 账户更多菜单不提供 OAuth 用量主动刷新按钮，额度快照由后台定时器刷新
- 统计概览页默认查看近一天监控窗口，并可筛选近三天、近一周和近一月，查看模型分布、Token 趋势、错误情况和系统监控采样
- 日志搜索页仅管理员可见；按 SQLite 索引检索最近 3 天普通运行日志，常规筛选和 `traceId` 查询必须达到毫秒到秒级，最大不超过 5 秒
- 审计日志页仅管理员可见；成功请求默认 10% 采样保存，非成功、客户端中断、流式中断和中间尝试失败后最终成功的链路全量保存
- 审计日志写库必须通过后台 worker 批量落库，不能在网关请求链路同步写表；SSE 必须在流结束或终态确定后投递给 worker 队列
- 后台定时任务必须和 Web/API/网关主进程隔离运行；调度框架只能在后台 worker 进程内触发任务，不能让 worker 调度后回到主进程执行任务函数
- 后端接口有统一结构
- 文档能说明每个关键字段的作用
- 系统设置可配置用户级默认临时不可调用时长、临时状态短暂重试参数、请求熔断时间和流熔断阈值；未命中账号规则的上游错误、未知异常和流式中断都会写入账号临时不可调用状态
- 全局品牌设置可以被管理员修改，未登录页可以读取
