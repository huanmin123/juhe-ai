# PLAN-20260726T000000000Z：AI 问答生图真实链路与统一候选切换

## 状态

已完成

## 目标

在隔离、免登录的本地实例中验证 AI 问答的“首次生图 → 基于会话图片编辑 → 再次连续生图”完整链路，并统一普通文本、图片和其他请求的失败候选切换规则。

## 发现

- `gpt-5.6-*` 的优先候选分别返回 `model_not_found` 与 HTTP `401`。旧逻辑把图片和其他可能产生副作用的请求视为派发后不可重放，导致当前候选失败后直接返回 `upstream_outcome_unknown`，没有继续使用用户已经准备好的可用账户；这是生图没有切号的直接原因。
- 对话模型 `gpt-5.4` 和同一会话使用的图片模型可完成真实文本、图片生成、图片编辑和连续生成，证明聊天编排、图像资产谱系、Images API 及消息工具栏不是根因。
- 首次编辑测试期间开发 watch 重启了隔离后端，长连接被进程退出中断并记为 `stream_interrupted`。重启稳定后，在同一会话重新提交编辑已成功；这不是上游图片编辑语义错误。

## 决策

- 所有请求采用同一 availability-first 规则：当前候选没有交付可用结果且下游尚未语义提交时，继续下一个 Key、账户或后备分组。
- 完整 HTTP 非 `2xx`、timeout、连接重置和正文中断都触发当前请求内的候选切换；不通过状态码、错误码、错误正文、模型或请求类型决定“是否切号”。
- 统一规则采用有界 at-least-once，可能造成小概率重复生成、重复外部副作用或重复计费。产品明确接受该风险，以换取未拿到结果时优先救回请求。
- 真实协议事件、正文或可见输出已经交付后不得拼接另一候选的结果。图片保留独立的 600 秒首响应、120 秒 idle、3600 秒单次未提交 attempt 和默认 3600 秒整请求候选切换墙钟；这些时间参数不改变切号准入。
- 普通路由 `cost_first / speed_first` 的文本首 token 截止、慢样本和 `latency_degraded` 不作用于图片；直接 `/images/*` 也绕过 `speed_first` 专用正文 admission。直接图片与账户模型映射升级出的图片都使用图片整请求墙钟；跨过文本 270 秒后首选才失败时，只要图片墙钟仍有余量就继续健康后备候选。
- 自动切号只改变当前请求候选；不得根据状态码或错误正文写账户、Key、代理、模型或供应商共享状态。

## 验收

- [x] 隔离实例启用 development 自动登录，业务库、聊天库、数据集库、日志和运行时目录均使用独立临时路径。
- [x] 浏览器中真实完成普通文本请求、首次图片生成、基于上一张图片的编辑和再次连续图片生成。
- [x] 已完成图片预览、下载与真实图片复制工具。
- [x] 真实 HTTP 回归覆盖 background、hosted tool、audio 和 `/v1/images/generations` 的 transport reset、任意非 `2xx`、HTTP `401`、`model_not_found`、`model_not_supported` 与显式策略场景，均验证切换到后备账户并返回成功结果。
