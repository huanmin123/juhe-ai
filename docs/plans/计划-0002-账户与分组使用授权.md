## 需求目标

- 背景：账户和分组目前只能由所属用户自己管理和使用，无法把可用能力临时授权给其他系统用户。
- 目标：账户所有者可以把单个 AI 账户授权给其他用户使用；分组所有者可以把整个分组授权给其他用户使用，且被授权用户只有使用权，没有编辑、删除、凭据、代理、并发、状态、错误策略、权重和再次授权权限。
- 交付物：数据表、领域类型、后端接口、网关调度与统计归属、账户/分组页面授权管理弹窗、API Key 绑定授权分组能力、验证记录。

## 范围边界

### 本次包含

- [x] 账户使用授权：所有者授权、查看授权列表、查看被授权人用量汇总、收回授权。
- [x] 被授权账户使用：被授权用户在账户列表可见、可加入自己的分组、可被调度使用，但不可修改账户资料。
- [x] 分组使用授权：在账户授权闭环后实现，所有者授权整个分组给其他用户使用。
- [x] 被授权分组使用：被授权用户在分组列表可见、可绑定自己的 API Key 使用，但不可管理分组或分组内账户。
- [x] 日志与统计归属：请求日志归实际调用者；账户/分组总量按真实资源累计；授权弹窗展示授权对象维度的聚合用量。

### 本次不包含

- 授权额度上限：先不做按授权人限额、每日额度、模型限额，后续可在授权表扩展 quota 字段。
- 授权有效期：先只做主动收回，后续可增加 `expires_at`。
- 管理型授权：本次固定为 `use` 使用权，不开放编辑、删除、凭据查看和二次授权。
- 二次共享：分组授权第一阶段只共享分组所有者自己的账户，不传递其他人授权给该分组的账户。
- 细粒度日志开放：授权管理只展示聚合统计，不展示请求快照、响应快照、IP、API Key 明文或敏感内容。

## 方案概述

- 方案原则：授权只代表可使用，不改变资源所有者；所有管理动作仍按资源所有者校验。
- 数据变化：新增 `account_authorizations`、`group_authorizations`；`usage_records` 增加账户/分组所有者、访问类型和授权记录字段。
- 接口变化：账户与分组增加授权列表、创建授权、收回授权接口；API Key 允许绑定自己分组或被授权分组。
- 前端变化：账户“更多”增加“授权管理”；分组操作增加“更多”与“授权管理”；授权资源显示来源并隐藏管理动作。
- 后端变化：列表接口合并自有资源与授权资源；写操作只允许自有资源；网关按 API Key 所属用户校验分组使用权。
- 兼容策略：旧数据默认视为所有者自用，新增字段为空时按 `owner` 访问类型处理。

## 风险与注意事项

- 凭据泄露风险：授权账户列表不能返回完整凭据，只能返回脱敏或空凭据。
- 权限穿透风险：所有写接口必须按资源所有者校验，不能因为列表可见就允许修改。
- 二次共享风险：授权分组调度必须过滤非分组所有者账户。
- 存量 API Key 风险：API Key 可绑定授权分组后，网关每次请求都必须实时校验授权状态。
- 统计口径风险：统计缓存和实时聚合必须保持同一归属口径，避免 owner 与 caller 混淆。
- 回滚建议：如授权链路异常，可隐藏前端入口并拒绝授权资源调度，保留自有账户/分组原流程。
