## 需求目标

### 背景

切号必须以首次命中账户冻结的有效上游目标（`SwitchTarget`）为锚点：`responses` 等非 Chat 协议目标禁止跨供应商，防止上游加密上下文与协议状态交给错误供应商。该契约此前只在设计文档中承诺、计划目录没有排期条目；本计划登记其实施排期，消除悬空状态。

### 目标

- `gatewaydispatch` 新增请求级 `SwitchTarget` 冻结结构与 target-aware 候选过滤，全部跨账户切换点消费同一份冻结目标。
- target 缺失或不可解析时 fail-closed，停止跨账户切号并留下可诊断证据。

### 非目标

沿用权威设计文档第 8 节"明确不改变"清单，本次全部不触碰：

- 初始路由、模型目录和显式 `Responses -> Chat` mapping 的允许矩阵；
- 客户端画像既有职责（请求整理、状态恢复、响应检查和审计），不作为切号候选硬门槛；
- 配额、并发、熔断、质量排序、预算、物理凭据去重和已提交响应后的禁止切换边界；
- 当前分组的供应商硬过滤，不把跨供应商账号混入同一分组；
- 新 HTTP 请求的重新选路，不跨请求继承 target。

## 范围边界

### 本次包含（实施范围）

- [ ] 新增 `gatewaydispatch` 内 `SwitchTarget` 冻结结构，至少包含 `ProviderCode`、`ProviderProtocolProfileID`、`UpstreamModel`、`UpstreamEndpointFamily`、`UpstreamEndpointMode`（`contextContract` 见暂缓项 c）。
- [ ] 新增 `FilterAccountsForSwitchTarget` 目标感知过滤：按冻结的精确 `upstreamEndpointMode`、`upstreamModel`（大小写不敏感逻辑比较、保留候选规范拼写）、别名 RHS 命中和供应商规则筛选候选；别名左侧 `SourceModel`、`SourceEndpointFamily`、客户端画像和客户端请求路径不参与切号资格判断。
- [ ] 冻结时点：第一个候选完成 mapping / 状态恢复 / bridge / 请求构造之后、首次真实上游发送之前；不在只知道客户端路径或请求 `model` 时提前冻结。
- [ ] 全部跨账户切换点消费冻结目标：流式未提交重试、上游失败账户推进、分组 fallback、模型感知 reload；不重新调用只接受 `sourceModel + sourceEndpointFamily` 的初始 mapping resolver。
- [ ] fail-closed：target 缺失或不可解析时记录 `switch_target_unresolved` 诊断并停止跨账户切号，不退回客户端 source 协议，不进入"放宽筛选"降级路径。
- [ ] 空 `SupportedEndpointModes` 保持既有"不受限"语义，不因本次改造收紧。

### 本次不包含（暂缓项）

- **a) 验收矩阵第 8 行的一般化**——"别名 LHS 与客户端 source 不同但 RHS 相同"的候选加载：需要按 RHS 的独立候选加载查询与不依赖 LHS 的请求重建路径。本次切号候选仍要求能按客户端 LHS 解析（LHS 窗口内做 RHS 校验）；窗口外 RHS-only 加载暂缓。
- **b) `ConvertedContext` 的独立结构化重构**：本次复用既有 codex 逐账户物化链路（`gatewaycodex/chatbridgestate.go`），不新建独立上下文结构。
- **c) `SwitchTarget` 的 `contextContract` 字段**：随 b) 暂缓。

## 风险与注意事项

- fail-closed 会让混合协议或模型配置不完整的号池切号候选减少、最终失败或客户端交接增加；这是保护上游状态与加密上下文的预期成本，不视为回归。
- `SwitchTarget` 是请求内易失状态，不写入业务库；凭据、Base URL 和 opaque payload 不进入 target metadata。
