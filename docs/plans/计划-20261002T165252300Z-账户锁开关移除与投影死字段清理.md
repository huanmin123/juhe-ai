- 状态:**已实施完成(2026-10-03,独立复审 pass 无 blocker)**

## 目标

落实"功能只存在或不存在,不设开/关"的契约:业务功能正确性机制不提供关闭路径,有问题修问题。清理该理念下仅存的两个残留:

1. **移除 `JUHE_AI_ACCOUNT_LOCKS_DISABLED`**(gateway):账户 ENGAGED 锁是并发正确性机制,显式关闭开关让"账户视为未锁"成为一条合法运行路径,属于用关闭代替修复的后门。该开关自 2026-09-08 BUG-0174 B-2 引入后,生产配置(docker/ 与 .local 生产资料)从未使用;2026-09-21 批次清理了其他全部功能开关,此项为漏网。
2. **移除 `ListProjectionEnabled` 死字段**(jobs):2026-09-21 投影开关移除后恒 `true` 的残留字段与死分支。

## 非目标

- 不改 `disabledAccountLocks` 类型与 `chain_compose.go` 的 nil-guard:它与 `disabledSuppression`/`disabledDegradation` 同模式(生产恒装配真实实现,nil 仅组合测试),不是功能开关。
- 不改历史报告/bug 文档(docs/reports/账户核心专项深查与修复报告-20260908.md、docs/bug/问题-0174)中的开关记载:历史事实保留。
- 不动验证码豁免(`JUHE_AI_AUTH_CAPTCHA_DISABLED`)、运行时指标 `store=disabled`、jobs 防呆守卫(`JUHE_AI_MODEL_CHECK_ENABLED`)等合理例外。

## 行为变化(可观察)

- gateway 进程:设置 `JUHE_AI_ACCOUNT_LOCKS_DISABLED=true` 不再产生任何效果(锁运行面恒装配);未设置时行为不变。该 env 从此不属于契约,已配置它的环境在升级后锁照常运行。
- jobs 进程:无行为变化(死字段/死分支删除)。
- 部署文档:该 env 从未出现在 `docker/single-server/README.md` 或部署指南,无可同步项,无需变更。
