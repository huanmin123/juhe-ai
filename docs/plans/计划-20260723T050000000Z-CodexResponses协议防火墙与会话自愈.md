# PLAN-20260723T050000000Z Codex Responses 协议防火墙与会话自愈

## 状态

实施前设计已落地；当前从 `master` 新 worktree 开始，按阶段开发、测试、合并和发布。

## 目标

建立一套可证明、可回退、对健康账户无误伤的 Codex Responses 防火墙：源头生成正确 ID，修复确定的历史/响应协议错误，识别错误模型污染，严格拦截作为可选策略，完成使用记录与账户状态可观测性，并验证协议转换和性能边界。

## 范围

- Node 网关：Responses contract registry、JSON/SSE guard、provenance、历史 sanitizer、实际响应写回。
- 协议转换：raw upstream / gateway bridge checkpoint、模型和 item 映射自审。
- 账户配置：safe repair 默认开、strict intercept 默认关，Node API/前端一致。
- 可观测性：usage 状态、审计、账户异常原因和黄色展示。
- 测试：SQLite、PostgreSQL、Redis 边界、Mock AI、可选真实模型验证。
- 发布：本地 master 合并、远程 master 冲突处理和推送验证。

不包含：未经证据支持的通用模型内容审查、对未知协议自动猜测、将所有 502/解析失败统一归因到账户。

## 阶段与完成标准

### P0 设计和源头历史自愈（已完成）

- 设计文档、契约 registry、源头 ID factory、历史 sanitizer。
- 完成 `fc_*`/`ctc_*` 等前缀按 contract 直接生成。
- 完成 `store=false`、重复 ID、禁止字段和未知 item 的边界回归。

### P1 响应 guard 和性能（已完成）

- JSON/SSE 统一 guard、双 checkpoint provenance、R0/R2/unknown 分类。
- `response.completed` 终态、SSE stable mapping、实际 wire rewrite、JSON content-length 回归。
- `off/shadow/safe_repair/strict_intercept` 性能矩阵和有界内存门禁。

### P2 账户策略与可观测性（Node 已完成）

- Node 账户 safe repair / strict intercept 凭据字段、默认值和校验。
- strict intercept 的切号、异常账户状态和 retry/cutover 语义。
- Node usage/audit 摘要和管理端黄色状态、解释文案。

### P3 转换器自审与真实联调

- OpenAI/Anthropic/Gemini bridge 矩阵。
- SQLite/PG/Redis 运行边界、mock gateway E2E、可选真实模型测试。
- 性能复测、灰度开关、回退演练和发布报告。

## 设计约束

- 每个修复必须有规则 ID、测试和提交边界。
- provenance 必须显式携带，不能通过缺失字段推断。
- unknown 不触发账户 R2；strict intercept 不与 safe repair 同时交付同一响应。
- 清理和诊断必须有内存、数量、字节上限。
- 所有远程 master 变化先 fetch，并合入功能分支后再继续；最终只推送 `master`，不推送临时分支。
