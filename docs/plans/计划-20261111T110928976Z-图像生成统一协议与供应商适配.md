## 复查结论（2026-11-11）

本轮按厂商官方文档复核后，原计划有 3 处必须修正/裁决，不能直接按旧假设开工：

1. **异步不是厂商能力，而是网关能力；本批已决定不做异步。** OpenAI / xAI / 火山 / Qwen 2.0 的图像 API 全部是同步；没有任何厂商提供图像 async job。后续若做 `async: true`，必须新增图像任务 worker 执行同步上游调用；当前 `media_jobs` 没有图像 kind/worker。gpt-image 只返回 `b64_json`，而 `media_jobs.artifact` 零资源存储只存 URL，后续做异步前需裁决 A（仅 URL 供应商异步）/ B（受限 b64 落库）/ C（本地产物存储立项）。
2. **qwen 协议假设已纠正，且 3.0 已实测可用**：Qwen-Image 2.0/3.0 都是同步 `POST /api/v1/services/aigc/multimodal-generation/generation`，没有 task_id 轮询，也明确不支持 OpenAI 兼容模式；2026-11-11 真实探针 `qwen-image-2.0` 与 `qwen-image-3.0` 均 200，响应都是 `output.choices[0].message.content[0].image`，但 **3.0 的 usage 字段与 2.0 不同**（3.0 `output_image_count/output_width/output_height/input_image_count/...`，2.0 `image_count/width/height`），adapter 必须兼容两种形态。
3. **图像流式是 OpenAI 的协议扩展，不是厂商通用能力；本批不做**：OpenAI Images 有 `stream: true` + `partial_images`（0-3）与 `image_generation.partial_image` 事件；xAI / Qwen 原生图像 API 没有 stream；火山 Ark 仅部分 Seedream 模型支持逐张 `stream`，语义也不是 OpenAI 部分图事件。2026-11-12 用户裁决：图像统一契约**只返回 JSON、不支持 stream**，四家（含 gpt）收到 `stream: true` 都不返回 400，接受但忽略并回显 `params_ignored`，上游请求不携带；gpt 不再直通 SSE，后续确有需要再单独扩展。

已纠正的其他事实：

- 火山 Seedream 的 `seed` / `guidance_scale` 在官方页未文档化，首批不能承诺；`watermark` 默认 true（网关首版默认显式传 `false`，可用 `provider_options.volcengine.watermark` 覆盖）；`stream: true` 仅 Seedream 5.0 lite / 4.5 / 4.0 支持，5.0 pro/flash 不支持，且事件形态与 OpenAI SSE 不同。
- xAI 只确认了 endpoint、模型 `grok-imagine-image-2.0`、能力描述和 `data[].url` 响应；`n` / size / aspect ratio / response_format 的精确字段名需 OpenAPI 或真实探针。
- 计费不是四家统一按张：gpt-image 2.5 等是图像 token 计价（`image_output_usd_per_1m`），xAI/火山/qwen 图片行是按张；按模型行现有策略执行。
- 注册表计数：qwen 增加 image 域/mode 后，官方组合 42→43、单 mode 133→134，fingerprint 变化。

**结论**：本批只做同步适配；异步移出本批，后续立项前再裁决 worker/b64；qwen-image-3.0 与 xAI 字段名必须真实上游探针后再定 adapter。

## 需求目标

### 背景

图像生成是当前媒体域唯一没有统一适配的类型：

- 对外虽然有 OpenAI Images 直通，但没有按供应商适配官方协议。
- xAI 图片模型有目录行，但网关没有 xAI Images 出站 driver。
- 通义 `qwen-image-3.0` 有目录行，但 qwen 注册表没有 image 域和 `images_json` mode。
- 火山 Seedream 只有基础透传，`watermark` / `sequential_image_generation` / `stream` / `image`（图生图）等参数没有统一映射与回显。
- `provider_options` 只在视频/音频链消费，图像请求没有这条扩展通道。

### 目标（可观察）

1. 对外统一 OpenAI Images 协议：客户端只按 `POST /v1/images/generations` 调用，不感知供应商差异。
2. 网关按最终模型/供应商适配官方协议：gpt（OpenAI 原生）、xAI Grok、火山 Seedream、通义 Qwen-Image 主流优先。
3. `provider_options` 作为唯一厂商扩展通道：按供应商命名空间取子对象，deep-merge；未支持参数进 `params_ignored`。
4. 响应统一为 OpenAI Images 形态，错误归一，usage 按模型行计费（按张或图像 token）。
5. 本批只做同步；异步生图移出本批，后续有需求再立项（需要图像任务 worker 与 b64/存储策略，见风险）。
6. 补齐 qwen image 能力域与注册表，图像车道按模型能力判定。

5. **中转项目对照（One API / New API）**
   - One API：统一 OpenAI API 格式；OpenAI 兼容下游渠道透传，非 OpenAI 上游“中继并修改请求体和返回体”；通过 channel 负载均衡与模型映射选上游；README 明确支持绘图接口。
   - New API：明确列出 `/v1/images/generations` 与 `/v1/images/edits`；按 channel（上游 Key/模型/分组）路由，带模型映射、优先级/权重、重试；图片/视频任务 API 可通过 JavaScript 插件扩展。
   - 含义：中转项目的通用做法就是“OpenAI 兼容面 + 按渠道透传/改写”，图像与文本同一套中继；gpt 官方与 OpenAI 兼容中转可以共用 native passthrough，xAI/火山/Qwen 官方上游才需要 adapter；不要为中转另造协议，也不要按模型名判断厂商。
   - 来源：`https://github.com/songquanpeng/one-api`、`https://github.com/Calcium-Ion/new-api`。

6. **后续异步（本批不做）的约束**
   - 四家图像 API 目前都是**同步**（OpenAI/xAI/火山/Qwen 2.0）；没有任何一家提供图像 async job 协议。后续若要“异步”，只能是**网关侧任务**：POST 建任务、worker 执行、任务面查询。
   - 现有 `media_jobs` 只有 `video` / `audio_transcription` / `audio_speech` 三种 kind，且是网关在 GET 时轮询上游；**没有图像 kind、没有图像 worker**。
   - `media_jobs.artifact` 只存 `ContentURL`（零资源存储，不存字节）。gpt-image 的响应是 `b64_json`，没有 URL；后续异步 gpt-image 若要落任务结果，就会撞零资源存储，必须先裁决 A/B/C。
   - 本批不涉及以上改造；保留本节作为后续立项的依据。

## 方案概述

### 1. 对外契约

- 端点：`POST /v1/images/generations`；对外统一 OpenAI Images 形态。
- 同步（默认）：返回 `{ created, data: [{ url | b64_json, revised_prompt }], usage? }`。
- **响应宽容（2026-11-11 用户裁决）**：不校验上游返回的 `model` / 厂商 / `mime_type`；只要 `data[]` 至少一项带 `url` 或 `b64_json`，就视为“能出图可用”。`created` / `model` / `usage` / `mime_type` 可缺省，额外字段忽略；响应里的 `model` 只记录到 usage 的 `upstream_response_model`，**不参与路由、不拦截、不改价**。没有可用图片才按上游错误/无图片处理。
- 图像流式（2026-11-12 用户裁决，本批不做）：图像统一契约**只返回普通 JSON、不支持 stream**。四家（含 gpt）收到 `stream: true` / `partial_images` 均不返回 400，接受但忽略，回显 `params_ignored`，上游请求不携带这两个字段；不返回 SSE，也不把厂商逐张流式语义混入统一契约。后续确有需要再单独立项扩展。
- 本批只做同步；异步（`async: true`、任务面、worker）不在本批，后续有需求再立项。
- 公共参数：`model`、`prompt`、`n`、`size`、`quality`、`background`、`output_format`、`output_compression`、`safety_identifier`；`stream` / `partial_images` 仅为客户端兼容输入，四家统一忽略并进 `params_ignored`。`safety_identifier` 是 OpenAI 新字段（`user` 已 deprecated）；`response_format` / `moderation` 不是所有厂商都支持，按供应商矩阵处理，不能当作全局公共参数。
- L3 扩展：`provider_options: { "<supplier_code>": { ... } }`；只取命中供应商的子对象 deep-merge，其余忽略；未知键原样透传由上游裁决。
- 回显：`provider`、`params_applied`、`params_ignored`、`provider_options_applied`（键名摘要，不含值）。
- 未支持参数：本地可判定的忽略并进 `params_ignored`；上游参数错误保留原始错误语义，不静默降级。

### 2. 供应商适配（主流优先）

| --- | --- | --- | --- |

### 4. usage 与计费

- **计费跟随模型行，不强制统一按张**：有 `output_usd_per_image` 的行按张计费（xAI/火山/qwen 图片行）；gpt-image 2.5 等行是图像 token 计价（`image_output_usd_per_1m`），按现有 `pricing.BuildCostBreakdown` 的按张/图像 token 策略执行。
- 张数提取按厂商归一：xAI `data[]` 长度（无显式张数）+ `usage.cost_in_usd_ticks` 保留 raw；火山 `usage.generated_images`；qwen 2.0 `usage.image_count`、qwen 3.0 `usage.output_image_count`；gpt 走现有图像 token/张数策略。
- **usage 记录请求模型与实际返回模型**：复用现有 `usage_records.upstream_model`（本次实际发送的 wire model）与 `upstream_response_model`（上游响应 `model` 字段，缺失则空），`pricing_model` 用配置模型行；不因两者不一致拦截请求、不改价、不猜厂商。xAI 响应无 `model` 时 `upstream_response_model` 留空；中转返回别家模型时如实记录实际值。
- `usage.cost_in_usd_ticks` 是厂商成本提示，不直接替代目录价；保留在 raw usage，成本仍按模型行计算（若要按上游成本计费，另立口径）。
- 成本快照与 usage 记录沿用现有媒体口径；失败不虚计。

4. **xAI 响应/usage 与 OpenAI 不同**：实测 `n`/`response_format` 可用；响应 `data[].url` + `mime_type`，usage `cost_in_usd_ticks`，无 `created`/`model`；size/aspect ratio 字段名仍需补。
5. **gpt 中转不按响应模型拦截**：新 Key 已验证真实 OpenAI Images（b64_json + token usage）；另一组 403；shenwenai 把 gpt-image 名称映射到 xAI。按用户裁决，只要返回里有可用图片就接受，不因响应模型/厂商不一致拦截；usage 记录 `upstream_model`/`upstream_response_model`，按配置模型行计费。只有想精确 error/usage 语义时才建议按实际上游配置账户。
6. **产物 URL 时效**：qwen 图片 URL 官方 24 小时有效，火山实测 TOS 签名 24 小时；本批同步直接返回 URL，由客户端自行取回；后续异步任务要带 `expiresAt`/过期提示。
7. **火山参数差异**：`watermark` 默认 true（网关首版显式 false）、`seed`/`guidance_scale` 未文档化；`size` 支持档位/WxH；`stream` 仅 Seedream 5.0 lite/4.5/4.0 支持（5.0 pro/flash 不支持），且是逐张返回而非 OpenAI 部分图事件；首批不承诺未文档化参数。
8. **gpt b64 响应体量**：2026-11-11 实测 `gpt-image-2` 单张 `b64_json` 约 1.58MB，2026-11-12 复测同模型单张约 5.8MB（随 prompt/尺寸变化）；现有文本 body 限制/缓冲可能不足以承载图像响应。需确认 image lane 的请求/响应体上限；本批 gpt 为同步 JSON 字节透传、不做 SSE，避免额外缓冲放大，多张 `n` 时按张数线性增长。
9. **图像流式口径**：本批按用户 2026-11-12 裁决**统一只返回 JSON、不支持 stream**；四家（含 gpt）`stream`/`partial_images` 接受但忽略并回显 `params_ignored`，上游请求不携带，不返回 400。xAI/Qwen 无原生流式、火山逐张 `stream` 的厂商语义也不混入统一契约；后续确有需要再单独立项扩展。
10. **注册表计数/fingerprint**：qwen 增加 image 域/mode 后，官方组合 42→43、单 mode 133→134，fingerprint 变化；必须同批更新注册表测试、设计文档 §1.1、schema 校验。
11. **图像车道**：preflight 已有 `accountModelsTargetImage` 按模型目录能力升级 image lane；前缀只作早期提示，不能只靠模型名猜。
12. **计费口径**：不是四家都按张。gpt-image 2.5 等是图像 token 计价，xAI/火山/qwen 图片行是按张；按模型行的现有策略执行，不能强行统一。
13. **不混入其他改造**：本计划不做账户协议重构、菜单、自定义供应商、请求覆盖；相关改动另立项。
14. **发布**：本期不执行生产发布；涉及注册表/模型目录变更时按 `docker/single-server` 标准流程与发布窗授权执行。
