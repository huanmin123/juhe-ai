## 已确认并实施的契约

- 路由：`GET/PATCH /settings/sections/:sectionKey`，只接受服务端目录中的固定 key。
- section：`brand`、`gateway-core`、`account-health`、`api-rate-limit`、`account-test`、`cooldown-retest`、`data-retention`。
- 首屏：只加载 `brand` 与 `gateway-core`；其他 section 接近视口或展开时加载。
- PATCH：只接受本 section 实际出现的字段，返回本 section 最新值；未知、跨 section 和危险 key 返回 400。
- 前端：每 section 独立 loading/error/saving/baseline/dirty/generation；未加载区块不渲染可编辑默认值。
- 缓存：section 独立缓存，写后同步失效目标 section、对应完整 settings、品牌和网关 runtime 缓存。
- 兼容：内部完整 settings 永远不由页面 section 拼装；现有完整管理入口暂留兼容但禁止新增调用方。

上述契约已获本轮剩余 Node/Vue 按需加载实施授权；前端身份/KeepAlive generation 和外部验证仍属于完成门禁。

## 验收标准

- 首屏只请求品牌和高频网关 section，其他 section 未触发时请求数为 0。
- 每个管理 GET/PATCH、repository 和 worker 都只处理固定 section 白名单，不接受客户端任意 keys。
- 保存 payload 只含已加载且 dirty 的本 section 字段，未加载字段和内部 runtime 字段保持数据库原值。
- PATCH 响应不含完整 settings，写后 section、完整 settings、品牌和 runtime 失效正确。
- 内部完整 `getSettingsAsync()`、SQLite worker、真实 PostgreSQL、前端竞态和既有 runtime 回归全部通过。

## 风险与注意事项

- 不能用完整 `getSettingsAsync()` 后裁字段伪装 section 冷读，否则只缩小响应而没有缩小查询和校验。
- 不能继续从带默认值的完整 `SystemForm` 构造 payload；这是未加载字段被覆盖的主要风险。
- section cache 正确不代表 runtime cache 已刷新；系统 PATCH 必须保留现有网关失效通知。
- 兼容完整管理入口暂留不等于允许 Vue 或新调用方继续依赖。
- 当前工作树包含大量既有改动，实施时禁止整理、回退或提交无关差异。
