# PLAN-20261024T051925945Z：SQLite 与内存模式彻底退役

> 状态：已批准，实施中（2026-10-24 用户拍板）。本计划是本次存储形态收口的契约权威；批次完成情况在文末状态表滚动更新。

## 1. 背景与决策记录

- 2026-09-19 产品决策（PLAN-20260919T000723744Z 时代的开源降门槛）：gateway 二进制空 env（standalone sqlite + memory 驱动）零配置可启动。**本计划经用户 2026-10-24 明确裁决反转该决策**：sqlite + 内存本地模式维护吃力（每次存储迁移双方言双工、组合根双臂、golden 双份、跨进程契约双载体），彻底退役，全仓唯一存储形态 = PostgreSQL + Redis。
- 用户裁决原文要点：彻底下掉、没有缓冲期、不要向后兼容、彻底物理删除、兼容口子都不要；测试基建一并迁真实 PG（在「仅删运行时面」与「彻底全删」之间选择了后者）。
- 事实基线（2026-10-24 五路并行取证）：组合根受四开关（`JUHE_AI_RUNTIME_MODE` / `JUHE_AI_DATABASE_DRIVER` / `JUHE_AI_CACHE_DRIVER` / `JUHE_AI_RUNTIME_STATE_DRIVER`）控制的分支约 128 处、涉及约 30 个非测试源文件；包级方言 selector 30 处（gateway 15 / jobs 11 / shared 4）；maintenance 双方言 DDL 文件对 6+ 域、PRAGMA 守卫 19 函数（含 3 处删列重建）；323 个测试文件直接 `sql.Open("sqlite",...)`（81 包，宽口径 370）；`modernc.org/sqlite v1.58.0` 为 4 个 go.mod 直接依赖；memory 驱动臂约 14 项可删、4 项与驱动无关保留、3 项需细审。

## 2. 目标

1. 仓库内 sqlite 存储形态物理清零：运行时模式开关、组合根 sqlite/memory 装配臂、共享层方言双实现、maintenance `--driver sqlite` 形态、sqlite 分片（usage shards / codex-context state shards）、sqlite 专库文件族路径派生（datadir 固定名表中的 `*.sqlite3` 项）全部删除。
2. `modernc.org/sqlite` 及其传递依赖从全部 go.mod 移除；全仓非历史文档、非安全红线条目中不再存在 sqlite 存储形态的可运行引用。
3. 测试基建统一迁真实 PG：新建共享测试设施 pgtestkit（每测试隔离数据库 + maintenance fresh DDL），323 个直接建库测试文件全部迁 PG；`go test ./...` 在可达 PG 上全绿。
4. 文档与部署契约同批收口：`SQLite存储说明.md` 退役（现行事实迁入 PG 文档），`PostgreSQL与Redis高性能模式设计.md` 改写为唯一存储形态权威，部署文档 env 契约、脚本与回归断言同步。

## 3. 非目标

- 不改变任何 PG/Redis 路径的现有运行行为（本战役是纯删除 + 测试设施替换；redis 下同步定价关闭、`pricing_model` 恒 NULL 等现行为保持不变）。
- 不新增任何兼容层：不为旧 env 值、旧命令行形态、sqlite 数据文件迁移提供任何读取或转换能力（sqlite 数据文件本身不做迁移——生产与开发均无活在 sqlite 上的数据）。
- 不动 `sqldialect`（生产 PG 路径依赖 `?`→`$n` 占位符重写）、advisorylock（PG-only）、miniredis / pgfake / 录制驱动 / scripted 假驱动等与 sqlite 无关的测试设施。
- 不处理 docs/plans、docs/bug、docs/refactors 历史文档（保留为历史截面）；不动发布包 `.sqlite` 禁入安全红线。

## 4. 终态契约

- 删除 env：`JUHE_AI_RUNTIME_MODE`、`JUHE_AI_DATABASE_DRIVER`、`JUHE_AI_CACHE_DRIVER`、`JUHE_AI_RUNTIME_STATE_DRIVER`、`JUHE_AI_DATABASE_PATH`、`JUHE_AI_CHAT_DATABASE_PATH`、`JUHE_AI_DATASET_DATABASE_PATH`、`JUHE_AI_RUNTIME_LOG_DATABASE_PATH`、`JUHE_AI_USAGE_CATALOG_DATABASE_PATH`、`JUHE_AI_STATS_DATABASE_PATH`、`JUHE_AI_ACCOUNT_BALANCE_DATABASE_PATH`、`JUHE_AI_USAGE_SHARD_ROOT`、`JUHE_AI_USAGE_SHARD_COUNT`、`JUHE_AI_CODEX_CONTEXT_STATE_SHARD_ROOT`、`JUHE_AI_CODEX_CONTEXT_STATE_SHARD_COUNT`、`JUHE_AI_ACCOUNT_HEALTH_JOBS_OUTCOME_SQLITE_PATH`、`JUHE_AI_MAINTENANCE_J3B_SQLITE_PATH`，以及 `JUHE_AI_AUDIT_LOG_STORE` / `JUHE_AI_OPERATION_LOG_STORE` / `JUHE_AI_RUNTIME_LOG_STORE` / `JUHE_AI_J3B_STORE` / `JUHE_AI_ACCOUNT_HEALTH_INPUT_SOURCE` 的 sqlite 与 files 取值（变量本体是否保留以「PG 语义仍有独立取值」为准，逐个裁决：仅剩单一合法值的变量整体删除）。

- 保留派生（普通文件目录，PG 模式仍消费）：`JUHE_AI_DATA_DIR` 缺省 `./data` 下派生 `usage-record-spool`（D1）、`codex-context` segments 根、`logs`、`chat-assets`、`audit-blob`。

- `--mockdata` / `--verify-mockdata-coverage` 改造为 PG 造数（D7）。

### 4.2 测试形态

- 新建 `shared/platform/pgtestkit`：只做基础设施（管理员连接解析、每测试建独立数据库、DDL 准备回调注入、测试后删库）。模块边界约束：kit 不 import maintenance（跨模块），DDL 准备由各包以回调注入（如 `bootstrap.EnsurePostgres`）。
- 管理连接解析顺序：`JUHE_AI_TEST_PG_ADMIN_URL` 显式 env → `.local/project-resources/dev/env/shared.env` 的 `JUHE_AI_POSTGRES_URL`（`:6432→:5432` 直连、库名可改写）+ `DEV_POSTGRES_ADMIN_*` 凭据组合。临时库命名遵守开发库约定前缀 `juhe_ai_sub2api_dev_<name>`，用完即删。
- **PG 不可达时相关测试显式失败（非 skip）**：测试基建迁 PG 后，存储测试即核心回归面，静默跳过等于假绿。离线/无开发库环境需显式提供 `JUHE_AI_TEST_PG_ADMIN_URL`。现有 53 个 env-gated skip 语义的专项测试保持各自现状不变。
- 建库策略（独立 database 为隔离单元）以 B1 POC 实测定案：首选「模板库 + `CREATE DATABASE ... TEMPLATE`」加速，备选每测试直建 + fresh DDL；并发安全（并行包）必须成立。

## 5. 关键设计决策

| # | 决策 | 理由 |
| --- | --- | --- |
| D1 | usage spool / overflow spool 目录派生改挂 `JUHE_AI_DATA_DIR`（缺省 `./data`），不再以 `JUHE_AI_STATS_DATABASE_PATH` 目录为派生根 | 取证 R1：PG 模式 spool 派生寄生在 stats 库路径上；删库路径派生会断 gateway↔jobs 交接链。改挂 DATA_DIR 后 PG 零配置派生路径不变（`<DATA_DIR>/usage-record-spool`），显式 `JUHE_AI_USAGE_SPOOL_DIRECTORY` 覆盖语义保留 |
| D2 | codex-context：保留 segments 文件根（`<DATA_DIR>/codex-context`，gateway/jobs 同源契约），删除 `state-shards` sqlite 分片子面 | 取证 R2：父子目录关系，删子不伤父 |
| D3 | `JUHE_AI_RUNTIME_MODE` 的非 driver 消费点（`UpdateAgeOnGet`、statreads、内部注册表 publisher、RuntimeDriverConfig）随模式删除收敛为 PG+Redis 恒定行为 | 取证 R3：standalone 不再是合法值，判据必须消除而非保留恒 false |
| D4 | gateway 侧 memory 形态恢复组件（chain_circuit_recovery、KeyModelMemoryRecovery）删除；redis 形态恢复归 jobs 为生产现状 | 生产已运行 redis 形态，恢复链路已在 jobs；B7 全量回归验证 |
| D5 | gatewaysession `trafficMigrationPreference`（redis 无实现）随 memory 臂删除而永久下线 | 生产（PG+Redis）现状即关闭；属既有行为固化，非新行为变更 |
| D6 | `SyncPricingAllowed` 门保持现语义（redis 下同步定价关闭）不变；删除的只是「按 cacheDriver 判断」的写法 | pricing_model 恒 NULL 是已知生产事实，启用同步定价属独立行为裁决，不在本战役 |
| D7 | mockdata 域整体 PG 化重写（目标开发库/测试库，复用 pgtestkit 同源连接约定） | 取证 R7：--mockdata 现为 sqlite-only，sqlite 删除后命令失效；dev 工作流需要造数能力存续 |
| D8 | `shared/contracts/business_sqlite_schema.go` 改写为 PG-only 业务形状契约（重命名去 sqlite 化），`CheckBusinessPostgresSchema` 继续以该 map 为事实源；sqlite 校验函数删除 | 取证风险 1：该 map 同时驱动 PG 启动门禁，不能直接删 |
| D9 | sqlite 特有失败臂测试（WAL/busy_timeout/文件锁/垃圾文件/零配置 seed）裁决原则：有 PG 对应失败模式的按 PG 臂重写（池获取失败、schema 探针失败、连接拒绝），无 PG 对应物的删除 | 取证 C：约半数 cmd 层臂测试无 PG 对应场景 |
| D10 | maintenance golden 快照断言 `ORDER BY rowid` 改为按主键排序 | PG 无 rowid |
| D11 | gateway go.mod 对 maintenance 的 replace：六库 preflight 删除后评估解除；同目录 PG 检查函数保留 | 取证风险 2：replace 的唯一运行时理由是 sqlite preflight |
| D12 | accounthealth `InputSource` 收敛为 postgres 单值（sqlite 直读臂与 files 臂删除，env 随之退役） | 「无兼容口子」；files 属同族本地形态 |
| D13 | jobs `jobregistry` 调度注册表清理 sqlite 行与 sqlite-only 任务注册（usage-scope-range-windows 等），避免永不可达注册项 | 取证 R8 |
| D14 | retention 的 usage-shards 清理面（cleanuprepo.NewShardStore）：随 sqlite 分片删除一并移除其消费点；实施时先验证 PG 形态无行为依赖 | 取证 R6 |
| D15 | PolicyCache 进程内 LRU / pendingHits 在 redis 模式的消费路径：由该文件实施切片细审，保持 redis 路径行为逐字节不变 | memory 臂判定表的需细审项 |
| D16 | dev `.local` env 文件（shared.env / standalone.env）中的模式变量清理为可选跟进项，不在本战役强制范围（未知 env 代码不再读取，无行为影响） | 私有资源最小扰动 |
| D17 | SQLite-only 生产臂的测试组（被测对象在 PG 上不存在，如分片、镜像半区、结算链）不提前迁移也不提前删除，随其生产臂删除批次（B6 等）同批退役；D9 的执行细则 | cleanuprepo POC 裁决（2026-10-24）：组B 约占该包建库测试面 60%，强行迁移必改写断言；提前删除会让仍在场的生产臂失去语义覆盖 |

## 7. 验收标准

1. 每批次结束：三项目 `go build ./...` 与 `go vet ./...` 绿；该批次涉及包 `go test` 绿（PG 可达环境）。

3. B9 结束：公开文档（docs/、docker/、根 AGENTS.md、backend-go/README）中 sqlite 存储形态引用清零（历史文档目录 docs/plans|bug|refactors 与发布包安全红线除外）；部署文档 env 契约与代码一致。
4. 网关冒烟：PG+Redis 环境下 gateway/jobs/maintenance 全流程可用（`--ensure-schema --seed`、启动、`/v1` 链路、usage spool 交接）。

## 8. 风险与回滚

- 全程工作树内进行、不提交不推送（用户未授权提交；交付时按批次建议提交切片）。回滚 = `git checkout -- .`（覆盖/删除前不产生不可恢复状态；所有删除对象均在 git 追踪内）。
- 测试迁 PG 后套件时长上升（每测试建库）；B1 POC 实测，超预期则以模板库加速，仍超预期回 Plan 调整隔离粒度。
- 高风险点：D1 spool 派生改挂（错则 PG 零配置断粮）、D8 契约改写（错则 PG 启动门禁失效）、B2 组合根大量删臂（以组合根守卫测试与 w1/w2 迁移后回归兜底）。
