## 背景与动机

### codex-proxy-rs 调研结论（价值分档）

- **第一档（真实价值，修已验证的失效模式）**：官方客户端版本自动跟版、请求体透传保真、观测节奏随机化。本计划只落这一档。
- **第二档（对冲性赌注，无公开实证）**：账号级指纹一致性策略、TLS 同栈（rustls + aws-lc，官方 Codex 同为 Rust，属于语言选择的低成本副产品）、Responses WebSocket 传输、版本滞后档位。全部留观不实施。
- **天花板（代码不可控）**：`x-oai-attestation` 设备证明头（codex-proxy-rs 也不伪造，仅剥离下游值）；账号层风控变量（支付、IP、并发、使用模式）权重大概率高于请求层特征。"不降智"最可能的主要成因是劣质代理破坏协议导致上游按协议劣化响应，请求层保真是本分而非秘籍。

### 现状事实（已核实，构成零改动/纯接线判断的依据）

- **override 消费链路已三处接线**：jobs `cmd/juhe-ai-jobs/worker_settings.go`、gateway `internal/settings/store.go`、gateway `cmd/juhe-ai-gateway/compose.go` 均把 system_settings 键 `upstreamClientVersionOverrides` 加载进 `upstreamidentity.SetClientVersionOverrides`（全量替换语义：nil/空 map 回落内置常量）。自动跟版任务**只需写该键**，gateway 与 jobs 的身份生成代码零改动。
- **抖动基建已存在**：`backend-go-platform/schedulejitter`（SubMinute/Minute/Hour/Day 四档窗口），jobs 侧 `internal/schedulejitter` 薄转发。阶段 3 是审计接线，不是新建。
- **任务注册模式**：`jobs/internal/jobregistry/schedule.go`（对齐旧 Node `background-jobs.ts` 的调度参数），新任务族按此注册。
- **Grok 426 解析代码不存在**：现锚点 1.0.13 来自服务端 426 "Grok CLI version ... outdated" 门槛值（identity.go 注释记录），但无任何解析代码，升档靠人工。阶段 2 为新增逻辑。
- **UA 混合格式疑点**：`Codex Desktop/0.159.3 (Windows 10.0.22621; x86_64) unknown (codex_exec; 0.159.3)` 为 Desktop originator + CLI exec 风格后缀的组合；codex-proxy-rs 严格区分两个 surface（Desktop 后缀为 `(Codex Desktop; <desktop_version>)`，CLI exec 的 originator 即 `codex_exec`）并有配套一致性校验。该格式是否为当时实测值待核实（阶段 4）。

## 需求目标

1. 客户端版本自动跟官方发布源，消除手写常量的过期失效模式（xAI 对 Grok CLI 强制最低版本导致 426 的先例已发生，OpenAI 跟进只是时间问题）。
2. 打外部上游的周期任务节奏随机化，消除多账号池化的"整点共享特征"。
3. UA 身份格式核实，消除混合身份疑点（若坐实则修复）。
4. 留观项显式登记，明确各自触发条件。

## 范围边界

- **做**：阶段 0–5（见执行拆解）。
- **不做（留观）**：TLS 指纹对齐（Go 侧需 utls 类方案，维护成本高且无实证必要性）；Responses WebSocket 上游传输（大工程，官方未弱化 HTTP/SSE）；请求正文结构改写；版本滞后档位/账号画像差异化（无风控反馈前属过度设计）。
- **授权边界**：本计划覆盖代码与文档实施，**不含生产部署/发布**（另行授权）；预期无新增 env、无 compose/部署面变化（复用现键 `upstreamClientVersionOverrides`）。

## 验收标准

1. dev 隔离环境完成一轮真实拉取：四族新值写入 `upstreamClientVersionOverrides`，`EffectiveCodexVersion()` 等返回新值，停掉任务后值保留。
2. 单源故障注入不影响其他族，日志含失败族与保留值记录。
3. 手动覆盖语义符合裁决 B（手动值不被自动任务改写）。
4. UA 核实结论落文档；若裁决 C 为随批修复，修复含测试且全绿。
5. 文档同步清单：设计文档（新建）、`docs/functions/README.md`、`docs/plans/README.md`（本条目状态更新）；无部署面变化则不动 docker 文档。

## 风险与注意事项

- **同日集体升版的池化特征**：自动跟版使全部账户同日切新版本，codex-proxy-rs 用滞后档位对冲；属第二档赌注，本计划不做，登记留观。
- **发布源结构变更**：GitHub/npm 接口稳定，仍以 semver 校验 + 保留旧值兜底；解析失败显式记录，不静默。
- **Grok 文案样本不足**：仅一例历史证据，宽松匹配 + 失败保留现值，不猜测语义。
- **单调不回退语义边界**：单调检查按"族"隔离（Claude 回退不影响 Codex 更新）；管理员显式降级（裁决 B 的手动值）优先于单调检查。
- **总工作量估计**：含阶段 2 约 4–6 天；不含约 3–5 天。
