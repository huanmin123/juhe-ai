## 目标

## 固定工作法

每次只处理一个小功能切片或一个可验证缺陷，不因为同属一个大模块而一起改动。

1. 冻结证据：定位对应 Node 路由、服务、存储和测试，再定位 Go 路由、服务、store、调用方及已提交 diff；标明比较的历史提交。
2. 比较结果：按成功、失败、空值、权限、并发/幂等和必要副作用列出 Node 与 Go 的可观察结果。实现方式不同但结果等价时记录为“非缺陷”并说明依据。
3. 先记录：将确认的差异、触发条件、影响、Node/Go 证据和最小复现补入既有 BUG 文档；无法证明的线索不升级为缺陷。
4. 再修复：只修改该差异的最小 Go 范围，补充可回放的 Mock/单元或 HTTP 回归用例；不得同时夹带迁移、重构或未审计的并行文件。
5. 验证与复审：运行受影响 Go 包的定向测试、-race、必要的 go vet 与 git diff --check；由未参与写入的审阅者根据 Node 证据、diff 和测试独立复核。发现 blocker 则回到第 1 步。
6. 提交：只精确暂存本切片的代码、测试和问题记录，使用独立提交；提交后重新核对 git status --short，确保未带入并行迁移改动。

## 验证矩阵

| 类型 | 最低验证 | 通过标准 |
| --- | --- | --- |
| Node/Go 对照 | 源码、路由挂载、调用链、已有测试和提交 diff | 可定位到同一入口与同一结果，不以注释或迁移说明替代行为证据 |
| 回归测试 | 受影响 Go 包的定向 go test；有并发、缓存或状态机时补 go test -race | 覆盖成功、确认差异的失败路径和至少一个相邻回归路径 |
| 外部依赖 | 优先可回放 Mock；Redis/PostgreSQL/多实例行为仅在依赖真实可用时做定向集成验证 | Mock 不代替真实 owner/多实例结论；不可执行时标为未验证 |
| 静态检查 | go vet（受影响包）与 git diff --check | 无新增诊断或格式错误 |
| 提交后复审 | 独立审阅 Node 证据、Go diff、测试和范围 | 无 blocker；否则回到证据阶段，不能标记完成 |

## 验收标准

本计划只有在纳入的每个迁移单元都满足以下条件时才可关闭：

- 每项都存在可追踪的“等价”“已修复”或“经维护者确认不做”的结论；不存在只凭迁移提交说明推断的通过项。
- 已确认缺陷都有问题记录、最小回归测试、独立复审和精确 Git 提交。
- 对完整接管相关功能，唯一 Go owner、Node 活跃路径归零、migration-backup 归档和切换/回滚证据按迁移规则单独验收；这些缺失不得被单元测试掩盖。
- M09、M09b 和并行未提交工作仍保持排除，除非维护者显式更新本计划范围。

## 风险与注意事项

- 当前工作区已有其他 AI 的未提交迁移改动；任何提交前必须精确指定路径，禁止 git add .、git commit -a、reset、restore、stash 或清理。
- 已发现的问题通常是“遗漏或逻辑偏离”的聚合记录。聚合问题不能被一次局部改动自动关闭，必须逐个子项复核。
- 不把 Go 的更高并发能力误判为功能差异；也不把 Node 的限制、错误映射、权限或状态副作用当成可随意删掉的实现细节。
- K2 入口缺失会遮蔽真实运行行为，但不改变对 Go 实现本身继续做静态/Mock 对照的必要性。
