## 验收标准

- 管理端和个人端打开测试弹窗均不请求 `test-options`。
- 模型下拉首次展开才请求供应商模型窗口；搜索和已选补齐保持现有语义。
- 请求形态下拉首次展开只请求当前模型 capabilities，不拉完整模型列表。
- 从模型下拉切换模型直接使用该模型选项随响应返回的请求形态。
- 切账户、切模型、关闭弹窗、失败重试和迟到响应都有自动化证据。
- 账户测试提交的后端最终校验、草稿测试和图片模型协议不退化。

## 风险与注意事项

- 初始只有一个保存的请求形态时，协议选择器仍需允许展开，否则用户无法触发完整能力加载。
- 模型 options 与单模型 capabilities 是不同资源，不能共用一个 AbortController 或 loaded key。
- 本工作区已有其他未提交修改；只修改本计划列出的前端和文档文件，不整理无关差异。

## 完成总结

账户列表标量默认值已成为弹窗首开唯一数据源；模型与请求形态分别使用批量 options 和当前模型 capabilities 两级按需加载。两类请求拥有独立缓存、错误、取消和迟到响应门禁，模型切换时也会清除旧能力请求的加载态。

Browser 使用自动登录的隔离开发实例验证。隔离 SQLite 账户列表受工作区另一项未完成改动影响，触发“仅支持 PostgreSQL DatabaseClient”错误，因此页面列表采用固定账户响应夹具；弹窗代码、交互事件和 Network 请求均为真实运行结果，未修改或掩盖该无关后端问题。
