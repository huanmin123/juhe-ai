## 需求目标

- 背景：代理管理列表只能维护代理配置，无法直接判断代理是否可用，也看不到最近延迟。
- 目标：代理列表支持手动测试、展示检测报告，并保存最近检测状态与延迟；后台 worker 默认每 1 分钟刷新启用代理的最近延迟。
- 交付物：代理测试接口、测试报告弹窗、延迟列、后台刷新任务、存储字段和文档记录。

## 方案概述

- 方案原则：测试目标以后端供应商表为事实源，前端只展示后端报告；后台刷新在独立 worker 中执行。
- 数据变化：`proxy_profiles` 新增 `latency_ms`、`last_test_message`、`outbound_ip` 和 `outbound_region`，复用 `test_status` / `last_tested_at` 保存状态和时间。
- 接口变化：新增 `POST /api/proxies/:id/test`，返回 `ProxyTestReport`；手动测试会通过代理访问出口探测服务获取出口 IP / 地区，定位失败时用纯 IP 服务兜底。
- 前端变化：代理列表增加“延迟”“出口 IP”“地区”列和“测试”操作；列表测试只打开弹窗，弹窗内点击“开始测试”后再展示分数、等级、摘要和检测项表格。
- 后端变化：新增代理测试 service；后台任务 `proxy-latency-refresh` 默认 60 秒执行一次，批量大小默认 20，定时刷新只更新状态和延迟，不请求出口定位服务。
- 数据处理策略：当前预上线阶段使用 schema maintenance 自动补本地字段；正式上线后如需版本化升级另开计划。

## 风险与注意事项

- 检测请求会访问真实供应商默认地址；代理或网络异常会导致报告失败，这是预期反馈。
- 手动测试会额外通过代理访问出口定位服务用于展示出口 IP / 地区；如果定位服务不可用，出口信息显示为空，不影响供应商默认地址检测。定时刷新不会更新出口定位，也不会清空最近一次手动检测得到的出口信息。
- 部分供应商默认地址可能返回 `401`、`403`、`404`、`405` 或 `429`，这类状态视为“目标可达但鉴权或方法受限”的告警，不等同于代理完全失败。
- 启用代理较多时，后台任务按批量大小分批刷新，列表延迟不是强实时值。
