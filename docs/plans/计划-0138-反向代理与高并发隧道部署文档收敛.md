## 需求目标

- 新增反向代理与高并发隧道的权威指南，统一拓扑、参数、切换、回滚和验证门禁。
- 明确区分“Edge 终止 TLS 的 HTTP 反代”和“Edge L4 TLS 透传”两种入口模式；高并发家庭回源固定使用后者。
- 统一推荐 `公网 Edge Caddy layer4 + PROXY v2 -> WireGuard -> macOS Caddy 终止 TLS -> Nginx/juhe-ai`。
- 明确公网回源只允许 WireGuard，禁止 SSH `-R`、autossh 或其他单 TCP 反向隧道。
- 收敛 Linux、macOS、Caddy、Nginx、WireGuard、文件句柄和网络参数的起步值与证据驱动调优边界。
- 将外部应用 watchdog 调整为默认不部署；进程常驻由 systemd / launchd 负责，外部探针默认只告警。
- 让部署场景、HTTPS、平台和通用部署文档只维护各自边界，通过链接引用权威指南，避免参数多处漂移。

## 风险与回退

- Caddy layer4 与 proxy_protocol 依赖自定义模块，标准安装包不一定包含；部署前必须用 `caddy list-modules` 验证。
- 系统参数是起步值，不是容量保证；必须结合业务 SLO、突发与渐进两类压测以及指标增量验证。
- launchd 没有严格依赖排序；重启后必须复核 sysctl、实际进程资源上限、监听、路由和 WireGuard 握手。
- 文档变更可通过按文件恢复本计划 diff 回退，不影响运行中的生产环境。
