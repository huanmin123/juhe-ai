# PLAN-20260725T085700550Z：AI 健康监控

- 计划 ID：PLAN-20260725T085700550Z
- 状态：已完成（未上线）

- 目标：提供最近一个月按小时的 AI 账户健康状态列表，支持账户名搜索和分页。

- [x] 增加管理 API 和用户 API，限制 31 天窗口并稳定分页。
- [x] 增加菜单、路由、搜索、分页、Canvas 状态条和响应式空态。
- [x] 补充 Mockdata、回归测试和开发文档关联。
- [x] 完成前后端类型检查、前端生产构建、专项回归与 Browser 桌面/移动验收。
- [x] 收口为“可用 / 不可用 / 无记录”三态，删除失败归因和供应商错误规则设计。
- [x] 将页面文案统一为“不可用”，并支持点击小时槽查看失败原因。
- [x] 完成三态收口后的专项回归和 Browser 复验。
- [x] 健康监控账户在后端分页前按近期请求数、最后使用时间稳定排序。

## 决策记录

采用使用记录中的 `account_health_check` 作为唯一历史事实，小时槽位最后结果覆盖；使用灰色缺测状态区分“没有执行检查”和“检查失败”。不在接口请求时扫描明细，避免一个月窗口乘账户数造成 shard fan-out。

2026-07-26 收口决策：本页面只回答账户当时能否完成健康检查。成功为绿色“可用”，所有失败统一为红色“不可用”，缺测为灰色“无记录”。错误码和错误消息只用于详情展示，不识别失败来源、不维护供应商规则、不增加第四种状态。

2026-07-26 调度决策：正常账户默认健康检查周期从 12 小时调整为 1 小时，按账户 ID 在 0 到 10 分钟内稳定错峰；真实请求成功继续复用同一计划窗口，后台按到期窗口、固定批次和受控并发执行，不在整点全量探测。

## 验收标准

1. 菜单可以进入 AI 健康监控，管理/用户作用域符合现有权限。
2. 默认最多展示 31 个统计日、每小时 24 个状态槽位，绿/红/灰含义清晰，悬停可看摘要、点击可看详情。
3. 账户名搜索和分页触发后端查询，前端不二次聚合明细。
4. stats worker 增量消费健康检查记录后，SQLite/PostgreSQL 结果一致且重放不重复计数。
5. 后端类型检查、前端构建、专项回归和 Browser 页面检查通过。
