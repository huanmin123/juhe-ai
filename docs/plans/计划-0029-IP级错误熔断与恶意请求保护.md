## 需求目标

- 背景：PLAN-0028 已完成 IP 级账号回避与自动切号，但该能力只调整候选账号排序，不会因为某个客户端 IP 持续制造错误请求而主动拦截。如果某个来源使用有效 API Key 高频构造错误请求，或在认证前反复缺少 Bearer / 使用无效 API Key 探测，仍可能反复消耗网关认证、调度、上游请求、重试、审计和日志资源。
- 目标：新增认证前入口保护和认证后 IP 级错误熔断能力。当同一认证前窄作用域反复失败，或同一 `systemAccountId + apiKeyId + clientIp` 短窗口内重复产生高置信本地请求错误时，短 TTL 返回本地 OpenAI-compatible `429`，保护认证校验路径、账号池和网关热路径，同时不影响正常用户体验。
- 交付物：长期设计文档、计划文档、网关运行态实现、回归脚本、验证记录和相关索引同步。

## 方案概述

### 方案原则

- 熔断和回避分层：IP 级账号回避负责切号救请求；IP 级错误熔断负责错误风暴止损。
- 不解释状态码：默认逻辑只消费本地校验失败等高置信事实；上游非 2xx 错误不再因代码内置特征进入来源熔断，同签名确认的请求级失败也只用于请求收口，不作为恶意来源证据。
- 不写死区域和错误码：不按地区、国家、ASN、运营商、IP 段或固定错误码名单拦截。
- 客户体验优先：重复同一无效 token 只影响该 token 指纹；随机无效 token 只在确认无效后软拦，不能挡同出口有效 Bearer。
- 不扩大账号惩罚：来源错误熔断不写账号冷却、异常、限流或不可调度状态。
- 不惩罚公共故障：账号池整体未知失败、代理失败、容量失败和客户端取消不计入来源错误熔断。
- 短 TTL 可恢复：熔断短期有效，成功请求可以衰减或清理当前来源错误态。
- 热路径轻量：使用进程内有界窗口，不新增数据库查询，不扫描历史明细。

### 后端变化

- 新增 `runtime/client-ip-error-circuit.service.ts`，维护认证前窄作用域、认证后 scope 级和错误签名级短窗口、熔断状态和测试辅助清理。
- 在 `request/pre-auth.ts` 的认证前链路接入缺失 Bearer、重复无效 token 和随机无效 token 探测保护。
- 在 `request/preflight.ts` 的认证后、账号调度前检查熔断态；命中后返回本地 `429`。
- 在失败收口中只把高置信本地请求错误记录为来源错误样本。
- 在成功响应最终化中衰减或清理当前来源错误态。
- 新增日志和审计 metadata，避免安全事件 metadata 保存完整请求体、完整响应体或敏感凭据；审计 payload、审计 queryString 和使用记录 snapshot 中的凭据类信息统一脱敏。

### 数据变化

- 不新增数据库字段和表。
- 新增进程内短 TTL 状态，属于易失运行态。

### 响应变化

- 命中来源错误熔断时返回本地 OpenAI-compatible `429`。
- 认证前错误码为 `client_ip_pre_auth_circuit_open`，认证后错误码为 `client_ip_error_circuit_open`，错误类型均为 `rate_limit_exceeded`。
- 响应头携带 `Retry-After`，并保持现有 `x-trace-id` 链路追踪语义。

## 验收标准

- [x] 同一认证后来源短窗口重复高置信本地请求错误后，本地短 TTL 返回 `429`。
- [x] 缺失 Bearer、重复同一无效 token 高频失败后，本地短 TTL 返回 `429`。
- [x] 高频随机无效 token 探测不会在认证前挡住同 IP 的有效 Bearer 请求。
- [x] 熔断只影响当前 `systemAccountId + apiKeyId + clientIp`，同一 API Key 下不同分组共享，不同来源互不影响。
- [x] 熔断不写账号状态、不触发账号复测、不影响其他 IP 的账号调度。
- [x] 账号级失败、容量失败、客户端取消和未知账号池失败不触发来源错误熔断。
- [x] 成功请求或 TTL 到期后来源可恢复正常调度。
- [x] 不存在地区、国家、ASN、运营商、IP 段或固定状态码 / 错误码黑名单。
- [x] 文档、回归脚本、类型检查、构建和相邻回归完成，验证边界已记录。

## 风险与注意事项

- NAT 或代理出口会让多个真实用户共享同一客户端 IP；阈值必须保守，熔断 TTL 必须短，日志和前端文案不能把 IP 描述成真实用户身份。
- 恶意请求可以随机化错误签名规避同签名窗口；总高置信错误窗口需要兜底，但阈值应更高，避免误伤真实调试流量。
- 上游公共故障时不能把未知失败算到来源头上，否则会在故障期间扩大影响。
- 认证前攻击已纳入应用内保护；公网连接洪泛、TLS 握手耗尽和网络层 DDoS 属于应用进程外层能力，应由反向代理、WAF 或基础设施承接。
- 多实例部署下进程内熔断状态不共享，符合当前轻量部署边界；横向扩容形态下每个实例只保护本实例收到的请求，不承诺跨实例一致熔断。
