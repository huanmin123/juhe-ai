## 需求目标

- 背景：普通路由当前更偏向成本优先，会尽量保持会话亲和和账号缓存命中；当上游账号时快时慢时，用户会被慢账号长期拖住。
- 目标：在普通路由内新增成本优先和速度优先调度偏好。速度优先通过首字等待阈值、慢样本窗口、连续触发次数和后台探针恢复，把近期首字慢的账号临时后置，并在安全窗口内切换同分组其他账号。
- 交付物：策略路由配置字段、后端校验和运行态、网关调度与首字慢切号、后台探针恢复、前端配置入口、Mock / 回归测试、文档和验证记录。

### 本次不包含

- 并发抢跑 / hedging：不同时向多个上游发同一请求，避免双倍计费和并发压力。
- 跨分组借号：普通路由仍然只能绑定一个分组；跨分组能力继续由故障回退、轮询和权重路由表达。
- 持久账号惩罚：首字慢不写 `temporary_unavailable`、`rate_limited`、`error`、`cooldown_until` 或账号健康检测失败次数。
- 旧数据兼容迁移：当前项目不做运行时向下兼容；缺省配置按成本优先解释。

## 方案概述

- 方案原则：速度优先是 `normal` 路由内部调度偏好，不新增路由模式；慢账号只临时后置，不持久处罚。
- 数据变化：`route_strategies.config_json.normalRoutingConfig.schedulingPreference` 支持 `cost_first / speed_first`；速度优先参数使用当前文档默认值和范围。
- 接口变化：策略路由管理 API 接收并返回普通路由配置；普通路由继续只允许一个启用分组。
- 前端变化：策略路由编辑页在普通路由下展示调度偏好；成本优先隐藏额外参数，速度优先显示首字阈值、触发次数、窗口期、恢复次数、探针间隔、降级 TTL、当前请求重试开关和重试次数。
- 后端变化：网关根据调度偏好调整候选排序和首字慢切号；短 TTL 运行态支持 `latency_degraded`；真实达标请求和 ops-worker 后台主动探针都可累计恢复；审计和使用记录记录相关摘要。
- 数据处理策略：缺省或缺失 `normalRoutingConfig` 按成本优先处理；不写运行时迁移或旧结构兼容分支。

## 参数基线

| 字段 | 默认值 | 范围 | 说明 |
| --- | --- | --- | --- |
| `firstByteThresholdMs` | `30000` | `10000..60000` | 首字等待阈值，最低 10 秒，避免误判正常波动。 |
| `slowTriggerCount` | `3` | `2..10` | 窗口内连续慢样本触发速度降级。 |
| `slowWindowSeconds` | `120` | `60..600` | 慢样本观察窗口。 |
| `recoverySuccessCount` | `3` | `3..10` | 连续达标后恢复正常排序。 |
| `probeIntervalSeconds` | `30` | `10..300` | 速度降级恢复探针基础间隔，执行时带 jitter。 |
| `degradedTtlSeconds` | `300` | `60..3600` | 速度降级最大保留时长。 |
| `retryOnFirstByteTimeout` | `true` | `true / false` | 是否在安全窗口内中止慢上游并切号。 |
| `maxFirstByteRetriesPerRequest` | `1` | `1..3` | 单请求首字慢额外换号次数。 |

## 风险与注意事项

- 误判风险：阈值过低会导致正常上游波动被后置，当前设计通过 30 秒默认、10 秒下限、3 次默认触发和 120 秒窗口降低误判。
- 成本风险：当前请求首字慢切号会消耗额外上游请求，默认单请求只允许 1 次额外换号，且不做并发抢跑。
- 流式边界风险：下游一旦写出可见内容，不允许透明切号，否则会破坏协议语义。
- 多实例风险：performance 模式下 `latency_degraded` 必须进入 Redis runtime state，不能退回本地内存后仍声明跨进程一致。
- 发布异常处理：可把普通路由调度偏好切回成本优先并清理速度降级运行态；不需要回滚数据库结构或账号状态。
