## 目标

只基于模型厂商官方客户端的稳定会话请求头建立客户端专属 resolver，把厂商 Header 投影为内部 `sessionId`，按客户端隔离普通/混合路由亲和，并用审计 `session_id` 串联一个会话的全部请求。

## 验收边界

- 已确认客户端有合法 Header：记录 `session_id`，生成客户端隔离的亲和键并参与审计聚合。
- 无 Header：`missing`，正常调度，不承诺粘黏。
- Header 冲突或非法：不生成 key、不记录 `session_id`、不污染亲和；请求仍按普通调度执行。
- Gemini CLI 等没有官方会话 Header 的客户端：当前范围明确不支持会话串联。
