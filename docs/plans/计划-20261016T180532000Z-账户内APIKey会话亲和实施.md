## 执行拆解

1. gatewaysession：`SessionBinding.UpstreamApiKeyFingerprint` + JSON 编解码（64 位小写 hex 校验、逐字段容错）+ 服务 sticky 读 / Key 指纹 CAS 写回（Redis 2 轮上限、进程内 TTLCache 双路径）。
2. gatewaydispatch：`SessionAffinityPort` 增 `StickyApiKeyFingerprintAsync` / `RememberApiKeyFingerprintAsync`；`SelectApiKeyOptions.PreferredApiKeyFingerprint`；`selectAccountRuntimeApiKeyEntry` 健康候选黏性分支（不消费计数器）；`UpstreamDispatchResult` 增延迟写回回调；`dispatchSingleAccount` 每调用至多读一次黏性、仅首轮传递。
3. cmd：`chainSessionAffinityDispatchPort` 适配两方法；`localSessionAffinity` 条目扩展指纹（claim 同 owner 保留、账户 remember 同 owner 保留/换 owner 清除、Key 写回仅更新现存同 owner 记录并刷 TTL）；v1_loop post-verdict `protocolValidatedSuccess` 分支调用写回回调。
4. 测试：设计 §9 矩阵（rotation 黏性分支 / gatewaysession 编解码与 CAS / localSessionAffinity 语义 / chain 适配与调用时点）。
5. 文档同步：设计 §10 清单 + 部署文档补 JUHE_AI_SECRET 实例间一致性要求。

## 验收标准

设计 §8 验收标准 1-11：验收 1/2/3（401 与冷却两变体，冷却变体兼作验收 6 冷却边界）与验收 5 已按 §9「集成」要求以隔离后端 + mock 多 Key 上游执行通过（`TestFullchainApiKeySessionAffinity`）。两点执行口径：验收 4（全部 Key 冷却按 recovery 池序首项兜底）在黑盒流量下不可达——Key 失败走「确认失败」冲刷语义（全失败请求不写抑制，最后救回成功的 Key 必然健康），该断言由单测 `TestSelectAccountAPIKeyStickyIgnoredWhenOnlyRecovery` 覆盖；验收 5 在集成层按真实行为包络断言——非流式协议校验失败触发既有 `ForgetSessionAffinity` 整删绑定（指纹未被替换而是随绑定同删），符合 §8.5「不得新增或替换」+「既有 forget 整删」边界。验收 6 其余边界（disabled、单 Key、OAuth、fixed 优先）与验收 7-10 语义由 §9 单测矩阵覆盖；验收 11 按设计裁决属部署检查（见 §8.11）。§9 声明的完整 1-11 mock 上游集成矩阵未全部在集成层重做，语义覆盖以单测证据为准。

## 风险与注意事项

- Redis Lua 三脚本以整 rawValue 做 CAS，对新增字段透明（已核验）；指纹更新走 set 脚本，refresh 脚本不可用于改值。
- 账户级 `RememberAsync`（2xx 头时点）与 Key 写回（最终协议成功）解耦，二者不得互相改写对方语义。
- 测试内 fake `SessionAffinityPort` 实现须同步补两方法，否则编译失败。

## 完成总结

已按设计契约交付账户内 API Key 会话亲和：

- **gatewaysession**：`SessionBinding.UpstreamApiKeyFingerprint` 可选字段 + 64 位小写 hex 编解码校验（存量记录兼容）；`StickyOpenAIApiKeyFingerprintAsync`（读不刷 TTL、owner 校验、失败降级）与 `RememberOpenAIApiKeyFingerprintAsync`（只更新现存同 owner 绑定、Redis ≤2 轮 GET+CAS、不创建不改 owner）双路径实现。
- **gatewaydispatch**：`SessionAffinityPort` 增两方法；`SelectApiKeyOptions.PreferredApiKeyFingerprint`；选择管线在健康候选集内黏性直选（优先于单候选/continuation/策略，不消费轮转计数器，recovery 次序不变）；`UpstreamDispatchResult.ConfirmSessionApiKeyFingerprint` 延迟写回闭包（捕获 WithoutCancel，2xx 头只构造不执行）；`dispatchSingleAccount` 每调用至多读一次黏性且只传首轮。
- **cmd**：`chainSessionAffinityDispatchPort` 委托 AffinityService；`localSessionAffinity` 条目扩展指纹（同 owner claim/remember 保留、换 owner 清除、写回不创建）；`confirmProtocolSuccessSideEffects`（唯一调用点在 `!RetryUpstream` 最终成功分支）消费写回句柄一次。
- **文档同步**：设计 §10 清单全部落实（故障隔离 / OpenAI 账号接入 / 会话身份 / functions README / 前端帮助文案 / 测试与验证说明），另按 §8.11 解释性裁决在部署文档补 JUHE_AI_SECRET 实例一致性要求。
- **验证**：三个包全量测试通过（gatewaysession 10.8s / gatewaydispatch 52.8s / cmd 1005.7s），新增 12 个测试函数覆盖设计 §9 矩阵；独立只读复审通过（无 blocker）；集成验收 `TestFullchainApiKeySessionAffinity` 覆盖设计 §8 验收 1/2/3（双变体）/5 并 PASS（连跑 3 次稳定），验收 4 黑盒不可达保持单测覆盖（理由见进度记录）。
