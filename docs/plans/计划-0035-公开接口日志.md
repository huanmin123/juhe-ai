## 需求目标

- 背景：当前 `/__aipublic__` 公开接口已经支持来源系统鉴权、聚合读取和资源写入，但日志管理中缺少专门的公开接口调用日志，难以排查外部来源系统调用时间、速度、状态、请求数据和响应数据。
- 目标：新增公开接口日志能力，在日志管理菜单中可查询公开接口调用记录和详情，并保证公开接口日志最多保留 7 天。
- 交付物：功能设计文档、计划文档、数据表、记录中间件、管理接口、前端页面、保留清理接入和验证记录。

- 不做超过 7 天的可配置保留：用户明确要求最大保留 7 天。

## 方案概述

- 方案原则：公开接口日志是轻量调用排障日志，和原始审计日志分开；请求 / 响应快照必须限制捕获范围和容量、保留捕获值原文，并在超限时截断和标记状态。
- 数据变化：新增 `public_api_logs` 表，保存来源系统、token 摘要、接口、状态码、耗时、客户端 IP、请求和响应快照。
- 接口变化：新增管理员列表和详情接口，按 traceId、来源、接口、状态码、成功 / 失败、客户端 IP 和时间范围筛选。
- 前端变化：日志管理中新增 `公开接口日志` 页面，提供列表筛选和详情抽屉。
- 后端变化：在 DB service 的公开接口 Express app 上挂载记录中间件，响应结束后写入数据集目录库；后台保留清理删除 7 天前记录。
- 数据处理策略：当前 schema 直接新增表；历史没有公开接口日志，不做运行时迁移兼容。

## 风险与注意事项

- 公开接口日志会保存捕获预算内的请求 / 响应原值摘要；对外分享截图或数据库前必须检查并人工移除业务敏感内容。
- 当前写入采用请求结束后同步写数据集目录库；公开接口流量如果显著升高，可后续按记录类写入队列化方案改成后台批量落库。
- JSON body 解析失败发生在业务路由前，需要记录中间件挂在 public body parser 之前或错误处理路径能补记。
