## 目标、边界与授权

目标是在 API Key → 路由策略 → 分组 → 账户链路内，引入组模型目录及多 connector 账户，统一管理模型规格、报价和账户能力。同组可容纳采用不同 connector 的账户。

账户唯一归组，官方组允许用户自己的 AI 账户；组不声明 connector 清单。一个账户保有一套上游连接与身份，可支持多个 connector；创建默认填写组、名称、连接认证及支持模型，不强制预选 connector。按模型、操作及账户真实声明的支持范围唯一解析 connector，只有歧义时提出最小选择；高级设置可收窄模型默认 connector 范围。模型目录声明不等于账户实际上游支持。相同入口存在多个视频 adapter 时不得取首个、轮询或通过生产试错猜测。

账户模型映射可配置 connector 专用上游 ID，优先级为 connector 专用 → 账户级 → 模型默认；同一实际目标 group_model 使用其稳定身份计价。现行映射也允许 A→B 的真实模型替换，见[自定义模型与模型映射设计](../functions/自定义模型与模型映射设计.md) §2/3；建议按实际目标 group_model 价格计费，此项仍需确认，不能写成已批准。授权仍使用来源模型和账户的实际支持范围，本地组不新增 connector 门槛。

模板是先定义模型规格和计价结构的父级，如 DS、GLM、GPT；每个模型必须选一个模板。选模板后可从其他有读取权限的组中选择同模板模型复制填值。结构模板与现有模型行复制不是同一对象。组克隆复制模型实例、其 connector 绑定及报价、模板引用，不复制账户、凭据、授权、路由或任务。

直接账户授权保留原 grant 范围：来源组、模型、模板、价格和额度走授权人体系，使用方本地组只负责放置与调度，不能修改来源价格；调用方统计归属维持既有语义，不把账户 grant 升为组 grant。

旧分组限制和超级分组拟随实施退役，旧设置不迁移；API Key 直接新配账户软阈值和单 IP 限制，默认未设置，不放共享调度偏好。本轮仅文档和静态核对，不执行代码、数据库、真实上游或生产写入，不删除数据、不提交、不推送。实际迁移、生产及共享环境写入另按项目授权和备份门执行。

## 简化核对

1. **用户明确决定**：删除组 connector 清单这一重复能力；账户可支持多个 connector，模型显式多 connector 绑定；按模型、操作与真实声明支持共同解析，授权使用来源模型集合。
2. **本稿建议**：模板 revision、`billing_rule_id` 如实现需要仅作内部细节，用户只选结构模板；复用固定字段和计价规则，不构建 JSON Schema、公式或多版本转换平台。
3. **本稿建议**：同模板填值使用普通表单复制；有覆盖时必要确认，复制后独立不自动更新。不要求逐字段 diff、独立重新套用工具、来源版本或逐字段选择。
4. **本稿建议**：硬限沿用现有账户及 grant 来源身份，不新增相同凭据全局去重或新资源实体；Q11 不再作为本轮阻塞。
5. **本稿建议**：统一视频 API 与上游原生协议双向适配是 connector 核心，禁止任意用户脚本 bridge 不应禁止此适配。
6. **r4 方向**：一套上游连接与身份可关联多个 connector，地址和认证可填写、固定或派生；不强迫托管 OAuth 用户手填 BaseURL，认证流程端点不算额外连接。多个 connector 不等于必须新增多个 `account_connections` 行，保留逻辑单 endpoint 身份，具体存储待实施设计。

这些建议控制计划范围，不表示用户逐项批准；此前复审未证实已有完整版本链或任意 ID 改写引擎，也未认定迁移前禁止讨论。
