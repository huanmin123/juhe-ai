> 已完成：R1/R2 的 Explore 取证（七类 helper 逐处替换清单、缓存扇入消费方分析：扇入主体为类型词汇而非方法调用，cache 包外方法调用点仅 39 处；preauth 窄接口收益接近零，列入后续波次）；R1 基础设施已落 `shared/platform` 六个新包（timeclock 100% / timefmt 98.1% / sqldialect 100% / rediscfg 100% / jsonenc 100% / idgen 100% 覆盖率，全绿）。
> 待做：逐包迁移（11 处 Clock、8 处 newID、6 处 sanitize、3 处 jitter、3 处 bind、4 份 RFC3339 → 引用 shared 包）；M1 覆盖率收尾 6 包。

## 1. 背景与当前事实

Node 后端已完成全量清零迁移并归档，Go 后端进入持续维护期。当前工作区实测（评估文档 2026-09-18）：

- 后端五模块生产代码 466,565 行 / 测试 614,567 行 / 2,837 文件，gateway 独占 33.6 万行。
- 7 类基础设施 helper 跨包重复且行为漂移：`newID`×8 包、`Clock`/`FixedClock`×11 包、`sanitizeRedisName`×4、`passiveJitterWindowMS`×3、RFC3339 毫秒×10+ 包、`?`→`$n` 占位符改写×3 处实现、`encodeJSON`/`writeError`/`normalizeRange`×2。
- 缓存架构成为耦合中心：`gatewayruntimecache` 扇入 231、`gatewaypreauth` 198。
- god 包：`accounts` 29,841 行、`cmd/juhe-ai-gateway` 26,884 行、`chat` 16,085 行等 11 个逻辑包超 8k 行。
- 2 个 DDL 数据文件超 3000 行硬上限（pg_schema.go 7,954 / sqlite_schema.go 4,410）；4 个逻辑文件超 2000 行预警线（bridge_request.go 2,850 / chain_v1.go 2,693 / policyreads/external.go 2,662 / policyreads/inspection.go 2,259）。
- 时钟注入不统一：dispatch 退避用真实时钟（`gatewaycircuit/lua.go` 的 `retryAtMs = now_ms + 3000`、`wait.go` 的 `time.AfterFunc`），无注入点，gateway cmd 包链路测试 559s（默认 10m 超时仅 40s 余量）。
- 前置条件：覆盖率攻坚剩余 6 个 <95% 包（auditlog / gateway cmd / chat / jobs cmd / modelcheckapp / accounthealth）沿既有缺口清单收口，与本项目波次共享执行配额。

## 2. 目标

1. **复用性**：基础设施 helper 收敛到 `shared/platform`（时钟、ID、jitter、时间格式化、方言占位符、Redis 命名清洗、JSON 编码），同名同义同签名，消除行为漂移。
2. **扩展性**：治理 `gatewayruntimecache`/`gatewaypreauth` 扇入——按读/写/失效/并发语义拆分对外接口面，使缓存模型演进不再波及全部 gateway 包。
3. **可维护性**：god 包按子域评估包级拆分（优先 accounts）；4 个预警线超标逻辑文件与 2 个超硬上限 DDL 数据文件按大文件重构指南拆分。
4. **可测性与性能**：时钟注入统一后，dispatch 退避与链路测试获得注入点，gateway cmd 包测试时长目标 <300s；对 `/v1` 网关链与 chat 建立 pprof 基准，量化后再决定优化项。

## 3. 非目标与保护边界

- **行为基线不变**：对外 API、路由、字段、页面流程、SQLite/PG 双模式语义、owner lease 边界一律不变；重构只动结构不动行为。
- **不引入新框架/新依赖**：收敛用标准库与既有 platform 设施，不引入 DI 容器、不引入通用 Queue adapter、不做"过度抽象"。
- **三项目边界不破**：gateway/jobs/maintenance 互相禁止 import 依然成立；收敛目标只到 `shared/platform`（无业务编排）。
- **覆盖率不降**：每波交付后受影响包 `go test -cover` 仍 ≥95%（未达标包沿缺口清单收口，不因重构回退）。
- **Store Port / Adapter 与供应商五层模型不动**：拆分不得破坏既有端口收口与白名单桥接边界。
- 热路径优化（R5）在 pprof 基准出来之前**不做任何"凭感觉"的优化**。

## 4. 波次与验收

执行按波次推进，每波独立验收后才进入下一波；波内并行时按最小非重叠写入范围分工（orchestrate-model-workflow），写入统一 `glm_5.3_flash_max`、复审 `glm_5.3_high` 起。

### 波次 R1：shared/platform 基础设施收敛（P0，先行）

- 范围：新建 `shared/platform` 下的 `idgen`（crypto/rand ID + fallback）、`timeclock`（Clock/FixedClock 统一签名）、`timefmt`（RFC3339 毫秒解析/格式化）、`sqldialect`（`?`→`$n` bindSQL + instantParam/boolLit）、`rediscfg`（sanitizeRedisName/命名空间 key）、`jsonenc`（encodeJSON）各小包；然后逐包把 11 处 Clock、8 处 newID、4 处 sanitizeRedisName、3 处 jitter、3 处占位符改写改为引用。
- 顺序：先建 shared 设施（新包 + 单测 ≥95%），再按"一个包一个边界"逐包替换，每替换完一个包跑该包全量测试。
- 验收：重复 helper 的 `rg -l "func newID" backend-go --type go` 只命中 shared/platform；五模块 build/vet 干净；受影响包覆盖率不降；R1 完成后全量回归全绿。
- 风险控制：Clock 签名以最大公约数收敛（评估文档已记录签名漂移点），替换时保留各包原语义断言。

### 波次 R2：缓存与 preauth 扇入治理（P0）

- 范围：`gatewayruntimecache`（231 处引用）按读快照/写失效/并发控制/SQL 模型拆分对外接口面（包内文件已分，重点是把"231 处都 import 整个 Service"收窄为按消费方语义的窄接口）；`gatewaypreauth`（198）职责边界复查——可用性/重试预算/预算调度是否需要拆包。
- 方法：先扇入清单分析（每个消费方用了哪些方法），再定窄接口分组；不改缓存语义。
- 验收：消费方 import 面按语义分组；全量回归全绿；覆盖率不降；`gatewayruntimecache` 包内文件不超 3000 行。
- 明确不做：不把缓存迁出 gateway、不改 Redis/内存双模式语义、不合并 store。

### 波次 R3：god 包与超限文件拆分（P1/P2）

- 范围（按收益排序）：
  1. `accounts`（29.8k）按子域评估包级拆分（CRUD / 导入导出 / 批量编辑 / 测试会话 / 余额 / 调度时间计划）——先出拆分设计（子域边界、共享类型归属、循环依赖检查）再动文件；
  2. 4 个预警线超标逻辑文件：`openaicompat/bridge_request.go`（2,850）、`cmd/juhe-ai-gateway/chain_v1.go`（2,693）、`policyreads/external.go`（2,662）、`policyreads/inspection.go`（2,259）——按大文件重构指南"先拆纯函数/类型/常量，再拆副作用"；
  3. 2 个 DDL 数据文件：`pg_schema.go`（7,954）/`sqlite_schema.go`（4,410）按 schema 组拆为多个数据文件（保持 `postgresSchemaStatements` 单一事实聚合不变）。
- 验收：每个拆分对象交付后目标行为与基线一致（既有测试全绿 + 覆盖率不降）；文件不再超限（DDL 聚合入口除外，其行数上限按数据文件豁免并登记）。
- 依赖：R1 完成后拆分文件中的 helper 引用直接指向 shared/platform，避免拆完再改。

### 波次 R4：时钟注入统一与热路径确定性（P1，依赖 R1）

- 范围：`gatewaycircuit`（lua.go `retryAtMs = now_ms + 3000`、wait.go `time.AfterFunc`）与 dispatch recoverable-wait 的退避接入统一 Clock；`waitForDelayMs` 保持 ctx 取消语义；cmd 包链路测试注入短退避。
- 验收：gateway cmd 包测试时长 <300s（默认 10m 超时余量 >50%）；退避节奏在测试中可确定性断言；生产行为不变（退避时长契约不变，只是可注入）。
- 风险控制：退避是生产契约（Node 语义对齐），注入点默认值=生产行为，测试覆写。

### 波次 R5：热路径性能基准先行（P2）

- 范围：对 `/v1` 网关链（dispatch → response → usage → cache）与 chat 建立 `go test -bench` + pprof 基准（CPU/分配），量化 JSON 编解码、SSE 泵、缓存命中的占比；基准产物放仓库 `reports/`（机器产物），结论进 `docs/reports/`。
- 验收：基准可重放（固定输入、确定性断言）；产出量化的热点排序；优化项另行立项，不在本波内"顺手优化"。
- 明确不做：无基准证据不优化；不改缓存命中率语义。

## 5. 执行与验收约定

1. 每波交付物：实际改动清单、验证命令与结果（build/vet/受影响包测试/全量回归）、未解决问题；主代理核验 diff 后才算完成。
2. 全量回归门：每波完成后五模块 `go test ./...` 全绿 + 覆盖率账本复算（gateway ≥95.7%、jobs ≥94.3% 现状不回退）。
3. 独立复审门：每波由未参与写入的只读角色复审 diff 与验证。
4. 文档联动：每波复盘记入 `docs/refactors/`（REFACTOR-000N）；波次状态更新回本文件。
5. 与覆盖率收尾的协调：剩余 6 个 <95% 包的收口 agent 与本项目波次共享执行配额，优先级高于 R3（先清覆盖率债，再拆结构）。
