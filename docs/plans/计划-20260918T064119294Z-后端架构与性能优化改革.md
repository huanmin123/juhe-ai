## 1. 背景与当前事实

Node 后端已完成全量清零迁移并归档，Go 后端进入持续维护期。当前工作区实测（评估文档 2026-09-18）：

- 后端五模块生产代码 466,565 行 / 测试 614,567 行 / 2,837 文件，gateway 独占 33.6 万行。
- 7 类基础设施 helper 跨包重复且行为漂移：`newID`×8 包、`Clock`/`FixedClock`×11 包、`sanitizeRedisName`×4、`passiveJitterWindowMS`×3、RFC3339 毫秒×10+ 包、`?`→`$n` 占位符改写×3 处实现、`encodeJSON`/`writeError`/`normalizeRange`×2。
- 缓存架构成为耦合中心：`gatewayruntimecache` 扇入 231、`gatewaypreauth` 198。
- god 包：`accounts` 29,841 行、`cmd/juhe-ai-gateway` 26,884 行、`chat` 16,085 行等 11 个逻辑包超 8k 行。
- 2 个 DDL 数据文件超 3000 行硬上限（pg_schema.go 7,954 / sqlite_schema.go 4,410）；4 个逻辑文件超 2000 行预警线（bridge_request.go 2,850 / chain_v1.go 2,693 / policyreads/external.go 2,662 / policyreads/inspection.go 2,259）。
- 时钟注入不统一：dispatch 退避用真实时钟（`gatewaycircuit/lua.go` 的 `retryAtMs = now_ms + 3000`、`wait.go` 的 `time.AfterFunc`），无注入点，gateway cmd 包链路测试 559s（默认 10m 超时仅 40s 余量）。
- 前置条件：覆盖率攻坚剩余 6 个 <95% 包（auditlog / gateway cmd / chat / jobs cmd / modelcheckapp / accounthealth；其中 modelcheckapp 已于 2026-09-20 随 jobs 的 J3b 历史材料清理整体删除，不再适用）沿既有缺口清单收口，与本项目波次共享执行配额。

## 2. 目标

1. **复用性**：基础设施 helper 收敛到 `shared/platform`（时钟、ID、jitter、时间格式化、方言占位符、Redis 命名清洗、JSON 编码），同名同义同签名，消除行为漂移。
2. **扩展性**：治理 `gatewayruntimecache`/`gatewaypreauth` 扇入——按读/写/失效/并发语义拆分对外接口面，使缓存模型演进不再波及全部 gateway 包。
3. **可维护性**：god 包按子域评估包级拆分（优先 accounts）；4 个预警线超标逻辑文件与 2 个超硬上限 DDL 数据文件按大文件重构指南拆分。
4. **可测性与性能**：时钟注入统一后，dispatch 退避与链路测试获得注入点，gateway cmd 包测试时长目标 <300s；对 `/v1` 网关链与 chat 建立 pprof 基准，量化后再决定优化项。

## 3. 非目标与保护边界

- **行为基线不变**：对外 API、路由、字段、页面流程、SQLite/PG 双模式语义、owner lease 边界一律不变；重构只动结构不动行为。
- **不引入新框架/新依赖**：收敛用标准库与既有 platform 设施，不引入 DI 容器、不引入通用 Queue adapter、不做"过度抽象"。
- **三项目边界不破**：gateway/jobs/maintenance 互相禁止 import 依然成立；收敛目标只到 `shared/platform`（无业务编排）。
- **覆盖率不降**：每波交付后受影响包 `go test -cover` 仍 ≥95%（未达标包沿缺口清单收口，不因重构回退）。
- **Store Port / Adapter 与供应商五层模型不动**：拆分不得破坏既有端口收口与白名单桥接边界。
- 热路径优化（R5）在 pprof 基准出来之前**不做任何"凭感觉"的优化**。
