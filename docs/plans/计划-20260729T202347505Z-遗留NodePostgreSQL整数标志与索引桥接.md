# 遗留 Node PostgreSQL 整数标志与索引桥接计划

- 目标：修复 Node PostgreSQL 仓储对已证实 `INTEGER(0/1)` 标志的布尔字面量/参数错配，并交付可审计的遗留索引桥接操作。
- 授权：本地源码、测试和文档实施；不连接、不修改任何远程或生产数据库。
- 范围：`accounts.schedulable`、`accounts.balance_query_enabled`、`group_accounts.enabled`、供应商目录相关 `enabled` 字段，以及 87/93 对应的三条索引桥接。
- 非目标：变更 Node legacy schema 类型、运行或基线 Goose、写迁移 ledger、修改业务行/表、请求上下文日志。
- 背景与依据：Node PG schema 从 SQLite 生成时上述字段仍为 `integer`；账户余额、健康检查和供应商目录查询曾使用 PostgreSQL `TRUE/FALSE`，而 pg 参数不会自动转换为整数。
- 硬约束：操作默认只读；`apply`/`cleanup-invalid` 必须显式数据库身份、目录 allowlist、表/列/类型/值/所有权/index validity 检查和 session advisory lock；只使用 `CREATE INDEX CONCURRENTLY`。
- 风险：高。索引 DDL 作用于生产数据库，但实际执行只由部署人员在发布环境触发。
- 回滚：新增有效索引不自动回滚；无效索引只能使用显式 `cleanup-invalid --index <allowlisted-name>` 删除，再重新 `apply`。代码改动按常规发布回滚。
- 验收：整数 SQL 与参数均为 `0/1`；明确的 PG boolean 转换字段保持不变；目录恰有三条批准索引；发布包包含脚本、目录和文档；静态/目标回归通过。
- 验证：`pnpm.cmd --filter juhe-ai-backend test:account-balance-refresh`、`test:account-health-check`、`test:provider-repository-driver`、`pnpm.cmd test:legacy-node-index-bridge`、`test:macos-operations`、`test:release-package`、相关 typecheck。
- 停止条件：缺少数据库身份、目录指纹不符、前置检查不满足或任一索引无效时停止，不用宽松 DDL 绕过。

## 设计结论

1. Node PG 的账户调度、余额和 group binding 标志是整数；供应商、协议档案和端点族的 `enabled` 也保留整数。它们统一使用 `= 1`、`= 0` 和数值参数。
2. `proxy_profiles.enabled`、模型目录可见性、账号测试取消等 fresh Node PG 显式转换为 `boolean` 的字段不在修复范围，继续使用布尔语义。
3. 索引桥接不复用 Goose：87 原迁移含删除步骤，桥接仅保留两条最终创建定义；93 的 boolean predicate 必须改为 Node legacy integer predicate。

## 复审修复

- 索引校验按 `pg_index` 的键数量、键顺序、默认排序选项和 `pg_get_expr(indpred, ...)` 的布尔结构比较，保留字符串与正则字面量大小写；缺失、额外或重排键/谓词均视为不匹配。
- 旧问题与计划记录明确区分 fresh Goose 管理库和 legacy Node 库：前者遵循独立 Goose 发布流程，后者禁止运行或基线 Goose，只能执行桥接。
- macOS 门禁涵盖桥接脚本、目录及中文操作说明，并校验 README 链接与关键安全边界。
