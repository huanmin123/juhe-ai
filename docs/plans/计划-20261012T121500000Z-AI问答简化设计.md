## 需求目标

### 背景

AI 问答自 2026-07 MVP 起逐步叠加了站内模型工具体系（`web_search` 联网搜索、`generate_image` 生图、`generate_video` 视频、`generate_audio` 语音合成的子代理绑定与编排）、用户图片输入链（上传/压缩/资产/语义观察）和"主对话恒 Chat Completions"的协议裁决。功能面与维护面持续膨胀，而产品的真实定位始终是：**登录用户测试账户/模型、以及日常简单询问的内置客户端，不是复杂 Agent 平台**。

用户于 2026-10-12 做出方向裁决：

1. 去掉视频、音频、生图（未来迁移到独立"媒体工作室"菜单，见 PLAN-20261012T123000000Z 媒体工作室规划建议（已退场归档，2026-10-14 用户裁决媒体工作室整体移除））。
2. 去掉站内联网搜索工具，改用模型内置搜索能力；内置不支持的就搜不了。
3. 协议按供应商主推：用 GPT 就走 GPT 主推的 Responses 协议，用 DeepSeek 就走 Chat Completions——支持全部供应商各自的协议。
4. 会话一旦绑定了账户 + 模型，当前会话不允许再切换模型，只能开新会话，避免协议串扰。
5. AI 问答不再做复杂功能，定位收缩为测试 + 日常简单询问。
6. 用户补充明确保留图片识别：用户上传图片给模型理解的能力继续保留；删除的是调用图像生成模型的工具（包括图标生成），不删除 `/v1` 图像生成公开能力或未来工作室图像菜单。

本次交付范围为设计审核与决策收口。下文代码、存储和权威功能文档更新是后续实施范围，不代表已经执行；Sora 退役见媒体工作室计划。

## 设计

### D1 功能定位与产品边界（已裁决）

AI 问答 = 登录用户使用自己 API Key 的平台内置**文本与图片识别客户端**，用于账户/模型测试与日常简单询问。用户图片识别属于主对话输入；媒体内容生产迁媒体工作室，复杂 Agent 编排与站内工具执行退场。聊天继续作为普通网关客户端走 `API Key -> 路由策略 -> 分组 -> AI 账户 -> 供应商/协议`，鉴权、计费、审计边界不变。

删除"模型工具 = 会话级绑定「账户+模型」子代理"的整个体系：

- 后端删除：`generation_tools.go`（注册表与编排器；注册表实为五工具——四模型工具 + development/test `diagnostic_echo`，随编排器一并退场，`resolveTools` 五工具断言同步删除）、`generation_websearch.go`、`generation_images.go`、`generation_media.go`、`media_task_routes.go`、`tool_bindings.go`、`tool_preferences.go`；`stream_execute.go` 四个工具闭包与 `MediaArtifactSink`、编排器启动点；`stream_route.go` 生图观察调度与 `scopeHasImageGenerationRoute`；`routes.go` 的 PATCH 工具绑定键、`toolCapabilities`、tool-preferences 与 media-tasks 路由；`conversations.go` 的 `SupportedChatImageModels` 等生成模型枚举及 `ClearConversation` 中仅 `chat_image_generations` 专属删除语句。共享 `chat_asset_references` 与释放结算保留。

### D3 搜索 = 上游内置工具透传（审核定案）

站内 `web_search` 子代理（绑定候选、流式过程可视化、结果回喂）删除后，联网能力回归上游协议原生形态：

本次仅允许注入已验证的 hosted `web_search`；不注入 `image_generation`、音视频生成或站内 function tools，避免删除生成工具后又从 Responses hosted 工具重新引入图片/图标生成。

- 仅 Responses 协议且模型目录声明内置搜索能力（`supportedToolsByProtocol["responses"]` 含 `web_search`）的模型可用：请求直接携带 `tools: [{"type":"web_search"}]` 透传，上游自行执行，站内只展示真实事件投影（Responses hosted 工具事件经既有内容块通道下发，不伪造、不重复执行——沿用《AI问答设计》§8.6 既有口径）。
- Chat Completions 协议供应商（DeepSeek、GLM、xAI、MiniMax 等）目录未声明内置搜索的，前端不显示联网控件，请求不携带工具——即"内置不支持就搜索不了"。
- **请求选项**：输入框提供“联网”勾选项，默认不勾选；本轮勾选时携带 `enableWebSearch: true`。能力接口 `builtinWebSearch` 决定是否提供该选项；不新增会话列、部署配置或 feature flag，搜索能力交付后始终可用，用户选择的是本轮是否调用上游工具。能力不支持却提交 `true` 时明确拒绝，不静默忽略；上游搜索失败保留原始错误，不自动转为离线回答。
- **桥接账户口径**：联网开关仅对原生 Responses 直连账户可见。anthropic（responses 请求形态经桥接）与 gemini（chat 形态桥接）账户不提供联网控件——桥接层对 hosted 工具按 guidance 降级、不真实执行搜索（`bridge_request_openai_responses_to_anthropic.go:309-324`），若提供控件会造成"开关可见但静默不生效"。目录能力查询按上游原生协议键执行，不按请求形态键。
- 现成资产：Codex 链 `web_search_preview -> web_search` 归一（《核心功能设计》"中转协议与流程"）已有，透传路径无需新增归一逻辑。

### D4 协议按供应商主推直连（已裁决）

废除 `stream_route.go:472` 的 `protocol := ProtocolChatCompletions` 硬编码，主对话协议改为按绑定账户解析：

| 供应商 | 主推协议 | 承载方式 |
| --- | --- | --- |
| openai（API Key）/ gpt / codex（OAuth） | `responses` | 原生直连（`/v1/responses`） |
| deepseek / glm / xai / minimax / volcengine / qwen 等 OpenAI 兼容 | `chat_completions` | 原生直连（`/v1/chat/completions`） |
| anthropic | `responses`（请求形态） | 网关桥接 `responses -> messages`（`openaicompatbridge/bridge_request_openai_responses_to_anthropic.go`，已落地） |
| gemini | `chat_completions`（请求形态） | 网关桥接 `chat -> generate_content`（`bridge_request_openai_chat_to_gemini.go`，已落地） |

- **主推协议解析**：上表是各供应商默认原生档案的方向。解析必须同时读取绑定账户真实 protocol profile、模型映射与 `SupportedEndpointModes`；`accountscore/endpointmodes.go:42-54` 还存在 DeepSeek/GLM 的 anthropic 档案及 Gemini 的 OpenAI 档案，不能只按 provider code 覆盖账户真实协议。`ChatTransportAccount` 当前未投影 profile（`transport.go:46-53`、`chain_chat.go:226-233`），实施时补最小必要投影，与目录派生同源选择请求形态及既有桥接；不匹配或档案未知时明确失败，不猜测 fallback。`builtinWebSearch` 也按最终上游原生协议判断，不仅按供应商名字。
- **解析结果与优先级**：resolver 输出 `{requestProtocol, upstreamProtocol, upstreamModel}`；先以账户实际 profile 和模型映射确定原生上游，再选择合法的主推请求形态。Anthropic profile（包括 DeepSeek/GLM 的该档案）为 `responses -> messages`，Gemini native 为 `chat_completions -> generate_content`，Gemini OpenAI profile 为 `chat_completions -> chat_completions`；其他 OpenAI profile 按上表供应商方向及已有映射校验。合法既有桥接保留，未知/歧义显式失败；主轮、压缩、观察共用这份解析结果。
- **请求构造**：`transport.go` 按解析协议构造 Responses（顶层 `instructions` + `input`，沿用 chat-system 提示注入既有契约）或 Chat（首条 `system` message）请求体；`/v1` 入口相应为 `/v1/responses` 或 `/v1/chat/completions`。
- **响应消费**：复用 Responses SSE 消费经验并补齐主对话 collector，与 `CollectOpenAIChatSse` 并列按协议选用；验证增量文本、工具事件、来源引用、usage、错误与终态。两者投影到既有内部 `content_block.*` 事件族，不另造前端协议。
- **Responses 完成判据**：当前 `consumeWebSearchStream` 对失败/EOF 的处理不能直接沿用为主对话成功依据；仅合法 `response.completed` 算成功，`response.failed` / `response.incomplete` / error / 缺终态 EOF 明确失败并保留已收到正文及原始错误。停止走已有取消语义，消费有界且 usage 不重复记账。
- **上下文组装**：checkpoint 保持中性结构，补齐真实 Responses `input` 与 Chat `messages` 转换；当前输入、历史图片和观察说明保序保义；system 提示分别进入 `instructions` 与 `system` message。删除仅生图索引 `ListRecentImageGenerations`，不能删用户图片记忆。
- **辅助请求统一**：自动/手动压缩及用户图片观察也按同一绑定账户主推协议构造，**响应形态按账户真实 profile 决定，不假设 JSON**：Codex OAuth 归一化强制 `stream=true`（`gatewayoauthcodex/oauthnormalizer.go:169` `cloned["stream"] = true`），对这类账户辅助请求返回的是 SSE 流——辅助链必须具备有界 SSE 聚合消费能力（复用主对话 Responses SSE collector 的解析与预算边界，聚合出完整 JSON 语义后再走既有解析），原生非 OAuth 账户仍走普通 JSON。主轮 SSE 与辅助消费共用协议解析及上下文转换。不得主轮改成 Responses 后仍向 Responses-only 账户发 Chat 压缩请求，或向 Chat-only 账户发 Responses 图片观察请求。**既有缺陷一并根治**：当前图片观察固定按 JSON 消费（`chain_chat_observation.go:306-321` `io.ReadAll` + `json.Unmarshal`），对 Codex OAuth 账户本就会解析失败；本次实施以"OAuth 账户压缩与图片观察经真实网关路径的 Mock 回放"作为验收门（见测试项）。
- **模型能力接口**：`getConversationModel` 不再按双协议过滤取交集，按主推协议定点返回；前端思考级别/服务等级/生成参数载荷逻辑不变（其来源是能力载荷而非协议字段）。
- **模型列表口径**：在绑定账户范围解析模型映射，以 `upstreamModel + upstreamProtocol` 核验原生目录能力，再向 `requestProtocol` 投影可保真参数与图片输入能力。直连时请求/上游协议相同；Claude 原生目录声明 `messages` 即可，不要求它声明 Responses；Gemini 同理按实际 profile 处理。OpenAI 原生 Responses 账户仅 Chat 模型不出现在列表。目录与实际上游不符时明确失败；候选重试只在绑定账户允许的既有路径内，不能隐式切其他账户或模型，绑定账户不可用时提示新建会话。
- **明确非目标**：不恢复"协议偏好由工具能力驱动"的旧路径；不为单一供应商增加第三种请求形态；桥接层（`openaicompatbridge`）属于 `/v1` 公共链，本次只消费不修改。
- **附带收益**：GPT OAuth（Responses-only）账户在问答内首次获得原生直连路径，消除恒 chat × Responses-only 的结构性张力和潜在错误形态。

### D5 会话锁定"账户 + 模型"（审核定案）

- **锁定语义**：`chat_conversations.last_model` 语义从"最近一次使用模型（每轮覆盖）"变更为"会话锁定模型（首轮接受时写入，此后不可变）"。空值 = 未锁定（未产生任何轮次）。
- **锁定时机**：第一轮通过校验、被 `AcceptTurn` 接受并与消息同事务提交时写入模型、锁定账户与模型。未接受的请求不锁定；接受后上游失败或用户停止仍保留锁定，可原模型重试。空会话可以自由更换账户与模型。
- **锁定后行为**：
  - 发送请求 `body.model` ≠ `last_model` → `400 chat_model_locked`（中文提示"当前会话已绑定模型 X，如需更换请新建会话"）。
  - `PATCH /conversations/:id` 实际改变或清空 `accountId` → `409 chat_conversation_locked`；重复提交相同账户不算切换，其他偏好正常修改。
  - 前端：锁定后账户选择器与模型选择器均禁用（tooltip 说明），发送正常。
- **锁定后前端交互状态表**（实施时按此实现，回归脚本按此断言）：

| 会话状态 | 账户选择器 | 模型选择器 | 发送 | 说明 |
| --- | --- | --- | --- | --- |
| 空会话（未绑定账户） | 可用（引导条提示先选账户） | 不可选（候选列表为空，同现状"先选账户再出模型"） | 禁用（400 `chat_account_required`） | 现状行为不变 |
| 已绑账户、未锁定（无轮次） | 可用（切换联动清空不可路由的模型） | 可用（自由换，能力按需加载） | 可用 | 选错即换，不逼弃会话 |
| 已锁定（`last_model` 非空） | 禁用，tooltip「会话已绑定账户与模型，更换请新建会话」 | 禁用，tooltip 同左 | 可用（仅当前锁定模型） | `/clear` 后保持本行 |
| 生成中/待确认 | 禁用 | 禁用 | 禁用（既有单生成门禁） | 现状行为不变 |
| 归档会话（存量只读） | 禁用 | 禁用 | 禁用（403 `chat_conversation_archived`） | 现状行为不变，纳入断言 |

- 锁定相关错误的前端提示与恢复动作：`400 chat_model_locked`（换模型发送）→ 提示「当前会话已绑定模型 X，如需更换请新建会话」，不自动改写请求；`409 chat_conversation_locked`（切账户 PATCH）→ 提示同型文案并保持当前绑定；`409 chat_conversation_binding_changed`（预检与接受间绑定被并发改变）→ 提示「会话绑定已变化，请刷新后重试」，前端刷新会话详情后恢复输入。三码进 `chatErrorMessage.ts` 映射表并配回归断言。
- **重置路径**：变更账户或模型必须新建会话；`/clear` 只清空消息、checkpoint 和用户资产引用，保留账户与模型锁定，前端选择器仍禁用。清空后下一轮不得覆盖 `last_model`。
- **并发边界**：首轮校验与写锁定模型、账户 PATCH、清空均使用同一会话并发裁决；PG 事务行锁 / SQLite 等价串行写入保证双首轮、首轮与切账户不能交错绑定。`AcceptTurn` 持锁时比较预检账户 ID 与实际绑定值，若期间改变则明确拒绝本次接受，不能拿旧账户 executor 写入新绑定会话；PATCH 持同一会话锁检查 `last_model` 后再修改。幂等重放返回原轮次，不重新锁定或覆盖模型。
- 预检与接受之间绑定已改变返回 `409 chat_conversation_binding_changed`，提示刷新会话；不支持图片/联网及协议能力不匹配均在接受轮次前拒绝，不让无效请求占用首轮锁定。
- **存量会话**：上线时已有 `last_model` 的会话视为已锁定（它们已存在多模型上下文，符合锁定本意）；`last_model` 为空按未锁定。不做回填迁移。
- **归档会话**：行为不变（本就只读）。

### D6 保留用户图片输入与识别（用户明确裁决）

- 保留 Tiptap 图片节点、粘贴/选择、压缩与上传队列、预览、`/image` 添加图片命令、图片政策端点和图文混排；“添加图片”与“生成图片”必须区分，工具菜单删减不能误删上传入口。

- 生图谱系表、图像生成模型枚举与生成超时设置删除；图片识别仍走绑定的主对话账户和模型，不新增图像识别子模型或工具绑定。模型无图片输入能力时明确提示并拒绝带图发送，不自动换模型、丢图或降级为纯文字。

### D8 验收标准

1. GPT OAuth 账户会话发送成功且网关上游请求为 `/v1/responses` 原生形态（审计/轨迹可证）；DeepSeek 等兼容供应商会话为 `/v1/chat/completions`；anthropic/gemini 账户经桥接成功且内部 SSE 事件族不变。

3. 工具退场：tool-preferences / tool-bindings / media-tasks 端点移除；生成媒体/站内工具历史块占位，用户图片正常显示；`image-policy` 与用户资产端点正常；造数链路不引用已删工具表。

5. 模型列表和视觉能力按解析后的原生上游模型/协议过滤并投影：OpenAI 原生 Responses 账户仅 Chat 模型不可见，Claude messages-only 模型经 Responses 桥接仍可见；Gemini native/兼容档案、DeepSeek/GLM Anthropic 档案分别验证；绑定账户不可用不切其他账户。
6. 回归：上下文压缩（软/硬水位、手动 `/compact`）、SSE 重附、幂等、停止、容量门禁、`purpose=chat` Key、Prompt Cache 稳定前缀全部保持既有契约。
7. 图片识别：粘贴/选择上传、多图顺序、取消/失败重试、超限、所有权、预览与历史读取正常；Chat / Responses 双形态带图发送及压缩后图片指代均通过 Mock 回放；非视觉模型带图明确失败；清空与 retention 正确释放引用和容量。
8. SQLite standalone 与 PG performance 新库均按当前 schema 启动，工具表/列不存在，用户资产表正常；本次不以真实存量库清理作为设计交付结果。
