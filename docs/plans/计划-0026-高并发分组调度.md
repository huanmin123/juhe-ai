# PLAN-0026 高并发分组调度

## 基本信息

- 编号：PLAN-0026
- 状态：第一版完整实现，待真实流量复测
- 创建时间：2026-05-22
- 需求来源：用户反馈同一个 API Key 大量并发时，请求会持续打入单个可用账号，导致上游排队、超时和用户长时间无响应。
- 关联模块：分组 / AI 账户 / API Key / 网关 / 调度运行态 / 使用记录 / 文档 / 验证

## 需求目标

- 新增高并发分组设计，用于同一个 API Key 被大量用户或程序并发调用时协调账号负载。
- 保留个人分组当前轻量行为，不因高并发场景改变默认用户体验。
- 高并发分组优先尊重账号配置，包括超级优先、优先级、备用、权重和并发上限。
- 调度不默认依赖上游状态码，而是依据本地可观测体验信号分流：当前并发、分组排队、请求耗时、首段等待、近期超时和质量缓存。
- 性能优先作为实现地基：高并发策略不能在每次请求里增加额外数据库往返、扫描历史明细、复杂全局锁或无界排序。

## 范围边界

本计划第一版已经完成代码实现，当前覆盖分组类型、策略字段、前端配置、绑定级权重和单账户排队阈值、运行态并发排序、默认最大单账户排队阈值、阈值后打破亲和、备用启用、进行中慢请求降权、分组短队列、每 API Key 队列上限和分组繁忙 `429`。除最大单账户排队阈值外，其它高并发保护策略默认开启，不提供用户侧开关。

总体设计范围：

- 分组类型：`personal` / `high_concurrency`。
- 高并发调度策略：单账户排队阈值轮转、快速优先、慢请求分流、备用账号排队启用、分组级短队列。
- 绑定级调度配置：权重、单账户排队阈值覆盖、本地超级优先、本地备用。
- 网关运行态：账号当前并发、分组等待、慢请求计数、最近分配时间等单节点易失指标。
- 热路径性能约束：复用一次运行时快照，候选账号 O(n) 评分，运行态 O(1) 更新，本地队列有上限且可快速失败。
- 指标分层：当前并发、排队和慢请求进行中状态由网关内存维护；近期质量、超时率、首 token 和总耗时趋势由 background worker 或请求终态事件反向写入紧凑缓存。
- 页面：创建 / 编辑分组时选择分组类型，高并发分组只暴露最大单账户排队阈值配置，其它保护策略内置默认开启。

暂不做：

- 分布式队列、多实例共享调度态或 Redis。
- 把慢请求分流直接写成账号异常。
- 主动中断或迁移已经发往上游的请求。
- 依赖上游状态码白名单做默认账号健康判断。

## 验收标准

- 用户确认高并发分组命名、配置项、策略优先级和待复查问题。
- 实现后个人分组行为不回归。

- 权重、超级优先、备用和授权账户本地配置在高并发分组中生效且作用域正确。

## 风险与注意事项

- 会话亲和与快速优先存在天然冲突；当前已确认高并发分组默认在达到单账户排队阈值后允许打破亲和，优先避免请求锁死在单账号。
- 流式长请求可能长期占用并发槽，后续可能需要按请求类型设置不同单账户排队阈值或慢请求阈值。
- 高并发实现必须先占用账号并发槽再发起上游请求，并保证所有退出路径释放，否则会在瞬时并发下继续集中打到同一个账号。
- 本地队列满、等待超时和客户端等待中断没有上游尝试，但仍需要记录为网关本地失败，便于统计和排障。
- 后台反向缓存允许滞后，不能作为强一致健康事实；缓存缺失或过期时必须保守降级，不能阻塞请求重算。
- 单节点易失运行态在重启后会丢失，这符合当前轻量边界，但后续多实例部署需要重新设计共享调度态。
- 分组繁忙对外返回 `429`，表达本地容量不足且客户端可重试。

## 完成总结

第一版已落地高并发分组的完整调度闭环：历史和默认分组保持个人分组语义；高并发分组在同一 API Key 大量并发时，会按当前并发、单账户排队阈值、硬并发、绑定权重、绑定阈值覆盖、备用、超级优先级、优先级、进行中慢请求和质量分对候选账号重新排序。达到阈值后默认允许打破会话亲和，避免请求被锁死在单个账号排队；全部候选达到硬并发时先进入有界分组短队列，账号释放后唤醒队列，队列满、单 Key 超额或等待超时后返回 OpenAI-compatible `429`。

性能上，第一版不在请求热路径新增额外数据库查询，不扫描使用记录或日志明细，不依赖上游状态码做默认健康判断。账号质量继续复用后台维护的 `account_quality_scores` 快照；实时当前并发和进行中慢请求由网关运行态动态读取，缓存只保存账号静态信息，避免缓存旧并发导致调度失真。短队列只保存轻量元信息，并受分组总量、单 API Key 数量和最大等待时间限制。
