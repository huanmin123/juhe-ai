## 需求目标

修复“页面显示待探针确认，但普通调度仍继续命中”的语义冲突。普通用户请求失败仍只能投递一次后台核实信号；只有独立后台探针形成真实上游尝试并确认失败后，才能进入共享 `precheck_pending` 软阻断。全池软阻断时先尝试后备分组，再执行单账户单飞半开和有界等待，整个请求不得超过 270 秒绝对总预算。

## 范围边界

- 包含 memory / Redis 下一致的 `precheck_pending` 普通调度软阻断、generation 校验、受控半开、进程内有界等待和请求绝对截止时间。
- 不增加数据库 schema，不将请求 payload / headers / 凭据放入 Redis 或后台队列。
- 不让普通用户请求的成功或失败直接修改账户级状态；账户所有者明确配置的错误策略和响应拦截仍按原契约执行。
- 后台探针未真实到达上游、任务取消或执行器自身错误均属于未知，不得软阻断。
- 不部署、不切流、不修改生产 Redis / 数据库 / 代理配置。

## 验收标准

1. 账户列表显示 `precheck_pending` 时，普通调度不再命中该账户。
2. 用户请求不能直接建立、续期或升级账户级软阻断。
3. 全池软阻断时不失败开放，也不并发打满上游；只有租约持有者可半开。
4. 等待、重试和换号使用同一绝对截止时间，最多 270 秒，断开后无残留等待者或租约。
5. 离线自动化验证通过，生产发布仍保持冻结。

## 风险与注意事项

- 该改动直接影响网关调度，必须分阶段验证，禁止与页面缓存等无关改动合包直接上线。
- Redis 不可用时不得把空快照当作“全部正常”，也不得在请求热路径回源业务数据库。
- 半开成功要求完整协议成功，仅 headers、首字节或部分 token 不能解除软阻断。

## 完成总结

memory / Redis 存储契约下的 `precheck_pending` 软阻断、generation + leaseId CAS、同账户 / 同分组单飞半开、FIFO 等待和 270 秒绝对 deadline 已完成，并通过真实 HTTP Mock、类型、lint、构建和关联回归。普通请求仍不能建立或清理账户级运行态，显式用户策略例外保持不变。当前只剩真实 Redis 隔离实例验证和生产发布，发布继续冻结等待用户通知。
