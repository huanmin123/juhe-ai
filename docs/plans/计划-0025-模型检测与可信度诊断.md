## 需求目标

- 背景：用户希望新增一个独立菜单，让管理员和普通用户都能自行检查当前链路是否可信地提供目标模型；第一版只支持 `gpt-5.5` 和 `gpt-5.4`。
- 目标：提供内置自托管的模型可信度检测能力，供用户在 `我的 AI 账户` 中检查自己的 AI 账户是否像目标模型，同时把检测请求纳入现有权限、额度、使用记录、审计和脱敏边界；默认用最多 2 个单轮轻量探针快速初筛，用户显式开启深度检测后保留原有准确率优先完整检测。
- 交付物：长期设计文档、调研结论、接口契约、后端检测服务、数据集目录库检测事实表、前端中文页面、专项回归和验证记录。

## 方案概述

- 方案原则：内置检测、自托管执行、复用本地 OpenAI 网关链路、按真实使用计入额度和记录、只保存脱敏有界摘要。
- 数据变化：检测运行表和检测项表继续复用现有 `profile` 字段，记录 `quick | full`、等级、分数、traceId、调用方、耗时、错误摘要和脱敏证据；不新增数据库列。
- 接口变化：新增管理侧和用户侧两套 model-checks 接口，普通用户接口固定当前登录用户作用域，管理员接口支持管理筛选。
- 前端变化：独立菜单 `模型检测` 提供 AI 账户选择、模型选择、默认关闭的“深度检测”开关、仅深度模式可选的可信对比账户、结果总览、证据列表和历史记录；历史与详情明确展示快速 / 深度模式。
- 后端变化：新增模型检测模块，复用账号测试中的内存网关请求能力和网关实际转发路径，不在检测服务里另写直连上游。
- 数据处理策略：检测历史属于数据集目录库排障数据，遵守保留期和分页窗口规则；检测产生的真实模型请求继续进入既有使用记录、统计和审计流程。

## 风险与注意事项

- 模型检测是概率诊断，不能用于法律、财务或官方认证结论。
- 探针题库必须隐藏和版本化；公开题面容易被中转服务针对适配。
- 检测会真实消耗 token、成本和授权额度，当前成本由发起用户承担；快速档只减少本系统主动探针和等待，不承诺固定耗时，深度档仍可能因上游超时、限流和分钟级重试持续数分钟。
- 可信对比会额外消耗用户选择的对比账户额度，必须由用户显式选择；未选择或账户不可用时不能自动降级为普通检测。
- OAuth / Codex adapter 与公开 OpenAI API Key 行为不同，报告必须展示 adapter 能力边界。
- 本地 `/v1/models` 当前来自模型目录，不能当作上游账号可见模型的强证据。
- 发布异常处理：实现后如检测误报，先修正当前检测逻辑或暂停运行入口，检测记录保持只读查询。
