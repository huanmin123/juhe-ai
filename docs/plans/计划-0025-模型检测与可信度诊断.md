## 需求目标

- 背景：用户希望新增一个独立菜单，让管理员和普通用户都能自行检查当前链路是否可信地提供目标模型；第一版只支持 `gpt-5.5` 和 `gpt-5.4`。
- 目标：提供内置自托管的模型可信度检测能力，避免用户把本地 API Key 粘贴到第三方网站，同时把检测请求纳入现有权限、额度、使用记录、审计和脱敏边界；当前优先保证检测准度，成本和耗时由发起用户承担。
- 交付物：长期设计文档、调研结论、接口契约、后端检测服务、记录库摘要表、前端中文页面、专项回归和验证记录。

## 方案概述

- 方案原则：内置检测、自托管执行、复用本地 OpenAI 网关链路、按真实使用计入额度和记录、只保存脱敏有界摘要。
- 数据变化：新增检测运行表和检测项表，字段覆盖目标类型、目标 ID、目标模型、profile、等级、分数、traceId、调用方、耗时、错误摘要和脱敏证据。
- 接口变化：新增管理侧和用户侧两套 model-checks 接口，普通用户接口固定当前登录用户作用域，管理员接口支持管理筛选。
- 前端变化：新增独立菜单 `模型检测`，提供目标选择、模型选择、profile 选择、进度、结果总览、证据列表和历史记录。
- 后端变化：新增模型检测模块，复用账号测试中的内存网关请求能力和网关实际转发路径，不在检测服务里另写直连上游。
- 数据处理策略：检测历史属于记录库排障数据，遵守保留期和分页窗口规则；检测产生的真实模型请求继续进入既有使用记录、统计和审计流程。

## 风险与注意事项

- 模型检测是概率诊断，不能用于法律、财务或官方认证结论。
- 探针题库必须隐藏和版本化；公开题面容易被中转服务针对适配。
- 检测会真实消耗 token、成本和授权额度，当前成本由发起用户承担；页面仍必须提前给出成本、次数和预计耗时提示。
- 官网对照会额外消耗官网基线账号额度，必须由用户显式开启；没有可用官网基线账号时不能自动降级为普通检测。
- OAuth / Codex adapter 与公开 OpenAI API Key 行为不同，报告必须展示 adapter 能力边界。
- 本地 `/v1/models` 当前来自模型目录，不能当作上游账号可见模型的强证据。
