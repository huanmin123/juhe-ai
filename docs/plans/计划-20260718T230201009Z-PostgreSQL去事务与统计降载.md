# PLAN-20260718T230201009Z PostgreSQL 去事务与统计降载实施计划

> **给执行 Agent：** 使用 `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans` 逐任务实施；严格执行先失败回归、再最小实现、最后验证。

**目标：** 在不删除、关闭或弱化任何管理、统计、额度、审计和网关功能的前提下，消除 PostgreSQL 普通查询的隐式事务开销，将统计写入改为增量、批量、低频且可重建的后台工作。

**架构：** 普通 PostgreSQL `query`、`one`、`execute` 直接使用连接池执行一条 SQL；只有同时维护多个数据库状态且不能拆开的真实不变量使用最小范围事务。统计页面继续读取全部现有窗口和汇总字段，后台只处理变化范围并批量写入，派生统计允许短时滞后并可离线重建。

**技术栈：** Node.js 22、TypeScript、`pg`、PostgreSQL 18、PgBouncer、DatabaseClient、stats-worker、pnpm。

## 现场依据

- `backend/src/storage/database-client.ts:createPostgresDatabaseClientInternal` 的普通 `query` / `execute` 调用 `queryPostgresWithLocalTimeout`。
- `queryPostgresWithLocalTimeout` 每次执行 `pool.connect -> BEGIN -> 三个 SET LOCAL -> SQL -> COMMIT -> release`。
- 生产主调用组累计约 `49,518,510` 次 `BEGIN`、`49,479,168` 次 `COMMIT` 和 `48,299,700` 次 timeout `SET LOCAL`。
- PgBouncer 历史平均实际 SQL 约 `4.32ms`，平均事务约 `37.51ms`。
- `usage_scope_range_windows` 主写入组平均 `1733.5ms`、最大 `28.16s`；`usage_quota_hourly_windows` 平均 `343.5ms`、最大 `6.69s`。
- `group-account-stats-cache.repository.ts:refreshGroupAccountStatsCacheAsync` 先按 chunk DELETE，再逐行 INSERT；每条 execute 又套普通查询事务。

## 不删减功能的硬边界

- 不删除任何菜单、页面、接口、响应字段、统计维度、额度规则或后台任务能力。
- 不关闭使用记录、统计、审计、授权用量、额度窗口或分组统计来换取性能数字。
- 不使用 `items: []`、零值统计、缺字段、吞错或固定缓存结果伪装快速响应。
- 统计刷新失败时继续读取上一份真实快照或返回明确错误，不把失败伪装成“真实值为零”。
- 额度判断入口、规则和拒绝语义保持不变；允许派生窗口在约定时限内滞后，但不能绕过额度判断或永久停更。
- 账户、授权、API Key 等真实多表不变量仍使用最小显式事务。

## 事务分级

### 必须删除事务包装

- 所有纯读 `query` / `one`。
- 单条 INSERT / UPDATE / DELETE。
- 展示性日志、审计和运行状态单条写。
- 清理任务的一条有界 DELETE。
- 可重建统计 cache 的单条批量 upsert。

### 必须保留最小事务

- 一个业务命令需要同时修改多张业务表，部分成功会使当前功能无法继续运行。
- 账户 / 分组 / API Key / 授权的多表创建、更新或删除不变量。
- 统计聚合一个小批次的结果与该批次 cursor 共同推进。
- staging window 构建完成后的单次发布切换。

### 禁止的大事务

- 整轮 stats job。
- 跨多个独立窗口 stage。
- 多个账户、分组或授权的循环。
- 包含 Redis、HTTP、文件 I/O 或 sleep 的事务。
- 为设置 timeout 而创建的空业务事务。
