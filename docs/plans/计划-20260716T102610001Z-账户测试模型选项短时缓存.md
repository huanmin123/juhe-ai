# PLAN-20260716T102610001Z 账户测试模型选项短时缓存

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 避免用户反复打开“测试账号连接”时重复等待同一账户的 `test-options` 请求，同时保持权限、账户版本和管理范围隔离。

**Architecture:** 在前端账户模块增加一个只保存 `AccountTestOptions` 的模块级短时请求缓存，复用 `createShortLivedRequestCache` 的 TTL、容量和并发合并能力。缓存键包含当前登录系统账户、用户/管理视图、目标系统账户、账户 ID 和 `configRevision`；Node 后端已有模型目录缓存，本次不增加完整接口响应缓存，也不改变 Go 后端。

**Tech Stack:** Vue 3、TypeScript、现有前端回归脚本、pnpm。

## 事实与方案确认

- 当前每次打开已保存账户的测试弹窗都会重新调用 `test-options`；弹窗内切换模型不请求网络。
- `test-options` 查询本地账户配置和模型目录，不会访问真实上游或消耗模型额度。
- Node 模型目录已有 60 秒、最多 1000 项的内存/Redis 缓存，因此不再缓存整个后端响应。
- Go 模型目录缓存属于独立渐进迁移事项，本次生产仍运行 Node，不随本需求扩展。

比较过的方案：

1. 前端短时请求缓存：直接消除重复打开等待，改动和风险最小；采用。
2. Node 缓存完整 `test-options`：会把权限、账户配置和目录失效揉在一起，且重复现有目录缓存；不采用。
3. 浏览器持久化或记住手选模型：会改变现有“重开恢复账户检查模型”契约，且不是本次缓存问题；不采用。

## 缓存契约

- TTL 为 5 分钟，容量上限 100 个键；仅驻留当前页面进程内存，不写 `localStorage` 或 `sessionStorage`。
- 相同缓存键的并发请求共用同一个 Promise；失败请求不进入缓存。
- 缓存键：当前用户 ID + 用户/管理视图 + 目标系统账户 ID + 账户 ID + `configRevision`。
- 账户配置修改后 `configRevision` 变化会自然形成新键；不同用户、不同视图和不同管理范围不能复用结果。
- 供应商模型目录写入触发现有模型选项缓存失效时，同时清理账户测试选项缓存。
- 保持现有请求 token：缓存命中或并发合并后，旧弹窗结果仍不能覆盖新打开账户。
