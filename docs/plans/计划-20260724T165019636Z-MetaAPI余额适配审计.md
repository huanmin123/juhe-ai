## 1. 背景与目标

用户希望参考 [cita-777/metapi](https://github.com/cita-777/metapi) 扩充本项目尚未覆盖的余额查询。目标是审计该项目的实际路径、鉴权方式和金额语义，只纳入能以本项目既有“单 API Key + Base URL + 已绑定代理”安全、确定地查询真实余额的规则；不把用量窗口、固定占位零或管理端登录态误写成 API Key 余额。

## 2. 范围与非目标

- 范围：MetaAPI `41767a65ec8e5470a9a70f4615b47dc24949afff` 的平台余额实现，与本项目 `sub2api`、`newapi`、`litellm`、`user_balance` 和自定义接口逐项比对。
- 范围：零、负数、订阅不限额、API Key 鉴权失败及自动回退请求数的语义复查。
- 非目标：新增站点登录、密码保存、Cookie 持久化、网页抓取、用户 ID 猜测、会话自动续期或把余额接入调度/额度判断。
- 非目标：生产发布、生产库迁移或使用用户真实凭据批量探测。

## 3. 准入规则

一个新内置适配器必须同时满足：

1. 仅通过账户现有 Base URL、单 API Key 和账户代理即可发出只读请求。
2. 上游明确把该 API Key 用于该余额接口，而不是站点 session、Cookie 或后台 JWT。
3. 返回 JSON 中存在可验证的余额或可计算的总额/已用额，并可确认 USD 或明确的稳定换算关系。
4. 请求能遵守当前同源、禁止重定向、256 KiB 响应上限、15 秒总 deadline 和 `401/403` 立即停止的安全边界。
5. 不会仅因 API Key 缺少管理端权限就误判为账户余额为零，也不会显著增加一次刷新向同一上游发送的探测数量。

## 5. 调研结论与决策

MetaAPI 的 `balanceService` 在 `credentialMode=apikey` 或没有 `accessToken` 时直接返回缓存并标记 `proxy_only`，不调用 adapter；因此 MetaAPI 本身没有可直接迁移的“单 API Key + Base URL”余额规则。它的 New API、AnyRouter、One API、OneHub、DoneHub、Veloera 余额读取均为 `/api/user/self` 的站点管理登录态，并在一些分支中再回退 Cookie 和用户 ID。其 `verifyToken` 明确先把输入识别为 session，只有无法得到用户信息时才按 API Key 查询模型。Sub2API 使用 `/api/v1/auth/me` 的 JWT/session；OpenAI、Claude、Gemini、Gemini CLI、Antigravity 和 CLIProxyAPI 在 MetaAPI 中没有真实余额查询，部分实现直接返回零。

这五个项目的共同协议已收敛为 `openai_billing`：先读取 `/api/status` 判定单位，再读取 API Key 保护的 `/dashboard/billing/subscription` 和 `/dashboard/billing/usage`，按 `hard_limit_usd - total_usage / 100` 计算。源码中的 `hard_limit_usd=100000000` 是无限 Key 限制占位而不是可消费余额，返回 `unsupported`。不调用 MetaAPI 使用的 `/api/user/self`、Cookie、用户 ID 头或站点 access token，也不把 `401/403` 解释为零余额。

这不是耗尽余额问题的完整解法：五个项目的 `ValidateUserToken` 都在普通 Key `RemainQuota <= 0` 时拒绝请求，dashboard handler 不会得到可计算的 JSON。仅凭 API Key 不能区分零、负数、撤销 Key 和访问限制；要解决该状态，必须由上游把账单路由改成 read-only token 验证，或提供另一个明确的 API Key 余额接口。

同时，本轮已经确认并回归：余额为 `0` 和任意负数必须按实际金额保存、展示；只有明确的订阅不限额哨兵才映射为 `unlimited`。

## 8. 当前结论

MetaAPI 没有可直接迁移的 API Key 规则，但已审计的 One API、New API、OneHub、DoneHub 和 Veloera 源码证明存在共同的 API Key dashboard billing 接口。本项目已通过 `openai_billing` 自动匹配该协议，适用于上游实际允许 API Key 进入账单路由的账户；主线源码的耗尽 Key 会被鉴权前置拦截，不能用客户端猜成零。管理端登录态余额仍单独立项，不复用 API Key 凭据。真实上游响应仅待用户以单账户人工刷新确认。
