## 需求目标

- 背景：当前网关已有 OpenAI `200 + SSE` 流内失败拦截，但策略写死在代码里；部分上游中转会在流中插入广告或污染事件，普通非 `2xx` 错误策略无法处理。
- 目标：把流式拦截从硬编码能力升级为可配置策略，支持协议层、供应商层和账户追加规则分层隔离，并让用户只选择处置模板 `action`，避免自由组合底层开关。
- 交付物：配置设计文档、实施计划、存储 schema、管理 API、前端策略管理页、账户编辑入口、网关运行时匹配、审计元信息和必要回归验证。

## 方案概述

- 方案原则：配置层只表达业务意图，执行层按当前流阶段和客户端能力选择具体落地方式。
- 数据变化：新增策略表保存管理端策略；账户追加规则优先复用账户配置 JSON，必要时再拆表。管理端策略保存 `scope_type`、`protocol_code`、可选 `provider_code`、匹配条件、`action`、优先级和基础元数据；账户规则只保存匹配条件、`action`、优先级和基础元数据。命中阶段由网关运行时按真实下游写入状态判断，不作为用户配置字段。
- 接口变化：新增管理员策略管理接口；账户详情和保存接口补充账户追加规则与继承摘要；创建 / 更新接口只接收 `action`，不接收执行参数组合。
- 前端变化：新增独立策略管理页；基础区显式选择协议层 / 供应商层，账户编辑弹窗新增账户级流式拦截卡片；处置区改为模板选择并展示模板说明。
- 后端变化：新增策略 repository / service / routes；网关请求开始前加载并编译候选规则，流式循环内只消费内存规则。
- 数据处理策略：不缓存完整流，不保存完整命中文本；命中摘要只记录规则 ID、规则名称、命中字段、短片段和执行结果。

## 风险与注意事项

- 风险 1：广告关键词误杀正常输出。规避方式是按账户追加规则优先、小范围启用、支持试运行和短 TTL 运行态避让。
- 风险 2：已输出后重试会破坏客户端状态。规避方式是禁止服务端静默拼接，只能按客户端能力通知失败 / 重试。
- 风险 3：策略过多拖慢流式转发。规避方式是请求开始前合并候选规则、规则数和关键词数设上限，并按来源顺序和优先级短路。
- 风险 4：命中正文保存过多引入隐私和存储风险。规避方式是只记录短摘要和结构化命中字段。
- 发布异常处理：如上线后误拦截，可停用管理端策略或账户追加规则；默认规则变更需要发布修正版本。
