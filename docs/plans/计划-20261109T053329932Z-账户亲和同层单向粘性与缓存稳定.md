## 需求目标

- 背景：自营模型可能由不同上游服务承接，缓存是否互通无法确认；高并发下账户容量满时，同一会话在 A/B 账户之间反复切换，导致上游缓存持续失效。
- 现状放大因素：账户亲和 `first-binder-wins` + 绑定账户每请求仍被排到首位 + 普通分组并发短等最多约 1.2s + 成功后不改绑，形成“先撞 A、失败用 B、A 一空又回 A”的振荡。
- 目标：同层内改为**单向粘性（latch）**：A 容不下 → 切到 B 成功后，绑定改到 B；A 恢复空闲也不主动回切。会话在有限资源内尽可能稳定在同一账户，减少切换风暴和缓存损失。
- 缓存限制：上游缓存是否跨账户/跨服务共享**不可知**，本计划不建模缓存域；唯一可靠缓存单元是账户，跨账户切换按“可能丢缓存”处理并单独计数。latch 只减少切换次数，不承诺跨账户缓存命中。
- 量化目标：先建立基线，再以“会话-账户命中率提升、跨账户切换率下降、缓存命中率不降、p95 不显著恶化、429 不增加”作为验收口径；具体目标值在基线观测后回填，不在实施前拍脑袋。
- 交付物：设计契约文档、同层谓词四层模型、账户亲和绑定/租约/重绑代码、有界等待、会话名额（软占位，按需）、容量“满”语义修正、指标、单测与集成验证、文档同步。

## 方案概述

### 术语与资源边界

- **owner**：会话当前绑定的账户。
- **调度层**：`GatewayAccountDispatchPriorityTier` 四元组 `modelRank:fallbackRank:superRank:priority`（`gatewayproxyhealth/dispatchpriority.go:29-44`、`gatewaydispatch/dispatchsegments.go`）。
- **同层**：四元调度层相等。super/fallback/priority 已包含在四元组内。
- **质量带**：`QualityScore`（毫秒量纲：首字 EWMA + 状态/年龄罚分；未知=1,000,000）按 `qualityBandWidthMs` 量化；只用于层内排序与后继选择。
- **latch**：同层内 owner 一旦因容量不可用而切到新账户，绑定即迁移到新账户；owner 恢复空闲也不主动回切。
- **lease**：会话对 owner 的优先占位，默认 30 分钟滑动续期；过期后占位可回收，下一次请求是全新分配。
- **slot**：每账户可同时记住的会话数软上限；只用于分配与 LRU 治理，**不占并发、不占 RPM、不作为拒绝请求的依据**。

### 同层谓词四层模型（W1 固化）

| 层 | 内容 | 作用 |
| --- | --- | --- |
| L0 硬门 | 配置启用、配额、模型/协议、权限、健康、屏蔽、熔断、调度排除 | 不通过即不可用，不参与后续比较 |
| L1 调度层 | `modelRank:fallbackRank:superRank:priority` 四元组 | **唯一“同层”定义**；层序由引擎既有 tier 排序决定 |
| L2 质量带 | `QualityScore` 按 `qualityBandWidthMs`（建议 2000ms）量化；未知最差 | 层内排序/后继选择；不改变同层定义，不主动破 owner latch |
| L3 运行态/显式覆盖 | `latency_degraded`、软阈值、traffic migration、账户锁死 | 可破 latch 或覆盖 latch；不是“层” |

谓词：

```
eligible(a)        := 通过 L0 所有硬门
sameLayer(a,b)     := GatewayAccountDispatchPriorityTier(a) == GatewayAccountDispatchPriorityTier(b)
qualityBand(a)     := unknown ? WORST : floor(QualityScore(a) / qualityBandWidthMs)
ownerUsable(o)     := eligible(o) && !hardBusy(o) && !runtimeExcluded(o) && !softBroken(o)
latchAllowed(o,c)  := ownerUsable(o) && sameLayer(o,c) && !trafficMigrationOverride && !accountLocked
successorEligible(o,c) := eligible(c) && sameLayer(o,c) && !hardBusy(c) && !runtimeExcluded(c)
successorOrder     := qualityBand asc -> load/occupancy asc -> stable order
```

关键点：

- **super/fallback/priority 已在四元组内**：超级优先是更高层、备用是更低层，不再需要单独的“super priority 覆盖 latch”规则。
- **建议删除 `anySuperPriority` 短路**：当前组内存在超级优先账户时会关闭整个个人分组亲和，与“超级优先只是更高层”不一致；删除后普通层内亲和恢复，超级优先层仍按层序优先。W3 补行为变更测试；若保留，需登记为显式例外。
- **质量带不破 latch**：owner 健康时，即使同层 peer 质量带更好也不让位；质量只在后继选择中优先，严重退化由 `latency_degraded` 例外兜底。
- **重绑只允许同层**：跨层成功不重绑，绑定留在原 owner；跨层后果与最短驻留见 P2。

### 行为契约

1. **同层优先 owner**：owner 仍在候选集、健康且未硬满（并发/RPM/lane）时，同层内优先它；不因其他同层账户更空闲、质量分更高或缓存率更高而让位。更高层账户可用时仍按层序优先（跨层不 latch）。
2. **不可用时切换**：owner 硬满或被运行态排除时，先做有界优先等待（仅并发类失败，共享 1-2s：200ms×5-10 次；RPM reset 在预算内才等待），仍不可用则按后继规则选择同层可用账户。
3. **后继规则**：同层 → 质量带优先 → 负载/占用分散 → 稳定顺序；同层无可用候选才走跨层正常 tier walk。不建模缓存域。
4. **成功后重绑**：新账户最终协议成功（`ProtocolValidatedSuccess`）后，以 CAS 把绑定从旧 owner 改到新账户；旧 owner 不因恢复空闲被重新提升。仅同层重绑。
5. **再次失效再迁移**：新 owner 也失效时，重复第 2/3/4 步；任何时刻以“最后一次最终协议成功的同层账户”为 owner。
6. **跨层不 latch**：更高层账户恢复仍按层序优先；跨层切换保持现有语义，不在本计划内禁止。
7. **租约边界**：lease 有效期内 latch 生效；租约过期或被 LRU 驱逐后视为新分配，允许重新落到旧账户（用户已确认这是可接受边界）。
8. **多分组容量满**：组内所有候选都通过既有 lane 容量 busy 判定（硬并发 + image lane）才算该组满；RPM 仍由派发阶段处理；按 `RoutePlanSnapshot` 顺序走到所有目标都不可用才是终态。组级亲和仍按既有“成功组不回切”。

### 会话名额（slot）语义（P1，已实施）

- 每账户一张会话名额表（Redis ZSET），跨分组共享；member = `sessionAffinityKey`，score = `leaseUntilMs`。
- 名额上限是**软护栏**，不直接等于 `min(concurrency_limit, rpm_limit)`：`clamp(min(C×4, R/2), 32, 10000)`（C=并发硬上限，R=RPM；4=每并发位记住的会话数，2=活跃会话平均每分钟请求数）。
- 名额作为**分配目标**而非“新会话到达就驱逐”：owner 已持有名额直接使用；既有会话名额过期/被驱逐且 owner 满时先做 200ms×5-10 次（1-2s）等待，再按“同层空闲名额 → 其他层空闲名额”回退；新会话占位 owner 不等待，直接分配空闲名额；全池满保留 owner，成功结算时 `ZPOPMIN` 最久未成功会话。
- 名额满不拒绝请求；owner 并发/RPM 仍由派发阶段处理；slot 写失败只告警。
- 被驱逐会话异步清理绑定，下次请求重新分配；这是缓存损失的可接受边界。请求开始对 active 名额 touch，LRU 按最近请求排序，降低在途会话被驱逐概率；仍不维护逐请求在途计数。

### 数据与接口变化

- 账户亲和绑定记录（Redis JSON）增加 `leaseUntil`、`lastActiveAt` 字段；旧记录缺字段按“无 lease”处理，首次成功请求补写，不批量清洗。
- 新增 Redis 名额索引键空间（按账户，已实施）；使用 Lua 原子完成“清理过期 → 计数 → 冷会话驱逐 → 写入”。
- 新增内部端口方法：`SessionAffinityPort.RebindAsync(expectedOwner, newOwner, scope) bool`（reason 只在调用方审计/指标，不进入存储接口）；不新增公开 API、不改前端 DTO。
- `DispatchContext` / `UpstreamDispatchResult` 增加：claim owner、本请求容量拒绝账户 ID、最终成功账户、同层标志（供最终成功结算使用）。
- 不改 PG schema、env、compose、部署路径；回退只需换回旧二进制，新 JSON 字段与 Redis 键对旧二进制无害。

### 排序与调度变化

- 个人分组：`orderOpenAIPersonalAccountsBySessionBinding` 已能在同层提升 owner；新增“owner 硬满时不做 claim 重排”的守卫，避免把硬满 owner 重新提到首位。
- 普通分组比较器：`compareSoftConcurrencyCandidates` 中 `affinityAllowed = bound && !hardBusy && !softBusy` 位于层键之后、load ratio 之前；紧随其后的 `softBusy` 键用于非 owner 排序，硬满仍排最后。原高并发分组比较器随分组退役删除。
- 有界等待：owner 与名额等待共享 `SessionAffinityOwnerWaitBudgetMs`（默认 2000ms），固定 200ms 轮询；准备期消耗后剩余额度传给派发阶段；RPM reset 在剩余预算内才等待，否则立即切换。
- D-94：`AreGatewayAccountsCapacityBusyForLaneAsync` 由 any 改为 every；两个调用点（`preparation.go 当前组回退调用点`、`fallbackcandidate.go:202`）一起回归。
- 名额规划：准备期 `PlanSessionSlot` 把 owner/同层空闲名额账户提到候选首位；`slot_fallback` 允许跨层 CAS 重绑；成功结算 `ConfirmSessionSlot` 写入/释放/LRU。
- 后继分散：稳定随机/轮转键仍未实施；P0 保留 `loadRatio`/`currentConcurrency`，名额优先分配作为集中度的主要护栏，发布后按 T199 指标决定是否补充。

## 风险与注意事项

- 行为契约变更：账户亲和从 `first-binder-wins` 改为“同层 latch + lease”，需先改设计文档再改代码；旧客户端/旧二进制回退时新 JSON 字段应被忽略，需在实现时验证。
- 尾延迟：有界等待会增加 p95，必须严格上限（共享 2000ms、200ms×5-10 次），且 RPM reset 超预算不等待；若观测到长尾，优先缩短等待而非扩大。
- 负载集中/herd：A 满后大量会话同时迁移到 B，可能把 B 打满；P0 先靠同层分散排序，P1 名额 cap 兜底，必须观测迁移目标分布。
- 质量被粘性覆盖：owner 健康时同层质量带更好的 peer 不会抢占；若产品要求质量优先，必须把质量升为层或调整例外。
- 缓存共享不可知：任何跨账户切换都可能丢缓存；latch 只减少切换次数，不能保证跨账户命中。若观测到跨账户切换仍然很高，说明容量/分组结构才是主因，不能靠本机制硬扛。
- 名额上限误判：`clamp(min(C×4, R/2), 32, 10000)` 是保守起点（4=每并发位会话数，2=活跃会话每分钟请求数）；若生产会话时长/请求频率明显偏离，需用 `slot_fallback`/驱逐/命中率指标校准，不能把名额当作容量门。
- `anySuperPriority` 删除是行为变更：需要覆盖“普通层内亲和恢复、超级优先层仍优先”的测试；若保留，必须在契约中写明整组关闭亲和。
- lease 30 分钟与上游缓存 TTL 不匹配：缓存 TTL 不可知，30 分钟到期/LRU 驱逐可能丢掉仍热的缓存；P1 需按观测调整。
- 多实例：lease/名额/CAS 全部走 Redis；进程内 fallback 只用于测试/降级，生产不得依赖本地 map。
- D-94 修复会改变多分组回退频率（减少过早回退），需回归 failover/rr/weighted 与组级亲和；`fallbackcandidate.go:202` 也会从 any 变 every，需专门用例。
- 跨层仍可能回切；如果观测到跨层抖动，按 P2 单独裁决最短驻留，不要顺手扩大 latch 范围。
- P1 名额表复杂度高（Lua/索引/驱逐/多实例）：当前已实现并有单测；剩余风险是 LRU 不区分在途会话与名额公式偏离真实会话负载，发布后按 `slot_wait_ms`/`slot_fallback_total`/`slot_evictions_total` 观察，异常回滚二进制。
- 发布异常处理：回退旧二进制；新增 Redis 键按 TTL 自然过期，绑定 JSON 新字段对旧解析器无害；无 PG schema/env 变更。
