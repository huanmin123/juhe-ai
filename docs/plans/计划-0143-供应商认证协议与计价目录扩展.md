## 需求目标

在不影响迁移分支的独立 worktree 中，补齐供应商认证、协议能力、模型目录和计价边界：

1. 修复现有 OpenAI OAuth 的刷新、会话和错误处理风险，保持浏览器授权码回调与用户提供 Access/Refresh Token 两种已实现入口。
2. 增加 xAI/Grok 官方 API Key 文本主链，复用 OpenAI Chat/Responses wire protocol，不伪造新的协议语义。
3. 完成 Anthropic 官方 Workload Identity Federation 能力评估，明确当前缺少可信 assertion source 时不开放的边界，不接入 Claude.ai/Claude Code 订阅 OAuth。
4. 增加 Gemini 官方 OAuth 与 Interactions API 能力，保留 GenerateContent 主链。
5. 将模型目录和计价改成可追溯、按供应商语义隔离的事实，避免历史使用记录按当前价格重算。

## 范围边界

### 本次范围

- provider auth driver、OAuth session、token refresh 和账户类型能力边界。
- OpenAI OAuth 浏览器授权码回调、Access/Refresh Token 凭据入口及其刷新契约；Device Code 仅作参考能力对照，本次不实现。
- xAI provider、OpenAI Chat/Responses profile、官方模型和价格快照。
- Anthropic 模型能力、effort、上下文和服务等级映射修正；WIF 官方能力调研、非开放边界和未来可信服务端 assertion provider 前置条件。
- Gemini OAuth、Interactions profile、模型能力和价格快照。
- 相关后端 seed、前端账户创建能力、回归测试、功能文档和计划记录。

### 明确不做

- Claude.ai、Claude Code、Grok CLI、Gemini CLI 等订阅账号 OAuth。
- Anthropic `workload_identity` 账户类型、导入、前端表单和运行时 token exchange；仅保存静态数据库 IdP JWT 不视为可用的自动轮换 source。
- 复制 CLIProxyAPI 的 TLS 指纹伪装、CCH 签名或第三方订阅账号绕过逻辑。
- 在请求路径实时扫描 usage 明细做统计或计价。
- SSH 反向隧道、autossh 或单 TCP 回源方案。
- 无官方来源的模型别名作为正式计价事实。

### CLIProxyAPI 认证方式对照

CLIProxyAPI 的命令入口在 `cmd/server/main.go` 中明确包含 Codex 浏览器 OAuth、Codex Device Code、Claude OAuth、Antigravity OAuth、Kimi OAuth、xAI OAuth 和 Vertex service-account JSON 导入。它面向 CLI/订阅账号池，其中部分流程使用订阅或内部服务凭据，不能直接等同于公开开发者 API 的官方账户类型。

| 参考能力 | CLIProxyAPI | 本项目当前结论 |
| --- | --- | --- |
| Codex / GPT 浏览器 OAuth | 已实现 | 保留并修复现有授权码 + PKCE 回调 |
| Codex Device Code | 已实现 | 未实现；不得在计划或 UI 标记为已支持 |
| 用户提供 OpenAI Access/Refresh Token | 可由认证文件承载 | 已支持用户自行配置；系统不主动为 AI 账户生成或预配 |
| Claude OAuth / Setup Token | 已实现订阅/CLI 账号路径 | 不接入；Anthropic 当前只允许官方 API Key |
| Antigravity / Gemini CLI OAuth | 已实现内部/CLI 路径 | 不复制；Gemini 只接收用户已有 Google OAuth token，并走公开 token endpoint 刷新 |
| xAI Device OAuth | 已实现 discovery、device-code 与 refresh | 不接入；xAI/Grok 当前只开放官方 API Key |
| Vertex service account | 已实现 JSON 导入 | 本次不接入；不与 Gemini API Key / Google OAuth 混成一个账户类型 |

## 风险与注意事项

- 上游 OAuth 合规和协议可用性优先于参考项目的技术实现；参考项目代码只能用于理解流程，不能作为授权依据。
- 认证类型必须表达真实凭据语义，不能用一个通用 `oauth` 字符串掩盖 API Key、Google OAuth 和订阅 OAuth 的差异；官方 WIF 在没有可信服务端 assertion provider 前不能只靠静态 IdP JWT 伪装成可用账户类型。
- 价格变更需要新快照和离线同步策略；运行时代码不写历史 schema 兼容分支。
- 当前工作树已同步到上述 `origin/master` 基线，原迁移工作树保持不变；后续继续合并 master 前必须先检查提交差异和路径重叠，避免覆盖双方改动。
