# 计划：在线帮助多篇文档站与协议使用说明

- 状态：in-progress
- 创建：2026-10-06
- 关联：`docs/functions/使用手册页面设计.md`（现行帮助中心权威设计）、`docs/functions/音频视频模型接入与统一媒体网关设计.md`（媒体协议契约）、`docs/functions/实时语音Realtime网关设计.md`

## 1. 目标

1. 网关最终用户能在在线帮助里查到三类协议（chat / 视频 / 音频，含 realtime）的完整请求说明：端点、认证、请求参数表、响应结构、可复制的 curl 示例、错误处理。
2. 每篇帮助文档可**下载为 Markdown 原文**。
3. 全部在线帮助从 2 篇长手册（用户/管理员各一）重写为**多篇小白向教程**：从 0 到 n，每篇讲明白一件事。
4. 内容单一数据源：Markdown 是唯一人工维护层；页面渲染物与下载件都从它派生。

## 2. 非目标

- 不改 gateway 的 helpweb 托管、会话门控与角色分流逻辑（`backend-go/projects/gateway/internal/helpweb/`）。
- 不改 docs/ 维护者文档体系（本计划只重做 `/__aisys__/help` 在线帮助面）。
- 不做全文检索引擎；篇目过滤沿用轻量前端过滤。
- 不新增后端接口；内容仍走静态托管。

## 3. 现状（2026-10-06 取证结论）

- 在线帮助 = `frontend/public/help/` 纯硬编码静态 HTML（user 8 章节 + admin 9 章节 + 门控分流页 + help.js/help.css），gateway 按 `JUHE_AI_FRONTEND_DIST_PATH` 会话门控托管在 `/__aisys__/help`；无 Markdown 源、无下载功能。
- 内容受回归 `frontend/src/scripts/regression/help-content-regression.ts` 锁定（17+28 条管理页深链、"更新于 2026-09-22"固定文案、禁止内联脚本断言）。
- 协议事实已取证（见 §5 附录）：认证 Bearer、chat/responses 透传、视频异步任务、音频三子形态、realtime 两步握手、统一错误信封。
- CSP：`script-src 'self' 'unsafe-inline'`（kernel/security.go:16），同源脚本与内联脚本均允许。
- 可复用先例：`externalSourceApiDocs.ts` 的 markdown 下载（Blob+download）；`marked` 18 已在依赖（chat 域）。

## 4. 设计

### 4.1 内容架构（Markdown 单一数据源 + 生成物入库）

```
frontend/public/help/
├── index.html            # 角色分流门控页（保持不变）
├── help.css              # 文档站样式（重写扩展）
├── help.js               # 文档站交互（重写：篇目导航/hash路由/搜索/下载）
├── manifest.json         # 篇目清单（id/标题/简介/受众/文件名，人工维护）
├── docs/                 # ★ 唯一人工维护层：23 篇 Markdown
│   ├── user/01-first-request.md … 15-faq.md
│   └── admin/admin-01-getting-started.md … admin-08-troubleshooting.md
└── rendered/             # 构建期生成物（入库，Code generated 头）
    ├── user/01-first-request.html …
    └── admin/…html
```

- 渲染脚本 `frontend/scripts/render-help-docs.mjs`：marked 渲染 `docs/**/*.md` → `rendered/**/*.html`；`--check` 模式渲染后与存量 diff（不一致退出非 0）。package.json 增 `render:help` 与 `test:help-content` 接线。
- 一致性门禁：help 回归测试内调用 `--check`（同 maintenance 种子生成器模式：源与生成物同库，测试钉一致）。
- XSS 面：内容全部自家维护，渲染后 HTML 直出；marked 默认转义内联 HTML 之外的文本，`dompurify` 净化兜底（依赖已有）。

### 4.2 页面形态（文档站）

- `/__aisys__/help/user/` 与 `/admin/` 的 index.html 变为文档站壳：顶部（产品名+返回管理台+角色标识）、左侧篇目列表（fetch manifest.json，按受众分组）、右侧内容区（fetch rendered html + innerHTML）、当前篇右上「下载 Markdown」（`<a href="../../docs/user/xx.md" download>` 同源直链）。
- hash 路由 `#/doc/<id>`：刷新/前进后退/外链深链均可还原；默认落到第 1 篇（用户）/第 1 篇（管理员）。
- 搜索：manifest 标题+简介前端过滤（保留现有无依赖风格）；浏览器内查找引导 Ctrl+F。
- 旧两篇长 HTML 的**内容资产**（五层旅程、17+28 条页面深链、排障症状表）拆改进对应篇目后，旧文件退役删除。
- 帮助页内联脚本禁令（旧回归断言）放宽为：允许同源打包脚本（help.js/rendered 内联骨架），仍禁外部域脚本——CSP 本就允许，回归断言同步改写。

### 4.4 写作规范（小白向）

- 每篇结构固定：这一篇解决什么问题 → 准备条件 → 分步操作 → 参数表 → 完整可运行示例 → 常见错误 → 下一篇链接。
- 协议参数表逐字段：字段名/类型/必填/说明/默认值；值必须与实现核对（取证材料为准，不确定的不写）。
- 示例全部可复制运行（curl 为主，`BASE_URL` 与 `YOUR_API_KEY` 占位符统一）；示例中模型名用 GET /v1/models 实际返回的形态。
- 语言：简体中文；接口字段/命令/路径保留原文。
- 禁臆造：实现没有的能力不写"即将支持"之类预告；高级通道（provider_options）点到为止并注明一般无需使用。

3. 写作批 B（上手与配套）：01/02/03/11/12/13/14/15。

5. 集成：全量渲染、旧 HTML 退役、manifest 定稿、隔离实例实测（登录→帮助→逐篇→下载 md）。
6. 回归重写：help-content-regression.ts 改为 manifest/rendered 一致性 + 篇目断言 + 下载链接断言 + 深链保留断言。

## 6. 验收标准

- 隔离实例登录后，用户/管理员角色各自能从"帮助"进入文档站，23 篇全部可读、可下载 .md，下载件为合法 Markdown。
- 协议篇的端点/参数/错误码与后端实现一致（复审抽查通过）。
- `render:help --check` 绿；前端回归（含重写后的 help 回归）绿；vite build 绿。
- gateway helpweb 代码零改动（纯前端静态资产交付）。
- 深链资产保留：旧 17+28 条管理页深链全部出现在新篇目中。

## 7. 风险

- 旧回归断言（固定文案/深链/无内联脚本）需全部同步重写，漏改即红——在集成步集中处理。
- 大量内容写作的准确性风险——以取证材料为准绳 + Critique 独立抽查。
- helpweb 静态服务对 .md 的 Content-Type/下载行为未实测——基础设施步先验证（若浏览器导航预览而非下载，用 download 属性兜底）。

## 8. 附录：协议取证结论（写作材料，2026-10-06）

- 认证：`Authorization: Bearer <API Key>`（Bearer 大小写不敏感）；realtime WS 升级可用 `?token=<ephemeral>`。
- chat：`POST /v1/chat/completions`，标准 OpenAI 报文透传，`stream:true` 走 SSE；`GET /v1/models` 本地目录渲染；`POST /v1/responses` Responses 面；`POST /v1/embeddings`、`/v1/images*` 透传；anthropic `/v1/messages`、gemini `/v1beta` 原生面并存。
- 视频（异步任务）：`POST /v1/videos` 必填 model/prompt，可选 seconds/size("WxH")/n/input_reference(图生视频)/negative_prompt/seed/audio；任务面 `GET /v1/videos`、`GET/DELETE /v1/videos/{id}`、`GET .../{id}/content`(completed 后 mp4)；job 对象 `id(video_前缀)/object:"video"/status/progress/model/prompt/seconds_length/size/error/provider/params_applied/params_ignored`；状态 queued/in_progress/completed/failed/cancelled/expired。
- 音频：TTS `POST /v1/audio/speech`（model/input/voice 必填，speed/response_format[mp3,opus,aac,flac,wav,pcm]/instructions/language 可选，同步音频二进制）；短转写 `POST /v1/audio/transcriptions|translations`（multipart 同步）；长转写 `POST /v1/audio/jobs`（model/input_url 必填——唯一输入形态，必须 http(s) URL）+ 同构任务面（object:"audio_job"，id 前缀 audiojob_）。
- realtime：`POST /v1/realtime/client_secrets`（body {"model":…}，须在 realtime 目录，响应 {"value","expires_at"}）→ `GET /v1/realtime?model=…`（Bearer 或 ?token=）WebSocket，事件透传 OpenAI Realtime。
- 错误：统一 `{"error":{"message","type","code"}}`（4xx invalid_request_error / 5xx server_error 等），按请求协议自动转 anthropic/gemini 形态；`/v1` 外路径 404 为裸 `{"message":"资源不存在"}`；SSE 已提交后失败走流内 failure event。
- 调度：用户传网关目录模型名；分组无账户支持时报 `unsupported_model`；无 model 报 `missing_model`；命中模型映射时出站改写、用户无感知。
