## 需求目标

- 背景：用户在前端网络卡顿时连续点击创建按钮，可能导致重复创建多条业务数据；同时希望每个功能都有明确唯一键，尽量通过数据库唯一约束保证数据安全。
- 目标：设计统一防重复提交能力和业务唯一约束策略，通过后端 AOP-like 路由切面和前端统一提交能力接入，避免把防重复逻辑散落在每个按钮或接口里。
- 交付物：幂等与唯一约束设计文档、计划记录、后端内存防重复切面、首批创建接口接入、前端统一提交锁、第一批数据库唯一索引兜底。

## 方案概述

- 方案原则：前端防重复只做体验，后端内存短 TTL 缓存拦截短时间重复提交，数据库唯一约束负责最终数据安全。
- 数据变化：不新增独立防重复提交表；补充实体和关系表业务唯一索引。
- 接口变化：管理端创建类 `POST` 由后端按操作指纹计算防重复 key；同资源指纹正在处理时返回 `409`。
- 前端变化：表单提交统一 pending 管理，显式按钮通过 `v-submit-lock` 一类全局指令声明接入，提交函数通过 `useSubmitAction()` 一类封装防止回车提交或弹窗 OK 绕过按钮。
- 后端变化：新增进程内防重复提交服务，并通过 `mutationGuard(config)` 或长期的 `defineMutationRoute()` 统一接入；与操作日志服务衔接，重复拦截、唯一冲突和无变化更新不写操作日志。
- 数据处理策略：正式加唯一索引前先检查重复数据；当前预上线本地库可备份后清理或重建。

## 决策记录

| 日期 | 决策 | 原因 | 影响 |
| --- | --- | --- | --- |
| 2026-05-10 | 采用“前端防连点 + 后端内存短 TTL 缓存 + 数据库唯一约束”三层方案 | 当前项目轻量单机优先，重复点击通常发生在短时间内；数据库唯一约束负责最终安全 | 不新增独立防重复提交表 |
| 2026-05-10 | 不做泛用防重复记录表 | 业务幂等应该由业务模型自己表达；强副作用业务用业务流水号、外部请求号、任务号或订单号等字段唯一约束兜底 | 后续实现只做管理端短 TTL 防重复缓存和业务唯一索引 |
| 2026-05-10 | 不对事实流水表按内容强唯一 | 使用记录、审计日志和运行日志可能存在真实重复事件 | 这类表只要求主键唯一，不按内容去重 |
| 2026-05-10 | 重复提交拦截不写第二条操作日志 | 操作日志表示真实业务变更，不表示重复 HTTP 请求 | 后端防重复服务应在进入业务写入前拦截 |
| 2026-05-10 | 后端采用 AOP-like 路由切面，不采用 TypeScript decorator | 当前项目是 Express Router 结构，元信息中间件更轻量；decorator 需要反射和 class controller 架构 | 首批实现使用 `mutationGuard(config)`，后续可演进 `defineMutationRoute()` |
| 2026-05-10 | 前端采用 Vue 指令 + 统一提交函数双层接入 | 单靠按钮指令会漏掉回车提交和弹窗 OK；单靠函数封装又不如按钮属性直观 | 显式按钮用 `v-submit-lock`，实际提交逻辑统一走 `useSubmitAction()` |

## 验收标准

- [ ] 创建类接口接入内存短 TTL 防重复缓存，重复提交不会创建多条业务数据。
- [ ] 同资源指纹正在处理时返回中文提示；不同资源指纹不被误拦截。
- [ ] 绕过缓存但命中业务唯一键时返回 `409`，由数据库约束兜底。
- [ ] 操作日志只记录真实成功变更，重复提交拦截不产生第二条日志。
- [ ] 每张表至少有主键或组合主键；实体表和关系表补齐业务唯一键或明确不适用原因。
- [ ] 后端首批写接口通过 AOP-like 路由切面声明接入，不散落手写缓存逻辑。
- [ ] 前端创建 / 提交弹窗统一 pending 状态防连点，显式按钮可通过 `v-submit-lock` 属性接入。
- [ ] 内存缓存有 TTL 和容量上限，不影响高频网关主链路性能。
- [ ] 必要文档、类型、接口契约和存储说明已同步。

## 风险与注意事项

- 第一版内存缓存不保存 API Key 明文、OAuth token 或完整响应，只保存安全摘要和状态。
- 外部调用类接口不能长事务包住网络请求，否则会放大 SQLite 写锁等待。
- 新增唯一索引不做运行时兼容；如本地旧数据重复，先离线清理旧数据，再用最新 schema 建索引。
- 公告、操作日志、使用记录等不能为了“每表业务唯一”强行按内容唯一，否则会误删或拦截真实事件。
- 网关侧 `Idempotency-Key` 是公开 API 透传语义，和后台管理端防重复缓存暂不混用。
