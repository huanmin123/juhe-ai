## 目标

将授权团队/用户用量从同步 overview 拆成 rows 与 summary：当前页 rows 有界补齐并优先展示，summary 按同一 scope/range/filter signature 独立读取；分页和移动端 load-more 不重复请求 summary，同时删除未调用的聚合 options loader并补齐权限、worker、PostgreSQL和前端竞态证据。

## 已确认的设计候选

- Rows：现有 `/usage/team-details` 与 `/usage/user-details` 返回 `range/rows/total/page/pageSize/hasMore`，不再返回 `summary/teamCount/userCount`。
- Summary：新增 `/usage/team-summary` 与 `/usage/user-summary`，admin/self 各一条，只返回 `range/summary`，不接受分页。
- DTO：团队行删除 `status/accountId/accountName`；用户行删除 `accountId/accountName/sourceLabels`，保留真实展示的 `teamNames` 以及列表/跳转需要的资源和 owner 字段。
- Signature：kind、admin/self、viewer、role、auth revision、有效 owner scope、实际日期范围、resource/team/grantee 筛选构成业务签名；page/pageSize 不进入 summary signature。
- 请求矩阵：首次/筛选变化 rows 与 summary 并行；桌面分页、pageSize 与 mobile load-more 只请求 rows；显式刷新可同时刷新两者。
- Lookup：只对 `takePageRows()` 后的 IDs 批量读取；PG 独立团队/用户/成员/资源 lookup 并行，owner 在资源结果后批量读取；无 N+1。
- Options：删除从未调用的聚合 loader，现有 dropdown/search/selected 补齐继续按需工作，首屏 options 请求保持 0。
- 安全：rows/summary 共用 access/range/filter normalization；管理保持 admin/owner scope，个人强制 self，迟到响应按签名与 generation 拒绝提交。

以上内容在用户明确确认前只作为设计草稿，不授权修改运行时代码。

## 测试项

- Parser/HTTP：team/user、admin/self、日期、资源、团队、用户、owner scope、分页参数和 summary 拒绝分页。
- DTO：rows/result 精确白名单、summary 仅 `range/summary`、空窗口零值、稳定排序和 `hasMore`。
- 权限：管理全局/owner、普通用户管理 403、个人 self、伪造 scope、rows/summary 口径一致。
- Query：只读范围窗口；rows 不读 summary，summary 不读 detail/lookup；当前页 IDs、固定批量、无 N+1。
- Worker：四类只读 operation、错误传播、空态、同步 SQLite 逐字段等价。
- PostgreSQL：实际并行 lookup、金额转换、teamNames、资源/owner、summary 精确键与真实权限 smoke；SKIP 不计通过。
- 前端：首屏并行且 rows 可先显示；分页/pageSize/load-more 不重取 summary；签名变化各发一次；独立失败/重试。
- 竞态：A→B、A→B→A、route/owner/range/admin-self/auth revision/卸载迟到不污染数据、loading 或错误。
- Options：首屏零请求、首次展开/搜索/selected 补齐；死 loader 源码与行为门禁。
- 回归：团队跳转用户明细、范围窗口刷新、分页上界、background worker 和 repository lookup cache 不退化。

## 验收标准

- team/user rows 与 summary 契约独立，rows 不等待 summary。
- rows DTO 只保留真实展示/跳转字段；summary 只读取精确预聚合窗口行。
- 同一 signature 的分页和 load-more 不重复请求 summary。
- 当前页 lookup 有界并行，无逐行查询；SQLite worker、真实 PostgreSQL和权限语义等价。
- 死 options loader 删除后，各筛选下拉仍保持按需加载。
- 关键前端竞态、失败重试、既有回归和文档全部有可复现证据。

## 风险与注意事项

- DTO 拆分是管理和个人接口的破坏性收窄，必须同步 Node/Vue/类型/测试，不保留双形态兜底。
- summary signature 不含分页；若把 page 混入 key，会重新引入每页重复请求。
- rows 返回的 `total` 是分页上界，不得改名或展示为精确团队/用户总数。
- 用户 `teamNames` 来自当前有效成员关系，不能为省 lookup 删除或由前端猜测。
- PG 并行只用于独立 lookup；resource owner 依赖资源结果，必须按依赖分阶段。
- summary 失败不能用零值伪装，rows 失败也不能清除已成功的当前 signature summary。
- 当前工作树包含大量既有改动，实施时禁止整理、回退或提交无关差异。
