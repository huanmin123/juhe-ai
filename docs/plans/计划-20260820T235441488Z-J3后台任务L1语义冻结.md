## 1. 目标与非目标

目标是为 J3 候选任务留下可审计 L1 语义、证据等级和后续门禁。候选分为 J3a 代理延迟检测、J3b 模型检测、J3c 质量检查；账号复制因缺少后台契约排除。

本计划不修改 Node/Go 代码、测试、配置、schema、部署，不启动服务，不读取 `.local`，不访问远端，不创建 jobs。

## 2. 已完成决策

- 路线图中的 J1/J2 状态改为“已生产 Go-owner”（该状态来自用户提供的生产事实，不由本地源码推断）；不修改 J1/J2 代码。
- J3a 推荐代理延迟检测：独立代理表、无需账户凭据、固定批次、单代理 PG lease、`config revision + observed time` CAS、直接目标 URL 和手动入口。
- J3b/J3c 保持高耦合后续项；质量检查拆分 `stats-worker account-quality-refresh`、`ops-worker failure-precheck`、模型检测本质的 scheduled/recovery/health-sync。
- 模型检测 handler 取消固定 25 秒总 deadline；专用 DB-service HTTP proxy 的可配置 `chatTimeoutMs` 默认 15 分钟（`backend/src/config/runtime.ts:606-609`、`backend/src/server.ts:78-84,264-265`），由 `upstream.setTimeout` 作为 socket idle timeout 使用，而非绝对总时限。10 秒 SSE heartbeat 可保持 socket 活动，但不承诺无限运行。
- 账号复制仅证明 `GET /accounts/:id/clone-context`、`account-interaction-context` 读取和 revision 二次检查；未找到后台复制校验，因此不设计 job。
- 保留架构硬约束：Go jobs 禁调 Node/gateway/IPC/Redis Stream/Node DB-service/gateway HTTP；SQLite 单 writer；PG 最小权限、冻结 schema、transaction/lock timeout；Node 仅输入发布和结果投影。
