## 需求目标

- 背景：管理员已经支持在用户模式和管理模式之间切换，但切换菜单、跨页面跳转或回到之前页面时，如果页面内容和左侧菜单不同步，或筛选、分页、排序等操作现场丢失，会降低长期使用效率。
- 目标：让“切换模式”和“跨页面返回”都保持清晰一致；用户从 A 页面筛选后切到 B 页面，再回到 A 页面时，优先恢复 A 页面的操作现场。
- 交付物：前端路由页面缓存、页面状态缓存设计、有明确查询状态页面的状态缓存接入、文档和验证记录。

## 方案概述

- 方案原则：页面现场用 Vue `KeepAlive`，长期操作习惯用项目自己的轻量状态缓存；两者分工明确，避免把所有状态塞到路由或全局状态里。
- 数据变化：不新增后端字段和数据库表；浏览器本地存储 key 按当前登录系统账户和路由区分，默认第一次进入使用页面初始状态。
- 接口变化：无。
- 前端变化：
  - `AppLayout` 的 `router-view` 改为可缓存结构，并给菜单路由设置稳定缓存 key。
  - 管理员模式切换时继续跳转到对应默认页，直接访问某路由时以路由 `viewScope` 同步当前模式。
  - 新增 `usePageStateCache` 一类 composable，页面显式声明要缓存的字段、默认值、读写和清理逻辑。
- 后端变化：无。
- 数据处理策略：本地缓存读取失败、字段无效或浏览器禁用 `localStorage` 时回落到页面默认状态；重置筛选时同步清理对应页面缓存。

## 状态缓存设计

### 1. 路由页面实例缓存

- 只缓存登录后的菜单页面，登录页不参与应用壳缓存。
- 缓存 key 使用路由路径，保证 `/my-accounts` 和 `/accounts` 即使复用同一个 Vue 文件，也会保留两份独立页面现场。
- 缓存只解决当前浏览器会话内的页面实例保留，例如输入框、当前分页、表格排序、抽屉打开状态和滚动位置。
- 由于缓存会保留组件实例，页面在重新激活时如果依赖登录用户或模式变化，必须以路由 `viewScope` 和接口返回为准，不允许用缓存绕过权限。

### 2. 页面查询状态缓存

- 缓存对象只允许包含可序列化的查询状态：
  - `filters`：关键字、状态、类型、系统账户筛选、分组筛选等。
  - `pagination`：当前页、页大小。
  - `sorts`：排序字段和排序方向。
- 不缓存：
  - 列表接口结果、统计结果和审计 payload。
  - 已选中行、批量操作选择、弹窗打开状态、编辑表单内容。
  - API Key 明文、上游密钥、OAuth token、代理账号密码、请求原文。
- 缓存 key 建议格式：`juhe-ai:page-state:<systemAccountId>:<routePath>`。
- 页面恢复缓存后再发起首次查询；无效字段要丢弃并回落默认值。
- `重置筛选` 必须同时清理页面缓存和内存状态。
- 管理模式中系统账户筛选变化时，依赖该系统账户的分组、账户等下级筛选必须按页面原有规则清空。

### 3. URL query 使用边界

- 普通列表筛选不默认写入 query，避免后台 URL 变长、变脏。
- 从其他页面跳转过来的明确动作可以继续使用 query；授权用量不再通过用量统计页 query 打开，统一从 `我的授权` / `统一授权管理` 进入。
- 当 query 与本地页面缓存同时存在时，显式 query 优先；页面可在处理完一次性动作后保留或清理 query，按具体页面语义决定。

## 风险与注意事项

- `KeepAlive` 会增加前端内存占用，应限制缓存范围或数量；如果后续页面很多，可按路由配置逐步精简。
- 页面状态恢复必须在首次请求前完成，否则会先请求默认条件再请求恢复条件，造成闪烁和多余请求。
- 管理页的系统账户筛选和用户页作用域必须分开缓存，避免管理员用户模式和管理模式串状态。
