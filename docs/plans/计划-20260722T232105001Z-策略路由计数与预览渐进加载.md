## 验收标准

- 基础列表先返回且不等待动态 count/preview。
- 每个当前页只有一个有界 snapshot HTTP，请求和后端查询次数不按行增长。
- 动态字段失败不阻塞基础列表，真实零值不与未知/失败混淆。
- 权限、详情、预览语义、写后刷新、SQLite worker、PG 与竞态证据闭合。

## 风险与注意事项

- 当前权威文档和 PLAN-0077 历史契约要求基础列表同步返回 counts/preview，确认实施后必须记录由 PLAN-0153 局部替代。
- snapshot 不能先查全量数据再由 JS 做 owner 过滤。
- 不得把缺失 snapshot 项当成 0；否则会同时造成误导和潜在存在性泄漏。
- 不增加缓存，避免 API Key、分组、授权和绑定写路径失效不完整。
- 当前工作树已有大量既有改动，禁止整理、回退或提交无关差异。
