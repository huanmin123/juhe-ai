## 已确认并实施的契约

- 路由：`GET /model-checks/account-options` 与 `GET /my-model-checks/account-options` 共用 Router 实现。
- purpose：`run` 面向目标/可信对比，要求当前可运行、授权 quota 可用和协议合格；`history` 面向历史筛选，不因当前 inactive 或 quota 耗尽丢失仍可见账户。
- DTO：严格 `id/name/providerCode/providerProtocolProfileId/protocolCode/protocolVersion` 六字段。
- 参数：keyword 小窗口、selectedIds 最多 20 个补齐、limit 默认/最大 50；补齐不绕过权限或 purpose 资格。
- 安全：不可见、不存在、撤销授权或不合格 ID 静默省略；POST run/stream 继续最终校验。
- 前端：首屏 0 个账户 options 请求；首次展开/搜索加载；精确 key singleflight；缓存按用户、角色、auth revision、admin/self、owner scope 和参数隔离；各消费者独立 generation。

上述契约已获本轮剩余 Node/Vue 按需加载实施授权并落地；options 仍不能替代运行入口最终校验。

## 测试项

- Parser：purpose、keyword、limit、selectedIds canonical/bracket、去重、数量/长度/形状边界。
- DTO/query：精确六字段、稳定排序、selected 补齐、无完整 Summary/credentials/runtime/N+1。
- 权限：管理全局/owner、个人 self、自有/授权、伪造 scope、不可见/不存在省略。
- 资格：run 的 active/schedulable/授权 quota/支持 profile；history 的可见历史账户与协议资格。
- 最终校验：选择后状态、quota、profile、模型或分组变化仍由 run/stream 拒绝。
- 存储：SQLite 同步/read worker 与真实 PostgreSQL 等价，PG SKIP 不计通过。

- 回归：模型检查运行、可信对比、协议 profile、历史列表/详情和通用账户 options 不退化。

## 验收标准

- 模型检查页面不再使用通用账户 options，专用响应和查询只含六字段。
- 首屏不新增账户 options 请求；run/history 用途和 selected 补齐行为有 HTTP 与前端证据。
- run 候选正确执行授权 quota 和协议资格过滤，history 保留仍可见的不可运行历史账户。
- 不可见省略和后端最终校验防止存在性泄漏及选择后状态变化绕过。
- SQLite worker、真实 PostgreSQL、前端 singleflight/身份缓存/竞态和既有回归全部通过。

## 风险与注意事项

- 不能为了复用通用 options 在 route 层最后裁剪；优化必须从 repository 投影开始。
- `selectedIds` 不能绕过资格，否则会把已撤销授权或协议不支持账户重新暴露到可执行候选。
- `history` 不能复用 `run` 的 active/quota 过滤，否则旧记录的账户筛选会随当前状态消失。
- singleflight 只合并完全相同的身份和参数 key；网络共享不能取消 target/comparison/history 各自的提交代次。
- options 只表示查询时候选，不能替代运行入口对权限、quota、模型、分组、凭据和真实候选的最终校验。
- 当前工作树包含大量既有改动，实施时禁止整理、回退或提交无关差异。
