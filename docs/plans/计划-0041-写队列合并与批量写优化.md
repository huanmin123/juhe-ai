## 需求目标

用户要求全局检查写数据库队列是否具备“同操作只保留最后一次”的机制，并在确认缺口后开始改造。经过全局只读检查，当前真正具备 last-write-wins 队列合并的路径只有 `record-maintenance` 中的 `account_usage_snapshot_upsert`；使用记录、审计日志、操作日志、运行日志索引等事实明细队列不应做最后覆盖，否则会丢失事件事实。

本计划目标是：

- 对状态 / 快照类写入补齐同 key 最新值合并，减少短时间重复写数据库。
- 对公开接口日志补齐批量事务写入和失败保留重试，避免队列批次退化成多次独立提交。
- 保持使用记录、审计日志、操作日志、运行日志索引等事实明细的 append-only 语义，不把事件明细错误改造成覆盖写。
- 明确 DB service 是数据库进程边界，不默认作为通用写合并层；高频写必须在具体写入入口按语义设计合并或聚合。

## 范围边界

### 本次包含

- [x] 梳理并记录本次目标、步骤、验收标准、影响范围和注意事项。
- [x] 公开接口日志 `public-api-logs` 增加批量 repository 写入，队列 flush 使用单事务批量插入，失败时保留批次等待重试。
- [x] 修正 `account_usage_snapshot_upsert` 队列合并 key 与数据库唯一键一致，按 `accountId + kind` 保留最后一次快照。
- [x] 在 server 到 worker 的 `background-ipc` pending queue 中，对 `account_usage_snapshot_upsert` 做同 key 合并，减少消息尚未到 worker 前的重复占用。
- [x] 对网关账号副作用队列增加安全 coalescing：成功回写取消同账号待执行失败副作用；同账号待执行 `apply_account_error_handling` 只保留最新项；不合并有计数语义的 `record_account_stream_failure`。
- [x] 补充或更新回归脚本，覆盖公开接口日志批量写、账号快照合并、IPC 合并和账号副作用队列合并。

### 本次不包含

- 不把 `usage_records`、审计日志、操作日志、运行日志索引改成 last-write-wins；这些是事实明细，必须保留每条事件。
- 不新增 Redis、Kafka 或跨进程持久队列；继续保持当前单机轻量部署边界。
- 不新增数据库迁移运行时代码；本次不计划变更表结构。
- 不把 DB service 改造成全局批量写调度器；后续如有更多高频状态写，按 operation type 单独设计。

## 风险与注意事项

- 队列合并必须按业务语义拆分：状态 / 快照类可覆盖，事实明细不可覆盖。
- `record_account_stream_failure` 不能合并，否则会降低连续失败计数，影响流式熔断触发。
- 公开接口日志批量写失败后保留队首批次，可能短时间阻塞后续日志落库；这是为了避免无声丢失，应通过延迟重试和队列上限控制风险。
- DB service pending request 仍不做全局合并；后续如果新高频写入直接走 DB service，需要在具体 operation 前增加批量队列或合并队列。
- 当前仓库已有用户未提交修改，执行时只修改本计划和本次相关代码，不回退无关文件。

## 完成总结

- 已新增 `createPublicApiLogsBatch` 并让公开接口日志队列按批次事务写入；失败时保留队首批次并延迟重试，避免日志静默丢失。
- 已将 `account_usage_snapshot_upsert` 的合并 key 对齐数据库唯一键 `accountId + kind`，并在 worker 本地队列与 server IPC pending queue 两层都做最后写入保留。
- 已让网关账号副作用队列对同账号 pending `apply_account_error_handling` 做替换，并在成功回写时取消同账号待执行失败状态覆盖写；`record_account_stream_failure` 继续保持同账号重复也逐条入队，且不会被成功回写取消，避免改变失败计数语义。
- 已补充公开接口日志、数据维护队列、网关账号副作用队列回归，并通过后端类型检查。
