## 需求目标

- AI 账户服务等级和思考级别选项按已选模型声明能力的合集展示，只要至少一个已选模型支持就允许选择。
- GPT API Key 与 GPT OAuth 使用相同模型能力判断，不再本地禁止 Flex。
- 支持该配置区的供应商始终显示服务等级和思考级别控件；当前没有可选能力时显示禁用态和中文原因，不再整体隐藏。
- 网关在最终上游模型和协议形态确定后逐字段判断；精确支持配置值时覆盖，不支持或能力未知时保留对应客户端原值。
- 不做运行时降级，不因一个覆盖项不适用而影响另一个覆盖项，也不把账户整体判为不可用。

## 范围边界

本次只处理以下请求体字段：

- 服务等级：`service_tier`。
- 思考级别：Responses 的 `reasoning.effort`、Chat Completions 的 `reasoning_effort`。

本次不处理：

- 任意请求头或任意请求体 patch。
- `OpenAI-Beta`、Responses Multi-agent Beta、Codex Ultra 或多代理编排。
- API Key、路由策略、分组、账号调度、OAuth 授权协议或计费规则重构。
- bridge 无法安全映射客户端已有受保护字段时的既有明确 `400`；该错误边界保持不变。
- 历史数据库兼容或运行时迁移分支。

## 稳定契约

### 保存与展示

- 已选模型中已知模型的能力数组按原顺序去重合并；未知模型不贡献能力，也不清空其他已知模型能力。
- 每个非空覆盖值必须至少由一个已选模型声明支持；只有未知模型或没有任何模型声明该值时拒绝保存。
- `service_tier_override=default` 在至少一个已选模型声明服务等级能力时可选；运行时只对声明服务等级能力的最终模型生效。
- GPT API Key 和 OAuth 都可保存模型目录声明的 `flex`。
- 已保存值在模型能力变化后不被前端静默清空；页面保留当前值并提示其不在当前能力合集内，用户可主动清除或改选。

### 运行时

- 服务等级和思考级别独立判断、独立应用。
- 最终模型精确支持配置值时写入对应 wire 字段。
- 最终模型不支持或目录能力未知时，不修改该客户端字段，不选择较低值，不返回账户覆盖错误。
- `default` 受支持时删除客户端 `service_tier`，让供应商使用默认档位。
- compact 请求继续不注入 reasoning 覆盖；客户端已有 reasoning 按原 compact 契约处理。

## 风险与注意事项

- 账户保存时允许合集值意味着同一账户的不同模型可能表现不同；页面必须明确“按最终模型支持情况生效”。
- 目录能力缺失时按“不覆盖”处理，避免错误注入；这不是对真实上游能力的推测。
- bridge 对客户端原字段无法安全映射的明确错误不属于账户覆盖跳过语义，不能顺手移除。
- 当前 `master` 和 `feature/20260706-go` 检出工作区都有用户未提交修改；集成前必须重新检查，不能 stash、清理、提交或覆盖这些修改。
- 生产发布只读取任务必需的密码文件，密码、私钥、token 和完整连接串不得进入命令输出、日志、提交或最终报告。
