## 方案概述

- 数据变化：`accounts.default_test_model` 改为必填 `accounts.health_check_model`；`provider_default_test_models` 改为 `provider_default_health_check_models`；删除 `accounts.health_check_enabled`。
- 默认机制：个人默认检查模型优先于管理员系统默认和协议档案内置默认，只用于新账户初始化；账户保存后以自己的检查模型为准。
- 人工测试：使用账户或草稿配置执行真实最小请求，只写测试任务、诊断结果、使用记录和审计，不写生产状态。
- 后台检查：激活、周期健康、运行态恢复、账号冷却恢复和 Key 恢复共享底层 probe executor，由各自策略层决定状态副作用。
- 前端：支持模型下方增加“检查模型”；新增 / 编辑测试固定使用检查模型；列表点击测试时按需读取供应商协议模型选项并允许本次自由选择；删除批量测试入口。
- 数据处理：不做运行时兼容；上线时按当前 schema 单独完成字段和数据同步。

## 冲突审计

当前实现和旧文档存在以下冲突，代码阶段必须一起处理：

1. `defaultTestModel` 同时承担人工偏好和后台探针模型，必须拆除。
2. 人工测试成功仍可能由前端写账户默认模型，必须删除保存队列和独立写接口。
3. 创建接口仍接受人工草稿测试任务作为直接激活凭证，必须改为后台激活检查。
4. 编辑凭据仍可能要求人工测试成功后才能保存，必须改为保存后后台复检。
5. 人工多 Key 测试仍有写 Key 运行态的历史设计，必须改为只返回诊断。
6. 后台探针共用通用模型解析器并存在多层回退，必须改为严格读取账户检查模型。
7. `health_check_enabled` 虽未开放前端开关，但仍能关闭周期检测，必须从 schema 和候选查询删除。
8. 人工测试会话当前存在用户级全局互斥，账户 A 运行时会阻止账户 B，必须改为会话与账户隔离。
9. 列表摘要缺少测试模型选项；不能把完整供应商目录重新塞回列表，必须新增按需 test-options。
10. 人工测试响应头仍可能更新 OAuth 额度快照，必须禁止诊断流量改变生产额度调度事实。
11. 历史恢复矩阵仍把“手动测试成功”作为 `temporary_unavailable / rate_limited / error` 恢复出口，必须删除。
12. 多供应商接入文档仍使用“默认测试模型”和“测试通过后激活”表述，必须统一改名并指向后台检查。
13. 批量测试牵涉共同模型、批次执行、会话恢复和取消治理，当前需求已删除该功能，相关前后端和测试代码必须一起移除。
14. 新增 / 编辑和列表测试的模型边界不同，不能继续共用一个下拉解析器：表单固定检查模型，列表读取供应商协议目录。

## 风险与注意事项

- 检查模型只能证明固定最小请求链路可用，不能代表全部支持模型都可用。
- 模型级错误必须和账户级故障分开，否则更换检查模型仍可能误伤整个账户。
- OAuth 人工测试如需刷新 token，只允许写回凭据，不允许更新生产健康和额度调度状态。
- 新账户后台激活和关键配置复检需要受控并发、退避和任务可观察性，避免保存后无提示地长期待检查。
- 发布异常处理：上线前必须准备同一 schema 下的回滚构建和离线数据处理方案，不能依赖运行时兼容旧字段。
