# AI 账户上游能力与客户端画像解耦 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让账户上游接口能力成为候选筛选和人工测试的单一事实来源，移除客户端画像对账户候选的硬门槛，并保证模型映射右侧始终受真实上游能力约束。

**Architecture:** 网关先解析模型映射得到真实上游协议，再按账户 endpoint mode 过滤；客户端画像只进入请求准备和返回策略。`test-options` 由后端读取完整账户能力，前端直接消费，不再依赖列表摘要或模型协议标签推导。

**Tech Stack:** Node.js、TypeScript、Express、Vue 3、Ant Design Vue、pnpm workspace。

## 验收标准

- 普通 OpenAI-compatible API Key 开启 Responses 后不再因 `openai_standard` 被 Codex 请求排除。
- 客户端画像仍驱动请求整理、错误和重试策略，但不创造未声明的上游能力。
- 人工测试只展示后端基于完整账户返回的上游请求形态。
- 启用模型映射的右侧协议族必须命中当前上游能力；停用映射允许保留。
- 页面不出现“可承接请求”，用户配置统一命名为“上游接口能力”。
- master 与 feature 远端均包含修复，生产统一验收通过。
