# PLAN-20260718T230201011Z 管理接口渐进加载与事件循环治理实施计划

> **给执行 Agent：** 使用 `superpowers:subagent-driven-development` 或 `superpowers:executing-plans`，逐任务实施、逐任务验证；所有动态字段和操作入口必须经过功能完整性审查。

**目标：** 在不删除、关闭或弱化任何页面、字段、动态状态、余额、用量和操作入口的前提下，让管理列表先返回可交互主数据，再异步补齐动态快照与选项，并建立能定位事件循环、DB queue 和接口分段耗时的观测链路。

**架构：** 列表请求只承担分页、筛选、排序和立即展示所需的稳定数据；运行态、并发、今日用量、最近使用和余额作为真实动态快照并行加载，成功后合并，失败时保留最近一次成功值。Provider / Proxy options 与列表并行，不作为首包前置条件；后端用 DTO、Server-Timing 和 DB service queue 指标拆分耗时。

**技术栈：** Vue 3、TypeScript、Ant Design Vue、Express、Node.js、PostgreSQL / SQLite、Redis、System API、DB service、pnpm。

## 现场依据

- `frontend/src/views/accounts/useAccountListData.ts` 当前 `fetchPage` 会等待 `loadAccountOptions`，provider options 的 10 到 15 秒长尾可阻塞账户主列表发起。
- 账户列表后端依次等待基础列表、运行并发、动态状态筛选和余额；DTO 装配还会读取多组授权、用量、模型和 API Key 信息。
- 列表完成后立即启动 status snapshot，成功和失败均约 10 秒继续请求；故障期没有指数退避。
- `account-status-snapshot.repository.ts` 一次请求包含主查询和 5 组 usage / authorization / API Key / quota 读取，再叠加 runtime 和 Redis concurrency。
- provider options 多轮平均约 `1.5s`，生产日志有 `10s` 到 `15s`；账户列表有 `3.99s` 到 `6.7s` 长尾。
- server event-loop P95 约 `2.68s`，db-service P95 约 `0.80s`，Nginx 转发时间基本等于 upstream time。

## 不删减功能的硬边界

- 不删除页面、菜单、筛选项、表格列、移动端卡片字段、余额、用量、动态状态、详情、编辑、测试、批量操作或刷新入口。
- 不关闭审计、统计、余额、运行态或使用记录能力来换取页面速度。
- 不把主列表字段永久移除；动态字段从同一响应阶段拆到快照后，最终行模型仍提供实施前全部字段。
- 不返回假空快照、假零并发、假零余额或假零用量。
- 首次无快照时显示中文“正在获取”或“暂不可用”；已有成功值时展示最后成功值和 `generatedAt`。
- 需要动态状态筛选时仍返回准确筛选结果；不能为了快速列表忽略筛选条件。
- options 失败只影响对应筛选 / 编辑辅助状态，不能清空已加载主列表。

## 数据契约分层

### AccountListBaseItemDto

- 身份：id、name、provider、type、status、tags。
- 静态调度：priority、concurrencyLimit、superPriority、fallback、schedulable。
- 关联摘要：group、proxy、授权来源和 owner 摘要。
- 权限与操作判定：permissions、disabledReason、可编辑 / 删除 / 测试标记。
- 时间和静态配置摘要。

### AccountStatusSnapshotItemDto

- runtime availability、current concurrency、today usage、最近使用时间、冷却和最近错误。
- `available`、`generatedAt`、`fieldUpdatedAt`、`staleReason`。
- 只能来自真实查询、预聚合或最后成功快照。

### AccountBalanceSnapshotItemDto

- 余额配置状态、最后成功余额、下一刷新时间、快照生成时间和可用性。
- 批量读取当前页已有快照，不触发真实上游余额刷新。

### AccountListRowViewModel

- 前端由 base item + 最后成功 status snapshot + 最后成功 balance snapshot 合成。
- 表格和移动端卡片继续获得全部功能字段。
- 未知值使用明确状态，不使用业务数值默认值。

## 验收标准

| 指标 | 目标 |
| --- | --- |
| 无动态筛选账户主列表 | P50 `<150ms`，P95 `<300ms`，P99 `<800ms` |
| 有动态筛选账户列表 | P95 `<500ms`，P99 `<1000ms` |
| 100 个账户状态快照 | P95 `<300ms`，P99 `<800ms` |
| 100 个账户余额快照 | P95 `<250ms`，P99 `<700ms` |
| Provider / Proxy options | P95 `<300ms`，且不计入列表可见时间 |
| 页面进入到主列表可交互 | P95 `<500ms` |
| 动态快照成功后完成合并 | 主列表后 P95 `<500ms` |
| DB service queue wait | P95 `<50ms`，持续超过 200ms 触发诊断 |
| db-service event-loop | P95 `<100ms`，单次超过 500ms 可关联慢请求或后台任务 |
