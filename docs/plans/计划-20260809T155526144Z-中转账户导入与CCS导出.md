# PLAN-20260809T155526144Z 中转账户导入与 CCS 导出

## 状态

- 状态：已完成（Node/Vue 已落地，Go 不在本次范围）。
- 范围：Node 后端与 Vue 前端；不改 `backend-go`。
- 目标页面：管理端与“我的 AI 账户”的导入弹窗，以及 API Key 列表的更多操作。

## 背景与目标

现有 AI 账户导入只接受 `juhe-ai-account-import v1`。本计划让导入弹窗可以直接选择来源：`原生`、`Sub2API`、`NewAPI`、`CPA / CLIProxyAPI`、`One-API`，并把可确认的外部账号归一化为原生导入文档后复用既有的权限、预览、去重、分组、代理和确认写入链路。

同时，在 API Key 的更多操作中增加“导出 CCS”。该操作只向 CC Switch 发起本地协议 deeplink，不新增密钥持久化、后端导出接口或用量探测脚本。

## 已核实的来源事实

| 来源 | 可用输入 | 导入对象 | 不作为账号导入来源 |
| --- | --- | --- | --- |
| Sub2API | `sub2api-data` / 兼容 `sub2api-bundle` JSON | accounts、proxies、原始 credentials | CRS 同步响应、渠道配置 |
| NewAPI | Channel 单对象、数组或列表 API 的 `data.items` JSON | 明文 `channel.key`、`base_url`、名称、单一 group | Token、兑换码文本、普通列表的掩码 key |
| One-API | Channel 单对象、数组或列表 API 的 `data.items` JSON | 明文 `channel.key`、`base_url`、名称、单一 group | Token、兑换码文本 |
| CPA / CLIProxyAPI | `config.yaml` / `config.yml`，或单个 `auth-files/*.json` 内容 | `codex-api-key`、`openai-compatibility`、`type: codex` OAuth 文件 | Vertex 服务账号、Gemini/Claude 文件、运行时状态 |

NewAPI 与 One-API 没有稳定的渠道批量导出协议；支持的是其管理员 reveal 或数据库导出的 Channel JSON 形态。两个项目的 `type` 数值已分叉，不能共用数字映射表。

## 导入契约

请求体新增 `sourceMode`：`native`、`sub2api`、`newapi`、`cpa`、`oneapi`；缺省是 `native`。`native` 保持现有严格的 `juhe-ai-account-import v1` 校验，不改变未知字段报错语义。

外部模式先由后端来源适配器产出原生导入文档，再进入既有 planner 和 executor。适配器返回以下来源摘要，随预览和确认结果返回：

| 字段 | 含义 |
| --- | --- |
| `mode` | 本次选择的来源模式 |
| `records` | 识别到的来源账号记录数 |
| `accepted` | 已转换为原生账户的记录数 |
| `skipped` | 因供应商、结构或关键凭据不成立而未转换的记录数 |
| `ignoredFields` | 已忽略的非关键来源字段总数 |
| `messages` | 不含密钥的来源级提示与跳过原因汇总 |

预览可以在部分来源记录跳过时继续导入其余有效账户；只有归一化后的原生账户或代理失败时才阻止确认。`active` 账户仍由既有逻辑落为 `pending_test`。

### 共同规则

- 外部非关键字段不写入 `credentials`，直接忽略并计数；包括统计、余额、运行时状态、内部 ID、未知 header、冷却、轮询和多 key 运行态。
- 缺少可用 API Key / OAuth token、无法确认目标协议、无效 Base URL、来源代理引用不可用等关键问题会跳过该来源记录，绝不臆造凭据或网络路径。
- 外部没有可安全映射的单一分组时，使用按目标供应商区分的来源默认分组，例如 `Sub2API 导入`；现有同名分组复用，允许时才自动创建。
- 模型列表、模型映射和来源数值 `type` 不在第一期直接写入目标账户；它们与本地供应商目录、协议档案和数值枚举不具备稳定等价关系，归入忽略计数。
- API Key 账户必须具有明确或安全默认的 Base URL。已确认的 OpenAI / Codex 默认使用 `https://api.openai.com/v1`；其余来源地址必须通过现有 SSRF 校验。

### 各来源映射

| 来源 | 接受条件 | 目标账户 | 关联资源 |
| --- | --- | --- | --- |
| Sub2API | `platform: openai` 且 `type: apikey` 或 `oauth` | API Key -> `openai/profile_openai_openai_v1`；OAuth -> `gpt/profile_gpt_openai_v1` | 通过 `proxy_key` 转原生 `proxyRef`，仅有效 HTTP/HTTPS/SOCKS 代理可创建 |
| NewAPI | Channel `type` 是该来源定义的 OpenAI，且有 key | `openai/profile_openai_openai_v1` API Key | 只接受 NewAPI 自己的数字 `1` 或明确的 `openai` 字符串；`group` 仅为单一名称时复用，否则来源默认分组 |
| One-API | Channel 有明确的 `openai` / `openai-compatible` 字符串和 key | `openai/profile_openai_openai_v1` API Key | One-API 数字 `type` 不猜测；规则同 NewAPI |
| CPA YAML | `codex-api-key` 或 `openai-compatibility[].api-key-entries[]` | `openai/profile_openai_openai_v1` API Key | 不自动把 `proxy-url`、headers、prefix、模型 alias 变为本地代理或凭据 |
| CPA auth-file | JSON `type: codex` 且有 `access_token` 或 `refresh_token` | `gpt/profile_gpt_openai_v1` OAuth | email、account ID、expires 等已知 OAuth 元数据可映射 |

## 前端交互

导入弹窗顶部增加固定宽度的来源下拉选择。切换来源后清空已预览结果，更新输入提示；`原生`保留模板、协议 Markdown 和 AI 提示词，外部模式不鼓励用户手工改写为原生格式。

预览摘要新增“来源跳过”和“已忽略字段”。来源提示使用 warning；原生校验错误继续使用 error。导入成功提示同时报告已创建、已跳过和来源跳过数。

账户列表工具栏使用“导出”和“导入”两个短文案，导出使用上传方向图标，导入使用下载方向图标。导出不再按当前页静默截断：未选择或全选当前列表时按当前筛选读取全部匹配账户，最多 500 条；筛选匹配超过 500 条时拒绝导出并提示筛选或分批次操作。部分选择按 ID 导出，同样受 500 条前后端双重限制。名称、账户类型、供应商和状态是浏览字段，不提供排序；旧页面缓存中的这些排序自动回落为优先级排序。

## CCS 导出

- 入口：API Key 行的“更多操作”增加“导出 CCS”。
- 读取：复用既有受权 `GET .../api-keys/:id/secret`，仅在用户确认后获取明文 key；不新增状态或下载文件，既有 secret reveal 审计仍保留（只记录脱敏前后缀，不记录完整密钥）。
- deeplink：`ccswitch://v1/import`，参数固定为 `resource=provider`、`app=codex`、`model=gpt-5.5`、`name`、`homepage`、`endpoint`、`apiKey`、`configFormat=json` 与 `enabled=true`。
- `endpoint` 与 `homepage` 使用当前页面已归一化的网关 base URL；不加入未经本项目稳定实现验证的 `/v1/usage` 脚本。
- deeplink 的 query 含明文 API Key。点击前显示明确确认；使用同页导航打开，未检测到处理程序时显示安装或配置 CCS 的错误。

## 验收

- 原生严格导入回归仍通过，未知 native 字段继续失败。
- 每个外部模式都有最小成功 fixture，并在隔离 SQLite 中经过实际导入服务的预览、确认和落库；Sub2API 覆盖 API Key、OAuth 和代理，CPA 覆盖 YAML 与 Codex auth-file。
- NewAPI / One-API 的非 OpenAI Channel 和空 key 均只出现在来源跳过摘要，不会被误导入。
- 外部未知字段不会进入存储凭据；缺少关键凭据不会创建账户。
- API Key “导出 CCS”只在用户动作后读取一次明文 key，生成的 URL 参数正确且不带 usage script。
- 完成后运行定向回归、前后端类型检查；由于项目规则未授权截图，不采集浏览器截图。

## 非目标

- 不导入来源系统的 Token / 兑换码、用户、路由、渠道运行态、余额或审计数据。
- 不支持 SQL dump、CSV、压缩包自动解包或外部路径读取。
- 不把 CPA 的 YAML 代理、headers、模型别名或服务账号隐式改写为本地资源。
- 不修改 `backend-go`，也不启用未经验证的 CCS usage script。
