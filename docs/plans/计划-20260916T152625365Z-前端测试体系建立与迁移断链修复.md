# 计划-20260916T152625365Z-前端测试体系建立与迁移断链修复

> 状态：已实施完成（2026-09-16）。本文记录任务范围、实施结果与验证证据，供后续审计与维护引用。

## 1. 背景与问题

Node→Go 迁移终局（commit `3f51156e0`，2026-09-05）删除了 frontend/package.json 全部 161 个 `test:*` 入口（原执行器 `pnpm --dir ../backend exec tsx` 依赖已归档的 Node backend），造成四类遗留问题：

1. **入口断链**：frontend 的 137 个回归脚本（约 1.8 万行）成为无入口孤儿；根 package.json 仍有 36 个 `pnpm --filter juhe-ai-frontend test:*` 引用全部断链；`test:runtime-display-contract` 的目标脚本文件本身也已删除（双重断链）。
2. **前端零测试基建**：无 vitest/jest、无单测、无覆盖率口径（happy-dom 只是 DOM 垫片依赖）；Node 归档区也无前端测试基建可借鉴。
3. **前后端打通无自动化**：前端 408 个端点模板与 Go gateway 路由注册面（337 处 `k.Register` + 5 处动态注册表 + J3b model-checks 独立面）无机器比对；`docs/migration/X04` 差异清单已过时。
4. **规范缺口**：`docs/develop/后端测试分层规则.md` 写死"前端不做自动化覆盖要求"；`测试与验证说明.md` 大量章节引用已失效命令。

## 2. 实施内容

### 2.1 迁移断链修复

- frontend 新增 devDependency `tsx`（4.23.13），167 个 test/smoke 入口从 git 历史（`3f51156e0~1:frontend/package.json`）机械转换恢复为本地形态 `tsx --tsconfig tsconfig.json <脚本>`；剔除目标已删除的 `test:runtime-display-contract`（根 package.json 死引用同步清理）。
- 批量运行暴露 18 个失败，定性四类并全部处置：
  - **7 个 `smoke:plan0081-real-go-*`**：缺 `JUHE_REAL_GO_MANAGEMENT_BASE_URL` 等环境变量快速失败，属真实后端 smoke 的设计行为，不修（需隔离 Go 实例 + 会话 Cookie 时手动执行）。
  - **3 个断言"入口必须已删除"过时**（w3/w4 smoke、account-edit-save-flow）：终局 commit 翻转的断言与恢复入口冲突，更新为"入口存在且为本地 tsx、不含 `../backend`"（保留不依赖 Node 后端的边界意图）。
  - **4 个归档契约源缺失**（ai-health-monitor、log-progressive-loading、stats-overview、system-metrics）：所读 Node 契约源（`account-health-monitor.repository.ts`、`sqlite-read-worker.ts`、`runtime-logs.routes.ts` 等）在归档区和 git 历史归档时点均已不存在（Node 时代后期已断）；断言对象迁到现役 Go 实现（statreads/logreads 源码），保持原契约意图。
  - **4 个逻辑漂移**（dynamic-data-cache-boundary、account-clone-demand-loading、plan0081-external-source-reset wrapper、frontend-build-info）：均为有提交佐证的有意变更（在途请求协调器重构、多 Key 余额查询契约演进、wrapper 的 tsx 路径失效、`docker/Dockerfile.builder` 随 go-only 收口删除），按当前语义更新断言，无真实回归。
- 2 个 IndexedDB 浏览器脚本（`test:chat-local-cache-indexeddb-browser*`）需真实 Chrome，保留入口、不纳入默认批跑。

### 2.2 前端单元测试与覆盖率体系（新建）

- vitest 3.2.7 + @vitest/coverage-v8@3（vitest 4/5 与项目锁定的 vite 5.4 不兼容，降版本线）+ 既有 happy-dom；`frontend/vitest.config.ts`：alias `@`、include `src/**/*.test.ts`、coverage 仅逻辑域七目录（api/shared/composables/lib/utils/config/directives）。
- 新增 71 个测试文件、828 个用例（co-located，显式 import，全 Mock：axios adapter 捕获、fetch stub、fake timers、stubEnv）。
- 覆盖率基线（2026-09-16）：逻辑域整体语句 98.81% / 分支 95.31% / 函数 99.14% / 行 98.81%；门槛写入 config（statements/lines/functions 95、branches 90）防回退。
- 附带修复：测试类型链引入 `@types/node` 后 `ReturnType<typeof window.setTimeout>` 声明与 `window.setTimeout` 值调用在声明合并下类型分裂，15 处定时器句柄声明显式改为 `number`（14 文件，纯类型层，`pnpm typecheck` 恢复全绿）。

### 2.3 前后端契约打通测试（新建）

- `frontend/scripts/contract/api-contract-check.ts`（入口 `test:api-contract`）：从源码静态提取前端调用面（axios + fetch SSE + J3b 流端点，排除 `*.test.ts`）与 Go 注册面（`k.Register` 家族 + prefix 拼接求值 + chat/aipublic/oidc/m11/statreads 动态注册表展开 + J3b `MountScoped` 面），断言前端 408 个端点模板全部命中（方法相等 + 模板参数段对齐）；Go 独有端点信息性输出（当前 36 条）；豁免走 `api-contract-allowlist.json`（当前为空）。负向验证（注入未注册端点必失败）已确认非假绿。

3. `测试与验证说明.md` 正文中几十条 `juhe-ai-backend` 命令的逐条清理未做（头部现状声明已消除误导），可在下次文档整理时收敛。
4. views/components 内联逻辑的覆盖维持 tsx 回归脚本模式；若未来页面交互自动化需求变更，需先修订前端测试分层规则第 1.3 条。
