# PLAN-0115 页面数据缓存与增量更新

> **已退场：** 本计划定义的通用页面缓存、confirm/revision、增量和 publisher 机制已由 [PLAN-0081](计划-0081-Node转Go渐进减法迁移.md) 的退场记录彻底删除。本文只保留历史过程。

- 创建时间：2026-07-16

## 需求目标

建立覆盖管理后台页面数据的统一缓存与增量更新能力：页面优先显示 IndexedDB 缓存，当前可见页面每 30 秒只访问轻量变更确认接口；无变化不请求完整业务接口，有变化时只获取变化字段、记录 cursor 或统计区块。通过 Redis / standalone 内存投影、最近 7 天用户预热和有界回填降低数据库压力并改善页面反馈。

长期稳定契约见 [页面数据缓存与增量更新设计](../functions/页面数据缓存与增量更新设计.md)。

2026-07-18 起的模型目录、人工测试、下拉与统计首屏第一批接入由 [PLAN-0139 双层持久缓存统一第一批](计划-0139-双层持久缓存统一第一批.md) 跟踪；本计划继续保留 P0-P3 的完整范围，不因第一批实施而缩小。

## 已确认决策

- 采用“版本向量 + 有界变更日志 + 字段投影 + IndexedDB”方案，不采用纯 TTL 或版本变化后总是整页重取。
- 当前 Node standalone / performance 两种模式使用同一 HTTP 契约，分别使用 memory / IPC 和 Redis。
- Node / Go 共存期共享协议；Go 长期只实现 PostgreSQL + Redis，不新增 standalone。
- 前端统一确认周期为 30 秒；页面隐藏时停止，恢复可见和聚焦时立即确认。
- IndexedDB 可直接保存 System API 已返回的有界数据，不做字段级敏感信息排除。
- 用户自己的写操作成功后立即更新当前页面并标记同域缓存 dirty；其他会话变化在 revision 发布后接受最多约 30 秒确认延迟，端到端还包含落库、队列 / 聚合和发布延迟。
- 最近 7 天登录用户预热首页和“我的 AI 账户”默认第一页。
- 已上线的 [PLAN-0104](计划-0104-账户动态快照与私网BaseURL白名单.md) 作为 AI 账户 30 秒快照基线，本计划先优化其后端读取，不重复建立轮询器。

## 范围边界

### 本次包含

- 统一 revision token、事件 schema、scope、field mask 和 confirm API。
- PostgreSQL outbox / Redis 发布链路及 Node standalone 内存 / IPC adapter。
- 服务端静态、运行态、追加记录和统计区块投影缓存。
- 前端 IndexedDB 缓存协调器、多标签 leader、30 秒确认和写后立即 patch。
- AI 账户、首页、使用记录、统计及后续全部页面的数据域登记和分阶段接入。
- 最近 7 天用户 P0 页面预热、singleflight、击穿保护、容量限制和观测指标。
- Node / Go 契约对齐、真实依赖验证和性能压测。

### 本次不包含

- WebSocket、SSE 广播、Kafka、ClickHouse 或重型前端全局状态框架。
- 前端实时聚合业务统计。
- Redis 故障时回源数据库承接全部页面确认流量。
- Go standalone / SQLite adapter。
- 旧 revision、旧事件 schema 或历史 IndexedDB 结构的运行时兼容；协议升级直接换 epoch / 版本并重建。

## 验收标准

- 所有实际路由和壳层读入口进入可机器检查 registry，并按 P0-P3 完成接入。
- 页面刷新和重新打开优先显示 IndexedDB 缓存。
- 当前可见页每 30 秒最多一次 confirm，多标签默认单 leader。
- confirm 在两种 Node 模式下均为 0 次业务数据库查询。
- 变化字段、追加记录和统计区块按需读取；不安全 patch 时正确重取当前页。
- Redis 故障不触发数据库回源风暴，standalone 重启不把旧缓存误判为最新。
- 最近 7 天用户的首页和“我的 AI 账户”默认入口完成有界预热。
- Node / Go 共享契约，Go 不新增 standalone 分支。
- 类型检查、构建、真实依赖 smoke、前端体验回归和性能压测达到功能设计目标。

## 风险与注意事项

- 这是跨全部页面和多个 writer 的基础设施项目，必须按 P0-P3 分阶段，不能用单个通用拦截器一次性包住所有接口。
- outbox、revision、事件裁剪和权限 scope 任何一个遗漏都可能造成长期陈旧缓存；日志不连续时必须 reset。
- 字段 patch 只适用于成员、筛选、排序和分页不受影响的情况；无法证明时重取当前页。
- Redis 故障不得回源数据库承接确认流量；页面保留旧缓存并等待恢复。
- PLAN-0104 已上线账户动态快照，本计划只收敛其投影读取和统一契约，不改变已验证的 30 秒前端行为。
