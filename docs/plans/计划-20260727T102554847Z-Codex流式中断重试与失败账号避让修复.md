## 问题

- 精确 Codex Responses 流在已经输出后发生上游读取中断时，网关虽然会补 `response.failed`，但使用 `upstream_stream_interrupted`，且最终化入口固定关闭了客户端重试码协调。
- 补发失败终态后才记录 turn 状态，客户端立即重试时可能先于状态写入，再次选中同一账号。
- 下游连接异常消失只记录为 `client_aborted`。这不能区分用户主动停止、客户端网络中断和代理断流，因此不能直接处罚账号；但同一 Codex turn 在同一账号上连续出现无终态断流时，现有实现也没有受控的临时避让。
- turn 状态的 Redis 更新使用读后整对象覆盖，并发失败会丢计数；旧阈值按整个 turn 累计，不适合弱证据。

## 不变边界

- 不在已经语义提交的同一 HTTP 响应中重新请求上游或拼接另一账号的输出。
- `session-id` 只用于现有会话亲和，不单独启用 Codex turn 避让；必须由合法 `x-codex-turn-metadata.turn_id` 精确识别。
- 主动停止、网络断开和代理断流仍统一属于客户端生命周期事实，不写账号状态、API Key 状态、账户电路、共享质量或全局冷却。
- 通用 OpenAI / Anthropic / Gemini 客户端的既有透明语义不改变。
- 状态写入、审计追加或 Redis 暂时不可用时 fail-open，不得遮蔽原始流式收尾。

## 验收标准

- Codex 输出后上游 idle/read incomplete/缺少终态时只产生一个 `response.failed/upstream_retryable_error`，立即结束流，不泄漏上游私有错误。
- 强证据在失败终态写出前可供同一 turn 的下一请求读取，并避开当前账号。
- 一次 client abort 不改顺序；同账号同 turn 在短窗口内两次合格 abort 后，第三次请求优先使用未激活账号。
- A、B 各一次弱断流不能互相凑阈值；重复 observation 不能重复计数；弱证据过期后失效。
- 无输出、仅心跳、终态后关闭、parser skipped、generic 客户端、缺少 turn_id 和网关主动关闭均不记录弱证据。
- 激活账号独占较高优先级时仍能切到本 turn 的备用账号；全部账号激活时恢复原顺序，不制造无账号。
- Memory / Redis 状态语义一致，并发写不丢账号集合、弱计数或强证据升级。
- 账户持久状态、电路、运行时抑制和共享质量保持不变。
