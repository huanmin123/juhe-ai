## 方案概述

- 方案原则：先做可测试的鉴权 demo，不把 IP 用量、公益榜和来源鉴权混在一个接口里。
- 数据变化：业务库新增 `external_integration_sources` 和 `external_integration_source_tokens`，token 只保存 hash、前缀、scope、状态和过期时间。
- 接口变化：新增 `/__aipublic__` 公开接口前缀下的 demo 路由；新增 `/__aisys__/api/external-integration-sources` 管理 API。
- 后端变化：新增来源鉴权中间件，业务接口通过 required scope 复用；内置测试 token 会进入 mock 标记上下文，不读取真实业务数据。
- 数据处理策略：鉴权按 `token_hash` 点查并通过 `source_ref_id` 关联来源系统；`last_used_at` 至少间隔 60 秒才刷新，避免高频调用导致每次写业务库；来源限频使用进程内固定窗口，只作用于 `/__aipublic__`，限频状态清理采用小批量扫描避免单次事件循环停顿过长。

## 风险与注意事项

- 风险 1：来源 token 创建后如果保存到前端包会泄漏。规避方式是文档明确 token 只放调用方后端配置。
- 风险 2：每次调用都更新 `last_used_at` 会放大写业务库。规避方式是低频刷新，同一来源 / token 至少间隔 60 秒才更新。
- 风险 3：调用方误传来源头并期望参与鉴权。规避方式是接口契约明确只认 `Authorization: Bearer <source_token>`。
- 发布异常处理：如上线后发现外部来源接口异常，可删除或不创建来源 token；demo 路由不会影响后台登录态 API 和网关 API。
