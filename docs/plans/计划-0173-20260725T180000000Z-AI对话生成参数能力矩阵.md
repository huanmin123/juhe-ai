# PLAN-0173：AI 对话生成参数能力矩阵

## 目标

一次完成 AI 对话的 `temperature`、`top_p`、频率惩罚、存在惩罚、最大输出 Tokens 与随机种子：按供应商、精确模型和本轮 Chat/Responses 协议保守判断，前端仅展示实际可发送的项，后端重新校验并以正确字段透传。

## 决策

- 能力键为「供应商 + 精确模型 + 请求协议」；模型版本与协议优先于供应商的通用能力。
- 跨候选模型目录以交集返回；详情和发送阶段都以 API Key 实际命中的账户、端点模式、模型映射和最终协议再次收敛。未知、兼容层静默忽略和任一路径不支持都不展示、不发送。
- OAuth 归一化和跨协议桥接只能保留其明确保真映射的参数；不能因为目录静态能力存在就向前端承诺可用。
- `temperature` 和 `top_p` 互斥；最大输出 Tokens 同时受模型能力和目录手工覆盖上限约束。
- 所有值都由服务端拒绝越界或不支持的输入；前端设置不是信任边界。
- 参数入口使用编辑器 `/参数`（兼容 `/parameters`）命令，不在输入框底部放置设置图标或悬浮小面板。命令会移除自身文本后打开独立弹窗，避免遮挡输入区，也让参数说明和范围有足够空间。
- 弹窗只渲染当前能力矩阵允许的项目。每项必须说明用途、启用/默认状态、当前值、可选范围和推荐值；参数开关保持关闭时不发送该字段并继续使用模型默认行为。设置在下一次发送时生效，关闭弹窗不重置已选值。

## 工作项

1. 建立供应商/模型/协议能力注册表并接入聊天模型能力响应。
2. 扩展流式请求契约、服务端校验和 Chat/Responses payload 构造。
3. 在 AIComposer 添加 `/参数` 命令触发的独立参数弹窗，随模型能力动态显示、切换模型时归一化，并解释每项参数的作用、范围和默认行为。
4. 补充命令和参数控件回归脚本、类型/构建验证与 AI 问答设计文档；页面联调由人工按需执行。

## 验收

- 不支持或未知参数不会出现在聊天设置，也不会进入网关请求。
- 支持的 Chat 与 Responses 参数使用各自正确 wire name。
- 服务端对绕过前端的参数仍能稳定返回能力错误。
- 输入 `/参数` 能打开可读的独立弹窗；弹窗没有底部设置图标入口，也不会展示当前模型不可用的参数。
