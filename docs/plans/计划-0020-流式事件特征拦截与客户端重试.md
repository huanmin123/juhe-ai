## 需求目标

- 背景：Codex 请求上游时出现 `Selected model is at capacity. Please try a different model.`。审计日志确认上游返回 `200 + text/event-stream`，但 SSE 内含 `server_is_overloaded` 或 `slow_down`。Codex 会把这些错误映射为不可重试的 `ServerOverloaded`，导致用户需要手动发送“继续”。
- 历史目标：在后端代码中维护确定性的流式事件特征规则表。第一阶段在未输出可见内容前命中已确认特征时，网关拦截原始上游失败事件，改写为 Codex 可自动重试的 `response.failed`，并立即结束 SSE；当时确认的容量类规则不改变账号状态。
- 历史交付物：长期功能文档、需求计划、系统默认规则模型与规则表、网关 SSE 拦截实现、移除系统设置配置入口、专项回归脚本和验证记录。

> 2026-05-17 更新：该计划记录的是早期专项方案。当前运行时已下线 `server_is_overloaded` / `slow_down` 流式错误码特征规则，改为“可见输出边界 + 客户端策略”处理：可见输出前只有命中 Codex profile 才改写为 Codex 可重试失败，非 Codex 不伪造可重试码；可见输出后统一进入流失败计数。流式规则类型、空规则接口和前端流式页签也已移除，历史规则模型只保留为调研背景，不再作为现行行为。
> 维护规则：不要从本文恢复流式错误码规则表或 `client_retry/server_replay/custom_rewrite` 动作模型。现行事实以 `docs/functions/流式中断与客户端重试调研.md`、`docs/functions/网关异常重试与兜底策略.md` 和 PLAN-0023 为准。

## 方案概述

- 方案原则：只有未输出前客户端自动重试可以改写 SSE；已输出后如果后续要自动继续，必须实现服务端重放，且重放不能改写 SSE。
- 数据变化：不再使用 `system_settings.streamInterceptRules`。已有本地库残留该 key 时，系统设置白名单会忽略它，运行时不读取。
- 接口变化：系统设置读写接口移除 `streamInterceptRules` 白名单字段。
- 前端变化：系统设置页移除“流式事件特征规则”配置区，只保留流式超时与熔断参数。
- 历史后端变化：当时网关流式转发新增 SSE 事件缓冲与解析，在写下游前匹配系统默认规则；命中已实现的 `client_retry` 时写入可重试的 `response.failed`，关闭上游和下游流。
- 当前数据处理策略：现行代码不再保留流式错误码规则表，也不提供运行时编辑入口；如要调整流式失败处理，应从可见输出边界和客户端策略分层进入。

## 风险与注意事项

- 客户端行为风险：本方案针对 Codex / OpenAI Responses 事件语义，不能直接推广到 Claude Code 或 Anthropic 原生协议。
- 审计解释风险：命中特征时客户端看到的是改写错误，排障时必须能追溯上游真实 `server_is_overloaded` / `slow_down`。
- 误伤账号风险：容量类错误默认不冷却账号；即使已输出后无法改写为客户端重试，也不能回落到通用流失败统计打账号。只有代码规则显式声明临时不可调用才写账号状态。
- 输出边界风险：`outputSeen` 判定必须保守，任何可见文本、工具参数、reasoning delta 或会改变客户端执行状态的 output item 写出后，都不能再伪造客户端重试错误。
- 后续重放风险：服务端重放会涉及响应 ID、turn state、工具调用副作用、重复输出、审计多次尝试和请求预算，必须另起阶段设计，不能夹在本阶段实现里。
- 发布异常处理：如上线后误拦截，应删除或禁用对应代码规则并发布修正版本；运行时不提供系统设置开关。
