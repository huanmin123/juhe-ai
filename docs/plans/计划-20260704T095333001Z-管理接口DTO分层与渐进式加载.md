## 需求目标

- 将管理端接口从“一个 Summary 到处用”改为“按场景返回刚好够用的数据”。
- 下拉接口只返回选择器需要的字段，通常是 `id`、`name`、`status` 和少量展示标签，不返回深层配置、成员、凭据、统计明细或大数组。
- 列表接口只返回表格和移动端卡片需要的字段，不承担编辑页、导出、测试、详情页的数据来源。
- 编辑页先加载基础字段；高级折叠区在用户展开时再请求高级配置，避免默认打开编辑弹窗就拉取大字段。
- 敏感信息、原始 payload、成员列表、策略绑定、规则数组、模型映射、测试结果和导出快照改为专用接口，避免混在列表和下拉里。
- 保留标准 HTTP 压缩作为网络层优化，但不自定义“服务端压缩字段、前端手动解压”的私有协议。

## 核心结论

1. **压缩不能替代接口瘦身**：`gzip` / `zstd` 可以减少网络字节，但浏览器仍要下载、解压、解析完整 JSON，前端响应式对象和表格仍要处理多余字段。当前问题的根因是接口契约过宽。
2. **不要做自定义前端解压协议**：自定义压缩字段会增加调试、缓存、错误处理和类型约束复杂度；内容在前端仍会被解开，不能解决安全问题。
3. **最佳方案是 DTO 分层 + 渐进式获取 + 标准 HTTP 压缩**：列表、下拉、详情、编辑高级区、敏感信息和任务快照各自定义 DTO，后端查询只读取对应字段。
4. **安全要靠敏感字段隔离和权限审计**：API Key、OAuth token、凭据、外部集成 token 等不能因为压缩而变安全，必须从列表和普通详情里移除，通过明确的 reveal / secret 接口按权限和操作日志读取。

## 现状问题

当前多个模块把 `Summary` 同时当作列表、详情、编辑、下拉、操作菜单和任务输入使用，导致接口天然膨胀。

| 场景 | 当前常见问题 | 直接影响 |
| --- | --- | --- |
| 下拉选择 | 使用 `Pick<Summary>` 或完整 definition，包含选择器用不到的配置和统计 | 首屏和弹窗加载慢，搜索下拉额外传输无用字段 |
| 列表 | 返回完整 summary，带 credentials、config、bindings、members、payload、usage 明细 | 20 行数据明显变大，JSON 解析和 Vue 响应式代理成本增加 |
| 编辑 | 打开编辑弹窗时一次性加载所有基础、高级、规则、映射、运行时字段 | 用户只改名称或状态时也要等待完整配置 |
| 操作 | 复制密钥、导出、测试、成员维护复用列表对象 | 敏感字段进入列表，或者为了操作把大字段塞进列表 |
| 日志/审计 | 列表携带 metadata、raw JSON、changes、request / response 摘要 | 日志页翻页和搜索成本升高 |

## DTO 分层规范

后续不再把 `XxxSummary` 作为所有读场景的默认返回类型。新增或改造接口时按以下命名和边界拆分：

| DTO 类型 | 用途 | 字段边界 |
| --- | --- | --- |
| `XxxOptionDto` | 下拉、选择器、远程搜索 | `id`、`name`、`status`，必要时增加 `type`、`providerCode`、`ownerName`、`disabledReason` |
| `XxxListItemDto` | 表格行、移动端列表卡片 | 页面可见列、筛选状态、操作按钮禁用原因、少量计数或摘要 |
| `XxxDetailBasicDto` | 打开详情或编辑弹窗的基础区 | 基础表单字段、展示标题、状态、权限、必要的关联 id/name |
| `XxxDetailAdvancedDto` | 高级折叠区 | 模型映射、策略规则、可用时间、代理、错误策略、响应检查等大配置 |
| `XxxRuntimeDto` | 运行态信息 | 健康检查、并发、冷却、最近错误、探测结果 |
| `XxxUsageDto` | 用量和趋势 | 来自预聚合或窗口表的用量摘要，禁止请求链路扫描明细 |
| `XxxSecretDto` | 密钥、token、凭据 reveal | 单独鉴权、单独日志、禁止进入列表和普通详情 |
| `XxxTaskSnapshotDto` | 导出、测试、导入校验等任务 | 任务所需完整快照，由任务接口内部读取，不给列表复用 |

接口路径建议：

| 场景 | 路径建议 | 说明 |
| --- | --- | --- |
| 列表 | `GET /xxx` | 返回 `XxxListResult<XxxListItemDto>` |
| 下拉 | `GET /xxx/options` | 返回 `XxxOptionDto[]`，默认限制数量，支持 keyword 和 selectedIds 补齐 |
| 基础详情 | `GET /xxx/:id` 或 `GET /xxx/:id/basic` | 只返回基础详情；若保留 `/:id`，语义调整为基础详情 |
| 高级详情 | `GET /xxx/:id/advanced` 或按领域拆为 `/model-mappings`、`/policies` | 只在折叠区展开时请求 |
| 敏感信息 | `GET /xxx/:id/secret` 或 `POST /xxx/:id/reveal` | 需要权限、操作日志和 no-store 响应头 |
| 任务 | `POST /xxx/:id/test`、`GET /xxx/export` | 任务自己读取完整快照，不要求列表携带 |

## 优先级矩阵

| 优先级 | 模块 / 接口 | 当前问题 | 目标契约 |
| --- | --- | --- | --- |
| P0 | AI 账户 `GET /accounts` | 返回 `AccountSummary`，字段横跨列表、编辑、凭据、模型映射、授权、运行态 | 改为 `AccountListItemDto`，只保留列表列、状态标签、操作禁用原因和必要计数 |
| P0 | AI 账户 `GET /accounts/options` | `AccountOptionSummary` 仍来自 summary，PostgreSQL 分支存在先查完整列表再 map 的风险 | 改为独立轻量 SELECT，只返回选择器字段 |
| P0 | AI 账户 `GET /accounts/:id` | 编辑一次性拿基础、高级、规则、映射、凭据运行态 | 基础详情和高级详情拆分，展开高级区再请求 |
| P0 | API Key `GET /api-keys` | 列表类型含 `key`，复制逻辑可从列表对象取完整密钥 | 列表只返回 `keyPrefix` / `keySuffix` / 掩码；复制完整密钥走 `/:id/secret` |
| P0 | 策略路由 `GET /route-strategies` | 列表携带 `groupBindings` 和 `hybridRoutingConfig`，编辑复用列表对象 | 列表返回绑定数量、前 3 个分组名摘要、模式、状态和 API Key 数；编辑先拉详情 |
| P0 | 分组 / 账户 / 策略等 options | 下拉普遍复用 summary 或带过多权限、调度、成员字段 | 统一 `XxxOptionDto`，选择器只收选择器字段 |
| P1 | 分组 `GET /groups` | 列表带 `accountIds`、`accountStats`、`authorizationSources` | 列表保留账号数量、可用数量、状态摘要；账号 id 列表改详情或绑定接口 |
| P1 | 分组 `GET /groups/account-options` | 选项里带 `accountIds`，用于账号编辑判断，数据随分组账号数膨胀 | 改为 `groupId/name/status/accountCount`，账号绑定关系按账号或分组单独读取 |
| P1 | 系统团队 `GET /system-teams` / `/my-teams` | 列表返回 members 数组 | 列表返回 `memberCount` 和 owner 摘要；成员维护弹窗再请求 members |
| P1 | 外部集成源列表 | `ExternalIntegrationSourceSummary.tokens` 数组可能随 token 数增长 | 列表返回 tokenCount、activeTokenCount、recentTokenPreview；token 明细单独接口 |
| P1 | 日志、审计、运行记录列表 | 列表可能携带 rawJson、metadata、changes、queryString、payload 摘要 | 列表只给时间、状态、动作、对象、耗时、错误摘要；完整 payload 走详情 |
| P1 | 模型检查历史 | 列表含 requestSummary / resultSummary | 列表只给模型、账号、状态、耗时、时间、错误摘要；完整请求和结果走详情 |
| P2 | 公告列表 | 当前 content 已截断，但字段名仍易混淆 | 列表改 `contentPreview`，完整正文只在详情和编辑中返回 |
| P2 | Provider options | `providers/options` 返回完整 `ProviderDefinition` | 新增轻量 provider option，完整 definition 留给供应商详情和账号创建表单 |
| P2 | 代理列表 | 列表包含连接和测试详情 | 列表只保留名称、类型、状态、最近延迟摘要；完整连接配置和测试历史单独读取 |

## AI 账户专项设计

AI 账户是本次治理第一优先级。当前 `AccountSummary` 在前后端都承担过多职责，字段包含基础信息、凭据、模型能力、模型映射、授权、运行状态、用量、分组、代理、错误策略和响应检查规则。后续应拆成以下契约。

### `AccountListItemDto`

只服务 `frontend/src/views/accounts/AccountList.vue`、`AccountsView.vue` 和移动端卡片：

- 身份和展示：`id`、`name`、`providerCode`、`providerName`、`type`、`status`、`tags`。
- 列表状态：`effectiveAvailability`、`runtimeAvailability`、`schedulable`、`statusReason`、`cooldownUntil`。
- 调度摘要：`priority`、`superPriorityEnabled`、`fallbackEnabled`、`currentConcurrency`、`concurrencyLimit`。
- 关联摘要：`boundGroupId`、`boundGroupName`、`proxyProfileId`、`proxyProfileName`、`proxyUnavailable`。
- 用量摘要：`todayUsage`、`oauthUsage` 必要摘要；不得实时扫描明细表。
- 权限摘要：`accessType`、`permissions`、`ownerSystemAccountName`、`authorizationStatus`、`authorizationExpiresAt`、`authorizationQuotaExceeded`。
- 时间摘要：`createdAt`、`updatedAt`、`accountExpiresAt`、`availabilityScheduleSummary`。

不得返回：

- `credentials`、`apiKey`、`access_token`、`refresh_token`、密钥明文。
- `modelMappings` 完整数组。
- `supportedModels` 完整大数组，列表最多返回计数或少量 preview。
- `error_handling_rules`、`response_inspection_rules`。
- 完整 `authorizationSources`、完整 API Key 绑定、完整运行时测试结果。

### `AccountDetailBasicDto`

打开编辑弹窗先请求基础详情，满足用户最常见的修改：

- 基本字段：名称、供应商、账号类型、状态、备注、标签。
- 基础连接：Base URL、协议配置、API Key 是否已配置、OAuth 授权状态、凭据存在状态和过期状态。
- 基础调度：分组 id/name、优先级、并发限制、启停状态。
- 基础能力：协议 profile、客户端兼容信息、模型能力摘要或受限模型列表。
- 权限信息：当前用户可编辑范围、只读原因、授权来源摘要。

敏感字段只返回“是否存在、是否过期、掩码后缀、需要重授权”等状态，不返回 token 或密钥明文。

### `AccountDetailAdvancedDto`

高级折叠区展开时再请求：

- 模型映射 `modelMappings`。
- endpoint modes、协议桥接配置和混合供应商高级配置。
- 代理配置、账号过期时间、可用时间计划。
- 错误处理规则 `error_handling_rules`。
- 响应检查规则 `response_inspection_rules`。
- API Key 池、权重、策略关联等高级调度配置。

如果高级区继续变大，第二阶段再拆成更细的 section：

- `GET /accounts/:id/model-mappings`
- `GET /accounts/:id/policies`
- `GET /accounts/:id/availability`
- `GET /accounts/:id/runtime`

### 保存规则

- 编辑表单必须记录 `basicLoaded`、`advancedLoaded` 和各 section 的 dirty 状态。
- 保存基础信息时，不得因为高级区未加载而把 `modelMappings`、规则数组、可用时间、代理配置清空。
- 保存高级区时，只提交已加载且用户改动过的高级 section。
- 当前 `accountSavePayload.ts` 已有部分 `hasOwnProperty` 保护思路，后续应扩展到所有高级字段。

### 任务接口

- 测试账号、测试草稿、导出账号、导入校验继续使用专用快照，不从列表 DTO 取完整数据。
- 导出接口内部可以读取完整凭据、模型映射、规则和计划，但响应对象属于导出协议，不影响列表契约。
- 测试结果中的完整 JSON 只在测试弹窗折叠区展示，不进入账号列表。

## 前端改造策略

- 在 `frontend/src/types/domain/*` 中新增 `XxxOptionDto`、`XxxListItemDto`、`XxxDetailBasicDto`、`XxxDetailAdvancedDto`，停止让页面直接依赖宽 `Summary`。
- 在 `frontend/src/api/*` 或 scoped API 中按场景暴露方法：`list`、`options`、`detail`、`advanced`、`secret`、`task`。
- 列表页只绑定 `XxxListItemDto`，操作按钮需要的禁用原因由列表 DTO 明确返回，不允许临时读取详情字段。
- 编辑弹窗打开时先请求基础详情；高级折叠区首次展开时请求高级详情，并显示独立 loading / error 状态。
- 下拉组件默认远程加载，默认最大 50 条；编辑已有选中值时通过 `selectedIds` 补齐 label，不为了 label 拉全量 options。
- 移动端卡片和 PC 表格使用同一个列表 DTO，避免移动端因为隐藏列而下载完整详情。
- 复制密钥、查看 token、成员管理、日志 payload 查看等动作走专用接口，并在 UI 上保持中文提示和错误态。

## 后端与存储改造策略

- 在 `backend/src/domain/types.ts` 或更细的模块类型文件中新增场景 DTO，不再用 `Pick<Summary>` 伪装轻量对象。
- routes 层按接口场景调用明确的 repository 方法，例如 `listAccountListItemsPageAsync`、`listAccountOptionsAsync`、`findAccountDetailBasicAsync`、`findAccountDetailAdvancedAsync`。
- repository 层必须按 DTO 字段写 SELECT，不允许先查完整 summary 再 map 掉字段，尤其是 PostgreSQL 分支。
- 下拉 options 独立查询，支持 keyword、limit、selectedIds 补齐和访问范围过滤。
- 列表中的计数、最近状态和统计摘要来自已有缓存、窗口表或轻量聚合结果；不得为了新列表字段扫描明细表。
- 详情和高级详情可以读取大 JSON 字段，但只在用户进入该场景时读取。
- secret / reveal 接口必须带权限校验、操作日志和 `Cache-Control: no-store`，响应体不进入通用列表缓存。
- 修改契约时同步更新前后端类型、接口测试和文档；不为旧宽字段保留运行时兼容分支。

## 响应大小目标

这些目标用于后续实现时验收，不能通过返回假空值或省略页面必需字段达标：

| 场景 | 初始目标 |
| --- | --- |
| 下拉 options 20 条 | 未压缩 JSON 尽量控制在 1KB 左右 |
| AI 账户列表 20 行 | 从当前接近 6KB 降到 2KB 到 3KB 区间；标准压缩后网络字节进一步接近 1KB |
| 普通管理列表 20 行 | 移除深层数组和大 JSON 后，至少减少 40% 未压缩体积 |
| 编辑基础详情 | 不超过当前完整详情的 40% 到 60%，高级字段不默认返回 |
| 高级详情 | 仅在展开时请求，体积单独计量，不计入列表和基础编辑首包 |

## 风险与注意事项

- 列表字段不能删到影响操作判断。AI 账户列表仍需保留 `effectiveAvailability`、授权状态、冷却状态、并发状态、权限和操作禁用原因。
- 编辑懒加载最大的风险是未加载高级字段被提交为空，需要在表单模型和 payload builder 中显式区分“未加载”和“已清空”。
- options 不能因为轻量化丢失已选项 label，需要 `selectedIds` 补齐。
- 敏感字段拆出去后，要同步检查操作日志、权限和缓存头，避免 secret 被浏览器或代理缓存。
- 统计摘要字段不能在列表请求里实时扫描明细，必须使用已有预聚合、缓存或后台 worker 产物。
- 旧前端和旧接口不作为兼容目标，改造时应一次性更新前后端契约和测试。
- PostgreSQL account options 在 `status=active/rate_limited` 或 `schedulable=enabled/disabled` 这类需要授权额度语义的查询下，当前先回退到完整列表路径保证正确性；后续需要补 PG 版轻量 quota SQL 后再完全移除该回退。
