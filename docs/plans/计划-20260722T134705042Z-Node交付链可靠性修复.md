- 范围：Node 后端与 Vue 前端；不包含 Go 迁移实现。
- 关联问题：[BUG-0119](../bug/问题-0119-Node页面数据删除残留与网关可靠性回归.md)

## 目标

1. 完整移除已退役 page-data 确认机制的残留调用、脚本和文档，使构建恢复。
2. 收紧 generic 网关失败处理：禁止不可证明幂等请求跨账号重放，opaque 失败不触发账户状态副作用。
3. 让完成请求的 usage 事实不因内存队列水位而丢弃，并收紧 Redis 断线与 API Key 失效边界。
4. 修复前端资源恢复的路径级防循环状态，并完成本地启动、HTTP 与浏览器验证。

## 实施顺序

1. 清理 page-data 残留并替换为现有直接请求路径。
2. 修复网关失败、usage 收尾与 Redis 客户端边界，补回归。
3. 修复前端路由资源恢复的多路径状态。
4. 更新验证入口，运行类型检查、构建、定向回归和本地 HTTP / 浏览器烟测。

## 完成标准

- 不存在对退役 page-data 模块的生产或回归导入。
- 不可证明幂等的上游失败不会跨账号重放，opaque 失败不改变账户运行态。
- 用量事实具备有界但不丢失的收尾路径。
- 本地 Node 服务和前端可启动并访问。

## 验证记录

- `pnpm typecheck`、`pnpm build` 通过。
- 网关失败、Redis queue fence、会话亲和和前端资源恢复的定向回归通过。
- 独立本地实例以 Node `3001` 和 Vite `5174` 启动；后端 health、前端页面及前端 API 代理均返回 200。
