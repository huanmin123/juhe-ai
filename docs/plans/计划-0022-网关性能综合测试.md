## 需求目标

- 背景：需要通过模拟测试评估项目可支持的 QPS、延迟、错误率、资源占用等性能指标，形成可重复执行的本地压测入口。
- 目标：新增不消耗真实 OpenAI 额度、不污染本地业务库的性能综合测试脚本，覆盖 OpenAI 兼容网关主要请求路径。
- 交付物：性能测试脚本、`pnpm test:perf` 命令、验证文档、执行结果记录。

## 范围边界

### 本次包含

- [x] 使用临时 SQLite 业务库、数据集目录库、usage shard 目录和统计结果库，避免影响 `backend/data/`。
- [x] 启动本机模拟 OpenAI 上游，支持 `/v1/models`、`/v1/responses`、`/v1/chat/completions` 和流式 responses。

- [x] 输出 QPS、成功 QPS、错误率、延迟分位、事件循环延迟、CPU、内存、使用记录和审计日志增量。

### 本次不包含

- 真实 OpenAI 上游压测：避免消耗真实额度，也避免把网络和上游限流混入本机网关容量判断。
- 生产多进程拓扑压测：脚本以本机临时库直接运行网关模块，不启动独立 DB service / worker 子进程；生产容量需在部署实例上补测。
- 前端页面性能测试：本计划聚焦后端 OpenAI 兼容网关。

## 方案概述

- 方案原则：压测走真实网关 HTTP 路由，但上游和数据库都用临时资源，保证可重复、安全、低成本。
- 数据变化：无生产 schema 变更；脚本运行时创建临时 SQLite 文件，结束后删除。
- 接口变化：无新增业务接口。
- 后端变化：新增 `backend/src/scripts/performance/gateway-performance-test.ts`，并增加 `pnpm test:perf` 命令。
- 数据处理策略：测试产生的使用记录写入临时 usage shard，审计日志写入临时数据集目录库；脚本输出聚合指标和可选 JSON 报告。

## 风险与注意事项

- 本机模拟结果受 CPU、磁盘、Node 版本、SQLite WAL 状态和开发机负载影响，不能直接等同生产容量。
- 默认脚本压测的是本进程临时网关，覆盖网关主要逻辑，但不覆盖主进程、DB service、worker 三进程间 IPC 的真实部署开销。
- 上游响应越慢，测试结果越接近“并发等待能力”；上游响应越快，结果越接近“本机网关和 SQLite 写入能力”。
- 发布异常处理：如脚本影响开发体验，可先移除 package 命令；脚本不改运行时代码和生产 schema。
