# PLAN-0134 余额失败持续调度与人工刷新

## 基本信息

- 编号：PLAN-0134
- 状态：实现完成 / 本地验证通过 / 禁止上线
- 创建时间：2026-07-18
- 需求来源：生产 `bigmodel` 余额查询失败后永久停止，非正常状态无法人工刷新
- 关联模块：AI 账户、余额查询、后台 worker、运行态、账户列表

## 生产证据

- `bigmodel` 的业务状态为 `active`，`schedulable=true`，有效可用性为 `available`。
- 余额快照为 `unsupported`，原因是当前内置接口未匹配。
- `balanceQueryEnabled=true`，但 `balanceQueryNextRefreshAt=null`，因此账户永久退出 due 候选；worker 本身仍在运行。

## 目标与边界

- 余额查询的成功、超时、上游宕机、鉴权失败、结构不匹配或 `unsupported` 都必须保留用户配置的后续周期。
- 自动查询只执行数据库活动可调度且运行态可调用的物理单 Key 账户；运行态阻断只延后，不推进到期时间。
- 自有物理账户只要余额功能开启，就允许人工刷新，不受账户状态和运行态限制。
- 授权实例继续禁止刷新来源账户余额；余额结果永远不改变账户状态或调度状态。
- 不新增字段，不执行生产数据修改，不在本次上线。

## 验收标准

- `bigmodel` 同类历史记录在发布后由 recovery 扫描重新获得下一次计划。
- 单次或连续余额失败不再产生新的 `balance_query_next_refresh_at=NULL`。
- 运行态短暂避让、待探针、半开和探针失败期间不自动请求余额，恢复后无需人工修改配置即可补查。
- 非 active 自有账户可以人工刷新；授权实例仍不能刷新。
