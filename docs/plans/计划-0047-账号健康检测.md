# PLAN-0047 账号健康检测

## 基本信息

- 编号：PLAN-0047
- 状态：已完成
- 创建时间：2026-06-17
- 需求来源：用户提出“正常账户每隔固定 12 小时探测一次，避免列表里长期显示正常但实际不可用的死号”

## 需求目标

为正常且可调度的 AI 账户增加后台周期健康检测。默认 12 小时检测一次，但优先使用真实成功流量作为健康信号，避免无意义全量探测；检测结果在后端持久化并在前端账户列表可见。

## 范围边界

本次做：

- 增加账号健康检测功能文档。
- 增加 `accounts` 健康检测字段、类型和 DTO 映射。
- 在 `probe-worker` 内增加到期账号探测任务。
- 探测复用现有账号测试 / 网关诊断链路。
- 前端账户状态 tooltip 展示健康检测摘要。
- 增加必要回归脚本或针对 repository / worker 的验证。

本次不做：

- 不新增新的账户物理状态枚举。
- 不新增外部队列、Redis、分布式 lease 或多实例协调。
- 不给旧 schema 写运行时兼容迁移。
- 不新增单独“健康检测”按钮；继续复用现有“测试”入口。

## 验收标准

- 正常账户超过检测间隔且没有近期成功信号时，会被 `probe-worker` 分批探测。
- 探测成功 / 失败均持久化健康检测事实。
- 连续失败不会立即误杀账号，达到阈值后才进入现有临时不可调用 / 冷却复测链路。
- 账户列表能看到后台检测时间、下次检测、失败次数和失败原因。
- 后端和前端类型检查通过，必要回归通过或说明未覆盖原因。

## 风险与注意事项

- 探测会产生真实上游请求，必须限制批量和频率。
- OAuth 和代理失败需要保留真实错误摘要，便于排障。
- 真实业务成功信号应尽量减少后台探测量。
- 健康检测字段是当前 schema 的一部分，不在运行时代码里兼容旧字段缺失。
