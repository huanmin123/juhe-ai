# 计划-0100 模型目录完整性与视图一致性

状态：已上线（生产自动门禁通过，登录后角色页面保留人工抽查）

## 目标

让管理员与普通用户看到相同的完整模型事实，并修复生产 Go/Node/前端链路中的真实字段丢失。权限差异只体现在允许执行的操作，不体现在隐藏模型能力、价格事实或返回不同字段。

## 语义基线

- 配置模板不是独立模板实体，而是直接选择当前可见的另一模型作为配置来源；选择后把该模型的用途、协议、服务等级、思考级别、上下限和可信价格带入当前新增表单，普通用户和管理员都保留该能力。
- 普通用户可维护自己个人自定义模型的价格；服务端仍按所有者和作用域校验，不允许修改他人或全局模型。
- 管理员进入“我的模型”时按普通用户视图执行；只有管理端模型目录允许价格维护和目标用户切换。
- 内置模型只允许管理员维护，可编辑列表已展示的状态、能力、上限和完整计费配置；全局/个人/内置来源必须明确显示。
- 空值必须区分：`仅标准`、`不支持`、`官方未公布`，禁止为了视觉完整臆造厂商能力或上下限。

## 已确认缺口

- 生产 Go 管理目录把内置模型 `id` 返回为空，前端无法生成编辑价格操作。
- `defaultReasoningEffort` 在 Node/Go 创建、模板复制或普通 PATCH 时被主动清空，和存储/响应/文档冲突。
- 档位价格表单缺 `cacheWrite1hUsdPer1M`，目录不展示 service tier 价格；移动端还缺标准 cache write。
- 内置模型编辑错误显示为个人模型；管理员“我的模型”仍显示价格输入。
- 新供应商没有现成枚举时无法录入首个用途、服务等级或思考级别。
- Node 内置目录查询未按 `status` 和 `shutdown_date` 过滤；SQLite seed 使用 `INSERT OR IGNORE`，已有库不会同步事实。
- 生成器真实 `--check` 未统一 CRLF/LF；feature 存在重复 Goose 49/50，不能整分支合并。

## 数据与契约设计

- 从生产 master 精选/重做 feature 中已验证的内置 ID、模板可见合并和 hybrid source 修复，不合并其他迁移提交。
- 打通 `defaultReasoningEffort` Node schema、Go decoder/service/store、模板复制、无关 PATCH 保留、前端表单和目录展示。
- 模型用途按供应商能力和当前目录事实提供合法下拉项；GPT 提供已确认的服务等级和思考级别候选，其他供应商只合并自身目录事实，不开放任意 tags 输入且不把 GPT 值注入其他供应商。
- 目录桌面/移动端统一展示：协议、状态、来源、上下文、最大输入/输出、支持及默认思考、服务等级、标准价格、每个档位输入/输出/cache read/cache write/cache write 1h。
- `supportsPromptCaching=false` 时价格显示“不支持”；支持但厂商未给价格显示“官方未公布”；空 service tiers 显示“仅标准”；未知上限显示“官方未公布”。
- Go 与 Node 对 built-in/global/self personal/other personal 的列表字段和权限做同一 fixture 等价测试。
- 缓存失效失败不得静默：业务已提交时继续返回主写成功，结构化记录“已保存但缓存同步失败”和 traceId；不得用 503 误报主写失败并诱导重复提交。

## 供应商数据规则

- GPT：核对 service tier prices、reasoning/default、`gpt-5-pro*` 输出上限与上下文/最大输入语义。
- Anthropic：识别并映射仓库现有 `supports_service_tier` 能力，不把 OpenAI priority/flex 价格语义套到 Anthropic；Claude Code alias 是否可见以正式功能文档和用户侧模型目录用途为准。
- Gemini/DeepSeek/GLM：只补仓库已归档官方事实；DeepSeek Anthropic bridge 属协议档案能力时进入正确字段；GLM 总上下文不得误写成 max input。
- PostgreSQL 目录快照继续保留管理员价格，不用官方快照覆盖人工价格；状态、能力、上下限和可见性必须幂等更新。
