# 计划：模型目录 JSON 单一数据源

- 状态：方案确认中（2026-10-05 用户提出，待确认 §6 两个细节后实施）
- 关联：`计划-20261005T110000000Z-模型目录全厂商补全与场景化展示.md`（现状目录事实与验收记录）、`docs/functions/厂商模型目录更新与清洗指南.md`

## 1. 背景与问题（实证）

当前目录数据散布在五层，全部靠手工保持一致：

```text
data_*.go（9 个 Go 文件硬编码计价+能力）
  ↓（编译进 gateway 静态快照）
model_catalog_data.go（种子 39 列，逐行手工同步，每行 1-2KB 长行）
  ↓（maintenance --seed）
sqlite/pg provider_model_catalog
  ↓（ApplyBuiltInStaticDerivedFields 静态派生）
展示投影 derived.go（9 家各自实现的 section 组装）
  ↓
前端目录弹窗（动态渲染 sections）
```

2026-10-05 一天内八轮批次暴露的问题全部源于此结构：

| 问题 | 层 | 根因 |
| --- | --- | --- |
| anthropic 15 行 Mode 系统性漏同步、gpt-4o-2024-05-13 cached 漏 | 种子层 | 计价层→种子手工同步 |
| glm 投影缺美元换算披露（九家唯一）、缺 image 场景分支 | 投影层 | 九家各自实现，无逐行完整性门禁 |
| USD 明文行（cogvideox-3 等）有价格无来源披露 | 投影层 | 披露逻辑只覆盖 CNY 行 |
| hasDirectPrice 漏媒体四维 → 媒体行从 priced-only 目录整行消失 | 过滤层 | 字段扩展后判断逻辑未同步 |
| 每轮核对需要多 agent 对比「官网原文 vs Go 代码 vs 种子」 | 全链 | 核对对象是五层代码而非单一数据 |

结论：核对成本高、缺陷反复出现的结构性原因是**没有单一数据源**。

## 2. 目标

1. 单一数据源：全部目录事实（官方明文价、来源、日期、模态、协议、窗口）进 JSON 文件，改数据=改 JSON。
2. 核对收敛为一条命令：`catalog-lint` 校验（schema、mode 词表、CNY 四件套、日期格式、必填、行数、排序、ID 哈希），谁缺谁错一目了然。
3. 消灭层间手工同步：种子从 JSON 生成，展示 section 由数据+统一渲染器驱动。
4. 非工程师可读可审：diff 是 JSON 而非多列长行 Go 代码。

## 3. 非目标

- 不改变对外行为：rawModel/PriceSet/ModelCatalogItem 类型、API 契约、目录页展示不变。
- 不做运行时热加载：仍是编译期打包（go:embed），改数据需重新构建——与现状一致，单二进制部署形态不变。
- 不迁移用量/统计等运行时数据，只迁目录静态事实。

## 4. 设计

### 4.1 数据文件

`backend-go/projects/gateway/internal/pricing/catalogdata/`，按供应商一个文件（gpt.json / gemini.json / xai.json / anthropic.json / deepseek.json / glm.json / minimax.json / volcengine.json / qwen.json），`go:embed` 编译期打包。

### 4.2 数据与规则分离（关键取舍）

JSON 只存**官方事实**（页面明文），派生规则留在 Go 加载层：

| JSON 存（官方事实） | Go 加载时派生（规则，现状不变） |
| --- | --- |
| USD/CNY 明文价、来源 note、币种、汇率、日期 | priority 两倍价（xAI/gemini priority 档） |
| 模态、协议、窗口、发布/退役日 | 分钟价 ÷60 直除每秒（§2.4） |
| 分档原句（batch/flex/priority 明文） | 人民币 ÷7.0 换算（约定汇率裁决） |
| 长上下文阈值/倍率明文 | perToken 换算、cached 同值才落模态无关通道（M3 裁决） |

理由：派生规则是"裁决"（有行注释与测试锚定），混进 JSON 会让同一规则散布 221 行；数据/规则分离后改价=改 JSON 数字，改规则=改 Go 一处。

### 4.3 层间关系（改造后）

```text
catalogdata/*.json（唯一数据源，go:embed）
  ↓ 加载+派生（原 data_*.go 逻辑收编为 loader）
rawModel/PriceSet（类型不变 → golden/链级测试不动）
  ↓ maintenance 种子生成器读同一 JSON
sqlite/pg 种子（39 列自动生成，手工同步废除）
  ↓ 展示统一渲染器（section 矩阵由数据驱动）
前端目录弹窗（不变）
```

### 4.4 catalog-lint 校验器

maintenance 新增子命令（或独立 go test 入口），校验规则由现有 Go 门禁平移：

- schema 校验：必填、类型、枚举（mode 词表、协议词表）
- CNY 行四件套齐全且汇率恒 7.0；USD 行无换算残留
- 模型名日期后缀与 releaseDate 同值；ID 哈希与 providerModelCatalogID 一致
- 与 sqlite 种子行数/内容一致（防生成器漂移）
- 输出「缺失/多出/价变」清单——每次核对这个 JSON + 官网对照即可

### 4.5 展示投影收敛

section 组装从「9 家各自实现」收敛为「统一渲染器 + 数据声明」：每行渲染哪些 section 由模式（chat/audio/video/image_generation）与数据存在性决定（现有 appendStaticMediaPriceSections/appendSourceDisclosureSection 已是此形态，glm image 分支缺失类问题结构性消失）。

## 5. 迁移步骤（每步全量测试绿再进下一步）

1. **导出**：脚本从现有 data_*.go 生成 9 个 JSON（机械转换，含行注释中的登记信息进 note 字段）。
2. **等价校验**：临时测试对比「JSON 加载派生」与「原 Go 数据」的 PriceSet 全量逐字段相等（221 行）。
3. **切换加载**：data_*.go 改为从 JSON 加载+派生，删除硬编码数据；全量测试（golden/门禁/链级）绿。
4. **种子生成器**：maintenance 从 JSON 生成 39 列种子，model_catalog_data.go 退役；schema 测试绿。
5. **catalog-lint**：门禁规则平移为校验器，清洗指南 §13.7 改为「跑 catalog-lint」。
6. **投影统一渲染器**：9 家投影收编为数据驱动（可独立最后一步）。
