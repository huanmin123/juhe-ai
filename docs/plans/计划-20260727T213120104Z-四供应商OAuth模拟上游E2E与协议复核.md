## 验证结果

- 四供应商模拟上游 E2E 已覆盖系统 API 建号、落库、分组 selector、driver 请求构造和本地 inference 首请求；同时覆盖 owner/state、token 临时失败重放、invalid_grant、429、请求中断和 Refresh Token 轮换。
- Gemini AI Studio、Code Assist、Google One 均经过真实本地 HTTP token endpoint；Code Assist 新用户额外经过 `loadCodeAssist` 与 `onboardUser`，Resource Manager 保留为成熟实现中的条件 fallback；三种模式均完成系统 API 落库、刷新和首次请求。Refresh Token 绑定原签发 client/client secret，legacy fallback 不再由宽松 mock 自洽放行。
- 独立只读审计发现并推动修复两项 P1：Grok 403 正文检查由逐 chunk timeout 改为绝对总 deadline；Gemini 从仅 AI Studio 的宽松 mock 扩展为三模式、client 绑定 token、Code Assist onboarding/Resource Manager 条件 fallback 和三模式系统 API 首请求。
- 四份 OAuth 协议契约、刷新并发锁、凭据归一化、OpenAI Codex 适配、Gemini Code Assist 运行时和 xAI provider 回归全部通过。
- Node 后端与 Vue 前端 TypeScript 全量检查通过。
- 隔离开发实例完成 OpenAI Refresh Token Client ID、Gemini 三种 OAuth 类型往返切换和授权结果输入交互验证；桌面视口无横向溢出，浏览器控制台无错误。
- Gemini capabilities 加入请求代次、供应商和协议档案复核，避免快速切换时旧响应覆盖新表单；AI Studio 会恢复协议档案默认端点模式。

## 非目标与剩余风险

- 不修改 Go 代码。
- 不把真实 OAuth endpoint 指向本地地址，也不提供生产 endpoint override。
- 不声称模拟器可以证明供应商当前线上可用性、账户资格、风控或订阅权益；这些仍需要真实凭据 smoke。
- OpenAI Device Flow、Grok 直接 Device Flow 和更多导入形态只在有明确产品入口需求时单列实施，本计划先保证现有浏览器绑定链路正确。
