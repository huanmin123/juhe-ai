## 验证结果

- 速度优先：慢首字降级、健康账户承接、120 请求混合流量、恢复探针成功后三次确认和恢复后重新排序通过。
- 热质量：成本/速度排序、同层探索、reservation/cursor、公平轮转、取消/未知终态不污染质量分母通过。
- 电路：`SUSPECT -> OPEN -> HALF_OPEN -> RECOVERING -> CLOSED`、恢复失败回退、singleflight/CAS、dispatch revision fencing 和控制面 outbox 通过。
- 质量状态：真实 HTTP 失败进入质量窗口，后台确认升级 `temporary_unavailable`，冷却复测后回到 `active/available`，容量和客户端中断不进入质量失败分母。
- 客户端边界：Codex/精确流式协议在服务端切号成功时不见中间错误；候选耗尽返回有界脱敏错误。通用客户端收到完整 HTTP 非 2xx 时按不透明协议保留原响应，不跨账号重放。
- 可靠性修复：质量回归明确激活 `pending_test` 账户、声明模型能力、关闭 SQLite read worker，并将容量等待压到 10 秒，连续回归不再留下句柄锁。

## 剩余风险

- 本轮未配置真实 Redis 地址，因此跨进程 Redis Lua smoke 未执行；已有 memory、Redis boundary 和控制面回归通过。
- 未执行真实账户异常风暴，避免费用和外部账户状态污染；真实模型只适合单请求探针，不替代 Mock 全矩阵。
- `provider-failure-recovery-matrix` 的非标准完整 HTTP 错误不属于当前自动重放契约，不能用它证明通用非幂等 POST 会跨账号切换；可重试的流式/传输异常已有独立回归覆盖。
