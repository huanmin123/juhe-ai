# PLAN-0145 全局请求阻塞等待治理

## 基本信息

- 状态：统一候选实现与专项验证完成，已合并生产日志分支，待合并 master 后执行生产验收
- 创建时间：2026-07-20
- 需求来源：生产 `/v1/models` 性能门禁暴露请求链路串行等待，用户要求全局排查并避免过度设计
- 执行者：Codex

## 需求目标

- 找出所有位于用户响应前的 Redis、数据库、IPC、审计、使用记录、统计和运行态副作用等待。
- 区分必要业务依赖与可并行、可复用、可在响应后进入有界队列的旁路工作。
- 优先消除重复读取和无依赖串行等待，不通过延长缓存、放宽一致性或删除安全校验换速度。
- 完成统一回归、性能门禁和 temporary-first 发布验证后再允许切流。

## 范围边界

本次包含：

- 网关认证、API Key、IP 策略、限流、运行态失效同步。
- 路由选择、账号并发快照、响应检查策略、session affinity。
- 流式和非流式失败处理、usage、审计、原始捕获及后台队列。
- 高频管理接口的重复确认、串行查询和响应前旁路。
- `/v1/models` 在启动预热完成后的首次请求和热请求性能。

本次不做：

- 不要求服务刚监听后、预热未完成时立即满足性能门禁。
- 不引入周期性全量预热、永久缓存、重型分布式协调或新的基础设施。
- 不把授权、最终并发槽获取、server retry 前账号避让、Gemini interaction 提交前亲和状态改成无等待。
- 未取得部署计划锁前不切 Nginx、不升级 main、不清理其他任务现场。

## 已确认问题

1. 账号并发调度在同一请求阶段重复读取 total/image 快照，image lane 内部读仍串行；本次已对四个独立读取点并行化，最终槽位仍保持同步权威。
2. 正常多供应商模型路由在 mapping miss 后对相同 binding 重复读取 group access、accounts 和过滤结果。
3. runtime/normal/hybrid 已读取响应检查策略，preflight 在最终候选上又无条件重载。
4. 非流式检查失败和部分流式失败在客户端可见错误前等待 usage 或 Redis 运行态旁路。
5. 响应结束后仍串行执行多项 Redis、usage、audit 收尾，延迟半开租约和处理协程释放。
6. API Key 失效同步按三个 topic 串行 GET；models 双层 limiter 使用两次顺序 EVAL。
7. 普通网关 runtime 在 Redis 模式下仍可能每请求经 DB service 重建，需在秘密不进入 shared cache 的边界下重新设计 metadata 快路径。
