## 需求目标

- 背景：`juhe-ai-public-welfare` 前端排行榜已先用 mock 对接，后续需要从 `sub2api-lite` 拉取公开数据；当前边界是 `sub2api-lite` 提供账号 / IP 维度事实聚合，不做公益站业务快照。
- 目标：复用 `/__aipublic__` 来源授权鉴权和接口级独立 scope，提供真实账号聚合读取、IP 聚合读取、IP 消耗排行便利视图和接入信息接口。
- 交付物：后端公开接口、接入文档目录、回归测试和功能文档更新。

## 范围边界

### 本次包含

- [x] `GET /__aipublic__/ip/usage`：读取 IP 维度聚合列表。
- [x] `GET /__aipublic__/account/usage`：读取账号维度聚合列表，供公益站按 `sub2apiAccountId` 生成贡献榜快照。
- [x] `GET /__aipublic__/consumption/ranking`：基于 IP 聚合的 TopN 消耗排行。
- [x] `GET /__aipublic__/access/info`：返回公开接口接入范围和边界说明。
- [x] 内置测试 token 返回 mock 数据；正式 token 返回真实 IP 聚合数据。
- [x] 公开接口授权页接入文档目录新增真实接口。
- [x] 回归覆盖 scope、mock、真实聚合读取和敏感字段不返回。

### 本次不包含

- 公益站业务贡献排行榜快照。
- 公益站用户维度消耗排行榜快照。
- IP 到公益站用户的业务归属。
- 公益站公网 IP 拦截和用户频率拦截。
- IP 范围总汇总卡片或范围 summary 表。

## 方案概述

- 接口统一挂载在 `/__aipublic__`，复用 `requireExternalIntegrationSource(...)` 鉴权中间件，并为每个公开接口传入自己的资源 scope。
- `ip-usage` 只调用 `listClientIpStats`，读取已经 ready 的 `client_ip_usage_range_windows` 和 `client_ip_registry`。
- `account-usage` 只读取已经 ready 的 `usage_scope_range_windows` 账号范围窗口，不在公开请求路径扫描使用记录明细。
- `consumption-ranking` 是 `ip-usage` 的 TopN 排序包装，不引入新聚合表，也不扫描明细。
- `access-info` 只返回接入边界和可用指标，不返回 API Key、上游账号凭据或公益站业务配置。
- 对测试 token 走 mock 分支，保证公益站后端可以不依赖真实统计数据先验证解析。

## 决策记录
