# PLAN-0139 双层持久缓存统一第一批

> **部分退场：** 本计划中的浏览器 page-data IndexedDB、confirm/revision 和写端 publisher 已由 [PLAN-0081](计划-0081-Node转Go渐进减法迁移.md) 的退场记录删除；独立 repository/shared cache 仍按各业务功能保留。本文只保留历史过程。

> **For agentic workers:** 实施时必须使用测试驱动；每个生产改动前先运行对应失败回归。不得创建提交、部署、清理生产 Redis 或加入运行时数据库迁移。

**Goal:** 在既有 page-data 基础设施上完成手动测试错误展示、供应商模型目录、常用下拉和统计首屏的“前端 IndexedDB -> 后端 cache -> 事实库”就近读取及写后失效。

**Architecture:** 前端复用 `pageDataCache`，新增面向非页面列表的有界 resource loader，让模型和下拉先读 IndexedDB、后台只做轻量 confirm。后端模型目录修复 read-worker 绕缓存并增加并发合并；新增有限 page-data domain 和领域失效发布，读请求只在后端 cache miss 时访问数据库或预聚合表。

**Tech Stack:** Vue 3、TypeScript、IndexedDB、BroadcastChannel、Express、Node SQLite read worker、PostgreSQL、Redis、现有 pnpm 回归脚本。

## 验收标准

- 人工测试失败不出现全局错误 toast，测试终端继续显示错误、traceId、requestId 和完整 JSON。
- 同 scope 模型目录热读不访问 SQLite read worker / PostgreSQL，前端刷新后 IndexedDB 热读不访问完整模型接口。
- 模型目标、内置模型配置或自定义模型发生变化后，前后端旧模型缓存都不能继续命中。
- 用户、团队、账户、分组和授权候选按权限 scope 持久缓存；删除或越权后不会因旧缓存继续显示。
- 统计首屏只保存预聚合区块，热缓存先显示并通过轻量 confirm 确认，不扫描明细。
- 未纳入持久化的敏感 / 命令 / 无界数据仍保持 `session/memory/no-store`。
