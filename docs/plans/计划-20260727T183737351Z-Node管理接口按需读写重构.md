## 验收标准

- 打开 AI 账户测试弹窗不请求模型；展开模型才加载供应商模型，展开请求形态只加载当前模型能力。
- 打开 AI 账户新增弹窗不请求 group / tag / model options；选择供应商也不自动加载模型或完整分组目录。
- 打开 API Key 新增 / 编辑弹窗不请求 route strategy options；展开下拉才请求。
- AI 账户列表和 edit-basic 的 repository 不调用完整 summary 查询后裁剪，响应不含设计明确禁止字段。
- 单字段账户 / API Key PATCH 不覆盖其他字段、不重写无关关联表、不访问 usage 统计；相同值不产生写入。
- 任何归一化后真实发生的业务变化都推进 `configRevision`；只有网关身份、连接、调度、额度或健康相关字段触发运行态、探针、额度窗口或缓存副作用。
- 管理员目标账户与本人默认引用缓存严格隔离；登出、切换用户和相关资源写入后正确失效。
- 已确认的重复详情 / 模拟下拉路径完成修复，确有必要的详情路径保留。
- 固定 20 行与 100 行列表都最多 3 次业务查询（2 条列表 / 状态查询加 1 条 circuit 摘要查询）和 1 次统计查询；20 行未压缩 JSON 最多 64 KiB，100 行最多 160 KiB。`edit-basic` 最多 3 次业务查询、0 次统计查询、0 次 DML、8 KiB JSON；同值 PATCH 为 0 次 DML，单标量 PATCH 最多 1 次账户 DML、0 次统计查询、0 次关联表写入、1 KiB mutation JSON。不得用虚构的改造前基线替代这些绝对预算。
- 所有自动化、类型、构建、Browser 网络验证和性能采样有可复核记录。

## 风险与注意事项

- 默认资源 ID 是用户作用域数据库事实，不是跨用户编译期常量；缓存失效和管理代管 scope 必须准确。
- 列表中 today usage 与并发是可见列，不能为缩包直接删除；应改为专用最小摘要和有界批量查询。
- 账户凭据保存在聚合 JSON 中，字段级 PATCH 必须在 Node 合并后做完整校验，不能在 SQL 层盲目 JSON merge。
- 授权账户的来源字段、权限和绑定语义不同，不能套用 owner 账户写入命令。
- 当前工作区存在其他未提交改动；重叠文件必须保留现有修改，不整理无关差异。
- 账户主链路之外的供应商模型、授权、响应检查策略、模型检测及部分 B 批次资源已经按独立契约和回归分批治理；剩余审计项不混入本计划完成口径，实施状态以 [PLAN-20260728T141710063Z](计划-20260728T141710063Z-Node管理接口按需读写后续分批治理.md) 为准。
