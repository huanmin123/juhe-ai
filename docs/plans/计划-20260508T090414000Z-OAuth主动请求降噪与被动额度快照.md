> 归档说明：本文记录 2026-05-08 的实施计划和验证现场。当前运行路径以最新代码、`docs/functions/SQLite存储说明.md` 和 `docs/functions/模型检测设计.md` 为准，不保留账号质量主动探测字段、主动额度刷新脚本或旧探针入口。

## 基本信息

- 计划 ID：PLAN-20260508T090414000Z
- 状态：已完成
- 创建时间：2026-05-08
- 需求来源：用户复查 OpenAI OAuth / API Key 透传后，要求 OAuth 额度快照被动优先，直接去掉主动刷新；Codex 请求形态识别暂不做，以用户体验优先。
- 执行者：Codex

## 需求目标

- OpenAI OAuth 额度快照只从真实网关请求返回的 Codex rate-limit 响应头被动更新。
- 移除建号后和后台定时的 OAuth 额度快照主动刷新，避免系统为了“看额度”额外请求上游模型接口。
- 账号质量主动探测能力直接删除，不保留 dormant 开关；冷却复测只保留“冷却到期后的恢复性复测”。后续 BUG-0013 已将冷却复测收敛为仅处理 `temporary_unavailable`，`rate_limited` 不再进入后台复测。
- 本轮不做 Codex 请求形态识别或拒绝，不因为请求看起来“不像 Codex”而影响用户调用体验。
- 文档明确 API Key 与 OAuth 的透传边界，避免再次把用户不知道的 OpenAI 组织、项目、Beta 字段放到账户表单。

## 范围边界

- 本次覆盖后端 background worker、OpenAI OAuth 建号接口、默认系统设置、回归脚本和相关文档。
- 保留 OAuth Access Token 自动刷新；它是凭据续期，不是模型请求。
- 保留真实网关请求响应头被动写入 `account_usage_snapshots` 的能力。
- 不删除 `account_usage_snapshots` 存储结构，因为列表展示仍需要读取被动快照。
- 不新增 Codex request shape 识别、拦截、伪装开关或用户可见字段。
- 不做真实上游 OpenAI 请求验证，只做本地脚本和类型检查。
- 不改变 API Key Header 策略；当前继续剥离客户端传入的 `OpenAI-Organization` / `OpenAI-Project`，保留 `OpenAI-Beta` 透传，不把这些字段加到账户或 API Key 表单。

## 风险与注意事项

- 被动快照依赖真实业务请求返回 Codex rate-limit 响应头；新建账号在第一次真实请求前可能没有 OAuth 专属额度展示，这是可接受边界。
- 删除主动探测后，同层级质量排序完全依赖真实流量样本；没有样本时调度回落到“超级优先 > 优先级 > 稳定兜底顺序”。
- 冷却复测仍会产生恢复性测试请求；当前已避免固定 `hi` 和固定 stream 形态，并在 BUG-0013 中增加退避上限。没有真实样本时使用最小 Responses 恢复探活 payload，后续如风控仍敏感，应继续增加更严格的批量预算和审计来源。
- 冷却复测形态只取 `usage_records.endpoint/model/stream`，不读取 `request_snapshot_json`，因此不会重放用户内容；代价是无法完全复刻复杂客户端 header 和 body 形态。
- 如果后续要恢复任意主动请求，必须先有明确需求、预算上限、退避和可追踪来源字段。
