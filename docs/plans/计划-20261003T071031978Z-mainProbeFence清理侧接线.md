## 需求目标

补齐主探针 fence 的清理侧接线：J1（账户健康检查）得出终态后提前清除或显式延后 `mainProbeFence`，替代当前"只能等 90s TTL 过期自愈"的现状，收敛同一键模型组合在 J1 结论后的无谓 blocked 窗口。

## 背景（取证事实）

- 写侧已接线：gatewayaccounteffects 结算链 `settleOnce` → `RecordMainProbeFence`（`keymodelattempt.go:321` 经 `dispatchHealthCheck` 携带 `KeyModelFenceReference` 发起 J1 探针），Redis 写入 `SET <prefix>:mainProbeFence:<capabilityHash> ... PX 90000`（`keymodelredis.go:66-68` 键派生、:363 脚本参数）。
- 清理侧零生产调用：`KeyModelRuntimeStore.ClearMainProbeFence` / `DeferMainProbeFence`（`gatewayaccounteffects/keymodelmemory.go:72-73` 接口，memory `:505/:524`、redis `:367+` 实现）全仓非测试零调用（BUG-0277 删除 `key_model_runtime` 双实现时确认）。
- 现状自愈：fence 生命周期靠 90s TTL（`KeyModelForegroundPrecommitLeaseMs`）过期，属有界偏差；J1 结论无法提前放行被 fence 拦截的同一 key-model 组合。

## 范围边界

### 范围内

1. outbox 行承载 fence 三元组：`account_health_probe_request_outbox` 行增加 `KeyModelFenceReference`（账户 id + 模型 + 端点族三元组的承载列）——gateway `cmd/juhe-ai-gateway/chain_request_failure_health.go` 的 `chainProbeRequestOutboxSchema`（:54-70，现仅 `source_fence` 单列）与 jobs `cmd/juhe-ai-jobs/worker_health_probe_outbox.go` 的 `healthProbeOutboxSchema` 两侧 DDL 同步（逐字一致约束），`w0cross_contract_golden_test.go` golden 同步更新。
2. 透传 fence 引用替代丢弃：`cmd/juhe-ai-gateway/compose_accounts_reset.go:266-268` 的 `chainKeyModelHealthDispatcher.DispatchAccountHealthCheck` 现以 `_` 丢弃 `*KeyModelFenceReference`，改为透传到 outbox 写入。
3. J1 outcome 观察器：J1 探针终态结算时——成功且命中获胜凭据（winner 匹配）→ `ClearMainProbeFence`；unknown（无法判定）→ `DeferMainProbeFence`。落点二选一（实现前裁决）：
   - 选项 A（推荐）：gateway 观察 jobs 投影后的终态，在 gateway 进程内复用 `gatewayaccounteffects` 现成 `Clear/DeferMainProbeFence` 方法清理——避免跨进程 Redis 写权限扩散；
   - 选项 B：jobs 侧开窄 Redis 写口直写主链 fence 键（需 jobs 侧显式最小权限与键空间契约）。

### 非目标

- 不动 `admitScript` 的 `mainProbeFence` 准入读取语义（BUG-0277 保留的门语义不变）。
- 不动 90s TTL（`KeyModelForegroundPrecommitLeaseMs`）数值与语义：观察器未接线/失效时 TTL 自愈兜底保留。

## 验收标准

1. J1 终态后 fence 提前清除（success+winner → Clear；unknown → Defer）。
2. blocked 窗口从 ≤90s 收敛到 J1 耗时级。
3. 两侧 DDL golden 契约测试绿（gateway `chainProbeRequestOutboxSchema` 与 jobs `healthProbeOutboxSchema` 逐字一致）。

## 风险与注意事项

- DDL 变更涉及 gateway↔jobs 交接表，两侧 schema 必须同批逐字一致（`CREATE TABLE IF NOT EXISTS` 幂等，存量表需评估加列路径）。
- 落点若选选项 B（jobs 直写主链 fence 键），需先冻结键空间契约与最小权限，避免跨进程写权限扩散；推荐选项 A。
- `DeferMainProbeFence` 语义不得弱化为"永远不清"：unknown 是有界延后，TTL 仍是最终兜底。
