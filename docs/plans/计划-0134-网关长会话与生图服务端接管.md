## 需求目标

- 背景：当前图像请求虽然能进入 `image` lane，但首响应、流式停顿和隐藏重试仍使用文本超时；270 秒还被整次请求墙钟时间使用，可能在仍有可用账号时提前结束服务端接管。
- 目标：只要仍有可派发或可恢复账号，服务端尽可能维持客户端连接并继续接管；通用网关不根据上游状态码、错误类型或错误正文决定切号；服务端确实无法继续时才交给客户端重试。
- 交付物：lane timeout profile、无账号等待预算、传输 / 语义提交边界、快速模式 lane 隔离、跨协议生图 provider 超时与取消传播、系统设置与管理端契约、回归测试和长期文档。

- 已产生模型语义输出后的跨账号拼接：协议上不可安全恢复，保持客户端重试边界。
- 旧设置字段运行时兼容、双读双写或自动迁移：项目只维护当前最优字段结构。

## 方案概述

- timeout profile：文本默认 `120/30/1800` 秒，图像默认 `600/120/3600` 秒，共享无账号等待 `270` 秒。
- 可用性状态：`dispatchable_now` 立即派发，`recoverable_later` 等待本地运行态变化，`hard_exhausted` 交给客户端重试；同一 tick 有候选时派发优先。
- 提交边界：HTTP / SSE 传输写出与模型语义写出分别记录；只有语义尚未提交时允许服务端透明换账号。
- 通用错误边界：状态码和错误正文作为不透明上游响应转发；MIME 只用于选择 SSE / JSON 解码，不参与调度判定。
- 快速模式：文本 lane 保留原有慢样本、切换次数、目标槽预占和共享预算；图像 lane 完全退出速度优先慢状态。
- 大响应：图像 JSON 不新增整包缓冲，审计继续使用现有明确上限并省略完整 Base64。

## 验收标准

- [ ] Images、edits、图像模型和 Responses 图像工具进入 image profile；optional 图像工具被移除后回到 text。
- [ ] 任一可派发账号存在时，270 秒不会停止服务端接管；无账号预算只在零可派发阶段累计。
- [ ] A 账号在语义提交前失败、B 成功时，客户端只看到 B 的响应。
- [ ] SSE 注释心跳后仍可在语义提交前切号，最终失败不再尝试返回 HTTP `503`。
- [ ] 非流式图像首字节后中断不拼接第二账号，也不使用无界 Base64 缓冲。
- [ ] 通用请求对任意状态码、错误类型和错误正文采用相同调度决策。
- [ ] 文本快速模式保持原有确认慢切号；图像请求不记录快速模式慢样本。
- [ ] 活跃且已有语义输出的 SSE 不被旧 1800 秒机械中断；未提交单次尝试仍有界。
- [ ] provider 外层取消信号可终止图像请求，默认 / 最大超时为 600 / 900 秒。
- [ ] 聚焦测试、类型检查、构建和相关协议回归通过，或有明确的既有阻塞证据。

## 风险与注意事项

- 长首包会占用账号并发槽；使用 lane 并发上限、客户端取消和未提交单次尝试寿命约束资源。
- SSE 心跳一旦提交传输，最终失败只能按 SSE / 客户端画像结束，不能切回 HTTP JSON。
- 通用请求不解释业务错误，因此完整上游错误响应可能直接透传；这是协议中立与不可穷举错误定义之间的明确取舍。
- 设置字段直接改名会要求部署时按当前字段结构同步数据库；运行时代码不得携带旧键兼容。
- 合并到有未提交修改的 `feature/20260706-go` 前必须核对重叠文件，不能覆盖用户本地工作。
