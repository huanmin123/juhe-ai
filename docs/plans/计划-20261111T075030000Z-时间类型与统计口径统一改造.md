## 需求目标

- 背景：当前时间存储有三种表示——UTC 文本（约 300 个 instant 列定义）、`timestamptz`（约 29 个业务列 + Go 自建表约 100 个列引用）、epoch 毫秒 `bigint`（锁/熔断运行态）。文本形态的正确性依赖一条数据库未约束的隐形约定：所有写入必须是定宽 UTC 毫秒，字典序才等于时间序。这条约定散落在 200+ 个手写 `Format` 点，并催生了 `::timestamptz` cast、±2ms 容差、毫秒截断、按 id 而非时间定位等防御代码。W24/W27/BUG-0180 已证明该约定会失效。
- 用户裁决：2026-11-08 的 T185“放弃 text 时间戳改造”由本次指令覆盖。本次不以“稳定性/迁移成本”为否决理由，目标是代码质量与长期可维护性。
- 目标：把**绝对时刻、日期、业务日历键**三类语义在数据库类型上分开，收敛到单一时间层；让“错误的时间写法”在类型层和测试层不可表达，而不是靠人肉纪律。
- 交付物：设计/计划文档、`dbtime` 与 `statcalendar` 共享包、读写面收敛、分阶段 schema revision、迁移 dry-run 与验收记录。

## 方案概述

### 方案原则

1. **语义先于类型**：先分“瞬时 / 日期 / 业务日历键”，再选类型；不把日历键机械改成 `timestamptz`。
2. **单一入口**：instant 只经 `dbtime`，日历键只经 `statcalendar`；禁止各域自写 `isoMillis`、`dateKey`、`time.LoadLocation`。
3. **数据库可验证**：能用 `NOT NULL`、`CHECK`、主键、类型表达的不变量，不留给 Go 代码注释。
4. **API 契约不变**：对外默认仍是 RFC3339 UTC 毫秒 `Z`，已有微秒输出字段保持原精度；类型迁移不改变前端和外部客户端行为。
5. **精度逐列决策**：目标精度 = max(现有存储精度, 现有 API/DTO 输出精度, 目标契约精度)，由 Phase 1 inventory 逐列输出；禁止批量套用 `timestamptz(3)`。`to_char(... AT TIME ZONE 'UTC', '...US...')` 若承载 revision/CAS/API 输出，属于精度契约，不是冗余格式化。
6. **文本编码过渡规则**：列迁移完成前，text 列只接受定宽 UTC 毫秒；`dbtime.DBText`（微秒）只允许用于已迁的 `timestamptz` 列。禁止在 Phase 0 把微秒文本写入 text 列，否则 `'....123456Z' < '....123Z'` 会提前破坏字典序。
7. **不保留运行时双读/双写**：单机停写窗口内完成类型切换；迁移期兼容只存在于维护命令，不存在于 gateway/jobs 运行路径。
8. **分区日与统计日分开**：分区继续按 UTC 日；统计按 `usageStatsTimezone` 业务日；文档明确两者最多差一天，不用分区名直接对账。

### 目标类型矩阵

| 语义 | 目标类型 | 典型列 | 说明 |
| --- | --- | --- | --- |
| 绝对时刻 | `timestamptz`，精度显式 | `created_at`、`updated_at`、`expires_at`、`last_used_at`、`lease_until`、`cooldown_until` | 按逐列 inventory：默认 API 毫秒契约用 `timestamptz(3)`；现有存储/输出为微秒的列（如 `proxy_profiles.created_at`、revision 列）用 `timestamptz(6)` |
| 日期 | `date` | `stat_date`、`stat_week`（周一）、`stat_month`（1 日） | 周/月起始用 CHECK 约束固化 |
| 业务时区本地小时/分钟 | `timestamp(0) without time zone` | `stat_hour`、`stat_minute` | 表示业务时区墙钟；时区来源仍是 `usageStatsTimezone` |
| 不透明窗口键 | 保留 `text` | 窗口缓存 `start_date/end_date`、`window_key` | 缓存键不是事实时间；避免改生成列连锁 |
| 升级账本 | 保留 `text` | `schema_state.converged_at`、`schema_migrations.started_at/applied_at` | 升级机制自身的引导期例外，改型会造成循环依赖 |
| epoch 毫秒运行态 | `timestamptz`（Phase 5） | `account_lock_states.*_ms`、`account_circuit_*.*_ms` | 保留数值的列在 Phase 5 逐列列名（如 Redis/外部协议计数），不设模糊例外 |
| 外部目录日期 | 保留 `text` | `models.release_date`、`models.shutdown_date` | 允许空串/非完整日期，先普查再定 |

### 统一层设计

- `backend-go/shared/platform/dbtime`：
  - 解析：`ParseAPI`（委托 `timefmt`，毫秒截断）、`ParseDB`（RFC3339Nano，保留微秒）。
  - 格式化：`API`（UTC 毫秒 `Z`）、`API6`（UTC 微秒 `Z`，仅现有微秒输出字段）、`DBText`（UTC 微秒，仅用于已迁 `timestamptz` 列；text 列迁移前仍用 `timefmt.FormatRFC3339Millis`）。
  - 绑定：`DBValue`（显式 `UTC().Truncate(time.Microsecond)`）、`DBValueMillis`（毫秒截断，用于 `usage_records.created_at` 等毫秒契约列）、`DBValueOrNil`。
  - 读取：`Nullable` 实现 `sql.Scanner`，接受 `nil/string/[]byte/time.Time`，统一 UTC；只用于维护命令/迁移 dry-run 与切换过渡；运行路径在类型切换后只接受 `time.Time`，不保留旧列回落。
  - SQL：`SQLText`、`SQLNow`、`SQLInstant`；禁止对时间列再包 cast。
  - 日历键：`DateKey/HourKey/MinuteKey/WeekKey/MonthKey`、`LoadTimezone`、`StartOfZonedDateKey`。
- `backend-go/shared/platform/statcalendar`：
  - `Day/Hour/Minute/Week/Month` 类型；`Of`、`StartOfDay`、`Next`、`DaysInclusive`。
  - 周一周起始、月 1 日语义沿用现行“UTC 正午纯日历”算法，避免 DST 与宿主时区漂移。
- 连接层：`pgcfg`/`pgpool` 统一设置 `TimeZone=UTC`；maintenance 的直连（`upgradepipeline/db.go`、`j3bmodelcheck/bootstrap.go`、各 CLI）同样纳入，不依赖容器 `TZ`，也不依赖 PG 服务端默认值。
- API 边界：DTO 禁止直接序列化 `time.Time`；统一经 `dbtime.API`/`API6` 输出，默认毫秒 `Z`，已有微秒字段保持原精度。

### 迁移机制

- 每批 schema 变更新增 **Revision=N 的 Step**，同批递增 `contracts.SchemaRevision`（当前 26，起编 24），并在 `backend-go/projects/maintenance/cmd/juhe-ai-maintenance/upgrade_steps.go:1293` 后注册；非破坏为 prepare，破坏为 swap/retire。
- Step 契约：`Satisfied` 查 `information_schema.columns.data_type`；`Apply` 幂等执行 `ALTER COLUMN ... TYPE ... USING ...`；`Verify` 复核类型、行数与关键约束。
- **每批同步清单**：新增 Step 同批更新 `contracts.BusinessSchemaVersion`、`shared/contracts/schema_w9a_test.go` 冻结值、`upgrade_registry_golden_test.go` 的 `(revision,id,implVersion)` 清单；fresh 库 `pg_schema_*.go` 的 `CREATE TABLE` 列类型同步翻成目标类型；j3b/j3a 表迁移同批更新 `shared/contracts/j3b_model_check_schema.go`、`j3a_proxy_latency_schema.go` 及对应测试；shape digest 只覆盖 `juhe_business`，其它 schema 用迁移前后类型断言补足。
- **非分区批 preflight**：每批先用 `information_schema` + 逐列扫描确认无空串/无 offset/非规范值；检查默认值、CHECK、生成列、触发器、外键/视图依赖；失败在加锁前返回，不留下长锁。`ALTER TYPE` 单表执行，`SET LOCAL lock_timeout` + `SET LOCAL timezone='UTC'`。
- **执行入口**：prepare 在发布窗前用新 maintenance 镜像跑 `upgrade --phase=expand --online --backup-confirmed --secret ...`（gateway/jobs 保持运行）；停写窗 `deploy.sh upgrade` 默认 `--phase=all`，会 adopt 已完成 prepare、只跑 swap。若未预跑 prepare，`all` 会在窗口内从头跑 prepare+swap，窗口显著变长。`deploy.sh` 当前不暴露 phase 参数，需同步 `docker/single-server/README.md` 与 `docs/deploy/部署指南.md` 写明预跑命令。
- **prepare 后门禁**：`--phase=expand` 会把 `schema_state.schema_revision` 推到新值但保持 `min_readable_binary_revision` 为旧值；在 swap 完成前不得启动新 gateway/jobs（新二进制会按 timestamptz 读取仍是 text 的列）。旧 gateway/jobs 可继续运行。
- 长耗时复制使用专用进度表（不复用 `detail_json`，它在 `MarkRunning` 时会被清空）；每批独立事务 + cursor CAS，可中断续跑。
- `usage_records` 采用“影子 schema + prepare + swap + retired”：
  - prepare（非破坏）：建 `juhe_usage_migrate`、新父表 `timestamptz(3)`、逐分区复制、建索引、校验。
  - swap（破坏）：停写窗口单事务 `LOCK → 追平 → 校验 → 旧表移入 retired → 新表移入 juhe_usage → COMMIT`。
  - retire（后续破坏 revision）：观察期后 DROP `juhe_usage_retired`。
- 账本/seed 例外：账本保持 text；seed 继续用规范文本参数，因为它在类型迁移步骤之前执行，且只补种内置行。

## 风险与注意事项

- 破坏相后旧二进制不能读新类型：`deploy.sh upgrade` 必须在停写窗口执行；回滚只能恢复备份或前向续跑，不能仅换回旧镜像。
- 精度截断：`timestamptz(3)` 会不可逆截断存量微秒；必须先由 inventory 判定每列精度，迁移前备份并用 `count(distinct)/min/max` 抽查；revision/CAS 列按现有输出精度保留微秒。
- maintenance 会话时区：upgrade/CLI 直连也必须 `TimeZone=UTC`，否则分区边界渲染、`pg_get_expr` 输出和类型检测会随连接漂移。
- 文本/微秒过渡：`dbtime.DBText` 只用于已迁 `timestamptz` 列；迁移完成前 text 列继续用定宽毫秒，否则字典序提前失效。
- 空字符串 fail-closed：`dbtime.Nullable` 把空串视为非法值并报错；Phase 2 前必须对每个待迁 text 时间列做空串预检，不能假设历史数据全部规范。
- 分区键不能原地 `ALTER TYPE`：`usage_records` 必须整族重建；旧族保留在 `juhe_usage_retired` 作为人工恢复载体。
- 清理正则失配会静默停摆：Phase 1 必须先上线“名字 + 数据守卫”清理，再迁类型。
- CAS/revision 精度耦合：`updated_at` 兼作 revision 的域（`proxy_profiles`、`announcements`、`apikeys` 等）必须保证读侧输出精度与 CAS 绑定一致，否则恒 miss。
- 统计日历键改类型会让旧的字符串 map/切片静默返回空：必须用真实 schema 测试臂覆盖，不能只跑 SQLite/手写 text 夹具。
- `usageStatsTimezone` 变更后必须重建统计：保留 `ErrHistoryLoss` fail-closed；typed 键不改变“改时区需重建”的契约。
- 生产规模未知项：分区数、表/索引体积需迁移 dry-run 现场取证，不能沿用推断值。
