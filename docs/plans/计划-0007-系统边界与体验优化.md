## 需求目标

- 背景：系统已完成用户侧和管理侧菜单拆分、团队与授权、代理强制使用、系统运行设置全局生效等核心修正，但后端用户侧和管理侧接口仍有混用，关键页面在方向表达、目标用户提示、分页筛选和排障体验上仍有优化空间。
- 目标：把高价值改造沉淀为可持续执行计划，优先降低权限作用域串味风险，再改善用户和管理员的高频操作体验。
- 交付物：接口拆分、回归测试、授权方向 UI、管理页目标用户提示、列表分页筛选、系统设置和排障体验优化、文档与验证记录。

- [x] 补充高价值回归测试，覆盖管理员用户侧 scope、管理侧按用户写入、代理强制使用、授权入站只读等场景。

### 本次不包含

- 正式上线后的版本化数据库迁移体系：当前仍按预上线规则维护当前模型，如后续上线再单独制定升级方案。

## 方案概述

- 方案原则：先收紧接口边界，再补测试兜底，最后改善高频页面体验和性能。
- 数据变化：第一阶段优先不新增核心业务表；分页筛选可能新增查询参数、索引或轻量统计读取口径。
- 接口变化：新增用户侧 `/api/my-*` 或等价明确用户侧入口；管理侧接口保持原路径但显式管理员能力。
- 前端变化：用户侧页面调用用户侧接口；管理侧页面调用管理接口并明确目标系统账户；授权页增加方向表达；列表组件接入服务端分页。
- 后端变化：routes 明确用户侧 / 管理侧边界；repository 减少对隐式请求上下文的依赖；写接口显式接收作用域。
- 数据处理策略：本计划优先兼容当前 SQLite 数据，不做破坏性数据清洗；如需要索引，按当前 schema 直接补充。

## 风险与注意事项

- 接口拆分会触及前后端请求路径，必须分阶段替换并保持兼容，避免一次性大改导致页面不可用。
- 服务端分页会改变前端表格状态管理，需要确认移动端加载更多、刷新、筛选重置行为一致。
- 授权方向 UI 不能只做前端筛选，后端权限仍必须保证入站记录不可管理。
- 回滚建议：若接口拆分出现问题，可先保留旧接口兼容层，让前端逐页切换，待验证完成后再清理旧入口。
