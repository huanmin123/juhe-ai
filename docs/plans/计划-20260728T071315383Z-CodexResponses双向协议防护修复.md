- 不通过单个模型名、`reasoning unavailable` 文案或未知事件证明上游一定是“假模型”；只对可验证的协议、工具生命周期和模型指纹作确定性判定。

- 不在已输出语义内容后切换账户，不把两个上游响应拼成一条流。
- 不因未知、截断或解析覆盖不足自动处罚账户。

## 验收标准

- 最终上游请求不再包含可重放 `custom_tool_call` 上的 `item_*`，且 `call_id`、工具名和 input 保持不变。

- 某 identity 已无映射暴露后不得中途改 ID。
- strict 模式在提交前可排除当前账户并换号；提交后拦截但不换号。
- clean、dirty、千级和万级 JSON/SSE 性能样本通过现有预算，且内存受有界 identity 表约束。
