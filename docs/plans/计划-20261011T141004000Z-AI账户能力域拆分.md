## 需求目标

### 背景

当前 AI 账户是"万能容器"：一个账户可通过 `supported_endpoint_modes` 自由声明对话、视频、语音、图像任意多种能力，导致表单承载全部形态字段、调度/健康/统计/故障域耦合、扩展点单一复杂度递增。

2026-10-11 用户裁决方向：AI 账户按 **对话 / 视频 / 音频 / 图像** 四个能力域拆分菜单与账户形态。除对话外，其他域的调度都很简单，拆开后各域表单可以做得简单，相互之间没有影响。

### 目标

- 账户具备显式**能力域**（capability domain）：`chat / video / audio / image`；域创建时确定、不可更改。
- 能力域决定：可绑供应商档案、上游接口能力（域内允许集）、表单字段集、健康检查方式、所属菜单。
- 同一上游在多个域使用 = 建多个账户（凭据可复用）；配置与运行状态按账户隔离。
- 网关 `/v1` 派发机制**零改动**；`/v1` 对话链是全程保护对象（见测试边界）。
- 四个菜单独立可扩展：新增形态只动对应域的表单与派发分支。

## 已裁决决策（2026-10-11 用户确认按推荐执行）

| 决策点 | 裁决 | 理由 |
| --- | --- | --- |
| 域字段 | **显式落库**：`accounts.capability_domain TEXT NOT NULL DEFAULT 'chat'` | 菜单归属、统计口径、迁移判定都有唯一事实源；从 modes 实时推导会让账户随规则演进"漂移" |
| 存量混合账户 | **含对话能力的混合账户归对话域、modes 全量保留；纯媒体混合账户按迁移规则第一命中域归属**（兼容优先） | M1 不中断现有调度；域外能力保留并提示，显式清理只经 M3 提示动作或重建 |
| 落地顺序 | **管理面 `/accounts` 先行，用户面 `/my-accounts` 跟进（M2）** | 管理面先验证域矩阵与迁移正确性 |

## 关键决策与理由

### D1 域字段显式落库，而不是从 modes 实时推导

- **为什么**：推导规则会随时间演进（如 gemini 族门裁决），域=推导结果会让账户"漂移"、菜单归属不稳定、统计口径不可比。落库后推导只在三个时机发生——存量迁移一次、M2 切换停写重算一次、（授权实例）随源账户继承——其余全部读列。
- **代价**：一次加列迁移（加式、可回滚）；域与 modes 可能不一致（由"实际声明集"契约兜底，见三集合模型）。

### D2 网关派发零改动（本方案范围可控的根）

- **为什么**：`/v1` 派发按「请求 lane ∈ 账户 `supported_endpoint_modes`」过滤是既定契约（`chain_driver.go` `endpoint_mode_unsupported` 淘汰 + `switchtarget.go` mode 门），域拆分不改变判定语义，只改变 modes 的**生产方式**。改派发 = 直接触碰核心对话链。
- **边界**："不改派发代码"只证明该处未变，不证明请求行为不变——行为等价由测试边界 T4/T5 行为级验收证明。
- **共享 lane 表述（v5 精确化；v8 待审修订）**：`images_json` 是 chat 与 image 两域**有意共享的 lane**；网关不读取 domain，同一分组内两类账户都按现有派发规则共同参与图像请求候选。域隔离的准确含义是"**新增声明按各域允许集限制；配置与运行状态按账户隔离**"，不承诺共享 lane 的候选互斥，也不为此修改网关。v8 后本表述收敛为「**存量共享、新增隔离**」：对话域存量已声明的 `images_json` 继续参与图像候选（派发只读 modes），新建对话账户不再能声明（见对话域纯粹化章节）。

### D3 域创建后不可更改

- **为什么**：改域 = 能力集整体切换 = 调度画像、健康检查、统计口径同时断裂。新建账户成本极低（凭据可复用、表单简单），用重建表达变更比可变域安全。未来如需"克隆到其他域"另行立项，仍不做原地改域。
- **推论**：所有写入口必须拒绝 `capability_domain` 变更；授权实例的域恒等于源账户域（随源继承，不独立赋值）。

### D4 存量混合账户归对话域，而不是迁移时强制拆户

- **为什么**：拆户需要凭据重录、重新验证、调度画像迁移，任何一步出错直接伤及在跑流量；兼容方案下迁移是纯加列 + 按规则赋值，凭据密文零触碰（I1 按密文哈希证明），派发行为可用"迁移前后候选矩阵逐一相等"证明零变化。

### D5 M1 纯读通道；写入口约束全部随 M2 交付

- **为什么**：写路径校验必须与表单同交付，否则 M1–M2 之间出现媒体账户创建空窗；M1 提前启用任何写拒绝都会在旧单列表制造新错误，违背"用户零感知"。
- **M1 窗口期语义**：创建/编辑与现状完全一致（新建账户落默认 `chat` 域）；M2 切换采用**停写全量重算**（见存量迁移节 v5 修订），覆盖窗口期新增与修改能力的全部账户，之后新建账户不进入迁移。

### D6 modes 由域约束：三集合模型与保存规则（v5 闭合创建/编辑冲突）

三个集合：

- **允许能力集**（allowed）＝ 域 × 供应商档案 × 账户类型推导，新建及普通编辑可新增声明的上限；不包含仅为兼容保留的遗留值。
- **默认能力集**（default）＝ 新建账户初始勾选（现行 `defaultEndpointModesForAccount` 按域收窄）。
- **实际声明集**（declared）＝ 账户当前生效 modes，**可含域外遗留值**（存量兼容，D4）。遗留集合以**服务端数据库中的现值**为准，不信任客户端"遗留"标记。

保存规则（按操作类型区分，服务端执行）：

- **新建**：`newDeclared ⊆ allowed`——不允许新增任何域外声明。
- **普通编辑**：`newDeclared − allowed == oldDeclared − allowed`——允许集外遗留集合必须与数据库现值逐项相等（既不扩大也不缩小）；允许集内可选择，但仍须满足非空、账户类型兼容、必需能力及任务组完整性校验。域约束追加在既有凭据、模型及映射校验之上，不替代这些校验。
- **显式清理**（M3「域外能力」提示动作）：遗留集合**只能缩小，不能扩张**；清理动作单独审计。
- **导入/克隆**：按新建规则（见服务端统一校验节，v5 修订）。

装载契约：编辑装载**不裁剪**实际声明集——表单数据含完整 modes，域外值以只读「域外能力（保留）」标识展示；基线快照含完整集合 ⇒ 无变化保存/仅改名不产生 modes diff；用户修改域内能力提交完整数组，域外值原样保留。三场景验收见 T4（含服务端接受与保存后重载核对）。

- **上下文与差量语义**：沿用现行 PATCH 契约，供应商、协议档案和账户类型不可原地修改；`allowed` 按数据库现存 domain/profile/type 计算，old/new 共用同一允许集。`newDeclared` 是按既有补丁合并规则得到、最终将持久化的集合；未携带 modes 时保留旧集合，不套用新建默认集；显式 `null`、空数组或删除键不得借默认归一化绕过保存规则。未来如开放身份字段切换，另行定义兼容迁移。
- **并发一致性**：旧值读取、补丁合并、集合校验与提交在既有事务及 `expectedConfigRevision` CAS 内完成；批量编辑逐账户核对版本。版本冲突返回既有 409，要求重载，不自动重试覆盖或重新加入已被显式清理的遗留能力。

Gemini 兼容校验联动：现行 `assertGeminiEndpointModesCompatible` 要求至少一种对话能力，按域×档案联动调整（gemini 对话域仍须至少一种对话能力，纯媒体走 native 档案视频/音频域）。

### D7 媒体表单按 供应商×域 出必需字段，域内模型映射保留

- **为什么**：hybrid 的 `video_generation`/`tts` 模型映射是在用能力（M4b 出站改写）；火山语音需要 `speech_appid`/`speech_token` 双值凭据（`credentials_normalize.go:223`）。"全默认值"会破坏两者。
- **修订**：媒体表单按 M2 产出的「档案×域 × 必需/可选凭据字段 × 模型目录来源」清单表动态渲染；hybrid 视频/音频域保留域内模型映射编辑；**编辑态未渲染的既有配置保留原值**（payload 合并存量，不统一默认值）。
- **不变**：对话专属语义（错误/响应策略、请求覆盖、锁死、余额、时间计划）媒体域不渲染；支持模型一律必选（`assertSupportedModelsRequired`）。

### D8 不采用"一个账户挂多域标签"的折中方案

- **为什么**：多标签下账户仍是同一配置/故障/统计单元，只解决菜单展示没解决隔离。独立账户才是故障域、配置域、统计域的天然边界。

### 档案×域清单表定案（v7，D7 依赖，前端媒体表单按此渲染）

**凭据字段**（证据：`credentials_normalize.go`、`endpoint_modes.go`、`gatewaypreauth`/`gatewaymedia` 出站构造）：

- api_key 型通用必填：`base_url`（必填 + `assertSafeUpstreamBaseURL` 安全断言）、`api_keys`（1–10 个）；其余策略字段可选。
- volcengine 音频域追加 `speech_appid` + `speech_token`：表单在 audio 域标必填（出站缺一即显式失败；出站 host 恒 `openspeech.bytedance.com`，不经账户 base_url）；其他供应商该双值写侧直接拒绝。
- oauth 型媒体可用性：gpt/xai oauth 只允许 responses 族 → 媒体域不可选；anthropic 系 oauth 仅 messages → 媒体域不可选；**gemini native `google_oauth` 在 video/audio 域可用**（词表含媒体形态）；minimax/volcengine/qwen 档案仅 api_key。
- 结论（账户类型×域矩阵）：媒体域可选账户类型 = `{api_key}` ∪ (gemini native: `google_oauth`)。

**模型目录来源**（证据：`model_catalog_data_gen.go`、`provider_model_catalog` 表、`account_model_mappings`）：

- chat/image/video/audio 域统一来自 `provider_model_catalog` 静态快照按 mode 过滤（video / audio_speech / audio_transcription / image_generation）+ `providers.default_supported_models_json`；`custom_provider_models` 手加模型照常参与。
- **hybrid 特例**：无上游目录；媒体模型 = 账户级 `account_model_mappings` 的 `video_generation`/`tts` 族改写（出站 `chainVideoMappedModel`）；hybrid 视频/音频域表单保留域内映射编辑（D7）。
- qwen 音频域允许集 = 长音频任务四值 `audio_job_*`（paraformer）；cosyvoice 目录行存在但写侧词表未收 `audio_speech`，TTS 契约回填前不进允许集。
- glm 写侧词表不含 `images_json` → glm 无 image 域（与矩阵一致）。

前后端允许集/默认集镜像按本表实现，并以源码契约回归钉住（M1 词表完整性测试同法）。

### 网关影响（论证"零改动"）

- 域字段不进入派发投影与判定：`supported_endpoint_modes` 来自 credentials JSON 装载水合（`chain_accounts_secret.go`），域推导仅改变写入来源；派发候选窗口是显式列清单（`chainCandidateColumns`），无需加列；缓存失效沿用 `InvalidateGatewayRuntime` 代际推进；`dispatch_revision` 是电路 CAS revision，与本变更无关。
- M1 回归确认两处 mode 过滤消费点行为不变（`chain_driver.go`、`gatewaydispatch/switchtarget.go`）。
- 行为等价不由"未改派发文件"自证，由 T4/T5 行为级验收证明（见测试边界）。

## 服务端统一校验（M2 交付，全部写入口；v5 按保存规则重构）

统一按 D6 保存规则执行，**旧集合（oldDeclared）一律由服务端读数据库现值，不信任客户端提交的"遗留"标记**：

- **创建（POST，含批量新建）**：`newDeclared ⊆ allowed`；域必须在矩阵内；账户类型联动校验（同档案 api_key/oauth 允许 modes 不同；gemini 兼容档案至少一种对话能力按域联动）。
- **更新（PATCH）**：域不可变（携带域变更即拒绝）；按 D6 在既有事务与版本 CAS 内校验合并后最终集合，`newDeclared − allowed == oldDeclared − allowed`（遗留集合逐项相等）；保持既有非空、类型兼容与组完整性规则。省略 modes 的凭据更新不重置声明集。
- **显式清理（M3）**：遗留集合只能缩小不能扩张，单独审计。
- **导入**：**按新建规则严格校验**（`⊆ allowed`）——无域字段的旧包按迁移规则推导并在预览回显；含允许集外能力的包明确报冲突，要求先拆分后再导入，不静默裁剪。预览与执行使用同一套服务端校验，执行时重验，不信任客户端预览结果；不引入"上传包自称 legacy 即放行"的例外。若未来确需完整历史备份恢复，另行立项定义入口、权限与验收。
- **克隆**：按新建规则校验；含遗留能力的源账户须在克隆草稿中明确显示冲突，由用户确认整理为域内能力后才能创建，不改源账户。M2 补 `cloneSourceId` 可选契约，正式克隆客户端必须发送；服务端沿用 clone-context 的访问范围、归属检查及授权实例禁克隆规则加载源账户，断言目标域 = 源域。源不存在、已删除或越权按既有错误语义拒绝，不退化为普通新建；目标独立通过普通创建的归属、分组、凭据、模型和能力校验。未携带此字段的请求是普通新建，不宣称阻止维护者手工录入凭据新建其他域账户。
- **批量编辑**：服务端同域校验（请求内全部账户 ID 域一致，否则整批拒绝）；按普通编辑规则校验 modes。
- **授权实例**：新建/恢复实例域 = 源账户域（`instance_provision.go` 写入路径补继承）；读取/列表投影实例域随源。
- **新建默认集按域收窄**：modes 缺省时按域取默认集（chat=现行档案默认；video=视频四值组；audio=音频组按供应商实际接入；image=`images_json`）；后端缺省解析与前端 `defaultEndpointModesForAccount` 按域收窄镜像。chat 域默认集与差量语义一个不改（I3）。
- **Gemini 对话域联动**：chat 域 gemini（api_key/google_oauth）保持「至少一种对话能力」要求（现行 `assertGeminiEndpointModesCompatible` 规则扩展到创建/编辑链的 gemini chat 域）；媒体域走 native 档案域内允许集，不适用对话能力要求。chat 域其他供应商不新增任何既有校验之外的拒绝（I3/对话域行为零变化）。

### M2 启动门禁与部署顺序（v7 定案）

- **阶段记录读取下沉共享**：gateway/jobs 启动需读阶段记录，但阶段读写符号在 maintenance `internal/` 下无法跨模块 import（Go internal 规则）。将 `capabilitydomain` 包（或至少 stage 记录子集）下沉到 `shared/platform/`，maintenance 改引用，**禁止两处解析语义并存**；具体取整包下沉或子集抽取由实施按依赖证据选择并记录。
- **启动要求**：gateway/jobs 启动在既有 schema 形状校验之上，加读 `global_settings` 阶段记录——要求存在、`m2_finalized`、ruleVersion 一致；缺失/不符 fail-fast，错误信息直接指向 maintenance 迁移命令序列。启动只读，不把启动变成迁移执行者。
- **全新空库自动封存**：maintenance `--ensure-schema`/`--seed` 对全新空库（accounts 无行）按计划「全新 M2 安装」条款自动按序执行空库 M1→M2 阶段并封存；**非空库一律不自动写记录**（真实切换必须显式跑迁移命令）。gateway SQLite preflight 与测试夹具经 bootstrap 路径自动获得记录。
- **部署顺序契约**：升级 M2 版本前停写 → `--migrate-account-capability-domain --stage=m1` → `--stage=m2-cutover` → 核验通过 → 启动新版；回滚保留 `m2_finalized`（见回滚策略）。同步部署文档。
- **测试夹具集中补点**：gateway 走 bootstrap 自动覆盖；jobs 手建联合 schema 夹具（`wgSeedAllJobsFixture` 等）与 PG 夹具补阶段记录 seed；acceptance harness 启动前执行 ensure-schema。

## 存量数据迁移（M1 与 M2 切换）

### 阶段记录与重跑边界

- 推导规则固定为 `ruleVersion=1`；复用业务库既有 `global_settings` 的专用 key `account_capability_domain_migration` 保存迁移阶段、规则版本与完成时间，不存凭据。阶段依次为 `m1_running → m1_complete → m2_running → m2_finalized`；这是一次性迁移记录，不是功能开关，也不允许通过删除记录或覆盖参数重新开放迁移。
- M1 首次执行写入 `m1_running`，失败保留该阶段供恢复；已为 `m1_complete` 的 M1 重复执行只报告完成，不再重算窗口期数据。M2 切换只接受 `m1_complete` 或恢复中的 `m2_running`，在停写状态全量重算并核验；核验成功后才写 `m2_finalized`。并行迁移进程不得同时运行，阶段变更以数据库锁或条件更新保证单执行者；最终落库核验与完成记录提交处于同一事务，核验或阶段提交失败都保留 running，不得提前标记完成。
- `m2_finalized` 后任何会重新赋域的命令均拒绝，不能覆盖 M2 用户显式创建的不可变域；只读核验仍可执行 schema、域值合法及实例与源域一致检查，明确标记「推导对账不适用」。M2 gateway 启动只读要求该完成记录与 schema 合法，不把启动变成迁移执行者。
- 恢复失败批次始终先核对记录与规则版本，再重新读取当前数据；分批提交不是已完成标记。M2 回滚保留 `m2_finalized`，禁止因回退代码而重开推导。全新 M2 安装先完成新库 schema，再按顺序执行空库 M1/M2 阶段并封存，之后才允许账户创建。

### 执行协议（四阶段，顺序固定）

1. **预检（preflight）**：只读，允许域列尚不存在；「预计需要赋域 N 个账户」是正常结果。验证既存 schema 形状、阶段/规则版本、解密与声明格式、授权实例源关联，输出预期域和失败清单；预计域与现值不同只作为待迁移项，不作为预检失败。源账户先推导、实例继承源的预期结果，不读取实例占位凭据。报告只含账户 ID、域、计数及脱敏错误，不输出凭据、解密 JSON 或连接串。
2. **停写 + 备份 + 重验**：停止 gateway/jobs 及其他会写账户、授权实例或运行态的进程，记录停写时点并等待在途事务完成；不能用「低峰」或未观察到请求代替停止写者。按运维手册验证可恢复备份，再在停写状态重跑预检及迁移前 I1/I2 快照。整个执行、恢复失败批次及核验期间保持停写；迁移命令沿用显式停写/备份确认门禁，无确认不得执行。
3. **执行**：核对阶段记录 → 加列并校验形状 → 源账户分批赋值 → 授权实例分批继承；每批短事务，先完整读取该批并检查 `rows.Err()`、关闭结果集，再写入（BUG-0308）。只更新域列及迁移记录，不修改凭据、配置版本或派发版本。解密失败、声明格式错误或缺失源账户不猜域，计入失败清单；源失败则实例列为依赖失败。进程中断、SQL 错误或任一失败都返回非零，不写完成阶段；已提交批次保留，修复后在同阶段重跑。部分成功不满足上线门禁。
4. **核验 + 版本切换 + 恢复写入（postflight）**：只读命令要求域列存在并核对全表域值合法、源/实例一致、阶段内推导一致及失败清单清零，同时复核 I1/I2 快照；执行命令在同一停写窗口使用相同核验逻辑后持久化完成阶段。确认通过后才部署/启动对应版本并恢复写入，不能先启动依赖域列的新版再迁移。M1 新版含实例继承写入；M2 新版要求 `m2_finalized`。封存后核验不再按当前 modes 重新对账，不作为常驻推导任务。

### 推导规则

- 扫描范围含软删除账户，以便日后恢复仍保域；源行软删除但仍存在时可继承，源行不存在或关联不完整则报告失败，不改写授权关系。读取原始声明时区分缺省、空数组、null、非数组和未知模式；缺省仅在与现有网关运行时归一化一致的已验证规则下取生效能力，不使用新建默认集猜测。不能证明运行时口径一致的行列为预检失败，保留原凭据；空值、未知模式等边界纳入金集，不能用通配符把未知 `video_*` 自动视为合法能力。
- **对话 modes 集合**（锚定义，前后端镜像）：`chat_json` `chat_sse` `responses_json` `responses_sse` `messages_json` `messages_sse` `generate_content_json` `generate_content_sse` `interactions_json` `interactions_sse` `count_tokens` `embed_content` `message_token_counting` `realtime_session` `audio_transcription_json`。
- 规则（按序命中即停）：

  1. 授权实例 → 继承源账户域（依赖源账户迁移成功；源失败则实例列依赖失败）；
  2. 不含对话 modes 且含任一视频四值 `video_create/get/content/cancel` → `video`；
  3. 不含对话 modes 且含 `audio_speech` 或任一长音频四值 `audio_job_create/get/content/cancel` → `audio`；
  4. 不含对话 modes 且含 `images_json` → `image`；
  5. 其余 → `chat`，modes 全量保留（域外值由三集合保存契约承载）。

### M2 切换（v5 修订：停写全量重算，不再按时间窗筛选）

- M2 新写契约启用前设停写切换点，对全部已有账户（含窗口期新增、改过能力及软删除行）按固定规则重算，再同步所有实例域；这次受控迁移是「域不可变」的明确例外，M2 封存后不再重算。按上述四阶段完成 I1/I2 与核验，写 `m2_finalized` 后启用 M2 写契约与菜单，此后新建账户不进入迁移。

## 测试边界与核心对话保护

**保护对象**：`/v1` 对话链。第一验收 = **对话域行为零变化**；行为等价由 T4/T5 证明，不由"未改派发文件"自证。

### 不变量清单（每期逐条核对，破坏即 blocker）

- **I1 迁移与装载密文不变**：迁移、重算和纯装载前后比较 `credentials_encrypted` 密文哈希（非解密 JSON）；用户显式编辑凭据或 modes 引起的正常重加密不受此字节不变量约束，按 T4/T5 核对具体字段变化。
- **I2 迁移派发语义不变**：在同一停写快照及固定隔离 fixture 下冻结账户状态、模型、分组、路由、排序游标及请求输入，以「策略/分组 + model + lane」为比较键，记录候选账户 ID 与淘汰原因；受排序状态影响的有序结果使用相同初始状态回放。迁移/重算前后逐一相等；用户显式修改能力后的预期候选变化另按 T5 验证，不要求与编辑前完全相同。
- **I3 既有字段与差量语义不变**：保留对话账户既有字段含义和保存差量语义；允许本计划明确新增的新建 `capabilityDomain`、克隆 `cloneSourceId` 及只读域回显，不把新增写字段误判为回归。
- **I4 现有回归全绿**：`test:account-name-suggestion`、`test:account-model-mapping-model-options`、`test:account-batch-edit`、`test:temporary-unavailable-probe-toggle`、`test:account-health-check-endpoint-mode`、`test:account-edit-save-flow`、`test:account-clone-demand-loading`、`test:xai-account-capability` + vitest 当前全量，每期零新增失败。
- **I5 `/v1` mock 矩阵零回归**：Stage1/Stage2 全量每期必跑。
- **I6 媒体行为不前移**：生命周期表定案前不改变媒体账户既有健康检查/J1 行为。
- **I7 存量声明不被静默删除**：普通编辑的保存规则保证遗留集合与库中现值逐项相等（服务端执行，客户端标记不可信）；只有 M3 显式清理动作可缩小遗留集合。

- **T5 真实网关链路、Mock 上游验收**：经本次隔离实例实际 `/v1` 请求链验证创建和修改能力/映射/凭据后的对应 lane 成功，至少覆盖 chat 普通编辑、image、volcengine 音频双值凭据、hybrid 视频映射及 qwen 长音频任务；核对出站路径、鉴权、模型名和响应，任务型能力覆盖创建/查询/内容/取消。可复用已覆盖这些路径的全链路用例，记录具体复用项及结果，不重复无关测试；没有可用 Mock 的新增路径先补依赖边界。付费上游实调用另行授权安排并计入成本，不作为本轮文档复审结果。
- **T6 授权实例闭环**：四个域的源账户 × 授权实例（新建/恢复/读取），域继承与派发正确。
