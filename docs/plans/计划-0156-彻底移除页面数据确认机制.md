## 需求目标

- 删除 `/data-changes/confirm` 和整套 page-data domain/revision/change publisher。
- 删除前端 IndexedDB/resource/request cache、activation 和 mutation 自动失效。
- 删除 Node/Go Redis publisher、dirty-domain recovery、IPC、测试和脚本。
- 页面恢复直接调用业务接口，不保留兼容层或替代探针。
- 完整验证后合并并推送 master，不部署。

## 验收标准

- [ ] `/data-changes/confirm` 不存在。
- [ ] 前端不再存在 page-data API、revision token、activation、IndexedDB page-data cache 或 mutation interceptor。
- [ ] Node/Go 不再发布或恢复 page-data change，不再读写 page-data Redis key/dirty-domain。
- [ ] 当前文档不把该机制描述为有效架构；历史计划有明确退场标记。
- [ ] 页面直接请求业务 API，自动化和浏览器验证通过。
- [ ] 已合并并推送 master；未部署。

## 决策记录

- 不做“只删聚合层、保留旧 confirm”的折中，因为根因是高频域持续 changed。
- 不做空路由、feature flag 或兼容 shim，避免机制继续被误用。
- 不用新的版本协议替换；未来高频页面优化必须按静态数据与动态快照分层另立计划。
- 不运行生产 Redis 扫描清理；旧 key 按 TTL 过期，本次不部署。
