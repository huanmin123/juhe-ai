## 目标

AI 账户导入时，来源系统（含我们自己系统的 sub2api 格式）声明的模型列表必须已存在于平台模型目录（计费定价来源），否则导入预览即失败、无法确认导入，并提示用户先创建模型。解决「导入了却因模型不在目录而无法测试/无法计费」的问题。

**非目标**：不处理 NewAPI 的 `model_mapping` 字段（继续忽略计数）；不新增「部分导入」语义（保持现有「任一账户失败则整次不可确认」的管道语义）；不修改共享断言 `assertAccountSupportedModelsInProviderCatalog` 的既有文案；cpa（CLIProxyAPI）模式本次不映射模型（保持既有迁移计划声明的边界，文档写明）。

## 行为设计

| 来源模式 | 来源模型字段 | 处理 |
| --- | --- | --- |
| sub2api（自有格式） | 账户对象 `supportedModels` / `healthCheckModel` / `healthCheckEndpointMode` / `modelMappings`（export.go 导出时携带） | 适配器透传进账户记录，与 native 协议同键 |
| newapi / oneapi | channel `models`（逗号/换行分隔字符串，也接受数组） | 拆分、去空白、去重、保序后写入 `supportedModels`；`models` 加入 accepted 键不再计 ignoredFields |
| native | 原生协议已支持 | 不动（已有目录拦截） |
| cpa | — | 不映射，维持现状 |

拦截语义沿用现有管道：目录断言失败 → per-account message → 该账户 failed → `CanImport=false` → confirm 拒绝执行（预览即可见，前端已渲染 per-account messages）。导入链对目录类失败的 message 追加引导后缀：「。请先在模型目录创建这些模型并配置价格后再导入」。

依据：模型目录是计费取价来源（`pricing/lookup.go`），且自定义模型 active 状态创建时后端强制完整价格（`providers/write_routes.go` `validateCustomModelPricing`），「先建模型=补齐计费」成立。

## 边界与风险

- 行为变更：来源声明目录外模型的导入从「静默成功（回退默认模型）」变为「预览失败」——这正是本次目的；对存量数据无影响。
- Node 归档同为丢弃行为，本次是有意的行为改进，非回归修复。
- cpa 模式模型映射如有需要，后续单独任务（需先核实 CLIProxyAPI YAML 模型字段与 alias 语义）。
